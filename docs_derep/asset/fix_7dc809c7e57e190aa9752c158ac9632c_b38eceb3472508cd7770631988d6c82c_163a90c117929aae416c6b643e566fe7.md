##### 4. 对齐微调的做法与效果

为了让输出更贴合人类价值与使用偏好，DeepSeek V1 同时采用了监督式微调与直接偏好优化。两者配合后，答案的准确性与实用性同步提升，用户满意度与信任感随之增强。

为何要做监督微调与偏好优化？预训练后的模型像个未经修剪的海量学习者，什么都收录，没有善恶之分。关键下一步是教它辨别可接受的表达与不可接受的内容，类似对孩子的教育，既要传授知识，也要建立边界。

监督微调的重点是让模型学会给出准确无误的答案，掌握人类问答的范式。直接偏好优化则是在多个看似都对的答案里，挑选出更符合人类价值的那一个，通过对答案的好坏排序，让模型自己学会“能说什么、不该说什么”。

对 7B 这类小模型，数学和代码数据集上的长时间微调是拉升表现的核心。但实践中发现，监督微调阶段数学数据越多，输出重复率也越高，可能是模型过度记住了解题套路。为此采用了两阶段微调：第一阶段做全科补充，涵盖全部微调数据含数学代码；第二阶段转为主攻对话，去掉数学代码后聚焦聊天，并引入偏好优化。两种做法都能在保持基准分数的前提下明显降低重复。

偏好优化的偏好学习集涵盖了无害性和有益性两条线。无害性不仅是学会拒绝危险提问，还要对比好回答与坏回答；有益性不仅是学会作答，还要对比优质回答与普通回答。训练时使用 1 个 epoch，学习率 5e-6，批次大小为 512。实验显示偏好优化不仅改善了开放式问答，还在各领域带来了普遍提升。

#### 1.2.2 DeepSeek 技术迭代路径

V1 验证可行后，团队持续打磨，陆续推出 V2、V3 等更强版本。

##### 1. 引入MoE架构

V2 首度引入混合专家机制，训练效率和推理性能双双提升。稀疏激活配合动态路由，推理时只唤醒少量专家，大幅省算力。

##### 2. 提出MLA机制

为进一步提升推理效率，V2 提出了多头潜在注意力。把输入 token 的注意力压缩为潜在向量，使用时再解压得到对应的 Key 和 Value，极大减少了 KV 缓存占用。

##### 3. 升级模型规模与训练数据

随着技术演进，V3 的参数规模是 V2 的三倍，训练数据量接近翻倍。配合 FP8 混合精度训练和优化的通信内核，训练成本得到有效管控。

##### 4. 强化学习与蒸馏技术的结合

为提升推理能力，R1 系列探索了强化学习与蒸馏的结合。用强化学习训练出高性能模型后再蒸馏到更小模型，实现低成本、快速复用推理能力。
