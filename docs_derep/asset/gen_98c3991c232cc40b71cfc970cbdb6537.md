属性面板就是你的核心操控区，坐落在 Figma 界面的右侧，也是整套工具里最聪明的部分。它具备情境感知能力，会随画布上的选中对象实时切换可用选项。点到矩形，它就展示填充、描边、圆角等控制；选到文字，它就换成字重、字号、行高等属性。所有细节打磨基本都在这里完成。

接下来要聚焦本节的核心方法：框架优先思维。在现代界面设计里，几乎所有元素都在某个容器里。Figma 里真正强大且通用的容器就是框架。

对从 Photoshop 这类传统图形软件转过来的新人来说，框架、组、形状很容易混淆，分清三者是入门的关键。

- **形状**：最基础的构件，比如用工具栏画出的矩形、圆形，属于纯粹矢量图形，是搭建界面的“原子”。
- **组**：只是把多个对象简单捆绑起来，像把散落的文件塞进一个文件夹。组的包围盒完全由内部元素决定，拖动或缩放内部内容时边界也会跟着变。在界面设计里，组的实用价值很有限。
- **框架**：UI 的基础单元，可理解为智能画板或智能容器。它拥有独立可调的尺寸，还自带组没有的额外能力——约束能定义子元素在框架缩放时的定位与尺寸变化规则；内容裁剪能在需要时把溢出边界的部分自动隐藏。框架同时是自动布局和组件创建的唯一基础。

强调框架优先，本质是把静态平面思维切换到动态界面思维。UI 不是画一张固定图，而是搭建能随屏幕尺寸和内容变化而自适应的系统。组是被动跟随内容，框架则能主动管理内容行为。社区里资深设计师几乎一致主张“能用框架就别用组”，正是因为它更贴近 Web 开发里基于容器的构建逻辑，比如 HTML 中的 `<div>`。

为了快速体会两者差异，表2-2 做了一个对照。

表2-2 框架与组的核心差异

| 特性 | 框架 | 组 |
| :--- | :--- | :--- |
| 尺寸行为 | 尺寸可单独设定，与内部内容无关 | 尺寸由内部元素的边界决定，随内容变动 |
| 内容裁剪 | 可开启裁剪，把超出边界的部分隐藏 | 不支持裁剪，全部内容始终显示 |
| 约束 | 子元素可设置约束，控制缩放时的相对位置和大小 | 没有约束概念，缩放时整体等比变化 |
| 自动布局 | 只有框架能承载自动布局 | 不支持自动布局 |

使用建议很明确。

- 框架是 UI 设计的基础单元，凡是要求精确尺寸、响应式排布或动态承载内容的场景都应使用，从按钮到整页都适用。
- 组只适合临时操作，比如把图标的多条路径先绑在一起方便移动或缩放，处理完后最好再放到框架里继续设计。

理论到此，马上动手巩固。

## 3.建立视觉语言

框架是骨架，颜色、文字和网格则是血肉与灵魂。和谐统一的设计源于一套内在的视觉语言。在 Figma 里，我们用样式和布局网格来定义并落地它。

###### 样式
样式是对重复出现的视觉属性做标准化预设，既能保证一致性，又能大幅降低后期改动成本。分为颜色样式和文本样式。

- **颜色样式**用来统一管理色彩体系，把某个色值保存为可复用样式并赋予语义化名称，例如 color/primary/blue。品牌主色后续调整时，修改这一个样式，所有引用它的地方会即时同步。
- **文本样式**统一管理字族、字重、字号、行高等排版规则，注意它不包含颜色属性，这样文字样式和颜色样式可以自由组合。常见命名如 typography/h1、typography/body，搭配不同颜色即可满足多样需求又保持规范。

###### 布局网格
布局网格是秩序的隐形脚手架，帮助元素对齐、间距统一，让页面更专业。Figma 提供三种网格。

- **均匀网格**：等大的正方形网格，适合图标设计或强制执行基础间距单位，如 8pt 网格系统。
- **列网格**：网页和 App 设计常用，可设定列数、列间距、内容距边缘的内边距。
- **行网格**：水平参考线，通常与列网格配合形成更精细的模块化布局。

创建样式和网格本质上是把设计决策具象化。把一个十六进制色值保存为 color/brand/primary，就是在宣告“这是主品牌色”，这正是设计令牌思想的雏形——把数值抽象为语义，为设计系统规模化打基础。

#### 2.3.2 构建可扩展的动态界面
掌握基础后进入 Figma 最激动人心的部分：让设计“活”起来，从静态像素变为能随内容自适应变化的智能组件。以下内容偏进阶，可按需学习。

## 1.自动布局的威力
自动布局堪称 Figma 的核心功能，能让布局像真实网页或应用一样随内容增减、文字长度自动适配。

启用很简单，选中一个或多个元素后按 Shift + A，Figma 会用一个开启自动布局的框架把它们包裹。

启用后在右侧 Design 标签的 Auto layout 区域可以掌控智能容器的行为。

- **排列方向（Flow）**：决定内部元素垂直堆叠、水平排列，或在空间不足时自动换行 Wrap。
- **间距（Gap）**：定义元素之间的距离，可设固定值或 Auto 让元素撑满可用空间。
- **内边距（Padding）**：容器内部边缘与内容之间的空白。

###### 三种核心尺寸调整行为
理解自动布局的关键在于这三种尺寸行为。

- **适应内容（Hug contents）**：容器尺寸由内部内容决定，会紧贴内容加上内边距，适合按钮、标签等需随文字长度自适应的元素。
- **填充容器（Fill container）**：元素主动伸展填满父容器所有可用空间，是响应式布局的关键，常用于输入框、卡片内文本区。
- **固定宽度/高度（Fixed width/height）**：尺寸固定，不受内容和容器变化影响，适合图标、头像等必须定尺寸的元素。

真正威力来自嵌套。层层嵌套并组合三种行为，就能构建任意复杂的完全响应式界面。

## 3.组件、变体与属性（可选学习）
重复设计元素时，组件是最佳拍档。组件化体系由三个层面构成。

- **组件（Component）**：把任意设计元素转为主组件，随后可在设计稿中放置实例，修改主组件时所有实例同步更新。
- **变体（Variant）**：当组件有多状态或样式，如按钮的默认、悬停、禁用，无需建多个独立组件，可用组件集统一管理变体。
- **组件属性（Component Property）**：添加到主组件的“控制器”，让使用者在实例层面自定义。主要有三种类型。

  - **布尔（Boolean）属性**：开关，控制图层可见性，如是否显示图标。
  - **文本（Text）属性**：允许在属性面板直接修改组件内部文本。
  - **实例交换（Instance Swap）属性**：允许把组件内部嵌套的实例替换为另一个，如替换按钮图标。

初学者常问变体和属性该怎么选。简单法则是：变体处理视觉风格、交互状态的预设固定差异；属性处理内容变化或可选元素的显隐，供使用者自定义，具体如表2-3所示。
