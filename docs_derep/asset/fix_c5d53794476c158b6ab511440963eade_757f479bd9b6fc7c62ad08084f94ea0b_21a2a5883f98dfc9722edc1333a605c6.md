### 10.5 嵌入模型接入概览

Cohere Embeddings 实现与 Cohere 平台的顺滑对接，让文本向量化兼顾速度与准确性。HuggingFaceEmbeddings 与 LlamaCppEmbeddings 则提供两种额外方案，均已通过充分验证，可稳定高效地接入 Hugging Face Hub 与 Llama.cpp，让开发者在 LLM 项目中更便捷地使用前沿嵌入能力。

#### 10.5.1 HuggingFace 嵌入接入

SentenceTransformersEmbeddings 带来了一种简洁高效的文本向量化手段。其底层多为深度学习模型，擅长捕捉文本间的细腻语义关联，助力更精准的匹配与更深层的语义洞察，进而提升 LLM 应用表现。

事实上 SentenceTransformersEmbeddings 是依托 HuggingFaceEmbeddings 调用的。针对已熟悉 sentence-transformers 的用户，LangChain 额外提供了 SentenceTransformerEmbeddings 的别名，方便沿用习惯命名。

使用前请先确认开发环境。sentence-transformers 包需提前安装到位，才能保证向量化流程顺畅。若尚未安装，可按指引执行安装命令完成部署。

#### 10.5.2 LlamaCpp 嵌入接入

Llama.cpp 的核心目标是让 LLaMA 模型在 MacBook 上以 4 位量化运行。它采用纯 C/C++ 编写，无外部依赖。虽以 Apple 芯片为优先，通过 ARM NEON、Accelerate、Metal 进行优化，也为 x86 架构提供 AVX、AVX2、AVX512 支持。精度层面兼容混合 F16/F32，并支持 4/5/8 位整数量化。BLAS 部分兼容 OpenBLAS、Apple BLAS、ARM Performance Lib、ATLAS、BLIS、Intel MKL 等，以及 cuBLAS 与 CLBlast。

[PRE12]
在实际应用中，要利用 llama-cpp 进行文本嵌入，首先需要初始化模型。开发者可以通过 LlamaCppEmbeddings 类为其提供特定的模型路径（如 `/path/to/model/ggml-model-q4_0.bin`）来完成这个步骤，从而为后续操作创建一个 llama 嵌入模型实例。

[PRE13]
为了从 LLM 应用中的文本数据中生成嵌入，开发者只需将所需文本传递给已初始化的 LlamaCppEmbeddings 实例。例如，对于文本 "This is a test document."，通过调用 llama-cpp 模型的嵌入方法，开发者可以获得该文本的向量嵌入表示。

[PRE14]
对于要嵌入的一组文档，开发者可以简单地传递一个包含所有文档的列表给 llama.embed_documents 方法。例如，将文本列表 [text] 传入方法后，它将返回这些文档的向量嵌入表示，并存储在 doc_result 变量中。这使得对多个文档的批量嵌入变得简单、高效。

[PRE15]
一旦成功集成 llama-cpp 到 LangChain 中，开发者就可以充分利用其高效的文本嵌入能力，进一步为 LLM 应用带来高准确率和低延迟的体验。通过不断地测试、优化和调整，开发者可以确保 llama-cpp 嵌入在各种场景下都能稳定发挥其最大潜能。

#### 10.5.3 Cohere 嵌入接入

随着嵌入技术多样化，Cohere 已成为 LLM 场景的热门选项，以其稳定与高效获广泛认可。下面介绍在 LangChain 中接入 Cohere 嵌入的具体做法。

相较其他方案，Cohere 在部分任务上呈现更高准确率与更佳性能。其基于 BERT、GPT 等 Transformer 深度模型生成向量，不仅保留表面结构，更能捕捉深层语义，使得表述不同但含义相近的文本获得相似向量。

为简化使用，LangChain 内置了 Cohere 相关嵌入模块。只需从 langchain.embeddings 导入 CohereEmbeddings，即可在项目中快速启用 Cohere 功能。

### 10.6 Agent 工具包接入指南

Agent toolkits 集成旨在提升 LLM 应用的数据处理与分析效率。CSV Agent 专注 CSV 数据操作，PandasAgent 融合 Pandas 框架实现高效数据处理，PowerBI Agent 则与 Microsoft PowerBI 深度结合，提供直观的可视化能力。整体让数据处理、分析与可视化更简便高效。

##### 10.6.1 CSV Agent 接入

LangChain 提供了多类 CSV 交互方案，尤其适用于问答场景。以下将详细介绍 CSVAgent 的使用方式，并提示相关安全要点。

CSVAgent 主要用于 CSV 文件的查询与检索。其内部会调用 Pandas DataFrame Agent 与 Python Agent，若 LLM 生成的代码存在缺陷，执行时可能带来非预期风险，故使用时需保持谨慎。

实现 CSV Agent 需要调用若干关键 API。`create_csv_agent` 位于 `langchain.agents`，用于创建与管理代理；`OpenAI` 来自 `langchain.llms`，负责模型管理与平台交互；`ChatOpenAI` 从 `langchain.chat_models` 引入聊天模型封装；`AgentType` 则定义了可用代理类型，明确各自角色。组合使用这些接口，即可在 LLM 应用中便捷地创建 CSV Agent。

[PRE16]
在初始化方法中，`create_csv_agent` 函数被用于构建一个新的 CSV Agent。此代理的特点是使用 `ZERO_SHOT_REACT_DESCRIPTION` 类型，这意味着该代理可以在没有预先训练的情况下对数据进行描述或反应。在示例代码中，代理被配置为处理名为 `titanic.csv` 的文件，使用 OpenAI 模型并设置其温度参数为 0，以获得更具确定性的输出。同时，通过 `verbose=True` 参数，代理在运行时会显示更多的详细信息。

[PRE17]
另外还可以使用 `OPENAI_FUNCTIONS` 类型进行初始化。这是一种不同于 `ZERO_SHOT_REACT_DESCRIPTION` 的代理构建方法。在这种方法中，代理是基于特定的 OpenAI 功能进行操作的，特别是那些与 ChatOpenAI 模型相关的功能。例如，在给出的代码中，使用了模型 gpt-3.5-turbo-0613 来创建一个代理，该模型的温度参数被设置为 0 以获得确定性输出。这个代理专门为处理名为 `titanic.csv` 的文件而设，并通过 `verbose=True` 参数提供额外的运行时的详细信息。

`OPENAI_FUNCTIONS` 类型是一个代理初始化选项，专门为高级的 OpenAI 模型设计。这些模型如 gpt-3.5-turbo-0613，是在 2023 年 6 月 13 日之后发布的。之前发布的型号并不能使用 `OPENAI_FUNCTIONS` 类型进行初始化。
