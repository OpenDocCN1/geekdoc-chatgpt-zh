### 10.5 嵌入模型接入手册

Cohere Embeddings 实现了与 Cohere 平台的无缝衔接，保证文本向量化既快又准。HuggingFaceEmbeddings 与 LlamaCppEmbeddings 则提供了另外两种嵌入方案。两者的集成都经过充分验证，能稳定高效地与 Hugging Face Hub 与 Llama.cpp 平台协作，让开发者更容易在 LLM 项目里使用这些先进的嵌入技术。

#### 10.5.1 HuggingFace 嵌入接入

SentenceTransformersEmbeddings 为开发者送来了一种简洁高效的文本向量化方式。这类嵌入通常基于深度学习模型，擅长捕捉文本间细腻的语义关联。借助它，开发者可以实现更精准的文本匹配与更深层的內容洞察，从而优化 LLM 应用的表现。

实际上 SentenceTransformersEmbeddings 是经由 HuggingFaceEmbeddings 包装调用的。对已熟悉 sentence-transformers 包的开发者而言，LangChain 提供了 SentenceTransformerEmbeddings 的别名，方便在代码中沿用习惯命名。

开始前请先做好环境准备。确保 sentence-transformers 包已正确安装，以保证向量化流程顺畅。如未安装，可按提示执行安装指令完成配置。

#### 10.5.2 LlamaCpp 嵌入接入

Llama.cpp 的核心目标是让 LLaMA 模型能够在 MacBook 上以 4 位量化运行。它是纯 C/C++ 实现，不依赖外部库。虽然优先针对 Apple 芯片做了 ARM NEON、Accelerate 与 Metal 优化，但也为 x86 架构提供 AVX、AVX2 与 AVX512 支持。精度方面支持混合 F16/F32，并可使用 4 位、5 位、8 位整数量化。在 BLAS 操作上兼容 OpenBLAS、Apple BLAS、ARM Performance Lib、ATLAS、BLIS、Intel MKL、NVHPC、ACML、SCSL、SGIMATH 等，也支持 cuBLAS 与 CLBlast。

[PRE12]

实际使用 llama-cpp 做文本嵌入时，首先要完成模型初始化。开发者可通过 LlamaCppEmbeddings 类传入具体模型路径，例如 `/path/to/model/ggml-model-q4_0.bin`，从而得到一个可用的 llama 嵌入实例。

[PRE13]

要为 LLM 应用中的文本生成嵌入，只需把目标文本交给已初始化的 LlamaCppEmbeddings 实例。以 “This is a test document.” 为例，调用其嵌入方法即可获得向量表示。

[PRE14]

若需批量处理文档，可把文档列表整体传给 llama.embed_documents 方法。例如把文本列表 [text] 传入后，方法会返回对应的向量集合并存入 doc_result 变量，让批量嵌入变得简单高效。

[PRE15]

完成 llama-cpp 与 LangChain 的集成后，开发者即可利用其高效的嵌入能力，为 LLM 应用带来高准确率和低延迟体验。持续测试与调优能确保 llama-cpp 嵌入在不同场景下稳定发挥最佳效果。

#### 10.5.3 Cohere 嵌入接入

随着文本嵌入技术多样化，Cohere 成为 LLM 应用中的又一热门选择，因其稳定与高效广受青睐。下面介绍在 LangChain 中集成并使用 Cohere 嵌入的做法。

相较其他方案，Cohere 在特定任务上往往能提供更高的准确率与更优的性能。它基于 BERT 与 GPT 等 Transformer 架构的深度模型为文本生成向量，这些向量不仅记录表面结构，还能深入反映语义含义，即使表述不同但意思相近的文本也会得到相似的向量。

为简化工作流，LangChain 内置了 Cohere 相关的嵌入模块。开发者只需从 langchain.embeddings 模块导入 CohereEmbeddings 类，即可在应用中启用 Cohere 功能。

from langchain.embeddings import CohereEmbeddings

在 LangChain 中实际使用 Cohere 嵌入前，需要准备一个有效的 Cohere API 密钥以保障通信。获取密钥后，可用 CohereEmbeddings 类并通过 `cohere_api_key` 参数完成初始化，进而在应用中生成文本嵌入。

在 LLM 应用中，若想为特定文本如 “This is a test document.” 生成向量表示，可直接调用 Cohere 的嵌入方法。该方法把文本转为数值向量，捕捉语义信息，为后续分析奠定基础。

### 10.6 Agent 工具包接入指南

Agent toolkits 的集成旨在简化并增强 LLM 应用的数据处理与分析能力。CSV Agent 提供处理 CSV 数据的专用工具。PandasAgent 融入 Pandas 框架，让开发者在应用中高效操作数据。此外，PowerBI Agent 与 Microsoft PowerBI 深度结合，提供丰富直观的数据可视化能力。这些工具套件让 LLM 应用的数据处理、分析与可视化都更简便高效。

##### 10.6.1 CSV Agent 接入

LangChain 为开发者提供了多种与 CSV 文件交互的方式，尤其适用于问答任务。下面详细说明如何使用 CSVAgent，并提示相关安全注意事项。

CSVAgent 主要用于与 CSV 文件交互，特别是在查询或检索信息时。需注意 CSVAgent 内部调用了 Pandas DataFrame Agent 与 Python Agent。这意味着 LLM 生成的 Python 代码若存在问题，执行时可能带来非预期后果，使用时应保持谨慎。

CSV Agent 是 LLM 应用中处理 CSV 数据的工具，实现它需要引用一系列 API。`create_csv_agent` 是创建与管理 CSV Agent 的核心方法，位于 `langchain.agents` 模块。`OpenAI` 来自 `langchain.llms` 模块，用于模型管理或与 OpenAI 平台交互。`ChatOpenAI` 从 `langchain.chat_models` 导入聊天模型的封装。`AgentType` 则定义了 LLM 应用中可用的 Agent 类型，帮助明确各 Agent 的角色与功能。借助这些 API 的组合，可在 LLM 应用中轻松创建并使用 CSV Agent。

[PRE16]

在初始化阶段，`create_csv_agent` 函数被用来构建新的 CSV Agent。该代理默认使用 `ZERO_SHOT_REACT_DESCRIPTION` 类型，表示无需预训练即可对数据进行描述或反应。示例中代理被配置为处理 `titanic.csv` 文件，使用 OpenAI 模型并将温度设为 0 以获得更确定的输出，同时通过 `verbose=True` 参数输出更详细的运行信息。

[PRE17]

另外也可以采用 `OPENAI_FUNCTIONS` 类型进行初始化。这是与 `ZERO_SHOT_REACT_DESCRIPTION` 不同的构建方式，代理基于特定的 OpenAI 功能运行，尤其适用于 ChatOpenAI 模型。例如，使用模型 gpt-3.5-turbo-0613 创建代理，温度设为 0 以保证确定性输出，该代理专门处理 `titanic.csv` 文件，并通过 `verbose=True` 提供额外运行细节。

`OPENAI_FUNCTIONS` 类型是专为较新的 OpenAI 模型设计的初始化选项。此类模型如 gpt-3.5-turbo-0613，需在 2023 年 6 月 13 日之后发布。更早的模型不支持使用 `OPENAI_FUNCTIONS` 类型进行初始化。
