## 前言
2025年，AI Agent正式进入落地期，从验证概念迈向规模化应用，蚂蚁阿福等AI原生产品的出现，标志着智能体突破纯对话局限，成为新型生产力工具。但随之而来的门槛问题，让大量非技术用户望而却步。即便有扣子、Dify等低代码平台，打造适配垂直业务的专家级智能体仍要跨两道鸿沟。

第一道是繁复的工作流编排。节点设计、数据流转、条件判断本质仍属图形化编程，对无编程基础的人来说操作繁琐易错。第二道是技术协议的使用门槛。想要让扣子空间接入垂直领域知识，需基于模型上下文协议 Model Context Protocol，MCP 编写工具代码。

简单讲，MCP如同为AI智能体提供标准USB接口。此前AI工具接入缺乏统一规范，开发者A做的工具往往只能适配自己做的智能体。MCP实现了工具与智能体的标准互通，只要双方遵循规范即可无缝对接。遗憾的是，MCP仍需代码实现，对非程序员仍是障碍。

真正的零门槛转机出现在2025年底。Anthropic推出Skills功能，拉开AI应用零代码定制的序幕。Skills本质上是可复用的经验沉淀，一份指导智能体做对事的提示词文档，无需写一行代码，就能让通用智能体变成股票分析专家、PPT架构师或小红书爆款图文写手，把个人经验快速变为生产力。

初期Skills未开源，仅限Anthropic自家的Claude Code、Claude桌面版使用，与国内场景脱节。直到2026年1月，困局被打破：Skills开源后获得扣子官方深度集成，国内用户才迎来真正贴合本土场景的零门槛环境。

此次升级带来两大突破，也是本书诞生的契机：升级后的扣子开发平台更名为扣子编程，摆脱低代码束缚，全面拥抱AI原生自然语言编程，用户仅用日常语言对话即可完成智能体、工作流、Skills的全流程开发；升级后的扣子空间更名为扣子，新增技能商店功能，用户在与智能体对话时可直接加载官方、社区或自研的Skills，实现即调即用。

简言之，扣子编程是开发智能体与Skills的工厂，扣子本身则是开箱即用的通用智能体，可直接用自然语言解决问题。

本书的核心使命是帮助非技术读者无缝衔接这次升级，零理解成本玩转Skills。我们以扣子系列产品为核心，以通俗语言与落地项目为载体，带你把个人经验、业务逻辑转化为可自动执行的AI Skills，让通用智能体变身专属专家，技术退后，创意与经验向前。

## 1.1 智能体概述
过去两年，“AI Agent”或“智能体”是否反复刷屏？是否尝试过用扣子、Dify搭建自己的智能体应用？

随大模型能力持续跃升与智能体设计模式的成熟，智能体正经历深刻变化：它不再是程序员的专属玩具，而是逐渐演变为普通人也能轻松上手、按需定制的实用工具。正如“旧时王谢堂前燕，飞入寻常百姓家”——昔日高居技术殿堂的智能体，如今已走进大众日常工作与生活。

本节帮助读者快速建立认知，为实践创新打基础。

### 1.1.1 智能体的本质
本质上，智能体是一种让大模型更聪明、更能干的方法——通过赋予目标感、规划能力与工具调用权限，使其从被动应答转向主动执行。

一个形象的比喻来自武侠小说。主角临危受命完成复杂任务，临行前高人递给他三个锦囊，嘱咐在特定时刻开启依计行事。主角并非全知全能，却凭借预设策略与时机判断化险为夷。

在这个故事中，主角原本只是听话的执行者，如同基础大模型，一旦获得何时使用何种策略的框架，就具备了自主决策与行动能力——这正是智能体的核心。

三个锦囊相当于智能体中的Skills或工具调用能力，主角对情境的判断与锦囊调用逻辑构成智能体的推理与规划机制。高人并未全程操控，却通过结构化赋能，让主角从工具升格为代理。

因此，“把大模型变成智能体”本质就是为其配备一套可组合、可触发、可执行的Skills，让它在复杂动态的真实场景中，像武侠主角一样有策略、有步骤、有应变地完成任务。

### 1.1.2 智能体的发展路线
智能体的演进并非凭空而来，其雏形可追溯至2024年初OpenAI在ChatGPT推出的GPT Store，允许普通用户开发定制化ChatGPT。开发方式是上传自定义工具如天气查询、股票查询的使用说明，对话时ChatGPT可自主决定是否调用工具解决。

该机制极大拓展了ChatGPT边界，用户可创建体育赛事助手、投资分析机器人等垂直应用。GPT Store迅速激发社区创造力，也奠定了“大模型+工具=智能体”的基本范式。

随后扣子、Dify等国内平台跟进并优化，提供更友好可视化界面与更丰富工具集成，进一步降低构建门槛。

但人们很快发现，仅能调用工具的智能体在面对复杂逻辑问题时力不从心。例如“2024—2025赛季NBA总冠军球队主教练的父亲叫什么名字”需要依次查询冠军球队、主教练、父亲姓名等多步推理。早期工具调用型智能体常因缺乏整体规划而中途迷失。

为突破瓶颈，2024年中后期，ReAct、Plan、Reflection等从论文中发展出的增强推理设计模式开始被工程化实现。它们引导大模型显式生成中间推理步骤、制定任务计划，并在执行后自我校验修正，显著提升复杂任务准确性。

新挑战随之而来，随着任务复杂与数据增多，大模型上下文记忆成为瓶颈。记忆过载会导致中断任务。于是如何扩展记忆能力，如摘要压缩等，也成为研究核心。

至此，智能体从最初的工具调用者，逐步进化为具备计划、执行、反思与记忆能力的复杂系统，为2025年大规模产业落地奠定基础。

## 1.2 主流智能体实现形式介绍
上节介绍了智能体本质及其从工具调用到自主推理再到具备记忆能力的演进。本节进一步介绍业界主流的几种智能体形态，帮助读者见形知用、按需选择。

### 1.2.1 工具调用类智能体
目前市面上最常见、适用范围最广的智能体属基础工具调用类。核心目标是让大模型不仅能“说”，还能“做”——通过自主规划决定调用外部工具如搜索接口、数据库、计算器、API等完成具体任务，从被动问答升级为主动执行。

实现路径上主要有两种范式：Function Calling与ReAct。

Function Calling可理解为大模型出厂前练就的基本功。就像习武之人日复一日扎马步、练套路，形成肌肉记忆，遇到合适场景自然准确使出对应招式。

ReAct则是在后天通过提示词工程引导大模型具备工具调用能力，无需基本功。类似《天龙八部》逍遥派掌门无崖子将八十载内力注入虚竹，虚竹虽未苦修却瞬间拥有顶尖高手内力。

二者殊途同归，都能赋予工具调用能力，但底层逻辑与适用条件不同。

工具调用类智能体实现简单，对不太复杂的问题如“今天天气”“今晚比赛场馆附近烧烤店”效果很好，因此在扣子、Dify等产品的基础智能体模式中得到应用，其设置页面如图1-2所示。

### 1.2.2 深度思考型智能体
深度思考型智能体是当前演进的高阶形态，典型代表包括DeepResearch、Manus、扣子等。这类智能体不再满足快速响应或单步调用，而是模拟人类专家解决复杂问题的流程，堪称智能体全能选手。

与基础工具调用类不同，深度思考型智能体接收任务后不会急于执行，而是启动结构化多阶段认知引擎。其执行流程如图1-3所示。

1. 意图识别：解析用户输入，不仅理解字面，更捕捉背后真实需求。
2. 生成执行计划：基于意图制定详细分步计划。
3. 反馈人类：暂停执行，将计划呈现给用户审核，待反馈后再恢复。
4. 执行计划：用户确认后开始执行，灵活组合搜索引擎获取实时信息、调用工具获取垂直信息、必要时自动生成并运行代码如数据清洗、回测策略等。
5. 反思与重新规划：执行完成后进行反思，检查逻辑是否闭环、数据是否矛盾、结论是否充分。若发现漏洞会主动修正计划、补充调研甚至重执行，直至输出可信。
6. 记忆：为应对上下文长度限制，这类智能体通常配备外部记忆机制，将关键中间结果、最终报告、执行摘要持久化存储，避免重复劳动，也为未来相似任务提供参考，相当于为用户构建可积累可复用的个人知识库。

可以说，深度思考型智能体是对2023年以来智能体技术的综合应用。

对于需要处理研究分析、商业决策、技术开发等高复杂度任务的用户而言，深度思考型智能体已不再是简单助手，而是一位具备专业素养、严谨方法论与持续学习能力的研究员。
