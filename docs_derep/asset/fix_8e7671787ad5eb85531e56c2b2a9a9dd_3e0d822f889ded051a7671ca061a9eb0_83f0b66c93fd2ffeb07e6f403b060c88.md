从实验室原型迈向企业级应用，Agent 协作系统的设计方法论正在发生深刻变化。当多个 Agent 需要在真实业务场景中协同运行时，系统架构师必须以业务需求为出发点，精确界定每个 Agent 的定位边界，选择合适的协作模式，并构建可扩展的模块化架构，才能打造稳定、高效、可维护的生产级系统。

## 5.1 Agent协同系统的架构设计

### 【学习目标】

1. 掌握从业务流程到 Agent 角色的映射方法
2. 理解四种典型 Agent 协作模式的适用场景
3. 学会定义 Agent 的能力边界与职责范围
4. 掌握模块化 Agent 系统的架构设计原则

架构设计是 Agent 协作系统能否成功落地的关键。本节从业务需求分析入手，阐述定位映射、协作模式选择、能力边界定义与模块化设计的完整方法论。

### 5.1.1 从业务需求到Agent角色的映射方法

构建生产级 Agent 协作系统的首要工作是将业务需求准确转化为 Agent 定位定义。这一过程要求架构师深入理解业务流程，识别关键决策节点，并映射为职责明确的 Agent 定位。与传统软件职责划分不同，基于 LLM 的定位映射还需要考量模型的推理能力、上下文理解能力以及自然语言交互特性。

业务需求到 Agent 定位的映射可分为四个核心步骤。第一步梳理业务流程，绘制完整流程图并标注参与者、决策节点和信息流转路径。第二步识别决策节点，从流程中找出需要智能判断、信息整合或专业知识支撑的关键节点。第三步进行能力抽象，将决策节点所需能力抽象为 Agent 的核心职能，包括信息搜集、分析推理、决策建议和执行操作。第四步定义定位，为每个 Agent 赋予清晰的名称、职责范围和协作接口。

- 用户发起咨询→意图识别→业务分流→专业处理→结果反馈

【Agent 角色映射结果】

1. 意图识别 Agent：分析用户输入，输出意图类别和置信度
2. 路由分发 Agent：根据意图类别和业务规则，分配至对应处理 Agent
3. 售前咨询 Agent：回答商品信息、促销活动等问题
4. 订单服务 Agent：查询订单状态、修改配送信息
5. 售后处理 Agent：处理退换货、质量问题
6. 投诉升级 Agent：识别严重投诉，触发人工介入
