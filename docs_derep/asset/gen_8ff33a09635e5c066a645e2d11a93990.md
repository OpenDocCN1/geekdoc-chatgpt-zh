## **第三章 核心架构深度解析**

本章带你深入 OpenClaw 核心架构。我们从宏观系统组件入手，逐步拆解 Gateway、Node 以及 Agent Loop 这三大核心模块。

## **3.1 永不离线的中枢**

将 OpenClaw 比作生物体，Gateway 就是它的“大脑”和“中枢神经”。它是一个长期运行的后台守护进程，负责协调内部组件、管理外部连接、维护会话状态，并作为整个系统的唯一控制平面。

理解 Gateway 的设计哲学，是理解 OpenClaw 行为的起点。它不是简单 HTTP 服务器，而是有状态的事件驱动系统。

**3.1.1 单例事件总线与控制平面**

OpenClaw 架构中 Gateway 采用严格单例模式，同一主机同一时刻只能运行一个实例。这种设计出于系统一致性与资源管理的考量。

单例不仅带来技术简洁，更从根本上定义安全边界：所有权限决策都在可信受控进程中做出。若允许多实例并行，状态同步与权限策略一致性将难以保证。单例把复杂性扼杀在萌芽。

1．统一事件总线

网关内部实现高性能事件总线。用户聊天消息、定时任务 Cron 触发、外部 Webhook 调用、内部状态变更等活动都被抽象为事件，在总线上广播与路由。

消息路由是核心功能之一。当你在飞书或企业微信发送消息时，Gateway 接收该消息事件，按配置的绑定信息准确分发给对应 Agent 与 Session。过程完全透明：无论来源渠道如何，消息统一转成内部事件格式，再由 Agent Loop 处理。

状态同步是另一关键职责。Gateway 负责维护所有连接客户端如 macOS 菜单栏应用、CLI 工具、Web 控制台的状态同步。当 Agent 状态变化，例如从“空闲”到“思考中”或“执行工具中”，Gateway 会通过事件总线实时推送到订阅客户端，实现打字机效果与实时进度展示。

2．唯一的控制平面

作为控制平面，Gateway 拥有系统资源的绝对控制权，核心职责如下。

• 生命周期管理：负责启动、停止与监控 Agent 进程，拥有绝对决策权，决定何时为特定会话启动 Agent Loop，以及因超时或不可恢复错误而强制终止它。
• 配置管理：负责加载与热更新系统配置如 openclaw.json，统一管理多智能体工作空间 workspace 与状态目录 agentDir。修改配置后只需 openclaw gateway restart 即可重载，无需重启整个系统。
• 连接管理：是系统中唯一直接与外部消息平台建立底层连接的组件。集中式连接管理避免多进程同时连接同一账号导致冲突与封禁，渠道连接统一维护，并在网络波动时自动重连。
• 工具安全校验：Gateway 是工具策略执行的最终关卡，无论 Agent 请求调用何种工具，都必须经过 Gateway 权限校验层，确保底层安全。

以上四大职责均基于 Gateway 的集中式控制设计，也贯穿其与内外组件的交互。作为控制平面能力的延伸，Gateway 对系统内外组件的统一调度与权限校验进一步保障交互安全与一致性——所有客户端、智能体、外部消息平台的交互都需经过 Gateway 统一调度与校验，具体连接架构如图 3-1 所示。

**3.1.2 网络模型**

OpenClaw 网络设计秉持环回优先 Loopback-First 理念。除非明确配置，否则 Gateway 拒绝外部网络直接连接。所有控制命令、状态查询与数据传输都在本地完成，从外部网络视角看 Gateway 是“隐形”的。默认 WebSocket 服务器仅绑定 127.0.0.1:18789。

1．设计理念

• 极致安全性：AI 智能体通常拥有高权限如读取本地文件、执行 Shell 命令、发送消息。若 Gateway 默认暴露公网，一旦漏洞或配置不当将造成灾难。环回优先从物理网络层面切断外部攻击可能，确保默认安全。官方文档明确：“永远不要在 0.0.0.0 上无认证地暴露 Gateway。”
• 隐私保护：聊天记录、个人数据与凭证本地存储，限制网络访问可最大程度防止数据泄露。
• 简化信任模型：本地环回中，Gateway 可合理假设连接请求来自受信任本地 CLI 或 UI，从而简化身份验证，提升交互流畅度。

2．网关绑定模式

• 环回模式 loopback 默认：仅监听 127.0.0.1，专为纯本地使用设计，提供最高安全，彻底隔绝外部探测。
• 局域网模式 lan：适用于家庭或办公内网共享，绑定 0.0.0.0，允许同一局域网设备连接。
• Tailscale 网络模式：OpenClaw 推荐的跨设备方案。Gateway 绑定到 Tailscale 分配的内部 IP，用户可在全球安全访问 AI 助手，无需端口暴露公网，兼顾便利与安全。
• 自定义模式 custom：针对特殊网络拓扑的高级部署，允许手动指定监听的特定 IP。

3．安全的远程访问实现

为实现远程访问，OpenClaw 强烈推荐零信任网络方案，特别是 Tailscale 或其他 VPN 技术。

通过 Tailscale，可将手机、笔记本与运行 Gateway 的机器组成安全私有虚拟局域网 Tailnet。Gateway 仍只监听本地或 Tailnet 地址，但你可通过 Tailscale 内部 IP 安全连接，体验与本地一致。

Tailscale 集成还带来额外好处：Tailscale Serve 可在 Tailnet 内部为 Gateway 提供 HTTPS 加密，并通过 Tailscale 身份验证机制将请求者身份信息如 Tailscale-User-Login 头传递给 Gateway，实现基于身份的访问控制。配置示例如下：

//在 openclaw.json 中配置 Tailscale 绑定
{
"gateway": {
"bind": "tailnet",
"port": 18789,
"auth": {
"mode": "token",
"token": "your-long-random-secret-token"
}
}
}

4．必须配置的认证模式

一旦 Gateway 绑定到非环回地址，必须同时配置认证。OpenClaw 支持三种模式。

• 令牌认证 token：基于共享密钥，是最常用且推荐的方式。客户端在 WebSocket 握手时必须提供正确令牌，否则连接被立即拒绝。
• 密码认证 password：适用于需要人工输入凭证的特定客户端场景。
• 无认证 none：极度危险，仅建议在完全隔离的本地测试环境使用。

OpenClaw 安全审计工具 openclaw security audit 会主动检测并警告任何“非环回绑定但无认证”的配置，标记为严重 critical 级别问题。

**3.1.3 客户端与节点的通信协议**

Gateway 与所有客户端 Client 和节点 Node 之间的通信完全依赖 WebSocket 协议。全双工、低延迟，适合 AI Agent 实时流式输出与频繁状态更新的场景。

1．协议基础

传输层面，OpenClaw WebSocket 通信采用文本帧 Text Frame 格式，所有负载均以 JSON 编码。默认 Gateway 在 18789 端口监听连接，管理员可通过修改 gateway.port 配置项或设置 OPENCLAW_GATEWAY_PORT 环境变量来自定义端口。

连接握手阶段，客户端建立 WebSocket 连接后发送的第一个数据帧必须是 connect 请求。若 Gateway 配置了访问令牌 OPENCLAW_GATEWAY_TOKEN，客户端必须在握手帧中携带该令牌，否则 Gateway 将立即强制关闭连接，拒绝所有未授权访问。

2．消息类型体系

OpenClaw WebSocket 协议定义了 3 种基本消息类型，构成了客户端与 Gateway 之间完整的通信语义。
