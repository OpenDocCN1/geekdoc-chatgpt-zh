## 7.4 小程序数据存储全景
存储能力直接影响使用体验。以需会员登录的应用为例，首次登录后把凭证暂存，下次打开即可免登。整体上可分为缓存存储和持久化存储两类。

缓存存储偏向小容量、短周期的场景，比如会员凭证；持久化存储偏向大容量、长周期的场景，比如聊天记录。下面分别展开。

### 7.4.1 缓存读写实践
小程序提供一套对缓存库进行写入、读取、删除的操作，上手门槛很低。具体接口见表 7-11。

表 7-11 数据缓存相关方法

| 方法名 | 意义 | 参数 |
|---|---|---|
| wx.setStorage | 往缓存库写入数据 | { key:数据对应的键 data:要存入的数据 success:存入成功的回调 fail:存入失败的回调 complete:存储完成的回调 } |
| setStorageSync | 同步写入缓存库 | key:数据对应的键 data:要存储的数据 |
| getStorage | 从缓存库读取数据 | { key:要获取的数据对应的键 success:获取成功后的回调，数据会包装在回调函数参数的 data 属性中 fail:获取数据失败的回调 complete:获取数据完成的回调 } |
| getStorageSync | 同步读取缓存库 | key:要获取的数据的键 |

缓存内容在用户主动清理或超时后会被释放，平时保持可用。单条上限 1MB，总上限 10MB。

### 7.4.2 文件接口实现持久化
小程序文件系统划分为代码包文件、本地临时文件、本地缓存文件、本地用户文件四类。

代码包文件是开发时打包进来的代码与资源，只读不可改。本地临时文件由下载等接口产生，生命周期很短，程序退出即清除。本地缓存文件由缓存接口产生，只能通过缓存接口操作。本地用户文件是使用过程中产生的可长期保存的数据，有专属目录，开发者可自由读写。

通过 wx.env.USER_DATA_PATH 可获取用户文件的根目录，可在此下创建子目录存放文件。
