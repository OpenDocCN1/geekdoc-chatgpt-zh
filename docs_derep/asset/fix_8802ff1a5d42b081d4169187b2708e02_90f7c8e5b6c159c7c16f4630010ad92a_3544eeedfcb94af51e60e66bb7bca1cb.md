LLVM 编译管线全景：源码怎样变成机器指令

拿到 LLVM IR 之后，并不代表编译器全流程都只用一种中间表示。不同阶段会采用不同的内部结构，只是始终围绕一个相对标准化的 IR 运转。下面聚焦前端与优化阶段，说明它们如何对源文本和 IR 进行解析、改写，为最终产出目标指令做准备。

### 8.7.1 前端实现 Clang

前端的核心工作是把高级语言文本，比如 C、C++、Objective-C 等，转成编译器内部的中间表示 LLVM IR。这一阶段处于目标码产生之前，与具体硬件无关，最后一步就是生成 IR。

Clang 作为 LLVM 的入口工具，负责把 C、C++、Objective-C 源文件译成 LLVM 中间表示。

在 Clang 内部，源文件依次经历词法、语法、语义三步处理，逐步提炼为可供后续优化和后端使用的中间形式。

- 词法工序把源文件拆成标记流，如关键字、标识符、操作符、常量等，构成语言的基本单元。
- 语法工序依据语言规则，把标记流组织成符合语法结构的树形表示。
- 语义工序核查树中各部分的关联与含义是否成立，例如类型是否匹配、变量作用域是否合规，以保障程序的正确性和可靠性。

每个语言前端都会配备自己的词法、语法、语义工序，把程序员书写的源码转成统一的 AST，为后续处理提供一致的数据结构。AST 是一种便于分析、优化与转换的中间表示。

#### 3. 语义分析

语法分析关注结构是否合法，语义分析则确保含义与逻辑正确。该阶段会检查变量类型是否匹配、函数调用是否合规、表达式是否合理，以避免运行期逻辑错误。

语义分析借助符号表检验是否符合语言类型系统。符号表保存标识符到类型的映射及相关信息。一种直观的类型检查做法是在解析后遍历 AST，并从符号表中获取类型信息。

## 8.7.2 优化阶段

LLVM IR 处于前端与后端之间，让 LLVM 能够解析多种源语言并为多种目标生成代码。前端产生 IR，后端消费 IR。大量与目标无关的优化也在 IR 阶段完成。

优化阶段进入时通常是 AST 语法树，输出时已变为 DAG 图。每一种优化方式称为 Pass，Pass 即对程序做一次遍历。

### 1. Pass 基础概念

优化一般由分析 Pass 与转换 Pass 构成。

- **分析 Pass**：用于探测程序的特定属性或行为，不修改程序。通常用于收集信息或做静态分析，供其他 Pass 使用。分析 Pass 原则上只读，不改动代码。
- **转换 Pass**：用于修改代码以实现优化或重构，会改变结构或行为以提升性能或满足需求。转换 Pass 会应用各种优化技术重写代码部分或整体，得到更高效的实现。

分析 Pass 负责信息收集与行为理解，转换 Pass 负责据此修改程序以达成优化。在 LLVM 中两者常配合使用，实现全面优化。

#### 2）隐式依赖

转换或分析 Pass 要求 IR 使用特定表达式。需手动按正确顺序把 Pass 加入队列，可通过命令行工具 clang 或 opt，或由 Pass 管理器完成。

### 3. Pass API

Pass 类是实现优化的主要资源。但我们并不直接使用它，而是通过其明确的子类实现特定优化。实现 Pass 时应选择合适的 Pass 粒度，并据此选择合适的子类，例如基于函数、模块、循环、强连通分量等。

## 小结与思考

- LLVM 前端使用 Clang，负责把源码转换为 LLVM IR；
- LLVM 优化层负责对 IR 进行优化，以提升性能；
- 前端与优化层是编译器的核心，与后端一起构成 LLVM 编译器的完整生命周期。

## 8.8 LLVM 后端产出

8.7 节介绍了前端与优化阶段。前端对高级语言做词法分析，把高级语言特性转成 token，再交语法分析判别物理布局，最后由语义分析检查逻辑。优化阶段则进行常量折叠、死代码消除、循环展开、内存分配优化等。

本节介绍 LLVM 后端的产出过程。LLVM 后端将优化后的代码生成目标代码，可为汇编语言或机器码。

### 8.8.1 代码产出

LLVM 后端与特定硬件平台紧密相关，负责把经过优化的 LLVM IR 转换为目标代码，这一过程即代码生成。不同平台的后端实现针对该平台的指令集，例如 ARM 后端实现 ARM 架构汇编指令集，x86 后端实现 x86 架构指令集，PowerPC 后端实现 PowerPC 架构指令集。

产出阶段，LLVM 后端依据目标硬件特性与要求，将 LLVM IR 转换为适配该平台的机器码或汇编语言。该过程涉及指令选择、寄存器分配、指令调度等关键步骤，以确保生成的目标代码在目标平台高效运行。

LLVM 的代码产出能力使开发者借助统一的前端如 Clang，为不同硬件平台生成优化代码，从而更易实现跨平台开发与优化。同时，后端的可扩展性使其能够应对新硬件架构与指令集的发展，为编译器技术和工具链进步提供强劲支持。

### 8.8.2 LLVM 后端——Pass

整个后端流水线涉及四种不同层次的指令表示：

- 内存中的 LLVM IR：LLVM 中间表示，提供高级抽象，用于描述程序指令与数据流。
- SelectionDAG 节点：在编译优化阶段生成的一种抽象数据结构，用以表达程序计算过程，辅助高效的指令选择与调度。
- MachineInstr：机器相关指令格式，用于描述特定目标架构下的指令集与操作码。
- MCInst：机器指令，是具体的目标代码表示，包含特定架构下的二进制编码指令。
