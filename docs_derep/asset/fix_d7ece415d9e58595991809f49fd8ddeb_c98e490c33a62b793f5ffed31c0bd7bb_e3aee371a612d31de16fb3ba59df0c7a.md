向量化工作的开端是对原始文本进行拆分，把整段材料切成词、短语或句子等更小的语义单元。之后借助特定的映射算法，把每个单元转换成稠密的数值向量。这些向量既承载了词汇本身的语义，也尽力保留了上下文的关联，对把握语言的深层含义起到关键作用。

当文本被转成向量后，就能直接进入各类计算流程，比如相似度度量、聚类分析、文本分类和情感判断。向量化显著提升了处理效率，也让机器能够承担更复杂的语言任务，从而推动自然语言处理出现一系列突破。它本质上是把人类语言送入机器智能的关键转换层，为高级语言处理提供基础。

检索效果在很大程度上受向量化质量影响。目前业界常用的 embedding 模型汇总在表 6-1。若遇到罕见专有名词、生僻字等特殊情况，或希望进一步优化，就能选用开源 embedding 模型进行微调，或在自己的数据上训练专属模型。

### 6.2.4 数据检索
在 RAG 系统的检索阶段，会利用前面得到的文本向量，在大规模知识库中执行精准的信息查找。具体做法是比较查询向量与库中向量的相似度，例如余弦相似度或欧氏距离，从而筛选出与用户问题最贴合的文档或片段。该步骤决定了能否从库中抽取出相关性高、信息价值大的内容，为后续生成准确丰富的答案奠定基础。通过这种方式，RAG 不仅能返回与查询紧密相关的内容，还能在生成时兼顾更广的上下文与背景，提升输出质量。常用的检索手段包括相似性检索、全文检索等，实际中常会组合使用以提高召回。

- 相似性检索：先把查询转成向量，再与所有存储向量计算相似得分，按分数高低返回记录。常见度量有余弦相似性、欧氏距离、曼哈顿距离等。
- 全文检索：经典方式，写入时为关键词构建倒排索引，查询时依据关键词匹配定位相应记录。

### 6.2.5 注入提示
检索得到的信息会被整合成一个全新的文本提示，而这个提示正是引导 RAG 生成答案的核心输入，直接影响系统如何调动检索到的知识。通过精心设计的 prompt，系统既能保证输出与用户查询保持高度相关，又能融入丰富的背景知识与深层理解，得到更全面、更精准的回答。

prompt 设计更偏向方法论而非硬性语法，依赖经验积累。常规的 prompt 会包含任务说明、检索获得的背景知识、以及任务指令即用户提出的问题等要素，根据场景和大模型能力，还可加入其他优化指令。下面给出一个基础问答场景的示例。

整体而言，RAG 的设计旨在增强传统语言模型的表现，通过把外部检索信息与高级语言生成能力结合，提供更丰富、更精确的用户体验。未来随着技术演进，这一范式有望在智能搜索、个性化教育、自动化内容创作等众多领域发挥更大价值。

## 6.3 RAG 与微调和提示词工程的比较
在 LLM 的优化手段里，RAG 经常与微调和提示词工程并列比较，三者各有侧重。提示词工程对模型本身和外部知识的改动最小，核心是充分发挥 LLM 自身能力；微调则需要重新训练模型以更新知识，能够深度定制行为与风格，但对数据准备和算力消耗较大；RAG 的知识获取更灵活，可实时从外部数据源检索，特别适合需要精确信息检索的任务。RAG 起步阶段对模型改造需求较低，随着研究深入，模块化 RAG 越来越多地与微调结合，在更多场景下获得更好效果。图 6-4 对比了 RAG 与微调、提示词工程在上下文优化和行为优化方面的能力差异。
