## MCP 资源与工具交互要点

想探知服务端当前暴露了哪些资源，调用方通常会先发一次 resources/list 请求拿到资源清单。接口本身支持分页，当资源量很大时可以带上可选的游标 cursor 逐页拉取。

返回的每条条目至少包含唯一定位符 uri 和基础名称 name，另外还会按需带上展示用的标题 title、简要说明 description、MIME 类型 mimeType 以及以字节为单位的大小 size。

##### 2. 资源读取（resources/read）

需要获取具体内容时，调用方向 resources/read 传入目标 URI，服务端会以列表形式回传对应内容。

[PRE1]

[PRE2]

内容形态分为文本和二进制。文本放进 text 字段，二进制则先做 Base64 编码后放在 blob 字段。注意一次 read 请求也可能返回多条结果，比如读取目录时会把目录内的文件一并返回。

##### 3. 资源更新通知（notifications/resource/updated）

MCP 为资源变化提供了两种实时感知方式。

（1）列表变更通知：当可用资源集合发生变化，且服务端声明了 listChanged 能力时，会主动推送变更提醒。

[PRE3]

（2）资源订阅（resources/subscribe）机制：调用方可以为单个资源建立变更订阅。

[PRE4]

[PRE5]

被订阅的资源发生更新后，客户端会先收到提示，再通过 resources/read 拉取最新版本。取消监听可使用 resources/unsubscribe。

异常反馈遵循标准 JSON-RPC 规范，常见错误包括资源未找到 -32002 与内部错误 -32603。

[PRE7]

在实现 MCP Server 的资源接口时，安全需作为核心考量。服务端往往要把本地文件、数据库乃至外部 API 的数据暴露给模型，任何设计或编码上的疏漏都可能引入严重风险。因此应采用纵深防御思路来保护资源。

首层防线是 URI 的严格校验。所有进来的 URI 都应视为不可信输入，除了格式检查，还要确认其指向的范围在授权白名单内，以阻断路径遍历等攻击，例如阻止通过 ../../etc/passwd 之类的构造访问敏感文件。URI 校验是保护资源的第一道屏障。

确认 URI 合法后，第二层是细粒度的访问控制。不同资源敏感度不同，涉及隐私、配置或商业机密的内容必须受限。权限判断不仅看能否访问，还要结合操作类型如读取、写入或执行，并在真正执行操作前的瞬间完成，以保证授权的即时有效性，体现最小权限原则，让每个调用方只能触及完成任务所必需的最小集合。

第三层关注数据的完整性与保真度。二进制资源如图片、音频或可执行文件在传输前必须做正确编码，MCP 常用的 JSON-RPC 是文本协议，直接透传原始字节易导致解析错误或损坏。经过例如 Base64 的编码后，客户端才能收到与源一致的内容，确保端到端完整。综合严格的 URI 校验、最小权限的访问控制与二进制编码，才能构建既强大又可靠的 MCP Server。

#### 2.3.2 工具集成

MCP 允许服务端向大模型暴露可调用的能力，模型借此查询数据库、调用 API、执行计算、获取实时信息或完成自动化任务。每项能力以唯一名称区分，并附带描述使用方式的元数据。

在 MCP 中，工具可以依据功能和特性分为6类，如表2-4所示。

表2-4 MCP工具的类型

| 工具类型 | 描述 | 示例 |

| :--- | :--- | :--- |

| 计算工具 | 执行计算和数据处理 | 计算器、单位转换、统计分析 |

| 数据检索工具 | 从外部源获取数据 | 天气查询、股票价格、新闻搜索 |

| 内容生成工具 | 创建或修改内容 | 图像生成、代码格式化、文档转换 |

| 通信工具 | 与外部系统或人员通信 | 电子邮件发送、消息通知、API调用 |

| 自动化工具 | 执行系统操作或工作流 | 文件操作、任务调度、工作流触发 |

| 分析工具 | 分析和解释数据 | 情感分析、文本摘要、数据可视化 |

调用结果可包含结构化与非结构化信息。结构化结果放在 structuredContent 字段作为 JSON 对象，为兼容旧版本，建议同时返回等价的非结构化描述，例如文本块中的序列化 JSON。非结构化内容置于 content 字段，可能的类型包括：

- 文本内容：{"type": "text", "text": "工具结果文本"}。

- 图像内容：{"type": "image", "data": "base64编码数据", "mimeType": "image/png"}。

- 音频内容：{"type": "audio", "data": "base64编码音频数据", "mimeType": "audio/wav"}。

- 资源链接：{"type": "resource_link", "uri": "file:///project/src/main.rs", ...}。

- 嵌入资源：{"type": "resource", "resource": {"uri": "...", "text": "..."}}。

若工具声明了 outputSchema，服务端必须返回符合该模式的结构化结果，客户端据此校验。
