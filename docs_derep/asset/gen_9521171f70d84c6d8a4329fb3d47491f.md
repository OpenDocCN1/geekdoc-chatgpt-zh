参数高效微调对显存的友好度很高，通常在入门级消费卡上就能跑起来，比如 RTX3090。实测来看，Llama-2-7b 以及 Llama-2-7b-chat 的半精度版本，即便在只有 16GB 显存的 P100、T4 这类卡上，也能顺利完成训练。其核心思路是把底座模型整体冻结，只在外部挂接少量可学习的小组件，真正参与更新的参数非常有限。业界常用的实现方式有 LoRA、LLaMA Adapter 和 Prefix-Tuning。LoRA 在 1.4.4 节已有介绍，本质是通过低秩矩阵分解来近似权重改动，把需要训练的参数量大幅压缩，从而提升效率。LLaMA Adapter 是面向 LLaMA 模型的设计思路，在不同层之间插入轻量适配模块，通过调优这些模块实现任务迁移，而原始权重不被改动。Prefix-Tuning 则是在输入序列前面加一串可训练的前缀向量，利用前缀对后续生成的影响来适应新任务，模型本体参数保持不变。

这一类方法的优势主要体现在三方面。

❍ 微调开销小：只训练额外的一小撮参数，而非整网，这让消费级显卡也能负担参数调整。

❍ 部署开销小：增量的参数体量在 MB 级，而非 GB 级。加载时只需先载入 LLaMA2 预训练主干，再叠加几个 MB 的微调参数，就能实现以主干为基础、用微调参数适配不同任务的联合推理。

❍ 缓解灾难性遗忘：底座参数被锁定，大模型原本积累的知识不会因微调而被覆盖。

**2.全/部分参数微调**

全量或部分微调针对的是模型本身的权重参数。可以只冻结预训练体、仅训练任务头如分类器；也可以冻结主干、在顶部加若干全连接层；最彻底的是对全部图层进行训练。

如果显存受限，单卡往往装不下模型参数、梯度和优化器状态的完整占用，具体大小取决于参数规模和精度。此时可引入完全分片数据并行 Fully Sharded Data Parallel，FSDP，让模型分布到“一机多卡”“多机多卡”环境下训练。FSDP 不仅对数据分片，还对参数、梯度和优化器状态进行分片，每个 GPU 只保留模型的一个切片，从而大幅节省显存，使更大模型能够在多卡上运行。

## **第七章**

## **大语言模型量化**

大语言模型本质上是将语言问题转为数学计算的人工智能技术。由于大量浮点运算，即使是 6B 或 7B 这类较小规模模型，也至少需要 16GB 显存的推理卡。若算力不足仍想实践应用，模型量化是一种可行路径。

本章介绍在笔记本等低算力条件下部署大语言模型的方法，即在 Windows 系统上使用 llama.cpp、gemma.cpp 等量化方案实现 AI 问答，让完整模型在低算力环境下运行。

### **7.1 量化介绍**

大语言模型通常包含数十亿甚至数百亿参数，运行会占用大量显存和计算资源。模型量化是指把权重或激活值从 32 位浮点高精度转为 4bit 或 8bit 低精度整数，模型变小、计算复杂度下降，可在 CPU 等低算力设备上推理。实践中除降低精度外，还需用 C++重写原先的 Python 程序，以保持能力同时提升性能。量化一般只用于推理，不用于训练。

### **7.2 llama.cpp 量化过程**

llama.cpp 是基于 LLaMA 架构的大模型量化方案，由开源开发者 Georgi Gerganov 用纯 C/C++开发，目标是让大模型能在 GPU 之外的硬件上运行，甚至在 Android 手机上。

llama.cpp 基于机器学习张量库 GGML 构建。GGML 同是由 Georgi Gerganov 用 C/C++实现，经处理的大模型可在 CPU 上高效运行。

对 Hugging Face 格式模型量化，需先把权重转为 GGUF 格式。GGUF 全称 GPT-Generated Unified Format，是 Georgi Gerganov 定义的模型文件规范，采用紧凑二进制编码和内存映射等技术，使模型存储和加载更高效。转换后的 GGUF 文件可更快载入内存并减少资源消耗。

本节以 Qwen-1.8B 为例，用 llama.cpp 进行量化，使其脱离 GPU 环境在 Windows CPU 上运行。
