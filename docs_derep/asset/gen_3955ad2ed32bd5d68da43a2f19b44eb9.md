（6）`researcher_node.py` 里实现的 `researcher_node` 函数是研究任务的执行入口。它会调用 `research_agent.invoke` 来驱动研究流程，并对返回的结果做收尾处理。必要时会对最后一条消息的内容做 JSON 格式修复，修复后将其打包成一个 `Command` 对象返回，对象内带上更新后的消息列表并明确下一步跳转到 `supervisor`，由监督节点裁定后续走向。

[PRE0]

（7）`supervisor_node.py` 中的 `supervisor_node` 函数充当监督节点的决策大脑，负责判断下一个由哪位智能体接手。函数先依据当前状态生成适配监督 Agent 的提示模板，并对对话消息进行预处理以提升判断质量。随后通过 `get_llm_by_type` 获取对应的大模型来处理这些提示，得到下一步需要跳转的 Agent 名称。若结果为 `FINISH`，说明整个工作流已完成；若不是，则把任务委派给指定的 Agent 继续推进。

[PRE1][PRE2]

（8）`types.py` 声明了 `State` 与 `Router` 两种类型，用来描述工作流状态和监督路由结果。`State` 记录了消息列表、完整计划、下一步操作、深度思考模式是否开启、规划前是否需要搜索等字段。`Router` 则定义了监督 Agent 可以选择的路由目标，涵盖 `coordinator`、`planner`、`supervisor`、`researcher`、`coder`、`browser`、`reporter` 以及结束标志 `FINISH`。

[PRE3]

### **11.6.2 浏览器 Agent 解析**
本系统在 `agents` 根目录下为不同角色分别建了独立文件，涵盖浏览器 Agent `browser_agent`、编程 Agent `coder_agent`、协调 Agent `coordinator_agent`、报告 Agent `reporter_agent` 与研究 Agent `research_agent`。它们统一通过 `invoke` 方法接收消息列表，调用各自绑定的语言模型完成处理并返回结果，共同构成网页浏览、代码执行、任务协调、报告生成、信息研究等多角色协作的多 Agent 体系。

`browser_agent.py` 定义了 `BrowserAgent` 类，专门处理网页浏览类任务。类内 `invoke` 方法接收消息列表作输入，借助 `get_llm_by_type` 获取浏览器 Agent 对应的 LLM，进而处理消息并返回结果。模块中导出 `browser_agent` 实例，可被其他组件直接引用调用。

[PRE4][PRE5]

### **11.6.3 编程 Agent 概览**
`coder_agent.py` 提供了 `CoderAgent` 类，用于承接编程相关任务。类中 `invoke` 方法接收消息列表，通过 `get_llm_by_type` 拉取编程 Agent 绑定的 LLM，对输入消息进行处理后返回处理结果。

### **11.6.4 Agent 协调器说明**
`coordinator.py` 实现了任务协调器 `TaskCoordinator`，负责在多个 Agent 与工具之间做任务编排。初始化阶段会装载规划 Agent、执行 Agent、工具 Agent 等角色，以及网页浏览器工具、代码执行工具、数据检索工具等资源。该类对外暴露 `execute_task` 方法，接收任务描述后先由规划 Agent 生成执行计划，再由执行 Agent 按计划推进。类内每个工具都配有对应方法，可完成网页浏览、代码运行或数据检索等具体操作。

## **11.7 提示模板体系**
项目在 `prompts` 目录集中存放并管理各 Agent 的提示模板。该目录下有多份 `.md` 模板文件，分别对应浏览器、编程、协调、规划、报告、研究、监督等不同功能的 Agent，定义了执行时所需的提示内容。`template.py` 提供了统一的工具类，用于加载与应用这些模板，确保 Agent 能按任务需求生成合适的提示，提升与大模型的交互效率。

### **11.7.1 模板管理机制**
`template.py` 定义了 `OpenManusPromptTemplate` 类，用来统一管理 Agent 提示模板，包含两个静态方法。

◎ `get_prompt_template`：从指定文件读取模板，并把模板中 `<<VAR>>` 形式的占位符转换为 `{VAR}` 格式。
◎ `apply_prompt_template`：把当前 Agent 的状态变量填充到模板中，生成包含系统提示与历史消息的消息列表。

该类保证 Agent 能根据任务动态生成适配的提示内容，从而更高效地与语言模型协作。

[PRE11][PRE12]

### **11.7.2 浏览器 Agent 提示模板**
`browser.md` 是 Markdown 格式的提示模板，专门为浏览器 Agent 设计。模板涵盖角色定位、核心职责、执行指引、技术规范和输出规范，为 Agent 提供完整的上下文与指令，助力其高效完成网页浏览、交互操作与数据抽取，并以清晰格式汇报执行状态与结果。

## **11.8 Web 请求响应能力**
系统基于 FastAPI 实现了 Web 请求响应，提供聊天流式接口并支持跨域与任务处理。同时提供命令行客户端，可向服务器提交任务并输出格式化结果。

### **11.8.1 FastAPI 服务端**
`server.py` 是 FastAPI 服务器实现，提供 OpenManus 的 API 接口。定义了聊天流式接口 `/api/chat/stream`，接收请求并返回流式响应。内部通过 `run_agent_workflow` 调用工作流服务处理消息并生成事件流。服务配置了日志记录与 CORS 中间件以支持跨域，并在主程序中使用 `uvicorn` 启动。

[PRE17][PRE18]

### **11.8.2 客户端脚本**
`client.py` 是命令行客户端脚本，用于向 OpenManus 服务器提交任务。脚本借助 `requests` 库向服务器 `/task` 接口发送 POST 请求并处理返回。成功时返回服务器的 JSON 响应，失败时返回错误信息。脚本使用 `argparse` 解析命令行参数，支持用户指定任务描述与服务器地址。
