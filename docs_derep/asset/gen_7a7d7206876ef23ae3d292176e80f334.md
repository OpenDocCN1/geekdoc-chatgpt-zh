#### 2. 记忆检索机制

当新消息进来时，必须从长期记忆里把相关内容找出来，才能让 AI 回复更贴合。检索过程一般包含下面几个环节。

(1) 查询生成：基于当前用户消息，构造出用于检索的查询表达。

(2) 相似度计算：衡量查询与已存记忆之间的相似程度。

(3) 排序与筛选：按相似度对记忆打分排序，挑出最相关的部分。

(4) 上下文融合：把检索到的记忆与当前对话上下文拼接起来。

落地时有多种技术可选，以提升效率与精度。

- 关键词匹配：只做关键词的直接命中，适合记忆量比较小的场景；
- 向量相似度：先用嵌入模型把文本转成向量，再算余弦相似度；
- 图遍历算法：在知识图谱上扩散，定位到与当前话题相关的实体和关系。

组合使用这些手段，就能在海量记忆里迅速锁定与本次对话最相关的信息，作为上下文喂给模型。

### 6.3.3 Function Call 在 Agent 中的应用

Function Call 是大模型的重要能力，让模型能输出结构化的函数调用请求，而不只是自然语言。在 Agent 的记忆模块里，Function Call 可实现存储、检索、更新记忆等更精准的操作。

#### 1. Function Call 的工作原理

可以类比人类的“思考—行动”过程。做事时先思考调哪个函数、参数怎么填，再执行。模型模拟的就是这一流程。

具体流程包括：

1. 函数定义：先给出可用函数及参数格式。
2. 模型推理：根据上下文判断是否需要调用函数及调用哪个。
3. 参数生成：按函数定义生成合法参数值。
4. 函数执行：系统执行函数并返回结果。
5. 结果整合：把执行结果融入对话继续生成。

在 OpenAI 的方案里，Function Call 通过 tools 参数传入模型，模型会返回 tool_calls 字段，携带函数名和参数，如图 6-1 所示。
