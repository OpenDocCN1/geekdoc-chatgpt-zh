让 AI 真正读懂你的意图，从把话说清楚开始

刚入门编程时，老师随口一句“写个程序”，新手立刻懵掉：要完成什么功能？用哪门语言实现？输入输出有哪些约定？描述越模糊，模型生成的片段越跑偏，学生交上去的作业也越容易出错。把需求摊开讲明白，无论是丢给模型还是让同学自己做，都能更快进入状态，产出更贴合预期的结果。[PRE0][Prompt 使用 C++编写一个程序，实现从键盘输入两个整数，计算并输出它们的和、差、积、商。程序需要包含必要的输入提示信息，并对除数为零的情况进行简单的错误提示。]

信息学竞赛同理。题面写得含糊，选手连题意都抓不住，更别说写出能通过的代码。Prompt 本质上就是任务说明书，越具体歧义越少，就像做数学题，前置条件越清晰，答案越稳。

**4.2.2 给 AI 一张专业名片**

给模型套一个明确的职业身份，等于换一套思维框架。身份不同，看问题的角度、措辞和知识切面都会变，回应也更对味。

学习 C++ 时碰到指针，若直接问“指针是什么”，得到的往往是教科书式的定义，配上一堆专业名词，初学者基本看不懂。若明确让它扮演中学信息科技老师，情况就完全不一样了。[PRE1][Prompt 你是一位 C++编程教师，语法基础扎实，代码能力优秀，教学经验丰富，讲述知识通俗易懂，熟悉中小学生的认知规律，善于使用生活类比解释概念，传授知识逻辑层次清晰，擅长鼓励和引导学生。]

它会主动降维，用学生能接受的方式来讲。内存可以想象成一排带门牌的储物柜，指针就像一张写着门牌的便签，拿着它就能快速找到对应柜子，查看或改动里面的内容。这种具象化的说法，比干巴巴的定义更容易吸收。

再看动态规划。直接问解题套路，AI 容易先堆理论、状态定义、转移方程，抽象又枯燥。若把角色定为有多年竞赛带队经验的教练，答案就会更贴合备考。[PRE2][Prompt 你是一位信息学奥赛教练，熟悉 C++基础与算法知识，熟悉 GESP、CSP、NOIP 的大纲，熟悉竞赛题型，解题能力优秀，讲解细心细致、步骤清晰、逻辑严谨，注重对学生解题思路和独立性的培养，能通过题目的考点及学生的解题过程发现学生的知识盲区，擅长归纳总结和举一反三。]

它不会只讲原理，而是结合最长上升子序列、0-1 背包等经典例题，从竞赛解题思路拆解入手，逐步推到状态转移，再细化到代码实现的关键点，还会提醒这类题常见的边界坑。身份明确后，模型才知道该用什么高度、视角和知识点来回应。

**4.2.3 先报备背景再提问**

模型知识面很广，但不会主动猜你的身份、能力边界或使用场景。缺少背景，它只能给通用答案，要么太深看不懂，要么太浅没用。

以循环求和为例。只问“怎么用循环算 1 到 100 的和”，它可能默认你有经验，直接讲 for 嵌套、while 优化甚至迭代器，还举遍历复杂数组的例子。对刚学会变量定义和 cout 的新手来说，等于天书。补充具体背景后，画面立刻清晰：[PRE3][Prompt 我是小学五年级学生，刚接触 C++半个月，只学过 int、cout 基础语法，还没弄懂数组和函数，现在作业里需要用循环计算 1 到 100 的和。我希望例子里只有最基础的代码，还要有注释，别用复杂概念。]

这时它会先用做重复动作的生活化比喻解释循环本质，再给出仅包含头文件、main、for、累加变量的极简片段，每行加注释，最后提醒输出 sum。难度、重点和表达方式都对路，无需再过滤。

背景信息就像一把定位尺，帮助模型把握难度和切入点。

**4.2.4 把要做什么说到点上**

提问含糊，回复就容易答非所问。你问 A 它回 B，需要反复追问修正，效率很低。除角色背景外，任务怎么做、想要什么结果形态、范围、逻辑顺序、输出形式，都要讲透。

刷题时只说“帮我解这道 C++ 题”，大概率会直接甩完整代码并优化。若你真正想要的是思路引导，就必须把限制说清：[PRE4][Prompt 我现在要解这道编程竞赛题，题目是“从给定数组中选 k 个元素使和最大且不重复”。要求：1.不要直接给出完整代码。2.特别重要：你不要把所有的步骤都告诉我，你告诉我第一步的一点提示即可。3.提示内容可以是用什么算法或者第一步的思路。4.如果我没有思路，让你继续提示，你可以一步一步往下给我提示。]

明确后，它只给第一步提示，配合你逐步推进，真正起到训练作用。

调试代码也一样，只说“帮我看看错在哪”，它可能只指“变量未初始化”。想要深度复盘，需要框住细节：[PRE5][Prompt 帮我分析这段 C++代码的错误：｛C++代码片段｝要求：1.指出具体的错误位置和错误类型。2.修正错误并写出完整代码，可以把错误代码和正确代码做一次对比。3.重点解释这个错误对应的知识点，说明我没掌握哪个知识点才导致这个错误。4.举 1 个类似的错误案例，帮我巩固这个知识点。]

回答就有清晰框架：定位问题、给出修复、深挖根因、举一反三。细节越具体，结果越精准。

**4.2.5 提前约定输出样子**

想直接拿来用，就要先说清怎么组织内容。不是指文件格式，而是指需要哪些内容项、用什么标题、分量大概多少。这样后续整理几乎零成本。

比如每节课后整理 C++ 学习笔记，可以约定固定五块：学习目标、主要内容、关注难点、易错点、学习总结，并要求每篇都用这五个标题统一呈现。提示词就可以是：[PRE6][Prompt 请以 C++初学者的视角，为“C++基础”课程中的××××生成学习笔记。课程的内容是：｛列出课程的主要内容或者课程的具体链接｝学习笔记需要按照以下格式整理。1.学习目标：明确本节课的学习目的。2.主要内容：分几点总结本节课的核心知识，每点配几行关键代码。3.关注难点：列出课中难度较高的概念，用通俗的语言解释。4.易错点：列举 3 个错误案例，为每个案例附修正后的代码。5.学习总结：用几句话串起本节课的内容逻辑和知识脉络。所有内容控制在 400 字内，语言简单、易懂。]

提前约定标题和篇幅，输出统一、可检索，复习效率直接提升。

**4.2.6 用范例牵着走**

当需要特定风格或结构时，直接给一个样例比用文字描述更省事。模型模仿力强，示例能快速锁定语气和排布。

语文托物言志仿写，只说“写篇《竹》”不够具体。给它一篇以《梅》为主题的范文，结构和笔触就被框住了：[PRE7][Prompt 请参考下面以梅为主题的托物言志短文，写一篇同样风格的以《竹》为题的短文。示例短文：《梅》寒冬腊月，别家花木早已褪尽芳华，墙角的梅却顶着风雪抽出嫩芽。它的枝不算粗壮，花瓣也不似桃李那般娇艳，可风愈烈，它的香愈清；雪愈厚，它的骨愈挺。这不正是那些在困境中坚守本心的人吗？不与春争艳，独在寒中绽，以一身傲骨，写尽生命的倔强。]

它会沿用“描物—咏志—喻人”的套路。

编程注释风格统一也适用。给出一段带功能、适用场景、参数、核心步骤解析的注释样例，让它照着给别的代码加注：[PRE8][Prompt 请参考以下示例中 C++代码的注释风格，为给定的代码添加同样风格的注释。###]  [示例开始//]  [功能：对整数数组进行选择排序//]  [适用场景：数据量较小的场景//]  [参数：//]  [arr［］：待排序的整数数组（输入/输出参数，用排序后的结果直接修改原数组）//]  [n：数组元素个数（需满足 n≥1，否则无意义）//]  [核心步骤解析：//]  [1.外层循环控制轮次：共需 n-1 轮（最后一个元素无须再比较）//]  [2.每轮找出未排序部分的最小值下标//]  [3.将最小值与未排序部分的第一个元素交换//]  [4.重复上述步骤，直至所有元素排序完成###]  [代码示例结束需要添加注释的 C++代码为：]

**4.3 把 Prompt 结构化**

面对代码讲解、错误调试、作业辅导等重复任务，零散的 Prompt 容易遗漏信息。结构化提问能提升交互效率，并沉淀为可复用的模板，让每次回复更稳定。

**4.3.1 What：结构化 Prompt 到底是什么**

结构化 Prompt 就是把任务要素按逻辑拆成多个段落，形成有层次的指令。它是提示词工程的基础。

非结构化像一段口语：[PRE12][Prompt 我要写一篇题为《我的周末》的作文，老师让写 300 字左右。我周六上午去公园看到了樱花，周日帮妈妈扫了地、洗了碗，感觉挺有意思，你帮我组织一下语言吧。]

结构化像任务说明单：[PRE13][Prompt#]  [角色你是一名小学五年级学生，正在完成语文老师布置的作文。#]  [背景周六上午去了公园，看到了樱花。周日没出门，在家中帮妈妈做家务。#]  [任务写一篇题为《我的周末》的短文。#]  [要求 1.包含周六、周日两天的活动。2.在开头简单介绍周末的整体安排，在结尾总结这个周末的收获。3.对看樱花要有细节描写，对做家务要突出我和家长的感受。#]  [格式文体为记叙文。篇幅为 300 字左右。]

信息更完整，逻辑更清晰。

**4.3.2 Why：为什么非结构化不行**

每次使用模型时回复不稳定，往往是因为信息不足或理解偏差，模型会自行“脑补”。脑补充满随机性，跑偏后需要多轮纠正，费时且打击信心。

结构化提问有两个核心好处。信息完备：像填问卷，模块固定不容易漏。理解更准：模块自带层级，主次分明，模型和人读起来都更快，减少误解。它能一次性把核心需求、背景、输出要求说清，压缩幻想空间，让一次交互就能拿到可用答案。
