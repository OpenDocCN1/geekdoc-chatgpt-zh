| 布尔 | 组件里有没有需要按需显隐的要素 | 为按钮加入名为 Show Icon 的布尔属性，通过开关决定图标是否出现 |
| 文本 | 按钮文案是否需要使用者自行改写 | 给按钮文字层添加名为 Label 的文本属性，使用者在属性区直接编辑文案 |
| 实例交换 | 图标或子部件是否需要替换 | 为按钮图标创建名为 Icon 的实例交换属性，允许从图标库中挑选替换 |

下面进入综合演练，把按钮组件打造成既强悍又灵活的设计资产。

## 4. 十五分钟实战：搭建完整按钮组件集（可选学习）

这次练习帮助你吃透组件系统的核心，沉淀出可复用的设计资源。通过制作具备多种状态与可调参数的按钮集合，可以直观体会组件化带来的效率——一次搭建，到处复用，一处修改全局生效。

操作流程如下。

1. **搭起基础按钮**。新建一个 Button 文本层，旁侧放置一个来自 2.3.1 节练习的图标实例。选中两者后按 Shift + A 自动生成水平自动布局，微调间距与内边距，并为外层框架填充底色。
2. **生成主组件并定义属性**。选中第一步完成的框架，按 Ctrl/Cmd + Alt + K 设为主组件。在右侧 Design 侧栏的 Properties 区域点 “+”，为图标层新增布尔属性命名为 Show Icon；为文字层新增文本属性命名为 Label。
3. **新增变体属性**。再次在 Properties 区点 “+”，选择 Variant，将首个变体属性命名为 Style，取值设为 Primary。
4. **扩展更多变体**。点击组件集紫色边框下方的 “+” 新建变体，把该变体的填充改为描边，并将 Style 值改为 Secondary。
5. **补齐状态变体**。选中整个组件集，再新增一个变体属性命名为 State，默认值设为 Default。分别为主样式与次样式创建 Hover 变体：框选这两个变体，右键复制粘贴出两份，将 State 改为 Hover，并调深背景色模拟悬停。
6. **验证组件**。把左侧资源区中的按钮组件拖到画布。右侧属性区应出现 Style 与 State 的下拉选择、可编辑的 Label 文本框，以及控制 Show Icon 的开关，可自由尝试各种组合。

掌握组件后，再认识一个更进阶的概念——变量。

## 5. 用变量构建设计令牌（可选学习）

样式是将数值固化成名称，变量则是其进阶形态：一个能随不同情境承载不同值的占位符。这正是设计令牌的实现基础。

设计令牌把设计决策，例如主背景色该是什么，从实现中抽离，以数据化的方式统一管理，形成单一可信来源，提升系统可维护性。

在 Figma 里，变量由专门的 Variables 面板管理，核心包含三点。

- **集合 Collection**：归类变量，比如一个集合放颜色，一个集合放间距。
- **模式 Mode**：同一集合内可配置多套取值组合，是实现明暗主题切换的关键。
- **别名引用 Aliasing**：高级用法，允许一个变量引用另一变量的值，进一步增强关联与可维护性。

后续练习将让你体验变量带来的“一键换肤”。

## 6. 十五分钟实战：实现明暗主题切换（可选学习）

本练习让你感受变量系统的威力——一次配置即可驱动整套设计系统的主题。

开始前请确认已完成前置练习，特别是响应式卡片的制作。若未完成，可先快速做一张含标题、描述与按钮的简易卡片作为测试对象。步骤如下。

1. **新建颜色集合**。清空画布选择，点击右侧边栏的 Variables 打开面板，新建集合命名为 Theme: Colors。
2. **定义模式**。在面板中把默认模式标题改为 Light，再点 “+” 新建模式命名为 Dark。
3. **创建颜色变量**。
    - **color/background**：Light 设为 #FFFFFF，Dark 设为 #1E1E1E。
    - **color/text**：Light 设为 #1E1E1E，Dark 设为 #FFFFFF。
4. **应用变量**。打开之前制作的响应式卡片，把卡片根框架的填充设为 color/background 变量，内部所有文字层的填充设为 color/text 变量。
5. **观察切换**。在画布新建一个顶层框架，模拟手机屏幕尺寸，放入已应用变量的卡片实例。选中该顶层框架，在右侧属性区的图层区域找到变量模式图标，点击把模式从 Light 切到 Dark，框架内所有卡片会同步变为深色主题。

## 2.3.3 从静态稿到可交互产品（可选学习）

到这里，你已经能做出结构清晰、样式统一、行为响应式的界面单元。本节讲解如何把这些静态稿串联，制作出可真实点击的交互原型并交付开发。难度较高可先跳过。

### 1. 高级原型制作

原型让设计“会说话”，直观展示流程与交互细节。Figma 原型制作的核心是建立页面间的连接并定义触发条件与动画效果，从基础跳转到条件分支均可实现。关键环节如下。

- **基础连接**：切换到右上角 Prototype 标签，选中任意图层或框架，拖动其边缘的蓝色圆形节点到目标框架，建立基础交互。
- **触发器与动作**：连接建立后，在右侧 Interaction 面板可定义触发方式如点击、拖拽，以及动作类型如跳转页面、弹出浮层。
- **智能动画 Smart Animate**：制作平滑过渡的利器。把两个框架间的过渡设为 Smart Animate 后，Figma 会为同名图层在位置、尺寸、颜色变化时自动生成补间。
- **用变量制作有状态原型**：借助变量可创建具备记忆与状态的真实原型。可通过交互动作 Set Variable 修改变量值，如点击按钮让 itemCount 加 1，也可添加 if/else 条件实现状态动态切换。

### 2. 十五分钟实战：搭建动态购物车原型

本练习让你体验变量的真正威力——打造能记住用户操作的动态原型。我们将构建一个简洁但完整的购物车交互，演示如何用变量管理应用状态。

1. **设置变量**。打开 Variables 面板，新建 Number 类型变量命名为 cartItemCount，初始值 0。
2. **设计界面**。在某框架内设计一个带“加入购物车”按钮的商品卡片，并在框架顶部设计导航栏，内含购物车图标与旁边的文本层。
3. **绑定变量**。选中购物车图标旁的文本层，在右侧 Design 标签的 Text 区域点最右侧的 Apply variable 图标，选择 cartItemCount，文本会立即显示 0。
4. **创建交互**。切换到 Prototype 标签，选中“加入购物车”按钮。
5. **添加 Set Variable 动作**。为按钮创建 On Click 交互，在 Action 下拉中选择 Set Variable，Target 选 cartItemCount，Value 输入表达式 cartItemCount + 1。
6. **测试原型**。点右上角 Present 进入预览。每次点击“加入购物车”，导航栏里的数字会实时递增。

完成原型后，最后一步是交付给开发团队。

### 3. 开发者模式完全指南

开发者模式是 Figma 官方提供的协作工作区，目标是缩小设计与开发的差距。作为设计师，了解开发者的可视信息有助于更精准地准备交付物。

Figma 底部工具栏有设计/开发切换开关，快捷键 Shift+D。切换后开发者可看到以下核心信息。

- **检查面板**：开发者的核心工具。选中元素，面板会实时展示尺寸、颜色、字体等属性，并自动生成 CSS、iOS、Android 等代码片段。
- **资源导出**：可快速查看并一键导出标记为可导出的图标与图片资源。
- **变更对比**：清晰展示当前版本与上一版本的设计差异。
- **注解**：设计稿上的评论与批注在开发者模式下会完整呈现。

下面的练习模拟交付阶段的收尾工作。

### 4. 十五分钟实战：为开发者交付设计文件

本练习模拟交付前的收尾，确保交付物清晰完整。具体步骤如下。

1. **最终检查与清理**。交付前再次审视文件，确保所有图层已合理命名、有序归类，删除草稿或无用页面。
2. **标记导出项**。检查开发需要使用的资源如图标、图片、Logo，选中后在右侧 Design 面板底部的 Export 区域点 “+”，图标设为 SVG，位图设为 PNG 或 JPG。
3. **标记就绪**。按 Shift + D 切到开发者模式，选中已确认可进入开发的顶层框架，点击顶部工具栏的 Mark as ready for dev 按钮，为框架标注明确状态，便于开发者定位。
4. **添加关键批注**。对于静态稿无法完整表达的复杂交互，使用评论工具添加说明。例如“此处的卡片列表加载时需淡入，时长 300ms”。
5. **分享交付链接**。点击右上角 Share 生成链接，确保开发团队拥有查看权限。发送后交付完成。

最后，了解如何借助自动化工具把设计稿直接转为代码。

### 5. 实战工作坊：从 Figma 到 Tailwind CSS 代码

这里带你领略设计到代码自动化的前沿。这些工具不是取代开发者，而是作为加速器，把高质量设计稿转化为前端基础代码。关注两个核心技巧。

###### 实现设计到代码的自动化转换

在现代前端开发中，设计到代码自动化已成为提效关键。输出质量取决于输入设计稿的质量。要获得高质量代码，Figma 文件需遵循以下结构化原则。

- **语义化命名**：图层名称应体现内容与功能。
- **全面使用自动布局**：可直接映射为 CSS Flexbox 或网格布局。
- **组件化设计**：将可复用元素创建为 Figma 组件。
- **规范使用变量/样式**：工具可将其转化为 CSS 变量或 Tailwind 配置文件。

###### 借助第三方插件实现自动化转换

市场上已有大量插件可智能分析 Figma 设计并自动生成前端代码。以下两款较为流行。

- **Anima**：可直接把 Figma 设计转为 React、Vue 或 HTML 代码，并支持 Tailwind CSS，提供灵活的技术栈选择。
- **Builder.io**：借助 AI 驱动工具的核心功能 Visual Copilot，可将 Figma 设计一键转为多种前端框架和样式库的代码，适合多框架团队。

### 6. 十五分钟实战：从 Figma 设计到 React + Tailwind CSS 代码

下面通过完整实战演示如何把登录页设计稿转为可用的 React + Tailwind CSS 代码。本练习使用 Anima 插件完成流程。

1. **设计登录页英雄区**。在 Figma 中运用自动布局、组件、变量等技巧，设计一个简洁美观的登录页面英雄区。
2. **安装 Anima 插件**。在 Figma 的 Resources 菜单中搜索 Anima 并安装。
3. **配置并导出**。运行 Anima 插件，在插件窗口中将代码输出设为 Framework -> React，Styling -> Tailwind CSS。
4. **选择并生成**。在画布上选中英雄区的顶层框架，Anima 会实时分析设计并生成代码预览。
5. **审查与使用**。可在插件中直接复制生成的 JSX 组件代码和 Tailwind 类名。代码虽需开发者少量微调与逻辑集成，但已完美把视觉设计转化为代码，为开发提供极佳起点。
