#### 5.4.3 用 LangChain 的 Vector Store 搭建向量库
把文本向量化只是第一步，真正做相似检索需要把向量放到专业的向量库里。LangChain 的 Vector Store 层做了统一封装，适配了不少主流后端：

- Chroma：开源库，支持本地文件或云存储，多套相似度策略可选。
- Pinecone：完全托管服务，弹性伸缩和高可用开箱即用。
- Weaviate：开源向量搜索引擎，基于 GraphQL，支持跨模态。
- FAISS：Meta 出品的稠密向量近似检索库，速度极快。
- Milvus：开源可扩展向量库，吞吐并发表现强劲。
- Qdrant：开源搜索引擎，内置高级过滤与完整 CRUD。
- Pandas DataFrame：内存表存向量，适合验证和轻量场景。
- Annoy：基于随机投影树的近似最近邻 C++ 库。
- Elasticsearch：基于 Apache Lucene 的搜索引擎，已原生支持向量相似度。

落地选型除了功能性能，还要看易用性、可维护性和数据安全。隐私要求苛刻时更倾向自托管的 Chroma 或 Milvus，追求上线效率的团队则适合 Pinecone 的托管方案。评估时建议做对比实验或 PoC。

LangChain 的 Vector Store 提供了统一规范，切换库成本很低，能灵活应对数据量、性能和部署环境的变化。Embedding 与 Vector Store 结合，就能把非结构化文本变成语义向量并实现可扩展检索，这是智能问答知识库的基石。

### 5.5 实现问答流程
知识库建好后就能串起端到端的问答链路。LangChain 提供了一系列 Question Answering Chain，把问题理解、检索、生成串联起来，显著降低开发复杂度。

#### 5.5.1 问题理解和分析
问题理解是入口，目标是从用户自然语言输入里准确提取查询意图和关键信息，为检索提供依据。主要涉及问题分类、实体识别和问题扩展。

（1）问题分类和意图识别。
问题分类是判断输入属于哪种类型，常见有事实型、定义型、观点型、过程型、比较型等。不同类型对应不同的生成策略，比如事实型适合直接检索，观点型需要带论据的主观生成。还要识别具体意图，常见有查询、请求服务、寒暄、闲聊等，不同意图会触发知识问答、任务协助、关系维护等不同对话能力。

在 LangChain 里可以用 HumanChatMessage 和 SystemChatMessage 组成对话记录，再加入 few-shot 示例，实现少样本的问题分类和意图识别。
