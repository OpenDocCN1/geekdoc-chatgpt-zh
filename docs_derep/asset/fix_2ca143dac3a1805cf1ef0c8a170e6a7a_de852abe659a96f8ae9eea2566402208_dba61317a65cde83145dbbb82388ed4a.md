查询加速方案：分层缓存与检索优化

这套方案把进程内存缓存叠加外部 Redis，形成两级缓存体系，在保证响应速度的同时具备良好的水平扩展能力。

- 1）高频访问的数据交由 cachetools.TTLCache 驻留在进程内存，利用内存读写特性获得极快取数速度。
- 2）并发场景下借助 threading.Lock 做加锁保护，确保多线程同时操作时的一致性。
- 3）为满足跨进程、跨服务器共享，引入 Redis 作为分布式存储，后端依托其持久化与高性能特性保存数据；键名使用 SHA256 哈希生成，保证唯一性并避免名称过长；装饰器 cached_retrieve_decorator 统一封装流程：先查进程内存，失效则查 Redis，最后若仍未命中才调用真实的数据检索函数，并把返回结果同步写入进程缓存和 Redis。
- 4）每个条目都设定 TTL 过期时间以维持数据新鲜度，同时打印命中日志，便于监控与后续调优。

总体来看，两级结构大幅削减了重复查询成本，提升了响应速度与整体性能，扩展性与可靠性俱佳，适合高频重复查询的生产环境。

##### （3）并行处理

在面对海量数据及高并发请求时，引入并发化手段能显著提升整体吞吐。常见的并发化方式有多线程与多进程。多线程是在同一进程内部创建多个线程，各线程可独立执行任务实现并发。多进程则是启动多个独立进程，每个进程拥有独立内存空间并行处理不同任务。

> 提示：分布式计算框架如 Apache Spark 与 Dask 在并发化中也非常重要。它们把计算任务分发到多台计算节点上完成大规模数据的并发运算。Spark 与 Dask 提供了丰富的 API 与优化调度策略，能够有效管理分布式任务，进一步提高处理能力与吞吐。

### 3.2.2 关键词检索

关键字检索的核心在于把用户查询中的检索词与文档词汇进行匹配，从而定位相关信息。该技术广泛应用于搜索引擎、数据库查询和文本分析，帮助用户快速找到所需内容。通过精确匹配或模糊匹配，可筛选出包含特定词的文档，提升检索效率与准确度。

#### 1. 基本原理

关键字检索的基本思路是识别查询中的检索词，并在文档集合中找出包含这些词的文档，在信息检索领域具有重要意义。传统方法主要有布尔检索和基于概率模型的检索，如常用的 BM25 算法。

布尔检索是经典方法，利用 AND、OR、NOT 等逻辑运算符组合检索词实现精确匹配。例如查询“人工智能 AND 教育”会返回同时包含这两个词的文档。其优点是简单直观，便于构造复杂表达式，但在处理自然语言和复杂查询时局限明显，难以应对词义多样性和上下文关联。

BM25 是一种基于词频 TF 与逆文档频率 IDF 的相关性打分算法，用于衡量文档与查询的匹配程度。其核心是结合词在文档中的出现次数与在整体语料中的稀有程度计算得分，能更细腻地刻画匹配关系，适用于大规模文档。与布尔检索相比，BM25 在自然语言和复杂查询上优势更明显，更能捕捉用户真实意图。

在 RAG 系统中，关键字检索通常作为初筛环节，快速从海量文档中抽取与查询相关的子集，再送入生成模型进行深度加工。生成模型可进一步分析内容并输出更精确详细的答案。因此关键字检索的效率与准确性直接决定 RAG 系统表现，优化该环节是提升整体性能的关键。

#### 2. 实现步骤

实现关键字检索一般包含以下关键环节。

##### （1）文本预处理

文本预处理旨在把原始文本转换为更利于检索的形态。主要包括词干提取与分词校准。

词干提取是将词语还原为基本形式，如把 running 还原为 run，有助于统一词形，提升泛化能力，使不同形式的同一词汇得到统一处理，从而提高准确率与效率。

分词校准对中文尤为重要。分词是把连续文本切分为有意义词语的过程，由于中文缺乏明显分隔符，准确分词对检索词匹配至关重要，错误分词会导致检索词无法命中，影响结果质量。经过上述处理，文本噪声减少，后续检索更高效准确。

##### （2）构建倒排索引

倒排索引是信息检索中常用的高效结构，通过把检索词映射到包含该词的文档列表来加速检索。构建过程大致分为：

- 1）词表构建。系统遍历全部文档，抽取所有独特检索词并组织成词表，为后续索引提供基础。
- 2）文档列表关联。对词表中的每个检索词，记录包含该词的文档 ID，并以有序列表存储，便于快速检索与交集运算。查询时可迅速从倒排索引中找到所有相关文档。

例如，假设有以下三篇文档。

- 文档 1：人工智能在教育中的应用
- 文档 2：机器学习与深度学习的区别
- 文档 3：教育技术的发展趋势

##### （3）评分和排序

检索到含检索词的文档后，需进行评分与排序以确定相关性。常用算法为 BM25。

BM25 能较好处理检索词频率与文档长度对评分的影响，避免极端偏差。其评分公式如式（3-1）所示：BM25(q, D) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)} \quad (3-1)

其中：
- BM25(q, D) 为文档 D 与查询 q 的相关得分。
- IDF(q_i) 为第 i 个检索词的逆文档频率。
- q_i 为查询中的第 i 个检索词。
- f(q_i, D) 为检索词 q_i 在文档 D 中的出现次数。
- |D| 为文档 D 的长度。
- avgdl 为所有文档的平均长度。
- k_1 与 b 为调节参数，通常取 k_1 = 1.5 和 b = 0.75。
