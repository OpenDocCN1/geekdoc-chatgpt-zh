相关参数含义如下。

- community_reports：传入已载入的聚类概要 reports，用于在近场检索中补充聚类层级的背景。
- text_units：传入已载入的文本块，提供来自原始文档的片段，用以回答具体问题或补充信息。
- entities：传入图谱中的实体，提供实体详情与属性，帮助定位目标实体。
- relationships：传入图谱中的关系，用于刻画实体间的交互，有助于组织更复杂的答案。
- covariates：传入协变量，若索引阶段未启用则设为 None，用于提供额外声明式元数据。若未启用，近场检索仍可运行，但附加语义会减少。
- entity_text_embeddings：传入实体嵌入存储对象 description_embedding_store，将实体文本嵌入存于向量库，支持语义检索快速定位相关实体。
- embedding_vectorstore_key：设置嵌入向量库的键类型。若库按 ID 存储实体，使用 EntityVectorStoreKey.ID；若按标题存储则设为 EntityVectorStoreKey.TITLE。
- text_embedder：传入嵌入生成器对象 text_embedder，用于生成问题或文本的语义向量，与存储的实体向量做相似度比较。
- token_encoder：传入分词器，确保生成的背景不会超过 LLM 的窗口上限，有助于合理分配查询时的信息量。

背景构建器是近场检索的核心，它把载入的数据整合成结构化信息，作用如下。

- 融合聚类概要，提供更上层的背景，利于主题性提问。
- 整合文本块，引入原始文档片段，为问题构建直接信息。
- 集成图谱实体与关系，为实体相关提问提供详细语义材料。
- 借助嵌入与分词器，保证信息生成语义准确且符合 LLM 的窗口限制。

相关参数含义如下。

- text_unit_prop：信息窗中分配给文本块的比例，默认值 50%。控制原始文档文本在信息中的权重。
- community_prop：信息窗中分配给聚类概要的比例，默认值 10%。为回答提供更高层的聚类背景。
- conversation_history_max_turns：信息中包含的最大对话轮数，默认值 5 轮。控制是否纳入过往对话历史及保留轮数。

- top_k_mapped_entities：从向量库检索的相关实体数量，默认值 10 个。
- top_k_relationships：检索并纳入信息窗的最大关系数，默认值 10 个。
- include_entity_rank：是否在信息中包含实体排名，默认按节点度数计算。
- include_relationship_weight：是否在信息中包含关系权重，用以体现关系重要性。
- include_community_rank：是否在信息中包含聚类排名。

- embedding_vectorstore_key：嵌入向量库的键类型，若标识符为实体标题而非 ID，则设为 EntityVectorStoreKey.TITLE。
- max_tokens：信息窗允许的最大 token 数，12 000 个。需依据所用 LLM 的限制调整，如 GPT-4 支持 8192 或 32 768。
