#### 8.1.9 从 LangChain 到 LangGraph 的平滑过渡
LangChain 社区自 2023 年起就在定义大模型应用规范，目前已发布多个大版本，其体系里最关键的两块是 RAG 和 AI Agent。LangChain 中构建 AI Agent 的底层架构如图 8.12 所示。

[PRE12]

在 LangChain 框架里，AI Agent 内部被拆为 Agent、Message 和 Toolkits 三大核心。每个 Agent 通常由大模型+提示+输出解析器组成，形成一个 Chain 来处理输入。Agent 可处理的输入来自三方面：Input 为用户原始输入，Model Response 为模型对子任务的响应，Context 则携带上下文信息。Agent 的输出会连接到工具库，具体调用哪些工具由 Agent 处理后拆分出的子任务决定。大模型调用外部函数分为识别工具和实际执行两步。Messages→AI Agent→Toolkits 流程负责拆解子任务、定位工具并提取名称与参数，可视作静态执行流程，而把决策转化为行动的工作则交给 AgentExecutor。

总体而言，LangChain 的 AI Agent 架构中，Agent 负责接收输入并决定操作，但不直接执行，执行由 AgentExecutor 完成。只有 Agent 与 AgentExecutor 结合，才能构成完整 Agent，其中 AgentExecutor 负责调用 Agent 并执行其指定的工具。

LangChain 仍是构建大语言模型应用的前沿框架。最新 v0.3 版本基本完成了从传统类向 LCEL 的过渡，让定义和执行分步操作序列变得更简洁。专业角度看，LangChain 构建的是有向无环图 DAG。随着 AI 应用尤其是 AI Agent 的发展，大模型的使用正从单纯执行工具转向更复杂的推理引擎，这正是 LangGraph 诞生的根源，也带来了对循环结构和复杂条件交互的更多需求，使得基于 LCEL 的线性序列在构建更高级系统时逐渐受限。
