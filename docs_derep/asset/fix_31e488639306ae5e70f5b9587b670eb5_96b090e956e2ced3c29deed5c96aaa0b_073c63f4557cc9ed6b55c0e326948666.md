### 2.4 本地部署避坑手册

本地部署 OpenClaw 时底层报错很常见，多与硬件适配、权限、版本兼容有关，不同系统表现不一。以下聚焦高频问题，给出可落地的排障思路。

#### 2.4.1 问题一：Llama 本地推理启动失败

报错表现：运行轻量任务时出现 Out Of MemoryError 或 Model Load Failed，Mac 提示进程被内核终止，Windows 报 CUDA 初始化失败，Linux 报显存不足。

◎ 核心原因
① 算力显存不匹配，如 8GB 显卡加载 13B 量化模型；
② 量化配置错误，未按硬件选择 GGUF 量化等级；
③ 平台依赖缺失，Mac 缺 Metal，Windows 缺 CUDA，Linux 缺 libtorch。

分平台解决办法见表2-3。
表2-3

| 平台 | 具体解决步骤 |
| :--- | :--- |
| MacBook | 1.改用 Q4_K_M 或 Q2_K 等轻量化 Llama 量化包；2.安装 Metal 加速依赖：pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/nightly/cpu；3.关闭后台高内存程序释放资源 |
| Windows | 1.核对显存：7B 需 ≥8GB、13B 需 ≥16GB，不足则降级量化模型；2.安装对应显卡的 CUDA Toolkit，如 RTX 40 系装 CUDA 12.1；3.将 CUDA_PATH 加入系统 Path |
| Linux | 1.nvidia-smi 查看显存与驱动，驱动低于 535 则升级；2.启动参数添加 --load-in-8bit 降低显存占用；3.sudo apt-get install libgomp1 |

#### 2.4.2 问题二：向量数据库 RAG 检索连接超时

报错表现：调用记忆系统时报 Vector DB Connection Timeout，无法召回习惯或规则，FAISS/Chroma 进程未正常启动。

◎ 核心原因
① 存储目录写入权限不足；
② 路径写法跨平台不兼容；
③ 缺少 faiss-cpu/chroma-core 依赖。

分平台解决办法见表2-4。
表 2-4

| 平台 | 具体解决步骤 |
| :--- | :--- |
| MacBook | 1.为启动程序授予完全磁盘访问权限；2.配置文件路径改为 ~/Documents/OpenClaw/vector_db；3.pip install faiss-cpu==1.7.4 |
| Windows | 1.以管理员身份运行终端启动程序；2.配置文件中使用双斜杠路径 C:\OpenClaw\vector_db；3.安装 VC++ 运行库修复 Chroma 依赖 |
| Linux | 1.chmod 777 /opt/OpenClaw/vector_db；2.配置文件使用绝对路径 /opt/OpenClaw/vector_db；3.sudo apt-get install libssl-dev |

#### 2.4.3 问题三：API 熔断机制初始化失败

报错表现：启动时成本监控报 Env Variable Not Found 或 Circuit Breaker Init Error，Token 阈值加载失败，熔断功能失效。

◎ 核心原因
① 环境变量未配置，缺失 TOKEN_LIMIT、API_KEY 等；
② pybreaker 与 Python 版本不兼容；
③ 配置文件 yaml/json 存在语法错误。

分平台解决办法见表2-5。
表 2-5

| 平台 | 具体解决步骤 |
| :--- | :--- |
| MacBook | 1.编辑 ~/.zshrc 添加 export DAILY_TOKEN_LIMIT=100000，执行 source ~/.zshrc；2.pip install pybreaker==1.0.1 python-dotenv==1.0.0；3.用 YAML 校验工具检查 config/circuit_breaker.yaml |
| Windows | 1.系统设置→高级系统设置→环境变量新建 DAILY_TOKEN_LIMIT=100000；2.Python 降至 3.10 以兼容 pybreaker；3.VS Code 打开配置文件修复 json/yaml 语法 |
| Linux | 1.编辑 /etc/profile 添加环境变量，执行 source /etc/profile；2.conda create -n OpenClaw python=3.10 隔离依赖；3.yamllint config/circuit_breaker.yaml |

#### 2.4.4 问题四：WSL / 容器部署路径映射错误

报错表现：Windows 使用 WSL 或全平台使用 Docker 时报 File Not Found，模型、记忆、技能读取失败，映射失效。

◎ 核心原因
① WSL 路径转换错误；
② Docker 挂载参数错误；
③ 挂载目录权限不足。

分平台解决办法见表2-6。
表2-6

| 部署场景 | 具体解决步骤 |
| :--- | :--- |
| Windows+WSL | 1.Windows 路径转为 WSL 路径，如 C:\OpenClaw → /mnt/c/OpenClaw；2.wsl --set-default-version 2 启用 WSL2；3.sudo chown -R $USER:$USER /mnt/c/OpenClaw |
| 全平台+Docker | 1.run 命令修正挂载：-v 宿主机绝对路径:容器内绝对路径，如 Mac -v ~/OpenClaw:/app/OpenClaw；2.避免挂载符号链接目录；3.启动时添加 --privileged 提升文件访问权限 |

#### 2.4.5 问题五：离线模式下 Skills 调用失效

报错表现：断网时执行本地任务如文件整理、日程提醒，提示 Skill Execute Failed 或 Tool API Unavailable，违背全天候设计。

◎ 核心原因
① 技能未开启离线支持，默认依赖云端；
② 本地工具缓存未初始化；
③ 系统限制离线访问本地工具。

分平台解决办法见表2-7。
表2-7

| 平台 | 具体解决步骤 |
| :--- | :--- |
| MacBook | 1.编辑 config/skills.yaml 将核心技能 offline_support 设为 true；2.python scripts/init_offline_cache.py 初始化本地缓存；3.系统设置→网络→防火墙放行 OpenClaw |
| Windows | 1.同上修改配置开启离线支持；2.管理员身份运行缓存初始化脚本下载离线依赖；3.防火墙高级设置允许 OpenClaw 在域、私有、公网下离线访问 |
