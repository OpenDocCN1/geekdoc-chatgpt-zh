不管选什么语言，技能的本质都一样：收参、执行、回传。参数从 `params` 对象里取出，环境信息诸如当前用户、会话 ID 这些上下文则从 `context` 获取。最后必须返回一个对象，核心字段是 `success`，成功时附带 `data`，失败时附带 `error`。

### （3）参数从哪来

一个技能的输入只有两个来源。

用户直接触发：例如在命令行敲 `weather:current --city 北京`，`city=北京` 就会被封装成参数传入。

Agent 触发：Agent 根据自然语言指令从对话里解析出城市名，生成参数对象再传给技能。

技能本身不用管参数怎么来的，`run` 函数里直接从 `params` 读取即可。为了让 Agent 能准确提取，你需要在 `skill.yaml` 里把参数定义写清楚：类型、说明、是否必填。描述越清晰，Agent 规划时生成参数就越准确。

### （4）核心逻辑怎样写

处理部分是技能的价值所在，你可以做的事情很多：

- 调外部 API，比如天气、股票、翻译；
- 跑本地命令，读文件、启动程序；
- 读写数据库；
- 调用熟悉的 Python / Node 库。

只要在技能目录的依赖文件里声明即可，Node 用 `package.json`，Python 用 `requirements.txt`。比如示例用了 `requests`，就要在 `requirements.txt` 里加上 `requests==2.28.1`。

注意技能是在 OpenClaw 主进程之外运行，不会把主进程拖垮，但要控制资源，不要写死循环，不要长时间占用大量内存。

### （5）输出要符合什么规范

技能的返回值必须是对象，且至少包含 `success` 字段。建议格式如下：

成功时：`{ success: true, data: 你想返回的结构化数据, message: “可选的说明” }`

失败时：`{ success: false, error: “错误原因”, message: “给用户的友好提示” }`

Agent 会拿到这个结果，可能原样透出，也可能用大模型再润色成自然语言。所以 `data` 最好保持结构化，方便 Agent 理解和使用。

## 5.3 技能串联：让龙虾自动走完复杂流程

单个技能能力有限：查天气、发邮件、读文件……真实任务往往更复杂。比如“每天 9 点检查股市，若某股跌超 5% 就发邮件提醒，同时把近三天走势图存到桌面”，至少需要定时、查股、发信、存文件四个技能。难道要分四次下指令？

不用。OpenClaw 的强项就是让 Agent 把技能像积木一样串起来，你只说目标，它自己决定用哪些技能、什么顺序、中间结果怎么传。

### 为何要组合技能

举个例子：每天自动生成竞品分析报告，需要

- 爬取竞争对手网站最新动态；
- 用大模型提炼要点；
- 生成表格；
- 邮件发送给团队。

没有组合，每天要手动跑爬虫、复制给 ChatGPT、粘到 Excel、再发邮件，自动化程度为零。

有了 OpenClaw，可以把每一步封装成技能：

- `browser` 抓取网页；
- `llm` 分析提炼；
- `excel` 生成表格；
- `email` 发送邮件。

然后只说一句：“每天上午 9 点生成竞品报告并发给团队。” Agent 会自行规划：先用 `cron` 定时，到点用 `browser` 抓数据，再用 `llm` 分析，用 `excel` 写表，最后用 `email` 发信。全程无需人工。

这就是组合的价值：把复杂流程压缩成一句话。

# 第六章 记忆管理：让“龙虾”记住该记的

## 6.1 龙虾如何记住你？向量数据库是什么

有没有这种体验：刚告诉 AI“我叫张三，在腾讯做产品经理”，聊半小时后问它职业是否适合学编程，它侃侃而谈却忘了你是产品经理。又得重复一遍。这种健忘症让人很烦。

OpenClaw 想做的不是健忘的 AI，而是越聊越懂你的 AI——你喜欢简洁还是详细、项目叫什么、生日哪天、讨厌什么回复风格。这些信息靠一次对话记不住，需要长期记忆。

问题是，记忆怎么存、怎么在需要时又快又准地找出来？如果只存成文本文件，问“我叫什么”时，AI 得把所有文件全扫一遍，关键词匹配也不一定命中。

OpenClaw 用的是更聪明的方案：向量数据库。

### 先抛开技术，想一个画面

想象你有一个超靠谱的秘书，笔记本不是按时间排，而是按“意思”分类。你说“我叫张三”，他会把这条信息归到“姓名、身份、称呼”这个抽屉。下次你问“怎么称呼我”，他立刻想到“姓名”抽屉，拿出“张三”。

向量数据库做的就是这件事，它用“意思”而不是关键词来检索。

### 文字变成数学坐标

让电脑理解意思，要把文字变成可计算的东西——向量。可以把向量想象成高维空间里的一个点。文字转向量叫嵌入。OpenClaw 的嵌入模型接收一句话，输出一个几百维的数字数组。关键特性是：意思相近的句子，向量距离也近。

例如：

“我叫张三”和“我的名字是张三”，字面不同但意思相同，向量很近。

“我叫张三”和“今天天气真好”，意思无关，向量很远。

有了这个特性，计算机就能通过距离判断两句话是否相关。

### 向量数据库：存向量的仓库

向量数据库专门存储向量，并能快速找到最相似的几个。它不按 ID 查，而是给你一个向量，返回库里最接近的向量。

OpenClaw 的长期记忆就建在上面。你说“我叫张三”时，系统会：

用嵌入模型生成向量；
把向量连同原文“我叫张三”及元数据如“姓名类、今天”一起存进库。

下次你问“我叫什么名字”时：

同样把问题转成向量；
在库里找最接近的向量；
取出对应的原文“张三”。

于是 AI 能回复：“你叫张三。”不管你怎么问——“我的名字是啥”“你还记得我叫啥吗”，只要意思相近，就能命中。

### 为何不用传统数据库

传统 SQL 很适合存 `user_info(name='张三')` 这种固定字段。但 AI 记住的内容千奇百怪：喜欢的电影、讨厌的语气、上次提的项目细节、内部术语……没有固定字段，也无法预测提问方式。向量数据库的语义检索，能处理这种模糊、不确定的查询，只要意思接近就能找到。
