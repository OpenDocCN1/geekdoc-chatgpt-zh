思维图的演化轨迹

并行推理是思维图最早的雏形。系统把一个复杂命题拆成若干子命题，让它们各自独立产出结果，最后再手工拼接起来。速度看起来不错，但致命缺陷是分支之间互不交流，结论无法相互修正、融合，形成各自为政的局面。

静态图谱引入了聚合与提炼操作，拓扑在设计时就固定下来，例如 先发散成三条支线，再经两层汇总，最后进入一个循环节点。预先规划的骨架让分散的信息得以深度交汇，最终产生的洞见通常超越单一分支的水平。

动态图把图结构的决定权交给了运行时的智能体。图不再是建模时画死的蓝图，而是现场即时绘制的推理网：当发现某处证据不足，智能体就会自行分叉去查阅资料，待结果回来后再汇合。这样的自组织能力让系统具备很强的适应性，思考方式更像人在面对未知时的探索与生成。

### 2. 模式组合示例

思维图擅长承载复杂的信息流，经常充当主干拓扑，用来挂载记忆模块和行动模块，支撑高阶认知任务。

思维图+RAG = 图谱增强生成
针对需要全局视野的难题，例如梳理上百份合同之间的关联风险。RAG 提供的不是零散段落，而是实体间的关系网络。思维图把知识图谱的连接直接转译成推理路径，智能体沿着边进行多步跳跃推断，并在每个节点整合邻域信息，达成结构化知识与结构化推理的同构。

思维图+工具编排 = 自动化数据流水线
借助图的回路特质实现代码质量的螺旋式提升，常出现在自动化分析与修复场景。推理图被转化为执行流程，形成“生成代码—运行代码—修复代码”的闭环。
节点 A Generate 调用代码生成工具产出分析脚本；
节点 B Execute 调用代码解释工具执行脚本；
节点 C Analyze 若执行失败，解析错误日志并在图上创建指向节点 A 的反馈边，触发重写。

把线性思维解网，智能体就不再沿着单一路径推进，而是能在宏观层面调度、分拣、重组信息。

### 6.3.5 设计哲学：网络的韧性

思维图反映了现实问题的网络本质。真实难题很少是纯线性的思维链，也很少是纯树状结构，因为树状意味着选定一条路就放弃其他可能性。

现实往往要求多重兼顾。
一方面要兼顾成本与质量，这体现了多分支的汇聚；
另一方面要兼顾推进与复核，这体现了循环往复。

思维图赋予智能体整合力，让它不再是钻牛角尖的专家，而像一位善于倾听、综合众家之长并持续自我完善的架构师。

至此，推理的基本拓扑已经完整。
思维链侧重数学、逻辑等一步步推导的任务；
思维树侧重搜索、决策等需要多路分叉的任务；
思维图侧重综合、创意、优化等需要多向关联与整合的任务。

由此形成一套相对完整的推理拓扑体系。接下来进入类比推理，探讨如何借助记忆获得推理捷径。

## 6.4 类比推理模式

> “创造力并非凭空产生，而是通过将已知事物相互关联，从而发现新的可能性。”
> ——道格拉斯·侯世达，《哥德尔、艾舍尔、巴赫：集异璧之大成》

面对陌生任务，例如“如何整顿一家混乱的初创公司”，智能体不会从零推导管理理论，而是去记忆库里寻找结构相似的历史情境，比如战国时期的合纵连横，或乔布斯重返苹果的经历。

它会说：“我见过类似的局面，人名地名换了，但权力博弈的规则没变，可以借鉴当时的策略再做调整。”

类比推理的核心是结构映射，从长期记忆中检索出与当前问题在关系结构上相似的源案例，并把源案例的解法迁移到目标问题。这正是人类举一反三和大模型少样本学习的关键机制。

### 6.4.1 模式架构：跨域的跳跃

类比推理不像流水线，更像一座跨时空的传输门。设计目标是让智能体穿透表象，直达记忆中问题的本质结构，再把旧智慧搬到新场景。

架构中的关键部件包括：
检索器 Retriever 负责联想，不仅做关键词匹配，更做结构匹配，例如能识别原子结构和太阳系在组织方式上的相似。

三者协同构成从记忆提取到认知重组的闭环，把静态知识转换为动态策略。

### 6.4.2 类比推理核心机制

智能体能把原子和太阳系联系起来，并非魔法，而是剥离具体细节、捕捉拓扑同构。

1. 结构映射理论
认知科学家德德雷·根特纳提出的理论指出，属性可以舍弃，关系必须保留。
太阳是金黄色的，原子核没有颜色，这些表象无关紧要；
“太阳吸引行星”和“原子核吸引电子”都是“中心吸引外围”的关系模式，关系才是映射的关键。

类比本质是在高维向量空间中寻找关系拓扑的同构。

2. 抽象与具体化
类比是 V 形思维。
抽象：剥离源案例的细节，提炼通用图式；
具体化：把通用图式套用到目标情境并填入细节。

3. 自我生成案例
记忆库没有现成案例时，强模型可以自创。例如提示“构想一个逻辑相似但领域不同的案例并据此给出建议”，模型可能用做菜类比写代码，提出模块化如同提前备菜的建议。

这些机制赋予智能体流体智力，能应对从未见过的情境。

### 6.4.3 类比推理工程实践

工程上类比推理常表现为检索增强的少样本提示，不仅要找知识，更要找思路。

案例1：智能代码助手
在 GitHub Copilot、Cursor 等工具中，用户输入 def connect_to_redis 时，系统通过类比自动补全。
检索：在代码库中找到已有的 connect_to_mysql 实现作为源案例；
映射：识别出 mysql.connector 与 redis-py 的对应，以及主机、端口等连接逻辑的共通性；
迁移：借鉴异常处理风格和配置读取方式，生成符合项目规范的 Redis 连接代码。
既复用了经过验证的稳健逻辑，也保持了代码风格统一。

案例2：法律判例推理
律师借助 Harvey、Casetext 分析新型虚拟币诈骗案时：
检索：在判例库中找结构相似的跨境电信诈骗或庞氏骗局案件；
映射：把虚拟币类比为既有金融产品，把交易平台对应到传统金融中介；
迁移：借用旧案的定罪逻辑、法律适用和量刑标准，生成新的法律意见书。

案例3：跨域设计灵感
设计师用 Midjourney Prompt Helper 构思“像跑车一样的鼠标”时：
检索：从跑车提取流线车身、进气格栅、金属漆等特征；
映射：流线车身→鼠标整体造型，进气格栅→按键布局，金属漆→材质与表面处理；
迁移：整合后生成绘图 Prompt。

### 6.4.4 类比推理模式的演化与组合

类比推理并非照猫画虎，而是从静态提示技巧演进为动态检索增强，最终发展为可解释的结构映射。

1. 演化路径：从示例到映射
静态少样本 Static Few-shot 是“刻舟求剑”阶段的代表。

2. 模式组合示例
类比推理常作为直觉引擎，需与逻辑引擎或执行引擎配合。

类比推理+思维链 = 启发式推理
类比提供 System 1 式的战略直觉，思维链负责 System 2 式的战术执行。
类比阶段：检索相似旧题，提取解题框架，例如“像追及问题”；
推导阶段：用思维链把框架迁移到新题，逐步补全细节。

类比推理+工具编排 = 经验迁移
常见于 AI 编程助手或运维智能体，把他人的经验转化为当前操作。
检索：从代码库检索风格相近的片段或历史修复记录；
映射：识别变量与结构对应关系；
生成：调用代码生成工具补全代码或生成修复补丁。

类比是获得流体智力的关键，让智能体在陌生场景快速建立认知锚点，从死记硬背走向举一反三。

### 6.4.5 设计哲学：创造力的源头

思维链和思维树拼算力，类比推理拼阅历。人的聪明之处在于善于联想。
见飞鸟造飞机，观游鱼造潜艇。
类比推理赋予智能体创造力的雏形，真正的创造并非凭空而来，而是把 A 领域的智慧搬到 B 领域。它是突破领域边界、走向通用智能的关键钥匙。

小结 理性地编织

到此，智能体大脑中最核心的推理模块已经搭建完成，不再依赖大模型的概率直觉，而是建立结构化的认知拓扑。

若把推理比作交响乐，本章四种模式就是乐器。
思维链模式如小提琴，线性精准；
思维树模式如钢琴，多声部探索；
思维图模式如电子合成器，网络化融合；
类比推理模式如鼓点，跳跃直觉、连接共鸣。

优秀的架构师不应迷信单一模式，而应指挥整支认知乐团。
遇到陌生难题，先敲类比的鼓点激发灵感；
方向明朗后，用思维树的钢琴探索路径；
路径确定后，交给思维链的小提琴严谨演绎；
最后借助思维图的合成器融合打磨。

未来推理将不再局限于文本平面，正向三维环境跃迁。智能体的推理对象将从文本转向几何、物理、动力学，空间智能成为构建世界模型的关键。

推理结束后，智能体已经明白要做什么、为什么以及不做的后果。但这还不够，它必须走出思维空间，介入现实。

# 第 7 章

## 行动模式

> “知行合一。”
> ——王阳明

感知、记忆、推理之后，智能体迎来最激动人心的时刻：走出大脑，迈向现实。若推理是参谋部，行动就是远征军。

智能体需要四种能力。
边想边打 ReAct 模式：在行动中实时获取前线信息并动态调整策略；
运筹帷幄 规划—执行模式：制定全局战略并拆解为可执行步骤；
调兵遣将 工具编排模式：精准挑选、协同调度海量资源与工具；
自我进化 自适应策略模式：从成败中总结经验，动态优化策略。

行动的本质是对物理或数字世界的有效干预。
从认知看，行动是具身智能的起点，智能不再是缸中之脑，而是具备手眼协调能力的实体；
从工程看，行动是结果的载体，API 调用、数据库写入、文件修改需具备原子性与回滚机制；
从控制论看，行动是反馈回路的执行器，把决策转化为实际影响，触发反馈实现动态调节。
