## 第1章
为何需要向量数据库
大语言模型凭借强大的自然语言处理能力推动多项应用。但在高维矢量表示与语义嵌入环节，其内在缺陷逐渐显现。矢量虽能捕捉复杂语义关系，却常伴随信息丧失与分布不均，导致语义相似度计算难以准确映射真实含义。嵌入空间的组织方式也会引入相似性度量的偏差，制约模型在特定场景下的表现。

随AI与大数据发展，高维数据的存取需求持续攀升。从文本嵌入到图像特征，高维矢量成为数据表征的主流形式。然而这类数据并非传统数据系统擅长的范畴，传统系统主要面向结构化数据设计，在矢量计算与高效检索方面支持有限。

高维空间固有的“维度诅咒”进一步放大检索难度，使得常规算法难以高效完成高维矢量间的相似度计算。与此同时，传统数据系统在实时检索需求面前张力不足，随着数据规模扩张，性能瓶颈愈发明显。向量库正是为解决这一矛盾而诞生，通过专用的存储结构与索引方法显著提升检索效率，已广泛应用于图像搜索、推荐系统等领域。

本章围绕高维数据特性、检索存储瓶颈以及传统系统与向量库的对比，阐明向量库的重要性与技术优势。

### 1.1 大语言模型的缺陷
本节聚焦大语言模型在高维矢量表示与嵌入空间中存在的核心问题，并分析其对模型效能与实际落地的负面影响。

#### 1.1.1 高维向量表示中的信息丢失问题
近两年人工智能领域出现显著变化，GPT-3.5与GPT-4的到来带来惊人能力，也暴露出明显限制，给开发者带来困扰。

以GPT模型的输入为例，存在上下文token容量的上限。以gpt-3.5-turbo为例，最大输入限制为4K tokens，约3000字，意味着单次对话最多只能提供约3000字供模型理解推理。

有人会认为借助对话记忆功能，可将内容分批输入从而绕过限制。但事实上LLM本身并不具备记忆能力。不同类型LLM可处理的token上限如表1-1所示，常见模型在不同版本与配置下的最大token限制各不相同，token上限越高越适合处理长文本任务。

表1-1 不同类型LLM的token上限

| 模型类型 | 最大 token 数量 | 模型类型 | 最大 token 数量 |

|---|---|---|---|

| GPT-3.5 | 4K tokens（约 3 000 字） | Mistral | 8K tokens |

| GPT-4 | 32K tokens（约 24 000 字） | PaLM 2 | 32K tokens |

| Claude 模型 | 100K tokens（约 75 000 字） | Anthropic Claude | 72K~100K tokens |

| LLaMA 2 | 4K~8K tokens（根据版本不同） | | |

所谓的记忆，实质是开发者在后台将对话记录保存在内存或数据库中，发送消息时把最近几次对话内容在4096 tokens限制内拼接到新Prompt一并送入模型。因此一旦对话超出4096 tokens限制，模型便无法回溯更早内容，这直接影响复杂任务的处理效果。

不同模型的限制差异明显，如GPT-4为32K tokens，Claude模型已支持高达100K tokens，相当于可一次性输入约75 000字的上下文，足以让模型通读一篇完整的中篇小说并作答。

这种提升是否彻底解决问题？并非如此。以Claude模型为例，处理72K tokens上下文的响应约需22秒。若处理GB级乃至更大规模文档，响应速度将急剧下降，难以保持流畅体验。此外，GPT API计费与token用量挂钩，上下文越多成本越高，对大规模应用构成沉重负担。

这与早期计算机内存极度受限的开发困境相似。一方面内存资源昂贵，另一方面容量不足以支撑复杂任务。在模型性能、成本与注意力机制取得革命性突破前，开发者仍需寻找绕过token限制的方案。

高维矢量表示是将文本、图像等数据映射为数值向量的核心手段，旨在把原始数据的语义或特征投射到高维空间以便计算。然而在实际应用中常出现信息丢失，主要表现在以下几方面。

#### 1. 特征表达的不均衡性
高维矢量的每个维度通常对应某种特征或语义，但各特征的重要性并非均等。例如在300维词向量中，部分维度承载关键语义，其他维度则包含次要或冗余信息，这种不均衡会导致关键特征在降维或聚类中被弱化甚至丢失。

#### 2. 高维空间中的稀疏性与冗余性
随着维度增加，数据点在空间中更趋稀疏，相似性度量的有效性被削弱。同时高维向量常包含冗余特征，即多个维度传递相似信息，干扰模型对语义结构的精准捕捉。

#### 3. 降维方法引入的误差
处理高维向量时常采用PCA或t-SNE等降维技术以简化计算并提升效率，但降维必然伴随信息损失，尤其在高低频特征权衡不当，重要模式可能被忽略，导致模型性能下滑。

#### 4. 嵌入空间的不均匀分布
高维向量的分布并非均匀，可能源于训练数据偏差或模型架构限制。嵌入空间中密集区易过度泛化，语义模糊；稀疏区则难以充分刻画边缘数据的语义。

以新闻分类为例，假设语义嵌入模型用于将新闻映射为向量以进行分类，主题包括体育、娱乐、科技、政治。

模型嵌入后在高维空间可能出现以下问题。

- **密集区域的语义模糊**：若训练数据多来自体育与娱乐新闻，这两类向量在嵌入空间中高度密集。例如“足球比赛新闻”与“电影票房报道”语义关联弱，却因训练偏差距离很近，导致模型区分力下降。结果可能是将体育明星生活报道误分到体育类。

- **稀疏区域的语义难以捕捉**：科技与政治样本不足，其向量分布稀疏且远离密集区。模型难以准确刻画其语义关系，如“AI技术最新进展”因训练数据不足被嵌入到远离科技中心的点，导致分类错误。

#### 5. 维度诅咒的影响
高维数据的复杂性增加计算负担，也削弱欧氏距离等度量方法的效果。随着维度上升，数据点间相对距离趋于一致，相似性判别力下降，进一步加剧信息丢失。

在高维矢量中，每个维度通常对应颜色、形状、语义类别等特定特征，但重要性分布不均，部分维度承载大部分关键信息，其余维度多为次要或冗余信息。

这种特征表达不均衡在高维处理中十分常见。表现为关键特征过度集中，模型在降维、聚类或相似性计算中过度依赖少数维度，而忽视次要维度中可能蕴含的重要信息。
