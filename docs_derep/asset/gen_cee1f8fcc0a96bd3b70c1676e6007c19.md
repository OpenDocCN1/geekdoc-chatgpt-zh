### 4.1 RAG技术体系介绍

本节围绕 RAG 技术展开，梳理其原理、关键模块和工程落地思路。RAG 是一种融合信息检索与大模型生成的智能问答范式，既能提升回答的准确性和信息丰富度，又能有效缓解大模型的幻觉问题，广泛适用于知识库问答、企业智能助手等场景。

本节以搭建本地化 RAG 系统为主线，逐步拆解文本向量化、文档加载与分块、向量库构建、检索策略设计以及大模型问答调用等核心环节，并引入主流 API 模型作为生成组件，帮助理解 RAG 与大模型的协同方式。

#### 4.1.1 RAG简介

大语言模型在生成时容易出现幻觉或偏差，主要表现有：

- 信息误导：生成内容可能源于不准或过时的信息。
- 知识滞后：无法获取最新尤其是专业领域的知识。
- 推理不足：面对复杂推理任务时准确性和效率偏低。

RAG 正为解决这些痛点而生。它先从知识库检索与问题相关的信息，再基于检索结果生成答案，从而显著提升输出的准确性和相关性。该方法还能加快知识更新、增强结果可追溯性，让应用更可靠。

#### 4.1.2 RAG系统的核心组成模块

搭建 RAG 需要 5 个核心模块：

（1）向量化模块：把文档片段转为向量表示，供检索使用。
（2）文档加载与切分模块：读取文档并切分为适于处理的片段。
（3）数据库模块：存储文档片段及其向量。
（4）检索模块：根据用户查询召回相关片段。
（5）生成模块：调用语言模型基于检索信息生成回答。

RAG 系统结构如图 4.1 所示。

由图可得 RAG 的基本构建流程：

- 索引：先把文档库切成较短的 chunk，通过编码器构建向量索引，使文档库具备可检索的向量形态。
- 检索：依据用户 Query 计算与片段的相似度，返回相关文档及其得分。常用 BM25、KNN/ANN 等方法判定相关性。
- 提示：把检索结果与系统 Prompt 拼接，构建完整提示模板，为生成提供上下文。

#### 4.1.3 文本向量化模块创建

在 NLP 与机器学习中，Embedding 是将文本转为数值向量的常用手段，可衡量文本相似性并用于搜索、分类、推荐等任务。OpenAI 推出了第三代 Embedding 模型，在性能、成本和多语言能力上都有提升。下面介绍其特点与调用方式。

##### 1. OpenAI第三代Embedding模型简介

Embedding 本质上是把文本字符串映射为浮点数列表组成的向量，通过向量距离衡量相关性，距离越近相关性越高。

典型应用包括：

- 搜索：按相关性排序结果。
- 聚类分析：依据相似性分组文档。
- 个性化推荐：基于相关内容推荐信息。
- 异常检测：找出相关性较低的异常文本。
- 多样性评估：分析文本集合的相似分布。
- 分类任务：按与标签的相似度归类。

OpenAI 的 text-embedding-3-small 和 text-embedding-3-large 支持更多语言，分别输出 1536 维和 3072 维向量。用户还可通过维度参数在保留语义的前提下优化存储与计算。
