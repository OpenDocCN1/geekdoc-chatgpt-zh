语法约束解码，典型代表是 GBNF，在生成采样时直接把不符合 Schema 的 Token 概率置零，从源头上杜绝格式错乱。

#### 3. 自愈式修复
这是 Agent 与传统 RPC 的本质分野。比如模型输出 `{"date": "2024-02-30"}`，接口会回传错误 “Invalid Date”。编排器把这条错误信息喂回 Prompt，模型据此纠正为合法日期 `{"date": "2024-02-29"}`。

语义路由解决规模问题，结构化强制解决格式问题，自愈式修复解决逻辑问题，三者一起构成了工具编排的护城河。

工具编排正从编程技巧升级为基础设施组件。MCP 的出现标志着 Agent 生态进入互联互通的新阶段。

### 7.3.4 演进与组合：从作坊到工业互联
工具编排的演进，是 Agent 从手工作坊走向工业互联的缩影。接口定义由模糊自然语言走向严格 JSON Schema，最终收敛为通用协议。架构师不再写定制胶水代码，而是维护统一的工具注册表。

#### 1. 演化三阶段：从正则到协议
- MRKL，字符串解析时代。LangChain 2022 年初让模型按 Prompt 输出固定文本如 `Action: Search[Paris]`，再用正则解析。空格多一个、括号少一个就会失败，鲁棒性很差。
- Function Calling，结构化时代。OpenAI 在 GPT-4 2023 年训练阶段引入原生 JSON 输出，模型直接生成符合预设 Schema 的对象。调用稳定性大幅提升，解决了长期困扰落地的格式不一致问题，为现代 Agent 架构奠基。
- MCP，协议互联时代。基于 Anthropic 2024 年发布的 MCP，工具方一次实现标准接口即可被所有兼容 Agent 自动发现并调用。相当于 Agent 工具生态的 USB 通用接口，集成与维护成本显著下降。

#### 2. 组合实战
工具编排是执行层的“手脚”，需与决策层“大脑”或万能工具协同。

- 工具编排与规划—执行模式的组合，形成战略与战术分离，适合复杂数据分析、系统运维。
  - 规划器做宏观决策，例如“先取数、再清洗、最后出图”，定义 What。
  - 编排器做微观落地，例如“取数调用 Query_SQL，清洗调用 Pandas_Lib”，决定 How。
- 工具编排与代码生成①的组合，形成动态工具库。代码执行环境是编排的终极兜底，可拓展 Agent 能力边界，适合注册表里没有现成工具的长尾任务。
  - 编排器在注册表检索未命中。
  - 触发降级，调用代码解释器这一元工具。
  - Agent 动态生成一段 Python 作为临时工具并即时执行。

工具编排成熟后，Agent 不再是困在参数里的“缸中之脑”。依托 MCP 与代码解释器，它有了伸向数字世界的触手，能发现、调用、组合外部能力，甚至自生成新工具，通过 API 主动干预现实，成为真正具备行动力的数字实体。

### 7.3.5 设计哲学：让工具可被 AI 理解
Agent 是单兵，工具编排是工匠的瑞士军刀。

- 工具不仅是 API，更是 Agent 的手与眼。
- 编排不仅是调用，更是选择、参数化与组合的艺术。

工具编排的最大启示是 API 文档的受众变了。过去写给人看，现在必须机器可读。描述模糊，路由器检索不到；Schema 不严谨，模型填错参数。

我们要从 API 优先转向语义优先。架构师除了设计高性能接口，更要打造“AI 能读懂的接口”。这正是 Agent 友好架构的起点。

> ① 代码生成是常见的重要应用，但不属于本书列出的 Agent 设计模式。

## 7.4 自适应策略模式

> “以无法之法为法，以无极之限为限。”
> ——李小龙

> “智能的本质不在于机械地遵循规则，而在于从混沌中演化出秩序。”
> ——黄佳

ReAct、规划—执行、工具编排本质上都是“神创论”架构：工程师扮演上帝，预先写死行为逻辑，代码怎么写 Agent 就怎么跑。

自适应策略模式则是“进化论”产物，见图 7-8。Agent 置于未知环境，通过试错、反馈与选择，逐渐演化出最优决策策略。

进化论的核心要素：
- 基因：策略参数，包括 Prompt 模板、工具选择权重、推理路径。
- 环境：用户请求及外部工具反馈。
- 适应度：衡量策略好坏的奖励信号，如点赞、任务成功率、响应速度。

目标是赋予元认知：不仅执行任务，更学会如何更好地执行。借助强化学习 RL 或多臂老虎机 MAB，Agent 在探索与利用间动态平衡。

### 7.4.1 架构：强化学习闭环
不同于输入—处理—输出的线性结构，自适应策略是一种反馈闭环，见图 7-9。架构师的任务从写业务逻辑转向设计奖励函数。

关键组件：
- 策略网络 Policy Network：决策大脑。可是 MAB 概率表做 Prompt A/B 选择，也可是深度网络决定下一个 Token。
- 环境 Environment：黑盒系统。Agent 通过动作影响它，通过奖励感知状态。
- 奖励模型 Reward Model：评价体系。比如代码运行成功 +1，报错 -1，延迟过高 -0.1。RLHF 中奖励模型来自人类偏好数据；GRPO 等算法中奖励可基于规则或组内相对比较生成。
- 学习器 Learner：演化引擎，按奖励更新策略参数。常用 PPO、DPO、Thompson Sampling 等。

闭环的价值不在于单点聪明，而在于持续改进的因果回路：执行—评估—更新—再执行，Agent 在未知环境中不断修正偏差、优化行为。

### 7.4.2 核心机制
让机器“吃一堑长一智”，要解决探索—利用平衡和奖励稀疏两大难题。

## 1. 探索与利用
- 探索：主动尝试不熟悉策略，短期可能踩坑，长期有望发现更优解。
- 利用：贪婪地选当前最好策略，易陷局部最优，如坐井观天。

常见解法是 ε-Greedy，以 90% 概率选最优，10% 随机尝试，简单但粗放。

更优的是 Thompson Sampling。根据每个动作的后验分布采样，选采样值最高的动作。不确定性越高越值得探索，能自适应调节探索强度，是当前主流策略选择方法。

## 2. 会思考的模型
传统强化学习重对齐，让模型更“听话”；新一代强化学习重推理，增强逻辑思维与问题解决，让模型更“聪明”。

DeepSeek-R1 使用 GRPO，舍弃昂贵的值网络，只依赖最终答案正确性奖励进行策略优化。模型自发习得自我反思、多步验证、思维链回溯等高级推理能力。

这证明即便奖励极度稀疏，模型仍能自我组织出有效中间推理结构。行为并非硬编码，而是在稀疏奖励压力下自然涌现。复杂的认知不需要显式指定，恰当的激励机制即可诱导出。
