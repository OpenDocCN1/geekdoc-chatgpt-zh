## **5.3** **一人指挥多名 AI 助手**

到现在，你手里可能只有一只龙虾在干活。但真实生活里，你同时要兼顾好几个角色：上班的自己、生活的自己，可能还有做副业的自己。把所有摊子都丢给同一只龙虾，记忆很快就会打架。

一个 AI 轮流干完全不相干的事，前一秒在拆财务报表，下一秒要写婴儿餐单，再下一秒去审代码……上下文越堆越多，输出自然越走样。这并不是模型能力不行，而是使用方式出了问题。

更合理的打法是多 Agent 协同：不同任务配不同龙虾，每只只负责自己最拿手的领域，各自保有独立记忆，互不串台，你在上层统一调度。

**Agent 究竟是什么：一个完整的大脑**

在配队之前，先搞清楚 Agent 的定义。一个 Agent 就是一个自成体系的 AI 助手，内部包含独立的组件集合（见表 5-1）。

**三种高频使用模式**

弄懂结构后，可以对照下面三种常见玩法，找到最适合自己的。

**模式一：工作与生活分家**

工作 Agent 接上飞书、企业盘，记住项目脉络，只在办公时间响应。生活 Agent 接微信、连个人文件，记住家庭日程，全天候待命。工作内容不会流进生活对话，生活琐事也不会污染工作记录，这是新手最稳妥的第一步。

**模式二：家庭共享号**

个人 Agent 拥有完整权限，可以执行命令、改文件。家庭 Agent 放在沙箱里，只能读文件、不能跑系统指令。全家人都能用，却不会因误操作破坏重要数据。

**模式三：独立开发者的 AI 小组**

一个人既要做产品、写代码、管运营、回客服，三个 Agent 分工协作，各司其职（见表 5-2）。

**搭建多 Agent 的三大步骤**

说完场景，下面讲落地。配置核心都在 openclaw.json 里面，分三步走。

**第一步：列出 Agent 名单**

在 openclaw.json 的 agents.list 里新增需要的 Agent，每个都要有唯一 id 和独立的 workspace 路径。

{
"agents": {
"list": [
{
"id": "main",
"name": "主助手",
"default": true,
"workspace": "~/.openclaw/workspace"
},
{
"id": "work",
"name": "工作助手",
"workspace": "~/.openclaw/workspace-work",
"model": { "primary": "anthropic/claude-sonnet-4-6" }
},
{
"id": "family",
"name": "家庭助手",
"workspace": "~/.openclaw/workspace-family",
"sandbox": { "mode": "all" },
"tools": {
"allow": ["read", "memory_search"],
"deny": ["exec", "write", "edit"]
}
}
]
}
}

四个核心字段：

● id：唯一标识，后续路由和通信都靠它
● workspace：独立工作目录，Agent 之间必须不同
● sandbox：沙箱模式，用来限制系统访问
● tools：工具白名单/黑名单，精确控制能做什么

**第二步：配置消息路由 Bindings**

Bindings 决定哪条渠道的消息交给哪个 Agent，是多 Agent 调度的核心。

{
"bindings": [
{ "agentId": "main", "match": { "channel":"telegram" } },
{ "agentId": "work", "match": { "channel":"feishu", "accountId": "work" } },
{ "agentId": "family", "match": { "channel":"feishu", "peer": { "kind": "group" } } }
]
}

意思是 Telegram 发给主助手，飞书 work 账号的消息发给工作助手，飞书群聊发给家庭助手。渠道与账号的组合，决定响应者。

**第三步：绑定渠道账号**

不同 Agent 可以挂不同的渠道账号，例如工作助手用公司飞书 Bot，主助手用个人飞书 Bot：

{
"channels": {
"feishu": {
"accounts": {
"main": { "appId": "cli_xxx","appSecret": "xxx", "main": true },
"work": { "appId": "cli_yyy","appSecret": "yyy" }
}
}
}
}

配完后重启网关并检查：

openclaw gateway restart
openclaw agents list

列表里能看到全部 Agent，再测试各渠道消息是否路由正确就算完成。

**AGENTS.md：给每只龙虾写岗位说明**

技术配好后，还要给每个 Agent 写清人设和边界，通过各自 workspace 下的 AGENTS.md 实现。相当于新员工的岗位说明书，包含角色、模型、可用范围、行为限制。下面以独立开发者为例。

AI 协作团队 AGENTS.md 示例：

# AGENTS.md——我的 AI 协作团队

## 角色总览

三个 Agent 各自负责，互不干扰：

## 技术 Agent：Code

**负责范围**：
- 代码编写、评审、重构、排错
- 技术文档与 API 说明
- 架构讨论与技术方案评估

**工作规范**：
- 回答简洁精准，优先给出可运行代码
- 技术不确定时主动说明并给出备选
- 复杂任务默认用 Claude，日常用 DeepSeek

## 运营 Agent：Ops

**负责范围**：
- 用户反馈整理与需求分析
- 更新日志、发布说明撰写
- 数据统计与周报生成

**工作规范**：
- 面向非技术用户，语言通俗
- 优先用表格和要点呈现
- 数据类任务需附来源说明

## 客服 Agent：Support

**负责范围**：
- 用户问答模板生成
- 常问问题库维护
- 退款投诉等敏感建议

**工作规范**：
- 语气耐心友好，避免否定措辞
- 回复先出草稿，经确认后再发出
- 无法判断时提供两个以上方案供选择

此配置覆盖独立开发者全流程：Code 写代码、Ops 管运营、Support 处理客服。同一 OpenClaw 实例，记忆完全隔离。

按渠道投放：Code 走终端直调，Ops 走飞书单聊，Support 走飞书客服群。切到哪个入口，就是哪个 Agent 上线。

[PRE3]

**小贴士**

职责划分越清晰越好，尤其要写明“拒绝处理”的范围，能大幅减少越界插手。

**任务自动分派：说一声它自己派单**

多 Agent 配齐后，还能开启懒人模式：你只需说“帮我做 X”，OpenClaw 根据任务特征自动路由，无需手动指定。

在主 Agent 的 SOUL.md 里加入路由规则：

## 任务自动路由
收到任务后先判断类型再派发：
- 含“代码/bug/函数/接口/架构”等 →交给 Code
- 含“数据/用户/周报/发布/公告”等 →交给 Ops
- 含“用户反馈/投诉/退款/客服”等 →交给 Support
- 跨领域复合任务 →拆解后分别路由

派发后简短提示：“此任务交给[Agent 名]处理”

实际效果：
**用户：**帮我看一下本周新增用户数据，另外登录页有个报错麻烦看一下
[PRE4][PRE5]

**小贴士**

路由规则写在 SOUL.md 里是可随时修改的文本，用一段时间后发现误判，直接改关键词即可。

**同题多视角：让多只龙虾一起答**

多 Agent 还能做同一问题多角度分析，对复杂决策很有帮助。

**用户：**新版本 v2.1 要上线了，主要改动是搜索算法优化、速度提升 40%。请分别从 Code 和 Ops 角度写上线通告
[PRE6]

同一需求同时拿到技术版说明和用户版公告，分场景使用。一个团队，覆盖所有受众。

**Agent 间通信与 Sub-Agent**

默认各 Agent 完全隔离，但有时需要协作，例如工作 Agent 写完周报后让主 Agent 审核。可开启 Agent 间通信：

{
"tools": {
"agentToAgent": {
"enabled": true,
"allow": ["main", "work", "family"]
}
}
}

开启后可说“写好报告后交给主助手审核”，工作 Agent 会自动传递结果。

Sub-Agent 专门处理后台耗时任务，不阻塞主对话。典型场景：
**用户：**帮我调研最新 AI 模型性能排名
**AI：**已启动后台研究任务，完成后会主动通知你，你可以继续聊别的。

Sub-Agent 常配便宜模型省成本：
{
"agents": {
"defaults": {
"subagents": {
"model": "deepseek/deepseek-chat",
"maxConcurrent": 4,
"archiveAfterMinutes": 30
}
}
}
}

核心原则只有一条：边界越清晰，效果越好。不要追求一个 Agent 什么都会，专精永远比全能好用。

**五个实用建议**

**建议一：从两个开始**
先配工作和生活两个，等跑顺再扩容。一次上十个，排查问题会很痛苦。

**建议二：workspace 必须不同**
每个 Agent 路径要独立，建议命名 workspace-work、workspace-family、workspace-ops，清晰好查。

**建议三：家庭 Agent 要限权**
家人共用的 Agent 必须配置 sandbox 和 tools.deny，至少禁止 exec 和 write，避免误删文件。

**建议四：Sub-Agent 用低价模型**
主 Agent 用强模型保证质量，Sub-Agent 用 DeepSeek 或本地 Ollama 控制成本。

**建议五：定期复查路由**
Bindings 乱了会出现工作消息跑到生活 Agent 的隐形问题。建议定期用 openclaw agents list 确认。

**常见问题**

**问题 1：Agent 会互相窥探聊天记录吗？**
不会，Session 完全独立，除非主动开启 Agent 间通信。

**问题 2：多 Agent 会增加 API 费用吗？**
会，调用会叠加，但可通过 Sub-Agent 用便宜模型、不同 Agent 配不同模型来控制，主强副弱是常用省钱法。

**问题 3：如何删除一个 Agent？**
从 agents.list 删除条目，删对应 workspace 文件夹，执行 openclaw gateway restart 即可。

**问题 4：能否共用 workspace？**
技术上可行，但强烈不建议，会导致文件冲突和 Session 混乱。

**记住三点**

一个 Agent 等于一个完整大脑，workspace、认证、Session 全独立。

Bindings 决定谁接收哪条消息。

职责边界要写死，专精比全能更靠谱。

多 Agent 本质是让不同龙虾管不同事。配好后，OpenClaw 从单兵作战升级为团队协作，处理力和体验都会明显提升。

## **5.4** **模型切换省钱指南**

用久 OpenClaw 会发现规律：80% 的日常对话根本不需要 Claude 或 GPT 这类顶级模型，DeepSeek 足够，甚至本地 Ollama 也能应付。

聪明的做法是：简单活儿用便宜模型，复杂任务才上顶级模型。本节教你配智能路由，每月 API 费用至少省一半。

**接入本地模型 Ollama**

Ollama 可在本地 Mac/Linux 跑开源模型如 Llama、Qwen、Mistral，完全免费且隐私可控。接入后可设为默认主力，复杂任务再切线上 API。

配置完成后，普通对话走本地，不消耗额度。

**智能模型路由：按任务自动选型**

手动切换麻烦，可在 ~/.openclaw/openclaw.json 配置自动路由：

{
"models": {
"mode": "merge",
"routing": {
"rules": [
{
"if": "task.type == 'code' || task.complexity ＞ 0.8",
"use": "claude/claude-sonnet-4-5"
},
{
"if": "task.type == 'search' || task.complexity ＜ 0.3",
"use": "ollama/qwen2.5:7b"
},
{
"default": true,
"use": "deepseek/deepseek-chat"
}
]
}
}
}

逻辑：简单查询走本地 Ollama 免费 → 中等任务走 DeepSeek 便宜 → 高复杂度代码走 Claude。OpenClaw 自动判断，无需人工干预。

[PRE8]

**小贴士**

用 openclaw status --usage 查看各模型用量，第一个月对比即可看出节省金额。

**临时指定模型**

不想改配置，可在对话里直接说：
**用户：**用 Claude 帮我改一下这段代码，写完后切回默认模型
[PRE9]

命令行临时指定也行：
openclaw chat --model claude/claude-sonnet-4-5“帮我分析这段代码的性能瓶颈”

## **5.5** **给 AI 上安全锁**

OpenClaw 能操作文件、执行终端命令、发送消息。权限越大，风险越高。进阶用户必须做安全配置，否则一次理解偏差后果很严重。

**沙箱模式——限制活动范围**

沙箱可把龙虾的操作权限锁在指定目录内，只能读写该范围文件，超出圈子无权访问。

# 启用沙箱，仅允许操作 ~/workspace 目录
openclaw config set security.sandbox.enabled true
