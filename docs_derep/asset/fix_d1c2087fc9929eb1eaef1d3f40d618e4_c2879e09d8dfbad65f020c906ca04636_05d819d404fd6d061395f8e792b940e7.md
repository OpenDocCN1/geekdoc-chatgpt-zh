# 第79条征求意见稿三处关键改动

《上海市数据条例（草案）》征求意见稿对第79条做了细化，与现行稿相比主要调整了三点。第一处是在“定期对其数据处理活动开展风险评估”前加上了“按照规定”的限定，为行业针对评估周期和具体做法进行差异化细化预留空间。第二处是把风险报告的接收对象由原来列明的“行业主管部门、市网信部门和公安机关”调整为“依法有关主管部门”，并在主体前加入“依法”，明确报告义务要置于《数据安全法》的制度框架下运行。评估报告应涵盖处理的重点数据类型与数量、数据处理活动开展情形、面临的安全风险及对应的应对举措。第三处是把接收主体统一表述为“有关主管部门”，避免对归口单位作刚性限定，让接收主体的确定能够结合行业特点灵活把握。

## 第八十二条 【公共数据安全管理的特别规定】

市级责任部门应当制定本系统、行业公共数据安全管理制度，并根据国家和本市数据分类分级相关要求对公共数据进行分级，在数据收集、使用和人员管理等业务环节承担安全责任。

属于市大数据中心实施信息化工作范围的，市大数据中心应当对公共数据的传输、存储、加工等技术环节承担安全责任，并按照数据等级采取安全防护措施。

[PRE1]

本条集中规范公共数据安全。先是给市级责任部门设定制度制定的责任，再明确市级责任部门和市大数据中心在公共数据上的安全边界。

[PRE2]

本条的特殊之处在于，它把适用范围收窄到公共数据，把责任主体收窄到市级责任部门和市大数据中心，与条例第79条的数据安全保护一般要求形成对比。

### 一、公共数据的界定

本条是公共数据安全管理的特别条款，也是《上海市数据条例》的亮点。目前《数据安全法》及上位规范并未对“公共数据”作出统一界定，条例第2条予以明确：“公共数据”是指本市国家机关、事业单位，经依法授权具有管理公共事务职能的组织，以及供水、供电、供气、公共交通等提供公共服务的组织，即公共管理和服务机构，在履行公共管理和服务职责过程中收集和产生的数据。定义中包含“国家机关”，因此条例中的公共数据涵盖政务数据，政务数据只是其子集。

### 二、市级责任部门对公共数据安全管理的特别规定

对第1款要把握两点：

第一，“市级责任部门”按条例第26条第1款体系理解，指负责本系统、行业公共数据管理的市级部门，简称市级责任部门。该部门应依据业务职能制定本系统、行业公共数据资源规划，完善管理制度和标准规范，组织本系统、行业数据的收集、归集、治理、共享、开放、应用及相关质量和安全管理。若管理涉及多个部门或责任不清，由市政府办公厅指定。也就是说，有明确规定的按规定确定，未明确或不清的由市政府办公厅指定。

第二，“本市数据分类分级相关要求”对应《上海市公共数据开放分级分类指南（试行）》，并衔接条例第28条公共数据目录管理机制和第29条公共数据分类管理制度。市级责任部门应按市政府办公厅制定的目录编制规范，遵循数据与业务对应的原则，编制本系统、行业公共数据目录，明确来源、更新频率、安全分级、共享开放属性等要素。市政府办公厅负责统筹规划、协调推进、指导监督公共数据安全管理，指导各单位开展目录编制及相关数据的归集、整合、开放、应用。市级责任部门按规范开展数据采集，确保准确、完整、及时，并承担数据质量责任，保证数据适时、真实、准确、完整。最终依据市大数据中心制定的分类规则和标准，对公共数据实施分类管理。

### 三、市大数据中心对于公共数据的安全保护义务

条例中的公共数据关系民生、社会迫切需要与重大公共利益，部分数据还具有显著的产业增值潜力和战略价值，需要更严格的管控。第2款据此明确了市大数据中心的安全保护职责：属于其信息化工作范围的，应当对公共数据的传输、存储、加工等技术环节负责，并依数据等级采取防护措施。

“属于市大数据中心实施信息化工作范围的”尚需细化。贯穿条例的市大数据中心职责包括第27条统一规划大数据资源平台；第29条制定公共数据分类规则和标准，明确不同类别管理要求；第32条负责非公共数据采购；第33条公共数据归集；第34条数据库建设；第35条公共数据质量管理；第39条中断超出必要范围数据的便携共享；第44条对公共数据授权运营实施监督管理；第45条在公共数据授权运营中履行数据安全保护义务。哪些属于实施信息化工作的范畴，须进一步厘清。实施信息化工作是市大数据中心承担安全责任、采取防护措施的前提，边界明确后才能更好地指导合规操作，也为后续追责提供依据。

数据等级可参照《网络数据安全管理条例》（征求意见稿）第5条，按数据对国家安全、公共利益或个人、组织合法权益的影响和重要程度划分为一般数据、重要数据、核心数据，不同级别采取差异化保护。如征求意见稿第9条要求，数据处理者应按网络安全等级保护要求加强系统、传输网络、存储环境的安全防护，处理重要数据的系统原则上应满足三级以上网络安全等级保护和关键信息基础设施安全保护要求，处理核心数据的系统按规定从严保护。

## 第八十三条 【数据安全风险监测预警】

本市按照国家统一部署，建立健全集中统一的数据安全风险评估、报告、信息共享、监测预警机制，加强本地区数据安全风险信息的获取、分析、研判、预警工作。

[PRE4]

本条聚焦数据安全风险监测预警，意在构建风险管控综合机制，提升风险信息管理效能。

[PRE5]

数据安全风险，是指数据遭到篡改、破坏、泄露或者非法获取、非法利用的潜在可能程度与潜在危害程度。

[PRE6]

本条在《网络安全法》《数据安全法》基础上，重申集中统一的风险评估、报告、信息共享、监测预警机制的重要性，以及风险信息获取、分析、研判、预警工作的价值。2017年施行的《网络安全法》确立网络安全监测预警和信息通报制度，要求加强安全信息收集、分析和通报。2021年《数据安全法》第22条在该基础上细化补充，明确国家建立集中统一、高效权威的数据安全风险评估、报告、信息共享、监测预警机制，协调有关部门加强风险信息获取、分析、研判、预警。作为总体国家安全观下的数据安全领域，必须强化国家统筹协调。本条强调“按照国家统一部署”，旨在响应上位法要求，协同构建自上而下、协同一致的数据安全保护体系，提升整体性和全局性的安全保障能力。

### 一、建立健全数据安全风险评估、报告、信息共享、监测预警机制

条例明确“按照国家统一部署，建立健全集中统一的数据安全风险评估、报告、信息共享、监测预警机制”。坚持总体国家安全观、落实《数据安全法》基本制度是核心要求。

集中统一的风险评估机制是后续报告、共享、预警的前提。数据不具备物权法意义上的有体性，数据叠加风险的不确定性，使数据安全具有很强的隐蔽性和复杂性。必须以科学方法客观评估风险，进而采取预防和应急处置。相较于偏重底层架构的网络安全评估，数据安全风险评估更关注数据处理全生命周期的完整性、可用性与可控性，包括风险识别、分析与评价。虽然尚无统一细则，但参考《数据安全法》第30条及条例第81条关于重要数据风险评估的规定，评估一般应包括数据的种类、数量、范围、处理活动情况、面临的风险及其应对措施。

风险报告、信息共享、监测预警应在评估基础上展开。尤其是监测预警，本质是从单一静态向动态实时评估的转变，通过及时反馈实现精准防控。依据《网络数据安全管理条例》（征求意见稿）第56条，未来数据安全信息共享、风险威胁监测预警及事件应急处置仍将置于现有网络安全机制和平台之中。因此，现行网络安全相关信息报告、共享、预警制度及规范性文件、国家标准虽非完全一致，仍具参考价值，如工信部《公共互联网网络安全威胁监测与处置办法》《公共互联网网络安全突发事件应急预案》，以及《信息安全技术网络安全监测基本要求与实施指南》等国家标准。

### 二、加强数据安全风险信息的获取、分析、研判、预警工作

条例进一步强调了风险信息获取、分析、研判、预警的重要性。从《网络安全法》的“加强网络安全信息收集、分析和通报”到《数据安全法》的“加强数据安全风险信息获取、分析、研判、预警”，体现出国家对数据安全风险信息的重视。在数据驱动时代，风险信息来源更广、内容更复杂、时效更紧迫、价值更凸显，有必要从一维搜集转向多维感知、从初步分析转向综合研判、从简单通报转向智能预警。

按获取来源区分，数据安全风险信息主要包括自主监测信息和外部情报信息。工业和信息化领域走在前列，2021年底发布的《工业和信息化领域数据安全风险信息报送与共享工作指引（试行）》（征求意见稿）明确了报送共享概念、工作规程、保障措施等。例如该指引将数据安全风险区分为数据泄露、篡改、滥用、违规传输、非法访问、流量异常等。

总体来看，条例在《数据安全法》第22条指引下，明确“按照国家统一部署”，强化统筹协调、形成研判合力，及时把握本市数据安全整体态势，提升风险处置能力。未来需出台配套法规标准，对风险评估、报告、信息共享、监测预警及风险信息获取、分析、研判、预警等作出细化。

## 第八十四条 【数据安全应急处置】

本市按照国家统一部署，建立健全数据安全应急处置机制。发生数据安全事件，市网信部门应当会同市公安机关依照相关应急预案，采取应急处置措施，防止危害扩大，消除安全隐患，并及时向社会发布与公众有关的警示信息。

[PRE8]

本条明确数据安全事件后的应急处理规程与要求。

[PRE9]

数据安全应急处置，是指在出现数据安全事件时相关负责部门及时采取措施以防止危害扩大，消除安全隐患。

数据安全事件，是指因数据遭到篡改、破坏、泄露、窃取等而对公民个人利益和政治、经济、社会等公共利益产生威胁，需要采取应急处置措施予以应对的情形。

[PRE10]

本条确立数据安全应急处置机制，覆盖事件发生前、中、后的全流程管理。与《数据安全法》第23条相比，条例有两点变化：一是建立健全机制需“按照国家统一部署”；二是启动预案、采取措施的“有关主管部门”明确为“市网信部门会同市公安机关”。

### 一、数据安全应急预案与应急处置的基本概念

应急处置机制是数据安全管理制度的重要环节。完全消除风险不现实，因此数据处理者及主管部门应防患于未然，做好事件发生前、中、后的全生命周期管理。数据安全事件指数据因篡改、破坏、泄露、窃取等对个人利益和公共利益构成威胁，需应急应对的情形。参照《突发事件应对法》及《国家网络安全事件应急预案》，可按事件性质、严重程度、社会危害、影响范围等建立分级，并据此构建响应分级体系，实现全流程管控，降低影响和危害。

事件发生前，应做好预案并强化演练。国务院办公厅《突发事件应急预案管理办法》规定，应急预案为依法、迅速、科学、有序应对突发事件而预先制定的工作方案，遵循统一规划、分类指导、分级负责、动态管理原则。数据安全应急预案不同层级侧重点不同，省级专项和部门预案侧重组织指挥机制、信息报告要求、分级响应及行动、资源保障与调配程序、市县级政府职责等，确保省级应对行动规范并具指导性。预案还应开展演练评估，分析合理性和可操作性，形成完善预案、应急准备、应急机制、应急措施的建议，并实现动态优化、科学规范管理。作为总体国家安全观下的数据安全，应急处置同样需“按照国家统一部署”，构建自上而下、协调一致的机制。

### 二、数据安全事件发生后的应急处置措施

事件发生后，有关主管部门应依预案采取处置措施，防止危害扩大、消除隐患。参照《国家网络安全事件应急预案》《公共互联网网络安全突发事件应急预案》，应急处置可分为先行处置、事件报告、响应分级、事态跟踪、决策部署、应急结束等环节，具体因响应级别而异。本条将《数据安全法》第23条中的“有关主管部门”明确为“市网信部门会同市公安机关”，依据《数据安全法》第6条及条例第5条，本市个人信息保护、网络数据安全及相关监管由市网信部门统筹协调，市公安机关在职责范围内承担监管职责。

这并不免除数据处理者的应急义务。依据条例第78、79条及《数据安全法》第27、29条，数据处理者作为责任主体，应在日常管理中建立健全全流程安全管理制度和技术保护机制；事件发生时，应立即处置、按规定告知用户并向主管部门报告。把数据处理者的保障责任与部门监管职责深度融合，有利于构建全方位、多层次、立体式应急处置体系，确保事件后处置快速、稳定、高效、精准。
