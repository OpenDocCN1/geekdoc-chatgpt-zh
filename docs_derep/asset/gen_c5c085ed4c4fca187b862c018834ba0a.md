<h1>Nginx + Flask 混合部署全流程实战</h1>

想让一个轻量站点既能快速托管静态资源，又能稳定提供动态接口？下面用 Nginx 做入口分发，Flask 负责业务处理，手把手演示从零搭建到性能验证的完整链路，顺带展示一个模型推理的扩展思路。

先看下最终接口返回的样貌，Flask 的 /api/hello 会以 JSON 形式回应：
[PRE0]

{
    "message": "Hello from Flask!"
}

浏览器或 curl 发起请求后，Nginx 的访问日志就会留下类似记录，可以用来快速确认路由是否命中：
[PRE1]

127.0.0.1 - - [01/Dec/2024:10:00:00 +0000] "GET /api/hello HTTP/1.1" 200 33 "-" "curl/7.68.0"

环境准备阶段，先把 Nginx 安装到位，保持系统包最新再执行安装：
[PRE2]

sudo apt update

sudo apt install nginx -y

服务装好后启动并设为开机自启，同时检查运行状态是否正常：
[PRE3]

sudo systemctl start nginx

sudo systemctl enable nginx

sudo systemctl status nginx

静态文件先放进统一目录，index.html 和一份基础样式先创建出来：
[PRE4]

sudo mkdir -p /var/www/html/static

echo "<h1>欢迎访问 Nginx 静态内容</h1>" | sudo tee /var/www/html/static/index.html

echo "body { background-color: lightblue; }" | sudo tee /var/www/html/static/style.css

在 nginx.conf 里增加一个 server 块，用 location /static 指向刚才的目录：
[PRE5]

server {

    listen 80;

    server_name localhost;

    location /static {

        root /var/www/html;

        index index.html;

    }

}

改动生效需要重启服务：
[PRE6]

sudo systemctl restart nginx

动态侧使用 Flask，先装依赖：
[PRE7]

pip install flask

一个最简的应用示例，/api/greet 返回欢迎信息：
[PRE8]

from flask import Flask, jsonify

app = Flask(__name__)

@app.route('/api/greet')

def greet():

    return jsonify(message="欢迎访问 Flask 动态内容!")

if __name__ == '__main__':

    app.run(host='127.0.0.1', port=5000)

本地启动调试：
[PRE9]

python app.py

接下来让 Nginx 把 /api 的请求反向代理到本地 5000 端口，静态与动态统一入口：
[PRE10]

server {

    listen 80;

    server_name localhost;

    location /static {

        root /var/www/html;

        index index.html;

    }

    location /api {

        proxy_pass http://127.0.0.1:5000;

        proxy_set_header Host $host;

        proxy_set_header X-Real-IP $remote_addr;

    }

}

重启后生效：
[PRE11]

sudo systemctl restart nginx

这时访问 /api/greet 能得到如下 JSON：
[PRE12]

{
    "message": "欢迎访问 Flask 动态内容!"
}

为了可维护性，把静态、动态区块加上注释，并配置错误与访问日志：
[PRE13]

server {

    listen 80;

    server_name localhost;

    # 静态内容

    location /static {

        root /var/www/html;

        index index.html;

    }

    # 动态内容

    location /api {

        proxy_pass http://127.0.0.1:5000;

        proxy_set_header Host $host;

        proxy_set_header X-Real-IP $remote_addr;

    }

    error_log /var/log/nginx/error.log;

    access_log /var/log/nginx/access.log;

}

生产环境需要进一步调优，以下是针对高并发的事件模型、缓存与压缩配置片段：
[PRE18]

worker_processes auto;              # 自动调整工作进程数，通常为 CPU 核心数

events {

    worker_connections 4096;         # 每个工作进程最大连接数

    use epoll;                      # 高效的事件驱动模式，适用于 Linux

    multi_accept on;                # 同时接受尽可能多的新连接

}

http {

    include /etc/nginx/mime.types;

    default_type application/octet-stream;

    sendfile on;                    # 启用零拷贝文件传输

    tcp_nopush on;                  # 提高大文件传输效率

    tcp_nodelay on;                 # 减少小文件传输延迟

    keepalive_timeout 15;           # 长连接超时时间，设置为 15 秒

    keepalive_requests 100;         # 每个长连接允许的最大请求数

    gzip on;                        # 启用 Gzip 压缩

    gzip_types text/plain application/json text/css application/javascript;  # 压缩的文件类型

    gzip_min_length 1024;           # 压缩的最小文件大小

    open_file_cache max=1000 inactive=20s;      # 缓存打开的文件句柄

    open_file_cache_valid 30s;                  # 文件缓存有效期

    open_file_cache_min_uses 2;                 # 仅缓存被使用两次以上的文件

    log_format minimal '$remote_addr [$time_local] "$request" $status';

    access_log /var/log/nginx/access.log minimal;   # 自定义精简日志格式

    server {

        listen 80;

        server_name localhost;

        location / {

            root /var/www/html;

            index index.html;

        }

        location /api {

            proxy_pass http://127.0.0.1:5000;

            proxy_set_header Host $host;

            proxy_set_header X-Real-IP $remote_addr;

            proxy_cache cache_zone;             # 启用代理缓存

            proxy_cache_valid 200 10m;          # 缓存 200 响应 10 分钟

        }

    }

    proxy_cache_path /tmp/nginx_cache levels=1:2 keys_zone=cache_zone:10m max_size=100m inactive=60m;  # 配置缓存

}

如果要把动态接口扩展到模型推理，先安装依赖：
[PRE21]

pip install transformers torch

以下代码演示加载中文分词器与序列分类模型，并在 CPU 或 CUDA 上运行一次推理：
[PRE22]

from transformers import AutoTokenizer, AutoModelForSequenceClassification

import torch

# 检查 CUDA 是否可用

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

print(f"当前设备: {device}")

# 1. 加载预训练模型和分词器

model_name = "bert-base-chinese"

print(f"加载预训练模型和分词器: {model_name}")

tokenizer = AutoTokenizer.from_pretrained(model_name)

model = AutoModelForSequenceClassification.from_pretrained(

    model_name, num_labels=2).to(device)

# 2. 定义示例文本

text = "这个产品非常好，我很喜欢！"

print(f"输入文本: {text}")

# 3. 文本编码

print("将输入文本转化为模型输入格式...")

inputs = tokenizer(text, return_tensors="pt", padding=True,

                   truncation=True, max_length=128).to(device)

print(f"编码后的输入: {inputs}")

# 4. 模型推理

print("开始推理...")

with torch.no_grad():

    outputs = model(**inputs)

    logits = outputs.logits
