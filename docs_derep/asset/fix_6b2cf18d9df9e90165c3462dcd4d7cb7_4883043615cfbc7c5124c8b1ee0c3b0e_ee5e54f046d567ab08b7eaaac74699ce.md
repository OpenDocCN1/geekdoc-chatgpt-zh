在受限网络的虚拟环境中拉取 OpenAI 及其依赖包时，代理的设定是关键准备。下面先说明如何通过命令行设定 HTTP/HTTPS 代理，再用 pip 按指定版本安装 OpenAI 并按需补充其他包的整体思路。

需要代理的环境下安装流程大致如下：

1. 打开终端或命令行窗口。
2. 配置 HTTP 与 HTTPS 代理，执行：
set HTTP_PROXY=http://YOUR_PROXY_IP:YOUR_PROXY_PORT
set HTTPS_PROXY=https://YOUR_PROXY_IP:YOUR_PROXY_PORT
3. 将 YOUR_PROXY_IP 和 YOUR_PROXY_PORT 替换成实际使用的代理地址和端口号。
4. 执行安装命令：
pip install openai==0.28.1
5. 根据需求，可用类似的 pip 命令补充安装其他相关库。

完成以上设置后，就能在代理环境下顺利完成 OpenAI 库的安装。

### 4.1 检索增强生成全景解读
本小节围绕检索增强生成展开，梳理其运行机理、组成单元以及工程落地思路。它把信息检索与大模型生成结合，形成一种智能问答范式，既能让答案更准确、更丰富，也能降低大模型产生虚构内容的风险，常用于知识库问答、企业智能助手等场景。

接下来以搭建本地化系统为线索，逐步拆解文本向量化、文档读取与分块、向量库构建、检索策略设计以及模型问答调用等核心环节。同时会引入主流 API 模型作为答案生成组件，帮助读者理解框架与大模型的衔接方式。

#### 4.1.1 检索增强生成概念速览
大语言模型在生成时容易出现偏差，主要表现有：

- 内容失真：生成结果可能基于错误或过时的知识。
- 知识滞后：无法触达最新信息，尤其在专业领域更明显。
- 推理乏力：面对复杂推理任务时，效率和准确度不足。

为应对这些问题，检索增强生成应运而生。它先从知识库检索与问题相关的信息，再基于检索结果生成回复，从而显著提升输出的准确性和相关度。该方法还能加速知识更新并增强可追溯性，使方案在实际应用中更可信、更实用。

#### 4.1.2 检索增强生成系统核心单元拆解
实现一个检索增强生成系统通常需要 5 个关键单元。

1. 向量化单元：把文档片段映射为向量表示，为后续检索做准备。
2. 文档读取与切分单元：负责读取原始文档并切分为便于处理的片段。
3. 存储单元：保存文档片段及其对应的向量表示。
4. 检索单元：根据用户输入的查询检索出相关的文档片段。
5. 生成单元：调用语言模型基于检索信息生成回答。

- 推理：在此阶段使用大语言模型基于完整提示进行推理，生成问题的答案，随后做后处理优化输出质量和准确性。

这几个单元共同构成简易检索增强生成的核心骨架，各自在检索到生成的不同阶段发挥作用，保证查询处理的连贯性。

#### 4.1.3 文本向量化模块构建
在自然语言处理和机器学习领域，Embedding 是把文本映射为数值向量的常用手段。通过向量，模型可以度量文本间的相似性，并用于搜索、分类、推荐等任务。OpenAI 已推出第三代 Embedding 模型，在性能、成本和多语言支持上均有提升。下面介绍该系列模型的特点与调用方式。

##### 1. OpenAI 第三代 Embedding 模型概述
Embedding 是一种把文本字符串表示为浮点数列表的技术，通过比较向量间的距离来判断文本相关性，距离越近相关性越高。

常见应用包括：

- 搜索：按相关性对结果排序。
- 聚类分析：依据文本相似度分组。
- 个性化推荐：基于相关内容推荐信息。
- 异常检测：找出与整体相关性低的异常文本。
- 多样性评估：分析文本集合的相似度分布。
- 分类任务：根据文本与标签的相似度归类。

OpenAI 的 text-embedding-3-small 与 text-embedding-3-large 性能更高，支持更多语言，分别输出 1536 维和 3072 维向量。用户还能通过设置维度参数在保持语义的前提下优化存储与计算开销。
