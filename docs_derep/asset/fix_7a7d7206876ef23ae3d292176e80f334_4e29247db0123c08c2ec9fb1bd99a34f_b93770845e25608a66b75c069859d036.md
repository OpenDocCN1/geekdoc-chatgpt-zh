#### 2. 记忆检索机制

用户发出新消息时，需要从长期记忆里调取相关片段来提升回复的贴合度。召回过程大致可拆成四步。

(1) 查询生成：依据当前发言构造检索用的查询表达。
(2) 相似度测算：评估查询与已存储记忆的相似程度。
(3) 排序筛选：按相似度打分排序，挑选最相关的片段。
(4) 上下文融合：把检索到的记忆与本次对话串接起来。

落地时常会组合多种技术以提升效率与精度。

- 关键词粗筛：直接做关键词命中，适用于记忆体量较小的情形；
- 向量相似度：先用嵌入模型把文本转为向量，再计算余弦相似；
- 图上遍历：在知识图谱上扩散，定位到与当前话题相关的实体和关系。

综合使用这些手段，就能在海量记忆里快速锁定与本次对话最相关的信息，作为上下文输入给模型。

### 6.3.3 Function Call 在 Agent 中的应用

Function Call 是大语言模型的一项关键能力，它允许模型生成结构化的函数调用请求，而不仅是自由文本。在 Agent 记忆模块中，Function Call 可帮助我们实现更精确的记忆操作，如存储、检索和更新记忆。

#### 1. Function Call 的工作原理

可以类比人类的“思考—行动”过程。做事时先思考调哪个函数、参数怎么填，再执行。模型模拟的就是这一流程。

具体流程包括：

1. 函数声明：先给出可用函数及参数格式。
2. 模型判读：根据上下文判断是否需要调用函数及调用哪个。
3. 参数填充：按函数定义生成合法参数值。
4. 函数执行：系统执行函数并返回结果。
5. 结果融合：把执行结果融入对话继续生成。

在 OpenAI 的方案里，Function Call 通过 tools 参数传入模型，模型会返回一个 tool_calls 字段，携带函数名和参数，如图 6-1 所示。
