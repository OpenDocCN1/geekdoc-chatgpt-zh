**3. MCP 服务端日志监控**

日志是排查问题的关键依据。MCP 服务端基于 Python 运行，采用标准 logging 模块记录运行状态与事件。合理利用日志可以追踪行为、调整输出粒度，并在生产环境实施监控。说明如下。

1）日志记录器

通过 logging.getLogger 可获取根记录器或模块记录器。用它们记录关键信息，是跟踪与调试的常规做法。

[PRE3]

2）日志输出位置

通常情况下，服务端的日志由 logging 在本地记录并展示。

（1）调试模式下使用 mcp dev 命令启动 stdio 传输时，标准输出会被 MCP Inspector 捕获，并在 Inspector 界面左侧日志区实时呈现，便于观察。

（2）直接用 python/uv/uvx 或 mcp run 启动时，日志会输出到终端控制台。

（3）采用 HTTP 远程传输启动时，日志同样出现在服务端终端控制台。

（4）必要时可将日志导向文件或集中式日志系统，默认不会自动落盘，需要手动重定向或配置。

3）向客户端推送日志

依据 MCP 规范，服务端可通过通知机制把关键日志推送给客户端，走远程 notifications/message 方法，由客户端自行处理，例如在界面展示。这样既能看到工具调用结果，也能了解中间过程。MCP 还允许客户端调用服务端的 logging/setLevel 方法动态修改日志级别。

6）日志分析

除自定义输出外，MCP SDK 在处理请求时也会记录关键步骤。例如收到 tools/call 请求，会记录：“INFO- Processing request of type ListToolsRequest”，随后记录调用了哪个工具、是否成功、返回结果或异常。若工具代码抛出未捕获异常，SDK 也会输出完整 traceback 方便排错。生产环境定期审阅错误日志有助于预防问题扩大，并可据此触发告警。

总体而言，养成查看日志的习惯能大幅提升 MCP 服务端开发与运维效率。开发期借助 MCP Inspector 与控制台日志，上线后通过文件或系统日志监控运行状态，才能迅速定位并解决问题。

## **基于 SDK 开发客户端**

实际应用中，客户端通常是大模型所在的宿主应用，如 VS Code Copilot、聊天机器人、智能体等。本节介绍客户端开发方式。你可以不使用 SDK，直接通过 HTTP 接口调用服务端，或使用官方 MCP SDK 简化开发。

这里的客户端指完整客户端，可对应官方架构中的 MCP Host。

## **4.1 用 Python 库模拟客户端**

MCP 规范基于 JSON-RPC 2.0 实现客户端与服务端通信，无论是 stdio 还是 HTTP，核心都是传输 JSON 请求和响应。因此掌握原理后，理论上可不依赖 SDK，直接通过 HTTP 或 stdio 与服务端交互。

在学习 SDK 前，本节引导你仅用 Python 基础通信库，通过 HTTP 或 stdio 发送符合 MCP 规范的 JSON-RPC 2.0 消息，调用服务端开放的功能，以工具调用为例演示。

这部分不强制学习，但能加深对交互机制的理解，更好地使用 SDK。
