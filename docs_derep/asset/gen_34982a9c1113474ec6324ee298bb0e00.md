这条指令会依据 `docker-compose.yaml` 的编排描述，自动从指定的镜像源拉取全部依赖的服务镜像，并在后台完成容器的创建与启动。

第4步要做的就是核验服务是否正常起来。

[PRE1]

把所有关联容器的一并查看运行情况，确认状态都显示为 `Up` 或 `Running`。

[PRE2]

第5步则是打开 Dify 平台。待全部服务就绪后，就可以用浏览器访问 Dify，前端入口通常由 `.env` 里的服务域名或可达 IP 配合端口决定。默认情况下 Dify 会监听 80 与 443 端口。

[PRE3]

部署途中容易碰到的潜在风险与排查思路。端口被占用时，需要修改 `.env` 或 `docker-compose.yaml` 更换端口；Docker 权限不足，要保证当前账号具备执行 Docker 命令的权限，且 Docker 守护进程对宿主机映射的数据卷目录拥有正确的读写权限；服务器算力不够时，应检查 CPU 内存磁盘占用情况，考虑升级硬件或做优化；镜像拉取失败，多半是网络不通或未配置镜像加速器；数据库初始化失败或连不上，往往源于 `.env` 中的数据库凭据与 `docker-compose.yaml` 不一致、数据卷目录权限错误或磁盘空间耗尽；后端 API 无法连接数据库或 Redis 缓存，则要细看 `.env` 里的连接参数是否准确，以及服务间网络是否连通。通读各容器启动日志，是解决这些问题的关键抓手。

#### 10.1.1 应用类型的选择

点击“创建应用”后，Dify 通常提供几种针对不同交互模式的预设类型供挑选。常见类型包括聊天助手、文本生成应用、智能体、对话流和工作流。

- (1) 聊天助手：最常用的对话交互类型，基于大模型的轮次对话能力，适合客服机器人、智能伙伴等场景。
- (2) 文本生成应用：面向创作类任务，如写故事、生成摘要、文本分类或翻译，更偏重单向文本生成。
- (3) 智能体：更高级的类型，可拆解复杂任务、进行推理并调用外部工具与现实世界交互。
- (4) 对话流：适合需要定义复杂多轮对话流程的场景，强调记忆与上下文管理，通常可视化编排实现。
- (5) 工作流：侧重自动化、批处理等单轮任务，如批量文本处理、按固定流程生成报告，也可视化编排实现。

选对类型是后续设计的基础。对初学者而言，从“聊天助手”或“文本生成应用”入手，能快速熟悉 Dify 的交互与提示词设计。

Dify 的可视化逻辑编排画布是其产品创新的核心。它提供所见即所得的图形化工作区，通过拖拽、连接与参数配置，清晰地设计、构建和管理 AI 应用运行时的内部流程。

Dify 编排画布中常见的核心节点类型在前章已介绍，这里回顾实操意义。

- 1. “开始”节点：定义流程起点与核心输入变量，如用户查询。
- 2. “LLM”节点：与 DeepSeek 等模型交互的关键处，用于配置提示词模板与模型参数。
- 3. “知识检索”节点：实现 RAG 的核心步骤，从关联知识库中检索相关信息。
- 4. “工具”节点：连接外部 API 与服务的执行器，让智能体具备行动能力。
- 5. “条件分支”节点：依据变量值或大模型输出判断，实现流程的智能分叉。
- 6. “代码执行”节点：进行数据处理、转换或执行简单代码片段。
- 7. “结束”节点：标志流程终点与最终输出结果的定义。

#### 10.2.2 有效运用指令、变量与上下文管理

在可视化编排画布中，“LLM”节点里的提示词模板设计是构建 AI 应用最核心也最具灵魂的部分。它决定了如何与 DeepSeek 模型交互，直接影响模型能否准确理解意图并生成期望的高质量输出。

编写提示词模板时，首先要在节点中输入核心指令内容。可借用前序章节的提示词工程实践：明确设定模型角色，例如你是一位专业的某领域顾问；下达清晰具体的任务指令，例如请分析以下文本并提取关键信息；提供必要的背景或约束条件，例如基于公司最新规定；若适用可加入高质量的少样本示例，例如输入：[示例 A] 输出：[期望结果A]，并明确指定期望的输出格式，例如请以 JSON 格式返回结果。
