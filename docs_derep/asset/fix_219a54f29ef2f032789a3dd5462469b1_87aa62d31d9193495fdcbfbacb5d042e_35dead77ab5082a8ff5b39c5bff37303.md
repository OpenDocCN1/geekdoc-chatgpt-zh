## 6.2.2 Skills：给Agent装上渐进加载

5.1.4 节已介绍 Skills 的设计初衷。Skills 本质上是一种按需载入的知识库。在大型项目里，若把所有文档、规范和最佳实践一次性塞入系统提示，不仅会迅速耗尽上下文窗口，还会混入大量噪音。渐进式加载机制很好地解决了这一矛盾。

为控制实现复杂度，本节仅演示 Skills 的加载流程。基于 6.1.2 节的代码，仅针对 SKILL.md 实现一个两级渐进加载方案。

整体设计拆为两层：

第一层在代理启动初始化时，扫描指定 Skills 目录，读取每个 Skill 下 SKILL.md 的元数据。
第二层在处理具体业务时，一旦判定需要某个特定 Skill，就通过调用 `load_skills` 工具读取该 Skill 的完整 SKILL.md 内容。

下面开始实现。

### 1. 构建一级加载流程

需要一个 `SkillLoader` 类来负责目录扫描与 SKILL.md 元数据的解析，元数据采用 YAML Frontmatter 格式。

具体实现与说明如下。

[PRE9]

该实现采用面向对象的方式封装技能管理逻辑，核心由三个方法构成，对应加载的不同阶段。

（1）`_load_all()` 负责递归扫描与索引构建。代码第15、16行先校验 `skills_dir` 是否存在。随后借助 pathlib 的 `rglob()` 递归查找所有名为 “SKILL.md” 的文件。对每个文件读取内容并调用 `_parse_frontmatter()` 分离元数据与正文。解析结果存入 `self.skills` 字典，键取元数据中的 `name`，若为空则回退到文件夹名，值包含 `meta`、`body` 与 `path`。一级加载主要关注 `meta`，但 `body` 也一并读入内存以免后续重复 IO。

（2）`_parse_frontmatter()` 负责元数据解析。采用正则 `^---\n(.*?)\n---\n(.*)` 精准匹配 Markdown 开头的 YAML Frontmatter，`re.DOTALL` 使点号可匹配换行。若格式不符，函数返回空元数据字典并把全文作为正文，保证健壮性。解析时按行拆分再以冒号分隔键值，实现轻量级 YAML 解析。

（3）`get_descriptions()` 用于导出 Skills 描述。该方法遍历 `self.skills`，提取每个 Skill 的 `description` 与 `tags`，整理为人类与模型均可读的列表文本。
