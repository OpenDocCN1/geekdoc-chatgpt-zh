# 启发式引导的 k+1 循环测试生成模型与不可达路径特征分析

## 核心算法：启发式引导的 k+1 循环处理策略

针对前文讨论的循环嵌套难题，本节给出一套名为“启发式引导的 k+1 循环处理模型”的算法实现。该模型的核心在于混合使用符号执行与动态执行，专门用于生成覆盖循环体内目标节点的测试用例。

模型名称中的各要素含义如下：
*   **k**：对目标循环 `L_target` 进行 k 次展开的符号执行；
*   **1**：对目标前循环 `L_before` 与目标后循环 `L_after` 采用一次动态执行，获取部分可达路径；
*   **启发式**：引入目标函数，指导 `L_before` 内的动态执行倾向于选择更靠近目标的路径；
*   **+**：将上述策略融合，实现对目标可达路径的增量式构建。

为提升运行效率，算法引入**预处理阶段**，一次性完成主宰节点到目标节点的距离计算。完整流程如下：

### 算法流程详解

**预处理阶段**  
全程扫描控制流图（CFG）识别所有循环结构，并标记出目标循环 `L_target`。随后反向遍历 CFG，获取目标节点 `t` 的主宰节点集合 `S_t`，并计算该集合内所有节点到 `t` 的距离集合。

**步骤 1：入口搜索与循环分发**  
从程序入口出发，沿 CFG 进行符号执行搜索，同步收集路径约束。每新增一个逻辑约束，即调用求解器校验可满足性；若不可满足，判定路径不可达并回溯。搜索过程中一旦遇到循环入口，根据循环类型分流：
*   若为 `L_target`，跳转至**步骤 3**；
*   若为 `L_before`，跳转至**步骤 2**。

**步骤 2：启发式动态执行穿越 `L_before`**  
此步骤旨在获取 `L_before` 内既可达又可能通往目标的路径。利用步骤 1 积累的前置路径约束，通过求解器生成多组测试用例并动态执行，捕获执行轨迹。所有轨迹在入口至 `L_before` 入口段拥有相同前缀，随后在循环内部随机探索分支。  
关键在于**排序筛选**：依据预处理阶段计算的节点距离（算法 5-1），对轨迹按路径距离升序排列。距离越小，说明轨迹越接近目标。选取距离最小轨迹在 `L_before` 内的路径片段作为前缀，返回**步骤 1**继续搜索。

**步骤 3：目标循环 `L_target` 内的符号执行深搜**  
在 `L_target` 内开启全路径符号执行搜索，确保覆盖到达目标 `t` 的路径。针对嵌套循环的复杂情况，采取递归策略：
*   遇到 `L_before`：跳转**步骤 2**；
*   遇到 `L_target`：递归执行**步骤 3**；
*   若在预设展开上限 `k` 内未找到含 `t` 的路径：回溯至上一回溯点尝试其他分支；
*   若在 `k` 次展开内成功获得含 `t` 的可达路径：携带该部分路径进入**步骤 4**。

**步骤 4：动态执行补全 `L_after` 路径**  
利用步骤 3 得到的部分可达路径对应的测试用例，直接通过动态执行获取目标节点之后的完整路径，从而拼凑出覆盖目标的完整可达路径。

符号执行进入 `L2` 全路径搜索。目标位于 `a[0]%3==0` 真分支。第一次展开条件不成立，第二次展开成功得到部分可达路径，约束为 `(n>2) ∧ (n≤3) ∧ (max%2 ≠0) ∧ (a[0]%3=0)`。求解器给出测试用例 `({-4, 6, 7, ...}, 3)`，实际执行即覆盖目标的完整可达路径。

## 聚焦难点：基于代码片段与反向符号执行的不可达路径判定

### 背景与动机

程序中的**不可达路径**指任意输入均无法触发的执行轨迹。循环结构导致路径爆炸式增长，不可达路径随之激增，严重拖累静态分析精度与效率——例如在自动测试生成中，大量无效路径消耗资源，导致覆盖率难以达标。

主流判定手段是符号执行过程中的约束可满足性检查。按分析方向分为：
*   **正向符号执行**：从入口出发，顺控制流生成路径并判定可达性。
*   **反向符号执行**：从指定目标点出发，逆控制流搜索判定。

**核心痛点**：不可达本质是约束矛盾（CSP 问题），而 CSP 不可判定，不存在通用高效算法。现有技术（矛盾片段识别、约束求解、动态执行等）效果深受程序结构、约束类型、搜索策略影响。

**典型场景对比**（参考 P. Dinge 工作 [10]）：  
若路径末尾两个谓词矛盾（如 `y>0` 与 `y==0`），正向分析需遍历完整长路径才能发现冲突，极易超时；反向分析从目标点出发，**即可瞬间捕获矛盾**。路径越长，优势越明显。

[PRE2]

**结论**：不可达路径特征决定了最优判定策略，但现有研究缺乏对“特征-策略”映射关系的系统探索。本章将重新定义判定问题，归纳路径特征，挖掘程序结构与不可达路径的关联，给出适配的判定技术。

### 问题重定义：精准建模不可达路径

*   **路径定义**：路径 `p` 由节点序列 `n1...nk` 及控制流边组成，`k` 为长度。
*   **定义 5-4 (可达路径)**：存在输入 `v ∈ D` 使执行轨迹与 `p` 一致。等价于路径约束 `Cp` 可满足 (`Cp ⊨_D v`)。
*   **定义 5-5 (矛盾约束)**：路径约束 `Cp = φ1 ∧ ... ∧ φk`。若 `p` 不可达，则 `Cp` 在域 `D` 上无解，记为 `Cp ⊨_D ⊥` (后文省略 `D`)。
*   **定义 5-6 (矛盾位置)**：不可达路径 `p` 中，存在子式 `φi ∧ ... ∧ φj` 不可满足 (`i ≤ j ∈ [1, k]`)。称 `j` 为矛盾触发位置。**若 `k-j < i-1`，反向分析比正向分析更早发现矛盾。**

下节将通过调研，统计不可达路径上矛盾约束的位置分布特征。

### 核心模式：依赖循环的等值代码片段

#### 1. 基础概念铺垫

*   **循环结构**：`L = (EL, NL, inL, outL)`，对应 CFG 中的有向环。
*   **定义 5-7 (数据依赖)**：节点 `ni` 与 `nj` 对同一内存位置存在读写交集 (`R∩W`, `W∩R`, `W∩W` 不为空)，记为 `ni ↔ nj`。
*   **定义 5-8 (数据传播)**：赋值语句 `v = expr(y)` 表示 `y → v`，具有传递性。
*   **定义 5-9 (条件依赖)**：两条件节点 `ni`, `nj` 间路径 `p` 上，若无赋值且读变量集交集非空，或有赋值且变量经传播关联，则存在条件依赖。这反映了不同上下文中约束对同一变量的关联约束。
*   **定义 5-10 (主宰循环)**：节点 `n` 的所有主宰节点中包含某循环 `L` 的入口与出口，则 `L` 为 `n` 的主宰循环。意为：通往 `n` 的每条路径必完整经过 `L`。
*   **定义 5-11 (独占节点)**：循环 `L` 内节点 `n`，若从 `inL` 到 `n` 的所有路径要么不经过任何循环，要么完整包含另一循环 `L'` 的入口出口。见图 5-10 示意。
*   **定义 5-12 (等值判定条件)**：条件节点 `n` 的逻辑式含 `v = N` 形式（`N` 为常量）。C 语言典型形式见表 5-1（如 `v==N` 真分支、`v!=N` 假分支、`if(v)` 假分支、`switch case N`）。求解器常对此类约束专项优化。

#### 表 5-1 C 语言等值判定条件速查

| 代码表达式 | 约束形式 (分支条件) |
| :--- | :--- |
| `if(v == N)` | 真分支: `v = N` |
| `if(v != N)` | 假分支: `v = N` |
| `if(v)` | 假分支: `!(v!=0)` 即 `v=0` |
| `switch(v) case N:` | 每个 `case N`: `v = N` |

#### 2. LDc² 模式正式定义

**定义 5-13 (依赖循环的等值代码片段 / LDc²)**  
设 `L` 为循环，`n` 为等值判定条件节点。若满足：
1.  **控制流前提**：`L` 是 `n` 的**主宰循环**，**或** `n` 是 `L` 的**独占节点**；
2.  **数据流关联**：`L` 内存在节点 `n_l` 与 `n` 存在**数据依赖**或**条件依赖**；
3.  **纯净性约束**：`L` 内**无** `n` 中变量的重定义（重定义会破坏内存位置一致性，违背依赖定义）。

则称 `L` 与 `n` 构成 **LDc² 模式**。

**模式语义**：
*   **主宰循环/独占节点** → 保证从入口到 `n` 的路径必经 `L`，路径可达性由 `L` 主导。
*   **数据/条件依赖** → `L` 内操作直接影响 `n` 的约束变量值。
*   **无重定义** → 变量身份在循环内保持稳定，依赖链完整。

图 5-11 列举多种拓扑结构，满足条件的标记 `√`，不满足（如非主宰循环 `L_4`, `L_5`）标记 `×`。

**核心猜想**：包含 LDc² 模式的程序中，等值判定条件 `n_c` 极易引发矛盾路径约束，**且矛盾恰在 `n_c` 处被触发**。这为针对性判定（如反向符号执行切入点选择）提供了理论锚点。
