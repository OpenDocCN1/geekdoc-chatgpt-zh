第六项 train_batch_size 用 “auto” 让系统自动推算全局训练批次大小；第七项 train_micro_batch_size_per_gpu 也是 “auto”，由框架自行决定单卡微批量；第八项 wall_clock_breakdown 设为 false，关闭各阶段训练耗时明细的输出。这几项共同决定了 DeepSpeed 在 ZeRO 优化配合 BF16 混合精度下的运行行为，核心目标是提升训练效率与性能。

### 3.3.3 ZeRO 第三阶段配置全览
ds_config_zero3.json 同样是 DeepSpeed 的 JSON 配置文件。它开启 BF16 混合精度训练，采用 AdamW 优化器并搭配 WarmupLR 学习率调度，同时针对 ZeRO 第三阶段做了细化设定：包括参数与优化器卸载、通信重叠、梯度连续等，还涉及梯度累积步数、梯度裁剪、打印间隔、训练批次大小等参数。
[PRE0][PRE1]

### 3.3.4 ZeRO 二三阶段核心差异
在 DeepSeek MoE 项目里，ds_config_zero2_no_offload.json 对应 ZeRO Stage 2，ds_config_zero3.json 对应 ZeRO Stage 3。两者在内存优化深度和策略上存在明显差异。

**1. ZeRO Stage 2 ds_config_zero2_no_offload.json**
● 优化范围：对优化器状态和梯度进行分片，显存占用可降至约 1/8，通信开销与数据并行度基本不变。
● 配置特点：zero_optimization.stage 设为 2，未启用参数或优化器状态的卸载，所有数据保留在 GPU 显存中。

**2. ZeRO Stage 3 ds_config_zero3.json**
● 优化范围：同时分片优化器状态、梯度和模型参数，内存节省幅度随数据并行度线性增长。以 64 卡为例，显存可降至约 1/64，代价是通信量会相对增加约 50%。
● 配置特点：zero_optimization.stage 设为 3，并开启参数与优化器状态的卸载到 CPU，进一步降低 GPU 显存压力。

总体来看，相较 ds_config_zero2_no_offload.json，ds_config_zero3.json 通过更激进的内存优化能支撑更大规模模型训练，但也带来了更高的通信成本和实现复杂度。

## 3.4 模型微调实战
本项目中的 finetune.py 提供了一套完整工具链，用于对 DeepSeek MoE 预训练语言模型进行微调。支持指定任务数据加载、预处理编码，并可通过 LoRA 量化、分布式训练等配置选项实现高效训练。用户可按需用命令行参数或配置文件调整策略，优化模型在特定任务上的表现。

### 3.4.1 微调底层技术
finetune.py 主要依赖两项技术对预训练模型进行微调。

● LoRA 技术：在 MoE 模型的 q_proj、v_proj、k_proj、o_proj 等特定层插入低秩矩阵，用少量可训练参数调整模型行为，避免全量微调带来的灾难性遗忘和高计算成本。
● 量化技术 4/8-bit：把模型权重从 32-bit/16-bit 浮点转为 4-bit 或 8-bit 低精度格式，大幅减小 GPU/CPU 内存占用，让资源受限设备也能开展后续训练。

具体实现流程如下。
（1）模型加载与配置
根据配置加载预训练 MoE 模型，bits 参数决定是否进行量化；启用 flash_attention_2 或 optimized 注意力实现以提升计算效率；若开启 LoRA，则按配置初始化 LoRA 模块并作用于目标模块 trainable.split(',')。
（2）数据加载和预处理
使用 load_dataset 加载训练数据；通过 train_tokenize_function 完成指令提示构建、分词和标签预处理。
（3）训练准备
将预处理后的数据集交给 Trainer，并配置学习率、批量大小、梯度累积步数等；使用 DataCollatorForSupervisedDataset 对输入和标签进行收集与格式化。
（4）训练过程
借助 Hugging Face Trainer 执行训练，支持从检查点恢复；训练中采用 BF16 或 FP16 混合精度加速计算并降低内存占用。
（5）模型保存与推理
训练过程中通过 SavePeftModelCallback 回调定期保存 LoRA 适配器权重；训练结束后保存模型状态或调用 safe_save_model_for_hf_trainer 将权重安全写入指定目录。

### 3.4.2 提示构建函数
build_instruction_prompt() 用来生成包含指令和响应格式的提示文本。函数接收字符串参数 instruction，返回多行字符串，内含预设上下文说明、指令区和响应区模板，并把传入的 instruction 填入指定位置形成完整提示。
[PRE2][PRE3]

### 3.4.3 模型参数类
ModelArguments 数据类用于配置微调参数，涵盖可训练参数列表、LoRA 相关设置、需保存模块、是否使用 LoRA、预训练模型路径、注意力实现方式、是否双量化、量化数据类型与位数等配置，便于在微调中灵活调整。
[PRE4][PRE5]

### 3.4.4 数据路径类
DataArguments 数据类用于指定训练数据位置，包含字段 data_path 保存训练数据路径。
[PRE6]

### 3.4.5 训练超参类
TrainingArguments 继承自 Hugging Face transformers.TrainingArguments，用来配置训练超参数，如缓存目录、优化器类型、模型最大序列长度等，控制训练全流程。
[PRE7][PRE8]

### 3.4.6 PEFT 回调保存
SavePeftModelCallback 是自定义回调，与 Hugging Face Trainer 配合使用，在训练过程中仅保存 PEFT 模型的适配器权重而非整个基础模型，从而节省存储并提高加载效率。训练结束时会创建 completed 文件标记训练完成。

在 PEFT 微调中，正确保存加载适配器权重至关重要。按照 Hugging Face 建议，保存时只需保留适配器权重。通过实现该回调，可确保适配器权重被正确保存，并在训练结束时生成完成标记。
[PRE9]

### 3.4.7 定位最新 checkpoint
get_last_checkpoint() 用于获取指定目录中最新的检查点。先检查目录是否包含 completed 文件，若存在则认为训练已完成返回 None；否则遍历以 checkpoint- 开头的子目录，取编号最大者返回；未找到则返回 None。
[PRE10]

### 3.4.8 安全保存函数
safe_save_model_for_hf_trainer() 的主要作用是将 Trainer 中的模型安全保存到指定目录。保存前把模型 state_dict 从 GPU 迁移到 CPU 释放显存，再调用 Trainer._save 方法写入输出目录，确保分布式或混合精度训练下模型能正确保存，避免内存问题。
[PRE11][PRE12]

### 3.4.9 单批分词函数
_tokenize_fn() 对一批输入字符串进行分词，并返回分词后的 ID 序列及长度信息。通过 tokenizer 将文本转为模型可理解的 ID，并提供长度信息供后续训练推理使用。
[PRE13]

### 3.4.10 源目标预处理
preprocess() 实现对源文本和目标文本的预处理，为训练准备结构化输入与标签。核心是将源文本和目标文本拼接后分词，并把源文本部分标签设为 -100 即 IGNORE_INDEX，使模型训练时只对目标文本部分进行预测。
[PRE14][PRE15]

### 3.4.11 监督数据整理器
DataCollatorForSupervisedDataset 类用于在监督微调中把多个数据实例整理为模型所需批量格式。主要功能是将 input_ids 和 labels 转为张量并做 padding 保证维度一致，同时生成 attention_mask 标识有效输入位置。
[PRE16]

### 3.4.12 训练数据切分函数
train_tokenize_function() 用于对训练数据进行分词和预处理。接收 examples 和 tokenizer，examples 包含指令与对应输出。函数先调用 build_instruction_prompt 为每条指令构建提示文本，然后在输出后拼接 EOT_TOKEN。随后对提示与输出分词，并通过 preprocess 转为适合训练的格式，最终返回包含输入 ID 和标签的字典。
[PRE17]

### 3.4.13 模型构建函数
build_model() 根据参数构建并配置模型，支持量化和 LoRA。
● 计算数据类型：依据 training_args.bf16 决定使用 torch.bfloat16 或 torch.float16。
● 加载预训练模型：使用 AutoModelForCausalLM.from_pretrained 加载，根据 model_args.bits 决定是否做 4 位或 8 位量化；启用 LoRA 时需配置量化参数如双量化。
● 设置模型属性：将 model_parallel 和 is_parallelizable 设为 True 支持并行化，并按 bf16 设置 torch_dtype。
● LoRA 配置：若启用 LoRA 且量化位小于 16，则调用 prepare_model_for_kbit_training 准备 k-bit 训练；若提供检查点目录则加载 LoRA 适配器，否则初始化 LoRA 并配置目标模块、秩、dropout、alpha 等。
● 层数据类型转换：遍历模型各层，按需转为 bfloat16 或 float32。
● 返回模型。
[PRE18][PRE19][PRE20]

### 3.4.14 主训练流程
train() 是 DeepSeek MoE 项目的主训练函数，负责完整的微调流程。先加载数据并完成分词预处理；构建模型时应用 LoRA 和量化以优化显存占用；训练中采用梯度累积、动态损失缩放等技术，并通过检查点机制支持断点续训；训练结束保存权重供后续评估或推理。

具体实现流程如下。
（1）解析命令行参数：使用 HfArgumentParser 将参数解析为 ModelArguments、DataArguments、TrainingArguments 实例。
（2）设置日志：按训练参数日志级别配置 logger，并启用默认处理器和格式。
（3）加载分词器：用 AutoTokenizer.from_pretrained 加载预训练分词器，设置最大序列长度、填充方向、是否使用快速分词器等。
（4）加载模型：调用 build_model 构建并配置模型。
（5）加载训练数据：使用 datasets.load_dataset 加载数据集，按路径和缓存目录配置。
（6）数据预处理：用 train_tokenize_function 完成指令提示构建、分词和标签处理。
（7）数据收集器：创建 DataCollatorForSupervisedDataset 实例整理数据格式。
（8）初始化训练器：用 Hugging Face Trainer 初始化，传入模型、分词器、训练参数和数据组件。
（9）添加回调：若启用 LoRA 则加入 SavePeftModelCallback 保存适配器权重。
（10）开始训练：调用 trainer.train 开始训练，可从检查点恢复。
（11）保存训练状态：训练结束后调用 trainer.save_state 保存模型权重、优化器状态等。
（12）保存模型：若未启用 LoRA，则调用 safe_save_model_for_hf_trainer 将权重安全保存到指定目录。
