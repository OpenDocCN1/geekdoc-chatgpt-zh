# 第7章 Harness 实战：Claw 类产品架构拆解

在近期 AI 技术社区里，OpenClaw（中文社区常称“龙虾”）是讨论热度极高的开源项目。无论是开发者还是 AI 爱好者，都在各自设备上“养虾”，探索这只“龙虾”能进化到什么程度，并感受 AI 助手深度融入日常工作的便利。

从技术视角看，OpenClaw 的成功在于精准卡位用户接口层。通过接入飞书、钉钉等即时通信 IM 软件，它把 Agent 变成了一名 7×24 在线的数字员工。用户只需私聊或在群里 @ 它就能下达指令。更巧妙的是，OpenClaw 内置定时任务机制，Agent 可以自主为自己安排未来的工作计划并按时执行，摆脱了必须实时触发的限制。

这种始终在线且自主调度的设计，正是 Harness 工程理念的典型体现。本章将由浅入深拆解其工程实现。

## 7.1 Claw 类产品的核心架构

在阅读源码前，先厘清这类项目的通用构建范式。

### 7.1.1 入门路径：先从 NanoClaw 开始

第6章拆解了 Claude Code 的核心机制，提炼出一个关键公式：现代 Agent = Coding Agent + Skills。

OpenClaw 展现出的办公自动化能力，比如写 PPT、回邮件、整理晨报，并非原生自带，而是依托内部封装的 Code Agent 实现，该 Agent 基于 Pi 框架。OpenClaw 更像一层功能外壳，在核心 Agent 之上封装了任务编排、并发调度、定时任务和 IM 通信协议等基础设施。

但 OpenClaw 代码量高达 40 万行，对初学者不友好。因此建议从精简版 NanoClaw 入手。NanoClaw 用 NodeJS 编写，代码量约 4000 行，约 35 000 个 Token。极简设计让开发者能把完整源码一次性喂给 GLM-5 等支持 200k 上下文的大模型，让模型全盘掌握上下文，大幅降低理解与二次开发门槛。

### 7.1.2 NanoClaw 的内外双层结构

NanoClaw 的架构可概括为内外两层：内层是运行在 Docker 容器中的核心 Agent，外层是负责 IM 通信与定时调度的 Claw 机制。NanoClaw 架构示意如图7-1 所示。

图7-1 NanoClaw 架构示意

#### 1. 容器内部执行层

NanoClaw 将核心 Agent 放在 Docker 容器中，形成系统内层。

容器内，Agent 基于 Claude Code 官方提供的 Agent SDK 实现了一个持续运行的 Loop。Loop 不断检查 IPC 输入目录，一旦发现新任务消息就立即读取、处理并产出结果，然后继续等待下一个任务，循环不止。

除 Agent Loop 外，容器内还能集成浏览器等工具及一系列 Skills，如文件系统操作、代码执行等，使 Agent 具备网页浏览、文件读写等复杂能力。

为何要放进容器？答案是安全隔离。把 Agent 限制在沙箱中运行，即便执行危险操作，如误删文件或向群聊发送垃圾信息，后果也只局限在容器内部，不会波及宿主机。

#### 2. 容器外部管理层

如果把容器内视作执行层，容器外就是 NanoClaw 的管理层。正是这一层把普通的 Code Agent 转变为始终在线、可通过 IM 交互、能自动执行定时任务的数字员工。容器外系统包含 8 个模块，概览如表7-1 所示。
