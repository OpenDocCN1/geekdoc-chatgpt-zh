**DIKWP 白盒测评：让大模型采购从模糊到可量化**

◎ **可做验收标准：**借助 DIKWP 白盒测评所输出的客观评估，采购方与供应商能够就性能达成一份透明、好执行的指标协议。合同不再只笼统约束“总准确率”或“综合得分”，还能明确到 DIKWP 各子维度的底线要求。

本质上，DIKWP 白盒测评不只是测评方法，更是一种认知分析框架。它推动我们从多层视角拆解大语言模型的真实水准。在此框架下，可搭建一套分层、多维的题库，把贴近业务的真实测试用例归入数据、信息、知识、智慧、意图五大范畴，以此作为能力衡量支架，逐步刻画出模型的能力画像。

### **10.1.2** **测评流程**

结合 DIKWP 白盒测评，机构可遵循一套标准化的操作路径，实现采购、优化、验收、反馈的闭环运转。每一步都有明确目标和方法，逐层推进。

**1.** **黑盒测评初筛**

在进入白盒环节前，多数机构仍会先用传统黑盒方式对市场上可选的大模型做快速筛选，尤其候选数量较多、来源分散时。

◎ **黑盒测评工具：**常见的问答正确率测试、通用 NLP 任务如翻译摘要的评分、分类检索效果评估等。以这些指标快速剔除基础能力不足或功能缺失的模型。

◎ **优点：**上手快、对比直观，成本低，能迅速压缩候选池。

◎ **局限：**看不到模型在不同认知阶段的具体表现；进入深度定制阶段后，诊断和指导会显得不够细。

因此黑盒测评的核心价值在于快速淘汰，为后续的 DIKWP 白盒深度分析准备一个更小、更精准的模型集合。

**2.** **DIKWP 白盒测评**

筛选出具备基础能力的模型后，即可启动白盒测评，共涵盖以下维度。

◎ **数据→信息：**检验模型能否从原始数据如文本、表格中提炼关键信息或结构化要素。政务场景可让模型阅读公告并抽取发布单位、时间、政策要点；金融场景可让模型处理交易记录并识别买卖方、金额、日期等。

◎ **信息→知识：**评估模型能否对信息进行归纳总结，形成稳定知识表征。例如阅读多段相关文本后梳理要点，或基于一组案件资料归纳共同规律，检验整合与逻辑联结能力。

◎ **知识→智慧：**考察模型能否将已有知识灵活运用于复杂情境的推理决策。医疗场景可让模型结合多名患者的病史分析症状并建议下一步检查或治疗；制造场景可让模型依据产线数据进行故障预测与处置建议。

◎ **智慧→意图：**衡量模型在多目标情境下能否准确理解并协调用户或业务需求，完成更具决策性的任务。智能客服需兼顾满意度与合规性；营销策略制定需在不同产品线、预算等约束下给出可行方案。

◎ **层内一致性（数据→数据，信息→信息，知识→知识，智慧→智慧，意图→意图）：**关注同一层级的连续操作是否自洽。例如数据→数据测试同一批原始数据多次抽取是否一致；信息→信息测试同一文本多次归纳的稳定性；知识→知识测试对同一知识库关联点的引用是否连贯；智慧→智慧测试多轮对话中推理的延续性；意图→意图测试不同上下文下同一意图的执行策略是否稳定。以此衡量内在一致性与鲁棒性。

最终结果常以雷达图或能力矩阵呈现，直观展示五大层面及细分模块的得分、排名或定性评价。相比黑盒仅给一个综合分数，DIKWP 白盒测评能让采购方一眼看到模型的优势区、短板区，以及与业务需求的匹配点，为后续定制指明方向。

**3.** **优化目标制定**

有了白盒测评结果，优化方向会更精准。

◎ **信息→知识能力不足（能抽取不会用）：**模型能抽数据却难以整合为可用知识时，需加强阅读理解与知识建构类微调数据，或补充相关领域语料，强化归纳总结。

◎ **知识→智慧能力不足（推理逻辑弱）：**知识储备尚可但综合应用易错，说明推理链或逻辑处理有漏洞。可通过链式思维提示、逐步推理训练数据来补强。

◎ **智慧→意图能力不足（难理解需求）：**若模型难以捕捉隐性需求或不按规范执行任务，需在指令跟随与对齐训练、RLHF 等方面加码。金融医疗等高合规场景尤为关键。

制定目标时应把能力要求写进需求文档或开发合同，并量化。例如“知识→智慧推理正确率提升至 75% 以上”“意图→意图一致性测试错误率不超 5%”。这样避免供应商空谈概念而缺乏实质交付。

**4.** **定制化优化与微调**

明确改进模块后进入深度协同优化阶段。

◎ **数据增强：**数据→信息或信息→知识表现不佳时，可用高质量专有数据提升感知与整合能力。如法律咨询可标注案例文本，电商客服可收集常见问答对话。需注意安全与隐私，尽量在内网沙箱或私有云完成。

◎ **架构改进：**针对特定短板可做结构级升级，如引入强化记忆模块、接入外部知识库 API 或检索组件。能力增益明显但会提升实现与维护复杂度。

◎ **提示工程：**通过优化指令与对话设计激活模型潜在推理能力。对知识→智慧或智慧→意图的失误，可让模型展示中间推理步骤或补充场景背景，引导出更准确结果。

在此阶段，DIKWP 白盒测评既指导方案制定，也提供迭代验证。小范围改动后即可复测对应模块，效果提升则方向正确，否则需重新定位问题。

**5.** **交付验收**

优化完成后需正式验收。传统验收多看综合准确率、F1、BLEU 等黑盒指标。如今更倾向在合同中约定白盒指标，要求模型在数据、信息、知识、智慧、意图各能力项上达标。例如：

◎ **“数据→信息”信息抽取准确率≥90%：**在多条政务公告中抽取负责人、部门、政策要点等信息，保证正确率。

◎ **“知识→智慧”投资策略推理能力≥80 分：**在金融分析题中，模型能否基于已有知识给出合理策略并解释推理过程。

◎ **“智慧→意图”合规对齐度≥85%：**面对合规敏感问题，能否严格遵循监管要求，对不当请求拒绝或提示风险。

验收团队用 DIKWP 白盒题库对模型复测，核验各模块是否满足合同阈值，未达标则需继续修复直至交付。这种透明可量化的验收大幅降低了采购风险，也倒逼供应商重视质量与安全。

**6.** **持续反馈与优化**

大模型不是一次性交付品，而是持续进化的智能体。数据分布、用户需求、法规环境都会变化，需周期性跟踪与迭代。

◎ **定期复测：**建议每季度或半年做一次全量白盒测评，关注新增功能或新场景下的稳定性。

◎ **新问题收集与回溯：**上线后收集用户真实反馈，将新出现的输入类型归入相应层级的挑战，进行针对性分析。

◎ **自动化监控与告警：**对大规模应用可建自动化监测，一旦发现高置信度错误或场景性能骤降，自动触发白盒诊断脚本，及时止损。

由此形成“测评-开发-验收-再测评”的良性闭环，每一步都在数据、信息、知识、智慧、意图的框架下推进。

## **10.2** **机构采购 LLM 的关键考量**

选型与定制 LLM 不仅要看模型能力，还需权衡数据安全、投入成本、可扩展性。DIKWP 白盒测评可辅助做出平衡决策。

### **10.2.1** **数据安全**

数据安全与隐私合规是机构选型的首要关切。政府企业掌握大量敏感信息，引入 LLM 时必须防止泄露滥用。

一方面，若选用第三方闭源云服务，需评估供应商隐私政策与安全机制，签署严格保密协议，必要时要求本地私有部署。另一方面，自行基于开源模型微调，可在内网完成训练，保持数据可控。段玉聪团队的研究显示，在数据不出域前提下进行领域微调，既保隐私又提升专业适配。

除了训练数据泄露，还需关注模型对敏感信息的处理。白盒测评可检测模型是否不当复现训练语料中的隐私。利用意图层评估，可检验模型对“不应回答”请求的拒绝能力，了解其安全边界管理。例如意图识别测试中，若模型对隐私探询无警惕直接作答，则判定不合格，需对齐训练修正。

◎ **训练数据的保密：**开源微调需对内部敏感数据做脱敏与权限管控。DIKWP 的数据→信息层可测试模型是否会无意暴露内部信息。

◎ **推理过程的合规：**运行阶段模型是否可能泄露训练片段。可通过意图→意图层白盒测试，检验权限与合规意识，对不当请求及时拒绝或预警。

◎ **供应商合规能力：**采购闭源模型需考量其隐私保护能力与本地部署支持，合同中明确泄露后的追责与应急条款。

### **10.2.2** **成本控制**

LLM 部署与定制涉及许可费用、算力投入与运维开销，需衡量投入产出。

首先从架构层面评估模型规模。并非所有场景都需要超大模型，中小规模模型配合精细微调即可满足需求。段玉聪团队的 DeepSeek 优化采用混合专家 MoE，提升效率并降低推理参数占用，对预算有限的场景很友好。

其次，数据标注与获取成本很高。DIKWP 白盒测评可避免盲目大规模标注。通过精准定位短板，资源集中投向关键能力。例如法律推理弱，只需增强案例解析与法条应用数据，避免在无关领域浪费。

最后考虑运营成本。参数量小的精调模型或蒸馏压缩模型可降低日常推理成本。DIKWP 框架下的知识蒸馏能在保留多层能力的同时减小模型体积。开源社区活跃度高、无许可费用，长期成本更低，但需投入内部优化人力。采购者需在买商业模型与自建开源能力间权衡。

◎ **算力与规模选择：**白盒结果若显示高层推理需求不高，可选择中小模型节约成本。

◎ **迭代式优化：**通过白盒定位弱点，避免“广种薄收”。少量高质量数据针对信息→知识层短板即可实现有效提升。

◎ **部署模式：**算力要求低的可本地化部署，减少云租用费；高负载场景可采用弹性伸缩，按需增减资源。白盒揭示的真实需求有助于合理取舍。

### **10.2.3** **可扩展性**

可扩展性包含能力扩展与系统扩展两层含义。前者指模型能否随需求演进而升级，后者指系统能否随用户增长平稳扩容。

能力扩展方面，业务会不断产生新知识、新语言、新工具需求。闭源模型需确认供应商更新频率与插件支持。DIKWP 视角下，可扩展模型应具备模块化架构，知识与推理组件分离，新知识接入无需重训全模型。段玉聪团队提出知识可迁移、主题专家化思路，有助于模块化管理。

系统扩展方面，模型需应对更高并发与多模态负载。应明确硬件依赖与分布式推理支持，如张量并行、流水线并行等。扩展往往伴随成本上升，需权衡收益。

白盒测评可评估扩展后的认知稳定性。例如接入新知识库后，知识层表现是否稳定提升；高并发下信息→信息一致性是否可靠。及时发现扩展带来的性能波动并调整。

◎ **模型能力扩展：**未来若需在知识→智慧层做高级推理，可提前评估模型是否易于接入外部知识库或持续微调。

◎ **系统部署扩展：**用户激增时系统能否弹性扩容、负载均衡。白盒测试可评估高并发下智慧→智慧、意图→意图的一致性，预判极端压力表现。
