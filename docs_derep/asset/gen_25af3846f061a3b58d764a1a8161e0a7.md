### 3.2.1 目录规范

咖哥在白板坐标旁写下一个典型 Skill 的目录。

“这就是那只‘牛’的构造。”他逐条拆解。

[PRE1]

这些细节看似繁琐，其实是工程里用血泪换来的防错设计。

文件名：SKILL.md 是唯一触发器。必须全大写，skill.md、Skill.md、SKILL.MD 都不认。加载器扫文件时做的是精确字符串匹配，不是模糊搜索。

目录名：kebab-case，是跨平台通用语。只能用全小写加短横线，如 api-doc-generator，最多 64 个字符，字符集限制为 [a-z0-9-]。禁止空格、下划线、大写、首尾横线和连续横线。为抹平系统差异，Windows 不区分大小写，Linux 严格区分，kebab-case 保证在任何环境都能被无损识别。

禁入 README.md——保持指令空间纯净。Skill 目录内不能放 README.md，人类文档放父目录即可。激活时 Claude 会贪婪读取目录下所有 Markdown 作为上下文，SKILL.md 是给 Claude 的指令，README.md 是给人看的说明，两者混在一起会引入噪声，干扰理解。

命名中立：拒绝品牌词。name 字段里不能出现 claude 或 anthropic。Skill 是一种开放的知识封装格式，保持品牌中立才能让知识流动，而不是绑定某个产品。

### 3.2.2 YAML 头信息：Skill 身份卡

SKILL.md 顶部的 YAML Frontmatter 定义了身份与行为边界，完整字段可归为三组，对应设计的三条主线：触发、权限、运行。

[PRE2]

身份字段，触发机制：name、description、argument-hint。说明 Skill 是什么、用来干嘛、怎么调用，是触发的基础。

权限字段，权限控制：disable-model-invocation、user-invocable、allowed-tools、model。规定谁能调用、能做什么，通过限制调用来源、可用工具和模型划定安全与资源边界。

执行字段，运行时环境：context、agent、hooks。决定在哪里执行、执行过程如何展开，用来配置隔离环境、子智能体类型和生命周期钩子，保证任务在预期上下文中运行。

掌握这三条主线，就掌握了 Skill 架构的设计框架。

> 咖哥发言

disable-model-invocation 和 user-invocable 很容易混，实际控制的是两个正交方向。disable-model-invocation: true 表示 Claude 不能自动触发，必须由用户用 /skill-name 手动执行。适合有副作用或高风险的操作，比如 /commit、/deploy，确保用户显式确认。默认值是 false。

user-invocable: false 表示 Skill 不会出现在 / 菜单里，用户无法手动触发，但 Claude 仍可在内部逻辑中自动调用。适合纯知识型或辅助型参考 Skill，隐藏菜单减少干扰，同时保留自动加载能力。默认值是 true。

默认配置下，Skill 对 Claude 和用户都是双向开放的。

### 3.3.2 description 预算限制

渐进披露的第一层是所有 Skill 的 description，它以常驻方式注入上下文，必须瓜分一个有限预算，形成系统瓶颈。

官方规则：description 总预算上限为上下文窗口的 2%，未指定或计算异常时默认固定 16000 个字符。预算由全部已安装 Skill 平分，不是按需分配。

单个 Skill 可用字符数 = 总预算 / Skill 总数

装 20 个 Skill 时，默认 16000 字符下平均每个 description 只有 800 字符，见图 3-4。

[PRE4]

若某个 description 超过 800 字符，它会被静默排除。Claude Code 完全感知不到该 Skill，既不会在扫描阶段看到，也无法后续加载。对用户来说，Skill 就像消失了。

避坑有三招。技巧 1，在配置里设 disable-model-invocation: true，该 Skill 的 description 不会被注入上下文。技巧 2，跑诊断命令 /context，可查看是否有 Skill 被静默排除。技巧 3，通过环境变量 SLASH_COMMAND_TOOL_CHAR_BUDGET 手动扩预算池。

这揭示了工程哲学：不要堆 Skill，要做少而精的架构。超过 20 个 Skill 通常是信号，需要重审策略：

合并同类项，把碎片 Skill 合成一个综合体；隐藏内部工具，把纯内部调用子任务标记为 disable-model-invocation: true，减少预算占用；用 Token 投资回报率思维看待 description，每个字符都很贵，投得准才换来高效检索和准确执行，投得浪费不仅浪费自己配额，还挤占别人的生存空间。

## 3.4 触发逻辑：Claude 何时启用 Skill

触发机制是整个系统最关键的一环，比内容本身更重要。触发不了，再好的内容也无效。

### 3.4.1 两种激活方式

每个 Skill 都有两条激活路径。

1. 显式调用
用户在对话输入 /skill-name，Claude Code 立刻加载执行，像终端命令一样明确无歧义。若定义了 argument-hint，还可带参数，如 /commit fix login bug 或 /review src/auth/login.ts。

2. 语义匹配
Claude 理解意图后自主判断哪个 Skill 最匹配，然后自动加载。这是日常核心价值：用户只描述需求，Claude 幕后决策调用与否、怎么调用，过程透明，实现所想即所得。
