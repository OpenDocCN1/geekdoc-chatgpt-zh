# 第6章 智能体——生成式AI应用的主流形态

第5章已初步提到智能体的基本概念。智能体是生成式AI应用的主要形态，面对不同需求要选用不同类型的智能体实现。本章将介绍几种典型实现，并探讨如何构建自定义智能体。

### 6.1 智能体实现概述

可以把智能体视作存在于计算机世界里的“人”，它能在特定环境中执行任务。要实现具备某种特定能力的智能体，它需要的能力与现实世界中具备相同能力的人类相似。具体来说，智能体不仅要有基础的计算与处理能力，还要具备感知、决策与行动能力，以应对复杂多变的环境。此外，它还必须具备学习与适应的能力，以便在未知或变化情况下调整行为策略。人类能力与智能体能力模型的相似性，为设计与开发提供了有价值的参考框架，使其能更好地模拟和替代人类在特定任务中的表现。

人类之所以拥有智力，根源在于更发达的大脑。因此构建智能体时，最核心的一环是赋予它生成式AI模型提供的语义理解与推理分析能力，作为智力基础。

一个人的智力水平不仅取决于逻辑分析推理能力，还与知识储备即记忆能力紧密相关。同理，智能体也必须具备相应的记忆能力，以支撑复杂认知活动。

人类做决策和行动时，通常要通过特定器官感知环境要素的状态或变化，据此制定决策，再通过特定器官采取相应行动，这些行动往往会改变环境要素。对应到智能体，为实现与环境的有效交互，它需要一套功能完备的工具，用于从环境获取有价值的数据，或对环境施加影响改变要素状态。

此外，人类面对不同问题时会采用不同的思考模式和策略。智能体也应具备同样灵活性，在推理过程中根据具体问题特点和需求选择并应用适当的思维模式，以确保结果准确有效。

综上，构建智能体需要强大的推理分析能力作为智力支撑，还需要记忆能力、与环境交互的工具以及灵活多变的思维模式，具备这些能力的智能体才能模拟和实现人类智力的多样性和复杂性。在计算机领域，这些构成部分分别对应大语言模型LLMs、记忆系统Memory、工具Tools以及规划Planning，它们协同构成完整的智能体。其整体结构如图6-1所示。

## 6.2 智能旅行规划助手——ReAct 型智能体

ReAct型智能体是当前应用最广泛的类型之一，其运作规则遵循“推理后行动”的原则。通常实现过程如下。

首先智能体会对当前环境进行感知和分析，收集所有可能影响决策的外部信息。接着通过内置算法或模型对这些信息进行处理或推理，从而生成适当的行动策略。这一步通常涉及大量数据分析和复杂推理，以确保行动策略的准确性和有效性。最后智能体据此采取相应行动，不断适应环境变化并实现预定目标。

ReAct型智能体强调在任何行动前必须充分推理和分析，以提高决策科学性和合理性。该类智能体广泛应用于机器人、自动驾驶、智能客服等领域，表现出典型的优越性。

实现ReAct型智能体过程中，最关键的是如何高效进行信息处理与推理，这通常依赖先进的人工智能算法和强大计算能力。在本书示例程序中，这些能力由生成式AI模型及工具共同提供。通过不断优化推理过程和行动策略，ReAct型智能体能够持续提升性能和适应性。

### 6.2.2 提示词

提示词对智能体的行为影响极大，提示词的优劣在很大程度上决定了智能体完成任务的可能性和质量。

一般而言，为生成式AI模型预先设定一个明确的角色身份，有助于模型从该角色的独特视角或专业能力出发更精准地解决问题，甚至借助该角色的专业能力完成任务。倘若任务存在通用的解决流程或思路，将其一并写入提示词传递给模型，也能进一步提升效率与准确性。

因此为智能旅行规划助手编写的提示词可以采用如下文字作为开篇。

> 你是强大的AI出行助手，可以使用工具与指令自动化解决问题。

你首先应当使用对应工具查询天气信息，然后使用对应工具查询城市景点信息。

最终综合考虑天气对出行的影响、城市景点信息及用户的出行需求，给出最终出行日程安排。

如前文所述，规划旅行行程时为有效从外部环境获取所需信息，智能体需要借助搜索引擎、天气预报等工具的支持。为此构建提示词时，应当详尽列出所有备选工具及其功能说明，以确保模型清晰知晓可用工具及其功能，从而在恰当时机选择合适的工具进行信息检索或查询。随后应用程序将执行模型选定的工具，并把执行结果反馈给模型。

以下提示词简要说明了哪些信息需借助工具获取。然而列举工具时，提示词并未直接描述工具名称，而是使用由大括号包围的占位符“{tools}”，类似占位符将在程序运行时替换，从而确保代码与提示词的相对独立与灵活。

> 在思考过程中，天气或景点信息必须使用以下工具进行查询获取。其他信息由大模型直接推理即可。

{tools}

ReAct型智能体的核心理念在于先推理后行动。为实现这一特性，智能体向模型提供的提示词中必须详尽描绘完成任务的逻辑路径，以引导模型的推理思维方式。这一过程通常遵循以下顺序。

首先智能体需明确向模型阐述当前需要解决的具体问题或任务，进入“问题定义”阶段。此阶段要确保问题表述清晰无误，便于模型准确把握核心。事实上这个问题通常由用户输入，因此必要时可增加由模型润色用户输入并经用户确认后再作为问题输入的步骤。

随后模型进入“思考”阶段，对问题进行深入剖析，并基于其强大的语义理解和推理能力决定采取何种行动以解决问题或获得前置条件。这一决策不仅依赖对问题的理解，还涉及对可用资源和备选工具的评估。

紧接着模型需给出具体的“行动”方案，以及执行该行动所需的“行动输入”。这些方案通常包括调用特定工具、执行特定操作或查询特定信息等。

应用程序在接收到模型推理决策的行动指令后，便需要执行具体行动，即调用相应工具或接口获取信息或完成操作，并将行动结果反馈给模型。

模型在接收到行动结果后进入“观察”阶段，对结果进行细致分析。基于分析结果，模型会进一步思考，推导出下一步行动策略或提出新解决方案。

上述过程将重复迭代数次，直至模型认为已获得最终满意的“结果”，整个问题解决流程方告终止，智能体成功完成任务。

根据以上思路编写完成的提示词如下。

> 使用以下过程解决问题，并按以下格式使用中文进行输出：

Question：用户输入的、你必须解决并回答的问题。

Thought：你应该一直考虑为解决问题下一步应当做什么，每一步应当仅完成一个动作，或者判断当前已经获得最终答案而可以结束思考过程。

Action：当前要采取的行动，它应该是 [ {tool_names} ] 中的一个，如果没有合适的工具，尝试由大模型直接完成回答。
