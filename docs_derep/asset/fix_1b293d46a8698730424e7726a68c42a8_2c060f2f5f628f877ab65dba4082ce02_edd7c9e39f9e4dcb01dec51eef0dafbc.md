❑ 扫描材料中是否存在乱码、异常符号或排版错误并即时清理修正。
❑ 对缺失关键字段的记录进行处置，可舍弃该条或从他处补全信息。
❑ 排查明显偏离语言规范或主题的异常样本，选择剔除或二次校验。
❑ 去重以保证每条文本记录唯一。
❑ 纠正拼写、语法及用词不准确之处。
❑ 开展分词、词性标注等预处理，帮助模型更好理解文本。
❑ 面对多语种语料时，需先做语言识别后统一规范。
❑ 核验清洗后语料的质量，重点看清晰度、连贯性及相关性是否达标。

按以上流程完成清洗，可明显提升语料质量，降低噪声与错误对大模型训练的干扰，从而改善模型表现与精度。实践中清洗方案需结合数据特点与业务诉求定制化，强化数据的可信度与适用性，以满足大模型训练需求。

**3.知识抽取**

当采集出现空白时，可让大模型生成边界测试场景来弥补真实采集不足，比如借鉴银行风控的合成数据生成思路，模拟各类风险交易模式。对采集到的数据通常要补充标签，例如测试类型、功能模块、优先级等。

❑ 测试类型：功能测试、性能测试、安全测试、兼容性测试等。
❑ 功能模块，按产品自身的定义或分类统一标注。
❑ 优先级：很高、高、中、低、很低等。

### **7.1.3 知识库构建与索引**

搭建高效测试知识库，先要建立科学的知识表征模型。常见表征方式如下。

❑ 逻辑表征法（如谓词逻辑）：用形式逻辑表述事实，如“狗是哺乳动物”可写成∀x Dog(x)→Mammal(x)。
❑ 产生式表征法：以“IF-THEN”规则链表达因果，如“如果下雨，那么带伞”。
❑ 框架表征法：用结构化框架描述对象属性及默认值，如“鸟”框架包含“翅膀”“会飞”等槽位。
❑ 语义网络：由节点与边构成图结构，如“苹果-属于-水果”。
❑ 向量表征法（如 Word2Vec）：把知识映射到低维向量空间，利用数值距离反映语义关联。

大模型本身可视为一种向量表征，把文档向量化后即可被大模型读取，这在 RAG 应用中常见。知识图谱本质上是语义网络的工程化延伸，依赖实体及其关系的建模，更强调结构化、规模化与语义互联，因而具有独特的方法论。

测试知识呈现多层次、多维度特征，需要统一的表征框架承载各类信息。前文已给出单项内容的数据结构，表示测试知识时还需进一步提炼，抽象为测试知识元素并构建元素间关联。我们采用分层知识表征架构。

❑ 原子层：测试步骤、验证点、测试数据等基础元素。
❑ 组合层：测试用例、测试场景、缺陷模式等复合实体。
❑ 关系层：实体间的依赖、包含、触发等语义关联。
❑ 语境层：项目背景、业务规则、环境约束等背景信息。

该分层设计既保留知识的原子性，又能完整表达复杂测试场景。例如针对业务域数据，需整理交易场景分类树，为银行风控测试建立的交易场景分类树如图 7-3 所示。

清洗后数据虽已干净，却仍是非结构化文本。要转化为可用知识，关键在于识别文本中的核心实体及其关系。

**1.测试实体的智能识别**

测试领域核心实体包括测试场景、测试步骤、测试数据、预期结果等。可采用规则与机器学习结合的混合方式。例如识别测试步骤时发现多数用例遵循固定表达模式，如“单击登录按钮”“输入用户名”。基于这些模式可训练专用实体识别器。

在缺陷分析方面，自动抽取缺陷特征尤为重要。大量缺陷记录显示缺陷描述通常包含症状、复现步骤、影响、根本原因等要素。针对这一规律，可开发专用抽取器，从冗长描述中提炼关键信息，为后续应用奠定基础。

实践中，可从测试管理平台导出数据，提取功能验证要点、常见失败模式、环境依赖等核心知识，降低团队获取成本。

**2.构建测试知识的关系网络**

孤立实体无法构成完整知识，关系才是核心。测试领域典型关系包括测试用例验证需求、缺陷由测试用例发现、测试场景包含测试步骤等。可从结构化数据直接获取显式关系，例如测试管理系统记录的用例与需求关联可直接映射为知识图谱。

也可从文本挖掘隐式关系。通过自然语言处理识别文档中的因果、条件等关系。例如“登录失败时，系统应显示错误提示”可提取登录失败与错误提示之间的触发关系。

**3.从多模态的数据中提取知识**

测试知识不仅是文本，还包含截图、日志、代码等多模态内容。处理非文本数据是构建完整体系的关键。

测试截图常蕴含重要信息。借助光学字符识别与图像识别，可从 UI 测试截图中提取界面元素、错误信息等，并将截图与对应测试步骤关联，形成可视化测试知识，在 UI 密集型应用中价值突出。

测试日志是另一重要来源。需开发日志解析器，从海量系统日志中抽取关键事件序列并与测试步骤对应。例如在性能测试中，通过日志分析可定位导致响应变慢的典型调用路径，有助于性能优化。

自动化测试脚本也蕴含丰富知识。通过代码分析可提取测试意图、验证点、测试数据等。如从 Selenium 相关自动化代码中识别关键用户交互路径，从单元测试中提取接口规范与边界条件。

**4.从碎片到体系：知识的整合与验证**

数据处理与知识抽取需要持续迭代验证。我们采用“抽取-验证-优化”循环，保证知识质量。

验证环节实施多层次质量控制。首先是自动化检查，用预定义规则校验格式与完整性。其次是抽样人工审核，重点核查关键测试场景的抽取结果。在大规模处理项目中，可随机抽样人工复核，发现模式错误及时修正，确保整体质量。

知识整合是最后关键步骤。将不同来源、不同模态的知识连接成有机整体，形成完整视图。例如把需求描述、测试用例、执行结果、缺陷记录与解决方案串联，形成从发现问题到解决问题的完整链路。

通过系统化处理与抽取，原始测试数据被转化为结构化、关联化的测试知识，为知识库构建奠定坚实基础。

### **7.1.4 应用层设计与集成**

完成知识库构建与索引后，应用层设计与集成成为连接底层知识与上层业务价值的关键中枢。本节阐述检索策略、提示工程、服务构建及与现有系统集成的核心思路，打造高效、智能、可扩展的 AI 知识应用平台。

**1.检索策略与排序机制设计**

精准高效的检索是发挥知识库价值的前提。可设计多阶段多策略融合的检索与排序机制，帮助用户快速获取最相关知识。

**（1）检索策略**

可采用混合检索策略，例如将布尔检索与向量检索结合，对查询先做关键词过滤，再在候选集中计算嵌入向量相似度，既保证精确性又兼顾召回率；也可采用分段检索，先在核心知识域快速检索如高频用例、权威文档，再扩展到全量库，降低响应延迟。

**（2）排序机制设计**

排序采用多因子融合，主要考虑：

❑ 基础分：基于 BM25 或 TF-IDF 的关键词匹配得分。
❑ 语义得分：利用 SBERT、SimCSE 等模型计算查询与文档向量的余弦相似度。
❑ 业务权重：结合文档质量标签如专家评分、点击率、更新时效加权，提升高价值或新内容权重。
❑ 个性化调优：参考用户画像、历史点击与反馈，对结果再排序实现个性化推荐。

排序还可分阶段精细化：

❑ 轻量级重排模型：对初步召回的 Top-N 候选集使用轻量交叉注意力模型或基于大模型的少量样本打分模型初筛，平衡精度与效率。
❑ 语境感知与业务逻辑注入：将用户角色、历史查询、任务背景、时效性、权威性等元数据及业务规则注入排序模型。
❑ 大模型增强排序与可解释性：对 Top-K 结果用大模型深度判断相关性并生成解释，增强信任度。
❑ 多样性与个性化调整：引入 MMR 等算法避免信息冗余，在相关性基础上兼顾多样性。

在此基础上，通过在线学习与反馈闭环优化：记录点击、采纳、评价等行为持续更新模型参数；定期 A/B 测试不同参数组合，按点击率、满意度等核心指标迭代。

**2.提示工程体系开发**

提示词质量直接决定大模型输出效果。需构建系统化、可维护、可优化的提示工程体系。例如按应用场景如缺陷根因分析、测试用例生成、知识问答、代码解释、文档摘要分类设计标准化模板；也可把常见任务抽象为可参数化模板统一管理，便于复用与版本控制。模板一般包含角色设定、任务指令、语境注入位、输出格式约束、少量示例、追问引导等。

**（1）提示词模板**

可实现动态构建与注入。

1）语境感知组装：依据用户查询、检索到的知识片段、用户画像与任务目标动态选择填充模板。
2）智能语境选择与截断：针对模型输入长度限制，优先保留最相关信息，可用摘要与关键信息提取预处理。
3）指令链与思维链：对复杂任务设计链式提示，引导多步推理。例如根因分析先识别症状，再推测原因，最后结合知识库判断。

**（2）提示词模板及其多轮对话设计**

最好支持以下特性。

1）占位符替换、条件分支与多段拼接，提升灵活性。
2）分层多轮对话设计：
❑ 一级模板：接收原始请求，完成意图识别与参数抽取。
❑ 二级模板：针对不同业务场景调用专属提示词，形成链式推理。
❑ 会话历史维护：记录管理多轮语境信息。
❑ 语境压缩与摘要：对历史对话智能压缩，保留关键信息。
❑ 意图继承与切换：支持平滑切换意图，提示词自适应调整。
3）自动化评估与迭代：
❑ 引入准确率、召回率、生成质量打分等指标定期基准测试。
❑ 结合人工反馈微调，支持 A/B 实验持续优化。

**3.应用接口与服务层构建**

将检索、排序、提示生成、日志监控等模块化为独立微服务，如知识检索服务，支持分页过滤，接收文本或结构化参数，返回排序后的知识片段。服务可用 Docker/Kubernetes 编排，支持弹性伸缩与灰度发布，通过 API 网关统一对外提供鉴权、限流、熔断等能力。设计要点：

1）输入校验与安全过滤：检测 XSS、SQL 注入等风险，对敏感内容脱敏或拒绝。
2）异步任务与缓存：耗时检索或多轮推理使用消息队列异步处理，结果落地 Redis 缓存提升效率。
3）监控与可观测性：集成 Prometheus+Grafana 监控调用量、延迟、错误率并告警，记录完整调用链便于排查。

提供多语言 SDK 并封装容错机制，便于业务接入。根据前端形态设计统一的 JSON-RPC 或 WebSocket 接口，保证交互一致性。

**4.与现有系统集成**

通过 ETL 或实时消息总线接入 JIRA/Tapd、TestRail、Confluence/Git 等异构系统：

1）知识库保鲜：定期全量拉取加增量订阅，保证一致性与时效性。
2）身份与权限统一：接入企业单点登录，对接 LDAP/AD 实现统一认证与角色访问控制。
3）在业务界面嵌入检索组件或智能助手，提供语境感知建议。
4）支持双向链接：检索结果可跳转回原系统实体，形成工具链闭环。
5）建立 CI/CD 流水线：代码、提示词、模型版本纳入管控，实现自动化部署、回滚与灰度。
6）定期评审机制：每季度评估检索命中率、响应时长、用户满意度等指标，联合业务方调整路线。

通过上述架构，应用层既能高效调用底层知识，又能与现有业务深度融合，形成可持续演进的智能测试与运维平台。

### **7.1.5 评测与优化**

构建先进 AI 知识应用平台需持续评测与优化。本节阐述评估指标体系、定量定性测试、模型与知识库优化的方法。

**1.建立评估指标体系**

科学全面的指标体系是衡量效果的基础，覆盖技术性能到业务价值。

**（1）检索质量指标**

❑ NDCG@K：衡量 Top-K 排序质量，综合相关性与位置。
❑ MAP：多查询平均检索精度。
❑ Precision@K：Top-K 中相关结果比例。
❑ Recall@K：Top-K 中相关结果占全部相关比例。
❑ MRR：首个相关结果位置倒数均值。
❑ 覆盖率：知识库对目标领域知识点的覆盖程度。
❑ 多样性：结果能否覆盖查询意图多方面。
❑ 新颖性：能否提供用户未知信息。

**（2）生成质量指标**

❑ 流畅性：语法规范、阅读通顺。
❑ 一致性/连贯性：逻辑一致、语境自然。
❑ 相关性/事实性：与查询相关、信息准确。
❑ 实用性/帮助性：对解决问题有实际帮助。
❑ 无害性：无偏见、歧视、攻击性内容。

**（3）结构质量**

❑ 格式规范性：符合标准模板。
❑ 分类准确性：分类标签正确率>95%。
❑ 关联完整性：相关链接有效率>85%。

**（4）语义质量**

❑ 语义一致性：同类概念描述一致。
❑ 概念覆盖度：领域核心概念覆盖率。
❑ 知识密度：单位文本有效信息量。

**（5）系统性能指标**

❑ 端到端查询延迟：请求到完整响应的时间。
❑ 各模块延迟：检索、重排、大模型推理、API 网关等环节耗时。
