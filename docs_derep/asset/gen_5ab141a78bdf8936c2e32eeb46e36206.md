[PRE0]

AI Core 在处理通用卷积时，指令经总线接口从核外 L2 缓冲区或内存中取出，写入指令缓存完成预取，待标量指令处理队列译码。队列若无指令在跑，就立即从指令缓存取指令做地址与参数配置，随后指令发射模块按指令类别分发到各自队列。卷积开始时最先发出的是数据搬运指令，该指令先进入存储转换队列，再送达存储转换单元。

卷积数据流如图 3-16 所示。当数据全在 DDR 或 HBM 时，存储转换单元接到读数据指令后，由总线接口单元经数据通路①把矩阵 X 与 W 从片外存储读入输入缓冲区，再经数据通路③送入存储转换单元。单元对 X 与 W 做补零与 Img2Col 重排，得到重构矩阵 X_I2C 与 W_I2C，实现从卷积到矩阵的格式转换。转换期间存储转换队列可提前投递下一条指令，指示转换完成后经数据通路⑤把 X_I2C 与 W_I2C 送往矩阵计算单元等待运算。受局部性影响，若 W_I2C 需多次复用，可经数据通路⑰将其固化在输入缓冲区，复用时再经数据通路⑱送到矩阵计算单元。此外，转换过程中存储转换单元同步经数据通路④从片外把偏置读入输出缓冲区，经数据通路⑥重排为矩阵格式，再经数据通路⑦暂存输出缓冲区，随后经数据通路⑨写入累加器寄存器，供后续偏置累加使用。

[PRE1]

左、右矩阵准备就绪后，矩阵运算队列经数据通路⑤把矩阵乘指令发给矩阵计算单元。X_I2C 与 W_I2C 被切分为 16×16 的块，由矩阵计算单元执行乘法。若输入较大则重复多次并累加，中间结果 Y_o 留在矩阵计算单元。乘法结束后若需偏置处理，累加器接收偏置累加指令，一方面经数据通路⑨从输出缓冲区读入偏置，另一方面经数据通路⑧取回矩阵计算单元的中间结果 Y_o 进行累加，最终得到输出特征矩阵 Y，经数据通路⑩转至输出缓冲区待后续处理。

AI Core 借矩阵乘完成卷积网络计算后，向量执行单元接收到池化与激活指令，输出特征矩阵 Y 经数据通路⑫进入向量计算单元做池化与激活，处理结果经数据通路⑬写回输出缓冲区。向量计算单元可处理激活等特殊计算，并高效实现降维，适合池化。在多层网络执行时，Y 会再次经数据通路①从输出缓冲区搬回输入缓冲区，作为下一层的输入重新开始计算。

达芬奇架构面向通用卷积的特征与数据规律，采用高度定制化的功能划分，将存储、计算与控制紧密结合，单模块独立高效又实现整体协同。AI Core 把矩阵计算单元与数据缓冲区紧密组合，缩短存储到计算的路径，降低时延。

片上还集成大容量输入与输出缓冲区，可一次性缓存足够数据，减少对核外存储的访问频次，提升搬移效率。缓冲区相较核外存储访问更快，大量片上缓存显著提升了实际可用的数据带宽。

同时针对深度神经网络结构多样，AI Core 提供灵活的数据通路，使数据可在片上缓冲区、核外存储、存储转换单元与计算单元间快速切换，满足不同网络的计算需求，提升通用性。

### 3.3.2 架构对比

回顾 GPU 与 TPU 处理卷积的方式，再与昇腾 AI 处理器达芬奇架构对比。以图 2-5 的卷积加速案例为例，GPU 采用通用矩阵乘法，把卷积转为矩阵计算，靠海量线程在多个周期内并行得到输出特征矩阵。流处理器内的 SIMD 同时执行多个线程，线程在一段时间内完成矩阵乘、激活或池化等步骤。操作完成后由于片上存储有限，GPU 往往需把数据写回内存，下一步再读回。通用计算能力使其能用相似模式处理卷积、池化、激活等。

TPU 用脉动阵列直接加速卷积。片上大容量缓冲区一次容纳几乎全部所需数据，再由内部脉动数据流控制单元送入脉动计算阵列。当阵列全满达到饱和时，每个时钟周期可输出一行结果。卷积结束后需经定制矢量运算单元做激活或池化。

昇腾 AI 处理器也采用通用矩阵乘法加速，先展开重组输入特征与权重矩阵，再做矩阵相乘。与 GPU 不同的是，昇腾的矩阵计算单元一次处理 16×16 矩阵，并在极短时间内完成，吞吐率高于 GPU。向量计算单元与标量计算单元可并行处理卷积、池化、激活等，进一步提高并行度。

GPU 以集中式寄存器管理、多线程并行、类 CPU 片上组织实现灵活调度，开发门槛较低。但通用性代价是每次计算都需遵循从寄存器取数到写回寄存器的规范，增加数据搬运开销与功耗。

TPU 通过精简指令一次性把大量数据读入缓冲区，以固定模式流入脉动阵列，减少搬运次数与整体功耗。但定制化限制了应用范围，且大缓冲区占用面积，会压缩其他资源。

昇腾 AI 处理器对矩阵与卷积高效，主要受益于达芬奇架构的定制硬件，专加速矩阵运算，可快速完成 16×16 矩阵乘法。配合大量分布式缓存与计算单元，有效减少数据搬运，兼顾算力与功耗，在深度卷积网络尤其是大规模卷积场景具优势。但固定 16×16 的矩阵计算单元在小规模网络上易出现算力未满、资源利用率低的问题。

总体看，三种架构各有优劣，脱离具体应用评判没有意义。同一应用内数据规模、分布、计算类型、精度、网络结构等都会显著影响优势发挥。不同于传统专用芯片，面向特定域的架构芯片性能很大程度上取决于运行其上的软件效率，后续章节将聚焦软件优化，帮助建立软硬件协同理念，以适应后摩尔时代需求。

# 第 4 章 软件架构

昇腾 AI 处理器的达芬奇架构在硬件上定制计算资源，功能与硬件高度匹配，为卷积神经网络性能提升提供硬件基础。从开源框架到模型实现再到芯片运行，需多层次软件管理模型、计算流与数据流。神经网络软件流为模型落地提供支撑，开发工具链为应用开发带来便利，二者构成基础软件栈，自上而下支撑芯片执行。

### 4.1 昇腾 AI 软件栈总览

为发挥昇腾 AI 处理器最佳性能，需完善的软件方案。完整软件栈包含运行框架与性能调优，以及配套工具。软件栈分为神经网络软件流、工具链及其他模块。

神经网络软件流包含流程编排器 Matrix、框架管理器 Framework、运行管理器 Runtime、数字视觉预处理 DVPP、张量加速引擎 TBE 及任务调度器 TS 等，完成模型生成、加载与执行。工具链为实现过程提供辅助。

如图 4-1，软件栈各部分功能相互依赖，承载数据流、计算流与控制流。软件栈共 4 层加工具链，分别为 L3 应用使能层、L2 执行框架层、L1 芯片使能层、L0 计算资源层。工具链提供工程管理、编译调测、流程编排、日志管理与性能分析等能力。

#### 1. L3 应用使能层

L3 为应用级封装，面向特定领域提供算法，含通用业务执行引擎、计算机视觉引擎与语言文字引擎。通用业务执行引擎提供通用推理能力；计算机视觉引擎面向视觉领域封装视频图像处理算法；语言文字引擎面向语音文本等提供基础处理算法。基于流程编排器定义计算流程，由通用业务执行引擎实现具体功能。L3 通过通用框架调用 L2 的调度能力生成神经网络，实现引擎功能。

#### 2. L2 执行框架层

L2 为框架调用与离线模型生成能力的封装。L3 将领域算法封装为引擎后，L2 根据算法特点调用深度学习框架，如 Caffe、TensorFlow，生成离线模型。L2 包含框架管理器与流程编排器。

L2 使用在线框架与离线框架。在线框架基于主流开源框架，通过模型转换与加载在昇腾上加速。对网络模型提供训练与推理能力，支持单卡、单机、多机场景。另提供自研 MindSpore 框架，其功能类似 TensorFlow，由其生成的模型可直接运行在昇腾，无需适配。

昇腾支持在线生成与执行，也支持离线生成与执行，即脱离框架下离线模型 Offline Model 仍具备推理能力。框架管理器含离线模型生成器 OMG、离线模型执行器 OME 与 AI 模型管家推理接口，支持生成、加载、卸载与推理。离线模型生成器将 Caffe 或 TensorFlow 的模型与权重转为离线模型文件；离线模型执行器负责加载卸载并编译为可在昇腾运行的指令序列。流程编排器统筹加载与执行，提供开发平台，负责模型生成、加载与运算调度。L2 将原始模型转为可在昇腾运行的离线模型后，由离线模型执行器传给 L1 进行任务分配。

#### 3. L1 芯片使能层

L1 是离线模型通向芯片的桥梁。接收 L2 生成的离线模型后，通过加速库为计算提供加速。L1 最接近底层，负责向硬件输出算子级任务。包含 DVPP、张量加速引擎、运行管理器、驱动与任务调度器。

以张量加速引擎为核心，支持在线与离线模型加速。引擎内含优化后的标准算子加速库，执行时与上层的运行管理器交互，运行管理器与 L2 通信，提供算子接口。若标准库无所需算子，可通过张量加速引擎编写自定义算子，从而为 L2 提供完备算子能力。

张量加速引擎下方为任务调度器，依据算子生成计算核函数后，按任务类型分发至 AI CPU 或 AI Core，驱动执行。调度器运行在专属 CPU 核上。DVPP 是面向图像视频的多功能封装，为上层提供底层专用硬件的数据预处理能力。

#### 4. L0 计算资源层

L0 为硬件算力基础。L1 完成算子任务分发后，具体执行由 L0 启动。包含操作系统、AI CPU、AI Core 与 DVPP。AI Core 完成神经网络矩阵相关计算，AI CPU 完成控制算子、标量与向量等通用计算。若需预处理，DVPP 专用硬件被激活进行图像视频预处理，为 AI Core 提供合适格式数据。AI Core 负责大算力任务，AI CPU 负责复杂计算与执行控制，DVPP 负责数据预处理，操作系统使三者协同，保障深度神经网络计算执行。

#### 5. 工具链

工具链是面向程序员的开发平台，提供自定义算子开发调试、网络移植优化分析等支撑，并提供可视化 AI 引擎拖拽式编程服务，降低开发门槛。含工程管理、编译调测、流程编排、离线模型转换、比对工具、日志管理、性能分析、自定义算子与黑匣子工具等，为开发与执行提供多层次便捷服务。

### 4.2 神经网络软件流

为实现神经网络应用，需在深度学习框架到昇腾 AI 处理器之间架起软件流，提供高性能计算支撑。从原始模型到计算图表示再到独立执行的离线模型，软件流围绕生成、加载与执行，聚集流程编排器、DVPP、张量加速引擎、框架管理器、运行管理器与任务调度器，形成完整功能集群，如图 4-2 所示。

各模块分工明确：流程编排器统筹落地与实现，控制模型加载与执行；DVPP 在输入前做数据处理与格式修饰；张量加速引擎为模型源源不断提供计算算子；框架管理器将原始模型塑造为昇腾可用的形态并引导高效运行；运行管理器提供资源管理通道；任务调度器驱动硬件执行任务。运行管理器与任务调度器协同，实时监控与分发任务，形成软硬件结合的执行流程，推动生态发展。

#### 4.2.1 流程编排器

### 1. 功能简介

昇腾 AI 处理器将网络执行按功能划分为基本执行单元，形成颗粒化计算引擎 Engine。每个引擎在流程编排中对数据完成具体操作，如图像分类、输入预处理、输出标注等。计算引擎由开发者自定义，完成所需功能。
