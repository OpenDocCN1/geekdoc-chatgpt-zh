# RAG双引擎：检索与生成的实战拆解

在RAG架构里，FAISS 与 Transformers 分别承担召回与理解生成两大职责。FAISS 来自 Meta AI 研究团队，专为海量向量近邻查找而设计，在高维特征空间中检索效率突出；Transformers 是 Hugging Face 社区维护的模型工具箱，内置 BERT、GPT、RoBERTa 等大量预训练权重，覆盖理解、生成、问答等自然语言任务。将两者串联，就能把用户提问编码成向量并快速命中相关知识库，同时用生成模型润色回答，提升准确度与响应速度。

下面分别展开两者的工作机制，并通过代码演示在 RAG 场景下的典型用法。

##### 1. FAISS原理与构建流程

FAISS 是一个面向大规模向量相似查找的高性能库。思路是对高维向量做压缩和结构化建库，从而把检索时间复杂度大幅降低。

核心围绕两件事：索引 Indexing 与量化压缩 Quantization，即便面对上亿量级向量也能保持流畅。

落地通常经历以下环节：

- 编码阶段：借助 Transformers 中的预训练编码器把原始文本转为稠密向量
- 建库阶段：创建检索结构并批量导入向量
- 查询阶段：对查询向量做近邻查找，返回最接近的向量及其对应的原文

##### 2. Transformers原理与落地流程

Transformers 集合了 BERT、GPT、RoBERTa 等多种预训练模型，可覆盖分类、生成、问答等 NLP 任务。底层依赖自注意力机制，能捕捉序列中的长程依赖。

常规使用流程包括：

- 模型引入：从 Hugging Face 模型库拉取所需权重，例如 BERT 做嵌入、GPT 做生成
- 文本标准化：通过分词器把输入转为模型可接受的 token 序列
- 推理计算：把标准化后的数据送入模型，得到预测结果
