在 DB2RDF 这类把图数据塞进关系表的方案里，谓语往列上怎么放是关键难点。关系表的列数是硬上限，所以映射设计要兼顾两件事：一是总共用到的列别超过阈值 m，二是别让同一个主体的不同谓语频繁撞进同一列，降低溢出概率。因为溢出发生，查询时就得做自连接，代价会显著变大。

比较常见的做法是引入一组哈希函数。每个谓语通过哈希得到一组候选列号，写入时把谓语和宾语放到这组里第一个空闲的列。如果该主语所在的那一行，哈希算出的所有候选列都被它自己已有的谓语占满，就判定为溢出，接下来要另开一行继续存放。以 Android 为主语的三元组写入过程就能说明问题：先写 (Android, developer, Google)，按 h1 落到 pred1；再写 (Android, version, 8.1)，按 h1 落到 pred2；再写 (Android, kernel, Linux)，h1 指向 pred1 已被占用，于是用 h2 落到 pred3；再写 (Android, preceded, 8.0)，h1 指向 predk；随后写 (Android, graphics, OpenGL)，h1 指向 pred3、h2 指向 pred2，这两列都已被占用，于是产生溢出，把 graphics 挪到下一行的 pred3 中保存，如图 -13 的 dph 表所示。

如果能提前拿到知识图谱的一个子集，就可以利用图自身的结构来优化映射。做法是把谓语到列的映射转化成图着色问题。把同一个主体上一起出现的不同谓语叫做共现谓语，目标是让共现谓语染不同颜色即映射到不同列，而非共现的可以复用同一列。为此先构造冲突图：所有谓语是节点，每对共现谓语之间连一条边。图着色的要求是给冲突图的每个节点上色，相邻节点颜色必须不同，且颜色总数尽量少；对应到映射，就是让共现谓语分到不同列，非共现可共享列，同时最小化列数。图3-15 给出的是图3-4 知识图谱的冲突图，可见 13 个谓语仅需 5 种颜色，即 5 列就够。需要说明的是，图着色是经典 NP 难问题，面对大图通常用贪心类算法比如 Welsh-Powell 算法求近似解。

# 3.2.2 RDF 三元组存储方案

RDF 是 W3C 推荐的语义网关联数据标准，也是目前在 Web 上发布知识图谱的主流格式。面向 RDF 的三元组数据库就是专门为海量 RDF 数据设计的知识图谱存储系统，核心能力是支持标准的 SPARQL 查询语言。下面介绍几类主流的开源与商业系统。

开源阵营主要有 Apache 系的 Jena、Eclipse 系的 RDF4J，以及学术界的 RDF-3X 和 gStore；商业阵营则有 Virtuoso、AllegroGraph、GraphDB 和 BlazeGraph。Apache Jena 会以实践方式详细展开，下面先分别介绍 RDF4J、RDF-3X、gStore、Virtuoso、AllegroGraph、GraphDB 和 BlazeGraph。

# 1. RDF4J 开源三元组库

RDF4J 是 Eclipse 基金会下的开源孵化项目，前身是荷兰 Aduna 公司开发的 Sesame 框架。Sesame 可追溯到 1999 年，最初是 Aduna 的语义 Web 研究项目，后发展为知名的 RDF 管理与处理 Java 框架，涵盖解析、存储、推理和查询。2016 年 5 月，Sesame 改名为 RDF4J 并转入 Eclipse 社区继续维护。

RDF4J 同时提供内存和磁盘两种存储，完整支持 SPARQL 1.1 的查询与更新，用与本地库相同的 API 就能访问远程库，兼容 RDF/XML、Turtle、N-Triples、N-Quads、JSON-LD、TriG、TriX 等主流格式。

架构上的模块化是 RDF4J 的重要特征，整体采用分层设计。

# 2. RDF-3X 开源三元组库

RDF-3X 由德国马克斯·普朗克计算机科学研究所研发，最早成果发表于 2008 年 VLDB，后经扩展完善，最新版本为 GH-RDF3X，代码托管在 GitHub，目前仅支持 Linux。

RDF-3X 的核心是为 RDF 量身定制的压缩物理存储与查询优化。逻辑上仍基于三元组表，但首次提出全索引方案：6 种三元组索引 spo、sop、osp、ops、pso、pos；6 种二元聚合索引 sp、ps、so、os、po、op；3 种一元聚合索引 s、p、o。物理上采用基于 B+树的压缩：用字典表把 RDF 字符串映射为整数 id；用面向字节的增量编码压缩三元组；压缩限定在 B+树页面内部，不跨页，避免不必要的解压，查询效率更高。在压缩技术加持下，全索引的空间开销可接受，却为查询处理带来很大便利。

以 spo 索引为例，查找三元组模式 (Albert_Einstein, invented, ?x)。如图 3-18，spo 中存放的是字典编码后的整数 (s,p,o)，并按 s、p、o 排序。步骤如下：

# 3. gStore 开源三元组库

gStore 是图基础的 RDF 三元组数据库。它把 RDF 图 G 中每个实体及其邻居属性和值编码成二进制位串，由这些位串组成标签图 G*。查询图 Q 同样转成标签图 Q*。研究已证明 Q* 在 G* 上的匹配是 Q 在 G 上匹配的超集。为加速匹配，gStore 提出 VS 树索引，本质是为标签图建立多粒度摘要图；借助摘要图可大幅缩小 SPARQL 的搜索空间，提升速度。

gStore 已开源，代码与文档在 GitHub，可在 Linux 运行，细节参见文献[33]。用 gconsole 交互式客户端的操作步骤如下：

+ 步骤 1. 在编译好的 gStore 目录下运行 bin/gconsole 进入客户端。
+ 步骤 2. 执行 build testds music_1000_triples.nt 构建库并导入数据。
+ 步骤 3. 执行 load testds 加载库。
+ 步骤 4. 执行 query sparql.rq 运行查询文件。
