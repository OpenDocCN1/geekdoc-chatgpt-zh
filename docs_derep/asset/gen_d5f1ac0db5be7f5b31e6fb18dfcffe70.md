自然语言提问常常带有一定的歧义、口语化或表述不规范，直接拿去检索很容易跑偏。LangChain 在这个问题上提供了一套提问预处理机制，帮助把用户的原始意图先和知识库“对齐”再去检索。常见的手段包括多查询生成、RAG 融合和问题拆解：多查询会围绕同一意图产出若干等价表述扩大召回面；RAG 融合把不同表述拉回的结果聚合并去重；拆解则把复杂复合问题拆成多个子问题单元逐个处理，整体提升语义层面的匹配精度，让后续检索更准。

##### 2. 路由决策
路由模块负责根据提问的类型和语义特征挑选最合适的检索路径和提示模板，主要分两类：

- **逻辑路由**：依据问题结构判断去哪类数据源、用什么查询方式。
- **语义路由**：把问题转成向量后，在向量空间里匹配最契合的 Prompt 结构。

##### 3. 数据库类型支持
在 LangChain 的高级 RAG 流程里，底层可以接入三类存储：图数据库、关系型数据库和向量数据库。

[PRE0]

##### 4. 查询构建
面对自然语言问题时，系统会先确认目标数据库类型，再生成结构化查询指令。

- **关系型数据库**：用 Text-to-SQL 把自然语言转成 SQL，再叠加向量检索做增强。
- **图数据库**：用 Text-to-Cypher 生成 Cypher 等图查询语言，从知识图谱中抽取语义关联。
- **向量数据库**：借助 Self-query retriever 自动提取意图和元数据过滤条件，产出向量检索请求。

##### 5. 索引构建
检索质量很大程度上取决于索引，LangChain 在构建索引时引入了几项做法。

- **块优化**：按字符、段落或语义断点切分原始文档，提升嵌入效果。
- **多表示索引**：例如 Parent+Summary+Dense 向量组合，让检索更全面。
- **专业嵌入**：结合微调或 ColBERT 等模型生成更贴合领域的向量。
- **层级索引**：像 RAPTOR 那样构建跨层级、多抽象的文档树，实现摘要层级的高效检索。

##### 6. 检索执行
路由确定后进入实际检索：

- **排名**：对候选文档做语义打分排序，常用 Re-Rank、RankGPT、RAG-Fusion 等方法。
- **细化**：首轮结果不理想时，会触发再检索或检索压缩。
- **主动检索**：根据首轮回答质量自动判断是否需要重写问题并重新检索。

##### 7. 答案生成
拿到检索文档后，大模型会结合原始问题和增强上下文生成最终回答。LangChain 在生成阶段引入 Self-RAG / RRR 优化，模型会在生成时主动校验理解是否正确、信息是否足够，不足时触发再检索与反馈闭环。

## 8.1.5 LangGraph核心概念与工作流搭建
LangGraph 是 LangChain 生态里构建有状态、多步骤、可循环的 AI Agent 工作流的核心框架。它把复杂任务抽象成一张图，节点对应处理步骤，边对应流转关系，状态则是在全流程中传递和更新的数据。

### 1. 核心概念
- **状态（State）**：图内共享的数据结构，通常是字典或 Pydantic 模型，保存工作流执行所需的所有信息。
- **节点（Node）**：图的执行单元，每个节点是一个函数，负责调用 LLM、处理数据或调用外部工具等，接收当前状态并返回状态更新。
- **边（Edge）**：定义节点间的连接，决定执行路径，可能是无条件的直接跳转，也可能是条件跳转。
- **条件边（Conditional Edge）**：根据路由函数返回值决定下一步走向，使工作流能依据中间结果动态调整路径。

### 2. 构建工作流
常规构建步骤如下：

1.  **定义状态**：先设计 State Schema，描述流程中数据结构。
2.  **创建节点**：为每个处理步骤写节点函数。
3.  **实例化图**：用 StateGraph 初始化图并传入状态模式。
4.  **添加节点**：通过 add_node 方法把节点注册进图。
5.  **定义入口点**：用 set_entry_point 指定起点。
6.  **添加边**：用 add_edge 连接节点，形成基础流程。
7.  **添加条件边**：用 add_conditional_edges 实现分支路由。
8.  **设置出口点**：用 set_finish_point 指定终点。
9.  **编译图**：调用 compile() 生成可执行的链。
