（2）查询提速技巧
向量数据库的检索效率直接决定终端体验，可以通过以下手段加以提升。
1）调参搜索行为：例如 HNSW 的 ef 参数控制搜索阶段的候选池大小，调大能提升召回精度但也会拖慢响应，要与 efConstruction 参数区分开，后者作用于索引构建阶段的候选池。
2）合并请求：把多条查询打包成批量调用，减少网络往返开销。
3）混合查询模式：把精确条件过滤与向量相似度检索结合使用。
4）热点结果缓存：对高频访问的向量检索结果做缓存复用。

（3）分布式部署思路
面对大规模业务，向量库必须走分布式路线。
1）水平分片：依据数据 ID 区间或哈希规则把数据散布到多个节点。
2）读写分离：将查询节点与索引构建节点拆开，提升资源利用率。
3）多副本机制：通过副本提升可用性和并发查询能力。
4）增量索引更新：避免在海量数据上做全量重建，采用增量方式维护。

向量数据库的挑选与使用是构建大模型应用的关键，须结合具体业务、数据体量与性能诉求综合权衡。

#### 1. 知识库架构设计
一个完整的知识库存储系统要兼顾结构化与向量化数据的存放，并支持多样化查询与更新。如图 5-4 所示，典型架构由数据接入层、存储层、索引层、查询层四部分构成。

四个核心层级职责分明：
1）数据接入层：负责汇聚、校验与预处理多源数据，涵盖文件解析、API 接入、清洗、格式校验等。
2）存储层：分别存放结构化数据如元数据与关系信息、向量数据即文本的嵌入表示，以及原始文档内容。
3）索引层：构建多种索引加速检索，包含传统倒排索引、向量索引与元数据索引。
4）查询层：提供关键词检索、语义检索、混合检索和元数据过滤等多种能力。

#### 2. 知识库数据模型设计
数据模型需能有效组织异构数据并支持灵活检索与更新。
设计时需关注：
1）粒度划分：将文档切分为合适的块 Chunk 以兼顾精准检索与上下文连贯，通常控制在 100~1000 token 之间，1 token 约等于 0.75 个英文单词或 1~2 个汉字，既保留完整语义又避免结果冗长。
2）关系建模：简单场景可用扁平化组织，复杂场景则构建实体间关系网络，获得更丰富的知识表征并支撑复杂推理。
3）元数据管理：完善的元数据是精确过滤与分类的基础，需为文档、块、实体等不同层级设计元数据模式。
4）版本控制：知识会持续演进，需建立版本管理机制以追溯变更历史并保证查询一致性。

#### 3. 知识库存储优化策略
实际系统要承载海量数据和高并发查询，常用优化如下。

（1）分层存储策略
按访问频率采用差异化存储，如图 5-5 所示。

[PRE2]
分层主要包括：
1）热数据层：存放最常访问的向量与结果，多用内存缓存如 Redis 实现，响应在毫秒级。
2）温数据层：存放活跃度中等的向量索引与结构化数据，多用向量数据库与关系数据库，响应在百毫秒级。
3）冷数据层：存放访问稀少的历史数据与原始文档，多用对象存储或文档数据库，成本低但延迟较高。
数据会随访问频率在各层间自动迁移，在保证性能的同时优化成本。

（2）分片与复制策略
大规模知识库需考虑分片与复制：
1）水平分片：按文档 ID 或主题将数据分散到多节点，各节点负责部分存储与检索。
2）垂直分片：将元数据、向量数据、原始内容等不同类型数据存放在不同系统。
3）多副本复制：为关键数据创建多个副本，提升可用性与读性能。

（3）存储格式优化
合理格式可显著提升效率：
1）向量压缩：采用标量量化、乘积量化等技术压缩向量，节省空间。
2）列式存储：结构化数据选用列式存储，提升特定属性查询效率。
3）增量存储：对频繁更新的知识库只存储变更部分，降低写成本。

### 5.1.3 缓存体系优化
在大模型应用中，缓存设计对性能与体验至关重要。合理策略可降低延迟，减少对模型与数据库的压力并节约成本。

#### 1. 多级缓存架构设计
通常采用多级缓存，如图 5-6 所示。

各层作用如下：
1）L1——浏览器/客户端缓存：直接在用户端缓存，响应最快但容量有限，适合 UI 资源与高频查询结果。
2）L2——API 网关缓存：位于入口，可缓存通用 API 响应，减轻后端压力。
3）L3——应用服务缓存：多用 Redis 等内存数据库，是主要缓存层，可存复杂结构与中间计算结果。

4）L4——数据库结果缓存：缓存查询结果，降低数据库负载，常用于复杂查询优化。

#### 3. 缓存优化实践
结合业务特征与用户行为常用手段：
1）缓存预热：在启动或低峰期提前计算并加载热门内容，避免冷启动延迟。
2）分级过期：按访问频率与重要性分配不同过期时间与存储空间。
3）穿透防护：用布隆过滤器等拦截对不存在数据的频繁查询。

#### 2. 嵌入模型选择
不同模型特性各异，选择需考虑：
1）向量维度：维度越高表达力越强，但存储与计算成本也越高。
2）语义保留能力：对特定领域语义的捕捉差异明显。

3）语义分块：依据语义相关性动态调整块大小。
4）重叠分块：相邻块保留重叠，防止信息丢失。

### 5.3.1 语义检索实现
语义检索基于文本语义相似度而非关键词匹配。

#### 1. 基本原理

#### 2. 检索流程优化
高效系统需优化全流程：
1) 查询扩展：通过同义词扩展或重写增强查询。
2) 多路召回：结合多种召回策略提升覆盖率。
3) 重排序：对初筛结果做精细排序。
4) 结果聚合：合并去重多路召回结果。

2) 稀疏向量 + 密集向量：结合 BM25 等统计方法与神经模型。
3) 精确搜索 + 模糊匹配：处理拼写错误与变体。

### 6.1.1 大模型服务层规划

#### 1. 服务层架构模式
