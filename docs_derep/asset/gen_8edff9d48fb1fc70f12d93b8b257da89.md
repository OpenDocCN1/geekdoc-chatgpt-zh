### 7.3 MoBA——块注意力混合

Kimi 团队于 2025 年 2 月发布论文 “MoBA: Mixture of Block Attention for Long-Context LLMs”。论文提出 MoBA，即 Mixture of Block Attention，块注意力混合，旨在提升大语言模型处理长文本的效率。MoBA 将上下文划分为多个块，让每个查询 token 动态挑选最相关的块进行注意力计算，从而高效处理长序列。实验显示 MoBA 在长上下文场景下的性能与 Full Attention 相当，而在处理 1M 长文本时速度提升 6.5 倍。

#### 7.3.1 MoBA 介绍

MoBA 是一种新型注意力机制，旨在解决传统注意力在长文本场景下计算复杂度高、资源消耗大的问题。

##### 1. 架构设计

架构设计包含以下方面。

- 块稀疏注意力：MoBA 将输入上下文切分为多个固定大小的块，每个查询 token 仅关注最相关的块，而非整个上下文。该稀疏机制显著减少计算量，同时保留长文本处理能力。
- 动态块选择：通过无参数的 Top-K 门控机制，MoBA 为每个查询 token 动态挑选最相关的块。机制计算查询 token 与各块的相关性得分并选取前 K 个。
- 因果性保持：MoBA 限制查询 token 只能关注当前块与过去块，保证自回归语言模型的因果性，同时对当前块施加因果掩码以避免未来信息泄露。
- 细粒度块分割：MoBA 支持细粒度块分割，类似 MoE 架构中的专家划分，进一步提升性能。
- 与 Full Attention 的混合：MoBA 可在 Full Attention 与稀疏注意力间无缝切换，既适用于长文本任务，也兼容现有预训练模型。

MoBA 架构示意图如图 7-6 所示，该图说明 MoBA 如何通过选择性关注最相关块来减少计算量，同时保持长文本处理能力。

##### 2. 实现细节

实现细节包含以下方面。

- 块划分：上下文被划分为多个块，每个块包含一组连续 token。
- 门控机制：通过计算查询 token 与各块的相关性得分，门控机制动态选择最相关块。该机制类似 MoE 中的专家选择，但应用于注意力机制。
- 注意力计算：MoBA 仅对选定块进行注意力计算，显著降低计算复杂度。同时通过 Flash Attention 等高性能库优化计算。
- 因果掩码：为保持自回归因果性，MoBA 对当前块应用因果掩码，避免 token 关注未来位置。
- 与现有模型的兼容性：MoBA 保持与 Full Attention 相同的参数量，可作为 Full Attention 的替代品，无需对现有模型做大规模修改。

##### 3. 性能优势

性能优势包含以下方面。

- 显著加速：在处理长文本时 MoBA 大幅提升效率。例如处理 100 万 token 上下文时，MoBA 比传统 Full Attention 快 6 倍。
- 灵活切换：MoBA 可在稀疏注意力和 Full Attention 间无缝切换，适用于不同长度上下文。
- 与现代加速器兼容：MoBA 结合 Flash Attention 等高性能库，进一步优化计算效率。

##### 4. 使用与部署

使用与部署包含以下方面。

- 环境设置：MoBA 实现依赖 PyTorch 与 Flash Attention。用户可通过简单命令安装依赖并使用 MoBA。
- 集成与转换：MoBA 可轻松集成到现有 Transformer 模型中，也可将现有预训练模型转换为 MoBA 模型。

总体而言，MoBA 的设计与实现为大语言模型处理长文本提供了一种高效且灵活的解决方案，同时保持与传统注意力机制相当的性能。

#### 7.3.2 测试结果

Kimi 团队对 MoBA 进行了全面测试与验证，结果显示在处理长文本时具备显著性能优势。

- 缩放定律实验：尽管注意力模式稀疏度高达 81.25%，MoBA 在语言模型损失上的表现与 Full Attention 相当。
- 长文本缩放能力：实验表明，随着文本长度增加，MoBA 与 Full Attention 的差距逐步缩小。
- 细粒度块分割消融研究：实验显示更细粒度的块分割可进一步提高 MoBA 性能。
- MoBA 与 Full Attention 的混合训练：实验表明混合使用 MoBA 与 Full Attention 训练可在训练效率与性能间取得平衡。
- 效率和可扩展性：实验表明 MoBA 在处理长序列时比 Full Attention 更高效，计算复杂度为亚平方级。在处理 1000 万 token 序列时，MoBA 的注意力计算时间降至原来的 1/16。

这些结果表明 MoBA 在保持相近性能的同时，显著降低注意力计算时间和内存消耗，尤其在超长文本场景下优势更加明显。

#### 7.3.3 NSA 和 MoBA 的对比

Kimi 的 MoBA 与 DeepSeek 的 NSA 均为针对长文本处理的创新技术，在提升处理效率与降低计算成本方面均有显著表现。

1. 相似之处

两者的相似之处如下。

- 两者均针对长文本处理优化，旨在提高 AI 处理长文本的效率。
- 两者均通过优先处理重要信息减少计算负载，从而提升计算效率。
- 无论是提升推理能力还是改善长文本处理，这两种技术均有助于使 AI 更智能。

2. 不同之处

两者的不同之处如下。

- 主要关注点：NSA 更侧重逻辑推理与效率提升，MoBA 则专注更快处理长文本。
- 核心方法：NSA 采用稀疏注意力机制，通过挑选关键值优化注意力；MoBA 采用基于块的注意力机制，有选择地进行处理。
- 最佳应用场景：NSA 更适合复杂问题求解与深度推理，MoBA 更适合摘要、长对话与文档分析。
- 计算策略：NSA 通过优化注意力机制减少内存使用，MoBA 通过将文本分块并仅处理相关部分来缩短计算时间。
- 性能方面：MoBA 在处理 1M token 时比 Full Attention 快 6.5 倍，而在处理超长文本如 1000 万 token 时优势更显著，可达 16 倍以上加速。此外 MoBA 在大语言模型高效注意力计算方面取得显著进展。NSA 在通用基准测试中超越传统 Full Attention。
