总体来看，Manus 是一套以任务拆解与结构化执行为逻辑主线的多代理协作系统。交互初始阶段，系统会先用需求解析环节读取用户的真实意图，借助大模型提炼出关键目标，对模糊或不完整的描述主动追问澄清，随后把整体诉求拆成可落地的子任务。

在实施层面，Manus 接入了一套复合型工具集，覆盖网页操作、文件读写、Shell 调度、通信通道以及部署能力，支持多模态任务的开展，并兼容 JavaScript、Python 等十余种编程语言和主流开发框架。

执行层面采用动态规划策略，任务分步推进时全程监控进度，一旦出现阻碍便触发自适应调整，生成备选方案。

质量保障侧形成验证、测试与反馈闭环，确保交付结果可靠，同时严格遵守隐私保护、系统安全限制和伦理准则。

整体上，Manus 可通过持续学习提升处理效能，但受上下文窗口长度和沙盒隔离机制制约，无法触及外部系统或执行越权操作。

### 7.1.3　开源方案介绍

Manus 的表现带动了开源社区对通用代理技术的快速跟进。闭源收费与邀请码管控让开发者寻求可自主掌控、成本更低且原理可查的替代方案，于是诞生了 OpenManus 等项目。

技术思路上，这些开源实现与 Manus 高度一致，都采用多代理协同架构。基本做法是将用户提供的复杂自然语言指令，例如“分析数据并生成报告”，自动拆分为逻辑清晰的子任务，分派给各有专长的执行单元，如负责检索的、负责编程的、负责整理文件的协同完成。同时都很重视工具接入，通过网络检索、代码解释器、文件操作等外部能力，扩展代理在数字环境中的实际行动半径。

开源与闭源的差别不仅是使用费用，更在于透明度与可演进空间。以 OpenManus 为例，其致谢中明确提及 Computer Use 与 Browser Use 等项目，清晰交代了技术来源与构建思路。架构可视后开发者能审阅、定制并优化，进而推动整个代理领域的迭代与生态繁荣。

OpenManus 主要由四部分构成。

（1）**代理模块**。定义基础代理接口与主要实现，涵盖任务规划、ReAct 式推理与工具调用处理。
（2）**流程模块**。提供类 Manus 的工作流基类，实现代理的获取、添加与状态维护，状态包括未启动、进行中、已完成、受阻，并提供 FlowFactory 用于为多个代理创建不同类型的工作流。
（3）**工具模块**。收纳各类工具脚本。同样选用 browser-use 库驱动浏览器，支持的动作包括地址跳转、返回、刷新、网页搜索、元素交互、内容抽取与标签页管理等。
（4）**提示词模块**。内置 Manus、Planning、Swe、Toolcall 等代理的提示词，分为系统提示词与指导下一步行动的 NEXT_STEP_PROMPT。

从 Manus 到开源替代的发展路径表明，多代理任务分解与工具调用已成为通用 AI 代理的技术共识。公开代码与协作开发降低了门槛，使代理技术从封闭产品转变为可审阅、可修改的开放基础设施，为后续创新提供基础。

### 7.1.4　商业对手介绍

Manus 的走红让用户直观感受到通用 AI 代理与传统对话大模型的本质差异，前者能够自主操作电脑、使用浏览器、编写代码。Manus 基本定义了该品类的功能与形态，也点燃了赛道热情。

#### 1．扣子空间

2025 年 4 月 18 日，字节跳动旗下首个面向消费者的通用 AI 代理“扣子空间”正式开启内测。其定位兼顾通用实习生的广度与领域专家的深度，具备无限拓展能力。可自动分析需求、拆解子任务、调用浏览器与代码编辑器等工具，并以 PPT、网页、文档等多种形式交付结果，核心能力是集成外部工具与服务以处理复杂任务。

发布前，字节在 2025 年 3 月开源了代理产品 TARS。界面与 Manus 相似，左侧对话区，右侧实时展示代理在虚拟机中的操作过程。TARS 支持 MCP 协议，具备图形界面交互能力。

TARS 的视觉交互基于字节自研的原生 GUI 代理模型 UI-TARS。该模型采用视觉-语言架构，通过增强感知、推理机制与统一动作建模解析 GUI 元素并执行点击、输入等操作。扣子空间的浏览器调用与界面操作应用了该模型。

从 Manus 到 TARS 再到扣子空间，竞争焦点由“能否操作”转向“如何高效开放地操作”。开源 UI-TARS 并支持 MCP 协议，字节既推出消费级产品也在构建以代理为核心、工具可扩展的开放生态。

#### 2．AutoGLM

AutoGLM 是由智谱团队开发的移动端通用 AI 代理，核心创新在于将大模型的规划决策能力与机器人流程自动化技术深度融合，使其能够像人类一样直接操作手机应用界面，完成真实日常任务。

与依赖 API 的方案不同，AutoGLM 的技术基础是 Android 无障碍服务，通过“观察”屏幕内容解析 GUI 并“模拟”点击、滑动等操作实现自动化。兼容性广，但对界面稳定性有依赖。

行动导向代理的主要特征如下。

（1）端到端自主执行：接收“点外卖”“预订机票”等自然语言指令后，自主完成打开应用、搜索浏览、比价到下单的完整链路，最终支付需人工确认。
（2）多模态感知与决策：结合视觉识别与 ReAct 式推理实时分析屏幕元素如按钮位置，动态规划下一步路径。
（3）持续学习优化：借助在线强化学习，任务成功率随使用反馈不断提升。

覆盖生活服务自动化如外卖订购、旅行预订，信息处理自动化如新闻整理、论文摘要，设备管理自动化如手机清理、跨应用数据迁移。

生态还延伸出 AutoGLM-Web 专注浏览器自动化，以及 GLM-PC 专注桌面办公自动化，形成移动、网页、桌面全覆盖的解决方案。

#### 3．Genspark

Genspark 超级代理由 MainFunc 公司推出，用于执行复杂数字任务与现实世界任务。其定位不是对话接口，而是一个具备自主规划与执行能力的数字执行者，可调用多样工具替代或辅助用户完成信息处理到实际联络的全流程。

核心架构采用混合代理模式，不依赖单一大模型，而是动态整合 DeepSeek 系列等多种专用模型，形成内部专家委员会。系统会根据任务类型自动分派给最合适的模型或模型组合，在速度与准确性上取得平衡。

为实现广泛实用性，构建了庞大的工具调用生态，包括深度信息获取，通过增强搜索与网页抓取主动整合信息；现实世界交互，具备自动电话呼叫等独特功能，可代为酒店预订、餐厅订座；内容与创意生成，能够创建图像、视频、专业文档及演示文稿；数据分析，可直接处理复杂数据集并提供见解。

此外还能按指令生成功能性数字成果，如个人介绍页、可交互网页应用、简易 HTML 游戏，体现“思考即构建”的产出能力。

总体而言，Genspark 通过多模型协同决策加广域工具调用，将 AI 从提供建议的顾问角色推向能够主动执行并交付复杂成果的代理角色。

#### 4．ChatGPT Agent

### 7.2　AI 自动化工具

通用 AI 代理的背后离不开各类 AI 自动化工具，如浏览器自动化工具、桌面自动化工具和移动端自动化工具等。这些工具让代理可全面覆盖 Web 端、桌面端和移动端。

### 7.2.1　Browser Use

Browser Use 是专为 AI 代理设计的浏览器自动化工具，为不具备物理交互能力的代理提供标准化接口，使其能够理解网页内容并执行精细化操作，与真实 Web 应用交互。

不同于传统脚本化自动化，Browser Use 直接服务于代理的决策流程。可接收自然语言指令如“查询今日美股涨幅前十的股票”，并将其分解为导航、点击、滚动、表单填写、数据提取等精准动作，自主完成信息收集、任务执行与状态验证。

技术架构围绕赋能代理设计。

（1）多模型驱动内核：可接入 GPT-4、Claude 或 DeepSeek 等大模型，由大模型负责理解指令、解析页面结构并做决策，适应不同任务复杂度与成本要求。
（2）智能化环境感知：不仅能通过 DOM 与 XPath 识别元素，还能结合视觉与语义理解精准定位交互目标，确保在动态网页中操作稳健。
（3）复杂任务流管理：支持多标签页管理，使代理能在多任务间切换协作；跨平台特性保证部署环境一致。
（4）可扩展行动体系：开发者可为代理添加自定义工具如保存数据到数据库，将浏览器操作与企业内部工作流无缝连接。

关键应用场景包括自主信息代理，定期抓取竞品价格、金融数据等结构化信息；交互验证与测试，模拟真实用户行为执行复杂 UI 流程并动态校验；数字化工作流执行，登录在线办公系统完成文档撰写、报表生成与导出等任务。

Browser Use 通过将自然语言指令翻译为低层浏览器操作，在 AI 代理与 Web 环境之间建立接口，增强环境感知与行动执行能力。

### 7.2.2　Computer Use

Computer Use 是 Anthropic 于 2024 年 11 月提出的技术范式，使 AI 能像人类一样操作计算机系统，包括点击图标、输入文本、管理文件等。

核心特点包括。

（1）**多模态感知**：通过视觉语言模型解析屏幕截图，结合光学字符识别识别文字，定位可交互元素坐标。
（2）**拟人化操作链**：遵循“感知→决策→执行”循环，例如截图分析→光标移动→点击→验证结果。
（3）**系统级输入模拟**：直接调用操作系统 API 执行键盘鼠标操作，支持跨应用操作如 Excel 处理、PPT 制作。

典型场景为跨软件任务，如从股票分析到数据整理的自动调用；端到端测试，模拟用户行为进行软件全流程测试；隐私限制场景，通过界面操作间接完成任务以避免直接访问 API。

该技术可将自然语言精确转换为复杂系统操作指令，未来用户无需学习繁琐软件逻辑，用自然语言即可完成计算机上的常见工作。

OmniParser 是该范式的另一种实现。2025 年 2 月，微软研究院发布 OmniParser V2，可实时解析屏幕界面元素并转化为 JSON 等结构化数据，使 AI 能理解指令并执行点击、输入等操作，无需针对特定界面微调，显著提升效率与精准度。

主要特点为精准解析 UI 元素，从像素级图像中提取可交互区域边界框、功能语义描述及文本内容，无需依赖 HTML 或视图层级；多模态兼容，可与 DeepSeek-R1、Qwen 2.5VL 等主流大模型无缝集成，提升代理任务执行精度。

### 7.2.3　DroidRun

DroidRun 是一个强大的工具，可用自然语言命令控制 Android 设备，具备视觉理解与 UI 结构提取能力，实现流畅交互。

（1）**视觉+UI 解析**：结合视觉模型识别屏幕内容与 UI 结构提取解析控件树，实现精准交互。
（2）**智能自愈机制**：能检测网络中断、界面变化等错误并自动调整操作路径。
