DeepSeek-R1 分布式推理落地与产品化实践全景

（1）算力与网络底座
要让 DeepSeek-R1 实现高效推理，硬件基础必须先行。在 FP8 精度模式下，具体组合可根据计算需求与显存规模灵活选择。8×H200 或 8×MI300X 凭借强大的并行算力与充裕的显存，能扛住大模型复杂的计算压力；2×8×H100/H800/H200 的编排则更具弹性，可依据业务负载动态扩展。

计算之外，节点间的互联质量同样关键。低延迟、高带宽的网络才能避免分布式推理中的传输瓶颈。落地时常用 InfiniBand 等高速互联技术，为多节点协同提供稳定底座。

（2）Kubernetes 集群搭建
Kubernetes 已成为容器编排的主流标准，为分布式推理提供统一的资源调度与管理能力。用户可直接选用 GKE、AWS、阿里云、腾讯云、火山云等主流云厂商提供的托管 Kubernetes 服务，借助成熟的平台快速起稳集群。对数据安全与隐私要求更高的企业，也可自行构建私有 Kubernetes 集群，完成对底层基础设施的完全掌控。

（3）核心组件安装与编排
在集群内部，首先要部署稳定可靠的容器运行时 containerd。它轻量高效，能为推理任务提供坚实运行环境。随后安装 LWS 是实现 DeepSeek 分布式推理的关键，LWS 将一组节点抽象为一个副本单元，统一管理分布式推理负载，保证多节点间的协同效率。

如图 4-19 所示的整体架构，把 Kubernetes 的资源管理能力与推理服务核心功能融合在一起，覆盖了推理基准测试、流量治理、工作负载 API、调度策略等关键环节。通过合理调度与动态资源分配，系统能依据实时推理需求灵活调配算力，提升利用率与推理表现。同时兼容 vLLM、Triton、SGLang 等多种模型服务，为不同场景提供多样化部署选项。

配置文件中 replicas 用来设定副本数，每个副本由一个领导者节点和若干工作者节点构成。leaderTemplate 与 workerTemplate 分别描述领导者与工作者的镜像、启动参数及资源限制，合理配置可确保模型在分布式环境下稳定高效运行。

2）模型加载与初始化
容器启动后，系统会按配置从 Hugging Face 等源地址拉取 DeepSeek 模型权重，此过程要求网络通畅，避免下载中断或文件损坏。借助 vLLM 等推理引擎完成模型初始化与加载时，张量并行 TP 与流水线并行 PP 的参数调优至关重要。

TP 将模型张量拆分到多个 GPU 并行计算，提升算力效率；PP 则把不同层分配到不同 GPU，形成流水处理，减少空闲。结合硬件与模型特性精细调节，可充分发挥分布式系统的性能优势，显著提高吞吐与效率。

3）资源动态分配
Kubernetes 的动态资源分配 DRA 结合 LWS，为推理提供灵活的异构资源管理。通过定义 ResourceClaim，可以按设备属性精准挑选资源，满足不同推理场景需求。

例如指定 nvidia.com/gpu:1 与 rdma/rdma_a:1，表示任务需要一块 GPU 与特定 RDMA 网卡；借助 selectors 中的 CEL 表达式，可进一步筛选显存不小于 80Gi 的 GPU、以及 sriovType 为 vf 的网卡；constraints 则用于约束 GPU 与 RDMA 网卡位于同一 PCIe 根节点，避免资源不匹配带来的性能损耗。

该方式可随推理负载实时调度异构资源，提升利用率并降低成本。

4）推理性能优化
（1）优化缓存机制。缓存感知的推理策略是提速的关键。SGLang v0.4 引入的缓存感知数据并行技术，相较传统轮询调度，缓存命中率从约 20% 提升至 75%。通过优化 KV 缓存管理，避免重复计算，减少资源浪费，大规模推理任务的整体吞吐与延迟均得到明显改善。

（2）推理引擎选择与调优。依据模型架构与目标硬件选型引擎至关重要。vLLM 在大模型推理上具备高效计算与灵活配置能力；SGLang 在缓存管理与特定硬件环境下表现突出，适合对缓存利用率要求高的场景。

选定引擎后需进行针对性调参。以 vLLM 为例，可调整批处理大小、队列长度等参数。通过多次压测找到吞吐与响应速度的最佳平衡点，例如高并发时适当增大批处理可提升吞吐，但可能增加延迟，需结合业务权衡。

5）推理服务管理
（1）弹性伸缩。结合 Kubernetes 的 Horizontal Pod Autoscaler 与 LWS，实现推理服务的智能弹性。传统方案以 GPU 利用率为指标易导致分配不合理，本方案改用更贴合大模型负载的指标：请求队列长度、批处理大小、KV 缓存使用率等。

请求上升时 HPA 自动扩增 LWS 副本，引入更多节点组参与推理；请求下降时自动缩减副本，释放闲置资源，兼顾质量与成本。

（2）故障恢复。LWS 提供完善的故障处理机制。组内节点或容器异常重启时，系统执行整组重启策略，保证推理工作负载的一致性，避免部分故障导致结果不一致或服务中断，提升生产环境可靠性。

（3）滚动更新。LWS 支持滚动更新实现平滑发布。通过配置 maxUnavailable 与 maxSurge，可控制更新过程中不可用节点的最大数量与可超额副本的最大数量。旧节点组逐步替换，同时对新节点进行充分验证后再接管流量，实现零中断升级，降低运维风险。

1.行业概况
过去数十年，国内企业级数字化建设经历了电算化、系统化、网络化到智能化的演进。从 20 世纪 90 年代基础业务电子化，到 21 世纪初互联网重塑业务模式，再到 2010 年后云计算、大数据、AI 赋能的智能化应用，政企机构取得阶段性成果。

作为数字化重要伙伴的集成商也经历定位变革。信息化初期，传统集成商聚焦系统集成，构建服务器、存储、网络等底层 IT 环境并提供运维。随着互联网与中台战略兴起，硬件集成价值收窄，集成商向应用集成转型，承接门户、OA、ERP 等复杂系统的建设与集成，推动数据、业务、AI 中台底座建设与业务系统打通，提供咨询、方案实施与运维服务。

尽管如此，市场仍存在系统割裂、重复建设、效率不高等问题，成果多停留在工具层面，业务价值难以充分体现，数智化转型仍面临挑战。
