# 构建HR体系的确定性底座

制度文件和架构图只是表象，真正让企业稳健运转并持续进化的，是贯穿始终却鲜被看见的支撑结构。它要承载当下的业务，也要具备迭代能力去承接未来的不确定。环境波动越大，越需要一个可依赖的内部基座。

本篇拆解HR体系搭建中的八大痛点，聚焦AI如何作为HR的专业增幅器，让体系设计更清晰、更落地。

## 第一节 职位管理：组织运转的操作盘

当企业从依赖机会和个体冲刺的阶段，转入依赖系统和能力的阶段，组织建设就成了必答题。在这个演进里，人力体系的底建作用最关键。

不少公司在做HR建设时，优先扑向薪酬、绩效这类冲突大、见效快的模块，却忽略了地基工程，最后陷入反复修补的困局。

根子在于基础没打牢。地基正是职位管理体系，其价值可归纳为三层。

第一，职位体系是战略落地的触点。战略在组织里落地，靠的是最小单元职位将意图传导到人。数千人的组织不可能逐个点对点指挥，必须靠职位承接。

第二，职位体系是责任、权力、回报与能力匹配的载体，决定组织的价值秩序。扎实的职位体系不仅是HR的底盘，也为流程、质量等体系提供坐标。

第三，职位体系是抑制组织熵增的工具。通过动态调整职位、层级、人员适配与考核标准，能把人引向目标。华为对赴艰苦地区攻坚员工缩短晋升年限甚至破格晋升，正是“不让奋斗者吃亏”文化的制度表达。

为什么多数企业对职位体系重视不足，长期处在盲区？核心是低估了设计难度。

传统做法沿用愿景-战略-组织-部门-职位的线性路径，在VUCA环境下会遭遇双重卡点：战略的模糊变动与组织架构的刚性固化冲突。若HR缺乏战略到组织的解码能力，就容易出现职责漂移，战略需求与职位设计脱节，企业要什么和员工能做什么之间出现裂缝，最终资源空转、效率耗损。

这对HR提出三重要求：战略穿透、组织敏感、系统平衡。AI的加入，正好是破解这一困局的杠杆。

图3-1 工作分析全景图

对中国企业而言，处于高速增长与高频竞争中，工作分析应自上而下，先跳出专业深井。实践中多见自下而上，这正是症结。

建议聚焦三大变量。

- **业务战略。** 通过战略解码，厘清战略对组织与职位的具体诉求。
- **人才生态。** 关键任务与现有人才的匹配度，需从人才密度、人才锐度、人才厚度三维度评估。
- **政治生态。** 组织权力结构对职责落地的制约，需审视核心决策者的领导力、部门博弈关系与文化潜规则。

职位体系设计的成败，取决于这三者的动态适配水平。忽视这些，职位体系再漂亮也难以落地。

##### 1.核心能力演绎法

战略的定义多样，但共识有三点：战略是有目的的行动，是今日选择决定未来；战略是在取舍，是不做什么比做什么更关键；战略是目标与能力的匹配。

王志纲将战略概括为东方式表达：在关键阶段如何做正确的事、如何正确地做事，即回答能不能做、怎么做、做什么、谁来做。

该方法先对现状流程做客观描绘，再借助AI识别职责缺失、重叠或模糊之处。

###### 案例：项目管理流程与工作分析

背景：某企业跨部门核心流程如图，寻找改进点。

[PRE3]

输入指令：

请结合标杆企业类似流程经验，分析可能存在的职责缺失、交叉问题，说明理由并给出改进建议。

AI反馈：

####### 1.职责交叉问题

物流安排与生产制造：多部门均涉及“物流安排”“生产制造”“工程安装”，分工不明。

例如：

- 物流调度由谁主导？
- 生产制造优先级由谁协调？

内部沟通重复：“内部沟通”出现在计划与执行阶段，未指定牵头部门，如是否由PMO统一协调。

####### 2.流程衔接模糊问题

- 验收环节责任分散：技术支持/报价部门“协助验收”，主责部门不明。
- 售后服务衔接断裂：售后服务由物料事业部和技术支持共同标注，缺乏客户问题闭环机制。

风险：客户重复投诉，安装问题未反馈至生产端改进。

####### 3.关键控制点缺失

- 风险管控空白：合同签订后未见法务/风控介入审核条款合规性。
- 质量控制缺位：生产制造到工程安装阶段无质检节点。
- 绩效反馈缺失：无部门负责收集项目执行数据，无法支撑持续改进。

####### 4.改进建议

职责清晰化：绘制RACI矩阵。例如物流调度：仓库/钢构部执行，物料事业部需求提报；

流程衔接强化：

- 在关键节点增加跨部门联席会议；
- 建立售后闭环流程。补充控制机制：
- 增设风控审核岗；
- 插入质检关卡；
- 设计项目复盘模板。

集团管控梳理法的应用逻辑与此相近，不再赘述。

明确“应该做什么”后，还需判断“现实中能做到什么”。这要结合政治生态与人才生态，评估一年内的可行路径。没有标准答案，需HR基于实情判断。

###### 案例：成本控制到底要控什么

某民营建筑企业年产值约40亿，下属多家子公司，四家主力贡献超80%营收。各子公司差异大，负责人多为老板亲信，自主权高。老板宽厚、战略强、管理弱。

行业下行期，总部设成本控制部，意图加强子公司成本监管。按制度设计，部门负责全过程成本管控，参考国企模式。理论上合理，实际遇阻：

- “诸侯制”导致协调受限，业务难以被总部有效介入；
- 专业能力与资源不足，动态管控依赖经验丰富的驻场专家，公司难以承担。

权衡后，企业短期调整策略，聚焦基础工作：统一成本测算口径与核算标准，优先推动制度合规，为后续深化管理铺路。

从“控成本”转向“控流程标准”，是在资源约束下的渐进转型路径。

#### 三）部门定位与职责厘清

自上而下与自下而上的分析完成后，部门职责初稿形成。可借助AI结合职责房屋模型进一步厘清定位，如图3-4。

[PRE4]

图3-4 部门职责分析之房屋模型

部门职责分三类：顶层设计类即房顶，流程类即腰部，支持类即地基。

- 顶层设计类：体现战略定位与全局视角，侧重政策、规划、资源整合等决策；
- 流程类：涵盖端到端流程分解，保证任务完整与协调；
- 支持类：底层支撑与保障，如系统建设、资源支持、团队管理。

示例指令：

请结合部门职责房屋模型，分析附件职责说明书，归类各项职责，并参考标杆经验识别交叉、重叠或遗漏。

部门职责定稿后，若首次构建职位体系，应先完成体系框架设计，包括模式选择与职级定位规则，再分解至职位。类比建房，先定地基与承重，再布水电。

工作分析扎实后，再进入职位体系初始化与导入，成功率大幅提升。

#### 一）三种职位体系模式的选择

常见模式有以职责为基础和以能力为基础两种，逻辑与适配场景差异明显，如表3-1。

表3-1 职位体系典型模式

| 模式差异 | 职位体系模式 |
| :--- | :--- |
|  | 以职责为基础（A） | 以能力为基础（B） |
| 特点 | 侧重点 | 对岗位价值评价 | 对个人能力评价 |
|  | 职位级别 | 窄带 | 宽带 |
|  | 评估工具 | 较为复杂 | 相对简单 |
| 适用条件 | 外部环境 | 变化较少 | 灵活多变 |
|  | 工作性质 | 流程性、程序化强 | 非结构化高智能 |
|  | 人的要求 | 严格按流程执行 | 发挥主观能动性 |
|  | 职位职责 | 相对稳定 | 职责多变 |
|  | 适用企业 | 稳健发展 | 快速发展 |
| 与薪酬对接逻辑 |  | 以岗定级以级定薪岗变薪变易岗易薪 | 以能定级因类定薪人事相宜级随人走 |

两类模式各有挑战。

A模式挑战：如何保持职位设置与业务需求贴合？如何构建透明动态的岗位价值评估体系？

B模式难点：如何确保不同序列层级含金量一致？如何让能力标准对齐战略且可演化？

除此之外，混合模式C逐渐流行。其做法包括：

- 族群区分式混合。管理类职位采用A模式，专业类职位采用B模式；
