# 检测接口与 JNI 桥接解析

整体架构拆成两部分：C++ 侧完成模型推理调度与资源管理，JNI 层负责把 Java 侧的调用和数据搬运到本地。先从推理入口看逻辑。

单目标路径是 ApiDetect。函数一进来就把 error 置为 FRAS_SUCCESS，随后按传入的句柄从 DetectorPool 取出对应的 MlDetector。取不到资源时会把错误改写成 FRAS_HANDLE_NOT_FOUND 并直接返回 0。拿到有效资源后会调用 MlDetectObjects，传进去的是图像指针、宽高、行步长 width*3、通道数 24、置信阈值 0.7f 以及最大返回数 1。检测到目标时，内部的 MlLandmarkResult 会被转写成对外统一的 ObjectLandMarks，最后返回实际命中个数。

多目标路径是 ApiDetectMany，流程与单目标相近但面向批量。同样先校验句柄，校验通过后根据 maxCount 分配一个 MlLandmarkResult 缓冲区，调用 MlDetectObjects 时把上限设为 maxCount。推理结束后再按索引把每个内部结果映射到 detectionResult 数组的对应位置，并把真实数量交还给调用方。

JNI 封装把上述 C 接口暴露给 Android。initialize 会把 jstring 转成 std::string 调用 ApiCreateDetector，拿到句柄后写回 Java 对象的 handle 字段。destroy 从对象中取出句柄调用 ApiDestroyDetector。setParam 先读取句柄并解析 Java 参数对象，再调用 ApiSetDetectorParam。detectObject 通过 GetByteArrayElements 把 jbyteArray 映射为 unsigned char*，调用 ApiDetect，释放数组后根据 objectCount 决定返回包装好的 Java 对象还是 nullptr。detectManyObjects 则先 new 出 ObjectLandMarks 数组，调用 ApiDetectMany，释放字节数组后再按返回数量构造 Java 对象数组并逐个填充。

资源管理以提取器为例。ExtractorPool 是一个静态实例，容量固定为 32。ApiCreateExtractor 先清零错误码并校验 license，校验失败则标记 FRAS_LICENSE_NOT_FOUND 并返回无效句柄。随后调用 MlCreateExtractor 创建底层提取器，错误码透传给 ApiError，创建失败同样返回无效句柄。成功后通过 ExtractorPool.Allocate 分配句柄，若池已满则把错误置为 FRAS_HANDLE_USE_UP。ApiDestroyExtractor 先重置错误，再用句柄从池中取出底层资源。
