# 第6章 【实战案例】“插件开发”智能体——让AI能查天气、处理图片

插件相当于给 Coze 平台上的 Bot 装上的外接设备。有了插件，Bot 不再受限于内置知识库和基础能力，可以直接连到外部世界：查询实时天气、调用股票接口、甚至操作私有系统的数据。本章聚焦 Coze 平台的两大核心插件：已有服务 API 插件与编程插件，从概念到落地，手把手教你为 Bot“升级装备”，应对更复杂的业务需求。

## 6.1 快速插件

动手做插件前，先搞清楚插件是什么、怎么运转，就像用新工具前先看说明书，基础明白了，后续操作会更顺。

### 6.1.1 到底什么是插件

简单说，插件是 Coze 平台上可即插即用的功能模块。举例，用户问“北京今天天气怎么样”，Bot 自身没有实时天气数据，就需要调用“天气插件”。该插件已提前与第三方天气 API 完成对接，Bot 只需下达“查询北京天气”的指令，插件即可实时拉取数据，Bot 再用自然语言转述给用户。

本质上，插件是 Bot 与外部服务之间的“翻译官”：把 Bot 的需求转成外部 API 可识别的请求格式，再把 API 返回的原始数据，比如 JSON 格式的天气信息，整理成 Bot 可理解的内容，最后转成用户能读懂的回答。

### 6.1.2 工作全流程

以“查天气”为例，拆解插件的运行链路：首先用户提问，比如“杭州现在气温多少”。Bot 收到消息后先判断能否自行处理，若知识库里没有实时天气，则可借助“天气插件”解决，这一步是意图识别。其次 Bot 按插件规范准备必要参数，比如“城市：杭州”，触发插件调用。再次插件把请求转换为第三方天气 API 可识别的格式，例如拼接成 https://api.weather.com/now?city=杭州&key=xxx，再经 Coze 平台发送给外部 API。外部 API 处理后返回包含温度、天气状况的 JSON 数据，插件从中提取关键信息，比如仅保留“温度25℃”“晴”。最后 Bot 把这些关键信息组织成自然语言，回用户“杭州现在晴天，气温25℃”。

整个过程类似你请朋友帮忙查天气：你描述需求，朋友知道用哪个工具，朋友按工具要求提供信息，工具返回结果，朋友整理后再告诉你。在此过程中你无需关心朋友用 App 还是网页查询，而插件就是 Bot 的得力助手。

### 6.1.3 关键构成

无论哪种插件，都有几个必备要素，就像做菜不能缺主料，缺了这些插件无法正常工作，具体如下。

首先是**名称与描述**。名称要直观，比如“天气查询服务”，一眼就能看出用途，别起“小助工具”这种模糊名字；描述更重要，要讲清“插件能做什么、需要什么条件”，例如“本插件可查询全球城市实时天气及未来3天预报，调用时需提供城市名作为必填参数”。Bot 正是依据描述判断是否调用，若描述含糊，比如仅写“能查天气”，用户问“北京明天冷不冷”时可能不触发，反而在问“北京有什么景点”时误触发。

其次是**认证方式**。这相当于访问外部 API 的“门禁卡”。常见有三种：一是“无认证”，适合公开公益 API，无需密钥；二是“API Key”，最常用，通常把密钥放在请求头或 URL 参数里，如“Authorization: Bearer sk-xxxx”；三是“OAuth 2.0”，更安全但配置更复杂，适用于需要用户授权的场景，比如插件要连接微信账号获取聊天记录。

再次是**API 端点**。简单说就是外部服务的“地址”，如天气 API 的端点是 https://api.weather.com/v3/weather/n**。插件必须知道正确端点才能发请求，端点填错，其他配置再对也没用。

然后是**输入参数**。相当于插件需要的“原材料”。比如天气插件需要“city 城市名，字符串，必填”“date 日期，可选，默认当天”。每个参数都要说明类型、是否必填、填写规范。若只说“需要 city 参数”，没说明支持中文或拼音，Bot 可能传入“Beijing123”这类无效值，导致调用失败。

最后是**响应解析**。外部 API 返回的数据往往很庞杂，比如天气 API 可能返回温度、湿度、风速、气压、能见度等数十项，但 Bot 实际只需求“温度”和“天气状况”。此时需在插件里设置“只提取 temperature 和 weather 两个字段”。若不做解析，把全部数据传给 Bot，不仅增加传输时间，还可能让 Bot 抓不住重点、甚至出错。

## 6.2 实战详解：让AI学会调用外部服务

若想让 Bot 调用已有 API，比如高德地图 API、和风天气 API，“已有服务 API 插件”是最高效的选择——无需写代码，只需填对配置即可。

## 6.2.1 创建流程

以下以集成“和风天气 API”为例，演示插件创建步骤。

首先，进入 Coze 平台的插件创建入口。登录后在左侧菜单选择“插件”，点击“创建”按钮，选择“新建插件”。此时会出现两个选项——“已有 API”和“编程插件”，选择“已有 API”。

其次，填写基础信息，这一步直接影响 Bot 是否会调用该插件。插件名称建议写“和风天气实时查询”，避免只用“天气插件”导致混淆。描述要写详细，例如“本插件用于调用和风天气 API，查询全球任意城市的实时天气数据，包括温度、天气状况、湿度、风速等信息，并将城市名称如‘北京’或‘Shanghai’作为必填参数，支持中文和拼音输入”。另外可上传一个小云朵图标，让插件在列表中更易识别。

再次，进行认证信息配置。查阅和风天气 API 文档可知它采用“API Key”认证，需把密钥放在请求头，参数名为“X-Qweather-Key”。在 Coze 的认证设置中选择“API Key”，位置选“Header”，参数名填“X-Qweather-Key”，再填入在和风天气平台申请到的 API Key。需特别注意，API Key 为私密信息，不可泄露。

然后，导入 API Schema。这是核心步骤，决定插件能否正确调用 API。若和风天气提供了 OpenAPI/Swagger URL，通常在文档里能找到，如 https://dev.qweather.com/docs/schema/openapi.js，可直接粘贴到 Coze 的“OpenAPI/Swagger URL”输入框，点击“导入”，Coze 会自动识别所有接口、参数及响应结构，省去手工填写。若没有该 URL，则选“手动编辑”，填写 API 的“URL Path”，比如和风天气实时天气路径为 /v7/weather/now，再选择 HTTP 方法，这里选 GET；随后点击“添加参数”，把“location”设为必填参数，类型选“字符串”，描述写“城市名称如‘北京’或城市 ID 如‘101010100’”，再添加“lang”作为可选参数，默认值设为“zh”中文。
