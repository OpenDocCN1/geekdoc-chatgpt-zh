#### 8.1.9 LangChain向LangGraph过渡
LangChain 社区自 2023 年起就活跃定义大模型应用规范。当前已发布三个大版本，其构建体系里 RAG 与 AI Agent 是两大支柱。LangChain 中构建 AI Agent 的底层架构如图 8.12 所示。

[PRE14]
在 LangChain 框架内，AI Agent 设计被拆分为 Agent、Message 和 Toolkits 三个核心组件。每个 Agent 通常由大语言模型 + 提示 + 输出解析器构成，形成一个 Chain 来处理用户输入。Agent 可处理的输入来自三方面：Input 为用户的原始输入，Model Response 为模型对某个子任务的响应，Context 则携带上下文信息。Agent 的输出连接到实际工具库，具体调用哪些工具由 Agent 模块拆分后的子任务决定。大模型调用外部函数分为识别工具与实际执行两步。Messages→AI Agent→Toolkits 流程负责拆解子任务，并在工具库中匹配相应工具，提取工具名及所需参数，可视为一种静态执行流程。将决策转化为实际行动的工作则交由 AgentExecutor 完成。

总结来看，LangChain 的 AI Agent 架构中，Agent 负责接收输入并决定操作，但并不直接执行，由 AgentExecutor 负责执行。只有把 Agent 作为决策核心与负责运行时的 AgentExecutor 结合，才能构成完整 Agent。其中 AgentExecutor 调用 Agent 并执行其指定的工具，从而实现整体功能。

LangChain 仍是构建大模型应用的前沿框架之一。最新 v0.3 版本基本完成从传统类向 LCEL 的过渡，让定义和执行分步操作序列变得更简洁高效。专业上讲，LangChain 构建的是一个有向无环图。随 AI Agent 发展，大模型使用正从单纯工具执行转向更复杂的推理引擎，这正是 LangGraph 诞生的根本原因。该转变对循环结构和复杂条件交互提出更高需求，使得基于 LCEL 的线性序列在实现更高级系统时逐渐受限。

#### 8.1.10 LangGraph构建Agent的底层逻辑
##### 1. LangGraph概览
从名字看 LangGraph 与 LangChain 关系紧密。实际上 LangGraph 正是以 LangChain 表达式语言为基础构建的 AI Agent 开发框架。因此在模型支持、接入与 Agent 构建方面的优势可以自然迁移过来。从技术角度看，大模型本身无法采取行动，只能输出文本，即接收输入并给出响应。
