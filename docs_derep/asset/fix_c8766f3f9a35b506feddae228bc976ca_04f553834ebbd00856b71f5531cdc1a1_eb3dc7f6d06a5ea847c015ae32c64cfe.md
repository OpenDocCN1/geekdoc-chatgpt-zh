--nproc-per-node 8 定义单机上同时运行的进程数量，设为 8 的目的在于让该节点的多张 GPU 均能被充分调用。
--node-rank $RANK 用来标记本节点在集群中的顺序编号，$RANK 是环境变量，可区分各台机器。
--master-addr $ADDR 指定集群主控节点的网络地址，由主节点统一协调其余节点。$ADDR 通常填写主节点的 IP 地址或主机名。
generate.py 是启动文本生成任务的主脚本，内部会调用模型推理并生成文本。
--ckpt-path /path/to/DeepSeek-R1-Demo 指向已转换完成的 DeepSeek-R1 模型权重目录，该路径即为转换阶段保存的文件位置。
--config configs/config_671B.json 指定模型配置文件，其中包含结构、超参数等信息，此例采用 671B 对应的配置。
--interactive 启动交互式会话，开启后可在命令行直接输入并即时获得模型返回。
--temperature 0.7 调节输出的随机强度，取值越大越发散，越小越确定，0.7 属于适中偏创造性的设定。
--max-new-tokens 200 限制单次请求最多生成的全新 token 数，上限为 200。

同期开源了 DeepSeek-R1-Zero 与 DeepSeek-R1 两个约 660B 的模型，并基于 R1 的输出蒸馏出 6 个轻量化模型对外开放，其中 32B 与 70B 版本在多项指标上逼近 OpenAI o1-mini。

因此 R1 项目仓库中未单独列出权重、推理脚本或本地部署说明，这些内容已收录在 DeepSeek-V3 项目中，可参考 3.1 节。

#### 3.2.3 参数与能力边界说明

通过 API 调用 R1 时，可调整多项参数以控制长度、风格多样性与逻辑严谨性。chat.completions.create（）接口的核心参数在前文已说明，R1 与 V3 共用同一接口。

同时 R1 在参数解析与推理机制上存在部分特有规则，调用时需注意：

##### 1. max_tokens 参数

- （1）max_tokens 仅限制最终答案部分，即 content 字段的最大长度。默认 4096 token，约 3000 汉字，上限 8192 token。
- （2）该限制不包含思维链 reasoning_content。在复杂任务中，reasoning_content 可达 32K token，因此总输出可能远超 max_tokens 设定。官方后续计划推出 reasoning_effort 参数以调节推理深度与长度。

##### 2. reasoning_content 字段

- （1）R1 的特点是除 content 外还会返回 reasoning_content，二者同级。
- （2）该字段记录模型推导结论前的思考过程，适用于解释、教学与评估场景。

##### 3. 功能支持情况

- （1）目前已开放标准对话补全 Chat Completion，以及对话前缀续写 Beta，支持在已有内容基础上续写。
- （2）Function Calling、JSON 格式输出、FIM 补全 Beta 暂未开放，相关字段设置无效。

##### 4. 不生效的参数

temperature、top_p、presence_penalty、frequency_penalty、logprobs、top_logprobs 在调用 deepseek-reasoner 模型时会被静默忽略，但为保持与 OpenAI 接口兼容，设置后不会报错。

##### 1. DeepSeek-R1 思维链演化过程

思维链 reasoning_content 是 R1 完成任务时自动生成的推理轨迹，以自然语言呈现模型处理问题的逻辑展开与中间判断，并与最终答案 content 一同返回。其演化规律如图 3.30 所示。

[PRE0]

DeepSeek-R1的思维链在多轮对话中呈现出清晰的阶段性演化规律。

- （1）第一轮对话通常体现为独立推理，模型基于用户的初始提问进行结构完整、逻辑自治的思考。
- （2）进入第二轮时，模型开始进行递进式推理，能够引用前文内容（前文的问答对）并进行自然衔接，展现出良好的承接性。
- （3）到第三轮及更复杂的轮次，模型则逐步发展为综合性推理，整合多轮信息与多个变量，输出具有清晰逻辑排序的推理链条。随着对话的深入，DeepSeek-R1不仅展现了强大的单轮分析能力，更体现出对上下文的记忆保持、逻辑递进与归纳整合能力，具备类人类的“思维连续性”与“对话一致性”。这使得它不仅适用于一次性问答，还能胜任复杂交互场景。
