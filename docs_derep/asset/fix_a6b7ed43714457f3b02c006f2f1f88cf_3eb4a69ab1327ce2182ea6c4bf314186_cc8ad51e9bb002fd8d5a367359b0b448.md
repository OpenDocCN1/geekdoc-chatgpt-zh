阻断未授权访问的关键在于入口管控，建议同时启用防火墙与 IP 白名单机制，严格限定数据库的连接源头，只让列入名单的账号操作。敏感资产应按重要程度分级，并以强加密结合细粒度访问管控作为防护底座，减少泄露风险。再辅以高可用部署架构和 DDoS 抵御方案，保证服务稳定不中断。

## 6.3 模型公平性优化

拒绝回答机制（参见 4.3.2 节）只是对模型产生不当输出的补救举措。能否从根源上预防偏见的出现？本节聚焦这一问题。RAG 系统通过知识库为大模型提供外部信息，使回答更贴近现实。但若基础模型本身带有偏见，生成阶段容易放大这种倾向。即使检索到的资料保持中立，先验偏好仍会左右最终结果。因为语言模型的能力受训练语料影响，语料中的偏见会在推理时被复现。因此即便知识库客观，输出仍可能偏离真实，甚至带有歧视色彩。这会损害答案准确度，也可能让用户产生负面体验，并推动不公平信息的扩散。构建 RAG 系统时必须把偏见控制放在优先位置，通过发现和清除模型内部的偏见来保障结果的公平与可信。

### 7.1.1 原理解析

LongRAG 通过重构检索与生成流程，有效缓解了传统 RAG 在长文本场景下的挑战。

1. 传统 RAG 框架的局限性

传统 RAG 中，检索模块从海量文档库里找出与查询相关的短片段，通常是约 100 词的维基段落；生成模块则基于这些片段产出答案。这种设计存在明显失衡。

1）检索压力过大：在庞大库中搜寻短片段，难度和计算成本都很高。

2）生成信息不足：短片段容易丢失上下文，导致答案准确性和完整性受损。

3）无关信息干扰：切片窗口过短，检索容易带入与查询无关的内容，干扰生成。

2. LongRAG 的创新设计

LongRAG 通过引入长上下文检索单元和对应的长上下文生成模块，重新分配检索与生成的工作量，核心设计包括三点。

（1）核心设计模块

1）长检索单元：将整篇文档或若干相关文档合并为长度超过 4K Token 的检索单元。单元更长意味着总数大幅下降，同时保留更完整的上下文。例如检索单元数从 2200 万降至 60 万，减轻检索负担并提升效率。

2）长检索器：在少量长单元中检索，只返回前若干个（通常少于 8 个）最相关单元。相比传统 RAG 需要召回数百个短单元，长检索器检索更快、成本更低，也减少了引入硬负样本的风险。

3）长生成器：将检索到的长上下文（约 30K Token）输入支持长上下文的语言模型，如 Gemini-1.5-Pro 或 GPT-4o，进行零样本生成。依托现代长上下文模型的强大能力，长生成器能在更丰富的上下文下产出更准确、更详实的答案，无需额外训练。

（2）性能优势

借助上述设计，LongRAG 在多个数据集上表现突出。无训练情况下，在 NQ 和 HotpotQA 上分别达到 62.7% 和 64.3% 的精确匹配率（EM），与最先进的全监督 RAG 模型相当。在 Qasper 和 MultiFieldQA-en 等非维基数据集上，LongRAG 在 F1 分数上也有显著提升。

LongRAG 通过长检索单元与长生成模块，有效缓解了传统 RAG 检索过载与生成信息不足的问题，既提升了检索效率，也增强了答案的准确性和完整性，为下一代 RAG 设计提供了新思路。
