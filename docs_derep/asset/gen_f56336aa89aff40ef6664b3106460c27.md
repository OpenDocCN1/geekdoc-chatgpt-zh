另外值得一试的是自动混合精度训练，半精度模式通常能带来明显的提速。虽然它可能会对收敛行为和模型质量产生波动，但绝大多数模型在开启后仍能与单精度训练达到相近的效果。需要注意的是使用时要保持谨慎，必须对收敛情况做严格验证。总的来说，自动混合精度是一种带一定风险的优化手段。

我们把自定义算子放在最后考虑，主要是投入产出比偏低且不确定性较大。一般只有在追求极致性能的场景下才会去尝试。会写 CUDA / CPU 加速算子的开发者，需要具备扎实的高性能计算背景，开发门槛高、耗时耗力。另一种做法是使用开源算子库，不过第三方库往往存在适用限制或副作用，不一定能直接用于自己的模型，优化效果也难以掌控。

总体而言，高级优化方法在门槛、精力与时间成本上要求都比较高，但一旦适配成功，性能提升非常可观。第10章以 GPT-2 为例，同时应用了 torch.compile 与自动混合精度训练，取得了显著提速。感兴趣的读者可以直接跳转第10章，亲眼感受这些高级技巧的实际效果。

## 10 GPT-2 训练优化实战全流程

前面章节已经介绍了不少优化思路，但在讲解单个技巧时，为保证阅读体验示例都比较简化。那么这些方法在真实训练中表现如何？本章就以 GPT-2 训练为例，从实战角度检验各项技巧的真实效果。

选择 GPT 系列，主要是模型结构简洁且可扩展性强，几乎可以放大到任意规模。模型代码主要在 MinGPT 开源实现上做了修改。选用 MinGPT 的原因是它代码简洁、优化较少，非常适合用来展示优化前后差异。

### 10.3 显存优化

显存优化的主要目的是消除 Out of Memory 错误，让更大的模型在现有硬件上跑起来。

即使出现 OOM，也可以通过打印显存图谱定位峰值，但无法量化每个技巧的节省效果。为此本节使用相对较小的 GPT-large，并在其上逐步压缩显存。

GPT-large 含 774M 参数，n_layers 为 36，n_embd 为 1280，n_heads 为 20，未经优化且 BatchSize 为 32 时训练显存约 35GB。

整体思路很直观：先打印显存使用情况，再确定峰值位置，分析成因并制定策略，反复迭代即可逐步降低占用。最后还会展示优化后最大可训练模型规模扩大了多少倍。

#### 10.3.1 基线显存占用

参考 7.2 小节，虽然可用 torch.cuda.max_memory_allocated 或 torch.cuda.max_memory_reserved 来打印占用，但实际以 NVIDIA-smi 为准。为保持严谨，本节统一以 NVIDIA-smi 为依据，同时打印显存使用图表以便分析峰值。

未经任何优化的 GPT-large 显存占用为 36272 MB，训练 10240 个样本耗时 16.3s。从图10-3 可见峰值出现在前向传播结束、反向传播开始的位置。一般这是因为反向计算图缓存了过多中间结果。

[PRE4]

#### 10.3.2 使用跨批次梯度累加

当峰值出现在前向结束、随反向推进逐渐下降时，通常是前向构建反向图时缓存了大量张量。

最直接的办法是降低 BatchSize，但会明显影响吞吐。这里采用 7.5.1 小节的跨批次梯度累加，在保持有效 BatchSize 不变的前提下减小前向张量尺寸。

将累加因子设为 2，即每轮 BatchSize 减半，每两轮更新一次参数。优化后峰值降至 25194 MB，训练 10240 个样本总时间增至 17.2s。

此时显存图如图10-4 所示。

[PRE5]

可以看到原本一个峰被拆成两个连续训练的峰值，峰值仍出现在前向刚结束、反向尚未开始的位置，说明减尺寸只是缓解了问题，并未根除成因。

#### 10.3.3 开启即时重算前向张量

要从根本上解决，可要求 PyTorch 减少对前向中间结果的缓存，这正是 7.5.2 小节的即时重算方法。在 Transformer Block 中开启后，显存峰值降至 15394 MB，对应训练时间增至 23.1s，额外开销来自反向时重算前向张量。优化后显存图如图10-5 所示。
