在今天的计算体系里，图形处理器早已不只是绘图工具，更是承载大规模并行计算的核心引擎。相较于 CPU 偏向顺序执行的编程思路，GPU 编程更聚焦于数据并行与任务并行，以此来消化海量数据与复杂运算的压力。图 3-5 所示为 GPU 数据处理流程。

GPU 编程模型的关键构成要素可归纳为并行执行单元、线程与线程块、内存层级、数据并行与任务并行、同步与通信，逐项说明如下。

**并行执行单元：**GPU 内部部署了海量的并行执行单元，能够同时处理多组数据或多项任务。开发者通过设计并行算法把计算拆分到这些单元上，从而获得加速效果。

**线程与线程块：**GPU 上的计算通常被抽象为线程 Thread 与线程块 Block。线程是最基本的执行粒度，多个线程聚合成一个线程块。线程块能够在 GPU 的流式多处理器 Streaming Multiprocessor, SM 上协同运行，充分发挥并行算力。

**内存层次结构：**GPU 的存储系统呈现多层结构，包含全局内存、共享内存、常量内存、纹理内存等。不同类型在访问速度与容量上差异明显，编程时需依据任务特征合理调配。

**线程同步：**CUDA 程序中大量线程并发执行，需要像交通调度一样避免冲突。线程同步是协作完成任务的基础，CUDA 提供了多种同步原语来保持一致性。

**1. __syncthreads()函数**

__syncthreads()是线程块级别最基础的同步手段，用于让同一线程块内的全部线程汇聚到同一点再继续。调用该函数的线程会阻塞，直至块内所有线程都到达同步点，常见于共享内存写入完成后统一读取。

[PRE2]

**2. __threadfence_block()函数**

为了保证数据一致性，CUDA 提供了 __threadfence_block()用于块内同步。其作用是确保调用前对全局内存或共享内存的写入，对调用后同一线程块内的所有线程可见，形成块内屏障。

典型用途有：

**共享内存同步：**共享内存读写速度快，但缺乏同步易导致竞争。该函数可确保所有线程完成写入后再访问，避免不一致。

**全局内存写入同步：**当块内线程向全局内存写数据并希望在块内立即可见时，可用此函数实现同步。

示例中线程先向共享内存写入，随后调用 __threadfence_block()确保写入完成，再安全读取并写入全局内存。

注意：该函数仅作用于当前线程块，不涉及其他块；会带来同步开销，需谨慎使用；若块内并非所有线程都执行到该点，可能引发死锁。

**3. __threadfence_system()函数**

在块级同步之上，CUDA 还提供系统级同步原语 __threadfence_system()。它保证调用前的全局内存写入对所有 CUDA 流、所有 GPU 上的所有线程都可见，形成系统范围屏障。

使用场景包括：

**跨流同步：**不同流可独立进行计算与传输，若共享全局内存，可用该函数让一个流的写入对另一流可见。

**多 GPU 同步：**在多卡环境下，确保某卡的全局写入对其它卡的线程可见。

注意：作用范围极广，开销较大，实际中应尽量避免。调用会阻塞所有流与设备线程，若相关线程未全部抵达同步点易死锁。大多数情况下更细粒度的同步或 CUDA 事件是更优选择。

**3.2.2 GPU 内存管理**

CUDA 程序性能高度依赖内存管理，涵盖分配释放、数据搬运、访问策略与内存池等多个环节。

**1. 内存分配和释放**

使用 CUDA API 在设备上申请与回收内存。cudaMalloc()分配设备内存，cudaFree()释放。与 CPU 不同，GPU 显存有限，合理分配并及时释放可避免泄漏并提升利用率。

**2. 数据传输**

CPU 与 GPU 拥有独立内存空间，计算前需把数据从主机拷贝到设备 Host-to-Device，即 H2D；计算后需把结果从设备拷回主机 Device-to-Host，即 D2H。cudaMemcpy()支持这两种方向的搬运。为提升效率，可采用批量传输、异步传输等策略。

**3. 内存访问策略**

不同内存类型访问速度与容量各异。频繁访问的小数据宜用共享内存加速，大规模数据多放全局内存。此外，优化数据布局、减少 bank 冲突等手段也能改善访问效率。

**4. 内存池技术**

为降低频繁分配释放的开销，可采用内存池技术预先分配一块显存，运行时从池中取用，减少 API 调用次数，提升执行效率。开发者可在 CUDA 程序中自建内存池管理显存。

注意：

（1）内存对齐：部分 GPU 操作要求数据对齐到特定边界，分配与传输时需注意对齐，避免性能下降或错误。

（2）错误检查：CUDA API 可能返回错误码，应定期检查并妥善处理异常。

（3）资源管理：需合理控制线程与内存使用，过量占用可能导致性能衰退或系统崩溃。

良好的 GPU 内存管理是 CUDA 程序高效稳定运行的基础，对加速深度学习模型训练、提升模型性能意义重大。

### **3.3 大模型训练中的 GPU 优化**

大模型训练对计算需求极大，GPU 的并行能力使其成为首选。但仅靠硬件不足以达到最优，需结合优化策略提升训练效率。

**3.3.1 数据并行与模型并行**

为充分利用多 GPU 资源，常用数据并行与模型并行两种思路。图 3-9 所示为两种方式的对比，上方为数据并行，将数据分块处理；下方为模型并行，将模型拆分为多个子模型并通过数据交换协作。

**1. 数据并行**

把训练集切分为多个子集，由不同 GPU 并行处理各自子集，完成前向、损失计算与反向后再通过参数平均等手段同步模型，保持一致。

优点是可以充分利用多卡算力加速训练。挑战在于参数同步开销与 GPU 间通信延迟，可通过梯度累积、异步更新等技术缓解。

在 PyTorch 中，可借助 torch.nn.DataParallel 与 torch.nn.parallel.DistributedDataParallel 等接口快速实现数据并行。

**2. 模型并行**

将模型的不同部分分配到不同 GPU 计算，适用于单卡无法容纳整个模型的大模型场景。通过拆分层或模块并配合 NVLink、PCIe 等进行通信实现协同训练。

实现相对复杂，需处理模块依赖与通信成本。PyTorch 可手动指定各部分所在设备，也可借助 Megatron-LM 等高级库简化模型并行开发。
