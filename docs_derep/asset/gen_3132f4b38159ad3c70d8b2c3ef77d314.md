FTP 建立数据通道的本质就是数据传输模式的选择，业界常见的是主动模式 `PORT` 和被动模式 `PASV`。判定标准以服务器为视角：若服务器主动向客户端发起连接即为主动模式，若服务器仅保持监听等待客户端来连即为被动模式。

主动模式 `PORT` 的流程是这样的。客户端先向 FTP 服务器的 21 端口发出连接请求，握手成功后控制链路就建立了。需要传数据时，客户端会在控制链路上发送 `PORT` 命令，告诉服务器我已经打开了一个本地端口，请过来连。随后服务器就从自己的 20 端口向客户端指定的端口发起连接，客户端接受后数据链路成立，开始传输。

被动模式 `PASV` 的流程则相反。客户端同样先连 21 端口建立控制链路。需要传数据时，服务器在控制链路上返回 `PASV` 命令，告知客户端我已开启了一个临时端口，请来连接。客户端收到信息后向该端口发起连接，服务器接受，数据链路即建立。

读到这里有人会问，为什么除了 21 端口还会出现 20 端口和随机端口。部分资料称 FTP 使用 TCP 20 和 21 端口，这是不准确的，会造成误导。实际情况是主动模式下 21 端口负责控制连接，20 端口负责数据连接；被动模式下 21 端口仍负责控制，数据连接则使用服务器分配的随机端口。因此做防火墙策略时，运维人员必须清楚 `PORT` 与 `PASV` 的工作机制。

**注**
FTP 服务器默认工作在 `PORT` 模式下。

`PORT` 与 `PASV` 的核心差异在于数据端口的建立方式。从网络安全角度看，`PORT` 模式因为端口固定，更利于防火墙做端口保护。`PASV` 模式的出现是为了降低数据被偷抓的风险，因为 `PORT` 模式里 20 端口固定传输数据，容易被嗅探工具捕获，改用随机端口能显著提升窃取难度。

企业实际使用中，FTP 从来不是单打独斗，通常会配合防火墙等安全组件一起使用，才能形成完整的安全运维体系。

## 第 22 章 企业服务体系：DNS

### 22.1 DNS 工作原理揭秘

DNS 服务在日常上网中无处不在，它的核心职能就是把域名解析为对应的 IP 地址，可以把它想象成互联网的通讯录，域名对应电话号码。

早期网站只能用 IP 地址访问，比如 `192.168.4.23`。随着网站数量爆炸，靠记忆一串数字极不现实，查表成本也太高。于是 DNS 服务应运而生，让用户只需记住域名，浏览器输入后由 DNS 自动翻译成 IP，后台完成转换。

# DNS 服务核心概念

## 域名构成与规则

域名由两个或两个以上部分组成，用英文句号分隔。最右侧为顶级域名 TLD，左侧紧邻的是二级域名 SLD，再往左是三级域名，以此类推。

域名只使用字母和数字，不区分大小写，每级最长 63 字节，完整域名不超过 255 字节，通常在 7 到 20 个字符之间。

图 22-1 单个域名的结构

## DNS 分布式架构

从整体看，DNS 采用层级树状命名。上层服务器知晓下层位置，下层不了解上层。每台服务器不可能掌握全球域名信息，因此 DNS 是一个分布式数据库，由众多服务器协同完成解析。每个站点维护自己的数据，运行查询服务，即使单台故障也不会导致整体失效，避免了单点故障。

## 域名层级划分说明

（1）根域名：互联网顶级解析由根域名服务器完成，被视作互联网的中枢神经。
（2）顶级域名：分为国家类和国际类。
➢ 国家顶级域名 nTLDs：按 ISO3166 国家代码分配，如中国 .cn、美国 .us、英国 .uk、日本 .jp。
➢ 国际顶级域名 iTDs：按组织性质划分，如商业 .com、教育 .edu、非营利 .org、政府 .gov、企业 .biz、网络服务 .net、军事 .mil。
（3）二级域名：顶级域名下可注册的域名，主要由企业和运维人员管理。
（4）三级域名：二级域名的延伸，由网站管理员自行命名，如 mail.abcd.com、www.abcd.com。

## DNS 服务器角色

在同一节点或区域内，DNS 服务器按工作形式可分为：

➢ 主 DNS 服务器 Primary Name Server：权威信息源，从本地磁盘区域文件加载数据，可权威回答所管辖域的查询。
➢ 辅助 DNS 服务器 Secondary Name Server：协助主服务器分担压力，通过区域文件复制获取完整数据，也属权威服务器，无需自行生成区域文件。
➢ 高速缓存服务器 Caching-only Server：无域名数据库，仅缓存远程查询结果，提供间接信息，非权威服务器。
➢ 转发服务器：本地无法解析时将请求转发给其它 DNS 服务器，通常不缓存数据。

## 查询方式解析

本地向 DNS 服务器查询有两种方式：

（1）递归查询：由被请求的 DNS 服务器直接返回最终答案，只需一次请求。
（2）迭代查询：需要多次查询才能得到结果。

图 22-3 展示了典型的迭代查询过程。主机先查本地 `hosts` 文件，无则查本地 DNS 缓存，缓存无则查本地 DNS 数据文件，仍无则向根域名服务器询问，根服务器只告知负责该区域的服务器位置，再逐步追查。根服务器不负责最终解析。

## 解析类型对比

DNS 提供正向解析和反向解析两种功能：

（1）正向解析：`FQDN` 到 IP，域名对应一个或多个 IP。
（2）反向解析：IP 到 `FQDN`，一个 IP 可能对应多个域名。

正反向解析使用两棵不同的解析树，不必部署在同一服务器。

## 常见记录类型

DNS 缓存表中的映射被称为记录，常用类型有：

（1）`A` 记录：正向解析，将域名转为 IP。格式：`完整主机名 IN A IP 地址`
（2）指针记录 `PTR`：反向解析，将 IP 转为域名。格式：`IP 地址 IN PTR 主机名`
（3）`SOA` 记录：起始授权机构，标识区域数据来源，每个区域唯一且位于文件首条。格式：`区域名 IN SOA 主域名服务器 管理员邮件地址 (序列号 刷新间隔 重试间隔 过期间隔 TTL)`，邮件地址中 @ 用 . 代替。
（4）`NS` 记录：向下授权，标识区域的权威服务器。格式：`区域名 IN NS 完整域名`
（5）`MX` 记录：邮件交换器，规定邮件服务器及优先级，数值越小优先级越高。格式：`区域名 IN MX 优先级 邮件服务器名称`
（6）`CNAME` 记录：别名记录，将多个名字映射到同一主机。格式：`别名 IN CNAME 主机名`

**注**
`A` 记录和指针记录必须分开存放。
