在很长一段时间内，一阶谓词逻辑和 λ 演算常被当作符号化语义的表达手段，但它们并非专为自然语言问答设计。文献 [284] 的图 2 显示，这类表示的内部结构与自然语言的句法结构差异明显。面向知识库问答的语句解析，Percy Liang 等人 [285] 提出依赖组合语义 Dependency-Based Compositional Semantics, DCS，配合 Lambda DCS [283] 用以在知识图谱层面形式化问句。该体系的组合方式非常简洁，只用到 join 与 intersect 两类操作，比组合范畴语法里的词典规则要简单得多。

DCS 把逻辑式写成树形结构，称作 DCS 树，其形态与句子的句法结构基本对应。相比一阶谓词逻辑和 λ 演算的写法，DCS 树更便于解析和学习。树中每个节点代表一个约束满足问题 CSP，可逐层求解目标值，根节点的目标值即为整段逻辑的含义。DCS 初次被用于限定领域的知识库问答 [284]，在 Geo880 等多个集合上取得当时最好的成绩。2013 年起 Berant 和 Percy Liang 等人 [49, 50] 将 DCS 迁移到面向 Freebase 的问答，不仅给出方法与模型，还开源了完整的问答系统和评测平台 SEMPRE [资源10-11]，借助该项目后续工作持续提升了解析效果和问答性能 [478]。

### 2. 语义辞典构造

要让自然语言到逻辑表达式的映射能够自动学习，多数方案都需要句子与逻辑表达式配对的标注数据：

句子：哪些城市靠近大上海？
逻辑表达式：λx.City(x) ∧ next_to(x, Shanghai_City)

标注只给出整句到整段逻辑的对应，而解析过程需要词或短语与更细粒度的逻辑片段建立对齐，例如“靠近”对应 λx.λy.next_to(x, Shanghai_City)，“哪些城市”对应 λx.City(x)。

以“杭州靠近上海？”和逻辑表达式 next_to(Hangzhou_City, 上海_City) 为例，理想的词典条目应为：

- 杭州 := NP : Hangzhou_City
- 上海 := NP : Shanghai_City
- 靠近 := (S \ NP)/NP : λx.λy.next_to(x, y)

若词对齐未知，也会出现错误条目：

靠近 := NP : Hangzhou_City
靠近上海 := (S \ NP)/NP : λx.λy.next_to(x,y)

构建过程中允许这类噪声，后续可通过剪枝过滤，例如剔除低频词典项、剔除无法解析出正确逻辑的词典项。

从训练集的 <句子，逻辑表达式> 对中得到 <短语，子逻辑表达式> 的对应关系，常用做法是先用模板和规则从整句逻辑里抽取子逻辑，再与从问句里抽取的短语匹配，生成候选词典项。每条规则都带有一个能触发逻辑子结构识别的词。凡是能匹配该触发词的子结构，CCG 就会为其生成一个范畴。以图 10.8 中①的第二个规则为例，该规则以一元谓词 p 为触发，生成的范畴为 N : λx.p(x)。对于逻辑表达式 λx.major(x) ∧ city(x)，它包含两个一元谓词，可得到 N : λx.major(x) 和 N : λx.city(x) 两个范畴。

图 10.8 辞典构建规则

| 输入触发词 | 输出范畴 | 示例 |
|---|---|---|
| 常量 c | NP : c | NP : 上海 |
| 一元谓词 p1 | N : λx.p1(x) | N : λx.state(x) |
| 一元谓词 p1 | S \ NP : λx.p1(x) | S \ NP : λx.state(x) |
| 二元谓词 p2 | (S \ NP)/NP : λx.λy.p2(y, x) | (S \ NP)/NP : λx.λy.next_to(y, x) |
| 二元谓词 p2 | (S \ NP)/NP : λx.λy.p2(x, y) | (S \ NP)/NP : λx.λy.next_to(x, y) |
| 一元谓词 p1 | N/N : λg.λx.p1(x) ∧ g(x) | N/N : λg.λx.state(x) ∧ g(x) |
| 第二个参数为常量 c 的二元谓词 p | N/N : λg.λx.p1(x, c) ∧ g(x) | N/N : λg.λx.next_to(x, 上海) ∧ g(x) |
| 二元谓词 p2 | (N \ N)/NP : λx.λg.λy.p2(x, y) ∧ g(x) | (N \ N)/NP : λx.λg.λy.next_to(x, y) ∧ g(x) |
| 包含 argmax/min, 且参数二为一元谓词 | NP/NP : λg. argmax/min(g, λx.f(x)) | NP/NP : λg. argmax/min(g, λx.size(x)) |
| 数值型的一元函数 | S/NP : λx.f(x) | S/NP : λx.size(x) |

这是 Zettlemoyer 和 Collins 所提出的从句子–逻辑对构造初始词典的基本方法 [522]。用这些词典项对训练句进行解析，往往得到一个或多个高分分析，从中抽取产生高分的词典项加入原词典，迭代直至不再出现新条目。

该做法实现直接，但对人工模板依赖很重，不易迁移到其他领域或语言。为此 Kwiatkowski 等人 [256] 提出一种不依赖模板和语言的高阶合一方法，把完整逻辑形式切分成可组合的子逻辑形式，能更有效地扩展词典、泛化更好。Wong 等人 [489] 则借助 IBM 翻译模型学习自然语言问句与逻辑表达式之间的符号对齐，假设逻辑表达式是问句意义的另一种语言表达，机器翻译的对齐模型即可捕捉两者符号对应，这种做法常被用来获取初始词典和估计初始参数 [522, 524]。不过文献 [256, 257, 522–524] 中的传统方法多在限定领域和小规模知识库上效果较好，面对 Freebase、DBpedia 这类大规模图谱时，依赖手工规则与模板的词典构造 [522] 难以满足需求。因此在大规模知识库问句解析中，如何扩展限定领域的词典是关键任务。近年来 [49, 77] 等工作主要思路是通过文本与知识库间的对齐关系，学习到文本符号与知识库符号之间的关联强度。

### 10.2.2.2 无监督方法

问句解析的目标是把自然语言转换为可在知识库中直接查询的形式化语句，例如 Semantic Web 中的 SPARQL。部分工作利用人类总结的经验，在没有 (自然语言问句，逻辑表达式) 或 (自然语言问句，答案) 这类监督数据的情况下完成转换。典型流程包括：① 问句分析，把自然语言问句转成查询三元组形式；② 资源映射，确定 Query Triplet 中每个短语在知识库中的对应资源；③ 生成形式化查询语句，按问题类型用模板生成 SPARQL。

PowerAqua 系统 [299] 是 AquaLog 系统 [300] 的后续，通过融合多个异质知识库来回答问题。2011 年 Lopez 等人提出的 PowerAqua 能定位并整合多个知识库的语义资源，采用流水线框架，共 4 步，如图 10.9 所示：

- 1. 语言分析模块 linguistic component：分析问句词语间关系，得到一系列三元组查询表示 (subject, property, object)，即 Query-Triples，把用户需求形式化为三元组语言。
- 2. 元素级匹配模块 PowerMap：决定哪些语义资源适用于用户问句。借助句法分析从各知识库中找出 Query-Triples 可能对应的资源，随后语义验证模块做消歧，保证同一问题的词语不会有多重解释。
- 3. 三元组映射模块 triple similarity service, TSS：利用问句上下文和所选实体周围的知识库信息，从整体上确定最可能的解释。抽取与已有 Query-Triples 最匹配的知识库三元组，把 Query-Triples 映射到具体知识库三元组得到 Onto-Triples。为控制复杂度大量使用启发式规则缩小候选集。

## 10.2.3 基于搜索排序的方法

事实型问答系统通常只处理与实体相关的事实，例如“屠呦呦是哪里人？”这类问句至少包含一个实体词“屠呦呦”，知识即该实体对应的事实，答案是事实中的尾部实体，如 <屠呦呦，出生地，宁波市> 中的“宁波市”。基于搜索排序的知识问答近似人工回答过程，如图 10.10 所示。若给定图谱回答“屠呦呦是哪里人？”，首先要确定主题词“屠呦呦”并链接到知识库实体，这里称为主题实体。答案一般是与主题实体通过关系或路径相连的实体，提取这些实体作为候选，最后从中挑选正确答案，可视为排序或二分类问题。

图 10.10 基于搜索排序的知识问答示意图

检索匹配方法不要求得到问句的形式化查询，直接在图谱中检索候选答案并按匹配度排序。给定问题和目标图谱，先识别问句中的主题实体；然后沿图谱遍历得到候选答案，通常是与主题实体有一条关系路径连接的实体；最后从问句和候选答案中抽取特征，用 (问题，答案) 数据训练匹配打分模型，测试时计算得分。根据获取特征表示的技术不同，基于搜索排序的方法可分为基于特征工程的方法和基于表示学习的神经网络方法。

### 10.2.3.1 基于特征工程的方法

直接对问句和候选答案定义特征，用特征工程抽取后再以分类模型建模匹配程度。Yao Xuchen 等人 2014 年 ACL 论文 “Information Extraction over Structured Data: Question Answering with Freebase” 是这类方法的基础。主题词提取、实体链接与前文所述一致，主要步骤是从问句抽取特征、从候选答案抽取特征并计算匹配。

### 1. 问句特征抽取

为更好提取特征，先对问句做句法分析得到依存句法树，如图 10.11 左图所示。依存树包含丰富信息，例如通过 Dex（人，哪裡）可知答案应为地点且是“人”的“哪裡”；再通过 Exp（是，屠呦呦）可确定要找“屠呦呦”实体的“哪裡人”信息。基于这些初步信息可进一步抽取抽象特征：① 问题词 question word, qword，如谁、哪；② 问句焦点词 question focus word, qfocus，暗示答案类型如名字、时间、地点，通常取与 qword 相关的名词；③ 问句主题词 question topic word, qtopic，帮助定位知识图谱相关知识点，一个问题可能含多个；④ 中心动词 question verb, qverb，提供答案线索如“参与”“战胜”，可通过词性标注确定。提取这四类特征后，依存树可转化为问题特征图，如图 10.11 右图所示。
