# 实战复盘：从莎翁剧本词频统计到 Spark 实时推特流处理

[PRE0]

首先处理文本清洗环节，利用 `filter` 算子剔除停用词，只保留有实际语义的词汇。

[PRE1]

接着构建词频统计管道：将单词映射为 `(word, 1)` 的键值对，再借助 `reduceByKey` 配合 `operator.add` 完成聚合累加。

[PRE2]

为聚焦核心高频词，设定阈值过滤掉出现次数不足 60 次的条目。

[PRE3]

随后将分布式集合拉取至驱动端，利用 `itemgetter` 按频次降序排列，并动态计算最长单词长度实现对齐美观输出。

[PRE4]

控制台最终呈现的高频词榜单中，`romeo` 以 298 次领跑，`thou`、`juliet` 紧随其后，`love`、`death` 等核心意象词亦榜上有名，直观展现了剧作的人物与主题权重。

[PRE5]

环节切换至集群部署准备。先在本地 Conda 环境核对依赖包版本。

[PRE6]

通过 SCP 将剧本文本推送至 HDInsight 头节点。

[PRE7]

建立 SSH 连接进入远程会话。

[PRE8]

随即在 HDFS 中创建目录并上传数据文件，完成数据就绪。

[PRE9]

针对 NLTK 词典资源，采用离线下载至本地目录的方式规避网络限制。

[PRE10]

并通过追加 `nltk.data.path` 确保运行时能正确定位词典资源，同时确认打印格式化代码无误。

[PRE11]

进阶场景转向实时流处理：安装 `tweepy` 库对接 Twitter API。

[PRE12]

进入项目工作目录 `work/SparkHashtagSummarizer`。

[PRE13]

启动入口脚本 `starttweetstream.py`，支持自定义抓取数量与检索关键词，例如抓取 1000 条含 "football" 的推文。

[PRE15]

核心脚本逻辑解析：导入认证密钥、Socket 通信模块及系统参数，初始化 Tweepy 流监听器。

[PRE16]

自定义 `TweetListener` 继承 `StreamListener`，在构造函数中绑定 Socket 连接并设置默认 1 万条的采集上限，为后续 Spark Streaming 接收数据打通传输通道。
