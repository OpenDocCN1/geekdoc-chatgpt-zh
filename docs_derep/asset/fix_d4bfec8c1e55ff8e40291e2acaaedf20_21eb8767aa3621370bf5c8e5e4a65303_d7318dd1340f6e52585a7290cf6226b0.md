- 与 React 的核心思想 界面是状态的函数 更贴合。
- 让关注点拆分做得更彻底。
- 受函数式编程范式的影响。
- React 内部实现持续优化。
- 社区生态的反哺与推动。

### 3.7.2 仍需掌握类组件吗
现阶段官方建议新项目优先使用函数来定义组件，开源社区的主流库也在向函数式组件加 Hooks 迁移。类式写法被标记为过时 API，但鉴于存量代码体量庞大，官方没有计划彻底移除，它仍可能出现在旧项目、老文档或教材中。

以学习 React 开发为目标，现在是否还要花时间学类式写法？我认为必要性不大，原因如下。

- 官方已把组件概念默认等同于函数式写法。自 2019 年初发布 v16.8.0 到现在已过去数年，React 已演进至 v19.1.0，函数式组件已全面取代类式写法，成为标准模式。
- 先入为主风险。类式写法对应面向对象，函数式写法更接近函数式编程。先接触类式写法，容易用面向对象的思路套用 React 概念。

## 4.1 React 的数据驱动本质
数据驱动是一个宽泛概念，在商业、技术、方法论和实践中都有体现：

- 数据驱动决策：依据数据分析而非直觉做决策，用于战略、营销、财务、运营等。
- 数据驱动设计：在产品、交互、界面设计中，利用用户行为追踪、反馈收集、A/B 测试等手段指导设计。
- 数据驱动开发：以数据为核心贯穿设计、开发、测试等环节。
- 数据驱动编程：一种范式，把数据流和控制流抽象为运行时数据，提升灵活性，例如动态表单库会根据字段类型自动选择组件。

React 的设计理念 界面是状态的函数 正体现了这一思想，其中 state 就是数据参数。给定组件，不同数据输入即可得到不同界面。数据导向为 React 带来：

- 更清晰的关注点拆分：React 用专属 API 分离视图与状态，开发者声明式构建组件，React 在数据变化时自动更新。
- 更好的用户体验：界面始终与最新数据同步，交互更流畅。
- 更高的性能：虚拟 DOM 与高效差异对比机制让数据变化只触发必要的 DOM 操作。
- 更强的复用与扩展：对数据流的抽象让组件更专注视图与业务逻辑，便于复用和扩展。

第 3 章介绍了如何搭建组件，本章将讲解 React 中的数据种类及设计使用方法。

驱动 React 应用的数据主要有三种：属性 props、状态 state、上下文 context。这三个是 React 的专有名词，各自有 API 与实现。为避免混淆，本书直接使用英文原名。

### 4.2.1 Props 的声明与使用

- 在组件内部直接读取 props 数据结构里的属性；
