### 1.1.3 通用预训练 + 任务微调，让模型更强
深度学习快速演进中，先在海量无标注数据上学习通用表征，再在下游任务上做针对性调优，已成为提升效果的主流思路。该做法在自然语言处理领域验证充分，在计算机视觉等方向同样奏效。

### 1．先训的核心思想
先训的本质是借助大量无标注语料，让模型学会可迁移的特征表示。通常采用自监督或无监督方式，使得模型在初期就能从丰富上下文中抽取出有价值的表征。

### 2．微调的落地流程与工程实践
该范式在 NLP、CV 等多个方向被广泛采用。以 BERT、GPT 家族为例，都能在 PyTorch、TensorFlow 等框架上完成针对性微调，调优后使用测试集检验泛化表现。整体步骤可参见图 1-6。

**图 1-6 大模型的预训练与微调流程分析图**

先训得到的模型是在海量无标注文本上训练出的通用语言基座，依赖自监督机制学习语言结构、语法与语义关联。

微调后的模型则是在该基座上，用特定任务的有标注数据做有监督训练，得到面向具体任务的专用模型。两者差异见表 1-2。

**表 1-2 预训练模型与微调后的模型对比表**

| 特点 | 预训练模型 | 微调后的模型 |
| :--- | :--- | :--- |
| 定义 | 在大规模未标注数据上训练，具有通用语言理解能力 | 在特定任务数据上训练，具备任务专属性能 |
| 适用场景 | 开放式任务，零样本、少样本学习 | 明确的特定任务场景，精确度要求高 |
| 任务表现 | 通用表现良好，任务精度较低 | 任务表现优异，具有更高的精度 |
| 扩展性 | 适合多任务迁移，适应新任务较快 | 针对单一任务优化，迁移至新任务效果差 |
| 计算资源需求 | 预训练阶段资源消耗大 | 计算成本较低，适合在预训练模型基础上开发 |

## 1.2 LangChain 的运作原理与开发路径
随着大语言模型在智能应用中的普及，如何高效搭建、部署和管理这些模型成为关键。LangChain 正是为此而生，它把 LLM 的开发流程标准化，让复杂任务的组合更顺手、更灵活。

下面先介绍 LangChain 的基本原理与开发思路，聚焦核心构件、协作机制与上手技巧。

### 1.2.1 核心构造：Chain 与 Memory
在基于 LLM 的 NLP 场景里，模型既要生成内容，也要在多步任务中保持背景连贯与记忆能力。LangChain 围绕 Chain 与 Memory 构建核心架构，这两块是搭建复杂语言应用的关键。

#### 1. Chain：多步任务的编排
Chain 是 LangChain 最基础的组织形式，提供模块化方式来串联多步操作。

##### 1）Chain 的运行机制
一个大目标会被拆成若干子目标，每个子目标独立执行但会接收前一步的输出。LangChain 中的 Chain 由多个节点构成，节点间通过数据流相连。

##### 2）Chain 的类型与典型用途
按复杂度与需求，常见类型有：

（1）顺序 Chain Sequential Chain：按固定顺序执行子任务，适合强依赖的流程。比如用户请求处理中依次做意图判断、信息抽取、回复生成。

#### 2. Memory：背景保持与记忆机制
在多轮对话、复杂推理与长文本生成中，模型需要记住用户提供的信息并保持连贯。LangChain 的 Memory 正为此设计，它通过持久化的背景记录和动态回溯，为任务执行提供记忆支持。

#### 2．任务链的设计与配置
Chain 的设计决定了 LLM 如何按逻辑顺序完成多步任务。一个 Chain 通常包含文本生成、信息抽取、数据分析等子任务，具体选择取决于需求。

配置时需指定各组件的顺序及其依赖关系。借助 LangChain 提供的接口，调用逻辑可按预设流程自动运行，从而高效完成多步任务。

##### 4. 数据存储与内存模块集成
LangChain 的 Memory 负责暂存 Chain 执行产生的中间数据，为后续步骤提供背景，保证数据在任务间流转与共享，提升整体效率。它支持会话 Memory 与持久化 Memory，可按需配置。

在需要复杂信息检索的场景，还会结合向量数据库。向量数据库对数据做向量化存储与相似度计算，能提高文本匹配与检索精度。LangChain 的架构让 Memory 与向量数据库无缝协作，从而提升模型在信息管理与检索方面的能力。
