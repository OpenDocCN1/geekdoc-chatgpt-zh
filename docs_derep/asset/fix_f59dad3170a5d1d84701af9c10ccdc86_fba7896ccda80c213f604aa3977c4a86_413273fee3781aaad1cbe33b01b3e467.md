### 3.5 多模态嵌入模型：Visualized_BGE

小雪：咖哥，单模态的嵌入比如纯文本或纯图像现在已经挺成熟了。可实际业务里常常要同时处理图文、甚至音视频，需求明显更复杂。

咖哥：这正是多模态嵌入要做的事情。它把不同模态的输入投射到同一向量空间，从而支撑跨模态检索、跨模态生成以及多模态分析。

比较有代表性的是智源研究院推出的 Visualized_BGE。该项目在 BGE 的基础上做了可视化增强，专门面向多模态场景。目前主要聚焦图像与文本两类模态的联合建模。把图和文都映射到同一个嵌入空间后，两者相似度可以直接度量，进而实现图文互查。用户可以用一段描述找最相关的图片，也能用一张图反查最匹配的文字说明。

Visualized_BGE 的构成大致可拆成三部分。

- 视觉编码器：通常采用 ViT 或各类卷积架构，负责把图像切块或卷积后再抽取多层次视觉信息，最终压缩成一张全局图向量。
- 文本编码器：基于 BERT、RoBERTa 等预训练语言模型，负责把输入序列编码成表征整体语义的向量。
- 对比学习：用对比学习的方式做训练，把配对的图文拉近，不配对的推远，这样跨模态对齐与检索能力才会稳定下来。

### 3.6 通过 LangChain、LlamaIndex 等框架使用嵌入模型

前面几节我们要么直接调商用嵌入 API，要么从 Hugging Face 下载开源模型。本节介绍借助 LangChain、LlamaIndex 这类主流框架来加载与调用嵌入模型。这种做法的好处是可以在统一的开发环境里无缝切换不同嵌入模型，无需为每种模型单独写适配代码，更专注业务逻辑。框架自带的缓存机制还能避免重复计算向量，提高检索与查询效率。

#### 3.6.1 LangChain 提供的嵌入接口

LangChain 提供了丰富的组件把大模型融入应用，并在嵌入层面做了很好的抽象，切换 OpenAI 的嵌入、Hugging Face 的嵌入或本地模型都很方便。

LangChain 里常用的嵌入类有：

- OpenAIEmbeddings：调用 OpenAI 文本嵌入接口。
- HuggingFaceEmbeddings：调用本地或远程的 Hugging Face 模型。
- SelfHostedPipelineEmbeddings：调用自行部署的 Pipeline。
- CacheBackedEmbeddings：把任意嵌入模型包装成支持缓存的形式，避免重复计算。

#### 3.6.3 通过 LangChain 的缓存嵌入

处理海量文本或对同一批文本反复查询时，每次都重算嵌入会浪费算力和时间。LangChain 提供的 CacheBackedEmbeddings 可以把嵌入结果持久化到本地文件系统或其他键值数据库。下次遇到相同文本时，框架直接返回缓存结果，不再重复计算。

LangChain 会用输入文本的哈希值作为键，对应的嵌入作为值，存入指定的 ByteStore。计算时先查缓存，命中就直接返回，未命中再调用底层模型生成。

### 3.7 微调嵌入模型

本节聊聊嵌入模型的微调。

微调本质上是让预训练模型向特定任务靠拢。关键是保证任务目标与已有数据高度契合。动手前要先判断是否真的需要微调。若任务不清晰或与数据特性不匹配，微调可能浪费资源甚至适得其反。比如只是想让模型回答几个专业问题，而现有开源模型已能给出满意答案，就没必要微调。

可能值得微调的情形包括：

- 高度专业化的任务，比如某个细分领域的医学报告生成。
- 有特定格式要求，比如必须符合内部文档规范的输出。
- 有本地化需求，比如要在特定语言或文化语境下生成内容。

总之微调应围绕真实任务和现有数据展开，避免为微调而微调。
