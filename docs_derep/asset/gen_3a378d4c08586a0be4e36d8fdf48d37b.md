# 第3章 模型格式迁移与部署实战

深度学习模型要在不同框架、不同硬件上流转，关键就在于格式的标准化与转换。TensorRT 作为 NVIDIA 推出的推理优化套件，核心思路是通过算子融合把多个连续层合并成一个大核，降低 kernel 启动开销；借助层级精度校准，在保持精度损失可控的前提下把部分计算切到 FP16/INT8，提升吞吐并压缩显存占用；同时对工作区、中间特征的内存布局进行重排复用，减少显存峰值。这三项手段共同作用，让 GPU 端的推理延迟下降、算力利用率提升，显存占用更平稳。

评测模型效率时，计算复杂度是绕不开的视角。时间复杂度反映模型在输入规模扩大时计算量增长的趋势，直接关联 FLOPs 大小；空间复杂度则描述中间激活、参数在运行时占用的内存规模。实践中通过剪枝、蒸馏、通道压缩等手段压低 FLOPs，同时以梯度检查点、内存复用、混合精度等方式优化内存占用，就能显著提升推理的实时性和资源友好度。

PyTorch 内置的 torch.utils.benchmark 模块为性能对比提供了标准工具。对语义分割模型做基准测试时，可用 Timer 封装前向推理语句，设置重复次数和预热轮数，收集多轮耗时。模块会输出平均运行时间和标准差，前者衡量推理速度的基准水平，后者反映运行波动是否稳定，两者结合才能判断优化是否真正可靠，而非偶然加速。

在分布式训练场景下，学习率调度器决定优化轨迹。StepLR 按固定步长衰减学习率，能在训练后期收敛更精细。结合 Horovod 使用时，先调用 hvd.init 初始化进程组，再用 hvd.DistributedOptimizer 包装优化器同步梯度。Scheduler 仍作用于原始优化器实例，通过每轮 step 更新全局学习率，确保各 rank 步调一致，既加速收敛又避免震荡。

构建在线推理服务时，FastAPI 搭配 PyTorch 能实现动态批处理。请求进入批队列排队等待凑批，锁机制保证模型参数和显存访问线程安全，事件触发则在队列达到阈值或等待超时时唤醒推理。三者协同可以在延迟敏感和小批量到达的矛盾中取得平衡，实现高吞吐的同时控制单次响应时间。

# 第3章 模型格式转换

本章围绕模型格式转换的底层逻辑与工程落地展开，梳理 ONNX、TensorRT、OpenVINO 等主流工具链，解析跨格式转换的流程、常见坑点与排错思路，并以实战案例演示如何在真实项目中完成格式迁移与性能调优，夯实模型轻量化与推理加速的技术基础，推动深度学习模型更好地落地各类应用。

## 3.1 模型格式的定义与转换

模型在多框架、多平台间流通的基础是格式的统一表达。模型格式本质上是对网络结构、权重参数和计算图的规范化编码，直接影响移植性和兼容性。当前生态里 ONNX 和 TensorFlow SavedModel 等代表性格式在训练、验证、部署环节发挥关键作用。

借助格式转换，模型可以跨框架迁移，保留精度同时简化多平台发布的复杂度。转换过程依赖 ONNX 转换器、TensorFlow 转换工具等自动化方案，提升效率与准确性。但不同框架对算子支持度存在差异，容易出现转换失败或性能回退的问题。因此，理解格式定义、掌握主流格式特性与转换方法，对高效部署至关重要。

本节先介绍常见格式与转换思路，再剖析兼容性难点，为后续实践奠定理论基础。

### 3.1.1 常见的模型格式：ONNX、TensorFlow的SavedModel

模型生态的多样化催生了多种格式。ONNX 提出开放互操作的思路，兼容 PyTorch、TensorFlow、Caffe2、MXNet 等主流框架，通过统一表示实现跨平台迁移，促进模型复用。

TensorFlow 的 SavedModel 是该框架的原生保存标准，包含结构、参数和计算图信息，支持跨语言部署，适合生产化发布。它保留了训练配置，也方便后续推理与优化。

相比之下 ONNX 更通用，适合跨框架场景。借助 tf2onnx 可将 SavedModel 转为 ONNX，再配合 ONNX Runtime 等高效引擎部署。ONNX 生态还提供量化、剪枝、优化等工具链，进一步提升运行效率与资源利用。
