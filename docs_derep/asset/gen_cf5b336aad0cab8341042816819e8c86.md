## FPGA 硬件加速

若想提速，从硬件层面入手往往比单纯改进软件算法更有效，配备 GPU 的显卡即是明证。

针对单一任务定制专用大规模集成电路虽能高效完成工作，却丧失通用性，硬件难以频繁改动。为兼顾效率与可变性，业界普遍改用现场可编程门阵列 FPGA。速度与规模虽不及定制芯片，但电路可随时重构。FPGA 对高速数据流处理能力强，常用于视频压缩、格式转换等实时性要求高的场景，它把硬件性能与软件灵活性结合起来，很适合原型阶段使用。

此外 FPGA 的耗电远小于 GPU，在对精度要求不高时，可用于浮点运算等计算任务。面对 CPU 与 GPU 负载较重的处理，先引入 FPGA 是降耗的常见做法。

微软曾大规模部署 FPGA 搭建服务器进行特征抽取与机器学习，并将其用于 Bing。部分高校也把 FPGA 用在卷积神经网络与循环神经网络等深度学习模型中做图像识别等模式识别。

有研究报告指出，基于 Xilinx Virtex-5 SX240T 的卷积神经网络性能是基于 NVIDIA Tesla C870 的 1.4 倍。另一项研究在 Xilinx Zynq 上并联卷积神经网络电路后，能效约为 GPU 与 CPU 的 10 倍。

## 多进程

程序运行时，操作系统会为其创建进程并分配独立的内存空间。各个进程可访问的内存互不干扰。

现代操作系统可同时运行多个进程，通过进程间通信在不同进程间传递或交换信息。

为提升数据处理效率，通常为每个进程分配一项任务或任务的一部分。最先启动的进程为父进程，由其创建的新进程为子进程或从属进程。

父进程可挂起等待子进程结束，并在各个子进程完成后再汇总结果（图13-6）。

## 图13-6 多进程

多 CPU 并行运行进程时常用信息传递接口 MPI（Message Passing Interface）进行数据交换。MPI 是一套库，可被 C 与 Fortran 77 调用。它支持套接字通信，既能在单机的多进程间使用，也能在集群系统各机器间的并行处理中使用。

## 多线程

一个进程至少包含一个线程，即主线程。系统分配给进程的内存与处理时间通常被主线程占据。当使用多进程并行时，每个进程的内存空间相互独立，这会降低内存利用率并增加编程复杂度。

多线程可缓解上述问题。多线程可在进程内存内共享。进程的主线程相当于父线程，可创建并运行子线程，随后回收子线程数据继续处理（图13-7）。

# HDFS

HDFS 即 Hadoop 分布式文件系统，是 Hadoop 的核心。一个 HDFS 集群由一个 NameNode 主节点和多个 DataNode 从节点组成。

NameNode 保存文件名与权限等文件属性，数据被切分为固定大小的数据块，每个数据块以冗余方式在多个 DataNode 上保存多份副本，默认 3 份。即使 DataNode 因硬件故障无法访问，数据可靠性仍能得到保障。

需注意，HDFS 适合大文件处理，处理小文件易造成资源浪费。

# MapReduce

MapReduce 是处理数据的编程模型。处理分为三个阶段：把数据分发到多个进程并行处理的 Map 阶段，对 Map 输出进行整理汇总的 Shuffle 阶段与 Reduce 阶段。每个阶段的输入输出均为键值形式。

若在 Map 阶段把数据分配给 M 个进程处理，该阶段耗时可降至 1/M；若在 Reduce 阶段使用 N 个独立进程处理，该阶段耗时可降至 1/N（图 13-11）。

[PRE6]

# 图13-11 MapReduce 的处理过程

早期 Hadoop 由主节点 JobTracker 与从节点 TaskTracker 组成。

JobTracker 为主线程，负责 MapReduce 作业管理。它把作业中的处理任务分配给 TaskTracker 进程，并监控 TaskTracker 存活状态。若检测到任务失败，会把任务重新分配到其他 TaskTracker 运行，从而保证处理能够继续。TaskTracker 进程创建子进程执行任务并获取 HDFS 信息。

# Hadoop 2.0 对 MapReduce 框架进行重构，称为 YARN（图 13-12）。YARN 由主节点 ResourceManager 与从节点 NodeManager 组成，NodeManager 中运行的 ApplicationMaster 通过启动 Container 运行任务。

NodeManager 监视节点资源状态，当 ApplicationMaster 需要启动 Container 时，先向 ResourceManager 请求任务，获取空闲节点资源，再在空闲节点上启动 Container。

使用 YARN 后，Container 可支持 MapReduce 以外的计算框架，如后来的 Apache Tez 与 Apache Spark。

# Hadoop 的使用方法

Hadoop 主要用于批处理。例如可用于 ETL 数据预处理。ETL 是从关键业务系统抽取数据、清洗转换、继承后加载至数据库的过程。此外还可用于生成月度任务等汇总报告，或基于 Hadoop 与 Mahout 进行大规模机器学习并输出结果。

Hadoop 也可作为业务数据分析平台或专用数据分析平台，必要时在云平台构建集群处理数据。

2007 年左右，日本出现名为 blogeye 的服务，该服务主要使用 Hadoop 与 HBase，根据博客等推断日本流行语排行榜。

该服务利用爬虫实时采集分析数据，更新数据库中的作者属性与关键字并建立流行语库。现已与 AWS 的 Amazon EC2/S3 服务集成。

# **Apache Spark**

Hadoop 是大规模数据处理分布式系统，主要用于批处理，但随着对数据流处理与在线机器学习等实时处理需求的增长，Apache Spark 应运而生。Spark 是基于内存的分布式计算系统，可将数据扩展在内存中，实现低延迟并加速作业。加州大学伯克利分校 AMPLab 于 2009 年开始开发 Spark，2013 年捐赠给 Apache。

Spark 用 Scala 实现，也可使用 Java、Python、R 运行。整体主要由五个模块组成：核心模块 Spark Core，包含数据存储机制 RDD；在其基础上还有 Spark SQL、Spark Streaming、机器学习库 MLLib 与图数据处理库 GraphX。

Spark 未使用 Hadoop 的 MapReduce，而是使用 YARN 等集群管理器进行分布式计算。它可轻松访问 Hadoop 的 HDFS、Amazon S3、GCP 的 Google Cloud Storage 等多种数据源，易用性不断提升（图 13-13）。

# RDD

Spark 以 RDD（Resilient Distributed Dataset，弹性分布式数据集）为单位从数据源读取数据进行计算。RDD 可视为由多个分区组成的数组，可对其进行转化操作与行动操作（图 13-14）。

转化操作针对 RDD 元素实施，如 map、filter 等；行动操作针对 RDD 实施聚合，如 count、collect、reduce 等。

利用持久化技术使 RDD 不可变，就可在多次操作中重复使用同一 RDD 进行高速计算，无需再次读取输入数据。

# 分区

Spark 中数据分区后才进行分布式处理。分区数量会影响处理时间，分区过少时 Shuffle 处理会集中到部分工作节点即 NodeManager，严重时导致处理失败。

相反，分区过多会在转化与行动操作时增加系统开销，因此分区数建议控制在 100 ~ 10 000 之间。

分布全国各地的零售商、电子商务网站、社交游戏运营公司等可获取实时数据流的企业都会使用 Spark。典型应用有 Spark 机器学习库 MLLib、基于图数据分析库 Spark GraphX 的推荐引擎开发等。开发过程中有时也会把基于 Hadoop 的 Hive 用于 Spark 以提升效率。
