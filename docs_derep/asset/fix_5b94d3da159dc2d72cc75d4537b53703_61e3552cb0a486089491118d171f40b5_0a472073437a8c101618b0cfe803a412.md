Milvus 提供三种部署模式，可覆盖从简单应用到管理数百亿向量的大规模 Kubernetes 集群。

- Milvus Lite 作为轻量级版本，易于集成到应用中，本书以它为例进行介绍。

可扩展性上，Milvus 采用云原生架构，支持处理数百亿规模的向量数据，其模块化设计使搜索、数据插入和索引构建等核心功能可以独立扩展。

### 4.2 向量数据库中的索引

向量数据库的工作流程通常包含以下步骤。

1. 数据存储：将高维向量数据存入向量数据库。
2. 索引构建：通过哈希、量化或图结构等技术为向量嵌入建立索引，以加速查询过程。
3. 查询检索：接收查询请求后，向量数据库比较查询向量与索引中的向量，利用相似度度量方法如余弦相似度、欧几里得距离或点积确定最邻近向量。
4. 检索后处理：对找到的最近邻结果进行进一步筛选或排序，以优化查询结果。

在大型数据集中进行向量搜索是计算密集型任务，尤其在高维空间。为提升搜索效率，可引入多种索引结构，以减少需要比较的向量数量，从而降低计算成本。

> 索引在向量数据库和整个 RAG 系统中都是重要概念。2.6 节定义过，RAG 系统中的索引目的是通过建立高效的文本块数据存储机制来优化检索效果，其内容包括文档的嵌入向量和元数据的构建过程及方式，属于应用层索引。本节讨论的向量数据库内部索引则更偏向技术实现，主要目的在于优化高维向量数据的存储和检索性能，提升相似度检索效率，涉及 FLAT、IVF、HNSW 等数据结构和算法，用于组织和加速向量的 ANN 搜索，属于数据库内部实现。

向量索引是向量数据库中加速检索的关键技术，决定了向量的组织和检索策略。接下来介绍几种常见方式。

#### 4.2.1 FLAT

扁平索引 Flat Index，简称 FLAT，是一种最基本的索引方式，其特点是逐一比较数据库中的所有向量，以确保检索结果的绝对准确性。由于不涉及近似处理或数据压缩，FLAT 能保证 100% 的召回率。

执行查询时，FLAT 通过计算查询向量与数据库中每一个向量之间的相似度或距离来进行比较。然而，由于需要遍历所有向量，在数据规模较大时检索速度会显著下降。

FLAT 适用于数据规模较小的场景，如数据量在百万级别以下。当应用对检索准确性要求极高且可接受较长查询时间时，FLAT 是理想选择。

#### 4.2.2 IVF

倒排文件索引 Inverted File Index, IVF 通过将向量数据聚类来减少查询时需要比较的向量数量，从而显著加快检索速度。最基础形式是 IVF_FLAT，还有 IVF_SQ8、IVF_PQ 等变体。

IVF_FLAT 首先将向量数据聚类成若干簇，每个簇代表数据空间的一个特定区域。执行查询时，先计算查询向量与每个簇中心的距离，然后仅选择与查询向量最相似的前 n 个簇。接下来在这些选定簇中对所有向量进行精确匹配。示例中向量被分组到不同簇，查询向量只需要与选定簇中的向量比较。图4-12 查询向量（红色）仅需要与选定的簇（粉色区域）中的向量进行比较

[PRE7]

通过只搜索部分簇，IVF_FLAT 大幅减少了需要计算的向量数量，提升查询效率。同时在选定簇内进行精确比较，确保了检索结果的准确性。

小冰：为什么叫倒排？

咖哥：在文本检索场景中，倒排索引是指为给定词维护一份文档列表，列出所有包含该词的文档。搜索某个词时，只需从该倒排列表中查找相关文档，无需遍历整个文档集合。

IVF 借鉴了这一理念，将所有向量聚类成多个簇，每个簇记录自己的向量列表，就像文本检索中的倒排列表一样。执行查询时，根据查询向量与各簇中心的相似度，仅选择最相似的几个簇进行检索，而非遍历整个数据集。
