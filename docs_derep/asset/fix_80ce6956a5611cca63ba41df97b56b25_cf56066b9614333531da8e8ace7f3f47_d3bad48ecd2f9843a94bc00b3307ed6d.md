##### 2. DeepSeek-R1 推理实战

R1 是一个参数规模庞大、结构复杂的 MoE 模型，Hugging Face 上发布的权重默认面向训练或单卡调试。若要在本地实现高效推理，尤其是在多卡或多节点环境下完成真实规模调用，就必须做下面两步处理。

（1）模型格式转换。借助 convert.py 脚本把 Hugging Face 格式的 R1 权重，转成适配官方推理框架如 DeepSeek MoE 推理引擎所需的专用格式。该转换不只是改名，还涉及：

- 将专家模块 experts 的权重做结构化保存。
- 引入张量并行 tensor parallelism 等推理优化机制。
- 去除冗余权重，提升加载效率。

执行如下命令。

[PRE11]

参数含义如下。

- python convert.py：执行转换脚本，把 Hugging Face 格式权重转为推理专用格式。
- --hf-ckpt-path /path/to/DeepSeek-R1：指定 Hugging Face 格式的检查点路径，即模型文件所在位置，示例为 /path/to/DeepSeek-R1。
- --save-path /path/to/DeepSeek-R1-Demo：指定转换后权重保存的目录。
- --n-experts 256：指定模型中专家的数量，与 MoE 分布式相关，设为 256 表示使用 256 个专家。
- --model-parallel 16：指定模型并行度，通常表示把模型分到 16 张 GPU 上进行训练或推理。

（2）分布式推理部署。R1 的参数规模达到数百亿至千亿级别，单卡无法容纳全部权重，必须多卡甚至多机协同。因此推理阶段需用 torchrun 启动多进程。

执行如下命令。

[PRE12]

参数含义如下。

- torchrun：分布式启动器，可跨多节点运行多个进程。
- --nnodes 2：指定集群节点数，示例中使用两台机器。
- --nproc-per-node 8: 每个节点启动的进程数，每个节点 8 个进程以充分利用多 GPU。
- --node-rank $RANK: 当前节点在集群中的序号，$RANK 为环境变量表示节点编号。
- --master-addr $ADDR: 指定主节点地址，主节点负责调度，$ADDR 为环境变量表示主节点 IP 或主机名。
- generate.py: 执行文本生成任务的脚本，用于模型推理生成文本。
- --ckpt-path /path/to/DeepSeek-R1-Demo: 指定转换后 R1 模型的检查点路径，即上一步保存的位置。
- --config configs/config_671B.json: 指定模型配置文件，包含架构和超参数等信息，示例为 configs/config_671B.json。
- --interactive: 开启交互模式，可在命令行输入内容并实时获得模型响应。
- --temperature 0.7: 生成温度，控制输出随机性，数值越高越随机，0.7 为适度随机。
- --max-new-tokens 200: 限制本次生成的最大新 token 数量，最多生成 200 个新词元。
