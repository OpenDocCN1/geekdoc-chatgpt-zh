## 4.10 vLLM

vLLM 的目标是大幅提速大模型推理，相较于直接调用 HuggingFace 的 generate()，加速比可达约 24 倍。

### 4.10.1 KV Cache

先回顾 token 生成的流程。以“中国的历史”为例，会被切分成“中国”“的”“历史”三个 token，经编码后模型先输出“非常”，随后把“非常”接在已有序列后继续预测，得到“悠久”，示意如图。

[PRE4]

再看 Transformer 自注意力。以这三个 token 为例，注意力只向前看。第1个 token 仅关注自己，得到自己的 v。第2个 token 用自身的 q 去匹配第1个 token 和自己的 k，经 softmax 加权后对对应的 v 求和。由此可见，自注意力只依赖当前及之前位置的 k、v，不受后续 token 影响。

[PRE5]

## 图4-62 第2个token的自注意力计算

Prompt 中所有 token 在首次前向时即可算出各层 k、v，并产生首个新 token“非常”。

随后把“非常”追加到输入尾部进行第二次前向。因为 Prompt token 的 k、v 已在首次计算完成且不会因新 token 改变，所以无需重算。HuggingFace 的 generate 默认会缓存已产生的 k、v。需注意后续自注意力并不需要历史 token 的 q，只保留 k、v 即可。第二次生成后，“非常”的 k、v 也会被写入缓存，这便是 KV Cache，如图所示。

[PRE6]

## 图4-63 大模型第2次生成

有了 KV Cache，对话式的生成就不会随输出变长而持续变慢。每次只需计算当前新 token，历史部分的 k、v 均已缓存复用。

### 4.10.2 Page Attention

KV Cache 能加速，但传统预分配策略浪费严重。以 40GB A100 部署 13B 模型为例，权重约占 26GB，KV Cache 约占 12GB。

实测该部分显存利用率常在 20%~40% 之间，主要浪费来自：

1. 生成长度不可知，通常按最大 token 数一次性预留 KV 缓存，如设上限 1000，实际只产生 100，则多余 900 的空间被闲置。

[PRE7]

2. 假设某请求确实要产出 1000 个 token，第 1 个 token 产生时其余空间已先行占用，导致其他可快速完成的短请求无法并行进来。

3. 碎片问题。不同请求的 Prompt 长度不同，预分配大小也不同。请求结束释放后，若下一个请求的 Prompt 更长，就无法填入，形成碎片。

vLLM 通过优化 KV 缓存分配来提升吞吐。传统系统批处理规模约 8，经优化后可扩展到约 40，输出速率从约 300 token/s 提升到约 900 token/s，如图4-65 所示。

[PRE8]

## 图4-65 vLLM与现有系统性能比较

为什么能提升这么多？关键是 Page Attention。KV 缓存的分配难题与操作系统的内存管理相似：是否预分配？何时释放？如何防碎片？操作系统用虚拟内存与分页解决了。

操作系统把物理内存切成固定大小的页，进程按页申请释放，物理页不必连续。进程在虚拟地址空间操作，页表负责映射。

Page Attention 把同样的思路搬到 KV 缓存。显存被划分为若干 KV 块，按块分配和管理，每个请求的 KV 缓存被分散到不连续的物理 KV 块上。

以每个 KV 块容纳 4 个 token 的 k、v 为例，“中国的历史非常悠久”共 5 个 token，会占用两个 KV 块，且在显存中不必相邻，如图4-66 所示。

同时引入类似虚拟内存的访问机制。每个序列在逻辑上拥有连续的 KV 缓存，物理上却可能分散。逻辑块到物理块的映射由序列专属的映射表维护，如图4-68 所示。

### 4.10.3 块共享

vLLM 的第二个改进是 KV 块共享。当同一 Prompt 需要多路输出时，例如对一句话做两种英译，可把 sampling 的 n 设为 2。

此时显存中只保存一份 Prompt token 的 KV 块，被两个序列的逻辑缓存共同引用。物理块上会记录引用计数，计数归零时才释放，如图4-69 所示。

第一个序列生成首 token Color 时，会触发 Copy-on-Write。发现目标块被多引用，就复制一份新块，旧块引用减一，新块引用置一，再写入 Color 的 k、v。第二个序列生成 Matter 时，其引用的块引用计数已为 1，可直接写入。随后两路各自继续，如图4-70 所示。

块共享也体现在 Beam Search 中，例如 Beam Num=3 时，“中国的历史”对应的 KV 被 3 个 Beam 共享，“非常悠久”对应的 KV 被 2 个 Beam 共享，如图4-71 所示。

## 4.11 FlashAttention

训练大模型时现在普遍采用 FlashAttention，论文名为 Fast and Memory-Efficient Exact Attention with IO-Awareness。名字已点明两大优势：更快、更省显存，且是精确注意力，结果与标准 Attention 完全一致。核心在于 IO 感知设计，通过优化 I/O 模式提升整体效率。

Transformer 中 Attention 的简化步骤如下：

1. 编码输入：将 token 映射为向量。
2. 构造矩阵：生成 Q、K、V 三个矩阵。
3. 计算分数：Q 与 K^T 相乘得到分数矩阵 S。
4. 归一化：对 S 行做 softmax 得到权重矩阵 P。
5. 聚合输出：P 与 V 相乘得到输出 O。

## 图4-72 简化Attention计算流程

若考虑 GPU I/O，流程为：

- 1. 存储：Q、K、V 初始放在高带宽内存 HBM，形状均为 N×d。
- 2. 加载：把 Q、K 从 HBM 搬到片上 SRAM。
- 3. 计分：计算 S = QK^T。
- 4. 写回：把 S 写回 HBM。
- 5. 读回：再把 S 从 HBM 读回 SRAM。
- 6. 归一化：softmax 得到 P。
- 7. 写回：把 P 写回 HBM。
- 8. 加载：把 P、V 从 HBM 读回 SRAM。
- 9. 输出：计算 O = PV。
