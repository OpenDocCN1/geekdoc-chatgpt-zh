# Agent协作的四种经典范式全解析

在工程落地中，多智能体配合通常会收敛到四种典型结构：顺序链式、并行扇出、层级管理与网状协商。顺序链式是把多个Agent按固定工序串起来，前一个的输出直接作为后一个的输入，适合步骤明确、依赖强的流水线任务。并行扇出则是把同一问题拆成多条线，由多个Agent同时处理不同侧面，最后由聚合Agent汇总，适合可拆分的复杂分析。层级管理由一个Manager Agent负责分解与调度，多个Worker Agent执行具体工作并回传结果，适合需要动态分派的场景。网状协商则让Agent之间自由交互，通过多轮对话达成共识，适合需要多方博弈的决策问题。

图5-2对四种结构的外形与边界做了可视化。左上线性链A→B→C依次推进，逻辑清晰、调试友好，但延迟会逐级累加，常见于文档处理流水线。右上先由分发节点拆分任务，多路并行计算后由聚合节点合并，速度快但合并逻辑较重，适合多视角分析。左下以管理者集中指挥执行者，虚线表示结果回传，调度灵活且易于负载均衡，但管理节点容易成为瓶颈。右下允许全网互通，通过多次沟通达成一致，决策质量高但通信成本大，多用于复杂的多方决策。

### 5.1.3 基于LLM的Agent能力边界定义

在LLM多Agent体系里，清晰界定能力边界是避免职责混乱与协作冲突的前提。边界不仅要说明能做什么，还要明确不能做什么以及越界时的处理方式。最好把边界写进System Prompt，让模型准确把握自身职责范围。

完整的能力边界包含五大要素。第一是角色定位，明确在协同网络中的身份与核心使命。第二是能力范围，列出可处理的任务类型、支持的输入形式和可调用工具。第三是边界约束，划定不承接的任务类型及越界时的标准回应。第四是协作接口，定义与其他节点交互的报文格式、协议和交接条件。第五是决策权限，说明可自主决定的范围与需要上报或转交的情形。

为避免职责重叠，设计时需遵循以下原则。

- 单一职责原则：每个Agent只负责一类明确的业务功能
- 显式边界声明：在System Prompt中明确“能做什么”和“不能做什么”
- 标准化转交：定义统一的任务转交协议和上下文传递格式
- 兜底机制：设置默认路由Agent处理无法归类的请求
- 定期审查：根据实际运行数据调整Agent职责划分

### 5.1.4 协同系统的模块化与可扩展性设计

生产级Agent协同系统必须具备良好的模块化与可扩展性，以支撑业务演进与技术迭代。核心思想是把系统拆分为职责独立、接口统一的模块，单个模块可独立升级或替换而不影响整体。

典型模块化体系包含六层：接入层负责接收各类外部请求并响应；路由层依据请求特征分发任务；Agent层托管所有业务Agent，通过消息总线异步通信；工具层提供数据库、外部服务、RAG检索和代码执行等能力；存储层负责上下文管理、记忆持久化和日志记录；监控层负责性能监控、日志分析和告警。

图5-3展示了模块化Agent系统的整体架构。

模块化设计需遵循四项基本原则。接口标准化要求所有模块通过统一接口通信，确保交互一致可预期。可插拔设计使Agent和工具可独立部署替换，无须改动其他模块。配置驱动通过配置文件管理Agent和路由规则，实现运行时的灵活调整而无须重新编译。水平扩展支持Agent实例的动态扩缩容，根据负载自动调整系统容量。图5-3展示了一个典型的模块化Agent系统架构，从上到下分为六个层次。接入层作为系统入口，负责处理来自API、Web和消息队列等多种渠道的请求，提供认证鉴权、限流熔断和协议转换功能。路由层负责意图识别和请求分发，将任务路由到对应的Agent。Agent层是系统核心，包含多个独立的业务Agent，每个Agent可配置不同的LLM，Agent之间通过消息总线进行异步通信。工具层提供Agent执行任务所需的各类工具，包括数据库API、外部服务调用、RAG检索和代码执行等。存储层负责上下文缓存、向量数据库、对话历史和审计日志的持久化。监控层贯穿整个系统，提供性能指标、日志分析、链路追踪和Token统计等可观测性能力。

### 5.2.1 System Prompt的结构化设计方法

System Prompt是定义Agent行为、人格和能力边界的核心配置，其设计质量直接决定Agent的表现水平。在多Agent协同系统中，结构化的System Prompt设计尤为重要，它不仅需要清晰定义单个Agent的职责，还需要规范Agent间的协作方式和信息交换格式。

结构化System Prompt的设计遵循“角色-能力-约束-协作”四层架构。角色层定义Agent的身份、背景和专业领域，帮助LLM建立正确的人格画像。能力层明确Agent可以执行的任务类型和可调用的工具集。约束层规定Agent的行为边界、禁止事项和异常处理规则。协作层定义与其他Agent交互的协议、消息格式和状态转换条件。这种分层设计使System Prompt既具有完整性，又便于维护和迭代。

图5-4展示了System Prompt的四层结构化模板。第一层角色定义包含身份声明、专业背景、人格特征和服务对象四个要素，用于建立Agent的基本人格画像。第二层能力声明涵盖任务范围、工具清单、知识边界和输出格式，明确Agent的能力范畴。第三层约束规则定义禁止事项、安全边界、异常处理和决策权限，确保Agent行为可控。第四层协作接口规定消息格式、转交条件、状态同步和协作对象，支持多Agent协同工作。底部的输出规范统一了标准响应、转交响应和错误响应的JSON格式，确保系统间通信的一致性。
