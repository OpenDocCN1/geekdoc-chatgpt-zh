#### 1.4.1 第一招：先跑健康自检
OpenClaw 自带一套健康扫描工具，可以自动检查常见环境与配置问题。无论报什么错，最稳妥的第一步都是执行一次自检：

[PRE0]

这条指令会逐项核验：Node.js 版本是否达标、依赖是否齐全、Gateway 是否能连上、API Key 是否填对、守护进程是否正常、网络是否通畅。完成后会给出汇总报告，看不懂就整段复制给 AI 分析，它会指出问题点并给出修复建议。

常见提示例如“Node.js 版本偏低，需要 22.0.0 以上”“API Key 无效，请检查”“端口 18789 已被占用”。有了明确指引，就不用盲目尝试，效率会高很多。

如果自检命令本身都执行不了，提示 command not found，说明 OpenClaw 并未正确安装，需要重新走安装流程。

### 1.5 如何配置 OpenClaw，有哪些必填项？

#### 1.5.2 核心必填项：这三样不配置不能用
无论哪种方式，以下三项都是必填，未填则无法启动或无法工作。

##### 必填项 1：Gateway 认证模式
从 v2026.3.7 起，OpenClaw 强制要求设置 Gateway 认证，不能裸奔。必须选择 token 令牌认证 或 password 密码认证。
[PRE25]
选择建议：
- 仅本地浏览器访问，选 password 模式，设置一个密码即可。
- 需通过 API 调用或接入第三方工具，选 token 模式，使用较长随机字符串作令牌。
目的在于防止陌生人访问 Gateway。虽然默认只监听本地 127.0.0.1，但若配置远程访问或意外暴露到公网，无认证会很危险。曾有 3 万多个实例因未设置认证被扫描到。
未设置会怎样：Gateway 直接拒绝启动，并提示必须配置认证，此为强制要求。

OpenClaw 仅是框架本身不带 AI 能力，必须调用外部模型。因此至少要配置一个模型的 API Key。
