### 3.1 程序员最容易踩的安全漏洞

写代码如同盖房子，地基或结构若有缺陷，整栋楼都会受威胁。在软件世界里，这些隐患可能导致被攻击、数据泄露，甚至造成经济损失。即使是资深开发者也易在细节处失误，因为安全问题往往隐蔽。

最常见的问题之一是 SQL 注入。好比服务员把顾客随口一说当成厨房指令。若网站把用户输入直接拼接到数据库查询语句中，攻击者就能通过特殊字符篡改查询意图，从而窃取或删除敏感数据。某大型零售商就曾因此类漏洞导致上百万客户支付信息被盗。正确做法是使用参数化查询，像点餐只能按菜单选，不能随意改流程。

跨站脚本攻击 XSS 也是高频隐患。可以理解为黑客在公告板贴上带陷阱的告示。网站若未过滤用户输入，攻击者可注入恶意 JavaScript，在其他用户访问时自动执行，窃取 Cookie、会话信息或诱导钓鱼。某小型教育网站曾因留言板未做校验，第二天大量用户被重定向到假登录页，账号被盗。防范要点是对所有用户输入严格过滤，确保页面展示内容不可执行脚本。

密码存储不当是数据泄露的根源。有人直接明文存密码，相当于把钥匙挂在门外；即使用哈希也常因未加盐或使用弱算法而被快速破解。某知名社交平台曾因密码存储不善导致数亿用户密码泄露，黑客借助彩虹表迅速破解。安全做法是采用 bcrypt、Argon2 等专用哈希算法，并为每个密码添加随机盐值。

身份认证与会话管理的缺陷同样常见。会话标识暴露在 URL、Cookie 缺少安全属性、缺少防暴力破解的账号锁定等，都易被利用。某电商平台曾出现会话固定攻击，黑客通过特制链接劫持购物会话并盗用支付信息。正确处理需使用安全随机会话 ID、设置合适的 Cookie 属性并实现会话过期与账号保护。

[PRE9]
文件上传常常成为薄弱环节。未严格限制类型和内容时，攻击者可上传恶意脚本并执行。某医疗机构网站允许上传 X 光片，因未校验文件内容，黑客上传伪装成图片的 PHP 脚本，获取服务器控制权并接触大量病历。安全实现应校验类型、内容、大小，并将文件存放在不可执行目录或独立存储服务。

对第三方组件的过度信任也带来风险。开源库和框架可能存在漏洞或被篡改。某航空公司网站因使用含后门的第三方支付组件，导致支付信息被拦截。开发者应审慎选用依赖、定期更新到安全版本并进行完整性校验。

配置错误看似微小却后果严重。开发环境调试信息暴露到生产环境、云存储权限配置不当、默认账号密码未移除等都可能酿成事故。某科技创业公司因 MongoDB 未设密码暴露在互联网上，导致数千万用户记录泄露。完善的配置管理与上线前安全检查可避免此类问题。

总体而言，编程是在安全与便捷间走钢丝。追求功能与速度时易忽视细节。正如资深安全专家所言：“安全不是功能，而是一种思维方式。”每一行代码都可能成为攻击入口。
