### 5.2.4 实战最佳实践

本节围绕 API Key 管理、设置界面、异常处理和代码迁移给出建议。

API Key 管理建议分 3 种场景：

- 开发阶段：可硬编码 API Key，方便快速调试。
- 生产环境：必须通过设置界面配置或使用环境变量，防止前端泄露。
- 推荐做法：前端做一个设置页让用户输入 API Key 并存到 LocalStorage，后端则使用环境变量。

设置界面建议包含 4 个要点：

- 基础配置：API Key 输入框，API 地址配置可选。
- 使用信息：展示 API Key 的用量情况，如已消费金额、最高限额等。
- 模型选择：在多模型场景下提供模型选择器。
- 本地存储：配置写进 LocalStorage，刷新后依然保留。

错误处理建议包含 4 条：

- API Key 未配置：启动时校验，未配置则提示用户前往设置。
- API Key 无效：捕获认证错误，提示检查 Key 是否正确。
- 网络请求失败：加入重试机制，并给出错误提示。
- 异步任务超时：设置合理超时时间，支持手动重试。

代码迁移建议根据项目情况选择接入方式，共 3 种：

- Google AI SDK 项目：优先用 setDefaultBaseUrls 方法改动最小。
- 需要多模型支持：使用 OpenAI SDK 兼容接口。
- 视频生成等长耗时任务：采用异步任务 API，并实现轮询逻辑。

### 5.2.5 常见问题解答

#### Q1：如何获取胜算云 API Key？
进入胜算云官网注册账号，注册完成后即可创建 API Key。

#### Q2：如何查看支持的模型列表？
登录官网后点击顶部标签“大厂模型”，即可查看“大语言模型”和“多媒体模型”的完整列表。

#### Q3：API Key 可以设置哪些限制？
主要限制有 3 项：

- 消费限额 max_quota：最大可消费额度。
- 支持的模型范围 supported_models：限定可调用的模型。
- 有效期 expires_at：设置 Key 的过期时间。

#### Q4：使用 Google AI SDK 时出现 API Key 验证弹窗怎么办？
Google AI Studio 的 Gemini 3 可能会弹出 API Key 验证。如需关闭，可在提示词中加入如下指令：

#### Q5：视频生成任务失败该怎么处理？
建议按以下流程排查：

- 查看 status 和 fail_reason，确认失败原因。
- 核对图片格式和大小是否符合要求。
- 检查提示词是否包含敏感内容。
- 增加断点重试能力，从失败节点继续生成。

## 5.3 Vercel 云端部署指南

代码打磨完成之后，就要把应用放到网上让别人使用。就像书稿完成要出版、菜肴做好要上桌，个人作品也需要一个公开的入口。

传统上线流程要租服务器、搭环境、配域名解析、办 HTTPS 证书，步骤繁琐。借助 Vercel，使用 Vibe Coding 开发的 AI 应用可以把部署简化到只需几次点击。Vercel 能把本地代码直接发布到互联网，无需自建服务器，体验类似发邮件，应用会部署到全球分布式节点，技术细节自动处理，同时提供性能优化和安全保护。

对个人开发者来说，Vercel 目前几乎免费，每月 100 GB 流量基本够用，还会自动申请并续期 SSL 证书，保证访问安全。

使用前先明确适用场景，避免选错。

适合 Vercel 部署的类型主要有 3 类：

- 前端框架应用：React、Vue、Next.js、Vite 等构建的单页应用。
- 静态网站：纯 HTML、CSS、JavaScript 构成的页面。

### 5.3.1 GitHub 导入与首次部署

想用 Vercel 部署，建议先把项目托管到 GitHub。Vercel 与 GitHub 深度结合，可直接导入项目，代码更新后还能自动重新部署。若尚未托管，可参考 5.1 节方法。

项目已在 GitHub 仓库后，按如下步骤完成首次部署：

- (1) 登录 Vercel 并授权 GitHub。
用 GitHub 账号登录 Vercel，并授权访问仓库。
- (2) 进入导入页面。
在控制台首页点“Import Project”或“Add New Project”，系统会列出账号下的所有仓库，仓库多时可使用顶部搜索定位。
- (3) 选择并导入项目。
找到目标项目后点右侧“Import”，Vercel 会自动分析结构，识别框架并自动设置构建命令和输出目录。
- (4) 确认导入配置。
在配置页确认以下项，如图 5-7 所示。
  - Project Name：作为访问地址的一部分，例如 my-learning-app，最终地址为 https://my-learning-app.vercel.app。
  - Framework Preset：通常自动识别，识别错误可手动选择。
  - Root Directory：代码在子目录时需指定，否则保持默认。
- (5) 配置构建设置（可选）。
Build and Output Settings 包含：
  - Build Command：编译命令，npm 项目通常为 npm run build。
  - Output Directory：构建产物目录，常见有 dist、build、out。
Vercel 会按框架自动填好，一般无需改动。
- (6) 添加环境变量（如需）。
如需 API Key、数据库连接串等，可在 Environment Variables 中添加。例如调用 Google AI API 时添加 GOOGLE_AI_API_KEY，值为你在 Google AI Studio 获取的 Key。敏感信息会安全保存，不会进入代码仓库。
- (7) 启动部署。
确认无误后点底部“Deploy”。Vercel 会依次拉取代码、安装依赖、执行构建、生成静态文件、上传至全球 CDN、配置 HTTPS，约需 2～5 分钟。
- (8) 访问应用。
部署成功后会显示访问地址，通常为 https://你的项目名.vercel.app，点击即可打开，全球用户均可访问。

首次部署后，Vercel 会监听 GitHub 仓库变更。每次推送更新，都会自动触发重建与部署，耗时约 2～5 分钟。后续只需在 Cursor 中优化代码并推送，发布由 Vercel 自动完成。

### 5.3.2 部署错误排查

部署失败很常见，无需紧张。Vercel 会给出详细日志，说明错误环节和原因。

常见错误类型：

- 构建命令不正确：构建脚本配置错误。
- 缺少环境变量：代码引用了未在 Vercel 配置的变量。
- 依赖安装失败：npm 包因网络或版本不兼容无法安装。
- 代码语法错误：项目本身存在编译错误。

标准修复流程：

- 查阅错误日志：仔细阅读 Vercel 的报错信息，定位问题点。
- 本地构建测试：在终端运行 npm run build，与 Vercel 环境一致，可快速复现问题。
- AI 辅助修复：把错误信息粘到 Cursor 的 AI 功能中，获取定位和修复建议。
- 推送修复代码：修复后推送到 GitHub，Vercel 会自动重新部署。
- 确认部署结果：在控制台的 Deployments 标签页查看最新部署状态。

若因环境变量缺失导致失败，需在项目设置中补全变量后点“Redeploy”。Vercel 会保留历史部署记录，出现问题时可一键回滚到之前可用的版本。
