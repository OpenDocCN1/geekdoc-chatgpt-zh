## 7.4 单体智能向多体协作的转变
当前业界对从单一智能体扩展到多体系统的讨论较为热烈，其中一个共识是协作式多体架构能够显著提升整体效能。Plan-and-Execute 本身并没有把多体场景作为核心诉求，其主旨是通过拆分规划与执行，并给出细化的操作指引来增强推理质量，降低单次推理负担，从而提高计划与执行的稳定性。

运行中，规划与执行可以由同一智能体承担，但更优的做法是为二者配备不同的模型，即不同的智能体。用推理能力更强的模型负责需要深度思考的规划，用体积更小、响应更快、成本更低的模型负责具体步骤的落地。进一步说，执行环节本身也能够拆分给多个智能体协同完成。

因此 Plan-and-Execute 的思路完全可以在多体系统中复用。不论是单体还是多体部署，关键点都在于如何有效地拆解任务、构建解决方案，以及如何提供明确的操作步骤来驱动模型或智能体完成工作。

## 7.5 小结
第六章的 ReAct 与本章的 Plan-and-Execute 都能提升大模型在复杂任务上的表现。目标接近，但侧重点有别。

ReAct 强调“观察-思考-行动”的循环，侧重让模型更好理解外部环境、形成推理轨迹并采取行动，特别适合需要与外部环境交互的场景，比如信息查找、环境探索等。通过记录每一步的推理，提升了可解释性与可靠性。

Plan-and-Execute 则更聚焦于复杂情境下的性能提升。做法是先将整体任务拆解为更小、更易掌控的子任务，再借助更详尽的指令提升推理步骤的质量与精准度。该方法尤为适合需要多步推理的难题，如数学求解、逻辑分析等。

因此本章标题所说的“计划与执行的解耦”正是 Plan-and-Execute 的核心要义：把问题解决过程明确划分为规划阶段与执行阶段。规划负责理解问题、剖析结构并制定详细方案；执行则按规划逐步求解。先规划后执行的策略能帮助大模型更系统、更准确地解决问题。

Plan-and-Execute 的优势包括：
- 任务拆解：把大任务分解为小任务，便于管理和攻克复杂问题。
- 细化指引：提供详尽指令以改善推理质量和准确度。
- 适应性强：可依据不同任务类型调整，在各类复杂问题中保持稳定表现。

对于需要多步推理的复杂问题，Plan-and-Execute 通常更占优势；而 ReAct 更适合模型与环境交互的任务。二者各有长处，也能互补。在多体环境下，可用不同智能体分别承担规划与执行，或由不同智能体完成任务的不同环节。

## 8.1 何谓检索增强生成
检索增强生成 RAG 是一种融合信息检索与文本生成的AI技术，常用于问答、对话生成或内容摘要等自然语言处理任务。

其工作大致分为两部分：
- 信息检索：从大规模数据集中查找相关信息。数据集可以是维基文章、新闻稿件等文本，也可因大模型的多模态能力而包含图片、代码、关系数据库等形式。接收到查询后，系统会从中检索相关内容。
- 文本生成：检索到信息后，由预训练语言模型如GPT等据此生成响应。模型基于检索内容构建连贯且相关的回答或文本。

RAG 的优势在于兼顾了检索系统的精确信息获取能力和语言模型的流畅生成能力，使得在复杂语言理解任务中能提供更丰富、更准确的信息。例如在问答系统中，RAG 能给出基于事实的答案，而非仅依赖模型的泛化推断。

图8.3展示了借助RAG从知识库提取上下文，再由大模型处理用户查询并生成响应的闭环。基于此流程的Agent可应用于聊天机器人、搜索引擎、推荐系统等需要从海量数据中提取和处理信息的场景。

[PRE4]
图 8.3 展示了一个从用户查询到最终响应的闭环。首先用户提出查询，其次系统根据查询从知识库中提取上下文信息，然后大模型使用这些上下文信息来生成一个合适的响应。基于这个过程的 Agent 可以在聊天机器人、搜索引擎、推荐系统或任何其他需要从大量数据中提取和处理信息的系统中发挥作用。

RAG 还能持续更新所检索的数据源，以适应新信息和趋势，保持响应的相关性与准确度。
