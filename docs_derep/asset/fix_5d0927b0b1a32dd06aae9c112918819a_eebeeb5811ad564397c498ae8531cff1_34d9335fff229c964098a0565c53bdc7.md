从游戏显卡到智算引擎

其实图形处理器在三维 PC 游戏的黄金时期就已经崭露头角。那一批游戏追求极致沉浸感，典型特征就是精细的三维场景、细腻材质和逼真光影，像实时的天气变化、光线反射都成为标配。要把这种画面实时拼出来，需要海量即时运算。中央处理器在处理大规模并行任务时效率一般，图形处理器却能同时推动成千上万条简易运算，高效完成画面渲染，让玩家获得更流畅的体验。

2）AI 芯片常用性能指标
搞清处理器作用后，下面把几个在实际评估中很常用的关键参数梳理一遍。

（1）算力。指的是处理器每秒能够完成的浮点运算数量，用 FLOPS 表示，是衡量计算能力的直观标尺，数值越大处理能力越强。常见计量单位有 TFLOPS，即每秒万亿次浮点运算；PFLOPS，即每秒千万亿次浮点运算。在大模型训练与推理场景里，经常会按 FP32 单精度、FP16 半精度或 BF16 脑浮点等不同数值精度来谈算力。总体规律是精度越低，标称算力越高。如今训练和推理普遍支持 FP16、BF16 甚至 INT8 八位整型等低精度模式，厂商多以这些精度的高算力来做宣传。跨产品对比时一定要把精度对齐，否则结论会失真。

（2）显存。相当于集成在智能处理器内部的专用高速缓存，而不是挂在主板总线上供 CPU 调用。这种布局让数据搬运带宽更高，并且离计算核心更近，能持续为算力供给高速数据流。可以把显存视作处理器的操作台面，模型权重、中间结果以及待处理的输入数据如长文本、图像等都会暂时放在这里。容量越大台面越宽阔，能够一次载入更大规模的模型，或处理更长文本、更复杂的任务。对参数量动辄数百亿、数万亿的大模型来说，大容量显存是刚需。

（3）显存传输速率。指计算核心与显存之间数据搬运的速度，可理解为两者间的通道宽度，单位通常是 GB/s 或 TB/s。若核心算力很强但数据传不过来，核心就会空等，整体效率被拖累。足够高的传输速率可以保证数据被快速持续喂入，让强劲算力得到释放，避免出现数据饥饿，对大模型的高效训练与推理尤为关键。

（4）芯片间互联速率。指多颗智能处理器之间传输数据的速率，一般借助 NVLink、HCCS 等专用高速互连实现，可看作芯片间的连接通道宽度，单位同样是 GB/s 或 TB/s。训练超大模型时，模型往往分布在数百甚至上万颗芯片上协同工作，需要频繁交换参数、同步梯度。互联速率越高，数据在芯片间流动越顺畅，就越不容易让通信成为系统瓶颈，从而提升大规模集群的训练效率与扩展能力。

以上几个参数数值普遍越大性能越强，成本也越高。它们并不是孤立存在，相互匹配程度直接决定整体表现。就算算力很高，若存储容量或传输速率不足，实际速度仍会被限制。因此选型时不能只盯单一数字，要看各项参数的平衡与协同。

**2.AI 芯片江湖：群雄逐鹿与生态博弈**
1）各式各样的智能算力单元
当前智能算力市场正处高速扩张期，图形处理器仍是绝对主力，得益于天然的并行优势，非常契合模型中的复杂计算。不过图形处理器并非唯一解，随着应用场景细分与技术演进，NPU、ASIC、FPGA 等类型也在迅速抬头。

（1）图形处理器。擅长并行计算，最初为图形渲染而生，后被广泛用于深度学习的矩阵运算。通用性强，是目前训练和推理的主流选择，尤其适合大规模并行任务。典型产品有英伟达 H100、H200、RTX 系列；AMD Instinct MI300X、Radeon RX 系列。

（2）专用集成电路 ASIC。为特定智能任务量身打造，在特定场景下能实现极高的计算效率和能效比，但功能固定、灵活性较差。典型产品有谷歌的张量处理单元 TPU、英特尔的 Habana Gaudi 系列。

（3）现场可编程门阵列 FPGA。制造完成后可按需重配置逻辑电路，性能和能效通常略逊于 ASIC，但比图形处理器更易做定制化，适合算法需要快速迭代或有特殊定制需求的场景。典型产品有英特尔 Arria 系列、Xilinx Versal 系列，后者现属 AMD。

（4）神经网络处理器 NPU。专为神经网络计算设计，常集成在 CPU 或 SoC 中，主要面向高效推理，特别适合低功耗的边缘设备和移动终端。一般不具备训练能力，但在执行已训练模型时表现突出。典型产品有高通 Snapdragon 系列中的 Hexagon NPU、苹果 A 系列芯片中的 Neural Engine、英特尔酷睿 Ultra 系列中的 Intel AI Boost NPU。

（5）其他创新架构。除以上主流类型外，众多厂商正在探索新型架构，希望突破传统限制，为智能计算提供更优解。

这场算力竞争既在类型之间展开，也在企业之间展开。过去英伟达凭借图形处理器在智能芯片领域占据主导，尤其在大型模型训练上领先。如今竞争加剧，传统芯片巨头 AMD、英特尔，科技公司谷歌、Qualcomm，以及中国本土厂商华为、百度、摩尔线程、寒武纪、沐曦、壁仞科技等都在加大投入，推动技术革新，并在国内市场快速扩大份额。

2）软件生态：算力的“灵魂”
硬件强劲还需要软件驱动，就像电动车配强劲电机也需要操作系统和自动驾驶辅助系统才能跑起来。软件栈包括驱动、编程工具、库文件等，核心目标是帮助开发者更高效利用算力运行大模型。

英伟达的 CUDA 生态是智能软件领域的事实标准，像一种通用语言，让开发者能便捷地在各款英伟达图形处理器上编写和运行智能程序。统一的编程模型让应用可在所有英伟达图形处理器上灵活部署与扩展。

AMD 为其图形处理器尤其是 Instinct 系列数据中心加速卡推出开源平台 ROCm，提供编译器、库和开发工具，支持 PyTorch、TensorFlow 等主流框架。AMD 正联合社区及合作伙伴如 Meta 的 PyTorch 团队，不断优化 ROCm 对大模型的支持，提升在训练与推理领域的竞争力。

英特尔推出 oneAPI，这是一种面向多种架构的统一编程模型，旨在简化 CPU、GPU 包括英特尔 Xe 架构、FPGA 和智能加速器如 Gaudi 系列等不同硬件的开发流程。oneAPI 包含 oneDNN、oneCCL 等工具包，提供 C++、Fortran、Python 接口，核心理念是打造开放标准化统一软件栈，避免因硬件差异反复改代码。智能应用可通过 Intel Extension for PyTorch 在英特尔硬件上高效运行并优化大模型。

华为为昇腾 AI 处理器构建全栈软件 CANN，覆盖底层驱动到上层应用开发，提供统一编程接口、算子库、编译器、运行时及开发工具，目标是简化智能应用开发与部署，支持自研 MindSpore 以及 PyTorch、TensorFlow 等主流框架，帮助充分发挥昇腾处理器算力，高效训练和部署各类大模型。

中国本土厂商正积极自建软件栈以降低对 CUDA 的依赖，如华为 CANN、摩尔线程 MUSA、寒武纪 NeuWare/MagicMind、沐曦 MXMACA 等，均致力于提供类似 CUDA 的功能，支持主流智能框架并配备工具链帮助迁移代码。

本土软件生态发展很快，但在成熟度、生态广度和全球开发者支持方面与 CUDA 仍有差距，可能带来互操作性问题和跨平台开发复杂度。但随着开源大模型的普及，硬件无关和开放平台趋势加强，为本土厂商提供了凭兼容性和性能扩大份额的机会。

3）智能芯片的软件栈小结
CUDA 仍是最成熟、生态最完善的智能软件平台之一，对追求极致性能和即开即用体验的开发者仍是首选，但仅限英伟达硬件，存在平台绑定。

ROCm 是 AMD 为挑战英伟达地位推出的开源平台，性能与生态成熟度不断提升，与 PyTorch 等主流深度学习框架的兼容性日益增强，对看重开放性和成本效益的开发者极具吸引力。

oneAPI 是英特尔提出的跨硬件统一编程模型，旨在打破厂商锁定，提供更灵活的开发体验，特别适合需在 CPU、GPU、FPGA 等多种英特尔硬件上部署智能应用的场景。其中 OpenVINO 是 oneAPI 在推理端的关键组成部分，已成为边缘计算和高性能推理的亮点。

CANN 是华为昇腾 AI 处理器专属的全栈式软件平台，体现中国在智能芯片领域实现自主可控的重要进展。对致力国产化替代并采用昇腾硬件的开发者而言，CANN 提供深度优化的性能表现和持续完善的生态支持。
