Chain走固定路线，Agent靠动态决策

本质上看，Chain在识别意图后会严格按预设步骤推进。这种刚性安排有两面性。优势体现在标准流程下执行稳定、可预期；局限体现在面对表达各异的用户输入时，可能需要多次调用外部函数，且中间环节不固定，硬套既定逻辑会限制完成度。要打破这个瓶颈，需要一个能够先理解输入再循环推进、直到全部需求闭环的决策大脑，这正是Agent的定位。它更接近人类大脑，具备自主分析与处理的智能体特性。

因此在LangChain体系里，当前端接收的内容更松散、后端处理路径不再唯一时，用Agent来组织整条链路更贴合。其核心作用是自动解析意图，对拆解后的子任务判断是否需要调用外部函数、调用频次、如何保存与传递中间结果等复杂流程，由它来拍板。

以LangChain为例，若没有代理人，只能把动作和逻辑写死在代码里，也就是所谓的链条。这种硬编码难以释放大模型本身的推理潜能。引入代理后，模型可以充当推理引擎，既能进行问答交互，也能调用工具、API等外部资源，并自行决定调用顺序，灵活性显著提升。

### 9.5.3 架构

#### 1. Agent

Agent担当决策者的角色，主导后续行动，其行为通常依赖语言模型、精心设计的提示以及输出解析逻辑的共同作用。不同代理在推理提示风格、输入编码形式和输出处理方式上各不相同。更多内置代理清单可参考代理分类指南，用户也可以根据需要自定义代理以获得更精细的控制。

##### 2. AgentExecutor

AgentExecutor是代理的实际运行环境，负责驱动代理的运行循环：选择行动、执行动作、收集结果反馈给代理并循环往复。简化伪代码见代码9-29。

- （2）处理工具执行错误的情况。
- （3）处理代理生成无法解析为工具调用的输出的情况。

##### 3. Tools

工具是代理可激活的功能模块，本质上是可调用的函数。其设计包含两个核心要素。

- （1）输入架构：工具的接口说明，明确LLM调用时必需的参数组合。参数命名要直观、描述要详尽，才能保证准确调用。
- （2）执行函数：工具背后的实际运行逻辑，通常是一段可执行的Python代码，是功能实现的载体。

设计工具时需注意两大原则。

- （1）权限与可达性：确保代理能够访问所有必要的工具，工具库必须完整覆盖实现目标所需的全部功能。
- （2）描述的精确性与友好性：工具表述必须精准且易懂，避免歧义，提升代理识别与使用效率。清晰的描述直接影响任务执行的效率与准确性。

偏离上述准则会阻碍高效代理系统的构建。工具集不足会限制任务完成能力；描述模糊则会导致代理无所适从。

LangChain配备了丰富的工具集以加速开发，同时也支持用户自定义工具与个性化描述。完整清单可参考官方文档的工具集成部分。

##### 4. Toolkits

对于常见业务场景与复杂任务，代理往往需要一组协同工作的工具。LangChain引入了工具包的概念，每个工具包通常包含3～5个相互配合的工具，针对特定领域或目标。例如面向GitHub的工具包内含搜索问题、读取仓库文件、在议题下发表评论等工具，使代理能够全方位参与平台操作与管理。

LangChain持续扩展生态，提供覆盖多个领域的入门级工具包，便于集成与快速部署。详细列表与说明可查阅官方文档的工具包集成内容。

##### 5. Agent Type

按关键维度对现有代理类型进行梳理有助于选择合适的方案。

- （1）代理型号：用于聊天模型还是LLM，影响提示策略。
- （2）支持聊天历史记录：是否可用作聊天机器人。
- （3）支持多输入工具：是否支持具有多个输入的工具。
- （4）支持并行函数调用：是否可同时调用多个工具以提升速度。
- （5）所需的模型参数：是否需要模型额外参数支持，如OpenAI函数调用。
- （6）何时使用：适用场景。
