### 1.1.3 让模型越用越强：先训后调的思路
深度学习里，把大规模无标注数据先用来学习通用表征，再在下游任务上做针对性调优，已成为提升效果的主流做法。该思路在自然语言处理上成效显著，在视觉等方向也同样适用。

### 1. 先训阶段的原理
先训的核心是用海量未标注语料让网络学会通用的特征。常见做法是自监督或无监督，让模型在初期就能从上下文中抽取出有迁移价值的表示。

### 2. 后调的落地流程与工程实践
先训后调的范式已在 NLP、CV 多个方向落地。以 BERT、GPT 这类模型为例，均可在 PyTorch、TensorFlow 等框架上完成针对性调优，调优后用测试集检验泛化能力。完整步骤可参考图 1-6。

**图 1-6 大模型的预训练与微调流程分析图**

先训得到的模型，是在海量无标注文本上训练出的通用语言表征，依赖自监督机制学习语言结构、语法与语义关联。

后调后的模型，则是在先训模型基础上，用特定任务的有标注数据进行有监督训练，得到面向具体任务的专用模型。两者的差异见表 1-2。

**表 1-2 预训练模型与微调后的模型对比表**

| 特点 | 预训练模型 | 微调后的模型 |
| :--- | :--- | :--- |
| 定义 | 在大规模未标注数据上训练，具有通用语言理解能力 | 在特定任务数据上训练，具备任务专属性能 |
| 适用场景 | 开放式任务，零样本、少样本学习 | 明确的特定任务场景，精确度要求高 |
| 任务表现 | 通用表现良好，任务精度较低 | 任务表现优异，具有更高的精度 |
| 扩展性 | 适合多任务迁移，适应新任务较快 | 针对单一任务优化，迁移至新任务效果差 |
| 计算资源需求 | 预训练阶段资源消耗大 | 计算成本较低，适合在预训练模型基础上开发 |

## 1.2 LangChain 原理与开发方法
随着大语言模型在各类智能产品中的普及，如何高效搭建、部署与管理这些模型变得关键。LangChain 就是为解决这一问题而设计的工具链，它把 LLM 的开发流程做标准化，让复杂任务的组合更顺手、更灵活。

下面先介绍 LangChain 的基本原理和开发思路，聚焦核心组件、协作方式与上手技巧。

### 1.2.1 LangChain 核心构造：Chain 与 Memory
在基于 LLM 的 NLP 场景里，模型既要生成内容，也要在多步任务中保持上下文连贯与记忆能力。LangChain 围绕任务链 Chain 和内存模块 Memory 构建核心架构，这两块是搭建复杂语言应用的关键。

#### 1. 任务链：多步任务的编排
任务链是 LangChain 最基础的组织形式，提供模块化方式来串联多步操作。

##### 1）任务链的运作机制
一个大目标会被拆成若干子目标，每个子目标独立执行但会接收前一步的输出。LangChain 中的链由多个节点组成，节点间通过数据流相连。

##### 2）链的类型与典型用途
按复杂度和需求，常见的链类型有：

（1）顺序链 Sequential Chain：按固定顺序执行子任务，适合强依赖的流程。比如用户请求处理中依次做意图判断、信息抽取、回复生成。

#### 2. 内存模块：上下文保持与记忆
在多轮对话、复杂推理与长文本生成中，模型需要记住用户信息并保持连贯。LangChain 的记忆模块正是为此而生，它通过持久化的上下文记录和动态回溯，为任务执行提供记忆能力。

使用 LangChain 构建应用，第一步是明确需求与场景。要弄清哪些业务逻辑可由大模型承担，以及各任务的输入输出特征。

#### 2．任务链的设计与配置
链的设计决定了 LLM 如何按逻辑顺序完成多步任务。一个链通常包含文本生成、信息抽取、数据分析等子任务，具体选择取决于需求。

配置时需指定各组件的顺序及其依赖关系。借助 LangChain 提供的接口，调用逻辑可按预设流程自动运行，从而高效完成多步任务。

##### 4. 数据存储与内存模块集成
LangChain 的内存模块负责暂存链执行产生的中间数据，为后续步骤提供上下文，保证数据在任务间流转与共享，提升整体效率。它支持会话内存与持久化内存，可按需配置。

在需要复杂信息检索的场景，还会结合向量数据库。向量数据库对数据做向量化存储与相似度计算，能提高文本匹配与检索精度。LangChain 的架构让内存模块与向量数据库无缝协作，从而提升模型在信息管理与检索方面的能力。
