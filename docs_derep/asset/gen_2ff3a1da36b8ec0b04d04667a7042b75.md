# 4. 加入 Docker 官方仓库
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 5. 刷新源并部署 Docker 核心包
sudo apt install -y docker-ce docker-ce-cli containerd.io

# 6. 检查 Docker 运行状态
sudo systemctl status docker

# 7. 让普通用户免 sudo 调用 Docker
sudo usermod -aG docker $USER

# 8. 开启 Docker 开机自启
sudo systemctl enable docker

**注意：**以上操作完成后，需要退出当前终端重新登录一次，普通用户的组权限才会生效。

2. Docker Compose 安装
Ubuntu 自带源里的 Docker Compose 版本普遍偏旧，兼容性易出问题，建议直接拉取官方最新稳定版，流程如下：

# 1. 获取最新版 Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose

# 2. 赋予执行权限
sudo chmod +x /usr/local/bin/docker-compose

# 3. 确认安装结果
docker-compose --version

部署 OpenClaw 的首要动作是把官方镜像拉到本地，镜像地址为 ghcr.io/openclaw/openclaw:latest，latest 代表当前稳定版。执行 docker pull ghcr.io/openclaw/openclaw:latest 后，引擎会从 GitHub 仓库把镜像下载到本机服务器。

运行容器前要理解数据卷与目录挂载的原理。容器默认是临时性的，停止删除后内部产生的一切文件都会消失，包括配置、日志。OpenClaw 的核心资产如 openclaw.json、会话记录、技能插件等都需要长期保存，因此必须把宿主机的物理目录映射进容器。根据官方说明，容器内部统一使用 /root/.openclaw 作为数据根目录。

### 8.4.3 编写 Docker Compose 文件
用一条冗长的 docker run 命令也能启动，但参数多且难维护。实际使用更推荐 Docker Compose，通过一份结构清晰的 YAML 来统一管理。

在服务器上新建一个存放 OpenClaw 数据的目录，并在其中创建 docker-compose.yml。文件里定义一个名为 openclaw-gateway 的服务，指定官方镜像，并加上 restart: unless-stopped 策略，保证异常或重启后自动恢复。

端口方面把容器内 3000 映射到宿主机 3000。数据卷是关键，把宿主机的 ./data 挂载到容器内的 /root/.openclaw，实现持久化。

还可通过 environment 注入环境变量，比如时区 Asia/Shenzhen，或把大模型 API Key 以变量形式传入，避免写进文件。最后用 command: ["gateway"] 指定启动网关服务。

OpenClaw 官网给出的标准 Compose 配置如下：

services:
  openclaw-gateway:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN:-}
      OPENCLAW_ALLOW_INSECURE_PRIVATE_WS: ${OPENCLAW_ALLOW_INSECURE_PRIVATE_WS:-}
      CLAUDE_AI_SESSION_KEY: ${CLAUDE_AI_SESSION_KEY:-}
      CLAUDE_WEB_SESSION_KEY: ${CLAUDE_WEB_SESSION_KEY:-}
      CLAUDE_WEB_COOKIE: ${CLAUDE_WEB_COOKIE:-}
      TZ: ${OPENCLAW_TZ:-UTC}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    ports:
      - "${OPENCLAW_GATEWAY_PORT:-18789}:18789"
      - "${OPENCLAW_BRIDGE_PORT:-18790}:18790"
    init: true
    restart: unless-stopped
    command:
      [
        "node",
        "dist/index.js",
        "gateway",
        "--bind",
        "${OPENCLAW_GATEWAY_BIND:-lan}",
        "--port",
        "18789",
      ]
    healthcheck:
      test:
        [
          "CMD",
          "node",
          "-e",
          "fetch('http://127.0.0.1:18789/healthz').then((r)=>process.exit (r.ok?0:1)).catch(()=>process.exit(1))",
        ]
      interval: 30s
      timeout: 5s
      retries: 5
      start_period: 20s
  openclaw-cli:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    network_mode: "service:openclaw-gateway"
    cap_drop:
      - NET_RAW
      - NET_ADMIN
    security_opt:
      - no-new-privileges:true
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN:-}
      OPENCLAW_ALLOW_INSECURE_PRIVATE_WS: ${OPENCLAW_ALLOW_INSECURE_PRIVATE_WS:-}
      BROWSER: echo
      CLAUDE_AI_SESSION_KEY: ${CLAUDE_AI_SESSION_KEY:-}
      CLAUDE_WEB_SESSION_KEY: ${CLAUDE_WEB_SESSION_KEY:-}
      CLAUDE_WEB_COOKIE: ${CLAUDE_WEB_COOKIE:-}
      TZ: ${OPENCLAW_TZ:-UTC}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    stdin_open: true
    tty: true
    init: true
    entrypoint: ["node", "dist/index.js"]
    depends_on:
      - openclaw-gateway

### 8.4.4 启动与管理服务
文件写好后，进入 docker-compose.yml 所在目录执行 docker-compose up -d，即可在后台守护模式启动服务。

运行期间可通过 docker-compose logs -f 实时跟踪日志。若需初始化配置或安装插件，不能在宿主机直接运行，而应先用 docker exec -it openclaw-gateway /bin/bash 进入容器，再在容器内部执行 openclaw configure 等命令。

版本更新也很顺滑：在同目录执行 docker-compose pull 拉取新镜像，再执行 docker-compose up -d 用新镜像重建容器。得益于数据卷挂载，./data 中的配置与历史数据会完整保留并自动接入新版本。

## 9.1 集成飞书
飞书由字节跳动打造，以流畅体验与开放平台能力著称。OpenClaw 对飞书提供原生支持，核心在于采用飞书开放平台的 WebSocket 长连接事件订阅，而非传统 Webhook。这样无需在服务器暴露公网 URL，也省去反向代理与 SSL 配置，安全性更高。

### 9.1.1 创建飞书企业应用与机器人
首先在飞书开放平台创建自建应用作为身份凭证。登录后进入开发者后台，点击创建企业自建应用，填写名称如“OpenClaw 智能助手”、描述并上传图标。

创建成功后进入详情页，在凭证与基础信息中获取两个关键参数：
• App ID，通常以 cli_ 开头；
• App Secret，应用密钥。
这两个值相当于机器人的账号密码，后续校验身份时会用到，需妥善保存。

随后在添加应用功能中打开机器人开关，机器人即成为 OpenClaw 在飞书里的交互入口。

### 9.1.2 配置权限与事件订阅

{
  "scopes": {
    "tenant": [
      "im:chat.members:bot_access",
      "im:message",
      "im:message.group_at_msg:readonly",
      "im:message.p2p_msg:readonly",
      "im:message:readonly",

其中 user 下的 contact:contact.base:readonly 用于只读访问企业通讯录基础信息，是机器人识别用户身份、完成上下文匹配的前提。若未开通，用户发起指令时机器人将因缺少数据而失效。
