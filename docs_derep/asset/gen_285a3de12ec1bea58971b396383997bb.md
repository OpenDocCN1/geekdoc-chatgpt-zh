近年来大量实验反复验证，在训练数据充足的情况下，单纯扩大语言模型的规模和算力投入，确实能带来能力提升。但随着模型逼近十亿、千亿级参数，算力成本的飙升已经成为制约继续放大的关键障碍。混合专家 MoE 架构正是在此背景下出现，它让模型参数可以大幅增长，同时保持计算开销相对可控，从而实现了参数规模的跃迁。

即便 MoE 在扩展性上很具吸引力，落地时仍暴露出明显的专家专业化不足问题。传统做法是在 Transformer 的每层把标准的 FFN 换成 MoE 层，层内放置若干结构类似 FFN 的专家，每个输入 token 通常只送给一到两个专家计算。这种做法虽然增加了参数量，却带来两大痛点。

（1）知识混杂。现阶段常用的专家数量普遍在 8 到 16 个左右，每个专家承接的 token 来自多个知识域，被迫同时承载多种异质知识，导致在特定领域难以形成深度专精。

（2）知识重复。不同专家在处理 token 时都不可避免地要学习通用表征，于是各自的参数逐渐趋同，产生大量冗余，降低了整体参数的利用效率。

这两个问题共同拉低了 MoE 的理论上限。为此 DeepSeek 团队提出 DeepSeekMoE，目标是把专家专业化推向极致。思路上是在传统 MoE 基础上做两件事：其一，把单个专家继续拆成更小的子专家，运行时只激活其中一部分，从而获得更灵活、可组合的专家集合；其二，单独设立一组共享专家来统一吸收通用知识，让路由专家可以专注于各自的专长。双管齐下，既控制计算成本，又显著提升专业化程度，为大模型的高效扩容提供了更稳健的方案。

#### 4.1.2 架构拆解：DeepSeekMoE 的设计思路

为解决知识混杂与冗余，DeepSeek 提出 DeepSeekMoE，核心目标是在大规模扩展中兼顾性能与算力。主要由细粒度专家拆分和共享专家分离两大策略构成。

1. 细粒度专家拆分
该策略把传统 MoE 中的每个专家进一步拆成多个子专家。通过下调 FFN 中间隐藏层的维度，使每个子专家能在不改变总参数量的前提下聚焦更窄的知识范围。在相同算力预算下可以激活更多的细粒度单元，专家组合的灵活性明显增强，知识获取的针对性也随之提高。不同领域的知识被更精细地切分，每个单元保持高度专精，有效缓解了专家数量受限引发的知识混杂。

2. 共享专家分离
为避免多专家重复学习通用知识，设计了一组始终在线的共享专家。它们在每次前向传播中都被激活，负责汇聚和压缩跨上下文的共性表征。这样路由专家只需学习各自独特、专业化的知识。隔离机制提升了参数利用率，也让每个专家在特定任务上输出更精准、更专一的表示。

总体来看，DeepSeekMoE 通过细粒度拆分与共享专家分离实现了极致专业化，并在有限算力下为参数扩展提供了高效可持续的路径，也为大模型在性能与效率之间的平衡提供了新的参考。

#### 4.1.3 对比剖析：DeepSeekMoE 与传统 MoE 的差异
DeepSeekMoE 与传统 MoE 的区别主要体现在以下方面。

- 专家拆分的粒度：传统 MoE 多采用粗粒度的专家划分，而 DeepSeekMoE 使用更细粒度的拆分。例如其 MoE 层通常包含 1 个共享专家和 256 个路由专家，让单个专家处理更具体的任务，提升灵活性和表达力。
- 共享专家机制：DeepSeekMoE 引入共享专家负责所有 token 的通用特征提取，路由专家则按 token 特性动态分配。分工明确减少了冗余，提升了计算效率。
- 稀疏激活机制：DeepSeekMoE 采用稀疏激活，每个 token 仅激活少数路由专家，例如 8 个，而不是全量激活。降低了计算负担，也让模型能更灵活地应对不同输入。
- 动态路由机制：DeepSeekMoE 使用动态路由为每个 token 选择最相关的专家，例如 Top-K 策略从全部专家中挑选 K 个最匹配的专家。相比传统 MoE 的固定分配，更能适应输入差异。
- 训练与推理优化：DeepSeekMoE 在训练推理阶段加入多头潜注意力与 RMSNorm 等优化，进一步提升性能与效率。

总体而言，DeepSeek 通过创新的 MoE 设计显著提升了计算效率与灵活性，同时降低了资源消耗。

### 4.2 DeepSeekMoE 工作原理详解

前文提到 DeepSeekMoE 依赖细粒度专家拆分与共享专家分离两个关键手段，二者协同显著提高专家专业化水平，进而提升整体效率与性能。下面详细说明其原理。

#### 4.2.1 细粒度专家拆分

#### 4.2.2 共享专家分离
在传统路由下，不同专家处理的 token 往往需要部分通用知识，导致多专家参数收敛到相似的共享知识，产生冗余。若存在专门捕捉跨上下文通用知识的共享专家，其他路由专家的参数冗余将被缓解，模型更参数高效，路由专家更聚焦独特方面。

#### 4.2.3 负载平衡
自动学习的路由会根据输入特征动态选择专家。但数据分布与路由机制的限制可能导致负载不均，带来两大缺陷。

- 路由崩溃风险：负载不均可能使模型长期只用少数专家处理大部分输入，其他专家缺乏训练信号，导致利用率下降，多样化任务能力受损。
- 跨设备通信瓶颈：在分布式训练中，专家分布于多设备，若部分设备过载而部分闲置，会加剧通信开销与计算瓶颈，降低训练效率并增加延迟风险。

为此现有方法多引入辅助损失项鼓励均衡，但会增加超参数调优负担并可能损害性能。DeepSeek 提出一种无辅助损失的负载平衡策略，通过路由决策中的动态偏置调整，自发实现均衡，既防止路由崩溃，又缓解多设备瓶颈，确保各设备专家充分训练。

### 4.3 DeepSeekMoE 微调实战
DeepSeekMoE 在架构层面通过细粒度专家拆分与共享专家分离提升效率；同时借助 LoRA、量化、ZeRO 等技术进行微调，使其更好适配指令与对话任务。

#### 4.3.1 微调关键技术
微调过程中使用了以下关键技术。

1. LoRA 技术
LoRA 是一种高效微调方法，通过在关键层如注意力层的 q_proj、v_proj、k_proj、o_proj 等插入低秩矩阵，仅训练低秩参数，减少训练量，避免灾难性遗忘并降低计算成本。

2. 量化技术（4 位/8 位）
量化把模型权重从浮点如 32 位或 16 位转为 4 位或 8 位格式，大幅减少 GPU 或 CPU 内存占用，提高推理效率，同时保持性能。

3. ZeRO 优化
ZeRO 是一种显存优化技术，通过把模型参数、梯度与优化器状态分片存储到多 GPU，减少单卡内存占用，支持更大规模训练。DeepSeekMoE 使用了 ZeRO 第二阶段与第三阶段。

4. 混合精度训练
使用混合精度如 BF16 或 FP16 减少显存占用并加速计算。BF16 是一种更高效的浮点格式，适合相应硬件。

5. 分布式训练（DeepSpeed）
DeepSpeed 是支持大规模分布式训练的库。DeepSeekMoE 使用 DeepSpeed 框架实现高效分布式训练。

6. 数据预处理和分词
对训练数据进行预处理，包括构建指令模板、分词、处理标签掩码等。使用 Hugging Face 的 AutoTokenizer 与自定义 train_tokenize_function 将文本转为模型可接受格式。

7. 自定义数据收集器（DataCollator）
定义 DataCollatorForSupervisedDataset 用于把多条数据实例整理为批量格式，支持填充与注意力掩码生成，保证训练数据格式一致。

8. 梯度累积和动态损失缩放
训练中使用梯度累积以实现更大全局批次大小，适应有限显存。动态损失缩放用于优化混合精度训练的数值稳定性。
