## 8.4　AG-UI 协议

AG-UI 协议由 CopilotKit 团队于 2025 年 5 月提出并开源，主要用于规范 AI 智能体与前端 UI 之间的实时双向交互，核心目标是解决复杂应用中智能体与界面高效、可预测通信的问题，把智能体的决策与推理能力转化为动态的用户体验。

（1）前端客户端发起与 AI 智能体的会话。
（2）双方通过 HTTP 流，如 SSE 或 WebSocket，建立持久连接作为事件传输通道。
（3）智能体以流式方式向 UI 推送结构化事件，驱动 UI 实时更新。
（4）UI 向智能体发送用户交互或上下文变化事件，形成双向交互闭环。

（1）文本消息事件：支持智能体思考与回答的流式输出，实现逐字生成体验。
（2）工具调用事件：管理智能体调用外部功能或 API 的完整生命周期，实现能力扩展。
（3）状态管理事件：在智能体与客户端之间同步执行状态与上下文，确保双方认知一致。
（4）生命周期事件：对智能体的任务执行步骤进行精细化控制与管理。

## 9.1　上下文工程

2025 年，上下文工程在大模型应用中成为继提示词工程之后的又一核心技术热点。

### 9.1.1　上下文工程简介

上下文工程是一种系统化的方法论与技术集合，其核心目标是在与大模型交互时，动态、精准地构建并提供最相关、最优质的上下文信息，从而让模型能够生成更准确、更可靠、更个性化的回答。

提示词工程像是教用户如何向一个博学但无背景的超级大脑提问；上下文工程则是在提问前把相关参考资料与背景信息准备好一并提供，让模型基于材料作答。重点已从优化问题本身转向工程化地管理和优化供给给模型的信息背景。

#### 1．为什么上下文工程如此重要

大模型的记忆本质是一个固定大小的文本窗口，类似人类的短期记忆，有容量上限。新信息进入时旧信息会被挤出。系统上下文包含系统提示词、历史对话和当前输入，一旦超出窗口限制，模型就会遗忘前文，这是上下文管理失效的典型表现。

上下文工程的重要性在于提供系统性解法：不是让模型记住所有信息，而是在每个时刻确保其获得最重要的信息，即上下文窗口的理念。

#### 2．上下文工程相关技术有哪些

基础是上下文窗口，即每个大模型都有记忆容量限制。关键技术包括：

（1） **RAG** 。RAG 让 AI 能够从庞大知识库中检索相关信息，相当于为 AI 配备智能图书馆。用户提问时先检索相关资料，再连同问题输入模型，大幅提升准确性和深度。

（2） **上下文学习** 。通过在输入中提供示例，AI 能够快速学会新的任务模式。例如提供若干特定风格邮件的示例，模型即可模仿风格生成，无需重新训练。

（3） **动态上下文管理** 。解决长对话中的信息管理问题。例如客服场景中，重要信息易被冗长历史淹没。智能的上下文管理系统会识别并保留关键信息，剔除无关内容，确保模型始终聚焦重点。其核心策略是滑动窗口加关键信息保留。

#### 3．上下文工程的工作原理是什么

以“我的订单什么时候到？”为例。无上下文工程时，模型仅看到该句，回答可能是“我不知道你的订单信息，请提供订单号”。有上下文工程时，模型可看到完整背景：提问者身份、购买时间、商品等，从而给出准确回答。

背后流程如下：

（1） **语义搜索** 。系统把用户问题转为向量，在用户数据库中搜索语义相似内容，相当于为文本打上语义标签。

（2） **信息检索与匹配** 。通过相似度计算自动找到相关信息：
**·** 识别用户身份；
**·** 找到最近订单记录；
**·** 匹配物流信息；
**·** 检索预计送达时间。

（3） **上下文构建** 。系统把检索到的信息组装成完整上下文，包括用户基本信息、最近订单、订单状态、预计送达、用户问题等。

（4） **注意力机制处理** 。大模型接收到上下文后，通过注意力机制自动关注最相关的部分，然后生成准确回答。

通过上述流程，上下文工程使 AI 从只能看到一句话，升级为拥有完整用户档案，实现了知情对话而非盲目问答。

构建可靠智能体，应逐步摆脱寻找万能提示词或依赖模型迭代的路径。上下文工程的核心在于恰时、恰形、恰量的信息与工具供给。这是一项跨职能挑战，需要深刻理解业务场景、明确输出目标并精心组织必要信息，使大模型真正完成任务。

### 9.1.2　Manus 的上下文工程经验分享

团队归纳出以下 5 条核心原则。

（1） **质量重于数量，进行策略性信息筛选** 。盲目把整份代码库塞给智能体效率低且风险高。Manus 采用按需供给策略，不一次性投喂全部文档，而是在智能体需要执行特定操作时才动态注入最相关的代码片段与文档，提升决策质量。

（2） **结构化是高效理解的基石** 。人类难以阅读杂乱文本，模型亦然。Manus 强调对输入进行精心结构化，包括清晰章节划分与格式化管理。用明确标记分隔不同性质信息，用代码块区分代码、命令、数据与自然语言指令，为模型提供清晰心智模型。

（3） **建立持续性，赋予智能体记忆** 。无记忆的智能体每一步都像从头开始。Manus 通过维护不断更新的任务历史实现持续性，记录已完成任务、遇错情况及解决方案。后续步骤可回溯历史，避免重复劳动与重复犯错。

（4） **预设反应路径，构建稳健决策框架** 。开放环境中智能体可能遭遇意外。可在上下文中预设反应模式，例如遇到不熟悉错误时先分析日志再检查相关代码最后给出修正方案。这相当于为智能体编写应急预案，增强系统稳健性。

（5） **塑造行为模式，而非仅描述任务** 。最有效控制是引导思考方式。Manus 在上下文中明确塑造行为模式，包括角色定义、工作流程与沟通规范。通过这种方式，上下文工程从被动信息供给转向主动行为与人格塑造，培养出稳定高质量的输出风格。
