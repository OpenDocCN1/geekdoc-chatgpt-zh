#### 8.1.10 LangGraph 智能体底层原理解密

##### 1. 框架渊源与定位
从命名就能看出 LangGraph 和 LangChain 关系紧密。实际上 LangGraph 建立在 LangChain 表达式语言之上，专为打造 AI 智能体而生。因此在大模型接入与智能体搭建方面的优势可以自然迁移。技术层面看，大模型本身无法执行动作，只能输出文本，即接收输入并给出回应。

##### 2. 图式网络的基本构成
在图式框架里，任何可执行单元都能作为对话、智能体或程序的入口。该入口可以是模型 API、基于模型搭建的智能体，或借助 LangChain 等实现的线性序列，如图 8.13 中标记为 Start 的圆。无论形式如何，它先处理用户输入，再决定下一步动作。图 8.13 展示的就是最简的 LangGraph 智能体模型。

在 LangGraph 中，具备执行逻辑的组件都被抽象为节点，涵盖模型调用、检索、条件判断等。Start 节点是入口，接收用户输入后会根据需求：
- (1) 触发工具环节做外部信息查询，如网络检索、数据库查询或 RAG 召回。
- (2) 把查到的信息传给语言模型环节，生成自然语言回复。
- (3) 最终把回复送到终点环节，完成整条链路。

如图 8.13 所示，每个圆点对应节点，每条连线决定流程走向；状态则沿着连线通过消息传递更新。

无论智能体复杂度如何，最终都是节点与连线按特定方式组合成的图。工作流的核心在于节点完成后通过连线通知后续节点继续推进。简言之，LangGraph 内部的消息传递机制定义了通用程序模式：节点执行完毕后沿一条或多条连线向其它节点发送消息，接收方执行后把结果传给下一跳，如此循环往复。

如图 8.14 所示，智能体第一次处理后若判定要调用函数，下一步该选哪个工具、带什么参数？当可选工具不止一个时，调用工具环节会出现多条可能路径。LangGraph 为此引入了分支连线。分支连线依据是否满足特定条件来选择分支，比如决定用检索工具还是直接给出最终答案。管理这种决策的结构类似 if-else，称为 Router。Router 决策后，智能体可能被导向网络检索节点执行检索并返回原始文本，也可能直接前往终点节点得到格式化后的自然语言响应。若走检索分支，检索到的文本还需经另一大语言模型处理成用户可读的答案；若直接回答，则可通过专用工具做格式化。

在 LangGraph 中，Router 的 if-else 逻辑主要通过三类手段实现：
- 提示工程：让大模型按指定格式给出回应。
- 输出解析器：对模型响应做后处理，提取结构化数据。
- 工具调用：利用大模型的内置工具调用能力生成结构化输出。

##### 4. 公共状态管理
前面提到 LangGraph 用节点和连线组合出复杂的环形流程，用消息传递串联各节点。让消息及时更新并送达正确位置，依赖的就是状态机制。每一次执行都会启动一个状态，节点在处理时会读写并修改该状态。状态不是静态快照，而是随节点输出动态演进，进而影响环形中的后续操作，如图 8.15。

公共状态指图执行过程中节点之间传递的数据与信息。LangGraph 支持节点在执行时通过公共状态交互。借助这种机制，节点能在共同维护的数据基础上通信、交换信息并相互影响行为，从而实现操作的协调与同步，支撑动态交互与复杂工作流，让各节点基于已有共享信息协同决策。

##### 5. 官方解读与主要优势
官方将 LangGraph 定义为基于大模型构建有状态、多参与者应用的库，可创建智能体与多智能体工作流。官方总结的优势如下：
- 循环与分支：在应用中实现循环和条件逻辑。
- 持久化：每个步骤后自动保存状态，可随时暂停、恢复执行，支持错误恢复、人机协作流程、时间旅行等。
- 人机交互：可中断执行以审批或编辑智能体下一步计划。
- 流式输出：每个节点都可产生流式输出，包括 Token 流。
- 无缝集成：与 LangChain 和 LangSmith 深度集成。
