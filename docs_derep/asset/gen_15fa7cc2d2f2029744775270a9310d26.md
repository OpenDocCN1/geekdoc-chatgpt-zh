# **前言 Preface**

技术变革的浪潮总是以惊人速率推动着行业演化。回望软件工程发展，我们经历了从手工编码到敏捷开发的转变，如今正站在新一轮门槛前 —— 软件工程 3.0 时代的入口，由大模型主导的变革正在重塑整个软件产业。

**为何要写这本书**

2022 年 11 月 ChatGPT 横空问世，像一道闪电照亮人工智能天空。短短一年多时间，LLM 的能力从基础文本生成，发展到理解复杂需求、编写代码、分析系统、设计测试方案，乃至模拟多角色协作。这一技术浪潮不仅改变了人机交互方式，更深刻影响软件开发全流程。

在这场变革中，软件测试既迎来前所未有的机遇，也面临严峻挑战。传统自动化测试正被更高级的范式取代 —— 由 LLM 驱动的智能测试。这不仅是工具迭代，更是思维模式与工作流程的根本转变。

本书正是在此背景下产生。作为一线实践者，我们亲历 LLM 在软件测试中的落地，见证效率提升与质量改善。我们认为该领域亟需一本系统性指南，既要讲清技术原理，更要提供可落地的应用方法，帮助测试人找到新定位和发展路径。

**本书主要内容**

本书以软件测试全生命周期为线索，系统探讨 LLM 在各环节的应用。全书共 8 章。

❑ **软件测试的新时代：** 剖析软件研发迈入软件工程 3.0 的大背景，解析测试面临的新机遇与挑战，为全书奠定理论基础。

# **第一章**

# **软件测试的新时代**

在数字化浪潮推进下，软件研发正步入全新阶段 —— “软件工程 3.0 时代”。其核心驱动是 LLM，凭借强大的语言理解与生成能力，彻底改写传统开发与测试范式。从需求分析到代码生成，再到用例设计与脚本开发，LLM 正以前所未有的深度融入研发每一个环节。

软件测试作为研发关键环节，也迎来机遇与挑战并存的新局面。传统自动化正向智能化演进，测试人员不再单打独斗，而是与基于 LLM 的智能助手协同，完成需求分析、设计与执行等核心任务。人机协作模式显著提升效率，为覆盖率与质量带来跃升。

但新技术落地并非一帆风顺。如何保证 LLM 生成的用例与脚本准确可靠？怎样实现高覆盖的测试场景？如何全面检出潜在缺陷？性能测试与缺陷定位中如何释放 LLM 潜能？这些问题构成智能化测试的关键挑战。本章将剖析软件工程 3.0 背景下测试面临的新机遇与挑战，为未来蓝图提供视角。

## **1.1 软件研发进入软件工程 3.0 时代**

软件工程 2.0 时代虽涌现众多开发、测试与运维工具，但自动化水平提升有限。大量工作仍依赖手工，研发成本居高不下。持续集成与持续交付也受阻，研发速度与质量难以满足市场对快速迭代与高质量交付的需求，差距日益扩大。

所幸 AI 迅猛发展，尤其是 GPT-4 等 LLM 的推出逐步缩小了差距。借助 AI，研发自动化显著提升，持续构建与持续测试从概念走向现实。2022 年 11 月 ChatGPT 惊艳亮相，触发了 2023 年 LLM 的爆发式增长。人们惊喜发现，LLM 不仅能生成代码与用例，还可仅凭自然语言对话完成应用开发，这在过去难以想象。谷歌前首席工程师 Matt Welsh 曾表示，ChatGPT 与 GitHub Copilot 预示编程开端终结，领域将迎来根本性变化，未来可能仅保留产品经理与代码评审角色。观点虽激进，却折射出 LLM 对研发的巨大冲击。

LLM 进化速度惊人。GPT-4 从单模态快速拓展到多模态的 GPT-4v、GPT-4o，以及推理模型 GPT-o1、GPT-5.1、GPT-5.2，能力大幅增强。如今 LLM 已能分析架构设计与 UI 设计，未来更强大的模型有望承担代码生成、缺陷检测、软件设计等复杂任务，影响将更深远。

当前 LLM 已具备理解业务需求的能力，可全程参与软件研发生命周期，推动革命性变革。我们认为 LLM 正在开启软件工程新纪元：软件工程 3.0 时代，即智能软件工程时代。2023 年被视为软件工程 3.0 元年。软件工程时代划分示意如图 1-1。

在此过程中，研发人员与 LLM 紧密协同。LLM 或其构建的工具、系统作为助手、副驾驶或合作伙伴，通过提示词生成所需内容。例如在测试需求分析阶段，测试人员通过引导使 LLM 逐步细化测试项。提示工程成为提升 LLM 在测试中应用效果的关键。LLM 生成内容需经测试人员检查、评审与完善；测试成果也可借助 LLM 工具进行复核，形成人机协同测试环境。未来人机交互智能有望超越模型自身智能，人机协同测试将成为常态。

实践中，多家企业已尝试利用 LLM 进行研发：

❑ 某知名互联网公司在开发电商 App 时，借助训练好的研发 LLM 快速生成基础框架与部分功能代码，大幅缩短周期。

❑ 某些企业结合智能体与相关工具，让基于 LLM 的研发平台生成代码流程图与类图，并辅以自然语言解释，提升代码可视性与交互性。

❑ 部分大厂已将 LLM 用于代码审查或 CI/CD 流程，如拉取请求中自动识别质量问题并提出改进建议。

❑ 某银行测试中心使用测试 LLM 根据需求文档生成大量用例，覆盖各类用户场景与边界条件，通过人机协同及时发现并修复潜在问题，保障 App 质量。

学术研究也在持续探索：

❑ 在软件工程背景下，AI 协调器持续监控工件变化、协调智能体感知与行动，并调用专业 AI 智能体检查一致性与完整性，从而支持端到端开发过程。

❑ 大模型可在需求工程中提供帮助，能分析、组织与总结大量数据，在需求提出初期发挥关键作用。

❑ AI 可使用 C4 模型生成系统高层概述，并自动为开发者生成 UML 类图、序列图、状态机图、组件与部署图等底层图表。

研究表明，对 LLM 进行特定领域微调可显著提升其在该领域研发任务中的表现。例如针对金融行业软件研发，将 LLM 在金融业务数据上微调后，生成的代码更符合行业规范，用例更能覆盖业务风险点。

## **1.2 软件测试的新机遇**

软件测试长期面临工作量大、自动化推进难的问题，多数工作停留在半自动化阶段，严重制约质量提升与效率改善。LLM 的出现为破解难题提供新思路，为测试带来前所未有的发展机遇。

在工业场景中，企业高度关注 LLM 的实际效益与操作便利性，LLM 在多方面助力突破测试困境。企业通常在通用大模型上进行监督微调，将自有业务数据、丰富测试数据如大量用例、脚本、缺陷报告等以及专业领域知识融入其中，构建贴合自身需求的测试 LLM。结合 RAG 技术与智能体开发框架如 LangChain，对测试知识库进行向量化处理，打造知识增强型与检索增强型模型，显著提升其在测试分析、场景挖掘、用例评审、缺陷定位、结果分析等关键环节的能力，并借助模型生成用例、脚本与报告等测试制品。
