## 线程进程核心差异

线程与进程的本质区别可以概括为以下几点。

- 1. 进程内部的线程共享同一块内存区域，而不同进程之间完全隔离。
- 2. 同一进程下的线程彼此共享数据，便于进程内通信；而不同进程的数据各自独立。
- 3. 对主线程进行修改可能波及到同进程的其他线程，但父进程对子进程的改动，除删除外，一般不会影响子进程运行。
- 4. 线程本质上是单条指令流的执行上下文，进程则是围绕计算所拥有的资源集合。
- 5. 同进程线程间可直接交互，进程间通信则必须借助中间媒介。
- 6. 新建线程开销很小，新建进程需要复制父进程，成本较高。
- 7. 线程可操作同属一个进程的其它线程，进程只能管理自己的子进程。
- 8. 线程启动迅速，进程启动较慢，运行期性能不可直接比较。

## 5.3.3 协程

协程英文为 Coroutine，也称微线程或纤程。线程与进程的调度依赖系统接口，最终执行者是操作系统，属于系统层能力。而协程的调度由程序员自行控制，在 Python 中常借助 yield 关键字手动实现并发。

多线程环境下，CPU 采用时间片轮转切换线程，切换本身会消耗开销。协程则在一个线程内部维护多个微任务，按既定顺序执行代码块。

当程序大量耗时操作集中在 I/O 而非计算时，协程会更合适。常用的第三方实现有 gevent 与 greenlet，其中 gevent 是对 greenlet 的高级封装，使用更方便，效率也较高。

协程拥有独立的寄存器上下文和栈。切换时把当前上下文和栈保存到别处，恢复时再加载回来，因此能记住上一次调用时的全部局部状态。下一次进入时，相当于回到上次离开的逻辑位置。线程切换由操作系统在 CPU 寄存器层面完成，CPU 无法感知协程的存在，协程完全由用户态控制。

数据存储是什么？

简言之，数据存储就是把数据持久化到数据库中。数据库是按照一定结构组织、保存和管理数据的仓库。随着信息技术发展，数据管理的重点已从单纯存储转向按需访问和管理。数据库类型多样，从简易的表格式存储到可处理海量数据的企业级系统，在各领域都有广泛应用。

## 6.1.1 初识 MySQL

学习 MySQL 前，先熟悉关系型数据库管理系统 RDBMS 的常用术语。

- 数据库：由多个关联表组成的集合。
- 数据表：数据的集合，在数据库中呈现类似电子表格。
- 列：通常存放同类数据，如邮编列。
- 行：一条相关记录，如一条用户订阅信息。
- 冗余：重复存储数据，用以提升系统性能。
- 主键：唯一标识，一张表只能有一个主键，便于精确定位查询。
- 外键：用于关联不同表。
- 复合键：将多列组合成索引键，常用于复合索引。
- 索引：对表一列或多列的值进行排序的结构，类似书籍目录，加速查询。
- 参照完整性：要求关系中不能引用不存在的实体。

在 Web 领域，MySQL 是主流的 RDBMS 之一。由瑞典 MySQL AB 开发，2008 年 1 月被 Sun 收购。其体积小、速度快、成本低且开源，深受中小型网站青睐。

MySQL 主要特点如下：

- 1. 使用 C/C++ 编写，经过多种编译器测试，源代码可移植性强。
- 2. 支持 AIX、FreeBSD、HP-UX、Linux、Mac OS、Novell Netware、OpenBSD、OS/2 Warp、Solaris、Windows 等系统。
- 3. 为 C、C++、Eiffel、Java、Perl、PHP、Python、Ruby 等语言提供 API。
- 4. 支持多线程，能充分利用 CPU 资源。
- 5. SQL 查询算法经过优化，查询效率高。
- 6. 可作为独立客户端服务器程序运行，也可嵌入其他软件提供多语言支持，常见编码如 GB2312、BIG5、SHIFT_JIS 可用于表名列名。
- 7. 提供 TCP/IP、ODBC、JDBC 等连接方式。
- 8. 配备管理、检查、优化等运维工具。
- 9. 可管理千万级记录的大型数据库。
