#### 3.2.1 DeepSeek-R1模型介绍

DeepSeek-R1 由 DeepSeek 于 2025 年 1 月发布，旨在提升大语言模型的推理能力。评测表明其在数学、代码、自然语言推理等任务上的表现可与 OpenAI o1 正式版媲美。

同期开源 R1-Zero 与 R1 两个 660B 级模型的同时，团队基于 R1 输出蒸馏出 6 个轻量模型，其中 32B 与 70B 版本在多项指标上对标 OpenAI o1-mini。

另外，article 元素也可用于表示插件，使之看似内嵌于页面。

需注意，R1 与 DeepSeek-V3 架构完全相同，仅训练流程与数据不同。具体而言，R1 是在 V3 base 上先进行有监督微调，再进行强化学习训练得到；而 R1-Zero 省略了有监督微调，直接从 V3 base 经强化学习训练获得。

因此 R1 项目中并未提供参数文件、推理脚本与本地部署说明，因这些内容已收录于 DeepSeek-V3 项目，详见 3.1 节。

#### 3.2.3 DeepSeek-R1模型参数详解

通过 API 调用 R1 时，可灵活调整多项参数以控制生成长度、风格多样性与逻辑严谨性等输出特征。`chat.completions.create()` 接口的关键参数已作说明，R1 与 V3 共用该接口。

不过 R1 在参数解析与推理机制上存在部分特有特性与限制，实际调用时需注意以下要点。

##### 1. max_tokens参数

（1）`max_tokens` 控制最终回答部分即 `content` 字段的最大长度。默认值 4096 token，约 3000 汉字，上限 8192 token。

（2）该限制不计入思维链内容 `reasoning_content`。在复杂任务中，思维链可长达 32K token，因此总输出长度可能远超 `max_tokens` 设置。官方预计未来会上线 `reasoning_effort` 参数，用于调节 `reasoning_content` 的推理深度与长度。

##### 2. reasoning_content字段

（1）R1 的特点是除普通回答 `content` 外，还会返回推理过程字段 `reasoning_content`，与 `content` 平级。

（2）该字段记录模型得出结论的思考轨迹，适用于解释性任务、教学与评估场景。

##### 3. 功能支持情况

（1）已支持对话补全标准 Chat Completion 和对话前缀续写 Beta，可用于接续已有内容生成完整对话。

（2）目前暂不支持 Function Calling、JSON 格式输出、FIM Fill-in-the-Middle 补全 Beta 等功能，相关字段设置无效。

##### 4. 不生效的参数

`temperature`、`top_p`、`presence_penalty`、`frequency_penalty`、`logprobs`、`top_logprobs` 在调用 `deepseek-reasoner` 模型时不生效。为保持与 OpenAI 接口兼容，设置它们不会报错，仅被静默忽略。

图3.30 思维链的执行演化规律

在多轮对话中，R1 的思维链呈现清晰的阶段性演进。

（1）首轮对话多为独立推理，模型基于初始提问进行完整且自洽的思考。

（2）进入第二轮时，模型开始递进式推理，会引用前文问答对并自然衔接，体现较好承接性。

（3）第三轮及以后，模型转为综合性推理，整合多轮信息与多个变量，输出逻辑排序清晰的推理链条。随着对话深入，R1 不仅展现单轮分析能力，也体现上下文记忆、逻辑递进与归纳整合能力，具备类人类的思维连续性与对话一致性，适用于复杂交互场景。
