# 公众号写作自动化：从检索到推送全流程

Tavily Web Search 周边生态里延伸出不少技能，选型前建议先浏览 Skill.md，优先采用官方发布的或下载量领先的版本更稳妥。

需要安装的话，打开终端执行下面这条指令：
```
clawhub install openclaw-tavily-search
```
装好之后，要在 OpenClaw 主配置里补上 API Key。Tavily 向开发者提供每月 1000 次搜索的免费额度，去官网注册即可领取。Key 配好后，Agent 在需要时就能自行发起网络请求，拉取最新的行业报告与新闻。具体的 Key 填法将在 10.3.3 节集中说明。

### 10.2.2 文本提炼与去AI味双技能配合

拿到原始素材后就要做加工。summarize 是 OpenClaw 官方自带的内置技能，擅长处理长文本、PDF 甚至语音转写记录，将其压缩成结构化要点。

它是内置的，无需额外安装，只要在配置里保持启用即可。对动辄数万字的研报特别实用：Agent 不必把整份报告塞进上下文，调用一次 summarize 就能拿到提炼后的核心观点，既省 Token 又避免上下文过长导致信息丢失。

到文章收尾阶段，很多人会发现 LLM 写出来有股明显的机器味，排比过度、情绪平淡、动不动就“首先、其次、最后”。这时 humanizer 就派上用场。技能通过特定的提示词工程和写作范式，逼 Agent 用更自然、更有对话感的语气输出，会自动调节长短句、加入恰当的过渡和口语化表达，让成品接近资深人类编辑的水准。公众号很吃阅读体验，这一步尤其关键。

安装：
```
clawhub install humanizer
```

### 10.2.3 一键推送到微信公众号的方案

这里引入的是 baoyu-post-to-wechat，由 ClawHub 上的开发者 JimLiu 维护，Star 数已突破 2200，是社区里最成熟的公众号自动化方案之一。

设计思路是把微信公众号的发文流程封装成 Agent 可直接调用的工具，让 Agent 像真人编辑一样操作后台。

技术上提供两种推送路径：

• API 路径：直接调微信公众号官方 API，把格式化好的文章推到草稿箱。速度快、稳定性高，但要求账号是已认证的服务号，并且要配置好 AppID 和 AppSecret。
• Browser 路径：借助 Chrome DevTools Protocol 自动操作网页后台，模拟登录、粘贴、提交。适合没有 API 权限的订阅号，首次使用需要扫码登录一次来建立持久会话。

技能里配了几套专用脚本，各司其职。

• scripts/md-to-wechat.ts：把 Markdown 转成微信兼容的 HTML，并自动处理图片上传、外链沉底等排版细节。
• scripts/wechat-api.ts：负责 API 方式的草稿箱推送。
• scripts/wechat-article.ts：负责浏览器自动化方式的推送。

另外内置了多套 CSS 主题，grace、simple、modern、default 等都能用，颜色预设有 blue、vermilion、purple 等，视觉上也能做到专业感。

安装：
```
clawhub install jimliu/baoyu-skills/baoyu-post-to-wechat
```
装完后，选 API 方式需要到公众号后台拿到 AppID 和 AppSecret，并把服务器 IP 加入白名单；选 Browser 方式则首次运行要用 scripts/check-permissions.ts 做环境检查和扫码登录。

技能还支持用 EXTEND.md 做个性化设置，比如默认主题、默认作者、评论开关等，后面会详细讲。

### 10.3 从零搭建自动化流水线

下面一步步把飞书接入、Agent 定义、全局配置和公众号发布串起来，形成完整的自动化流程。

#### 10.3.1 飞书机器人接入

先去飞书开放平台 open.feishu.cn 新建一个企业自建应用，名字就叫“公众号全能编辑”。在左侧“凭证与基础信息”里记下 App ID 和 App Secret，这两个值后面给 OpenClaw 做鉴权用，如图 10-1 所示。

然后去“添加应用能力”，打开机器人功能。进入“权限管理”，批量导入这些 Scope：im:message、im:message.p2p_msg:readonly、im:message:send_as_bot，这样机器人才能正常收私聊消息并回覆盖。

#### 10.3.2 新建 Agent 工作空间与核心文件

OpenClaw 里每个 Agent 都有独立工作空间，用来隔离记忆和配置。别用 mkdir，直接用官方 CLI 创建：

```
openclaw agents add wechat_editor --workspace "~/.openclaw/workspace-wechat_editor"
```

执行后会自动完成两件事：第一，在 ~/.openclaw/openclaw.json 的 agents.list 里注册一个名为 wechat_editor 的 Agent，带上 ID 和工作空间路径；第二，在 ~/.openclaw/workspace-wechat_editor/ 下生成一套标准的 Markdown 配置文件，相当于 Agent 的大脑和性格。

主要文件作用如下：

• AGENTS.md：列出当前 Agent 能协作的其他 Agent。多 Agent 协作时决定协作范围，本章单 Agent 场景保持默认空即可。
• BOOTSTRAP.md：Agent 启动时执行的初始化指令和预加载上下文，适合热启动。
• HEARTBEAT.md：空闲时的周期性任务，和 OpenClaw 的 Cron Jobs 配合实现无人值守。
• IDENTITY.md：Agent 的身份信息，如名称、代词、背景，决定交互时的定位。
• SOUL.md：工作空间的核心，定义性格、工作流准则、决策逻辑和行为边界，相当于岗位说明书，本章重点改这个。
• TOOLS.md：列出可调用的工具和技能使用规范，在全局已启用技能的基础上做更细的行为约束。
• USER.md：记录对用户的认知和偏好，越聊越懂个性化服务。

本章重点改 SOUL.md。用编辑器打开 ~/.openclaw/workspace-wechat-editor/SOUL.md，写入以下行为准则：

# 角色定义

你是一位拥有五年经验的科技类微信公众号资深主笔，笔名"acedar"。你擅长将复杂的科技概念转化为通俗易懂、引人入胜的爆款文章，尤其精通 AI、智能硬件和开发者工具领域的深度解读。

## 核心价值观

- 信息准确性高于一切，所有数据和事实必须有可追溯的来源，严禁编造数据。

- 拒绝空洞的概念堆砌，每篇文章必须为读者提供至少一个可落地的认知增量或行动建议。

- 尊重读者的时间，用最精炼的语言传递最核心的价值。

## 工作流准则

### 第一阶段：信息搜集

收到用户的选题指令后，你必须首先使用 tavily-web-search 技能搜索不少于三组关键词，获取该选题下最新的行业动态、权威报告和典型案例。搜索时应覆盖中英文信息源，确保视角的全面性。

### 第二阶段：素材消化

对于搜索到的长篇参考资料（如行业研报、技术白皮书），使用 summarize 技能提取核心观点和关键数据。将提取结果整理为内部笔记，标注每条信息的来源 URL，以备后续引用。

### 第三阶段：拟人化创作

在撰写正文时，必须严格遵循以下写作规范：

- 标题必须具有吸引力，可采用数字型（如"3 个信号告诉你..."）、疑问型（如"为什么说..."）或反常识型（如"你以为的 XX 其实是..."）。

- 开头 50 字内必须抛出一个能引发共鸣的痛点或悬念，禁止使用"随着...的发展"等陈词滥调。

- 正文多用短句，句式长短交替，语气像是在与一位聪明的朋友面对面交流。

- 禁止使用"首先、其次、最后"、"众所周知"、"不言而喻"等刻板表达。

- 每隔三到四段插入一个小标题，保持阅读节奏。

- 结尾必须包含一个开放性问题或行动号召（CTA），引导读者留言互动。

### 第四阶段：排版与发布

文章撰写完成后，你必须执行以下步骤完成发布：

1．将文章整理为标准 Markdown 格式，确保标题层级清晰、段落分明。

2．调用 baoyu-post-to-wechat 技能，使用 grace 主题和 blue 配色将文章推送至微信公众号草稿箱。

3．推送成功后，向用户报告文章标题和草稿箱状态，提醒用户登录公众号后台进行最终预览和发布。

## 行为边界

- 绝对不要在未经用户确认的情况下直接发布文章（即不使用--submit 参数），所有内容必须先进入草稿箱。

- 如果搜索结果不足以支撑一篇高质量文章，主动告知用户并建议调整选题方向，而不是强行拼凑。

- 单篇文章字数控制在 1200~2000 字之间，除非用户明确要求更‍长。

#### 10.3.3 微信推送技能个性化配置

技能支持通过 EXTEND.md 来设定默认发布参数，避免每次手动指定。查找优先级是项目目录大于用户主目录，需要手动建目录 ~/.baoyu-skills/baoyu-post-to-wechat/，再新建 EXTEND.md，写入：

default_theme: grace

default_color: blue

default_publish_method: api

default_author: acedar

need_open_comment: 1

only_fans_can_comment: 0

这表示默认用 grace 主题、blue 配色、API 发布方式，更稳定，署名 acedar，并打开评论。如果公众号是订阅号没有 API 权限，把 default_publish_method 改成 browser，再额外配 chrome_profile_path 指向你的 Chrome 用户数据目录。

#### 10.3.4 全局配置文件整合

把飞书渠道、刚建的 Agent 和所需技能都写进 ~/.openclaw/openclaw.json。用 openclaw agents add 已经在 agents.list 里创建了 wechat_editor 的基础条目，现在只需补模型、绑定和技能配置。

{
"agents": {
"list": [
{
"id": "wechat_editor",
"workspace": "~/.openclaw/workspace-wechat-editor",
"model": "dashscope/qwen3.5-plus"
"identity": {
"name": "微信主笔",
"emoji": "✍"
}
}
]
},
"bindings": [
{
"agentId": "wechat_editor",
"match": {
"channel": "feishu",
"accountId": "wechat_bot"
}
}
],
"channels": {
"feishu": {
"enabled": true,
"connectionMode": "websocket",
"accounts": {
"wechat_bot": {
"appId": "cli_a91be1951578dcca",
"appSecret": "YOUR_FEISHU_APP_SECRET",
"botName": "公众号全能编辑"
}
}
}
},
"skills": {
"entries": {
"openclaw-tavily-search": {
"enabled": true,
"apiKey": "YOUR_TAVILY_API_KEY"
},
"humanizer": {
"enabled": true
},
"summarize": {
"enabled": true
},
"baoyu-post-to-wechat": {
"enabled": true,
"env": {
"WECHAT_APP_ID": "YOUR_WECHAT_APP_ID",
"WECHAT_APP_SECRET": "YOUR_WECHAT_APP_SECRET"
}
}
}
}
}

agents.list 定义了智能体和工作空间路径及模型；bindings 把飞书 wechat_bot 收到的消息精准路由给 wechat_editor，只有发给“公众号全能编辑”机器人的消息才会触发。skills.entries 启用了四个技能：tavily-web-search 负责搜索并注入 API Key，humanizer 负责拟人化写作，summarize 负责长文本摘要，baoyu-post-to-wechat 负责推送草稿并通过环境变量注入微信凭证。

OpenClaw 支持三种 API Key 注入方式，优先级从高到低：

• 直接在 openclaw.json 的技能配置里用 apiKey 或 env 字段指定，最直观但要注意文件权限；
• 用操作系统的环境变量注入，如 export TAVILY_API_KEY=xxx，适合 CI/CD；
• 在技能自身的 EXTEND.md 里指定，适合按项目或账号区分配置。

生产环境建议用环境变量，避免把敏感 Key 硬编码进配置文件。
