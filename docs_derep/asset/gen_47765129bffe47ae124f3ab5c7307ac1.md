### 3.5.5 拆分组件时的心态管理

决策疲劳 Decision Fatigue 是一个心理学概念，指连续做决策会导致决策效率和准确性下降，甚至出现误判。

开发 React 应用时，要把设计稿转化为界面，需要不断决定拆分粒度、复杂度、可维护性、可测试性等权衡。这种持续的取舍容易产生决策疲劳，让开发者对后期的拆分产生怀疑，甚至否定前期决策，从而增加心理负担。

减轻决策疲劳可以尝试以下做法。

- 不必追求一步到位，拆分可以在实现过程中逐步优化。
- 不必追求绝对完美，后续可以根据实际需求随时调整结构。
- 拆分时保持专注，暂时屏蔽后端接口设计等无关维度，减少决策变量。
- 日常积累拆分经验，有助于提升后续项目的效率。

## 3.6 AI 辅助：让 AI 参与组件树设计

设计和拆分组件就像庖丁解牛，经验多了会越来越顺手。但在 React 学习初期，很多开发者会犹豫不决，不知道怎么划分组件，这时 AI 可以充当导师角色。

### 3.6.1 用 AI 指导拆分

在启动新项目或为现有项目增加新模块时，如果对组件设计感到困惑，可以向 AI 寻求指导。下面仅用文字描述 UI 需求，而不依赖原型图。

打开 Copilot 界面，把聊天模式切到“询问 Ask”，模型选择 o3-mini，输入以下提示：

> 我需要实现一个网页端聊天应用的 UI，UI 设计如下：
> 
> * 这个 UI 整体是横向三栏式的。它包括两种视图：聊天视图和联系人视图。UI 的左栏是纵向导航栏，包含分别指向两种视图的链接。中栏和右栏会随视图动态改变。
> 
> * 当 UI 处于聊天视图时，中栏从上到下显示搜索框、聊天列表，用户可以选中列表中的其中一个聊天，右栏从上到下显示选中聊天的联系人名称、消息列表和发送消息文本框。
> 
> * 当 UI 处于联系人视图时，则中栏从上到下显示搜索框、联系人列表，用户可以选中列表中的其中一个联系人，右栏显示当前选中的联系人的详细信息（包括联系人名称等信息）。
> 
> 请根据上述 UI 需求，帮我设计 React 组件层次结构，组件名称为英文，根组件为 `App`。输出结果采用 Markdown 格式。例如：
> 
> * `App`
>   * `Form`
>     * `TextInput`
>     * `Button`

“询问”模式下的 Copilot 类似通用 LLM 聊天机器人，但更专注软件开发问题。选择 o3-mini 是因为它在深度思考和推理任务上表现更好。各家 IDE 会接入多种模型，开发者可按需切换。

提示词的妙处在于在 UI 描述后明确任务：设计 React 组件层次结构，并指定输出格式和示例。这种单样本提示 One-shot Prompting 能引导模型给出更准确的答案。提示工程还包括零样本、少样本、思维链等技术，感兴趣可进一步查阅。
