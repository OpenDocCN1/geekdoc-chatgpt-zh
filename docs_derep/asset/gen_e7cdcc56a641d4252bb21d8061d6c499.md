# 记忆即基础设施：Agent 心智的演进路径

[PRE0]

Agent 现在已经拥有了元认知能力——它清楚自己的记忆容量受限，并会主动进行管理。记忆技术正从 SDK 层级向上迁移，先是工具包、随后是框架，再从云服务抽象上升为平台级能力。MaaS，即记忆即服务，有望成为跨 Agent、跨应用的云端记忆底座。它把用户画像、长期偏好、行为轨迹、任务履历和意图模型打包成可调用的服务，让不同 Agent 共用同一套认知底座。也可以称之为云原生记忆。

这种机制让系统获得了时间旅行的能力，成为企业级风控与调试的根基。在执行转账、代码部署等敏感动作前，人可以把系统挂起，直接改写内存里的状态，再决定是否放行。没有持久化的状态管理，人工介入就无从谈起。

### 3. 协议化治理：MCP 作为“USB-C 标准”

工具和记忆源激增后，点对点 API 集成已经难以为继。Anthropic 等推动的 MCP 正在成为 Agent 互联的 USB-C 等价物。它采用 Client-Host-Server 拓扑，把记忆与工具统一抽象为可发现的资源。

> 此处有两个关键概念：时间旅行，指系统能回到任意历史状态；人类介入，指关键决策必须经人类确认。前者提供可追溯，后者提供可控，两者结合才让企业敢于放手使用 Agent。

无论后端是本地文件、Notion 还是 PostgreSQL，Agent 都能通过统一的 read_resource 语义访问，模型与存储后端被彻底解耦。这为异构 Agent 生态的互操作提供了保障。比如基于 OpenAI 模型的 Agent 可以直接读取由 Claude 构建的 Agent 留下的记忆资源，无需重写接口。

工程实践上，记忆层正从业务逻辑中剥离，下沉为独立的基础设施。

第一代记忆是无状态的瞬时记忆，每次对话被当成全新会话，如 GPT-3 的 API。

第二代记忆是滑动窗口，仅保留最近 N 轮对话，旧内容被丢弃。实现简单，却“健忘”。

第三代记忆是分层记忆，也是当前的主流做法。热数据保留在上下文中，冷数据沉到 VectorDB。下面是典型案例。

- ChatGPT Memory：用户说“记住我讨厌香菜”，系统写入核心记忆，是最简单的 Key-Value 形式。
- Claude Projects：允许上传大量文档作为项目知识，是上下文缓存的典型，通过预加载静态知识降低延迟。
- MemGPT：学术界先驱，借助类操作系统的内存管理，让窗口受限的模型表现出接近无限上下文的能力。

第四代记忆将是神经符号记忆：向量检索提供模糊匹配，知识图谱提供精确关系，逼近人类的联想记忆。

这一演进与二十年前数据库从单体应用中解耦如出一辙，标志着 Agent 系统趋于成熟。

### 5.1.4 分层记忆模式的演化与组合

分层记忆从滑动窗口起步，经摘要压缩，发展到类操作系统的虚拟内存管理。架构师的诉求不变：在上下文窗口这一物理限制下，模拟近乎无限的记忆体验。

### 1. 演化路径：从金鱼到操作系统

- 滑动窗口：记忆的原始阶段，采用 FIFO 只保留最近 N 轮。痛点是金鱼效应，长对话中早期关键信息如用户画像、System Prompt 约束会被彻底丢失。
- 摘要增强：在丢弃旧对话前用 LLM 生成摘要留在上下文头部。缓解遗忘，但有信息损耗，反复再摘要会让细节逐渐失真。
- 虚拟上下文：借鉴操作系统分级存储与换页。L1 缓存即模型的上下文窗口，放高频访问的热数据；L2 缓存由向量数据库实现，持久化低频的冷数据。Agent 可通过系统调用自主决定何时写、何时读，实现更灵活的控制。

### 2. 模式组合示例

分层记忆是存储底座，需与感知、反思、协作模块闭环。

- 分层记忆与注意力聚焦模式的组合 = 精准召回：分层记忆保证高召回不遗漏，注意力聚焦保证高精度。适用于海量历史查询。
  - 分层记忆解决“存在哪”的问题，提供海量候选数据即 L3 缓存。
  - 从 L3 检索出 100 条记录直接注入会超窗且引入噪声。
  - 注意力聚焦模块对候选评分压缩，提炼精华注入工作记忆 L1。
- 分层记忆与反思记忆模式的组合 = 经验结晶。
  - 反思模块在任务失败后生成教训。
  - 教训经巩固写入分层记忆的长期区 L3。
  - 新任务启动时自动检索相关教训加载至 L1 指导决策。
- 分层记忆与群体模式的组合 = 集体潜意识。
  - 单个 Agent 只有短暂 L1。
  - 所有 Agent 共享同一个 L3。
  - Agent A 把解法写入 L3，Agent B 遇到相似问题可直接复用。

分层记忆的成熟，让 Agent 从无状态函数变为有历史的实体。操作系统级的内存管理不仅突破了上下文物理限制，也为终身学习提供了存储基础。

### 5.1.5 设计哲学：对抗遗忘

传统数据库视遗忘为故障，Agent 设计里遗忘是特征，甚至是智能的必要条件。

博尔赫斯在《博闻强记的富内斯》里描写了一个无法遗忘的人，他记得每片树叶的每一次摆动，却丧失思考能力，因为“思考就是忘却差异，进行概括”。

若 Agent 试图把全部历史塞入上下文，会陷入注意力沼泽，噪声淹没信号，推理迟钝。

分层记忆的本质不是记住更多，而是高效遗忘。无关细节沉到冷存储，关键活跃信息留在意识表层的热存储。由热转冷、由表及里，正是数字心智的新陈代谢。

## 5.2 RAG 模式

> “最强大的 AI 不是知道一切，而是知道如何找到一切。知识不再是静态的库存，而是动态的流。”

——RAG 论文①

传统 LLM 如同闭卷考试的天才，参数记忆惊人，却会在冷门或新近知识上胡编。

RAG 像是开卷考试，遇到不懂的问题可翻阅参考书检索相关段落，再结合自身理解作答。

RAG 核心在于动态检索外部知识库，将相关信息实时注入上下文，无需重训即可解决知识老化、长尾缺失与幻觉。

### 5.2.1 模式架构：检索与生成的交响

RAG 是检索器与生成器的非对称组合。

- 检索器：系统海马体，负责高通量低延迟召回，常基于 Bi-Encoder 如 BERT，以牺牲深度理解换取速度。
- 生成器：系统前额叶，负责推理与语言组织，基于 Decoder 如 GPT，算力需求高但推理强。

## 5.2.2 RAG核心机制

RAG 涉及索引、检索、重排序与生成。

1. 索引：把世界切片
模型只能处理片段。好切片按语义切，确保一个 Chunk 承载完整知识点。
Anthropic 提出的上下文检索指出，单独 Chunk 易失上下文，如仅剩“它上涨了”。解决办法是索引时用模型为每个 Chunk 生成约 50 字的上下文说明拼接到头部再向量化。

2. 检索：大海捞针
向量检索擅长模糊语义，不擅长精确匹配如产品型号“iPhone 15 Pro Max”。混合检索更精确：向量检索找语义相关，关键词检索找精确匹配。

3. 重排序：选择最佳
Cross-Encoder 将查询与文档拼接入 BERT 输出 0-1 相关分数。比双塔慢但能捕捉细粒度交互。常用做法是向量粗筛 Top 100，再用 Cross-Encoder 精排至 Top 5。

4. 生成：基于资料作答
检索结果注入 Prompt，Prompt 成为融合上下文与针对性知识的载体。

## 5.2.3 RAG工程实践

RAG 落地极为普遍，几乎每个企业都会搭建企业级知识库。

- Perplexity.ai 展示了进阶形态，将 RAG 从搜答管道升级为理解-多步搜索-阅读-综合，并通过来源引用缓解幻觉焦虑。
- Glean 是企业级代表，解决了落地痛点权限控制，在检索层严格执行数据权限过滤，保证安全。
