**5.2.5 RAG**
第三章已详细阐述 RAG（检索增强生成），它通过向量相似检索来丰富模型的输出，在 AI 开发中应用广泛。RAG 主要包含三步： [PRE9]
文本切分（Text Splitting）：把原始文档如 PDF、网页、Markdown、Word 或代码等拆成语义较小的片段，便于向量化与后续检索。 [PRE10]
向量化与存储（Embedding + Vector Storage）：将每个片段转成向量，存入向量数据库以备检索。 [PRE11]
向量相似检索（Vector Similarity Search）：用户提问时，按语义相似度从库中找出最相关片段，供给大模型生成答案。

第三章已手写实现完整 RAG 流程，覆盖切分、向量化存储、相似匹配三阶段。但手动实现较为繁琐，对底层理解要求也较高。

借助 LangChain 的模块化，围绕文档切分、嵌入、检索三大环节已提供现成工具链，开发者无需从零搭建，只需调用高阶 API 即可快速搭建可用 RAG 系统。

**5.2.7 SQL 联动**
即便是基础 Agent，通常也基于 ReAct（Reason+Action）架构拆解任务。想要 Action 更精准，就需要强化 Reasoning 环节。除用户提问和 RAG 知识库外，业务数据库是另一类常见数据源。该方案让模型先理解表结构并生成 SQL，由工具链执行后回传结果，从而增强模型能力。整体流程见图 5-16。

该流程大致包含六步：
（1）用户以自然语言提出问题。
（2）模型读取数据库表结构，为生成 SQL 做准备。
（3）模型结合表结构把自然语言转成 SQL，交给工具链执行，避免模型直接操作数据库。
（4）工具链连接数据库并执行 SQL，返回结果集。
（5）工具链把结果集传回模型。
（6）模型基于查询结果做后续推理并回复用户。
