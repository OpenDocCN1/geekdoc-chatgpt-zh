### 6.1 微调入门：概念、方法与环境

本节介绍大模型微调的核心概念、常见方法，以及合理的软硬件环境搭建思路，帮助读者在实际开发中匹配合适的算力与工具，兼顾性能与资源利用。

#### 6.1.1 微调的三大驱动力

在预训练大模型层出不穷的背景下，这些模型通过海量无标注数据学习通用语言规律，具备较强的理解与生成能力。但通用性强也意味着缺乏针对性，需通过微调适配具体任务。

##### 1. 让模型在细分任务上更准
通用模型在文本生成上表现不错，但在情感分析、医学问答等具体任务上可能不够准确。微调借助任务相关数据，让模型学习特定模式，显著提升细分任务表现。

##### 2. 注入专业领域知识
不同领域知识结构各异，通用模型难以掌握。法律文本严谨、金融涉及公式、医学包含化学表达等，通过微调注入领域数据，可提升专业问答能力。

##### 3. 省算力省成本
全量训练成本极高，例如 GPT-3 拥有 1750 亿参数，需数千张 A100 分布式训练。微调在预训练模型基础上做少量调整，大幅减少计算资源与时间。

#### 6.1.2 核心概念拆解

##### 1. 什么是微调
在已有预训练大模型基础上，利用标注数据训练，使模型参数发生变化以适应特定任务或场景。与 RAG、Agent 等工作流优化不同，微调是通过改变模型参数实现“永久性”能力增强。

##### 2. 全量 vs 高效
微调可分为全量微调和高效微调。全量微调更新全部参数，改造彻底但算力消耗大；高效微调只更新部分参数，是“四两拨千斤”的做法。

##### 4. LoRA 与 QLoRA 对比
全量微调改造深度大但门槛高，多数场景更倾向高效微调。

1) LoRA
LoRA 通过引入低秩适配矩阵，减少可训练参数数量，降低显存与计算需求。仅训练插入的适配层，保留原始参数不变，适合显存受限设备。

2) QLoRA
QLoRA 在 LoRA 基础上加入量化，将权重压缩至 INT4/INT8，进一步降低存储与计算需求，在极端显存受限或需快速推理场景下优势明显。

表6.1 LoRA与QLoRA特性对照表

| 特性 | LoRA | QLoRA |
| :--- | :--- | :--- |
| 核心技术 | 低秩适配器（low-rank adapters） | 低秩适配器+量化技术（low-rank adapters + quantization） |
| 适用场景 | 显存受限，但设备性能较好 | 极限显存受限或需要快速推理的设备 |
| 计算效率 | 提高计算效率，减少调整的参数数量 | 进一步提升效率，减少内存使用并加快推理速度 |
| 量化技术 | 无量化 | 将权重量化为低精度（如 INT4 或 INT8） |
| 内存消耗 | 较低，但不如 QLoRA 低 | 显著降低内存消耗，适合更小的设备 |
| 训练复杂度 | 较简单，适用于大多数微调场景 | 需要更多的量化和适配工作，但适合超大模型和设备受限场景 |

#### 6.1.3 高效微调能用在哪些地方

##### 1. 调整对话风格
可针对客服、虚拟助手等场景微调语气、礼貌度、回答风格，使模型输出更符合品牌调性。

##### 2. 知识灌注
将外部或领域专有知识快速注入预训练模型，无需从零训练。例如法律、医疗领域，用少量标注数据提升术语与规则理解。

##### 3. 推理能力提升
通过微调增强长文本理解、隐含信息推理与逻辑提取，提升多轮复杂推理任务的准确率。

##### 4. Agent 能力提升
在多任务协作与功能调用场景，微调可让模型更精准解析指令、调用 API、传递参数，提升自动化服务与智能助手的执行效果。
