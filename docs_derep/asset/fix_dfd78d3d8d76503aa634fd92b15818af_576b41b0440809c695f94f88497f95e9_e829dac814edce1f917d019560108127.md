网络侧可调项：主要关乎相邻层之间的融合逻辑，比如加法、乘法、拼接等操作，同时涵盖卷积核的个数与尺寸、整体模型的深度，以及激活函数的选择。

优化侧可调项：通常指学习速率、单次迭代的样本规模、不同优化器的内部设定，以及损失函数中允许手动干预的系数。

正则化侧可调项：聚焦于权重衰减的强度和 Dropout 的丢弃比例。

### 13.1.3 调参的底层矛盾
本质上是模型拟合能力与正则约束之间的博弈。优化的诉求是逼近全局最优或更靠谱的局部最优，而正则希望模型在拟合的同时保持简洁。两者常出现冲突，但目标一致，都是压低期望风险。优化侧重经验风险的最小化，容易过拟合；正则侧重限制模型复杂度。怎样在两者之间做权衡，拿到最优或次优解，就是超参数调节要解决的核心问题。

### 13.1.4 谁更值得优先调
按实战经验排优先级，第一梯队是学习速率和损失函数里可调的系数；第二梯队是小批量规模和动量优化器的动量系数 β；第三梯队是 Adam 的内部参数、权重衰减因子、Dropout 比例以及网络结构本身。下面展开说明。

（1）学习速率与损失函数可调项
在网络、优化、正则三类可调项里，学习速率的影响最直接，它决定了参数更新的步幅，进而影响模型的实际表达上限。

损失函数里的可调系数需结合具体函数来定，多半也能明显改变有效容量。常见可以归为三类。
第1类是辅助损失，用来强化特征表达。例如度量学习里的 Center Loss，通常和交叉熵以一定权重并用。经验上建议辅助损失的量级不要与交叉熵相差超过两个数量级。
第2类是多任务模型的若干损失，各自服务不同任务，彼此独立或有关联，效果取决于任务间的相关性。
第3类是独立型损失，在特定任务上效果突出。如 RetinaNet 的 Focal Loss，其中的 γ、α 对最终结果影响很大，这类参数论文里一般会给出建议值。

（2）小批量规模与动量系数 β
Batch Size 影响梯度下降的方向。过小时方向波动大，极端到 Batch Size=1 时，每个样本都改一次方向，样本差异越大越难收敛。若使用批归一化，样本过少统计不稳甚至失效，因为样本越少统计代表性越差、噪声越大。过大时梯度方向过于平滑，容易卡在局部最优，精度受损。实践常用区间是 [1, 1024]，具体要看硬件和数据。

动量系数 β 用来做梯度指数加权平均，也可用于参数更新，取 0.9 是常见且稳定的做法。

（3）Adam 超参、权重衰减、Dropout 比例和模型深度
放在后边不代表不重要，而是实践中不建议频繁大范围尝试。

- (a) Adam 里的 β1、β2、ε 常设为 0.9、0.999、10⁻⁸，表现通常不错。
- (b) 权重衰减一般有推荐值，如 0.0005，建议直接采用，无需过度搜索。
- (c) Dropout 多用于全连接层防过拟合，建议控制在 [0.2, 0.5]。需注意两点：第一，在 RNN 中不要把 Dropout 直接放在记忆单元，会放大噪声扰乱学习，建议放在输入和输出；第二，不要让 Dropout 紧跟批归一化，会干扰统计量计算，导致推理时方差偏移，极端情况下模型会崩。
- (d) 网络深度本身也是超参。通常加深能提升容限，但真实有效容限还受样本量与质量、层间关系影响。因此一般先固定深度，调优到一定阶段或算力充足后再考虑加深。

## 13.2 训练阶段的调参策略

### 13.2.1 寻优的标准流程
超参数优化通常按下面流程进行。
- （1）选择一组超参数，可自动选择。
- （2）构建相应的模型。
- （3）将模型在训练数据上拟合，并衡量其在验证数据上的最终性能。
- （4）选择要尝试的下一组超参数，可自动选择。
- （5）重复上述过程。
- （6）最后，衡量模型在测试数据上的性能。
核心在于如何利用验证集的历史表现来挑选下一组待评估的超参数。

### 13.2.2 调试模型的四个着力点
谈到调试容易想到各种优秀模型和技巧，但数据才是根本。数据质量或数据处理水平带来的收益往往大于模型挑选。必须在数据质量过关的前提下再谈设计与训练技巧。

- （1）探索与清洗数据集。数据探索是建模前最重要的环节。以图像分类为例，需要了解类别是否平衡、各类别样本量是否充足，是否存在跨域问题，如网图质量参差、噪声多。若类别远多于单类样本，如 1 万类每类 10 张，常规方法效果有限，可考虑小样本学习做增强。目标检测中目标尺度范围直接影响性能，要明确关注大目标还是小目标、是否密集，这完全取决于数据集本身。因此数据探索与清洗是深度学习里最易被忽略却最关键的一步。
- （2）分析模型结果。对验证集性能做细化剖析有助于进一步提升。将训练集与验证集结果都做校验和可视化，能直观判断是否存在较大偏差。以分类为例，若类别不平衡，要重点看小样本类别在两集上的表现差异，对错例做数值分析和可视化，确认模型行为。
- （3）监控训练与验证误差。代码规范性和正确性验证常被忽略，易致命。若训练验证都异常，先确认代码是否正确；再根据误差曲线追踪拟合状态。训练集很小时，监控误差尤为重要，这会让学习率策略或其他超参的选择更从容。
- （4）反向传播数值校验。多用于自研算子。虽然主流框架已内置自动求导，但未必完全符合需求。可通过对比自动求导结果与有限差分结果的一致性来验证正确性。

### 13.2.3 为何学习速率要动态变化
学习速率是训练中最核心的超参数。合适的学习速率既能加速收敛，也能获得更优精度。过大或过小都会影响收敛。当训练到一定阶段，损失不再下降，一阶梯度接近 0 时，Hessian 矩阵有两种可能。

（1）正定，所有特征值均为正，此时接近局部极小。若该点接近全局最优，性能已不错；若差距大，则仍有提升空间，这在训练初期常见。
（2）特征值正负混杂，可能陷入鞍点，此时模型表现较差。
训练初期与中期出现上述情况，若仍用固定学习速率，容易左右震荡或停留在鞍点。衰减或适当增大学习速率可帮助减少震荡或跳出鞍点。

### 13.2.5 极端批量下的训练注意
极端批大小指 Batch Size 为1 或大于6000 的情况。用得不当会导致性能不达最优甚至崩溃。

在目标检测、分割或三维图像等输入尺寸大的场景，Batch Size 通常很小，这会让梯度不稳定，批归一化的统计也不准确。
