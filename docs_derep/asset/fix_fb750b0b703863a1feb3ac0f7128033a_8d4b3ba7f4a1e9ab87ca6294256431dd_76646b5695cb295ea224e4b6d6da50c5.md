# TorchScript 追踪会固化分支，脚本化才保留控制流

刚接触 TorchScript 的人常有一种错觉：跑一次 trace 就能把整个模型封存。真实情况是 trace 更像一次运行的记录，它只保存喂入的那组输入实际走过的路径。一旦模型里出现条件、循环这类动态逻辑，未被执行的分支就会直接消失。

import __torch__

import __torch__.torch.nn.modules.linear

def forward(self,

            input: Tensor,

            h: Tensor) -> Tensor:

    _0 = self.linear

    weight = _0.weight

    bias = _0.bias

    _1 = torch.addmm(bias, input, torch.t(weight), beta=1, alpha=1)

    return torch.tanh(torch.add(_1, h, alpha=1))

这一步还很直观，没有分支。接下来引入一个会根据张量总和符号来取正或取反的门控结构，这就是典型的控制流情形。

把门控嵌入到一个带线性变换的细胞里，形成完整的计算单元。

[PRE2]
>>class MyCell(torch.nn.Module):

    def __init__(self, dg):

        super(MyCell, self).__init__()

        self.dg = dg

        self.linear = torch.nn.Linear(4, 4)

    def forward(self, x, h):

        new_h = torch.tanh(self.dg(self.linear(x)) + h)

        return new_h

import __torch__.___torch_mangle_0

import __torch__

import __torch__.torch.nn.modules.linear.___torch_mangle_1

def forward(self,

    input: Tensor,

    h: Tensor) -> Tensor:

  _0 = self.linear

  weight = _0.weight

  bias = _0.bias

  x = torch.addmm(bias, input, torch.t(weight), beta=1, alpha=1)

  _1 = torch.tanh(torch.add(torch.neg(x), h, alpha=1))

  return _1

可以看到，条件判断被完全抹平了。当前示例让总和不为正，记录里只剩下取反这条路。若换一个让总和为正的输入再追踪，得到的结果又会不同。这正是 trace 的局限：分支被写死在那一次运行的路径上。

要得到真正的可运行分支，需要改用脚本化。

  _1 = _0.weight

    if torch.__isnot__(_2, None):

      bias0 = ops.prim.unchecked_unwrap_optional(_2)

      output0 = torch.add_(output, bias0, alpha=1)

    else:

    ret = output0

脚本化后，基于总和正负的判断被保留下来，运行时两种情况都能正确执行。

        x = F.relu(self.linear1(x))

        x = self.dropout(x)

        x = self.linear2(x)

        return x
