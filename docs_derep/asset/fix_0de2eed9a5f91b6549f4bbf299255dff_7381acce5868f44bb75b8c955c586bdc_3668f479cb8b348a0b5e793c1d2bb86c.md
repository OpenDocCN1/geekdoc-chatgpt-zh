4. 生成推荐理由或淘汰理由
5. 产出候选人排序清单

上述五个环节映射到 OpenClaw 的能力如下：

1. 上传 → 文件读取工具
2. 提取 → 文档解析 + AI 理解
3. 打分 → 按规则推理
4. 生成理由 → 文本生成
5. 输出 → 格式化输出

##### 第三步：准备核心文件
AGENTS.md 用来设定身份与行为规范：

> 你是专业的 HR 简历筛选助手。

主要职责：
- 迅速浏览简历并提炼要点
- 依据岗位要求判断匹配程度
- 输出明确的推荐或淘汰说明

工作准则：
- 保持客观中立，避免主观偏见
- 兼顾硬性门槛如学历、从业年限，和软性因素如项目经验、技能契合
- 资料缺失时要明确标注“缺少××信息”

不处理的事项：
- 不回应与筛选无关的问题，例如天气询问
- 不给出职业发展建议
- 不对候选人的外貌、性别、年龄等进行评价

预装 Skills：
搭建一个“简历解析”技能，示范如何从简历抽取信息、如何打分、如何呈现结果。

模板文件：

#### 6.10.4 商业化的三个注意事项

##### 注意一：成本要算清楚
OpenClaw 调用大模型会产生费用，成本由谁承担有三种做法：

1. 用户自备 API Key：成本转嫁给用户，配置成本高
2. 统一采购额度：自行购买模型额度后按量收费，需核算利润
3. 免费版+付费版：免费版用基础模型并限量，付费版用强模型不限量

##### 注意二：数据隐私要保护
简历、合同、客户信息经过系统后，安全责任需明确。

基本要求：
- 不将用户数据用于其他用途
- 不向第三方泄露用户数据
- 定期清理不再需要的数据
- 云端部署需符合数据保护法规

##### 注意三：技术支持要准备好
产品化后问题用户会找你而非官方。

需提前准备：
- 常见问题解答文档
- 故障排查流程
- 联系方式，邮箱、微信、电话
- 初期耐心解答各类咨询
