# 第 3 章

## LangChain 基础

本章先从整体架构、核心库和扩展模块切入，随后讲解如何调试、实现回退以及使用回调机制，最后谈到 LangChain 应用在隐私方面的注意事项。

### 3.1 认识 LangChain

本节将拆解 LangChain 的整体构成、底层库组合以及可扩展模块。

#### 3.1.1 LangChain 的架构

LangChain 0.1 体系大致由四块组成。

- LangChain 的库：同时适配 Python 与 JavaScript，提供大量组件接口与集成、一个基础运行环境来拼接链和代理，并附带开箱即用的链/代理实现。

- LangChain 的模板：针对不同任务的一套可直接部署的参考方案集合。

- LangServe：把 LangChain 链封装成 REST API 的部署工具。

- LangSmith：面向开发者的平台，支持对任一 LLM 框架构建的链进行调试、测试、评估与监控。

#### 3.1.2 LangChain 的库

核心库拆分为三类包。

- langchain-core 包：提供底层抽象以及 LangChain 表达式语言 LCEL。

- langchain-community 包：负责对接第三方应用与库。

- langchain 包：收纳构建应用所需的链、代理和检索策略。

#### 3.1.3 LangChain 的模块

LangChain 围绕外部集成提供了若干可扩展模块。

##### 1. Model I/O 模块

模型是 LLM 应用的中心，Model I/O 模块专门负责模型的调用、输入管理与输出格式化。

该模块包含三大要素。

- 语言模型（Language Model）模块：通过统一接口调用各类大语言模型。

- 指令（Prompt）：负责编排模型的输入。

- 输出解析器（Output Parser）：对模型返回内容进行抽取与结构化解析。

##### 2. 检索模块

检索模块帮助应用接入外部知识，主要涵盖私域知识库的向量存储 Vector Store、文档加载 Document Loader、文档转换 Transformer 以及向量检索 Retriever。

##### 3. 内存模块

内存模块承担对话历史的保存与读取。

##### 4. 链模块

链模块负责编排调用顺序，将 Model I/O、内存、检索等模块串联起来，实现多轮对话或推理流程的串行执行。

##### 5. 代理模块

代理模块在链的基础上接入工具，实现 LLM 与本地/云端服务能力的融合，增强整体功能。

##### 6. 回调模块

回调模块负责记录链的中间执行过程并可流式输出，常用于日志、追踪等场景。

### 3.2 LangChain 的调试

搭建 LLM 应用过程中出现问题在所难免，调试工具能帮助快速定位与修复。核心价值包括。

- 精准找到问题根源并迅速给出解决思路。

- 在复杂的嵌套模型调用中，快速锁定报错的具体位置。

- 深入分析模型运行时的性能表现与行为特征，以优化系统。

- 检视模型输出是否符合预期，从而提升应用质量。

- 获取调用失败的详细原因，为后续修复提供依据。

#### 3.2.1 跟踪工具 LangSmith

LangSmith 专为生产级 LLM 应用打造，具备调试、测试、评估和监控能力，可应对基于各种 LLM 框架构建的链和智能代理。

> 提示 LangSmith 与 LangChain 无缝衔接，进一步提升工作效率。

### 3.3 LangChain 的回退

使用 LLM 时，底层 API 经常会出现速率限制或宕机等各类问题。在将应用推向生产环境时，容错与安全变得尤为重要。因此 LangChain 引入了“回退”概念。

回退是一种有效的容错策略，旨在 API 调用失败或性能下降时，LLM 应用仍能保持正常运行。通过回退，可在调用失败时自动切换到预设的备用 API 或降级方案，保证稳定性和可用性。

> 提示 回退策略的应用范围广泛，不仅适用于 LLM 级别，也适用于整体可运行级别。因为各类 LLM 通常需要特定的指令，因此在制定和实施回退策略时，必须充分考虑和适应不同模型的需求。例如，在调用 OpenAI 失败时，不能简单地改为向 Anthropic 发送相同的指令，而应该考虑使用不同的指令模板，并且针对这些模板发送不同版本的文本。
