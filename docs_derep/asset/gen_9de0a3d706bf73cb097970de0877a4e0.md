到目前为止，“音乐下载”模块的性能测试已经完整走通了从设计到落地的全链路，LLM 在每一步都提供了实质性支持。尽管该用例整体并不复杂，底层仍是标准的 HTTP 调用，但如果选用 JMeter 来实现，就很难优雅地表达并发场景下随机拉取不同文件的需求，这恰好凸显出借助 LLM 生成 Locust 或 Grinder 脚本的独特优势。LLM 在 Python、Java、YAML 等语言上的生成能力较为成熟，相比撰写 JMeter 脚本，产出 Locust 或 Grinder 脚本对它而言更易上手，结果的准确度也更高。

本节的梳理让我们更深刻体会到 LLM 在推动性能测试从规划到执行的巨大潜力。随着模型持续演进并与 AI 智能体技术结合，未来在软件性能测试领域将实现更全面、更深度的辅助，共同期待 LLM 深度赋能测试的时代到来。

## **6.7 本章小结**

本章系统研究了 LLM 在非功能测试方向的实践价值，覆盖了性能压测、安全漏洞检测、安全策略建议、用户体验评估等多个维度。借助具体案例，展示了 LLM 如何参与发现性能瓶颈、识别安全缺陷、生成安全策略、优化体验，以及贯穿性能测试设计到实施的端到端工作。

在性能结果分析环节，LLM 表现较为出色。它可以对 JMeter 等自动化工具采集的数据进行深入解读，定位问题并给出优化思路。例如在某在线商城项目中，模型准确捕捉到并发场景下异常率抬升的现象，并引导通过代码修改消除数据不一致，从而显著提升系统表现。

在性能瓶颈定位上，LLM 的效果相对有限，但仍能在一定程度上提高排查效率。未来随着技术进步以及与计算机视觉的融合，其在瓶颈识别方面的助力空间会进一步放大。

安全漏洞检测方面，LLM 同样表现良好。通过阅读源代码，它能够发现 SQL 注入等典型漏洞并给出修复建议。如在在线商城案例中，模型建议调整 SQL 写法并强化输入校验，成功修复了注入问题，提升了系统安全性。

在安全策略智能推荐上，LLM 展现出明显优势。它能够依据具体业务场景和安全诉求，生成并优化策略。无论是金融机构的网银系统，还是医疗机构的患者信息处理，均可得到符合行业规范的建议，帮助企业筑牢安全防线。

用户体验测试层面，LLM 通过解析用户行为数据，可以识别影响体验的关键因素，例如页面加载时长，并提出针对性改进建议。该能力对提升产品满意度和市场竞争力具有重要意义。

最后，在性能测试从设计到实施的流程中，LLM 潜力突出。设计阶段可依据系统架构和业务需求辅助生成负载模型、设计压测场景、确定合理并发数与负载分布，显著提升设计效率和覆盖面。实施阶段则可与 Locust 等自动化工具联动，生成并优化测试脚本，并在测试结束后辅助解读性能指标，帮助团队及时发现并发瓶颈并提供优化方案。

尽管 LLM 在非功能测试中前景广阔，也存在局限。其推荐与分析依赖训练数据，未必能覆盖全部潜在威胁。因此未来需关注知识库的持续更新与优化，以及决策过程的可解释性。结合可解释 AI，今后 LLM 将能提供更透明、更可信的安全策略建议。

总体来看，LLM 的引入为非功能测试带来革新，提升了效率与质量。随着技术不断成熟，期待它成为保障软件系统性能、安全与用户体验的核心力量。

## **7.1 为软件测试服务的知识工程**

随着 LLM 在测试领域的渗透加深，建设高质量的测试知识工程流水线已成为实现测试智能化的关键底座。本节以银行智能风控平台测试为例，围绕 LLM 驱动的数据采集、处理、构建与评估全流程，阐述如何搭建面向行业或企业的软件测试知识库，如图 7-1 所示。

### **7.1.1 数据规划与采集**

知识工程起步阶段的核心工作包括明确知识需求与边界、梳理数据源与获取方式、建立数据治理与合规机制、设计初始数据结构等。知识需求相对清晰，即覆盖当前产品线所需的业务知识、功能与非功能需求、测试分析与设计、自动化脚本与工具等。数据主要来自项目管理与研发平台沉淀的资产，包括文档库中的研发资料。

为构建面向行业或企业的测试知识库，应尽量采集具有代表性的场景数据，同时保证来源多样、覆盖广泛。假设通用软件工程知识与测试方法已被基础模型掌握，重点应放在行业或企业内部的测试数据上，主要包括：

❑ 测试方案类文档，涵盖测试需求分析、技术方案、测试计划等；
❑ 测试用例与脚本；
❑ 历史缺陷库；
❑ 用户行为日志；
❑ 需求与测试的关联关系；
❑ 代码与测试的映射关系；
❑ 测试环境配置信息。

**1.数据来源识别与获取方式**

**（1）软件测试数据分类**

按来源与性质划分，测试数据大致可分为：

1）内部结构化数据。来自测试管理平台、缺陷跟踪系统、CI/CD 链路的结构化记录，字段明确、关系清晰。
2）内部非结构化数据。包括测试文档、设计说明、会议纪要、邮件往来，以及测试过程中产生的截图、录屏等多模态素材。
3）外部知识资源。行业标准、最佳实践、开源工具文档、技术博客等。
4）历史项目数据。已结项项目的测试结果、性能数据、问题解决记录等。

**（2）数据获取方式**

针对不同来源采取差异化采集：

1）API 集成。通过 JIRA、TestRail、Jenkins 等工具的接口自动抓取最新的计划、用例、执行结果与缺陷信息。
2）数据库直连。在确保安全前提下，通过直连方式批量获取历史数据。
3）文档解析工具。从 Word、Excel、PDF 等格式中抽取结构化信息。
4）网络爬虫。对特定外部资源进行定向采集，收集公开测试知识。
5）手动上传接口。为难以自动获取的数据提供人工补全通道，保证完整性。

**2.数据治理框架与隐私合规**

**（1）建立数据治理框架**

为保障质量与安全，建立多层次治理体系。

1）数据分类与标签体系。按敏感度、来源、业务领域等维度分类，为数据资源打标。
❑ 敏感度分级：公开、内部、保密、机密；
❑ 来源标签：项目代码、文档类型、创建时间等；
❑ 业务领域标签：功能测试、性能测试、安全测试等。
2）数据生命周期管理。
❑ 明确采集、存储、使用到归档或删除的完整流程；
❑ 建立更新机制，保持知识库时效性；
❑ 实施版本控制，支持关键知识追溯。
3）数据质量控制。
❑ 建立完整性、准确性、一致性校验机制；
❑ 实施输入校验规则，减少错误引入；
❑ 定期进行质量审计与清理。

**（2）实施严格的隐私保护措施**

针对可能含敏感信息的测试数据，采取以下保护：

1）脱敏处理。
❑ 自动识别并遮盖个人身份信息；
❑ 替换或模糊化客户名称、IP 地址、账号等；
❑ 按类型开发专用脱敏算法与规则。
2）访问控制。
❑ 基于角色的访问控制，限定数据范围；
❑ 遵循最小权限原则；
❑ 建立访问审计日志，记录敏感数据操作。
3）合规性审查。
❑ 建立敏感数据使用审批流程；
❑ 定期自查，符合 GDPR、CCPA 等法规要求；
❑ 编写数据处理协议与隐私政策文档。

**3.初始数据结构设计**

为支持后续知识抽取与检索，需设计合理的数据模型。

**（1）统一的测试数据模型**

核心实体及关系可按以下方向设计：
❑ 测试项目：基本信息、时间线、相关人员；
❑ 需求项：名称、描述、优先级、状态；
❑ 测试计划：范围、策略、时间安排；
❑ 测试用例：名称、类别、优先级、前置条件、测试数据、步骤、预期结果、实际结果、测试环境、自动化信息、关联缺陷、执行历史等，如图 7-2 所示；
❑ 测试执行：状态、结果、环境信息；
❑ 缺陷：标题、描述、复现步骤、严重程度、关联截图或日志；
❑ 知识点：从上述实体中提炼的可复用知识。

### **7.1.2 数据处理与知识抽取**

测试数据来源多样、格式不一，常存在混乱、冗余等问题，直接使用会影响抽取效果。因此在原始数据获取后，需进行清洗、格式化等处理。数据清洗即识别并纠正错误、不一致与冗余，过滤低质量内容，提升数据准确性、完整性与一致性，类似于从矿石中提炼金属。

**1.数据处理**

数据集构建的目标是将原始数据转化为结构化、标准化的测试集。结构化是指通过统一模板使异构数据归一，例如测试用例描述符合{场景描述、前置条件、操作步骤、预期结果、实际结果}格式，并能自动识别非结构化文档中的关键要素并转换。

**（1）数据处理标准**

处理后数据应满足：
❑ 格式统一性：不同来源遵循一致表示；
❑ 语义连贯性：语义完整、上下文清晰；
❑ 内容完整性：构建场景知识图谱，保证覆盖；
❑ 可追踪性：数据来源与使用场景可关联。

**（2）数据处理方式**

常见手段包括：
❑ 异常检测与清洗：用统计模型识别修正异常，结合领域规则验证业务合理性；
❑ 特征清洗与增强：移除执行过程中的冗余信息，补充上下文；
❑ 过滤：多级过滤去除低质量用例，基于成功率与有效性评分建立规则；
❑ 去重处理：用语义相似度识别功能重复用例，合并保留覆盖面。

**2.数据清洗**

数据清洗是质量保障的关键，一般流程如下。

**（1）清洗步骤**

1）数据评估：检查来源、格式与内容，确定完整性、准确性、一致性与可靠性问题。
2）数据预处理：
❑ 处理缺失值：删除、填充或模型预测；
❑ 处理异常值：统计方法、可视化或领域知识识别后删除、修正或标记；
❑ 数据转换：类型转换、标准化、归一化，如日期统一为 YYYY-MM-DD，字符串统一小写；
❑ 标准化：构建测试领域词典统一术语，如将“测试通过”“PASS”“√”统一表达，并将缺陷严重级别映射到统一体系。

**（2）具体工作**

1）数据清理：
❑ 去除重复数据：识别并删除重复记录；
❑ 纠正错误数据：按规则修正格式与逻辑错误；
❑ 降低噪声：去除页眉页脚、水印等干扰信息。
2）文档记录与元数据管理：记录清洗过程与变更，便于复查。
3）数据验证：核查字段间一致性、外键完整性、逻辑关系，可用工具或人工检查。
4）数据标注：确保分类或标记的准确性与一致性，可人工或自动完成。
