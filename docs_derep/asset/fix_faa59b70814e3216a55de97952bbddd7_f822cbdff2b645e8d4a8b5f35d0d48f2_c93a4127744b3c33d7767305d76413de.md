# 大规模向量检索：内存到度量全攻略

当数据体量持续膨胀，内存已无法一次性装下完整的检索索引时，就需要借助磁盘化方案，例如 DiskANN，把部分索引结构外移到 NVMe SSD 这类高速存储上，从而在内存受限的情境下依然能服务超大规模检索。

另一个思路是把向量搬进 GPU 显存里构建索引，利用显卡的并行加速完成距离运算。这类做法在追求高吞吐、低时延、高召回以及高并发查询的场景里优势明显。硬性限制在于显存容量，整体数据量必须能完整装入显存，否则该路线就不可行。

#### 4.5.3 选择合适的度量标准

在 Milvus 里，距离函数的选用直接决定检索质量。不同数据形态和业务目标需要匹配不同的度量方式，选对之后检索准确率和响应效率都会明显改善。

在做选择前，可以先自问几个问题来收敛方案。

- 数据形态：输入是浮点向量还是二进制向量？
- 向量特性：是否在意向量的模长？是否已做归一化？
- 业务场景：是文本语义检索、图像向量检索还是哈希编码比对？
- 成本预期：能否接受额外的归一化开销？对精度和速度的权衡点在哪？

下面先看三种密集浮点向量常用的函数。

- **欧几里得距离**：衡量两点直线远近，适用于图像、音频、视频等连续实数特征。直观且常用，但对特征尺度敏感，通常需要先做归一化。
- **内积**：衡量两个向量在方向和大小上的共同贡献，常用于推荐里用户和物品的相关性、文本嵌入的语义比较。使用时要注意归一化，否则模长会主导结果。
- **余弦相似度**：通过夹角余弦衡量方向一致性，对模长不敏感。常用于 TF-IDF 或大模型嵌入的文本比较，比如 BERT、GPT、BGE 等生成的表示，重点在于语义方向而非长度。

小冰：内积和余弦相似度看起来都可以比较文本向量，我没有完全明白二者的差别。

咖哥：内积没有固定的数值边界，受向量大小和方向共同影响。模长越大，内积往往越大，若未归一化，大模长向量容易占优。余弦的范围固定在 [-1,1]，计算时先归一化消除模长影响，只保留方向信息。

举例说明。做推荐且用协同过滤的矩阵分解得到用户、物品向量时，模长本身可反映偏好强度或物品重要性，这时内积能把强度叠加，直接用于排序更合理。若只关心兴趣方向是否一致，例如冷启动阶段数据稀疏，余弦更稳妥，能避免大模长向量长期霸榜。

再看文本嵌入语义检索。大模型如 BERT、OpenAI 嵌入、BGE 生成的向量，通常希望忽略文本长度等无关因素。余弦只看方向，能规避长度偏差，是常见做法。若向量已归一化，用内积也行，计算更快，本质等价于归一化后的余弦。

再看图嵌入。若向量模长代表节点影响力，如社交网络好友推荐，内积自然体现影响叠加。若只关心关系方向而忽略权重，例如找兴趣相近的用户群，归一化后的余弦更能突出关系相似性。
