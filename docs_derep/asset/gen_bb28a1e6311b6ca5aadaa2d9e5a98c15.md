**持续训练**：制造业的研发生产环境一直在变，零件换了、工艺调了、设备在老化，模型一旦定型就会慢慢掉队。持续训练就是 MLOps 脱离传统 DevOps 的关键能力，它会一直盯着模型表现，一旦捕捉到衰减信号就自动拉起再训练，用最新数据把模型刷新一遍，保持预测始终在线。

**持续监控**：上线后的在线表现要全景可视，既看运行指标如预测延迟、吞吐量，也看结果指标如准确性，同时要监控输入数据的质量，以及模型对业务 KPI 的实际拉动效果。

要让闭环跑得通，MLOps 平台一般会配三件套：特征库统一沉淀和复用特征；模型注册中心做版本管理和合规治理；试验跟踪系统记录、比对每次训练的全过程。

2.模型上线与发布策略
**A/B 测试**：新旧版本可以同时在线，流量分流后看真实表现，再决定是否全量放开。
**蓝绿部署/金丝雀发布**：先把新模型放到一小撮节点上试水，确认稳定后再逐步扩散，降低变更风险。
**安全与合规**：细粒度权限控制，只有授权的应用和用户才能调用服务；所有调用全部留痕，满足审计要求。

3.Kubeflow 与 MLflow 怎么选
开源 MLOps 里，Kubeflow 和 MLflow 是最常被拿来对照的两条路线，背后是不同的建设思路。

**Kubeflow**：基于 Kubernetes 的端到端 ML 平台 ^(⁷³)。它的强项是编排和弹性，能定义执行复杂的多步骤工作流，并充分利用 K8s 的资源调度和弹性伸缩，特别适合分布式训练、超参数大规模搜索这类重计算场景。代价是系统很重，完整环境部署维护需要扎实的 K8s 经验，学习曲线陡，对平台团队要求很高。

**MLflow**：走轻量路线，核心聚焦试验跟踪、模型打包和模型注册 ^(⁷⁴)。设计上更倾向于松散耦合，和开发者现有的工具链友好共存，几行日志代码就能开始追踪实验，上手很快。短板是自身编排能力有限，通常需要 Airflow 或 Kubeflow 来补全端到端流水线。

在制造场景里，选型取决于成熟度和规模。刚起步、只想为单条线做第一个预测性维护的团队，MLflow 的简洁更友好；跨国制造集团要为全球工厂建统一可扩展的 AI 平台，Kubeflow 的编排与基础设施管控能力更匹配。实践中常见的折中是混合架构：Kubeflow 扛底层任务编排，MLflow 负责上层的实验记录和模型资产管理，各取所长。尤其是 GPU 需求大的大模型应用，Kubeflow 在硬件资源管理上的原生优势会更明显。

MLOps 不是可有可无的加分项，而是成熟制造 AI 平台的底座。它把 AI 从手工探索式的试验，变成可重复、可度量、可规模化的工业化生产。没有这层能力，企业很难跨过从原型验证到规模化落地的鸿沟，AI 投入也难以产生回报。

### 6.6.4 上线后如何守护模型健康
模型投产后，服务质量和预测效果必须持续被看住。

**服务性能监控**：实时观测运行状态，包括①延迟，即单次预测的响应时间；②吞吐量，单位时间内处理请求的能力；③错误率，调用失败的比例；④资源占用，CPU/GPU 使用和内存消耗等。

**模型效果监控**：①数据漂移，线上输入分布与训练时分布是否明显偏离；②概念漂移，特征与目标的关联关系是否发生变化，比如市场需求因技术迭代而改变；③模型衰退，当漂移出现时准确率、召回率等指标会下滑，需据此判断是否要重训；④自动优化，基于监控信号自动扩缩容应对流量波动，并在检测到显著衰退时自动触发再训练。

总体来看，模型服务层是把数据科学成果与软件工程纪律结合起来的关键环节，把模型、运维、监控、治理串起来，构成了 AI 研发到业务应用的“最后一公里”，是实现规模化、可靠化、产业化落地的核心基础设施。

## 6.7 Agent 编排层：多 Agent 协同的核心枢纽
Agent 编排层位于模型服务层之上，是平台 AI 编排能力的中枢。依托多 Agent 管理平台，它负责组织多个 AI Agent 协同作业，通过调用 PLM、ERP 等系统的数据服务，完成变更影响分析、工艺参数优化这类复杂任务。

可以把它理解为 AI 项目经理或交响乐指挥，协调不同专长的 Agent 分配任务、编排流程、化解冲突，让跨领域多步骤问题被无缝解决。它是把单个 Agent 能力连到宏观业务目标的桥梁，提供规划、执行、监控复杂多阶段工作流的完整机制，让真正面向制造业系统性挑战的智能应用成为可能。多 Agent 系统是运行基础，相关能力在第五章已有详述。

### 6.7.1 工作流管理是编排的引擎
Agent 工作流关注设计、执行、监控、优化多 Agent 协作的完整任务流，核心包含：

1.工作流设计与定义
**可视化编排器**：拖拽式界面，用功能节点连线定义工作流模板，节点可以是 Agent、工具调用或逻辑判断。
**代码化定义**：也支持用 Python 等代码描述，便于版本控制，是专业团队更常用的做法。
**Agent 与工具注册表**：中央目录管理所有可用 Agent 及其能力与可调用工具/API，像技能库一样供设计时选用。

2.计划与调度引擎
**动态规划**：不同于传统静态路径，计划引擎会根据具体请求从模板出发实时生成执行计划，通常是明确依赖关系的有向无环图。
**资源调度**：按任务需求和优先级智能分配 CPU/GPU，决定启动时机。

3.执行引擎
**任务执行**：按计划顺序调用对应 Agent 或任务。
**工具调用**：需要外部交互时安全调用已注册工具并回传结果。
**并发并行**：对无依赖的任务并行处理，提升效率。

4.状态管理器
**状态跟踪**：记录每个任务的等待、运行、完成、失败等实时状态。
**中间结果传递**：提供共享工作区，前一个 Agent 的输出作为后一个 Agent 的输入，保证信息顺畅流动。

5.监控与日志记录
**实时监控仪表盘**：可视化展示运行中的工作流实例、进度与状态。
**详细日志**：记录每一步推理、决策、工具调用及返回结果，便于排错。
**性能分析**：统计平均耗时、成功率、资源消耗及瓶颈，为优化提供依据。

更进一步的系统还会加入人机协作接口，在关键节点设置暂停等待人工审批或补充信息；以及异常处理与自愈机制，定义重试、回滚或备选方案，提升健壮性。

当前生态中，LangChain 提供模块化构建块成为事实标准；微软 AutoGen 擅长构建可对话解决问题的 AI 群聊；CrewAI 让角色扮演的 AI 小队编排更直观；LlamaIndex 在与复杂数据源深度交互的场景表现突出；Flowise AI 等可视化平台把代码框架封装成拖拽节点，降低使用门槛，共同推动 AI 从单模型向多 Agent 协同演进。

然而，LLM 在制造业流程自动化里仍面临明显挑战，即推理准确率随流程复杂度上升而下降。

1.核心矛盾：推理准确率与复杂流程的冲突
基于 LLM 的 Agent 推理准确率约 95%，但流程超过十步后，整体准确率会跌到 60% 以下，约等于 95%¹⁰。这暴露了长链推理的长尾问题和黑箱特性。对制造业而言，微小误差会推高劣质品成本甚至引发安全事故，可容忍度极低。

2.解决方案：在顶层流程框架下迭代优化
关键不是放弃 AI，而是在坚实的顶层框架里做嵌入式、辅助式应用。

（1）顶层流程框架规划：构建智能化业务蓝图
先做顶层业务架构规划，把端到端价值流解构建模，例如把 OTD 拆成可控可验证的子流程。用平台化 AI 架构建立统一数据底座和数字主线，作为事实骨架，让 Agent 每一步都有可信单一数据源运行。

（2）业务流程解耦：实现智能与个性化
遵循顶层框架，把复杂流程拆解为多个可控子流程，由高度优化的场景化、领域驱动 Agent 各自负责。如研发中一个 Agent 生成设计方案，另一个生成结构化需求。复杂度降低后准确率提升。

**人机协同优化模式**：在高风险高复杂度环节，Agent 定位为智能助手，提供基于领域知识的建议与预测，最终决策仍由专业工程师把控。

**迭代优化与持续进化**：建立后向通道，把 Agent 推理结果与实际业务数据比对，形成持续学习闭环，准确率随时间提升，实现从经验驱动到 AI 增强创新的跃迁。

总之，Agent 编排层通过任务分解、Agent 分配、计划执行、通信管理与结果合成，把分散的 AI 工具和专家模型组织成自主规划、协同作战的 AI 团队，让平台从执行单点指令的工具，升级为解决端到端复杂流程的智能方案。

## 6.8 AI 应用层：价值兑现的最终界面
这是分层架构的最顶层，也是价值的最终呈现面。面向工程师、采购、管理者、客户等最终用户，把底层模型、数据、算力封装成易用的应用，嵌入业务流程，产生可衡量的商业价值。

### 6.8.1 AI 应用的三大典型形态
1.交互式 AI 助手/AI Chat
提供统一对话入口，用户用自然语言与企业数据、系统、AI 能力交互。它不止问答，还能理解复杂意图、执行多步任务，是真正的数字同事或领域 Copilot。

传统 Chatbot 只能处理预设 FAQ 的一问一答，而交互式助手是任务完成者，能基于高层目标自主规划、调用工具、整合信息。

在研发它可作为设计副驾驶，跨 PLM、质量库做关联查询；在生产现场化身运维顾问，实时分析 MES 与设备数据定位 OEE 下降根源；在供应链担任风险分析师，整合地缘政治、气象、SRM、ERP 数据预测供应风险；在工业软件场景，它能结合操作手册和上下文，指导设计师完成复杂操作。

核心价值在于把碎片化工业数据转化为主动决策能力，形成“人类提问-AI 执行-结果洞察”闭环，推动从经验驱动到数据智能驱动的范式转变。

2.内容生成类 AI 应用
核心是创造而非分析，能基于学习模式生成文本、代码、图像、音频、视频、三维模型等新内容。

主要形态包括智能创作助手、内容生成引擎、合成数据生成器。

在制造领域，创成式设计突破想象边界并自动生成 CAE 分析脚本；生产环节可自动生成图文工艺规程，用合成数据解决质检样本稀缺问题；营销服务可动态生成个性化技术文档；运维培训可实时生成故障维修指南和虚拟训练场景。AI 从辅助工具进化为创新引擎，实现全价值链智能再造。

3.流程自动化应用
目标是把重复性、规则性、需认知判断的业务流程端到端自动化，提升效率、降本、减少人为错误，释放人力去做创造性工作。
