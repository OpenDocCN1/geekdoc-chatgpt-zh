#### 3.2 AI 模型开发全流程拆解

人工智能模型的落地通常遵循四大核心环节：**需求拆解、数据筹备、模型训练、模型落地**。借助百度 EasyDL 平台，开发者可在全链路实现“零代码”极速构建。下面我们以**商品检测项目**为切入点，深度复盘平台实操方法论。

#### 3.2.1 需求拆解：从“货架争夺战”到技术指标

**业务痛点直击：**
在线下终端的“生死局”中，货架陈列的黄金位置与排面占比直接决定销量。然而执行层面乱象频出：必销品缺货、新品被挤至边缘、陈列凌乱、物料缺位屡见不鲜。数据显示，货架缺货会让品牌流失 **46%** 的潜在购买者，零售商流失 **30%**。引入 AI 商品识别技术，辅助人工审查陈列合规性，成为破解终端管控难题、提质增效的关键路径。

**技术任务定义：**
核心诉求转化为**目标检测任务**——在图像中精准框出所有目标商品，输出类别与坐标位置。基于此，我们直接选用 **EasyDL 零售行业版**，无需写代码即可定制专属检测模型。

#### 3.2.2 数据筹备：模型性能的基石

数据环节分三步走：**采集 → 处理 → 标注**。本项目需准备两类核心素材：**SKU 单品图** 与 **实景图**。

> **核心区别**：单品图非训练必需，但通过“合成增强”技术能让模型低成本学会多角度特征，显著降低实景图采集标注成本；实景图则是模型训练的“主粮”，必须源自真实业务现场。

##### 1. 数据采集：标准决定上限

**【单品图采集规范】**
平台预置海量饮品/日化类商品库（含 50+ 角度图），多数场景无需自行上传，仅需针对识别效果差的 SKU 补拍。

| 维度 | 硬性指标 |
| :--- | :--- |
| **内容** | 单图仅 1 个商品；纯色背景且与商品主色对比度高（参考 [PRE0]）；光照覆盖真实场景差异（如暖黄/冷白灯光）。 |
| **清晰度** | 分辨率 ≥ 1920×1080，相机 ≥ 200 万像素。 |
| **角度覆盖** | 货架场景需覆盖**水平、俯视、仰视**三大视角（参考 [PRE1]）；无人货柜侧重俯视；结算台以水平/俯视为主。 |
| **数据量建议** | 各角度各 **10 张** 起步（详见表 3-1），地堆场景建议在实景图中覆盖角度。 |

**【实景图采集规范】**
*   **来源一致性**：巡店业务用巡店机/手机拍，结算台业务用结算台自带摄像头拍，设备必须与落地环节一致（参考表 3-2 分辨率建议）。
*   **清晰度底线**：肉眼能清晰辨认每个商品特征（参考 [PRE2]）。
*   **角度约束**：货架场景**正面拍摄为主，微倾斜可接受，大倾斜严禁**（参考 [PRE3]），避免遮挡变形导致识别率骤降。
*   **起训量门槛**：首训每个 SKU 至少 **20 张** 已标注实景图。平台自动 7:3 切分训练/测试集；数据不足会导致 mAP、精确率、召回率全扑街。

##### 2. 数据处理：平台准入门槛
*   格式：PNG/JPG/BMP/JPEG
*   单图 ≤ 4MB
*   长宽比 ≤ 3:1，长边 < 4096px，短边 > 30px
*   压缩包仅限 ZIP，≤ 5GB

##### 3. 数据标注：质量生命线
单品图免标注；实景图标注规范直接决定模型上限。

*   **框选准则**：**能覆盖目标 SKU 的最小外接矩形框**（参考 [PRE4]）。
*   **遮挡策略**：
    *   货架场景：露出 **>70% 且保留识别特征** 才框。
    *   无人货柜/结算台：**只框露出的部分**（参考 [PRE5]）。
*   **相似品强制分类**（防混淆）：
    1.  同品牌不同系列/口味/包装（[PRE6]）
    2.  同款不同规格（如 330ml vs 500ml，[PRE7]）
    3.  高度相似竞品（色/型/材质酷似，[PRE8]）
    > *切记：将相似品归为同一类会大幅提升误识别率。*
*   **避坑指南——拒绝“误标”与“漏标”**：
    *   **误标高发区**：同款不同规格/口味/包装最易错标为同一类。
    *   **漏标三大元凶**（参考 [PRE9]-[PRE11]）：
        1.  角度偏见：只标正面，忽略侧面/背面。
        2.  粗心大意：目视未扫全。
        3.  遮挡误判：明明露出特征 >70% 却因犹豫而漏标。

#### 3.2.4 模型应用：从评估到落地的闭环

训练完看**评估报告**，核心指标看 **F1-score**（精确率与召回率调和均值）：
*   **F1 > 85%** → 可支撑**商品计数**业务。
*   **F1 > 60%** → 可支撑**分销统计**业务。

**效果不达标？只管优化数据，别动算法参数。** EasyDL 零售版已完成场景化调优，模型迭代遵循 **“数据飞轮” 5 步法**：
1.  **回流补实景图**（用优化工具挖掘难例）。
2.  **补齐弱项单品图**（针对识别差的 SKU 补角度图）。
3.  **新旧数据混合重训**。
4.  **发布新版 API 实测**。
5.  **循环往复，直至达标上线**。

**部署形态灵活**：云端 API 直调，或一键嵌入 H5 页面体验验收（界面见 [PRE12]）。

#### 3.4 手把手实操演示（EasyDL 零售版）

##### 步骤 1：新建模型 & 录入 SKU 库

1.  **进场**：登录实训系统 → 启动 “AI 平台实验” 中的 EasyDL（[PRE13]）。
2.  **选型**：点击 “立即使用” → 选择 **“零售行业版”**（[PRE14]） → 登录账号。
3.  **建模**：左侧导航 “我的模型” → “创建模型”（[PRE15]-[PRE16]）。
    *   **模型名**：业务导向命名，如 “饮料检测”。
    *   **归属/场景**：个人 / 普通货架-货柜。
    *   **功能描述**：10-500 字，说清解决什么问题。
4.  **确认**：点 “下一步” 落地，列表页即可查看（[PRE17]）。
5.  **建 SKU**：点击列表 “创建 SKU”，按提示填写核心字段：
    *   **命名规则**：返回格式为 `SKU名称_品牌_规格`，**三字段严禁重复内容**。
    *   **必填维度**：SKU 名称（如“原味可乐”）、品牌（如“可口可乐”）、规格（如“330mL”）、品类、包装类型。
    *   **业务关联**：商品编码（条码）填入便于后续系统对接。
    *   **增强素材**：上传单品图用于合成增强，提升识别鲁棒性。
