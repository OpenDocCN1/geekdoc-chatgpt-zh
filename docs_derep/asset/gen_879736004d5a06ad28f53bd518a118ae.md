# TensorFlow 变量作用域与图机制深度解析

## 变量定义的差异：`Variable` 对比 `get_variable`

在 TensorFlow 中，`tf.Variable` 允许同名变量重复创建，每次调用都会在图中生成独立节点（通过后缀 `_n:0` 区分），后定义的变量在计算图中生效。例如连续定义两个 `var1`，内存中实则存在两个不同名称的节点，最终生效的是赋值为 2.0 的那个。

而 `tf.get_variable` 则强制要求变量名在当前作用域内唯一。若尝试同名二次创建，程序将直接抛出异常崩溃。若首个同名变量是由 `Variable` 创建，系统会自动重命名后续 `get_variable` 变量（如 `firsttvar_2:0`）以避免冲突。若需同名共存，必须显式指定不同的 `name` 参数，此时新变量覆盖生效，数值随新初始化器改变。

## 作用域隔离：`variable_scope` 的核心作用

既然 `get_variable` 禁止同名重复，如何实现“同名不同变量”？答案是 `tf.variable_scope`。通过将同名变量置于不同命名空间（如 `test1` 与 `test2`），即可合法创建。输出显示变量全名分别为 `test1/firstvar:0` 与 `test2/firstvar:0`，确认了作用域的隔离效力。

作用域支持嵌套：内层 `scope` 缩进于外层之下，变量全名体现层级关系（如 `test1/test2/firstvar:0`）。这种机制为模型模块化管理提供了结构化保障。

## 变量共享：`reuse` 机制与 `AUTO_REUSE`

`get_variable` 设计初衷即服务于变量共享。`variable_scope` 的 `reuse=True` 参数开启复用模式：不再创建新变量，而是从图中检索同名变量。

实例中，首次在 `test1` 与 `test1/test2` 创建 `firstvar`；再次进入相同 scope 并设 `reuse=True` 获取 `var3`、`var4`。输出证明 `var1` 与 `var3` 指向同一内存（`test1/firstvar:0`），`var2` 与 `var4` 同理（`test1/test2/firstvar:0`）。此机制允许多模型（如训练/测试模型）共享参数，梯度更新同步作用于单一参数集。

> **实战避坑**：在 Spyder 等交互式环境中重复运行共享代码会报错“变量已存在”，因默认图保留了上次运行的变量。解决方案：运行前调用 `tf.reset_default_graph()` 清空图，或重启 Kernel。

进阶用法 `tf.AUTO_REUSE`：首次进入 scope 时 `reuse=False`（创建），再次进入自动切为 `True`（复用），无需手动切换，代码更简洁。

## 初始化器的继承与覆盖规则

`variable_scope` 与 `get_variable` 均可指定初始化器。规则为：**就近原则，显式优先，隐式继承**。

- 外层 `test1` 设初始值 4.0（即 0.4 矩阵）。
- `var1` 无显式初始化 → 继承 `test1` → 值 0.4。
- 内层 `test2` 无初始化 → 继承 `test1` → `var2` 值 0.4。
- `var3` 显式指定初始化 0.3 → 覆盖继承 → 值 0.3。

此特性在多模型训练中极具价值：顶层统一设定参数初始化策略，子模块自动继承，关键层可单独定制。

## 作用域的“穿透”特性与 `name_scope` 边界

`with tf.variable_scope("name") as scope:` 语法赋予 scope 对象“穿透”外层限制的能力。实例中 `sp` 定义于 `scope1`，后置入 `scope2` 并重命名为 `spl`，但 `spl` 及其内部变量 `var3` 全名仍以 `scope1/` 开头，完全无视外层 `scope2`。

**关键区分**：
- `tf.variable_scope`：管变量命名，也管 Op 命名。
- `tf.name_scope`：**仅管 Op 命名，不管变量命名**。

实验对比：在 `scope/bar` 下，`get_variable` 创建的 `v` 命名受 `variable_scope` 约束；`tf.add` 等 Op 创建的 `x` 同时受双重 scope 约束。若在 `name_scope` 中用 `""` 空字符串重置，Op 命名回归顶层；而 `variable_scope` 用 `""` 仅增加一层空名层级，变量命名不回顶层。这是两者设计分工差异导致的本质不同。

# 图的基本操作

TensorFlow 程序默认隐式构建一张计算图。除自动建图外，支持手动创建多图并切换上下文。

## 三种建图方式与默认图切换

1.  **隐式默认图**：无代码干预，`tf.get_default_graph()` 获取即是。
2.  **显式创建+上下文管理器**：
    ```python
    g = tf.Graph()
    with g.as_default():
        # 此处操作归属图 g
    ```
3.  **显式创建+临时设为默认**：
    ```python
    g = tf.Graph()
    with g.as_default() as gg:
        # gg 即 g，操作归属图 g
    ```
验证手段：在各上下文中调用 `tf.get_default_graph() is g` 判断生效情况。

## 图内容检索操作

建图后，常需从图中取回张量、操作或集合：
- `graph.get_tensor_by_name("name:0")`：按全名精准取张量。
- `graph.get_operation_by_name("op_name")`：取操作节点。
- `graph.get_collection(key)`：按键取集合（如 `tf.GraphKeys.GLOBAL_VARIABLES`）。
- `graph.get_all_collection_keys()`：列举图中所有集合键名。

掌握图的显式管理与检索，是实现多模型隔离、模型迁移、分布式切分等高级场景的基石。
