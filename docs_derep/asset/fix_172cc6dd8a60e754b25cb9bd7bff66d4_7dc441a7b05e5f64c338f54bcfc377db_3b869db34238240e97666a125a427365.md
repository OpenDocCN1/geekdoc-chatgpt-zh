**小贴士**
不确定要不要上云时，先在本地把环境跑通会更稳。等你遇到离开本地网络后无法访问龙虾、或者定时任务经常掉线的情况，再把整套环境搬到云上也不迟，迁移可以一键完成。

**云端部署需要什么条件？**
把 OpenClaw 放到云上，本质是在云厂商租一台可远程操控的主机并安装上去。并不要求你会运维，但有几项前置要准备好：

● 操作系统：首选 Ubuntu 22.04 或 24.04，其次 CentOS 7 及以上版本，均需 64 位
● 硬件下限：入门建议 2 核 CPU、2~4 GB 内存、40 GB 磁盘；追求顺滑体验可提到 4 核、8 GB 内存起步，预算充足还能加 GPU
● 网络：OpenClaw 默认占用 18789 端口，主机买好后要在控制台的安全组/防火墙里放行，否则浏览器打不开 Web UI
● 费用：主流厂商的入门规格月付不贵，部分提供新客优惠或免费试用

**部署流程：五步通用模板**
无论选哪家厂商，整体套路大同小异，可按下面五步走。

第一步：购置云主机。在厂商官网注册并实名，完成支付后选一台轻量应用服务器，入门配置就够。
第二步：装系统镜像。很多厂商已提供 OpenClaw 的预装镜像或一键应用模板，直接选用最省事。若没有则挑 Ubuntu 22.04，再按 2.4 节的 Linux 安装步骤操作。
第三步：远程接入服务器。推荐使用 Termius 或 FinalShell 这类 SSH 客户端，填入公网 IP、账号密码即可登录。多数厂商也提供网页终端，无需装软件。
第四步：接入 AI 模型。和本地一样执行 openclaw onboard，选择模型并填入 API Key，具体可参考 2.2 节。
第五步：验收。浏览器打开 http://服务器IP:18789，发送一条消息，若龙虾能回话即说明上线成功。

**云端部署安全须知**
数据上云后安全不能放松，部署完成务必自检以下底线：

（1）登录密码要强，杜绝 123456 这类弱口令。SSH 密钥登录比密码更安全，有条件优先使用。
（2）端口最小化，仅开放 18789 与 22，其余一律关闭，减少攻击面。
（3）养成定期备份习惯，建议每周一次。配置文件和记忆文件丢了很难恢复。
（4）优选正规大厂。小众或海外不明服务商的稳定性和数据安全难以保证。
（5）避免存放高度敏感信息，不要上传银行卡密码、身份证照片等。OpenClaw 的对话会经由模型商的服务器处理，注意信息边界。

**常见问题**
**问题 1：云端部署安全吗？**
数据存放在你自己付费的服务器上，仅你可访问。但自有服务器并非绝对安全，仍需做好上述加固。停用时可直接删除整台机器，数据会彻底清除。

**问题 2：会一直扣费吗？**
多数厂商支持按月或按量计费，删除机器后费用即停止。建议先买一个月试用，满意再续费。

**问题 3：手机怎么访问？**
两种方式：一是借助飞书、企业微信、QQ 等聊天工具发消息控制龙虾，最方便；二是手机浏览器直接打开 Web UI http://服务器IP:18789。

**问题 4：本地配置能迁移到云端吗？**
可以。将本地 ~/.openclaw 目录打包 tar -czf backup.tar.gz ~/.openclaw，上传到云主机解压即可，配置、记忆、技能都能无缝接续。

## **2.6** **更新与维护：让龙虾保持最佳状态**
OpenClaw 更新很快，平均两周一个版本。保持最新能获得性能改进、新功能和安全修复，操作很简单，一行命令搞定。

**检查与更新**
# 查看当前版本
openclaw --version

# 查看最新版本
curl -s https://api.github.com/repos/openclaw/openclaw/releases/latest | grep tag_name

# 方式一：使用安装脚本一键更新（推荐）
curl -fsSL https://openclaw.ai/install.sh | bash

# 方式二：手动更新（从源码）
cd ~/openclaw
git pull origin main
pnpm install

**备份数据**
使用一段时间后，记忆文件和技能配置都很珍贵，建议定期备份。

# 备份配置和数据（推荐每周一次）
tar -czf openclaw-backup-$(date +%Y%m%d).tar.gz ~/.openclaw

# 恢复数据
tar -xzf openclaw-backup-20260210.tar.gz -C ~/

**手动配置：接入 DeepSeek 或其他自定义供应商**
以 DeepSeek 为例，兼容 OpenAI 格式的国产模型配置思路一致，在 openclaw.json 的 models.providers 字段中添加：

{
"models": {
"mode": "merge",
"providers": {
"deepseek": {
"baseUrl": "https://api.deepseek.com",
"apiKey": "${DEEPSEEK_API_KEY}",
"auth": "api-key",
"api": "openai-chat"
}
}
}
}

然后在 ~/.openclaw/.env 中以环境变量形式写入 Key，避免明文暴露：

DEEPSEEK_API_KEY=sk-你的 API Key

配置完成后重启网关 openclaw gateway restart，再用 openclaw models list 确认模型已出现即可使用。

**本地模型：用 Ollama 在自己的电脑上跑 AI**
若有隐私顾虑或想离线使用，可用 Ollama 运行开源模型。OpenClaw 对 Ollama 有原生支持：

# 安装 Ollama（Mac/Linux）
curl -fsSL https://ollama.ai/install.sh | sh

# 下载一个中文优化模型（推荐 Qwen2.5）
ollama pull qwen2.5:7b

启动后 OpenClaw 会自动发现本地的 http://127.0.0.1:11434，无需额外配置。执行 openclaw models scan 扫描一次，本地模型就会出现在列表。

本地模型的权衡：数据完全不出本机，但对硬件有要求，70 亿参数模型建议 16GB 内存，响应速度比云端 API 慢。适合处理敏感文件、私密对话或网络不稳场景。

**模型故障转移：备用方案自动切换**
OpenClaw 支持配置备用模型，在 agents.defaults.model 中设置主模型和 fallback 链：

{
"agents": {
"defaults": {
"model": {
"primary": "zai/glm-5",
"fallbacks": ["openrouter/deepseek/deepseek-chat", "ollama/qwen2.5:7b"]
}
}
}
}

含义为：优先使用 GLM-5，若限速或不可用自动切到 DeepSeek，再不行切到本地 Ollama，形成三层保障。

## **2.8** **本章故障排查手册**
根据大量用户经验汇总，最常见的坑基本 5 分钟内可解。

**安装问题**
**问题 1：Node.js 版本不对**
# 检查当前版本（必须≥22.16.x）
node --version
# 如果低于 22，则升级
nvm install 22
nvm use 22

**问题 2：权限错误**
# macOS/Linux：修复权限
sudo chown -R $USER ~/.openclaw
# Windows：以管理员身份运行 PowerShell，然后执行：
takeown /F "$env:USERPROFILE\.openclaw" /R /D Y
icacls "$env:USERPROFILE\.openclaw" /grant"$env:USERNAME:(OI)(CI)F" /T

**问题 3：网络连接失败、下载太慢**
（1）检查网络，或开启科学上网后重试。
（2）使用国内镜像：curl -fsSL https://openclaw.ai/install.sh | bash -s -- --mirror=cn。
（3）换手机热点尝试。

**API 配置问题**
**问题 1：API Key 无效**
（1）检查是否完整复制，包含 sk- 前缀且无多余空格。
（2）检查账户余额是否充足，余额为 0 时无法调用。

**问题 2：模型不可用**
（1）检查模型 ID 是否正确，不同平台命名有差异。
（2）检查对应平台状态页是否正常。
（3）尝试切换其他模型版本。

**问题 3：Token 消耗太快、费用太高**
（1）切换到更经济的模型，DeepSeek 性价比较高。
（2）优化指令，避免每次对话都带入大量历史记录。
（3）定期清理会话历史：openclaw cache clear。

**Gateway 问题**
**问题 1：Gateway 无法启动**
# 查看日志找原因
tail -f ~/.openclaw/logs/gateway.log
# 重启 Gateway
openclaw gateway restart

**问题 2：18789 端口被占用**
# 查看占用程序
lsof -i :18789
# 可改端口
openclaw config set gateway.port 18790
