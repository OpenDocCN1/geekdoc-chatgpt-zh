大模型能力放开后，搭数据集的成本被大幅拉低。研究者能直接借助大语言模型生成问题与答案，为特定评测目标定制数据集。生成式建库让数据更贴合实际场景，同时也把 RAG 系统处理动态知识的能力推向了更高要求。

RGB[463]、MultiHop-RAG[464]、CRUD-RAG[465] 就是自动生成数据集的典型做法，它们都以在线新闻文章为原料合成评测集，用来检验 RAG 在真实世界信息面前的表现。数据刻意超出训练集覆盖范围，核心在考验对动态实时信息的跟进与适应。CDQA[466] 基于新闻源生成评估集，并引入标签器来搭建更复杂的评价任务。DomainRAG[467] 融合单文档、多文档、单轮对话和多轮对话等多种任务形态，数据来自不同年份的高校招生与注册信息，通过不断更新的内容逼迫系统依赖动态知识库，对时效性和适应性做全方位压测。OmniEval[468] 面向金融领域提出自动全方位基准，把查询划分为抽取式问答、多跳推理、对比、对话、长文本问答 5 类任务，覆盖股票市场、投资银行、财产保险等 16 个金融主题，形成 RAG 场景矩阵，实现对多样化查询的结构化评估。OmniEval 包含 11,400 个自动生成的测试示例和 1,700 个人工标注的测试示例。

### 3. 数据集怎么建才好用
在实际应用里，评估集的搭建要结合任务特性和评测目标，才能全面衡量 RAG 性能。为了模拟动态真实场景，部分基准如 RGB、MultiHop-RAG、CRUD-RAG 和 DomainRAG 都是通过爬取新闻、年度变化数据或实时信息来生成评估集。这类动态数据能有效检验系统在面对训练未见的最新信息时，适应能力和处理效率如何，从而评估其动态性和时效性。

针对特定评测目标，定制化数据集更能复现复杂任务。例如 DomainRAG 设计了单轮与多轮对话任务，用来测试 RAG 在复杂人机交互中的表现；CDQA 通过多文档生成任务，评估系统整合和分析多源信息的能力。任务定制让评估集更精准地反映系统在特定场景下的真实水平。

多样性和覆盖面是全面评测的关键。将开放域问答、多轮对话、事实验证等多种任务，与新闻、百科、结构化数据库等多样数据源结合，评估集就能更完整地展示 RAG 在不同领域里的适应性和泛化能力。这种多元化设计保证了系统在更广阔应用场景中的可靠性和实用性。

#### 2. 生成侧怎么评
生成模块负责基于检索结果为用户查询生成连贯准确的回答。评估需兼顾质量、真实性及与检索内容的一致性，主要从五方面说明。

（1）准确性与忠实度：生成内容必须忠于检索证据并准确回答问题。常用指标如下。
BLEU 通过计算生成内容与参考答案的 n-gram 重叠度评估准确性。计算公式如下：
BLEU = BP × exp(∑(wₙ × log(pₙ))) (9.20)
其中，BP 为长度惩罚因子，wₙ 表示 n-gram 权重，pₙ 表示 n-gram 匹配概率。BLEU 适合结构化任务，对开放任务灵活性有限。
ROUGE 主要用于摘要任务，衡量生成内容与参考答案的文本片段重叠。常用 ROUGE-N、ROUGE-L。计算公式如下：
ROUGE-N = ∑(Overlapping n-gram) / ∑(Reference n-gram) (9.21)
ROUGE-L = F₁(LCS) = (1 + β²) × Precision_LCS × Recall_LCS / (β² × Precision_LCS + Recall_LCS) (9.22)
其中，Precision_LCS 表示生成文本中最长公共子序列的精确率，Recall_LCS 表示参考文本中最长公共子序列的召回率。
Exact Match（EM）用于衡量生成内容与参考答案的一致性，常用于问答，计算公式如下：
EM = 正确答案数量 / 全部答案数量 (9.23)
EM 适用于有标准答案的任务，不适用于开放生成。

（2）连贯性与流畅性：内容需逻辑连贯、语法正确且自然。
人工评分是常用方法，通过评分标准量化表现。例如流畅性 0 到 5 分，0 为完全不流畅，5 为极其流畅；连贯性 0 到 5 分，0 为完全不连贯，5 为逻辑严谨且连贯，可反映语言表达自然程度和逻辑性。人工评分可结合情境做细粒度判断。
基于语言模型的自动评分通过计算生成文本条件概率来评估语言质量和逻辑性。可用公式 Fluency Score = log P(Generated Text|Context) 量化上下文中的自然程度。该方法效率高且一致，适合大规模评估，可降低人工成本，为流畅性评估提供数据驱动支持。

（3）生成内容的多维度质量：从易读性、丰富性和结构化程度衡量。
易读性常用 Flesch Reading Ease[469] 计算。该公式由 Rudolph Flesch 于 1948 年提出，具体如下：
RE = 206.835 - 1.015 × ASL - 84.6 × ASW (9.24)
其中，RE 为易读性分数，ASL 是平均句子长度，ASW 是每个单词的平均音节数。分数越高越易读。
结构化程度关注内容是否符合任务格式要求。例如表格生成需正确生成表头并填充数据，摘要生成需段落分布合理、按主题分块。结构化内容提升用户体验和信息利用效率。
丰富性衡量生成内容的全面性和细致性，通常用信息覆盖率（ICR）评估，计算公式如下：
ICR = 生成文本中包含的事实个数 / 参考答案中包含的事实个数 (9.25)
该指标反映是否涵盖关键信息并避免遗漏。高丰富性内容在复杂任务中尤其重要。

（4）开放性任务的多样性：在无标准答案的开放任务中，多样性是关键指标。评估需从语义多样性得分和冗余度入手。
语义多样性得分（Semantic Diversity Score, SDS）衡量语义层面的差异，公式为
SDS = 1 - cos(Embedding₁, Embedding₂) (9.26)
其中，Embedding₁ 和 Embedding₂ 表示生成内容不同部分的语义嵌入。分数越高，语义表达差异越大，创造性越强。
冗余度（Redundancy）用于检测重复信息比例，计算公式如下：
Redundancy = 重复单词或短语个数 / 单词或短语总数 (9.27)
高冗余度意味着重复率高、创造性低，低冗余度则信息表达更新颖。在创造性写作中，低冗余度更能保持阅读兴趣。
