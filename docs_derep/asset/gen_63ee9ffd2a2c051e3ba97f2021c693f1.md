# 第三章 核心架构深度解析

本章带你深入 OpenClaw 核心架构，从宏观组件入手，拆解 Gateway 网关、Node 节点以及 Agent Loop 智能体闭环三大核心模块。

学习后你将明白 OpenClaw 如何将大语言模型的推理能力与本地计算资源结合，构建出自主、安全且高度可扩展的个人 AI 操作系统。

3.1 永不离线的“大脑”

把 OpenClaw 比作生物体，Gateway 就是它的“大脑”和中枢神经系统。它是一个长期运行的后台守护进程，负责协调内部组件、管理外部连接、维护会话状态，并作为整个系统的唯一控制平面。

理解 Gateway 的设计哲学是理解一切行为的起点。它不是一个简单的 HTTP 服务器，而是一个有状态的事件驱动系统。

3.1.1 单例的事件总线与控制平面

OpenClaw 架构中 Gateway 采用严格的单例模式，同一主机同一时间只能运行一个网关实例。这并非偶然，而是对系统一致性与资源管理的考量。单例不仅简化技术实现，更从根本上划定安全边界：所有权限决策都在一个可信受控进程中做出。若允许多实例并行，状态同步与权限一致性将难以保证。

1．统一的事件总线
网关内部实现高性能事件总线。来自用户聊天、定时任务 Cron 触发、外部 Webhook 调用或内部状态变更等活动，都被抽象为事件在总线上广播与路由。

消息路由是核心功能。无论你在飞书、企业微信发送消息，Gateway 都能接收事件，按绑定信息准确分发到对应 Agent 和 Session。渠道差异被抹平，统一转成内部事件格式后交由 Agent Loop 处理。

状态同步是另一关键职责。Gateway 维护所有客户端如 macOS 菜单栏应用、CLI 工具、Web 控制台的状态。当 Agent 状态从空闲变为思考中或执行工具时，状态会通过事件总线实时推送，实现打字机效果与进度展示。

2．唯一的控制平面
作为控制平面，Gateway 对系统资源拥有绝对控制权，核心职责包括：

• 生命周期管理：启动、停止与监控 Agent 进程，决定何时为特定会话启动 Agent Loop，何时因超时或不可恢复错误强制终止。
• 配置管理：加载与热更新系统配置如 openclaw.json，统一管理多智能体的工作空间 workspace 与状态目录 agentDir。修改配置后执行 openclaw gateway restart 即可重载，无需重启系统。
• 连接管理：是系统中唯一直接与外部消息平台建立底层连接的组件。集中管理避免多进程同时抢占账号导致冲突与封禁，并在网络波动时自动重连。
• 工具安全校验：所有工具调用请求都必须经过 Gateway 的权限校验层，在底层确保系统安全。

以上四大职责源于集中式控制设计，并贯穿其与内外部组件的交互。所有客户端、智能体、外部消息平台的交互都需经 Gateway 统一调度与校验，具体连接架构如图 3-1 所示。

3.1.2 网络模型

OpenClaw 网络设计遵循环回优先 Loopback-First 理念，除非明确配置，否则拒绝任何外部网络直接连接。控制命令、状态查询与数据传输必须在本地完成，从外部看网关是隐形的。默认 WebSocket 服务器仅绑定在 127.0.0.1:18789。

1．设计理念
这一决策构成 Secure by Default 安全默认哲学。

• 极致安全：AI 智能体通常拥有高权限，如读取文件、执行 Shell、发送消息。若网关默认暴露公网，一旦存在漏洞将造成灾难。环回优先从网络层面切断外部攻击面。
• 隐私保护：聊天记录、个人数据与凭证本地存储，限制网络访问最大程度防止泄露。
• 简化信任：在本地环回中，连接请求可被视作来自可信本地 CLI 或 UI，从而简化身份验证，提升本地交互流畅度。

官方文档明确提示：永远不要在 0.0.0.0 上无认证地暴露 Gateway。

2．网关绑定模式
OpenClaw 提供多种绑定模式适应不同场景。

• 环回模式 loopback，默认，仅监听 127.0.0.1，专为纯本地使用设计，安全性最高。
• 局域网模式 lan，适用于家庭或办公内网共享，绑定 0.0.0.0，允许同一局域网设备连接。
• Tailscale 网络模式，跨设备场景推荐方案。网关绑定到 Tailscale 内部 IP，可在全球安全访问，无需把端口暴露公网。
• 自定义模式 custom，允许管理员手动指定监听的特定 IP 地址。

3．安全的远程访问实现
不可能永远只在本地使用。OpenClaw 强烈推荐零信任网络方案，特别是 Tailscale 或其他 VPN 技术。

通过 Tailscale，可把手机、笔记本与运行 Gateway 的机器组成安全的私有虚拟局域网 Tailnet。网关仍只监听本地或 Tailnet 地址，但你能通过 Tailscale 内部 IP 安全连接，体验与本地一致。

Tailscale Serve 还可在 Tailnet 内为 Gateway 提供 HTTPS 加密，并把请求者身份如 Tailscale-User-Login 头传递给 Gateway，实现基于身份的访问控制。配置示例如下 openclaw.json：
// 在 openclaw.json 中配置 Tailscale 绑定
{
"gateway": {
"bind": "tailnet",
"port": 18789,
"auth": {
"mode": "token",
"token": "your-long-random-secret-token"
}
}
}

4．必须配置的认证模式
一旦绑定到非环回地址，必须同时配置认证。OpenClaw 支持三种模式。

• 令牌认证 token，基于共享密钥，是最常用最推荐方式。客户端 WebSocket 握手必须提供正确令牌，否则被拒绝。
• 密码认证 password，适用于需要人工输入凭证的特定客户端场景。
• 无认证 none，极度危险，仅建议在完全隔离的本地测试环境使用。

OpenClaw 的安全审计工具 openclaw security audit 会主动检测非环回绑定但无认证的配置，并标记为严重 critical 级别问题。

3.1.3 客户端和节点的通信协议

Gateway 与所有客户端 Client 和节点 Node 之间的通信完全依赖 WebSocket 协议，全双工低延迟，非常适合需要实时流式输出和频繁状态更新的 AI Agent 场景。

1．协议基础
传输层面采用文本帧 Text Frame 格式，负载全部 JSON 编码。默认网关在 18789 端口监听连接，可通过修改 gateway.port 配置项或设置环境变量 OPENCLAW_GATEWAY_PORT来自定义端口。
