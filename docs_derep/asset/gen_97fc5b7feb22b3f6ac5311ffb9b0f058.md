目前手工部署 Cross-Encoder 或 ColBERT 已很少见。只想快速融合排序结果，RRF 就足够用了。若企业已有 Elasticsearch，想低成本增强语义排序，且对数据隐私要求不高、没有专职 NLP 团队、愿意按需付费，选 Cohere 重排更合适。反过来，业务规则特殊比如医疗搜索要接入专业词表，内部有模型调优能力且对数据隐私零容忍不愿用第三方 API，自建开源重排模型更稳妥。

压缩技术的目的是在去冗余的同时保留检索结果的关键信息，但压得过头会丢信息，影响生成的完整性和准确度。

上下文压缩方案如 ContextualCompressionRetriever、LLMLingua 能提炼要点、降噪。模型优化如 RECOMP、Sentence Embedding Optimizer 则靠改进嵌入或检索逻辑来提效。Prompt Caching 的缓存机制则缓解超长上下文的压力，在性能与资源消耗之间找平衡。

校正技术能在检索和生成环节纠偏，让输出更贴合事实和标准，从而提升 RAG 的可靠性。不过校正会增加系统复杂度和算力开销，尤其在需要深度语义分析时更明显。

经过检索后处理送入生成器的信息会更干净精炼，质量明显提升。

### 8.2 用输出解析控制格式

有些场景对格式要求很严，比如 Agent 需要调用函数时，就必须得到结构化输出。这时提示要写明期望格式，如列表、字数限制、结构要求等。若模型格式不准，还需进一步引导。

LangChain 和 LlamaIndex 都提供组件把模型输出规范化，适配不同业务需求。

#### 8.2.1 LangChain 输出解析机制

LangChain 提供了一组 OutputParser 组件来解析模型输出。

- StrOutputParser：默认解析器，直接返回文本。
- JSONOutputParser：确保输出符合 JSON 规范。
- PydanticOutputParser：基于 Pydantic 做复杂结构解析。
- RegexParser：用正则提取关键内容。
- StructuredOutputParser：基于 JSON Schema 解析结构化数据。
