## **4.3 模型权重**

README_WEIGHTS.md 详细说明了 DeepSeek-V3 权重文件的组织方式与加载规范，并涵盖了 FP8 权重的量化设置与反量化方法。对理解模型的权重布局与量化策略很有帮助，也方便开发者在落地时正确加载使用。

### **4.3.1 权重构成**

DeepSeek-V3 的权重由主体部分与 MTP 模块两部分构成。主体包含输入输出词嵌入与 61 个 Transformer 隐层，总规模达到 671B；MTP 则额外增加预测层以强化多 token 预测能力，其参数与主体独立。

1．主体权重
（1）构成：输入/输出词嵌入加完整的 61 个 Transformer 隐层。
（2）规模。
● 总体参数：671B。
● 实际激活参量：36.7B，含 0.9B 词嵌入与 0.9B 输出头。
（3）结构要点。
● 词嵌入：model.embed_tokens.weight。
● Transformer 隐层：model.layers.0 至 model.layers.60，共 num_hidden_layers 层。
● 输出部分：model.norm.weight 与 lm_head.weight。

2．MTP 模块
（1）构成：由 num_nextn_predict_layers 字段定义，本模型设为 1。
（2）规模。
● 独立参数：11.5B，不含共享的 0.9B 词嵌入与 0.9B 输出头。
● 激活参量：2.4B，含共享的 0.9B 词嵌入与 0.9B 输出头。
（3）结构要点。
● embed_tokens：与主体词嵌入共享。
● enorm & hnorm：用于推测解码的 RMSNorm 参数。
● eh_proj：对归一化结果进行降维投影的参数。
● 额外 Transformer 隐层：model.layers.61.self_attn 与 mlp，结构与主体隐层一致。
● shared_head：与主体输出头共享。

### **4.3.2 加载规范**

DeepSeek-V3 的权重加载遵循特定规则，保证主体与 MTP 模块被正确初始化。

1．主体权重加载
依赖 config.json 中的 num_hidden_layers。流程如下。
（1）读取配置文件：先读取 config.json，获取 num_hidden_layers。
（2）确定层数：按该值确定 Transformer 隐层数量。例如 num_hidden_layers 为 61，则主体含 61 层。
（3）载入权重：按确定的层数从权重文件读取输入/输出词嵌入及全部 Transformer 隐层权重。

2．MTP 模块加载
依赖 num_nextn_predict_layers。流程如下。
（1）读取配置文件：读取 config.json，获取 num_nextn_predict_layers。
（2）确定模块数量：按该值确定 MTP 模块数。例如值为 1，则存在 1 个模块。
（3）计算层 ID：MTP 模块的层 ID 紧随主体之后，起始层 ID = num_hidden_layers。例如 num_hidden_layers 为 61 且 num_nextn_predict_layers 为 1，则层 ID 为 61。
（4）载入权重：按计算出的层 ID 读取额外的 Transformer 隐层及相关参数。

### **4.3.3 FP8 权重**

FP8 权重采用 8 位浮点格式，用于深度学习模型的高效存储与计算。可把显存需求减半，同时显著提升吞吐，而对精度的负面影响极小。

DeepSeek-V3 原生支持 FP8 格式，采用 128×128 块缩放以优化存储与计算效率。FP8 权重文件通过 quantization_config 描述量化方式，确保低精度计算下仍保持性能与精度。

1．FP8 配置
权重文件引入 quantization_config 字段描述量化方法。示例配置：

[PRE2]

要点说明：
● 量化格式：quant_method 设为 fp8，fmt 设为 e4m3，对应 FP8 的 e4m3 格式，在 PyTorch 中即 torch.float8_e4m3fn。
● 权重块大小：weight_block_size 设为 [128, 128]，表示以 128×128 块处理。
● 激活量化方案：activation_scheme 设为 dynamic，采用动态激活量化。

2．反量化方法
FP8 权重文件包含 weight_scale_inv 字段，存储每个权重块的反量化尺度。
● 存储方式：weight_scale_inv 以 float32 张量形式与权重数据一同保存，保证反量化精度与效率。
● 反量化公式：若权重块未对齐到 128，则先零填充至 128，量化后再移除填充。反量化过程如下：

● 运行时操作：通过反量化 FP8 权重，可实现每个 token、每 128 个通道的在线量化。细粒度量化保证低精度下性能与精度，并提升计算效率与内存利用率。

注意
FP8 量化在效率上优势明显，但也可能引入量化误差。实际应用中需根据任务与模型要求权衡精度与效率。

总的来说，DeepSeek-V3 通过原生支持 FP8、128×128 块缩放与动态激活量化，实现了高效存储与计算。反量化借助 weight_scale_inv 记录每个块的尺度，维持低精度下的精度与性能，显著降低显存占用与计算成本。

## **4.5 模型架构**

文件 model.py 实现了 DeepSeek-V3，基于 Transformer 构建，融合 MLA、MoE 并引入 MTP。

### **4.5.1 DeepSeek-V3 架构概览**

模型在传统 Transformer 基础上，通过 MoE 与定制注意力扩展容量，提升灵活性，并支持分布式训练与低精度计算，为大规模语言模型的高效训练推理提供保障。

1．基础架构
● Transformer 编码器：多层编码器，每层含自注意与前馈网络，负责深度特征提取。
● 层数与隐藏维度：61 层 Transformer，隐藏维度 7168，提供强表达能力。

2．MLA
● 低秩压缩：将注意力键值压缩为低秩潜在向量，降低推理内存占用。
● 查询压缩：对查询同样做低秩压缩，减少训练激活内存。
● 旋转位置嵌入 RoPE：支持解耦的查询与键，增强位置敏感性。

3．MoE 架构
● 专家数量与分布：共 14,906 个专家，每层 257 个专家，含 1 个共享专家与 256 个路由专家，实现参数灵活分配。
● 路由专家：每个 Token 选择 8 个路由专家处理，实现知识深度挖掘。
● 共享专家：每个 Token 均使用 1 个共享专家，提供通用知识与稳定性。

4．MTP
● 多 token 预测：模型可预测每个位置的多个后续 token，增加训练信号密度，加速训练。
● 顺序预测：保持因果链完整，确保生成序列连贯与逻辑性。

5．参数与训练
● 总参数量：671B 总参数，每个 token 激活 37B，具备卓越表达与知识储备。
● 训练策略：采用 AdamW 优化器，预训练最大序列长度 4K，在 14.8T token 上训练，充分学习语言多样性。

6．推理与部署
● 硬件部署：部署于 H800 集群，采用预填充与解码阶段分离策略，保证在线服务质量与吞吐。
● 负载均衡：推理阶段采用冗余专家部署，确保各 GPU 处理 token 数相近，提升效率。

DeepSeek-V3 通过上述技术与架构设计，实现高效长序列处理、负载均衡与多 token 预测，在性能与效率上优于多数开源模型，并接近领先闭源模型。
