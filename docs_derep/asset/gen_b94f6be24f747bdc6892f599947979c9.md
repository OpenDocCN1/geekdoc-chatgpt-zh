主机跑得快，外设跑得慢，速度落差很容易丢数据。接口里通常会放一个数据寄存器或锁存器充当中转站，把信息先接住再分发。靠这个保持作用，主机和外设的速率冲突被削弱，也为批量传输提供了前提。

### (3) 控制与监视
I/O 接口既能接收 CPU 发来的命令和控制信号去指挥外设，也能把外设的工作状态以状态字或应答信号的形式回传。双方通过握手配合，保证输入输出动作在时间上同步。

## 3. I/O 接口的基本结构
一个接口电路里一般包含若干可被 CPU 读写的寄存器，统称 I/O 端口。CPU 通过这些端口与外设互换信息，每个端口像存储单元一样拥有唯一地址，部分端口线直接连向外设。

数据、状态、控制三类信息都走数据总线，但性质不同所以分端口传送。一个外设常占用多个端口，比如数据端口、状态端口、控制端口。CPU 对外设的操作本质上就是通过 I/O 指令读写对应端口：状态端口读出的是状态信息，控制端口写入的是控制信息，只有数据端口才真正完成数据的交换。不同外设的端口使用策略可以不一样，既可以各自独立，也可以把位数少的控制或状态信息合并到同一个端口共享。

接口的外特性体现在引脚信号上。面向 CPU 的一侧主要是数据线、地址线、控制线，与存储器连接方式类似，关键要处理好地址译码。面向外设的一侧信号则五花八门，功能定义、时序、有效电平各异，必须在了解外设原理和工作特点后才能正确使用。

## 4. I/O 端口的编址方式
CPU 访问内部存储器或 I/O 端口都靠地址总线，编址方式主要有两种：端口与存储器分开编址，和端口与存储器统一编址。

### (1) I/O 端口独立编址，也称为直接 I/O 映射的 I/O 编址
这种方式把端口地址空间和存储器地址空间分开，互不占用。Z-80/Z8000、i8080/8086/80X86 系列都采用这种方式。

8086 访问存储单元可用 A19～A0 全译码，共 1MB，范围 00000H～FFFFFH；而 I/O 端口只用 A15～A0，可得到 64K 端口地址 0000H-FFFFH。因为两者独立，用户可以把存储器扩到最大而不用为端口预留空间。这种方式需要专门的 I/O 指令，CPU 对端口和存储器用不同的控制线选择，如 MEMW、MEMR，接口电路相对复杂。

优点是专门指令操作端口，容易区分是访问存储器还是外设，程序可读性好；端口地址空间独立且通常小于存储空间，译码电路简单，且允许地址重叠而不混淆。

### (2) I/O 端口与存储器统一编址，也称为存储器映射的 I/O 编址
这种方式从存储器空间划出一块给 I/O 设备，把端口当作存储单元访问，不设专用 I/O 指令，部分访存指令也可用于端口。Motorola 系列、Apple 系列等采用此法。

优点是使用访存指令操作端口，指令种类多功能全，不仅能输入输出，还能对端口内容做算术逻辑运算、移位等；端口编址空间可较大，对大型控制和数据通信系统很有意义。

## 5. I/O 端口地址的分配
设计接口时必须清楚系统的端口地址分配，才能把新设备接入。以下以 IBM-PC/XT 为例。

8086 访问 I/O 端口可用 A15～A0，可寻址 64K 端口，但 PC/XT 实际只用低 10 位 A9～A0，所以可寻址范围只有 1K，即 000H-3FFH。A9 决定端口所在位置：A9=0 寻址主机板上的 512 个端口，A9=1 寻址 I/O 卡上的 512 个端口。其中 A9～A5 通过 74LS138 译码产生各接口芯片的片选信号，译码前提条件是...为高电平（低电平时表示由 DMA 控制器送出的地址有效），表明此时 CPU 掌管总线。A4～A0 交给 8255/8259/8253/8237 等芯片内部进行译码，用来选中芯片的不同端口或寄存器。

## （二）简单的 I/O 接口电路
从外设送数据进 CPU 的叫输入接口，送数据到外设的叫输出接口。不同设备的接口复杂度差别很大。三态缓冲器和数据锁存器结构简单、使用方便，常用来接功能简单的外设；但功能有限，复杂需求往往要用到可编程接口芯片。

### 1. 数据输入接口
输入设备都要经数据总线向 CPU 传数据，若直接连上总线不做隔离，总线数据会混乱，所以必须缓冲隔离。大多数外设自带数据保持能力，只用三态门缓冲即可。

三态指输出有高电平、低电平和高阻态三种。CPU 读数时，先在使能端加有效电平，三态门导通，外设数据被读入，同时其他输入设备被隔离到总线之外。使能撤除后三态门断开，输出成高阻，外设脱离总线，总线可供别的设备使用。

74LS244 和 74LS245 是常用数据缓冲器，均可提升总线驱动能力。74LS244 为单向缓冲，74LS245 为双向缓冲。二者各由 8 个三态门组成，有 1G、2G 两控制端，各控 4 个门。控制端有效为低电平时对应门导通，否则高阻。实际使用可把两个控制端并联，用一个信号同时控制 8 个门。

用三态缓冲做输入接口时，因为没有锁存功能，要求外设数据在 CPU 读完前保持稳定。

### 2. 数据输出接口
数据总线是 CPU 与外设的公共通道，CPU 写数据给慢速外设时必须考虑速度配合。CPU 送到总线的数据只能维持几微秒，对慢外设来说几乎一闪而过，所以输出接口必须有锁存能力。CPU 的数据先锁存在锁存器里，一直保持到外设取走。

输出接口常用带存储能力的双稳态触发器实现。最简单可用 D 触发器搭建。74LS273 含 8 个 D 触发器，有 D0～D7 输入、Q0～Q7 输出，CR 为低电平有效的复位端，CP 为时钟输入，脉冲上升沿把 Dn 锁存到 Qn 并保持到下一个上升沿。

## （三）CPU 与外设间的数据传送
CPU 与外设的数据传送分两段：CPU 与接口之间、接口与外设之间。不同外设对内容和服务质量要求不同，所以传送方式不同，控制方式和接口结构也随之变化。常见方式有程序控制和中断传送。

### 1. 程序控制的输入/输出方式
通过程序执行 I/O 指令实现 CPU 与外设信息交换，传送时机事先确定，可按需把指令插入程序。按外设要求又分为无条件传送和查询传送。

#### (1) 无条件传送方式
结构简明，要求外设始终处于就绪状态，可随时收发。外设为接收方时 CPU 不检查状态直接送数，若外设来不及取走，下一个数据会覆盖旧数据造成丢失。外设为发送方时，CPU 发出 IN 指令后外设必须已准备好数据，否则读到错误。

适用范围很窄，只能用于简单开关量。比如读取 DIP 开关状态，或向七段 LED 数码管写显示码，外设始终空闲，CPU 需要时随时交换。可见该方式要求主机与外设同步，只能用于极简单的输入输出。

#### (2) 查询传送方式
适用于主机与外设异步工作。CPU 通过不断查询外设状态判断是否就绪，再转入服务程序交换数据。若未就绪就继续轮询。外设就绪对输入指已有数据可读，对输出指已准备好接收新数据。I/O 操作由 CPU 主动发起，外设被动响应。

接口除数据缓冲端口外，还需状态端口。CPU 通过数据端口交换数据，通过状态端口读取状态。

输出查询类似，先查状态端口的 BUSY，若为 0 表示空闲就绪，CPU 通过数据端口写出，否则继续查询。写出后置忙触发器为 1，阻止新数据写入；输出完毕外设发回 ACK，忙触发器清零。

查询方式硬件简单、软件易实现、传输可靠，但 CPU 要耗费大量时间轮询，效率不高。若系统外设多，实时性要求高，或某外设故障导致长期不就绪，会出现死循环，通常需加超时判断。因此只适合 CPU 负载轻、外设少且任务简单的场合。

### 2. 中断传送的工作方式
查询让外设被动等待，浪费 CPU 时间。中断方式让外设主动请求服务。外设就绪后通过接口发出中断请求 INTR，CPU 收到请求后中断当前程序、保护断点，转去执行对应中断服务子程序，服务完毕恢复断点继续原程序。外设未就绪时 CPU 可处理其他事务，效率更高。

中断输入典型流程：输入装置就绪发出选通信号，数据被暂存到锁存器，同时中断请求触发器置 1，向 CPU 发出 INTR。若中断开放，CPU 在指令结束时响应，发出中断响应信号，外设把中断类型码放到总线上，CPU 跳转到对应服务程序，通过输入指令读数据端口并清中断请求。服务结束后自动返回。
