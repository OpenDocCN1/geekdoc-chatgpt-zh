要让大模型训练更快，业内最常用的两种并行思路是数据并行和模型并行。数据并行更适合数据规模很大、模型体量中等的场景，把整份数据集拆成多个子集交给不同 GPU 同时处理，从而缩短整体耗时。模型并行则针对参数极其庞大、单卡装不下的模型，把网络拆成若干块分散到多张卡上协同计算。工程实践中，通常会依据具体任务特征和可用硬件来挑选或组合策略，争取最优的训练性能。

**3.3.2 内存优化**

在大模型训练里，显存管理直接决定能不能跑起来。参数量和结构复杂度一起推高显存需求，稍有不慎就会 OOM。做好显存优化，既能提升训练效率，又能避免溢出，更能把硬件资源用足。下面是常见的几类做法。

**1. 梯度累积**

梯度累积特别适合 batch size 被显存卡住的场景。模型不再每一步都立刻更新，而是把若干小 batch 的梯度先累加起来，达到阈值后再统一更新参数。这样每次迭代只需保存一个小 batch 的中间结果，显存占用明显下降。缺点是参数更新被延迟了，整体迭代节奏变慢，但在大模型训练里这种延迟通常可以接受。

**2. 混合精度训练**

混合精度训练同时使用 FP32 和 FP16。FP16 占用的显存更少，能显著压缩内存开销；配合 loss 缩放和数值校正，又能保证训练稳定性和精度不掉。主流 GPU 均已原生支持半精度运算，这让混合精度成为性价比很高的显存优化手段。

**3. 内存池技术**

频繁申请释放显存会带来额外开销。内存池通过提前分配并复用内存块来降低分配成本。训练过程中常用到的内存块一次性申请好，需要时直接从池子里取，用完归还，减少管理开销。图 3-10 所示为 Python 语言中使用内存池技术管理内存的示意，其中 usedpools 为已使用的内存池，freepools 为空闲的内存池，freeblock 为用完后释放的内存块， untouched 为未使用的内存空间 free 为已释放的内存空间，allocated 为已分配的内存空间。

图 3-10 Python 语言中使用内存池技术管理内存的示意

**4. 优化数据加载和预处理**

数据加载和预处理本身也会消耗大量显存。通过把增强操作改成在线生成，而不是预先把所有增强样本全塞进内存，就能省不少空间。换成更高效的数据格式和压缩方式，也能进一步降低占用，提升流水线效率。

**5. 分批加载模型参数**

当模型整体太大无法一次性塞进显存时，可以采用分块加载。把模型拆成若干部分，每次只把当前计算所需的参数搬到 GPU，算完后卸载再换下一批。这种做法需要精细的参数调度与同步，才能保证训练正确且高效。

**3.3.3 计算优化**

计算效率决定了训练时间有多长。优化计算流程可以更好地发挥 GPU 算力，减少无效开销，从而整体提速。以下策略在实际中较为常用。

**1. 算子融合**

算子融合把多个连续操作合并成一个复合算子，减少中间结果的读写次数。卷积、激活、BatchNorm 等步骤合并后，数据在显存中的搬运频率下降，计算更连贯。TensorFlow、PyTorch 等框架普遍提供融合接口，开发者可通过配置或 API 开启。

**2. 使用高效的计算库和算法**

现代 GPU 自带针对深度学习的加速库。例如 cuDNN 用来加速卷积和池化，cuBLAS 负责矩阵运算。调用这些库能显著提升算力利用率。结合更先进的算法和数据结构，还能把计算再做一层优化。

**3. 优化数据布局和访问模式**

内存访问方式直接影响缓存命中率和带宽利用。采用连续的内存布局存储参数和特征，减少访问冲突；调整访问顺序、做循环展开等，也能让 GPU 读取更顺滑，计算开销随之下降。

**4. 利用 GPU 的并行和异步计算能力**

GPU 天生适合大规模并行。增大 batch、动用更多卡或调整架构都能提升并行度。同时借助异步能力，让 GPU 计算时 CPU 去做数据预处理、评估等任务，实现流水线并行，资源利用率更高。

**5. 监控和调优计算性能**

优化离不开量化。借助 TensorFlow Profiler、PyTorch Profiler 等工具定位训练中的性能瓶颈，再针对性调整参数、数据管线或换用更快的库。图 3-11 所示为带有 TensorBoard 的 PyTorch Profiler 界面，其中可以很方便地查看和统计模型训练时各环节的执行开销。

[PRE1]

图 3-11 带有 TensorBoard 的 PyTorch Profiler 界面

**3.3.4 GPU 优化总结**

大模型训练的 GPU 优化主要围绕数据并行、模型并行、显存优化和计算优化展开。不同任务、不同硬件组合下，最优方案并不相同，需要根据实际情况权衡选择。随着 GPU 架构和框架的演进，新的优化手段也会不断出现。
