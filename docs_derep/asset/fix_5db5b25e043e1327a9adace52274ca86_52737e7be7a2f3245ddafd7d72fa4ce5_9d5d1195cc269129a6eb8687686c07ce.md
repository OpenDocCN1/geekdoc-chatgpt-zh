本章先介绍 LCEL 与 LCEL 链，再讨论对话历史的维护、聊天消息的持久化及基础构件，最后演示如何校验可运行对象。

### 13.1 LCEL

LCEL 是 LangChain 提供的类 Linux 管道式表达式语法，便于拼装 LLMChain，实现对话调用、检索增强生成等能力。

#### 13.1.1 认识 LCEL

借助 LCEL 可以把多条子链合并成一条新链，简单指令加模型或复杂编排都可胜任。

主要体验提升如下：

- 首块 token 延迟更低：基于 LCEL 的链可把 LLM 原始 token 直接喂给流式解析器，解析速度几乎追上模型本身的输出节奏。
- 同步异步兼顾：LCEL 同时提供同步与异步接口，适合在 Jupyter 里原型，也适合部署到 LangServe 服务器，既保性能又支持并发。
- 并行执行被自动优化：链中存在可并行环节时，LCEL 会自行调整执行路径，同步或异步调用都能压低时延。
- 支持重试与回调：链的任意节点都可挂载重试和回调，提升大规模运行的可靠性。
- 可透传中间结果：复杂链支持流式输出中间步骤，便于实时通知与调试，该能力在 LangServe 上同样可用。
- 自动模式校验：LCEL 会根据链结构推导出 Pydantic 与 JSONSchema，用于校验输入输出，是 LangServe 的关键基础。
- 自动写入 LangSmith：随链复杂度增加，LCEL 会把各步骤自动记录到 LangSmith，提升可观测与可调试性。
- 与 LangServe 无缝衔接：用 LCEL 构建的链可直接集成到 LangServe，实现顺畅上线。

#### 13.1.2 LCEL 的核心特性

- 统一的调用面：每个 LCEL 对象都实现了 Runnable 接口，该接口定义了 invoke、batch、stream、ainvoke 等通用调用方式，链式结构自然获得批处理与流式能力。
- 丰富的原语：LCEL 提供了一组基础原语，让建链、并行化、添加备选、动态配置内部元素变得简单。

#### 13.1.4 Runnable 接口

为了简化自定义链的构建，LangChain 提供了 Runnable 接口，统一定义与调用方式。

- stream()：以流式返回响应片段。
- invoke()：对输入执行链。
- batch()：对输入列表执行链。

异步版本：

- astream()：异步流式返回片段。
- ainvoke()：异步执行单条输入。
- abatch()：异步执行输入列表。
- astream_log(): 在返回最终结果的同时流式返回中间步骤。

#### 13.1.5 流式处理

流式处理对 LLM 应用的响应性至关重要。

LangChain 的核心基础组件如 LLM、解析器、提示器、检索器和代理均实现了 Runnable 接口。该接口提供：

- sync stream() 与 async astream()：默认流式实现，从链中流式传输最终输出。
- async astream_events() 与 async astream_log()：可从链中流式传输中间步骤及最终输出。

#### 13.1.6 基于输入的动态路由逻辑

路由允许构建非确定性链，其中每一步的输出决定下一步的执行，为 LLM 交互提供清晰结构和一致性。

常用路由方式：

- RunnableLambda()：可有条件地返回可运行对象，是推荐做法。
- RunnableBranch()：可实现路由逻辑。
