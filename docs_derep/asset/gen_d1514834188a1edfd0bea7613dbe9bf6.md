要在安装 OpenAI 库时走代理，可按下面顺序操作：

1. 打开终端或命令行窗口。
2. 配置 HTTP 与 HTTPS 代理。执行以下两条指令：

set HTTP_PROXY=http://YOUR_PROXY_IP:YOUR_PROXY_PORT

set HTTPS_PROXY=https://YOUR_PROXY_IP:YOUR_PROXY_PORT

3. 将 YOUR_PROXY_IP 和 YOUR_PROXY_PORT 替换成你实际使用的代理服务器地址和端口。
4. 随后运行安装命令：

pip install openai==0.28.1

5. 若还需要其他配套库，可用类似的 pip 指令继续安装。

按以上流程设置后，就能在代理环境下顺利完成 OpenAI 库的安装。

### 4.1 RAG技术体系介绍

本节聚焦 RAG 技术整体框架，梳理其运行机理、关键构成以及工程落地方案。RAG 是一种把信息检索与大模型生成结合起来的智能问答范式，既能提升回答的准确性与知识丰富度，又能有效缓解大模型的幻觉问题，常见于知识库问答、企业智能助手等场景。

本节以搭建本地化 RAG 系统为主线，依次拆解文本向量化、文档加载与分段、向量库构建、检索策略设计以及大模型问答调用等核心环节。同时引入主流 API 模型作为生成组件，帮助读者理解 RAG 框架与大模型的高效对接方式。

#### 4.1.1 RAG简介

大语言模型在生成文本时容易出现幻觉或偏差，具体表现为：

- 信息误导：生成内容可能基于不准确或过时的信息。
- 知识滞后：模型无法触达最新资讯，尤其在专业领域更明显。
- 推理不足：面对复杂推理任务时，输出效率与准确性偏低。

RAG 的出现正是为了解决这些痛点。它先从知识库中检索与问题相关的资料，再基于检索结果生成答案，从而显著提升输出的准确性和相关性。该方法加快了知识更新的速度，也增强了结果的可追溯性，让 RAG 在实际应用中更可靠、更易落地。

#### 4.1.2 RAG系统的核心组成模块

构建 RAG 模型需要以下 5 大核心模块。

1. 向量化模块：把文档片段转为向量表示，为后续检索做准备。
2. 文档加载与切分模块：负责读取原始文档并切分为便于处理的片段。
3. 数据库模块：存储文档片段及其对应的向量。
4. 检索模块：依据用户查询召回相关文档片段。
5. 生成模块：调用语言模型基于检索信息生成回答。

#### 4.1.3 文本向量化模块创建

在 NLP 与机器学习里，Embedding 是把文本映射为数值向量的常用手段。通过向量化可以衡量文本间的相似性，进而应用于搜索、分类、推荐等多种任务。OpenAI 近期发布的第三代 Embedding 模型在性能、成本和多语言支持上均有提升。下面介绍该系列模型及其调用方式。

##### 1. OpenAI第三代Embedding模型简介

Embedding 本质上是将文本字符串转化为浮点数列表形式的向量，通过向量间距离判断文本相关性，距离越近相关性越高。

常见应用包括：

- 搜索：按相关性排序结果。
- 聚类分析：依据相似性分组文档。
- 个性化推荐：基于相关内容推荐项目。
- 异常检测：找出相关性偏低的异常文本。
- 多样性评估：分析文本集合的相似分布。
- 分类任务：按与标签的相似度归类。

OpenAI 推出的 text-embedding-3-small 与 text-embedding-3-large 性能更强、语言覆盖更广，分别默认生成 1536 维和 3072 维向量。用户还可通过维度参数在不损失语义的前提下优化存储与计算开销。
