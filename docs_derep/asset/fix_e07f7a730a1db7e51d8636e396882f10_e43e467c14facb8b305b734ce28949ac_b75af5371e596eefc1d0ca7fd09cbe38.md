## 4.2 智能网联底层报文的定义与结构
各阶段智能网联应用落地的根本，在于对基础报文进行定义与解析，以满足 V2X 互联需求。

### 4.2.1 数据集的分层与编码
消息层数据集合采用 ASN.1 抽象语法记法进行形式化描述，遵循 消息帧-消息体-数据帧-数据元素 的层层嵌套组织方式。编解码遵循非对齐压缩编码规则 UPER。帧是单个应用层报文的统一封装，也是编解码的唯一操作对象。帧由不同类别的体构成并支持扩展；体是最基础的五类报文；单元由若干数据单元或数据类型组合而成，具有特定实际意义，是体的组成部分；元素是体或单元的构成部分，由基础数据类型派生，具有物理意义。

### 4.2.2 五类核心报文解析

#### 1. 基础安全报文 BSM
##### 1）定义
BSM 是应用层使用最广泛的报文，用于车辆间交换安全状态数据。车辆通过广播自身实时状态向周边告知自身情况，以支撑各类协同安全业务。相关情境见图 4.2。

[PRE3]

图 4.2 BSM 应用情境

##### 2）组成剖析
作为网联汽车发送与广播的报文，BSM 需包含报文编号、车辆编号及发送时刻以实现区分与识别。

BSM 还需承载车辆自身属性。车辆出厂即具备尺寸与类型信息，类型可按车型如乘用车、货车定义，也可按动力形式定义。行驶时的实时运动状态是 BSM 的重要部分，可用三维位置、速度、航向概括，并延伸至控制层面，涵盖挡位、方向盘转角、四轴加速度、制动系统状态等。

其中三维位置为经度、纬度与高程；挡位包括空挡、驻车挡、前进挡、倒挡；四轴加速度包括纵向、横向、垂直加速度及横摆角速度；制动系统状态涵盖踏板踩下、车轮制动、牵引力控制、ABS、车身稳定、制动助力及手刹共 7 项。这些信息与速度、航向密切相关，故需纳入基础安全报文。

除必要自车信息外，部分精度信息有助于提升智能性与风险预判，包括发送时刻精度、实时位置精度、定位精度以及由车速精度、航向精度、转角精度构成的运行状态精度。该类精度决定了智慧交通中基于报文与算法得到的交通参与者实时信息的准确性，对交通组织管理意义重大。

此外 BSM 还包含车辆安全辅助信息集合与紧急车辆辅助信息集合。前者由特殊事件状态、历史轨迹、路径预测、灯光状态等组成；后者用于告知周边本车处于特殊作业状态，如警车、消防车、救护车等，需获得优先或避让，包含特殊行驶状态、警笛与指示灯使用等。

图 4.3 给出 BSM 核心构成，实线为必选，虚线为可选。

[PRE4]

图 4.3 BSM 主体结构

##### 3）应用
实际使用中 BSM 更像广播者，持续将自车状态推送给周边以交换安全状态并支撑业务。

例如前向碰撞预警、路口碰撞预警、紧急制动预警等情境，两车互收互解 BSM 中的时间、位置、速度、航向、车身尺寸等基础信息即可完成预警计算，结合转向灯判断可实现盲区/变道预警。

BSM 除基础信息外还含安全辅助信息及紧急车辆附加信息，涉及特殊状态位、灯光信息及紧急车辆状态，灵活应用可实现异常车辆预警、失控预警、紧急车辆提醒等。

BSM 支持兼容性扩展，如 T/CSAE158-2020 在 TD/T3709-2020 定义基础上丰富了自动驾驶车辆特有信息，提供更精确的车辆与行驶信息，支撑路侧协同的车道级通行等。

#### 2. 地图报文 MAP
##### 1）定义
MAP 由路侧单元广播，向车辆推送局部区域地图信息，包括路口、路段、车道信息及道路间连接关系。单个 MAP 可包含若干路口或区域数据。相关情境见图 4.4。

[PRE7]

图 4.4 MAP 应用情境

##### 2）组成剖析
与 BSM 类似，MAP 需具备报文编号与发送时间以区分不同广播。编号配合时间戳可防重放攻击，时间戳通常取自 GPS 后写入。地图中路段、车道、路口均由节点构成，故 MAP 包含地图节点列表，节点是地图最基本单元，可为路口或路段起点/终点。

为区分节点，引入节点 ID 与节点名。节点位置是构成地图的关键，为减小数据量，采用以地图中心节点为基准，其他节点用中心坐标叠加偏移量表示。相邻两节点可确定一条有向路段，起点记为上游节点，终点记为下游节点。定义路段时以下游节点为参照，记录其上游路段列表。

路段通常包含路段名与车道信息。映射到报文格式时，上游路段首先包含上游节点 ID 与路段名以确认起点与名称。路段常含多条车道，需定义宽度、限速、允许转向行为、车道属性、上游车道与下游车道的连接关系等。

图 4.5 给出 MAP 核心构成，为层层嵌套形式，实线为必选，虚线为可选。

[PRE8]

图 4.5 MAP 主体结构

##### 3）应用
MAP 用于描述道路信息，在智能网联应用中扮演服务者角色，为业务落地与预警触发提供位置基准。例如路侧设施可下发 MAP 给周边车辆，提升环境感知与定位精度，便于规划行驶路线。

MAP 还可与 SPAT 结合为车辆提供前方信号灯实时相位。在闯红灯预警情境中，若前方大车遮挡或恶劣天气影响视线，应用会检测车辆位置与速度，预测车头通过停止线时信号灯状态并预警。该过程用到 MAP 中的路口起止位置与 SPAT 中的相位状态。

#### 3. 路侧信息报文 RSI
##### 1）定义
RSI 即 Road Side Information，指路侧单元向车载单元发布的交通事件信息与交通标志信息。相关情境如图 4.6 所示。

其中交通事件信息当前遵循 GB/T29100-2012；交通标志信息当前遵循 GB5768.2-2009。RSI 可打包若干事件信息或标志信息，同时包含发送路侧单元编号与参考位置坐标。

车载单元依据自身定位与行驶方向，以及报文提供的时效信息与关联区域/路段范围，判定事件或标志的生效区域。

[PRE10]

图 4.6 RSI 应用情境

##### 2）组成剖析
路侧信息由 RSU 提供，报文包含序号与发送时间，同时包含 RSU ID 以区分发送方。为便于描述作用范围，提供作用范围内的参考三维位置坐标，报文内所有位置偏移均基于该参考坐标计算，真实坐标为偏移叠加参考坐标。

道路交通中的事件信息与标志信息由路侧信息承载。交通事件 RTE 可能包含若干，其描述涉及信息源、发生区域、时效、优先级、置信度及影响区域，除事件 ID 外还可用文本进一步定义。区域大小定义为以中心点为圆心的半径范围。

交通标志信息 RTS 同样具备 ID 与文字描述字段，可定义标志的位置、类型、起止时间、置信度、优先级等。

事件信息与标志信息均可通过关联路径及关联路段与 MAP 配合，帮助车载单元判定影响区域。

图 4.7 给出 RSI 核心构成，实线为必选，虚线为可选。

##### 3）应用
RSI 主要用于事件下发，向周边车载单元发布交通事件与交通标志信息。车载单元依据定位、行驶方向及报文提供的区域范围判定生效区域后向驾驶员推送。RSI 传递的是道路相关的预警或提示信息，不用于求救等安全类应用。

结合自车 BSM 与 RSI 中的位置与事件集合可进行道路危险状况提示，使行经车辆及时避让。RSI 中的标志集合结合 BSM 自身信息与 MAP 的路段车道信息，可应用于车内标牌提示。应用据此计算自车在路网中的位置并判断前方是否存在交通标识，若存在则在有效区域与时间段内点亮提示。也可对道路拥堵状况提示，帮助重新规划路线、缓解压力。

#### 4. 路侧安全报文 RSM
##### 1）定义
RSM 即 Road Safety Message。路侧单元通过自身感知识别手段，获取周边交通参与者包括路侧单元本身、车辆、非机动车、行人等的实时状态，并按本消息体格式整理后广播给周边车辆，支撑相关应用。

RSM 使车辆对周边环境的感知不再完全依赖 BSM。路侧传感器帮助车辆探测环境并通过 RSM 传递实时信息。

RSM 应用情境如图 4.8 所示。

[PRE13]

图 4.8 RSM 应用情境

##### 2）组成剖析
RSM 包含报文 ID 与发送 RSU ID。位置信息字段提供作用范围内的参考三维坐标，报文内所有偏移均基于该参考坐标计算，真实坐标为偏移叠加参考坐标。

RSU 获取路侧感知单元检测的周边交通参与者信息并组成参与者列表。该部分信息相当于 OBU 广播的自车信息，内容组成与 BSM 类似，只是信息由 RSU 感知获取后发送，部分只能由车辆自身提供的信息如制动状态无法体现在 RSM 中。

当参与者信息来源于 RSU 接收的 BSM 时，车辆 ID 需与 BSM 中一致。当报文包含非机动车、行人等时，可省略机动车部分字段。

图 4.9 给出 RSM 核心构成，实线为必选，虚线为可选。

[PRE14]

图 4.9 RSM 主体结构

##### 3）应用
RSM 主要对接路侧感知与边缘计算，用于道路事件识别，如事故、异常、异物闯入等。通过路侧感知识别技术获取周边交通参与者实时状态并整理为本消息体格式。RSM 使车辆感知不再仅依赖 BSM，可获得超视距感知。

在应用情境中，RSM 中的行人感知信息可用于弱势交通参与者碰撞预警，分前车遮挡盲区内行人碰撞与倒车视野盲区行人碰撞，可通过 RSM 提前提醒。
