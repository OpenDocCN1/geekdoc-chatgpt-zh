## 4.3 容器化部署的高可用分布式记忆方案

4.2.3 节在单节点数据库上完成了 Mem0 的本地验证。生产环境中单点故障风险很高，一旦实例宕机整个记忆系统就不可用。为满足企业级高可用、容错与横向扩展需求，本节介绍如何构建容器化分布式记忆架构，并改造历史对话复用代码以适配高可用模式。

### 4.3.1 架构设计与编排脚本

先完成架构设计，再编写 Docker Compose 脚本。

#### 1. 部署架构方案设计

Qdrant 原生支持分布式集群，多节点通过 P2P 协议组成逻辑集群，数据自动分片并多副本存储，可提升吞吐与容错。

官方建议集群节点不少于 3 个。因为共识机制要求多数派确认。若只有 2 个节点，其中一个永久失效后，剩余节点无法达成多数共识，写入与部分读取会被阻塞。3 个及以上节点可在单点故障时继续服务，并由健康节点完成数据恢复。

高频对话场景下 Qdrant 的读压力较大，因此前端引入 Redis 作为缓存，加速热点记忆召回。缓存策略为写失效、读回填。

- 写入记忆 `store_mem`：写库到 Qdrant 后立即清空该 `user_id` 在 Redis 中的缓存，避免读到过期内容。
- 召回记忆 `search_mem`：优先查 Redis，命中直接返回；未命中则去 Qdrant 查询并把结果写入 Redis 供后续复用。
