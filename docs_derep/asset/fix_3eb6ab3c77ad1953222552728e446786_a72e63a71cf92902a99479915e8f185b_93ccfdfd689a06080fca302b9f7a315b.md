# 让 AI 落地而不是摆设

艾美：把 AI 融进组织文化，用全员沟通提升认知和接受度，同时帮大家理清使用目的、边界和可选方案。企业还可以搭建内部学习渠道，让员工快速掌握各业务板块要点。^(4)

团队组建可以依托 IT 部门把数据科学和技术能力整合起来，也能由公司内部的专项小组主导。^(5)

克里斯：那些思维敏捷且富有创造力的人，通常会主动投身 AI 相关工作，因为他们渴望接触前沿技术。这类成员喜欢构思新东西、打造新产品、头脑风暴，并愿意尝试从未做过的概念。

正因为如此，人选挑选和项目管理方式会直接影响 AI 团队成败。这类人才需要足够的创新空间，排斥过度僵化的规则，也难以在受限环境中长期保持动力。

艾美：因此关键决策之一就是选定项目管理模式。组织若已有成熟做法，往往可以直接迁移到 AI 场景。

可参考瀑布式、敏捷、Scrum 这类迭代增量做法，以及看板。下面逐一对照。

瀑布属于连续线性类型，因历史久分而知名。排期常用甘特图，用条形展示里程碑及相关信息。管理风格高度结构化且缺乏弹性，图上每个任务必须完整走完团队才能进入下一步，部分工作可并行，依赖关系已预先写入。

## 四类开发模式对比

### 瀑布式

上手和管控比较直观，执行纪律强，文档与进度汇报天然内嵌。但模式僵硬，对变化反应慢，最终交付物要到后期才出现，反馈也被拖到尾声。^(6)

克里斯：与之不同，敏捷强调增量迭代，对需求随时间演变持开放态度，并在全程鼓励用户回馈。虽然是相对较新的做法，却因灵活与适应性迅速普及。

### 敏捷式

跨职能小组协同，按迭代推进。敏捷把可工作的成果作为进度标尺，最核心的是尽早、持续交付最小可行产品。

敏捷拥抱变化，因为变化本身写进方法里。目标在推进中不断明确并随需求调整。把工作拆成迭代，团队聚焦开发、测试与协作。每一步都邀请反馈，成果逐步显现。得益于用户与成员的持续回馈，产出往往能不断改进。

不过任务经常被重新排优先级，日程也常被快速变动，让计划变得难以把握。敏捷小组需要具备宽泛的知识与技能。^(7)

### Scrum

艾美：Scrum 是敏捷的子集，采用迭代开发模型。它使用 sprints，即团队完成一定工作量所需的短暂固定周期，通常一到两周。这让 Scrum 团队能以稳定节奏交付软件。

Scrum 项目倾向透明可见，全员清楚进展。因为没有专职项目经理，团队对一切负责。每个小组自行决定本 sprint 做什么，然后一起完成。变更在 Scrum 中很容易被吸纳。内部信任度高，Scrum Master 充当向导。^(8)

### 看板流

克里斯：Kanban 是实现敏捷的可视化框架。框架展示要生产什么、何时做、做到什么程度。概念建立在对现有系统做小步增量迭代之上。

看板使用一块板作为工具。过去可以用实体板、便利贴、纸张、磁铁列出待办。现在可以用软件实现。

实体板最简形式可分为“待办”“进行中”“已完成”三栏，按需可增列。每个便笺代表一项工作，被放到板上对应的状态栏里。看板很灵活、易懂，能优化工作流。另外，实体板必须实时更新，否则就失去作用。^(9)

最终，想法必须转化为行动，需要一个对个人、团队和组织都适用的流程。你选哪种流程其实不重要，只要能产生结果。

艾美：我们讨论了启动的必要性及原因，这是待解的问题。接下来是解决之道，即从技术和操作层面如何在生产过程中实现。

## 数据与AI的现实

### 数据乱、数据散

克里斯：之前我们详细谈过数据。如你所知，数据是 AI 的必需品，而且大多数 AI 都需要大量信息的快速供给。

艾美：在界定 AI 计划时，数据往往是非结构化的、分散在组织不同领域里。有必要对数据分类，并赋予某种结构使其可用。

[PRE0]

#### 人机协作的数据通道

克里斯：着手前，先问几个问题来厘清数据策略：我们需要哪些数据？如何访问？回收后怎么处理？需要保存多久？

艾美：我认为用例子说明更直观。假设某市市长成立工作组研究行人交通事故高发原因。AI 可以帮助发现诱因，不同 AI 能解决不同问题。每个路口都装了交通摄像头，记录已保存多年。

第一个计划是分析那些交通摄像录像，看能否找出导致行人意外的模式。这是大量完全非结构化的数据，视频可能超过 100 万小时。

克里斯：当前亟需解决的是，这些数据对找解法是否全部必需？没有事故的路口监控可被筛掉以减小数据集，也能用其他标准进一步筛选。

艾美：显然数据无需长期保存。交通摄像头视频经 AI 判断后就不再需要。

克里斯：访问数据可能只是收集、存储到超大磁盘或上传云端的环节。这会面临法律问题，如隐私问题。如果视频属于多方，如市政府、警察局，或私人公司，就需逐一联系并安排。

各部门、公司或政府机构的数据被存放在孤岛中——不同组织里的数据库彼此独立，每个数据库格式不同，甚至使用不同的数据库应用。例如一家公司可能用 Oracle，另一家用 Microsoft SQL，第三家用专有数据库。

艾美：一旦计划数据得到保护，就能构建 AI 引擎检查数据，找出涉及事故的案例和未涉及事故的案例。之后 AI 组件可查看精简后的数据集，判断行人的哪些行为导致事故概率升高。

克里斯：据此可提出相应对策。利用 AI 更好地同步交通信号灯，在特别危险的路口修建人行天桥，或在智能手机上向行人发出当前危险状况的警告。

艾美：另一个例子涉及黄瓜分拣，正如我们前面讨论的那样。你还记得那套 AI 方案吗？人工分拣黄瓜被自动化，从而把黄瓜分成不同类别。

克里斯：啊，对，黄瓜计划。这种情况下数据集相对小，由几千张黄瓜图像组成。数据存储和访问的问题远小于数百万小时的交通摄像头片段。

问题是，需要多少数据才够？什么情况下数据会太多？AI 方案不需要存储、去孤岛化分析以及不必要结构化数据。

### 实时处理的算力和吞吐

艾美：没错。在许多情况下，特别是在实时 AI 方案中，还必须考虑接收数据的数量和速度。帮助飞机在大型国际机场降落的实时 AI 应用需要快速处理海量数据。它可查看来自单架飞机、塔台、数十个雷达站、气象卫星等的信息。这对获取实时数据、去孤岛化、结构化后快速分析以帮助飞机着陆是一项重大努力。

克里斯：谈到实时 AI 应用访问大量数据，我们不如看看程序化购买在广告投放方面的实践，特别是在实时竞价方面。程序化广告是一种根据存储空间自动锁定客户的方法，而实时竞价则允许在网页加载时间内拍卖广告。^(10)这些方法使用 AI 在微秒内做出购买决策。

艾美：这让广告更贴合目标客户，对广告主和购买者都有用，因为不相关广告不会被展示。

克里斯：我们聊了数据与数据洞察的重要性。现在谈谈 AI 的技术层面，以及组织从何处开始。

## 技术落地的三层路径

### 接口与组件

艾美：无论公司是否新成立，基本做法有三种。我们称之为企业级、自定义等级和应用程序编程接口 API 或软件开发工具包 SDK。

克里斯：艾美，正如你所说的，API 是程序交互的接口，SDK 用于为特定平台开发应用。

艾美：谢谢，克里斯。创建企业 API 是为了执行特定任务或目的。它们易用，通常是预训练的，神经网络被隐藏。对没有强大机器学习背景的开发者很有用。这一层提供自然语言处理、数据分析、手写分析、知识分析等。

自定义方法提供了在标准企业级服务之外定制 API 服务的能力。这些需要训练，需要更多机器学习和 AI 知识。

API/SDK 提供了可用于构建定制化或企业级 API 的功能。对不可用的特定应用非常有用。

API/SDK 和自定义的一个例子是微软认知服务 Microsoft Cognitive Services，也称 Azure 认知服务 Azure Cognitive Services，它包含可在应用中使用的许多特定 AI 功能。已提供 API 包括计算机视觉、情感、内容审核工具、视频、面部识别等，目的是省去建立和训练客户 AI 模型的必要性。如果需要更深入的定制，也可使用 Microsoft 认知工具包 Microsoft Cognitive Toolkit。^(11)

另一个产品是 Adobe Sensei，它也提供多种选择，功能包括自动标记、看图说话、文本检测、图像质量、语义结构分析、异常检测和智能受众分割。^(12)

克里斯：从一个问题出发，朝着解决方向推进。AI 是通往解决方案的工具。有很多事需考虑，包括项目参与人员及其技能、专业和经验。选择一种能推动进展的流程，如 Scrum。数据可能是非结构化且孤立的，这种情况下需先清理数据以使其可用于 AI 项目。最后，需考虑用于 AI 的技术，这可能取决于团队人员的专业技能。

艾美：但现在，先让我们看看 AI 的安全、隐私和伦理主要关注点。

## 13. 安全隐私伦理的关键

克里斯：随着企业在战略上对 AI 的依赖性增强，安全必须一开始就摆在最前面。从庞大数据库到高速网络再到计算机系统，所有东西都必须在设计和构建时考虑到强大的安全策略。

AI 正成为企业、政府和个人成功的关键任务。目前正在设计和推出的许多举措涉及辅助决策过程，通过分析海量数据，产生可推动公司或政府进步的报告甚至建议。

### 企业防护

艾美：破坏企业和政府决策对攻击者来说优先级很高，不管他们参与工业间谍，还是针对单一民族独立国家的攻击。攻击者通过修改或控制输入 AI 系统的数据，并基于这些被控制和修改的数据做决策，如此不仅能访问决策过程，还能访问用于决策的机密数据或模型。

过去，应用运行在企业操作系统之上，如 OpenVMS、Linux、Unix 或 Windows。这些计算机通常被安置在由防火墙和安全程序保护的大房间或设施中。设施安全由企业负责，成败取决于直接负责人或顾问的行为。

[PRE1]

安全层

克里斯：时代已变，企业现在在云上运行 AI，这是一组不受他们控制的资源。云计算中的计算机和其他硬件通常在虚拟机上运行应用，比过去复杂得多。

为了使其更复杂，许多企业采用混合模式，部分资源本地存储，其他在云上，甚至跨多个云提供商。这引入许多潜在安全问题，依赖不同地区不同企业采取的安全策略。任何一个弱点都可能导致部分系统或整个系统被入侵。

艾美：像亚马逊、IBM 和谷歌这类云服务商会将设备维护在多个加固且高度安全的地方，并将最佳安全实践作为准则。在使用云解决方案前，需全面调研这些企业在安全方面采取的措施和技术以确保平台安全。

### 底层设施安全

克里斯：本地托管基础设施的安全性是企业的责任，也是企业成功的重要前提。安全不是事后附加的东西。训练有素的专业安全人员必须以安全为中心，强制执行安全准则并审核合规性。此外，必须定期进行入侵测试和其他形式测试。

最好的做法是从一开始就将安全考虑进基础设施。重新调整可能耗时又易错，因为现有应用也可能已考虑安全性。如果我们在设计、创建和安装好应用后再考虑安全，挑战会更多。

艾美：强安全标准从基础设施开始。机房设备在物理上是否安全？门上是否有锁，是否仅限授权人员进入？

克里斯：是的，这很重要，因为攻击者若能直接进入计算机系统，就更容易实施破坏并造成伤害。

艾美：网络也必须安全，在无线和有线链路上都必须执行强加密。除此之外，还需保护物理光缆和铜线电缆，让入侵者无法轻易通过直接访问暴露线路进入网络。

克里斯：人们常忽略的一点是，想穿透电脑防御系统的人都非常聪明，且善于发现哪怕最微小的漏洞。

艾美：这就是为什么创建多层防御系统是明智的，从逐步加密的硬件开始，到机器本身安全，再到操作系统安全，一直到给用户培训，让他们了解基本安全规则。每一层都必须是安全计划的一部分，因为破坏可能发生在任何地方，但在多层计划中，攻击者不太可能穿透所有安全层。

### 最脆弱的人为环节

克里斯：安全的一个常被忽视的组成部分是确保人员在入职仪式和入职过程中得到适当审查。背景调查是良好安全政策的重要组成部分。

有人说，安全中最薄弱的环节是人为因素，不管是有意还是无意。例如，人们会点击邮件中看似无害的链接，导致病毒被下载，造成安全漏洞。培训可消除大部分问题，但安全计划必须包括这类事故发生的概率。潜在恶意员工会造成更大风险，也必须提前安排。

艾美：重要的是，要了解本地计算机和云服务之间的接口是潜在弱点，因为云服务、应用提供商和本地计算机基础设施之间在架构、协议和程序上存在差异。

这是最值得关注的领域之一，因为许多供应商的组件都聚集在一起，每个组件都可能存在自身安全缺陷。通常，这些链接最好托管在一个被称为 DMZ 的网络中，这样可有效地将它们与其他网络隔离。

克里斯：云服务供应商、应用供应商与咨询公司和企业之间的良好沟通对于确保良好安全性至关重要。

企业负责数据和服务的安全，无论其托管在何处。虽然云服务商和其他供应商也负有责任，但不管关键设备和应用位于何处，对企业安全的负责人来说，最好的办法是理解、记录、实施和审计安全。

艾美：安全策略的重要部分是必须迅速修补漏洞。行业研究表明，平均而言，企业仅修复关键漏洞就需要 146 天。大多数攻击者都依赖这些做法，而新闻中出现的许多较大攻击正是这个问题的结果。所有操作系统都必须打补丁，因为它们都有漏洞。^(1)

令人震惊的是，我发现 AI 本身可以帮助解决安全问题，即使是用它的基础设施。

克里斯：机器学习安全算法的实现对于安全漏洞的监测有了显著改善。新的恶意软件和攻击正在迅速演变，因此有必要采取更灵活的方法。^(2)

扫描系统以获取病毒特征或对已知漏洞进行入侵测试已不够。AI 必须基于过去漏洞的历史数据库，以及对恶意软件行为和对系统攻击的理解，从而参与检测入侵和破坏行为。

艾美：这是人类和 AI 需要协同工作的领域之一，因为机器学习只能走到这一步。

当我们的模型在检测威胁方面变得有效时，危险分子就会寻找方法来混淆模型。这是一个我们称为对抗性机器学习的领域，或者叫对抗性 AI。危险分子会研究底层模型如何工作，并致力于要么混淆模型——我们称之为中毒模型或者机器学习中毒，要么专注于广泛的规避技术，其本质是寻找他们可以规避模型的方法。^(3)

### 隐私边界

克里斯：一个与隐私密切相关的话题。与计算和 AI 相关的数据隐私所面临的挑战很难被夸大。这个问题不仅在技术上具有挑战性，而且通常，那些谈论这个问题的人都倾向于夸夸其谈和高度情绪化的讨论。用法律语言所写的复杂隐私协议并不能使这个话题更容易理解。

艾美：随着物联网的指数级增长，企业更多地将海量大数据用于 AI 和其他目的，保护数据隐私变得具有挑战性。

克里斯：就像安全一样，数据库、系统和应用在设计时应该考虑到隐私问题。事实上，理想情况下，隐私和安全应该是企业经营方式的一部分。换句话说，企业应围绕隐私和安全来确定企业流程及运营方式。^(4)

艾美：让我们回头看一下，给隐私下个定义。当我们谈到隐私时，通常我们指的是保护互联网上的敏感信息和隐私信息。个人、企业和政府关心的是确保有关他们的信息只能以他们许可的方式共享。

克里斯：人们关心的是他们发布到社交媒体上的数据的隐私，比如照片、视频和文字。他们想决定谁能看到这些，要么是所有人，要么仅限好友，要么是某个特定分组的人。

然而，隐私并不仅仅是人们发布的关于自己的信息。

艾美：没错，克里斯。以你车内导航系统中的 GPS 为例。你开车经过的或可能经过的每一个地方的信息都存储在 GPS 中，甚至可保存在云上。那么拥有这些数据的是谁呢？是汽车制造商，还是 GPS 供应商，抑或是车主本人呢？

克里斯：警察需要搜查令才能访问这些数据吗？如果数据存储在云端，而不是在 GPS 本身上，谁能访问它？从智能电视到智能咖啡壶，再到智能手机和智能家庭摄像机，每个智能设备都会考虑到这些问题及其他问题。

先不论谁拥有这些数据，我们先想想这些数据是如何保密的。如果你的智能咖啡壶记录下你每次冲泡一杯咖啡的日期、时间和类型，并将那些数据发送到云端，咖啡壶制造商能使用那些信息吗？

艾美：正如你所知，数据隐私的管理正成为大型跨国企业面临的一个巨大挑战，这些企业在不同的地方部署了不同的孤岛数据。
