原理上可以分为两段。第一段用可学习的专家中心矩阵 Weight 对隐向量做线性投影得到亲和度，推理时启用 noaux_tc 分组路由：把全部路由专家划分为若干组，先为每个 Token 计算与所有专家的匹配分，再在组内取前两名分值求和作为组分，按组分挑出 Top K_group 个组，最后在这几个组内挑出 Top K 个专家并保留其原始分值。第二段对这 K 个分值做归一化并乘以路由缩放因子，作为最终门控权重输出。

    self.act_fn = ACT2FN[config.hidden_act]

    #3.将门控信号与“专家”的中间表示相乘，实现“专家”输出的加权组合
    #4.通过 down_proj 将加权后的“专家”输出映射回原始隐藏层大小
    down_proj = self.down_proj（self.act_fn（self.gate_proj（x）） * self.up_proj（x））
    return down_proj

6.1.2 MoE 架构下计算量下降的分析

稀疏激活让 MoE 的实际算力开销大幅下降。

1.MLP 架构下的计算量
设密集 MLP 含两层线性，中间宽度为 hidden_size 的 2.5 倍：
● 输入维度：[*h*]
● 第一层：[*h*,2.5*h* ]
● 第二层：[2.5*h* ,*h*]
单 Token 的 FLOPs 为
计算量[MLP]=*h*×*h*×2.5*h*+*h*×2.5*h*×*h*=5*h*³

2.MoE 架构下的计算量
在相同参数规模下，设专家总数为 *n*，每次激活 *k* 个，总参数仍为 5*h*²。单个专家的宽度被压缩为 *h*/*n*^(1/2)：
● 输入：[*h*/*n*^(1/2)]
● 第一层：[*h*/*n*^(1/2),2.5*h*/*n*^(1/2)]
● 第二层：[2.5*h*/*n*^(1/2),*h*/*n*^(1/2)]

下降主要来自两方面。专家数 *n* 增大但每次只激活 *k* 个，计算被大幅剪枝；同时每个专家的输入维度降到 *h*/*n*^(1/2)，矩阵乘法成本随之降低。因为 *k*<<*n*，因此 [PRE2] 远小于 1，整体算力显著下降。需要注意的是，训练总成本还受通信和稀疏调度影响，MoE 的通信开销较大，实际训练成本的降低并不完全等于算力下降。
