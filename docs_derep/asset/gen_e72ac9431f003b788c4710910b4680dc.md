大模型普遍存在输入 token 的硬性上限，例如 DeepSeek-V3 的上下文窗口大约在 32K tokens 左右。若想在有限额度内发挥最佳性能，就要按照图 7-2 所给出的上下文窗口管理思路来做。

如图 7-2 所呈现，窗口管理主要围绕以下做法展开。

- 1）关键信息前置：将最核心的指令与要点放到提示词最前面，让模型优先读取与处理。
- 2）上下文压缩：对篇幅较长的文本进行归纳或提炼关键点，从而降低 token 消耗。

## 2. 记忆管理策略

多轮对话里，对话历史的控制尤为关键，可以采用以下做法。

- 1）选择性记忆：只保留关键交互与结论，剔除冗余或无关内容。
- 2）记忆摘要：定期对历史对话做概括，只保留摘要而非完整原文。
- 3）重要信息重述：在新一轮提问中再次点明关键上下文，避免被遗忘。

搭建完整的提示词测试框架应包含以下核心要素。

- 1) 测试数据集：针对特定任务的测试用例集。

- 3) 测试流程：标准化的执行与分析流程。
- 4) 基准对比：与基准提示词进行性能对照。

#### 2. 质量评估方法

提示词质量可通过以下方式评估。

- 1) 人工评估：由专家或用户对模型输出做主观评价。
- 2) 自动评估：利用算法自动衡量输出的质量与相关性。
- 3) 对比评估：对不同版本提示词的输出进行横向分析。
