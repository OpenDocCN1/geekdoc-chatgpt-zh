RAG 生成质量怎么验？这份评估笔记给你答案

在 RAG 体系里，真正影响用户感受的是生成器。评测响应主要是在检查大模型输出是否准确、是否通顺、是否可靠。围绕生成部分，业界常用的评测手段大致可归为三类：基于 n-gram 重叠的指标、基于语义贴近度的指标、基于忠实度或 groundedness 的指标。

#### 9.3.1 n-gram 重叠类指标

这类方法包括 BLEU、ROUGE、METEOR，核心思路都是把生成答案和参考答案拆成 n-gram，再看重合程度来判断质量，侧重点在词和短语的重复。

小冰：我get到 METEOR 会看语义这一点，但 BLEU 和 ROUGE 到底差在哪还是有点模糊。

咖哥：BLEU 更看重精确率，就是生成文本里有多少内容能在参考里找到。它通过 n-gram 重叠衡量生成中被证实的比例，最早为机器翻译服务，对比译文与参考译文的 n-gram 重叠即可。

ROUGE 则更看重召回率，即参考文本里有多少关键信息被生成覆盖。虽然也是 n-gram 匹配，但核心是看生成是否囊括了参考的关键点，所以在摘要生成或文档抽取里用得更多。

机器翻译追求高 BLEU，说明译文接近人工译文。摘要或抽取任务则更看重 ROUGE，希望生成尽量覆盖参考的重要信息，不必逐字对应。

#### 9.3.3 基于忠实度或扎实性的指标

BLEU、ROUGE、METEOR 以及语义相似指标大多衡量相关性，即生成是否回应了查询并提供有用信息。但相关不等于正确，语义上贴合的答案仍可能出现幻觉或理解错误，见图9-7 幻觉错误和理解错误。

幻觉错误对用户尤其危险，非专业人士很难察觉。明显的逻辑混淆虽然也是失误，却更容易被发现。准确性相关指标更难量化，常出现看起来合理实则错误的答案，设计评估规则需要更多考量。

小冰：的確，即便像 DeepSeek-R1 这类强模型，在专业领域也会出错。细节上似是而非时，非专业读者很难辨别，可能误导初学者并产生连锁影响。

咖哥：因此引入忠实度或 groundedness 作为新标准，关注生成内容是否严格基于检索文档且无误，确保信息既相关又可信。

常用量化手段包括：

- 文档精确率和页面精确率：衡量模型引用的文档和具体页面的准确性，要求生成时明确标注来源，减少虚构。
- 幻觉检测 / 一致性检查：判断生成是否可从上下文推导，或不同查询下事实是否一致。评估常采用二分类 0/1，若答案无法从给定文档推出，即便本身正确也视为幻觉。
- 大模型评分量表：用更强模型打分，例如 0 到 5 分，按业务需求定制标准。
- 人工评估：由领域专家人工核查准确性及引用是否合理。

忠实度审查要严格审视逻辑推导。即使答案正确，若不能从提供文档推出，也应判为幻觉。需要设计可解析的来源引用、清晰的文献支撑、严格的上下文一致性检查，避免不同查询间自相矛盾。

缓解幻觉的一个做法是控制信息量。过度提供上下文可能提升某些指标，却降低响应质量并增加幻觉风险。

### 9.4 RAG 系统的评估框架

小冰：前面这些指标需要我们自己从零实现吗？

咖哥：目前没有一个通用且被广泛认可的 RAG 框架能一次性覆盖所有指标。实践中常先尝试 RAGAS、TruLens、DeepEval 等框架，根据项目需求组合使用，必要时再手工补充自有指标。

#### 9.4.1 使用 RAGAS 评估 RAG 系统

在 RAG 评测工具里，RAGAS 是开发者较为熟悉的选择之一。它提供面向大模型应用的客观指标，兼容 RAG 和 Agent 工作流，关注输出质量、准确性和一致性。

就 RAG 而言，RAGAS 的指标分为检索相关和生成相关两类。

检索相关指标主要包括：

- 上下文精确率：检索文档与查询的相关度。
- 上下文召回率：检索是否全面覆盖回答所需信息。
- 上下文实体召回率：针对人名、地名、专业术语等实体的召回能力，在医学、法律、金融等领域尤为重要。
- 噪声敏感度：模型抗拒检索中无关信息的稳定性。

生成相关指标主要包括：

- 答案相关性：生成是否直接准确回应用户查询，避免跑题。
- 忠实度：生成是否基于检索事实，避免幻觉。
- 多模态忠实度：面向文本-图像、文本-音频等场景，保证跨模态一致。
- 多模态相关性：衡量多模态输出是否符合用户需求，例如生成的音频是否传达了文本情绪。
