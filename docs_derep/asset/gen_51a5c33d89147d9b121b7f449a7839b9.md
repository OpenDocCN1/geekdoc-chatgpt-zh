当会话运行在隔离沙箱里时，系统会自动把沙箱路径、可用命令等环境细节注入提示词，让模型对当前运行环境保持准确感知。

3. 模型推理
上下文组装完成后，Gateway 会把完整的上下文包——System Prompt、历史对话、当前用户输入以及格式化后的工具清单——一起发送给已配置的大语言模型。支持的模型包括 OpenAI GPT-4o、Anthropic Claude Opus 4.5、阿里云 Qwen3.5-Plus 以及各种本地部署模型，模型随即进入思考状态。

OpenClaw 的推理是全流式输出。模型的内部推理过程和逐步生成的回复会通过 WebSocket 实时送到客户端，在界面上形成流畅的打字机效果。

另外还支持思考深度的精细调节。对于具备扩展思考能力的模型，例如 Claude 3.7 Sonnet，用户可以用 /think 命令或在配置文件中设置 thinkingLevel 参数，来控制生成最终答案前的思考预算，从而在速度和质量之间找到平衡点。

4. 工具执行
模型判断需要调用工具时，会输出一个工具调用请求。Agent Loop 暂时停止推理，进入工具执行子流程，关键环节如下。

工具分发上，OpenClaw 把工具分为两类：一类是底层库直接处理的内置工具，如文件读写和基础命令执行；另一类是 OpenClaw 自身实现的高级自定义工具，如浏览器控制、节点调用和定时任务。路由模块会拆分工具列表，拦截自定义工具的调用，由 Gateway 处理后再把结果无缝接回主流程。

确定目标工具后，会立即做权限校验，核对该工具是否在当前会话的工具策略范围内。若发现越权，调用会被直接阻断并向模型返回明确错误。

对于 Shell 命令执行这类高风险操作，还引入了执行确认机制。触发安全策略时，Agent Loop 会主动暂停，并通过 WebSocket 向用户推送确认请求，只有在用户明确批准后才会继续。

通过安全检查后进入执行阶段，视工具类型可能调用本地代码、经网络路由到远程 Node 执行，或在高度隔离的 Docker 沙箱容器中运行指令。

最后在执行反馈阶段，系统把工具执行的成功数据或捕获的错误信息整理成标准化的 Tool Result 消息，追加到对话上下文，为下一步推理提供事实依据。

5. 循环与终止
携带工具执行结果的新上下文会再次发给模型。模型据此继续推理，可能再调用工具，也可能直接生成最终回复。这个“推理→调工具→得结果→再推理”的过程会循环，直到用户需求满足，模型输出最终回复且不再发起工具调用。

为保证健壮性，OpenClaw 设置了多重硬边界：
• 循环达到预设最大迭代次数；
• 整体执行时间超过配置的超时阈值，默认通常为 120 秒；
• 用户通过特定命令或界面按钮主动中断。

同时内置了智能的工具调用循环检测机制，能识别无进展状态，例如反复用相同参数调用同一工具、对轮询类工具持续得到相同输出，或在两个工具间无意义地来回切换。一旦捕捉到异常，会先向模型发出警告提示，若仍未纠正且达到容忍阈值，系统将直接切断循环，防止资源浪费。

6. 持久化与清理
该阶段负责把本次 Loop 数据落盘并释放资源，具体操作如下。

1. 系统把本次 Loop 产生的所有新数据——用户的原始输入、模型的中间思考、每次工具调用的详细记录以及最终回复——以追加方式安全写入该 Session 专属的持久化记录文件。
2. 数据落盘后，立即释放当前会话的执行锁，让队列中等待的下一个请求进入处理。
3. 最后同步更新全局会话元数据文件，记录该会话最后活跃时间和累计 Token 消耗，为审计和资源管理提供依据。

3.3.2 上下文管理与记忆机制
大语言模型本身无状态，连贯对话依赖每次请求都带上历史上下文。但上下文窗口容量有限，输入越长成本越高、速度越慢。OpenClaw 设计了一套精密的上下文与记忆管理机制，在连贯性与效率间取得平衡。

1. 上下文管理
每次 Agent Loop 启动时，context-window-guard.ts 模块会估算即将发送的上下文 Token 数。若估算值超过模型窗口大小减去预留量，系统会自动执行上下文缩减策略。

不同会话类型采用差异化保留策略。私聊通常保留更长的历史，因为连贯性和完整性更关键；群组或频道会话限制更严格，因消息更分散、主题跳跃，且过长上下文会带来不必要的 Token 开销。

历史截取并非简单丢弃头部最早消息，系统会严格保证结构完整，例如绝不会在工具调用请求与其对应的执行结果之间截断，以确保模型始终看到完整的因果链。

当 Token 用量达到预设压缩阈值，通常为模型最大窗口的 70%～80% 时，系统自动触发上下文压缩，这是 OpenClaw 的亮点之一。

压缩前会先插入一轮用户无感知的静默摘要轮次。后台向模型发送系统级指令，告知会话即将压缩，要求模型梳理关键决策、用户偏好等重要信息，并通过文件写入工具保存到核心记忆文件或日常日志。完成后模型返回内部标记，保证不影响正常交互。

关键信息安全转移后，后台会独立启动一个专门的 LLM 摘要任务，引导模型阅读较早的冗长历史并提炼成高度浓缩的摘要文本，作为压缩节点永久写入会话记录。后续轮次不再发送被压缩的原始长文本，只发送摘要和压缩点之后的新消息。

该机制在不丢失核心上下文的前提下，极大释放上下文空间，使 OpenClaw 能够以极低成本维持近乎无限长度的连贯对话。

为防止压缩过程意外错误，例如摘要生成失败导致会话损坏，OpenClaw 实现了一个名为 compaction-safeguard 的 Pi 扩展。若压缩失败，系统会回退到简单的历史截断策略，确保对话不中断。

2. 记忆机制
除对话历史外，OpenClaw 还实现了一套基于 Markdown 文件的显式记忆系统，按层次管理。

最顶层是工作记忆，直接驻留在 LLM 上下文窗口中，包含当前对话完整历史。访问最快，但受 Token 上限严格制约，生命周期仅限当前会话。

为弥补短暂性，引入短期/日常记忆。以按日期命名的 Markdown 文件存储，记录当天流水账、临时笔记和中间思考结果，随时间推移自然滚动。

更深层次是长期/核心记忆，集中存放在 MEMORY.md 文件中，涵盖关键技术决策、重要用户偏好和不可丢失的重要事实，永久保留。

为让海量静态文本可被 AI 随时唤醒，底层构建了强大的向量索引。利用本地 SQLite 数据库，把所有记忆文件转为高维语义向量，并随文件修改实时更新。

这种立体记忆架构让 Agent 既能捕捉当下语境，又能深度调用历史。启动时自动读取近两日的日常日志和 MEMORY.md 全部内容并注入 System Prompt，确保每次对话都能记得近期事件和长期偏好。

OpenClaw 提供 memory_search 工具，后台对 MEMORY.md 和 memory/*.md 文件进行向量化处理并建立本地索引。当用户询问历史内容时，例如“上个月我们讨论过的项目计划是什么”，Agent 可调用该工具通过语义搜索快速召回相关片段，无需把所有历史塞入上下文。

将工作记忆与长期存储分离，使 OpenClaw 能够以极低成本维持长期对话连贯性，同时保持高效推理。

3.3.3 系统提示词的角色与定制
System Prompt 可理解为塑造 Agent 行为与性格的核心模板。在 OpenClaw 中，System Prompt 并非静态文本，而是基于配置文件与上下文在每次 Agent Loop 启动时动态组装而成，理解组装过程是深度定制的关键。

1. 系统提示词的动态组装
组装逻辑集中在 system-prompt.ts 与 system-prompt-params.ts，整体由以下模块按顺序拼接而成。

• 工具指引模块：由内部脚本动态生成，完整列出当前 Agent 有权使用的所有工具及其精确描述，经过严苛的提示词工程优化，用于引导模型理解每个工具的适用场景、参数结构及潜在限制。
• 安全护栏模块：一组不可逾越的底层约束，强制模型规避高风险行为，例如执行破坏性操作前必须征求用户同意、严禁突破沙箱边界访问宿主机文件。
• 技能指引模块：向模型展示当前加载的结构化技能列表，相当于操作手册，告知模型面对特定任务时应优先调用预设技能工作流，而非自由发挥。
• 环境感知模块：实时提供 Agent 当前工作目录路径、沙箱启用状态、精确本地时间与时区、底层操作系统版本、正在使用的模型名称，让模型具备真实环境感知能力。
• 运行时信息模块：补充 OpenClaw 核心版本号和当前会话唯一标识等元数据，为推理提供完整上下文支撑。

组装时，Gateway 会自动读取 Agent 工作空间下的特定 Markdown 文件并注入 Prompt。

• AGENTS.md：相当于岗位说明书，严格定义 Agent 核心职责、标准工作流及必须遵守的全局规则，例如专注的编程语言或技术栈。
• SOUL.md：塑造 Agent 的性格灵魂，通过设定性格特征、沟通语气和核心价值观，可让它成为严谨学者或幽默极客。
• USER.md：记录用户的个人背景、技术水平、偏好和特殊要求，使每次回答都能精准契合用户实际水平。
• TOOLS.md：允许高级用户针对特定工具编写自定义使用规范或补充说明，从而微调模型调用工具的行为模式。

在记忆层面，系统会自动读取 MEMORY.md 中的长期记忆，确保 Agent 始终牢记用户核心项目信息和关键技术栈。同时会动态加载按日期命名的日常日志文件，如 memory/YYYY-MM-DD.md，将当日与昨日的临时笔记和调试进度无缝融入当前对话，使 Agent 完美接续之前工作状态。

2. 定制你的专属 Agent
通过修改这些 Markdown 文件，无需改动代码即可完全重塑 Agent 行为。例如打造一位“暴躁但极其专业”的代码审查员：

• 在 SOUL.md 设定其性格：拥有 20 年后端经验，直率犀利、对代码质量要求严苛，发现问题不绕弯子，可使用直白甚至尖锐语言，但必须给出可落地的优化方案。
• 在 AGENTS.md 中定义职责与工作流：深度阅读代码，精准定位所有潜在逻辑缺陷、性能瓶颈和安全漏洞，并对整体架构和可维护性提出专业建议；制定严格纪律，如禁止空泛评价、必须解释原因并附重构示例；对安全漏洞醒目标注；审查结束给出量化评分与扣分说明。

再如打造专属个人财务顾问：
• 在 USER.md 详细记录用户的职业收入、家庭结构、核心理财目标，如在特定期限内筹集购房首付、对投资波动的风险承受能力，以及偏好数据图表而非空泛理论。
• 在 AGENTS.md 为财务顾问设定标准：建议必须结合实际存款与月储蓄额做精确推演，输出具体比例的资产配置方案；禁止使用笼统套话；涉及高风险标的时必须在显著位置提示风险。

• 处理超长文档，Gemini 2.5 Pro 凭借百万 Token 上下文窗口，可一次性处理整本书内容，无需分页或压缩。
