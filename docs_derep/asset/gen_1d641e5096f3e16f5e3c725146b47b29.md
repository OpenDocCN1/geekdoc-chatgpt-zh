恰当使用局部变量可以妥善保存中间数据，使函数更清晰高效。可一旦对生命周期把握不准，就容易埋下隐患。比如内存泄漏，程序占用了内存却无法回收；再比如引用已被销毁的变量，触及无效地址，进而引发崩溃或异常行为。

局部变量诞生于函数内部，从声明的那一刻起存活，到所在作用域结束才消亡。函数结束时，其占用的内存会被自动回收。注意，块级局部变量的存活期以最小代码块为界，例如 if、for、while 结束即失效，而非等到整个函数返回。

**11.4 函数进阶：递归函数**

**11.4.1 小故事**

小乐盘点时发现一批嵌套包装的饼干，最外层是木箱，里面放几只纸箱，纸箱内可能再装纸箱，最内层才是装饼干的小塑料盒。要统计一个木箱共多少盒饼干该怎么做？

他发现拆箱过程很相似：打开一个纸箱，若里面仍是纸箱就继续拆，若是饼干盒就计入总数。于是从最外层开始，遇到纸箱就把其视作同样的问题递归处理，直到遇到最内层无嵌套的盒子，最终得到总数。这种“函数调用自身逐步求解”的方式就是递归。

**11.4.2 知识精讲**

**1.递归函数的概念**

1）了解递归函数

递归是化繁为简的技巧，把复杂问题拆成结构相同的子问题，通过解决子问题来解决原问题。少量代码即可描述多次重复计算，大幅减少代码量。递归适用于具有自相似特征的问题，能让代码更清晰易懂。

2）递归函数的定义

递归就是函数在其内部调用自身。每次调用进入新层次，必须设置结束条件。

当执行到递归调用语句时，当前函数暂停，将控制权交给被调用的递归函数。被调用函数再次调用自身，如此形成递归调用链，直至满足终止条件。

满足终止条件后，递归开始逐层返回，最内层执行完后把控制权交回上一层，上一层继续完成剩余工作，层层回溯直到初始调用点，后续代码得以执行。

3）递归函数的执行流程

**2.递归函数的基本结构**

1）终止条件的重要性

终止条件是递归的成败关键，决定何时停止。若无终止条件，函数会无限自调用，最终导致程序崩溃。因为每次调用都会在栈上分配内存保存局部变量和调用信息，无限递归会耗尽栈空间导致栈溢出。

2）递推关系的作用

递推关系描述了原问题如何分解为规模更小的子问题，让递归不断简化问题直至达到终止条件。

以阶乘为例，递推关系为 n! = n * (n-1)!，计算 n 的阶乘即可转化为计算 n-1 的阶乘，问题规模缩小但结构相同。
