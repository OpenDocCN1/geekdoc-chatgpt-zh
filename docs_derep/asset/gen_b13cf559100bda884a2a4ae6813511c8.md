#### 7.2.2 LLMLingua 提示词压缩
LLMLingua 是微软推出的方案，专门对付大模型在长上下文里的遗忘问题，提升长文本处理能力。它主要靠压缩提示词和 KV-Cache 来加速推理，最高能做到约 20 倍的压缩，同时基本不牺牲效果。

KV-Cache 的作用可以概括为：

- 历史保留：已算过的 token 的键向量和值向量会暂存在内存里。
- 增量计算：生成新 token 时，只算当前部分，再与缓存的历史拼接。
- 速度提升：避免重复计算，推理更快。
- 内存取舍：缓存会占内存，但实际收益远大于成本。

举个例子，模型在生成“我喜欢吃苹果”时，生成“苹”后，“我 喜 欢 吃”的键值就被缓存了。等到生成“果”时，就直接复用之前的结果，不用重新算一遍。

论文里的做法是用小型且训练好的模型，比如 GPT2-small、LLaMA-7B，去识别提示词里可以删掉的无用 token，降低计算量，如图7-9所示。这样不用给大模型额外训练，也能保留提示词的核心信息。研究显示，借助快速压缩，仅用原来的 1/4 token 就能让 RAG 性能提升 21.4%。图7-9 LLMLingua的实现过程

实现上提供了两种压缩器：

- 抽取式压缩器：从检索文档里挑选最相关的句子。挑选时用对比学习来优化，确保选出的句子对任务帮助最大。
- 生成式压缩器：把多个文档的信息融合后生成新摘要。它先用大模型造训练数据，再通过知识蒸馏训练一个更小的压缩器。

如果检索到的文档对当前任务完全没用，压缩器会直接返回空字符串，避免干扰，提升整体生成效率。

#### 7.2.4 句子嵌入优化器
LlamaIndex 提供的 Sentence Embedding Optimizer 也是压缩手段的一种。它通过计算句子嵌入与查询的相似度，剔除不相关的句子，让输入更精简。

它是一个节点后处理工具，检索时利用嵌入相似性分析，根据用户问题剔除无关句子，从而缩短输入长度并提高相关性。压缩发生在 token 嵌入层面，保证信息精炼且准确。

支持两种过滤策略：

- 百分比截断 percentile_cutoff：只保留相似度高于设定百分位的句子。
- 阈值截断 threshold_cutoff：只保留相似度高于固定阈值的句子。

#### 7.2.5 用 Prompt Caching 缓存长上下文
小冰：对了咖哥，听完这些压缩手段，我想起之前看到的 Prompt Caching 思路。这是 Anthropic 提出的提示缓存方案，目标是降低重复任务的耗时和成本，这也能算压缩的一种吗？

咖哥：当然算。它属于上下文压缩的一种应用，核心是管理重复任务里的上下文，减少冗余计算，从而提升效率和降低成本。

实际业务里常有大量背景信息或多轮交互，比如长对话、文档分析。Prompt Caching 会把可复用的上下文前缀缓存起来，避免每次调用都重新处理大块内容，像长文档或背景资料。当检索内容与当前任务无关时，缓存会输出空。

和 RAG 相比，Prompt Caching 更聚焦性能优化。它不是检索或生成的核心环节，而是一种提升模型效率的缓存机制。在 RAG 的后处理阶段，多轮调用相同上下文时，缓存能避免重复加载相同背景，显著减少延迟和 API 费用。对频繁处理大文档或复杂用户背景的场景尤其实用。

### 7.3 校正
校正技术为 RAG 加入了自我反思和自我评分能力，可用在检索后处理，也可嵌入生成流程。典型代表是 Corrective Retrieval Augmented Generation，简称 CRAG。实现流程见图7-12。

[PRE10]
CRAG 的核心是反复评估与重检索，保证生成答案所依赖的信息足够相关。它包含两大部分：检索后知识校正和生成校正。

检索评估器先判断检索结果的相关性，只要有一个文档超过阈值就进入生成。生成前会做知识细化，把文档切成知识片段并打分，过滤掉无关部分。若所有文档都低于阈值或评估器无法判断，就会去外部数据源补充，比如联网搜索更相关的资料。

生成器给出初稿后，会进行二次校验与优化。比如把答案和检索信息对比校对，必要时纠错，还可补充事实核查、语法修正、语义一致性检查等，以提升最终质量。
