##### 4. 十分钟实战：数据安全与行级安全策略

TRAE SOLO 如何保证用户只能触达自己的数据，依靠 PostgreSQL 原生的 RLS 行级策略实现，可为每行数据设定精细规则。

###### 核心配置

在 supabase/migrations/001_initial_schema.sql 中可以看到为核心表开启 RLS 的语句以及具体策略，如账户档案访问策略、习惯创建策略等：

[PRE4]

策略遵循默认拒绝、用户隔离、操作细分三原则。

- 默认拒绝：未授权时直接阻断访问。
- 用户隔离：通过 auth.uid() = user_id 的判断，确保只能操作自身数据。
- 操作细分：对 SELECT、INSERT、UPDATE、DELETE 等分别制定独立规则。

auth.uid() 是 Supabase 内建函数，可在数据库层返回当前登录用户的唯一 ID，是把认证与权限连接起来的关键，即使应用层有漏洞也无法绕过。

在此基础上，生产环境常扩展更完整的邮件体系：注册欢迎邮件、每周习惯完成统计报告、基于设置与时区的个性化提醒、里程碑激励邮件等。

用个人邮箱程序化发送存在局限：送达率低易被判定为垃圾邮件、缺少打开率点击率等分析、需手动处理退订合规细节等。

因此专业邮件服务成为必然选择。API 密钥属敏感信息，不能暴露到客户端，正确做法是把发送逻辑封装在服务端路由，用环境变量管理。

- **完善的通知设置系统：** app/settings/page.tsx 提供完整的通知偏好管理界面。

系统通过 user_notification_settings 数据表与 API 路由 app/api/user/notifications/route.ts 实现了数据持久化，用户可以精细控制通知开关与提醒时间。
- **完整的用户信息收集机制：** 已收集用户姓名、邮箱、时区等关键信息，姓名用于个性化内容，邮箱用于投递，时区用于保证发送时机合理。

##### 2. 邮件系统的功能规划

基于现有架构，可规划以下功能提升体验：

- 新用户注册后发送含有使用指南的欢迎邮件；
- 每周自动生成用户的习惯完成统计报告，包含完成率、连续天数等可视化数据；
- 根据用户设定的习惯计划和时区偏好，发送个性化的智能提醒；
- 当用户达到特定里程碑时自动发送成就激励邮件，增强持续动力。

上述功能可由 Resend 实现，其优势契合本项目：API 设计友好，可与现代 Web 工作流无缝集成；免费额度能覆盖小型项目；原生支持 React Email，允许用 React 组件构建邮件模板，提升开发效率与复用性。
