WiFi 核心速览
WiFi 的技术根基是 IEEE 802.11 无线局域网协议，该协议族至今已分化出 a、b、g、n、ac、ax 六条演进路线，其 中 802.11n 对应 WiFi 4，802.11ac 即 WiFi 5 已成为当前的主流部署。常用频段集中在 2.4 GHz 附近。最突出的优势是速率，随着世代推进，WiFi 4 的理论吞吐约 150 Mb/s，WiFi 6 可攀升至 9.6 Gb/s，带宽随代际扩大，并发能力增强、延迟被压缩、功耗逐步优化。信号劣化或干扰加剧时，链路会自适应下调速率以维持连接稳定可靠。其主要特点是传输快、稳定性高；空旷环境配合大功率平板天线可实现数十公里覆盖，封闭室内也能达到数百米，实际可达距离取决于发射功率。WiFi 能与有线以太网络便捷融合，组网成本更低。与 Arduino 结合后，可广泛服务于物联网、智能家居、智能玩具等场景，实现近远距离的网络联动与控制。

13.2.1 蓝牙的工作状态与系统架构
蓝牙规范在配对连接期间定义了保持状态 HoldMode、嗅探状态 SniffMode、停泊状态 ParkMode 三种省电状态，再加上常规的活动状态 ActiveMode，支持电源管理的设备可在四种状态间切换。按功耗从高到低排序为活动状态、嗅探状态、保持状态、停泊状态，其中停泊状态省电效果最佳。蓝牙的出现为移动终端与外设之间提供了低功耗、低成本、短距离的无线互联手段。
蓝牙系统一般由天线单元、链路控制器 Link Controller LC 硬件、链路管理 Link Management LM 软件以及蓝牙协议栈软件构成，如图 13 - 2 所示。天线单元体积紧凑，多采用微带结构。链路控制器内部包含连接控制器、基带处理器与射频收发器。链路管理负责数据收发、名称请求、地址查询、连接建立、鉴权、链路模式协商与建立、帧类型判定等。

## 14.1 家庭儿童自助视力检测项目简介
儿童时期是晶状体发育最快的阶段，不良用眼习惯可能带来严重后果，及时关注视力尤为重要。传统视力检查需要专业医师配合，至少两人协作完成。为让家长居家随时检测，本项目设计并实现了一款可由使用者独立完成的儿童视力测试产品，如图 14-1 所示。方案基于国际标准视力检测原理，结合 Arduino Uno 开发板、RB-02S102 红外手势传感器、HC-SR04 超声波测距传感器等硬件，并以 Qt 图形用户界面框架开发高度封装的 exe 程序。可根据显示屏规格与用户年龄选择视力表。测试开始时先用 HC-SR04 判断检测距离是否达标，随后屏幕自大到小依次呈现视力表“E”字母，并以 RB-02S102 识别使用者判定方向是否正确，直至连续判断错误为止，从而给出视力值。该产品面向青少年儿童视力筛查与健康追踪，操作界面友好，可在短时间内独立完成检测，并让家长实时记录结果、追溯历史变化，及早把控视力动态。

### 14.2.1 项目设计

1. 产品功能
帮助儿童自主完成视力检测，省去以往两人配合所需的人力与时间成本，使用者无需外出到眼镜店或医院即可在家快速自助检测。

2. 产品特点
（1）年龄适配：针对 3～6 岁儿童视力差异，对不同年龄段视力表进行调整并配以相应音频提示，提升交互友好度。
（2）屏幕适配：适配主流电脑显示屏，避免画面呈现差异导致测试误差。
（3）降低空间需求：测试距离缩短至 1 m。
（4）信息保存：测试结束后可选择将视力信息导出至本地，便于日后观察变化。

3. 产品定位
面向非特殊视力状况的大众群体，尤其是近视儿童，完成远视力筛查并预警视力变化。

### 14.2.2 软件设计
基于 Arduino IDE 编写的程序主要采集传感器数据：超声波测距传感器获取使用者与屏幕距离，红外手势传感器获取手势挥动方向，并将数据发送至串口供 Qt Creator 接收处理。
基于 Qt Creator 的程序实现年龄适配、屏幕适配、音频播放等功能，并根据串口数据作出相应调整。距离数据用于判断使用者是否处于约 1 m 范围内以决定是否开始测试；手势方向数据用于判断挥动手势是否正确，进而决定是否切换图片或结束测试并输出视力数据。

### 14.2.3 算法设计
首先进行超声波测距，确认被测者与屏幕距离是否达到 1 m，并在超声波模块代码中加入滤波算法以减小误差，不达标则不呈现视力表。达标后屏幕随机出现字母图片，并读取红外手势传感器返回的手势方向，与屏幕上“E”字母朝向匹配并记录结果，按测量逻辑逐步缩小字母，直至得出视力测量结果并在屏幕显示。

### 14.2.4 硬件设计
主要硬件为 Arduino Uno 开发板、HC-SR04 超声波测距传感器与 RB-02S102 红外手势传感器。两类传感器采集的数据经 Arduino Uno 串口发送。HC-SR04 实时采集使用者与显示屏间距，RB-02S102 采集手势挥动方向。

2. 传输层
对数据进行处理与转发。项目使用 DistanceSRF04 扩展库支持 HC-SR04 滤波与数据传输，ALS_APDS_9960 扩展库用于 RB-02S102 手势识别并返回上下左右结果。Arduino IDE 将结果经程序发送至串口。Qt Creator 通过 QSerialPortInfo 读取可用串口信息，通过 QSerialPort 连接串口并读取 Arduino 发送的数据。

应用层包含实现整体功能的 MainWindow 类与导出结果到 txt 文件的 FileDialog 类。

整体上硬件与软件数据层负责产生与存储过程数据，Arduino IDE 与 Qt Creator 通过传输层交互，数据层为核心采集层，应用层与 UI 层负责与用户的直接交互。算法主要集中在软件层，Arduino 端负责降噪与结果生成并经传输层传给 Qt，后续由数据层与应用层处理，UI 层负责正确展示与切换并最终给出结果。
