# 用 AI 赋能 React 开发：React 19 与 GitHub Copilot 实战指南

## 内容提要

本书系统讲解 React 技术栈，聚焦 React 18 及之后版本的主流开发范式——函数式组件与 Hooks，并以一款即时聊天应用的构建过程演示现代 React 的落地方式。同时深度探讨 AI 技术在 React 前端工程中的实践路径。

全书划分为三大部分。第一部分是 React 基础，从零搭建项目入手，涵盖 JSX 语法、组件组织、核心 Hooks 等基础，再说明 props、state、context 如何驱动数据流，以及副作用、事件处理与样式实现等开发要点。第二部分是 React 进阶，剖析生命周期与虚拟 DOM 原理、应用级状态管理及相关方案、性能与体验优化，并从自定义 Hooks、代码复用角度阐述可扩展代码的编写方法。第三部分是 Web 应用实战，以聊天应用为载体，结合 React 生态演示前端路由、表单交互、服务端通信、质量保障、工程化与架构设计，并以构建 AI 聊天机器人为例探索前端在 AI 时代的创新可能。全书在对应章节融入 AI 辅助开发内容，涉及 AI IDE、智能体代码生成、组件拆分建议、性能诊断、样式生成、单元测试与代码评审等。

本书适合具备一定编程经验的 Web 开发人员阅读，也可作为高校及培训机构相关课程的参考教材。

## 前言

当生成式 AI 能在半分钟内产出可运行的页面源码，前端从业者的核心价值该如何定义？

自 2023 年起，生成式 AI 的爆发式增长正在重塑软件工程的基本模式。如今它已能有效支撑生产级开发，从编程到设计、测试、持续集成、运维等环节均在不同程度引入 AI 能力。前端领域里，GitHub Copilot、Vercel v0 已可通过自然语言生成组件，Claude 等大模型甚至能独立完成模块级开发。

Gartner 预计到 2028 年，75% 的软件工程师将使用 AI 辅助编程。由此引出两个核心疑问：

- 在 AI 已能生成可用代码的当下，为何仍要深入学习 React 等框架？
- 前端工程师会被 AI 取代吗？

答案隐藏在技术演进的规律里：**AI 越强，开发者对技术判断的精准与效率要求越高**。作为拥有二十余年前端经验的从业者，我的判断是持续夯实技术根基、深入业务实践、保持开放学习。具体可归结为两点。

其一，只有扎实掌握基础框架，才能真正发挥 AI 编程的效能。AI 在处理大任务时不确定性较高，但把大任务拆分为足够小的单元，成功率与准确度会大幅提升。因此工程师需要：

- 具备精准拆解开发任务的能力；
- 熟练掌握常用框架的原理与落地实践；
- 清楚 AI 工具的边界，掌握提示词设计技巧；
- 能客观评估 AI 输出的质量。

其二，AI 与前端工程师是协作而非替代。目前 Cursor、GitHub Copilot 等都在推进智能体技术，AI 可自主决策并完成更复杂的任务。如何与智能体高效协作成为新课题，同时带来责任归属问题：代码由谁对接产品、联调后端、部署运维、修复缺陷、迭代版本？只要最终责任仍在工程师身上，就必须理解智能体的工作逻辑与生成代码，并随时接管。

**AI 能极大提升效率，却无法取代对技术本质的深刻理解和对业务需求的精准把握。**

在这一背景下，React 展现出强劲生命力。2024 年，时隔三年 React 19 正式发布，带来多项突破：内置表单处理减少样板代码、强化异步处理以应对复杂交互、服务器组件为全栈开发开辟新路径。这些改进直击长期痛点，使 React 在 AI 时代仍具竞争力。

作为 Meta 开源的声明式 UI 框架，React 持续引领前端走向：

- 2023 年以 40.58% 的使用率位居框架榜首，数据来源 Stack Overflow；
- 自 React 18 起全面拥抱函数组件与 Hooks 现代范式；
- 生态如 Zustand、React Router 不断进化，形成完整技术矩阵。

无论门户、企业级应用，还是移动端、PC 桌面应用，React 应用广泛。就业层面，2021 年以来 React 前端岗位数量与薪资均显著领先其他框架。

技术迭代快也带来学习焦虑，如何避免“学不动”的困境？本书认为根源在于“为学而学”。解决方案是目标驱动学习，以 Web 应用开发为牵引，让技术服务于业务。

因此本书确立两大技术支点。

其一，现代 React 深度实践。讲解不止于框架本身，而是覆盖 React 开发全链路，包括概念、API、使用方法及为 Web 应用需求衍生的生态技术如 Zustand、React Router、React Hook Form。

- 以 React 19 为基准，兼容 React 18，聚焦函数组件与 Hooks；
- 弱化类组件等传统写法，优先使用 useState/useEffect 等核心 API；
- 选用适配 Hooks 的生态库；
- 对 React 19 新增与增强的 API 如 startTransition 异步回调、ref 作为 prop 传递等，以“React 19”为前缀专项说明。

其二，AI 辅助开发实战。面向 AI 与开发深度融合的趋势，在系统讲解 React 应用开发的同时，加入 AI 辅助实践。本书以 React 及生态为主线，将 AI 相关内容嵌入对应章节，并以“AI 辅助”为标题前缀。

- 在组件开发、单元测试等环节植入 AI 协作场景；
- 演示用大模型开发聊天机器人等 AI 功能；
- 构建人工与 AI 协作的完整工作流。

学习完毕，你将掌握 AI 辅助前端开发的最新实践与基于 AI 的 React Web 应用开发能力。

为降低门槛、强化实效，本书采用以下写作策略：

- 循序渐进，以一款聊天应用的完整开发过程串联知识点。复杂内容延后讲解，避免打断思路。例如 useReducer 与 useState 设计相近，故安排在第二部分进阶章节再介绍。
- 重在迁移应用，讲解技术细节时同步剖析其解决的实际问题，培养举一反三能力。
- 采用贯穿全书的聊天应用，各章围绕同一项目递进扩展功能，而非孤立示例，有助于建立项目上下文与架构关联。

## 贯穿全书的样例应用

动手写代码仍是学习软件技术的最有效方式。本书讲解现代 React 技术，实践项目是核心。市面上多数图书与课程为单个知识点提供独立示例，虽针对性强但与真实项目差距较大。现实开发需要整合多技术栈，综合运用技术要素。

因此本书选用典型、可扩展且适度复杂的“我聊”聊天应用，项目名 oh-my-chat，界面与微信桌面端相近。业务逻辑不过于复杂，确保不受行业或门槛限制。

建议读者跟随章节逐步编写 oh-my-chat 代码。完成后既能掌握 React 核心知识点，也能获得一套类似微信桌面端的 Web 前端源码。若想先系统学习再实践，可从 https://github.com/evisong/oh-my-chat 或 https://gitee.com/evisong/oh-my-chat 获取完整代码。仓库已按章节记录修改历史并打版本标签。

## 本书内容

全书共 18 章，分为 React 基础、React 进阶、应用开发三部分。知识体系与聊天应用的关系可参考图 0-1。图中自上而下的箭头展示学习路径：从基础到深入，同时从基础功能起步逐步为 oh-my-chat 增加高级能力并持续优化重构。

[PRE0]
第一部分 “React 基础” 第 1 至 8 章。以 React 概览起步，介绍如何从零创建项目并实现 oh-my-chat 初始页面；随后逐章讲解 JSX 语法、React 组件、基础 Hooks API，并在 oh-my-chat 中创建与拆分组件；最后介绍 props、state、context 驱动开发，以及副作用与事件处理实现业务交互，并为 oh-my-chat 加入数据流与基础交互。

第二部分 “React 进阶” 第 9 至 12 章。聚焦底层原理，先讲解生命周期与虚拟 DOM 机制；再围绕应用状态管理及相关框架、性能与用户体验优化、代码可扩展性展开；最后将不可变数据、独立状态管理框架、公共组件等技术应用到 oh-my-chat。

第三部分 “Web 应用开发” 第 13 至 18 章。跳出 React 本身，探索技术生态。以完整 Web 应用为线索系统讲解前端路由、表单处理、服务端通信三大主题，并在 oh-my-chat 中实践 React Router、React Hook Form、React Query；随后介绍单元测试、端到端测试及前端工程化实践，助力大型项目开发与团队协作；最后利用开源大语言模型为 oh-my-chat 加入聊天机器人功能，探索 React 在 AI 时代的新边界。

从第 2 章起，每章开头提供本章知识地图及项目实践，展示核心知识点与 oh-my-chat 的对应内容。三大部分的叶子节点与目录基本对应，其中星号节点代表含项目实作，小飞机图标代表 AI 辅助 React Web 应用开发内容，对钩图标代表已在前文介绍过的内容。知识点与项目实践通过虚线关联。

本书以 CSR 架构为核心，系统讲解 React 在浏览器环境的应用。17.5 节简要提及 SSR 趋势但不深入展开，因实际开发中 SSR 需求多通过 Next.js 等全栈框架实现，直接使用 React SSR API 的场景较少。

适合人群：

- 具备 HTML、CSS、JavaScript 基础的初级前端开发者，希望系统掌握 React；
- 熟悉 Vue、Angular 等技术的中级开发者，计划转向 React 技术栈；
- 曾使用 React 16.8 之前版本的开发者，希望学习最新特性与最佳实践。

## 写给 AI 时代的开发者

从 jQuery 到 React 的演进亲历者，我深知：**框架会更迭，解决问题的思维永恒**。在 oh-my-chat 项目中实践 AI 辅助开发时，你会体会到：

- 只有能精准描述需求的开发者，才能训练出真正有效的 AI 助手；
- 只有深入理解 Hooks 依赖数组等核心机制，才能识别 AI 生成代码中的潜在缺陷；
- 只有具备组件设计经验的开发者，才能将 AI 输出重构为可维护的优雅实现。

这不是简单的技术迭代，而是开发者能力的整体进化。**当 AI 承担基础代码的搬运工作，工程师可更聚焦业务本质——用技术为用户创造价值。**

软件是否被用户认可，关键在于“看得见摸得着”的用户界面。UI 是用户与软件交互的桥梁，在 AI 重塑代码生产的新时代，前端开发者凭借对界面交互细节的极致把控和对用户需求的精准解码，具备不可替代的核心竞争力。

宋一玮
2025 年 3 月于北京
