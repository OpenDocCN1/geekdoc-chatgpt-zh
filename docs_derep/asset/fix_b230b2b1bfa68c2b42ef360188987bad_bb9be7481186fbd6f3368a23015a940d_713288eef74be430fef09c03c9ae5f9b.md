# 第8章 CrewAI 多智能体实战演练

## 8.1 CrewAI 核心概念概览

### 8.1.1 框架初识与定位

CrewAI 是用 Python 打造的开源多智能体协同平台，未捆绑 LangChain 等外部库，旨在让开发者便捷搭建智能协作小组，推动复杂业务自动化。官网示意图见图 8-1。

[PRE2]

### 1. 核心理念

CrewAI 假设一个 Crew 由若干 Agent 组成，每个 Agent 都有清晰角色定位，比如资料研究、数据分析、文案创作等。团队通过任务拆分、协同配合和反馈迭代来达成复杂目标。各角色定义见表 8-1。

表 8-1

| 角色 | 定义与职责 |

| :--- | :--- |

| Crew | 负责调度团队成员和流程管理 |

| Agent | 执行具体任务并拥有独立背景、目标、工具接口 |

| Process | 协调任务顺序或并行执行 |

| Task | 最小单元任务，指定 Agent 与目标 |

该架构把复杂职责拆解并行处理，降低单点压力，提升整体稳健性。

### 2. 架构构成与功能特色

CrewAI 呈现清晰的分层设计，从基础框架到企业级能力各有亮点：

- (1) 独立轻便
纯 Python 编写，无冗余依赖，强调轻量与执行效率。
- (2) 角色配置精细
Agent 支持 YAML 与代码双模式定义，涵盖角色、目标、背景故事、LLM 选择、工具集合，并支持长期记忆与上下文管理。
- (3) 调度方式灵活
同时提供 Crew 与 Flow 两种编排手段，可实现顺序执行、并行执行、条件分支、循环等复杂逻辑。
- (4) 工具生态丰富且可观测
智能体可接入 Web 搜索、数据库、API 调用及自定义工具。企业版支持监控与日志链路追踪，兼容 AgentOps、MLflow、Langfuse 等。

### 3. Crew 与智能体协作方式

CrewAI 借鉴现实组织架构：

- 1) 团队 Crew：统筹任务调度与流程管理。
- 2) 智能体 Agent：承担特定角色如研究员、撰稿人，并可调用专属工具。
- 3）流程 Process：决定任务按顺序、并行或条件分支执行。
- 4）任务 Task：最小执行单元，由指定 Agent 以特定工具产出结果。

例如撰写“医疗 AI 最新进展”报告时，研究员 Agent 负责资料收集，撰稿人 Agent 基于资料生成完整文章，分工明确、过程可控。

### 4. 典型应用场景

CrewAI 在以下领域表现突出：

- 1）内容生产：自动撰写新闻、技术文章、教学材料。
- 2）商业流程：个性化简历投递、产品推荐、邮件营销等。
- 3）决策支持：案件分析、市场调研、投资评估。
- 4）对话客服：多轮上下文理解、智能分类回复与知识抽取。

相较单一语言调用，多角色结构更具组织性与扩展性，适合模块化开发和复杂逻辑。

### 8.1.2 Crew 与 Flow 的差异及协作

在 CrewAI 中，Crew 侧重多角色协作，Flow 侧重事件驱动的流程控制。两者定位不同，选型合理可让 AI 系统更灵活可控。主要对比见表 8-2。

表 8-2

| 核心特性 | Crew | Flow |

| :--- | :--- | :--- |

| 架构理念 | 模拟现实中的团队协作机制，多个智能体分工协作，共同完成复杂任务 | 以事件触发为核心，按顺序或条件驱动任务节点的执行，构成清晰流程链条 |

| 执行机制 | 启动 Crew 后，多个 Agent 可并行执行，或按流程顺序依次执行 | 使用装饰器如 @start()、@listen() 等定义任务执行条件与相应触发机制 |

| 状态管理 | 每个 Agent 拥有独立上下文，可通过共享数据或工具进行协作通信 | 统一使用全局状态变量（如 self state）维护流程中数据，便于流转与溯源 |

| 应用场景 | 适用于多角色、职责分明、协作密集的业务任务，如调研、生成、分析等 | 适用于逻辑清晰、状态驱动、需要条件判断或复杂控制流的业务，如审批、分支决策 |

| 扩展能力 | 易于新增角色、模块化集成，具备较高的组织灵活性 | 流程结构清晰，支持条件判断、路由逻辑、可视化控制，适合系统流程建模 |

举例而言，文本处理任务中 Crew 可模拟编辑小组，分类器、摘要器、格式器各司其职；Flow 则像装配线，每一步处理信息并决定下一步走向。

### 1. 何时选用 Crew，何时选用 Flow

任务本质决定选型。

（1）分工明确，优先 Crew
当任务可拆分为信息收集、分析、写作等专责模块时，Crew 更贴合。每个 Agent 仅关注自身职责，适合内容生成、调研分析等协作型任务。

（2）流程复杂，优先 Flow
涉及多步骤、条件判断、状态路由时，Flow 更合适。其以装饰器定义节点、触发器串联，逻辑清晰易调试，适合审批、问答、对话等条件密集场景。

### 2. 在 Flow 中嵌入 Crew 实现协同增强

复杂系统常需流程控制与多智能体协作结合。外部用 Flow 做指挥，内部调用 Crew 处理子任务，是高效架构。

该模式兼顾流程灵活性与协作优势，适用于报告生成、自动化客服、多阶段文档生成。例如智能推荐系统：

- 1）Flow 启动，接收用户查询并预处理。
- 2）Flow 调用 Crew 进行分类，如新闻或产品。
- 3）根据分类结果进入分支判断。
- 4）新闻类调用 CrewA 生成摘要，产品类调用 CrewB 整理推荐。
- 5）Flow 汇总输出并统一格式化。

这种组合具备清晰流程、可复用模块与智能协作能力。
