- 结果校验再审：先评估产出质量，再决定是否修正

## 8.7 本章核心回顾

本章系统梳理了 LangChain 框架在智能体开发中的底层思路与实操路径，为搭建工程化的 AI 应用提供了完整参考。

1. LangChain 框架总览：框架以模块化为设计主线，覆盖提示管理、模型调用、输出解析等核心模块。依托链式调用，从简单问答到复杂决策都能快速落地，典型场景包括对话机器人、文档解析生成等。

2. 输入输出处理：通过统一接口规范 LLM 的交互。Prompt 模板支持参数化，模型层屏蔽了不同厂商 API 的差异，输出解析器把非结构化结果转为程序可用的结构，三者共同保障交互可靠。

3. Chain 与表达式语言：Chain 是组件编排的核心抽象。LCEL 作为新一代表达式语言，基于 Runnable 接口实现更灵活的流式处理。RunnableSequence 负责线性串联，RunnableParallel 支持并行，RunnableBranch 实现条件分支，三者构成复杂应用的积木。

4. 记忆机制：解决对话上下文的长期记忆问题。BaseChatMessageHistory 提供了会话存储标准接口，可接文件、数据库等多种后端。RunnableWithMessageHistory 将记忆无缝注入链路，便于构建有状态的对话系统。

5. 检索增强生成：显著提升模型对实时信息的处理能力。完整链路包括多源 Loader 接入、递归字符切分、向量库语义检索，最后由检索器与生成模型协作产出基于外部知识的答案。

6. 智能体系统：智能体是 LangChain 的高级形态，具备自主决策与工具调用能力。单智能体可根据工具描述自动选路，多智能体框架 LangGraph 支持大规模协作，其图由节点与边构成，状态管理保证数据有序流动。工具封装可接入外部 API 与自定义函数，再审机制通过反馈循环不断提升决策精度。

掌握本章内容后，开发者能够从基础组件到高级智能体全流程落地，夯实专业 AI 应用的工程基础。

# 第9章

MCP 协议驱动的智能体构建

基于模型上下文协议 Model Context Protocol 的智能体开发正成为 AI 领域的重要方向，其价值在于用标准化协议打通大语言模型与外部工具、数据源的连接。本章从原理、环境搭建到实战三个层面展开。

## 9.1 MCP 原理概览

MCP 是一个开放协议，规范了应用程序如何为 LLM 提供上下文。可以把 MCP 视作 AI 应用的通用接口。像 USB-C 为设备外设提供统一连接一样，MCP 让模型能以统一方式接入不同数据源和工具。

### 1. 架构蓝图

MCP 采用客户端-服务器结构，主机可同时连接多个服务器。

- MCP Hosts：如 Claude Desktop、IDE 或各类 AI 工具，需要访问数据的程序主体
- MCP Clients：负责与服务器维持一对一连接的协议客户端
- MCP Servers：轻量进程，通过标准 MCP 暴露特定能力
- 本地数据源：服务器可安全读取的本地文件、数据库与服务
- 远程服务：服务器可通过 API 访问的互联网外部系统

### 2. 协议机制

1. 通信格式：基于 JSON-RPC 2.0，统一请求响应格式，支持上下文查询 Query、操作执行 Execute、流式更新 Stream 等标准动作
2. 通信方式：
- 本地通信：基于标准输入输出 STDIO，适合同设备内低延迟交互
- 远程通信：以 Server-Sent Events 与 HTTP 结合，实现跨网络实时传输
3. 安全机制：内置权限管理与加密传输，支持细粒度范围控制，如仅允许读取禁止写入，并通过 OAuth 2.1 完成身份认证
