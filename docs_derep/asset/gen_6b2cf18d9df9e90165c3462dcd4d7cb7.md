### 4.1 RAG 技术全景解析

本部分围绕 RAG 技术架构展开，梳理其运行原理、核心模块以及工程化落地方法。RAG 是一种将信息检索与大模型生成结合的智能问答范式，既能提升回答的准确性和知识覆盖面，又能有效缓解大模型的幻觉问题，常见于知识库问答、企业智能助手等场景。

后续内容将以搭建本地化 RAG 系统为线索，逐步拆解文本向量化、文档载入与分块、向量数据库构建、检索机制设计以及大模型问答调用等核心环节。同时会引入主流 API 模型充当答案生成组件，帮助读者理解 RAG 框架与大模型的衔接方式。

#### 4.1.1 RAG 概念速览

大语言模型在生成文本时容易出现错位或不准的情况，主要表现有：

- 信息偏差：生成内容可能基于错误或过期的知识。
- 知识滞后：模型无法触达最新信息，尤其在专业领域更明显。
- 推理短板：面对复杂推理任务时，输出效率和准确度不足。

RAG 正是为了应对上述问题而提出。它先从知识库中检索与问题相关的信息，再基于检索结果生成回答，从而显著提高输出的准确性和相关度。该方法还能加快知识更新速度，提升内容可追溯性，让 RAG 在实际应用中更可靠、更具实用价值。

#### 4.1.2 RAG 系统核心模块拆解

实现一个 RAG 系统通常需要 5 个关键模块。

1. 向量化模块：把文档片段转成向量表示，为后续检索做准备。
2. 文档载入与切分模块：负责读取原始文档并切分为便于处理的片段。
3. 数据库模块：保存文档片段及其对应的向量。
4. 检索模块：根据用户查询检索出相关的文档片段。
5. 生成模块：调用语言模型基于检索信息生成回答。

- 推理：大语言模型基于完整提示进行推理并产出答案，随后做后处理优化输出质量和准确性。

这几个模块共同构成了简易 RAG 的核心架构，各自在检索到生成的不同阶段发挥作用，保证查询处理的连贯性。

#### 4.1.3 文本向量化模块构建

在 NLP 与机器学习里，Embedding 是把文本映射为数值向量的常用手段。通过向量，模型可以度量文本间的相似性，并用于搜索、分类、推荐等任务。OpenAI 已推出第三代 Embedding 模型，在性能、成本和多语言支持上都有提升。下面介绍该系列模型的特点与调用方式。

##### 1. OpenAI 第三代 Embedding 模型概述

Embedding 是一种把文本字符串表示为浮点数列表的技术，通过比较向量间的距离来判断文本相关性。距离越近，相关性越高。

常见应用包括：

- 搜索：按相关性对结果排序。
- 聚类分析：依据文本相似度分组。
- 个性化推荐：基于相关内容推荐信息。
- 异常检测：找出与整体相关性低的异常文本。
- 多样性评估：分析文本集合的相似度分布。
- 分类任务：根据文本与标签的相似度归类。

OpenAI 的 text-embedding-3-small 与 text-embedding-3-large 性能更高，支持更多语言，分别输出 1536 维和 3072 维向量。用户还能通过设置维度参数在保证语义的前提下优化存储与计算开销。
