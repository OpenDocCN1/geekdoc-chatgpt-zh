大模型的技术底座来自 GPT 架构，这是一种典型的自然语言处理范式。GPT 的全称是 Generative Pre-trained Transformer，Generative 指的是通过生成方式呈现智能，Pre-trained 强调上线前要经过大规模预训练，Transformer 则是支撑整个架构的核心神经网络结构。在预训练阶段，模型会吃下海量的无标注文本来学习通用的语言规律和生成能力。这里的无标注意味着文本里没有预先配好的问答对，但上下文之间的关联信息非常丰富。训练的核心目标是根据前文去预测后文，训练完成后得到的就是预训练模型，也常被称为基础模型，例如 DeepSeek-V3-Base。基础模型在纯预测上表现不错，但在具体下游任务上往往力不从心。

要让预训练模型派上用场，就需要用少量精细标注的数据对权重进行二次优化，这就是微调。微调后模型会在特定任务上更对味，常见的结果就是在基础模型上长出对话能力。

微调的算力开销不小，通常由大模型厂商承担。到了企业落地层面，微调更多是指在已完成训练的模型之上，注入垂直领域的专业语料做继续训练。这样模型能更好地把握行业术语和用户真实意图。本书后续会演示如何用已标注的医学语料微调 DeepSeek-R1-Distill-Llama-8B，让模型在医疗场景下的推理与理解更靠谱。对于开源模型做垂直微调是打造行业专用大模型的常见做法，算力门槛相对友好，关键竞争点在于优质语料的整理。DeepSeek-R1 的面世让门槛再次抬高，因为数据整理的复杂度显著上升。传统监督微调依赖问答对标注，而推理类模型的微调语料必须包含思维链的结构化信息，简称为 CoT 语料，也就是在问、答之间还要补充思考过程。

本节将完整演示在 unsloth 框架下，利用开源医学 CoT 语料微调 DeepSeek-R1-Distill-Llama-8B 的全套流程，涵盖语料获取与改造、微调操作与代码解读、微调后模型合并以及效果验证方法。

### 13.1 微调工作机理
微调的本质是借助下游任务数据对原模型参数进行调整。通过计算损失并反向传播，更新部分或全部参数，使内部表征与目标任务需求对齐。实现方式按维度划分有很多种。

**13.1.1 参数调整范围分类**

**1.全量微调（Full Fine-Tuning）**
训练时覆盖模型全部权重，让模型彻底适应目标任务。通常能获得最佳适配效果，但可训练参数可能达到数十亿乃至万亿级别，对算力和时间要求很高。一般只用于数据充足且算力充裕的企业级定制场景。

**2.参数高效微调（Parameter-Efficient Fine-Tuning，PEFT）**
主体参数冻结，只更新少量参数即可达到较好效果。典型做法是 LoRA，即低秩适应微调，通过引入低秩矩阵增量来更新适配层，降低可训练参数量。PEFT 算力需求低、训练更快，且主体不变可避免灾难性遗忘。微调后专业能力提升的同时通用能力得以保留，适合资源受限环境。

**13.1.2 按训练算法分类**

**1.监督微调（Supervised Fine-Tuning，SFT）**
使用已标注数据降低损失、拟合任务。按是否具备推理能力，训练数据可分为输入-输出对和输入-思考过程-输出对，也常包含多轮对话。SFT 简单直接，适用于分类、生成等常规任务。在 DeepSeek-R1 及其蒸馏系列训练中被广泛采用。指令微调是 SFT 的一种变体，用自然语言指令数据增强泛化能力。

**2.强化学习微调（Reinforcement Learning Fine-Tuning）**
借助强化学习如 PPO 算法优化模型，利用奖励模型或 GRPO 策略量化人类偏好，使输出更符合偏好目标。DeepSeek-R1-Zero 的训练中强化学习发挥了关键作用，尤其在标注数据稀缺时，基于人类反馈的微调也属于此类。强化学习通过试错与奖励机制，让模型学会根据环境反馈调整行为，适用于需要多步决策的复杂任务。

### 13.2 微调实操路径
本节讲解 DeepSeek 蒸馏模型的参数高效微调，涉及 unsloth 库和 Hugging Face 的 trl 库。unsloth 专注大语言模型的高效微调，能显著提升速度、降低成本，同时保持性能。它采用无损精度的内存节省方案，不依赖量化带来的数值损失，而是通过计算图重构、内存调度优化和数学等价变换来减少资源占用。以 DeepSeek-R1-Distill-Llama-8B 为例，半精度加载配合 LoRA 一般需要约 20GB GPU 显存，而使用 Unsloth 仅需 8GB，且训练速度明显提升。trl 是 Hugging Face 开源的大模型训练库，面向 SFT、PPO、DPO 等技术构建，基于 transformers 生态，支持多种架构和硬件。

## Chapter 14 第十四章 SFT 复现 DeepSeek 推理能力
随着 DeepSeek-V3 与 DeepSeek-R1 的发布及广泛应用，业界掀起使用热潮。配套的技术报告详细披露了训练方法，使得在原理上复现类似 DeepSeek 的模型成为可能。在此背景下，开源社区涌现出大量复现尝试，其中 Hugging Face 的 Open R1 是典型代表。

Open R1 的目标是复现 DeepSeek-R1 训练中的关键环节，例如用 GRPO 训练推理模型、监督训练以及从已有模型合成训练数据。尽管尚未覆盖全部细节，但其实现思路与参考代码为开发者理解核心机制、部分复现训练效果提供了重要指引。

本章聚焦 Open R1 复现 DeepSeek-R1 的三项核心工作：用 CoT 数据集做监督训练获得蒸馏模型、在给定数据上用 GRPO 训练推理模型，以及通过数据蒸馏从已有模型生成训练数据。下面先介绍监督训练蒸馏的完整流程。

### 14.1 SFT 技术概览
第十二章已对 DeepSeek-R1 技术报告做过解读。从训练脉络看，监督训练被反复使用，例如冷启动阶段通过 SFT 让模型掌握格式遵循与反思验证能力，后续再做全场景 CoT 增强 SFT 以提升泛化。DeepSeek-R1 蒸馏模型的诞生也源于两轮 SFT。

Open R1 的 SFT 实践可对照 DeepSeek-R1 蒸馏流程。通过学习，读者能更深理解 DeepSeek-R1 的训练原理，并观察高质量 CoT 语料如何在基础模型微调中提升推理能力。

### 14.2 实现原理
DeepSeek-R1 核心竞争力之一是 60 万条推理训练样本和 20 万条非推理样本，这些数据未开源。Open R1 的做法是调用 DeepSeek-R1 模型生成训练语料，例如 22 万条含 CoT 结构化的数学领域数据集 OpenR1-Math-220k，总量约 12GB。

生成 OpenR1-Math-220k 的过程已有详细说明。首先从 AI-MO/NuminaMath-1.5 提取 40 万个问题，仅保留 problem，不需要原数据集的 solution 与 answer。因为新数据集的思维链和答案将由 DeepSeek 对这 40 万问题重新生成。Open R1 为每个问题生成 4 个解法，提供筛选与训练的灵活性。该方法支持拒绝采样，与 DeepSeek-R1 的训练思路一致，也利于 DPO 等偏好优化。

据官网介绍，SFT 是复现计划的第一步，按技术报告指导从 DeepSeek-R1 中提取高质量语料来复制 R1 蒸馏模型。由于 OpenR1-220k-Math 本身就是从 DeepSeek-R1 蒸馏而来，用它训练的模型自然能学到 R1 的推理能力。训练流程如图 14-1 所示。
