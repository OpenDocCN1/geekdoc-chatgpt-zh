③可以为不同模态的数据单独搭建向量库，同时保存原始素材和对应的摘要，方便后续相似检索调用。原始数据和摘要一起留存，能让语义命中更准，上下文也更完整。

#### 4.2.3 检索要读懂真实意图
做相似检索时，RAG 系统得像个“知心人”，先洞察用户内在需求，再把真正相关的资料找出来，才能助力大模型理解与生成。然而用户提问风格千差万别，问题形式五花八门，很难实现同频共振。

##### 1. 提问太宽或太窄
用户提问常带随机性和局限。一种是范围过宽，比如“电梯安装的步骤是什么”，问得太泛，模型容易给出表面化、缺乏精度的答案。另一种是范围过窄，比如“在 A 项目中，曳引机的参数选型和位置安放怎么做”，只盯曳引机，忽略了配套设备和整体流程，答案就会不够全面。

从技术上缓解局限的思路是问题数据增强：借助大模型围绕原问题生成多个不同视角的衍生问题，再用这些衍生问题做相似检索，最后对所有结果重新排序，挑出最相关的知识块，如图 4-20 所示。

[PRE1]

要注意，增强问题会带来更多次检索，检索量和耗时都会增加，可能影响用户体验。问题多维度扩展还会让大模型输入上下文变长，增加负担，输出内容也会相应膨胀。

##### 2. 问题一句话套太多
实际场景中，用户问题可能涉及多个领域和话题，语义很复杂。例如“在 MES 的落地实施时，离散制造行业和流程制造行业有什么需求差异？”就涵盖了多个话题，直接检索很难命中。

可行的做法是先把问题拆成更简单具体的小问题，再分别检索。例如拆成“在 MES 落地时，离散制造行业有什么需求？”和“在 MES 落地时，流程制造行业有什么需求？”并行查询后，把检索到的上下文合并输入大模型理解并最终输出。

#### 4.2.4 生成阶段的成败关键
拿到相似检索结果后，需要和用户问题一起作为大模型的输入，生成答案。合理的输入组合和输出控制是智能生成成功的关键。

##### 1. 提示词要设计好
直接把检索结果和用户问题拼给大模型，往往得不到理想效果。按提示词工程的原理，合理的提示词设计才能引导模型按预期生成。因此要针对检索结构和用户问题构建合适的提示。

结合明确性、具体性和角色设定等技巧，智能生成的提示词应明确限定回答仅基于搜索结果，不额外添加信息。可例如：“你是一名智能客服。你的目标是提供准确的信息，并尽可能帮助提问者解决问题。你应保持友善，但不要过于琐碎。请根据提供的上下文信息，在不考虑已有知识的情况下，回答相关查询。”面对复杂问题，还可采用少样本提示，把预设的问题例子加入提示词，指导模型如何利用检索知识。

合理的提示词能提升生成质量，让回答更精准，也更符合特定场景需求。

##### 2. 选好模型是基础
提示词构建完后，考验的就是大模型本身的能力。实际 RAG 应用中选型可从以下方面考虑。
- （1）可获得性与成本：大模型服务形态多样，按开放程度分完全开源、有限开源和闭源，按使用方式分本地部署和接口服务。获取难度和使用成本不同，需综合权衡。
- （2）生成质量：不同模型技术细节和规模不同，性能表现有差异。选综合生成质量评分较高的模型更稳妥。
- （3）推理速度：在 RAG 场景中，部分服务对响应时间要求高，忽视速度会带来差的用户体验，因此推理速度值得重点考虑。

总体上需综合多因素权衡，找到适合 RAG 的模型。

##### 3. 输出必须可控
大模型存在幻觉、安全等问题，生成时需要有效控制输出。
- （1）确保公平和负责任的使用：RAG 的道德部署要求负责任地使用技术并避免滥用或有害应用，开发人员和用户须遵守道德准则，维护 AI 生成内容的完整性。
- （2）解决隐私问题：RAG 依赖外部数据源，可能触及用户数据或敏感信息。需建立强隐私保护措施，保护个人数据并遵守相关法规。
- （3）减轻外部数据源中的偏差：外部数据源可能因内容或采集方式存在偏差。需建立识别和纠正偏差的机制，确保响应公正公平，这需要持续监控与优化数据源和训练过程。

#### 4.2.5 别急着上线，先评估
RAG 范式优化升级并构建完行业知识库后，不能马上投入使用。原因有三：
- ①大模型输出具有不确定性，结果不可预知，像开盲盒，投产前需测试以免出现太多惊喜或惊吓；
- ②RAG 知识库是外挂且动态的，生产维护中性能可能波动，需要定期检测评估；
- ③上线后必然有升级维护，需要手段衡量改进效果。

与传统软件需完整测试不同，RAG 的输入输出是自然语言，相关性和准确性难以直接判定，容易出现主观分歧。因此需要借助额外工具和评估模型来辅助判断。

Ragas 是用于评估 RAG 流程的框架，可评估、监控和改进生产环境的 LLM 和 RAG 应用性能。使用 Ragas 需提供四项信息：
- □ 问题：用户提出的问题，作为 RAG 输入。
- □ 答案：问题的答案，即 RAG 应该输出的结果。
- □ 知识：从外挂知识库语义检索出的相关知识。
- □ 基准事实：由人类提供或标注的事实，即正确答案。

#### 4.2.6 什么时候用 RAG 更合适
当需求对实时性、准确性和相关性要求较高时，大模型微调可能力不从心。RAG 通过向量数据库构建、相似检索、智能生成三个核心能力，利用外挂知识库拓展大模型处理特定需求的能力。正如微调并非万能，RAG 也有其适用场景，可考虑采用：
- （1）数据稀有：数据呈长尾分布时，RAG 的检索能力可触达稀有、非典型样本，增强对长尾数据的处理。
- （2）知识更新频繁：在新闻、科技等快速迭代领域，RAG 可通过实时搜索提供前沿信息。
- （3）回答需要验证追溯：要求答案可溯源的应用中，RAG 支持回溯答案出处，增强可靠性。
- （4）领域专业化知识：医疗、法律等高度专业场景，RAG 可提供深厚背景资料支持决策。
- （5）数据隐私保护：对敏感数据，RAG 可设计为查询脱敏或安全处理后的数据，避免直接访问原始信息，保护隐私。

#### 4.2.7 RAG 和微调怎么选
大模型微调是在预训练模型上用行业数据做少量参数更新，生成垂直大模型解决下游任务，但成本和时间较高，不擅长整合新知识或快速迭代新场景。

RAG 则不改变模型结构，通过外挂知识库检索扩展上下文语义作为模型输入，有助于提供实时精准答案。

两者思路不同，各有适用场景，如表 4-4 所示。微调重在把知识内化为参数，是一种隐式能力；RAG 重在利用外在知识检索，是一种显式能力。

##### 表 4-4 RAG 与大模型微调的对比

| 特点对比 | RAG | 微调 |
| :--- | :--- | :--- |
| 应对知识更新 | 模型无须重新训练，直接更新外挂知识库 | 数据和知识更新，模型需要重新训练 |
| 外部知识利用 | 擅长利用外部资源，非常适合文档或其他结构化/非结构化数据库 | 微调需要成本和时间，对变更频繁的数据源并不适用 |
| 数据处理要求 | 对数据加工和处理的要求低，直接外挂 | 微调依赖一定规模的高质量数据集，否则性能提升有限 |
| 模型风格 | 主要关注信息检索，擅长整合外部知识，模型风格依赖大模型本身的能力 | 依赖大模型本身能力，允许根据特定的语气或术语调整大语言模型的行为、写作风格或特定领域的知识 |
| 可解释性 | 答案通常可以追溯到特定数据源（即外挂知识库），提供可解释性和可溯源性 | 受限于大模型本身的可解释性问题，犹如开盲盒，具有相对较低的可解释性 |
| 资源消耗 | 外部数据源集成以及数据更新。需要高效的向量数据库构建与检索能力，以及大模型推理能力 | 准备和整理规模较大的高质量训练数据集，微调技术选型与相应的计算资源 |
| 延迟与实时性 | 在大模型生成之前，需要进行数据检索，可能会有更高延迟 | 经过微调的大语言模型无须检索即可响应，延迟较低 |
| 减少幻觉 | 本质上不太容易产生幻觉，因为每个回答都建立在检索到的外挂数据库上 | 基于特定领域的训练数据后，大模型可以减少幻觉，但仅适用于本领域。在跨领域或者知识更新时仍然有幻觉 |
| 道德与隐私 | 道德和隐私问题来源于从外部数据库检索的文本 | 道德和隐私问题则源于模型的训练数据中可能存在敏感内容 |
| 适用场景 | 稀有、动态数据场景 | 静态数据场景 |

两者并不互斥，甚至可互补。内在知识内化加上实时检索，内外兼修效果更好。例如在微调过的垂直大模型上用 RAG 提问行业最新问题，表现会更佳；RAG 的外挂知识库累积整理后也可用于微调，生成更高性能的垂直模型，如图 4-22 所示。

RAG 要让大模型回答最新话题相关问题，必须配备相应的外挂知识库。但知识库更新需人工操作，时效性有限；大模型只能回答问题，无法帮助决策和任务执行，智能度不足。那么能否让大模型自身感知用户真实需求，帮助决策和执行任务，成为更先进的助手呢？

### 4.3 AI Agent：从问答到行动
大模型通过微调和 RAG 能为特定行业提供精准回答，但一问一答模式仍局限于被动响应。随着智能化追求升级，人们希望模型不仅能感知需求，还能帮助完成后续工作，这催生了 AI Agent 技术的发展。AI Agent 不仅能理解和感知用户需求，还能基于上下文情境预测、规划并执行一系列连续操作，帮助完成复杂任务。例如在办公场景，AI Agent 可协助安排日程、处理邮件、编写文档，并基于历史行为推荐下一步工作策略。

#### 4.3.1 AI Agent 是什么
在认知中，AI Agent 的共识是构建能够感知外部环境并自主行动决策的系统，拥有类人智能。

Agent 中文直译为“代理”。代理在法律上有深刻内涵，一个合格代理人须满足：
- ①明确理解被代理人意思，不得误解，不超出代理人意思。
- ②代理人在代理权限范围内实施代理行为，独立与第三方进行代理行为。

AI Agent 相当于代理人。例如工厂老板张三对 AI Agent 瓦力说：“我要采购一批电缆，型号是 ZRYJ22-1KV，数量是 1 千米，请帮我采购吧”，如图 4-23 所示。为完成任务，瓦力需具备代替张三采购的能力，具体包括：
- ①准确无误地理解张三的意思，买电缆不能理解成买钢材，型号和数量也要准确。
- ②能够借助工具与供应商李四达成购买行为。例如会浏览采购网站、询价、下单、付款等。

[PRE4]

从代理角度看，可比较准确地解释 AI Agent 内涵。合法代理的要求也明确了 AI Agent 的能力方向，即理解被代理人需求，能使用工具并独立完成任务。

AI Agent 并非全新概念，自人工智能诞生之初就已存在。随着技术演进，其实现方式也在不断变化。
