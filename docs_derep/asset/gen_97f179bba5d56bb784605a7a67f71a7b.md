### 3.2 DeepSeek-R1 推理模型全解析

本部分聚焦 DeepSeek-R1，系统介绍其核心能力、API 调用方式、参数配置以及典型应用场景。DeepSeek-R1 是一款强推理型大模型，不仅文本生成与理解能力突出，还支持 Function Calling，可在复杂任务中与外部工具无缝协作。此外，还会介绍其在不同环境下的本地部署思路，以及结合主流推理框架进行优化的方法，以提升推理效果并拓展应用边界。

#### 3.2.1 模型背景与定位

DeepSeek-R1 由 DeepSeek 于 2025 年 1 月推出，目标是强化大语言模型的推理水平。测试显示，其在数学、代码、自然语言推理等任务上的表现可与 OpenAI o1 正式版相媲美。

DeepSeek 同步开源了 DeepSeek-R1-Zero 和 DeepSeek-R1 两个 660B 级模型，并基于 R1 的输出蒸馏出 6 个轻量模型，其中 32B 和 70B 版本在多项指标上对标 OpenAI o1-mini。

另外，article 元素也可用于表示插件，使插件看起来像页面原生的一部分。

需要说明的是，DeepSeek-R1 与 DeepSeek-V3 采用完全相同的架构，仅训练流程和数据不同。具体而言，R1 在 V3 base 上先进行有监督微调，再进行强化学习训练；同期开源的 R1-Zero 省略了有监督微调步骤，直接在 V3 base 上通过强化学习得到。

因此 R1 项目中并未单独列出模型权重、推理脚本、本地部署说明等信息，因为这些内容已包含在 DeepSeek-V3 项目中，详见 3.1 节。

#### 3.2.3 关键参数说明

调用 DeepSeek-R1 API 时，可灵活设置多项参数来控制输出长度、风格多样性、逻辑严谨性等。chat.completions.create() 接口的核心参数已作说明，R1 与 V3 共用该接口。

此外，R1 在参数解析与推理机制上存在部分特殊性和限制，实际调用时需注意：

##### 1. max_tokens 控制

- （1）max_tokens 用来限制最终回答部分（content 字段）的最大长度，默认值 4096 token，约等于 3000 中文汉字，上限可达 8192 token。

- （2）该上限不计入思维链内容（reasoning_content）。在复杂任务中，思维链可能长达 32K token，因此总输出长度可能远超 max_tokens 的设定值。官方计划后续上线 reasoning_effort 参数以控制推理深度与长度。

##### 2. reasoning_content 字段

- （1）R1 的特点是除常规回答 content 外，还会返回推理过程字段 reasoning_content，与 content 平级。

- （2）该字段记录模型得出结论的思考路径，适用于解释型任务、教学、评估等场景。

##### 3. 功能支持清单

- （1）目前已支持标准对话补全和对话前缀续写（Beta），可用于续写已有内容形成完整对话。

- （2）暂不支持 Function Calling、JSON 格式输出、FIM 补全（Beta）。相关字段设置无效。

##### 4. 无效参数提醒

temperature、top_p、presence_penalty、frequency_penalty、logprobs、top_logprobs 在调用 deepseek-reasoner 模型时不生效，但为保持与 OpenAI 接口兼容，设置后不会报错，仅被静默忽略。

R1 的思维链在多轮对话中呈现出清晰的阶段性变化。

- (1) 首轮对话多为独立推理，模型基于初始提问进行结构完整、逻辑自洽的思考。

- (2) 进入第二轮，模型开始递进式推理，能引用前文问答并自然衔接，衔接性良好。

- （3）到第三轮及以后，模型逐步形成综合性推理，整合多轮信息与多个变量，输出逻辑排序清晰的推理链。随着对话深入，R1 不仅展现单轮分析力，更体现上下文记忆、逻辑递进与归纳整合能力，具有类人类的思维连续性和对话一致性，适合复杂交互场景。
