用图数据库把程序员与项目的关系模型化，思路很清晰：先定义节点类型和边类型，再写入实体，最后连起关系。

首先创建两类节点。程序员节点类型继承自 V，项目节点类型也继承自 V。两类边的定义同理，熟人关系 Knows 继承自 E，参与关系 Participate 继承自 E。

节点数据落库时，程序员侧写入四个实例：张三 29 岁，李四 27 岁，王五 32 岁，赵六 35 岁。项目侧写入两个实例：项目名为图书馆，使用语言是 Java；项目名为 RDF 元组库，使用语言是 C++。

关系数据带权重建立。熟人关系里，张三指向李四，权重 0.5；张三指向王五，权重 1.0。参与关系里，张三指向图书馆，权重 0.4；王五也指向图书馆，权重 0.4；刘六指向 RDF 元组库，权重 0.2；赵六指向图书馆，权重 0.2。

建好图之后为了加速按姓名检索，需要在程序员节点上建索引，方便后续查询。
[PRE0]
CREATE INDEX ON :程序员(姓名)
[PRE1]
MATCH (p:程序员{姓名：'张三'})
RETURN p
