互联网技术不断演进后，业界希望借助日益充裕的网络数据来缓解问答系统长期存在的数据稀缺痛点。尤其在 20 世纪 90 年代中期，TREC-QA[120] 评测任务的推动下，检索式问答取得了一定进展。这类系统的主要做法是借助浅层自然语言处理对问题进行初步分析，再依赖信息检索等手段从大规模文本或网页集合里抽取答案。只不过用户需求千差万别、自然语言本身又极其复杂，浅层语义分析很难真正把握查询意图并筛出有价值的信息①，所以检索式问答并未实现广泛落地。

长期以来制约问答发展的两大瓶颈是高质量知识资源不足与自然语言分析能力不够。Web 2.0 兴起后，以 Wikipedia、Yelp [资源10-1]、大众点评 [资源10-2] 为代表的众包生成内容服务带来了海量高质量数据，依托这些数据，Freebase、YAGO、DBpedia 等知识库以自动或半自动方式相继构建起来。与此同时，统计机器学习方法在近年来快速成熟，自然语言处理各环节均实现跨越式提升，无论是基于语义分析的知识工程，还是面向开放域的问句理解，都已取得长足进展。可以说，知识资源匮乏和语言理解难题正逐步被攻克。

近期多款产品的突破也让公众对自动问答更为关注。IBM 研发的问答机器人 Watson 在美国智力竞赛节目 Jeopardy! 中击败人类选手；苹果 Siri 在智能手机上的真实使用效果良好，而 Siri 大量问题实际上交由知识计算引擎 Wolfram Alpha 处理。Watson 与 Wolfram Alpha 的成功归因于两点：① 知识储备充足。Watson 自建知识框架，并从约 2 亿份涵盖图书、新闻、电影剧本、辞海、文选和《世界图书百科全书》等资料中抽取知识；Wolfram Alpha 则针对各领域定义知识结构并抽取大量事实。② 语义分析能力强。Watson 的 DeepQA 系统融合了统计机器学习、句法分析、主题分析、信息抽取、知识库集成与知识推理等深度语义分析技术；Wolfram Alpha 依托早期研发的 Mathematica，该平台具备代数计算、符号与数值计算、可视化及统计等高效知识计算能力。

在国内，以问答和对话为核心的聊天机器人同样发展迅猛，除微软“小冰”、百度“度秘”、华为“小诺”等已上线产品外，众多企业与研究机构也在积极投入。它们目前仍难以满足大量真实信息需求，但以用户喜闻乐见的形式把技术进展呈现给大众，是推动成熟的关键一步。

按所依赖的数据源划分，问答系统可归为数类，典型的是：① 单文本问答系统，也称阅读理解式问答，例如 CLEF 主办的基于机器理解的人学考试评测任务 [资源10-3] 与斯坦福问答测试平台 SQuAD [资源10-4]；② 固定语料非结构化文本问答系统，系统在预先给定的语料库中检索抽取答案，例如 TREC 组织的问答评测任务 QA Track [资源10-5] 与 NT-CIR 组织的跨语言问答评测任务 CLQA [资源10-6]；③ 网络问答系统，直接在互联网中寻找答案，但因网络数据动态变化难以评测；④ 知识库问答系统，也称为知识问答或基于知识图谱的问答，从已建好的结构化知识库中查找答案，例如 CLEF 组织的基于关联数据 Linked Data 的问答系统评测 QALD [资源10-7]。实际应用中很多系统会融合多种资源与技术，很难严格归类，例如 IBM 的 DeepQA[155] 就综合使用结构化、半结构化、百科与领域知识，并结合检索匹配、句法分析、知识推理、机器学习等多项技术。本书聚焦知识图谱相关任务与技术，本章主要介绍面向结构化知识数据即知识图谱的问答与对话系统。鉴于结构化知识常被称作知识库，因此下文中“知识库”与“知识图谱”可互换使用。

① 例如，大部分检索式问答系统假设包含答案的句子至少含有一个问句中的词汇，但是这一假设在很多情况下不适用。

### 10.2 知识问答

### 10.2.1 知识问答技术概述

为了便于知识组织与管理，知识库系统通常需要一种描述性语言，用以检索与推理，例如 Freebase 提供的 MQL[资源10-8]、W3C 制定的 SPARQL[资源10-9] 等。类比关系数据库中的 SQL，知识库的描述语言既为用户提供统一交互入口，也能更便利地表达抽象知识如逻辑规则并执行复杂查询。

知识图谱虽然蕴含大量有价值的信息，却主要面向计算机使用，普通人难以直接获取。例如要在 Freebase 中查找“32 位出生于 20 世纪 60 年代且出演过两部电影的男演员”，就必须按 MQL 语法和 Freebase 的实体、属性、关系等词汇，输入类似如下的查询语句：[“film”：[“limit”：2]，“limit”：32，“type”：“/film/actor”，“/people/person/date_of_birth<”：“1970”，“/people/person/date_of_birth>=”：“1960”]。图 10.2 展示了一个查询 DBpedia 的 SPARQL 窗口。[PRE0]

图 10.2 用来查询 DBpedia 知识库的 SPARQL 窗口

这类结构化查询语言表达能力强，能满足精细信息需求，但门槛也很高，用户既要掌握语法，又要熟悉知识库的表示方式。未经训练的普通用户很难使用，因此在互联网应用中会降低使用意愿。如何构建便捷易用的交互方式，是知识库应用亟待解决的问题。

使用自然语言进行人机交互是最直观高效的模式，因此面向知识库的自然语言问句理解技术需求迫切。人们希望系统能直接响应自然语言信息需求，而非输入机器可读的形式化查询。知识问答以自然语言为交互媒介，为用户提供了更友好的知识图谱查询方式。一方面，自然语言表达能力强，可承载复杂需求；另一方面，无需专业训练即可使用。正因应用前景广阔，知识库问答成为学界与工业界的热点。例如图 10.3 展示了应用该技术的商业搜索引擎形态，如今在百度搜索中直接输入完整自然语言事实型问句，首条结果往往即来自知识图谱的答案。[PRE1]

知识图谱通常表示为相互关联的事实三元组集合，如图 10.4 右侧所示。系统接收用户以自然语言提出的问题，通过与知识图谱交互检索相关知识点，进而推理得出最终答案。目前面向知识图谱的问答系统按技术路线主要分为两种：

- （1）语义解析类型。知识图谱可通过其查询语言如 MQL、SPARQL 等检索信息，若能把自然语言问句自动转化为结构化查询语句，就可直接得到精确答案。例如“屠呦呦是哪里人？”可转为“select ?o where {屠呦呦 出生地 ?o.}”，检索后得到“宁波市”。这类模型称为基于语义解析的方法，见图 10.4 左侧。

### 10.2.2 基于语义解析的方法

基于语义解析的问答实质上是把问句转化为规范的形式化知识表示，即问句的语义解析。语义解析指把自然语言句子映射为某种形式化语义表示，表示形式随应用领域而异，典型应用包括提供航空旅游信息服务的 ATIS[384]、用于机器人足球赛的 CLang[83] 与美国地理知识问答系统使用的 GeoQuery[519] 等。

面向知识图谱的问句解析，是利用图谱中的实体、关系、类别等资源项来表达自然语言问句的语义，并以逻辑公式等形式化语句呈现。例如“有哪些城市靠近大上海？”，借助知识库中实体符号“Shanghai_City”、类别符号“City”、关系符号“next_to”可表示为 λx.next_to(x,Shanghai_City) ∧ City(x)。这是一个极具挑战的任务：首先需把问句中的词/短语映射到图谱资源项；然后对匹配到的资源项进行组合；最后消解匹配与组合过程中的歧义，选出最优结果。总体上可分为基于训练数据的有监督方法和基于规则或先验知识的无监督方法。

### 10.2.2.1 有监督方法

语义解析任务是把一种结构数据，如串行句子或树形句法树，转换成另一种结构数据，如逻辑表达式。与自然语言处理其他任务相似，早期方法多依赖人工规则。随着 20 世纪 90 年代统计方法兴起，研究者开始用机器学习从已有数据中学习显式或隐式模式，以预测未知数据。统计语义解析正是利用机器学习从现有数据学习解析模型，不同学习方法依赖于不同数据。

[PRE3]

典型监督数据形如图 10.5 所示，即<自然语言问句，逻辑表达式>的集合①。目标是学习结构预测模型，对新问句如“有哪些城市靠近大上海？”生成对应逻辑表达式 λx.next_to(x, Shanghai_City) ∧ City(x)。当前主流方法依托语义组合原则构建完整语义表示。语义组合原则由 Gottlob Frege 提出[376]：复杂语句的含义由其子句的含义及语义组合方式决定[资源10-10]。以“有哪些城市靠近大上海？”为例，其含义由“哪些城市”与“靠近大上海”的语义及“且”关系共同确定。因此语义解析需解决两个关键问题：子句含义的形式化与子句间的语义组合。鉴于词典构造与组合模型密切相关，本节先介绍语义组合模型，再说明基础词典构建。

1. 语义组合模型

组合范畴语法 Combinatory Categorical Grammars, CCG 是一种表达能力强、能处理长距离依赖等现象的有效语义组合形式[442, 443]。CCG 最初用于句法分析，2005 年 Luke Zettlemoyer 与 Michael Collins 首次将其应用于语义解析[522]，随后相关工作大量涌现。

CCG 的核心思想是将词的句法与语义信息融合形成分析基础词典，并依据组合语法规则自底向上解析句子。CCG 的核心是词典 Λ，它包含了语义组合所需的全部语法与语义信息。词典中每项由词/短语、句法类型/范畴与逻辑表达式组成。一般记为 w := s : l，表示词/短语 w 具有句法类型 s，对应语义表达式为 l。句法类型 s 可是原子类型如 NP、S，也可是复杂类型如 A/B。逻辑表达式 l 通常由知识库词汇结合 lambda 演算构成。例如 CCG 词典中：

[PRE4]

首项为简单项，“杭州”对应词/短语，NP 为其句法类型，Hangzhou_City 为逻辑形式。第五项城市 := N : λx.City(x) 使用 lambda 算子表示知识图谱中的实体类型。最后一项较为复杂，表示其右侧可接受类型为 N 的词典项，将被接受项的逻辑表达式作为参数 f 带入 λf.λg.λx.f(x) ∧ g(x) 形成新的组合逻辑表达式。总之，词典项的类型与语义表达式定义了其与邻近项的组合方式及组合结果。

仅有词典不足以完成语义组合。CCG 还包含一组组合规则，规定相邻词典项如何进行句法类型与逻辑表达式的组合，可循环迭代进行。CCG 主要包括如下两个基本组合规则①：

X/Y : f   Y : g ⇒ X : f(g)   (>)

Y : g   X \ Y : f ⇒ X : f(g)   (<)

(>) 与 (<) 分别为前向与后向组合规则，用于合并类型匹配的词典项。例如左右相邻的两项类型为 X/Y 与 Y，可按前向规则组合成类型 X。子句与语义表达式可分别构造：子句由左右两项子句拼接，如“毗邻”与“上海”组合为“毗邻上海”；语义表达式则由左右两项的语义表达式组合，如 λx.λy.next_to(y,x) 与 SH_City 组合为 λy.next_to(y,SH_City)。语义解析通过逐次应用这些规则得到句法树并生成逻辑表达式，S 表示最终句子的句法类型。图 10.6 与图 10.7 给出了示例，通过自底向上的解析过程依据句法结构合成最终逻辑表达式。[PRE5]
