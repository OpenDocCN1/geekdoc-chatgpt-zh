首先要厘清学习的目标。与传统迁移学习追求最优迁移函数不同，这里更看重方法的泛化能力。学习的目标就是以往积累的经验，这与人类认知规律相符：知识越丰富的人通常越厉害，唯一的例外或许是《权力的游戏》里的琼恩·斯诺，因为他一无所知。因此该方法的追求是尽可能从过往迁移知识中汲取经验，让后续任务的泛化效果达到最优。

何谓迁移学习的经验？简单来说，就是在一对迁移任务中该选用哪种算法，以及该算法能带来多少性能提升。这与人类学习异曲同工。常说失败乃成功之母，爱迪生测试了两千多种材料做灯泡都失败，却由此得出这些材料不适合的结论，这正是经验的积累。人类靠跌倒爬起、靠失败总结教训不断进步，学习算法也可以遵循同样的路径。

随后是综合学习迁移过程，让算法依据历史经验得到一个特征变换矩阵 W。获得 W 之后，下一步就是将其迁移到新数据上。直觉上会想直接使用刚学到的 W，但必须记住，这个变换矩阵源自旧经验，对新数据未必有效，不能照搬。那该怎么办？需要对它进行更新。

关键在于，面对新数据，变换矩阵应当发生改变。终身迁移学习给出的思路是：新的矩阵应该是在新数据上表现最优的那个。图10-38简要展示了终身迁移学习的示意图。

### 10.7.4 在线迁移学习
众所周知，迁移学习可用来缓解训练数据不足的问题，当前相关方法已取得不少进展。给定一个待学习的目标域数据，我们可以用已有标签的源域数据为目标域构造分类器。但这些方法大多是离线进行的：源域和目标域数据一开始就全部给出，直接离线完成迁移后流程即告结束。

现实应用往往并非如此，数据通常是源源不断、少量逐批到来。起初可能只有源域数据，目标域数据需要一点点积累。这就是在线迁移学习，其概念源自在线学习范式，而在线学习是机器学习的重要研究方向。

目前在线迁移学习的研究仍相对稀少。最早的研究成果由新加坡管理大学的 Steven Hoi 在 2010 年 ICML 上发表，作者提出了 OTL 框架 [Zhao and Hoi, 2010]，可较好地处理同构和异构数据的迁移。

近年来出现了一些相关工作。包括在多个源域和目标域上的 OTL [Wu et al., 2017; Yan et al., 2017]、在线特征选择迁移变换 [Wang et al., 2014; Zhang et al., 2017b]、在线样本集成迁移 [Gao et al., 2012; Patil and Phursule, 2013] 等。

其中，[Jaini et al., 2016] 提出用贝叶斯方法学习在线的 HMM 迁移学习模型，并将其用于行为识别、睡眠监测以及未来流量分析，是一个颇具代表性的应用研究。

### 10.7.5 迁移强化学习
Google 的 AlphaGo 系列在围棋上的突破让强化学习一词变得炙手可热，基于深度神经网络的强化学习自然也成为热点。与传统机器学习需要大量标注数据不同，强化学习是边获取样本边学习的，特定的反馈函数决定了算法的最优决策。

深度强化学习同样面临严峻挑战——训练数据不足。在此，迁移学习可以借助在其他数据上预训练好的模型来辅助训练。迁移学习已被用于强化学习 [Taylor and Stone, 2009]，仍有很大的发展空间。强化学习在自动驾驶、机器人、路径规划等领域的作用日益重要。

### 10.7.6 迁移学习的可解释性
深度学习虽取得众多突破，其可解释性薄弱始终是痛点。现有方法多停留在“黑盒”阶段，难以给出令人信服的解释。迁移学习同样面临此问题。即便万物皆有联系，其深层关联尚未被充分探索。领域间的相似性如同海森堡“不确定性原理”一般难以给出有效结论：为何领域 A 与领域 B 更相似，而与领域 C 则较不相似？目前多停留在经验层面，缺乏坚实的理论证明。

此外，迁移学习算法本身的可解释性也偏弱。现有算法往往只完成一次迁移任务，而学习过程中知识如何流动仍有待实验和理论验证。近期悉尼大学的研究者在 IJCAI 2017 上发表的工作有助于理解特征迁移的机制 [Liu et al., 2017]。使用深度网络进行迁移学习，其可解释性同样待探索。最近 Google Brain 研究者提出的神经网络“核磁共振”现象，为可解释性提供了有趣的思路。

# 第11章 网络架构与训练实战
深度学习作为当前的研究热点，Google、Facebook、Microsoft、腾讯、百度等商业巨头均围绕其重点投入并持续支持开源深度学习框架。

研究者常用的框架各不相同，有 TensorFlow、Torch、PyTorch、Keras、MXNet、NEON、Caffe、Theano、Deeplearning4j、PaddlePaddle 等，被广泛应用于计算机视觉、语音识别、自然语言处理和生物信息学等领域。本章重点介绍 TensorFlow、Caffe 和 PyTorch 这三种开源框架，以及部分分布式深度学习框架，并介绍网络搭建原则与训练技巧。

## 11.1 TensorFlow
TensorFlow 支持多种异构平台，兼顾多 CPU/GPU、服务器、移动设备，具有良好的跨平台能力。架构灵活，可支持各类网络模型，通用性强；同时可扩展性出色，在算子扩展和 Kernel 特化方面表现突出。

TensorFlow 最初由 Google Brain 的研究员和工程师为机器学习与神经网络研究而开发。下面将介绍其设计理念、特点、系统架构、编程模型，并以基于 TensorFlow 搭建 VGG16 为例进行说明。

### 11.1.1 设计理念
TensorFlow 的设计理念主要体现在两个方面。

（1）将图定义与图执行完全分离。
TensorFlow 被视为“符号式”库。编程模式通常分为命令式编程和符号式编程。命令式编程易于理解调试，按逻辑顺序执行；符号式编程涉及大量嵌入与优化，不易理解调试，但运行速度更快。现有深度学习框架中，Torch 典型地采用命令式编程，Caffe、MXNet 采用混合模式，而 TensorFlow 完全采用符号式编程。

符号式计算一般先定义变量，建立数据流图，规定各变量间的计算关系，随后对数据流图进行编译，此时图仍为空壳，没有实际数据，只有输入数据进入后，数据流才会形成输出。

### 11.1.2 核心特点
概括起来，TensorFlow 具有以下特点。

（1）高度灵活。
TensorFlow 不仅是深度学习库，只要计算过程可表达为数据流图即可使用。用户可用 Python 编写上层结构和库，也可自行编写底层 C++ 代码，通过自定义算子将新功能加入 TensorFlow。

（2）真正的可移植性。
可在 CPU 和 GPU 上运行，也可在台式机、服务器、移动设备上运行。

（3）多语言支持。
采用 Python 构建和执行计算图，同时支持 C++。可直接用 Python、C++ 编程，也可借助交互式 IPython 实践想法。

（4）丰富的算法库。
在开源深度学习框架中，TensorFlow 提供了最全面的算法库且持续扩充，基本满足大部分需求，普通应用无需自行实现基础算法。

（5）完善的文档。
官方网站提供详尽的文档，包括各 API 用法介绍、基础应用示例以及部分深度学习理论。

自开源以来，大量 Google 员工、外研人员和独立程序员为 TensorFlow 作出贡献，使其社区成为 GitHub 上最活跃的深度学习框架之一。
