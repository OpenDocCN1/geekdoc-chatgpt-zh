OpenClaw 技能系统：按需加载与沙盒安全全解

OpenClaw 通过兼容 AgentSkills 的技能目录来扩充 Agent 能力。每个 Skill 就是一个独立文件夹，最核心的是里面的 SKILL.md，它由 YAML frontmatter 元数据和 Markdown 操作指令组成，用来告诉 Agent 在什么任务下加载该 Skill，以及加载后如何使用其中的能力。

按需加载实现 Token 省与能力无限

设计的核心是按需加载。系统提示词里只放一份所有 Skill 的精简摘要清单，每个条目约 97 个字符，折算约 24 个 Token。Agent 在处理任务时自行判断是否需要某个 Skill，就会调用 read 工具把完整的 SKILL.md 拉下来，按里面的说明执行。

这种做法很聪明：你可以往 Agent 上装几十上百个 Skill，除非真的用到，否则不会占用本次对话的 Token。能力的增减只需要操作 skills/ 目录里的文件夹，不用改动任何核心代码。

SKILL.md 写法规范

SKILL.md 必须以 YAML frontmatter 开头，用 --- 包裹，至少包含两个必填项：
- name：Skill 的唯一标识，建议用 snake_case，方便在配置文件里引用
- description：单行说明，Agent 就是靠它来判断是否需要加载。写得越精准，触发越准；写得模糊或太宽泛，就容易误触或漏触

正文里可以用 {baseDir} 占位符指向 Skill 目录的真实路径，方便引用同目录的脚本或模板。可选的 frontmatter 还有 homepage、user-invocable 默认 true、disable-model-invocation 默认 false，以及 command-dispatch、command-tool、command-arg-mode 等命令分发相关字段。

#### Skill 加载路径与优先级

同名 Skill 多处存在时，OpenClaw 按此顺序取胜：工作空间的 skills/ 目录最高，可覆盖其它位置；其次是 ~/.openclaw/skills/ 托管目录；再次是安装包内的内置 Skill；最低的是通过 skills.load.extraDirs 配置的额外扫描目录。

#### 加载门控精准过滤不适用 Skill

可通过 metadata.openclaw 做加载门控，在环境不满足时直接不加载，省 Token 也避免误导。支持的条件包括：
- always: true 无条件加载
- os 如 ["darwin"] 仅限 macOS
- requires.bins 必须存在于 PATH 的二进制
- requires.anyBins 满足其一即可
- requires.env 必须存在的环境变量，常用于检查 API Key
- requires.config 配置项必须生效
- primaryEnv 关联的主要 API Key 环境变量，用于 UI 显示认证状态

没有 metadata.openclaw 字段时，Skill 默认始终可用，除非在配置文件里显式禁用。

#### 安装器规格实现依赖自动安装

若 Skill 依赖外部工具，可在 metadata.openclaw.install 中声明安装方式。支持 brew、node、go、download 四种类型，多安装器时 Gateway 优先选 brew，其次 node。download 类型可配置 archive 解压、stripComponents 路径处理和 targetDir 目标目录。

#### 会话快照与热重载机制

每个会话开始时会做一次快照，当时符合条件的 Skill 列表被固定，会话期间保持一致。会话中途安装的新 Skill 要等下次会话才生效。

默认开启 skills.load.watch 后，OpenClaw 会监控 SKILL.md 的变动，修改后下一轮次自动热重载，无需重启 Gateway。防抖延迟默认 250 毫秒，避免频繁保存导致重复触发。

ClawHub https://clawhub.ai 是 OpenClaw 官方的 Skill 与插件中心，类似 npm 式的发现、发布、版本管理、社区反馈和安全审核。

#### 安全审核机制

发布者 GitHub 账号需注册超过一周。已发布 Skill 可被用户举报，独立举报累计 3 个及以上会被自动隐藏待人工审核，审核员可执行隐藏、删除、封禁等操作。

#### 沙盒安全为 Agent 划定边界

沙盒并非完美的安全边界，但能在模型误操作时实质性限制文件系统和进程的访问范围。Gateway 始终在宿主机运行不受沙盒限制，只有 exec、文件操作等工具在沙盒内执行。

#### 三种沙盒模式

- off 关闭沙盒，所有工具在宿主机直接运行，适合可信的单用户本地开发测试
- non-main 仅非主会话沙盒，主会话 session.mainKey 为 "main" 时在宿主机运行
- all 所有会话都在沙盒运行，隔离最强，适合多用户或不可信输入

#### 三种沙盒范围

- session 默认，每个会话一个独立容器，会话结束销毁，隔离最彻底但有创建开销
- agent 同一 Agent 的沙盒会话共享一个容器，跨会话保留状态
- shared 所有沙盒会话共享同一个容器，成本最低隔离最弱

#### 三种沙盒后端

Docker 后端默认，提供完整文件系统和网络隔离，默认 network: none，可配置自定义镜像、binds 挂载、setupCommand 等。全局和 per-agent 的 binds 会合并。

SSH 后端把 exec、文件、媒体读取卸载到远程主机执行，适合把负载从轻量 Gateway 转移。首次使用会把本地工作空间 seed 到远程，之后远程为权威状态，本地变更不自动同步。认证材料支持 SecretRef。

OpenShell 后端为 OpenClaw 托管的远程沙盒，复用 SSH 传输并增加生命周期管理。工作空间模式有 mirror 本地优先双向同步，和 remote 远程优先初次 seed 后不自动回同步。

#### 工作空间访问级别

workspaceAccess 控制容器对真实工作空间的权限：
- none 默认完全隔离，只能看到 ~/.openclaw/sandboxes 下的独立空间，OpenClaw 会自动镜像符合条件的 Skill 目录
- ro 只读挂载到 /agent，禁用写操作
- rw 读写挂载到 /workspace，行为与非沙盒一致

#### 沙盒中 Skills 的可用性

workspaceAccess 为 none 时 Skill 目录会被镜像进沙盒；为 rw 时可直接访问 /workspace/skills。若 Skill 依赖二进制，需在 sandbox.docker.setupCommand 安装或使用预置镜像。沙盒不继承宿主机环境变量，需通过 sandbox.docker.env 显式注入或烘焙到镜像。

### 15.5 Skills 配置参考与开发最佳实践

#### Skills 配置详解

所有配置在 ~/.openclaw/openclaw.json 的 skills 字段下，采用 JSON5 格式。

##### 顶层配置字段
- allowBundled 内置 Skill 白名单
- load.extraDirs 额外扫描目录
- load.watch 是否监听文件变更，默认 true
- load.watchDebounceMs 防抖时间，默认 250 毫秒
- install.preferBrew macOS 是否优先 Homebrew，默认 true
- install.nodeManager Node 依赖包管理器，默认 npm

##### 单 Skill 配置字段
在 skills.entries.<skillKey> 下可配置：
- enabled 是否启用
- env 运行时的环境变量补充
- apiKey 支持 SecretRef 对象，避免明文
- config 供 Skill 引用的自定义配置

##### 配置键映射规则
键默认对应 Skill 的 name，metadata.openclaw 中若定义 skillKey 则以 skillKey 为准。含连字符的键名需加引号。配置变更实时生效，无需重启。

#### 创建 Skill 的完整流程
第一步，在工作空间 skills/ 或全局 ~/.openclaw/skills/ 下新建以名称命名的文件夹。
第二步，编写 SKILL.md，完善 frontmatter 并写清使用指令。
第三步，可选地在正文中用 {baseDir} 引用同目录脚本或模板。
第四步，新 Skill 在下次会话快照时加载，开启 watch 后内容修改下一轮热重载，本地验证后再发布到 ClawHub。

#### Skills 开发的最佳实践

description 是 Skill 的灵魂。用“当用户...时触发”的句式列出场景和关键词，比笼统描述更精准。

用 requires 门控避免无效加载，依赖不满足时不出现在提示词里，既省 Token 也防止调用失败。

API Key 必须用 SecretRef，不要硬编码在 SKILL.md 或配置文件中，避免仓库泄露。

SKILL.md 正文应精简，只写“做什么”的明确步骤，减少背景论述以免干扰 Agent。

沙盒使用时注意二进制依赖需提前安装，以及环境变量需显式注入。
