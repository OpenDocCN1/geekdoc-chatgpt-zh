Token 级强化建模的思路可以从一次简单的问答拆开看。初始状态 s0 就是 Prompt “你是谁”，把 s0 喂给模型 M，M 会先算出词表里每个词作为下一个词的概率分布，再按这个分布抽样，最终把 “我” 选出来。

现在状态变成了 Prompt 加上刚生成的词，即 s1 = “你是谁我”。把 s1 再输入 M，模型重新计算整张词表的概率分布并抽样，这一次抽到的词是 “是”。

依此类推，每生成一个词就把它拼接到历史里，状态随之更新，M 不断预测下一个词，直到遇到结束符才停止。生成结束整段回答会被送进奖励模型打分，得到一个奖励分数。

从这个过程可以看出，Token 级的强化建模很自然。Prompt 被视作环境给出的初始状态 s0，每生成一个新 Token 就并入历史，进入新状态 s_{t+1} = s_t + new_token。大语言模型扮演策略网络的角色，输入状态输出下一个 Token 的概率分布，属于一种随机策略。抽样得到的 Token 可看作一次动作。等整段回答写完，奖励模型才给出最终分数。与常规强化学习不同，这里没有动作即时奖励，只有回答完成后才给一次终局奖励。如何给每一步设计即时奖励，是一个值得继续探索的问题。

为了更好理解，下面用一个具体的多轮对话来说明 Sentence-level 的强化建模。假设有一个大语言模型 M，按算法 6.2 进行多轮对话。

第一句话 l1 是用户的提问，可以把它当作初始状态 s0。模型把 l1 输入后生成第二句话 l2，这相当于针对 s0 的一次动作 a0，即 s0 = l1，a0 = l2，且 a0 = M(s0)。把 l1 + l2 一起送入奖励模型，模型会评价 l2 的质量并给出奖励 r0。

从例子可见，句级强化建模同样很自然。用户的首次提问被视作环境提供的初始状态 s0，模型回答后用户会继续追问，新问题加上历史信息构成新的状态。大语言模型相当于策略网络，先接收状态再产生回答。因为解码带有随机性，这种策略也是非确定性的。与 Token 级不同，句级每生成一次完整回答就完成一次动作，回答连同历史一起送入奖励模型评估，于是出现了即时奖励。

整体来看，Token 级建模多用于单轮场景，每次完整答案是一次实验，每个 Token 是一次动作。句级建模多用于多轮场景，也能退化到单轮，因为单轮是多轮的特例。每完成一次多轮对话相当于一次实验，每生成一个回答算一次动作。目前大多数开源 RLHF 框架使用 Token 级强化建模，但直觉上句级更贴合强化学习的场景。Token 级里环境仅提供初始 s0，后续状态转移只是把模型新生成的 Token 接上去，环境不干预，迁移完全由智能体主导。而句级里用户被视作环境，不仅给出初始 s0，在模型回答后还会提出新问题，从而形成新状态，状态迁移真正由环境控制。此外，Token 级没有即时奖励，句级有即时奖励，且奖励机制更自然。可惜目前还没看到句级强化建模的开源实现，只在 Anthropic 的论文[8] 中见到类似做法。Anthropic 的创始成员大多出自 OpenAI，OpenAI 是否也在用句级强化建模呢？这是一个很有意思的问题。鉴于开源框架的缺失，后续内容将主要围绕 Token 级强化建模的具体实现展开。

#### 6.5 奖励模型：RLHF 的评分大脑
奖励模型是 RLHF 的核心组件，为训练提供软监督信号，引导模型对齐人类价值偏好。一个足够鲁棒$^{①}$ 的奖励模型至关重要，直接影响大语言模型的性能。本节将系统介绍奖励模型，涵盖结构、训练方式、损失函数分析三个层面。

#### 6.5.3 损失函数的深层矛盾
6.5.2 节已介绍 Token-level 损失与 Sentence-level 损失。理论上 Sentence-level 损失更合理，因为训练目标与预测目标一致。那么为何业界仍大量使用 Token-level 损失？深入探究后，笔者对背后的动机有了新认识。

训练好的奖励模型不仅在强化训练阶段为回答打分，还会作为评论员模型的初始状态。6.3.3 节介绍过评论员模型，它对 V 函数建模，输入状态 s，输出从该状态出发按一定策略继续决策后能获得的期望回报。在 Token-level 强化建模中，每生成一个 Token 就定义一个新状态，即状态由 Prompt+已生成 Token 构成。由于评论员需要为每个状态估计期望回报，所以它必须为每个 Response Token 输出一个估计值。为了用训练好的奖励模型初始化评论员，需要让奖励模型对每个 Response Token 都能给出奖励值。

有了这一背景，再看式 (6.37) 的合理性。结合图 6.7 说明。pos 和 neg 前两个 Token 相同，到第 3 个 Token 分道扬镳，可称进入状态 A 和状态 B。从这两个状态继续生成，最终 pos 的结果更好。这在一定程度上说明状态 A 比状态 B 更优，即从 A 出发的期望回报高于从 B 出发。由于评论员在某个 Token 上的输出代表进入该 Token 后可获得的期望回报，于是自然可以约束第 3 个 Token 上 r_3^p > r_3^n。这个约束能推广到后面所有 Token 吗？显然不行。因为生成过程充满随机性，可能后续 pos 进入了更差的状态，后面又回升，最终仍优于 neg。也就是说，不能断言后续相同位置的状态中 pos 一定拥有更高的期望回报。

举个例子，假设有两个相同的空箱子 C 和 D，每天随机往里面各放一些砝码。前两天两个箱子放入的砝码重量相同，第 3 天放入的重量不同，最后发现箱子 C 的砝码质量更重。可以确认从第 3 天到最后，C 累计放入的砝码更重。但能否推出从第 4 天开始 C 累计放入的砝码一定更重？不一定。例如第 4 天到最后 C 累计比 D 轻 0.5kg，但第 3 天 C 比 D 重 10kg，最终 C 仍重 9.5kg。回到式 (6.37)，只能对第 3 个 Token 的奖励做对比约束，后续 Token 的约束无法保证。

从更严谨的角度看，对第 3 个 Token 做对比约束也不成立。因为 pos_response 和 neg_response 只是两次实验，两次结果说明状态 A 的期望回报高于状态 B，但这能证明 A 的期望回报一定更高吗？不能，仅靠两次实验无法可靠估计期望回报，必须大量随机试验才能得到较可靠估计。类似地，假设箱子里有五个红球、一个黄球，每次随机取一个球后放回。如果取两次都是黄球就得出黄球更多，这显然不可靠，需要多次抽样。因此仅对图 6.7 中第 3 个 Token 计算损失也是不合理的。

综合来看，即便出于初始化评论员的目的，式 (6.37) 的损失也难以自洽。如果真的用该损失训练奖励模型，推理时用所有 Token 奖励的均值作为最终奖励或许更合理。

受此启发，笔者认为对奖励模型训练，选用式 (6.39) 更合理。同时可用式 (6.37) 对评论员模型做预训练初始化，该损失仍需进一步优化。
