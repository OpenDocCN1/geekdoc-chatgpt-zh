### 5.2.5 邮件触发机制与通知系统架构

学会发送后，本节聚焦真实项目里邮件是怎么被触发的，以及通知提醒系统的整体构成。

该习惯追踪应用内置了一套邮件通知体系，覆盖 4 类核心提醒。

- daily_reminder：每日习惯提醒，用于督促用户完成当日任务。
- weekly_summary：每周总结报告，展示最近一周的习惯完成情况。
- achievement_alert：成就提醒，在用户达成特定里程碑时触发推送。
- welcome：欢迎邮件，帮助新用户快速上手。

当推送成功触发，例如欢迎邮件发送后，用户收到的效果如图 5-13 所示。

需要说明的是，当前版本尚未接入自动化定时触发，所以每周总结等定时邮件暂时无法自动发出。若要实现自动通知，可考虑以下方案。

- Vercel Cron Jobs：在 vercel.json 中配置定时任务。
- GitHub Actions：用 workflow 定时调用通知服务 API。
- 第三方调度服务：接入 cron-job.org 等外部专业调度服务。

[PRE4]

- Supabase Edge Functions：结合 pg_cron 扩展在数据库层实现定时任务。
- 客户端触发：在用户访问应用时，前端逻辑检测后触发相关通知。

整体设计灵活性较高，扩展性强，但自动化的落地依赖外部调度机制的支持。介绍完通知体系后，接下来将转向另一个关键的基础设施。
