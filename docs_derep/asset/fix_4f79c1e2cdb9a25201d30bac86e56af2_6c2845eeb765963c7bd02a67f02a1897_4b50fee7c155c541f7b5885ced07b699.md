如何挑选最合适的交互方式
把 DeepSeek R1 安置在本地后，与之交互的入口并不唯一。不同方案各有优劣，对应场景也不同。比如开发者更习惯直接在命令行操作，团队协作则更偏好有界面的网页方案。选对交互形式，才能在不同用途下最大化模型的价值。

表 8-1 对比三种交互方式

| 交互方式 | 安装复杂度 | 使用难度 | 是否支持历史记录 | 适合场景 |
| :--- | :--- | :--- | :--- | :--- |
| 终端模式 | 低 | 高（需要命令行） | 否 | 开发者、技术人员 |
| Open WebUI | 低（图形界面） | 低 | 是 | 团队协作、长期使用 |
| Chatbox AI | 低（图形界面） | 低 | 是 | 个人快速使用 |

从上表可以看出，不同方式对应不同需求。

- 若希望长期使用并获取更丰富的属性，如保存会话记录、支持多人协作，Open WebUI 更合适。
- 若只想快速对话且不想安装 Docker，Chatbox AI 是更省心的选择。
- 若习惯命令行且追求极简运行环境，直接使用终端模式也足够。

8.1.3 谁适合本地部署 与未来走向
本地化运行并非人人适用。若只是偶尔提几个问题，云端接口更省心；若对隐私要求高、需要高频长时间使用，或希望对模型进行个性化定制，本地化方案的优势才明显。

比较适配的对象包括：
- 对数据隐私要求严格的机构和企业，例如政府部门、医疗机构、金融机构等。
- 高频使用人工智能的个人或团队，例如客服、开发者、研究人员等。
- 需要让模型读取私有数据，例如企业内部文档、科研论文等。

随着计算优化技术的进步，未来在本地运行人工智能的门槛会持续下降，更多人能够拥有真正属于自己的智能助手。

8.2 通过接口调用实现自动化工作
上一节介绍了如何在本地部署并配置 DeepSeek 模型，也提到本地模型在隐私保护和离线使用方面的好处。但现实限制是，受硬件条件制约，绝大多数人无法完整运行 671B 参数的满血版 DeepSeek R1，体验会打折。

因此本节讨论另一种不打折、更偏自动化的用法——接口调用。接口调用能够让人工智能无缝嵌入工作流、应用和产品中。

如果你希望人工智能不只是聊天窗口，而是能在后台处理任务、接入业务系统，甚至成为产品核心能力，学会调用接口就是必备技能。

8.2.1 接口是什么？工作机制是怎样的
1. 接口的基本概念
接口即应用程序接口，本质上是不同软件或系统之间沟通的“桥梁”。常见例子：
- 在天气 App 中查看天气，实际上是通过接口调用气象服务商的数据。
- 在网站使用微信、支付宝付款，网站实际上是通过接口连接支付服务商。
- 在 AI 生成图片的网站输入文字描述，站点实际上是调用人工智能的接口，让服务器上的模型生成图片。
接口本质上是一套标准化的规则，允许你向某个系统发送请求并获得想要的数据或结果。

2. 接口调用的基本流程
使用接口与人工智能交互，大致流程如下。
（1）获取密钥：接口需要身份验证，必须先申请一个唯一的接口密钥作为身份凭证。
（2）发送请求：用代码如 Python、JavaScript 向 DeepSeek R1 服务器发送 HTTP 请求，并附带密钥。
（3）服务器处理请求：DeepSeek R1 的云端模型接收请求，运行计算并生成回答。
（4）返回结果：服务器将生成的文本返回，你可以在应用中展示或做进一步处理。

8.2.2 接口应用场景：让智能融入工作流
调用接口的最大优势是自动化，能在后台处理任务，无需手动对话。常见应用场景包括：
- 智能客服系统：企业使用接口让人工智能自动回复常见咨询，并生成智能工单。
- 自动写作与内容创作：批量生成文章、广告文案、社交媒体内容。
- 代码生成与编程助手：自动写代码、修复错误、优化算法。
- 语言翻译与文本处理：快速翻译长文本，或进行摘要和关键词提取。

8.2.4 如何优化接口调用，降低成本
接口的调用通常按 token 数量计费，频繁调用会产生较多费用。优化策略如下：
- 控制 token 数量，提高调用效率。
  - 限制 max_tokens 参数，避免生成过长内容。
  - 精简提问，避免冗余信息。
- 缓存常见问题：如果人工智能需要处理重复性问题，如 FAQ，可以缓存生成答案，避免重复调用。

- 更多企业和个人开发者会将人工智能接口嵌入产品，形成更智能的应用；
- 本地人工智能接口部署会越来越普及，让企业和个人拥有自己的智能体，而不再依赖云端。
