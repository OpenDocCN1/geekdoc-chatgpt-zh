# 从向量检索到图谱推理，RAG 的进阶之路

检索增强生成的思路很直接：让大模型在生成时能调取外部真实信息，从而提升准确性和时效性。如今绝大多数基于 LLM 的产品都内置了这类能力。最常见的做法依赖向量相似度进行召回，业内普遍称之为基础版 RAG。

在企业私域场景中，这套机制的价值很明显，比如内部研究、业务资料、沟通记录等。但基础版也有短板：当问题需要融合多处片段并提炼新洞察，或面对海量复杂文本做全局归纳时，它很难把握整体，处理大体量集合或单份长文档的语义时容易失焦。

为此，社区不断探索更强的方案。微软研究院提出的 GraphRAG 是一条典型路径。它让 LLM 从原文抽取实体与关系构建知识图谱，再结合社区级摘要和图学习结果来丰富提示。在复杂推理和智能化程度上，GraphRAG 相比基础 RAG 有明显提升，尤其适合对私有知识库做深度分析。

> ### 说明

值得注意的是，**GraphRAG 生成的知识图谱结构具有不确定性和动态性。**

不同大模型处理同一文档时，可能识别出不同的实体节点或语义关系。即使同一模型，不同批次运行也可能因上下文边界切分、token 微调等因素，得到略有差异的图谱结构。

索引流程中包含“社区总结生成”“节点描述生成”等 LLM 生成步骤，默认配置下是非确定性执行。因此相同数据源在不同时间点运行 graphrag index，也可能输出不同数量的节点、不同权重的边，乃至不同粒度的社区划分。

若对一致性有强需求，建议固定 temperature 并保存图谱快照以便复用。
