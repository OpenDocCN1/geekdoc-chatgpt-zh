## 第 13 章 LCEL 生产实战

本章先讲 LCEL 与 LCEL 链，再聊消息历史、聊天记录的存储与基础组件，最后讲怎么检验可运行对象。

### 13.1 LCEL 总览

LCEL 是 LangChain 推出的一种管道式语法，跟 Linux 的管道操作类似，用来快速拼装 LLMChain，完成对话调用、RAG 等任务。

#### 13.1.1 LCEL 怎么用

靠 LCEL，把若干条子链拼成新链很顺手。简单到指令加模型，复杂到多层编排，都能搞定。

使用 LCEL 的主要好处如下。

- 流式体验更顺滑：LCEL 拼出的链首 token 延迟极低，能把模型吐出的原始 token 直接递给流式解析器，解析速度可媲美模型本身的输出速度。
- 同步异步都能用：LCEL 同时支持同步调用和异步调用，Jupyter 里做原型、LangServe 上线都能用，兼顾效率与并发。
- 并行自动加速：链里只要有可并行的环节，LCEL 会自动调度，无论同步还是异步，都能把延迟压到最低。
- 重试回调可配置：链的任意节点都能挂上重试与回调，大规模运行时更稳。
- 能看到中间过程：复杂链可以流式透传中间结果，方便实时通知和排查问题，LangServe 也支持。
- 自动校验模式：LCEL 按链结构推导出 Pydantic/JSONSchema，用来校验输入输出，是 LangServe 的核心能力之一。
- 天然接入 LangSmith：链越复杂，LCEL 越会自动把每一步记到 LangSmith，可观测性与可调试性直线上升。
- 一键部署到 LangServe：LCEL 构建的链能直接塞进 LangServe，上线很顺滑。

#### 13.1.2 LCEL 的核心亮点

LCEL 具备以下特点。

- 接口统一：所有 LCEL 对象都实现 Runnable，提供了 invoke、batch、stream、ainvoke 等通用方法，链式调用自然获得批处理和流式能力。
- 原子组件丰富：LCEL 包含一批基本构件，拼链、并行、加备选、动态改参都变得简单。

#### 13.1.4 Runnable 接口详解

为了让自定义链更好写，LangChain 提供了 Runnable 接口。它集合了一组方法，让链的定义和调用保持统一。

接口主要暴露这些方法。

- stream()：流式返回响应的块。
- invoke()：调用输入的链。
- batch()：在输入列表上调用链。

异步方法如下。

- astream()：异步流式返回响应的块。
- ainvoke()：在异步输入上调用链。
- abatch()：在异步输入列表上调用链。
- astream_log(): 除最终响应外，还在进行中间步骤时进行流式返回。

##### 9. astream_log()

所有可运行文件均配备 astream_log()方法，流式处理链/序列的中间步骤。无论是展示进度、利用中间结果，还是进行链的调试，astream_log()方法都能发挥重要作用。

#### 13.1.5 流式处理

流式处理对于确保 LLM 应用对最终用户具有响应性至关重要。

关键的 LangChain 基本组件（如 LLM、解析器、指令器、检索器和代理）都实现了 LangChain 的 Runnable 接口。Runnable 接口提供了以下处理流式内容的方法。

- sync stream()和 async astream()：这两种方法是流式处理的默认实现，它将从链中流式传输最终输出。
- async astream_events()和 async astream_log()：这两种方法提供了从链中流式传输中间步骤和最终输出的方式。

#### 13.1.6 基于输入的动态路由逻辑

路由功能允许构建非确定性链，其中每一步的输出将决定下一步的执行。这种机制为与 LLM 的交互提供了清晰的结构和一致性。

关于路由操作，有两种主要方法可供选择。

- RunnableLambda()：RunnableLambda()方法允许有条件地返回可运行对象，是推荐的方法。
- RunnableBranch()：使用 RunnableBranch()方法可以实现路由操作。
