#### 8.1.10 LangGraph 驱动 AI Agent 的底层原理

##### 1. LangGraph 概览
从命名即可看出与 LangChain 的紧密关联。LangGraph 基于 LangChain 表达式语言构建，专门用于开发 AI Agent，因此在模型接入、能力复用与 Agent 搭建上的优势可直接继承。技术层面看，大模型本身不具备执行力，只能生成文本，即接收输入并给出回应。

##### 2. 基础图结构模型
以图为基础的体系中，任何可执行逻辑都可作为对话、智能体或程序的起点。起点可以是 LLM API、基于大模型搭建的智能体，或由 LangChain 等实现的线性序列，如图 8.13 中 Start 圆圈所示。无论形式如何，起点先处理用户输入再决定后续动作。图 8.13 展示了基于 LangGraph 思想的基础智能体模型。

LangGraph 将带执行逻辑的组件视作单元，涵盖模型调用、检索与条件判断。Start 单元作为入口，接收输入后可做如下处理。

- 1) 调度 Action 单元进行外部信息查询，例如网络检索、数据库查询或 RAG 检索。
- 2) 将获取的信息交给语言模型单元生成自然语言回复。
- 3) 最终把回复送至 End 单元结束整条链路。

如图 8.13 所示，这是一个基于 LangGraph 思想的基础智能体示例。每个圆圈代表一个单元，每条连线用于控制走向；状态沿连线以消息形式更新传递。

因此，无论智能体设计多么复杂，最终都是单元与连线按特定方式组合成的网络。这种工作流的核心在于：单元完成任务后会通过连线通知下一个单元继续执行。简言之，LangGraph 底层通过消息传递算法定义通用程序运行模式：单元完成操作后沿一条或多条连线向其他单元发送消息，接收方执行对应功能并把结果传给下一个单元，如此循环往复。

LangGraph 中 Router 以 if-else 形式决定路径，主要通过三种方式实现。

- 提示工程：指示大模型以特定格式作出回应。
- 输出解析器：用后处理从大模型回应中抽取结构化数据。
- 工具调用：借助大模型的内置工具调用功能生成结构化输出。

##### 4. 共享状态 State 机制
目前已清楚 LangGraph 通过单元与连线组合创建复杂循环工作流，并以消息传递串联各单元形成通路。那么如何让消息及时更新并送到正确位置，则依赖 LangGraph 的状态概念。在 LangGraph 流程中，每次执行都会启动一个状态，单元在处理时会传递和修改该状态。状态并非静态数据，而是随各单元输出动态更新，进而影响循环内的后续操作，如图 8.15 所示。

共享状态是指图执行过程中单元间传递的数据或信息。LangGraph 允许单元在执行时通过共享和更新公共状态交互。这种机制使单元能基于共同维护的数据通信、交换信息并相互影响行为。借助共享状态，LangGraph 可以协调和同步单元操作，支持动态交互和复杂工作流构建，使单元能依据已有共享信息协同工作并作出决策。

##### 5. 官方定位与优势汇总
从官方定义看，该框架是用于基于大模型构建有状态、多参与者应用的库，可创建 Agent 和多 Agent 工作流。官方归纳的优势如下。

- 循环与分支：在应用中实现循环和条件判断。
- 持久性：在图每一步后自动保存状态。可随时暂停和恢复执行，以支持错误恢复、人机交互流程、时间旅行等。
- 人机交互：中断图执行以批准或编辑 Agent 计划的下一步操作。
- 流支持：每个单元生成的流式输出，包括令牌流。
- 与 LangChain 集成：LangGraph 与 LangChain 和 LangSmith 无缝集成。
