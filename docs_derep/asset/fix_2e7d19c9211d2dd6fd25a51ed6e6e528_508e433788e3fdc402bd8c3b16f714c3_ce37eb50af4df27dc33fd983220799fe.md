3．高风险工具的额外安全控制

平台内少数能力具备极高的破坏潜力，默认提供多层闸门。

exec 是最强也是最危险的组件，围绕它设计了三层管控。tools.exec.security 决定命令执行策略：deny 完全封禁 Shell，适合对安全要求极致的场景；allowlist 只放行 tools.exec.safeBins 白名单内的命令，在防护和可用性之间取舍；full 解放全部命令，灵活度最高但风险也最大，建议仅在完全受控的个人环境使用。tools.exec.ask 控制执行前的人工确认：off 直接运行，利于高度自动化；on-miss 仅在命令不在白名单时弹窗询问；always 要求每次都必须明确授权，提供最强人工监督。tools.exec.host 决定运行位置：sandbox 为默认隔离容器；gateway 在 Gateway 主机上直接执行，权限极高风险大；node 可投递到指定的远端节点。

gateway 工具可调用 config.apply、config.patch、update.run 等接口，对 OpenClaw 做持久化配置变更，权限极高。只要 Agent 可能接触到不可信输入，就必须明确禁止该工具。

cron 工具可在对话结束后创建持续生效的定时任务。一次成功的提示词注入就能植入长期运行的恶意任务，因此在处理不可信内容的 Agent 中也应禁止 cron。

5．安全加固基线配置

官方给出了一套 60 秒加固基线，可作为新环境的最小权限起点。示例如下：

{
  "gateway": {
    "mode": "local",
    "bind": "loopback",
    "auth": {
      "mode": "token",
      "token": "replace-with-long-random-token"
    }
  },
  "session": {
    "dmScope": "per-channel-peer"
  },
  "tools": {
    "profile": "messaging",
    "deny": [
      "group:automation",
      "group:runtime",
      "group:fs",
      "sessions_spawn",
      "sessions_send"
    ],
    "fs": { "workspaceOnly": true },
    "exec": { "security": "deny", "ask": "always" },
    "elevated": { "enabled": false }
  },
  "channels": {
    "whatsapp": {
      "dmPolicy": "pairing",
      "groups": {
        "*": { "requireMention": true }
      }
    }
  }
}

该最小权限带来的效果是：
Gateway 仅绑定本地回环并强制令牌校验，形成网络边界；每个渠道与联系人组合拥有独立 DM 会话，从源头避免上下文串扰；工具集收敛为消息类，其余自动化、运行时、文件系统能力全部禁用；Shell 执行被彻底禁止，消除最高风险向量；WhatsApp 私聊需配对认证，群聊需 @ 明确提及才触发，防止误唤醒。

4.3.4 安全审计与应急响应

平台内置自动化审计与标准化应急流程，帮助快速定位风险并控制损失。

1．内置安全审计命令

统一入口可自动扫描常见配置缺陷。
入站访问：核查 DM 策略、群组策略与白名单是否合理，确保只有授权主体能唤醒 Agent；
工具辐射面：评估权限提升是否会让提示词注入演变为 Shell、文件系统或网络操作；
网络暴露：检查 Gateway 绑定地址、认证配置、Tailscale Serve/Funnel 使用及令牌强度；
浏览器控制暴露：审查远端节点配置、中继端口开放与远程 CDP 访问控制；
本地磁盘卫生：检查关键文件权限、符号链接指向、配置文件包含关系与同步文件夹路径；
插件：确保所有扩展在显式白名单内，未经审查的插件可能引入未知风险；
策略漂移：定期比对配置是否被意外变更，并排查常见配置陷阱。

常用命令：
# 基础审计
openclaw security audit
# 深度审计，含实时 Gateway 探测
openclaw security audit --deep
# 自动修复可修复问题如文件权限
openclaw security audit --fix
# 输出 JSON 方便接入 CI/CD
openclaw security audit --json

2．安全事件应急响应步骤

怀疑遭受攻击或数据泄露时按以下流程处置：
遏制：立即执行 openclaw stop 停止 Gateway，断开所有外部渠道，防止扩散。
轮换：若凭证可能泄露，立刻轮换所有 API Key 与认证令牌，使旧凭证失效。
审计：检查 ~/.openclaw/agents/*/sessions/*.jsonl 中的完整历史，还原事件期间的操作并评估损失。
收集：完整保存相关日志与配置文件，为后续分析、复盘与合规提供证据。

4.4 定时任务（Cron）与自动化工作流

OpenClaw 不仅被动响应请求，通过内置 Cron 还能主动按计划触发 Agent Loop，实现端到端自动化，是从聊天工具升级为个人自动化平台的关键。

4.4.1 Cron 任务的工作原理

Cron 本质是预定的 Agent Loop 触发器，按时间点以特定初始消息启动一次会话。其 sessionKey 格式为 cron:<jobId>，历史与普通 DM 完全隔离。

在 openclaw.json 中静态定义的任务会在 Gateway 启动时自动注册，例如：

{
  "cron": {
    "jobs": [
      {
        "id": "daily-morning-brief",
        "schedule": "0 8 * * *",
        "agentId": "main",
        "message": "早上好！请执行以下任务：\n1. 检查今天的天气预报（通过 web_search 搜索）\n2. 查看 GitHub 上我关注的仓库有哪些新的 Release\n3. 总结昨天的工作日志（读取 memory/yesterday.md）\n4. 将以上信息整理成一份简洁的晨报，通过 WhatsApp 发送给我（+8613800138000）",
        "timezone": "Asia/Shanghai",
        "enabled": true
      },
      {
        "id": "weekly-code-review",
        "schedule": "0 10 * * 1",
        "agentId": "work",
        "message": "请执行每周代码审查任务：\n1. 扫描~/projects/main-project/src 目录下所有修改时间在最近 7 天内的 Python 文件\n2. 对每个文件进行代码质量检查\n3. 生成代码审查报告，保存到~/reports/code-review-$(date +%Y%m%d).md\n4. 通过 Slack 发送摘要给#code-review 频道",
        "timezone": "Asia/Shanghai",
        "enabled": true
      }
    ]
  }
}

对话中也可通过 cron 工具动态创建任务，任务会持久化，重启后依然有效。

Cron 采用标准 5 段表达式：分钟 0~59、小时 0~23、日 1~31、月 1~12、星期 0~6，格式 * * * * *。系统完整支持时区，可为每个任务单独指定 Asia/Shanghai、America/New_York 等，确保按本地时间触发。

4.4.2 构建实用的自动化工作流

Cron 的价值在于与工具调用结合形成闭环。

1．每日晨报自动化
工作日 7 点触发，执行 web_search 获取科技新闻、抓取 GitHub Trending、读取 MEMORY.md 项目记录，整理成 Markdown 晨报，通过 message 工具推送到指定 WhatsApp，并存档。

{
  "id": "daily-morning-brief",
  "schedule": "0 7 * * 1-5",
  "agentId": "main",
  "message": "执行每日晨报任务。请按以下步骤操作：\n\n1. 使用 web_search 搜索今天的科技新闻（关键词：AI,开发者工具,创业）\n2. 使用 web_fetch 获取 https://github.com/trending 的内容，提取今日 GitHub 热门项目\n3. 读取 MEMORY.md 中关于我当前项目的记录\n4. 将以上信息整理成一份 Markdown 格式的晨报，格式如下：\n   - ���� 今日科技要闻（3-5 条）\n   - ���� GitHub 热门项目（Top 5）\n   - ���� 今日待办（基于我的项目进展）\n5. 将晨报内容通过 message 工具发送到 WhatsApp 会话（sessionKey: agent:main:whatsapp:+8613800138000）\n6. 将晨报内容保存到 memory/morning-brief-$(date +%Y%m%d).md"

每周一 9 点进入 ~/projects/my-app，查看最近 7 天提交、运行 npm audit、npx depcheck、统计 TODO/FIXME/HACK 数量，生成健康报告，Critical 漏洞时通过 Slack 紧急通知 #security 频道。

{
  "id": "repo-health-check",
  "schedule": "0 9 * * 1",
  "agentId": "work",
  "message": "执行每周代码仓库健康检查。请按以下步骤操作：\n\n1. 进入~/projects/my-app 目录\n2. 运行 git log --since='7 days ago' --oneline 查看本周提交记录\n3. 运行 npm audit 检查安全漏洞\n4. 运行 npx depcheck 检查未使用的依赖\n5. 检查 TODO 注释数量：grep -r 'TODO\\|FIXME\\|HACK' src/ | wc -l\n6. 生成健康报告，包含：本周提交数、安全漏洞数、未使用依赖数、技术债务（TODO 数量）\n7. 如果发现严重安全漏洞（Critical），立即通过 Slack 发送紧急通知到 #security 频道\n8. 将完整报告保存到~/reports/repo-health-$(date +%Y%m%d).md",

}
