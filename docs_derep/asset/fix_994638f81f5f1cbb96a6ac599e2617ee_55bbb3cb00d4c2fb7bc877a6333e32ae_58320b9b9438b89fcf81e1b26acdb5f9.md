**5.3.5 工具调用**

实际部署中，仅靠模型推理在需要执行具体操作或跨系统调用时风险更高。引入工具调用后，模型可在推理中调用外部函数或服务，把复杂推理与结构化执行分离，模型专注决策规划，执行交由可控工具完成。

借助 Langgraph 可把流程结构化，将每个工具封装为图节点，结合 OpenAI Function Calling 实现自动化调用，使智能体能够：

· 按意图自动判断是否调用、调用哪个工具及参数。
· 必要时通过工具获取真实世界数据辅助推理。
· 把执行结果回传给模型用于下一步推理或回复。
· 在流程中保留可观测中间态，便于调试审计优化。

这样推理、执行、反馈解耦，形成可维护可追踪可控的执行链，适合复杂业务与跨系统协作的生产级应用。下面先讲工具定义与执行，再讲模型绑定。

· ToolNode：把已定义工具封装为可执行节点，模型发出调用后触发真实执行并把结果传回。

**5.4 典型 Agent 示例**

本节介绍实际应用中常见的 Agent 实现范式，包括 CRAG、ReAct 和 Supervisor 三类，覆盖从单步决策到多步推理、从自主执行到可控监督的不同路径。

（1）CRAG 融合检索增强生成与纠错机制，让 Agent 在生成答案的同时具备反思修正能力，提升准确性与可靠性。
（2）ReAct 结合推理与行动，让 Agent 边思考边行动，通过自然语言链式推理引导工具调用，是检索增强型 Agent 的常用思路。
（3）Supervisor 模式引入人类或系统监督作为外部可控环节，将中间状态或关键决策回传校验，适合对安全性要求高的生产环境。

下面结合既有知识展示三个示例，帮助在不同业务需求下选择合适的实现方式。

**5.4.1 CRAG**

**5.4.2 ReAct**

ReAct 是构建复合型 Agent 的常用范式，通过让大模型先对用户问题进行自主推理，再根据推理结果自动触发工具调用，并结合调用结果生成最终回复，实现高效可控的链式推理与工具调用闭环。
