#### 8.1.10 LangGraph构筑智能体的核心机制

##### 1. LangGraph的来龙去脉
名字上看 LangGraph 与 LangChain 关系密切，事实上它正是基于 LangChain 表达式语言搭建的 Agent 开发框架。因此在 LLM 接入、能力复用以及 Agent 搭建方面的优势都能直接继承。回到 LLM 本身，它并不能主动执行动作，核心能力仅限于生成文本：接受用户输入并返回对应回应。

##### 2. 图结构与节点边的基础模型
在图式框架里，具备执行能力的任何组件都可以作为对话或程序的入口。这个入口可能是大模型 API、基于大模型构建的智能体，或是 LangChain 实现的线性序列，如图8.13 中标记为“Start”的圆圈。无论形态如何，入口首先解析用户输入并决定下一步走向。

在 LangGraph 里，所有可执行逻辑都被抽象为节点 Node，涵盖模型调用、搜索操作、条件判断等。“Start”节点作为入口接收输入后会：

- (1) 触发 Action 类节点进行外部查询，例如 Web 搜索、数据库检索或 RAG 召回；
- (2) 把查询结果交给 LLM 节点生成自然语言回复；
- (3) 最终把回复送入 End 节点结束链路。

如图8.13 所示，这是一个典型的基础 Agent 图。每个圆圈代表一个节点，每条连线代表一条边控制流向；状态沿边以消息形式更新。

因此无论 Agent 多复杂，本质都是节点与边按特定方式组合而成的图。工作流的核心在于：节点完成任务后通过边通知下一个节点继续执行。换句话说，LangGraph 的底层消息传递机制定义了通用运行模式：节点完成后沿一条或多条边向其他节点发送消息，接收方执行后将结果继续传递，如此循环往复。

##### 4. 共享状态机制
了解了节点与边的组合方式后，关键在于如何让消息及时更新并送达正确位置，这依赖 LangGraph 的 State 概念。每次执行都会初始化一个状态，节点在处理时会读取并修改它。状态并非静态快照，而是随节点输出动态演化，进而影响后续循环，如图8.15 所示。

共享状态指图执行过程中节点间传递的数据。LangGraph 允许节点通过读写公共状态来交互，使各节点能在同一份数据上通信、交换信息并相互影响。借助共享状态，系统能够协调节点操作、实现同步，支持动态交互与复杂流程构建，让节点依据已有信息协同决策。

##### 5. 官方定位与核心优势
官方将 LangGraph 定义为基于大模型构建有状态、多参与者应用的库，可用于创建 Agent 与多 Agent 工作流。总结的优势包括：

- 循环与分支：可在应用内实现循环与条件判断；
- 持久化：每个步骤后自动保存状态，支持随时暂停恢复、错误恢复、人机协作流程、时间旅行等；
- 人机交互：可在执行中中断以审批或编辑 Agent 下一步计划；
- 流式输出：每个节点均可流式输出，包括 token 流；
- 与 LangChain 集成：与 LangChain、LangSmith 无缝衔接。
