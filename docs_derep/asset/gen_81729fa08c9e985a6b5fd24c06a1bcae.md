在库存系统里，一次数量更新往往需要牵动多个环节同时响应。传统观察者模式能做到“一改多知”，但全部同步回调容易拖慢主流程。把部分观察者切到异步执行，就能在保证即时感知的前提下降低阻塞风险。

下面这个实现用一个带线程池的被观察者 ProductInventory 统一分发变化。普通观察者走同步 update，实现了 AsyncObserver 的观察者则走线程池提交 updateAsync。订单管理对时效不敏感的处理走异步，库存管理走同步调整，两者并存不冲突，职责清晰。

核心思路是：状态变更只负责触发，通知方式由观察者类型决定，同步异步共存，提升响应效率。

class ProductInventory implements Observable {

    private List<Observer> observers = new ArrayList<>();

    private int quantity;

    private ExecutorService executor = Executors.newFixedThreadPool(5);

    public void setQuantity(int quantity) {

        this.quantity = quantity;

        notifyObserversAsync();

    }

    public void addObserver(Observer observer) {

        observers.add(observer);

    }

    public void removeObserver(Observer observer) {

        observers.remove(observer);

    }

    public void notifyObservers() {

        for (Observer observer : observers) {

            observer.update();

        }

    }

    public void notifyObserversAsync() {

        for (Observer observer : observers) {

            if (observer instanceof AsyncObserver) {

                executor.submit(() -> ((AsyncObserver) observer).updateAsync());

            } else {

                observer.update();

            }

        }

    }

}
