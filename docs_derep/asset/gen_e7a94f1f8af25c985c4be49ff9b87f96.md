其中 ReAct 框架表现亮眼，已被 LangChain、LlamaIndex 等众多 AI 应用开发框架选用为推理核心。它提供了兼顾强大与灵活的架构，支撑打造具备复杂推理能力和高效行动能力的智能体。

### 1.2.4 智能体如何连接现实世界

大模型在信息理解上很强，却无法直接感知现实并产生影响，这限制了它在需要对接外部系统或数据的场景中的可用性。某种程度上，模型的上限被训练数据所框定，再多数据也补不上与外界实时互动的能力。怎么让大模型获得实时交互与上下文感知？关键路径是函数调用、插件扩展和数据存储。

#### 1．函数调用
函数调用是打通大模型与外部工具的桥梁。调用时用户可为模型描述函数，包括功能说明、入参要求、出参说明，模型据此从自然语言输入中判断该调哪个函数，并把请求参数以 JSON 形式返回。用户拿着模型返回的函数名与参数去执行，得到结果后再喂回给模型，由模型整理成自然语言回复。

#### 2．插件扩展
插件可以独立开发，但作为智能体配置的一部分被挂载。运行中模型结合示例判断哪款插件最匹配当前问题，这正是插件内置示例带来的动态择优优势。借助调用外部 API 等方式，插件能赋予智能体原生不具备的能力，显著拓宽可操作边界。

常见可分为三类：一是信息增强类，用来获取实时或专业信息，比如股价、最新资讯；二是服务增强类，用来自动化日常操作，比如机票预订、外卖下单；三是交互增强类，可接收知识库、PDF、图片、语音等多模态输入，并产出表格、思维导图等多模态结果。

#### 3．数据存储
数据存储让模型能触达最新事实，保证回答基于当下情境。原理是将用户提供的原始文档转成向量集合，供智能体检索所需信息，进而支撑下一步行动或回复决策。

通常落地为向量数据库，这类数据库专为高维向量设计，支持运行期快速召回相关信息。检索增强生成 RAG 技术让智能体能迅速访问网站、PDF、CSV 等多种格式数据，扩展知识广度与深度。

上述机制名称虽不尽相同，却共同架起基础大模型与外部世界的通道，让智能体既能完成任务，又能更准确可靠。例如调节智能家居、更新日历、从库里调取用户信息，或按指令发送邮件。

### 1.2.5 从流程到智能体工作流

传统工作流是一组按预设规则和顺序执行的任务集合，强调标准化与自动化，确保事事按部就班。常见实现基于流程图或状态机，用 BPMN、Airflow 等工具落地，适合结构化、可重复的场景。如软件开发中的“提交代码→评审→测试→部署”，每一步都有明确依赖与触发条件。

到了 AI 时代，工作流与智能体不是对立而是融合，形成智能体工作流。这种新方法把传统流程管理与 AI 智能体结合，用大模型为底座，多智能体协同把复杂任务拆成可控子任务，并通过迭代细化逼近目标。

通俗讲，工作流是蓝图，智能体是执行者。流程提供秩序与可预测性，智能体提供智慧与灵活性，适应多变环境。二者边界在模糊，配合使用价值更大。

标准化落地常见三种形态：链式工作流、并行化工作流、路由工作流，智能体的动态决策则进一步拓展边界。

#### 1．链式工作流模式
多个环节按线性排列，前一步输出直接喂给后一步，形成连续处理链。清晰的顺序简化复杂任务，每个环节依赖上游结果，保证数据一致性。适合步骤明确且强依赖的场景，如新闻推荐中的内容筛选与排序。

#### 2．并行化工作流模式
多任务或多数据集同时推进，提升数据密集型操作的效率，缩短整体耗时，实现算力合理分配与吞吐量提升，并便于横向扩展。适合可独立执行的任务、需快速处理海量数据或多请求的场景，如大数据分析、实时监控、复杂决策支持。

#### 3．路由工作流模式
依据输入条件动态挑选执行路径，无需固定序列即可适应不同情况。任务按特征被分发到最合适的节点，提升资源使用效率。适合处理逻辑随输入特征变化的场景，如金融服务平台按用户兴趣主题把请求路由到不同 API 端点。 EXr6287u6NNVz+GYLY+7SDk226FstKIHdC0bNoQkB2Nqi1xSR0yxPmwrTs5gRi/BtfSbid6dBhii9q7cz2pIyA==

要读懂智能体内部运行方式，需要看清其核心模块、设计范式与推理引擎。

### 1.2.1 智能体的四大核心模块

在大模型驱动的智能体里，大模型相当于“大脑”。整体通常由记忆、规划、工具、行动四个核心模块构成，如图 1-1 所示。

（1）记忆模块负责信息存取，既有历史交互与学到的知识，也有临时任务信息。好的记忆机制让智能体能在新问题面前调用过往经验。记忆分短期与长期，短期用于上下文学习 in-context learning，长期则借助外部数据库与快速检索实现长期保留与召回。

（2）规划模块包含事前规划与事后反思。事前规划是对未来行动的预测与决策，帮助高效排布步骤。事后反思让智能体审视与改进方案，从错误中学习并沉淀到长期记忆，更新世界认知。常用方法有反射、自我反思、思维链、子目标拆解。

（3）工具模块让智能体调用外部资源完成任务，可通过 API 补齐模型数据盲区，也能用专业软件处理海量数据，从而提升效率与完成度。

（4）行动模块负责把决策落地。智能体拥有多种行动策略，可根据任务选择记忆检索、推理、学习、编程等不同方式执行。

### 1.2.2 主流设计范式

2024 年 3 月 26 日，吴恩达在红杉资本 AI 峰会演讲《Agentic Reasoning》中分享了四大主流设计范式：反馈、工具使用、规划、多智能体协作。

（1）反馈范式通过自我反思与迭代，让大模型不断修正输出，提升执行质量。

（2）工具使用范式让模型调用外部工具或库，摆脱纯知识依赖，提高效率与准确性。

（3）规划范式先做计划再分步执行，把复杂任务拆解为有序步骤。

（4）多智能体协作范式由多个智能体分工、交流、协同，共同攻克复杂问题。

### 1.2.3 推理引擎的选择

推理引擎即认知框架，是智能体做决策、调工具、执行行动的核心。它依托提示词工程与相关框架指导推理与规划，让智能体更有效与环境交互。

当前研究涌现出多种方案，如推理与行动 ReAct、思维链 Chain of Thought CoT、思维树 Tree of Thoughts ToT 等。

（1）ReAct 提供一种思考-行动策略，能在有无示例的情况下根据用户输入推理并行动。它在多项指标上胜过不少基线，也增强了人机互操作与可信度。

（2）CoT 通过中间步骤实现推理，包含自我一致性、主动提示、多模态 CoT 等子技术，各有优劣。

（3）ToT 适合探索与战略性问题，扩展 CoT 思路，让模型探索多条思维路径作为通用问题的中间步骤。

智能体可单用或组合这些引擎，为特定请求制定最优下一步策略。其中 ReAct 脱颖而出，被 LangChain 与 LlamaIndex 等框架作为推理引擎，采用其强大灵活的结构来构建能复杂推理并有效行动的智能体。

### 1.2.4 智能体怎样与外部交互

大模型擅长处理信息却缺乏直接感知与干预现实的能力，这使其在需要对接外部系统或数据的场景受限。模型性能本质上被训练数据边界所限，缺少与外界互动的基础能力。要赋予实时交互与上下文感知能力，可通过函数调用、插件扩展、数据存储实现。

#### 1．函数调用
函数调用是模型与外部工具联通的机制。调用时用户描述函数的用途、入参与出参，模型据用户自然语言选择函数并把参数转为 JSON 返回。用户执行函数并把结果回传，模型再组织成自然语言回答。

#### 2．插件扩展
插件可独立开发但作为智能体配置的一部分提供。运行期模型结合示例判断最适配的插件，内置示例让动态选择成为可能。插件通过调用外部 API 等方式扩展智能体能力。

三类常见插件：信息增强型，获取实时与专业信息如股价、新闻；服务增强型，自动化预订、点餐等常见任务；交互增强型，接收知识库、PDF、图片、语音等多模态输入，生成表格、思维导图等多模态输出。

#### 3．数据存储
数据存储为模型提供最新信息访问，保证回答基于时效事实。做法是把原始文档向量化，供智能体检索补充决策信息。

通常采用向量数据库，专为高维向量设计，支持运行期快速召回。RAG 技术让智能体能快速读取网站、PDF、CSV 等多样数据，拓宽知识广度与深度。

这些机制共同构成大模型与外界的桥梁，让智能体更可靠地完成任务，如调节家居、更新日历、调取用户信息、按指令发邮件等。

### 1.2.5 智能体工作流的演进

传统工作流是按预定义规则顺序执行的任务集合，强调标准化和自动化，常基于流程图或状态机、以 BPMN、Airflow 等实现，适合结构化重复任务，如“代码提交→评审→测试→部署”。

AI 时代，工作流与智能体融合为智能体工作流，以大模型为基础，多智能体协作把复杂任务拆解为子任务并迭代细化。工作流是蓝图提供秩序，智能体是执行者提供智慧与灵活性，二者结合价值更大。

三种典型模式：链式、并行化、路由。

#### 1．链式工作流模式
步骤线性排列，输出串联输入，形成处理链，简化复杂任务并保证一致性。适合顺序明确且强依赖的场景，如内容筛选排序。

#### 2．并行化工作流模式
多任务并行处理数据密集操作，提升效率与吞吐量，便于扩展。适合可独立执行、需快速处理海量数据或多请求的场景，如大数据分析、实时监控、决策支持。

#### 3．路由工作流模式
依据输入条件动态选择路径，无预设序列即可适应变化，提升资源利用率。适合输入特征决定流程的场景，如按用户兴趣把请求路由到不同 API。 EXr6287u6NNVz+GYLY+7SDk226FstKIHdC0bNoQkB2Nqi1xSR0yxPmwrTs5gRi/BtfSbid6dBhii9q7cz2pIyA==
