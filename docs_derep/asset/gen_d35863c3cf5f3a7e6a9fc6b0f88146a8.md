OpenClaw 让人担心的原因，并不是智商太高，而是动手能力太强。一旦它能触碰到系统资源、浏览器会话、群聊入口、自动化流程以及外部接口，风险等级就从单纯的内容产出，跃升为系统层面的风险。给它加上风控，并不是添麻烦，而是在真正投入使用前必须先完成的底座工作。

### 6.2 安全起步：先把范围锁在本地

很多人第一次跑配置向导，面对一串英文选项容易慌张。新手其实只需要抓住一个安全逻辑：先把 OpenClaw 关在自己电脑里。

初始向导默认走 QuickStart，配置大多是预设好的。想更安全，就在终端重新执行 openclaw onboard，切换到 Manual 手动模式，自行调整涉及安全的参数。模型、技能等此处不展开，重点从 Gateway port 开始往下看。

#### 1. Gateway port
这里显示的 18789 就是网关默认监听的端口，可以理解为系统对外等待连接的门牌号。数字本身不是安全关键点，普通用户保持默认值即可。真正决定安全的是端口被绑定在哪个网络地址上。

#### 2. Gateway bind
这个选项决定网关绑定在哪个网络地址，也决定谁有机会连进来。零基础建议选择 Loopback(127.0.0.1)。选择它的含义是只允许本机访问，只有这台电脑能直接连上 OpenClaw，局域网内其他设备和外部网络用户都无法直接触达。

### 6.3 预算防护：给模型设消费上限

用 OpenClaw 或其他 AI 智能体时，成本控制非常现实且紧迫。工具很强大，但没有预算防护，意外的高额账单会给个人或企业带来压力。

#### 1. OpenClaw 的钱是怎么花出去的？
OpenClaw 本身免费开源，花钱的是它调用的“大脑”，按量付费。

计费单位是 Token，可理解为字数。你发给 AI 的指令、网页内容、文档内容，以及它生成的回答和代码，都是字。AI 每读一个字、每输出一个字都在消耗 Token。

如果 OpenClaw 陷入死循环，比如不断重试失败操作，就像计价器停不下来的出租车，费用会飞快累积。

要保护钱包，需要主动设上限，在使用前给工具设定硬件和软件阈值，同时借助供应商的 API 或 Webhook 实时获取余额，进行动态监控。

### 6.4 细节防护：两处新手最容易踩坑

除了前文的风控项，还有两个极易被忽略的细节。

#### 1. 飞书群使用规范：谨慎引入 OpenClaw 机器人
很多新手觉得机器人好用，就随手把它拉进工作群。这个不起眼的小动作，正是超额账单、合规追责、数据泄露事故的常见源头。

##### （1）随意拉群的 3 个核心风险
随意将 OpenClaw 机器人拉进群会带来安全与成本风险。

- ① 超额账单风险。即便在飞书开放平台提前限定了机器人的可用范围，机器人进群后群内所有在白名单内的人都能通过 @ 方式调用。大量的非工作、无效、高频调用都会计入搭建者账号，月底极易超额，且在匿名调用场景下难以追溯，最终成本由搭建者承担。
- ② 合规追责风险。若机器人被拉进人员混杂的临时群、跨部门协作群或外部合作群，群内人员用机器人生成违规内容或敏感信息，最终的账号主体责任和合规风险全部由搭建者承担。轻则被封禁，重则被模型供应商追责甚至面临监管处罚。
- ③ 数据泄露风险。若 OpenClaw 已绑定企业内部知识库、核心业务文档、项目机密，机器人进无关群后，群内人员可通过提示词、上下文诱导调取未公开的内部数据，造成不可逆的商业数据泄露。

##### （2）飞书拉群的 3 条安全操作规范
- ① 坚守“非必要不拉群”核心原则。仅将机器人拉进日常核心工作必需的固定专属群，如核心运维群、固定内容创作群、专属项目执行群。临时协作群、闲聊群、非相关工作群、全员通知群一律不得拉入。
- ② 拉群前必须完成“双核查”。一是群内人员核查，确认所有成员都在预设的机器人可用白名单内且有使用需求；二是使用规则提前约定，拉群前在群内明确公示机器人的使用范围、禁止调用的内容与场景。
- ③ 定期完成群权限清理。每周固定核对一次机器人所在的所有飞书群，确认是否还有持续使用需求，对无需求、项目已结束的群立即移出机器人，缩小权限暴露面。
