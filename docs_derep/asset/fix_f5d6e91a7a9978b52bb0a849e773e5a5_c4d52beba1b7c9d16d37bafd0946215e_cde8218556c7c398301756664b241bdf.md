# 第4章 记忆工程：让 Agents 拥有长短期上下文管理

构建Agent系统时，对对话信息的持久化与精准检索，是提升智能水平的关键。以金融理财为例，AI助手不仅要处理当前对话，还需整合用户财务状况、投资偏好与历史交易数据。技术难点在于长周期多轮对话中如何精准提取并存储关键信息片段，从而在后续决策中提供个性化风险预警与资产配置方案。类似地，在智慧医疗场景，系统通过持久化病史、检查报告与诊疗反馈，可在复诊时快速检索历史上下文，辅助医生制定更具针对性的循证方案。随着应用场景扩展，记忆工程已成为Agent设计的核心环节。本章将解析长短期记忆结合的对话管理机制，探讨构建高效可靠的Agent记忆系统的方法。

## 4.1 理解 Agent 记忆的必要性

本节从 Agent 为何需要记忆出发，剖析记忆工程在复杂Agent系统中的必要性。

### 4.1.1 短期记忆：绕开大模型的无状态短板

主流大模型本质上是无状态的，每次API调用都是独立计算，模型不会自动保留历史对话。这导致几个核心问题。

- 记忆丢失：长对话中早期关键信息因窗口限制被截断。
- 个性化缺失：无法持续捕捉用户偏好与习惯。
- 学习能力受限：难以从过往交互中提取反馈优化决策。
- 逻辑一致性难维持：多轮对话易出现前后矛盾。

有了历史记录作参考，模型知道小明的爸爸是谁。这种借助模型对话窗口实现的临时存储，被称为短时记忆。

短时记忆受限于最大Token长度，例如Qwen3-Max为256KB。随对话轮次增加，全量携带历史记录会导致成本激增并触及上限。业界因此衍生出优化策略。

### 1. 滑动窗口

通过保留最近N轮对话或用算法剔除无关片段来精简对话记录。例如医疗问诊中穿插天气询问：

> Human: 我最近感觉不太舒服
> AI: 请问你哪里不舒服呢？
> Human: 我可能感冒了，头疼，流鼻涕
> AI: 那可能真是感冒了，可以具体描述一下你的症状，我来为你诊断一下
> Human: 今天天气怎么样？
> AI: 根据你的定位，你当前的地区今天下雨，请注意保暖。
> Human: 我嗓子也疼，浑身冷
> AI: 那你可能是风寒感冒，可以吃××药

后续引用历史时，系统可识别并过滤非相关内容，仅保留病情描述核心语义，节省Token开销。

### 2. 对话摘要压缩

对话达到一定长度后，用模型对历史记录进行压缩。

- 对话概况：提取决策点和关键事实，如“用户确认对阿司匹林过敏”。
- 偏好提取：记录行为模式，如“用户偏好简洁回复风格”。

对话压缩在Agent系统里很常见，例如AI编程工具Claude Code提供/compact命令强制压缩；GitHub上5个月获27万Star的OpenClaw也会在窗口将满时自动压缩对话。

### 4.1.2 长期记忆：构建 Agent 的持久化存储层

即便有多种压缩技术，对话窗口限制仍是天花板。为了让Agent具备跨越数周甚至数月的记忆能力，必须引入长时记忆。

如果说短时记忆像计算机的内存，随进程结束而清空；长时记忆则像硬盘，通过独立于模型的存储介质实现信息永久留存。

工程实践中长时记忆主要通过两种模式实现。

### 1. 外部文件持久化
