## 5.1　线上智能体开发全解析
线上智能体开发平台通常提供可视化界面，无需深入底层算法和代码就能快速搭出智能体，门槛明显降低。它支持聊天机器人、虚拟助手、自动化流程型智能体等多种形态，内置丰富的预训练模型与算法库，可灵活选用并做定制化开发。同时部署便捷，能把成品迅速推送到不同终端与场景，并具备强大的监控与管理能力，可实时追踪运行状态和性能指标并优化，从而提升开发效率与质量，加速智能体在各行业的落地。

借助扣子平台的可视化设计与编排能力，开发者可用零代码或低代码方式，迅速做出基于大模型的各类 AI 项目，满足个性化需求并产生商业价值。

本节以字节跳动的扣子平台为例，介绍如何通过线上智能体开发平台搭建单智能体、工作流和 AI 应用。选择扣子的原因在于：

（1）**工作流设计灵活**。扣子的流程编排可处理逻辑复杂且稳定性要求高的任务，提供大量可组合的节点，涵盖大模型、自定义代码、判断逻辑等。有无编程基础都能通过拖拽快速搭建。例如可创建一个撰写行业研究报告的流程，让智能体自动输出报告。

（2）**能力边界可持续拓展**。平台集成丰富插件工具，明显拓宽智能体能力。官方已发布多款功能插件可直接接入；也支持基于已有 API 通过参数配置快速创建自定义插件供智能体调用，自定义插件还能上架商店供他人使用。

（3）**数据源覆盖面广**。内置简易的知识库用于管理和存储数据，并支持智能体与用户数据交互。本地海量文件或网站实时信息均可汇入知识库，智能体即可基于库内内容作答。

（4）**记忆能力强劲**。提供数据库记忆能力，可长期保存用户对话中的关键参数或内容。例如建立一个数据库记录阅读笔记，包含书名、阅读进度、个人批注等，智能体即可通过查询给出更精准的答案。

### 5.1.1　扣子智能体开发功能概览
扣子借助大模型大幅简化智能体搭建流程。在发挥大模型优势的同时，还可通过知识库、流程等配置智能体对用户查询的响应，保证回复符合预期。下面简要介绍核心功能。

#### 1．编排能力
扣子提供多个大模型及多项设置，以应对不同复杂度的任务。

（1）**提示词编辑**。提示词定义模型表现方式及生成回复时的上下文指引。用户可为智能体设定人设，说明可答与不可答内容、回复格式要求等参考信息，以获得更精准的输出。平台还可利用 AI 功能优化提示词，让模型回复更结构化、更准确。

（2）**模型设置**。提供多款模型，支持按业务场景调节参数如温度等，直至对话效果最优。

（3）**编排模式**。默认单智能体模式，一个智能体独立完成全部任务。若需更复杂、功能更全的智能体，可切换为多智能体模式，为不同智能体配置不同提示词，把复杂任务拆分为若干简单子任务，避免在单一提示词中堆砌全部判断与限制。

#### 2．搭建功能
知识、插件等可缓解模型“幻觉”、专业知识不足的问题；平台还提供记忆功能，让智能体基于历史对话生成更准确回复。具体如下：

（1）**技能**。是智能体的基础能力，通过插件、工作流、触发器等扩展模型边界。

**·** **插件** 通过 API 接入各类平台与服务，扩展智能体功能。内置丰富插件可直接调用，也可创建自定义插件把所需 API 集成进平台作为工具使用。例如接入新闻插件搜索资讯，或使用搜索工具查找网络信息。

**·** **工作流** 用于规划与实现复杂逻辑，拖拽任务节点即可搭建，提升复杂任务处理效率。

**·** **触发器** 使智能体能在特定时间或条件下自动执行任务。

（2）**知识**。支持接入本地或线上数据，提升大模型回复可用性与准确性。

**·** **文本** 支持基于内容片段检索召回，大模型结合召回结果生成最终回复，适用于知识问答。

**·** **表格** 支持基于索引列匹配，也支持 NL2SQL 查询与计算。

**·** **照片** 支持 JPG 等常见图片格式，可通过图片标注检索召回。

（3）**记忆**。模型对话轮次有限，记忆功能提供可反复调用的长期记忆，让回复更个性化。

**·** **变量** 用于保存用户语言偏好等信息，使回复更贴合个人。

**·** **数据库** 提供简洁高效的结构化数据管理方式，支持自然语言插入与查询，并可开启多用户模式实现更灵活的读写控制。

**·** **长期记忆** 模拟人类大脑对用户个性化信息的记忆，基于此提供个性化回复，提升体验。

**·** **文件盒子** 实现多模态数据的合规存储、管理与交互，智能体可反复使用已保存的多模态数据。

（4）**语音对话**。除文字外支持语音交互，提供多款音色供选择。

#### 3．设计能力
卡片是一种特殊消息展示形式，可自定义智能体生成内容的呈现格式。平台支持为工作流、插件等绑定卡片。

#### 4．发布渠道
搭建完成后可发布到多种渠道，扩大服务范围。目前支持发布到商店、模板库、第三方应用、API、SDK 或自建第三方渠道。

#### 5．运营与运维
“预览与调试”区可对智能体进行调试与数据分析。在该区与智能体对话，根据响应效果优化配置；若实际使用中出现回复不符、响应缓慢或无响应，也可在此查看执行细节排查问题。

已发布智能体可通过分析看板追踪运行情况。数据分析提供用户量等基础数据、用户意图等访问数据、消息记录等使用数据，据此定向优化以更好满足需求。

### 5.1.3　工作流搭建实操指南
工作流是一组可执行指令的集合，用于实现业务逻辑或完成特定任务。它为应用/智能体的數據流动与任务处理提供结构化框架，核心在于把大模型能力与特定业务逻辑结合，通过系统化流程实现高效 AI 应用开发。

扣子提供可视化画布，可拖拽节点迅速搭建工作流，也支持在画布中实时调试，清晰呈现数据流转与任务顺序。

#### 1．工作流与对话流
平台提供两类工作流：

（1）**工作流**（workflow）：处理功能类请求，通过顺序执行任务实现特定功能，适用于数据自动化处理，如生成行业调研报告、生成海报、制作绘本等。

（2）**对话流**（chatflow）：面向对话场景的特殊工作流，更适合处理对话类请求。通过对话与用户交互实现复杂业务逻辑，适用于聊天机器人、个人助手、智能客服、虚拟伴侣等。

#### 2．节点
工作流核心是节点，每个节点为具有特定功能的独立组件，代表一个步骤或逻辑，负责处理数据、执行任务、运行算法，均具备输入与输出。

每个工作流默认包含开始节点与结束节点。开始节点定义启动所需输入参数，结束节点返回运行结果。

可通过引用节点输出将节点串联成操作链。例如代码节点的输入可引用大模型节点的输出，实现数据传递。在画布中可直观看到节点连接，如图 5-5 所示。
