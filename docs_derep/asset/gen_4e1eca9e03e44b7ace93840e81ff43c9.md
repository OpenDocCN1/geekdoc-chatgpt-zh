### 支持的 TensorFlow 算子与约束条件

当前模型编译器仅支持特定配置的算子集合，部署前请务必核对以下限制：

*   **稀疏张量**：不支持（`b_is_sparse: False`）。
*   **张量拼接** [PRE0]：仅允许在维度 1、2 或 3 上执行 `tf.concat` 操作。
*   **基础数学运算**：支持 `tf.add` 与 `tf.multiply`。
*   **激活与归一化**：
    *   `tf.nn.softmax` [PRE1]：归一化维度固定为 `-1`。
    *   `tf.sigmoid` [PRE2]：输入张量形状强制要求为 `[1, 1, 1, k]`。
    *   `tf.nn.l2_normalize` [PRE3]：输入通道数必须能被 8 整除 [PRE4]；归一化维度固定为 `-1`。
    *   常用激活函数 `tf.nn.relu`、`tf.nn.relu6`、`tf.tanh` 均受支持。
*   **形状重塑** [PRE5]：批次维度（`shape[0]`）不可变，必须保持与原张量一致。

#### 常见问题排查指南

**问**：照着 TensorFlow 官方目标检测教程重训练模型，为何在 Vision Kit 上跑不起来？

**答**：教程提供的 MobileNet 预训练模型默认输入 300×300、深度乘数 1.0，计算量过大超出 Vision Kit 承载上限。解决路径是缩减模型规模——采用 **MobileNet+SSD** 架构，输入分辨率降至 **256×256**，深度乘数设为 **0.125**。注意：无法在深度乘数 1.0 的权重基础上微调新乘数，必须**从零开始训练**。

**问**：基于 TensorFlow Object Detection API 训练的自定义模型，如何落地部署？

**答**：经验证可行的配置为 **MobileNet+SSD** 组合 [PRE6]。以下以 `embedded_ssd_mobilenet_v1_coco.config` 配合 PASCAL VOC 数据集为例，梳理完整流程：

1.  **环境就绪**：按官方文档安装 Object Detection API。
2.  **数据准备**：整理 VOC 训练集与验证集。
3.  **配置微调**：修改 `num_classes` 为 20（原 90 类）。
4.  **路径屏蔽**：注释掉 `fine_tune_checkpoint`、`label_map_path`、`input_path` 及 `PATH_TO_BE_CONFIGURED` 字段。
5.  **启动训练**：按文档执行训练命令。
6.  **模型导出**：推理图导出时 `trained_checkpoint_prefix` 通常指定为 `model.ckpt-${CHECKPOINT_NUMBER}`。**关键建议**：第 0 步结束后，立即验证模型能否在 Vision Bonnet 上跑通。
7.  **编译加速**：调用 `bonnet_model_compiler` 生成板端模型 [PRE7]。
8.  **板端验证**：运行测试脚本确认推理无误 [PRE8]。
9.  **推理代码**：参考 `src/aiy/vision/models/object_detection.py` 编写业务逻辑。若沿用配置文件默认 SSD 设置，可直接复用 `object_detection_anchors.py`；否则需自行理解锚框生成原理并重写脚本 [PRE9]。
