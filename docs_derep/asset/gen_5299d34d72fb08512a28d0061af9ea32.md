2）API 网关层：作为对外统一入口，集中处理所有外部流量，完成鉴权授权、限流熔断、路由分发以及日志监控等工作，从源头上守住安全与可维护的底线。
3）业务服务层：承载平台核心业务能力，包含用户服务、内容服务、分析服务、计费服务等组件，基于微服务解耦，让各个模块能够独立演进、弹性伸缩。
4）AI 引擎层：是整个系统的智能中枢，内聚写作引擎、知识引擎与智能体编排系统，负责文本生成、知识检索以及多智能体协同等核心 AI 能力。
5）基础设施层：提供底层支撑，涵盖主数据库、向量存储、缓存、消息队列、对象存储与容器编排等云原生设施，为上层业务提供稳定可靠的运行底座。

这种分层思路同时兼顾了模块化与可维护性，也让每一层可以单独扩展与优化。AI 引擎层内部把写作、知识与智能体协作拆得更清晰，不同能力可以各自专项打磨。

##### 1. 整体流向

图示覆盖了五类交互方式。
- 1）同步请求流：客户端经 API 网关向业务服务发起请求，业务服务调用写作引擎，并联动向量存储中的知识引擎处理后返回结果，是最基本的请求响应模式。
- 2）流式响应流：针对生成类耗时操作，采用流式返回机制，边生成边推送，提升交互体感。
- 3）知识检索流：知识引擎通过向量存储检索关联信息，用于增强生成内容的准确性与相关度。
- 4）数据持久化流：业务服务将关键状态写入数据库，保证数据可恢复与可追溯。
- 5）异步事件流：非关键路径如日志、行为分析等通过消息队列异步处理，减轻主流程压力。

整体设计兼顾了实时交互的流畅与系统的可靠性，流式响应让用户能够即时看到内容生成过程，体验明显提升。
