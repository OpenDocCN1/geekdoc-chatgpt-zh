**2.DeepSeek 带来的机遇和挑战**

1）机遇

事实上，组织软件运用智能的历史由来已久，无论是基于光学字符识别的图像识别、票据识别乃至废钢判定等应用，还是基于机器学习的价格与市场预测、排产优化等解决方案，都是决策式智能的成功案例。以巨型模型为代表的生成式智能则进一步为组织的全面智能化提供了更加广阔的空间，但是这种潜力的发挥需要技术供应商必须具备充足的经验与认知。

组织使用巨型模型，在容错性、可观测性等方面的要求比消费领域更高，因此对于巨型模型的要求也更加严格。在 DeepSeek-V3 与 DeepSeek-R1 出现之前，国内集团级市场可以选择的开源巨型模型在能力上与 OpenAI 等全球顶级供应商存在非常明显的差距。尤其是 OpenAI o1 与 DeepSeek-R1 模型，无论是在可观测性上还是在可控制性上都展现出了很大的潜力。DeepSeek 遵循开源协议，以及多种蒸馏后的版本，让组织在需要极高隐私的场景下，有了全栈私有化部署的可能，也为各行业的用户提供了可满足其隐私级别要求的模型部署形式。

从具体使用需求的角度来看，在层出不穷的应用场景中，对于智能技术的使用必须考虑三个方面的效果：响应速度、内容准确率与交互友好程度。在产品的具体实现中，往往需要在这三方面进行取舍，以实现最优效果。这也意味着在不同的场景下需要使用不同的巨型模型，或者在同一个场景中，需要多次调用不同性能的巨型模型。DeepSeek-R1 除了满血版本，还有多种蒸馏后与量化后的轻量级版本，各版本在不同维度的具体表现上各有千秋，再加上 DeepSeek-V3 的补充，这样丰富多彩的模型产品线为用户提供了丰富的选项。

2）挑战

一方面，对于大多数组织客户而言，虽然 DeepSeek 的开源协议为用户的私有化部署提供了技术上的可能，但是一般被称为满血版本的全参数版本 DeepSeek-V3 与 DeepSeek-R1 模型需要的算力，无论从经济成本还是运维难度来考虑，都绝非一般的组织可以承担。即便不考虑预训练、微调等训练场景的需要，仅仅从推理使用方向来看，在不确定性的影响下，以英伟达为代表的芯片供应商也无法充分满足国内的算力需求，而国产算力还需要一定的时间与经验积累，才能充分发挥出 DeepSeek 等基于 CUDA 架构的巨型模型的全部能力。此外，基于蒸馏技术或量化技术实现的多种轻量级 DeepSeek 模型，虽然降低了推理时对算力的需求，但是其实际表现各不相同，如何优化与选择，对使用方提出了更高的要求。生态化的全面合作是加速问题的最优形式，需要通用模型供应商、垂直场景实现方与最终用户等方面的通力配合。

另一方面，对于实现高价值的最终场景，无论巨型模型能够提供多么强大的能力，仅基于智能生成能力，也只能完成对话交流的部分，真正的执行动作则必须依赖智能代理。一个完整智能代理的构建，除了将巨型模型作为认知核心，还需要大量的技能与卓越的记忆，以及详细的流程与完善的编排。这些细微环节的实现与优化，需要智能代理开发者对使用需求与业务场景有深刻的理解。对于长期从事组织信息服务与数智化建设的用友网络来说，最擅长的是将智能等新技术在组织实践中成功落地。围绕组织的实际需求与实践挑战，用友总结出了组织智能的定义，包括统一数智底座、嵌入核心业务、实时智能运营与结果安全可靠。按照这个标准，如何充分发挥 DeepSeek 的能力，并衔接行业上下游，挖掘符合组织智能标准的应用场景，是一个必须面对的挑战。

不仅如此，对于不在 BIP 平台内的外部异构系统，iuap 底座内置的连接集成平台 YonLinker 具备数据总线、数据转换与格式映射等功能，还提供跨系统的 API 发布、调用与管理功能。作为用友 BIP 平台化与生态化、应用一体化的关键设施，连接集成平台 YonLinker 提供了开放与集成的能力，支持云内集成与云间集成，支持组织内业务集成与生态链间集成，可有效解决组织的账号集成、门户集成、主数据集成、服务集成、设备集成与流程集成等方面的问题，使组织能在公有云、混合云、专属云、私有云及多云之间互联互通。YonLinker 的产品模块包括 API 网关、数据集成、主数据、混合云网关产品，以与 MCP 相似的方式，让智友智能代理具备跨系统、跨平台的强大技能库。

**4.技术架构与创新突破**

在以 ChatGPT 为典型代表的生成式人工智能推动智能全面普及之前，用友网络就预见了从数字化到智能化的行业发展趋势，提出了“数智化”的概念，即数据技术与智能技术的结合将成为下一轮组织信息系统建设的战略目标。DeepSeek 的成功让这一预见成为现实。这种准确的预判源于用友的深厚行业底蕴，以及用友对于集团级智能需求的深刻理解。

1）产品技术架构

基于数据与智能结合的双轮驱动战略，用友找到了利用 DeepSeek 等巨型模型来升级传统数据平台产品的方式。基于 BIP 的智能代理架构，用友设计了对话式数据分析产品 ChatBI。一方面，以数据指标平台弥补巨型模型在本质上的随机性；另一方面，放大数据资产的应用价值，提升数据平台的使用体验。

用友的 Yondata 数据平台产品涵盖了数据存储、治理、开发与应用分析的全生命周期管理。从底层分布式数据仓库，到围绕数据质量资产等目标的数据治理模块，以及将数据与业务结合的指标平台，再到最终的智能分析展示，可以提供多个基于数据平台面向特定业务主体的分析资产包，如图 4-3 所示。

组织数智化数据治理、加工、分析的能力总成是一套覆盖数据全生命周期的综合性体系，其核心产品与服务深度融合了底层技术引擎、智能治理工具、多模态分析能力与场景化应用平台。在数据治理层，通过元数据管理构建全域数据血缘地图，依托数据标准管理统一编码规则，消除“一物多码”问题，结合数据质量规则引擎实时监控指标异常并触发闭环整改，同时基于主数据管理实现核心实体如客户、供应商的一致性管控，并借助敏感数据分类分级与区块链存证技术保障安全合规。在数据加工层，通过多源集成工具兼容 SAP、Oracle 等第三方系统及 IoT 设备数据流，利用分布式计算框架处理海量异构数据，依托可视化建模平台实现零代码 ETL 流程开发与任务调度，并引入 NLP 与机器学习技术自动解析非结构化文本或图像、清洗异常值，数据可用性得到了显著提升。在智能分析层，以智能分析工具为核心，提供 ChatBI 自然语言交互报告生成、语义模型、实时监控关键指标等功能，并针对供应链优化、经营决策、消费者洞察等场景提供深度服务，构建开放共享的数据资产目录，支持 API 计费服务。在技术底座层，以统一数据中台架构整合治理、加工、分析模块，通过 HTAP 混合引擎保障实时分析性能，结合 AI 开放平台沉淀语音识别、图像处理等通用能力，并依托认证/鉴权与审计日志满足合规要求，形成支撑全域数智化应用的坚实基座。
