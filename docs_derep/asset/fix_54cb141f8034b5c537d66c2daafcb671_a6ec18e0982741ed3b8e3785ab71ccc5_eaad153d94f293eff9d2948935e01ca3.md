# 并行训练：从数据到模型的全景图

从样本层面拆分训练批次，是数据并行最直观的做法，每一块子批次被送到不同算力节点上跑，如图 6.2 所示。各节点保存同一份模型参数，只拿本地那份数据做一次前向、反向以及本地更新。在一轮迭代收尾时，节点间把各自更新的结果汇总对齐，保证所有设备上的模型保持同一状态。这种方式的核心收益是吞吐加速，尤其在数据体量庞大的场景下效果明显。

[PRE0]

图 6.2 数据并行示意图

以参数服务器为代表的方案很常见。在该形态下，每台设备都保留一份完整模型。各个节点各自抽取不同数据，完成前向和反向梯度计算，这部分工作由 worker 承担。随后每个 worker 把计算得到的梯度上传到中心参数服务器，由服务器统一完成参数更新，再把更新后的权重分发回各节点。尽管数据并行的扩展性通常不错，仍存在两方面瓶颈：

1）当参与设备增多到一定程度后，每个 GPU 上的子批次会变得过小，导致算力利用率下降，同时同步通信的开销占比上升。

2）可扩展的最大设备数受限于最小可用的批次大小，进而限制了能投入训练的加速器规模。

### **6.3.2 模型并行**

当单个 GPU 显存装不下整个模型时，就需要把模型本身拆分。模型并行把超大网络分散到多台设备协同训练。在该设定下，模型的各个部分散布在不同设备中，每个设备都会参与到每一轮训练步骤中，如图 6.3 所示。常见的形态主要有张量并行和流水线并行两类。

[PRE1]

图 6.3 模型并行示意图

1）张量并行。核心思路是将模型参数、梯度及优化器状态等张量切成更小的子张量，分给多台设备托管。训练步骤中，各设备先独立计算自己负责的子张量，再通过设备间通信把结果拼回完整的参数张量。这种拆分能显著降低单设备上的显存压力，从而在有限资源下容纳更大的模型。

具体实现上，张量并行本质是对模型参数进行分片后分配。当前最广泛采用的是按一个维度进行的一维分片，即沿行或列对张量进行切割，未来也可能出现更高维度的分片方式。以图 6.4 所示的矩阵乘法为例，设***X**A****=****Y***，其中***X***为输入，***A***为权重，***Y***为输出。从数学上看，线性层可先分块计算再合并结果，而非线性层则无需额外处理。对于矩阵***A***，可选择按行或按列拆分：

例如把矩阵***A***切成两块分别放到两张 GPU 上，让它们各自完成对应的矩阵乘法部分，最后通过一次通信合并得到完整结果。该方法可以推广到更多 GPU 以及其他可分片的算子上。

2）流水线并行。基本策略是将模型按层切成多个连续阶段，每个阶段由若干层构成并部署在不同设备上。训练样本像流水线上的产品一样在各阶段间流动，设备完成本阶段计算后把中间结果传给下一级，从而提升设备利用率并加快整体训练速度。

不同算子往往适合不同的并行方式。参数量大的部分更倾向模型切分，参数量小的部分则更适合数据切分。单一并行模式的局限可以通过混合使用来缓解，例如在隐藏层较大的区域同时使用数据维度和模型维度的切分。虽然数据并行和模型并行都让设备执行同一层级的计算，流水线并行则把任务按先后顺序划分为多个阶段，不同阶段分配给不同设备，单台设备仅负责网络中一部分层级。这种多设备接力模式能够支撑更大模型或更大批次，提升训练效率。

举例来说，可先把网络的不同层初步分给不同的 GPU，然后按时间步串行执行并持续喂入新数据，以提高吞吐量。如图 6.5 所示，把不同阶段的任务分配给 4 台计算设备，每台可存储一层或几层网络，然后依次进行前向传播。第一个时间步接收输入时设备 0 计算第一层 F[0]；第二个时间步设备 0 可开始计算第二个样本的第一层，而设备 1 则开始计算第一个样本的第二层 F[1]，以此类推。实践中流水线并行与张量并行常会共存，二者正交且互补。但流水线下游设备必须等待上游完成计算才能启动，降低了平均利用率。在图 6.5 中设备 1 必须等设备 0 完成 F[0] 才能开始。同时流水线还存在气泡问题，设备在前向结束到反向开始之间的空闲期无法被利用。

[PRE4]

图 6.5 流水并行训练示意图

数据并行、张量并行、流水线并行三种模式在通用性、计算利用率、显存开销和通信量等方面各有取舍。可以看出，数据并行通用性强、计算与通信效率较高，但整体显存开销偏大；张量并行显存效率高，但需额外通信且通用性较弱；流水线并行显存效率高、通信开销小，但存在流水线气泡问题。

## **6.4 分布式训练的技术路线**

分布式训练相较于单机单卡能够支撑更大规模的模型。但并非盲目堆设备就能线性提速，受制于内存带宽增速慢于算力以及跨设备网络带宽的限制，数据搬运成为制约速度和收敛的关键因素。

在数据并行与模型并行之间做取舍时，若单批次产生的中间激活较多而参数量相对较少，数据并行通常更合适；反之若参数量大而中间结果较少，模型并行更具优势。数据并行相比模型并行一个明显优点是通信更容易与计算重叠，从而部分掩盖通信延迟，而模型并行实现该优化相对困难。

在大规模模型训练中，流水线并行具备优势。它的传输量仅与阶段间需要交换的数据有关，而不像数据并行和张量并行那样与整个计算图相关。对带宽受限的设备而言，流水线并行往往是更优选择。部分场景下流水线并行与模型并行的组合效果优于单一方案。数据并行与模型并行本身也存在可优化空间，即用计算时间掩盖传输时间。

随着大语言模型的兴起，针对 Transformer 的模型并行、流水线并行等的研究与工程实现成为学界与工业界的重点。例如基于 Lingvo 的 GPipe、微软的 PipeDream、英伟达的 Megatron-LM、Meta 的 FairScale、微软的 DeepSpeed ZeRO，以及 Google 的 Pathways 等。

当前训练超大语言模型主要有两条路线：一是 Google 主导的 TPU+XLA+TensorFlow/JAX 路线，该方案与 TPU 和自家云平台深度绑定；二是 NVIDIA、Meta、Microsoft 等支持的 GPU+PyTorch+Megatron-LM+DeepSpeed 路线，这是开源生态中最成熟的方案，均能在多 GPU 和多节点上并行训练大语言模型，有效解决内存与计算瓶颈，在有限硬件下实现更大规模模型的训练。

### **6.4.1 Pathways**

Pathways 是 Google 研发的一种异步分布式数据流架构，目标面向机器学习场景。在该架构中，模型的计算被抽象为有向无环图，节点代表计算任务，边表示数据依赖，如图 6.6 所示。Pathways 旨在提升分布式训练效率，特别在大规模模型和数据集上表现更佳。其异步分布式数据流具备四大特性：

[PRE6]

图 6.6 Google Pathways 异步分布式数据流

（图片来源：论文“Introducing Pathways: A next-generation AI architecture”）

1）灵活性。Pathways 支持数据并行、张量并行和流水线并行等多种并行模式，能够灵活适配不同任务和硬件配置。

2）异步执行。在输入依赖满足时任务即可立即启动，无需等待整批任务完成，有助于降低资源闲置。

3）分布式处理。计算任务可散布到多台设备上，充分利用硬件资源，提升速度和扩展性。

4）容错性。架构内置容错机制，单台设备故障时训练仍可持续，这对长时间大规模训练至关重要。

图 6.7 为 Pathways 架构总览，主要包含三个部分：

[PRE7]

图 6.7 Pathways 架构总览

1）分布式计算。计算以有向无环图呈现，每个节点是一个编译函数，边表示函数间数据流，是架构的基础。

2）资源管理器。为每个编译函数分配一组加速器子集，称为虚拟切片，使函数在特定加速器上运行以提升效率。

3）帮派调度。每个岛屿设有集中调度器，对岛屿内计算进行帮派调度，再分派给各分片执行器执行。

Pathways 让模型各部分可在多设备上并行，实现模型并行；在 DAG 表示中每个节点可代表模型子部分，整体任务并行执行。同时架构也支持数据并行，通过让多设备并行处理不同数据子集再汇总到全局模型。Pathways 可适配多种并行策略，并可动态调整并行粒度，实现模型并行、数据并行或二者组合。

架构目标是最大化利用现有硬件如 GPU 和 TPU。虽然不依赖特殊硬件，但性能与底层分布式计算能力密切相关。Pathways 可在多 GPU 集群、多 TPU 集群或混合环境中运行。为发挥最佳性能，需要高速互联如 InfiniBand 或高速以太网。但 Pathways 的具体实现由 Google 内部开发，细节和源码并未完全公开。

### **6.4.2 Megatron-LM**

Megatron-LM 由 NVIDIA 研发并开源，可与 PyTorch 和 TensorFlow 结合，在多种硬件软件环境下训练大语言模型。它采用多 GPU、多节点并行的策略，旨在有限资源下提升训练效率。

Megatron-LM 融合张量并行与流水线并行，实现大型 Transformer 的高效训练。通过在多个 GPU 上分布式处理权重和层，可训练更大更复杂的模型，但需要在 GPU 间传输数据并同步梯度，因此高效通信策略至关重要。

Megatron-LM 并未从零构建新框架，而是在现有 PyTorch Transformer 实现上做针对性修改，通过插入少量原语实现模型并行，方法直接简洁。它特别对 Transformer 中的掩码多头注意力和前馈网络部分进行算子拆分，实现并行化。

如图 6.8 所示，以掩码多头注意力为例，Megatron-LM 利用多头注意力的固有并行性，以列并行方式对键、查询、值相关的小矩阵乘法进行分区，在单 GPU 上本地完成每个注意力头的计算，每个 GPU 产生部分输出。

[PRE8]

图 6.8 具有模型并行性的 Transformer 块

在后续全连接层中，每个 GPU 拥有部分输出，权重矩阵按行切分直接与输入计算，再经 All-Reduce 与 Dropout 得到最终结果。实际中不必每个头独占一块 GPU，多头可共享一块 GPU，不违背单卡独立计算原则。设计时通常让注意力头总数可被 GPU 数整除。

对于前馈网络部分采用类似拆分策略。算子是否切分取决于计算量、参数量和通信量。一个单模型并行 Transformer 层的前后向传播共进行 4 次通信。自注意力层后的线性层输出的后续 GEMM 沿行并行化，直接消费并行注意力层的输出，无需 GPU 间通信。这种策略融合了多层感知器和自注意力层的两组 GEMM 操作，消除中间同步点，提升扩展性。最终在一个简单 Transformer 层中，GEMM 操作可在正反向路径中分别使用 2 次 All-Reduce。

Megatron-LM 的算子切分目标是降低通信并控制计算范围，并未让单 GPU 独立计算 Dropout、层归一化或残差连接后再广播，而是选择跨 GPU 复制计算。

在 Megatron-LM 架构中，模型并行与数据并行正交，如图 6.10 所示，结合张量与流水线并行训练大语言模型，使大部分操作为计算绑定而非内存绑定。Megatron-LM 通过 PTD-P 技术在设备上智能划分计算图，减少网络传输字节并降低设备空闲。该技术在 1000 张 GPU 上训练大语言模型时可达峰值吞吐的 52%，利用跨服务器流水线并行、服务器内张量并行和数据并行，在高带宽集群上训练万亿参数模型并展现良好扩展性。

### **6.4.3 ZeRO**

ZeRO 是 DeepSpeed 的核心组件，是一种降低训练内存需求和通信开销的数据并行策略。其目标是消除训练过程中的冗余，包括模型参数、优化器状态和梯度。通过在多个进程中分布式存储这些信息，实现更高效的分布式训练，让更大模型在有限硬件上运行。

在大语言模型训练中，混合精度训练和 Adam 优化器已成标准，如图 6.11 所示。Adam 使用每个参数梯度的一阶矩和二阶矩动态调整学习率。

训练阶段 ZeRO 把存储分为模型状态和剩余状态。模型状态包括模型参数 fp16、模型梯度 fp16、Adam 状态 fp32 的参数备份、fp32 的一阶矩和 fp32 的二阶矩。设模型参数量为 Φ，则总存储约为 2Φ+2Φ+（4Φ+4Φ+4Φ）=4Φ+12Φ=16Φ 字节，其中 Adam 状态占比约 75%。剩余状态包括激活值、临时缓冲区以及无法使用的显存碎片。
