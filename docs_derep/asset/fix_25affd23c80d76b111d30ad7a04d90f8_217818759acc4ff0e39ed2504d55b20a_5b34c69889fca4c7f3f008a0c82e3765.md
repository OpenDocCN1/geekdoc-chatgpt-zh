第二个预测头是在原有方案上追加可学习层得到，它读取主干最后一层 Transformer 的输出，先做 RMSNorm 归一化再与对应的输入嵌入拼接。区别于首个头从 $t_1$ 起步，这个头从 $t_2$ 起步。拼接后的表征经线性层投影到目标维度，再送入一个可训练的 Transformer 做进一步处理。训练阶段该头需要拟合 $t_3 \sim t_6$ 的 token，推理时只保留 $t_6$ 的输出。

[PRE0]

图 2-15 DeepSeek 的 MTP 案例 [8]

第三个预测头以第二头的 Transformer 输出为基础，并结合 $t_{3} \sim t_{6}$ 的输入向量，按相同节奏工作：训练时要预测 $t_{4} \sim t_{7}$ 的序列，推理时仅给出 $t_{7}$ 的结果。经过 MTP 训练后，模型对未来 token 的预先规划能力得到提升，预测更可靠。

总体来看，DeepSeek 的 MTP 方案是多轮研究的集大成，通过一次性生成多个未来 token，提升了样本利用率并帮助模型捕获更长的上下文。

### 小结
本章整体呈现了 DeepSeek-V3/R1 的架构骨架，为后续细节展开打下基础，重点拆解了 DeepSeekMoE、MLA 和 MTP 三大核心创新，三者共同提升了性能并优化了计算与内存开销。

DeepSeekMoE 在传统 MoE 上改进，引入共享专家与免辅助损失的负载均衡，缓解了参数冗余和资源分配不均的问题。共享专家压缩了冗余，提升了训练与推理效率；免辅助损失的均衡在不增加额外损失的前提下实现专家间的高效分配，进一步优化运算。

MLA 是另一项关键创新，通过低秩键值联合压缩与 RoPE 向量解耦，大幅提升注意力在计算与内存上的效率。从 Q、K、V 的下投影、上投影，到 RoPE，再到注意力输出，完整呈现了 MLA 的流程，在保证信息传递的同时实现效率跃升。

MTP 用来缓解传统单 token 生成效率低的问题。2018 年谷歌提出块级并行解码，通过多 lm_head 并行预测多个 token；2024 年 Meta 提出 MTP，多头并行预测后续 token，增强长依赖学习。DeepSeek 的做法借助顺序模块与共享 Embedding 逐层预测更多 token，提升样本效率与上下文捕捉。

本章系统阐述了 V3/R1 的核心架构与改进。对 MoE、MLA、MTP 的深入分析既揭示了原理，也体现了实际优势，为后续优化提供理论与实践依据。随着技术演进，该架构有望在更多场景发挥作用，推动大模型普及。

## 第 3 章 DeepSeek 的训练架构
在模型架构之外，训练体系的设计同样决定最终性能、效率与扩展性。DeepSeek 在硬件适配、算法优化、数据策略三个维度实现系统性突破，显著提升了大规模语言模型的训练与推理效率。本章介绍训练架构的核心理念与亮点，涵盖基础架构、硬件创新、算法创新与数据优化四个方面。

### 3.1 DeepSeek 的训练
DeepSeek-V3 与 DeepSeek-R1 的架构几乎一致，R1 是在 V3 基础上通过强化学习得到的强推理模型。

训练千亿参数模型如同指挥大型交响乐，需要精准分工、高效协作与灵活应变。DeepSeek 的训练体系借助分布式计算、存储优化与动态调度，把数万张 GPU 组织成高效运转的超级大脑。

#### 3.1.1 基础技术
训练需考虑的基础技术包括分布式训练、计算与存储优化及动态资源调度。

#### 1. 分布式训练：协作的智慧
设想多位画家合作绘制巨幅壁画，若各自为政画面会破碎。若分工负责轮廓、上色、统合风格，效率会大幅提升。DeepSeek 的分布式训练基于此理念。

#### 2. 计算与存储优化：厨房的高效法则

#### 3. 动态资源调度：智能交通管理
训练千亿参数模型像早高峰调度数万辆车，若信号灯不智能必然拥堵。动态调度系统扮演交通大脑，根据实时车流量自动调整信号灯时长即 GPU 分配，甚至临时增派交警即弹性扩容，类似双十一动态扩容服务器。

某辆车抛锚即 GPU 故障时，系统会立即把任务转移到其他设备，确保不中断。

系统还实时监控路段车速即 GPU 利用率，通过负载均衡算法引导车辆绕开拥堵，避免部分设备满载而其他闲置。

### 3.2 DeepSeek 在硬件层面的训练亮点
DeepSeek-R1 的表现不输 GPT-4o，成本却大幅降低，离不开硬件层面的创新。

#### 3.2.1 FP8 混合精度训练
FP8 混合精度利用 8 位浮点格式训练，降低精度以提升效率、减少内存并降低成本，同时尽量保持性能。随着硬件与算法成熟，FP8 在千亿级模型训练中优势明显。

核心优势有四点。
- ① 计算效率提升。FP8 计算速度约为 FP16 的 2 倍、FP32 的 4 倍，能大幅加速训练。
- ② 内存占用减少。存储仅为 FP32 的 1/4，显著降低显存需求，支持更大模型或更高并行。
- ③ 成本降低。减少计算与通信消耗，显著降本。
- ④ 性能平衡。尽管精度较低，借助高精度累加如 E4M3/E5M2 以及关键层保留 BF16/FP32，可保证数值稳定并提升收敛。

对精度敏感的模块如向量化层、输出头、MoE 门控、归一化、注意力等，V3 仍用 BF16 或 FP32 计算。

目前 FP8 混合精度已被广泛接受，微软已推出相应框架，优化通信与分布式策略，提升训练速度。

#### 3.2.2 DualPipe 算法
MoE 通过减少每个 token 的激活参数降低成本，MLA 显著减小 KV Cache 并提升推理速度。本节重点介绍 DualPipe，提升集群计算通信比与效率。

深度学习训练核心是前向与反向传播，如图 3-5 所示。

前向传播是输入从底层逐层传递到顶层，每层变换并生成输出。

反向传播是通过损失函数计算损失，利用链式法则逐层求梯度，并从输出层反向传递到输入层，最后用优化器如 Adam 更新权重。

> 注意：反向传播在前向之后。

具体而言，前向中数据从第 $n$ 层流向第 $n+1$ 层；反向中梯度从第 $n+1$ 层回传到第 $n$ 层。实际训练采用批处理，一批样本同时输入，完成前向与反向后再统一更新权重。

- ③ 容错与恢复。集群规模大，故障概率高，需从检查点恢复。

#### 1. 细粒度划分阶段
DualPipe 把每个计算块分为四种：注意力模块、分发模块处理设备间通信、多层感知机、聚合模块做跨设备输出合并。对反向块，注意力与 MLP 进一步拆分为输入反向与权重反向。

#### 2. 双向流水线调度
通过从流水线两端同时输入小批次，大部分通信可完全重叠。为此需维护两份参数副本。

例如 8 卡跑 8 层模型时：卡 0 同时持有第 0 层和第 7 层参数，卡 7 同时持有第 7 层和第 0 层参数。通过参数镜像与双向数据流动，显著提升利用率与效率。

#### 3. 高效通信内核
DeepSeek 定制高效跨节点全通信内核，减少专用通信流式多处理器数量，优化性能。
