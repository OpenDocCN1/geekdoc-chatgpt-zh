**3.3 RAGAS 召回评估**

在 RAG 里，检索相当于给大模型准备干粮。检索到的上下文如果不相关或缺失，再强的生成模型也很难给出可信答案。所以检索质量的量化，尤其是召回能力的评估，变得至关重要。

传统搜索团队往往靠人工打标来衡量召回，但成本高、主观性强。伴随大模型普及，RAG 对自动化评测的需求激增。RAGAS 便是在这种背景下出现的 Python 评测库，内部融合了嵌入模型和生成式模型，专注于 RAG 与 LLM 的语义级评测。它能自动分析检索结果的准确性和覆盖度，判断是否存在误召漏召，为开发者提供高效一致的召回评估，如图 3-21 所示。

关于字段，有几个细节要留意：

· reference 通常指向检索到的上下文 contexts，而 ground_truths 指标准答案，两者在 RAGAS 中的用途不同，不能随意互换，具体用哪个取决于选用的指标。
· 涉及对 LLM 生成结果评估时，answer 字段是必须的，否则只能评估检索召回部分。

**3.4 自我矫正：CRAG**

传统 RAG 的质量很大程度上取决于首次检索的结果。一旦初次检索遗漏关键信息，再强的语言模型也会胡编乱造。为提升鲁棒性，CRAG，即 Corrective RAG 自我矫正式检索增强生成应运而生。其思路是在初次生成后，反向核对生成内容与上下文的匹配度，并动态调整检索策略，形成“生成—验证—再检索”的闭环，流程如图 3-23 所示。

示例实现了一个 CRAG 自我矫正流程。先按标准 RAG 执行：向量检索、生成答案，再用 RAGAS 多指标评估。若 context_recall 或 faithfulness 不达标，系统会启动矫正逻辑，比如对原始查询做改写 query rewrite，随后重新检索、再生成并再次评估。

实际落地时矫正方式并不固定，可能是指标补充、联网搜索、Agent 推理链、查询重构或多跳检索的组合；在复杂任务中，CRAG 也可能演化为多轮交互、动态策略选择的智能流程。

因此 CRAG 更像一种设计理念和策略框架，强调自我诊断与自我修正，而不是可直接复用的通用模块。核心价值在于根据业务目标和数据特点制定合适的矫正策略，打造更稳健可信的增强问答系统。

**3.6 本章小结**

本章先介绍了 RAG 的基本原理与系统构成，阐明其在增强问答、私域知识问答等 LLM 场景中的核心价值。RAG 通过检索与生成的闭环，实现了高质量知识问答的主流范式。

接着引入 RAG 质量评估方法 RAGAS，并扩展 CRAG 自我矫正机制。通过结合检索评估、查询改写与再生成，构建面向质量反馈的闭环优化，展示更鲁棒可控的架构思路。

最后以服务端与客户端代码实现一个可复用的 RAG 服务原型，串联起知识加载、向量化存储、上下文增强、模型生成与质量评估的全链路。整章思维导图如图 3-24 所示。
