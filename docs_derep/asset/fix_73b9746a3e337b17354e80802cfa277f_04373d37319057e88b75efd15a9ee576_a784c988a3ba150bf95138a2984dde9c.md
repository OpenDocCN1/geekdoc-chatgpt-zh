# 第八章 数据安全

## 第七十八条 【数据安全责任主体】

本市实行数据安全责任制，数据处理者是数据安全责任主体。

数据同时存在多个处理者的，各数据处理者承担相应的安全责任。

数据处理者发生变更的，由新的数据处理者承担数据安全保护责任。

[PRE0]
本条是关于数据安全责任主体的概括性规定，旨在明确一般情形、多主体共同处理情形等情形下的数据安全责任主体。

[PRE1]
数据安全责任制，是指数据处理者在数据处理过程中，对数据安全负责的制度。

[PRE2]
本条作为条例第八章（数据安全）的第 1 条，开门见山地明确数据安全责任主体。具体而言，作为数据安全的总则性条款，该条分 3 款进行了阐发，分别对应一般情形、多主体共同处理情形、处理者变更情形。从适用对象看，本条涵盖所有对象的数据处理行为，既包括企业数据，也包括公共数据；既包括数据的收集、存储、使用、加工，也包括数据的传输、提供、公开、共享等行为。从责任内容来看，本条主要指数据处理者在数据处理过程中对所处理数据负有的安全保护责任，而不涉及数据安全监管责任。

### 一、常规情形下的责任归属

条款先把担责边界说清楚。按《上海市数据条例》第3条和《数据安全法》的表述，数据安全是指借助必要手段让数据始终处于可控且合法利用的状态，并具备持续抵御风险的能力。这一标准不是一成不变的，而是兼具状态性与适应性。

在大数据环境下，安全已成共识。徐玉玉案、滴滴网络安全审查等事件，让篡改、破坏、泄露、毁损及不当利用的风险被公众高度关注，从而倒逼数据安全责任制的建立。国内对责任制的理解可回溯到安全生产领域，1997年的《关于认真落实安全生产责任制意见的通知》以及《安全生产法》确立的“管生产必须管安全”“谁主管谁负责”，至今仍具指导意义。

平移到数据领域，思路一致：形成层层传导、人人尽责、权责明确的治理格局。通俗来说就是“谁拥有谁负责、谁保存谁负责、谁管理谁负责、谁使用谁负责、谁采集谁负责”，把责任压到具体操作层面。

《数据安全法》第6条明确了地方和部门的主体责任，并用第四章第27至36条细化了义务，如维护公共利益、风险处置、重要数据处理者的评估等。配套的《网络数据安全管理条例》正在制定中，用以落实《网络安全法》《数据安全法》《个人信息保护法》等要求。2021年11月公布的征求意见稿第6条第1款写道：“数据处理者对所处理数据的安全负责，履行数据安全保护义务，接受政府和社会监督，承担社会责任。”安徽、山西、贵州等地的数据地方条例亦将保护主体责任锁定在处理者身上。

总体看，守住数据安全生命线，关键在于把主体责任真正落下去。条例开篇即把责任主体界定为数据处理者，为后续各项具体保护要求奠定基础，推动制度框架落地生效。

### 二、协同处理与主体变更时的责任

第2、3款对多方协同与主体更替两类情形做了安排。

同一数据若由多方共同操作，各方都需按自身行为承担匹配的安全责任。立法意图是堵住多头操作带来的监管空档，避免通过拆分或联合主体来规避义务。不论多方形成的原因、关系远近或操作是否一致，保护义务都不能缺位。所谓的“相应责任”可理解为两层：一是按实际操作承担对应的技术和管理责任；二是因未尽义务造成损害时承担相应的赔偿责任。

责任必须与实际操作挂钩。数据风险贯穿全生命周期，必须做到闭环保障。义务源于真实行为，由实际执行者承担与其操作对应的责任，既能把安全嵌入业务流程，减少推诿，也更符合技术落地与成本效益的现实。

除行政合规责任外，还会衍生民事后果。《个人信息保护法》第20条可资参考：共同处理因未尽义务致损的，通常依据《民法典》承担连带责任，个少情形可按份处理。处理者之间内部如何分摊，可协商约定，但该约定不得对抗外部受损个人。

主体变更时，责任随之转移。实践中处理者多为政府部门、企业法人或非法人组织，机构改组、企业合并分立、解散破产等变更十分常见。条例明确，安全责任不因主体更换而免除，新主体须继受。个人信息保护法第22条作了类似安排：因合并分立等导致个人信息转移的，接收方须继续履行原处理者的义务。需要注意的是，此款仅适用于主体本身发生变化，若主体未变仍适用第2款。如委托处理，受托方虽为主要操作方，委托方的安全义务并不免除，双方均须承担相应责任，违约致损则依《民法典》承担连带责任。

## 第七十九条 【数据安全保护义务】

开展数据处理活动，应当履行以下义务，保障数据安全：

（一）依照法律、法规的规定，建立健全全流程数据安全管理制度和技术保护机制；
（二）组织开展数据安全教育培训；
（三）采取相应的技术措施和其他的必要措施，确保数据安全，防止数据篡改、泄露、毁损、丢失或者非法获取、非法利用；
（四）加强风险监测，发现数据安全缺陷、漏洞等风险时，应当立即采取补救措施；
（五）发生数据安全事件时，应当立即采取处置措施，按照规定及时告知用户并向有关主管部门报告；
（六）利用互联网等信息网络开展数据处理活动，应当在网络安全等级保护制度的基础上，履行上述数据安全保护义务；
（七）法律、法规规定的其他数据安全保护义务。

[PRE4]
本条强调了开展数据活动的合规性要求，对开展数据活动的不同主体设置了安全保护义务，同时明确了开展数据活动时应采取的风险管理以及安全事件的处理措施。

[PRE5]
全球迈入数字经济时代，数据成为驱动各国经济社会创新发展的关键生产要素，经济价值与战略价值愈发凸显，数据安全问题也成为数字经济时代国际竞争与合作的核心议题，网络安全、数据安全逐步升级为各国数据掌控与管辖的新焦点。

### 一、义务如何落地执行

第1项要求依据法规建立全流程制度与技术防护，对应《数据安全法》第27条。所谓全流程，涵盖生产、加工、筛选、分析、整合、处理、转让等各个环节，任一环节都可能出现泄露、遗失、窃取或篡改，因此必须实现全程管控。该项要求处理者建立健全制度与技术机制，重点保护涉及国家安全和个人隐私的数据，严控采集、存储、流动、使用的各环节。

第2项强调安全教育培训。当前具备合规与防护能力的专业人才供给存在缺口，企业难以满足实际需求。推进安全理念与文化建设，依托专业培训服务定期开展人才培养与资质认证，是补齐能力短板、满足监管要求的重要路径。

第3项要求通过技术手段与其他必要措施保障安全。结合《网络安全法》第21条，技术措施包括防范计算机病毒、网络攻击、网络入侵等危害的手段，以及监测、记录网络运行状态与安全事件的手段。“其他必要措施”在《计算机场地安全要求》GB/T 9361—2011中指向数据中心的物理安全，如供电系统、消防系统、网络接口安全等。目标是防止数据被篡改、泄露、毁损、丢失或非法获取利用。国际上GDPR第25条也要求以技术设计实现数据保护，第30条明确处理活动记录责任。

### 二、在等级保护框架下的要求

第6项要求在利用互联网等信息网络处理数据时，必须在等级保护制度基础上履行安全义务。《网络安全等级保护条例征求意见稿》第15条将网络分为五级：一级破坏后影响公民法人合法权益但不危害国家安全、社会秩序和公共利益；二级破坏后造成严重损害或对社会秩序公共利益造成危害但不危害国家安全；三级破坏后造成特别严重损害、严重危害社会秩序公共利益或危害国家安全的重要网络；四级破坏后对社会秩序公共利益造成特别严重危害或对国家安全造成严重危害的特别重要网络；五级破坏后对国家安全造成特别严重危害的极其重要网络。

因此处理者应根据网络遭破坏后可能造成的影响，采取相应的保障措施，满足等级保护要求，在此基础上落实本条规定的各项保护义务。

### 三、风险监测与应急处置

第4、5项对应《数据安全法》第29条，分别规定风险监测义务与安全事件应急响应。要求持续开展风险监测，及时发现缺陷漏洞并补救；一旦发生安全事件，要立即处置，按规定及时告知用户并向主管部门报告。
