双向流水线与气泡压缩：Chimera 方案全景

Chimera 是 Li 和 Hoefler 在 2021 年提出的反向拼接思路，把一条下行流水线和一条上行流水线反向组合。每台工作站在一轮训练迭代里会处理 D 个微批次。为保证各阶段始终有活，默认取 N 等于 D，实际上 N 大于 D 也是可行的。

下行流水线把阶段 0 到 3 线性映射到设备 0 到 3，上行流水线则反向排列。两条流水线平分 N 个微批次，N 假设为偶数，每条流水线对 N/2 个微批次采用类似 Dapple 的 1F1B 编排。两条线合并后形成 Chimera 调度，当 D 为偶数时不会产生冲突，前向与反向的气泡都被压缩到 D/2−1。

若模型为了收敛需要更小的 B，迭代内的微批次可能少于 D，即 N<D。此时 Chimera 仍可在两条流水线间尽可能均摊 N 个微批次，最极端是 N=1，只有一个微批次在单条流水线上运行。值得注意的是，Chimera 还可以把两条以上的流水线叠加，以进一步缩小气泡并平衡激活内存消耗，代价是通信开销和权重内存会上升。

流水线刷新本质上是把小批次拆成等大的微批次逐个送入系统。所有微批次的梯度收集完毕后，GPU 要等最后一个微批次的反向结束后才更新权重，这一过程称为微批次化。权重更新后，下一个小批次及其微批次被注入，实现计算重叠。通常微批次数量大于工作站数量，才能获得并发。

流水线刷新容易产生气泡。当 GPU 在最后一个微批次的前向和第一个微批次的反向之间空闲时，整体利用率会下降。有效使用刷新要求负载均衡，确保各层对 GPU 的负载均衡，同时均衡算法必须具备通信感知能力，因为在 GPU 边界交换的激活和梯度可能达到 GB 级。

为提升收敛质量，同步方案会在迭代结束时做梯度同步配合流水线刷新，但会留下气泡。GPipe 和 Dapple 通过一次性向流水线注入 N 个微批次来缓解，Chimera 则借助 1F1B 计划并定期刷新。气泡比率定义为气泡开销除以流水线总运行时间。GPipe 与 Dapple 的气泡比率为 2(D−1)，Chimera 为 D−2，D 表示流水线阶段数。

内存消耗主要由权重参数和激活决定。GPipe 与 Dapple 中每个工作站只保存一个流水线阶段的权重，而 Chimera 中每个工作站要保存两个阶段的权重，因为存在两条反向流水线。

GPipe 为充分利用流水线会同时注入 N 个微批次，但内存随之线性增长，难以扩展到大量微批次。Dapple 与 Chimera 使用 1F1B，启动时最多注入 N 个微批次，对大规模微批次更友好。与 PipeDream、PipeDream-2BW 等相比，Chimera 的优势在于各工作站内存消耗更均衡，能更好地利用内存资源。

Narayanan 等 2021 年提出的交错 1F1B 允许每台设备计算多个层的子集，即模型块。该做法降低了每个流水线阶段的计算量，若为每个工作站分配多个模型块，可显著减少气泡时间。但阶段数随模块数增加而增加，需要额外通信。计划要求微批次数量是流水线阶段数的整数倍，当每台设备配备 V 个流水线阶段时，有助于进一步缩小气泡。

**PipeFisher：流水线+二阶优化器**

流水线并行在大规模分布式加速器上高效训练大语言模型时，启动和收尾阶段的气泡会拉低利用率。尽管已有微批次、双向流水线等方案，同步的前向反向流水线仍残留大量未填满的气泡。

为此 Osawa 等 2022 年提出把额外工作分配给气泡，提出 PipeFisher 方法。该方法把基于费雪信息矩阵的二阶优化 K-FAC 的工作塞进气泡，以加速收敛。二阶优化器收敛步数少，但更新预处理矩阵需要额外计算，如图 6-9 所示。其中 GPipe 包含 4 个阶段、4 个微批次和 4 台设备。每个彩色框代表微批次的前向、反向、曲率、求逆或预条件工作。PipeFisher 利用多个流水线步骤的气泡，本计划中为两个步骤，来刷新曲率和逆矩阵一次。因此相比标准流水线方案，预条件是唯一的额外计算开销。本计划的第一个预条件使用了前几步计算得到的过时逆矩阵。

**2. 异步流水线**

该方法保持系统中活跃的小批次数量恒定，在第一个 GPU 完成反向后立即注入新小批次，以维持流水线满载。与刷新流水线不同，一旦 GPU 完成一个小批次的反向，就会立刻更新权重，从而消除刷新带来的气泡，提高硬件利用率。然而新小批次在前向时可能遇到尚未被旧小批次反向更新的过时权重，出现权重过时，显著降低统计效率。这也是非刷新流水线未被广泛采用的原因。

PipeDream 实现了非刷新流水线操作，并借助权重存储缓解权重过时。虽然与 GPipe 同时发布，PipeDream 的并行方式差异较大。类似同步 1F1B，PipeDream 在流水线中交错前向和反向，以优化利用率和吞吐量。小批次持续送入流水线，反向后异步执行参数更新。与 GPipe 的同步反向更新不同。

PipeDream 的异步反向更新易受权重过时影响，可通过权重存储解决。该技术保留多个版本的参数权重，每个活跃小批次分配一个版本。前向过程中各阶段使用最新的权重版本，前向结束后所用版本被存档，并用同一版本计算该小批次反向时的权重更新和上游梯度。PipeDream-2BW 把模型权重版本限制为两个，称为 2BW 或双缓冲权重。只要模型大小超过管道深度，每处理一个微批次就会创建新模型版本。但由于残差反向仍依赖前一版本，新模型无法立即取代旧模型。该策略只需存储两个版本，大幅降低内存占用。图 6-11 予以说明。

**3. 小结**

相比数据并行，流水线并行是一种更高级的算法，因仅使用点对点通信而适合多进程大规模训练，点对点通信成本低于全归约或全收集等集体通信。但必须管理闲置进程。

流水线并行虽有优点，反向传播中把前向输出激活作为反向输入是主要挑战，会导致各加速器内存需求不同。虽然计算负载相同，某些方法如 Dapple、PipeDream 和 PipeDream-2BW 要求第一个加速器存储与流水线深度等量的激活，而最后一个加速器需求较少。后期阶段内存利用率偏低，性能受限于首个加速器，微批次大小必须据此定制。这种不平衡可通过限制流水线中同时允许的微批次数量来缓解，但会产生气泡并降低整体系统利用率。

**6.4.3 张量/模型并行**

流水线并行与张量并行是深度学习分布式训练的两种技术。前者按层划分模型，后者在层内拆分操作（如图 6-12，7 层深度神经网络分布在 4 台设备上）。在 Transformer 中，瓶颈在于激活批次矩阵与权重矩阵的乘法。该乘法由行列对间的独立点积组成，可在不同 GPU 上计算，或把每个点积的不同部分分到不同 GPU 再求和。通过把权重矩阵划分为均匀分块并托管在不同 GPU 上计算相关部分后再合并，可实现并行。

模型并行需要两种通信：全收集操作，保证所有处理器都收到前向传递的所有激活；全归约操作，通过聚合输入梯度反向传播激活梯度。前向矩阵乘法需要全收集以确保各处理器可访问彼此的激活数据，这与全归约类似但系数不同。由于每个处理器只需自身参数的梯度来计算权重梯度，反向本身不需要通信，但聚合输入梯度时必须做全归约。

Megatron-LM 使用该策略并行化 Transformer 的自注意力和 MLP 层的矩阵乘法。在 MLP 层，权重矩阵按列拆分以并行化 GEMM，随后进行非线性 GeLU 传输。

2D 张量并行把输入数据、模型权重和层输出拆成两个维度，与 1D 张量并行相比内存消耗更低且内存冗余为零。张量被分为 N 个块，在方形网络拓扑中每个 GPU 拥有一块。设备间通信通过集体通信完成以保证算术正确。2.5D 张量并行在 2D 基础上为矩阵增加可选深度维度，可在扩展到大量设备时进一步降低通信量。张量分割满足 N=S D，其中 S 为正方形边长，D 为立方体深度。深度为 1 时与 2D 类似。

3D 张量并行把张量分割成立方体形状并划分首尾维度，可实现最佳通信成本并均匀分配计算与内存使用。扩展到更多设备时，高级张量并行可进一步降低通信并与流水线并行更兼容。与 1D 张量并行不同，1D 在传递到下一个流水线阶段前先分割张量，到达目标阶段后通过节点内通信收集，而高级张量并行已为下一阶段提供整个逻辑张量的子块，无需拆分-收集操作，从而降低通信成本。

## 小结

张量并行是训练全连接层大型模型的有效方法，把训练过程拆分为更小部分，减少通信时间，使训练更可行。但实现时前向和反向过程中都需要阻塞式集体通信。张量并行可保证进程永不闲置，但实现难度通常高于数据并行。

传统张量并行解决了模型数据造成的内存瓶颈，但 AlphaFold、文档级文本理解等任务面临由长序列非模型数据造成的不同瓶颈。Transformer 自注意力复杂度随序列长度呈二次方增长，限制训练能力，因中间激活会增加内存。为此研究者提出序列并行，把模型在设备间复制，并沿序列维度分割输入数据。这需要额外通信完成自注意力计算。为此提出了环自注意力模块交换部分嵌入。

**6.4.4 专家混合**

专家混合 MoE 是一种可在不增加计算成本的情况下使用更多参数的强大方法。它通过门控机制为每个输入选择网络的计算部分。旨在允许使用多组擅长不同技能的权重，即专家。借助 MoE，可增加模型使用的 GPU 数量，因每个专家可分配到单独 GPU。

该方法显著提升神经网络计算效率，使其更适合大规模应用。借助 MoE，门控机制可为每个输入确定合适的专家，使网络能动态适应不同输入。

总之 MoE 是一种很有前景的技术，有助于克服传统神经网络架构的某些限制。后文将更深入讨论 MoE 的内部原理及其在各类应用中的潜在优势。[PRE6]

## 6.5 混合训练和低精度训练

Micikevicius 等 2017 年提出使用半精度浮点数 FP16 训练模型并保持准确率。他们提出三种技术防止半精度丢失关键信息。保留模型权重的全精度 FP32 副本以累积梯度，然后把梯度舍入为半精度用于前向和反向。这确保梯度更新得以保留，因梯度更新可能太小而无法容纳在 FP16 范围内。损失缩放用于放大损失以处理幅度小的梯度。通过放大梯度，原本会丢失的值得以保留并移入可表示范围。对于向量点积或元素归约等常见算术，部分结果在 FP32 中累积，最终输出保存在 FP16 再写入内存。逐点操作可在 FP16 或 FP32 中执行。实验表明对图像分类和 Faster R-CNN 等网络损失缩放并非必需，但对 Multibox SSD 和大型 LSTM 语言模型却是必需的。

**6.5.1 单位缩放**

训练中使用 FP16 或 FP8 格式可显著提升效率，但范围可能不足以即插即用。为解决此限制，Noune 等 2022 年引入单位缩放方法。与其他方法不同，单位缩放无需通过多次训练寻找合适的缩放范围，计算开销也小。该方法的有效性在多种模型和优化器上得到验证。研究还表明现有模型可调整为单位缩放模型，例如先用 FP16 训练 BERT-Large 再用 FP8 训练不会降低准确率。

更具体地说，权重、激活和梯度都具有单位方差。三者都是目标，而非像初始化方案那样只针对其一。采用该方法时，由于每次运算都乘以一个常数，即梯度“出错”的固定常数，需要更新学习率和权重衰减。图 6-13 a 中每个张量乘以固定标量以实现一致缩放，无需损失缩放来控制 ∇[x] 的缩放。图 6-13 b 中阴影表示分区密度 Bin density。y 轴反映 FP16 中可用的指数值，虚线表示 Noune 等 2022 年提出的 FP8 E4 格式的最大最小指数。
