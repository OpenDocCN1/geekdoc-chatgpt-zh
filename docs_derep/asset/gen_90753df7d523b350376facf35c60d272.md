##### 2. MCP 客户端：协议适配的中枢

在 MCP 的整体架构中，客户端就是与服务端直接对话的执行主体，角色更像一个协议转换器。每个客户端实例都是由主机创建出来的，专门负责和一个服务器打通通信管道、完成协议格式的转换、安全校验等具体操作。它和服务器之间是一对一的，彼此独立，和其他客户端、服务器互相隔离。说个直观的比喻，主机相当于外交部长，负责定政策、管整体关系；客户端则像驻外大使，落地执行具体事务。

客户端主要干这几件事。

###### （1）会话通道的建立与维护
首要工作是搭好并稳住和服务器之间的标准通信。底层采用 JSON-RPC 2.0 来交换消息，管理连接全生命周期：从带状态的双向通道初始化，到保活心跳，再到优雅断开。客户端还会主动进行能力协商，明确告诉服务器自己能做什么，并自带错误处理和日志记录，保证全过程可追踪、可恢复。简单实现思路如下：

###### （2）根路径管理与安全沙盒
Root 是客户端里一个常被忽略却很关键的安全机制，连 Anthropic 自家的 Claude 也很少被提及。忽略不代表不重要，MCP 设计者显然预见了客户端和服务器协作时可能出现的安全风险。比如用户加了一个社区开源的本地文件操作服务器，Agent 执行任务时悄悄删掉了未授权目录，用户毫无察觉。安全问题总会滞后于技术热情，大家现在沉浸在 Agent 长出手脚、能连一切的兴奋里，社区服务器的安全考量普遍不足，需要使用者提高警惕。

###### （3）工具执行的网关校验
工具的定义和执行都在服务器侧，但实际调用必须经过客户端的网关，设置了三层校验：

- 协议层校验：模型返回的工具调用参数是否符合 Tool Schema 定义，例如 getWeather 必须带 city，否则调用非法。
- 语义层校验：调用名是否在服务器已声明的工具列表内。模型幻觉把 getWeather 写成 get_weather 就要被拦截。
- 权限层校验：这次调用是否获得用户授权。

###### （4）模型采样控制器
Sampling 是 MCP 的一个特殊能力，让服务器可以通过客户端向主机管控的 LLM 发起推理请求，类型可以是文本、音频、图像等，同时客户端保留对模型访问权限和策略的完全掌控，并把用户拉进流程，让用户审核请求内容和结果。

这个设计很特别。目前除了 fast-agent，几乎没有主机实现它，网上解读也很少。但从哲学上看，Sampling 让服务器不再是冰冷的工具执行者，而是具备一定主动性的参与者。MCP 生态里成千上万的服务器，现在看是本地文件函数或查天气的 API，但延伸下去它们可以是拥有智能的 Agent。既能机械执行，也能基于经验为任务提供方案。

##### 3. MCP 服务器：把能力做成标准件

MCP 服务器是为 AI 应用设计的标准化服务单元，通过统一协议向客户端提供上下文数据、工具能力和提示词模板。和传统 API 不同，它更关注 LLM 对动态上下文、领域工具和安全隔离的需求，核心价值是把 AI 能力模块化、即插即用。

作为 AI 原生时代的标准接口，MCP 服务器解决了 AI 能力集成的碎片化问题，构建可自由组合的模块化生态。就像能力插座，任意领域的专业知识、工具和服务都能封装成标准模块，无论是代码分析、医疗知识图谱还是智能家居控制，都能变成遵循统一协议的服务器。

搭建跨行业方案就像拼乐高：金融风控可快速接入法律条文解读和财报分析工具链，智能家居中枢能无缝整合环境感知和用户习惯模型。开发者不用重复造轮子，只需深耕垂直价值。协议层的安全隔离，如上下文沙盒和权限分级，保证了模块间安全互操作，既能让医疗诊断服务器与医学文献服务器协同，又避免敏感数据泄露。

社区驱动的开源服务器仓库放大了网络效应，经过场景验证的组件会沉淀为通用资产，比如自然语言转 SQL 的服务器可被电商、物流、科研复用，形成一次开发全域赋能的正循环。这种标准化、可组合、自进化的体系大幅降低 AI 落地成本，让中小团队低成本接入顶尖能力，让行业专家无需懂算法就能把领域知识变成智能服务。
