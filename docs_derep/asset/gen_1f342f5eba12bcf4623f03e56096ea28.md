大模型落地的隐形加速底座

（1）存储访问提速
进入大模型时代，存储面临的是体量爆炸与形态混杂的双重压力。规模上，亿级文件的预处理成为常态；多样性上，文本、图像、视频等多模态数据同步涌入。AI 基础设施里典型的数据访问模式可归纳为四类：
训练数据以只读或读多写少为主，训练时持续拉取；检查点数据写多读少，周期性落盘，单次可达 TB 级；模型数据训练后写入、推理时加载，同样是读多写少且体量巨大；缓存数据则以 KV Cache 为代表，为推理加速而产生，部分场景下需持久化。
训推一体时，训练数据的加载速度、模型参数的读写效率、检查点的保存恢复能力，以及推理时模型加载速度和缓存命中率，都直接决定 GPU 利用率。一旦存储成为瓶颈，计算单元空转，延迟与吞吐立即受损。
为此 DeepSeek 量身打造了 3FS 分布式文件系统，在大模型场景下提供高性能支撑。但多数 AI 作业仍依赖 POSIX 兼容的存储加速。阿里云服务器操作系统据此提供两项加速特性：
高性能文件协议加速：在保留 FUSE POSIX 兼容性的前提下，对 FUSE 核心路径做深度优化，性能较社区原生实现提升 6 倍以上，可对接所有 FUSE 协议的分布式存储。
低成本块协议加速：基于 EROFS 构建虚拟块设备直达对象存储，例如阿里云 OSS，用极低成本的云存储替代昂贵的高性能分布式存储。在百万级小文件读取场景下，对比标准 OSSFS 接入，读取性能提升 10 倍以上。

（2）PyTorch 在 ARM 架构上的优化
PyTorch 是学术研究与工业落地的核心底座，DeepSeek、通义千问等大模型均基于其构建。在英伟达 GPU 与英特尔 CPU 上表现优异，但在 ARM 芯片上因未能充分调用硬件加速指令而存在差距。
深度学习与 Transformer 结构里矩阵乘法占主导。阿里云服务器操作系统为 ARM 版 PyTorch 接入 ACL，即 ARM Compute Library 的矩阵乘法实现，释放处理器算力。实测在 ARM v8.6A 架构下进行 BF16 矩阵乘法优化后，ResNet-50 与 BERT 推理场景的吞吐性能实现翻倍。

（3）PD 分离特性
阿里云服务器操作系统团队参与 Mooncake Transfer Engine 与 Mooncake Store 的开发，并持续贡献开源。Mooncake 以 KV Cache 为中心解耦，支持 Prefill 集群与 Decode 集群分离，利用 GPU 集群中闲置的 CPU、DRAM、SSD 资源实现 KV Cache 解耦缓存。
团队随即参与 vLLM 与 SGLang 的 PD 分离架构支持研究。传统推理通过扩 batch 提升吞吐，对自回归生成效率有限。KV Cache 之后，推理可拆为两段：Prefill 计算密集、算力消耗高；Decode 访存密集、顺序生成、算力利用低。若同实例承载，Prefill 期显存利用不足、Decode 期算力闲置。
PD 分离带来的收益包括：并行 Prefill 与优化调度降低并发延迟；按需为 P 集群与 D 集群配置不同规格 GPU，例如算力强的 GPU 用于 Prefill、显存与性价比优的 GPU 用于 Decode，实现资源精细化与 Token 成本下降。
阿里云团队将 PD 分离能力上游化。vLLM 是面向大规模语言模型高效推理的开源库，集成 Paged Attention、Speculative Decoding、Chunked Prefill，2024 年 10 月加入 Linux 基金会；SGLang 是快速可改动的大模型与视觉语言模型服务框架，口碑优良。借助上游贡献，阿里云可第一时间获取最新推理特性，并推动 PD 分离成为事实标准。
在 Mooncake 框架下，团队提供两种标准化路径：基于 GDR 的直连传输与中心化 KV Cache 存储。2024 年 12 月起，通过中心化 KV Cache 模式分阶段完成 vLLM 的 PD 分离特性 1P1D、xPyD，并在主线合并，Time per Output Token 与 Inter-token Latency 均明显改善。2025 年 3 月，与 SGLang 合作，基于 Mooncake 的 GDR 直连传输模式完成 PD 分离主线支持。
总体看，AI 基础设施的训练与推理需求迫使系统从被动适配转向主动优化，稳定性、安全、弹性、性能与成本共同构成挑战。

4. 企业案例：DeepSeek 模型的高效商业化部署
某互联网公司在大模型商业化过程中，业务覆盖智能问答、个性化推荐与自动化内容审核，日均处理数亿级请求。原方案基于张量并行部署 MoE 架构的 DeepSeek 模型，出现成本高、效率低、扩展难的问题。

1）客户痛点：成本与效率双重受限
推理成本高企，内存碎片与 GPU 利用率不足 60%，每百万 Token 输出成本优化空间巨大。高频请求推高算力支出；MoE 稀疏计算导致专家负载不均衡，部分 GPU 长期空闲，单节点解码速度仅 4500 Tokens/s，Prefill 与 Decode 统一调度引发请求中断，首响时间长达 10 秒；传统专家并行 EP32 固定分组，难以随流量波动动态伸缩，扩容需重构集群。

2）解决方案：云原生与并行化技术协同
SGLang 社区联合阿里云技术团队，基于 SGLang、Mooncake 与 DeepEP，构建融合 PD 分离、数据高并行与大规模专家并行的全链路优化方案。

2.2.3 OceanBase：DeepSeek 生态下的数据管理新范式探索

1. 行业概况
数据已成为核心生产资料，数据库是支撑业务运营、用户交互与模型训练推理的基础。数据库从层次与网状模型演进至关系型，SQL 标准化推动普及；互联网与大数据时代催生 NoSQL 的横向扩展能力；NewSQL 在保持事务一致性的同时实现分布式扩展。近年来数据库向云原生、多模态、智能化演进。
以 DeepSeek 为代表的大模型带来范式革命。强大的推理能力让自然语言直接驱动查询，成为非技术人员的数据入口；同时参与运维调优，提供自动化异常检测、根因分析与修复建议；推动数据库从存储工具向智能引擎演进。向量能力与 RAG 架构的支持，使数据库成为 DeepSeek 生态的重要数据底座。

2. DeepSeek 带来的机遇与挑战
大模型与数据库正双向赋能。
智能化升级方面，自然语言查询让用户用口语表达意图，系统自动转译为 SQL；运维层面可基于历史日志智能推荐索引、查询改写与资源分配，实现自适应优化，并自动化异常检测与日志分析；数据治理层面可通过语义分析识别敏感字段、自动打标脱敏，构建统一数据字典；文档生成、知识问答与教学辅助能力也显著提升。
同时面临挑战：大模型生成 SQL 或逻辑判断时可能出现语义偏差，导致结果不准甚至泄露；用户输入含敏感信息时缺乏有效脱敏与访问控制会带来隐私风险；主流数据库生态相对封闭，与 AI 模型的接口标准尚未统一，无缝集成仍是技术难点。
