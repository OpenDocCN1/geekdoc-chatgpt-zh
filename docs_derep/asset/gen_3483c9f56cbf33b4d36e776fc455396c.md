让提示词真正活起来的核心，在于对“变量”这件事的灵活与精准。只要在模板里按 Dify 的语法把来自上游节点比如“开始”“知识检索”“工具”等产出的值引用进来，就能实现动态拼接。把这套引用机制用熟，提示词就能随流程里的实时数据与上下文自适应，令大模型始终给出最合适的输出。

#### 10.2.3 从开场白到多轮对话的智能管控

做对话类 AI 应用，单次问答的表述只是起点，整段会话的体感才决定留存。Dify 的可视化编排画布正好提供了搭建复杂会话流程的能力。

先把第一印象打好。面向终端用户的应用，一个友好、清晰且点明核心能力的开场白至关重要。Dify 里通常有两种做法：在应用基础设置里写死一段固定问候；或在“开始”节点后接一个专门的 LLM 节点，让它零输入地生成一段带点变化的迎宾语。这个节点的提示词不需要依赖用户侧信息，只负责输出对话的开场。

再来设计能应对不同复杂度的多轮逻辑。

基础对话。最纯粹的大模型问答可以压缩成一个循环：用户在“开始”节点输入 query，随后连同平台自动维护的对话历史变量 chat_history 一起送入 LLM 节点，生成回复后由“结束”节点回传。Dify 会自动完成历史的传递与维护，开发成本很低。

RAG 增强对话。需要私有知识时流程会更厚：收到 query 后先走“知识检索”节点，从关联集里挑出最相关的上下文，再把原始问题、检索到的片段和对话历史一起喂给 LLM，模型基于完整增强信息给出更准的答案，最后经“结束”节点发出。

工具行动对话。若要让 AI 真正去执行操作，通常需要两个 LLM 节点加一个工具节点，并配合条件判断。第一個 LLM 负责意图解析，判断是否需要调外部工具并生成结构化调用指令。随后“条件分支”依据是否存在 tool_calls 决定走向：不需要则直接结束；需要则进入“工具”节点调用外部 API 并取回结果。最后把执行结果连同前面上下文送入第二个 LLM，由它整合反馈并产出面向用户的最终回复。

借助“条件分支”等逻辑控制节点，可以按用户意图、知识库置信度或工具调用状态等动态条件来路由对话，从而支撑真正复杂的多轮交互。

#### 10.3.1 创建并管理知识库

先在 Dify 的知识库管理页点“创建知识库”，命名例如“附录-计算机系统-征求意见稿”，并上传文档，如图10-9所示。

[PRE1]

图10-9 创建知识库

上传后后台会自动预处理，核心是把长文档切成合适大小的文本块并生成语义向量。几个关键配置要留意。

（1）分段模式。通用模式按用户自定义规则，比如固定长度、标点分割，将内容拆成独立片段。提问时系统会分析关键词，计算与各片段的相关度并挑选最相关的供给模型。更进阶的是父子模式，采用双层结构兼顾检索精度与上下文。父块保持较大单位如段落提供丰富上下文，子块是更小的句子用于精确检索。先用子块精确定位，再带回父块补充上下文，可自定义分隔符与最大长度。

（2）Embedding 模型。选择在模型供应商侧已配置好的可用模型，模型选得好检索质量才有保障。

（3）文档处理模式，即索引方式。高质量模式用 Embedding 把分段文本转成数字向量，压缩存储且匹配更精准。经济模式则在各块内以少量关键词检索，准确度下降但省去 Embedding 费用，采用倒排索引。若经济索引效果不足，可在知识库设置里升级为高质量索引。

（4）检索设置。高质量索引下可配置向量检索、全文检索与混合检索。向量检索把用户问题向量化后与知识库向量算距离；全文检索靠明文关键词匹配；混合检索两者兼用，或用 Rerank 模型从候选里挑最优。

配置完成后 Dify 会开始处理文档，耗时取决于文档量与模型速度，界面可查看进度。完成后知识库即可使用。

#### 10.3.2 配置知识库的检索策略

回到“基于知识库的文档修订助手”应用，在编排画布里新增“知识检索”节点。配置时先明确目标知识库，这里选“附录-计算机系统-征求意见稿”。

再合理设定 Top K，即相似度检索后希望返回的前 K 个文档块。K 太小会漏掉关键信息，K 太大则引入噪声并增加模型负担与成本，通常从 3～5 开始尝试再根据效果调整。

平台还允许对相关性得分设过滤阈值，只有余弦相似度等指标高于阈值的块才被采纳，有助于剔除弱相关结果，但阈值过高会误杀有用信息，过低则形同虚设，需结合模型、度量方式与库内内容特性实验确定。

### 10.4 AI 应用的发布

当应用在 Dify 里经过反复设计、调试、预览后基本满意，就要正式发布，让目标用户能访问或嵌入到既有业务流程。

#### 10.4.1 发布前的全面预览与深度调试

点“正式发布”前，务必用平台提供的预览或在线调试功能做一次全覆盖的深度测试。覆盖典型输入与边界场景，检查知识检索的准确性、工具调用的正确性、多轮对话的连贯与鲁棒性。只有在各种情况下都能给出合理预期响应，体验与可靠性才有保障。

#### 10.4.2 应用的公开分享或嵌入代码

Dify 会为每个应用自动生成可即时访问的 Web 应用界面，交付给终端用户非常便捷。

在应用管理或发布设置里通常提供两种方式。

- 获取公开分享链接。平台会生成唯一公开 URL，直接转发给同事、客户或测试用户即可在浏览器打开使用，无需安装配置。
- 获取 HTML 嵌入代码。若希望把聊天窗口无缝嵌到企业官网、产品页或内部知识门户，平台会提供一段 `<iframe>` 代码，复制到目标页的合适位置即可实现原生体验。

#### 10.4.3 应用的 API 访问与集成

除了 Web 形式，Dify 还支持把应用发布为标准化 API 接口。企业内部其他业务系统、移动端或自有前端可通过调用该接口程序化交互，获取 AI 能力。

在应用设置或 API 管理区可查到调用说明：API 端点 URL、API Key 的获取与鉴权方式、请求参数格式、响应格式与错误处理。通过这种方式，Dify 上的 AI 能力能更灵活地融入整体 IT 架构与业务流程。

借助发布、分享、嵌入与版本管理功能，可以更可控地交付应用并持续迭代优化。
