#### 4. 指令生成与运行
在锁定相关实体与子图之后，系统要把自然语言需求转化为可在图库中执行的检索指令。整体可拆成编制指令和运行指令两个环节。

##### （1）指令编写
编制环节依据已识别的实体及其关联关系，产出对应的检索脚本。比如可让 LLM 生成 SPARQL 或 Cypher，用以抽取目标信息。以“谁创办了谷歌？”为例，系统需要产出一条指向该公司与其创办者节点相连的检索指令。

产出指令时要兼顾难度与精确度。简单提问可映射为简短指令；涉及多层关联或需推断的复杂提问，例如“谷歌的创办者是谁，他们的出生时间是什么”，指令就必须串联多条关系路径，才能同时取回创办者及出生时间。

#### 5. 多跳推理与深层关联
不少用户提问需要拆解为多跳推理，即从起点实体经多条关系链逐步抵达目标。这种能力让基于图谱的系统能够应对更抽象的问题。

##### （1）多跳检索
多跳即跨多层关系从一个实体抵达另一个实体。例如“谷歌的创办者是谁，他们的出生时间是什么”，系统需先从谷歌节点经创办者关系抵达创办者节点，再经出生时间属性取出具体值。该类检索涉及多个节点与多种关系，对推理要求较高。

实现时需高效遍历图谱，并结合提问上下文确保每一步准确。比如在医疗图谱中，“糖尿病常见并发症有哪些”就要求系统从糖尿病节点出发，沿并发症关系找到多个关联节点。

### 2.2.2 基于关系型数据库的检索
在检索增强生成框架中，关系型数据库的检索通过从结构化数据中快速抽取信息来增强生成模型的回答能力。借助关系型数据库与 SQL 技术，可高效管理与检索引擎海量数据。

SQL 数据库在检索增强生成中的作用主要涵盖结构化存储与管理、高效检索、动态指令生成以及多跳查询与复杂推理，下面逐项展开。

#### 1. 向量库的接入
在检索增强生成中，向量数据库负责初步检索与用户提问相关的文档或片段。集成主要步骤包括意图理解与处理、查询生成、信息检索以及检索结果的处理与生成。

（1）意图理解与处理
系统首先利用自然语言处理技术理解用户提问，识别其中的关键术语和意图，确保准确解释提问并生成合适的搜索请求。例如用户输入“如何提高检索增强生成系统的性能？”，系统需识别出“提高性能”是主要意图，并提取关键术语“检索增强生成系统”“性能”。在生成查询向量时可对这些关键术语和意图赋予更高权重，确保向量表示准确反映主要意图，重点关注这两个概念。
