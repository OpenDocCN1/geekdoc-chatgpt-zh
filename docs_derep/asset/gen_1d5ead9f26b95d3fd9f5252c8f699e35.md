8.4.3 用 Docker Compose 优雅部署

把 OpenClaw 搬到服务器上，第一步是把官方镜像拉下来。镜像地址是 ghcr.io/openclaw/openclaw:latest，latest 指的就是最新稳定版。在终端执行 docker pull ghcr.io/openclaw/openclaw:latest，Docker 就会从 GitHub 仓库把镜像下载到本地机器。

容器运行前，先弄明白数据卷和目录映射。Docker 容器本质上是无状态的，停掉删掉后，容器里的配置文件、日志都会彻底丢失。要让 openclaw.json、会话历史、后续装的技能插件等核心数据能持久保存，就必须把宿主机目录挂载到容器内部。官方说明里，OpenClaw 在容器内的默认数据目录是 /root/.openclaw。

用一行 docker run 硬刚端口、卷、环境变量很容易出错也不好维护。实际使用建议用 Docker Compose，用一份结构清晰的 YAML 来定义和管理。先在服务器上建一个专门存放 OpenClaw 数据的目录，并在里面新建 docker-compose.yml。

文件里定义一个服务 openclaw-gateway，指向官方镜像，并加上 restart: unless-stopped，让容器在崩溃或服务器重启后自动拉起。端口方面把容器 3000 映射到宿主机 3000，方便外部访问。最关键的是数据卷，把宿主机当前目录下的 ./data 映射到容器里的 /root/.openclaw，实现持久化。

还能通过 environment 注入环境变量，比如把时区设为 Asia/Shenzhen，或者把大模型 API Key 以环境变量形式传入，避免写死到配置文件。最后用 command: ["gateway"] 指定启动 Gateway 服务。

OpenClaw 官网给出的标准 Compose 配置如下：

services:

  openclaw-gateway:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN:-}
      OPENCLAW_ALLOW_INSECURE_PRIVATE_WS: ${OPENCLAW_ALLOW_INSECURE_PRIVATE_WS:-}
      CLAUDE_AI_SESSION_KEY: ${CLAUDE_AI_SESSION_KEY:-}
      CLAUDE_WEB_SESSION_KEY: ${CLAUDE_WEB_SESSION_KEY:-}
      CLAUDE_WEB_COOKIE: ${CLAUDE_WEB_COOKIE:-}
      TZ: ${OPENCLAW_TZ:-UTC}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    ports:
      - "${OPENCLAW_GATEWAY_PORT:-18789}:18789"
      - "${OPENCLAW_BRIDGE_PORT:-18790}:18790"
    init: true
    restart: unless-stopped
    command:
      [
        "node",
        "dist/index.js",
        "gateway",
        "--bind",
        "${OPENCLAW_GATEWAY_BIND:-lan}",
        "--port",
        "18789",
      ]
    healthcheck:
      test:
        [
          "CMD",
          "node",
          "-e",
          "fetch('http://127.0.0.1:18789/healthz').then((r)=>process.exit (r.ok?0:1)).catch(()=>process.exit(1))",
        ]
      interval: 30s
      timeout: 5s
      retries: 5
      start_period: 20s
  openclaw-cli:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    network_mode: "service:openclaw-gateway"
    cap_drop:
      - NET_RAW
      - NET_ADMIN
    security_opt:
      - no-new-privileges:true
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN:-}
      OPENCLAW_ALLOW_INSECURE_PRIVATE_WS: ${OPENCLAW_ALLOW_INSECURE_PRIVATE_WS:-}
      BROWSER: echo
      CLAUDE_AI_SESSION_KEY: ${CLAUDE_AI_SESSION_KEY:-}
      CLAUDE_WEB_SESSION_KEY: ${CLAUDE_WEB_SESSION_KEY:-}
      CLAUDE_WEB_COOKIE: ${CLAUDE_WEB_COOKIE:-}
      TZ: ${OPENCLAW_TZ:-UTC}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    stdin_open: true
    tty: true
    init: true
    entrypoint: ["node", "dist/index.js"]
    depends_on:
      - openclaw-gateway

8.4.4 服务启动与日常运维

文件写好后，启动就很简单了。在 docker-compose.yml 所在目录执行 docker-compose up -d，Compose 会以守护模式在后台创建并启动容器。

运行期间排查问题用 docker-compose logs -f 实时看日志。如果要做初始化配置，比如执行 openclaw configure，或者安装新插件，不能直接在宿主机跑命令，要先用 docker exec -it openclaw-gateway /bin/bash 进入正在运行的容器，再在容器内执行 OpenClaw 相关命令。

版本更新也很顺滑。官方发布修复或新功能后，在文件目录下先执行 docker-compose pull 拉取新镜像，再执行 docker-compose up -d 用新镜像重建并启动。容器会被平滑替换，而放在 ./data 目录里的配置文件和历史记录因为数据卷挂载，会完整保留并自动接入新版本。

第九章 让 AI 直接进群聊

上章把 OpenClaw 部署到云上，让它能随时待命。但好的 AI Agent 不能只活在服务器终端里，它要融入日常工作流，和大家常用的沟通工具无缝衔接。OpenClaw 的 Channel 架构支持接入主流聊天平台，本章重点讲如何把云端 OpenClaw 接入国内三大企业协同工具：飞书、企业微信和钉钉。

接入后，成员不用切网页或终端，直接在熟悉的聊天窗口里像跟同事一样对话、下指令、收报告，大幅降低使用门槛，提升协作效率。

9.1 飞书接入指南

飞书以流畅体验、开放能力著称，受到很多创新团队青睐。OpenClaw 对飞书提供原生深度支持，亮点是利用飞书开放平台的 WebSocket 长连接事件订阅。不需要像传统 Webhook 那样在云服务器上暴露公网 URL 接收消息，省去反向代理和 SSL 证书配置，也从源头提升了安全性。

9.1.1 新建飞书应用与机器人

先在飞书开放平台创建企业自建应用，作为 OpenClaw 在飞书生态里的合法身份。用有权限的企业账号登录，海外版用对应后台。进入开发者后台点“创建企业自建应用”，给助手起个好记的名字，比如“OpenClaw 智能助手”，填描述并上传清晰图标。

创建成功后进入详情页，左侧“凭证与基础信息”里有两项关键参数：App ID，通常以 cli_ 开头；App Secret，应用密钥。这相当于机器人的账号密码，用于 OpenClaw 校验身份，请妥善保存。

接下来在左侧菜单进入“添加应用功能”→“添加机器人”，打开“启用机器人”开关。这个机器人就是 OpenClaw 在飞书里的交互入口。

9.1.2 开放权限与事件订阅

创建应用后还需申请 API 权限。在应用详情页左侧依次选择“开发配置”→“权限管理”，选择“应用身份权限”。可以直接用批量导入导出功能，把下面 JSON 权限配置粘贴进去：

{
  "scopes": {
    "tenant": [
      "im:chat.members:bot_access",
      "im:message",
      "im:message.group_at_msg:readonly",
      "im:message.p2p_msg:readonly",
      "im:message:readonly",
      "im:message:send_as_bot",
      "im:resource"
    ],
    "user": [
      "contact:contact.base:readonly"
    ]
  }
}

其中 user 下的 contact:contact.base:readonly 最关键，它允许机器人只读访问企业通讯录基础信息，用于身份校验、上下文匹配和合规回复。如果没开通，机器人拿不到用户数据，会直接交互失败。

已开通的核心权限如图。最后配置事件订阅，让飞书把用户消息实时推给 OpenClaw。在左侧导航选择“开发配置”→“事件与回调”，事件配置里选“使用长连接接收事件 WebSocket”。这是官方推荐方式，避免公网 Webhook。
