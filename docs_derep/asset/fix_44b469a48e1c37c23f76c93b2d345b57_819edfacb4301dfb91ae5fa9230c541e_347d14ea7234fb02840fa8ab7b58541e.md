DeepSeek-V3 本地运行，函数调用实战演示

想让大模型不止会聊天，还能去查真实数据，思路很直接：先把 DeepSeek-V3 本地跑通，再用兼容 OpenAI 的方式教它调用外部函数。下面以查询天气为例，把整条链路拆开。

先把权重和分词器用魔搭的接口载入，半精度运行并让框架自动选卡。生成参数沿用模型自带配置，并把 pad token 指向 eos，避免生成时出现多余填充。

from modelscope import AutoTokenizer, AutoModelForCausalLM, GenerationConfig

model_name = "./deepseek-v3"

tokenizer = AutoTokenizer.from_pretrained(model_name)

model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

model.generation_config = GenerationConfig.from_pretrained(model_name)

model.generation_config.pad_token_id = model.generation_config.eos_token_id

把用户问句装进消息列表，用 chat template 编码并打开回复模式，限制新 token 长度，解码时去掉输入部分和特殊符号就能拿到结果。

# 构造对话消息列表

messages = [

    {"role": "user", "content": "你好，好久不见，请介绍下你自己！"}

]

# 使用 tokenizer 将对话消息转换为模型可处理的张量格式

input_tensor = tokenizer.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt")

# 使用模型进行文本生成

outputs = model.generate(input_tensor.to(model.device), max_new_tokens=100)

# 解码模型生成的文本

result = tokenizer.decode(outputs[0][input_tensor.shape[1]:], skip_special_tokens=True)

print(result)

def get_weather(loc):

    """

    查询即时天气函数

    :param loc: 必要参数，字符串类型，用于表示查询天气的具体城市名称。

    注意，中国的城市名称需要用其英文名称代替，例如如果需要查询北京市天气，则 loc 参数需要输入'Beijing'；

    :return: OpenWeather API 查询即时天气的结果，具体 URL 请求地址为：https://api.openweathermap.org/data/2.5/weather

    返回结果对象类型为解析之后的 JSON 格式对象，并用字符串形式进行表示，其中包含了全部重要的天气信息

    """

    # Step 1.构建请求

    url = "https://api.openweathermap.org/data/2.5/weather"

    # Step 2.设置查询参数

    params = {

        "q": loc,

        "appid": open_weather_key,        # 输入 API key

        "units": "metric",                # 使用摄氏度而不是华氏度

        "lang":"zh_cn"                    # 输出语言为简体中文

    }

    # Step 3.发送 GET 请求

    response = requests.get(url, params=params)

    # Step 4.解析响应

    data = response.json()

    return json.dumps(data)

要让模型认识该能力，需要给出函数名称、功能说明与参数格式。名称为 get_weather，描述强调按城市名获取实时天气，参数 loc 为字符串且必填，并再次提示国内城市使用英文。
