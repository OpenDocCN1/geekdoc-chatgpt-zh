## 7.1 数据入库：格式选型避坑指南

金融大数据存储是分析流程的基石环节。合理的存储架构不仅能驾驭海量数据，更能保障资产安全与读写效率。常见落地格式各有千秋，需按需取舍：

*   **SQL 数据库（MySQL、PostgreSQL、Oracle 等）**：结构化数据的主战场。凭借成熟的 SQL 语言与 ACID 特性，擅长处理交易流水、账户体系等强关联、高一致性场景，是核心业务系统的首选。
*   **Excel**：轻量级分析的“瑞士军刀”。电子表格直观易用，适配小规模数据整理、投资组合跟踪、财务报表输出等临时性、人工参与度高的任务。
*   **CSV（逗号分隔值）**：数据流转的“通用语言”。纯文本、轻量、跨平台解析无障碍，是海量行情导入、指标批量导出、异构系统对接的标准交换格式。
*   **JSON（JavaScript Object Notation）**：半结构化数据的天然载体。嵌套结构表达力强，契合 API 接口返回的行情快照、经济指标、另类数据等非标准化内容，也是 NoSQL 数据库的常用持久化格式。

**选型法则**：无绝对优劣，仅看契合度。结合数据规模、结构复杂度、查询模式、下游工具链综合考量；实战中常采用“多格式共存”策略，分层存储，各司其职。

#### 7.1.3 命令行模式：极客范的原生连接

服务启动后，打开 CMD/PowerShell，标准登录指令模板：

```bash
mysql -h<主机IP> -u<用户名> -p<密码>
```
参数解析：
*   `-h`：目标主机（本机可省略，远程填 IP/域名）。
*   `-u`：数据库账号（需预授权）。
*   `-p`：密码（跟随 `-p` 直接写或回车后交互式输入，后者更安全）。
