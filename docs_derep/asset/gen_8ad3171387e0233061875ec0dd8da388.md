知识图谱问答与深度学习的融合大致走两条路线。第一条是在传统范式上做增强，把问句理解里的实体识别、关系识别等环节换成神经网络来提升精度，或者直接用神经模型替代传统范式的语义解析与实体关系映射环节，这部分在语义解析相关章节已有介绍。第二条是做端到端的问答，直接把自然语言问句和知识库一起丢进系统，模型直接输出答案，中间推理对用户而言近似黑盒。端到端方案的运行逻辑见图 6-33 所示。

本文以 Bordes 等人 2014 年的工作为例说明端到端实现思路。研究者在 WebQuestions 和 Freebase 上构造问答对，用正负样本训练神经网络，让模型从海量知识库中自行学习常识，并在通用主题上给出回答，且几乎不用手工特征。

以输入问句 “Who did Clooney marry in 1987?” 为例，模型学习与推理大致经历五步。

1）借助实体链接把问题里主实体定位出来，这里是 “Clooney”。

2）在 Freebase 中找到该主实体的图谱表示，本例为 “G.Clooney”，随后在图上寻找从问题实体到候选答案实体的连通路径。

3）把候选答案实体展开成一个子图，即收集知识库中与答案实体有直接链接的所有实体作为候选集合。

4）把原始问句和候选答案子图分别编码成向量，形成统一的表示空间。

5）用点积计算问题向量与每个候选答案向量的相似度，取分值最高者作为结果。

### 6.3.4 模板匹配驱动的问答系统实战

本节演示如何用模板匹配搭建一个简易问答系统供参考。数据存放在 Neo4j 数据库中，系统借助句式模板把自然语言问题抽取出核心三元组——主语 Subject S、谓语 Predicate P、宾语 Object O。P 既可以是属性也可以是关系，并支持条件运算符 “<”、“>”、“<=”、“>=”、“：” 等，其中 “：” 相当于赋值等于。多个条件可用 “and”、“or” 等逻辑连词拼接。此外还支持聚合运算，如 count 计数、sum 求和、avg 平均、max 最大值、min 最小值、distinct 去重，用于处理特定类问题。

在知识问答里，问题类型决定了理解目标与查询表达式的构造方式。Li 等人\[34\] 观察 TREC 的 1000 个问题，归纳出 6 大类型：ABBREVIATION 缩写类、ENTITY 事物质类、DESCRIPTION 定义描述类、HUMAN 人物类、LOCATION 地点类、NUMERIC VALUE 数值类。BU\[36\] 等人基于百度知道数据，从功能角度提出另一套分类，聚焦事实类问答，分为 Fact 事实、List 列表、Reason 原因、Solution 解决方案、Definition 定义、Navigation 导航六类，具体说明与样例见表 6-3 所示。

1）常见特殊疑问句问答。
* What：“腾讯是什么性质的企业？”
* Who：“阿里巴巴的创始人是谁？”
* When：“小米上市的日期是什么时候？”
* Where：“百度的公司地址在哪里？”
* Which：“华为的公司性质属于哪一种？”
* How_many：“拼多多有多少员工？”
这类问题的 SPO 通常以 S 为问题主体，P 为查询的属性或关系，O 用 “x?” 占位表示待求结果。

2）一般疑问句即是否类问答。
例如 “周杰伦是摩羯座的吗？” SPO 为 S：周杰伦、P：星座、O：摩羯座。系统可从句中抽取完整三元组到图谱校验，匹配则返回 Yes，否则返回 No。

3）复杂问题问答。
包括比较类，如 “刘德华和周润发谁年龄大？”，以及多跳查询类，如 “美人鱼的导演的主要成就是什么？”。
