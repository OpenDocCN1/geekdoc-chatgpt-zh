## 12.2 Action 应用场景示例

Action 的落地方向大致可以归纳为以下几类。

1. 数据查询和读取

本质是让 GPTs 透过 Action 连上数据库或 API，拿到实时信息，特别适合需要即时回报的场景，例如天气、股价、机票酒店价等。

把 GPTs 塑造成个人助理时，这类用法能实现信息收集、分析和建议输出。

示例：扮演个人助理角色

把 “Google Calendar Assistant（Google 日历助手）” 作为 Action 挂载到 GPTs 后，模型即可承担助理职能。询问 “Google Calendar Assistant 我今天的日程有哪些” 时，它会先申请日历访问权限并读取行程，如图 12-7 所示。

图 12-7 “Google Calendar Assistant” 连接 Action 后会询问用户是否授权查询日历

授权通过后，该助手会经 Action 读取 Google 日历事项，并在对话窗口中汇总今日安排，如图 12-8 所示。

图 12-8 “Google Calendar Assistant” 查询 Google 日历事项并且回复用户

2. 数据搜索

ChatGPT 自身的知识时间点有限，接入外部知识库后可扩展信息范围。

此种用法适合把 GPTs 接入外部数据库，发挥 AI 大数据助手的角色。

## 12.3 Action 配置必备要素

新建 GPTs 后进入 “Configure” 选项卡，滚动至底部点选 “Create new action”，即可看到配置时需要准备的材料，如图 12-12 所示。

[PRE6]

图 12-12 单击 “Create new action” 按钮

进入后会来到 “Add actions” 页面，如图 12-13 所示。

[PRE7]

图 12-13 “Add actions” 界面

第一个要素：Authentication（认证）

指的是 GPTs 发起 Action 请求后，访问第三方软件或 App 时是否需要身份验证，如图 12-14 所示。

[PRE8]

常见做法有三种，如图 12-15 所示。

“None” 表示可直接调用 API，无需密码或密钥，多用于公开数据如天气、新闻头条。

“API Key” 相当于访问密码，只有持有者能调取对应数据，常用于权限管控场景。

“OAuth” 是更安全灵活的授权方式，相当于给 GPTs 发一张临时许可，代表用户安全访问第三方服务，如社交账号或个人资料，而不泄露登录凭证，多用于邮箱、日历等需用户授权的服务，确保只有获许可的应用才能操作数据。

[PRE9]

第二个要素：Schema（结构）

Schema 定义了 API 的结构与调用写法，例如要做天气查询助手 GPTs，就需定义 Schema 来描述如何向天气 API 发送请求，如图 12-16 所示。

[PRE10]

借助 Schema，GPTs 才能正确获取并把结果返回到对话界面。Schema 通常由开发者手写，若使用集成器搭建 Action，可直接 “Import from URL（从 URL 导入）”，填入厂商提供的现成 Schema，免去重复编写。

第三个要素：Privacy policy（隐私政策）

Privacy policy 是第三方软件或 App 提供 API 时附带的隐私说明，用于告知用户数据交互时的使用与保护方式，如图 12-17 所示。

[PRE11]

整体配置看似门槛较高，但借助集成器工具，即使不懂代码也能扩展 GPTs 能力。接下来结合案例说明如何利用集成器创建 Action。

## 12.4 Zapier 联动 GPTs：自动化创建 Notion 文档与待办

Zapier 是一款可连接全球 7000 多个主流应用的集成器。利用其 Action 配置，能让 GPTs 连通 Gmail、Outlook 查询最新邮件甚至撰写邮件，也能自动创建印象笔记、Notion 笔记。

本例搭建一个 GPTs，让它联网搜集最新资讯为 YouTube 视频提供灵感，并把结果存入 Notion，同时生成待办提醒。涉及两个核心 Action：一是把内容写入 Notion 文档，二是创建 Microsoft To Do 待办。

在 Zapier 中为 GPTs 配置 Action 主要分三步。

1. 进行 GPTs 的基础设置

设定 GPTs 的角色与任务：YouTube 视频研究与内容创作助手。要求在给出最终结果前严格按步骤执行。第一步联网查询信息，第二步归纳总结，第三步把总结和参考链接整理归档，第四步询问用户是否需要保存到 Notion，是否需要生成待办任务，如图 12-18 所示。
