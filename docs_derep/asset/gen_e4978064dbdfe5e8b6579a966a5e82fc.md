### 4.1 初识网络爬虫

数据科学的起点是“拿到数据”。手头没现成的整理好数据集？那就得靠**网络爬虫**自力更生，直接从互联网“抓”数据。

#### 4.1.1 爬虫核心概念

简单说，网络爬虫就是**绕过官方 API，直接从网页源码里提取信息**的自动化过程。学名叫“Web Data Extraction”（网页数据提取）。

这套流程跑通需要三大件“兵器谱”：
- **Chrome 开发者工具**：侦察兵。帮你在杂乱的 HTML 里精准定位目标数据的“身份证”（标签名、class、id 等属性）。
- **HTTP 库（Requests）**：运输兵。负责跟服务器对话，把网页源代码（HTML 文本）拉回来。
- **解析库**：**搬运工。把拉回来的文本变成树状结构，方便按图索骥提取数据。

#### 4.1.2 爬虫标准五步走

一个完整的爬虫脚本，通常遵循这套 SOP：

1.  **锁定目标 URL**：单个或批量目标地址。
2.  **请求拿源码**：`Requests` 发请求，拿到 HTML 响应体。
3.  **开发者工具“侦察”**：在浏览器里分析数据藏在哪个标签、用什么特征能定位到。
4.  **解析建树**：`BeautifulSoup` 把 HTML 字符串解析成可遍历的对象树。
5.  **提取清洗存储**：搜索/遍历树结构取数据，洗成 CSV 或 JSON 格式落地。

#### 4.1.3 HTTP 协议：客户端与服务器的对话规范

HTTP 是浏览器（客户端）和服务器之间的通用语言。典型的**主从架构（Client-Server）**交互如下：

[PRE1]

1.  客户端发起连接请求。
2.  服务器接受连接。
3.  客户端发送 HTTP 报文（带上 GET/POST 方法），索要资源。
4.  服务器回复 HTTP 响应报文，附上资源内容。

### 4.3 捕获 HTTP 响应内容

服务器回包的内容（Response Content）可能是：HTML 文本、JSON 数据、二进制流（图片/视频）。

#### 4.3.1 响应对象的三大核心属性

发请求后：`r = requests.get(...)` 或 `r = requests.post(...)`。`r` 是 `Response` 对象，常用属性见下表：

[PRE20]

| 属性 | 说明 |
| :--- | :--- |
| **text** | **解码后的字符串**（最常用）。编码可通过 `r.encoding` 查看/修改。 |
| **content** | **原始字节流**。适合下载图片、文件等非文本资源。 |
| **raw** | 原始 Socket 响应对象 (`urllib3.HTTPResponse`)，极少直接用。 |

> **编码提示**：HTML 网页真实编码通常在 `<head>` 里的 `<meta charset="...">` 指定（参考 3.1.4 节）。Requests 会自动猜测，猜错需手动纠正 `r.encoding`。
