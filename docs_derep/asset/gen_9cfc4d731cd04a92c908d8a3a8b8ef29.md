工具分组风险速查

在 OpenClaw 里不同工具的能力边界和风险等级是分层设计的。运行时执行类 group:runtimeexec、bash、process 属于高危，可执行任意系统命令。自动化类 group:automationcron 和 gateway 也列为高危，前者能创建脱离对话的定时任务，后者可调用 config.apply、config.patch、update.run 等方法做持久化系统改动。远程节点控制 group:nodesnodes 同属高危。

读写文件相关 group:fsread、write、edit、apply_patch 风险为中。会话数据操作 group:sessionssessions_list、sessions_history、sessions_send、sessions_spawn、session_status 为中。浏览器控制 group:uiBrowser、canvas 为中。消息发送 group:messagingmessage 为中。仅读网络访问 group:webweb_search、eb_fetch 风险最低。

2．预设工具配置方案

OpenClaw 自带四套开箱即用的工具配置，对应不同使用场景。

minimal 只保留 session_status，几乎没有执行能力，安全性最高。coding 组合了 group:fs、group:runtime、group:sessions、group:memory 与 image，面向代码开发。messaging 组合了 group:messaging、sessions_list、sessions_history、sessions_send、session_status，适合做纯消息助理。full 则是无限制的完全信任模式，不建议在生产环境使用。

3．高风险工具的额外安全控制

exec 是最强也最危险的能力，配有多层闸门。

tools.exec.security 决定执行策略：deny 完全禁止 Shell，适合极致安全场景；allowlist 只放行 tools.exec.safeBins 白名单内的命令，在安全和灵活间折中；full 允许任意命令，灵活性最大但风险最高，仅限完全可控的个人环境。

tools.exec.ask 控制执行前的人工确认：off 直接执行，适合高自动化；on-miss 白名单外才询问；always 每次都必须明确授权，人工监督最强。

tools.exec.host 决定执行位置：sandbox 为默认隔离容器；gateway 在 Gateway 宿主机直接运行，权限极高；node 则投递到指定的远程节点。

gateway 因能持久化修改配置，应在接收不可信内容的 Agent 中明确禁用。cron 能在对话结束后继续运行定时任务，提示词注入一旦成功就可能留下长期恶意任务，同样建议在不可信场景下禁止。

4．公共聊天平台DM访问策略

接入 Telegram、Discord 等公共平台时，OpenClaw 提供四种 DM 策略。

pairing 为默认配对模式。allowlist 为白名单模式。open 为开放模式，需要显式配置到白名单。disabled 则完全忽略所有 DM。

pairing 是最稳妥的默认做法：未知用户发来消息时，系统会推送配对码并在 CLI 侧显示请求，只有管理员手动批准后才能交互。

5．安全加固基线配置

官方给出了一套 60 秒安全加固起步配置，实现最小权限。

{
  "gateway": {
    "mode": "local",
    "bind": "loopback",
    "auth": {
      "mode": "token",
      "token": "replace-with-long-random-token"
    }
  },
  "session": {
    "dmScope": "per-channel-peer"
  },
  "tools": {
    "profile": "messaging",
    "deny": [
      "group:automation",
      "group:runtime",
      "group:fs",
      "sessions_spawn",
      "sessions_send"
    ],
    "fs": { "workspaceOnly": true },
    "exec": { "security": "deny", "ask": "always" },
    "elevated": { "enabled": false }
  },
  "channels": {
    "whatsapp": {
      "dmPolicy": "pairing",
      "groups": {
        "*": { "requireMention": true }
      }
    }
  }
}

这套最小权限带来的效果是：Gateway 仅监听本地回环并强制 Token 认证；每个渠道与联系人组合拥有独立 DM 会话，避免上下文串漏；工具集收敛到消息类，自动化、运行时、文件系统均被禁用；Shell 执行被彻底禁止；WhatsApp DM 需配对，群组消息必须 @ 提及才触发，有效阻断未授权唤醒。

4.3.4 安全审计与应急响应

OpenClaw 内置自动化审计和标准化应急流程，帮助快速定位风险并处置。

1．内置安全审计命令

提供基础、深度、自动修复和结构化输出能力。

# 基础审计
openclaw security audit

# 深度审计，含实时 Gateway 探测
openclaw security audit --deep

# 自动修复可修问题如文件权限
openclaw security audit --fix

# 输出 JSON，便于 CI/CD 集成
openclaw security audit --json

审计范围覆盖：入站访问的 DM 策略、群组策略、白名单合理性；工具爆炸半径，评估权限提升是否会把提示词注入转为 Shell、文件或网络操作；网络暴露，检查 Gateway 绑定地址、认证配置、Tailscale Serve/Funnel 使用及令牌强度；浏览器控制暴露，审查远程节点、中继端口、远程 CDP 访问控制；本地磁盘卫生，检查关键文件权限、符号链接、配置包含关系及同步文件夹路径；插件是否在显式白名单；策略漂移与配置错误是否随时间产生。

2．安全事件应急响应步骤

怀疑受攻击或数据泄露时按以下流程处理。

遏制：立即执行 openclaw stop 停止 Gateway，切断所有外部渠道，防止扩散。

轮换：怀疑凭证泄露时立刻轮换所有 API Key 与认证令牌。

审计：查阅 ~/.openclaw/agents/*/sessions/*.jsonl 完整历史，还原事件期间 Agent 的操作并评估损失。

收集：完整保存相关日志与配置文件，为后续分析、复盘与合规提供证据。

4.4 定时任务（Cron）与自动化工作流

OpenClaw 不只是被动聊天，通过 Cron 系统可主动按计划触发 Agent Loop，形成端到端自动化，这是从聊天工具走向个人自动化平台的关键。

4.4.1 Cron 任务的工作原理

Cron 本质是预定的 Agent Loop 触发器，按时间点用指定初始消息启动一次会话。每个任务拥有独立 sessionKey，格式为 cron:<jobId>，历史与普通 DM 完全隔离。

在 openclaw.json 中静态定义的任务会在 Gateway 启动时自动注册。Agent 也可在对话中通过 cron 工具动态创建任务，动态任务会持久化，重启后依然有效。

Cron 采用标准五段式表达式，从左到右为分钟 0~59、小时 0~23、日 1~31、月 1~12、星期 0~6，0 代表周日。格式 * * * * *。

常用表达：
0 8 * * * 每天早上 8 点
0 8 * * 1-5 工作日早上 8 点
0 10 * * 1 每周一早上 10 点
0 0 1 * * 每月 1 日午夜
*/30 * * * * 每 30 分钟
0 9,12,18 * * * 每天 9 点、12 点、18 点

系统完整支持时区配置，可为每个任务单独指定 Asia/Shanghai、America/New_York 等，确保按本地时间触发。

4.4.2 构建实用的自动化工作流

Cron 的价值在于与工具调用结合形成闭环。

1．每日晨报自动化
定时 7 点工作日运行，调用 web_search 抓取科技新闻，web_fetch 获取 GitHub Trending，读取 MEMORY.md 中项目记录，整理为 Markdown 晨报，通过 message 工具推送到指定 WhatsApp 并归档到 memory/morning-brief-YYYYMMDD.md。

2．代码仓库健康检查
每周一 9 点运行，进入 ~/projects/my-app，执行 git log 统计近七天提交，npm audit 检出漏洞，npx depcheck 找未用依赖，grep 统计 TODO/FIXME/HACK 数量，生成健康报告，严重漏洞时通过 Slack 紧急通知 #security 频道，报告保存到 ~/reports/repo-health-YYYYMMDD.md。

3．智能备份与归档
每周日 2 点自动备份工作区与对话历史，同时清理过期文件，防止数据丢失并保持存储整洁。
