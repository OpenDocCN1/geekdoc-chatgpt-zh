## 2.3 让模型具备记忆：对话上下文的保留

人与人交流时会自动借助上下文来理解意图，这源于长期的语言经验和认知习惯。模型本身却不会自动保存历史对话，缺乏持续的全局语境理解能力。要解决这个问题，需要在应用层显式地把当前对话的上下文一并喂给模型。

启动之前写好的示例程序 prompt-stream.py，按先后顺序输入两条有关联的提问，如图 2-8 所示。从返回结果看，这两次交互被当作孤立事件处理。第二次提问时，模型完全调用不到第一次的信息，说明现有的交互方式缺少语境记忆，每轮都是独立的。

这种割裂式的对话在需要连续交流的场景里并不友好。如果目标是打造能连续对话并理解上下文的应用，就必须让对话在语境中延续。一种简单有效的做法是，每次提交新提示时，把历史对话一起提交。这样模型能拿到完整记录，便可依据上下文应答，大幅提升连贯性和理解度。

需要特别补充说明的是，在与模型交互时，向模型提交的信息与模型返回的信息均会计入此次对话的 token 消耗（token 是生成式 AI 模型输入输出的基本单位，1 个 token 大约相当 3/4 个英文单词或 1 个汉字，它也是服务商收费的计量单位）。因此，在一个会话过程中，若每次对话均携带全部历史对话数据，将导致后续对话消耗的 token 数量越来越多。

这不仅会增加成本，还可能超出模型允许的每次交互的最大 token 限制。为了在实际应用中有效利用上下文信息并同时考虑成本与 token 数量限制，需要采取一些策略应对这一问题。通常建议使用的方案如下。

- 1) 保留最近的若干次对话记录：可以选择性地保留最近的对话记录，而丢弃较早的对话。这种方法能够显著减少每次交互的 token 消耗，同时保持对话的连贯性和上下文相关性。

- 2) 文本概括：在保留最近对话记录的基础上，对较早的对话记录进行文本概括。通过这种方法，可以以更精炼的形式保留对话的关键内容，达到减少 token 消耗的目的。文本概括的实现在本章前文实例中已有涉及。

# 第3章 函数调用：为生成式AI搭建外接能力通道

自 OpenAI 发布 ChatGPT 以来，生成式模型如雨后春笋般涌现，给人们带来全新体验。从技术层面看，生成式 AI 的本质可概括为“推理”，这其实是一个概率挑选过程。正因如此，生成式 AI 并非万能，它在语言处理和生成方面很强，但在需要精确结果的数学计算等领域，依赖概率推理显然不可靠，同时也应看到模型的数学推理能力仍在持续提升。另外，像数据库查询这类操作，无论从安全还是技术复杂度来看，都不适合由模型直接完成。所以在实际应用中，对于模型难以胜任或必须保证结果准确性的场景，应用程序需要借助传统具备严格逻辑与过程控制的方式来实现，结合模型与传统系统的优势协同完成任务。在这种协作里，函数调用扮演关键桥梁。

使用函数调用既能弥补模型在数理计算方面的短板，也能发挥其在语言理解与生成上的优势。例如在需要复杂数据处理或精确计算时，可通过函数调用把任务交给专门的计算函数，同时利用模型识别和生成待调用函数的参数、并以自然语言与用户交互。这样既提升交互体验，也保证结果的可靠与准确，形成强强联合。

此外，函数调用还能实现系统的模块化与解耦，让各功能模块独立开发与优化。例如在一个数据分析系统里，生成式模型负责接收用户的自然语言查询并解析需求，而底层的计算函数负责实际的数据查询、处理与结果生成。通过这种方式，不同模块既能独立维护，又能通过明确接口紧密协作，形成高效可靠的整体。
