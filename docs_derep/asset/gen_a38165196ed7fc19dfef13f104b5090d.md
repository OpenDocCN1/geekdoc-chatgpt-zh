def MMA_Mixed_Precision（A_FP8, W_FP8, scal_A, scal_W, NC=128）:

  """

  使用混合精度（FP8 + FP32）进行矩阵乘法累加（MMA）操作

  参数：

  - A_FP8: 形式为 [M, K] 的 FP8 激活值矩阵

  - W_FP8: 形式为 [K, N] 的 FP8 权重矩阵

  - scal_A: A_FP8 的量化缩放因子，形式为 [M, K // NC]

  - scal_W: W_FP8 的量化缩放因子，形式为 [K // NC, N]

  - NC:量化分组大小，默认为 128。

  返回：

  - final_answer:高精度的 FP32 结果矩阵，形式为 [M, N]

  """

  import numpy as np

  #获取输入矩阵的形式

  M, K = A_FP8.shape

  K, N = W_FP8.shape

  #初始化最终结果矩阵

  final_answer = np.zeros（（M, N）, dtype=np.float32）

  #遍历 A 的行

  for i in range（M）:                #遍历 A 的每一行

    #遍历 W 的列，以 NC 为步长

    for j in range（0, N, NC）:          #遍历 W 的每一列，每次处理 NC 列

      #初始化累加器，形式为 [1, NC]

      D_fp32 = np.zeros（（1, NC）, dtype=np.float32）

      #遍历内部维度 K，以 NC 为步长

      for k in range（0, K, NC）:

        #提取 A 的当前块，形式为 [1, NC]

        A_block = A_FP8[i, k:k+NC]       #A_block 形式为 [1, NC]

        #提取 W 的当前块，形式为 [NC, NC]

        W_block = W_FP8[k:k+NC, j:j+NC]    #形式为 [NC, NC]

        #在 Tensor Core 上使用 FP8 计算矩阵乘法

        C_FP8 = np.dot（A_block, W_block）   #形式为 [1, NC]

        #提取对应的缩放因子

        scale_A = scal_A[i, k // NC]      #A 的缩放因子

        scale_W = scal_W[k // NC, j:j+NC]   #W 的缩放因子，形式为 [1, NC]

        #在 CUDA Core 中进行反量化

        D_fp32 += scale_A * scale_W * C_FP8  #累加到 D_fp32

      #将累加结果存储到最终答案矩阵

      final_answer[i, j:j+NC] = D_fp32

  #返回最终结果

  return final_answer

**3.Tensor Core 和 CUDA Core**

Tensor Core 与 CUDA Core 是 NVIDIA GPU 的两类计算单元，特性差异明显。

（1）CUDA Core 的特点

●高精度支持：主要承担标准 FP32 与 FP64 运算。
●数值更稳：科学计算、仿真等对精度敏感的任务可依赖其 FP32/FP64 得到更高保真度。
●通用灵活：除高精度外也能处理整数及 FP16 等低精度运算，强项仍在高精度域。

（2）Tensor Core 的特点

●面向混合精度：专为深度学习矩阵运算设计，典型模式为 FP16 输入、FP32 累加。
●精度相对有限：默认以较低精度做矩阵乘，再以 FP32 累积，深度学习可接受但不及 CUDA Core 的纯高精度。
●追求吞吐：以适度牺牲精度换取大规模矩阵运算的加速。

（3）精度对比总结

●CUDA Core：FP32、FP64 为主，适合保真度要求高的场景。
●Tensor Core：FP16 混合精度为主，速度更快，适合对精度容忍度较高的深度学习场景。

大模型训练里，数据质量决定上限，处理方式决定效率。DeepSeek 通过多阶段数据治理，将 14.8T 原始语料提炼为信息密度提升约 300% 的高质量训练集，其方法论已成行业参考。

### **9.1 预训练数据工程**

预训练阶段的数据采集与处理是关键。优质语料可显著提升模型表现，劣质语料则易导致训练失败或性能回退。核心步骤如下。

**9.1.1 预训练数据的一般处理流程**

预训练数据处理通常包括以下几个步骤。

（1）数据收集

1）从公开集、网络爬虫、合作伙伴采购等多源获取原始语料。
2）保证来源多样、覆盖面广，以适配模型的潜在应用场景。

（2）数据清洗

1）剔除乱码、重复、无关内容、人名等噪声。
2）补齐缺失值并修正异常值。

（3）数据去重

采用 SimHash、MinHash 等去重算法消除重复，避免过拟合。

（4）数据质量评估

借助人工标注或自动化工具检验准确性与一致性。

（5）数据格式化

转为模型可读格式，如 json、TFRecord 等。

（6）数据划分

拆分为训练集、验证集、测试集，用于训练与评测。

**9.1.2 数据去重的常见算法**

少量重复对语言模型伤害极大。常用去重方法有：

●**SimHash：**把文本映射为定长二进制向量，用汉明距离判断相似，适合海量文本。
●**MinHash：**基于集合相似度去重，适合中等规模。
●**Bloom Filter：**概率型结构，快速判断是否已出现，适合内存受限的大规模场景。
●**Deduplication via Clustering：**用 K-Means 等聚类后组内去重，适合按类别差异化处理。
●**Exact Matching：**精确字符串匹配去重，适合小规模或高精度需求。

**9.1.3 数据质量保障**

1.数据清洗
1）去除乱码、重复、无关内容等噪声。
2）处理缺失与异常。

2.数据标注
人工或自动化标注，保证准确一致。

3.数据验证
1）用统计或规则检查分布与完整性。
2）抽样人工复核。

4.数据多样性保证
来源多元，覆盖目标场景。

5.数据更新
定期迭代，保持时效与相关性。

**9.1.4 预训练数据的格式**

1.文本格式
txt 每行一个样本，简洁易存，适合初期通用语料。大规模时可压缩为 zst。

json 采用键值对，每个样本为对象，扩展性强，可记录来源、领域、语言、采集时间、质量分、许可等元信息。

2.序列化格式
TFRecord 为 TensorFlow 推荐的二进制格式，体积小、并行读取快，常用在 CV、NLP、语音、推荐等。

HDF5 支持层次化多维数据存储，可容纳数组、表格、图像等，适合复杂科学数据与多模态。

3.多模态格式
融合文本、图像、音频等，需跨模态索引如 modality_links 建立关联。例如图像字幕任务用 json 记录图像路径与描述，通过索引关联，广泛用于标注、视频理解、跨模态检索。

**9.1.5 DeepSeek 预训练数据的处理**

DeepSeek 系列在数据处理上持续演进。

1.DeepSeek V1 的数据处理
目标是提升丰富度与多样性。流程分去重、过滤、重混三阶段，使用 BBPE 分词。

（1）去重
采用跨数据集全局去重，对 Common Crawl 91 个分片全局去重比单片去重多移除约 4 倍重复。

（2）过滤
剔除低质内容，提升信息密度。

（3）重混
调整不平衡问题，增加代表性不足的数据，补充多样性。

（4）分词器
基于 Hugging Face Tokenizer 实现 BBPE。预分词避免不同字符类 Token 合并，数字拆分为单字符。词表 100000 个常规 Token 加 15 个特殊 Token，实际大小 102400。

2.DeepSeek V2 的数据处理
（1）预训练语料库
构建 8.1T Token 的高质量多源语料，中文比例与质量显著提升。
（2）监督微调数据
收集 150 万条对话，覆盖数学、代码、写作、推理、安全等。

3.DeepSeek V3 的数据处理
（1）语料库优化
提升数学与编程样本占比，扩展多语言覆盖至英文、中文及更多语言。
（2）数据处理管道改进
在保持多样性的同时降低冗余，引入文档打包提升完整性，训练时未使用跨样本注意力掩码。
（3）预训练语料规模
14.8 万亿 Token，质量与多样性进一步提高。
