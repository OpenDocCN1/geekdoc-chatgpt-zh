# RAG 实战通关：从零搭建可控可优化的智能问答系统

## 本书概览

当大模型已成为智能系统的主引擎，检索增强生成技术正是用来补齐模型先天知识盲区、提升回答可靠性的关键方案。本书以 RAG 完整生命周期为主线，把系统架构与工程落地路径拆解清楚，帮助开发者和企业打造实用、稳定、可持续迭代的智能问答能力。

全书先以数据接入、文本切分、向量化、向量存储这条主线来讲透多源文档加载到结构化预处理的全过程，并深入讨论嵌入模型的挑选、微调策略以及多模态扩展；再从检索前的问句构建、问句改写、路由分发、索引调优，到检索后的重排与压缩，系统讲解召回质量与相关性提升的手法；随后介绍多种生成策略以及一套可落地的 RAG 评估体系；最后聚焦前沿范式，梳理 GraphRAG、模块化 RAG、Agent 化 RAG 和多模态 RAG 的构建思路。

适合 AI 研发工程师、企业技术负责人、知识管理从业者，以及对 RAG 构建感兴趣的高校师生阅读。无论是想快速搭起原型，还是追求检索性能的精细化优化，或是探索下一代 AI 系统架构，本书都能提供方法论与实操参考。

我的判断是抓住两条主线。

第一条是借助大模型的逻辑与工具调用能力，在业务与产品各层构建具有代理性的应用。可参考《大模型应用开发 动手做 AI Agent》中提到的 Agent 演进五层级。A2A 协议的到来为此注入新动能，通过 Agent Card、任务管理与消息传递等标准，让异构智能体协同工作并动态协商交互。

第二条是做好大模型时代的知识检索。通俗讲，大模型像一颗汇聚人类智慧的水晶球，但获取知识有门槛。如何在特定时间、场景、企业需求下快速精准地调取所需知识，是应用开发的核心命题。

以大模型进行知识检索的复杂度跨度很大，从简单的提示词对话到万亿参数的训练微调，只要通过大模型获取知识，就属于大模型应用开发。随着需求提升，技术会逐步从简单走向复杂。

在这条演进路径上，提示工程、检索增强生成 RAG、模型微调构成三大阶段。提示工程对模型改动小，主要依赖模型本身；微调则需要额外训练，对技术与成本要求更高。RAG 在两者之间取得平衡，对模型改动有限，目前处于技术演进的核心位置，如图1所示。

### 突破：RAG 驱动的知识扩展

当应用需要接入大量外部知识时，RAG 成为关键。它融合信息检索与生成式 AI，通过从外部知识库检索相关信息来增强大模型的生成能力，提升上下文相关性与回答准确性。

RAG 的核心在于，模型不再仅依赖训练时“记住”的知识作答，而是能访问外部文档集，检索与问题相关的片段，将最新或领域专属信息纳入思考过程后再生成答案。换句话说，RAG 让模型学会“查资料”，把静态、受训时间限制的语言模型转变为可动态获取信息、实时扩展知识的智能体。从闭卷变开卷，对应用效果的提升非常明显。

RAG 的核心组件包括知识嵌入、检索器和生成器。

- **知识嵌入**：读取外部知识库并切块，通过嵌入模型转化为向量表示，在高维语义空间中可比较。向量与原始文本一起索引到向量数据库，以支持高效检索。
- **检索器**：从向量化的知识库中查找与用户输入相关的信息，通过语义相似度快速匹配。常用方法有稀疏向量的 BM25 和密集向量的近似最近邻检索。
- **生成器**：基于检索结果生成上下文相关的答案，通常由大模型完成，并融合外部知识以保证流畅与可信。

从执行流程看，RAG 可细分为十个阶段：

- 数据导入：将多格式文档、数据库与文件加载入系统；
- 文本分块：把大文档切分为易处理的小块；
- 信息嵌入：为每个块生成语义向量；
- 向量存储：保存嵌入向量及关联原文，常用 Milvus、Pinecone 等；
- 检索前处理：对查询做扩展或语义重构，提升精度；
- 基于索引的检索：依据构建时的索引从向量库查找最相关文档；
- 检索后处理：清洗、排序或格式化检索结果；
- 响应生成：基于用户输入与检索结果生成最终答案；
- 系统评估：评估准确性、一致性与覆盖率；
- 复杂检索策略与范式：结合知识图谱、自主代理、多轮检索或多源检索等优化整体性能。

RAG 弥补了大模型仅靠参数记忆的不足，使其在变化或高度专业化问题上更具适应性与灵活性。它提升了回答的准确性、时效性与权威性，为垂直领域落地提供了坚实基础，如图4。
