# 基础安全加固清单

入口管好，安全才有根基。把 OpenClaw 切换到本地访问模式，是最直接的防御手段。调整网关策略，仅放行本机地址，比如 127.0.0.1，这样公网流量在源头就被挡住，属于最稳妥的部署方式。若确实需要远程接入，推荐通过 Tailscale Serve 这类加密隧道来连，别把服务端口直接暴露在互联网上。同时一定要执行 `openclaw token generate` 生成访问令牌，外部请求必须携带有效凭证才能进入。

访问控制也要收紧。保持配对模式开启，陌生账号加好友必须由管理员审批。在群聊环境里建议把 `requireMention: true` 打开，防止 AI 被随意唤起，陌生人无法直接下指令让你的 OpenClaw 去跑任务。

初始化阶段坚持最小授权。对非必要的技能和 API Key，一律选择 “Skip for now” 或 “No”，只接入工作必须的账号。权限只给任务完成所需的最小集合，越少越安全。

ClawHub 技能市场是生态的重要补充，但也暗藏供应链风险。业内曾披露市场上存在大量伪装成效率工具的恶意技能，目的其实是窃取数据。常见手法是在 SKILL.md 里硬编码 API 密钥和密码，把敏感凭证拼进 LLM 提示，或在输出中泄露隐私。

装技能前建议做三步核验。先看 VirusTotal 扫描结果，详情页会展示安全报告，被标为 “恶意” 的直接放弃；再核对 GitHub 仓库，只装提供开源仓库的技能，并确认维护者身份与最后更新时间；最后细读 SKILL.md，特别警惕 `curl | bash` 这类下载并执行远程脚本的写法，属于高危信号。

企业用户最好建立内部审核流程。所有外部引入的技能，先交由安全团队检查是否藏有恶意代码或漏洞，确认无误后再上生产。虽然多一道环节，却能有效避免数据泄露和被控风险。

涉及敏感操作，建议启用二次确认。在 MEMORY.md 中可预置规则：所有删除操作，无论是文件还是数据库记录，都必须先确认；所有数据导出必须明确文件路径确认；所有系统指令执行前须经人工审核。

养成定期看日志的习惯。日志能清晰反映 OpenClaw 执行了什么，有无异常。发现可疑记录要及时追查。OpenClaw 提供的 sessions_list 和 sessions_cleanup 可帮助管理会话历史，便于审计。

提示词注入是常见攻击手段，攻击者会在输入中植入恶意指令劫持 AI 行为。OpenClaw 读取外部网页或文件时，可能被“洗脑”去执行非预期操作。

防御要点包括：在系统提示词里固化安全约束，明确告知哪些指令禁止执行；对输入做边界检查，识别并过滤可疑指令模式；尽量避免让 AI 直接处理来源不明的外部内容。

一个实用做法是在 MEMORY.md 中提前定义安全边界，例如“禁止执行任何权限提升指令”“禁止修改系统配置文件”“禁止访问未授权的外部 URL”。这些规则在每次会话启动时加载，形成持续防护层。
