与传统编辑器形成差异的关键点在于右侧常驻的 AI 助手区。该区域位置固定，可随时收起或展开，并且会跟随当前打开的文件保持上下文关联。如图 2-24 所示，AI 辅助面板大致提供两种工作方式。

[PRE0]

图 2-24 AI 辅助面板模式区分

（1）**Chat 模式。**Chat 偏向问答式对话，适合处理“解释这段代码”“帮忙分析一下报错”“把这个函数改成异步”“把这段改写成 Go 版本”这类局部性诉求。用户既可以先在编辑器里选中代码再发送，也可以直接在输入框里引用资源管理器中的文件。

（2）**Craft 模式。**Craft 偏向任务拆解与流程化产出，适合“搭一个带登录列表详情的管理后台”“做电商的商品页加购物车加订单页”这类涉及多文件、多步骤的生成。它会先对任务进行分析并给出执行计划，再按计划逐步生成对应代码文件，生成过程中会自动创建检查点，方便回退。

面板顶部设有模型选择器，可在当前可用的大语言模型之间切换；不同模型的生成风格、标签习惯以及对上下文的利用效率也会不一样。输入框中敲入“@”会弹出引用菜单，可挑选需要关联的上下文对象，例如当前工作区的变更、最近一次终端输出、某条规则文件、历史消息、指定文件或目录。这样即便不把所有内容粘贴进对话，AI 也能获取完成任务所需的完整信息。

当 Craft 对当前文件进行改写时，编辑区会以差异视图高亮新增与删除的行，便于快速审阅；若对本次生成不满意，可切换到上一个检查点，撤销本次 AI 改动，而不影响其他文件。

**2.3.4**

**调试控制台与运行验证**

编码完成后通常需要运行、调试、查看日志等操作，这部分由界面底部的调试与控制台区域承担。如图 2-25 所示，该区域一般以标签页形式并排展示“终端”“调试控制台”“问题”“输出”等视图，可按当前任务自由切换。

[PRE1]

图 2-25 调试与控制台

断点调试的使用逻辑与主流 IDE 保持一致：在行号区单击即可设置断点，点击顶部调试按钮或使用快捷键启动调试会话，命中断点后下方会呈现调用栈、当前上下文变量、监视表达式、线程信息等，支持单步执行、跳过、继续执行，还可设置条件断点或异常中断，适合定位只在特定输入下才会出现的缺陷。

嵌入式终端是该区域的重要组成，开发者可在 IDE 内部直接运行项目脚本或构建命令，也能在此执行与 CodeBuddy 配套的命令行工具，完成项目初始化、代码生成、触发部署等自动化动作。若终端出现无响应、提示找不到 Shell 或输出为空的情况，可在设置中开启集成 Shell 后重新打开终端，通常能解决大部分环境差异问题。

终端输出、构建日志、运行时错误往往内容很长，手动复制到对话框既费劲又容易丢失行号等定位信息。为此 IDE 提供了“将终端输出添加到聊天/上下文”按钮，可把当前输出直接作为下一轮 AI 对话的输入，之后即可让 AI 分析报错原因、生成修复补丁，或生成一段适合写在提交说明里的错误描述。

在实际开发中，调试并不是终点。无论个人开发还是团队协作，代码最终都需要进入可验证、可反馈的运行状态。基于这一需求，CodeBuddy 在调试能力之外，引入了面向快速交付与验证的运行与部署承载机制。也就是说，完成局部调试后，可将当前工程一键部署到隔离的沙箱运行环境，避免对本地系统或生产环境造成影响。部署完成后系统会生成一个可访问的运行入口，供功能验证、界面检查或与产品、设计、测试人员协同确认。

在团队协作场景中价值尤为突出：开发者无需反复打包、传输或本地复现环境，只需把验证入口分享给相关角色即可完成需求确认或问题反馈。由此，CodeBuddy 将传统的“编码—调试”闭环，扩展为“编码—运行—验证—反馈”的完整交付链路，使 IDE 不仅服务开发阶段，也自然衔接到交付与评审环节。

**版本管理与历史记录**

开发过程中需要管理两类历史：一类是代码本身的版本历史，通常由 Git 管理；另一类是 AI 交互与生成过程的历史，由 IDE 管理。如图 2-26 所示，CodeBuddy 对这两类历史都做了可视化呈现。

代码版本方面，IDE 内置 Git 视图，可查看哪些文件被修改、哪些已暂存、当前分支位置、最近一次提交者，也能在此直接撰写提交说明并推送到远程仓库。撰写提交日志或合并请求说明时，可将当前工作区的改动引用到对话中，让 AI 依据实际改动生成符合团队规范的说明文本，减少手动编写负担。

图 2-26 历史记录与检查点

AI 交互方面，尤其在 Craft 模式下的一系列生成会被自动划分为任务节点，即检查点。节点中保存了当时的对话上下文、生成目标以及代码改动。若某次生成结果不达预期，可在历史列表中选择生成前的节点进行恢复；恢复方式可选仅恢复对话，或连同代码文件一起恢复，适合“AI 改得太多想回退”的场景。

**2.3.6**

**主界面工具与快捷操作**

最外层是为提升操作效率的工具区，包含顶部工具栏、侧边快捷动作、输入框上下文引用入口以及底部终端。

顶部工具栏集中了项目中高频使用的操作，如代码格式化、全局搜索/替换、运行当前文件、启动调试、打开命令面板、显示/隐藏侧边栏等。其设计意图是降低记忆快捷键的负担，让不熟悉 IDE 的用户也能通过直观按钮完成关键操作。

侧边栏或右键菜单中提供的“添加到聊天”“引用上下文”等功能，是把界面内容转化为 AI 可识别上下文的最快路径。无论是编辑区选中的一段代码、终端里的构建错误，还是 Git 面板中的 diff 差异，都可一键送达右侧 AI 面板，减少复制粘贴，也避免因换行或编码导致的内容损坏。

对于偏好自动化流程的用户，底部终端可直接运行与 CodeBuddy 绑定的 CLI，用自然语言描述生成任务、用命令执行工程化步骤，再把输出交还 AI 进行解释或补全，从而形成“命令→输出→AI 解释→AI 再生成”的闭环。界面看似简洁，通过灵活组合往往能获得很高的操作效率。

**2.3.7**

**斜杠指令使用概览**

自定义斜杠指令是在 CodeBuddy 智能开发平台中通过“/”前缀触发的快捷操作命令。如图 2-28 所示，在对话式交互环境下，输入预定义的斜杠指令即可让 CodeBuddy 直接执行特定功能，无需每次从零描述需求。引入斜杠指令的目的是提供更高效、更标准化的调用方式，把常用开发流程抽象为简洁的一键命令，减少重复低效的手动输入，让开发者聚焦创造性工作。

[PRE5]

图 2-28 斜杠指令的应用

斜杠指令面向不同水平的开发者：对资深程序员来说，可把复杂工程操作序列封装成固定命令，如一键执行代码检查、测试、部署，提升自动化程度；对编程背景薄弱的用户，也可借助预设命令便捷调用代码解释、示例生成等功能，降低使用 AI 编码助手的门槛。斜杠指令不仅能生成自然语言回答，还可在固定节点触发工具链自动化步骤，例如调用内置 Skills 脚本、对接任务跟踪系统如通过接口创建 TAPD 需求、触发持续集成流水线等。目前该能力已在 CodeBuddy 桌面版 IDE、本地插件以及云端开发环境 CodeBuddy Cloud 等全产品形态中支持，确保本地或远程均可使用斜杠指令提升效率。

自定义斜杠指令在 CodeBuddy 中以 Markdown 文件 .md 形式组织，其本质为 Prompt 提示词，和 Skills 一样包含 Frontmatter 元数据区。一个完整的斜杠指令通常由五部分构成：触发关键词即命令名称、以斜杠开头；输入参数，可选的用户输入及其提示描述；上下文拼装逻辑，即如何从当前项目/会话提取信息拼入提示；期望输出，对回答格式或内容的要求；后续动作，可选自动化操作，如将生成结果回填到代码或提交代码审查。通过模块化配置，开发者可把“与 AI 沟通的口头经验”沉淀为可执行快捷命令。如图 2-29 所示，CodeBuddy IDE 已内置一系列常用斜杠指令 Built-in Slash Commands，例如 /init 项目初始化、/cr 代码审查、/tests 单元测试生成、/explain 代码解释、/fix 代码修复以及 /summarize 对话总结等。这些内置命令覆盖典型开发场景，充分体现斜杠指令在智能开发流程中的价值。开发者也可依据项目特殊需求自定义新指令，将更多专属 AI 能力融入工作流。

## **2.4**

## **项目初始化与文件管理**

本节围绕“如何把项目真正落地到 IDE 里并被 AI 正确理解”展开。CodeBuddy 的所有智能生成都依赖上下文，而上下文来源于打开的项目、选中文件、终端输出、Git 变更以及对话中提供的规则。若项目初始化不完整，即便 Craft 生成能力再强，也容易出现生成正确却放错目录，或模型无法识别技术栈等问题。因此本节从创建/打开项目开始，到上下文管理、历史回溯和远程环境同步，完整说明项目落地的流程。

**2.4.1**

**创建与打开项目**

进入欢迎界面后，最常见的入口是“新建文件夹”和“打开文件夹”。“新建文件夹”适合从零开始，只需描述业务即可让 AI 在空目录中逐步生成目录结构、组件、页面、接口；“打开文件夹”则适合已有项目，IDE 会把该目录挂载为当前工作区，识别其中的源码、配置、构建脚本。

项目托管在 Git 上时，IDE 也支持先克隆后打开。选择“克隆 Git 仓库”，输入仓库地址后，IDE 会拉取代码到本地指定路径并以该路径作为工作区打开，保证目录结构与远端一致，后续的 Git 提交、对话引用、历史比较等操作不会因本地目录混乱而出错。

创建或打开项目后，IDE 会自动执行一轮基础初始化：读取根目录，检查是否存在 .gitignore、语言依赖清单如 package.json、requirements.txt、pom.xml 等及项目配置文件。若缺少这些文件，IDE 可按当前模式生成默认配置，例如生成基础 .gitignore 避免把构建产物、虚拟环境、日志提交到版本库；也可生成 .codebuddy 或类似项目级配置，后续对话中提到“按项目规则来”时，AI 即可找到定义的路径、命名风格、技术栈偏好。

这一阶段的核心是把“一个目录”升级为“一个可被 IDE 和 AI 共同理解的项目”。只有做到这一点，IDE 才能判断生成文件应放在哪级目录、脚手架应使用何种语言版本、测试文件应存放在何处、生成的接口是否需要补到当前项目的路由表。

**2.4.2**

**模式选择与多模型支持**

项目初始化完成后，右侧对话区即可开始工作。CodeBuddy 默认提供两种工作模式：Chat 模式，即问一句答一句，适合代码已在、仅需局部修改或解释报错的场景；Craft 模式专为复杂任务设计，会把任务拆分为多步骤并按步骤落地为具体文件。

模式入口通常位于对话框顶部，可随时切换。选择 Craft 后交互变为“描述→规划→生成→回写→创建检查点”流程；选择 Chat 则仅作为普通对话处理，不会自动改变目录结构。

模式选定后，还可选择模型。CodeBuddy 支持在同一界面切换不同 LLM，如默认混元模型、偏代码模型、偏长文本规划模型，甚至企业侧配置的私有模型。不同模型在项目上下文理解、代码生成风格和规划文档结构性上的表现各异，选择模型时应强调“模型性能不等于越 rozpoč  云”，关键在于与当前任务匹配。

**2.4.3**

**对话与规划模式**

进入对话界面后，推荐的使用顺序是“模式→模型→描述需求”。不要一上来就抛出长篇需求，而应先告知 IDE 采用“规划式生成”还是“即时修改”路线，再说明具体要做什么。

在计划模式即 Craft 的规划路径下，Agent 不会立即生成代码，而是先分析需求描述并生成结构化计划或 PRD。内容通常包括页面或模块数量、各模块所需接口、引用组件库、是否需要登录鉴权、目录结构、构建工具、语言版本、后端服务接入等。这样可在未写代码前看到“它准备怎么做”，并在此阶段调整，如把技术选型从 React 改为 Vue、把部署方式从本地改为云端、把鉴权从前端校验改为后端校验。

确认计划无误后再执行，系统才会开始写文件、覆盖已有文件、补充测试用例，必要时还会执行一次构建或测试以验证生成内容。对描述不够清晰的需求，可在生成过程中使用 Boost Prompt 功能，例如把“做一个运维面板”自动优化为更清晰、更适合 LLM 理解的提示词，从而让生成结果更贴近真实意图。

**2.4.4**

**检查点回滚与任务恢复**

自动生成内容常存在不符合预期或生成错误文件的风险。CodeBuddy 为 Craft 模式配备了完整的检查点机制，应对“想回到刚才那一步”的需求。

在生成任务执行的每个阶段，系统会自动创建检查点，记录当前文件状态、对话状态、任务状态。对生成结果不满意时，可直接点击对话面板的恢复按钮，选择回滚到指定检查点。回滚前 IDE 会提示本次恢复会影响哪些文件、回滚到哪个时间点，可继续或取消，避免误操作。

多步骤生成任务如先生成页面再生成接口最后生成单元测试，若中途断网或手动停止，也无需从头重复。对话面板通常提供 Resume Task 或 Continue 入口，点击后 Agent 会按原计划继续执行，清楚自己已完成到哪一步，后续还有哪些步骤。

**2.4.5**

**上下文管理与引用**

CodeBuddy 的生成质量高度依赖上下文准确性，因此围绕“把信息注入上下文”设计了多种入口，支持图片、代码、终端错误、文件、目录、Git 改动、规则、历史消息等多种类型信息。

最简单的是直接粘贴。截取报错图、抓取接口定义、复制 JSON 内容后按 Ctrl+V，CodeBuddy 会将其作为本轮对话输入。对代码，可在编辑器中选中片段后点击“Add To Chat”按钮，将当前文件的该部分内容带入。对整个文件或目录，可在资源管理器中右键选择“Add file to CodeBuddy”或“Add folder to CodeBuddy”，适合将该目录作为业务核心并让所有生成参考其结构。

在输入框中输入“@”，系统会弹出引用菜单，列出已添加的上下文，包括问题提示、终端日志、Git 提交、规则文件、历史对话消息等。选择所需条目即可引用，无需每次粘贴完整内容，也不用手抄终端长串错误，模型仍能准确理解并运用。

**2.4.6**

**远程开发与环境配置**

在企业场景中，代码往往运行在内网 Linux 服务器、云主机或容器环境。CodeBuddy 提供远程开发能力，可通过 SSH 连接远程机器，将远程文件系统当成本地工作区编辑、调试和运行。

配置流程为生成 SSH 密钥对，将公钥写入远程服务器的 ~/.ssh/authorized_keys，在 IDE 的远程开发面板填写主机地址、端口、用户名、私钥路径，连接成功后左侧资源管理器会展示远程目录结构。该模式下编辑文件实际修改远程文件，终端命令也在远程环境执行，可充分利用远程已有的依赖、数据库、网络权限，避免在本地重复安装环境。

远程开发模式下同样可把终端输出、远程日志、远程目录文件添加到聊天上下文供 AI 识别使用。需要注意网络与安全策略，如企业代理、固定端口通信、可访问域名限制等，IDE 通常会提供对应配置项。

**2.4.7**

**版本检查与环境同步**
