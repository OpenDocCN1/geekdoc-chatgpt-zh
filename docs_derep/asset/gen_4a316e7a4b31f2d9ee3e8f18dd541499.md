#### 8.1.2 LangChain 应用开发框架概览
LangChain 由 LangChain AI 公司开源，定位是一个面向大语言模型驱动应用开发的框架。其核心理念是通过一套标准化、结构化的模块抽象，对大模型的输入输出进行统一规范，从而实现可组合、可插拔的开发流程。框架以“Chain”为核心，强调链式组织模型调用、上下文管理、工具执行、内容解析等操作，帮助开发者从数据输入到智能响应搭建完整路径。

本质上，LangChain 始终围绕大模型能力展开，结合实践经验与典型任务，对模型的涌现能力做高级抽象，并用统一接口适配多种底层模型服务，形成通用的大模型应用开发范式。

目前 LangChain 已发展为通用性极强的大模型应用开发体系，其抽象的核心模块如图8.4所示。
[PRE9]
图8.4 LangChain 核心模块

##### 1. Prompt
Prompt 是大模型应用的起点。LangChain 的 PromptTemplate 提供了标准化的提示模板定义方式。开发者可自定义输入变量，为模型注入精确的背景与任务说明；模板结构化封装也支持变量插值、输入校验与复用，实现参数化生成动态提示。

##### 2. Models
Models 模块对主流大语言模型做封装，提供统一调用接口。只需配置模型信息，即可在不改动业务逻辑的情况下切换底层模型。

##### 3. Output Parser
大模型通常输出自然语言，而工程里往往需要 JSON、列表、表格、代码块等结构化结果。Output Parser 模块专门解决这一问题。LangChain 内置字符串解析器、列表提取器、Pydantic 校验器等，可规范每一步输出，提升链式调用的鲁棒性。

##### 4. Memory
Memory 模块为对话场景提供多轮上下文记忆能力，区分短期与长期记忆，支持用户历史与模型输出的存储与复用。

##### 5. Callbacks
Callbacks 提供事件监听机制，可对调用链路的每一步进行监控、调试与可视化，日志可输出到终端、文件或接入可观测平台，实现执行路径全追踪。

##### 6. RAG
LangChain 对 RAG 做了深度封装，涵盖 Retriever 构建、向量数据库集成如 Chroma、FAISS、Milvus、上下文压缩与匹配度过滤等标准化组件，可按需组合快速搭建语义检索增强链。

##### 7. Agent
Agent 模块是实现复杂任务自动执行的引擎，允许大模型以工具调用者身份动态决定是否调用外部工具、API 或其他链。LangChain 提供了多种内置 Agent 类型，支持任务自动分解与执行。

这七个模块如同积木，各自职责明确，又能灵活组合，图8.4 所示的体系既可实现基础问答，也能构建具备记忆、知识增强、结构化输出与多工具协作的高级 Agent。

#### 8.1.3 LangChain 高阶 RAG 构建实践
在 BiliAgent 的数据分析场景中，需要借助 LangChain 完成大模型接入与 RAG 流程搭建，如同搭积木，每一块都是 Agent 系统运转的基础。

如图8.5所示，RAG 的运行逻辑是把用户查询作为检索器的输入，在持久化的知识库 Knowledge 中定位高度相关的信息片段，再把检索结果作为上下文注入 LLM 的 Prompt，引导模型给出更准确、更相关的回答。
[PRE10]
换句话说，RAG 本质上是用外部知识补充 LLM 能力的一种增强技术。宏观来看，大语言模型虽具备强大的语言理解与推理能力，但受限于“知识封闭性”，只能基于训练时的数据推理，难以应对特定领域与实时信息。为让模型能够实时访问私有数据、动态引入背景信息，必须构建信息流通机制，把高质量外部知识按需引入推理流程，这正是 RAG 架构诞生的初衷。其核心流程如图8.6所示。
[PRE11]
如图8.6所示，RAG 构建主要包含：

- **索引（Index）**：离线执行的初始步骤。先清洗并抽取原始数据，将 PDF、HTML、Word 等转为标准化纯文本；再按上下文约束进行分块；随后用嵌入模型转为向量表示，最后建立键值索引以支持高效可扩展搜索。

- **检索（Retrieval）**：用户查询经编码模型生成语义嵌入后，在向量数据库中进行相似性搜索，取出前 k 个最接近的对象。

- **生成（Generation）**：把用户查询与检索到的上下文填充到提示模板，再输入 LLM 生成最终响应。

LangChain 封装让标准流程实现更简便，但仅复刻标准 RAG 在复杂任务中往往效果有限，因此优化至关重要。图8.7 展示了 LangChain 已封装的高阶 RAG 方案。

##### 1. 翻译查询
自然语言问题常语义复杂、表达不规范，直接检索效果受限。LangChain 提供输入问题翻译机制，支持多查询生成等价表述以增强召回、RAG 融合聚合不同表述的检索结果、分解将复合问题拆解为子问题等策略，提升查询与知识的语义对齐度。

##### 2. 路由
路由根据问题类型或语义特征选择合适的检索路径与提示模板，包含：

- **逻辑路由**：基于问题结构挑选数据库或查询方式；
- **语义路由**：将问题嵌入向量空间，按语义相似度匹配 Prompt 结构。

##### 3. 数据库的支持
高级 RAG 流程支持三种底层数据库：图数据库、关系型数据库和向量数据库。
[PRE12]

##### 4. 构建查询
面对自然语言问题时，系统会按目标数据库类型构建结构化查询指令。

- **关系型数据库**：通过 Text-to-SQL 把自然语言转为 SQL，并结合向量检索增强；
- **图数据库**：采用 Text-to-Cypher 生成 Cypher 语句，从知识图谱抓取语义关联；
- **向量数据库**：使用 Self-query retriever 从问题中抽取检索意图与元数据过滤条件，生成向量检索请求。

##### 5. 索引
高质量检索依赖优秀索引。LangChain 引入：

- **块优化**：按字符、段落、语义断点切分，提升嵌入效果；
- **多表示索引**：如 Parent+Summary+Dense 向量结构，使检索更全面；
- **专业嵌入**：结合微调或 ColBERT 等模型生成领域更精准的向量；
- **层级索引**：如 RAPTOR，构建跨层级多抽象层的文档树，实现摘要层级的高效索引。

##### 6. 检索
路由确定后进入信息检索：

- **排名**：对候选文档做语义打分排序，方法包括 Re-Rank、RankGPT、RAG-Fusion 等；
- **细化**：初轮结果不理想时执行再检索或检索压缩；
- **主动检索**：基于初轮回答质量自动判断是否重写问题并重新检索。

##### 7. 生成
检索到文档后，LLM 融合原始问题与增强上下文生成答案。LangChain 在生成阶段引入 Self-RAG / RRR 优化，主动判断问题理解是否正确、信息是否充分，从而触发再次检索与反馈。
