### 3.4 代理

代理的核心在于把语言模型当作决策引擎来用，能在运行时动态挑选并排序一系列行动。与链式结构里行动顺序被写死在代码中的做法不同，代理依靠模型的推理能力判断该执行哪些动作以及执行的先后顺序。设计代理时需要厘清几个关键角色：代理本身作为执行主体，代理执行器负责落地代理的决定，工具是代理可调用的操作单元，工具包则是一组协作工具的集合。这几部分共同构成代理的基础架构，帮助它在复杂环境中做出智能决策并完成任务。

#### 3.4.1 核心思想

在 LangChain 里，代理和链是互补的关系，但二者的根本差异很明显：链的步骤在代码中预先固定，而代理让语言模型担任推理引擎，根据上下文动态决定下一步做什么、怎么做。这种设计让代理能够依据当前情境和过往结果灵活调整行为，表现更智能。

实现上涉及以下核心要素。

- (1) AgentAction：数据类，用来描述代理打算执行的动作。包含 tool 用来指明调用的工具名称，tool_input 用来提供该工具的输入参数。
- (2) AgentFinish：表示代理进入终态，准备把结果返回给用户。通常包含 return_values 映射，其中一般有 output 键，对应返回给用户的响应文本。
- (3) 中间步骤：记录代理之前已执行的动作及其产出，以便在后续迭代中保持记忆。其类型为 List[Tuple[AgentAction, Any]]，observation 现阶段保留为 Any 以保证灵活性，实践中多为字符串。

Agent 类负责判定下一步动作，通常依赖语言模型、提示模板和输出解析器。不同场景下可能需要不同的提示风格、输入编码方式和输出解析策略，LangChain 既支持定制代理，也提供多种内置类型供扩展。

代理的输入是一个键值映射，其中必需的键是 intermediate_steps，对应上述中间步骤。一般由 PromptTemplate 把键值对转成适合 LLM 的格式。代理的输出则是下一个待执行的动作，或最终发给用户的响应，即 AgentAction 或 AgentFinish。

AgentExecutor 是代理的运行环境，负责调用代理、执行其选择的动作、把结果反馈给代理并进入下一轮迭代。表面看流程简单，但它替开发者处理了大量细节，比如工具不存在、工具执行失败、输出无法解析为工具调用等，同时在代理决策和工具调用各层级提供日志与可观测性。

#### 3.4.1 代理的执行过程

图3-4展示了代理的典型执行流程。观察阶段，代理通过输入接口接收外部触发，如用户提问或系统请求，并解析提取关键信息作为后续依据。随后进入思考阶段，利用预设规则、知识库或机器学习模型分析观察到的信息，判断如何响应，可能包括理解用户意图、推断所需工具及提取运行参数等子步骤。最后是行动阶段，基于思考结果执行具体动作，涵盖参数填充、工具调用、生成响应并输出给用户或系统等。LangChain 将整套流程高效实现，让代理能以高度智能的方式处理各类情况。

#### 3.4.2 代理类型

按 LangChain 的划分，代理可依据预期模型类型、是否支持聊天历史、是否支持多输入工具、是否支持并行函数调用等特征来挑选。比如 OpenAI Tools 代理兼容聊天模型，能处理聊天历史、多输入工具及并行函数调用，适合使用最新 OpenAI 模型的场景；而 XML 代理则更适合擅长 XML 格式的 Anthropic 等模型。选择取决于应用需求、模型能力与任务复杂度等多重因素。

选型时应综合考虑模型能力、任务复杂度、效率要求、可用工具和定制需求。若任务需要支持聊天历史的多轮交互，OpenAI Tools 这类代理更合适；若效率至关重要，可优先考虑支持并行函数调用的代理以加快处理；也需根据输出格式需求挑选支持 XML 或 JSON 的代理，或按工具特性挑选支持多输入的代理。充分了解各类代理的特性和适用场景，有助于做出更明智的选择。

例如搭建客服聊天机器人时，目标是理解用户查询并给出有用反馈。此时代理需要保留聊天历史以把握上下文，OpenAI Tools 代理就很匹配，它不仅支持聊天历史，还能使用多输入工具并行调用，提升效率。配合最新的 OpenAI 模型，机器人可以理解复杂提问，并借助外部工具如数据库查询给出准确答案。

再如内容生成工具，比如自动撰写新闻稿或代码注释，可能倾向于使用擅长特定格式的代理。若需要生成结构化 XML 数据，XML 代理更合适，因为 Anthropic 等模型能直接以 XML 格式理解和生成内容，从而提高准确性和效率。

在数据分析和报告场景中，可能需要代理整理、汇总数据后生成报告。此时 Structured Chat 代理是不错的选择，它支持多输入工具，可同时调用数据查询与数据处理工具，再把结果整合成易读的报告。并行函数调用特性还能加快数据处理与报告生成的速度。

#### 3.4.3 工具

在 LangChain 框架里，工具是构建智能代理不可或缺的部分，它让代理能够与外部世界交互。工具的设计思路是提供清晰的接口，使代理可以执行特定操作或访问特定服务。每个工具通常包含以下要素。

- 1. 工具名称：唯一标识，便于在代理中引用。
- 2. 工具描述：简要说明功能与用途，帮助理解其作用。
- 3. 工具输入的 JSON 模式：定义期望的输入格式，确保参数结构符合预期。
- 4. 调用的函数：指定被触发时应执行的函数或操作。
- 5. 结果处理方式：标明执行结果是否直接返回给用户。

这些要素构成工具的基本框架，使代理在决策时能精确指定并执行动作。简洁的输入有助于大语言模型更高效地使用工具，而清晰的名称、描述和 JSON 模式则确保模型准确理解和调用。
