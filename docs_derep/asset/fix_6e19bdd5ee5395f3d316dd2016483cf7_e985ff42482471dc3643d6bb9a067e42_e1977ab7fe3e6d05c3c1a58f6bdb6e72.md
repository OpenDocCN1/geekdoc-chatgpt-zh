Ubuntu 使用评估

版本迭代节奏较快：Ubuntu 大约每半年推送一个新版，能让用户比较早地接触到新软件和新功能。对于需要跟上深度学习框架更新的 LLM 场景，这种节奏是利好。

上手门槛较低：桌面交互比较友好，文档体系完备，新手容易入门。官方支持渠道和社区资源也相对丰富。

硬件适配广：对主流硬件的兼容度不错，在不同机器上部署 LLM 时选型压力较小。

需要注意的短板

系统稳健性受影响：追求新特性的策略会让稳定性相对打折，在对可靠性要求极高的生产服务器上需要谨慎评估。

LTS 维护时长偏短：长期支持版的维护窗口比普通版长，但在 Linux 阵营里仍不算最长，到期后必须规划升级或迁移。

## 8.3 搭建环境所需组件

### 1. CUDA
CUDA 是 NVIDIA 发布的通用并行计算平台，提供驱动、API、库、编译器、调试器等完整工具链。
该方案利用 GPU 内部的并行处理器，让开发者写出可扩展的并行程序。在编程模型里 CPU 扮演主机，GPU 扮演设备，代码可基于 C/C++ 等语言编写，再经 NVIDIA 工具链编译优化。
适用场景涵盖图像处理、物理仿真、深度学习、科学计算等。借助 GPU 的并行能力，CUDA 能把原本耗时长的任务大幅压缩，总体上帮助开发者释放 GPU 计算潜力。

### 2. cuDNN
cuDNN 是面向 NVIDIA GPU 的深度神经网络加速库。对前向与后向卷积、池化、归一化、激活等基本操作的实现做了深度优化，使得训练与推理提速明显。
全球研究人员和框架开发者普遍依赖它来获取 GPU 加速，避免在底层调优上花费太多时间。兼容 Caffe2、Chainer、Keras、MATLAB、MxNet、PyTorch、TensorFlow 等主流框架。
综合来看，cuDNN 是 CUDA 生态的关键组成，为神经网络的训练与推理提供高效便捷的方案。

### 3. Anaconda
Anaconda 属于开源 Python 发行版，自带 conda、Python 以及大量科学计算与数据分析包。conda 提供包管理与环境管理能力，方便解决多版本 Python 共存、版本切换、第三方包安装等问题。
发行版预装了许多常用数据分析与机器学习库，可快速搭建 Python 数据科学环境，适合新手到专业用户。

### 4. PyTorch
PyTorch 由 FAIR 团队研发，面向 GPU 加速的深度神经网络开发。
设计上追求封装少、冗余少，风格简洁灵活且易于调试。原生支持 Python，运行期生成动态计算图，错误可直接定位到触发行，调试体验流畅。
可与 Caffe2、Chainer、Keras、MATLAB、MxNet、TensorFlow 等互通，集成成本低，也支持分布式训练，可兼顾研究与生产需求。
总体而言，PyTorch 提供了 GPU 加速、动态图和高效分布式训练能力，是功能强大且易用的神经网络框架。

### 5. VSCode
VSCode 是微软推出的免费开源代码编辑器，覆盖 JavaScript、TypeScript、Python、PHP、C#、C++、Go 等语言，提供优秀的编辑与调试体验。
设计强调体验与扩展性，插件生态丰富，可通过扩展快速增强功能。具备语法高亮、可自定义快捷键、括号匹配、代码片段等现代编辑器特性。
内置 Git 版本控制，可直接提交、推送、拉取，也集成 GitHub、Bitbucket 等远程仓库。界面简洁，跨平台运行于 macOS、Windows、Linux，提升效率与代码可移植性。
总体看，VSCode 轻量而功能强，适合各类编程人群。

## 8.4 LLM 常用知识介绍

### 8.4.1 分类
1. 按开源与闭源划分
闭源：ChatGPT、文心一言。
开源：Llama、通义千问。
2. 按地域划分
国内：文心一言、通义千问、ChatGLM。
国外：ChatGPT、Llama、BLOOM。

### 8.4.2 参数规模
通义千问：72B、14B、7B、4B（推荐）、1.8B（推荐）、0.5B（推荐）。
ChatGLM：6B。
Llama：7B、13B、33B、65B。

### 8.4.3 训练流程
ChatGPT 的训练通常分为预训练与对话微调两个阶段。

### 8.4.4 模型类型
几乎所有 LLM 都基于 Transformer 构建，可归为三类。
1. Decoder-only
多用于生成任务，如文本生成、机器翻译。
代表：GPT 系列含 ChatGPT，多用于文本生成与对话。
2. Encoder-only
多用于理解任务，如文本分类、实体识别。
代表：BERT，即双向编码器表征，用于问答、文本分类等多种 NLP 任务。
3. Encoder-Decoder
兼具编码与解码，适合既需理解输入又需生成输出的任务，如机器翻译、问答。
代表：Transformer 本身是 Encoder-Decoder 结构，用于序列到序列学习。ChatGLM 也是基于该结构的对话模型，需说明 ChatGLM 并非通用名称，而是特指某项目或公司的模型。
总体来看，Transformer 凭借自注意力与并行计算能力大幅提升 NLP 性能，不同类型各有侧重。

### 8.4.5 模型开发框架
主流有 PyTorch、TensorFlow、PaddlePaddle 三种。

### 8.4.6 量化位宽
模型量化用于缩小体积、降低推理延迟，同时尽量保留精度。核心是将权重与激活值从 32 位浮点 Float32 换成更低精度整数，如 8 位 Int8 或 4 位 Int4。
1. Int8 量化
权重与激活转成 8 位整数，体积与显存占用明显下降，整数运算更快，推理速度提升。在保持较高精度的同时显著降低存储与计算需求，是目前应用最广的方式之一。
2. Int4 量化
权重与激活进一步压缩为 4 位整数，可实现更进一步的模型压缩。

## 8.5 量化技术
可归纳为三种手段。
- 1. AWQ
AWQ 用于压缩神经网络、降低计算复杂度。核心思路是仅保护约 1% 的关键权重，其余 99% 进行量化，从而大幅减少量化误差，保持性能可控。
- 2. GPTQ
GPTQ 由 Google AI 提出，基于 Group 量化与 OBQ 方法。Group 量化把权重拆成多个子矩阵量化，有助于减小模型与计算量。OBQ 用于优化量化流程，进一步提升量化后表现。注意在量化语境下指技术，而非生成式预训练模型。
- 3. GGUF
GGUF 由 Llama.cpp 团队推出，用以替代已停止维护的 GGML 格式。它提供标准化方式表示与交换量化后模型数据。GGUF 支持多种量化方案如 Q2_K、Q3_K_S、Q4_K_M 等，可优化文件大小与性能，并提供 2 位、3 位、4 位等不同精度模型，便于 CPU+GPU 环境推理。兼容性好，适配多款第三方界面与库。

## 8.6 模型选择

### 8.6.1 通义千问
阿里云推出的 LLM，具备多轮对话、文案创作、逻辑推理、多模态理解与多语言支持。
参数规模：7B（实测较卡）、4B（推荐）、1.8B（推荐）、0.5B（推荐）。
量化：不建议量化，以免影响精度。

### 8.6.2 ChatGLM
基于千亿基座 GLM-130B 开发，由清华大学 KEG 实验室与智谱 AI 共同研发，支持中英双语，具备问答、多轮对话与代码生成能力。目前有千亿参数内测版和 6B 参数开源版 ChatGLM-6B。
ChatGLM-6B 于 2023 年 3 月 14 日开源，可在消费级显卡本地部署。模型在约 1TB 中英双语语料上训练，结合监督微调、反馈自助、人类反馈强化学习等技术，能生成更贴合人类偏好的答案。
参数规模：6B。
量化：不建议量化，以免影响精度。

### 8.6.3 Llama
Llama 即 Large Language Model Meta AI，由 Meta AI 研究院研发，旨在帮助研究人员与工程师探索 AI 应用。该模型在生成文本、对话、总结材料、证明数学定理或预测蛋白质结构等复杂任务上前景广阔。
首次发布于 2023 年 2 月，在海量文本上训练，学习了广泛语言知识与模式，能根据输入生成连贯有逻辑的输出。
参数规模：7B、13B、33B、65B。
量化：不建议量化，以免影响精度。

## 8.7 模型应用实现方式
按实现难度从易到难分为 Chat、RAG、高效微调。

### 8.7.1 Chat
通过 prompt 实现模型应用，以对话方式解决问题，核心技术是 prompt 工程。

### 8.7.2 RAG
融合信息检索与文本生成。用户提问时，系统先从大型知识库或文档集中检索相关信息，再结合检索结果生成答案，使输出更准确具体。
优势在于引入外部知识源丰富模型输出。常见实现为 prompt + 知识库（通常为向量数据库）+ 向量化方法，向量化技术常用 BERT、ERNIE 等。

### 8.7.3 高效微调
对大模型进行快速有效调整，使其适配特定任务或领域。LLM 参数动辄数十亿，全面微调成本高昂，因此发展出多种高效方法。
代表 LoRA 即低秩自适应，通过在权重矩阵上添加低秩更新实现微调，大幅减少可训练参数量，在保持性能的同时降低成本与复杂度。
实践需要少量高质量标注数据，以及充足算力如 A100、V100。高效微调通常由 LoRA + 高质量标注数据 + 算力构成。

## 8.8 通义千问 1.5-0.5B 本地 Windows 部署实战

### 8.8.1 介绍
通义千问 1.5-0.5B，简称 Qwen1.5-0.5B，是阿里云 0.5B 参数规模的模型。基于 Transformer 架构，在超大规模预训练数据上训练，数据涵盖网络文本、专业书籍、代码等多种类型。基于该模型团队通过对齐机制打造了 AI 助手 Qwen1.5-0.5B-Chat，本案例基于该仓库。
主要特点：
低成本部署：提供 Int8 与 Int4 量化版，推理显存不足 2GB，生成 2048 个 token 约需 3GB 显存，微调最低约 6GB 显存。也提供基于 AWQ、GPTQ、GGUF 的量化模型。
大规模高质量语料：使用超 2.2 万亿 token 预训练，覆盖高质量多语言、代码、数学等，兼顾通用与专业领域，并对语料分布进行优化。
优秀性能：支持 32KB 上下文长度，在常识推理、代码、数学、翻译等中英文下游任务上显著优于同规模开源模型。
更全面的词表：约 15 万词表，对多语言更友好，便于在不扩展词表情况下增强部分语种能力。
系统指令跟随：可通过调整系统指令实现角色扮演、语言风格迁移、任务与行为设定。
更多细节可参考 GitHub 代码库。
