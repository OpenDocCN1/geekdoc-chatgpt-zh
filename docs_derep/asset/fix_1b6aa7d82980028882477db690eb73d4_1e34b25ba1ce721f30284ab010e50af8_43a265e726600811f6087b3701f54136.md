# 开放源码如何重塑AI生态，以及企业该如何避坑

2021年3月12日，《中华人民共和国国民经济和社会发展第十四个五年规划和2035年远景目标纲要》正式对外公布，其中明确写到要扶持数字技术开源社区等创新联合体建设，完善开源知识产权与法律环境，鼓励厂商公开软件源代码、硬件设计与应用服务。紧接着2021年12月27日，国务院知识产权战略实施工作部际联席会议办公室下发《知识产权强国建设纲要和“十四五”规划实施年度推进计划》，要求补齐新兴领域知识产权规则，提出要研究大数据、人工智能、区块链、基因技术等新业态的保护规则；同时要研究信息技术开源知识产权合规标准、社区代码贡献规则标准，推动行业开源知识产权风险研究和合规评估培训。两份文件共同传递的信号是，开源技术在落地应用时必然牵扯大量知识产权问题。

围绕开放源码及相关技术做一次梳理。

### 一、开放协作的基本逻辑
开放协作是一种在软硬件研发、数据和信息共享中被广泛使用的协作范式，其产出必须符合所选许可协议的要求。[^(\[3\])](#chapter001.html#m3)由此可知，开放源码并不等同于仅指程序，也不是商业模式本身，而是一种协作方式。产出可以是程序、小程序、数据库、文档等，每种载体都能依据自身特点挑选合适的许可。例如程序可选用通用公共许可证 GPL 以维护使用者自由；小程序可选用 Apache 许可，借其专利反击条款降低被诉专利侵权的可能；若开发者已使用以非自由或不够宽松许可证发布的数据库，可选用 GNU 宽通用公共许可 LGPL；教程、参考手册等资料可选用 GNU 自由文档许可证 GFDL 或知识共享许可 CC 协议。[^(\[4\])](#chapter001.html#m4)

### 二、开放技术在AI产业中的落地
#### （一）AI产业里的开放源码软件
据开放源代码促进会 OSI 官网信息[^(\[5\])](#chapter001.html#m5)，开放源码软件的定义最初来自 Debian 自由软件指南 DFSG，后由 Bruce Perens 从 DFSG 中剔除 Debian 专属表述后形成。开放源码远不止代码可读，分发条款必须满足十项 OSD 标准：（1）可自由再发布；（2）源代码必须公开；（3）允许衍生；（4）保持作者源码完整性；（5）不得歧视个人和团队；（6）不得歧视应用领域；（7）许可须公开；（8）许可不能绑定单一产品；（9）许可不能限制其他软件；（10）许可须独立于技术。[^(\[6\])](#chapter001.html#m6)

AI浪潮再起时，越来越多AI厂商选择开源。AI产业链常被分为基础、技术、应用三层，技术层涵盖计算机视觉、自然语言处理、机器学习与深度学习等核心技术。目前AI产业的开放源码软件主要集中在机器学习尤其是深度学习，并形成一批影响深远的框架。例如谷歌在 Apache 开源许可证 2.0 下发布 TensorFlow，提供基于数据流图的数值计算库，可在单/多核 CPU 或 GPU 乃至移动设备上运行；[^(\[7\])](#chapter001.html#m7)Meta 前身 Facebook 推出了 Caffe2 框架；百度推出了深度学习平台飞桨 PaddlePaddle 等。

#### （二）AI产业里的开放源码硬件
开放源码软件大幅缩短了软件研发周期并提升效率。硬件领域尤其是芯片设计，每个模块的验证都关系到流片成败，若所用开放组件成熟度不足导致流片后出现 bug，研发成本和周期会大幅增加，因此开放组件在芯片领域应用仍谨慎。但一旦品质过关，就能明显缩短设计周期并降低成本。近年来AI芯片备受关注，其需要执行大量矩阵乘法等计算。典型开放芯片项目包括 RISC-V 和 NVDLA。

2010年，美国加州大学伯克利分校 UCB 推出基于精简指令集计算 RISC 原理构建的开放处理器指令集 RISC-V，成为目前最成功的开放芯片项目，可免费使用并允许任何人设计、制造和销售 RISC-V 芯片及软件。基于 RISC-V 可设计服务器计算芯片、家电计算芯片、工控计算芯片以及微型传感器计算芯片。未来在异构计算和物联网 IoT 领域有望广泛应用。[^(\[8\])](#chapter001.html#m8)

NVDLA 是 NVIDIA 基于 Xavier 推出的开放深度学习推理加速器，面向终端片上系统 SoC 推理场景，模块化结构便于在物联网设备上扩展。NVDLA 允许 SoC 厂商免费使用并按需修改框架。但要注意，使用 NVDLA 虽免费，修改时仍需借助 NVIDIA 生态下的其他工具，比如用 TensorRT 优化深度学习模型，从而助推 NVDLA 生态构建等。[^(\[9\])](#chapter001.html#m9)

#### （三）AI产业里的开放数据
AI技术已广泛应用于手机、汽车、家电、安防、医疗、教育、金融等领域，这些突破都依赖海量训练数据。随着场景快速演进，数据开放正成为趋势。

一方面，AI领域已有若干标准数据集，如机器视觉的 MNIST、CIFAR、ImageNet，自然语言的 WikiText、SQuAD、Billion Words、Stanford Sentiment Treebank，语音识别的 2000 HUB5 English、CHIME，推荐系统的 Million Song Dataset 等。这些数据集对算法优化和工程开发起到了关键推动作用。若各厂商各自开发数据集，定义、格式、接口差异很大，会导致 AI 程序无法兼容互操作，影响平台集成性能。另一方面，AI 所用的海量训练数据需提前标注，高质量标注数据影响厂商竞争力。数据标注类型多样，如分类、画框、注释、标记等，可按行业、需求、目标、语言等进一步细分，导致不同机构标注的同类数据甚至同数据标注差异显著，不利后续分析和处理。[^(\[10\])](#chapter001.html#m10)基于上述两点，在确保商业秘密和数据安全前提下推进数据开放，不仅能减少重复采集、标注和处理工作，提升效率、降低研发成本，也能促进同领域厂商合作共同推动产业发展。

全球数据库流行度排行榜网站 DB-Engines 显示，截至 2020 年 9 月，全球开放数据库共 182 个，已超过商业数据库，[^(\[11\])](#chapter001.html#m11)较知名者包括 Apache 软件基金会 ASF 的 Hadoop、Spark，国内有华为的 Apache CarbonData 等。此外，还有保护开放数据的法律框架，如 Linux 基金会发起了社区数据许可协议 CDLA，用于个人和组织之间公开、共享和使用数据。

### 三、开放源码对AI技术演进的影响
#### （一）何为开放源码软件
开放源码对AI技术演进至关重要，了解其法律属性是使用前提。开放源码通常被理解为开放源代码的软件，任何人均可查看、修改或扩充其源代码。与专有软件不同，专有软件使用需作者同意或授权，一般还需付费。而开放源码由作者将源代码公开在网络上，任何人可依许可要求使用相应源代码。开放源码仍属作品，受著作权保护，作者对其公开的源代码享有著作权。需要明确的是，并非无前提公开源代码就意味着可随意使用。相反，根据各国著作权法一般规定，著作权人对源代码享有权利，任何人不得未经同意复制、使用、传播其作品。因此，若作者希望更多人使用、修改、完善其代码，可通过选择相应许可，建立作者与使用者间的授权关系，免除使用者的侵权责任。

#### （二）与开放源码相关的组织
既然许可对使用者行为提出要求，那么谁来保证实际遵循呢？1985 年，Richard Matthew Stallman、RMS 发起成立自由软件基金会 Free Software Foundation、FSF，它是非营利性组织，致力于促进计算机使用者自由。最初成立目的是促进自由软件开发，目前该协会自身就拥有 GNU 操作系统的版权。除此之外，通过协议签署，FSF 已拥有大多数 GNU 程序和其他一些自由软件的版权，以便可通过诉讼方式约束使用者履行许可项下义务。

早在 2008 年，思科公司 Cisco 曾因其销售的无线路由器 Linksys WRT54G 固件中使用 GNU/Linux 系统但未向用户发布全部源代码而遭到 FSF 起诉。此前数年 FSF 一直尝试与思科沟通促其主动发布产品源代码但未获有效回复。诉讼过程中双方最终和解，思科公司将任命一名免费软件总监，负责使 Linksys 品牌产品符合 GPL 授权方式，并向 FSF 汇报相关情况。思科公司还将告知现有 Linksys 客户其权利，并在网站上发布产品源代码，将源代码反馈给 FSF。

除了拥有开放源码版权的组织，开放源码作者自身也可依据许可内容维权。社区维权被认为更理想，不过在开放源码社区中，大多数人认为更主要努力方向是促使使用人合规，而不是惩罚。[^(\[12\])](#chapter001.html#m12)

#### （三）开放源码许可的主要类型
##### 1. 开放源码许可的主要内容
开放源码许可即程序开放时使用的许可证，其主要作用是规定许可内容，以便使用人能自由使用作者发布的源代码而不必担心侵犯版权。一般程序许可协议会规定许可期间、地域范围、权利类型、许可的具体权利，如复制、修改、传播、收费等。某些开放源码许可还会对与代码有关的专利许可作出约定。

##### 2. 常见的开放源码许可
目前比较常用的开放源码许可有 GNU 通用公共许可证 GNU General Public License、GNU GPL、Apache 许可证 2.0、Apache License version 2.0、BSD 许可证、BSD licenses、宽通用公共许可证 Lesser General Public License、LGPL、MIT 许可证、MIT license、Mozilla 公共许可证 1.1 版本 Mozilla Public License version 1.1、MPL-1.1 和通用公共许可证 1.0 版本 Common Public License 1.0、CPL-1.0 等，已有开放源码许可达 80 多种。以下介绍几种常见开放源码许可（表 1-1）。

#### （四）开放源码对AI技术发展的影响
AI技术发展离不开基础研究深入，该技术发展迅速，科技巨头都在着眼构建充满活力的开放社区以拓展自身开放生态圈。例如，2015 年 Google 推出其开放框架解决方案 TensorFlow，它是用于机器智能的开放软件库，吸引不同企业在此平台训练模型，其通用性使其也可广泛应用于其他计算领域。Facebook 也推出 Caffe2 框架，旨在让微软和亚马逊等主要市场参与者和社交网络的 PyTorch 框架一起使用该平台。[^(\[13\])](#chapter001.html#m13)开放平台的发展确实让企业获得更多创新力量，它们推出的深度学习开放平台在全球 AI 领域占有很大份额。2021 年 7 月 8 日，中国科学院院士梅宏在 2021 世界 AI 大会上提出，AI 快速发展离不开代码开放和数据开放，高质量开放数据促进了深度学习算法突飞猛进，深度学习框架极大提升了算法开发效率，二者相辅相成。[^(\[14\])](#chapter001.html#m14)

在大数据产品领域，基本上所有数据库产品都绕不开使用 MariaDB、PostgreSQL 和 MongoDB 等开放数据库的核心代码。著名手机系统安卓也采用了 Linux 内核项目，而该项目本身也是开放软件。开放软件的运用使得其他使用者无须从零开始开发全新系统，只需在已有开放项目基础上进行修改和定制即可，最重要的是开放软件通常免费，这在很大程度上刺激了行业创新积极性。

我国 AI 开放项目正处于起步阶段，2018 年中国 AI 开放软件发展联盟发布的《中国 AI 开放软件发展白皮书（2018）》指出，AI 开放软件是驱动 AI 技术创新和应用的重要支撑力量。[^(\[15\])](#chapter001.html#m15)2021 年《中华人民共和国国民经济和社会发展第十四个五年规划和 2035 年远景目标纲要》中也指出，“支持数字技术开源社区等创新联合体发展，完善开源知识产权和法律体系，鼓励企业开放软件源代码、硬件设计和应用服务”。目前，我国已打造 OpenI 启智平台、之江天枢 AI 开放平台等项目，为 AI 行业发展提供新动力。

### 四、AI 厂商在开放源码方面的合规风险
AI 厂商在引入、使用、修改、分发开放技术时，可能触发许可违约风险、合规风险、专利侵权风险、商标侵权风险、数据安全风险、出口管制风险和应用过程中的知识产权风险等。以下围绕许可合规风险、供应链管理风险、程序使用合规风险和应用过程中的知识产权风险展开讨论。

#### （一）开放源码许可合规风险
新思科技 Synopsys 发布的《2022 开放源安全和风险分析报告》显示，2021 年审计的代码库中有 53%的开放代码存在许可冲突风险，17%的开放代码存在许可兼容性问题。[^(\[16\])](#chapter001.html#m16)

AI 厂商在自定义许可时，应注意规则清晰。例如，JSON 许可实质上是宽松型 MIT 许可，其添加了“该款软件严禁用于恶意用途，仅限于善意用途”的注释。许多 Apache 软件基金会项目都因许可定义含糊不清而删除了使用 JSON 许可的代码。

#### （二）开放源供应链管理风险
虽然引入开放软件能提高研发效率、缩短产品上市时间，但由于开放软件贡献者往往人数众多、互不相识且散布全球，导致大量风险隐患。2022 年 3 月发生的 faker.js 与 colors.js 开放库遭到作者 Marak 恶意破坏事件就是典型例子。Marak 通过向两个包提交恶意代码进行供应链投毒，并发布到 GitHub 和 npm 包管理器中，之后又将项目仓库所有代码清空，完全停止维护，从而导致依赖两个库的数千个项目无法运行。

#### （三）开放软件使用合规风险
根据开放安全扫描平台 Snyk 和 Linux 基金会的调查结果，只有 49%的组织制定了开放软件开发或使用的风险管控策略。企业未建立完整的开放软件使用管理机制，导致开发人员对开放软件基本处于“只用不说”的状态，企业也无法了解其产品或服务中是否包含了开放软件，[^(\[17\])](#chapter001.html#m17)使得合规风险大大提升。

另外，AI 训练所需的数据许可并无国际组织对其进行标准化，这意味着对使用数据的企业来说暗藏诸多风险。此外，开放技术中的安全漏洞也会带来数据泄露风险。

### 1. 许可的法律风险
在许可背景下，选择适合企业情况的许可至关重要，这决定了软件使用者的自由程度。若选择得当，企业可在享受开放社区便利的同时提高自身产品适应性。但若选择不当，则有可能为衍生产品的使用埋下隐患。

#### （1）GPL 中的强制开放
GPL 具有高度的“传染性”，其允许第三方对开放的代码免费使用、修改，但不允许将修改后的代码作为闭源商业软件发布和销售。著名的 Linux 内核开放项目即使用 GPL 许可，由于使用 Linux 内核开放项目的上层服务不可避免会涉及调用 Linux 内核文件，若将该行为视为创作了衍生产品，将导致上层服务源代码被受 GPL 许可控制的 Linux 内核开放项目所“传染”，从而需要接受 GPL 许可。这就形成了一个以 Linux 内核开放项目为核心的传染源，任何基于 Linux 开发的内核驱动到中间服务到上层应用都受到 GPL 许可控制，在符合发布软件条件下需向大众开放源代码。不过 Linux 内核作者 Linus Torvalds 以及内核开发人员多次澄清普通系统调用为非 GPL 作用范围，也就是允许 Linux 用户空间程序使用其他许可。
