OpenClaw 技能图谱精读

效率与办公方向的核心逻辑，是把 OpenClaw 接入常用的生产力软件，实现流程自动化。这类方案通常把第三方平台的接口或命令行程序包起来，让智能体直接操作用户熟悉的工具。

1．Gog
该模块在同类里辨识度很高，维护者是核心贡献者 @steipete。对重度使用 Google 套件的用户提效明显。基于 gogcli 为 OpenClaw 提供了对 Gmail、Calendar、Drive、Contacts、Sheets、Docs 的全量操作能力。
典型场景有让 OpenClaw 检索近三天来自某联系人的邮件并提炼要点，在次日下午三点为设计组创建会议并标红，或读取项目进度表并指出延期项。技术层面它示范了用 OAuth 安全接入复杂生态，并把自然语言映射为明确的命令行参数以实现精准调用。

2．Notion
同样出自 @steipete。借助官方 REST 接口，OpenClaw 能直接读写页面与数据库。可以把讨论的会议纪要整理后写入指定库新建页面，或查询待办库中状态为进行中的任务。
SKILL.md 里详细说明了如何携带 Notion-Version 请求头的 curl 请求，以及如何处理复杂的 JSON 内容块来操作页面，是学习接口集成的参考样例。

3．Obsidian
也是 @steipete 的作品，面向偏好本地 Markdown 知识库的用户。通过 obsidian-cli 与本地 Vault 交互，可读写修改 Markdown 笔记。可在默认库新建会议记录，或搜索主题相关的全部笔记。与 Notion 不同，它完全离线运行，无需网络，隐私性更强。

4．Trello
面向看板式项目管理的团队，通过 Trello REST 接口管理看板、列表与卡片。可在产品迭代看板的待开发列表新建任务卡，或把已完成的卡片移至已完成。实现上结合 curl 与 jq，展示了如何优雅解析与过滤接口返回的复杂 JSON，提取智能体可用的核心信息。

5.2.2 开发与运维方向
对开发者而言，OpenClaw 配合此类模块可成为全能的结对编程助手，覆盖代码管理、网页自动化、接口集成等环节。

1．GitHub
开发者使用频率最高的模块之一，深度集成官方 gh CLI，让 OpenClaw 兼任代码审查与 CI/CD 助手。可检查某仓库特定 PR 的 CI 运行状态，列出当前仓库所有开启的 Issue 并按创建时间排序，或总结 PR 的代码变更。
SKILL.md 明确划定了适用场景如查看状态、创建 Issue，以及不适用场景如本地 git 提交、复杂代码审查应交由专业工具。这种清晰边界是高质量模块的写作范式。

2．Agent Browser
由 @TheSethRose 打理。基于 Rust 的轻量无头浏览器自动化命令行工具，为 OpenClaw 提供网页导航、点击、输入、截图能力。在网页自动化测试、数据抓取、复杂交互场景中作用明显。例如打开 Hacker News 首页，抓取前十文章标题与链接并保存为 CSV。

3．API Gateway
由 @byungkyu 构建，提供统一入口连接 Slack、Airtable、HubSpot 等上百种第三方接口，并内置托管式 OAuth 认证，极大降低调用复杂度。适合在单一工作流中集成多种 SaaS 服务的复杂场景。

4．Coding-Agent
一种特殊的元模块，允许 OpenClaw 后台生成并委托任务给专用的编码智能体，如 Codex、Claude Code 或 Aider。当需要在某个项目目录启动编码智能体重构用户认证模块时即可派上用场。
技术上它展示了后台进程管理能力：通过 Bash 工具的 pty:true 与 background:true 参数管理长时间运行的交互式 CLI，并用 process 工具轮询状态、读取日志。

5.2.3 智能体增强方向
该类模块聚焦提升 OpenClaw 自身的智能水平、反思能力与主动性，是推动智能体进化的核心工具。

1．Self-Improving-Agent
ClawHub 上下载量很高的经典模块，由 @pskoett 开发。它能捕获智能体运行时的学习经验、错误信息与用户的纠正指令，实现持续自我优化。命令失败或用户指出错误时会自动记录并调整后续行为，长期使用后表现会越来越贴合个人习惯。

2．Proactive Agent
由 @halthelobster 开发，把 AI 从被动跟随者变为主动合作伙伴。安装后 OpenClaw 能预测需求并主动执行后台任务。
模块引入了 WAL 预写日志协议、工作缓冲区与自主 Cron 任务等机制，使智能体具备自主规划与执行能力。例如每天早上开机时主动生成当日邮件摘要与日程提醒。

3．Skill Vetter
由 @spclaudehome 开发，是以安全为核心的模块审查工具，面向注重系统安全的用户。在从 ClawHub 或 GitHub 安装新模块前，可用它检查潜在风险、权限范围与可疑代码模式。它会分析模块脚本，标记可能存在风险的操作，如删除文件、访问敏感目录、发送网络请求等，帮助安装前决策。

5.2.4 内容处理与创作方向
这一类是处理文本、音频、图像与文档的高效工具，能显著提升创作与信息处理效率。

1．Summarize
内容处理领域的热门工具，支持多模态总结，可处理网页、PDF、图片、音频甚至 YouTube 视频。可总结长篇技术博客的核心观点，或提取视频字幕并给出摘要。
技术上它体现了多模态输入的处理思路：调用大模型做文本摘要，同时集成 Firecrawl 抓取带反爬机制的网站、Apify 获取 YouTube 字幕作为后备方案，提升鲁棒性。并支持 OpenAI、Anthropic、Google 等多家后端，可调用 GPT、Claude、Gemini 系列，按偏好灵活选择。

2．Nano Banana Pro
图像生成与编辑的核心工具，基于 Gemini 3 Pro Image 模型，支持文生图、图生图，最高 4K 分辨率。可生成赛博朋克风格的未来城市夜景，或对现有图片做风格转换。
脚本生成后会输出一行 MEDIA: 标记，Gateway 会捕获并自动把图片作为附件发送到 Telegram、Discord 等支持的聊天渠道，实现生成到分发的无缝衔接。

3．Nano PDF
针对高频 PDF 办公场景，支持用自然语言编辑 PDF，包括合并、拆分页面、提取特定页、添加水印等。对处理大量文档的办公人员可节省大量手工时间。

4．Sag
集成了 ElevenLabs 高质量文本转语音接口，提供类似 macOS say 命令的极简体验。可指定 Roger、Sarah 等不同声音角色朗读文本。它展示了如何通过环境变量 ELEVENLABS_API_KEY 安全注入接口密钥，并在本地播放音频，是外部接口集成的经典范例。

通过以上模块可以看出，只要有对应的命令行工具或接口，就能把 OpenClaw 的能力边界不断扩展，让 AI Agent 成为真正的得力助手。

5.3 模块的安装与使用
了解 ClawHub 的概念与生态后，下面说明如何把模块装到本地 OpenClaw 并高效使用。

5.3.1 安装 ClawHub CLI
与 ClawHub 交互需要先装命令行工具。ClawHub CLI 基于 Node.js，需要 Node.js v22 或更高版本及 npm。执行全局安装：
npm install -g clawhub
安装完成后用 clawhub -V 验证版本号，输出正常即表示就绪。

5.3.2 通过 ClawHub CLI 命令安装与更新
以 tavily-search-skill 为例，该模块集成 Tavily 接口，支持实时配额管理与付费模式切换，可执行网络搜索并返回内容片段、相关性评分与元数据。
安装命令非常简洁：
Bash
clawhub install tavily-search-skill
其中 tavily-search-skill 为模块的 Slug，通常可在 _meta.json 中找到。
默认安装到当前工作目录 ./skills，若已配置 OpenClaw 工作空间，则会自动安装到 ~/.openclaw/workspace/skills，确保 OpenClaw 可识别。
指定版本安装：
Bash
clawhub install tavily-search-skill --version 1.0.2
[PRE0]
版本迭代时可用更新机制：
# 更新所有已安装模块
clawhub update --all
# 更新特定模块
clawhub update tavily-search
clawhub update --all 会扫描本地模块并与 ClawHub 最新版对比自动升级。若本地文件被自定义修改，普通更新会跳过以免覆盖，需加 --force 强制执行。
ClawHub CLI 目前无卸载命令，需手动删除 skills 目录对应文件夹，例如：
rm -rf ~/.openclaw/workspace/skills/tavily-search
OpenClaw 下次运行时会自动检测并从加载列表中移除。

5.3.3 模块的加载机制与优先级
OpenClaw 从三个位置加载模块，按严格优先级覆盖。
优先级最高：当前 OpenClaw Workspace 模块，位于 <self-openclaw-workspace>/skills 目录，也是 clawhub install 的默认路径，适合放自定义开发的专属模块。
优先级中等：托管/本地模块，位于 ~/.openclaw/skills 目录，通常存放可被多个智能体共享的本地模块。
优先级最低：内置模块，随 OpenClaw 安装包发布的核心官方模块。
若三处出现同名模块，OpenClaw 优先加载高优先级版本。例如可通过在工作空间放同名 github 模块覆盖内置版本，无需改动核心代码。
还可在配置文件 ~/.openclaw/openclaw.json 中通过 skills.load.extraDirs 添加额外扫描目录，优先级最低，便于企业级部署与复杂模块包管理。
OpenClaw 默认启用热重载，监听模块目录变化，防抖间隔约 250 毫秒。安装新模块或修改 SKILL.md 后会极短时间内自动刷新快照，无需重启 Gateway，调试自定义模块时很方便。

5.3.4 在对话中调用已安装的模块
调用方式主要有自然语言触发与 Slash Command 强制调用。
自然语言触发最符合直觉。每个模块的 SKILL.md 包含 description 字段，既面向用户也用于向大语言模型说明用途与触发场景。例如安装 weather 模块后输入“今天北京的天气怎么样”，智能体循环会分析意图、匹配模块并自动调用工具，最终以自然语言回复。
Slash Command 适用于明确指定模块的场景。若模块配置 user-invocable: true，默认开启，OpenClaw 会自动生成斜杠命令，格式为：
/skill <模块名称> [参数]
例如强制用 summarize 总结网页：
/skill summarize https://example.com/article
该方式绕过意图识别，直接把指令传给模块，执行更确定，调试新模块时非常有用。

5.4 环境变量配置详解
许多调用外部接口的模块需要配置环境变量如 API Key、访问令牌。OpenClaw 提供多种配置方式，理解优先级与生效时间对顺畅使用很关键。

5.4.1 系统级环境变量
最基础的方式是直接在操作系统 Shell 配置文件中导出变量：
# 在 ~/.bashrc 或 ~/.zshrc 中添加
export GEMINI_API_KEY="your_gemini_api_key_here"
export GITHUB_TOKEN="your_github_token_here"
