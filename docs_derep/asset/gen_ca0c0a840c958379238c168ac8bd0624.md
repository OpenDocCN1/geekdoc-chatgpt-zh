[PRE0]

面对用户的输入，Agent 会先思考该调用哪一个工具、对应的参数应该填什么，随后发起调用并把观察到的结果记录下来。之后它会把工具名、输入参数和过往的观察历史一起送回模型，让模型判断下一步该怎么做，如此循环，直到模型认为不需要再动用工具时才会直接给出最终回复。

这种 ReAct 式的循环在简单场景下表现尚可，但随着用户目标越来越复杂，尤其是更多开发者和团队准备把 Agent 推向生产环境时，对可处理更复杂请求、同时具备更高稳定性的 Agent 的需求也在上升。

为了让 Agent 既盯住终极目标，又能记住并推导出之前的步骤，提示词不得不被不断扩容，塞进越来越多的历史记录。为了提升工具调用的可靠性，开发者又在提示里堆叠更多关于工具使用方式的说明。可靠性要求与复杂度攀升的双重压力下，大模型很容易吃不消，往往在几次 ReAct 交互后就会出现各种偏差。

正是在这样的背景下，研究者开始寻找更具想象力的 Agent 认知范式。

Lei Wang 等人在论文《Plan-and-Solve Prompting: Improving Zero-Shot Chain-of-Thought Reasoning by Large Language Models》[10] 中提出把高层规划和短期执行拆开的思路。论文认为，处理多步推理任务时，Agent 宜先勾勒出行动蓝图，再按部就班地执行。

### 咖哥发言

Zero-shot-CoT 认知范式的做法，是把目标问题的描述与“Let's think step by step”这类引导语拼接成提示词。这种组合融合了零样本学习与思维链推理，目的在于增强模型面对从未见过的任务时的应变能力，而不必依赖具体训练样本。

- 零样本学习指让模型在训练阶段未曾接触过的数据或任务上也能做出合理判断，核心在于泛化能力，即借助已有知识对新概念进行迁移推断。
- 思维链推理则模仿人类解题的展开过程，通过生成中间步骤和解释来逼近答案，能让模型在复杂问题上更清晰、可解释。

在 Zero-shot-CoT 框架下，面对新颖任务时模型会自行在内部生成一系列思维步骤，即“思维链”，从而在没有针对性训练数据的情况下完成推理。

示例问题：一个 20 人的舞蹈班，20% 的人选现代舞，剩余人群中 25% 选爵士舞，其余选嘻哈舞。整个班级中有多少比例的人选择嘻哈舞？

Zero-shot-CoT 与 Plan-and-Solve 对同一问题给出的推理路径和结论并不相同。

Zero-shot-CoT 鼓励模型产出多步推理，提示词常为“让我们一步一步思考”，希望模型按序求解。但当问题复杂度上升时，即便使用该方法，模型仍可能在中间步骤出错。本例中模型就错误地算出 55% 的人报名嘻哈舞。

Plan-and-Solve 则要求模型分两阶段工作：先制定解决问题的计划，形成逐步行动方案，再依此方案求解。它先把整体任务拆成若干子任务，再按计划逐项执行。

Plan-and-Solve 给出的具体解法如下。

- 计划：先算出选择现代舞和爵士舞的总人数，再算出选择嘻哈舞的人数，最后计算嘻哈舞的占比。
- 解法：步骤 1，20 人中的 20% 即 4 人选现代舞，剩下的 16 人中 25% 即 4 人选爵士舞，现代舞加爵士舞共 8 人。步骤 2，剩余 12 人选择嘻哈舞。步骤 3，嘻哈舞占比为 12/20 = 60%。

## 7.2 LangChain中的Plan-and-Execute Agent

LangChain 的 Plan-and-Execute Agent 正是受 Plan-and-Solve 论文启发而来。LangChain 团队认为它很适合处理更复杂的长期规划需求，能把庞大任务拆解为一系列子任务逐个攻破。尽管这会让大模型被调用得更频繁，却能避免 ReAct Agent 多轮循环时提示词过长的弊端。

LangChain 中的 Plan-and-Execute Agent 框架由计划者和执行者组成。计划者是一个大模型，利用语言模型的推理能力来描绘需要完成的事项以及可能出现的边缘情况。一旦计划生成，便会通过输出解析器处理，将原始文本转化为清晰的步骤清单，每个字符串对应计划中的一个步骤。

对于计划中的每一步，如何执行是关键，这涉及挑选合适的工具或方法。执行者需要充分理解可用资源和工具，从而选择最优路径。因此执行者也是一个大模型。在 LangChain 的实现里，执行者本身就是一个 ReAct Agent。它能接收一个高层目标，即单个步骤，并借助工具来实现该目标，可能一步完成，也可能需要两步。

这种拆分的好处在于把规划与执行分开——一个模型专注规划，另一个专注执行。规划阶段引导模型把握问题本质、将整体任务分解为可管理的子任务并制定清晰方案；执行阶段则专注按既定方案逐步解决子任务，最终达成整体目标。这种分阶段方式让问题解决更透明，也有助于提升质量与效率。
