## 小结与思考

- 模型序列化：将训练好的模型从内存写入磁盘以便复用，是必要的一步，核心在于把参数与结构信息持久化到文件。
- 序列化分类：主流做法可归为四类，跨平台跨语言通用的如 XML、JSON、Protobuf、FlatBuffers；模型自带的私有序列化；语言层面的通用序列化如 Python 的 pickle、joblib；以及用户自行定义的序列化方式。
- PyTorch 模型序列化：PyTorch 既支持内部格式的 torch.save 与 torch.load 保存加载，也支持通过 torch.onnx.export 导出 ONNX，实现跨框架、跨平台的迁移部署。
- 目标文件格式：Protobuf 是一种高效且与语言无关的数据序列化机制；FlatBuffers 则允许零解析直接内存访问，特别适合性能敏感的应用场景。

## 17.3 自定义计算图
模型转换本质上是对模型结构与参数进行再表达。转换时需要读懂计算图，再按目标格式的要求进行节点、边的增删改，确保转换后的图仍能正确反映计算流程。本节重点展开自定义计算图的实现思路，以及模型转换的流程与细节。

### 17.3.1 计算图定义回顾
回顾 17.1.2 节，转换模块由转换模块与图优化两部分构成，中间的 IR 作为中间表示承接不同 AI 框架。借助 IR，可方便地开展各类图优化。图优化是对计算图进行改造以提升计算效率，通过算子融合、算子替换等手段减少冗余、提升并行度、降低内存占用，从而加速训练与推理。

#### 1. 计算图组成
无论是 AI 框架还是推理引擎，计算图都由张量这一基本数据结构与算子这一基本运算单元构成。

**基本数据结构张量（Tensor）**：机器学习里多维数据统称为张量，用秩表示轴数。标量是零秩，含一个数值；向量是一秩，拥有一个轴；RGB 彩色图像为三秩，含三个轴。Tensor 元素类型可为 INT、FLOAT、STRING 等。图 17.3.1 中张量的形状为[3, 2, 5]。

[PRE1]

**基本运算单元算子（Operator）**：算子是神经网络的最小计算单元，对张量进行加工，涵盖数据变换、条件控制、数学运算等多种逻辑。算子通常由基础代数算子构成，再组合成复杂算子。常见类型包括数学运算如加法、乘法，数据变换如转置、Reshape，条件控制如 if-else 等。详见第 10 章 10.2 节表 10.2.1。N 个输入张量经算子计算可产生 M 个输出张量。例如加法算子接受 2 个输入张量逐元素相加输出 1 个张量；卷积算子可能有多输入如数据与卷积核，输出 1 个张量完成特征提取。复杂网络由多个算子串联，每个算子在图中执行特定操作并把结果传递给下一环节。

#### 2. AI 框架中的计算图
**AI 框架**：如 MindSpore、PyTorch 等，用于开发与训练机器学习模型的软件环境，提供构建网络、数值计算、自动梯度与优化等工具。

**计算图**：神经网络的一种表达形式。现代模型拓扑日益复杂，需要框架快速分析算子依赖、梯度计算与训练参数，便于结构优化、调度与自动化梯度，从而提升训练效率。为兼顾灵活性与高效性，设计了基于计算图的框架。计算图明确算子间依赖，使得计算过程清晰可控。在框架内，计算图用于描述前向传播，即输入数据经层层处理得到输出。基于此可进行算子融合、常量折叠、内存优化等，提升执行效率。

实践中计算图可为静态，如 TensorFlow 的静态图，构建时即确定流程，适合生产高效执行；也可为动态，如 PyTorch 的动态图，运行时构建，提供更大灵活性和易用性。

#### 3. 推理引擎中的计算图
推理引擎是执行模型推理的软件组件，模型训练完成后用于部署并生成预测结果，通常会做推理加速。

计算图是实现高效推理与跨平台部署的关键。标准化的图表示使推理引擎能在不同硬件上部署。推理时模型常被转为中间表示 IR，抽象出计算过程以适配不同硬件。推理引擎通过分析图识别常见算子模式，如连续算子融合以减少计算与内存访问，提升速度。

推理引擎还能依图精确管理内存分配与使用，减少碎片与重复拷贝。计算图明确了算子执行顺序与依赖，引擎据此调度任务，最大化多核与并行资源利用。

#### 4. AI 框架计算图与推理引擎计算图
如表 17.3.1 所示，两者在多个层面存在差异：

（1）前向和反向传播：推理引擎仅关注前向传播，推理阶段无需梯度计算与参数更新；AI 框架计算图需同时支持前向与反向，以完成训练中的梯度计算与参数更新。
（2）动静态图：AI 框架通常支持动态图以提升建模灵活性，部分场景会切换静态图提升效率，如 TensorFlow；推理引擎更偏向静态图，执行期易优化，动态图可能影响时延与调度。
（3）分布式并行：训练场景下，AI 框架计算图支持数据并行、张量并行、流水并行等策略，利用集群加速大规模训练；推理场景下，推理引擎计算图多以单卡服务为主，很少涉及分布式推理，更强调低时延与稳定服务。
（4）使用场景：AI 框架计算图用于训练、科研创新、模型微调等；推理引擎计算图用于工业级部署，对外提供高效、低时延的推理服务。

表 17.3.1 AI 框架计算图与推理引擎计算图对比

| | AI 框架计算图 | 推理引擎计算图 |
|---|---|---|
| 计算图组成 | 算子+张量+控制流 | 算子+张量+控制流 |
| 前向和反向 | 前向+反向 | 前向 |
| 动静态 | 动态图+静态图<br>部分 AI 框架实现动静统一可以互相转换 | 以静态图为主 |
| 分布式并行 | 依托 AI 集群计算中心，计算图支持数据并行、张量并行、流水并行等并行切分策略 | 以单卡推理服务为主，很少考虑分布式推理 |
| 使用场景 | 训练场景，以支持科研创新、模型训练和微调，提升算法精度 | 推理场景，以支持模型工业级部署应用，对外提供服务 |

## 17.3.2 推理引擎计算图实例
神经网络可视为计算图，推理即数据从起点流向终点的过程。为在推理引擎中构建高效计算图，可用 Protobuf 或 FlatBuffers 定义整体流程。

（1）构建计算图 IR：结合引擎特性与性能优化点，设计专属计算图中间表示。
- 选用 Protobuf 或 FlatBuffers 等序列化库定义 IR，需考虑引擎特性以满足性能与功能需求。
- 设计节点与边的数据结构，包含操作类型、参数、数据流等，确保能准确表达模型计算流程。
（2）解析训练模型：解析 AI 框架导出的模型文件，利用 Protobuf 或 FlatBuffers 提供的 API 将其映射到自定义 IR 对象。
（3）生成自定义计算图：使用 Protobuf 或 FlatBuffers API 导出自定义计算图。
- 基于解析信息生成图，并可引入算子融合、内存布局优化等策略。
- 对生成图进行深度优化，如公共子表达式消除、死代码消除、算子替换等，以提升推理性能与资源效率。

### 1. 张量表示
（1）张量数据存储格式：定义名为 DataType 的枚举，涵盖 float、double、INT32、uint8 等常见类型，每种类型对应整数编码，如 DT_FLOAT 为 1、DT_DOUBLE 为 2，依次类推。

[PRE2]

（2）张量数据内存排布格式：即张量在内存中的存储顺序，不同框架可能采用不同排布。
- ND：多维数组，无固定排布。
- NCHW：通道-高-宽排布，常用于卷积网络，按批次、通道、高度、宽度排列。
- NHWC：高-宽-通道排布，部分框架采用，按批次、高度、宽度、通道排列。
- NC4HW4：通道-高-宽排布，通道与宽度扩展为 4 的倍数，常用于 GPU 加速。
- NC1HWC0：通道-1-高-宽-0 排布，常用于 Ascend 等硬件，通道维度做扩展。
- UNKNOWN：未知排布，无法归入已知格式。

[PRE3]

（3）张量的定义：定义 Tensor 结构，用于描述张量的形状、数据排布格式与数据类型等属性。

[PRE4]

### 2. 算子表示
算子定义因框架而异，同一算子在不同框架中描述可能不同，故推理引擎需为每个算子做独立定义。

（1）算子列表：算子是计算图的基本单元，代表卷积、池化、全连接等操作。建议控制在 200~300 个左右即可覆盖 95% 场景。PyTorch 有 1200 多个算子，TensorFlow 有 1500 多个，但推理引擎不必全部实现。每个算子可能对应多个 Kernel，会影响引擎体积。

[PRE5]

（2）算子公共属性和特殊算子列表：不同算子需不同属性与参数，可用联合体在统一结构中存储信息，按算子类型选择对应成员。

[PRE6]

（3）算子的基础定义：算子对象包含输入输出索引、类型、参数、名称等信息，可清晰描述算子的功能与作用。

[PRE7]

### 3. 计算图整体表示
（1）定义网络模型：描述网络模型的整体信息，包括网络名称、输入输出张量名称、算子列表以明确执行顺序与算子关系，以及子图信息。
