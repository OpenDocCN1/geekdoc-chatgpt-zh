2）API 网关层：作为系统对外统一入口，集中处理外部流量，完成鉴权、授权、限流熔断、路由分发及日志监控等工作，从入口层守住安全与可维护性。
3）业务服务层：承载用户服务、内容服务、分析服务、计费服务等核心能力，以微服务方式拆分，使各单元可独立演进并弹性伸缩。
4）AI 引擎层：是智能中枢，内聚写作引擎、知识引擎与智能体编排系统，负责文本生成、知识检索及多智能体协同等核心智能任务。
5）基础设施层：提供底层支撑，涵盖关系数据库、向量存储、缓存、消息队列、对象存储与容器编排等云原生资源，为上层业务提供稳定运行底座。

该分层思路同时兼顾模块化与可维护，也让每一层能够单独扩容与优化。AI 引擎内部将写作、知识和智能体协作做了清晰区隔，便于对不同能力进行专项打磨。

#### 10.1.3 数据流转方案
数据在各组件间的流动效率，直接影响大模型产品的性能与用户体验。下面方案兼顾实时性、可靠性与可扩展性。

##### 1. 整体数据流设计
整体流向如图 10-4 所示。

[PRE0]

图示涵盖五种交互方式。
- 1）同步请求流：客户端经 API 网关向业务服务发起调用，业务服务触发写作引擎，并联动向量存储中的知识引擎处理后返回结果，是最基本的请求响应模式。
- 2）流式响应流：针对生成类耗时操作，采用增量返回机制，边生成边推送，提升交互体感。
- 3）知识检索流：知识引擎通过向量存储抽取相关信息，用于增强生成内容的准确性与相关度。
- 4）数据持久化流：业务服务将关键状态写入数据库，保证数据可恢复与可追溯。
- 5）异步事件流：日志记录、用户行为分析等非关键路径通过消息队列异步处理，减轻主流程压力。

该设计兼顾实时交互的流畅与系统的可靠性，流式响应让用户能即时看到内容生成过程，体验明显提升。
