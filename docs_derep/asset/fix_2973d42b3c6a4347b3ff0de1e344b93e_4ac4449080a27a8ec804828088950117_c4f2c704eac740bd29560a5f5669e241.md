在哔哩哔哩智能体 BiliAgent 的数据分析任务里，要把多阶段处理和智能解读串起来，LangChain 成为承上启下的关键组件。它一方面统一接入各类大模型，另一方面把检索增强生成的完整链路搭建起来，整体像搭积木一样模块化，每一块都支撑 Agent 稳定运行。

如图8.5所示，检索增强生成的运作方式是：用户提问先作为检索器的输入，在事先构建并固化的外部知识库中迅速定位高度相关的信息段，再把这些段落作为上下文注入到大型语言模型的提示词里，引导模型产出更准确且贴合上下文的回复。

[PRE0]

换个说法，RAG 的本质是用外部知识来补强基础模型能力的一种增强技术。宏观来看，基础模型在语言理解与推理上很强，但存在知识封闭的局限，只能依赖训练截止前的公开数据，很难覆盖行业垂直或时效性内容。若想让模型实时调取私有数据、按需引入背景信息，就必须建立一套信息流通机制，把高质量外部知识按需送入推理流程，这正是 RAG 架构诞生的初衷。其核心构造流程见图8.6。

[PRE1]

如图8.6所示，构建主要可拆为三步。

- **索引 Index**：这是离线执行的准备阶段。先对原始素材做清洗与抽取，把 PDF、HTML、Word 等不同格式统一转为标准纯文本。为贴合模型上下文限制，会把长文本切成更小可控的块，即分块，然后用嵌入模型把这些块转为向量表示，最后建立索引，把文本块及其向量以键值对形式保存起来，支撑高效可扩展搜索。
- **检索 Retrieval**：用户提问经编码模型生成语义向量后，在向量库中执行相似性搜索，取出前 k 个最接近的对象作为上下文。
- **生成 Generation**：把用户原始提问与检索到的补充上下文填入提示模板，最后送入 LLM 生成最终结果。

手写完整链路代码比较繁琐，LangChain 的封装让调用变得简洁。但仅复现标准流程在复杂任务中往往效果有限，优化很有必要。图8.7展示了 LangChain 已封装的高阶实现方案。

##### 1. 翻译查询
自然语言问题常语义复杂、表达不规范，直接检索命中率低。LangChain 提供输入问题改写机制，支持多查询生成多个等价表述以增强召回、RAG 融合把不同表述的检索结果聚合、分解把复杂复合问题拆成更小单元等策略，提升查询在语义层面与知识库的对齐度，让下游检索更精准。

##### 2. 路由
路由模块根据问题类型或语义特征挑选合适的检索路径与提示模板。主要包括：
- **逻辑路由**：依据问题结构选择数据库或查询方式。
- **语义路由**：把问题映射到向量空间，按语义相似度匹配合适的 Prompt 结构。

##### 3. 数据库的支持
在高级 RAG 构建流程中，底层可接入图数据库、关系型数据库和向量数据库三种类型。

[PRE2]

##### 4. 构建查询
面对自然语言问题时，系统会先按目标库类型生成结构化指令。
- **关系型数据库**：借助 Text-to-SQL 把自然语言转为 SQL 指令，并结合向量检索增强。
- **图数据库**：采用 Text-to-Cypher 生成图数据库查询语言，从知识图谱中抓取语义关联信息。
- **向量数据库**：使用 Self-query retriever 技术自动从问题中提取意图与元数据过滤条件，生成向量检索请求。

##### 5. 索引
高质量检索依赖优秀索引体系，LangChain 在索引构建中引入以下机制。
- **块优化**：按字符、段落、语义断点切分原始文档，提升嵌入效果。
- **多表示索引**：如 Parent+Summary+Dense 向量结构，让检索更全面。
- **专业嵌入**：结合微调或 ColBERT 等模型，生成更精准的领域向量。
- **层级索引**：如 RAPTOR，构建跨层级多抽象层的文档树，实现分层摘要索引。

##### 6. 检索
路由确定后进入实际信息检索，具体包括：
- **排名**：对候选文档做语义打分排序，方法包括 Re-Rank、RankGPT、RAG-Fusion 等。
- **细化**：首轮结果不理想时，可执行再检索或检索压缩。
- **主动检索**：依据首轮回答质量自动判断是否需要重写问题并重新检索。

##### 7. 生成
检索到文档后，大模型结合用户原始问题与增强上下文生成最终回答。LangChain 在生成阶段引入 Self-RAG / RRR 优化：生成过程中主动校验理解是否正确、信息是否充分，不足时触发再次检索与反馈。
