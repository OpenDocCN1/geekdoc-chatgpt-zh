### BiliAgent实战：LangChain驱动的RAG与B站数据闭环

在 BiliAgent 的数据分析场景里，完成多阶段编排与智能化解读，LangChain 是关键的基础设施。它负责把各种大语言模型统一纳入体系，同时把检索增强生成的整条工作流搭起来。整体搭建方式很像模块化拼装，每个组件都为 Agent 的稳定运行提供支撑。

RAG 的运行思路可以这样概括：用户发出的提问先进入检索模块，在预先持久化的外部知识库 Knowledge 中快速定位最相关的片段，随后把这些片段作为补充信息注入大语言模型 LLM 的 Prompt，引导模型给出更贴合、更精准的回复。

[PRE0]

换个视角，RAG 的本质是借助外部知识来扩充 LLM 能力的一种增强手段。从宏观上看，大语言模型在语言理解和推理上很强，但存在知识封闭的局限，只能基于训练截止前的公开信息做推断，很难覆盖行业垂直或即时性的内容。若要让模型能够实时调取私有数据、按需引入背景信息，就必须搭建一套信息流通机制，把高质量的外部知识即时送入推理链路，这正是 RAG 架构诞生的初衷。其整体构建脉络如图 8.6 所示。

[PRE1]

如图 8.6 所示，RAG 的搭建大致可拆为三步。

- **索引 Index**：属于离线前置。先对原始材料做清洗与提取，把 PDF、HTML、Word 等格式统一转成标准化纯文本。为适配模型上下文长度限制，会把长文本切成更小易管理的块，即分块，随后用嵌入模型把这些块转为向量表示，最后建立索引，把文本块与向量以键值对形式保存，支撑高效可扩展的搜索。
- **检索 Retrieval**：提问进来后由编码模型生成语义向量，再在向量库中做相似性搜索，取出前 k 个最接近的对象作为上下文。
- **生成 Generation**：把原问题与检索到的增强上下文一并填入提示模板，送入 LLM 生成最终答案。

底层代码手写这套链路比较繁琐，LangChain 的封装让接口变得极简。但要注意，照搬标准 RAG 在复杂任务里往往效果不足，针对性优化很有必要。图 8.7 展示的就是 LangChain 已封装的高阶方案。

##### 1. 翻译查询
自然语言提问常语义绕、表达不规范，直接检索命中率低。LangChain 提供了提问改写能力，常见策略包括多查询生成多个等价表述以提升召回、RAG 融合把不同表述的检索结果做聚合与重排、以及分解把复杂复合问题拆成若干子问题，整体提升查询与知识库在语义层面的对齐，让下游检索更准。

##### 2. 路由
路由模块负责依据问题类型或语义特征挑选最合适的检索路径和提示模板。主要分为：
- **逻辑路由**：依据问题结构决定使用哪类数据库或何种查询方式。
- **语义路由**：把问题映射到向量空间，按语义相似度匹配对应的 Prompt 结构。

##### 3. 数据库的支持
在高级 RAG 流程里，底层可接入三类存储：图数据库、关系型数据库和向量数据库。

[PRE2]

##### 4. 构建查询
面对自然语言问题时，系统会先按目标库类型生成结构化指令。
- **关系型数据库**：借助 Text-to-SQL 把自然语言转为 SQL，再结合向量检索做增强。
- **图数据库**：采用 Text-to-Cypher 生成图查询语言，从知识图谱中抽取语义关联。
- **向量数据库**：使用 Self-query Retriever 自动从问题里抽取意图与元数据过滤条件，生成向量检索请求。

##### 5. 索引
检索质量取决于索引质量，LangChain 在建索引时引入多项机制。
- **块优化**：按字符、段落或语义断点切分，提升嵌入效果。
- **多表示索引**：如 Parent+Summary+Dense 向量结构，让检索覆盖更全。
- **专业嵌入**：结合微调或 ColBERT 等模型，生成更贴合领域的向量。
- **层级索引**：如 RAPTOR，构建跨层级多抽象层的文档树，实现分层摘要索引。

##### 6. 检索
路由确定后进入实质检索，具体包括：
- **排名**：对候选文档做语义打分排序，常用 Re-Rank、RankGPT、RAG-Fusion 等。
- **细化**：首轮结果不理想时可触发再检索或检索压缩。
- **主动检索**：根据初轮回答质量自动判断是否需要重写问题并再次检索。

##### 7. 生成
拿到文档后，LLM 会融合用户原问题与增强上下文生成答案。LangChain 在生成侧也引入 Self-RAG / RRR 优化：生成过程中主动校验理解是否正确、信息是否充分，不足时触发再次检索与反馈。
