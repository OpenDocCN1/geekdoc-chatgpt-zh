**对话变长了？用 /compact 快速瘦身**

OpenClaw 的会话都受上下文窗口上限限制。交流越久，历史负担越重，回复会变慢、成本上升，还有可能遗忘前面的信息。/compact 能把对话历史压缩成精华，腾出空间继续聊。

# 在会话窗口里直接输入，别当终端命令

/compact

## **5.1** **自定义 Skills：教龙虾自己造工具**

第四章学了安装别人写的 Skills，这一节学自己写。

自己写 Skills 看起来门槛高，其实本质是写一份工作指南——告诉龙虾“遇到这类任务，按这套流程走”，它就能记住并自动执行。

**从零搭建最小技能**

一个 Skill 的核心只有一个文件：SKILL.md。顶部是元数据，相当于技能身份证，下面是给 AI 的操作指南。看一个最简例子——查询公网 IP：

---

name: my-ip

description: 查询当前公网 IP 地址和地理位置

version: 1.0.0

---

# IP 查询技能

当用户询问 IP 地址或网络位置时，执行以下命令：

curl -s https://ipinfo.io/json

返回结果中包含 IP、城市、地区、国家、运营商等信息。

把文件放到 Skills 目录即可，有两种做法：

# 方式一：直接拷贝到技能目录，最快

cp -r my-ip ~/.openclaw/skills/

# 方式二：通过 clawhub 本地安装，更规范

clawhub install ./my-ip

**小贴士**

Skills 目录下的文件会在下次对话启动时自动加载，无需重启 Gateway。放好后新开对话，直接问“能帮我查 IP 吗”，看是否识别到新技能。

**实战：从零写一个“自动投简历”技能**

用真实案例说明。找工作每天要在多个平台重复投递，令人烦躁。我们写一个 Skill 让龙虾代劳。

**第一步：明确技能的目标**

写 SKILL.md 前先想清三件事：什么触发、怎么执行、输出什么。

（1）触发条件：用户说“投简历”“申请岗位”“帮我投这个职位”等。

（2）执行步骤：读取指定目录的简历→填写申请表单→提交→记录结果。

（3）输出结果：告知用户“已成功提交 X 个，失败 Y 个，详情见记录文件”。

**第二步：编写 SKILL.md**

可以自己写，也可以用 AI 快速生成。把触发条件、执行步骤、输出结果告诉 AI，再加一句“帮我生成一个 skill 包”即可。以下为 AI 生成示例。

---

name: auto-apply

description: 自动填写职位申请表单并提交，记录投递结果

version: 1.0.0

author: 你的名字

---

# 自动投简历技能

## 触发条件

当用户说“投简历”“申请岗位”“帮我投这个职位”等相关词语时激活。

## 工作流程

1． 读取简历文件

- 默认路径：~/Documents/resume/latest.pdf

- 若用户指定路径则使用指定路径

2． 分析目标职位

- 从用户提供的 URL 提取职位信息

- 识别：职位名称、公司、要求、申请表单字段

3． 智能填写申请表

- 用 Playwright 打开申请页面

- 根据简历内容匹配填写各字段

- 上传简历附件

4． 提交前确认

- 列出即将填写的内容让用户确认

- 收到确认后提交

5． 记录结果

- 将投递记录写入 ~/Documents/apply-log.md

- 格式：日期 | 公司 | 职位 | 状态 | 链接

## 注意事项

- 遇到验证码或需要账号密码的情况，暂停并通知用户

- 同一公司同一职位不重复投递（检查 apply-log.md）

- 每次投递后等待 3~5 秒，避免触发反爬机制

## **5.2** **长期记忆升级：再也不健忘**

第四章讲了 MEMORY.md 基础用法，但它有上限：纯文本、无结构，几千行后检索效率下降。

这一节介绍两个进阶方案：向量数据库记忆 LanceDB 和多 Scope 隔离，让记忆真正无上限。

**LanceDB：为龙虾装上向量记忆**

LanceDB 是本地向量数据库。安装后 MEMORY.md 内容会转成向量存储。对话时 AI 不再线性扫描文本，而是语义检索——想什么就找到什么，记忆条数再多也能精准命中。

# 安装 LanceDB 记忆插件

clawhub install lancedb-memory

# 初始化向量数据库，首次使用

openclaw memory init --backend lancedb

# 迁移现有 MEMORY.md

openclaw memory import ~/.openclaw/workspace/MEMORY.md

装好后变化：

（1）主动检索：回复前自动检索相关记忆，无需手动提醒“记得上次说过…”。

（2）语义搜索：问“我上次提到的那个项目”，它能找到，即使原文使用的是项目名。

（3）无上限存储：向量数据库效率高，记忆增长不拖慢速度。

[PRE12]

**小贴士**

使用 LanceDB 后 MEMORY.md 仍保留，两者并行。LanceDB 负责快速检索，MEMORY.md 作为可读备份。建议每周运行一次 openclaw memory sync 保持同步。

**多 Scope 隔离机制：工作与生活记忆不混**

LanceDB 解决检索问题后，还会出现工作、生活、团队上下文混杂的问题。Scope 机制可按场景隔离记忆，互不干扰。

# 进入工作 Scope，仅用工作相关记忆

openclaw scope work

# 进入个人 Scope，私人助理模式

openclaw scope personal

# 进入团队 Scope，共享上下文

openclaw scope team

# 查看当前 Scope

openclaw scope current

不同 Scope 记忆完全隔离，切换 Scope 就像换一个身份。

**用户：**[work scope] 帮我看一下 OpenClaw 项目的 TODO 列表

[PRE13]

**用户：**[personal scope] 帮我看一下最近的购物清单

[PRE14]

工作和生活两套记忆，互不串扰，这才是真正的数字分身。

**噪声拦截机制：保持记忆干净**

长期使用后记忆会积累重复、过时、无意义的操作记录，噪声多了反而影响检索效果。噪声拦截可在写入前过滤掉无价值内容。

在 SOUL.md 中加入记忆过滤规则：

## 记忆过滤规则

以下内容不写入长期记忆：

- 单次查询结果（天气、股价、新闻等时效性信息）

- 临时性指令（“帮我看一下”“现在搜索”等一次性任务）

- 已完成且不再相关的任务记录

以下内容必须写入长期记忆：

- 用户明确说“记住”的偏好和规则

- 项目的关键决策和背景信息

- 反复出现三次以上的操作模式

- 重要的错误教训（来自 self-improving-agent）

# 让 AI 自动整理压缩记忆
