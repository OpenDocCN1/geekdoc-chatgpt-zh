OpenClaw 智能体编排与路由

在 openclaw.json 这种配置里，全部智能体都是透过 agents.list 数组逐条注册的。每个成员最少要有一个唯一的 id，剩余的配置都可以直接套用 agents.defaults 里设定的全局默认值。下面这段配置示范了三台相互独立运行的智能体。

{
"agents": {
"defaults": {
"model": "claude-sonnet-4-20250514",
"tools": {
"profile": "coding"
}
},
"list": [
{
"id": "main",
"agentDir": "~/.openclaw/agents/main",
"workspace": "~/projects/main-workspace",
"bindings": [
{ "channel": "whatsapp" },
{ "channel": "telegram" }
]
},
{
"id": "work",
"agentDir": "~/.openclaw/agents/work",
"workspace": "~/projects/work-workspace",
"model": "gpt-4.1",
"tools": {
"profile": "full",
"allow": ["group:nodes", "group:automation"]
},
"bindings": [
{ "channel": "slack" },
{ "channel": "discord", "guildId": "my-work-server-id" }
]
},
{
"id": "community-bot",
"agentDir": "~/.openclaw/agents/community",
"workspace": "~/projects/community-workspace",
"model": "gpt-4.1-mini",
"tools": {
"profile": "messaging",
"deny": ["group:fs", "group:runtime", "group:automation"]
},
"sandbox": {
"mode": "all",
"scope": "session"
},
"bindings": [
{ "channel": "discord", "guildId": "my-community-server-id" }
]
}
]
}
}

上面这套设定共出现了三条独立的智能体。

• main 智能体扮演个人助理，统一收纳 WhatsApp 与 Telegram 的私聊请求，并凭借内置的文件读写等工具处理日常事务。
• work 智能体侧重工作场景，对接 Slack 与指定 Discord 服务器的工作消息，采用更强的 GPT-4.1 模型，并开放更完整的工具使用权限。
• community-bot 智能体面向社区运营，只处理对应 Discord 服务器的消息。为控制成本选用更经济的 GPT-4.1 Mini，工具权限被严格收紧，全部运行在隔离沙箱里，以降低安全风险。

每台智能体都有专属的 workspace，从根本上实现物理隔离。举例来说，main 的核心记忆文件 MEMORY.md 与协作文件 AGENTS.md 对 work 完全不可见，个人信息与工作信息互不交叉。work 的对话历史以 .jsonl 形式单独保存在 ~/.openclaw/agents/work/sessions/ 目录，与 main 的历史记录彻底分离，不会相互干扰。

此外，各智能体都可以拥有独立的 SOUL.md，从而在不同场景下呈现截然不同的语气与交互风格，使用体验更自然专业。

模型可以在智能体间自由搭配，灵活性很高。需要深度推理的任务例如代码审查、复杂分析，建议优先使用 Claude Sonnet 或 GPT-4.1 等旗舰模型，保证输出质量。面对高频低复杂度的场景例如社区答疑、简单查询，可以切换到 GPT-4.1 Mini 或 Gemini 2.5 Flash，在保持基本水准的同时大幅压缩成本。若涉及个人隐私或商业机密，还可以配置 Ollama 驱动的 Llama 3、Qwen 等本地开源模型，从源头消除数据外泄风险。

**3.4.2** **子 Agent 与任务委派**

OpenClaw 还支持更高级的协作形态：子智能体。主智能体在处理复杂任务时，能把特定子任务分派给专精的智能体执行，待结果返回后再继续后续推理。

子智能体的创建依赖 sessions_spawn 工具，典型流程如下。

1. 系统为子任务新建独立会话，sessionKey 遵循 agent:<childAgentId>:sub:<parentRunId> 的格式，保证上下文隔离。
2. 主智能体把任务描述发送过去，触发子智能体的 Agent Loop 独立运行。
3. 子智能体在独立环境里完成任务后，通过 sessions_send 安全回传结果。
4. 主智能体接收结果并融合进自身上下文，继续后续逻辑。

以编码委派为例，假设存在通用助理 main 与专业编码智能体 coder。当用户在 WhatsApp 说“帮我写一个爬取 Hacker News 首页的 Python 爬虫”时，main 会把任务交给 coder。

用户（WhatsApp）: 帮我写一个爬取 Hacker News 首页的 Python 爬虫

main Agent 思考：这属于代码类任务，适合交给 coder 处理。

main Agent 调用工具：
sessions_spawn({
agentId: "coder",
message: "请编写一个 Python 爬虫，爬取 Hacker News 首页（https://news.ycombinator.com）的所有文章标题、链接和评论数，并将结果保存为 CSV 文件。要求：使用 requests+BeautifulSoup，代码需要有完整的错误处理，并在沙箱中测试通过。",
waitForCompletion: true,
timeoutMs: 300000
})

coder Agent 运行：抓取首页 HTML、编写解析代码、沙箱内测试、修复 Bug、返回成品代码与测试结果

main Agent 接收结果后整理格式回复用户。

这种多智能体协同带来明显优势。

• 专业化，每个智能体可针对特定领域深度调优，配置专属 System Prompt 与工具集，在职责范围内发挥最大效能。
• 安全隔离，高风险任务如代码执行被放到 coder 这类专用智能体在独立沙箱中完成，避免污染主智能体的工作空间。
• 并行可能，理论上主智能体可同时把多个独立子任务分给不同智能体并行处理，当前以串行为主，为未来并行优化奠定架构基础。

实际调用时可参考以下参数示例：
{
"tool": "sessions_spawn",
"params": {
"agentId": "coder",
"sessionKey": "optional-custom-session-key",
"message": "任务描述",
"waitForCompletion": true,
"timeoutMs": 300000,
"context": {
"parentRunId": "run-abc123",
"sharedFiles": ["/path/to/shared/file.txt"]
}
}
}

子智能体的工具权限完全由自身配置决定，不会继承自主智能体。这是关键的安全设计：即使主智能体权限很高，也无法借助子智能体绕过限制。如需让子智能体权限高于主智能体，必须在子智能体的配置中显式授权。

**3.4.3** **群组与渠道的精细化路由**

除私聊 DM 外，OpenClaw 也能对群组消息做精细路由，这对管理 Discord 或 Telegram 群组非常实用。Discord 群组路由示例如下：
{
"channels": {
"discord": {
"accounts": [
{
"id": "my-bot",
"token": "${DISCORD_BOT_TOKEN}",
"dmPolicy": "pairing",
"groups": {
"*": {
"requireMention": true,
"agentId": "community-bot"
},
"admin-channel-id": {
"requireMention": false,
"agentId": "work",
"allowFrom": ["admin-role-id", "moderator-role-id"]
}
}
}
]
}
}
}

在此策略下，所有 Discord 群组消息默认送给 community-bot，且必须用 @ 提及机器人才会触发，避免过度响应与 Token 浪费。

针对特定的管理员频道 admin-channel-id，消息直接路由给权限更高的 work 智能体，无需 @ 提及，但会通过角色过滤，仅允许拥有 admin-role-id 或 moderator-role-id 的授权用户交互。

群组场景中 requireMention: true 是重要安全项。它确保智能体只回应明确 @ 它的消息，不会处理群里每一条内容，既省 Token，也能防范间接提示词注入攻击。

OpenClaw 还支持按内容过滤，只处理符合条件的消息，例如：
{
"channels": {
"telegram": {
"groups": {
"*": {
"requireMention": true,
"filter": {
"minLength": 10,
"maxLength": 2000,
"allowMedia": false
}
}
}
}
}
}

该配置限定只处理长度在 10 到 2000 字符之间的纯文本，忽略图片、视频、语音等媒体，有效遏制通过大量媒体消耗 Token 的攻击行为。

**3.5** **工具系统深度解析**

工具是智能体与外部世界的唯一交互接口。掌握 OpenClaw 的工具体系，有助于更合理地分配权限，也为后续开发自定义工具提供清晰思路。

**3.5.1** **内置工具全景**

OpenClaw 内置工具覆盖文件操作、系统运行、网络访问、会话管理、消息通信、记忆存储、自动化调度、UI 控制与节点互联等全场景。以下是主要分类与说明。

1．文件系统工具
提供文件的全生命周期操作，包括读取、覆盖写入、精准编辑、补丁应用、路径匹配与内容检索，满足代码修改、配置更新、日志查询等需求。该组受 tools.fs.workspaceOnly 约束，开启后只能访问工作空间目录，形成严格的安全边界。文件系统工具详情如表 3-3 所示。
