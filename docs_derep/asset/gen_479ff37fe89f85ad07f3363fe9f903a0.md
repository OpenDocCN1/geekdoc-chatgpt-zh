## 5.2 开发风险如何规避

Cursor 能大幅提高效率，但它生成代码也可能因逻辑偏差、依赖冲突等引入隐患。下面介绍规避方法。

### 5.2.1 别盲目点 Accept all

“Accept all” 确实省事，但不加甄别地全部接受 AI 的改动，可能导致质量下降、引入安全漏洞，甚至破坏项目稳定。

1. **主要风险**

   - 逻辑问题：AI 可能产出不符合业务的代码，比如错误的支付逻辑或过时的库引用，造成功能异常或安全风险。
   - 文件改动风险：批量修改时容易误改敏感信息，引发依赖冲突，或破坏团队统一的代码风格。

2. **安全实践**

   - 测试验证：对业务逻辑和安全相关代码如认证、支付，必须人工测试验证后再接受。
   - 工具辅助：结合静态分析工具检查语法与规范，弥补人工评审的盲区。
   - 权限控制：关闭“自动执行修改”，限制 AI 对配置文件、核心模块等关键文件的写入权限。

3. **可接受场景**

   - 简单格式调整，如缩进、补分号。
   - 安全依赖的非高危漏洞修复。
   - 模板化代码。

### 5.2.4 训练 Cursor 自我复盘

开发过程中让 Cursor 自我反思，能明显提高代码质量、优化流程并规避错误。通过让 AI 回顾分析已有代码，开发者能更稳当地掌控进度。可以在提示词中明确要求自我反思。

> 向 Cursor 提问

（2）缺少表单状态反馈。

（3）安全问题。

缺少防止自动提交的机制。

（4）用户体验不佳。

注册表单缺少加载状态，提交后没有“处理中”反馈。

无法在表单中切换密码可见性。

发现问题后，可让 Cursor 针对性修正。例如对表单状态反馈不完善，可说：

> 向 Cursor 提问
