# Coze Skills + OpenClaw 实践：从零构建专属 AI 代理

## 内容提要
本书围绕 Skill 展开，阐明如何依托国产低代码工具 Coze 来搭建并使用 Skill。全书结构分为五大板块。首板块为基础引导，厘清代理与 Skill 的关系，并演示 Coze 平台与 Coze 空间的基础操作；随后三板块为实战演练，通过六个由简到繁的项目覆盖纯文本与图文型 Skill 的制作，涉及直播话术复用、股票技术研判、公众号配图、小红书图文生产、PPT 智能助手以及数字营销 GEO/SEO 技能库等高频场景。每个案例都呈现经验梳理、SKILL.md 撰写、联调上线到在 Coze 空间调用的完整链路，让没有技术基础的读者也能像用提示词一样驾驭 Skill。第五板块聚焦 OpenClaw 的部署与实战，说明 OpenClaw 在 Coze 编程中的接入方式，以及基于 OpenClaw 增添与使用 Skill 的操作。

## 前言
2025 年，AI 代理开始从验证走向规模化落地，蚂蚁阿福等原生产品的出现表明代理正突破聊天局限，成为新生产力形态。但门槛问题仍拦住多数非技术用户。即便有 Coze、Dify 等低代码工具，要打造适配垂直业务的专家级代理，仍需跨越两道鸿沟。

第一道是复杂的工作流编排。节点设计、数据流转与条件判断本质仍是图形化编程，对没有编程基础的人操作繁琐易错。第二道是技术协议使用门槛。若要让 Coze 空间接入垂直领域知识，需依托模型上下文协议 Model Context Protocol，MCP 编写工具代码。

通俗说，MCP 就像为代理提供统一的 USB 接口。此前工具接入缺乏统一规范，A 开发者做的工具往往只能用在自己开发的代理上。MCP 让工具与代理实现标准化互通，只要双方遵循规范即可无缝对接。可惜 MCP 仍需代码实现，对非程序员仍是障碍。

真正的转机出现在 2025 年底。Anthropic 发布 Skills 功能，开启 AI 应用零代码定制的序幕。Skill 本质是可复用的经验沉淀，一份指导代理正确完成任务的提示词文档，无需写代码即可让通用代理变为股票分析专家、PPT 架构师或小红书爆款图文作者，将个人经验快速转化为生产力。

初期 Skill 未开源，仅限 Anthropic 自家 Claude Code、Claude 桌面版使用，与国内场景脱节。直到 2026 年 1 月，情况被打破：Skill 开源后获得 Coze 官方深度集成，国内用户才迎来真正贴合本土场景的无代码环境。

此次升级带来两大突破，也是本书诞生的契机：升级后的 Coze 开发平台更名为 Coze 编程，摆脱低代码束缚，全面拥抱 AI 原生自然语言编程，用户仅用日常对话即可完成代理、工作流、Skill 的全流程开发；升级后的 Coze 空间更名为 Coze，新增技能商店功能，用户在与代理对话时可直接加载官方、社区或自研 Skill，实现即调即用。

简言之，Coze 编程是开发代理与 Skill 的工厂，Coze 本身则是开箱即用的通用代理，可直接用自然语言解决问题。

本书旨在帮助非技术读者无缝衔接此次升级，以最低理解成本玩转 Skill。我们以 Coze 系列产品为核心工具，用通俗语言与落地项目，帮助你把个人经验与业务逻辑转化为可自动执行的 AI Skill，让通用代理变为专属专家助手，让技术退后，让创意与经验前移。

## 1.1 代理概述
过去两年，“AI Agent”或“智能体”是否反复刷屏？是否尝试过用 Coze、Dify 搭建自己的代理应用？

随大模型能力持续跃升与代理设计模式的成熟，代理正经历深刻变化：它不再是程序员的专属玩具，而是逐渐演变为普通人也能轻松上手、按需定制的实用工具。正如“旧时王谢堂前燕，飞入寻常百姓家”——昔日高居技术殿堂的代理，如今已走进大众日常工作与生活。

本节帮助读者快速建立认知，为实践创新打基础。

### 1.1.1 代理的本质
本质上，代理是一种让大模型更聪明、更能干的方法——通过赋予目标感、规划能力与工具调用权限，使其从被动应答转向主动执行。

一个形象的比喻来自武侠小说。主角临危受命完成复杂任务，临行前高人递给他三个锦囊，嘱咐在特定时刻开启依计行事。主角并非全知全能，却凭借预设策略与时机判断化险为夷。

在这个故事中，主角原本只是听话的执行者，如同基础大模型，一旦获得何时使用何种策略的框架，就具备了自主决策与行动能力——这正是代理的核心。

三个锦囊相当于代理中的 Skill 或工具调用能力，主角对情境的判断与锦囊调用逻辑构成代理的推理与规划机制。高人并未全程操控，却通过结构化赋能，让主角从工具升格为代理。

因此，“把大模型变成代理”本质就是为其配备一套可组合、可触发、可执行的 Skill，让它在复杂动态的真实场景中，像武侠主角一样有策略、有步骤、有应变地完成任务。

### 1.1.2 代理的发展路线
代理的演进并非凭空而来，其雏形可追溯至 2024 年初 OpenAI 在 ChatGPT 推出的 GPT Store，允许普通用户开发定制化 ChatGPT。开发方式是上传自定义工具如天气查询、股票查询的使用说明，对话时 ChatGPT 可自主决定是否调用工具解决。

该机制极大拓展了 ChatGPT 边界，用户可创建体育赛事助手、投资分析机器人等垂直应用。GPT Store 迅速激发社区创造力，也奠定了“大模型+工具=代理”的基本范式。

随后 Coze、Dify 等国内平台跟进并优化，提供更友好可视化界面与更丰富工具集成，进一步降低构建门槛。

但人们很快发现，仅能调用工具的代理在面对复杂逻辑问题时力不从心。例如“2024—2025 赛季 NBA 总冠军球队主教练的父亲叫什么名字”需要依次查询冠军球队、主教练、父亲姓名等多步推理。早期工具调用型代理常因缺乏整体规划而中途迷失。

为突破瓶颈，2024 年中后期，ReAct、Plan、Reflection 等从论文中发展出的增强推理设计模式开始被工程化实现。它们引导大模型显式生成中间推理步骤、制定任务计划，并在执行后自我校验修正，显著提升复杂任务准确性。

新挑战随之而来，随着任务复杂与数据增多，大模型上下文记忆成为瓶颈。记忆过载会导致中断任务。于是如何扩展记忆能力，如摘要压缩等，也成为研究核心。

至此，代理从最初的工具调用者，逐步进化为具备计划、执行、反思与记忆能力的复杂系统，为 2025 年大规模产业落地奠定基础。

## 1.2 主流代理实现形式介绍
上节介绍了代理本质及其从工具调用到自主推理再到具备记忆能力的演进。本节进一步介绍业界主流的几种代理形态，帮助读者见形知用、按需选择。

### 1.2.1 工具调用类代理
目前市面上最常见、适用范围最广的代理属基础工具调用类。核心目标是让大模型不仅能“说”，还能“做”——通过自主规划决定调用外部工具如搜索接口、数据库、计算器、API 等完成具体任务，从被动问答升级为主动执行。

实现路径上主要有两种范式：Function Calling 与 ReAct。

Function Calling 可理解为大模型出厂前练就的基本功。就像习武之人日复一日扎马步、练套路，形成肌肉记忆，遇到合适场景自然准确使出对应招式。

ReAct 则是在后天通过提示词工程引导大模型具备工具调用能力，无需基本功。类似《天龙八部》逍遥派掌门无崖子将八十载内力注入虚竹，虚竹虽未苦修却瞬间拥有顶尖高手内力。

二者殊途同归，都能赋予工具调用能力，但底层逻辑与适用条件不同。

工具调用类代理实现简单，对不太复杂的问题如“今天天气”“今晚比赛场馆附近烧烤店”效果很好，因此在 Coze、Dify 等产品的基础代理模式中得到应用，其设置页面如图 1-2 所示。

### 1.2.2 深度思考型代理
深度思考型代理是当前演进的高阶形态，典型代表包括 DeepResearch、Manus、Coze 等。这类代理不再满足快速响应或单步调用，而是模拟人类专家解决复杂问题的流程，堪称代理全能选手。

与基础工具调用类不同，深度思考型代理接收任务后不会急于执行，而是启动结构化多阶段认知引擎。其执行流程如图 1-3 所示。

1. 意图识别：解析用户输入，不仅理解字面，更捕捉背后真实需求。
2. 生成执行计划：基于意图制定详细分步计划。
3. 反馈人类：暂停执行，将计划呈现给用户审核，待反馈后再恢复。
4. 执行计划：用户确认后开始执行，灵活组合搜索引擎获取实时信息、调用工具获取垂直信息、必要时自动生成并运行代码如数据清洗、回测策略等。
5. 反思与重新规划：执行完成后进行反思，检查逻辑是否闭环、数据是否矛盾、结论是否充分。若发现漏洞会主动修正计划、补充调研甚至重执行，直至输出可信。
6. 记忆：为应对上下文长度限制，这类代理通常配备外部记忆机制，将关键中间结果、最终报告、执行摘要持久化存储，避免重复劳动，也为未来相似任务提供参考，相当于为用户构建可积累可复用的个人知识库。

可以说，深度思考型代理是对 2023 年以来代理技术的综合应用。

对于需要处理研究分析、商业决策、技术开发等高复杂度任务的用户而言，深度思考型代理已不再是简单助手，而是一位具备专业素养、严谨方法论与持续学习能力的研究员。
