RAG 的本质，是让大语言模型在生成答案时能够引入来自真实世界的外部信息，从而显著提升输出的可靠性和时效性。可以说，当前绝大多数基于 LLM 的应用都内置了这套机制。最主流的实现依赖向量相似度来做检索，业内通常把它叫做基线 RAG。

在企业私有数据的推理场景里，RAG 的价值非常突出，比如专有研究资料、业务文档、内部通信记录等。只是基线 RAG 也存在明显短板：当问题需要融合多处信息并提炼出新的洞察，或是面对海量复杂文本做整体性总结与理解时，它往往抓不住全貌，对大体量数据集或单篇长文档的全局语义把握不足。

针对这些局限，社区一直在做方法上的延展。微软研究院推出的 GraphRAG，就是一个典型代表。它借助 LLM 从原始文本中抽取实体关系构建知识图谱，并结合社区层面的摘要与图学习结果来丰富查询提示。在复杂推理和智能化程度的对比上，GraphRAG 相较基线 RAG 有明显提升，特别适合对私有知识库做深度分析。

> ### 说明

值得注意的是，**GraphRAG生成的知识图谱结构具有一定的不确定性和动态性。**

不同大语言模型在处理同一文档时，可能会识别出不同的实体节点或语义关系。即使是同一个模型，在不同运行批次中，也可能因上下文边界切分、token数量微调等因素，生成略有差异的知识图谱结构。

GraphRAG的索引流程中包含了诸如“社区总结生成”和“节点描述生成”等LLM参与的生成性步骤，这些步骤在默认配置下**非确定性执行**。因此，两个完全相同的数据源，在不同的时间点执行graphrag index命令，也有可能输出不同数量的节点、不同权重的关系，乃至不同社区划分粒度。

若对一致性有强依赖（例如自动评测或持续集成场景），建议固定temperature以设定确定性参数，并保存图谱快照以便复用。
