Wikidata 的知识组织以若干核心构件为骨架，囊括页面 Pages、实体 Entities、条目 Items、属性 Properties、陈述 Statements、限定符 Qualifiers、引用 References 等。体系继承自 Wikipedia，因而同样把 Page 页面作为基础组织单元。Entities 可看作 OWL 中 Things 的上层概念，指代图谱最顶层的对象，每个 Entity 都有独立的维基页面。Entities 拆分为两类：Items 与 Properties。Items 对应 RDF 中的 Instance，用来指代具体实例。Properties 与 Statements 则分别对应 RDF 中的 Property 与 Statement。Item 页面一般还会收录多组别名 aliases 以及指向 Wikipedia 的站点链接 Sitelinks。

每个 Entity 下可挂载多条 Statement。Statement 由一个 Property、若干值 Values、若干 Qualifiers、若干 References 以及用于区分重要程度的 Rank 共同构成。

限定符用于补充多元情境。以“spouse: Jane Belson”为例，这本身是二元关系，通过 Qualifiers 可叠加额外限定来刻画多元信息，比如“start date: 1991 年 11 月 25 日”“end date: 2011 年 5 月 11 日”。

引用用来标明每条陈述的来源，比如来自某篇 Wikipedia 页面。引用本质上也是一种 Qualifiers，通常作为附加信息挂在 Statement 下。

取值层面，Wikidata 兼顾多种形式，包括自有的 Item 类型、RDF 字面量 Literal、URL、Commons Media，以及 Time、Globe coordinates、Quantity 三类复杂类型。

系统为每条 Statement 提供三种可信等级：默认的 normal、更可靠的 preferred、已作废的 deprecated。

在陈述的具体形态上，划分为三种 Snack：PropertyValueSnack、PropertyNoValueSnack、PropertySomeValueSnack。PropertyNoValueSnack 用于表达否定式知识，如“伊丽莎白一世没有配偶”。PropertySomeValueSnack 用于表达存在但未知的情况，如“林修斯教皇有出生日期，但目前未知”。

URI 设计遵循 Linked Open Data 规范，采用统一写法 http://www.wikidata.org/entity/<id>。其中 <id> 可以是 Item 如 Q49，也可以是 Property 如 P234。

## 2.5 知识图谱的向量表示方法
前文介绍的是离散符号化的表达方式，本节介绍把实体和关系映射到低维连续向量空间，而非继续使用离散符号。

# 2.5.1 知识图谱表示的挑战
既往的多种方案大多以三元组为基础组织知识。在知识库网络中，节点对应三元组的头实体与尾实体，边对应三元组的关系。离散符号化在结构化数据上效率很高，但在海量应用中会遇到瓶颈。

知识以离散符号表达时，符号本身无法承载语义，也难以进行语义计算，对下游任务并不友好。在图结构上应用算法时，因图特性多依赖图算法，复杂度较高，难以在海量数据上扩展。

数据存在长尾稀疏问题，实体与关系在现实图谱中分布不均，部分实体或关系仅有极少样本，会拉低应用准确率。

综合来看，面对数据体量大、应用场景多样的知识图谱，传统表示方式需要改进。

# 2.5.2 词的向量表示方法
在讨论图谱向量表示前，先回顾词的表示思路。自然语言处理中，离散符号化的词不蕴含语义，因此常把词映射到向量空间，便于计算且映射过程中向量可携带语义。知识图谱的向量表示借鉴了这一思路。

# 1. 独热编码
传统的 One-Hot Encoding 把词展开成一个很长的向量，向量维度等于词表大小。对某个具体词，其向量中仅在对应编号的维度上为 1，其余为 0。如图 2-19 所示，若 Rome 编号为 1，则其编码只有第 1 维是 1，其余皆为 0。该方法实现简单，但不包含语义信息，稀疏性极强，词典越大向量越庞大。

# 2. 词袋模型
Bag-of-Words、BoW 是对文本中词的一种计数式表示。把文本想象成装词的袋子，不考虑词序与上下文，仅统计每个词在该文本中出现的次数。具体流程是先汇集所有文本的可见词汇组成词典，给词编号，再用一个记录各词出现频次的向量来表示文本，该向量每维数值即对应词在该文本中的出现次数。如图 2-20 所示，在 doc_1 中 Rome 出现 32 次，Paris 出现 14 次，France 出现 0 次。

### 2.5.1 连续词袋模型
该模型忽略词序，核心思想是用上下文预测中心词，从而让训练出的词向量蕴含上下文信息。如图 2-21（a）所示，wₙ 为中心词，wₙ₋₂，wₙ₋₁，wₙ₊₁，wₙ₊₂ 为其上下文。将上下文词的独热表示与词向量矩阵 E 相乘得到各词向量求和形成投影层，再经 Softmax 输出，输出每维代表词表中每个词作为该上下文中心词的概率。训练时模型像滑动窗口在语料上移动，故称连续词袋模型。

### 2.5.2 Skip-gram 模型
Skip-gram 与 CBoW 思路相反，用中心词预测上下文。如图 2-21 （b）所示，先通过中心词的独热表示从词向量矩阵中取出词向量形成投影层，再经 Softmax 得到输出，输出每维表示某个词作为输入中心词上下文出现的概率。

训练完成的词向量在连续空间中会呈现可解释的关系，如图 2-22 所示。

vec(Rome) - vec(Italy) ≈ vec(Paris) - vec(France)

可以看出 Rome 与 Italy 之间存在 is-capital-of 关系，Paris 与 France 之间也有相同关系。通过对两对语义关系相同的词向量做相减得到相近结果，说明词向量具备空间平移性，is-capital-of 这类关系可以近似平移到其他类似词对之间。

### 2.5.3 知识图谱嵌入的概念
为解决前述表示挑战，受词向量启发，研究者尝试把知识图谱中的实体和关系映射到连续向量空间并保留语义信息，以便在问答、关系抽取等下游任务中更方便操作。对计算机而言，连续向量能携带更多语义，更易理解与处理。该方向即知识图谱嵌入 Knowledge Graph Embedding，也称知识图谱向量表示、表示学习 Representation Learning、知识表示学习。

与词向量相似，知识图谱嵌入也是通过机器学习训练模型。与独热编码、词袋模型相比，其训练基于监督学习。训练过程中可以学习语义层信息，且词向量的空间平移性同样适用。经典模型 TransE 的设计思想是，若三元组（h, r, t）成立，则需满足 h+r≈t，例如：

vec(Rome) + vec(is-capital-of) ≈ vec(Italy)

### 2.5.4 知识图谱嵌入的优点
研究者转向嵌入方法，是因为向量表达的实体关系相比传统方法有明显优势。

向量表达提升计算效率，映射到向量空间后算法可用数值计算，效率同步提高。

丰富下游应用设计。向量表示后知识图谱更适配当前主流的机器学习方法，如神经网络等。输入不再是符号，可选方法也不局限于图算法。

把知识图谱嵌入作为下游任务的预训练向量输入，使输入信息不再是孤立无语义的符号，而是已训练并包含一定信息的向量。

总体而言，知识图谱嵌入能提高计算效率、拓展下游应用、提供语义预训练，具有很高的应用价值与前景。

### 2.5.5 知识图谱嵌入的主要方法
多数模型依赖知识图谱中可直接观察到的信息训练，即基于所有已知三元组学习。对这类方法，常只需训练出的实体与关系表示满足训练三元组即可，但结果未必能完全满足所有下游任务。因此也有研究关注引入知识图谱之外的额外信息，如实体类型 Entity Types、关系路径 Relation Paths 等。

依据综述[11]，可将方法划分为：

### 1. 转移距离模型
转移距离模型 Translational Distance Model 的核心是把向量化后三元组的合理性问题转化为衡量头实体与尾实体距离的问题。关键在于设计得分函数，得分函数通常刻画利用关系把头实体转移到尾实体的合理性。

受词向量启发，可把知识图谱中头实体与尾实体的向量关系类比词与词的语义关系，即把两者映射到向量空间，其联系视为三元组中的关系。TransE 正是受词向量平移不变性启发，把实体和关系都表示为向量，对关系（head, relation, tail），把关系向量解释为头实体到尾实体的转移向量。若三元组成立，则需满足 head+relation≈tail。

### 2. 语义匹配模型
相比转移距离模型，语义匹配模型 Semantic Matching Models 更侧重挖掘向量化后实体与关系的潜在语义。该方向代表模型为 RESCAL 及其延伸。

RESCAL 的核心是把整个知识图谱编码为三维张量，再分解为核心张量与因子矩阵。核心张量中每个切片对应一种关系，因子矩阵中每一行对应一个实体。由两者还原的结果被视作三元组成立的概率，大于阈值则认为正确，否则错误。其得分函数可写成
