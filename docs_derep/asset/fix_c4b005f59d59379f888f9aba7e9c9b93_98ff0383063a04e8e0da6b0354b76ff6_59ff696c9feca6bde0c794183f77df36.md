## 第15章 RAG驱动的多智能体客服实践

本章围绕一套融合检索增强与多智能体协作的客服系统展开说明。系统在LangChain之上搭建，通过检索增强生成与多智能体分工，实现对客户提问的准确理解与结构化回复，覆盖文档问答、资料查询、库存核查等典型服务场景。

## 15.1 系统概述

本方案是以LangChain为底座的智能客服实现，核心在于检索增强与多智能体协同，目的在于提升复杂客服场景的响应速度与答复质量。

### 1. 核心定位

以阿里云DashScope平台提供的Qwen大模型作为推理引擎，多名专项智能体各司其职，负责产品咨询、库存查询、用户资料与订单查询等常见任务，最终给出结构化、准确的服务结果。

### 2. 技术架构特点

- (1) 分层协作：采用顶层调度与专项工具的分层设计，顶层智能体负责任务拆解与分发，下层工具智能体聚焦单一领域执行。
- (2) 检索增强结合：文档检索智能体可直接读取预置文档，如产品手册，基于真实资料生成回答，降低幻觉风险。
- (3) 轻量数据存储：用户资料、库存信息与文档均以CSV表格与文本文档保存，无需部署重量级数据库即可运行。
- (4) 一键初始化：首次启动时自动生成演示文档、演示用户与库存记录，并创建所需目录，降低上手难度。
- (5) 多轮上下文保留：借助 ConversationBufferMemory 记录交互历史，支持上下文延续与追问。

### 3. 核心功能模块

- (1) Qwen LLM封装模块：对Qwen大模型进行封装，提供统一的文本生成入口。
- (2) 文档检索智能体：读取本地文档内容并检索，解答产品使用方法等基于文档的问题。
- (3) 用户资料智能体：维护用户基础信息与订单历史，支持结构化查询。
- (4) 库存查询智能体：查询产品库存状态，返回数量与可售信息。
- (5) 顶层调度智能体：统筹各工具智能体，根据需求智能选择调用路径并生成最终回复。

### 4. 典型应用场景

- 1. 产品咨询，例如使用方法、功能细节说明。
- 2. 库存核查，例如是否在售、剩余数量。
- 3. 用户信息查询，例如会员等级、联系方式。
- 4. 订单查询，例如订单状态、物流进展。

## 15.2 系统架构

本系统采用分层智能体架构，通过多个专用智能体协同完成智能客服任务。整体结构如图15.1所示。

架构要点如下。

- 1. 分层关系：自顶向下共四层，上层调用下层能力，各层间通过统一接口通信。
- 2. 核心流转：请求先进入客户端交互层，由TopAgent解析意图后路由到对应工具智能体，工具智能体操作数据存储层完成后回传结果。

## 15.3 核心功能模块设计

### 15.3.1 核心功能模块设计流程

整体设计遵循“需求梳理→模块拆分→接口统一→协同机制→异常处理→系统集成”的路径：

- （1）需求梳理：明确产品咨询、库存查询、用户信息与订单查询等核心场景。
- （2）模块拆分：
  - 将功能映射为文档检索、用户资料、库存查询等专项智能体。
  - 设计顶层协调智能体负责分发任务。
- （3）接口标准化：
  - 定义ToolAgent基类，统一 get_tool() 接口。
  - 规范工具调用格式为JSON结构，明确参数传递方式。
- （4）协同机制设计：
  - 顶层智能体按React模式执行“分析问题→选择工具→调用执行→生成回答”。
  - 引入对话记忆保持上下文，支持信息延续。
- （5）数据初始化与异常处理：
  - 自动创建演示文档、用户数据与库存数据。
  - 完善文件缺失、API异常、参数格式错误等异常处理。
- （6）系统集成：
  - 汇总工具列表注入顶层智能体。
  - 设计 process_query 入口作为用户交互通道。

### 15.3.2 核心功能模块设计

#### 1. 自定义LLM模块（QwenLLM）

封装阿里云DashScope的Qwen大模型，作为系统推理核心。

[PRE1]

核心设计要点：

- 以LangChain LLM抽象类为父类，实现模型接入。
- 支持 temperature 与 max_tokens 等参数配置，控制随机性与输出长度。
- 具备完整异常捕获，API调用失败时返回友好提示。

#### 2. 工具Agent基类（ToolAgent）

为所有工具智能体提供抽象接口，实现设计统一。

[PRE2]

核心设计要点：

- 统一命名与功能描述，便于顶层智能体识别工具用途。
- 抽象 get_tool() 方法强制子类实现，确保与LangChain兼容。
- 为后续扩展提供模板，继承后实现抽象方法即可接入。

#### 3. 文档检索Agent（DocumentRetrievalAgent）

实现RAG核心能力，基于预置文档回答产品类咨询。

核心设计要点：

- 自动创建 docs 文件夹并生成演示文档，如智能手表使用说明。
- 将文件夹下所有TXT文档一次性载入内存，减少重复IO。
- 基于文档内容由Qwen模型生成答案，严格禁止信息编造。
- 工具描述明确限定使用场景为产品细节与使用方法。

#### 4. 用户数据库Agent（UserDatabaseAgent）

管理用户画像与订单记录，支持结构化查询。

核心设计要点：

- 以CSV文件保存用户数据，首次运行自动生成演示用户“张三”。
- 提供两种查询模式：user_info 获取基础信息，orders 获取订单历史。
- 自定义输入解析格式为 user_id:xxx,type:xxx，并做格式校验。
- 对用户不存在等边界情况返回可读提示。

#### 5. 库存查询Agent（InventoryAgent）

负责产品库存状态查询与可用性判断。

核心设计要点：

- 以CSV保存库存信息，字段包括产品ID、名称、数量、位置等。
- 自动判断有货或缺货，并返回结构化结果。
- 输入为产品ID，输出包含完整产品信息与库存状态描述。

#### 6. 顶层Agent（TopAgent）

系统调度中心，负责意图理解与工具调用编排。

核心设计要点：

- 集成全部工具智能体，形成工具池供决策使用。
- 使用 ConversationBufferMemory 保存历史对话，支持上下文理解。
- 自定义提示模板引导智能体执行“思考→选工具→执行→作答”流程。
- 基于 CHAT_CONVERSATIONAL_REACT_DESCRIPTION 构建，支持多轮交互。
- 提供 process_query 统一入口，可传入用户ID增强上下文。
