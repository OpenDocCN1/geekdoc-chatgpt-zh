### 4. 用 @file 与 @codebase 精准锚定上下文
随着工程体量增长，代码库会变得庞大而复杂，借助 @file 与 @codebase 指令能够有意识地引导助手注意力，确保生成内容与项目整体结构和编码习惯保持一致。

在小型仓库里助手可以自己把握全貌，但当文件数达到数十个、代码行数上千时，就需要给出明确指引。这有点像在藏书丰富的图书馆检索，要么指定某本专著，要么让管理员介绍整体分类体系，@file 与 @codebase 正是实现这种精准指向的两把工具。

@file 能把焦点收窄到当前打开的文件或选中的代码片段，适合单文件内的解释、纠错、补全；@codebase 则把视野扩宽到整个工程，覆盖所有文件与子目录，适合跨文件分析结构、梳理依赖或设计整体架构，有助于产出更贴合工程的代码。

下面用两个实操来演示用法。

- 案例1：用 @file 聚焦单个文件
如果你想让助手复查刚建的接口是否符合最佳实践，可以这样提问：
> 请审查 @app/api/hello/route.ts 中的实现，有无可优化之处。
通过 @ 符号明确位置，回答会更具针对性。

- 案例2：用 @codebase 做全局检查
若要确认项目配置能否兼容新接口，可提问：
> 基于 @codebase 审视整体配置，检查 TypeScript 与 ESLint 是否能正确支持刚才创建的 API 路由。
此时助手会读取 tsconfig.json、next.config.js 等配置文件，给出一份完整的工程健康报告。

本次实操的本质是体验对话式开发：你用自然语言描述战略目标，助手负责落地的战术细节。

## 4. 自动增强错误处理与数据校验
健壮的 API 需要优雅处理异常，可通过 Composer 迭代增强：先产出核心逻辑，再用精细指令补充错误处理与校验，提升接口的安全性。

- 增强错误处理：选中已产出的数据库操作代码，按 Ctrl/Cmd + K 输入“为这段代码添加详细错误处理。若 Supabase 返回唯一性冲突等特定错误返回 409，其他数据库错误返回 500”。Composer 会自动产出多场景错误处理代码。
- 添加数据校验：在 POST 函数开头按 Ctrl/Cmd + K 输入“在写入数据库前加入数据校验，确保 title 存在且不为空，校验失败返回 400 Bad Request 并给出清晰提示”。

##### 5. Composer Agent：一站式编程方案
以上所有步骤都可以用更高效的 Composer Agent 一次完成，按 Ctrl/Cmd + I 调出，其核心能力如下。

- 无需精确定位的智能改写：即使不使用 @ 符号指定，Agent 也能自动检索项目中最合适的改写位置。
- 从零到一的完整方案：通过描述完整需求，即可产出路由结构、数据库集成、中间件、错误处理、类型定义和环境变量配置的整体方案。
- 智能问题诊断与修复：描述问题如“API 返回 500 错误”，Agent 会协助排查修复。
- 跨文件复杂重构：支持“把所有数据库查询抽离到独立 service 层”或“为项目添加 Docker 支持”等复杂任务。

尽管功能强大，分步学习对初学者仍很重要，原因在于建立编程思维、提升需求表达能力、增强故障排查技能以及培养架构设计能力。

实际开发中可根据场景灵活选择工具。

- 快速原型阶段：用 Composer 代码生成模式快速搭框架。
- 学习探索阶段：用 IDE 编辑器产出和修改代码，深入理解实现细节。
- 问题解决阶段：用 AI 聊天助手深入讨论方案，获得技术指导。
- 复杂重构阶段：回到 Composer 代码生成模式，执行跨文件重构，保证架构一致性。

Composer Agent 不仅是代码生成工具，更像一位全栈技术顾问，能理解项目上下文、遵循最佳实践并提供完整方案。
