## 小波矩阵：加速检索的数据结构
在文本检索或数组元素查找的场景里，小波矩阵能够显著提升速度，图12-9展示了其思路。
需要先区分概念，小波矩阵和小波变换是两回事。
构建方式是从数值数组出发，以某个阈值做二分：大于等于的标记为1，小于的标记为0，于是得到两个子数组。随后对这两个子数组重复同样的二分操作，迭代后形成一棵只由0和1构成的二叉小波树，这棵树既可当作二进制文件读写，也可当作文本处理。
把上述数值以矩阵形式组织起来就称为小波矩阵。小波树和小波矩阵既能用于索引构建，也能用于图形网络分析，应用范围相当广泛。

## BWT 与 FM-Index：压缩检索的经典组合
在超大文本里找字符串时，BWT 块排序压缩配合 FM-Index 压缩查询算法能明显提高检索效率。
BWT 的做法是对待转换字符串做循环移位，每次移动一位，生成与字符数等量的循环串，再把所有循环串按字典序排序，并记录排序后每个循环串的最后一个字符，拼接后即为 BWT 输出。
块排序的日文维基里有 cacao 变换成 ccoa 的例子，重复循环排序可以把原始串还原。因为变换后相似字符会变得连续，BWT 很适合作为压缩预处理器，已被集成到 bzip2 中。若用朴素实现，变换后文本的内存需求会远超原文，所以算法加入了内存使用优化。
BWT 变换后的串可用于检索，此时原串会额外加上结束符号。

### 语义网络
让机器理解人类自然语言是人工智能的重要课题，但机器不可能完全掌握词语含义，人类也是在成长中通过相对关系逐步理解的。
机器在理解符号指称时出现的问题被称为符号接地问题，为此提出了语义网络，图12-10为示意。
语义网络是一个有向或无向图，顶点代表概念，边代表概念间的语义关系。
is-a 和 has-a 是两个核心关系，is-a 表示包含关系，has-a 表示属性或状态。例如 A is-a B 表示 A 是 B 的下位概念，B 包含 A；A has-a B 表示 A 处于 B 状态。

### 本体
自20世纪70年代中期起，为让机器自主获取概念，人们对构建概念体系即本体需求日益增长。
语义网络描述概念间语义关系，本体则是在此基础上加入元数据的描述模型。不同领域的本体描述实例、概念类、属性和关系。
> 小贴士 领域
领域指概念所属的特定范围，例如业务所需的知识和经验即领域知识。
本体间的语义关联有助于网页数据检索，检索某个词时其同义词或反义词也会被带出。这种基于概念语义进行网页信息检索和自动处理的技术即语义网。
本体在分子生物学已有十余年应用，研究基因时会基于其特性构建基因本体 Gene Ontology，GO 涉及的基因分为 biological_process、cellular_component、molecular_function 三大类，用于基因功能和相似性分析等，图 12-11。

图12-11 基因本体
2005年后，本体开始用于表达情感、颜色等接近自然语言的信息，计算机借此理解词与术语间的概念关联。构建本体实质是把因人、行业、领域和场景而异的词语概念进行共享和通用化。
未来要充分发挥本体作用，需要构建并开放庞大的本体知识库进行整合，这样面向人类的本体才能供计算机使用。

### 链接数据
进入21世纪，语义网领域开始用 HTML 标签创建网页、网站、文档间的连接关系数据库，检索质量进一步提升。
此过程中 SEO 和 OGP 等搜索引擎优化方法被完善，它们是目前让机器读取并解释信息最先进的技术。
通过“让机器读取并分享信息”的方法和技术表示的数据称为链接数据。
虽然该技术对数据本身和概念的作用并不明显，但2010年后围绕开放数据推进 LOD 关联开放数据的建设，现在日本的国情调查等统计信息也能作为 LOD 处理。

### RDF 与 SPARQL
RDF 即资源描述框架，是一种描述 Web 资源的标记语言，是处理元数据和实现语义网的重要技术。RSS 就是一个典型应用，RDF 扩展后可得到 OWL 网络本体语言，用于交换网站本体数据。
RDF 采用三元组结构。
SPARQL 是 SPARQL Protocol and RDF Query Language 查询语言，可跨 HTTP 查询，向 SPARQL 端点 URL 附加查询参数发送请求后可获得 XML 或 JSON 格式结果。

# 第13章 分布式计算
近年来机器学习和深度学习对数据量和处理速度要求越来越高，个人计算机或 GPU 扩展板可处理部分任务，但在某些场景下需要更大规模的分布式处理器。本章先介绍分布式计算环境，再说明分布式机器学习和深度学习平台。

## 第13章 | 分布式计算
## 01 分布式计算和并行计算
要点 ☑️分布式计算 ☑️并行计算
以前的计算机性能远低于现在，人们思考如何快速完成耗时处理，分布式计算和并行计算是主要解法之一。
两者都需要多台计算机配合完成耗时或大规模计算，因此相关系统被称作大规模计算机系统或大型计算机系统。
分布式处理的实现方式多样，例如通过网络连接多台计算机实现大规模处理，或在单机内部并行处理等。

### 网格计算
部分国家或高校的研究机构把多台计算机互联执行计算，这类系统被称为超级计算机，使用超级计算机等进行的超大规模计算称为高性能计算 HPC。
日本知名的超级计算机有“京”、TSUBAME 和地球模拟器等，节点数在100到80000以上，每个节点至少包含一个 CPU。
部分系统每个节点配备超高速内存，部分采用共享内存。为保证各节点可访问存储，通常使用 Lustre 文件系统等共享存储系统。为进行计算，多台计算机互联构成分布式计算系统的节点，称为网格计算机。节点间通过高速网络通信，对耐故障性要求高，因而常用 Infiniband 而非 LAN，图13-2。
[PRE9]
图13-2 共享存储系统
> 小贴士 Lustre文件系统
Lustre 有 MDS 元数据服务器，MDS 上有 MDT 元数据存储节点。系统中使用 OSS 对象存储服务器管理为文件对象数据提供存储的 OST 目标存储对象。Lustre 通过 RAID 等方式把 MDS 和 OSS 连接起来构建具有冗余的大型存储。
此外，与网格计算机和超级计算机类似的还有计算机集群。网格计算机可视为让多个集群作为通用基础设施使用的中间件。网格计算倾向于使用相同体系结构，通过纵向扩展提升单机性能来提升整体，而集群主要通过横向扩展增加机器数量提升性能。集群系统的机器在型号或操作系统上可有所不同。
SETI@home 是寻找外星智慧生命计划中的分布式计算项目，参与机器包括个人电脑，用户安装分析程序即可加入。
随着集群技术和虚拟化技术发展，AWS、GCP、Microsoft Azure 等的 PaaS 和 IaaS 逐渐普及。

### GPGPU
除运算外，CPU 还负责与芯片间数据交换、系统控制等。单 CPU 处理不了的运算可由协处理器辅助，FPU 是专门处理浮点运算的协处理器。早期 FPU 为独立芯片，后随集成度提升被集成进 CPU。图形协处理器因对运算速度要求不高而发展为独立显卡，面向 3DCAD、视频剪辑等用户。进入21世纪，图形加速器不仅能处理2D 还能高速处理纹理等3D图像并转为图像数据传输，其核心就是 GPU，图13-3。
[PRE10]
> 小贴士 DirectX
Windows 下显示图像开销较大，早期仅提供 GDI，引发诸多抱怨，于是出现 DirectX 和 OpenGL 等库让用户直接访问显卡硬件快速绘图。
GPU 专注图形计算，对矩阵运算等擅长，而 CPU 支持运算类型更多，在简单计算上并不占优。随着 CPU 处理任务增多，增加核心数会带来密度和发热问题，截至2016年通用 CPU 核心数仅约8个，而 GPU 核心数以千计。GPU 支持并行处理并配备专用显存 VRAM，因此基于 CUDA 平台的 GPU 可作为运算处理板，加速图像识别、语音识别等机器学习和深度学习任务。
