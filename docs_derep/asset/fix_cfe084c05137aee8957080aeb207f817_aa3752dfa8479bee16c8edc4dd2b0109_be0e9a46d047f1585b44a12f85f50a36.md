• 每次前向推理所需的全部输入节点和输出节点都归属到同一个 Bindings 对象里。在实例化阶段，系统会依据设定的 Shape 为每个节点提前划分主机端缓冲以及设备端缓冲。

• 推理请求到来时，调度器会从空闲池中挑出 Shape 匹配度最高的工作 Executor 来执行。如此既能复用该 Executor 内 Bindings 已预先分配好的存储空间，又能以最高效的方式完成推理。

• 推理结束后，该 Executor 会被归还到待调度队列，等待下一次指派。

• 把输入数据从 Host 搬运到 Device；
• 在 Device 上启动 Kernel；
• 把结果再从 Device 搬回 Host。

**4.提高 GPU 内计算访存比**

1）GPU 内存布局
按设备划分，存储分为 CPU 侧内存与 GPU 侧内存。GPU 内部呈现多级层次：
• 最外层是片外的全局内存；
• SM 内部包含 Shared Memory、L1 数据缓存与寄存器堆；
• 连接全局内存与 SM 的是 L2 数据缓存。

如图 5-27 所示，GPU 内存布局如下。
• 全局内存容量最大，以 A100 为例显存为 40GB，即通常所说的显存空间，传输带宽约 1.5GB/s。
• 再向内为 L2 缓存，在 A100 上为 40MB，传输带宽可达 7000GB/s。
• 再向内为片上存储 Shared Memory 与 L1 数据缓存。二者共享 192KB 空间，可配置二者大小。带宽可达 19TB/s。
• 寄存器堆是 GPU 中最快的存储，每个 SM 约有 64KB 寄存器。它是距离 Tensor Core 与 CUDA Core 最近的存储。

[PRE2]

图 5-27

推理时数据先从全局内存搬入寄存器，再由 Tensor Core 或 CUDA Core 在寄存器中完成计算，中间结果暂存在寄存器，最后写回全局内存。

2）FlashGemm
（1）GEMM 计算的痛点。模型推理中绝大多数计算是矩阵运算，若采用最原始的 GEMM 算法，因 GPU 全局内存带宽受限，大量读写会带来性能瓶颈。
（2）FlashGemm。为缓解 GEMM 对全局内存的高频读写，可利用 GPU 的分级内存架构，用带宽更高的共享内存与寄存器来分担全局访问。但共享内存与寄存器容量有限，无法容纳大块矩阵，于是采用数据分块、分级存储与分块计算的思路。FlashGemm 加速方案基于 Cutlass 实现的高性能矩阵计算方法，充分利用 GPU 多级内存体系 全局内存→共享内存→寄存器，实现了分块存储与分块计算，最大程度提升模型中矩阵计算的性能。
（3）数据分块。计算机内存是一维线性地址空间，而数学计算常处理高维空间。为更好表达高维空间并方便分块，可使用 Cutlass 中的 Layout 来描述矩阵。Layout 包含 Shape 与 Stride 两个概念。Shape 表示矩阵维度，Stride 表示步长，可表达行优先或列优先存储。

使用 Layout 描述矩阵后，便可通过指定坐标完成 Tensor 的切片操作，如图 5-28 所示。示例矩阵：Shape（（2，2），（3，3）），Stride（（3，6），（1，12））。

[PRE3]

图 5-28
（4）分级存储。GPU 内存分为全局内存、SM 内的共享内存与 L1 数据缓存，以及 Register File。可编程控制的结构包括全局内存、共享内存与寄存器。L1 与 L2 数据缓存为缓存结构，可控制 Bypass 与否。

为降低全局内存访问频率，首先把全局内存中的数据分块，将小矩阵加载到共享内存；然后按执行线程切分共享内存数据，拷贝到寄存器；Tensor Core 计算时优先从寄存器或共享内存取数，减少全局访问，从而提升性能，如图 5-29 所示。

整体流程为 全局内存→共享内存→寄存器→Tensor Core。

在数据分级存储与分块计算时，可通过多线程并行重叠全局内存到寄存器的数据复制与 Tensor Core 的 MMA 计算，尽量提升计算访存比，如图 5-31 所示。

3）OP 合并
模型推理中，层内每个 OP 的数据都要从全局内存复制到寄存器文件，再由 Tensor Core 从寄存器文件加载并计算。

因全局内存带宽有限，高频读写会带来严重性能问题。为降低全局访问频率，开发中可尽量进行 OP 合并，降低推理计算对全局内存的读取频率。

（1）图融合。图融合是 TensorRT 的关键优化技术之一，通过把计算图中的多个操作合并为单个复合操作，可显著降低内存访问开销与计算延迟。

TensorRT 在转换模型时默认启用图融合优化。若模型支持 Dynamic Shapes，转换时通过 optShapes 指定最优 Shape，TensorRT 会生成最优融合策略并优化内存分配。

[PRE7]

TensorRT 自动图融合策略仅限固定几种方式，如垂直融合、水平融合、常量折叠等。若需更深入融合，可通过自定义插件实现。

TensorRT Plugin 是英伟达 TensorRT 框架提供的扩展机制，允许开发者自定义实现深度学习模型部分结构。典型场景包括：
• 包含 TensorRT 不支持的算子；
• 需优化特定算子计算逻辑，如融合多层以减少内存拷贝；
• 实现硬件相关加速，如针对英伟达 GPU 的 Tensor Core 优化。

有了自定义插件后，可使用 ONNX-GraphSurgeon 修改模型，把插件嵌入原模型。ONNX-GS 是专为 ONNX 模型设计的 Python 工具包，允许对 ONNX 模型的图结构进行灵活操作与优化，提供丰富 API，可轻松增删改计算图中的节点与边，支持节点融合、子图替换等高级操作，实现对 ONNX 模型的全面优化与定制。

（2）Attention 改造。Transformer 已成为自然语言处理与图像分类等应用中最常用架构之一。尽管规模不断增大、加深，处理更长上下文仍是挑战，自注意力模块在序列长度上具有二次方的时间与内存复杂度，导致长序列时速度变慢且内存需求巨大。因此需要优化算法提升注意力模块计算速度与内存利用率，如图 5-32 所示。

[PRE8]

图 5-32

计算任务大致分为计算密集型与访存密集型：计算密集型耗时集中在计算本身，忽略显存读写，如 GEMM；访存密集型耗时集中在访存操作，计算本身较短，如 Mask、Softmax、Dropout 与 Matmul。从图中可看出，Transformer 中 GEMM 占比很少。

结合前述 GPU 内存布局，全局内存带宽较低，数据需先传到寄存器才能计算，对 Memory-Bound 场景一般采用融合操作。于是出现了 FlashAttention，它是由斯坦福团队于 2022 年提出的 Transformer 自注意力机制高效优化算法，核心目标是通过减少内存访问开销与优化计算效率，显著提升长序列场景下的训练与推理速度。

在 Transformer 自注意力中，Mask 用于控制不同位置的可见性，如处理可变长度序列的 Padding Mask 或防止解码器看到未来信息的 Causal Mask。使用 FlashAttention 时，不同场景需不同 Mask，常见类型如下：
• Padding Mask。用于忽略输入序列中的填充位置，通常为二值矩阵，0 表示掩盖，1 表示可见。
• Causal Mask。在自回归模型如 GPT 中，必须确保每个位置只能看到过去位置，防止未来信息泄露，表现为下三角矩阵。
• 推荐类 Mask。生成式推荐模型与大模型推理过程差异较大，大模型为自回归式推理，Token 生成依赖全部前序 Token，Mask 为倒三角样式。而推荐类 Transformer 模型无需生成新 Item，候选物品相互独立，因此 Mask 并非倒三角结构，需要自定义。

考虑到生成式推荐模型与生成式大模型在 Mask 机制上差异较大，以及批大小与多头结构的差异，最终借鉴 FlashAttention 思想手写了 Attention Kernel。它通过分块计算，将大型矩阵分割为小块，在 GPU 高速缓存中完成多个子 OP 计算，减少对全局内存的访问次数，大幅提高 Attention 计算效率，如图 5-33 所示。
