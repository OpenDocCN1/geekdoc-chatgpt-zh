**CPU 跑指令的底层三部曲**

**取操作数**
指令取数的第一步是让 CPU 去源头把参与运算的数据找出来。源头可以是寄存器文件、内存空间，也可以是写死在指令里的立即数。寄存器里的数直接读出来最快，内存里的数则要走内存总线拉取。取数阶段往往要一次性搞定多路数据，像双操作数加法这种指令就必须把两个数都拿到手。

**执行运算**
取数完成后就进入计算核心。先前解码时确定的操作类型会由控制信号送到 ALU 去执行，可能是算术、逻辑或比较。除了 ALU 之外，浮点运算常会交给 FPU 等专用单元来处理。

**写回结果**
算完的结果必须有去处。寄存器类操作会把结果写回对应的寄存器；存储类指令则把结果通过总线写回内存。分支类指令的执行结果还会直接改写程序计数器，让程序流向发生改变。

这套顺序模型只是理想化描述。真实的现代处理器为了提速，会叠加流水线、乱序执行、分支预测等手段，在不破坏数据依赖的前提下让多条指令的不同阶段并行推进，有兴趣可以自行深入查阅。

### 3.2.2 CISC 与 RISC

按照指令系统复杂程度，CPU 的 ISA 大致可分成 CISC 和 RISC 两个流派。如图 3.2.3 所示，两者区分很明显。

CISC 与 RISC 并非某款具体指令集，而是两种设计思想，相当于指令集里的两大门派。

#### 1. CISC 架构
CISC 的目标是通过提供大量指令来减少程序整体指令条数，从而用更少的指令完成任务。

设计哲学上，CISC 强调靠复杂的指令集和多样的寻址方式来简化编程、提升代码密度；复杂指令用微码来驱动，既能保持硬件相对简洁，又能保证指令功能完整；同时重视向后兼容，让新旧处理器能跑老软件，从而长期保持市场存在。

典型特征包括指令集复杂、寻址方式多样、指令长度不固定、采用微码控制、解码逻辑复杂。单条指令可一次完成多个操作，提升代码密度；灵活的寻址让内存访问更方便；不定长指令提供编码弹性；微码解释器把复杂指令拆成可执行的微操作；但正因为复杂，解码器也更重。

CISC 架构优缺点总结如下：
- **优点**：编程更省心、代码更紧凑、兼容性强。指令能打包多个操作，源代码更短；指令数少节省存储；新机器能跑旧程序，保护软件投资。
- **缺点**：指令复杂且长度不一，解码执行耗时；硬件结构和成本都更高；能效相对偏低，很难兼顾高性能与低功耗。

应用场景多在对兼容性和功能全面性要求高的桌面和服务器领域。代表有英特尔 x86 系列、IBM System/360、Motorola 68000 系列。x86 是最主流的 CISC 架构，长期统治 PC、服务器和工作站市场。

即便传统 CISC 有短板，现代实现已经吸收了 RISC 思路。比如现在的 x86 芯片内部会把复杂指令翻译成微操作并流水化运行，在保留复杂指令集优势的同时提高并行度和效率。

#### 2. RISC 架构
RISC 诞生于 20 世纪 80 年代初。当时研究者发现 CISC 里大量指令使用率极低，且复杂指令执行慢。为求更快、更简，提出了精简指令集路线。IBM 801、伯克利 RISC、斯坦福 MIPS 等项目奠定了基础。

设计原则是简化指令集并让指令执行时间趋于一致。典型特征有指令集精简、指令长度固定、加载-存储架构、通用寄存器众多、硬件流水线。单条指令只做一件事，解码执行都更轻；固定长度如 32 位让取指解码更高效；只有 Load/Store 访问内存，其他指令只在寄存器间操作；寄存器多减少内存访问；流水线让多条指令重叠执行。

RISC 架构优缺点总结如下：
- **优点**：执行更快、硬件更简单、能效更高。指令统一且简单利于高频运行；结构简洁降低设计成本；效率高适合低功耗高性能场景。
- **缺点**：代码体积偏大、对编译器依赖强。因为单指令功能小，完成同样任务需要更多指令；必须靠高质量编译优化才能发挥性能。

技术演进中，现代 RISC 引入超标量、超线程等手段提升指令级并行，并配合指令调度、寄存器分配等编译优化，进一步提高吞吐和能效。

#### 3. 两者之间的异同
CISC 出现更早，当时没有经验可循，程序员希望一条指令干更多事，把负担推给硬件。结果指令越来越复杂、长短不一、参数繁多。

随着工艺提升，硬件长期被 CISC 约束，成为性能和尺寸的瓶颈。RISC 正是在此背景下诞生。严格说，CISC 这个名字也是 RISC 出现后才被用来归类之前的指令体系。

CISC 像大杂烩，指令形式各异、频率不一、规则松散。RISC 是对 CISC 的重构，取其精华去其糟粕。定长指令提升了解码效率；复杂指令被拆分为若干简单指令，降低了硬件复杂度，给微架构更多发挥空间，像苹果 M 系列芯片就是典型；每个指令只做一件事，让流水线设计更高效。

## 3.2.2 CISC 与 RISC 架构
RISC 强调每条指令最多有一个内存寻址操作数，主张寄存器到寄存器的操作，并追求单周期完成执行。CISC 与 RISC 都遵循操作码加操作数的思路，操作数类型对应 CPU 寻址三大类：

- 寄存器寻址：操作数是寄存器。执行时从寄存器取数或写回。如 mov ax, bx，把 bx 的内容写进 ax。
- 内存寻址：操作数是内存地址。执行时需读写内存。可细分直接、基址、变址、基址变址等。直接寻址最直观，如 mov ax, [0x3000]，把 0x3000 地址的数据写入 ax。
- 立即数寻址：操作数是常数。常数直接可用，无需访存或取寄存器。如 mov ax, 0x18，把 0x18 写进 ax。

总体来看，CISC 靠丰富复杂的指令集简化编程、提高代码密度和兼容性，但解码执行复杂、硬件成本高。典型代表英特尔 x86 在 PC 和服务器领域广泛使用。RISC 主张精简指令和统一执行时间，靠固定长度简单指令和流水线提升效率、降低复杂度，性能优势明显。ARM 和 RISC-V 等 RISC 处理器在移动、嵌入式和物联网中占优。如表 3.2.1 所示，两者各有侧重，适用于不同场景。

表 3.2.1 CISC 和 RISC 架构对比

| | CISC | RISC |
|---|---|---|
| 指令系统 | 复杂、庞大 | 精简 |

## 3.2.3 CPU 并行处理架构
1966 年 Micheal J. Flynn 按指令流和数据流特征对体系结构分类，形成 Flynn 分类法，共四类：

- 单指令流单数据流 SISD
- 单指令流多数据流 SIMD
- 多指令流单数据流 MISD
- 多指令流多数据流 MIMD

### 1. 单指令流单数据流（SISD）
SISD 系统只有一个处理器和一个存储器，每个指令部件每次只解码一条指令，执行时只提供一份数据，计算串行，硬件不提供并行。为提速可采用流水线、设置多个功能部件形成超标量处理机，或用多模块交叉存储实现内存低位交叉编址。

[PRE0]

### 2. 单指令流多数据流（SIMD）
SIMD 在同一时间对多份数据执行相同操作，适合向量化运算。对数组类数据可一次性并行处理，提升效率。常见实现有 SSE 和 AVX。

SIMT 指在同一时间执行多个线程，线程可运行不同指令但通常执行同一程序，多用于 GPU 并行计算。CUDA 和 OpenCL 都是支持 SIMT 的编程模型。

SIMD 着眼数据并行，SIMT 着眼任务并行。实际应用中依据计算需求和硬件环境选择。

SIMD 系统由一个控制器带多个处理器，同时对一组数据的每个元素做相同操作。主要用于向量、矩阵等数组运算，处理单元数量固定，适合科学计算。特点是单元多但受通信带宽限制。一个指令流处理多个数据流，属于数据级并行。指令序列可并发但不并行。由指令控制部件和多个处理单元组成，每个单元指令相同但地址寄存器各自独立，于是数据地址不同。

[PRE1]

### 3. 多指令流单数据流（MISD）
MISD 用多条指令流处理单份数据流。该模式实用性低，仅作为理论模型，没有实际产品。

### 4. 多指令流多数据流（MIMD）
MIMD 是在多个数据集上执行多条指令的多处理器机器。处理器可通过 Load/Store 访问同一主存，并通过主存交换数据。硬件上是一台计算机内含多处理器和一个主存储器，多处理器共享同一物理地址空间。

[PRE2]

[PRE3]

MIMD 可分为共享内存系统和分布式内存系统。共享内存系统中处理器经互联网络连到内存，处理器间隐式通信。分布式内存系统中每个处理器有私有内存，通过互联网络显式通信。

[PRE4]

### 5. 单指令多线程（SIMT）
单指令多线程主要用于 GPU。

从硬件看，GPU 本质与 SIMD 接近，都是少量指令部件带大量运算单元。但高级语言并不直接支持 SIMD，编程复杂；SIMD 只在处理大量数据时高效，灵活性不足。

英伟达为解决这两个痛点，在指令集上仍像 SISD 一样定义操作数，但在执行时调度器会把一条指令分配到多套计算单元和寄存器。好处是代码可由类多线程的高级语言模型编译而来，即 CUDA，解决了编程复杂性。对用户而言，每套计算管道加寄存器就像一个线程，所以命名为 SIMT。

此外，指令还提供很多修饰符，比如 Bit Mask 可指定哪些线程工作哪些空闲，从而很好支持分支语句，解决了灵活性问题。

因此 SIMT 的初衷是让硬件保持 SIMD 的高效，同时让编程像多核多线程一样轻松。

[PRE5]

## 小结与思考
- ISA 是定义 CPU 功能和操作的蓝图，对软件编程和硬件设计具有决定性影响。
- CISC 架构以复杂指令集简化编程，而 RISC 架构以精简指令集提升执行效率和硬件简化。
- CPU 并行处理架构通过不同的数据流和指令流组合，实现计算性能的提升，满足多样化的应用需求。
