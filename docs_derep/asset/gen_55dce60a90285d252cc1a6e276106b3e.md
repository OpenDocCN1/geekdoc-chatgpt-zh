## 12.2.4 编程模型与硬件执行模型对比

编程模型是程序员编写程序时所依赖的抽象层，它规定了程序组织与控制的方式，并提供了一个简化视角，让开发者聚焦逻辑而不必下探硬件细节。通常涵盖编程语言、数据结构、算法设计及并发机制，用以描述程序行为与交互。

硬件执行模型则刻画计算机硬件实际运行程序的方式，涉及硬件结构、指令集、寄存器、存储层次、缓存以及并行执行策略等。它决定指令的执行次序、数据搬运路径与并发策略，硬件层面同时支持 SIMD 与 SIMT。

二者通过编译器衔接，编程模型最终被映射为硬件执行模型，在概念层面存在明显分野。

## 小结与思考

- SIMD 与 SIMT 都属于单指令多数据范式，但 SIMD 要求数据严格对齐且同步进行，SIMT 允许线程独立寻址并可异步推进，灵活性更高。
- NVIDIA CUDA 借助 SIMT 架构实现高效并行，依托线程块与网格组织，通过 CUDA 核心调度来提升 GPU 计算效率。
- 编程模型为开发者提供抽象以组织代码，硬件执行模型描述代码在物理设备上的真实运行，厘清二者关系对性能优化至关重要。

# 12.3 SIMD 与 SIMT 的编程关联

前面已对 AI 芯片上 SIMD 与 SIMT 的计算本质做过剖析，并结合英伟达 CUDA 做了对比，本节转向不同并行编程方式的讲解。

## 12.3.1 并行编程的三种典型范式

从指令级执行角度看，常见的编程模型可归为串行执行、数据并行与多线程三类：

- SISD：程序按顺序推进，每条指令依次处理单一数据。这是传统串行模型，适合简单顺序任务与小规模数据，面对大规模数据时效率受限。
- SIMD：通过向量化或并行指令一次处理多组数据，同一处理单元执行相同操作但作用于不同数据。适用于图像处理、科学计算等强数据并行场景。
- MIMD/SPMD：多处理器并行执行不同或相同的指令以处理不同数据，充分发挥多核优势，适用于分布式系统与并行计算等并发场景。

选用合适的并行模型能更好地发挥硬件资源，提升性能与效率。

## 12.3.2 串行执行 SISD

以向量相加 $C[i] = A[i] + B[i]$ 说明串行执行，每次 for 循环迭代都要完成一次 A 与 B 的加法得到 C，CPU 常用此方式。CPU 通常借助流水、乱序与超长指令集来提升效率。

[PRE1]

### 1. 流水线执行

流水线执行将指令拆分为取指、解码、执行、访存、写回等阶段，由专用单元分别处理，实现指令重叠。未使用流水线时每次迭代都要完整走完取指→解码→执行；启用流水线后可在空闲时间并行推进不同指令，提升指令并行度。

[PRE2]

### 2. 乱序执行技术

乱序执行在不改变语义前提下重排指令执行顺序，以提高指令级并行。处理器依据依赖关系与资源动态调整顺序。若不乱序，指令 1 完全结束后才开始指令 2，CPU 周期会出现大量空闲。

[PRE3]

因此采用乱序执行，可在 CPU 空闲时提前发射指令 2，受依赖的指令 4 需等待指令 1 写回后才执行，同时 for 循环由硬件动态展开。

[PRE4]

### 3. 超长指令字 VLIW

VLIW 架构允许一条指令打包多个操作，并在同一时钟周期内并行执行。并行由编译时完成，编译器优化能力直接影响 VLIW 处理器的性能，硬件负责执行编译后的并行指令，从而提升指令级并行。

## 12.3.3 数据并行 SIMD

数据并行体现在循环的每个迭代独立完成。程序层面可手写 SIMD 指令或由编译器生成，硬件层面提供宽 ALU 执行单元。以向量加法为例，执行 VLD 将 A 载入 V1 时，Iter.1 读取 A[0]，Iter.2 读取 A[1]，后续 VLD、VADD、VST 均以相同指令处理不同数据，实现数据并行。

[PRE5]

## 12.3.4 多线程 SPMD

SPMD 是一种并行计算模型，多线程 SPMD 指用多个线程执行并行任务。每个线程 Thread i 运行同一程序但处理不同数据，通过并发加速计算。程序上由程序员或编译器生成线程对应每次迭代。SPMD 属于编程模型，SIMT 属于硬件执行模型，后者利用独立线程管理来驱动硬件处理。

[PRE6]

SPMD 与 SIMD 的区别在于，SIMD 在同一指令下处理不同数据，而 SPMD 用线程管理每个迭代。SPMD 最终运行于 SIMD 机器之上，因而催生了单指令多线程的硬件执行模式 SIMT。

## 12.3.5 英伟达的 SIMT 机制

GPU 的 SIMT 实际是硬件以 SIMD 方式执行指令，采用 SPMD 编程模式控制线程。每个线程拥有独立上下文，执行相同指令时硬件会把线程动态组织为 Warp。Warp 本质是 SIMD 操作的体现，SIMT 构成前端调度，后端在 SIMD 上执行。

在 NVIDIA GPU 中，Warp 是执行相同指令的线程集合，是 SM 调度的基本单元，Warp 内部线程以 SIMD 方式推进。CUDA 编程本质是 SPMD，开发者只需写单程序多数据，硬件层面则以 SIMT 实现单指令多线程。

[PRE7]

综合来看，SISD、SIMD、SIMT、SPMD 与 DSA 各自概念清晰可区分：

- SIMD：指令执行方式及其对应的硬件体系结构。
- SIMT：以 SIMD 指令为基础，配备 Warp Scheduler 等硬件模块，支持 SPMD 编程模型的硬件架构。
- SPMD：具体并行编程模型，类似 CUDA 提供的编程范式。

| 类型 | 硬件架构或执行模型 | 方式 |
| :--- | :--- | :--- |
| 执行模型 | Traditional SIMD | （1）包含单条指令执行；（2）指令集架构（ISA）包含矢量/SMD 指令信息；（3）SIMD 指令中的锁同步操作，即顺序指令执行；（4）编程模型是直接控制指令，没有额外线程控制，软件层面需要知道数据长度 |

| 编程模型 | SPMD | （1）通过单个程序，控制多路数据；（2）针对不同的数据，单个线程执行相同的过程代码；（3）本质上，多个指令流执行同一个程序；（4）每个程序：①处理不同数据，②在运行时可以执行不同的控制流路径；（5）在 SIMD 硬件上以 SPMD 的方式对 GPGPU 进行编程控制，因此出现了 CUDA 编程 |

值得注意的是，英伟达在 GPU 中加入 Tensor Core，专用于神经网络矩阵计算并支持混合精度，因而其 GPU 呈现 SIMT+DSA 的混合形态。

## 小结与思考

- SISD、SIMD 与 MIMD/SPMD 是并行编程的三种基本方式，适用于不同规模与类型的计算。
- SIMD 借助向量化指令实现数据并行，SIMT 在 SIMD 基础上通过 Warp 实现更灵活的多线程并行。
- NVIDIA CUDA 编程模型基于 SPMD，利用 SIMT 硬件执行单指令多线程，使开发者以单程序多数据方式编写并行程序，降低开发复杂度。

## 2. Warp 与 Warp 级 FGMT 关系

SIMT GPU 通过细粒度多线程 Fine-Grained Multi-Threading 调度，将执行流水线切分为更小单元，使不同线程指令交错执行，减少等待与资源浪费，实现访存与计算重叠。

Warp 是在不同地址数据下执行相同指令的线程集合，Thread Warp 包含多个 Thread，多 Warp 组成 SIMD Pipeline 执行对应操作。

[PRE14]

SIMT 架构借助 FGMT 隐藏延迟，SIMD Pipeline 中每个线程一次执行一条指令，Warp 支持乱序执行以掩盖访存延迟，并非严格顺序调度，线程寄存器值保存在 RF 中且 FGMT 允许长延迟。英伟达通过 Warp Scheduler 硬件调度，在 Warp 访存完成后让 SIMD Pipeline 执行尽可能多指令，隐藏其他 Warp 的访存时间。

[PRE15]

SIMT 相比 SIMD 在可编程性上的根本优势在于硬件解决了大部分流水编排问题。Warp 指令级并行中每个 Warp 含 32 个线程与 8 条执行通道，每个时钟周期执行一次 Warp，一次 Warp 可完成 24 次操作。

在 GPU 宏观架构层面，GDDR 数据经内存控制器传输到片内总线，再分发至 CUDA Core/Tensor Core 等执行核心，每个核心内部含 SIMD 执行单元，从而实现并行计算。
