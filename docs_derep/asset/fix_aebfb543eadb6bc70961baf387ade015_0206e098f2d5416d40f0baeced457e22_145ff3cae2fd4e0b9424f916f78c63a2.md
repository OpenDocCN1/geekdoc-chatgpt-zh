**7.2.5 记忆**

在构建多能力智能体时，记忆层决定了交互是否连贯。它的价值体现在两点：一是沉淀用户画像、偏好等个性化信息，让回答更贴合个人；二是借助缓存复用，减少重复传历史记录与重复运转流程，从而压低 token 消耗、提升整体效率。

Coze 自主规划模式提供四类记忆手段：

（1）变量：承载用户个人资料，是驱动差异化交互的基石。变量的写入与刷新完全由智能体基于对话自动完成，无须人工干预。
（2）数据库：支持在控制台自行设计表结构，平台会生成对应实体库，数据存取同样由智能体自动处理。
（3）长期记忆：启用后，系统会自动归纳聊天记录并写入持久化缓存，后续问答可无缝衔接历史，实现持续个性化。
（4）文件盒子：启用后，智能体会自动收纳用户上传的文档，并在后续对话中检索引用。

四类记忆的配置都很轻，开启后即交由智能体自治。例如打开长期记忆后，询问它读过哪些文件，就能从缓存中调出阅读清单，如图 7-16 所示。

**7.3 对话流模式**

实际业务中常需要对流程做精细化把控，自主规划模式属于固定黑盒，只能调参、挂插件与知识库，无法对每个流转点做断点调试或自定义改动，可控性存在瓶颈。

为此 Coze 提供了对话流模式。核心概念只有两个：节点与数据流转。平台内置大量常用节点，开发者通过拖拽连线即可搭建复杂流程，前置节点的结果会沿连线传给后置节点被直接消费，形成清晰可控的逻辑链，可视化程度很高。例如图 7-17 所示的基础流程。

[PRE1]

图 7-17 对话流模式—基础示例

该示例包含开始、大模型、结束三个节点。开始节点接收用户输入并向下传递，大模型节点用 Prompt 组织输入后交给 LLM 处理，最后由结束节点把结果交回用户。这个最小单元几乎构成了所有 Coze 对话流 LLM 应用的基础模板，必要时可再追加节点编排更复杂流程。

对比自主规划，对话流的扩展性更强。除模型节点外，还能接入插件调用、代码执行、意图识别、条件分支、循环控制等节点，实现精细编排与深度定制，如图 7-18 所示。

**7.3.1 开始和结束**

开始节点与结束节点是对话流的系统默认组件，分别承担流程起点与终点，负责触发与返回结果，是任何流程不可或缺的部分。

开始节点用于定义启动输入，默认提供 BOT_USER_INPUT 表示本轮用户原始内容，开发者还能按需增加自定义输入参数供后续节点使用，如图 7-20 所示。它本身不产生输出，职责是为整条流程提供初始数据。结束节点则负责把运行结果交还给用户或调用方，支持两种方式：一是直接输出流程中某个中间变量的值，二是由开发者自定义文本内容，实现更灵活的呈现，如图 7-21 所示。

**7.3.2 大模型**

对话流模式同样提供大模型节点承接 LLM 能力。可在此配置 temperature、最大 Token、历史轮数、时间绑定等参数，精细调控生成风格与效果，配置项与自主规划模式基本一致，如图 7-22 所示。

更进一步，大模型节点可直接挂载技能，包括插件、工作流、知识库等，针对业务场景增强能力。例如问答类场景挂载知识库以获得领域问答能力，任务执行类场景集成插件或工作流以支持工具调用与多步处理，如图 7-23 所示。

**7.3.3 插件**

插件节点用于在流程中调用指定插件的工具，扩展智能体能力。插件本质是一组可调用 API，既可以来自商店，也可以是团队自建，统一以节点接入。

添加方式为画布中选择添加节点→插件节点，选择所需插件即可，已收藏的插件可在面板快速添加，节点显示如图 7-25 所示。

每个插件节点的输入输出结构由插件本身定义，不可修改。接入流程时需为必填参数指定来源，可填固定值也可引用上游输出。运行后结果会沿连线流向下一个节点。

插件节点还支持用模拟集替代真实调用，模拟集可手动编写也可由 AI 生成，常用于调试和降低测试成本，如图 7-26 所示。

此外还提供异常与运行配置：超时时间默认 600 秒，可设 0.1～600 秒；重试次数默认不重试，可设 1 次；异常处理方式可选中断流程、返回设定内容或执行异常分支，如图 7-27 所示。

**7.3.4 工作流**

工作流节点用于把子工作流嵌入主流程，实现任务模块化。常用或标准化的任务可封装为子流程，在主流程不同分支中复用，提升编排灵活性和可维护性，如图 7-28 所示。

工作流节点的输入输出同样由子工作流定义，不支持自定义，必填参数需指定来源。节点支持批处理模式，可多次运行子流程并传入不同参数，并可配置批处理次数上限和并行运行数量，显著提升批量任务效率，如图 7-29 所示。

异常处理方面支持异常忽略，开启后节点失败也不会阻断下游，未输出数据会使用默认值，保证流程连续性，如图 7-30 所示。

注意，子工作流发布新版本后，父流程不会自动更新引用，需要手动升级并重新调试。

**7.3.6 选择器与意图识别**

意图识别是指让智能体理解用户自然语言背后的目标。在复合 Agent 中极为常见，比如“我想查看今天的 AI 新闻”，其中“查看新闻”就是意图。

Coze 的意图识别节点可将用户输入分类，并把不同意图路由到流程的不同分支，提升体验。支持极速模式和完整模式两种运行方式。

极速模式追求分类速度，采用平台预设模型，不可更换也不支持追加提示词，如图 7-33 所示。输入通常为用户对话文本，可选带入部分上下文以增强多轮理解，但会增加 Token 消耗。最多支持 10 个分类，命中则流转至对应节点，未命中则走兜底策略，每个分类会分配递增的分类 ID 方便异常处理。

完整模式侧重准确性和复杂逻辑，支持选择大模型并自定义参数，可通过高级设置添加系统提示词和用户示例来提升精度，如图 7-34 所示。最多支持 50 个意图，输出除了 classificationId 外，还会生成 reason 说明分类依据。

实际使用中，意图识别节点常与选择器节点配合。选择器是 if-else 分支节点，用于在获得意图 ID 后将其路由到指定流程，如图 7-35 所示。设计分类时应避免语义模糊或交叉，必要时选用完整模式并加入示例优化准确性，仍不理想可尝试更换模型。

**7.3.7 知识库**

对话流模式同样提供知识库能力，包含知识库写入和知识库检索两类节点，也支持在运行时由用户上传知识。

**1．知识库写入**

该节点允许用户在对话过程中把文件或文本写入流程配置的知识库，如图 7-36 所示，沿用目标库的切片策略存储。

基础参数为上游传入的知识文件变量和目标知识库。写入配置包括文档解析策略和分段策略：解析策略可选快速解析，仅提取文本；精准解析，同时处理图片内容。分段策略可选自动分段，按段落切分；自定义分段，可设置块大小与重叠区间，如图 7-37 所示。

写入操作为异步，不会阻塞流程。单次仅能上传一个文件，若需多次写入可通过批处理或循环节点实现。

**7.3.8 记忆**

长期记忆节点用于在流程中调取智能体已保存的个性化信息，如用户画像、兴趣偏好或关键记忆点，突破上下文轮次限制，实现持续个性化交互，如图 7-40 所示。

使用时输入参数固定为 Query，可引用上游输出或直接填字符串；输出参数固定为 outputList，返回相关记忆供下游使用，如图 7-41 所示。例如新闻推荐流程中，Query 设为“喜欢什么类型的新闻”，下游插件据此调用接口并推荐个性化内容。

需注意，工作流运行时必须绑定开启了长期记忆功能的智能体，否则会报错；同时建议关闭“支持在 Prompt 中调用”以避免与对话过程中的记忆召回冲突，如图 7-42 所示。
