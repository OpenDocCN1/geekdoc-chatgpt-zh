**对话太长了？/compact 一键精简**

OpenClaw 的每次对话都受上下文窗口大小制约。对话拖得越久，历史记录堆得越多，响应就变慢、费用也跟着涨，甚至前面提到的内容会被遗忘。/compact 可以把已有的会话历史压缩成要点摘要，腾出窗口继续推进。

# 在对话区发送，别当成命令行

/compact

发送后助手会自动把整段历史浓缩，保留关键信息、剔除重复和闲聊，随后无缝接续。整个过程通常十秒内结束，之后对话明显更流畅。

**小贴士**

## **5.1** **自定义 Skills：教会龙虾造工具**

第四章学习了安装他人编写的 Skills，本节学习自行编写。

自行编写 Skills 看似门槛高，本质是写一份操作指南——告诉龙虾遇到某类任务按怎样的流程处理，它就会记住并自动执行。

**从零搭建最小技能**

一个 Skill 的核心只有一份文件：SKILL.md。顶部是元数据，相当于身份证，下面是给模型的操作说明。下面是一个最简例子——查询公网 IP：

---

name: my-ip

description: 查询当前公网 IP 地址和地理位置

version: 1.0.0

---

# IP 查询技能

当用户询问 IP 或网络位置时，执行以下命令：

curl -s https://ipinfo.io/json

返回结果包含 IP、城市、地区、国家、运营商等信息。

把文件放到 Skills 目录即可，有两种方式：

# 方式一：直接拷贝到技能目录，最快

cp -r my-ip ~/.openclaw/skills/

# 方式二：通过 clawhub 本地安装，更规范

clawhub install ./my-ip

**小贴士**

Skills 目录下的文件会在下次对话启动时自动加载，无需重启网关。放好后开启新对话，直接问“能帮我查 IP 吗”，即可验证是否识别。

**实战：从零写一个“自动投递简历”技能**

用真实案例说明。求职时需要在多个平台重复投递，十分繁琐。我们写一个 Skill 让龙虾代劳。

**第一步：明确技能目标**

撰写 SKILL.md 前先厘清三点：什么触发、如何执行、输出什么。

（1）触发条件：用户说“投简历”“申请岗位”“帮我投这个职位”等。

（2）执行步骤：读取指定目录简历→填写申请表单→提交→记录结果。

（3）输出结果：告知用户“已成功提交 X 个，失败 Y 个，详情见记录文件”。

**第二步：编写 SKILL.md**

可自行编写，也可让模型快速生成。把触发条件、执行步骤、输出结果告诉模型，再加一句“帮我生成一个 skill 包”即可。以下为模型生成示例。

---

name: auto-apply

description: 自动填写职位申请表单并提交，记录投递结果

version: 1.0.0

author: 你的名字

---

# 自动投简历技能

## 触发条件

当用户说“投简历”“申请岗位”“帮我投这个职位”等相关表述时激活。

## 工作流程

1． 读取简历文件

- 默认路径：~/Documents/resume/latest.pdf

- 若用户指定路径则采用指定路径

2． 分析目标职位

- 从用户提供的 URL 提取职位信息

- 识别：职位名称、公司、要求、申请表单字段

3． 智能填写申请表

- 用 Playwright 打开申请页面

- 根据简历内容匹配填写各字段

- 上传简历附件

4． 提交前确认

- 列出即将填写内容供用户确认

- 确认后提交

5． 记录结果

- 将投递记录写入 ~/Documents/apply-log.md

- 格式：日期 | 公司 | 职位 | 状态 | 链接

## 注意事项

- 遇到验证码或需账号密码时暂停并通知用户

- 同一公司同一职位不重复投递，检查 apply-log.md

- 每次投递后等待 3~5 秒，避免触发反爬

## **5.2** **长期记忆升级：告别健忘**

第四章介绍了 MEMORY.md 的基础用法，但它有上限：纯文本、无结构，几千行后检索效率下降。

本节介绍两个进阶方案：向量数据库记忆 LanceDB 和多 Scope 隔离，让记忆真正无上限。

**LanceDB：为龙虾装上向量记忆**

LanceDB 是本地向量数据库。安装后 MEMORY.md 内容会转为向量存储。对话时模型不再线性扫描文本，而是语义检索——想什么就找到什么，记忆条数再多也能精准命中。

# 安装 LanceDB 记忆插件

clawhub install lancedb-memory

# 初始化向量数据库，首次使用

openclaw memory init --backend lancedb

# 迁移现有 MEMORY.md

openclaw memory import ~/.openclaw/workspace/MEMORY.md

装好后变化：

（1）主动检索：回复前自动检索相关记忆，无需手动提醒“记得上次说过…”。

（2）语义搜索：问“我上次提到的那个项目”，它能找到，即使原文使用的是项目名。

（3）无上限存储：向量数据库效率高，记忆增长不拖慢速度。

[PRE12]

**小贴士**

使用 LanceDB 后 MEMORY.md 仍保留，两者并行。LanceDB 负责快速检索，MEMORY.md 作为可读备份。建议每周运行一次 openclaw memory sync 保持同步。

**多 Scope 隔离机制：工作与生活不混**

LanceDB 解决检索问题后，还会出现工作、生活、团队上下文混杂的问题。Scope 机制可按场景隔离记忆，互不干扰。

# 进入工作 Scope，仅使用工作相关记忆

openclaw scope work

# 进入个人 Scope，私人助理模式

openclaw scope personal

# 进入团队 Scope，共享上下文

openclaw scope team

# 查看当前 Scope

openclaw scope current

不同 Scope 的记忆完全隔离，切换 Scope 就像换一个身份。

**用户：**[work scope] 帮我看一下 OpenClaw 项目的 TODO 列表

[PRE13]

**用户：**[personal scope] 帮我看一下最近的购物清单

[PRE14]

工作和生活两套记忆，互不串扰，这才是真正的数字分身。

**噪声拦截机制：保持记忆干净**

长期使用后记忆会积累重复、过时、无意义的操作记录，噪声多了反而影响检索效果。噪声拦截可在写入前过滤掉无价值内容。

在 SOUL.md 中加入记忆过滤规则：

## 记忆过滤规则

以下内容不写入长期记忆：

- 单次查询结果（天气、股价、新闻等时效性信息）

- 临时性指令（“帮我看一下”“现在搜索”等一次性任务）

- 已完成且不再相关的任务记录

以下内容必须写入长期记忆：

- 用户明确说“记住”的偏好和规则

- 项目的关键决策和背景信息

- 反复出现三次以上的操作模式

- 重要的错误教训（来自 self-improving-agent）

openclaw memory clean --older-than 90d

# 让模型自动整理压缩记忆
