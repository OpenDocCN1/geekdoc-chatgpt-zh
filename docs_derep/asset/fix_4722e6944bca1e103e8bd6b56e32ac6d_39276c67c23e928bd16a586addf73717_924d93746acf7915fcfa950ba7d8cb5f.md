### 2.3.4 第三方集成部署方案

除了直接借助 Transformers 加载参数外，开发者还能选用更工程化、性能更强的第三方工具。这类方案在加载优化、推理提速、服务化与并发管理上优势明显，适合对性能与维护性要求较高的企业级场景。

##### 1. SGLang：面向 GLM 系列的推理框架

SGLang 由智谱 AI 开源，针对 GLM 家族如 GLM-4、ChatGLM 优化，原生支持对话模板、多轮历史缓存、函数调用、结构化输出等能力。

核心特点如下。

- 与 GLM 结构高度契合，支持多轮记忆。
- 支持并发调度与动态上下文构建。
- 内置类似 OpenAI 的接口。
- 可配合 FastAPI/uvicorn 快速搭建服务。

##### 2. LMDeploy：国产模型轻量部署工具

LMDeploy 由昆仑芯与魔搭社区联合打造，旨在为国产开源大模型提供统一高效的部署方案。支持 INT4/INT8/FP16 等多种精度，并集成一键脚本、服务启动、压测等功能。

核心特点如下。

- 兼容 Qwen、Baichuan、InternLM 等多个国产模型。
- 原生适配 INT4 推理，降低显存占用。
- 提供命令行、Web UI、HTTP API。
- 支持多线程调度与批量推理。

##### 3. vLLM：高并发且兼容 OpenAI 的服务引擎

vLLM 由 UC Berkeley 发布的高性能推理引擎，具备动态批处理、连续批处理、FlashAttention 2 等特性，并完整实现了 OpenAI API 协议。

核心特点如下。

- 支持 Hugging Face 格式模型如 LLaMA、Qwen、Baichuan。
- 实现高吞吐推理，可达数千 token/s。
- 支持流式输出。
- 原生兼容 chat/completions 接口格式。

##### 4. Ollama：开发者友好的本地一键部署平台

Ollama 面向开发者提供轻量部署方案，支持下载、管理、运行 GGUF 格式模型如 LLaMA 2/3、Mistral、Qwen、Phi，目标是让本地部署像使用 Docker 一样简单。

核心特点如下。

- 自动下载并注册模型，无需显式管理参数。
- 支持 macOS、Windows、Linux。
- 内置 HTTP API 与 CLI，调用便捷。
- 支持 CPU 与 GPU，并支持流式输出。
- 与 llama.cpp 生态一致，兼容 GGUF。

以上工具代表了当前主流的本地大模型上线方案，覆盖了不同结构、硬件资源与应用场景的需求。

##### 3. 模型格式说明

部署前需确认目标模型是否开放参数、支持的格式以及是否有量化版本。常见格式如下表。

表2.5 主流模型格式

| 格式类型 | 常见后缀 | 说明 | 适用部署框架 |
| :--- | :--- | :--- | :--- |
| 原始 PyTorch 格式 | .bin | Transformers 默认格式，文件较大，占用显存高 | Transformers/vLLM/TGI |
| 安全张量格式 | .safetensors | 安全、加载更快、支持并发加载的张量格式 | Transformers/vLLM/TGI |
| 量化格式-INT4 | .bin, .pt (压缩) | 通常通过 GPTQ/AWQ 等量化工具压缩后发布 | AutoAWQ/GPTQ-for-LLaMA/vLLM |
| 量化格式-GGUF | .gguf | llama.cpp/Ollama 使用的统一格式，支持 CPU/GPU 部署 | llama.cpp/Ollama/KoboldCpp |

选定模型后，需核查是否开源，是否有 Hugging Face 或 GitHub 地址，是否提供 INT4/INT8/GGUF 等版本，以及是否有官方或社区推荐的部署脚本或 Docker 镜像。

### 说明

GitHub 代码库并非调用的必要条件。

- API 服务部署方式如 FastAPI、Gradio。
- Docker 容器镜像与部署指令。
