PCA-EVAL 以真实道路交通场景、家庭机器人交互基准 ALFRED 以及开放世界游戏 Minecraft 为载体搭建并标注评测集，三个方向目前各已收录 100 条样本，且规模仍在持续扩充。为了更真实地衡量一个 Agent 的能力并推动可信赖的人工智能，PCA-EVAL 提出评测应覆盖感知、认知和决策三层核心维度。每一条标注实例都被组织成一个六元组，包含图像、问题、可选行为集、答案、推理原因以及关键概念。评测期望模型不仅能给出决策，还要能解释决策依据并指出图像中的关键信息。在端到端设定下，PCA-EVAL 对比了 Instructblip、MMICL 等当前主流视觉语言模型以及最新的 GPT-4V；在 HOLMES 框架下，则比较了 Vicuna、GPT-3.5 和 GPT-4 的表现。项目还提供了基于 LLM-EVAL 的自动化评测工具，用来量化感知、认知和行为层面的分数。脱离纯文本，进入多模态真实环境后，Agent 的表现如何？结果显示 GPT-4V 在端到端跨模态推理与决策上展现出突出能力，而其他开源视觉语言模型仍有很大提升空间。

### 5.5.2 具身知识与世界模型嵌入
大语言模型在各类自然语言任务上表现惊人，也能在一定程度上辅助具身任务的决策，显示出对物理世界的初步理解。但在涉及物理环境的推理与规划时，这种理解相当有限，常常在物体恒存性、家庭活动安排等简单问题上出错。如图 5.29 所示，即便是 ChatGPT，这类看似基础的任务如数数也可能出现失误。作者的推断是，当下 LLM 主要依赖大规模文本语料训练，缺乏在真实环境中导航、与物体交互、感知并追踪世界状态的具身经验，因此缺少支撑物理推理与规划所需的扎实全面的具身知识。

文献 [894] 希望在保留模型通用性的前提下，将基础的具身知识与技能注入预训练 LLM。为此提出一种新训练范式 E2WM，即从世界模型中获取具身经验进行微调。世界模型本质上是具身模拟器，能仿真真实世界中的物理交互，例如 VirtualHome，为 LLM 提供理解物体交互并执行操作的场景，从而实现更高水平的主动参与。这些世界模型相当于真实世界的简化版，能显著增强传统预训练范式。利用世界模型产生的具身经验对 LLM 进行微调，预期可在提升具身知识的同时保持通用性，进而改善各类具身任务的解决能力。

E2WM 关注具身任务所需要的基础知识与技能，如物体追踪、为达成目标的规划、识别其他 Agent 的行为等。为此设计了两种从世界模型中采集经验的方法：目标导向规划和随机探索。

目标导向规划旨在收集与目标驱动行为相关的经验，随机探索则侧重积累涉及物体和世界状态追踪的经验。在目标导向规划中，模型为某个具体活动设定目标，例如清洁地面时将垃圾丢入垃圾桶，并生成完成目标的计划。为此作者采用蒙特卡洛树搜索在世界模型中进行探索，这一过程被保存为一条具身经验。在随机探索中，一个或多个 Agent 被放置在世界模型里执行随机动作，同时记录所有物体的位置与移动。采集到具身经验后，E2WM 将其转化为微调任务，如计划生成、活动识别与追踪。

### 5.5.3 具身机器人任务规划与控制
完成复杂任务需要为具身 Agent 配备常识知识。由于下游数据稀缺且任务多样，直接在不同部署场景中训练具身 Agent 不现实。LLM 能从海量网络数据中获取丰富常识，可被具身 Agent 用来生成以自然语言表述人类需求的行动计划。但 LLM 缺乏场景感知，容易产生与不存在物体交互的不可执行指令。例如指令“给我一些葡萄酒”，GPT-3.5 可能生成“从瓶子里倒酒到玻璃杯”，而实际场景可能只有马克杯没有玻璃杯，可执行的应是“从瓶子里倒酒到马克杯”。因此需要将 LLM 生成的任务计划与物理世界关联，才能构建可执行的具身任务规划，让 Agent 顺利完成复杂任务。

#### 1. 基于 LLM 的具身任务规划
为了在特定物理场景中获得可执行的计划，过去的工作常通过视觉线索过滤或调整生成的动作，以实现桌面物体的通用操作。为让家庭任务类型更丰富，SayCan[359] 与 LLM-Planner[895] 利用视觉导航收集室内信息来生成基于场景的计划。SayCan 仅能在厨房场景中完成任务，LLM-Planner 在 ALFRED 模拟器中规划的任务大多是放置、摆放等简单操作，二者都难以满足日常生活里大量复杂任务和多样化部署的需求。

文献 [896] 提出 TaPA 任务规划 Agent，用于在物理场景中进行具身任务规划。SayCan 无法泛化到不同室内环境，ALFRED 基准上的 LLM-Planner 因模拟器预设指令简单而难以应对复杂任务。相比之下，TaPA 不受任务类型和目标物体的限制，能够生成具体计划。由此 Agent 获得一般常识知识，为复杂家庭任务如制作三明治、摆放餐具提供导航和操作的基础指令，可处理更高级的人类需求。

图 5.30 展示了 TaPA 的整体流程，即结合场景信息和人类指令生成可执行的行动计划。

TaPA 的任务更为复杂，涉及更多步骤。具体做法是先构建一个多模态数据集，每个样本由视觉场景、人类指令和对应计划构成三元组。利用该数据集，作者依据场景中物体列表预测行动步骤，进而微调预训练的 LLaMA 网络，这即为 TaPA 的任务规划器。在推理时，具身 Agent 会访问站立点，采集提供不同视角的 RGB 图像，并将多视图图像的开放词汇检测器推广到已有物体列表上。与先进的 LLM 及大型多模态模型如 LLaVA 相比，TaPA 在生成行动计划的成功率上更高。

#### 2. 基于三维场景图的机器人任务规划
“给我做一杯咖啡然后放到我的桌子上”这样看似简单的指令，对当前机器人仍是艰巨挑战，涉及导航、感知、操作及高级任务规划等多个环节。LLM 的进展已显著提升机器人引入常识知识的能力，使其能为需要大量背景知识和语义理解的任务进行复杂规划。

要成为有效的规划工具，LLM 必须与现实对齐，即遵循机器人操作的物理环境要求，包括可用动作、相关谓词以及动作对当前状态的影响。此外在广阔环境中，机器人还需知道自身位置、找到感兴趣物体并理解环境的拓扑布局，以规划跨越多个区域的路径。为此研究[897] 提出可扩展方法 SayPlan，用于在跨房间、跨楼层的环境中实现基于 LLM 的任务规划。作者借助三维场景图 3DSG 达成目标，如图 5.31 所示。3DSG 捕捉环境的丰富拓扑结构和分层语义图表示，具有用自然语言编码任务所需的灵活性，包括物体状态、谓词、动作选择和属性。SayPlan 可将三维场景图的 JSON 表示作为预训练 LLM 的输入，为使规划适用于更广场景，提出了三项关键创新。

图 5.31 三维场景图 3DSG 的分层结构, 包括 4 个层级

首先，SayPlan 设计机制让 LLM 能操作“折叠”后的 3DSG 节点，通过扩展和收缩 API 函数调用实现任务相关子图的语义搜索。这样 LLM 在规划时聚焦于规模较小、信息密集的子图，避免超出 token 限制，从而能在不断增大的环境中进行规划。其次，随着指令复杂度和范围增加，任务计划范围也在扩大，LLM 更易产生虚构或不可行的动作序列。对此 SayPlan 放宽 LLM 对导航组件的生成要求，利用现有最优路径规划器如 Dijkstra 连接 LLM 生成的高层节点。最后为确保可行性，SayPlan 引入迭代重规划流程，通过场景图模拟器的反馈验证和完善初始计划，纠正无法执行的动作，例如在将东西放入冰箱前忘记打开冰箱，避免因环境条件不一致、幻觉或物理约束导致的规划失败。

#### 3. 基于环境反馈的具身视觉-语言编程 Agent
伴随 LLM 兴起，视觉语言模型发展迅速，使机器能执行基于图像或视频的描述、推理和对话任务。在具身智能领域，SayCan[359]、PaLM-E[360] 和 RT-2[768] 等工作在机器人操作数据上训练，使 Agent 能处理视觉输入并输出精确的电机控制指令。

与之并行的是通过代码调用与环境交互的方法。该方法类似人类“系统-I”式的本能动作，像预定义代码一样直接触发。更深思熟虑的“系统-II”过程涉及规划与推理，更能发挥大模型认知推理能力。事实上，这一编程范式虽不涉及视觉，已在 ToolFormer[898]、HuggingGPT[899]、ViperGPT[900]、VisProg[901] 等工作中得到利用，它们让 LLM 制定程序并调用相关 API。以游戏为中心的 Voyager[902] 和 Smallville[903] 也让 GPT 在游戏引擎中进行函数调用，通常直接从环境解析数据。

然而融合视觉感知时，同类范式尚未充分探索。TAPA[896] 和 SayPlan[897] 只能输出规划，策略被限制在初始环境状态，难以转化为实际行动。另一个挑战是过度依赖预训练视觉模型将视觉内容转为语言，有时影响 LLM 性能。虽然 EmbodiedGPT[904] 通过视觉语言建模规划并用策略映射操作来缓解此问题，但具身视觉语言模型制定可执行程序的能力仍属空白。

文献 [905] 提出 Octopus，一种新型具身视觉语言编程系统。为赋予其视觉中心编程能力，作者借助 GPT-4 在开源社区 OctoVerse 中收集训练数据，GPT-4 获得复杂系统提示、丰富的环境线索和明确目标。基于这些输入，GPT-4 制定关键行动策略并生成对应代码。同时 Octopus 在使用数据时无缝融合视觉、语言指令和动作代码生成代码。在数据收集阶段，由 GPT-4 引导的 Agent 同时从模拟器获得每步代码执行有效性的反馈，区分成功与失败的移动。这促使作者将具备环境反馈的强化学习方法纳入流程，从而提升决策准确性。

尽管 Octopus 代码生成能力不错，仍存在明显局限，只能生成简单代码。面对复杂任务时常出错，且高度依赖环境反馈调整行动，往往难以达最终成功。未来可通过改进其应对更具挑战的环境和任务，或结合擅长创建复杂结构化程序的最新 LLM 来解决。此外，现有 Octopus 仅在模拟环境中运行，迁移到真实世界会引入大量复杂性。例如真实场景可能不提供像 OctoGibson 那样易用的真实场景图，使得用场景图模型传达环境细微差别更困难。对静态图像输入的依赖也引发了视频输入能否提升任务性能的讨论。

#### 4. 具身 GPT
具身智能任务如具身规划、具身视觉问答和具身控制，旨在赋予机器人感知、推理和行动能力，使其能基于实时观察自主执行长期计划。GPT-4、PaLM-E 等 LLM 已展现强大的语言理解、推理和思维链能力，为开发能理解自然语言指令、执行多模态思维链并在物理环境中规划行动的机器人带来新可能。

大规模数据集对训练大语言模型至关重要，例如 OpenCLIP 在含 20 亿图像语言对的 LAION-2B 上训练 ViT-G/14。具身智能任务与通用视觉语言任务不同，后者可从互联网获取大量弱标注图像文字对，而具身任务需要机器人领域的主观数据。此外精确规划需要结构化语言指令，通常成本高昂，这对高质量多模态具身数据的收集构成挑战。部分研究尝试用模拟器创建大规模具身数据集，但模拟器与真实世界仍存在差距。另有研究尝试用 LoRA 等高效微调策略将预训练 LLM 调整到新领域，仍有未解问题：如何将 LLM 应用于存在较大领域差距的机器人领域，如何利用思维链进行结构化规划，如何以端到端方式用输出的语言计划执行下游操作。

为解决上述问题，Mu 等人[904] 提出具身版 GPT，即 EmbodiedGPT。作者首先构建大规模具身规划数据集 EgoCoT，包含思维链规划指令。该数据集从 Ego4D 数据集挑选，含主观视频及对应的高质量逐步语言指令，指令经机器生成、语义筛选后人工验证。此外，作者扩展 Ego4D 创建 EgoVQA 数据集，专注于主观人-物互动视频问答，以提供更丰富的主观多模态数据。

基于 EgoCoT 和 EgoVQA，作者提出端到端多模态具身基础模型 EmbodiedGPT，能更自然直观地与物理世界互动，执行具身规划、具身视觉问答和具身控制等多项任务。EmbodiedGPT 包含四个集成模块。

- （1）冻结的视觉模型，用于编码当前观察的视觉特征。
- （2）冻结的语言模型，用于自然语言问答、描述和具身规划任务。
- （3）具身形态模型，带有语言映射层，用以对齐视觉与具身指令，并从生成的规划中提取任务相关的实例级特征供低层控制使用。
- （4）策略网络，负责基于任务相关特征生成低层动作，使 Agent 能有效与环境交互。

为进一步提升生成可靠规划的能力，作者在冻结语言模型上实施前缀调优，以鼓励生成更具可执行性的计划。

#### 5. RT-H：用语言来规划机器人层级化动作序列
随着 LLM 与机器人深度融合，具身智能研究备受关注。谷歌的 RT 系列最具代表性，Google DeepMind 于 2023 年 7 月推出全球首个可控制机器人的视觉语言动作模型 RT-2，用户只需用对话形式下达指令，机器人即可准确执行并完成任务。

语言是人类推理的引擎，能把复杂概念分解、纠正理解并在新环境推广。随着 LLM 快速发展，机器人也开始利用高效组合式语言结构分解高度抽象概念，实现新环境泛化。这类具身机器人模型通常遵循共同范式：面对语言描述的高层任务如拿起可乐罐，学习将视觉观察和语言描述映射到低层机器人动作策略，需要大规模多任务数据集。语言的优势在于能编码相似任务间的共享结构，例如拿起可乐罐与拿起苹果，减少任务到行为映射所需数据。然而任务越多样，描述语言也越多样，仅靠高层语言学习不同任务间共享结构变得困难。

为学习多样化任务并更准确捕捉其相似性，2024 年 3 月 Google DeepMind 发布 RT 系列最新框架 RT-H[906]，即 Robot Transformer with Action Hierarchies。RT-H 能将复杂任务分解为简单语言指令，再转化为机器人动作以提高执行准确性和学习效率。如图 5.32 所示，RT-H 的动作层级让模型学会不同任务间的共享结构。与直接任务到动作映射相比，这些语言动作能在多任务数据集间更好地共享数据。层级结构还允许人类选择性地为机器人提供语言动作纠正以防止失败，并利用新的语言动作预测更好的动作。人工干预完成后，RT-H 将继续像以往一样预测语言动作。

RT-H 结构如图 5.33 所示。RT-H 用语言创建策略学习的动作层级，将动作预测问题分为语言动作查询，使用图像标记和任务描述标记预测细粒度语言动作，并利用任务和场景上下文灵活解码为具体动作。用户可直接对动作查询进行干预，提供语言动作纠正。为从纠正中学习，RT-H 仅更新语言动作查询以包含新标注的语言动作纠正，然后将更新后的模型部署到动作层级。

RT-H 包含两个关键步骤。

- （1）根据任务描述和视觉观察预测语言动作，即语言动作查询，在图 5.33 的左上角。
- （2）根据预测的语言动作、具体任务和观察结果推断精确动作，即动作查询，在图 5.33 的左下角。

RT-H 的模型结构借鉴 RT-2，后者是在视觉语言数据上联合训练的视觉语言模型，旨在提升策略学习效率。RT-H 使用单一模型同时处理语言动作和动作查询，充分利用海量知识为动作层级的各层提供支持。在处理多样化多任务数据集时，使用语言动作层级带来显著改善。相比 RT-2，RT-H 在一系列任务上表现明显提升。当语言动作被修正时，RT-H 能在相同任务上达到接近完美的成功率，体现语言动作的灵活性和环境适应性。RT-H 的语言动作能更好地适应场景和物体变化，相较 RT-2 展现出更优的泛化性能。
