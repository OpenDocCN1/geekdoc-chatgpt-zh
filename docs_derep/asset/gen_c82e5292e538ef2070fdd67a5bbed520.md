## 7.4 从单Agent到多Agent体系
目前学界与业界关于从单一Agent向多Agent系统迁移的讨论非常活跃，其中一种共识是多Agent协作可以明显增强Agent的整体效能。Plan-and-Execute 框架本身并未特别强调多Agent场景，其核心思想是通过将任务拆分为计划与执行两部分，并提供细化的步骤与明确指引来提升推理能力，降低单步推理的复杂度，从而提高计划与执行的可靠性。

在实际运行中，计划与执行可以由同一个Agent完成，但更合理的安排是将两者分配给不同的语言模型，即不同的Agent。用能力更强的模型承担推理要求较高的计划任务，用体量更小、速度更快、成本更低的模型来完成具体步骤的执行。更进一步，执行环节本身也可以由多个Agent协同承担。

因此，Plan-and-Execute 的概念与策略完全可以在多Agent系统中复用。无论是单Agent还是多Agent部署，关键都在于如何对任务进行有效拆解、如何制定解决方案，以及如何提供清晰的步骤指引来驱动模型或Agent完成工作。

## 7.5 小结
第6章介绍的 ReAct 框架与本章的 Plan-and-Execute 框架都能提升大模型处理复杂任务的能力。目标相近，但侧重点不同。

ReAct 强调“观察-思考-行动”的循环，更关注让大模型理解环境、生成推理轨迹并采取行动，特别适合需要与外部环境交互的场景，如信息检索、环境探索等。通过完整记录每一步推理，提升了可解释性与可靠性。

Plan-and-Execute 更聚焦于复杂场景下的性能提升。做法是先把整体任务拆解为更小、更可控的子任务，再通过更细致的指令提高推理步骤的质量与准确性。该框架尤其适合需要多步推理的问题，例如数学求解、逻辑分析等。

因此，本章标题所说的“计划与执行的解耦”正是 Plan-and-Execute 的核心：把解决问题的过程明确分为计划阶段与执行阶段。计划阶段负责理解问题、分析结构并制定详细方案；执行阶段则按计划逐步求解。先规划后执行的策略能帮助大模型更系统、更准确地解决问题。

Plan-and-Execute 的优势在于：
- 任务拆解：把大任务分解为小任务，便于管理和解决复杂问题。
- 详细引导：提供细致指令以改善推理质量和准确度。
- 适应性强：可根据不同任务类型调整，在各类复杂问题中表现稳定。

对于需要多步骤推理的复杂问题，Plan-and-Execute 往往更强；而 ReAct 更适合模型与环境交互的任务。两者各有长处，也可互补组合。在多Agent环境下，可以用不同Agent分别承担规划与执行，或由不同Agent完成任务的不同步骤。

## 8.1 何谓检索增强生成
检索增强生成 RAG 是一种融合信息检索与文本生成的AI技术，常用于问答、对话生成或内容摘要等自然语言处理任务。

其工作大致分为两部分：
- 信息检索：从大规模数据集中查找相关信息。数据集可以是维基文章、新闻稿件等文本，也可因大模型的多模态能力而包含图片、代码、关系数据库等形式。接收到查询后，系统会从中检索相关内容。
- 文本生成：检索到信息后，由预训练语言模型如GPT等据此生成响应。模型基于检索内容构建连贯且相关的回答或文本。

RAG 的优势在于兼顾了检索系统的精确信息获取能力和语言模型的流畅生成能力，使得在复杂语言理解任务中能提供更丰富、更准确的信息。例如在问答系统中，RAG 能给出基于事实的答案，而非仅依赖模型的泛化推断。

图8.3展示了借助RAG从知识库提取上下文，再由大模型处理用户查询并生成响应的闭环。基于此流程的Agent可应用于聊天机器人、搜索引擎、推荐系统等需要从海量数据中提取和处理信息的场景。

RAG 还能持续更新所检索的数据源，以适应新信息和趋势，保持响应的相关性与准确度。
