# 第6章 Harness工程实践：复现Claude Code核心设计模式

Harness Engineering 近期在 Agent 开发圈逐渐被提起。名字听起来新，其实内核并不陌生。Harness 原意是马具，“马”指代我们常用的 LLM，所以 Harness 工程就是在 LLM 外围做系统性工程建设。用公式表达就是 Agent = LLM + Harness。前五章围绕上下文工程做的开发，本质上都属于 Harness 工程的范畴。

从 2025 年起，行业演示的重心明显变化：不再只秀单轮问答，而是强调 Agent 能连续运行数小时、整夜无人值守。

代表性案例包括：

- DeepResearch 可持续运行数十分钟，完成深度信息调研；
- Claude Code 作为 Coding Agent 的代表，能自动进行数小时的编码、测试、修复再测试闭环；
- OpenClaw 已支持 24 小时自动化任务，从邮件整理到股票监控全程无需人工。

这标志着 AI 应用从短时交互转向长时任务执行。除了要管好上下文、提升即时能力，还要为 LLM 搭建一个能长期稳定、安全运行的环境，这正是 Harness 工程被系统化总结出来的背景。

业界的 Claude Code 与 OpenClaw 这类产品，并不追求堆工具或复杂工作流，而是更像 Harness 工程的典型代表。本章会拆解、复现并理解这两类产品的设计精髓。

Claude Code 是 Anthropic 2025 年初推出的自然语言编程工具。与 GitHub Copilot 这类被动补全插件不同，它能根据开发者意图自主规划并执行任务。输入“构建一个 React 组件”，它不仅生成代码，还会分析现有代码库、写测试用例并完成集成。

Claude Code 没有走堆砌工具、硬性引导模型的老路，核心哲学是为模型打造理想的工作环境，按模型需求封装环境能力。

这一思路体现在四个层面：

- Agent Loop：保证持续工作的基础。针对本地文件操作需求，仅保留 Read、Write、Bash 等核心工具，并授予系统级权限，减少中间损耗；
- 上下文工程：通过上下文压缩等机制解决窗口限制和冗余信息导致的幻觉，实现动态精准筛选；
- 持久化与异步：借助持久化任务管理，实现跨会话延续；
- 多 Agent 系统：Agent Teams 新特性支持多个 Claude Code 实例协同工作。

不直接干预模型内部决策，而专注于边界支撑环境，正是 Harness 工程的核心。Claude Code 堪称编程领域的典型范例。

本章将从上述维度深入拆解 Claude Code 的运行机制并通过代码实现对应特性，帮助读者掌握 Harness 工程设计思想并迁移到其他 AI 产品研发中。

## 6.1 Agent Loop：Agent可以长时间工作的核心

自 2025 年起，衡量 Agent 的关键指标从单次交互质量转向自主长周期的连续工作能力。在此背景下，Agent Loop 成为实现该目标的技术基石，也是 Claude Code 构建 Harness 工程的核心引擎。

即使只配少量基础工具，依托 Agent Loop，Agent 也能在操作系统层面执行复杂的连续任务。下面通过代码实战剖析原理并演示效果。
