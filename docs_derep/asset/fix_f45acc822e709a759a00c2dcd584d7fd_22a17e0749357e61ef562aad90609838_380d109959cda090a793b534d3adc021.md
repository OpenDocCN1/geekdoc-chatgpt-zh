生成大模型能够产出连贯流畅的文本，关键在于自注意力机制被纵向堆叠成Transformer，并以自回归方式驱动解码器。这种组合大幅增强了模型对长距离依赖的捕捉，输出更自然，已成为当代生成技术的核心框架。

#### 2.1.2 生成检索结合
把检索能力嫁接到生成流程就是RAG的基本思路。推理时即时调取外部资料，能显著提升回答的可信度和时效性。单纯依赖预训练的生成器，知识边界被固定在训练时点，对训练之后的新事实基本无感。RAG通过外部检索通道，在生成瞬间从知识库抽取与问题相关的最新材料来补足盲区，让系统应对复杂提问时更有底气。

下面用两个代码片段演示检索如何为生成提供实时信息支撑。

##### 【例2-2】检索增强生成的基本流程。
本例用FAISS做向量检索，配合GPT-2演示RAG的工作机制。整体可拆成两步：先把文档集编码成向量写入FAISS，再在用户提问时检索最相似的片段作为补充提示喂给生成器。

from transformers import GPT2LMHeadModel, GPT2Tokenizer

from sklearn.feature_extraction.text import TfidfVectorizer

import faiss

import torch

# 初始化 GPT-2 模型与分词器

model_name="gpt2"

tokenizer=GPT2Tokenizer.from_pretrained(model_name)

model=GPT2LMHeadModel.from_pretrained(model_name)

# 示例文档集合

documents=[

    "人工智能是通过模拟人类智能来完成特定任务的技术。",

    "机器学习是人工智能的一个子领域，主要关注通过数据训练模型。",

    "深度学习是一种利用神经网络进行数据处理的机器学习方法。",

    "自然语言处理使得计算机能够理解和生成人类语言。" ]

# 使用TF-IDF将文档编码为向量

vectorizer=TfidfVectorizer()

doc_vectors=vectorizer.fit_transform(documents).toarray()

# 将文档向量插入FAISS索引中

dimension=doc_vectors.shape[1]

index=faiss.IndexFlatL2(dimension)

index.add(doc_vectors.astype('float32'))

def retrieve_document(query, top_k=1):

    """

    检索最接近的文档

    """

    query_vector=vectorizer.transform([query]).toarray().astype('float32')

    _, indices=index.search(query_vector, top_k)

    retrieved_docs=[documents[i] for i in indices[0]]

    return retrieved_docs

def generate_response(query):

    """

    结合检索结果生成回答

    """

    # 1. 检索与 query 最相关的文档

    retrieved_docs=retrieve_document(query)

    # 2. 将检索到的文档作为上下文提供给生成模型

    context=" ".join(retrieved_docs)

    prompt=context+" "+query

    # 3. 使用 GPT-2 生成响应

    inputs=tokenizer(prompt, return_tensors="pt")

    outputs=model.generate(inputs.input_ids, max_length=30,

                           do_sample=True, temperature=0.7)

    response=tokenizer.decode(outputs[0], skip_special_tokens=True)

    return response

# 测试查询

query_text="什么是机器学习？"

response=generate_response(query_text)

print("生成的回答:\n", response)

代码先借助TfidfVectorizer把示例文档转成向量并存入FAISS。retrieve_document会把查询向量化后在索引中找最接近的文档，再把检索结果拼接到问题前方形成提示送入GPT-2生成回复。

运行结果如下：

该演示中，RAG借助检索模块拿到与问题最吻合的片段作为提示，让生成器给出更精准的回复。

#### 2.1.3 检索增强与传统生成模型的区别
RAG与传统生成器在结构、运转方式及数据利用上差异明显。像GPT系列这类传统体系语言生成能力强，但时效性和知识准确性不足。RAG接入检索模块后，回答时可实时获取最新外部知识，从而提高内容可信度和更新频率。

##### 1. 数据源与信息获取方式
传统生成器主要依赖训练阶段学到的固化记忆。训练完成后，输出基本局限于当时的语料，无法自动随时间更新，因而对新知的理解有限，时效性和准确性较差。

RAG则引入动态检索机制，生成前后能从外部知识库、文档库等来源实时拉取最新数据。它不仅靠模型内置记忆，还能通过检索模块访问海量外部信息，实现知识的流动式更新，从而覆盖更广的信息需求。

##### 2. 架构与工作机制
传统生成器多基于自回归或序列到序列生成，逐步拼凑输出。提示主要来源于输入本身和训练时积累的内部记忆，生成完全依赖参数分布和已有记忆，知识覆盖受限。

RAG在生成过程中把检索到的外部内容作为提示注入模型。检索模块先根据用户输入找到最相关信息，再将其动态加入提示词，生成器据此产出内容。这种检索加生成的双轨机制，提升了回答的精准度和知识广度。

##### 3. 知识广度与深度
传统生成器的知识广度取决于训练数据的规模和质量，扩展新知识需要重新训练或微调，成本高昂。其深度体现在句法语义理解上，但在处理复杂背景时易泛化，准确性不足。

RAG借助外部检索显著扩大知识面和准确性。检索模块可从知识库、数据库、网页等多源获取数据，使模型在专业化、多领域场景下更具适应性。知识广度不再固化于训练集，且能通过检索获取更详细的背景，挖掘更深层次的信息。

##### 4. 适应性与拓展性
传统生成器适应性较弱，尤其在需要最新信息或专业知识的任务中，回答常缺乏时效性和精准度。每有新知识就需要昂贵的重训练，限制了其在高频更新场景的应用。

RAG通过实时检索提供高效适应方案，无需频繁重训生成器即可调用外部数据。在处理新兴知识或需要即时响应的任务上表现更好，也便于在知识库中扩充专业、时效性强的内容，让输出始终贴近实际。

##### 5. 性能与计算资源
传统生成器往往需要大规模参数和复杂架构才能在大规模数据上取得好效果，训练与更新成本高。生成长文本时计算量也随之激增，影响效率。

RAG的检索模块分担了知识记忆压力，生成部分只需把检索结果组织成流畅语言。生成器可以精简，计算成本下降。检索与生成还能分布式并行部署，提升响应速度。
