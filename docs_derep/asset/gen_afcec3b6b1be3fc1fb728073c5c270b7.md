RAG 分块策略与索引优化实战指南

前文已介绍过，LangChain 借用 Unstructured 能力提供了 UnstructuredLoader，可以把 PDF、Word、HTML 等多种格式的文件一次性读入，并在读取时自动把内容拆解成“文档单元”。在拿到这些单元后，再按设定的分块规则和最大字符阈值进行合并或二次拆分，最终得到更符合下游任务的文本块。

Unstructured 内置的两套主流切分思路是 Basic 与 By Title，两者都不是靠空行或换行符硬切，而是依据文档的语义结构来判断边界。

- Basic 模式会按顺序把相邻的文本单元拼进同一个块，直到触及 max_characters 上限或软限制 new_after_n_chars。单个单元如果本身就超长，比如很长的正文段或大表格，会被再次切分。表格类单元默认作为独立块处理，体积过大时会拆成多个 TableChunk。分块重叠可以通过 overlap 与 overlap_all 参数控制。
- By Title 在保留 Basic 的合并逻辑之上，额外加入标题感知：一旦识别到新的 Title 单元，就立即收尾当前块并开启新块。multipage_sections 与 combine_text_under_n_chars 等参数可以用来调节跨页片段的合并方式以及短小片段的处理。

通过 API 调用 Unstructured 时，还能使用两种更智能的切分方式。

- By Page：严格按页切分，保证每页内容自成一块。
- By Similarity：借助嵌入模型把主题相近的单元聚合成一块。

#### 2.5.2 用 LlamaIndex 的 SemanticSplitterNodeParser 做语义分块

语义分块属于更高级的文本处理范式，它不像固定字符切分那样机械，而是利用嵌入相似度自适应地寻找句子断点，让每个块内部语义更连贯。在 LlamaIndex 的体系里，文本块叫 Node，分块器叫 NodeParser，SemanticSplitterNodeParser 就是其中一种实现。

LlamaIndex 还封装了其他语义工具，例如：

- SemanticDoubleMergingSplitterNodeParser，通过多次合并策略实现语义一致性的分段，兼顾主题变化与相近语义单元的合并。
- TopicNodeParser，基于主题相似度把文档切成语义一致的块，可结合大模型或嵌入模型计算相似性。

同一批文档可以用不同工具对比分块结果、速度与效率。语义分块设计复杂，处理耗时较长。在常规 RAG 构建中，递归式切分往往已足够，语义切分并非必须。遵循奥卡姆剃刀，优先选择简单有效的方法更稳妥。

### 2.6 与切分相关的进阶索引构建技巧

在 RAG 体系里，索引构建广义上指为文本块建立包含向量与元数据的存储，让系统在海量数据中快速定位与查询最相关的片段，从而生成上下文合理的回答。

#### 2.6.4 在切分时构建有层级结构的索引

延续前一节的思路，这里介绍手工构造元数据并形成层级索引的策略，核心是通过层次化语料组织来优化检索与生成。该思路与滑动窗口和父子块有相似之处，都是通过文档层级提升 RAG 效果。本节介绍摘要→文档技术和文档→嵌入对象技术。

传统全文检索易带来噪音。摘要→文档技术的关键是在切分时为每个块生成摘要及关联节点，检索时先查摘要再扩展到完整文档，从而更精准地捕捉意图并提升效率。
