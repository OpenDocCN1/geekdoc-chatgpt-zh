Self-RAG：让检索式生成拥有自我审视能力的范式升级

Self-RAG，即自省式 RAG，是由华盛顿大学与 IBM 人工智能研究院的研究人员在论文《Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection》中提出的增强型 RAG 思路。开源原型在多项评测集上的表现都明显高于常规 RAG，验证了其在事实性与质量上的提升。

### 13.2.1 为什么要做 Self-RAG

RAG 通过外挂知识库降低了知识密集型任务的幻觉率，但即便不考虑上下文长度和响应时延，也存在两个难以回避的短板，这正是 Self-RAG 要解决的痛点。

1. 检索过度。传统 RAG 对几乎所有问题都执行 top_K 检索，容易把大量无关甚至干扰的信息带入上下文，反而拖累输出。

2. 生成不一致。检索到知识后，模型并不能保证严格忠于来源，相关性也无法 100% 确认，最终易出现偏离。

用更直白的说法类比，RAG 好比允许优秀学生考试时翻书。

- 无论题目难易，学生都去翻书找答案，效率并不高。合理做法是能直接答的就答，不确定的才去查。
- 即便翻了书，学生也可能看错、记偏或主观发挥，最终答案依然出错。

实践中常采用的补丁包括：检索前先让模型判断是否需要检索、在 Prompt 中强制要求忠实来源、多次迭代评估答案。这些办法虽有帮助，却增加了流程复杂度、拖慢响应，并引入更多不稳定因素。Self-RAG 的思路是把“判断”和“自检”内建到模型本身。

### 13.2.2 Self-RAG 工作机理

Self-RAG 与传统 RAG 的本质差异在于：通过模型层面的微调赋予大模型判断是否检索、如何按需检索的能力，再配合应用层流程，实现更准确、更可信的生成。

#### 1. 运行脉络

Self-RAG 的整体走法如图 13-4。

[PRE0]

流程可拆为四步。

1. 检索决策。传统 RAG 直接检索，Self-RAG 先由模型判断是即时作答还是先检索。
2. 按需检索。
   - 不需检索的任务，例如创作一首颂扬母爱的诗歌，模型直接生成。
   - 需要检索的任务，例如介绍公司最畅销的产品，则调用检索器取前 K 个最相关的知识块。
3. 增强生成。将每个检索块与原问题组装成 Prompt，分别生成 K 个候选答案。
4. 评估甄选。对 K 个候选进行打分，选出最优者作为最终输出。

#### 2. 四类自省指标

上述流程中有两处依赖模型自评：何时检索、如何挑优。为此设计了 4 类评估标记，原文定义见表 13-1。

表 13-1

| 评估指标 | 输入 | 输出 | 定义 |

| --- | --- | --- | --- |

| Retrieve | x/x,y | {yes, no, continue} | Decides when to retrieve with R |

| IsREL | x,d | {relevant, irrelevant} | d provides useful information to solve x. |

| IsSUP | x,d,y | {fully supported, partially supported, no support} | All of the verification-worthy statement in y is supported by d. |

| IsUSE | x,y | {5, 4, 3, 2, 1} | y is a useful response to x. |

通俗解读如下。

1. Retrieve：是否需要检索
   - [No Retrieval]：无需检索，直接生成
   - [Retrieval]：需要检索
   - [Continue to Use Evidence]：无需新检索，沿用已有证据

2. IsREL：知识相关性
   - [Relevant]：检索块对问题有帮助
   - [Irrelevant]：检索块与问题无关

3. IsSUP：答案支撑度
   - [Fully supported]：答案全部被检索知识支撑
   - [Partially supported]：仅部分被支撑
   - [No support / Contradictory]：无支撑或矛盾，例如知识只说“中国首都北京”，答案却加上“北京最受欢迎景点是长城”，后半句即属部分支撑。

4. IsUSE：答案有效性
   - 按有用程度给出 [Utility:1] 至 [Utility:5] 的评分。

#### 3. 自省标记如何产生

直接用 Prompt 让模型判断相关性虽然灵活，但交互次数多、成本高且难以量化。Self-RAG 采用微调注入自省 token 的做法，让模型在推理时自行输出标记。

模型在生成过程中会自行决定是否需要查证，并输出 [Retrieval] 等标记暂停；在拿到上下文后，会在答案中插入 [Relevant][Fully supported] 等自省标记进行自我校对。

#### 4. 如何打分选优

有了自省标记后，如何把它们量化比较并选出最优答案？关键在于大模型输出层的 logprobs，即对数概率。

##### 1）logprobs 是什么

大模型生成本质是逐步预测下一个 token 并循环，直到结束符。每次预测会给出多个候选 token 及其概率列表，再择一输出。logprobs 字段记录了每一步各候选 token 的对数概率。

[PRE3]

##### 2）评分规则

自省 token 同样有对应的概率。例如出现 [Fully supported]，说明模型在该位置同时计算了 [Fully supported]、[Partially supported] 等的概率并做了选择。评分基于这些概率计算：

1. 【IsREL】知识相关性。计算 [Relevant] 的输出概率占该指标两类 token 概率之和的比例。
2. 【IsSUP】答案支撑度。计算 [Fully supported] 的概率占比，加上 [Partially supported] 的概率占比乘以 0.5。
3. 【IsUSE】答案有效性。对五类效用标记分别计算其概率占比乘以对应权重后求和。

以 IsSUP 为例，官方测试代码的逻辑可简化为：定位自省 token，读取其预测概率，经 exp 转换后按公式聚合。

[PRE4]

使用时注意两点：logprobs 为对数形式，需用 exp 还原为概率；推理工具如 Llama_cpp 会在输出中提供 pred_tokens 与 pred_log_probs_dict 作为算法输入。
