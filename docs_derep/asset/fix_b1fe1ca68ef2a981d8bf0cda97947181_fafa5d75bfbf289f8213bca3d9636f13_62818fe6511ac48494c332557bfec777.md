（3）工具调用与执行效能：考察智能体在面对具体问题时，是否能够挑选出合适的外部工具或 API 并正确调用。衡量维度有单次调用的命中表现，以及在多步任务里保持系统状态一致的能力。比如 BFCL 这类基准侧重函数调用的准确性；MCPEval 则在模型上下文协议层面检验智能体与工具的协作，给出协议级的可落地洞察。

（4）系统稳健性与架构取舍：关注错误如何被遏制，以及性能和成本之间的权衡。

**·** 可扩展性与可靠性：在负载上升或部分组件出现异常时，延迟、吞吐和错误率的变化情况。

**·** 架构取舍的量化：用数据对比不同架构的性价比来指导选型。例如，多智能体协同或反思型架构在处理异构数据时准确率往往高于单纯规划型架构，但耗时和 token 消耗也会明显更高。

#### 2．评估的落地方式
多智能体评测一般落在两类做法上。

（1）综合基准评测体系：提供统一任务和环境，便于横向对比。常用框架有：

**·** MultiAgentBench：聚焦协作与竞争场景，检验多智能体整体能力，并分析通信拓扑对效果的影响。

**·** VitaBench：以外卖、旅行等真实场景为基础，搭建包含 66 个工具的交互式环境，考察推理、工具使用、交互三者的复合难度。

**·** FDABench：面向数据智能体，覆盖数据库、PDF、视频等异构数据源的分析任务，可评估规划、工具调用、反思、多智能体等多种流程。

**·** PlanBench：专注规划能力，检测计划生成、路径优化以及面对变化时的自适应水平。

（2）工程化评测与监控工具：面向开发与生产阶段的持续观测。

**·** DeepEval：内置 40 多项即用指标，支持自定义并接入 CI/CD，适合企业级全链路监控。

**·** TruLens、LangSmith：提供细粒度可观测性，帮助定位智能体间的决策与通信问题。

**·** MCPEval：基于 MCP 的开源方案，可自动生成测试用例、校验工具调用并评估表现。

有效评测的关键在于区分多智能体与单智能体的差异，把焦点放在协作过程。评测体系要随业务目标与场景调整。因为智能体输出不稳定，除了自动化评测，还要辅以人工校准，并建立“评测-优化”闭环，才能构建可靠的生产系统。

### 6.2.2　多智能体系统的优化方向
提升整体表现需从工程与算法两条线协同推进。工程侧保障稳定可靠，是能力释放的基础；算法侧则直接改善协作与决策水平。

#### 1．工程层优化
工程优化的核心是打造高可靠、可扩展的协作底座，围绕标准化、健壮性、高效性展开。

首先，统一通信协议是有效对话的前提。规范数据交换格式与接口，能消除异构体间的互操作障碍，降低因误解或格式问题导致的协作失败。

其次，需要系统化的容错与自检机制。引入中间件集中管理任务与重试，为工具调用设计带参数校验与结果核验的 API，并借助 Arize Phoenix、Langfuse 等监控工具实现全链路追踪，形成容错与快速排障能力，避免局部故障扩散。

最后，合理的分布式与混合计算架构可直接提升效率。让智能体在本地并行处理后汇总结果，能减少串行等待与单点压力。进一步可把不同求解器或算法封装为“智能体”，由元调度器动态协调，根据实时场景自适应选择或组合策略，减少无效计算与错误调用，逼近全局最优。

#### 2．算法层优化
算法优化旨在改进个体与群体的学习策略，让智能体在复杂环境中更“聪明”，主流方向是多智能体强化学习与进化算法。

多智能体强化学习是实现自主决策优化的核心。难点在于环境非平稳和个体贡献度评估，即信用分配问题。集中式训练、分布式执行的范式已成主流：训练时利用全局信息引导协作策略，执行时各体仅凭自身观测独立行动，在协作效率与部署灵活性间取得平衡。

进化算法则以群体试错为路径。模拟自然选择，维持多样化策略种群，通过迭代选择、交叉与变异淘汰低效策略、培育高适应度策略。该方法不依赖梯度，可跳出局部最优，探索更广阔空间，对非光滑多峰问题尤其有效。

实践中常将二者结合。例如 RACE 框架里，进化算法持续探索新颖协作策略，强化学习则深入优化特定策略。二者定期交换优良策略，加速探索与利用的结合。

总之，优化是系统工程。工程侧提供可靠通信、容错与计算舞台，算法侧提升群体的表现与协作上限。二者需紧密配合：先以工程保证基本稳定，再以算法持续迭代，最终通过“评测-优化”循环推动演进。

# 第七章
通用 AI 智能体构建

通用 AI 智能体是当前快速演进的重要范式，本质是构建能像人类一样灵活应对多样化任务的自主系统。区别于单一功能 AI，其具备跨领域任务处理、自主决策学习，以及与物理数字环境的深度交互三大特征。

技术上采用多层认知架构。底层是大模型，相当于“大脑”，赋予语言理解、逻辑推理与知识整合能力；中间层是任务规划与决策系统，把复杂目标拆解为可执行步骤；上层是交互接口，涵盖多模态输入输出及与物理执行机构的连接，形成认知到行动的闭环。

本章从 Manus 起介绍主流通用 AI 智能体及其技术原理。

## 7.1　Manus 与通用智能体
2025 年 3 月，Manus 在国内互联网迅速走红。

发布后评价普遍积极，有人称之为“智能体的 ChatGPT 时刻”，也有人视其为继 DeepSeek 之后的新爆款，代表人机协作的未来方向。

### 7.1.1　Manus 概览
官方称 Manus 是首个通用 AI 智能体，是实现端到端任务闭环的代表形态。简单说，它像一位自主性强的助理，用户只需给出最终目标，系统会自动执行相关任务。

与 DeepSeek 相比，Manus 更强调产品化设计，如任务拆解可视化、多模型动态调度，而非底层技术原创。

以撰写含数据报表的股票分析报告为例，通用大模型通常需用户明确指导拆解与执行顺序，如先出大纲再填内容。Manus 则能自动将复杂任务拆分为多步，全程无需干预，最终呈现图文并茂的网页报告。

其最大价值在于普及智能体概念，并为工程化方案提供新思路。爆火后，AutoGLM、Genspark、Skywork、扣子空间等相继出现，但受模型能力与架构限制，目前仍存在等待久、执行弱、效果不稳等问题。相信未来会涌现更多产品，真正改变生活。

### 7.1.2　Manus 技术解析
Manus 基于底层大模型，通过自主任务分解把复杂目标拆解为子任务，并动态调用不同智能体或工具执行，最终完成整体任务。

架构上采用云端虚拟环境，让 AI 在独立计算机中运行，避免占用用户本地资源，用户离线时任务仍可继续。

系统提示词定义了智能体循环、系统能力与助手行为等多项内容。

#### 1．智能体循环
动态的推理-行动闭环。接收任务后分析拆解目标，选择合适工具如浏览器，在安全监控下执行并观察结果，每步后重新评估进展，决定继续、转向或求助，直至完成。

#### 2．系统能力
根基是云端虚拟环境即数字沙盒。智能体拥有类似系统管理员权限，可调用 shell、使用图形浏览器、安装依赖、部署轻量应用，从而在标准化数字环境中完成复杂多步骤操作。

#### 3．助手行为能力
内置的行为准则与精细策略，用于约束决策。它规定不同场景下的思考与行动方式，如风险评估、优先安全工具、格式化进度汇报，以及在模糊或高风险操作时主动请求用户接管，将原始能力转化为可靠可预测行为。

总体看，Manus 是基于任务解析与结构化处理的多智能体框架。需求分析模块理解请求、识别核心目标、澄清模糊需求并拆解为可执行子任务。

通过浏览器交互、文件系统、shell、通信接口与部署能力等工具链，实现多模态任务处理，支持 JavaScript、Python 等十余种语言与主流框架。

执行引擎采用动态任务规划，实时监控进度，遇阻时触发自适应调整并生成替代方案。

质量保障依靠结果验证、代码测试与反馈学习闭环，同时遵循隐私保护、安全限制与道德准则。

Manus 能持续学习提升处理能力，但受上下文窗口与沙盒隔离限制，无法访问外部系统或执行越权操作。

### 7.1.3　开源替代方案
Manus 的成功激发了开源社区的跟进。闭源收费与邀请码限制促使开发者寻求可控、低成本、透明的技术替代，催生 OpenManus 等方案。

技术路线与 Manus 一脉相承，均采用多智能体协作架构，将自然语言指令自动拆解为逻辑子任务，分配给搜索、代码、文件整理等专用智能体协同执行，并注重工具链集成，接入网络搜索、代码解释器、文件系统等以扩展实际执行力。

开源与闭源的核心差异在于透明性与可演进性。以 OpenManus 为例，其公开致谢 Computer Use 与 Browser Use 等项目，清晰呈现技术渊源，便于审计与定制化，加速生态迭代。

OpenManus 主要包含智能体模块、流程模块、工具模块与提示词模块等。

（1）**智能体模块**。定义基础智能体接口与主要实现，涵盖任务规划、ReAct 模式与工具调用处理。

（2）**流程模块**。定义 Manus 智能体工作流基类，实现智能体获取、添加、状态管理（not_started、in_progress、completed、blocked），并提供 FlowFactory 类用于为多智能体创建不同类型工作流。
