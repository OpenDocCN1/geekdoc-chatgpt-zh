函数能够直接嵌入 SELECT 语句中参与运算，而存储过程不具备这一特性。例如已经存在一个返回 NUMBER 类型的函数 FUN_GETAVG，其功能是取绝对值，那么语句 SELECT FUN_GETAVG（COL_A） FROM TABLE 完全合法并可正常执行。

## 7.4 触发器

触发器属于一种由事件驱动的特殊存储过程，并非由程序显式调用或人工启动，而是当数据库发生特定操作时自动被数据库事件唤醒，完成相应的 SQL 执行。它的核心价值在于保障数据的有效性和完整性，并实现普通约束无法覆盖的复杂校验。

触发器与存储过程的主要差异如下表7-2所示。

表7-2 触发器与存储过程的区别

| 触发器 | 存储过程 |
|---|---|
| 在某些数据操纵 DML 语句发生时隐式被调用 | 由应用或其它过程显式调用 |
| 触发器体内禁止使用 COMMIT、ROLLBACK 语句 | 过程体内可以使用 PL/SQL 支持的所有 SQL 语句，包括 COMMIT、ROLLBACK |
| 不能接收外部参数输入 | 可以接收参数输入 |

按触发的 SQL 类别划分，触发器可分为 DML 触发器和 DDL 触发器。

DML 触发器在数据库服务器收到数据操作语言事件时运行，细分为 After 与 Instead Of 两种。After 触发器在记录修改完成之后才被激活。Instead Of 触发器则在记录变更之前先执行触发器自身定义的操作，从而取代原 SQL 的执行。DDL 触发器在响应数据定义语言事件时被执行。

触发器的实用价值主要体现在以下几个方面。

- 1) 提高系统的安全性。
- 2) 记录变更痕迹及相关操作信息，实现对用户行为的审计追踪。
- 3) 维护创建表时声明约束难以实现的复杂完整性约束，并对数据库特定事件进行监控与响应。
- 4) 实现复杂的非标准数据库相关完整性规则，并可实时同步复制表中的数据。
- 5) 触发器具备自动性，只要表数据被修改就会被激活。例如自动计算派生值，达到阈值时触发特定处理。以企业财务管理为例，若资金链紧张程度触及设定阈值，系统可自动发出预警信息。

## 7.6 索引

建立索引能够显著提升系统性能，总体优势如下。

- 1) 大幅加快数据检索速度，这也是创建索引最主要的原因。
- 2) 加速表与表之间的连接操作。
- 3) 在实现数据参照完整性方面意义重大，例如在外键列上建索引可有效避免死锁，也能防止更新父表主键时对子表进行全表锁定。
- 4) 是减少磁盘 I/O 的有效手段之一。
- 5) 使用分组 GROUP BY 与排序 ORDER BY 时，可明显降低分组排序耗时，加快检索。
- 6) 创建唯一性索引可保证表中每一行数据的唯一性。
- 7) 查询时借助优化器提升系统性能。

索引的不足之处如下。

- 1) 索引只能建在表上，不能建在视图上。
- 2) 创建和维护索引会消耗时间，且随数据量增长而增加。
- 3) 建立索引需要占用物理存储空间，聚簇索引所需空间更大。
- 4) 对表进行增删改时，系统需额外时间维护索引的一致性，从而降低数据维护速度。

索引使用的原则如下。

- 1) 仅在大表上建立索引才有意义。
- 2) 在 WHERE 子句或连接条件中频繁引用的列上建索引。
- 3) 索引层级最好不超过 4 层。
- 4) 若某属性常作为最大值最小值等聚集函数的参数，可考虑建索引。
- 5) 表的主键、外键必须有索引。
- 6) 创建主键和唯一约束后会自动生成唯一索引。
- 7) 经常与其他表连接的表，其连接字段应建索引。
- 8) 经常出现在 WHERE 子句中的字段，特别是大表的字段，应建索引。
- 9) 查询时只返回表中很小一部分行的列适合建索引。
- 10) 查询涉及较少且重复值较多的列尽量避免建索引。
- 11) 经常出现在 ORDER BY、GROUP BY、DISTINCT 后的字段宜建索引。
- 12) 索引应建在选择性高的字段上。
- 13) 索引宜建在小字段上，大文本、超长字段不适合；CLOB、TEXT、IMAGE、BIT 类型列不适合建索引。
- 14) 复合索引的建立需仔细分析，前导列一般选择选择性较好的字段。
- 15) 若单字段查询很少或没有，可建立复合索引；否则考虑单字段索引。
- 16) 若复合索引中包含的字段经常单独出现在 WHERE 子句，应拆分为多个单字段索引。
- 17) 若复合索引包含字段超过 3 个，需审慎评估必要性，考虑减少字段数。
- 18) 若已存在单字段索引，同时存在这几个字段的复合索引，一般可删除复合索引。
- 19) 频繁执行 DML 操作的表不要建立过多索引。
- 20) 删除无用索引，避免对执行计划产生负面影响。

“水可载舟，亦可覆舟”，索引亦然。合适的索引提升检索性能，过多或不当的索引会拖慢系统。表中每增加一个索引，数据库的工作量就会增加，过多的索引甚至产生碎片。因此需要构建“适度”的索引体系，尤其是聚簇索引更需精益求精。提升查询效率是以消耗系统资源为代价的，盲目建索引是衡量 DBA 水平的重要指标。

## 第8章 操作系统

操作系统在计算机体系中扮演基石角色，是连接底层硬件与上层应用软件的桥梁，负责控制程序运行、管理系统资源并提供配套系统软件支持。对于专业程序员而言，掌握操作系统知识不可或缺，无论是底层嵌入式开发还是上层云计算开发都离不开相关概念。操作系统知识也是面试笔试的重点考察项之一。

### 8.1 进程管理

### 8.1.1 进程与线程

进程是具有一定独立功能的程序在某个数据集上的一次执行活动，是系统进行资源分配和调度的基本单位。例如用户运行程序，系统创建进程并分配资源，包括各类表格、内存空间、磁盘空间、I/O 设备，随后进程进入就绪队列，由调度程序选中并分配 CPU 及相关资源后运行。

线程是进程的执行实体，是 CPU 调度和分配的基本单元。线程本身几乎不拥有系统资源，仅保留程序计数器、寄存器组和栈等最少运行资源，但可与同进程内的其它线程共享进程的全部资源。在未实现线程的操作系统里，进程既是资源分配单元也是调度单元；在实现线程的操作系统里，进程是资源分配单位，线程是调度单位，是系统并发执行的单元。

引入线程主要带来以下优点：

- 1）调度更加灵活。
- 2）提升并发性，方便实现并发执行。
- 3）开销更小，创建线程比创建进程更快、成本更低。
- 4）有利于发挥多处理器优势，每个线程可在不同处理器上运行，实现应用并行。

需要注意，线程与进程既相似又差异明显，主要区别如下。

- 1）一个线程只能属于一个进程，一个进程可拥有多个线程且至少有一个线程。
- 2）同一进程的线程共享打开文件、Socket 等资源，不同进程相互独立。
- 3）线程被称为轻量级进程，进程有进程控制块，线程有线程控制块且更小，线程切换代价低，进程切换代价高。
- 4）进程是程序的一次执行，线程可理解为程序中某个片段的执行。
- 5）每个进程拥有独立内存空间，线程共享其所属进程的内存空间。

引申：程序、进程与线程的区别是什么？

程序、进程与线程的区别如表8-1所示。

表8-1 进程与线程的区别

| 名称 | 描述 |
|---|---|
| 程序 | 一组指令的有序集合，是静态的指令，会永久存在 |
| 进程 | 具有一定独立功能的程序关于某个数据集上的一次运行活动，是系统进行资源分配和调度的一个独立单元，存在是暂时的，是动态概念 |
| 线程 | 线程的一个实体，是 CPU 调度的基本单元，是比进程更小的能独立运行的基本单元。本身基本上不拥有系统资源，只拥有一点在运行中必不可少的资源（如程序计数器、一组寄存器和栈）。一个线程可以创建和撤销另一个线程，同一个进程中的多个线程之间可以并发执行 |

简而言之，一个程序至少有一个进程，一个进程至少有一个线程。

### 8.1.2 线程同步有哪些机制

当前流行的进程线程同步互斥控制机制，归根到底由临界区、互斥量、信号量和事件四种基本方法实现。

- 1）临界区：通过对多线程访问进行串行化来保护公共资源或代码段，速度快，适用于控制数据访问。任意时刻只允许一个线程进入，另有线程等待临界区释放后才能抢占。
- 2）互斥量：为协调对共享资源的独占访问而设计，只有持有互斥量的线程才有权访问公共资源。互斥量唯一，能保证资源不会被多个线程同时访问，并可实现不同应用程序间公共资源的安全共享。
- 3）信号量：用于控制有限数量用户资源，允许多个线程同时访问同一资源，但可限制同一时刻访问的最大线程数。
- 4）事件：用于通知线程某事件已发生，从而启动后续任务。

### 8.1.3 内核线程和用户线程

根据操作系统内核是否感知线程，可分为内核线程和用户线程。

内核线程的创建、销毁由操作系统通过系统调用完成，调度时操作系统会参考进程内线程的运行状态。若进程内没有就绪态线程，该进程不会被调度。与之相对，用户线程无需内核支持，在用户程序中实现，不依赖操作系统核心。用户进程利用线程库提供的创建、同步、调度和管理函数控制用户线程。用户线程常见于历史悠久的操作系统如 UNIX，无需用户态/核心态切换，速度快，但一个线程阻塞会导致整个进程阻塞。处理器时间片以进程为单位分配，各线程执行时间相对减少。为在操作系统中加入线程支持，常在用户空间增加运行库实现线程，称为“线程包”，操作系统无法感知用户线程。

引入用户线程的优势有：

- 1）可在不支持线程的操作系统上实现。
- 2）创建、销毁和切换线程的代价远低于内核线程。
- 3）允许每个进程定制自己的调度算法，线程管理更灵活。
- 4）线程可利用的表空间和堆栈空间比内核级线程更多。

用户线程的缺点主要有：

- 1）同一进程中同一时刻只能有一个线程运行，若有线程因系统调用阻塞，整个进程会被挂起。
- 2）页面失效也会导致整个进程被挂起。

内核线程的优缺点与用户线程相反。实际上操作系统常采用混合方式实现线程。

### 8.2 内存管理

内存管理是计算机系统的重要功能，良好的管理方式可降低缺页中断并大幅提升性能。以下介绍经典的内存管理方式。

### 8.2.1 内存管理方式

常见的内存管理方式有块式管理、页式管理、段式管理与段页式管理，最常用的是段页式管理。

- 1）块式管理：将主内存划分为若干大块，当程序片段不在主存时分配一块主存空间载入。优点是管理简单，缺点是浪费严重，平均浪费约 50% 内存。
- 2）页式管理：用户程序地址空间被划分为固定大小的页，主存也被划分为同样大小的物理块，页可装入任意块，实现离散分配。优点是页大小固定便于管理，缺点是页长与程序逻辑大小无关，可能导致程序只有部分在主存，不利于编程独立性和换入换出、保护、共享等操作。
- 3）段式管理：段按程序自然分界划分，长度可动态变化。用户地址空间被分成若干不等长的段，每段包含一组相对完整逻辑信息，存储分配以段为单位，段在内存中可不相邻，实现离散分配。分页对程序员不可见，分段通常可见，因而分段利于组织程序和数据，但对程序员要求更高。

分段存储的优点：

- ① 段的逻辑独立性利于编译、管理、修改、保护，也便于多道程序共享。
- ② 段长可动态改变，允许自由调度，有效利用主存空间。
- ③ 方便分段共享、分段保护、动态链接、动态增长。

分段存储的缺点：

- ① 段大小不固定，存储管理较麻烦。
- ② 会产生段内碎片，降低存储利用率，且硬件支持需求高于页式。

页式与段式各有缺点，因此引入段页式管理，结合两者优点。

- 4）段页式管理：用分段方法分配和管理虚拟存储器，程序地址空间按逻辑单位分成若干段，每段再分成固定大小的页；用分页方法分配和管理内存，主存被分成与页同大小的存储块，可装入作业的任一页。程序调入调出按页进行，但可按段实现共享和保护。

### 8.2.2 虚拟内存

虚拟内存简称虚存，是计算机系统内存管理技术，相对于物理内存而言，可理解为“假”内存。它使应用程序认为拥有连续可用的内存地址空间，允许程序员编写并运行远大于实际系统内存的程序，使大型软件能在内存资源有限的系统上运行。实际上虚存常被分割为多个物理内存碎片，部分数据暂时存放在外部磁盘存储，并在需要时交换。

虚存相比实存的好处：

- 1）扩大寻址空间，无论段式、页式还是段页式虚存，寻址空间均大于实存。
- 2）内存保护，每个进程运行在各自虚拟地址空间，互不干扰，虚存可对特定地址提供写保护，防止篡改。
- 3）公平分配内存，采用虚存后每个进程相当于拥有相同大小的虚存空间。
- 4）进程通信时可采用虚存共享方式实现。

使用虚存的代价主要体现在：

- 1）虚存管理需要建立大量数据结构，这些结构会占用额外内存。
