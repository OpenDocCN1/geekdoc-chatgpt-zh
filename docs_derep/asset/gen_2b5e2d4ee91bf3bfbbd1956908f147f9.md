**11.5 函数进阶：默认参数、重载与内联**

**11.5.1 生活小案例**

响应环保倡议，乐乐超市默认不再主动提供塑料袋，只有顾客明确提出才提供。这种“默认不给袋”的做法，就像函数里提前写好的默认值，没有额外指示就按既定规则执行。

店员的打包流程因此很省事：平时不必反复询问顾客要不要袋子，直接按默认方式处理即可，沟通成本降低，也更符合环保理念。顾客若有特殊需求再提出，店员再做调整。这与函数默认参数的思路完全一致，提前设定常用规则，调用时不用每次都说明，特殊情况再传新值覆盖，既高效又灵活。

**11.5.2 知识精讲**

**1.函数的默认参数**

1）认识默认参数

函数调用中，部分参数在大多数情况下取值是固定的。每次调用都显式写出这些不变的值，会让代码冗余、阅读性变差。默认参数正是为了解决这个问题，它允许为某些参数预设默认值。调用时若未提供该参数，就自动采用默认值，调用过程因此更简洁。

拿乐乐超市收银举例，大多数订单不需要额外包装也不需要加急。若每次都要明确填写是否包装、是否加急，操作繁琐易错。此时默认参数就像超市的默认服务，让处理订单更轻松，只需关注关键信息，其他按默认设置走即可。

**2.函数重载**

在编码中，经常需要实现功能相近但参数类型或个数不同的函数。若为每个函数起不同名字，代码会臃肿难记，可读性和可维护性下降。函数重载允许在同一作用域内用同一函数名定义多个版本，只要参数列表不同即可，提升代码的统一性和可维护性。

1）重载的概念

函数重载指在同一作用域定义多个同名函数，核心要求是参数列表必须不同，具体表现为参数类型、个数或顺序至少有一项差异。例如 add（int a，int b）与 add（int a，int b，int c）因个数不同可重载，add（int a，double b）与 add（double a，int b）因顺序不同也可重载。编译器会根据实际调用的参数自动匹配合适的版本。

2）示例代码

[PRE9]

示例中 add 被重载三次，分别处理两个 int 相加、两个 double 相加、三个 int 相加。编译器依据调用时参数类型和个数选择对应实现。

3）重载解析流程

调用重载函数时，编译器按以下步骤选择：

（1）精确匹配。先寻找参数类型和个数完全一致的版本，找到即调用。
（2）类型转换匹配。若无精确匹配，编译器尝试进行隐式类型转换，挑选最接近的版本。
（3）错误处理。若转换后仍无合适版本，或存在多版本皆可转换，编译器报错。

**3.内联函数**

函数调用本身有开销，包括保存寄存器、参数传递、跳转等。对于简单且高频的函数，这些开销会累积影响性能。内联函数是一种优化手段，让编译器把函数体直接展开到调用位置，减少调用成本。

1）内联函数的定义

在函数定义前加上 inline 关键字即声明为内联函数，编译器会尽量把函数代码嵌入调用处，而不是做常规调用。例如：

注意：inline 只是建议而非强制，函数过长、含有递归等情况编译器可能拒绝内联，避免代码膨胀。

2）优缺点

（1）优点。减少调用开销，提升执行效率；代码路径更直观。
（2）缺点。若用于复杂或较大的函数，会导致代码膨胀，增加内存占用，降低性能。inline 只是提示，是否真的内联由编译器决定。

**12.1.1 生活小案例**
