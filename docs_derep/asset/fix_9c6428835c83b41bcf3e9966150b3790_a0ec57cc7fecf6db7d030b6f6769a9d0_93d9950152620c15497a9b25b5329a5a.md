大模型落地实战：训练与微调关键手记

把大模型从实验环境推向生产，经常卡在几个关键环节。分词层面，BERTTokenizer 与 GPTTokenizer 的底层切分逻辑并不相同，前者偏向双向的 WordPiece，后者偏向单向的 BPE。用同一段示例文字分别送入两个分词器，可以直观看出 token 序列与边界的差异，进而根据目标架构挑选匹配的分词工具。

标注环节，训练时需要把清洗后的文本绑定类别标签。标签的干净程度直接决定模型的上线水位，错误或模糊的标注会成为性能瓶颈。通过代码示例可以看到怎样为已分词的文本挂上类别，并把带标签的样本打包成 DataLoader 供模型读取。

大规模预训练进入分布式阶段时，要先配置多 GPU 的运行环境。world_size 描述的是参与任务的总进程数，rank 用来区分每个进程的身份。代码里会体现 init_process_group 的参数设置，以及 rank 与本地设备的一一对应。

训练真正起跑前，需要一个标准化的启动流程。环境初始化、进程组创建、模型与数据分布等步骤排好序后，分布式任务才能稳定拉起。

预训练的稳定性离不开中间检查点。把模型权重与优化器状态定期落盘，可以在出现异常时避免从零开始。示例里实现了每 10 个 epoch 自动保存一次权重和运行状态的逻辑。

TensorBoard 的记录密度会影响曲线可读性。记录频率过高会拖慢训练，过低则丢失细节。在训练回路里设定合适的日志步长，并写入自定义的评估指标，能让损失与精度变化更清晰。

设置了检查点后，如果训练中断，恢复时要同步学习率调度、优化器状态、已完成的 epoch 数以及随机种子等要素。示例演示了从本地检查点载入权重、优化器与计数器并继续迭代的完整路径。

中断与恢复并非无感操作，不合理的恢复策略会扰动收敛轨迹。通过固定恢复点、保持优化器动量一致，并避免在关键下降阶段频繁重启，可以把中断带来的精度损失降到最低。

DataLoader 的 batch_size 直接关联显存占用。显存受限时，适当调小批次或结合梯度累积，可以在保证训练效率的前提下平稳运行。

单卡与多卡的耗时差距明显。DistributedDataParallel 会把一个批次拆分到不同设备上计算，梯度再在后台汇总，从而实现负载均衡。代码示例展示了 DDP 下的数据划分与梯度同步带来的加速效果。

多卡环境下，优化器需要在各设备间保持参数一致。初始化时指定设备，更新时依赖分布式后端的 all-reduce 机制，才能让所有卡的参数更新保持同步。

from sklearn.metrics import accuracy_score

def evaluate_model(model, test_loader):

    model.eval()

    all_preds, all_labels = [], []

    with torch.no_grad():

        for batch in test_loader:

            inputs = {k: v.to(device) for k, v in batch.items()

                    if k in ["input_ids", "attention_mask"]}

            labels = batch["label"].to(device)

            outputs = model(**inputs)

            predictions = torch.argmax(outputs.logits, dim=-1)

            all_preds.extend(predictions.cpu().numpy())

            all_labels.extend(labels.cpu().numpy())

    accuracy = accuracy_score(all_labels, all_preds)

    print(f"Test Accuracy: {accuracy*100:.2f}%")

evaluate_model(model, test_loader)
