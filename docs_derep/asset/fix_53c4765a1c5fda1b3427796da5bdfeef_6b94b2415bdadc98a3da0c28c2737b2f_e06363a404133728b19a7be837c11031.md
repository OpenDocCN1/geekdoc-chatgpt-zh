# LangGraph 让写作闭环自动跑

把写作拆成可重复的工序，让模型在构思、查证、成稿、复盘之间来回跑，就能得到更扎实的文章。下面这个范例演示了如何用 LangGraph 把立意、资料搜集、初稿、审校和补充检索串成一个会自己迭代的流程，并画出可视化的图。

先定义一个贯穿全程的状态容器。里面放着标题、提纲、稿件、点评、已累积的参考资料，以及当前修订轮数和允许的上限。这样每一步都能读写同一个上下文，信息在图中稳定传递。

四个角色提示分别负责不同任务：提纲设计者根据标题产出结构，写作者依据结构和资料生成内容，审校者针对稿件给出专业反馈，研究员在起稿和改稿阶段各生成三条搜索 query。角色分工让每一步的意图更清晰。

整体实现包含六个处理单元：由标题生成提纲、基于提纲检索信息、撰写或重写、产出点评、根据点评补充信息、以及决定是否继续的判断函数。每次撰写后计数自增，判断函数对比次数与上限，超限则结束，否则进入审校。

执行顺序是先提纲后立项检索，为写作准备素材；首稿完成后走条件分支，达到上限直接结束，未达上限先审校再针对性检索，再回到写作。这样就能形成提纲-检索-写作-审校-检索的回路。最后用内存检查点编译图并渲染流程图，以“中国的茶文化”为案例，最多迭代两轮进行流式演示。

def should_continue(state:AgentState):

    if state["revision_number"] > state["max_revisions"]:

        return END

    return "reflect"

builder = StateGraph(AgentState)

#增加节点

builder.add_node("outline_node", outline_node)

builder.add_node("write_node",write_node)

builder.add_node("reflection_node", reflection_node)

builder.add_node("outline_search_node", outline_search_node)

builder.add_node("critique_search_node",critique_search_node)

#将生成大纲的节点作为起始节点

builder.set_entry_point("outline_node")

#增加条件边

builder.add_conditional_edges(

    "write_node",

    should_continue,

    {END:END,"reflect":"reflection_node"}

)

#连接各个节点

builder.add_edge("outline_node","outline_search_node")

builder.add_edge("outline_search_node","write_node")

builder.add_edge("reflection_node","critique_search_node")

builder.add_edge("critique_search_node","write_node")
