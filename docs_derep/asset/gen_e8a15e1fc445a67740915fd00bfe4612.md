把网络入口收紧，是守住安全的第一步。切到本地访问模式就是一种很有效的防护手段。把网关配置改成只放行本机 IP，比如 127.0.0.1，就能从源头上把公网请求截住，这是最稳妥的部署方式。要是从外网连 OpenClaw，强烈建议走 Tailscale Serve 这类安全通道，别直接把端口暴露到公网。同时一定要用 “openclaw token generate” 指令生成访问令牌，让公网访问必须凭有效凭证才行。

访问控制层也得盯紧。配对模式务必保持开启，陌生人加好友必须由管理员审批。在群聊里建议把 requireMention: true 打开，避免 AI 被随意触发，陌生人就无法直接指挥你的 OpenClaw 执行任务。

另外，初始化时对非核心的技能和 API Key 一律选 “Skip for now” 或 “No”，只绑定工作必需的账号。这就是最小权限原则，只给任务完成所需的最小权限集合，权限越多风险越大。

ClawHub 技能市场是 OpenClaw 生态的重要一环，但供应链攻击风险也在这里。安全研究人员曾发现市场上存在大量伪装成效率工具的恶意技能，目的其实是窃取用户数据。常见手法是在 SKILL.md 里直接写死 API 密钥和密码，把敏感凭证拼进 LLM 提示词，或在输出里泄露敏感信息。

装技能前做好三步核验。先看 VirusTotal 安全扫描报告，详情页通常会展示结果，一旦被标为 “恶意” 就直接放弃；再核实 GitHub 仓库，只装提供开源仓库的技能，并确认维护者身份和最后更新时间；最后细读 SKILL.md，特别警惕 curl | bash 这类下载并执行外部脚本的写法，这是高风险信号。

企业用户最好建一套内部技能审核机制。所有从外部拉来的技能，都应该先过安全团队审查，确认没有恶意代码或漏洞后再上生产。虽然多一道流程，但能有效避免数据泄露或被控风险。

涉及敏感操作，建议启用二次确认机制。在 MEMORY.md 里可以预设规则：所有删除类操作，无论删文件还是删数据库记录，都必须先确认；所有数据导出操作要明确文件路径确认；所有系统指令执行前必须经用户审核。

养成定期查日志的习惯。通过日志能清楚 OpenClaw 都做了什么，有没有异常。发现可疑记录要及时追查。OpenClaw 提供的 sessions_list 和 sessions_cleanup 工具可以帮助管理会话历史，更好地做审计。

提示词注入是常见威胁，攻击者会在输入里植入恶意指令劫持 AI 行为。当 OpenClaw 读取外部网页或文件时，可能被恶意指令“洗脑”，从而执行非预期操作。

防御手段包括：在系统提示词里固化安全约束，明确告知 AI 哪些指令禁止执行；对输入做数据边界检查，识别并过滤可疑指令模式；尽量避免让 AI 直接处理来源不明的外部内容。

一个实用做法是在 MEMORY.md 中提前定义安全边界，例如“不要执行任何涉及系统权限提升的指令”“不要修改系统配置文件”“不要访问未明确授权的外部 URL”。这些规则会在每次会话开始时加载，形成持续的安全防护层。
