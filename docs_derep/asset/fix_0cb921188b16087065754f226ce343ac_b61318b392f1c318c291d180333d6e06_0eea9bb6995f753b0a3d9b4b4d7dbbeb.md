# Runnable：让调用链既能流式又能异步

Runnable 提供了统一的调用契约，让响应式编程与事件驱动架构的搭建更顺手。同步能力集中在三类操作：stream 把数据切块逐段返回，适合海量或实时场景；invoke 针对一条明确输入跑完整条链并给出结果；batch 则一次性对输入清单批量跑链。三者共同构成同步调用的基础，让链式处理的组织更直观。

非阻塞编程普及后，Runnable 的异步版也随之补齐。astream 支持异步逐块推送数据，ainvoke 与 abatch 分别是单条与批量输入的异步版本，不会阻塞主线程。astream_log 能在执行过程中实时捕获日志并流式返回，astream_events 则把链路上发生的事件实时推送，对调试与监控非常友好。异步家族的加入大幅提升了系统的响应性，也让现代化流式系统的构建更有弹性。

工程实践里，各类型组件对进出数据的约定各不相同，详见表4-1。Prompt 接收字典配置，输出 PromptValue，用来生成提示。ChatModel 更通用，可接收纯文本、消息列表或 PromptValue，输出 ChatMessage，常用在对话与自然语言处理。LLM 输入形态与 ChatModel 相同，输出为纯文本，负责文本生成与转换。OutputParser 专门解析 LLM 或 ChatModel 的结果，输出形态由具体解析器决定。Retriever 以单条字符串查询，返回文档列表。Tool 的输入可能是字符串或字典，具体取决于工具实现，输出也随工具而变。

#### 4.3.4 异步事件流

异步事件流 Async Stream Events 于 langchain-core 0.2.0 引入，属于测试版 API，未来可能调整。为正确使用 astream_events API，需注意：整个代码尽量保持异步，包括异步工具；若定义自定义函数 Runnable，必须传播回调；若不借助 LCEL 直接调用 Runnable，确保在 LLM 上调用 .astream() 而非 .ainvoke()，以强制 LLM 流式传输 token。

复杂软件系统中，各类 Runnable 对象在执行时会触发多项事件，为监控与交互提供丰富信息。例如聊天模型开始、流式处理或结束时，分别触发 on_chat_model_start、on_chat_model_stream 与 on_chat_model_end，携带模型名称、消息块、输入数据，以及结束时生成的输出数据。LLM 也有开始、流式、结束三类事件，分别是 on_llm_start、on_llm_stream 与 on_llm_end，提供模型名称、输入文本、流式文本内容及最终输出文本的细节。

除聊天模型与 LLM 外，其它类型 Runnable 也会触发事件。例如 on_chain_start、on_chain_stream 与 on_chain_end 分别在文档处理链开始、处理中与结束时触发，关注点包括文档格式与内容。工具类 Runnable 如 some_tool，以及检索器类 Runnable 也类似地触发开始、流式、结束事件，携带工具执行状态、输入参数、处理中数据块及最终输出结果的信息。模板启动与结束事件 on_prompt_start 与 on_prompt_end 提供模板名称、问题输入及最终产生的提示值细节。这些事件共同构成系统交互与执行监控的基础，帮助开发者更好理解与调试系统行为。更详细内容可参考 LangChain 官方文档。
