层级化的文档体系搭配检索机制，具备很强的自适应调整能力。检索结果会直接影响上下文取舍范围，系统就能根据不同查询意图和场景灵活收敛或放宽窗口。这种弹性让应用在复杂多样的问题上依然保持响应度，提升整体使用体验。

#### 3. 扩大上下文的两种策略对比

滑动窗口式的句子检索在精准定位上优势明显。它在文本上滚动一个固定长度的窗口逐句抓取信息，很快就能挑出与问题最相关的几句。面对短文本时，这种局部聚焦的方式能迅速给出要点回复。局限在于视野太窄，容易丢失更广的背景，导致理解片面。

父文档检索则给模型完整的语境支撑，能更好捕捉长距离语义关联。该方式直接取回整段父文档，而非孤立句子，保证信息连贯且完整。在长文本场景下效果尤其突出，背景充足有助于模型把握整体意图。代价是速度偏慢，有时还会带入冗余内容。

实际选用要看任务目标和文本形态。求精确短答时，句子窗口更合适；需通盘理解时，父文档更稳妥。两者也可以组合使用：先用句子窗口锁定关键句，再按这些句子所属的父块判断是否需要进一步放大范围。这样既保留精准度，又兼顾完整性，能显著提升生成质量。综合示例如下：

indices_sentence = search(query, top_k=1)

expanded_context = []

for idx in indices_sentence:

# 使用父文档检索方法

indices_child = search_children(query, top_k=k_child)

parent_count = defaultdict(int)

    parent_count[parent] += 1

    combined_context = '\n'.join(parent_context)

else:

return combined_context

上面这段 combined_search 把句子窗口和父文档检索串联起来，向大模型供给更全面也更准确的上下文。通过策略切换，既能保证召回的精确，又能确保语境的完整性。

## 3.4 大模型选型与提示词设计

在 RAG 架构里，生成模型负责把检索到的材料和用户需求融合，用自然语言输出答案。提示词工程是提升生成效果的核心手段，合理设计提示可以在不增训的前提下引导模型产出更高相关性的结果。

模型选择同样关键，它决定了生成质量、上限和部署成本。

### 1. 选型时需要权衡的维度

选型要综合看能力、资源和许可，适配 RAG 的实际需求。相关考量汇总如下表。

表 3-2 模型选型的考虑因素

| 考虑因素 | 具体含义 |

| --- | --- |

| 性能 | 理解和生成能力：模型在理解用户查询和生成准确回答方面的能力<br>多语言支持：根据应用场景，是否需要支持多种语言 |

| 计算资源 | 参数规模：较大的模型通常需要更多的计算资源<br>部署成本：计算资源的消耗直接影响部署和运行成本 |

| 上下文窗口大小 | 长文本处理：RAG 系统需要处理长文本，较大的上下文窗口能够提高性能<br>内存消耗：上下文窗口越大，对内存的需求也越高 |

| 开源与商用 | 开源模型：便于二次开发和定制<br>商业许可：需要确保模型的使用符合许可协议，尤其是在商业应用中 |

### 2. 提示词工程

在 RAG 场景里，提示词不仅影响输出质量，也决定检索信息能否被有效利用。常用技术如下。

#### （1）零样本提示

零样本提示指直接用任务描述引导模型完成任务，无需示例。靠预训练知识即可快速验证新任务表现。

示例：
> “请用简洁的语言解释什么是量子物理。”

模型会基于已有知识给出简要说明。

#### （2）少样本提示

少样本提示给模型少量输入输出示范，帮助其把握任务模式。几个高质量问答对就能显著提升问答表现。

示例：
> “问：地球的卫星是什么？
答：月球。
问：太阳系中最大的行星是哪个？
答：”

模型会续写：“木星。”

在 RAG 中，少样本提示有助于模型更好地理解用户意图。

#### （3）思维链提示

思维链提示让模型先展示推理步骤再给出答案，把复杂问题拆解，降低错误率，也便于校验逻辑。

示例：
问题：小明买了两件衣服，衣服 A 原价 100 元，打 8 折出售，衣服 B 原价 199 元，在满 100 元立减 20 元的活动下购买。请问小明总共需要支付多少钱？

思考过程：
1. A 价为 100 元 × 0.8 = 80 元。
2. B 价为 199 元 - 20 元 = 179 元。
3. 合计 80 元 + 179 元 = 259 元。

最终答案：259 元

先推理后作答，能提升可信度和可追溯性。

#### （4）自动思维链提示

自动思维链通过多样本生成多条推理路径，增强鲁棒性，减少单一路线的偏差。

示例：
> “我会向你提出问题，请使用多种可能的思维链（至少 3 种不同的推理方式）来解答问题。分别列出每种思维链下的推理过程和结论。最后请你对所有思维链的结论进行综合比较，给出你认为最可信、最一致的最终答案。”

模型会产出多条推理并综合判断。

#### （5）思维树提示

思维树提示模拟树状搜索，让模型探索多个解法分支再汇总。

示例：
> “问题：如何优化网站的 SEO 排名？
思考 1：改进网站内容质量。
思考 1.1：提供有价值的原创内容。
思考 1.2：定期更新内容。
思考 2：优化关键词。
……
答案：通过提供高质量的原创内容，定期更新，并优化关键词，可以有效提升网站的 SEO 排名。”

灵活运用上述提示方法，可显著提高生成质量，实际落地时需结合任务和模型特性细化设计。

## 3.5 检索与生成的融合方式

RAG 框架里，信息融合主要有 RAG-Token 和 RAG-Sequence 两种模式。两者在检索时机和方式上不同，影响生成效率与灵活度。

RAG-Token 在生成每个 Token 时都触发检索，能实时引入最新信息，提升准确性和时效性，但计算开销和延迟也更高。RAG-Sequence 则在整段生成前做一次检索，效率更高，但实时性和精确度可能打折。

尽管机制不同，两者目标一致：让检索与生成协同，依场景提供高质量输出，充分利用外部知识并适配不同任务需求。

### 3.5.1 RAG-Token 模型

RAG-Token 的架构亮点在于生成过程中动态注入外部检索上下文。

#### 1. RAG-Token 模型概述

传统生成模型主要依赖内部知识库，受容量和更新频率限制，输出易不全面。RAG-Token 通过在生成时动态检索外部上下文，弥补了这一短板，能输出更准确、相关且全面的内容。

核心组件包括：

1）问题编码器：把用户查询映射为高维向量，捕捉关键意图，为检索提供结构化基础，便于后续匹配相关文档。
