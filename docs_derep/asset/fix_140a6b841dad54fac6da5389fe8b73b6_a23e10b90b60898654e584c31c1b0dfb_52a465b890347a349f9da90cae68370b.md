稳健调用：多模型熔断降级实践

线上业务若只绑定单一大模型，一旦该服务抖动、响应超时或触发限流，整体链路就会连带受损。把全部流量集中投递到一个出口，抗风险能力非常脆弱。下面这套框架通过请求预处理、按权重择路、熔断隔离与自动降级相结合，让大模型调用具备更高的韧性。

请求进入后先做安全预处理，剥离不可见控制码与 HTML 标记，并把文本截断到 4000 字符以内，随后依据当前健康情况挑选可用端点。每个端点会记录失败计数与熔断状态，连续失败到达阈值即切换为阻断态，期间不再调度；等待恢复窗口到期后转为试探态，放少量探针验证，验证通过则恢复服务，失败则继续保持隔离。阈值、恢复窗口、单次请求超时、最大重试次数均可通过配置集中管理，同时语义缓存可降低重复计算的开销。

端点初始化时按权重排序，权重数值越小越靠前，主用组包含 deepseek-v3、qwen-max、glm-4-plus，备用组包含 qwen-turbo 与 glm-4-flash，用于在主用不可用时承接流量。熔断器有三种工作模式：正常通行、阻断隔离、试探恢复，分别对应不同阶段的调度策略。

class CircuitState(Enum):

    CLOSED = "closed"    # 正常状态

    OPEN = "open"        # 熔断状态

    HALF_OPEN = "half_open"  # 半开状态（尝试恢复）

@dataclass

class ModelEndpoint:

    name: str

    base_url: str

    api_key: str

    priority: int  # 优先级，数值越小，优先级越高

    failure_count: int = 0

    last_failure_time: float = 0

    circuit_state: CircuitState = CircuitState.CLOSED

@dataclass

class FaultToleranceConfig:

    failure_threshold: int = 3      # 连续失败次数阈值

    recovery_timeout: float = 60.0  # 熔断恢复时间（秒）

    request_timeout: float = 30.0   # 单次请求超时时间

    max_retries: int = 2            # 最大重试次数
