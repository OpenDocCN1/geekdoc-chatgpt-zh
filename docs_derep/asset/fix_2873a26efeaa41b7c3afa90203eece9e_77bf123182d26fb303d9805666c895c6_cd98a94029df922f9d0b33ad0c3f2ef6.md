向量索引与 MCP 联动：RAG 实战拆解

先看这个简易向量库是怎么把文档落地成可检索的结构。建索引时它会用 enumerate 逐条遍历输入，用 mock_vector_for_doc 配合 VEC_DIM 把每段文字转成伪向量，随后把下标和向量一起追加到内部的 index 列表，同时把下标映射到原文保存在 doc_map 里以便后续回查。检索函数 search 接收一个查询向量，内部会遍历 index 中所有条目，按欧式距离公式算出与查询向量的距离并保存成包含 doc_id 与 dist 的记录，全部算完后按 dist 升序排序，仅返回前 top_k 条。get_doc_text 则很直接，通过传入的 doc_id 去 doc_map 取回对应的原文。整体使用上，模块启动时会先实例化一个全局的 VEC_DB，调用 build_index 喂入 DOCS 完成一次建库，后续所有查询都复用这份已建好的结构。
