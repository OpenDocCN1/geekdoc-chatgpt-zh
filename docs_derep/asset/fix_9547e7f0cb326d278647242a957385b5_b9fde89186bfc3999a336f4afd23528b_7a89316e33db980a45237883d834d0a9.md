#### 2.2.9 可扩展模块库
结构化提示更像一种方法论，本章提供的模板只是现阶段的实践参考。实际使用时完全可以根据需求增删、重组模块，甚至构建全新的体系。

提示词设计必须贴合场景，固定套路在需求差异大的任务上容易因描述不足而失效。以下按字母顺序整理出30个可组合的视角，撰写时可挑选拼装。

### 2.3 结构化提示词的写作要点

#### 2.3.1 格式选择
借助标记把提示拆分是常见技巧，为什么要把结构化提示和格式化提示区分开？格式化只是结构化的一部分。

格式化只关心形式，说明内容如何排布，却忽略了思维与语义的组织。结构化提示把格式当作手段，核心在于构建清晰的思维与语义体系，将角色化设计等技术有机融合。

日常文章靠字号、颜色区分层级，ChatGPT 输入不带样式，因此可以借鉴 Markdown、YAML 等标记语言或 JSON 等数据结构来实现结构表达。JSON、YAML 对开发者更友好，Markdown 对大众更友好。

理论上可用任意标记规则，实践中大模型对 Markdown、JSON 的识别较好，Claude 在 XML 下表现更好。下面是一个用 Claude 做法律合同分析的 XML 示例。没有标签时分析松散易漏点，加标签后输出条理完整，便于法务落地。

分析这份软件许可协议中的法律风险和责任。我们是一家跨国企业，正在考虑将此协议用于我们的核心数据基础设施。

<agreement>{{CONTRACT}}</agreement>

这是我们的标准合同，供参考：

<standard_contract>{{STANDARD_CONTRACT}}</standard_contract>

<instructions>

1.分析以下条款：-赔偿-责任限制-知识产权所有权。

2.注意不寻常或值得关注的条款。

3.与我们的标准合同进行比较。

4.在 <findings> 标签中总结发现。

5.在 <recommendations> 标签中列出可执行的建议。

</instructions>

本书推荐 Markdown，理由如下：

● 模型理解顺畅：训练语料中常见格式多，模型对这些格式更熟悉。
● 人类阅读友好：常见格式无需额外学习成本。

国内主流模型均支持 Markdown，且对程序员和非程序员都友好。本书采用轻量 Markdown，仅使用基础符号，便于快速上手。

#### 2.3.2 建立全局思维链
优秀的结构化模板本身就形成了一条全局思维链。以 LangGPT 为例，其链路为：

`Role`（角色）→`Profile`（角色简介）→`Profile`下的`Skills`（技能）→`Rules`（规则）→`Workflow`（工作流）→`Initialization`（初始化）→正式执行

提示词在内容上应逻辑连贯。结构化方法把经过验证的思维链固化在结构里，降低了链路设计难度。

可以参考优质模板的整体链路，再进行增删改。需要控制输出格式时，可加入`Output`或`OutputFormat`模块。

#### 2.3.3 保持语义一致
高质量提示词需要保持上下文语义一致，包含格式语义一致和内容语义一致。

格式语义一致指标识符的功能前后统一，不要混用。例如#同时表示标题和变量会干扰层级识别。

内容语义一致指链路上的属性词要恰当。LangGPT 最初用`Features`表示简介，后改为`Profile`，表意更清晰。结构化思想衍生出多种模板，但大都保留`Profile`，说明设计有效。

`Features`来源于 AI-Tutor 项目启发，该项目提示词复杂不通用。笔者结合工程经验和模型特性提炼出本书的结构化思想并设计模板。

内容语义一致还体现在属性词与模块内容的匹配。例如`Rules`里应写规则而非堆砌技能描述。

#### 2.3.4 融合其他技巧
结构化思想是一种方法，与 CoT、ToT、逐步思考等技巧并不冲突。构建提示词时可以协同使用，结构化更便于组织多种技巧。例如把 CoT 融入结构化模板编写提示词。

所有提示词方法都可用于结构化提示词，建议灵活组合，以用不可靠的 LLM 构建可靠系统。

### 2.4 提示词编写的自动化

简单使用时直接提问即可。若要构建复杂、稳定的提示词，通常需要：

1）编写提示词；
2）验证效果；
3）修改调整。

提示词较长时编写耗时，若领域不熟易无从下笔。初版完成后需反复验证与调优，耗时耗力，依赖经验。

一个好提示词往往需大量迭代调试。1.10 节已介绍迭代方法，本节聚焦用工具实现自动优化，加速编写。

#### 2.4.1 手工编写流程
基于模板，编写从“作文题”变成“填空题”。手工流程为：套用现有模板→手工迭代调优→满足需求的提示词。

学习者可通过手工流程加深理解。

#### 2.4.2 自动化编写流程
入门者建议用自动化生成初稿。复杂高性能提示词可采用：
