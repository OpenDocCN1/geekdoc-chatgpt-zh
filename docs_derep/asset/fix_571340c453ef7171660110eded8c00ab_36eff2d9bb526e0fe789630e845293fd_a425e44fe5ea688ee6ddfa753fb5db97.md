在实际部署中，大模型返回的 JSON 偶尔会出现细微瑕疵，例如多余的逗号或引号未配对，导致解析失败。为了提升健壮性，可以引入专门的 JSON 校正库，像 Python 的 json-repair、Node.js 的 jsonrepair 这类工具，在正式解析前先自动修复这些小问题。

同时，交互过程中的即时回馈也很关键。用户点击“保存”后界面应提示“正在提炼”，操作成功时显示“知识已保存”，失败则给出明确的错误信息，并且知识图谱与列表能够自动刷新。这些细节共同构成了流畅的使用体验。

借助上述做法，就能为 AI 知识助手搭建一个较为完善的客户端。用户既能浏览 Agent 的记忆，也能通过聊天进行互动，并将有价值的内容便捷地沉淀为长期记忆。

## 6.4.5 用户偏好，让AI更懂你

前文已实现与 AI 知识助手的对话，并把有用信息提炼为长期记忆。但真正智能的助手，除了记住知识，还要记住“使用者是谁”，即掌握个人偏好，从而提供更贴合的服务。

设想你有一位真人助理，无需每次都重复“请用通俗语言解释”或“我偏好看代码示例”，他会记住这些使用习惯。AI 知识助手也应具备同样的能力，这正是个人偏好功能要解决的问题。

### 1. 什么是用户偏好

用户偏好指的是用户在与 AI 互动时表现出的稳定习惯与喜好。有人偏爱简洁直白的回复，有人则希望解释详尽全面；新手可能需要基础概念铺垫，而专业人士只关注技术要点。把握并记录这些倾向，能让 AI 在没有额外指令时仍给出符合习惯的答案，从而显著改善体验。

### 2. 如何捕捉用户偏好

偏好的识别主要依赖提问方式、反馈态度和交互行为的分析。可以定制一个专用 Prompt，让 AI 在对话过程中持续挖掘并记录以下几类偏好。

(1) 回答长度偏好：用户更倾向简短核心的回复还是详尽全面的说明。
- 观察用户是否常跳过冗长内容或直接要求简化；
- 注意用户是否频繁追问“能详细点吗”或“还有更多细节吗”。

(2) 专业程度偏好：用户的领域知识水平和术语接受度。
- 分析用户自用专业术语的频率与准确性；
- 观察是否经常需要基础概念解释；
- 记录用户对专业术语的反应是否理解或要求释义。

(3) 语言风格偏好：用户喜欢的交流方式和语言特点。
- 分析用户自身语言是偏正式还是随意；
- 观察对幽默回应或严肃回应的反馈；
- 留意是否有特定语言习惯，如使用表情符号、简写等。

(4) 学习方式偏好：用户最容易理解新信息的方式。
- 记录对代码示例、理论解释或生活类比的反应；
- 分析提问模式和后续问题类型；
- 观察是否更倾向视觉学习如要求图表，还是文字学习。

### 3. 如何实现用户偏好功能

要落地该功能，客户端与服务端都需要改造。

（1）偏好分析：在每次对话结束后，用 LLM 分析本次交互可能体现的用户偏好，并生成结构化数据。可借助前面介绍的 Function Call 技术，强制模型输出符合预定义格式的 JSON。

（2）偏好存储：在 MCP 服务器上新增工具 update_user_preference，用于接收并持久化用户偏好数据。可存于单独文件如 user_preference.json 或数据库。

(3) 偏好应用：用户发起新对话时，客户端先从服务器拉取已保存的偏好，并将其作为系统提示词的一部分随请求发送给 LLM。这样模型在生成回答时会自然兼顾这些偏好。

下面是一些可作为系统提示词一部分的用户偏好示例。

用户偏好如下。

- 使用简单的语言，避免专业术语；
- 用户是素食主义者，不要推荐含肉食谱；
- 回答后附上西班牙语翻译；
- 在规划旅行时，包含每日成本估算；
- 用户只会JavaScript编程；
- 用户喜欢简短、精炼的回答。

### 4. 用户偏好的动态调整

用户偏好并非固定不变，会随时间与场景变化，系统需要支持动态更新。

(1) 权重系统：为每个偏好设置权重，出现频率越高权重越高。
(2) 时效性考虑：近期偏好应比早期偏好具有更高权重。
(3) 场景区分：识别不同对话场景如编程问题、生活建议等，为不同场景维护独立的偏好集合。
(4) 明确覆盖：当用户明确表达新的偏好时，应立即更新并覆盖旧的相关偏好。

通过这种方式，AI 知识助手不仅能记住知识，还能“记住”用户是谁，提供真正个性化的服务体验。这就像一个不断学习你习惯的朋友，每次交流都更默契高效。
