资源模板与参数解析

资源声明与此前不同之处在于新增了 URI 模板 users://{user_id}/profile。其中 {user_id} 充当可替换的变量位。FastMCP 能够自动读取客户端发来的 URI 中的变量位，并把解析结果作为参数传递给对应函数。例如客户端请求 user://user1/profile 时，服务端会调用 get_user_profile(user_id="user1")。函数内部可以根据入参自行实现处理，例如基于该 user_id 在数据库中检索相关资料。

基于此资源机制，开发者可以按需声明资源形态及参数，供客户端调用，从而为大模型提供持续的上下文补给。

### 3.2.5 启动 MCP 服务端

已完成一个功能有限的 MCP 实例搭建，接下来需要将其运行起来以便客户端调用。查阅资料时会看到调试启动、命令行启动、第三方集成启动等多种写法，表面差异较大，本质来自同一套启动代码。下面从两种基础传输方式的启动原理展开说明。

**1. 两种传输方式的启动原理**
在 MCP 集成架构中，客户端与服务端存在两种传输方式，即 stdio 与 SSE。依据支持的传输方式，启动方式分为两种，如图 3-4 所示。

[PRE4]
图 3-4

（1）基于 stdio 的本地传输。该模式下服务端与客户端通常部署在同一主机，通过标准输入输出 stdin/stdout 进行进程间通信。服务端的启动通常由客户端程序通过命令行自动触发，启动后服务端成为客户端子进程，通信依赖启动时建立的 stdin/stdout 通道。
因此采用 stdio 时，服务端的启动命令通常写在客户端配置中，虽可手动执行命令启动，但无法与客户端建立传输。

（2）基于 SSE 的传输。该模式下服务端不能由客户端拉起，需单独执行命令启动。启动后服务端会在配置的端口监听连接与请求。
因此采用 SSE 时，需在客户端配置服务端的地址、端口与连接端点如 /sse，然后手动执行命令启动服务端。可采用 python 或 uv run 启动，在 TypeScript 环境下常用 node 或 npx，也可使用 SDK 提供的 mcp cli 工具。
