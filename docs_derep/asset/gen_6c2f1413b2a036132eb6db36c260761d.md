LangGraph 的基本思路是用节点 Node 和边 Edge 拼装出复杂的循环化工作流，并以消息传递的方式把各个节点串联成一条可执行的路径。信息在图中能否及时刷新并精准送达，核心就依赖于它提供的 State 机制。图的每次运行都会孵化一个状态实例，节点在执行时读取、修改这个状态。状态并非一成不变的数据快照，而是随节点输出持续演进，进而影响循环内部后续操作的走向，如图 8.15 所示。

共享状态指的是图运行期间在节点间流动的数据与信息。LangGraph 允许节点在执行过程中读写同一个公共状态来完成交互。这种共享状态的设计让节点能够基于共同维护的数据交换信息、互相影响行为，实现操作上的协调与同步，支持动态交互和复杂流程的编排，使节点可以根据已有共享信息协同工作并做出决策。

##### 5. 官方定位与核心优势盘点
从官方定义来看，LangGraph 是一个用于基于大模型构建有状态、多参与者应用的库，可用来搭建 Agent 及多 Agent 流程。其总结的核心优势为：

- 循环与分支：支持在应用中落地条件分支和循环逻辑。
- 状态持久化：每步执行后自动保存状态，可随时暂停与恢复运行，便于错误恢复、人机协作流程、时间回溯等场景。
- 人机协同：可在执行中途中断，人工审批或编辑 Agent 下一步的计划。
- 流式支持：每个节点均可产生流式输出，包含 Token 级流式。
- 生态兼容：与 LangChain 和 LangSmith 无缝集成。
