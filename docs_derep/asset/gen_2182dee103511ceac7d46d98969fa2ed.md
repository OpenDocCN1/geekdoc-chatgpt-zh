下面对图3.6中 DeepSeek 项目开源代码做一简要说明。

- convert.py：负责模型检查点的格式迁移，把已训练好的 checkpoint，例如 safetensors 格式，转换并保存为适配特定模型并行度和专家数 n_experts 的格式。
- fp8_cast_bf16.py：把以 FP8 保存的模型权重转成 BF16 并写入，同时更新索引文件，移除对 scale_inv 的引用。
- generate.py：文本生成的示例脚本，兼顾交互式和批量生成，基于 Transformer 模型并支持分布式推理。
- kernel.py：聚焦量化与矩阵乘这类核心算子，借助 Triton 库加速，尤其针对 FP8 精度做了优化。Triton 是面向 GPU 高效自定义算子的编程框架，兼容 Python 和 PyTorch，用简洁代码即可实现高效 GPU 核。
- model.py：定义了 DeepSeek-V3 的整体模型结构。

图3.7 DeepSeek项目模型权重相关说明

DeepSeek-V3 的权重可在 Hugging Face 主页获取，整体约 650G 左右，也支持在魔搭社区下载。作为全量开源模型，官方给出的本地运行方案主要有：

- (1) DeepSeek-Infer Demo：轻量演示，支持 FP8 与 BF16 推理。
- (2) SGLang：完全兼容 DeepSeek-V3 的 BF16、FP8 推理模式，多标记预测 MTP 支持即将上线。
- (3) LMDeploy：提供高效的 FP8、BF16 推理，兼顾本地与云端部署。
- (4) TensorRT-LLM：现阶段支持 BF16 推理及 INT4/8 量化，FP8 支持正在推进。
- (5) vLLM：支持 DeepSeek-V3 在 FP8、BF16 下进行张量并行与流水线并行。
- (6) AMD GPU：经由 SGLang，可在 BF16、FP8 模式下于 AMD GPU 运行。
- (7) 华为 Ascend NPU：可在华为 Ascend 设备上运行 DeepSeek-V3。

DeepSeek 框架原生以 FP8 训练，因此只提供 FP8 权重，预估 700GB+ 显存即可启动。转成 BF16 后半精度需 1400GB+，量化到 INT4 则约需 450GB+。半精度下的显存占用示例为：占用 490G 显存，需 7 张 80G A100，租赁成本约 1000 元／天。

#### 3.1.5 DeepSeek-V3 Function Calling

##### 1. Function Calling功能简介

Function Calling 是大语言模型迈向通用智能体能力的重要环节，让模型不仅能生成自然语言，还能依据用户意图调用预定义函数或工具，实现更具交互与实用性的任务处理。其基本流程如图3.14所示。

传统对话系统仅能输出语言，缺乏对外部环境的真实调用能力。Function Calling 通过结构化接口定义，通常以 JSON Schema 描述函数，使模型具备

##### 2. 外部工具API

先说明外部工具 API 的概念。API 即应用程序接口，例如在 Python 中使用的 ChatCompletion.create 函数，本质上就是 OpenAI 提供的 GPT 系列模型的一个调用接口，通过该 API 或 openai 库即可便捷调用 GPT 并实时得到结果，其他应用也有类似接口。

本节示例采用可实时查询天气的 OpenWeather API。先调用 OpenWeather API 获取实时天气，再借助 Function Calling 调用该函数，相当于赋予 Chat 模型实时获取天气的能力。随后即可通过 Chat 模型查询天气或询问基于天气的穿衣建议。从功能上看，接入实时天气的 Chat 模型就成为一个简易的天气查询 AI 助手。

要调用 OpenWeather 服务，使用方式与 OpenAI 类似，需要先注册账号并获取 API key。多数在线服务的 API 都需 API key 校验身份，即使 OpenWeather 提供大量免费额度，身份验证仍必不可少以防滥用。获取流程如下。

- (1) 登录 OpenWeather 官网并选择 Sign in→Create an Account 完成注册，可使用国内邮箱或 QQ 邮箱。官网页面如图3.15所示，注册页面如图3.16所示。
- (2) 获取 API key：注册完成后可在用户主页的 API keys 选项卡查看当前账户的 API key，如图3.17所示。
