# 第八章 智能体协作协议全景
随着 AI 智能体复杂度提升，发现、通信与安全协作成为刚需，智能体协议正是为此制定的标准化交互契约。它是支撑 AI 从独立运作走向协同工作的基础框架，可视为数字空间的通用社交规则与沟通语言。

协议解决了三个核心问题：一是让异构智能体互相识别与发现，二是统一信息交换格式以保证语义一致，三是建立安全可靠的协作机制。通过标准化接口与交互范式，协议大幅降低了异构系统集成的复杂度，为大规模开放协同生态奠定技术基础。

目前已有多个机构发布自有协议。
· MCP（model context protocol，模型上下文协议）：由 Anthropic 公司推出。
· A2A 协议（agent-to-agent protocol，智能体间协议）：由谷歌公司推出。
· ANP（agent network protocol，智能体网络协议）：由起源于国内的 ANP 社区推出。
· AG-UI 协议（agent-user interaction protocol，智能体用户交互协议）：由 CopilotKit 团队推出。
· AComP（agent communication protocol，智能体通信协议）：由 IBM 公司推出。
· LMOS（language model operating system，语言模型操作系统）协议：由 Eclipse 基金会推出。

除此之外还存在面向特定领域的协议，例如为机器人与智能体交互设计的 CrowdES。

不同协议在设计理念与架构上各有侧重，共同构成智能体的基础设施，让智能体长出“手脚”、拥有协作伙伴，实现从单体到多体的进化，提升底层能力与上层体验。开放兼容性也让更多创新应用与跨界协作成为可能。

## 8.1 MCP 协议深度解析
当 AI 应用走向更复杂场景，单一模型局限明显，多模型协同与上下文感知需求迫切。从需要历史上下文的对话系统，到要求融合文本图像多源数据的跨模态任务，AI 发展呼唤新的协作范式。

MCP 正是在此背景下出现。作为专为模型间上下文传递设计的标准化协议，它提升系统连贯性与智能化水平，也为开发者提供应对计算挑战的灵活工具。

### 8.1.1 MCP 诞生与定位
MCP 由 Claude 母公司 Anthropic 于 2024 年 11 月开源，2025 年起进入快速关注期。2025 年 3 月 27 日，OpenAI 宣布在 Agent SDK 中支持 MCP；2025 年 4 月 4 日，谷歌在 Gemini 官方 API 文档中加入 MCP 使用示例。

MCP 的目标是统一大模型与外部数据源、工具间的通信，解决数据孤岛限制，让智能体安全访问本地与远程数据，成为 AI 应用的万物互联接口。

初衷是打造开放协议，标准化模型与外部数据源及工具的交互，解决传统集成的碎片化。它提供统一的上下文管理方式，并以标准协议连接外部世界。类比计算机的 USB-C 接口，简化适配。大模型通过 MCP 能轻松调用各类数据源与工具。

生态快速扩张，出现 mcp.so、smithery.ai 等集散地，网络上已发布数千个 MCP 服务器。智能体可对外部工具即插即用，减少重复劳动，开发者可用开源服务器或自建服务器，提升工具接入效率。

### 8.1.2 MCP 与函数调用的差异
函数调用是 OpenAI 于 2023 年 6 月在 GPT 系列中推出的 API 功能。开发者在请求中提供一组函数定义，包含函数名、参数 JSON Schema、描述等，模型据此判断是否调用并输出符合 Schema 的 JSON 指令。本质是通过 Chat Completion 接口提供一份工具说明书，让模型决定调用，获取外部数据后返回用户。

以“杭州天气怎样”为例，流程如下：向模型发送问题并附上 `get` `_` `weather()` 的 JSON 定义；模型分析后决定调用，返回 `completion.choices[0].message.tool` `_` `calls` 非空；客户端据此调用 `get` `_` `weather()` 获取天气；再把原始问题与天气信息回传模型；模型基于完整上下文自然回复。

函数调用解决了模型调用外部工具的问题，工具实现由开发者负责。但各厂商格式不一，例如 Claude API 将 OpenAI 的 `parameters` 字段改为 `input` `_` `schema`，导致每个函数需单独适配。随着工具增多，维护成本显著上升。

MCP 的出现让大模型与工具端只需一次适配即可复用，避免重复开发，大幅简化流程。

总体来看，MCP 是通用标准化交互协议，支持大规模工具集成；函数调用是特定厂商提供的接口，更适合简单工具扩展。

### 8.1.3 MCP 运行机制
本节介绍 MCP 的核心组件、数据基础与协同机制。

#### 1．MCP 的核心组件
包括 MCP 主机、MCP 客户端、MCP 服务器。

**MCP 主机** 是架构起点，指启动连接的应用，如 Cursor、Claude Desktop、Cline 等。它接收用户输入并传递给大模型，在交互中充当桥梁。

**MCP 客户端** 嵌入主机内部，负责与 MCP 服务器通信。当模型需要外部资源或工具时，客户端被激活并与对应服务器建立连接，实现资源访问。

**MCP 服务器** 通过标准化协议为客户端提供上下文、工具与提示。接收请求后执行操作，如访问数据源、调用 API，并将结果返回，扩展 AI 应用边界。

#### 2．MCP 的数据基础
包括本地数据源与远程服务。

**本地数据源** 是服务器的重要依赖，涵盖本地文件、本地数据库、本地 API。服务器可快速连接本地资源响应用户需求。

**远程服务** 包括外部文件、外部数据库、外部 API。服务器可与之交互，为用户提供更丰富数据与操作能力。

#### 3．MCP 的协同工作机制
主机接收用户输入传给大模型；模型需外部资源时，主机内客户端激活并连接合适服务器；服务器执行操作后返回结果；客户端将结果传回主机，再交大模型生成最终回答，最终由主机呈现给用户。
