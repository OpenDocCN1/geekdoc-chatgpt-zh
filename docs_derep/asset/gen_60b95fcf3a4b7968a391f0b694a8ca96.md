OpenClaw 环境搭建与本地部署完整指南

Windows 系统优先选择 WSL 2

面向 Windows 的开发者，强烈建议使用 Windows Subsystem for Linux 2 来运行 OpenClaw。WSL 2 是微软为 Windows 10 及更高版本提供的核心功能，能在 Windows 中运行完整 Linux 内核并与 Windows 文件系统无缝协作。官方文档提示，原生 Windows 下直接运行 OpenClaw 容易在文件路径、权限管控以及部分 Node.js 原生模块编译环节遇到异常。借助 WSL 2 可以规避这些风险，获得接近原生 Linux 的运行效率，是 Windows 下部署 OpenClaw 的最佳实践。

OpenClaw 本身不直接承载大模型，但作为代理层仍需消耗系统资源来处理请求、维护缓存、记录日志并存储 workspace 数据，因此机器需满足基础配置要求。

2．内存与存储：基础资源保障

为保证 OpenClaw 稳定运行，硬件门槛如下。

• 可用内存：建议至少 2GB，以确保 Node.js 运行时、OpenClaw 主进程及系统服务能够流畅并发，避免因内存吃紧导致的卡顿或崩溃。
• 可用磁盘空间：建议预留至少 5GB，用于安装包、日志、临时缓存以及 workspace 内产生的文件。随着使用时长和数据量增长，提前扩容更加稳妥。

2.1.2 软件依赖

OpenClaw 的运行依赖 Node.js 和 Git 两大核心组件。Node.js 提供运行时环境，Git 负责仓库克隆与版本管理。下面先说明 Node.js 的安装与版本管理，再说明 Git 的安装与校验。

1．Node.js 安装与版本管理

OpenClaw 需要现代 Node.js v22 或更高版本支撑，能够高效处理异步任务、网络 I/O 与文件交互。旧版本可能引发兼容性问题甚至无法启动。

推荐使用 nvm 管理版本，可在同一机器上自由切换。安装与校验步骤如下：

# 下载并安装 nvm:
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.4/install.sh | bash

# 若不想重启 shell
\. "$HOME/.nvm/nvm.sh"

# 安装 Node.js:
nvm install 25

# 校验版本:
node -v # 应输出 "v25.x.x".
npm -v # 应输出 "11.11.0".

**注意：** 安装前建议先确认本地是否已存在 Node.js 及其版本。

查看当前版本：node --version。若版本低于 v22.0.0 或提示 command not found，则需安装或升级。在已安装 nvm 的环境中可切换并验证：

nvm ls   # 列出所有可用版本
nvm use 25    # 激活 v25
node -v  # 应显示 v25.x.x
npm -v   # 应显示与 v25 兼容的 npm，例如 9.x.x 或 10.x.x

**注意：** 也可以通过官网下载安装包安装。访问 Node.js 官网下载 LTS 版本，Windows 为 .msi，macOS 为 .pkg/.dmg，Linux 为 .tar.xz。安装时建议勾选 Automatically install the necessary tools 以自动安装 Python、Visual Studio Build Tools 等编译依赖。完成后执行 node -v 和 npm -v 验证。

2．Git 安装与版本检查

Git 用于克隆 OpenClaw 代码仓库并进行后续更新维护。终端执行 git --version 检查版本，未安装或版本过旧按系统安装。

• macOS：brew install git
• Linux Ubuntu/Debian：sudo apt-get update 后执行 sudo apt-get install git
• Windows：在 Git Bash 或 WSL 2 终端中通过 curl 静默安装：
curl -o git-installer.exe https://github.com/git-for-windows/git/releases/latest/download/ Git-2.45.1-64-bit.exe
git-installer.exe /verysilent

**注意：** 所有系统均可前往 Git 官网下载安装程序，按向导完成安装，建议保留默认选项以确保 Git Bash 与 GUI 正常启用。

2.1.3 大模型的选择

OpenClaw 更像一个任务编排的“载体”与“操作系统”，负责调度工具与执行指令。要使其具备理解与推理能力，必须接入大模型，模型即为其“大脑”。

兼容性极强，几乎支持市面上主流服务。配置前需先选定模型并准备 API Key。

**注意：** API Key 是平台发放的唯一调用凭证，相当于账号密钥，用于鉴权与计费，属于高度敏感信息。请保存在安全文本文件如 ~/api_keys.txt 并设置严格权限，禁止硬编码到代码或公开分享。后续配置可通过环境变量管理。

主流推荐：

• Anthropic Claude：Claude Opus 4.6 在工具调用与复杂指令遵循上表现突出，多步任务与外部工具交互更准确可靠，适合高度自动化场景。需在 Anthropic 开发者平台获取 Key。
• OpenAI ChatGPT：GPT-5 系列通用能力强，多模态理解、代码生成与推理均衡，生态成熟、社区资源丰富。需在 OpenAI 开发者平台获取 Key。
• 国产模型：DeepSeek、阿里云 Qwen 通义千问、GLM-5、MiniMax 2.5、Kimi 2.5 等，中文理解与成本控制有优势，且均适配 OpenAI 接口规范，可直接接入 OpenClaw。Key 在各官网申请。

完成上述准备后，本地部署的基础已就绪，可进入安装环节。

2.2 本地快速安装

环境就绪后即可进入 OpenClaw 的本地部署。安装流程已做极简设计，普通用户与开发者均可快速上手。

2.2.1 官方脚本一键安装

对追求效率的用户，官方一键脚本是首选。它会自动检测环境、处理 Node 依赖并下载官方验证的稳定版本。

1．macOS 与 Linux 用户的极简操作

打开终端执行：
curl -fsSL https://openclaw.ai/install.sh | bash

脚本会自动完成：
• 环境检测：检查 Node.js 是否存在，若低于 v22 会尝试安装推荐 v24。
• 二进制下载：从官方服务器获取最新命令行工具。
• 全局配置：将 openclaw 加入系统 PATH，实现全局调用。
• 启动向导：安装后自动触发 onboard 交互式配置。

**注意：** 也可使用 npm 全局安装：npm install -g openclaw@latest

2．Windows 用户

为获得最佳稳定性与性能，强烈建议在 WSL 2 环境中安装。

1．安装与启动 WSL 2。
在 Windows 搜索“启用或关闭 Windows 功能”，勾选“适用于 Linux 的 Windows 子系统”和“虚拟机平台”。随后在 PowerShell 执行 wsl --install。

3．优化配置，避免权限或速度问题。
WSL 2 访问 /mnt/c/ 等 Windows 挂载盘较慢，建议将项目放在 WSL 内文件系统如 /home/用户名/。切回主目录可执行 cd ~。

WSL 访问 Windows 盘符时权限可能显示为 777，导致 Git 异常，需修改 /etc/wsl.conf：
sudo nano /etc/wsl.conf
写入：
[automount]
enabled = true
options = "metadata,umask=022,fmask=111"
root = /mnt/
[filesystem]
umask = 022
保存退出。

4．让配置生效。
管理员 PowerShell 执行：
wsl --shutdown
重启终端后即可在 WSL 中使用 curl 脚本一键安装。安装完成后输入 openclaw --version 验证。

2.2.2 源码手动安装

适合希望阅读源码、参与贡献或体验开发版的用户。

1．克隆仓库。
git clone https://github.com/openclaw/openclaw.git
cd openclaw

2．安装依赖。
官方推荐 pnpm，若未安装可执行 npm install -g pnpm，随后：
pnpm install
pnpm ui:build  # 构建前端控制台
pnpm build     # 编译核心逻辑

3．全局链接，可选。
npm link --global
链接后执行 openclaw --version 验证是否生效。

2.3 初始化与首次交互

安装完成只是搭建了“躯体”，初始化配置则是注入“大脑”与“神经系统”的过程。

2.3.1 交互式配置向导

OpenClaw 提供命令行向导 onboard，按“下一步”方式完成关键配置。

终端执行：
openclaw onboard --install-daemon    # 普通用户本地安装并启动后台守护进程
openclaw onboard    # root 用户使用
[PRE2]
图 2-3 OpenClaw onboard 向导工具启动成功

**注意：** --install-daemon 参数关键，会将 OpenClaw Gateway 安装为系统后台服务，保证关闭终端后助手仍在线。但守护进程依赖 systemctl --user，在 root 下通常无法正常工作。

**注意：** openclaw onboard --install-daemon 与 openclaw configure 用途不同。前者用于首次安装或彻底重置环境，后者用于运行中查看或修改特定配置项。建议：
• 刚安装完：先执行 openclaw onboard --install-daemon，完成后台服务与基础文件配置。
• 仅更换 API Key：直接执行 openclaw configure set llm.api_key your_new_key，更高效且不影响已调优的 AGENTS.md。
• 开机自启失效：重新运行 openclaw onboard --install-daemon 修复服务注册。
