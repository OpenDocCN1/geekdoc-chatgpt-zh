#### 7.3 工具组件与工具包概览

Agent 可调用的资源中，除了真正被执行的函数，例如 `func=search.run`，工具组件本身还包含若干元信息：`name` 为必填项，且在提供给 Agent 的工具集合里必须唯一；`description` 属于可选字段，但强烈建议补充，因为 Agent 正是依据它来判断何时使用该工具。

#### 7.4 Agent 组件能力增强

随着技术演进，Agent 组件的功能正在持续完善。下面重点介绍能力增强的方向。

##### 记忆能力升级

为 OpenAI Functions Agent 组件引入记忆功能是一次重要突破。这不仅让 Agent 保留先前对话内容，还能在执行连续任务时表现更稳定。例如 Agent 可从工具中取出 3 个质数并相乘，同时具备校验中间结果的能力，如确认输出是否为质数。

##### 与向量存储库的融合

为提升 Agent 与向量存储库的协作效率，建议引入一个 RetrievalQA 并将其纳入整体 Agent 的工具集。此外 Agent 还能同时连接多个 vectordbs 并在其中实现路由，使数据访问与处理能力得到明显扩展。

###### 7.4.1 为 OpenAI Functions Agent 添加记忆

本节说明如何为 OpenAI Functions Agent 组件添加记忆功能。OpenAI Functions Agent 能够调用函数并处理函数输入，但在默认配置下并不保留历史对话。许多实际应用却需要 Agent 记住过往对话以便提供更好服务。

这里设计了一个实验，用以检验大语言模型能否记住历史对话并在后续正确使用。下面先从问题设计与步骤展开，再深入介绍添加记忆的方法并验证效果。

为检测模型的记忆与对话能力，设计了以下对话流程。

1. 首先执行 `agent.run("hi")` 启动一次会话，相当于人类对话的开场白。
2. 然后执行 `agent.run("my name is bob")` 提供姓名信息，用以测试模型是否能够记住。
3. 最后执行 `agent.run("whats my name")` 询问姓名，检验模型是否保留了先前信息。

该设计的角度聚焦于记忆能力与对话连贯性，通过此流程可以判断模型在一次会话中能否记住前期信息并在后续正确调用。

下面是为 OpenAI Functions Agent 组件添加记忆功能的代码示例。

首先从 LangChain 模块导入所需的类与函数。

- LLMMathChain: 用于构建具备数学计算能力的 LLM 链，将工具与大语言模型串联，实现复杂任务。
- OpenAI：用于创建 OpenAI 大语言模型，可实例化后在后续代码中使用。
- SerpAPIWrapper: 用于创建 SerpAPI 包装器，可进行搜索引擎结果页查询。
- SQLDatabase 和 SQLDatabaseChain: 用于创建和管理 SQL 数据库，SQLDatabase 表示数据库对象，SQLDatabaseChain 可将数据库与大语言模型连接以执行复杂查询。
- initialize_agent 和 Tool: 用于初始化 Agent 组件与工具，前者创建 Agent，后者创建工具。
- AgentType: 枚举类，定义多种 Agent 类型，用于指定创建的类型。
- ChatOpenAI: 用于创建可聊天的 OpenAI 模型，可实例化后进行对话。
