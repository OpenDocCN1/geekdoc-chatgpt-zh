## Chapter 8 第八章 AI 代码生成实践

辅助软件开发就是通过自动化工具和平台为开发者提供智能编程支持。核心思路是用自然语言交互、自动生成代码、缺陷检测修复、智能补全等手段，提升交付效率、降低入门门槛并优化代码质量。应用形态涵盖代码编辑器插件、IDE、自动化测试、文档生成器等，能够适配多种语言和不同开发场景。

历经多年演进，这类工具从早期的代码生成器、低代码平台，发展为显著提效的高级助手。近两年大语言模型快速进步，智能化程度大幅提升，角色也从单纯辅助扩展为一站式解决方案。Copilot、Cursor、Bolt.new、通义灵码、Trae 等产品已相当成熟，可补全代码、生成片段乃至整套应用，把自然语言处理与开发、调试、测试、部署紧密结合，加速全流程并对人才培养和协作方式产生深远影响。

本章以一个辅助软件开发案例为例，展示用户通过对话即可让应用按目录树生成多个代码文件，形成具备完整工程特征的源码。市场上商业和开源方案都很完善，本案例并非重复造轮子，而是说明仅凭提示词配合大模型能力就能产出完整应用，帮助读者理解大模型辅助开发的基本原理和落地路径。

### 8.1 开发要点

❍应用场景：辅助软件开发，调用大语言模型生成代码集与程序流程图，并支持一键打包下载。
❍开发语言或框架：React.js。
❍大语言模型：DeepSeek，通过 vLLM 加载并对外提供 API 服务。
❍应用部署方式：前端源码编译为静态文件后托管于 Nginx，可与 LLM 服务同机或异机部署。
❍应用访问方式：浏览器直接访问。

### 8.2 案例场景

辅助软件开发工具已成为企业提升研发效能的关键手段。主要能力包括智能补全、代码库分析、代码生成与修改、单元测试生成、问题排查与修复，甚至可自动编写前端并运行部署。部分工具还能一次性产出前后端代码、数据库结构、测试数据并生成开发文档，基本覆盖软件开发全环节。总体可实现以下目标：

①提升开发效率。需求由开发者提出，后续工作交由工具自动完成。企业开发中大量重复代码如 CRUD 接口、DTO 转换、数据访问层等，均可依据自然语言描述或上下文自动生成，符合企业规范并节省手工时间。

②降低维护成本。对整套代码库进行分析可减少培训投入，也便于全局理解结构。大语言模型擅长处理逻辑正确但运行异常的复杂问题，将大段代码交给模型分析往往能提供有效启发。

③项目标准化。模型优秀的关键在于训练语料。结合 DeepSeek 等采用强化学习提升编码能力的实践，模型输出代表着优化、趋同和标准化的方向。随着 AI 生成代码比例上升，项目标准程度随之提高，开发维护成本同步下降。

④提升协作效率。开发者更愿意写代码而非注释、API 文档、结构图等文档，尤其是与代码同步的文档维护成本高。生成式大模型可高效完成这些繁琐工作，借助辅助工具团队能快速生成文档并做知识管理，实现文档层面的顺畅沟通。

⑤从辅助编码走向 AI 增强开发。随着思维链普及和 AI Agent 发展，工具正由被动辅助转向自主生成、自主执行和自主决策。传统软件面向人类使用，交互需符合人类习惯。但部分由 Agent 在运行时通过大模型生成的代码，是供机器使用的，其存在价值已发生根本变化。

### 8.3 关键原理

#### 8.3.1 架构

本例程命名为 code-llm，即由大语言模型生成源码，是一个纯前端程序。WebUI 直接调用大模型服务接口生成和管理代码，无需后端服务。架构简洁而强大，得益于大模型在代码与文档生成上的能力。

code-llm 使用 React.js 构建。开发阶段运行 npm start 启动本地 3000 端口的开发服务器，支持热模块替换和实时重载。部署阶段通过 npm run build 编译成静态文件，发布到 Nginx 应用服务器供用户访问。为简化开发，采用前端直连 LLM 的两层结构。因代码生成对模型要求较高，建议使用 vLLM 加载与 GPU 内存匹配的 DeepSeek 提供 API。不选用 Ollama 的原因之一是，本地调试 http://localhost:3000 与访问 Ollama 的 http://deepseek-dev:11434/v1 存在跨域问题，会增加调试复杂度。code-llm 的架构如图 8-1 所示。

### 8.5 部署方法

在 React.js 中，npm start 属于开发模式。此时启用快速增量编译、热更新，浏览器自动刷新，代码保留注释、不压缩，并保留完整错误提示和警告，体积较大且运行效率偏低。用于生产环境时需编译优化，压缩代码、减小体积并移除调试相关代码，以提升加载与运行效率。

编译产物是一组静态文件，可部署到 Nginx 上提供 Web 服务。Nginx 兼具反向代理与高性能应用服务器能力，相关安装细节见 4.3 节。
