### 7.3.5 PRS：基于排列视角的重排新范式

PRS模型的核心洞察在于：**主流推荐系统单次请求返回的本质上是一个“物品序列”**（如电商多商品曝光、短视频流式下发）。传统范式沿用“评分-截断”的贪心逻辑，而PRS另辟蹊径——从候选集中组合出若干定长序列，直接对“序列整体质量”建模评估，最终输出最优序列。这种**Permutation-wise（排列级）**建模天然内化了序列内部的相互影响与多样性约束，理论上限远超逐点贪心策略。

图7-14给出的电商案例极具说明力：商品A比B便宜。贪心策略输出`ABC`（按分高低序），用户可能无感；但`BAC`序列将贵品B置于廉品A前，利用“锚定效应”刺激购买（“发现更便宜的了，买它”）。List-wise模型（如PRM、DLCM）受限于点级监督，倾向于把购买率高的A前置，反而破坏最优序列`BAC`生成`ABC`。而排列级建模能直接识别：在`BAC`中，A的条件得分更高，从而锁定整体最优解。

[PRE3]

图7-14 电商场景案例：List-wise vs Permutation-wise建模差异（详见彩插）

理论虽美，落地挑战巨大：一是**组合爆炸导致的求解空间膨胀**（如百选十，排列数天文数字）；二是**序列级评估机制的缺位**，现有研究多仍依赖贪心代理。PRS针对性提出**PMatch（序列匹配/生成）**与**PRank（序列排序/打分）**双模块协同架构，旨在破解效率与建模双重难题。图7-15展示了传统流程与PRS的结构性区别。

## 2. 总结

PRS开创了**“离线训练+在线推理”全链路排列级重排**新范式。
- **生成端（PMatch）**：聚焦效率，将CTR/IPV引入Beam Search奖励函数，用FPSA缓解组合爆炸。
- **精排端（PRank）**：延续主流重排建模思路（类PRM/DLCM），通过DPWN建模序列局部上下文，结构差异可控。

### 7.4 端云协同推荐：把模型“搬”到用户手边

随着移动端算力（CPU/GPU/NPU）跃升，端侧智能迎来爆发：AR/VR、美颜、语音合成、推荐模型大量下沉，**端侧推理**极大降低网络延迟、实时响应用户行为；**端侧训练**则能捕捉长尾个性化兴趣，实现“千人千模”。本节重点剖析两大里程碑工作：**EdgeRec** 与 **DCCL**。

### 7.4.1 EdgeRec：移动端排序推理的先驱实践

#### 现状与痛点：云端推荐的“反应滞后”

图7-19描绘了主流“云到端”瀑布流架构：用户滑动触发请求 -> 云端拉特征 -> 召回排序 -> 回包展示。虽单次RTT<1s，但存在两大结构性短板：

[PRE16]

图7-19 典型云端协同瀑布流推荐架构（详见彩插）

1. **系统反馈延迟（离散响应）**：请求触发是离散的（翻页才拉取）。两次请求间隙内，用户的实时行为变化（如连续点赞、快速划走）云端完全“失联”，只能等下一次请求才能修正。
2. **用户感知延迟（日志回传慢）**：行为日志上报链路长，典型延迟约1分钟（图中红箭头）。云端模型基于“陈旧”画像决策，无法捕捉“当下”兴趣漂移。

**结论**：纯云架构难以动态适配实时兴趣，体验有损。**若终端具备排序推理能力，即可实现毫秒级闭环响应。**

#### EdgeRec方案：端云协同而非替代

EdgeRec提出**移动端排序推理**方案，定位为云端推荐的“实时延伸与补强”。架构如图7-20：左侧Client Services（端侧），右侧Cloud Services（云侧），四大核心模块协同。

##### (1) Client Native (CN) 模块：端侧“调度中枢”
- **双模请求机制**：初始化请求 & 常规请求（后者拉取更多候选，保证端侧重排池深度）。
- **实时行为采集与触发**：缓存云端下发候选集及特征；实时收集曝光反馈；依规则触发Model Serving重排；拿到结果即时重排列表刷新UI。
- **三大触发规则设计哲学**：端侧算力受限，定位“补强”而非“替代”，故触发频率可控，核心捕获**高价值稀疏信号**与**稠密负反馈**：
  1. **点击**（稀疏强正反馈）
  2. **删除/不感兴趣**（稀疏强负反馈）
  3. **连续曝光无点击**（稠密弱负反馈，防兴趣漂移）

##### (2) Model Serving (MS) 模块：端侧“推理引擎”
被CN触发后：抽特征 -> 神经网络建模实时兴趣变化 -> 重排 -> 回传结果&上报日志。

**部署硬骨头与破解之道**：
- **存储墙**：排序模型Embedding表巨大（例：150万Brand ID × 40维 = 6000万参数），全量下发不现实。
  > **解法：参数云端KV存储，端侧按需拉取**。Key为Item ID，随CN请求下发当前候选集所需Embedding，端侧仅存“骨干网络+高频参数”，存储压力骤降。
- **算力墙**：复杂重排模型（DLCM、Seq2Slate等含RNN）在端侧推理延迟不可控。
  > **解法：异步/增量推理**。预计算当前序列状态缓存端侧，新行为到来时仅增量前向，避免全序列重算。
