## 6.3.3 后台任务：耗时操作放后台
6.3.2 节的方案有个明显短板：无论耗时长短，所有作业都必须在前台串行跑。一旦遇到装包、编译镜像这类慢活，系统会被卡住，无法响应其他请求或继续推理，用户体验受损。

为打破前台阻塞，本节引入后台任务机制。核心思想是把耗时活挪到后台异步跑，释放主线程，让 Agent 能持续思考与决策。

具体方案采用多线程：LLM 在解析阶段识别出潜在的慢操作，随后调用工具函数动态创建并启动后台线程执行，主线程无需等待即可继续后续逻辑。
