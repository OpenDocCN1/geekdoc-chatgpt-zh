RAG 知识库的实时更新与稳态优化指南

当业务对时效性要求很高时，可以把消息队列引入更新链路，比如 Kafka 或 RabbitMQ，用来监听源数据的增删改动作。一旦捕捉到变更信号，系统就能自动触发后续处理，让知识库几乎做到同步刷新。

更新效率的提升可以从索引层面入手。采用增量索引更新的方式，参考 3.6.3 小节里对 LangChain 缓存嵌入的实现思路，只对受影响的部分做重算，而不是全量重建索引。这种做法能明显省资源、提速度。

性能调优是多点协同的结果。批量提交新增或删除，能大幅减少对数据库的频繁敲门，提升吞吐并降低负载；根据实际业务在 nlist 与 nprobe 等索引参数上做取舍，可以在检索速度和召回精度之间找到合适平衡点，进而优化用户体验。对访问热度高的对象开启内存或高速缓存，可以减轻数据库查询压力，让响应更快。这些手段共同支撑系统在规模扩张时仍保持高效稳定。

数据治理上建议采用分层思路。把数据划分为相对稳定的核心数据和需要频繁变动的动态数据。核心数据生命周期长、改动少；动态数据则随业务实时演进。分层后，增删改操作可以聚焦在动态层，整体效率自然提升。

可靠性的保障离不开版本与备份。为每次更新建立版本控制并保留历史快照，出现异常时可快速回滚。多副本定期备份同样关键，能有效抵御硬件故障或人为误操作带来的数据丢失风险，维护系统安全可用。

#### 4.8.2 Milvus 向量数据的增删改实操
RAG 场景里当上游原始数据发生变化时，嵌入向量、元数据和检索索引必须保持一致更新。Insert 新增操作常用来扩充知识库、修正错误、优化已有内容或按新需求做调整。

from pymilvus import MilvusClient

import numpy as np

###### 连接已有Milvus（使用本地SQLite模式）

db_path = "./test_vector.db"

client = MilvusClient(db_path)

###### 集合名称（之前已创建的集合）

collection_name = "my_collection"

data_insert = [

    {"id": 100001, "vector": np.random.random(128).astype("float32").tolist()},

    {"id": 100002, "vector": np.random.random(128).astype("float32").tolist()}

]

res = client.insert(collection_name=collection_name, data=data_insert)

data_upsert = [

    {"id": 100001, "vector": np.random.random(128).astype("float32").tolist()},  # 更新已有 ID

    {"id": 100010, "vector": np.random.random(128).astype("float32").tolist()}   # 插入新 ID

]

res = client.upsert(collection_name=collection_name, data=data_upsert)
