GCC 长年占据跨平台编译工具的头号位置。和其他只能绑定在特定系统上的编译器不同，GCC 采用统一的前端，在各平台上输出可保持一致的中间表示，因此借助 GCC 重新编译时，在不同环境下得到可靠输出的可能性很高。

#### 2. Clang 与 LLVM 的由来

##### 1）Clang

Clang 是面向 C、C++、Objective-C 以及 Objective-C++ 的编译器前端，后端依赖 LLVM。

Clang 项目由苹果于 2005 年启动，是 LLVM 工具链的前端部分，任务是为源码构建抽象语法树 AST 并生成 LLVM Bitcode，随后由 LLVM 后端转成各平台的机器码。项目的目标是提供一套可替代 GNU 编译器套件 GCC 的方案，整体包含 Clang 前端和 Clang 静态分析器等组件。

Clang 运行效率突出，其 AST 占用的内存约为 GCC 的五分之一左右。FreeBSD 10 已将其作为默认编译器使用。编译出错时，Clang 能给出位置精准的错误说明、代码提示和修复建议。

与名称对应，Clang 仅覆盖 C 家族语言。研发始于 2007 年，C 编译器最先完成，而 Objective-C 本质上是 C 的简化扩展，在多数场景可等价改写为对运行库的 C 调用，所以到 2009 年已可投入生产。

目前 GCC 在跨平台兼容性上仍是最强的，但兼容性的代价是性能。苹果为提升 Mac 系统的构建效率，自行打造了 Clang 与 LLVM，分工上 Clang 负责前端，LLVM 负责后端。

##### 2）LLVM

> LLVM 能提供编译器相关的支撑，涵盖源码优化、链接优化、即时编译优化与代码生成，简言之可作为多种编译器的通用后台。

LLVM 本身是编译基础设施，可容纳多种语言编写的程序，并通过虚拟化技术实现编译期、链接期、运行期乃至空闲期的优化。

## 8.3 GCC 基本介绍与特征

GCC 最初为 GNU 操作系统编写，目的是为 GNU/Linux 打造高效的 C 编译器，可追溯到 1987 年，由理查德·斯托曼作为 GNU 项目的一部分创建。

在 1990 年代和 2000 年代，GCC 经历多次重构与扩展，引入了新的优化技术，提升了代码生成和分析能力，并增强了对新兴语言和硬件架构的支持。随着 GNU/Linux 的快速发展，GCC 的支持范围扩展到 Microsoft Windows、BSD 系列、Solaris 和 MacOS 等多个操作系统平台。

GCC 的主要特征如下：

- 可移植性：支持多种硬件平台，可在不同架构上编译。
- 跨平台交叉编译：能在一种平台上为另一种平台生成可执行文件，对嵌入式开发尤为重要。
- 多语言前端：除 C 外，还支持 C++、Fortran、GO 等。
- 模块化设计：便于添加新语言和 CPU 架构支持，扩展性强。
- 开源自由软件：源代码公开，可自由使用、修改和分发。

### 8.3.2 GCC 编译方法

1. 本地编译

指编译平台与执行平台相同。平台可理解为 CPU 架构加操作系统，例如在 Intel x86/Windows 下用 Visual C++ 编译的可执行文件，需在相同架构和 Windows 10 下运行。

2. 交叉编译

指编译平台与执行平台不同。例如在 Intel x86/Linux Ubuntu 上用交叉工具链生成可在 ARM/Linux 上运行的可执行文件。

### 8.3.3 与传统编译区别

GCC 将过程拆分为预处理、编译、汇编、链接四阶段，其中预处理与编译对应三段式的前端，汇编对应后端。相比传统三段式的前端、优化、后端划分，GCC 的划分更细致，各阶段职责更清晰、独立。

小结与思考

- 本节介绍了 GCC 的编译过程，包含预处理、编译、汇编、链接四阶段。
- GCC 支持多种语言、跨平台广泛、功能完备，但难以作为 API 继承，代码量庞大。
- GCC 的阶段划分与传统编译有所不同。

## 8.4 LLVM 架构设计和原理

8.3 节已详细讨论 GCC 的编译过程与原理。但 GCC 存在耦合度高、难以独立操作、代码庞大等缺点，促使业界期待新一代编译器的出现。本节深入研究 LLVM 的架构设计和原理。

### 8.4.1 LLVM 发展历程

LLVM 项目起源于 2000 年伊利诺伊大学厄巴纳-香槟分校的维克拉姆·艾夫与克里斯·拉特纳的研究，目标是为静态和动态语言创建动态编译技术。LLVM 以 BSD 许可证发布。2005 年苹果聘用克里斯·拉特纳团队为 MacOS 和 iOS 开发工具，LLVM 随之成为这些平台工具链的一部分。

最初项目名称为 Low Level Virtual Machine 的缩写 LLVM，随着范围扩大，该缩写产生混淆，现 LLVM 已成为品牌，涵盖 LLVM IR、调试工具、C++ 标准库等子项目。

项目迅速发展成庞大的编译器工具集合，催生了多个新编译器，其中最著名的是 Clang，它提供 C、Objective-C、C++ 支持，并得到苹果大力支持。

### 8.4.2 LLVM 架构特点

LLVM 架构以组件独立和库化著称，使前端和后端工程师能相对独立工作，提升开发效率和可维护性。核心是中间表示 IR，通过统一灵活的 IR 实现对不同语言和目标平台的支持。优化器将 IR 转化为高效形式，后端再生成目标机器码。该设计赋予 LLVM 适应不同需求和硬件的灵活性和高性能。

### 1. LLVM 组件独立性

LLVM 的显著特点是组件独立与库化。前端工程师只需实现对应前端，无需改动后端，便于添加新语言，因为后端只需将 IR 翻译为目标机器码。

后端工程师只需将目标硬件的寄存器、调度等特性与 IR 对接，无需干预前端。这种灵活架构让前端与后端可并行开发，大幅提高效率。

在 LLVM 中，IR 扮演关键角色。它是一种类似汇编的底层语言，具有强类型和精简指令集 RISC 特性，并对目标指令集做了抽象。

### 2. LLVM 中间表示

LLVM 提供一套适用于编译器系统的中间表示，并围绕其进行大量变换与优化。经过优化的 IR 可被转成与目标平台相关的汇编代码。

与传统 GCC 前端直接对应后端不同，LLVM 的 IR 是统一的，可用于多平台的优化和代码生成。
