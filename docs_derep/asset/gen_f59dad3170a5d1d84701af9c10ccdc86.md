### 3.5 跨模态嵌入代表：Visualized_BGE

小雪：咖哥，单模态的嵌入模型比如纯文本或纯图像的版本已经相当成熟了。可是在真实的业务里，我们经常要同时处理文本、图像，甚至音频和视频，希望功能更丰富、更灵活。

咖哥：这正是多模态嵌入要解决的问题。它把不同模态的数据投射到同一个向量空间，从而实现跨模态检索、跨模态生成以及多模态分析等能力。

比较有代表性的是智源研究院推出的 Visualized_BGE。项目基于 BGE 研发，专门针对多模态场景做了可视化增强。模型目前聚焦图像和文本两类模态的联合建模。把图像向量和文本向量放在同一嵌入空间度量相似度，就能做到图文互搜。例如用一段描述去找最相关的图片，或用一张图片去找最匹配的文字说明。

Visualized_BGE 的技术构成大致包含下面几块。

- 视觉编码器：通常采用 ViT 或其他深度卷积网络，负责从图像中抽取特征。对输入图像进行分块或卷积后，逐层提取视觉信息，最终得到一张全局的图像向量。
- 文本编码器：基于 BERT、RoBERTa 等大模型架构，负责抽取文本语义。对输入的文本序列编码后输出一个表征整体含义的向量。
- 对比学习：用对比学习的方式训练，使匹配的图像-文本对在向量空间里距离更近，不匹配的对距离更远，从而完成跨模态对齐和检索能力。

### 3.6 基于 LangChain 与 LlamaIndex 的嵌入模型调用

前面几节我们要么直接调用商用嵌入 API，要么通过 Hugging Face 下载开源模型。本节介绍如何借助 LangChain、LlamaIndex 等主流应用框架来加载和使用嵌入模型。这种方式的好处是可以在统一的开发框架内无缝切换不同嵌入模型，无需为每个模型单独写适配代码，更专注业务本身。框架自带的缓存机制还能避免重复计算向量，大幅提升检索与查询效率。

#### 3.6.1 LangChain 的嵌入接口概览

LangChain 提供了丰富的组件把大模型整合进应用，并在嵌入层面做了很好的抽象，切换 OpenAI Embeddings、Hugging Face Embeddings 或本地模型都很方便。

LangChain 里常见的嵌入类有：

- OpenAIEmbeddings：调用 OpenAI 提供的文本嵌入接口。
- HuggingFaceEmbeddings：调用本地或远程的 Hugging Face 模型。
- SelfHostedPipelineEmbeddings：调用自行部署的 Pipeline。
- CacheBackedEmbeddings：把任意嵌入模型包装成支持缓存的版本，避免重复计算。

#### 3.6.3 LangChain 嵌入缓存机制

处理大量文本或频繁对同一批文本重复查询时，每次都重新算嵌入会消耗算力和时间。LangChain 提供了 CacheBackedEmbeddings，可以把嵌入结果持久化到本地文件系统或其他键值数据库。下次对相同文本编码时，框架直接返回缓存结果，不再重复计算。

LangChain 会用输入文本的哈希值作为 key，对应的嵌入作为 value，存入指定的 ByteStore。计算时先查缓存，有就直接返回，没有再调用底层模型生成。

### 3.7 嵌入模型的微调实践

本节讨论嵌入模型的微调问题。

微调本质上是让预训练模型向特定任务靠拢。核心是要保证任务目标与已有数据高度契合。在动手之前，需要先判断是否真的有必要微调。如果任务不清晰或与数据特性不匹配，微调可能会浪费资源甚至带来负面效果。比如只是想让大模型回答几个专业领域的问题，而现有开源模型已经能给出满意答案，那就没必要微调。

可能需要考虑微调的场景包括：

- 高度专业化的任务，比如某个细分领域的医学报告生成。
- 有特定格式要求，比如必须符合内部文档规范的输出。
- 有本地化需求，比如要在特定语言或文化环境下生成内容。

总之，微调应该围绕真实任务和现有数据展开，避免为微调而微调。
