DeepSeek 驱动的门诊病历校对工具

本节介绍一个借助 DeepSeek 实现的医疗文书核查应用，聚焦于门诊病历这类短文本的质量把控。使用者在 Web 界面内粘贴原始病历，模型会返回修改建议，并把改写后的文本与原文做对比，在页面上直观呈现增删差异。

### 10.1 核心要素
❍ 使用情境：使用者提交门诊病历原文，由大语言模型提供修改意见并对比校对前后文本。
❍ 实施语言与框架：Python。
❍ 大语言模型：DeepSeek，通过 Ollama 或 vLLM 载入并对外提供 API。
❍ 部署方式：前后端一体化部署。
❍ 访问方式：浏览器即可访问。

### 10.2 应用场景
门诊病历撰写是医疗流程的关键一环，在信息化管理中属于 HIS 的核心功能。门诊医生通过问诊获取主诉、现病史、体格检查等信息并给出初步诊断，书写时常借助自定义模板或分段控件辅助。医疗文书对规范性要求严格，门诊记录虽篇幅短，却多靠手工录入，易出现口语化术语、时间线冲突如病程 3 天与查体记录 1 周不符、诊断与病史矛盾等逻辑问题，还包括年龄或月龄计算偏差、患者与患儿称谓混用等隐性错误。发现并修正这些问题正是大语言模型擅长的方向。在教学与规培场景中，借助模型评估病历是否符合书写规范，也能减少人为疏漏。Transformer 的自注意力与多头注意力擅长处理长文本依赖，病历校对是其识别文本中逻辑关联的典型用例。像 DeepSeek 这类参数规模达 671B 的专家模型，已积累大量医学知识，门诊病历校对可作为人工智能在医疗落地的代表案例。

### 10.3 技术原理

#### 10.3.1 系统架构
此例程名为 emr-checker，承担门诊病历校正功能。整体分为两层：底层为 Ollama 或 vLLM 发布的模型 API 服务，上层为基于 Gradio 搭建的集成 WebUI 与业务逻辑的应用端。Gradio 是快速构建演示型 Web 应用的 Python 库。前端主要由输入组件与展示组件构成，文本差异采用 HTML 的<table>标签配合样式表动态渲染，Gradio 自带 HTML 显示组件。

原文经 Gradio 输入组件提交后，由提示词模板组织成包含任务要求、重点检查项、待校对原文及输出格式说明的完整提示，通过 AsyncOpenAI 组件异步调用本地部署的 DeepSeek API。结果以 SSE 方式由模型服务多次推送回 Gradio，暂存于变量中。输出组件以增量方式呈现修改建议和改写后文本。生成完成后，程序借助 Python 标准库 difflib 对比原文与改写文本。emr-checker 的架构如图 10-1 所示。

#### 10.3.2 处理流程
大模型快速演进后，文本校对不再依赖大量内置知识库与规则库，仅凭提示词与模型能力即可满足预期。关键在于提示词模板的编写与迭代，参数规模更大、专业训练更充分的模型校对效果越好。

emr-checker 的工作链路为：用户在 WebUI 录入原文，按模板格式化为提示词，DeepSeek 生成修改建议与改写后文本两部分内容。客户端解析目标文本，将改写部分与原文对比，产出仅含增删项，按条目展示的修改记录。

提示词模板是 emr-check 的核心之一，具备明确的任务描述、对语法与规范检查重点的说明，以及输出格式示例。面向专业医疗文本，重点检查需表述全面，并在实践中反复优化验证。

另一核心是大语言模型本身。定制化提示词在不同模型、不同参数规模、不同量化精度下，输出可能差异显著，甚至 API 入参的细微变化都会影响结果。企业落地时应固定模型、规模与精度，再对提示词进行调优。例如在 vLLM 上部署 16 位精度的 DeepSeek-R1-Distill-Qwen-32B 就需针对该条件优化模板。调用参数也很关键，医疗场景对确定性要求高，Temperature 建议设为 0.1～0.5，使模型偏向高概率词汇，输出更稳健一致，具体数值需调试确定。emr-check 的运行流程见图 10-2 所示。

## 第十一章 智能语音客服实践

智能语音客服是基于人工智能、以语音交互提供服务的自动化系统，整合了自动语音识别、自然语言处理、语音合成与对话管理等技术，可接收语音输入、解析意图并给出语音回应。相较人工客服，其具备 7×24 小时在线、响应迅速、成本低廉、可规模化部署等优势，广泛应用于银行、电信及公共服务的外呼与满意度回访等场景。

本章展示一个智能语音客服开发实例，涵盖语音录入、自动语音识别、基于 DeepSeek 的语义理解与答案生成、语音合成等完整流程，实现用户语音提问、系统语音答复的效果。

### 11.1 核心要素
❍ 应用场景：智能语音客服 Web 端应用。用户以语音提问，系统以语音回答。
❍ 开发语言与框架：Python。
❍ 模型：大语言模型 DeepSeek 通过 Ollama 或 vLLM 加载并提供 API；语音识别模型采用 Vosk 框架调用。
❍ 部署方式：基于 Windows 系统的前后端一体化部署。
❍ 访问方式：通过浏览器访问。

### 11.2 应用场景
自然语言交流是最直接便捷的沟通方式之一。用户咨询服务时常拨打电话，许多机构已使用数字电话系统，通过数字交换机接通呼叫并转接分机。借助该设备可实时将语音转为文本，文本信息即可发挥大语言模型的优势，结合 RAG 与模型微调生成更贴合需求的答案，再经语音合成分段回写交换机推送给用户。用户体验上如同与真人客服对话，过程顺畅自然。图 11-1 呈现医疗领域的智能语音客服场景。

理想情况下效果取决于交换机与识别准确率，更关键的是大模型与知识库带来的理解与生成能力。随着 DeepSeek 等模型持续发展，智能语音客服的功能与效率将进一步提升。

### 11.3 技术原理
