# 聊天话题体系搭建

上文讲了音乐推荐场景里的知识抽取，这部分聚焦用户画像构建里的另一核心任务——从对话中挖掘用户的聊天偏好。日常闲聊属于开放域任务，范围极大，很难精准把握一个人的兴趣点。比如用户 A 是篮球迷，用户 B 偏爱二次元，怎么从海量聊天记录里把这种倾向找出来？关键在于先对聊天话题做抽象归纳，把相关的话题关联起来，把相似的话题归到一类，形成完整的话题体系，并据此识别用户输入中的话题，再对触发频次进行统计分析，从而推断聊天偏好。搭建话题体系一方面能帮助抽取偏好，另一方面也能为话题跳转和关联联想提供依据。话题之间存在上下位关系，例如休闲娱乐下包含旅游、摄影、K 歌、游戏、阅读等细分，提到旅游就意味着在休闲娱乐范畴内，这时可以联想其他相关话题来生成回复，如图 5-15 所示。

[PRE1]

图 5-15　聊天话题联想示例

下面说明如何基于真实数据构建话题体系。核心思路是从用户日志里挖掘潜在话题词候选，对这些词进行聚类得到初步类别特征，再借助外部知识库补充领域概念信息，最后整合成一个完整的话题体系。实质上就是一个话题领域图谱，每个节点是一个话题，节点间有上下位关系，同层节点有相关度，每个话题都是一个概念，可通过外部知识库实现扩展、联想和跳转。用户每输入一句内容时，先做话题识别，再围绕该话题生成回复，或跳转到相关话题继续对话。具体步骤如下。

* 数据清洗：收集大量用户日志，过滤掉唤醒词、功能指令等无关内容。

* 关键词筛选。

  * 先对语料做分词和词性标注，可选用多种工具并行，以获得多视角结果。

  * 计算每个词的 TF-IDF 权重，训练 LDA 主题模型，得到各主题下的关键词清单。

  * 综合词性、TF-IDF 权重、是否在 LDA 关键词列表中的信息进行打分。话题抽取时，动词、名词更重要，形容词、副词次之，助词、代词、介词、数词等价值较低，可剔除。

* 话题领域映射。

  * 利用通用百科知识图谱，将关键词映射进去查找对应标签、属性及所属概念，从而抽象出多种话题类别并做领域划分。

* 剪枝：

  * 依据话题出现频率、所属标签与领域的频率，剔除过低频项。

完成上述流程后，能得到一批话题关键词及其标签、概念信息，通过分布统计可大致了解用户常跟机器人聊什么，进而据此构建话题体系。构建完成后还需人工整理干预，按用户关注范畴划分层级，补充同领域其他话题，完善体系。图 5-16 给出一个较为完整的话题结构示例，供参考。

# 第 6 章 知识图谱应用

知识图谱落地应用是检验构建价值的关键，也是衡量构建效果的金标准。在第 5 章构建领域图谱时，读者已能感受到底层设计需覆盖哪些实体类型、运用哪些关系属性。本章围绕图谱应用展开，先介绍较为成熟的知识可视化，再介绍与语义理解密切相关的实体链接，随后介绍业界广泛研究的知识问答，最后探讨一种前瞻性的应用——联想。

## 6.1 知识可视化

知识可视化是把结构化知识以图谱形式呈现出来。通过可视化能更直观地传递知识，更方便地挖掘关联，更友好地与用户交互。按是否内置 Neo4j 连接，可将工具分为内置 Neo4j 连接类、无直接连接类、独立第三方类三种\[1\](#part0033.html#note_1)。本节重点介绍以 D3 为代表的无直接连接工具、以 ECharts 为代表的第三方可视化工具，以及其他相关工具。

### 6.1.1 D3

D3\[2\](#part0033.html#note_2) 即 Data-Driven Document，是基于 Web 标准的可视化 JavaScript 库，可用 HTML、CSS、SVG、Canvas 呈现数据。以“节点-关系-节点”形式展示的力导向图是 D3 的重要手段，下面详细说明如何用力导向图实现知识图谱可视化。
