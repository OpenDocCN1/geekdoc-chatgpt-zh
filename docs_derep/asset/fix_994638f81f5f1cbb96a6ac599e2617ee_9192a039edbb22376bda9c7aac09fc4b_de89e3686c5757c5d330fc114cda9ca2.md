**5.3.5 工具调用**

实际部署中，若完全依赖模型推理来完成需要动手操作或跨系统调用的任务，风险会明显上升。引入工具调用机制后，模型可在推理阶段调用外部函数或服务，将复杂推理与结构化执行解耦，模型专注规划决策，具体执行交给可控工具。

借助 LangGraph 可把这一流程结构化，将每个工具封装成图节点，结合 OpenAI Function Calling 实现自动化调用，使智能体能够：

· 根据用户意图自动判断是否需要调用工具、调用哪一个、带哪些参数。
· 在需要时通过工具获取真实世界数据来辅助推理。
· 把执行结果回传给模型用于下一步推理或生成回复。
· 在流程中保留可观测的中间状态，便于调试、审计与优化。

如此一来，推理、执行、反馈得以解耦，形成可维护、可追踪、可控的执行链，适用于需要复杂业务与跨系统协作的生产级应用。下面先讲工具的定义与执行，再讲模型绑定。

**1．工具定义和执行**

· tool：用于描述工具的元信息与参数结构，即 Function Schema，便于与 OpenAI Function Calling 对接，让模型识别并自动生成调用指令。
· ToolNode：用于把已定义的工具封装为可执行节点，模型发出调用后触发真实执行并把结果传回下一步。

**5.3.6 子图嵌套**

在 LangGraph 中，图是描述多步骤、可控、可观测链式调用的核心抽象。随着规模扩大，流程复杂化后，将不同图拆分为子图并复用嵌套变得重要。子图可视为图中的一个节点，封装完整处理逻辑与状态管理，对外只暴露统一的输入输出，使复杂流程得以模块化、分层维护。

通过子图，开发者在保持图结构清晰的前提下灵活组合复用，提升可维护性和可扩展性，在多智能体、多工具场景下快速构建可调试、可回滚的复杂结构。

**5.4 典型 Agent 示例**

本节介绍实际应用中常见的 Agent 实现范式，包括 CRAG、ReAct 和 Supervisor 三类，覆盖从单步决策到多步推理、从自主执行到可控监督的不同路径。

（1）CRAG 融合检索增强生成与纠错机制，让 Agent 在生成答案的同时具备反思修正能力，提升准确性与可靠性。
（2）ReAct 结合推理与行动，让 Agent 边思考边行动，通过自然语言链式推理引导工具调用，是检索增强型 Agent 的常用思路。
（3）Supervisor 模式引入人类或系统监督作为外部可控环节，将中间状态或关键决策回传校验，适合对安全性要求高的生产环境。

下面结合既有知识展示三个示例，帮助在不同业务需求下选择合适的实现方式。

**5.4.1 CRAG**

**5.4.2 ReAct**

ReAct 是构建复合型 Agent 的常用范式，通过让大模型先对用户问题进行自主推理，再根据推理结果自动触发工具调用，并结合调用结果生成最终回复，实现高效可控的链式推理与工具调用闭环。
