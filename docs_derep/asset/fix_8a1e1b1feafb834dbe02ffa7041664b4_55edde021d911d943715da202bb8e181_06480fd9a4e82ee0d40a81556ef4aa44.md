用 MCP 把无人机巡检与智能体消息串成状态流

把一次巡检抽象成可控的状态机，通过 MCP 把派单到归档的各个动作串通起来，整个过程可追溯、易审计。下面用最小可运行的示例说明门禁校验、日志累积与设备释放，以及客户端如何按顺序完成一次农场 A 区的巡检闭环。

产出报告的环节做了严格的状态门禁。只有在工单当前状态为 REPORTING 时才允许进入，状态不匹配会直接返回错误并说明期望与实际。进入许可区后先模拟约一秒的耗时，随后把工单标记为 DONE，追加一条带时间戳的完成记录并关联机体，最后把该机体置为闲置并解绑工单，返回工单标识与终态。

查询侧提供两项只读能力。工单查询先校验键是否存在，不存在返回 task_not_found，存在则返回完整记录；机体查询逻辑相同，先在状态表里校验 drone_id，不在则返回 drone_not_found，否则返回当前快照。

服务端以 stdio 暴露能力，客户端稍作延迟后接入，随后按预处理、升空、采集、解析、产出报告的顺序推进一次完整链路：先为农场 A 区与 drone_001 发起巡检工单，再依次进入预处理、升空、采集、数据解析、报告产出，最后拉取工单快照与设备快照做收尾确认。全程状态变更与日志都被保留，能清晰看到 SCAN-7493 如何从 PREPARATION 演进到 DONE，设备恢复 idle 且无挂起工单。

同类思路可平移至智能体间通信。另一个示例构建了 agent-message-server，借助 AGENT_DB 与 MESSAGES_DB 两个全局字典分别保存注册信息与消息信箱。注册接口先检查标识是否已被占用，已占用则返回错误；成功则写入标识、描述与注册时间戳，并为该 Agent 建立空信箱。列表接口返回全部已注册条目。信箱创建与写入被封装为内部函数，确保每次发送前信箱必定存在。发送接口接收发送方、接收方与内容，将消息落入接收方信箱。

################ 全局数据结构 ################
###### 记录已注册的智能体
AGENT_DB: Dict[str, Dict[str, Any]] = {}
###### 存储智能体之间的消息
###### 格式：MESSAGES_DB[agent_id] = list of message dict
MESSAGES_DB: Dict[str, List[Dict[str, Any]]] = {}
app = FastMCP("agent-message-server")
def _init_agent_inbox(agent_id: str):
    """
    若对应智能体收件箱未初始化，则创建空列表
    """
    if agent_id not in MESSAGES_DB:
        MESSAGES_DB[agent_id] = []
def _append_message(receiver_id: str, msg: Dict[str, Any]):
    """
    向 receiver_id 的收件箱追加一条消息
    """
    _init_agent_inbox(receiver_id)
    MESSAGES_DB[receiver_id].append(msg)
@app.tool()
def tool_register_agent(agent_id: str, description: str) -> Dict[str, Any]:
    """
    注册智能体，记录其 ID 与描述信息，
    并在 MESSAGES_DB 中初始化收件箱
    """
    if agent_id in AGENT_DB:
        return {"error": "Agent ID already registered"}
    AGENT_DB[agent_id] = {
        "agent_id": agent_id,
        "description": description,
        "registered_at": time.strftime("%Y-%m-%d %H:%M:%S")
    }
    _init_agent_inbox(agent_id)
    return {"message": f"Agent {agent_id} registered successfully"}
@app.tool()
def tool_list_agents() -> Dict[str, Any]:
    """
    查看所有已注册的智能体信息
    """
    return {"agents": list(AGENT_DB.values())}
