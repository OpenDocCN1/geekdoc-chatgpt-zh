为响应环保号召，乐乐百货日常不再主动发放塑料袋，只有顾客明确提出需求时才会提供。这种默认不提供的做法，和编程中为函数设定初始默认值非常相似。

**11.5.2 知识精讲**

**1.函数的默认参数**

1）认识缺省值

在实际调用中，部分形参数值在多数情况下固定，反复显式传递会让代码冗余、可读性下降。缺省参数机制为这些形参提供预设值，调用时若省略该参数则自动采用预设值，从而简化调用过程。

以乐乐百货收银为例，多数订单无需额外包装也不急于配送。若每次都要明确填写包装与加急选项，操作繁琐易错。此时缺省设置相当于商店的默认服务，让订单处理更轻便，只需关注关键信息，其余沿用默认配置。

**2.函数重载**

编码时常需要实现功能相近但参数类型或个数不同的函数。若为每个版本起不同名字，代码会臃肿难记，可维护性下降。重载允许在同一作用域内用同一函数名定义多个实现，只要参数列表不同即可，提升代码统一性。

1）重载概念

重载指在同一作用域定义多个同名函数，核心要求是参数列表必须差异化，具体表现为参数类型、个数或顺序至少一项不同。例如 add（int a，int b）与 add（int a，int b，int c）因个数不同可构成重载，add（int a，double b）与 add（double a，int b）因顺序不同也可构成重载。编译器会依据调用时实际参数自动匹配合适版本。

2）示例代码

示例中 add 被重载三次，分别处理两 int 相加、两 double 相加、三个 int 相加。编译器依据参数类型与个数选择对应实现。

3）解析步骤

调用重载函数时，编译器按以下顺序选择：

（1）精确匹配。优先查找类型与个数完全一致的版本，找到即调用。
（2）隐式转换匹配。若无精确匹配，尝试进行类型转换，选择最接近的版本。
（3）错误处理。若转换后仍无合适版本，或存在多版本均可转换，编译器报错。

**3.内联函数**

函数调用本身存在开销，包括寄存器保存、参数传递、跳转等。对于简短且高频调用的函数，这些开销会累积影响性能。内联提供一种优化思路，让编译器尝试把函数体直接展开到调用位置，减少调用成本。

1）内联定义

在函数定义前加上 inline 关键字即声明为内联，编译器会尽量将代码嵌入调用处，而非进行常规调用。例如：

2）优缺点

（1）优点。减少调用开销，提升执行效率；代码路径更直接。
（2）缺点。若用于复杂或较大的函数，会导致代码膨胀，增加内存占用。是否真正内联由编译器决定。

**12.1 数组定义和基本操作**

**12.1.1 小故事**

乐乐百货饮料区过去摆放随意，空位便放，随意堆放导致顾客寻找费劲。随后将货架划分为连续固定格位，每种饮品固定存放。补货时按位放置，货架立刻整齐，取货与寻找都更顺畅。

C++中用于存放同类数据的连续固定“格子”即为数组。就像饮料格位只放同类饮品，数组的每个单元只容纳同类型数据，通过顺序编号即可快速定位。
