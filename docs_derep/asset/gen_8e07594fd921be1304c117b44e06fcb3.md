- 知识蒸馏的本质是将庞大复杂的教师模型所掌握的信息抽取出来，再迁移到一个体量更小、结构更简单的学生模型中。其要义在于在压缩模型规模、削减计算开销的前提下，尽可能维持原有的性能水平。
- 从知识形态来看，神经网络的知识大体可划分为四类，其中以响应为基础的、以特征为基础的、以关系为基础的较为常见，第四类在实践中使用较少。
- 按学习范式划分，蒸馏大致有三种实施方式：离线蒸馏、在线蒸馏以及自蒸馏。

# 第17章 模型转换全流程解析

## 17.1 引言

模型转换的核心使命是打通不同框架之间的模型流通。随着深度学习生态的演进，训练侧和推理侧的功能边界愈发清晰。

训练框架更强调易用性与算法探索，集成了分布式训练、自动微分、混合精度等能力，帮助研究者快速产出高性能模型。

推理框架则聚焦于对特定硬件平台的极致调优与加速，以保证模型在生产环境中高效运行。因为两类框架在职能、侧重点以及内部的模型表征方式上各不相同，不存在一个框架能全覆盖。模型转换因此成为必备桥梁，负责将训练产物顺利衔接到推理侧部署。

### 17.1.1 推理引擎

推理引擎是推理系统里承担实际推理任务的组件。整体可分为两个阶段：

- 优化阶段：属于模型转换工具链，包含模型转换与图优化，也涵盖模型压缩、端侧学习等配套模块。
- 运行阶段：真正的推理引擎，负责模型的加载与执行，内部可拆分为调度层与执行层。

模型转换工具主要由两部分构成：

1. 模型格式转换：把同框架或异框架的模型转成推理引擎可用的中间表示 IR 或其他兼容格式。
2. 计算图优化：计算图是深度学习编译框架的第一层中间表示。图优化通过等价变换对计算图进行简化，从而减少计算量或内存消耗。

### 1. 转换模块挑战与目标

#### 1）AI 框架算子的统一

神经网络由大量算子构成，不同框架的算子集合既高度重叠又不完全一致。推理引擎希望用有限的算子集去适配多个框架的算子。

各框架的算子冲突较为普遍，定义也存在差异。以填充为例，PyTorch 的 Padding 与 TensorFlow 的 Padding 在执行方式与方向上不同。PyTorch 的 Conv 支持直接指定填充步长，而 TensorFlow 的 Conv 不支持，若需此功能则要额外使用 tf.pad。

一个推理引擎通常要对接多个训练框架，不可能为每个框架单独实现全部算子。更可行的解法是让推理引擎自建一套算子定义与表达规范，用来统一对接各框架的算子层。

#### 2）支持不同框架的模型文件格式

主流框架导出的模型文件格式各不相同，且同框架不同版本也会出现算子增改。模型文件一般包含网络结构、权重参数、优化器状态等信息，便于部署与推理。表 17.1.1 列出了部分常见框架的模型文件示例。

表 17.1.1 主流框架模型文件格式示例

| AI 框架 | 模型文件格式 |

| :--- | :--- |

| PyTorch | .pt, .pth |

| TensorFlow | .pb(Protocol Buffers), .h5(HDF5) |

#### 3）支持主流网络结构

CNN、RNN、Transformer 等网络在不同场景各有优势。推理引擎应提供丰富的 Demo 与 Benchmark，展示加载与执行各类网络结构的方法，并通过基准测试评估在不同结构上的性能，给出主流模型的性能与功能参考，确保可用性。

### 2. 优化模块挑战与目标

#### 1）结构冗余

模型中常存在训练时生成、推理时无用的计算节点、重复的子图或相同的结构模块，在不改变语义的前提下可无损移除。通过计算图优化和算子融合可以削减结构冗余。

#### 2）精度冗余

精度冗余指模型使用的数值精度如 FP32 超出了实际需求，导致资源浪费。在很多推理任务中，FP32 的精度远高于必要水平。改用 FP16 或 INT8 能大幅降低存储与计算成本，对效果影响很小。

#### 3）算法冗余

算法冗余指算子或 Kernel 层面的实现本身存在计算重复，例如均值模糊与拉普拉斯的滑窗实现可能重复。这样会带来额外开销，降低效率。

#### 4）读写冗余

读写冗余指计算过程中出现不必要的内存读写或访问模式低效，导致带宽浪费和性能下降。常见表现包括同一数据被多次读写、内存访问不连续导致缓存命中率低、内存对齐不当无法充分利用硬件读写特性。

#### 1）格式转换

格式转换对应图 17.1.1 中 IR 上方的环节，即把不同训练框架的模型转成统一的中间表示，后续优化均基于该 IR。不同框架 API 各异，无法用单一 Converter 覆盖全部。

#### 2）图优化

图优化的核心是改善计算图的结构与执行方式，提升效率与性能。主要手段包括算子融合、算子替换、布局调整、内存分配等。

- 算子融合：将连续作用于同一张量的多个算子合并为一个更大算子，减少计算与内存访问开销。例如把卷积与激活函数合并，避免中间结果的存储与传输。
- 算子替换：在保持计算结果不变的前提下，用更适合在线部署的算子替代原算子。例如用深度可分离卷积替代标准卷积，降低计算量与参数量。
- 布局调整：重新组织张量的存储方式以匹配硬件偏好。例如把 NHWC 转为 NCHW，多数 GPU 对 NCHW 格式的处理效率更高。
- 内存分配：分析计算图峰值内存使用，必要时插入 CPU-GPU 拷贝，将数据在 CPU 与 GPU 间交换，以降低峰值内存，避免溢出或性能下降。

## 小结与思考

- 模型转换：将不同 AI 框架训练得到的模型统一为推理引擎可理解执行的中间表示 IR，实现跨框架部署。
- 推理引擎架构：包含优化阶段与运行阶段，优化阶段负责模型转换与图优化，运行阶段负责模型加载与执行，分为调度与执行两层。
- 转换模块挑战：AI 框架算子统一、不同框架模型文件格式支持、主流网络结构适配、各类输入输出兼容。
- 优化模块目标：通过消除结构冗余、精度冗余、算法冗余和读写冗余，提升效率与性能，同时保持准确性与功能。
