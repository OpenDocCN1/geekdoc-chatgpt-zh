4. 撰写推荐理由或淘汰理由
5. 生成候选人排序清单

上述五项工作分别对应 OpenClaw 的哪些能力：

1. 上传 → 文件读取工具
2. 提取 → 文档解析与 AI 理解
3. 打分 → 依据规则推理
4. 生成理由 → 文本生成
5. 输出 → 格式化输出

##### 第三步：准备核心文件
AGENTS.md 用于界定角色与规则：

> 你是一名专业的 HR 简历筛选助理。

工作范围：

- 快速阅读简历，提炼关键信息
- 按岗位要求评估候选人匹配度
- 给出清晰的推荐或淘汰说明

工作原则：

- 保持客观公正，杜绝个人偏见
- 兼顾硬性条件如学历、从业年限，和软性能力如项目经历、技能匹配
- 信息不全时明确标注“缺少××信息”

不承担的事项：

- 不回答无关问题，例如“今天天气如何”
- 不提供职业建议，属于候选人个人范畴
- 不评价候选人的外貌、性别、年龄等

预装 Skills：
搭建一套“简历解析”技能，教会 OpenClaw 如何从简历中抽取信息、如何评分、如何呈现结果。

模板文件：
准备若干常用岗位的需求模板，如“Java 工程师要求”“产品经理要求”“运营专员要求”等。

##### 第四步：测试和优化
找几位真实用户试用：

- 提供真实简历跑通流程
- 观察输出质量
- 收集反馈：哪里顺手、哪里卡顿、哪里看不懂

常见问题与对策：

- 信息抽取不准 → 优化 Skill 的抽取逻辑
- 评分不合理 → 调整评分规则
- 输出格式混乱 → 固化输出模板
- 用户无使用感知 → 增加引导提示

反复迭代，直到 80% 测试用户表示“还算可用”。

##### 第五步：打包和分发
面向公司内部：

- 部署于内网服务器
- 编写简要使用手册
- 开展约半小时培训

面向外部客户：

- 提供安装包或云端访问链接
- 提供详细文档与视频教程
- 提供技术支持，初期需保持响应

若考虑商业化：

- 准备销售资料，功能介绍与案例展示
- 留意法律风险，数据隐私与服务协议

#### 6.10.4 商业化的三大要点

##### 注意一：成本要算清
OpenClaw 调用大模型会产生费用，提供给用户后费用由谁承担？主要有三种做法：

1. 用户自备 API Key：成本由用户承担，配置较繁琐
2. 统一采购额度：自行购买模型额度，再按用量向用户收费，需核算利润
3. 免费版加付费版：免费版使用通用模型并限量，付费版使用强模型不限量

##### 注意二：数据隐私要保障
简历、合同、客户信息等流经系统，安全责任在提供方。

基本要求：

- 不将用户数据用于其他目的
- 不向第三方泄露用户数据
- 定期删除不再需要的数据
- 云端部署需符合相关数据保护法规

##### 注意三：技术支持要提前准备
产品化后出现问题，用户会找你而非 OpenClaw 官方。

建议准备：

- 常见问题解答文档
- 故障排查标准流程
- 联系方式，邮箱、微信、电话
- 初期耐心解答各类咨询
