#### 8.1.10 LangGraph构建AI Agent的底层原理

##### 1. LangGraph
从命名看 LangGraph 与 LangChain 关系紧密。LangGraph 正是在 LangChain 表达式语言之上搭建的框架，专用于打造 AI Agent。所以在大模型接入、能力复用和 Agent 搭建方面的优势，都能自然继承自 LangChain。从技术本质看，大模型本身不具备行动能力，只能生成文本，即接受输入并返回对应回应。

##### 2. LangGraph的基础图结构模型
在以图为基础的体系里，任何可执行的逻辑都可以作为对话、Agent 或程序的起点。起点可以是 LLM 的 API、基于大模型搭建的 AI Agent，或由 LangChain 等实现的线性序列，如图 8.13 中 Start 圆圈所示。无论形式如何，它先处理用户输入，再决定下一步动作。图 8.13 展示了基于 LangGraph 概念的基础 Agent 模型。

LangGraph 里凡带执行逻辑的组件都被视作单元，涵盖模型调用、检索操作及条件判断等。Start 单元是入口，接收用户输入后会根据需求执行以下事项。

- (1) 调用 Action 单元进行外部信息查询，例如网络检索、数据库查询或 RAG 检索。
- (2) 把获取的信息交给语言模型单元，用来生成自然语言回复。
- (3) 最终把回复送到 End 单元，结束整条链路。

如图 8.13 所示，这是一个基于 LangGraph 概念构建的基础 Agent 示例。需要明确的是，每个圆圈代表一个单元，每条连线是连线，用于控制流程走向；状态通过沿连线传递的消息不断更新。

因此，不管 Agent 设计多复杂，最终都是单元和连线按特定方式组合成的网络结构。这种工作流的核心在于：单元完成任务后会经由连线通知下一个单元继续。简言之，LangGraph 底层用消息传递算法定义了通用程序的运行模式：单元完成操作后，沿一条或多条连线向其他单元发送消息，接收方执行相应功能并把结果传给下一个单元，如此循环往复。

如图 8.14 所示，经过第一个单元 Agent 后，若 Agent 认为需要调用函数，会选哪个工具、带哪些参数？当可选工具多个时，Action 单元会出现多条可选路径。如何抉择？LangGraph 引入了条件连线。条件连线依据是否满足特定条件来决定走向，例如 Agent 可能要决定使用检索工具还是直接生成最终答案。为管理这些决策，使用了类似 if-else 的结构，称为 Router。基于 Router 的判断，Agent 可能被导向网络检索单元执行检索并返回原始文本，或直接前往最终答案 End 单元获取格式化后的自然语言回复。若选择检索路径，获取的文本还需另一个大语言模型处理以生成用户可读的回应；若直接回答，则可用专门工具格式化输出。

LangGraph 中 Router 以 if-else 形式决定路径，主要通过三种方式实现。

- 提示工程：指示大模型以特定格式作出回应。
- 输出解析器：用后处理从大模型回应中抽取结构化数据。
- 工具调用：借助大模型的内置工具调用功能生成结构化输出。

##### 4. 共享状态State机制
目前已清楚 LangGraph 通过单元和连线组合创建复杂循环工作流，并以消息传递串联各单元形成通路。那么如何让消息及时更新并送到正确位置，则依赖 LangGraph 的状态概念。在 LangGraph 流程中，每次执行都会启动一个状态，单元在处理时会传递和修改该状态。状态并非静态数据，而是随各单元输出动态更新，进而影响循环内的后续操作，如图 8.15 所示。

共享状态是指图执行过程中单元间传递的数据或信息。LangGraph 允许单元在执行时通过共享和更新公共状态交互。这种机制使单元能基于共同维护的数据通信、交换信息并相互影响行为。借助共享状态，LangGraph 可以协调和同步单元操作，支持动态交互和复杂工作流构建，使单元能依据已有共享信息协同工作并作出决策。

##### 5. 官方对LangGraph的定位与优势总结
从官方定义看，该框架是用于基于大模型构建有状态、多参与者应用的库，可创建 Agent 和多 Agent 工作流。官方归纳的优势如下。

- 循环和分支：在应用中实现循环和条件判断。
- 持久性：在图每一步后自动保存状态。可随时暂停和恢复执行，以支持错误恢复、人机交互流程、时间旅行等。
- 人机交互：中断图执行以批准或编辑 Agent 计划的下一步操作。
- 流支持：每个单元生成的流式输出，包括令牌流。
- 与 LangChain 集成：LangGraph 与 LangChain 和 LangSmith 无缝集成。
