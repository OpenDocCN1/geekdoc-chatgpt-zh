编程语言的萌芽与进化

1955年 IBM为702机型推出了Autocoder，被视作早期汇编器的雏形。它首次实现了助记符到机器码的自动转换，并提供了宏指令等增强手段，例如把操作码21写成更直观的ADD。编程仍然与硬件紧密耦合，但自动转译的思路为后续高阶语言提供了技术原型。

1963年 IBM把宏汇编器移植到7094晶体管机上。宏定义机制在此得到完善，开始支持条件汇编和递归展开。开发者可以声明带参数的宏，并用仅当为假的IFF与仅当为真的IFT来控制条件伪操作和迭代伪操作，形成可复用的模板，代码的可维护性和复用性明显提升。

早期宏汇编器普遍存在命名互相干扰的问题，同一宏名在不同模块里会覆盖彼此，容易产生难定位的错误。到1970年，DEC在PDP-11小型机上推出MACRO-11汇编器，首次加入LOCAL关键字实现宏定义的作用域隔离，有效避免了命名冲突。该机制后来被NASM与GNU汇编等现代工具继承，推动汇编走向工程化。

符号化寻址让开发者免于手工计算繁琐的绝对地址，可读性和可维护性得到改善，也为高级语言中变量与作用域概念的形成奠定基础。

在计算机发展的早期，基于x86的汇编编程堪称极限操作。以1981年发布的MS-DOS 1.0引导程序为例，哪怕是一段简短的启动代码，也要求开发者像校对精密仪器般精确操控每个段寄存器与偏移，稍有偏差便会导致系统崩溃。

[PRE2]

图 2-5 MS-DOS 1.0 引导程序界面（图片源自维基百科）

典型做法是先把数据段地址送入DS，使后续以DS为默认前缀的数据访问定位正确。地址必须手工核算，偏差一点就会让全局变量错位，进而失稳。

MOV AX, @DATA_SEGMENT   ; 将数据段地址加载到 AX 寄存器

MOV DS, AX              ; 将 AX 寄存器的值赋给数据段寄存器 DS

1985年Intel推出80386，保护模式随之到来。内存寻址权交由操作系统管理，段地址与逻辑地址被分离。程序员不再需要显式配置段寄存器，系统自动完成分配与访问控制，底层寻址的负担被卸下。

即便如此，汇编仍受硬件差异制约，不同处理器的指令集相差很大，跨平台移植困难，寄存器配置与地址映射等细节必须熟练掌握，开发风险高效率低。汇编解决了能否写程序的问题，却难以满足科研与商业建模对更高抽象的迫切需求。

### **2.1.3 高级编程语言的兴起**

五十年代起，计算机用途由军方起步逐步扩展到科研和商务，编程需求日趋细分，语言设计从贴近硬件转向贴近问题。高级语言由此出现，解放了思维方式，也标志着软件开发进入以业务与问题求解为核心的新阶段。

**1. 科学计算的奠基者：Fortran**

1957年IBM发布Fortran，即formula translation，开启了真正意义上的高级语言普及时代。它摆脱了直接操作硬件的束缚，允许开发者用接近数学的表达描述算法。

Fortran面向科学计算，具备循环、分支、函数等抽象结构，并由编译器转成高效机器码。编程重心从输入指令转向求解问题。

1962年的FORTRAN IV在编译技术上取得突破，引入了循环不变量外提等优化。以如下片段为例：

DO 10 I = 1, 100       ; 原始代码：计算数组 A 的值

   A(I) = B + C * I    ; 在表达式 B+C*I 中，**B****是循环不变量**，在整个循环过程中保持不变，因此可以提前计算

10 CONTINUE

编译器识别出B在循环中不变，将其提前计算。优化后的目标代码大致为：

MOV AX, B              ; 将变量 B 的值加载到 AX 寄存器

ADD AX, C              ; 计算 B+C 的值并保存在 AX

MOV DX, AX             ; 循环不变量 B+C 存入 DX

DO_START:

MOV [A+I], DX          ; 循环体仅执行乘法和存储操作

INC I                  ; 索引变量递增

CMP I, 100             ; 比较索引变量与循环上限

JLE DO_START           ; 若未达上限 100 则继续

循环体指令数减少约40%，在IBM 7094上，矩阵求逆耗时由2小时降至72分钟。

1978年的FORTRAN 77加入自动向量化，能把数组操作映射为Cray-1超级机的向量指令，矩阵乘法等线性代数运算性能提升百倍，推动有限元分析、气象模拟、地震建模等从理论走向工程。至今Fortran仍是高性能计算的支柱。

**2. 商业的标准化：COBOL**

1959年在美国国防部推动下诞生的COBOL，即common business-oriented language，目标是统一政府与企业的业务信息处理语言，解决开发效率低、维护难、可移植性差的问题。

COBOL的创新在于首次引入类自然语言风格，非技术人员也能读懂。

01 CHECK-RECORD.  

05 CHECK-NUMBER PIC 9(8) COMP-3.       ; 压缩十进制存储的支票号码（8 位数字）

05 ACCOUNT-NUMBER PIC 9(12) COMP-3.    ; 账户号码（12 位数字，压缩存储）

05 AMOUNT PIC S9(10)V99 SIGN TRAILING. ; 带符号金额，保留两位小数

05 ENDORSEMENT-AREA PIC X(30).         ; 背书区域（30 个字符的字符串）

其结构化语法与业务表单字段一一对应，广泛用于银行、电信、保险。COBOL还首创数据驱动范式与严格的数据定义体系，编译期即进行格式校验，为Java、C#等企业级语言提供了借鉴。

**3. 从算术到业务，编程语言走向多元**

Fortran与COBOL分别奠定科学计算与商业应用的基础，标志语言设计开始围绕任务展开。前者追求性能与算法表达，后者推动编程去技术化。语言逐渐摆脱对硬件的深度依赖，演变为抽象问题与系统建模的工具，也催生了编译器、抽象模型、数据结构等核心概念，为C、Pascal、Java等发展打下基础。

### **2.1.4 结构化编程与面向对象编程的突破**

集成电路进步使软件规模激增，十万行代码成为常态，线性编程在可读性和可维护性上捉襟见肘。高级语言虽解决了领域建模，但庞大复杂的工程仍需更严谨的逻辑结构与更高层抽象。编程随之从面向过程演进为结构化与面向对象，重塑了组织方式，也确立了现代软件开发范式。

**1. 结构化编程的里程碑：Pascal**

1970年发布的Pascal是结构化编程的典型。语言强调清晰结构、强类型约束与模块化，既适合教学也用于工程。

Pascal的静态类型检查在编译期通过符号表捕获类型错误，例如：

[LINE 15] ERROR: CANNOT ASSIGN BOOLEAN VALUE 'TRUE' TO INTEGER VARIABLE 'COUNT'

它是最早可在编译时发现大部分类型错误的语言之一，大幅前移质量控制。

1983年Borland的Turbo Pascal引入增量编译，以源文件时间戳为依据只重编变更单元，使十万行项目的编译时间从60分钟降到8分钟。这一思想后来被Java的Jikes与C#的Roslyn继承。

模块化方面，Pascal用UNIT封装功能：

UNIT MathUtils;

INTERFACE

FUNCTION Add(a, b: INTEGER): INTEGER;  // 接口声明

IMPLEMENTATION

FUNCTION Add(a, b: INTEGER): INTEGER;  // 接口实现

BEGIN

    Add := a + b;

END;

END.

封装提升复用，也为C的头文件、Java的包系统提供了原型，推动编程从堆砌逻辑转向模块化构建。

**2. 面向对象架构的破晓：Smalltalk**

1980年Smalltalk-80发布，标志语言从过程分解转向对象建模，核心思想是万物皆为对象。

Smalltalk把对象定义为封装状态与行为的独立单元，通过消息传递交互。

（1）封装：如BankAccount类把余额与转账方法整合为整体。

"BankAccount 是一个封装了余额和操作方法的类"

Object subclass: #BankAccount

    instanceVariableNames: 'balance'   "实例变量：balance（余额）"

    classVariableNames: ''

    category: 'Finance'

"初始化方法：设置初始余额为 0"

BankAccount >> initialize

    "方法 initialize：初始化账户状态"

    balance := 0.

"存款方法：将指定金额加入余额"

BankAccount >> deposit: amount

    "方法 deposit: 接收参数 amount（存款金额），并更新余额"

    balance := balance + amount.

"转账方法：从本账户转出并调用目标账户的存款方法"

BankAccount >> transfer: amount to: otherAccount

    "方法 transfer:to: 

       • amount — 转账金额 

       • otherAccount — 接收转账的 BankAccount 对象

       操作：先检查余额，再执行扣款与对方存款，或抛出错误"

    (balance >= amount)

        ifTrue: [

            balance := balance - amount.  "内聚行为：扣减本账户余额"

            otherAccount deposit: amount  "调用对方的 deposit:方法完成存款"

        ]

        ifFalse: [

            self error: 'Insufficient balance'   "余额不足时抛出错误"

        ].

外部代码只能通过接口访问数据，语言层面提升了安全与一致性。

（2）继承：类层次对现实建模，如SavingsAccount继承BankAccount并扩展利息。

BankAccount subclass: #SavingsAccount

    instanceVariableNames: 'interestRate'  "新增利率变量"

    classVariableNames: ''

    category: 'Finance'

SavingsAccount >> initiali

    super initialize.  "调用父类初始化方法"

    interestRate := 0.03.  "设置默认年利率%"

SavingsAccount >> calculateInterest

    balance := balance * (1 + interestRate).  "扩展父类功能，计算利息"

is-a关系使领域概念直观表达，提升复用与开发效率。

（3）多态：抽象父类统一接口，子类按语义实现差异。

AbstractObject subclass: #AbstractAccount  

    instanceVariableNames: ''  

    classVariableNames: ''  

    category: 'Finance'  

AbstractAccount >> withdraw: amount  

    self subclassResponsibility.  "强制子类实现取款方法"  

BankAccount >> withdraw: amount  

    balance := balance - amount.  "普通账户的取款实现"  

CreditAccount >> withdraw: amount  

    (balance + overdraftLimit) >= amount  

        ifTrue: [balance := balance - amount]  "允许透支时的取款实现"  

        ifFalse: [self error: 'Overdraft exceeded'].  

调用account withdraw: 100时，系统依据实际对象类型动态绑定逻辑，增强可扩展性。

Smalltalk还首创模型-视图-控制器MVC模式，将数据、展示与交互正交解耦，成为Java Swing、iOS UIKit、Web MVVM的理论起点。

**3. 从语法规则到系统思维**

结构化编程以模块化、类型检查与控制流规范为程序提供清晰秩序，面向对象则赋予语言建模现实世界的能力，推动开发从过程驱动走向对象驱动与架构驱动。

Pascal与Smalltalk分别在可控性与可建模性上实现关键突破，为C++、Java、Delphi等奠定理论根基与实践模板，使编程语言从描述算法的工具跃升为构建复杂系统的工具。
