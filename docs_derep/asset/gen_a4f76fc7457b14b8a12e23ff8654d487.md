#### 4.3.3 用 Cursor 配置并使用 MCP

接下来看另一款为 AI 协同编程而生的强大 IDE——Cursor。它从零为 AI 编程打造，内置的 Composer Agent 能自主理解复杂任务并调用已配置的 MCP 工具。

##### 1. 配置 mcp.json 并接入 Composer Agent

与 TRAE SOLO 一样，Cursor 支持全局和项目级两种 MCP 配置模式，文件名都是 mcp.json。

- **全局配置：** 作用于所有项目，文件放在用户主目录的 ~/.cursor/mcp.json。可按 Ctrl/Cmd + ，打开设置面板，左侧菜单点 Tools & Integrations，右侧找到 MCP 设置进行配置，如图4-16 所示。

- **项目级配置：** 仅当前项目生效的专属工具包，文件位于项目根目录的 .cursor/mcp.json。Cursor 打开该项目时才加载对应 MCP 服务器，适合存放项目特有能力，如某电商项目的订单数据库 MCP。团队协作时可把该文件提交到代码库，成员拉取后无需重复配置。

配置完成后启用 Composer Agent 模式：在 Composer 中按 Ctrl/Cmd + I，选择 Agent 模式即可。启用后 Agent 会主动识别已配置的 MCP 工具并在需要时调用。

Composer Agent 的核心能力包括：

- **读写代码：** 自动识别并修改代码文件。
- **搜索代码库：** 在项目中语义搜索，快速定位相关代码。
- **调用 MCP 服务器：** 借助 MCP 提供的各类功能。
- **运行终端命令：** 直接在编辑器中执行命令行操作。
- **自动搜索网页：** 获取最新信息和文档。

提出需要外部能力的请求时，Agent 会在聊天区提示将使用的工具并请求批准。对常用且可信的工作流，可开启“自动运行”模式，让 Agent 自动执行工具调用，实现更高自动化。

#### 4.3.4 MCP 进阶用法与实战技巧

MCP 的真正威力在于把独立工具组合起来，构建可自动完成复杂任务的个性化工作流。

### 1. 多个 MCP 工具协同与性能调优

让多个 MCP 服务器协同工作，核心是掌握编排技巧。编排是指让多个独立 MCP 服务器为共同目标协同的能力，AI 智能体扮演总指挥，根据复杂指令智能判断各步骤调用哪个工具。

典型案例是“线上事故响应”工作流：告诉 AI“我们的网站登录页面好像出问题了，帮我查一下”，AI 会立即启动多工具协同。

- 先调用 Sentry MCP 检查错误监控系统的最新日志，并反馈“好的，我正在检查 Sentry 错误监控系统的最新日志”。

- 发现用户认证相关严重错误后，调用 GitHub MCP 查找相关代码提交记录。

- 最后调用 Slack MCP 在开发团队频道发出警报“已定位到问题，可能是由昨晚一次代码合并引起的，已附上错误日志和代码链接”。

整个过程流畅自然，像经验丰富的工程师在处理事故。

这种复合型 AI 应用的核心价值来自工具的智能编排与组合，这与 UNIX 命令行哲学相似：用管道符连接简单命令构建强大流水线，而 MCP 正是 AI 世界的“管道符”。因此学习 MCP 的关键是培养超越单一指令的“工作流设计”思维。

为特定项目搭建复杂工作流时，最佳实践是使用项目级 mcp.json，确保只加载当前项目所需服务器，让 AI 环境保持轻便高效。

##### 3. MCP 常见问题排查

使用 MCP 服务器时可能遇到连接问题，如频繁断开、建立失败；性能问题，如响应缓慢、处理能力不足；数据处理异常，如格式错误、处理失败等。相关故障与排除指南可参考表4-5。

| 问题现象 | 可能的原因与症状 | 解决步骤 |
| :--- | :--- | :--- |
| 服务器无法启动 | 工具未出现在可用工具列表中，或 MCP 日志显示错误 | 1. 检查 Node.js、Python 等依赖程序是否安装正确<br>2. 在终端手动运行 mcp.json 中的 command 和 args，查看具体报错信息<br>3. 确认配置文件中的路径是否准确 |
