Wikidata 的知识组织围绕若干核心要素展开：页面 Pages、实体 Entities、条目 Items、属性 Properties、陈述 Statements、限定符 Qualifiers、引用 References 等。它继承自 Wikipedia，同样以页面 Page 作为基本组织单元。Entities 可类比 OWL 中的 Things，指最上层的对象，每个 Entity 都有独立的维基页面。Entities 主要分为两类：Items 和 Properties。Items 类似 RDF 中的 Instance，指向具体的实例对象。Properties 与 Statements 则分别对应 RDF 中的 Property 与 Statement。通常一个 Item 页面还会收录多个别名 aliases，以及多个指向 Wikipedia 的外部站点链接 Sitelinks。

每个 Entity 都挂载多条 Statement。一条 Statement 由一个 Property、一个或多个值 Values、一个或多个限定符 Qualifiers、一个或多个引用 References，以及一个表示重要程度的 Rank 组成。

限定符 Qualifiers 用于刻画复杂的多元情境。例如陈述 spouse: Jane Belson 本身是二元关系，通过 Qualifiers 可以附加多重说明来呈现多元关系，如 start date: 1991 年 11 月 25 日 以及 end date: 2011 年 5 月 11 日 等。

引用 References 用来标示每条陈述的来源或出处，比如源自某篇维基百科页面。引用也是一种 Qualifiers，通常作为 Statement 的附属信息。

Wikidata 支持多种数值类型，包含自有的 Item 类型、RDF 字面量 Literal、URL、媒体类型 Commons Media，以及 Time、Globe coordinates、Quantity 三种复杂类型。

系统允许为每条 Statement 赋予三种可信度权重：默认的 normal、preferred 和 deprecated。

Wikidata 还定义了三种 Snack 结构来细化 Statement 的描述形式：PropertyValueSnack、PropertyNoValueSnack、PropertySomeValueSnack。PropertyNoValueSnack 类似 OWL 中的否定，用来表达类似“伊丽莎白一世没有配偶”的知识。PropertySomeValueSnack 类似 OWL 中的存在量词 someValuesFrom，用来表达类似“林修斯教皇有出生日期，但目前未知”的知识。

URI 机制遵循 Linked Open Data 原则，采用统一格式 http://www.wikidata.org/entity/<id>。其中 <id> 可以是 Item，例如 Q49，也可以是 Property，例如 P234。

## 2.5 知识图谱的向量表示方法
与前面基于离散符号的表达不同，本节介绍的方法是将知识图谱中的实体和关系映射到低维连续向量空间，而非使用离散符号化表达。

# 2.5.1 知识图谱表示的挑战
前面提到的若干知识图谱表示方法，其基础大多以三元组组织知识。在具体知识库网络中，节点对应三元组的头实体与尾实体，边对应三元组的关系。这种离散符号化表达能高效结构化数据，但在规模化应用中面临挑战。

知识以离散符号表达，符号本身无法承载语义层面的信息，也难以进行语义计算，对下游任务并不友好。在基于图结构的知识图谱上应用时，因图结构特性，算法多与图算法相关，复杂度较高，难以在海量知识库上扩展。

数据存在明显稀疏性，现实知识图谱中实体和关系都呈长尾分布，即某些实体或关系仅有极少量实例样本，这会影响应用的准确率。

由此可见，面对数据量大、应用场景多变的大规模知识图谱，需要改进传统表示方式。

# 2.5.2 词的向量表示方法
在介绍知识图谱向量表示前，先回顾词的表示方法。自然语言处理中，离散符号化的词无法蕴含语义信息，因此将词映射到向量空间，这既利于计算，也能在映射过程中让向量蕴含语义。知识图谱的向量表示方法也借鉴了这一思路。

# 1. 独热编码
传统的独热编码 One-Hot Encoding 将一个词映射为一个很长的向量，向量维度等于整个词表大小。对于某个具体词，其独热向量中仅代表该词编号的维度为 1，其余均为 0。如图 2-19 所示，若词 Rome 编号为 1，则其独热编码只有第 1 维为 1，其余全为 0。方法简单，但不编码语义信息，稀疏性极强，词典越大向量维度越高。

# 2. 词袋模型
词袋模型 Bag-of-Words、BoW 是一种对文本中词的表示方法。该方法把文本看作装词的袋子，不考虑词间上下文关系，不关心顺序，仅统计每个词在该文本中的出现次数。具体做法是先收集所有文本的可见词汇组成词典，再对词编号，对每个文本用一个记录各词出现次数的向量表示，该向量每维数值表示对应词在该文本中的出现次数。如图 2-20 所示，在文本 doc_1 中 Rome 出现 32 次，Paris 出现 14 次，France 出现 0 次。

### 2.5.1 连续词袋模型
该模型不考虑词序，主要思想是用上下文预测中心词，从而训练出的词向量包含上下文信息。如图 2-21（a）所示，其中 wₙ 为中心词，wₙ₋₂，wₙ₋₁，wₙ₊₁，wₙ₊₂ 为其上下文。将上下文词的独热表示与词向量矩阵 E 相乘，提取相应词向量并求和得到投影层，再经 Softmax 层输出，输出每维表示词表中每个词作为该上下文中心词的概率。训练时模型像一个窗口在语料上滑动，故称连续词袋模型。

### 2.5.2 Skip-gram 模型
Skip-gram 思想与 CBoW 相反，用中心词预测上下文。如图 2-21（b）所示，先通过中心词的独热表示从词向量矩阵中取出中心词向量得到投影层，再经 Softmax 得到输出，输出每维代表某个词作为输入中心词上下文出现的概率。

### 2.5.3 知识图谱嵌入的概念
为解决前述知识图谱表示挑战，受词向量启发，研究者探索把知识图谱中的实体和关系映射到连续向量空间并保留语义信息，以便在下游任务如问答、关系抽取等中更方便操作。对计算机而言，连续向量能蕴含更多语义，更易理解与操作。该研究方向即知识图谱嵌入 Knowledge Graph Embedding，也称知识图谱向量表示、知识图谱表示学习 Representation Learning、知识表示学习。

与词向量相似，知识图谱嵌入也是通过机器学习训练模型。与独热编码、词袋模型的最大区别在于，知识图谱嵌入训练基于监督学习。训练过程可学习语义层信息，且词向量的空间平移性同样适用。经典模型 TransE 的设计思想是，若三元组（h, r, t）成立，则需满足 h+r≈t，例如：

vec(Rome) + vec(is-capital-of) ≈ vec(Italy)

### 2.5.4 知识图谱嵌入的优点
研究者转向嵌入方法，因向量表达实体关系的知识图谱嵌入相比传统方法具有多项优势。

用向量表达可提升应用计算效率，映射到向量空间后算法可用数值计算，效率同步提高。

增加下游应用设计多样性。向量表示后知识图谱更适配当前流行的机器学习算法，如神经网络等。因输入不再是符号，可用的方法也不限于图算法。

将知识图谱嵌入作为下游应用的预训练向量输入，使输入信息不再是孤立无语义的符号，而是已训练并蕴含一定信息的向量。

综上，知识图谱嵌入可提高计算效率、丰富下游应用、并作为预训练提供语义支持，具有较大应用价值与前景。

### 2.5.5 知识图谱嵌入的主要方法
多数知识图谱嵌入模型依赖知识图谱中可直接观察到的信息训练，即根据所有已知三元组训练。对于这类方法，常只需训练出的实体与关系表示满足训练三元组即可，但结果往往不能完全满足所有下游任务。因此也有研究关注如何利用除知识图谱外的额外信息训练嵌入，这些信息包括实体类型 Entity Types、关系路径 Relation Paths 等。

根据综述[11]，知识图谱嵌入方法可归类如下。

### 1. 转移距离模型
转移距离模型 Translational Distance Model 的核心思想是把向量化后知识图谱中三元组的合理性问题，转化为衡量头实体与尾实体距离的问题。重点在于设计得分函数，得分函数常被设计为利用关系把头实体转移到尾实体的合理性函数。

受词向量启发，可将词与词在向量空间的语义关系拓展到知识图谱头实体与尾实体关系，即把头实体与尾实体映射到向量空间，其联系可视为三元组中的关系。TransE 正是受词向量平移不变性启发，把实体和关系都表示为向量，对具体关系（head, relation, tail），把关系向量解释为头实体向量到尾实体向量的转移向量。也就是说，若知识图谱中某三元组成立，则其实体与关系需满足 head+relation≈tail。

### 2. 语义匹配模型
相比转移距离模型，语义匹配模型 Semantic Matching Models 更注重挖掘向量化后实体与关系的潜在语义。该方向代表模型为 RESCAL 及其延伸。

RESCAL 核心思想是将整个知识图谱编码为三维张量，由此张量分解出核心张量与因子矩阵，核心张量中每个二维矩阵切片代表一种关系，因子矩阵中每一行代表一个实体。由核心张量与因子矩阵还原的结果被视为对应三元组成立的概率，若概率大于阈值则三元组正确，否则不正确。其得分函数可写成
