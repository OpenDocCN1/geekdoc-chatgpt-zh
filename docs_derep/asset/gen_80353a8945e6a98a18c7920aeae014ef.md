多卡 GPU 让推理提速的核心在于并行。把多条输入一次性打包成一个批次喂给模型，就能让不同显卡同时处理不同样本，充分发挥并行计算能力，整体吞吐明显提升。

再往上走一步是分布式推理。此时模型的权重被拆分到多张显卡上协同执行，每张卡负责一部分样本或模型片段，算完后再把中间结果汇总输出。并行粒度更细，推理效率进一步放大。

配合使用多卡还能做好负载均衡。把推理任务按需分配到不同显卡，避免出现有的卡空转有的卡过载，算力得到更充分利用，整体效率更高。

需要注意的是，多卡环境并非无脑提速。数据如何切分、分发，显卡之间如何通信，模型参数如何同步，都需要额外优化和管理。要保证数据划分准确、传输顺畅、各卡负载均衡，否则资源竞争和通信开销反而会拖慢性能。合理的模型并行与数据并行策略，加上专门的工具库或框架来调度多卡协同，才是稳定加速的前提。

### 9.3.3 多机
多机推理是指把推理工作放在多台计算机或服务器集群上完成。面对海量数据或超大规模模型，单机算力往往吃紧，多机并行可以大幅提升计算效率与吞吐量，让原本不可行的任务变得可行。

常见的多机并行方式有三种。

（1）数据并行。数据被切分到各机器上，每台机器保存模型完整副本，只处理分配到的那部分数据。吞吐量可显著增加，但切分数据和汇总结果会带来额外开销。

（2）模型并行。模型被拆分部署到多台机器上，每台机器只负责模型的一部分计算。对单机放不下的大模型尤其有效，只是模型切分与结果合并会增加通信成本。

（3）流水线并行。模型的不同阶段在不同机器上按时间流水线推进，像工厂装配线一样连续作业。计算效率更高，但需要精细设计以保证每台机器都被充分利用。

多机推理与多 GPU 推理是不同层级的并行思路，可以单独使用，也可以叠加成多机多卡策略。也就是说每台机器内部有多张 GPU，任务先分到机器再分到卡。这样对算力需求极高的场景收益更大。

多机多卡也带来新挑战，比如任务如何有效分配、跨卡跨机结果如何同步、通信开销如何控制等。通常需要借助 TensorFlow 分布式版、PyTorch 分布式包等专业框架，它们提供调度与通信工具，让多机多卡推理更易落地。

## 9.4 Hugging Face Transformers库

### 9.4.1 简介
Hugging Face Transformers 是一个非常受欢迎的开源库，内置了 Llama、BERT、GPT-2、RoBERTa 等大量预训练模型，可用于各类自然语言处理任务。调用模型推理有多种途径。

（1）Pipeline API。最便捷的方式，覆盖文本分类、命名实体识别、问答等常见任务。几行代码即可完成模型加载、预处理、后处理与推理，细节见 9.4.2 节。

（2）Model and Tokenizer API。需要更精细控制时使用，例如自定义预处理流程或采用非默认模型，细节见 9.4.3 节。

（3）Onnx Runtime。面向生产部署，Hugging Face 提供模型转 ONNX 的工具，能在多种硬件上获得更快运行。

（4）Hugging Face Inference API。官方托管服务，通过 API 直接调用模型，付费使用，能免去自行搭建基础设施的负担。

本书及主流实践主要采用 Model and Tokenizer API 来使用 Transformers。

AutoModelForCausalLM 是一个自动模型类，根据模型名称或预训练路径自动选择合适的因果语言建模模型。学习式自回归生成是其核心，模型依据已有文本预测下一个词或字符。该类可返回 GPT、GPT-2、Llama 等对应预训练模型。

AutoTokenizer 是自动分词器类，根据模型名称或路径自动选择匹配的分词器。分词器负责把文本切分为标记序列，使模型能够处理离散输入。
