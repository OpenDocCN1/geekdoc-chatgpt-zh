BROKE 的思路分为五步。先把背景交代清楚，让模型抓住来龙去脉；再指定一个明确的人设，让模型按此身份回应；接着点明要完成的任务；随后给出可衡量、可验证的关键成果；最后通过小范围试跑和持续调整让结果更理想。下面给出金融领域的实操样例。

### 3.2.5　CO-STAR 框架

CO-STAR 由六大要素组成。

（1） 情境 context：把与任务有关的背景说明白，细节越充分越好，有助于模型把握关联，保证输出不跑偏。
（2） 目的 objective：说清希望模型完成什么具体事项，便于模型锁定方向。
（3） 呈现风格 style：规定回应的呈现方式。
（4） 语调 tone：设定情感基调，确保输出的情绪色彩符合预期。
（5） 读者 audience：明确内容面向谁，避免生成目标读者难以理解的信息。
（6） 输出 response：锁定格式和结构。比如要求 JSON 输出方便程序处理，或按金字塔、列表等常见结构组织内容。

## 3.2　指令框架

指令框架本质上是分模块、分场景的标准模板，能帮助使用者更高效地搭建精准指令。合理使用可以减少歧义，提升执行效率，满足复杂场景需求。

### 3.2.1　指令框架概览

借助框架可以达成以下效果。

（1） 打破 AI 的思维局限。大模型的输出质量高度依赖输入清晰度。结构化信息能帮助模型更准确地理解用户意图。
（2） 节省反复调试的时间。据统计，使用框架后人与模型之间的对话轮次能明显减少。
（3） 适配专业场景需求。不同领域如编程、营销、教育需要不同的沟通逻辑，框架能提供场景化解法。

使用指令框架要注意以下 5 点。

（1） 明确任务类型。按任务属性匹配框架，如创意类适合用 BROKE，技术类更适合 ICIO。
（2） 按模块填充信息。以 CRISPE 为例，“能力与角色”填“资深营养师”，“背景洞察”填“用户是健身新手，需制定减脂食谱”，“风格”填“步骤清晰并附热量计算”。
（3） 迭代细化。根据模型输出对模糊表述做优化，如把“正式风格”改为“商务报告风格”。
（4） 避免信息过载。框架不是越复杂越好，需根据任务复杂度选择。
（5） 灵活组合。可跨框架混用模块，如组合使用 BROKE 的“进化”与 CRISPE 的“能力与角色”。

### 3.2.2　ICIO 框架

ICIO 包含四个核心部分。

（1） 指令 instruction：要求模型执行的核心动作。
（2） 情境 context：为模型提供完成任务所需的环境信息、背景知识等。
（3） 输入数据 input data：需要模型处理和操作的具体素材或数据。
（4） 输出指引 output indicator：明确规定输出结果的格式、风格、长度、结构等。
