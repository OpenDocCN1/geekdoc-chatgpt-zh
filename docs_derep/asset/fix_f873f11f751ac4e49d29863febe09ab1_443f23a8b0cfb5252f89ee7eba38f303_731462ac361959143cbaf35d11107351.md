在系统兼容性上，OpenClaw 能在 macOS、Windows、Linux 三大桌面环境中运行。本书更建议用 macOS 或 Linux 来搭建。macOS 是官方最看重的部署选择，在该环境下可以获得最完整的系统调用能力，像日历操作、备忘录读取、屏幕截图等。底层基于 UNIX，与现有技术栈契合度很高，安装体验通常比较顺滑。

Windows 也能完整运行，日常使用感受与 macOS 版的核心能力基本一致，只是在部分系统级联动上会受限。如果你主要在 Windows 上工作，核心功能完全可用，不会影响常规操作。若追求更强的兼容性，可在 Windows 下借助 WSL2 来跑，体验会更好。

Linux 适合有一定技术积累的开发者，可玩性最高，支持源码编译、自定义部署参数等进阶操作。

### 2.1.2 通信平台选择
OpenClaw 把即时通讯工具作为交互入口，支持多家服务，用户只需挑选其一完成配置。不同服务的特性与网络可达性差异明显，挑选时要结合使用场景和所在地区网络综合判断。

在国内，首选是飞书。飞书的机器人接口相当完备，消息形态覆盖文本、图片、文件、卡片等，并且群机器人很适合团队协同使用。若没有飞书账号，企业微信或 QQ 也是备选，它们同样提供基础机器人接入能力，能满足核心交互需求，只是高级消息形态的支持有限。

面向海外用户，一般首推 Telegram。Bot API 设计规范、文档齐全、社区很活跃。WhatsApp 与 Discord 也可以选用，前者需要绑定手机号，后者更偏向技术社群场景。

### 2.1.3 AI 模型服务准备
OpenClaw 并不负责模型训练也不托管模型，它只是调度层，通过 API 接入外部大模型来实现功能。所以在使用前，必须先准备好一个可用的模型服务。

国内用户推荐走中转 API。中转服务把国内外多款大模型统一收口，像 GPT 系列、Claude 系列、Gemini 等海外模型，以及 Kimi、DeepSeek、GLM-4 等国产模型都能接入。优势在于计费统一、国内访问更快、模型切换灵活。主流服务商有开源项目 OneAPI、NewAPI，以及各大云厂商提供的 API 网关。挑选时可关注模型覆盖面、稳定性、价格和技术支持。

也可以直接调用官方 API，比如 OpenAI API 或 Anthropic Claude API，路径更直接，但需要自行解决网络连通问题。

有技术能力的用户还可以尝试本地部署开源模型，例如用 Ollama 运行 Llama、Qwen 等。本地部署的优点是可完全离线、数据不上传第三方，安全性更高；代价是对硬件要求较高。

建议按以下 6 个要点完成自我介绍，让 Agent 精准服务：

1. 你的称呼：告诉 Agent 怎么叫你，例如“叫我小明”或“叫我老板”
2. 时区和语言：告知所在时区及偏好语言，例如“我在中国，时区 UTC+8，用简体中文交流”
3. 它的角色：说明身份定位，例如“你是我专属的技术助手”或“你负责处理我的日常事务”
4. 工作环境：告知常用工具和系统，例如“我常用 VS Code 开发，主要用 Windows 系统”
5. 回答风格：说明偏好，例如“回答要简洁”或“重要信息要详细解释”
6. 红线：明确哪些操作必须先经你同意，例如“删除文件前必须经我确认”
