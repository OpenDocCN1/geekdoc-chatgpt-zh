### 6.3.2 Task System：持久化任务系统

上一节的 Todo 功能本质上只是扁平化的清单。它能保证串行执行，却无法处理复杂的依赖关系，比如“任务A完成后才能启动任务B”的前置约束，或“任务C与任务D可并行”的协同需求。更关键的是，清单仅驻留在内存中，一经上下文压缩或进程异常终止，状态就会丢失，难以支撑长周期开发的连续性。

为解决这些痛点，Claude Code 引入了 Task System。核心设计是将扁平清单升级为有状态的任务图，通过把任务状态落盘到磁盘，确保生命周期不再受单次对话窗口限制，实现跨会话的追踪与管理。

实现思路上采用文件化存储，每个任务抽象为独立的 JSON 文件并统一存放到指定目录。数据结构中新增了 blockedBy 表示前置依赖、blocks 表示后置依赖。
