GCC 在跨平台软件构建中长期占据主导地位。不同于只能锚定特定系统运行环境的构造器，GCC 使用同一套前端在各平台生成一致的中间表示，于是借助 GCC 重新构建时，获得可靠输出结果的可能性很高。

#### 2. Clang/LLVM

##### 1）Clang

Clang 是 C、C++、Objective-C 与 Objective-C++ 的编译器前端，后端由 LLVM 承担。

Clang 始于 2005 年苹果发起，是 LLVM 工具链的前端，职责是为源码生成抽象语法树并编译成 LLVM Bitcode，随后由 LLVM 后端转为平台相关的机器码。目标是提供可替代 GNU 编译器套件 GCC 的方案，项目包含 Clang 前端与 Clang 静态分析器等。

Clang 性能优异，其 AST 占用的内存仅约 GCC 的 20% 左右。FreeBSD 10 已将其作为默认编译器使用。编译出错时，Clang 能给出精确的位置、错误说明与修复建议。

与名称相符，Clang 仅支持 C 家族语言。研发始于 2007 年，C 编译器最先完成，而 Objective-C 实质是 C 的简易扩展，很多情况可等价改写为对运行库的 C 函数调用，因此 2009 年时已可用于生产环境。

目前 GCC 在跨平台兼容性上仍最强，但兼容性的代价是性能。苹果为提升 Mac 系统构建效率，自行打造了 Clang 与 LLVM，Clang 负责前端，LLVM 负责后端。

##### 2）LLVM

> LLVM 提供了与编译器相关的支撑，涵盖程序语言的编译优化、链接优化、即时编译优化与代码生成。简言之，可作为多种编译器的通用后台。

LLVM 本身是编译基础设施，可容纳多种语言编写的程序，并利用虚拟化技术实现编译时、链接时、运行时以及空闲时的优化。

## 8.3 GCC 基本介绍与特征

GCC 最初作为 GNU 操作系统编译器编写，旨在为 GNU/Linux 系统开发高效 C 编译器。其历史可追溯到 1987 年，由理查德·斯托曼创建，作为 GNU 项目一部分。

20 世纪 90 年代和 21 世纪 00 年代，GCC 经历几次重要重构与扩展。改进包括引入新优化技术、提升代码生成与分析能力，以及增强对新兴编程语言和硬件架构支持。随着 GNU/Linux 快速发展，GCC 逐渐扩展支持范围，涵盖 Microsoft Windows、BSD 系列、Solaris 和 MacOS 等操作系统平台。

GCC 主要特征：

- 可移植性：支持多种硬件平台，可在不同架构上进行编译。
- 跨平台交叉编译：支持在一个平台上为另一个平台生成可执行文件，对嵌入式开发尤为重要。
- 多语言前端：除 C 外，还支持 C++、Fortran、GO 等。
- 模块化设计：允许轻松添加新语言和 CPU 架构支持，增强扩展性。
- 开源自由软件：源代码公开，可自由使用、修改和分发。

### 8.3.2 GCC 编译方法

1. 本地编译

指编译源代码的平台与执行编译后程序的平台相同。平台可理解为 CPU 架构加操作系统。比如在 Intel x86 架构或 Windows 平台下使用 Visual C++ 编译生成的可执行文件，需在相同架构与 Windows 10 下运行。

2. 交叉编译

指编译源代码的平台与执行编译后程序的平台不同。比如在 Intel x86 架构 Linux Ubuntu 平台下使用交叉编译工具链生成的可执行文件，在 ARM 架构 Linux 下运行。

### 8.3.3 与传统编译区别

GCC 中编译过程分为预处理、编译、汇编、链接四个阶段。其中预处理、编译属于三段式划分的前端部分，汇编属于后端部分。

GCC 四阶段与传统三段式前端、优化、后端划分有重合对应，但 GCC 划分更细致全面，使各阶段功能更明确独立。

- GCC 支持多种编程语言、跨平台支持广泛、功能完备，但难以作为 API 继承，代码量庞大。
- GCC 与传统编译阶段划分有所区别。

## 8.4 LLVM 架构设计和原理

8.3 节已详细探讨 GCC 编译过程与原理。然而 GCC 存在代码耦合度高、难以独立操作、代码量庞大等缺点，人们期待新一代编译器出现。本节深入研究 LLVM 架构设计与原理。

### 8.4.1 LLVM 发展历程

LLVM 项目起源于 2000 年伊利诺伊大学厄巴纳-香槟分校的维克拉姆·艾夫与克里斯·拉特纳研究，旨在为静态与动态语言创建动态编译技术。LLVM 以 BSD 许可证开发。2005 年苹果雇佣克里斯·拉特纳团队为 MacOS 与 iOS 开发工具，LLVM 成为这些平台开发工具一部分。

项目最初命名为低级虚拟机 Low Level Virtual Machine 的缩写。随着发展，该缩写产生混淆，现 LLVM 已成为品牌，用于指代 LLVM 项目下所有子项目，包括 LLVM IR、调试工具、LLVM C++ 标准库等。

LLVM 已迅速发展为庞大编译器工具集合。LLVM 激发许多人为多种编程语言开发新编译器，其中最著名的是 Clang。作为新编译器，Clang 提供 C、Objective-C 与 C++ 支持，并得到苹果大力支持。

### 8.4.2 LLVM 架构特点

LLVM 架构具有独立组件与库化特点，使前端与后端工程师能相对独立工作，提高开发效率与代码可维护性。其核心在于中间表示 IR，通过统一灵活 IR 实现对不同编程语言与目标平台支持。优化将 IR 转化为高效形式，再由后端生成目标平台机器码。该设计使 LLVM 具有适应不同需求与硬件架构的灵活性和高性能。

### 1. LLVM 组件独立性

LLVM 显著特点是组件独立与库化架构。使用 LLVM 时，前端工程师只需实现相应前端，无需修改后端，从而添加新语言更简便。因为后端只需将中间表示翻译成目标平台机器码即可。

后端工程师只需将目标硬件特性如寄存器、硬件调度与指令调度与 IR 对接，无需干预前端。这种灵活架构使编译器前端与后端工程师能相对独立工作，大幅提高开发效率与可维护性。

在 LLVM 中，IR 扮演关键角色。它是一种类似汇编语言的底层语言，具有强类型与精简指令集 RISC 特点，并对目标指令集进行抽象化处理。

### 2. LLVM 中间表示

LLVM 提供一套适用于编译器系统的中间表示，并围绕其进行大量变换与优化。经过变换优化后，IR 可被转换为与目标平台相关汇编语言代码。

与传统 GCC 前端直接对应后端不同，LLVM 的 IR 是统一的，可适用于多种平台进行优化与代码生成。
