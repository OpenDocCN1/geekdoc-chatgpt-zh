Manus 的底座是围绕任务拆解与结构化执行的协同型多智能体架构。初期阶段，智能体先由需求分析模块读取用户意图，利用大模型提炼核心目标，对表述模糊的请求主动澄清，随后把复杂诉求拆解为可直接落地的子任务。

落地层面，Manus 集成了复合工具链，涵盖网页交互、文件系统读写、Shell 调用、通讯接口以及部署能力，可进行多模态处理，兼容 JavaScript、Python 等十余种语言与主流开发框架。

执行侧采用动态规划机制，分步推进时全程跟踪进展，遭遇阻碍即触发自适应调整并产出替代方案。

质量侧形成结果校验、代码测试与反馈学习闭环，保证输出可信度，同时遵守隐私保护、系统安全边界与道德规范。

整体而言，Manus 能随持续学习提升效能，却受制于上下文窗口大小与沙盒隔离原则，无法触达外部系统或执行越权操作。

### 7.1.3　开源方案介绍

Manus 的表现加速了开源社区在通用智能体方向的跟进。闭源收费、邀请码限流等做法促使开发者寻找可自主掌控、成本更低且原理透明的替代品，于是出现 OpenManus 等方案。

技术路线上，这些实现与 Manus 趋同，均采用多智能体协同架构。核心思路是将用户输入的复杂自然语言指令，例如“分析数据并产出报告”，自动转化为逻辑清晰的子任务，分派给不同专长的执行体协同完成，如检索类、编程类、文件整理类。工具整合同样被重视，通过接入网络检索、代码解释器、文件操作等外部能力，扩大智能体在数字环境中的实际行动半径。

开源与闭源的差异远不止费用，关键在透明度与可演进性。OpenManus 在致谢中点名 Computer Use、Browser Use 等项目，清晰交代了技术来源与搭建思路。架构透明后开发者可审阅、定制并优化，进而推动整体领域迭代与生态繁荣。

OpenManus 由四大模块构成。

（1）**智能体模块**。定义基础接口与主要实现，覆盖任务规划、ReAct 风格推理与工具调用处理。
（2）**流程模块**。提供 Manus 式工作流基类，实现智能体的获取、添加与状态维护，状态包括未启动、进行中、已完成、受阻，并提供 FlowFactory 用于为多智能体生成不同工作流。
（3）**工具模块**。收纳各类工具脚本。同样选用 browser-use 库驱动浏览器，支持的动作包括地址导航、返回、刷新、网页搜索、元素交互、内容抽取与标签页管理等。
（4）**提示词模块**。内置 Manus、Planning、Swe、Toolcall 等智能体的提示词，分为系统级提示词与指导下一步行动的 NEXT_STEP_PROMPT。

从 Manus 到开源替代的演进说明，多智能体任务拆解与工具调用已成为通用智能体的共识。公开代码与协作开发降低门槛，使智能体从封闭产品变为可审阅、可修改的开放底座，为后续创新提供基础。

### 7.1.4　商业对手介绍

Manus 的走红让行业直观感受到通用智能体与传统对话模型的分野，前者可自主操控电脑、浏览器、编写代码。Manus 基本框定了该品类的功能与形态，也点燃了赛道热情。

#### 1．扣子空间

2025 年 4 月 18 日，字节跳动首个面向消费者的通用智能体“扣子空间”开启内测。定位兼顾通用实习生的广度与领域专家的深度，具备可扩展能力。产品可自行解析需求、拆分子任务、调用浏览器与代码编辑器等工具，并以 PPT、网页、文档等形式交付，核心在于外部工具与服务的集成。

发布前，字节在 2025 年 3 月开源了智能体产品 TARS。界面与 Manus 相似，左侧对话区，右侧实时展示智能体在虚拟机中的操作。TARS 支持 MCP 协议，具备图形界面交互能力。

TARS 的视觉交互基于自研原生 GUI 模型 UI-TARS。该模型以视觉-语言结构为基础，通过增强感知、推理机制与统一动作建模识别 GUI 元素并执行点击、输入等操作。扣子空间的浏览器调用与界面操作即基于 UI-TARS。

从 Manus 到 TARS 再到扣子空间，竞争焦点由“能否操控”转向“如何高效开放地操控”。开源 UI-TARS 并兼容 MCP 协议，字节既推出消费级产品也在构建以智能体为核心、工具可扩展的开放生态。

#### 2．AutoGLM

AutoGLM 由智谱研发团队打造的移动端通用智能体，核心在于把大模型的规划决策与机器人流程自动化深度融合，使其能像人一样直接操作手机应用界面，完成真实日常任务。

与依赖 API 的方案不同，AutoGLM 基于 Android 无障碍服务，通过“观察”屏幕解析 GUI 并“模拟”点击、滑动实现自动化。兼容性强，但对界面稳定性有依赖。

行动型智能体的主要特征：

（1）端到端自主执行：接收“点外卖”“预订机票”等自然语言指令后，自主完成打开应用、检索浏览、比价到下单的完整链路，最终支付需人工确认。
（2）多模态感知与决策：结合视觉识别与 ReAct 式推理实时分析屏幕元素如按钮位置，动态规划下一步路径。
（3）持续学习优化：借助在线强化学习，任务成功率随使用反馈不断提升。

覆盖生活服务自动化如外卖、旅行预订，信息处理自动化如新闻整理、论文摘要，设备管理自动化如手机清理、跨应用数据迁移。

生态延伸出 AutoGLM-Web 专注浏览器自动化，以及 GLM-PC 专注桌面办公自动化，形成移动、网页、桌面全覆盖的解决方案。

#### 3．Genspark

Genspark 超级智能体由 MainFunc 公司推出，用于执行复杂数字任务与现实世界任务。定位不是对话入口，而是具备自主规划与执行能力的数字执行者，可调用多样工具替代或辅助用户完成信息处理到实际联络的全流程。

架构采用混合智能体模式，不依赖单一大模型，而是动态整合 DeepSeek 等多种专用模型，形成内部专家委员会，按任务类型自动分派给最合适的模型组合，在效率与准确性间取得平衡。

工具生态包括深度信息获取，通过增强搜索与网页抓取主动整合信息；现实世界交互，具备自动电话呼叫等能力，可代为酒店预订、餐厅订座；内容与创意生成，支持图像、视频、专业文档与演示文稿；数据分析，可直接处理复杂数据集并给出洞察。

此外还能按指令生成功能性数字成果，如个人介绍页、可交互网页应用、简易 HTML 小游戏，体现思考即构建的能力。整体路径为多模型协同决策加广域工具调用，推动 AI 从顾问角色走向主动执行并交付成果的代理角色。

#### 4．ChatGPT Agent

ChatGPT Agent 由 OpenAI 于 2025 年 7 月发布，由原 Operator 团队与 Deep Research 团队合并组建。

突破不在于新增工具，而在于技术路径的根本变化：不把浏览器操作、研究分析、代码执行等能力工程化拼接在模型之外，而是通过端到端统一训练将智能体技能内化为单一模型的核心能力，更像一个能自主规划并使用多种工具完成复杂任务的数字大脑。

可集成文本与图形浏览器、终端命令行及图像生成器等关键工具，呈现实用智能体特性。

（1）自主任务拆解与执行：用户以自然语言下达“分析我的日程与近期新闻，为下周客户会议准备简报”等复杂指令，Agent 会自行规划步骤，依次检索、筛选、分析并生成可直接使用的 PPT 或文档。
（2）交互式协作与可控性：支持多轮对话，会主动询问细节并确认意图。用户可随时打断、修改要求或完全接管控制，实现人机协同的灵活工作。
（3）安全与权限设计：可能产生实际影响的操作如购物、发邮件、处理个人信息默认需用户明确许可。模型内置严格防护，自动拒绝高风险请求如金融转账、法律建议，对生物化学等领域风险采取最高级安全处理。

发布标志着 AI 智能体从问答式聊天机器人向使用工具完成任务的主动数字助手演进，统一模型架构与安全优先原则为构建可靠、可协作的通用智能体提供技术基础。

### 7.2　AI 自动化工具

通用智能体的能力背后，依赖浏览器自动化、桌面自动化和移动端自动化等工具。它们让智能体覆盖 Web、桌面与移动端。

### 7.2.1　Browser Use

Browser Use 是为 AI 智能体定制的浏览器自动化工具，为缺乏物理交互能力的智能体提供标准化接口，使其能理解网页内容并执行精细化操作，与真实 Web 应用交互。

不同于传统脚本化自动化，Browser Use 直接服务于智能体的决策流程。可接收自然语言指令如“查询今日美股涨幅前十的股票”，并将其分解为导航、点击、滚动、表单填写、数据提取等精准动作，自主完成信息收集、任务执行与状态验证。

技术架构围绕赋能智能体设计：

（1）多模型驱动内核：可接入 GPT-4、Claude、DeepSeek 等大模型，由模型负责理解指令、解析页面结构并做决策，适配不同复杂度与成本需求。
（2）智能化环境感知：通过 DOM 与 XPath 识别元素，结合视觉与语义理解精准定位交互目标，确保在动态网页中操作稳健。
（3）复杂任务流管理：支持多标签页管理，可在多任务间切换协作；跨平台特性保证部署环境一致。
（4）可扩展行动体系：开发者可添加自定义工具如保存数据到数据库，将浏览器操作与企业内部流程无缝衔接。

关键应用场景包括自主信息代理，定期抓取竞品价格、金融数据等结构化信息；交互验证与测试，模拟真实用户行为执行复杂 UI 流程并动态校验；数字化工作流执行，登录在线办公系统完成文档撰写、报表生成与导出等任务。

Browser Use 在自然语言指令与低层浏览器操作之间建立桥梁，增强智能体的环境感知与行动执行力。

### 7.2.2　Computer Use

Computer Use 是 Anthropic 于 2024 年 11 月提出的技术范式，使 AI 能像人类一样操作计算机系统，包括点击图标、输入文本、管理文件等。

核心特点包括：

（1）**多模态感知**：通过视觉语言模型解析屏幕截图，结合光学字符识别定位可交互元素坐标。
（2）**拟人化操作链**：遵循感知→决策→执行循环，例如截图分析→光标移动→点击→验证结果。
（3）**系统级输入模拟**：直接调用操作系统 API 执行键盘鼠标操作，支持跨应用操作如 Excel 处理、PPT 制作。

典型场景为跨软件任务，如股票分析到数据整理的自动调用；端到端测试，模拟用户行为进行全流程测试；隐私限制场景，通过界面操作间接完成任务以避免直接访问 API。

该技术可将自然语言精确转换为复杂系统操作指令，未来用户无需学习繁琐软件逻辑，用自然语言即可完成计算机上的常见工作。

OmniParser 是另一种实现。微软研究院于 2025 年 2 月发布 OmniParser V2，可实时解析屏幕界面元素并转化为 JSON 等结构化数据，使 AI 能理解指令并执行点击、输入等操作，无需针对特定界面微调，显著提升效率与精准度。

主要特点为精准解析 UI 元素，从像素级图像中提取可交互区域边界框、功能语义与文本内容，不依赖 HTML 或视图层级；多模态兼容，可与 DeepSeek-R1、Qwen 2.5VL 等主流大模型无缝集成，提升代理任务执行精度。

### 7.2.3　DroidRun

DroidRun 是一个强大的工具，可用自然语言命令控制 Android 设备，具备视觉理解与 UI 结构提取能力，实现流畅交互。

主要特点包括：

（1）**视觉+UI 解析**：结合视觉模型识别屏幕内容与 UI 结构提取解析控件树，实现精准交互。
（2）**智能自愈机制**：能检测网络中断、界面变化等错误并自动调整操作路径。
（3）**支持 Android Portal APK**：类似智能体通行证的 Android 应用，部署后 AI 可操控整个系统。
（4）**多系统管理**：支持多台设备多实例，支持复杂工作流与并行处理。
（5）**元素追踪**：可精准提取点击元素，复现大模型行为，保证自动化一致性。
（6）**凭证管理器**：支持登录信息与双因素身份验证绑定，个性化用户体验。

DroidRun 标志着大模型与移动操作系统的闭环被打通，智能体终于能看懂手机、动得了 App，像人一样打开应用、点击按钮、滚动页面、处理表单，甚至完成网页交互与账号登录。

这一步让智能体从只能看网页走向全端自动化，实现智能化移动交互。
