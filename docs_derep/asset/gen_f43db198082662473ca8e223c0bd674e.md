扣子为 AI 交互提供了数据库级的记忆方案，能够长期保存对话中的关键参数与内容。比如创建一座数据库专门沉淀阅读笔记，收纳书名、阅读进度、个人批注等信息。借助数据库的查询，智能体能给出更精准的回答。

### 5.1.1　扣子的智能体开发功能概述
借助大模型，扣子把智能体搭建门槛降得很低。在发挥大模型长处的基础上，平台还允许用户借助知识库、工作流等手段微调智能体的应答逻辑，确保输出符合预期。以下概览扣子的智能体开发能力。

#### 1．编排能力
扣子集成了多款大模型，并提供丰富的配置选项，满足从简单到复杂的任务需求。

（1） **提示词调优** 。提示词本质上是定义模型行为方式和参考上下文的指令。用户可以塑造智能体的角色设定，明确其可答与不可答的边界、输出格式要求以及其他参考要点，从而提升回答质量。扣子还能借助 AI 自动优化提示词，让模型回复更结构化、更精准。

（2） **模型参数配置** 。平台提供多类模型，并允许按业务场景调节参数如温度等。用户可根据具体问题和应用场景反复调试，直至对话效果最优。

（3） **协作模式选择** 。默认情况下扣子采用单智能体模式，由一个体独立处理全部任务。若要构建更复杂、功能更全面的系统，可切换至多智能体模式。为不同智能体分别设定提示词，把复杂任务拆解为多个子任务，避免在单一提示词中堆砌所有判断与限制。

#### 2．搭建功能
通过知识、插件等手段，平台能够缓解大模型的幻觉问题并弥补专业知识短板。此外，记忆功能还能让智能体基于历史对话生成更贴合的回复。以下逐项说明。

（1） **技能拓展** 。技能构成智能体的基础能力池，借助插件、工作流、触发器等工具可在搭建时不断拓宽模型边界。

**·** **插件** 依托 API 将各类平台与服务接入智能体，实现功能扩充。平台内置大量现成插件可直接使用，也支持用户自建插件把所需 API 封装成工具。例如调用新闻插件获取资讯，或用搜索工具在线检索信息。

**·** **工作流** 用来设计并落地复杂逻辑。用户可拖拽任务节点搭建流程，从而提高处理复杂任务的效率。

**·** **触发器** 让智能体在特定时间或满足特定条件时自动启动任务。

（2） **知识接入** 。该功能允许导入本地或线上数据，提升大模型输出的可用性与准确度。

**·** **文本** 基于片段检索与召回，让大模型结合命中内容生成回答，适用于问答类场景。

**·** **表格** 可按索引列匹配数据，也支持自然语言转 SQL 的查询与计算。

**·** **照片** 支持 JPG 等常用图格式，通过图像标注实现检索与召回。

（3） **记忆** 。模型对话存在轮次限制，记忆功能为其提供可长期调用的记忆，令回复更具个性。

**·** **变量** 用于保存语言偏好等个性化信息，使回复更贴合用户。

**·** **数据库** 以简便高效的方式管理结构化数据，支持用自然语言增删查改，并可开启多用户模式实现精细化读写权限。

**·** **长期记忆** 模拟人脑对用户个性化信息的沉淀，借此提供定制化回复，增强体验感。

**·** **文件盒子** 实现多模态数据的合规存管与交互，让智能体能够多次复用已保存素材。

（4） **语音交互** 。除文字外，用户可用语音与智能体沟通，平台提供多种音色供挑选。

#### 3．设计能力
卡片是一种特殊的消息呈现形式，可自定义智能体输出的格式。扣子允许为工作流、插件等绑定卡片。

#### 4．发布渠道
扣子可把搭建好的智能体分发至多类渠道，扩大服务人群。当前支持发布到官方商店、模板库、第三方应用、API、SDK 或自建渠道。

#### 5．运营与运维
用户能在“预览与调试”区进行调试，也可对智能体做数据分析。

在“预览与调试”区可与智能体对话，依据响应结果优化配置。若实际使用中出现响应不符、延迟或无响应，也能在此查看执行细节以定位问题。

对已上线的智能体，开发者可通过分析看板追踪运营态势。数据分析提供用户规模等基础指标、访问意图等行为数据以及消息记录等使用数据，据此可精准优化智能体以更好满足需求。

### 5.1.3　使用扣子搭建智能体工作流
工作流由一系列可执行指令组成，用来实现业务逻辑或完成特定任务，为应用与智能体提供数据流转和任务处理的结构化框架。其核心是将大模型能力与特定业务逻辑结合，通过流程化方式提升 AI 应用开发效率。

扣子提供可视化画布，支持拖拽节点快速搭建流程，也可在画布中实时调试，清晰呈现数据流向与任务执行顺序。

#### 1．工作流与对话流
扣子提供两类工作流。

（1） **工作流** （workflow）：处理功能型请求，通过顺序执行任务实现特定功能，适用于数据自动化处理，如行业调研报告生成、海报制作、绘本创作等。

（2） **对话流** （chatflow）：面向对话场景的特化工作流，擅长处理对话请求，通过交互实现复杂业务逻辑，适用于聊天机器人、个人助手、智能客服、虚拟伴侣等对话式应用。

#### 2．节点
工作流核心是节点，每个节点都是具备特定功能的独立组件，代表一个步骤或逻辑，负责处理数据、执行任务、运行算法，并拥有输入输出。

每个工作流默认含开始节点与结束节点。开始节点定义启动所需输入参数，结束节点返回运行结果。

可通过引用节点输出把节点串联成完整链路。例如代码节点可引用大模型节点的输出作为输入，画布中可清晰看到两者连接，如图 5-5 所示。
