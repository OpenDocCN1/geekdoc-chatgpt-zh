## 7.12 渐进式落地策略

> “讲到这里，”小冰问道，“若团队想把无头模式用于 PR 评审，该怎样逐步推进？”

咖哥建议走四阶段渐进路线。

阶段一：观察者。Claude 仅做只读分析，产出评审报告以评论形式挂在 PR 上，不干扰任何合并流程。本阶段目标是建立信任，让团队直观感受评审质量，同时识别局限比如误报情形，据此迭代提示词与参数。

阶段二：顾问。在积累足够正向反馈后，把评审结果接入持续集成状态监控。发现 Critical 级问题时 CI 标记为黄色警告但不阻断合并，最终裁决仍由人工评审结合报告完成。本阶段核心是人机协同。

阶段三：门禁。评审成为代码合并的必要条件，一旦检出严重安全问题 CI 随即变红并阻断合并。此阶段必须配套逃生通道，允许有权限的人员手动覆盖阻断，类似跳过不稳定测试。

阶段四：主动修复。Claude 不止于发现问题，还能自动修正格式错误、补齐异常处理或生成单元测试。需要开放 Write 工具权限，但所有变更须以新 Commit 提交，严禁直接修改 PR 作者的原始代码。

“切忌一步到位，”咖哥强调，“每个阶段建议运行 2 到 4 周，持续跟踪误报率、成本走势及团队接受度。AI 辅助评审的意义不在完美替代人工，而在帮助人类评审把有限精力集中到最具价值的决策上。”

## 本章小结

无头模式让 Claude Code 从终端交互的智能助手，演进为可嵌入各式工程流程的可编程组件。这一转变由四类参数定义。

- -p 入口：把运行方式由交互式会话切换为非交互式执行，奠定自动化基础。
- --output-format 数据接口：规范输出结构，便于下游系统高效解析与调用。
- --allowedTools 安全边界：严格限定工具权限，保证自动化环境合规可控。
- --max-turns 与 --max-budget-usd 成本护栏：限制执行轮次与预算上限，避免无人值守时的资源失控。

在架构层面，无头模式的最大价值是让 Claude Code 成为 CI/CD 生态的平等成员。如同单元测试、静态分析或镜像构建，AI 代码评审正式进入流水线标准环节：需要明确的输入定义、确定性的输出格式、可量化的成本预算，以及可纳入版本控制的配置文件。

落地建议从观察者起步，逐步演进到门禁。渐进过程为团队预留信任建立、数据积累与配置优化的时间，不可急于求成。AI 辅助评审的核心并非追求对人工的完美替代，而是通过智能过滤，让评审员聚焦最关键的决策点。

第 8 章将从命令行参数转向编程接口智能体 SDK。你将学会用 TypeScript 或 Python 代码替代繁琐 CLI 参数，灵活掌控 Claude 行为，构建真正定制化、深度集成的 AI 应用系统。

## 8.1 Agent SDK 的定位：从工具到组件

此前介绍的 CLAUDE.md、子智能体、Skills、Hooks、MCP 以及无头模式，均以“使用 Claude Code”为视角。开发者作为使用者，在既定框架内通过配置扩展行为。

Agent SDK 的出发点不同。它预设开发者是应用构建者，目标是将 Claude Code 核心能力深度嵌入自有应用。何时启动、传递何种参数、如何编排中间步骤、如何管理多轮对话状态，全部由代码自主掌控。这时你不是在使用现成产品，而是在构建以 Claude 为智能引擎的新应用。
