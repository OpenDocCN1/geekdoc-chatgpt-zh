算子到底指什么？要分两层来看。

狭义上，Kernel 就是张量层面最基础的操作集合，覆盖四则运算、数学函数，以及对元数据本身的改动，比如 Squeeze 压缩维度、Reshape 调整形状这类操作。

广义上，Function 是 AI 框架里对算子的完整封装，里面串起了调度、Kernel 执行、自动求导以及代码自动生成等模块。

在神经网络的语境里，算子就是模型里会用到的计算单元。PyTorch 中的体现就是层里的计算逻辑，卷积层的卷积计算算一个算子，全连接层的加权求和也算一个算子。

#### 2. 系统落地时的关键痛点
Kernel 真正跑起来会碰到不少问题：
- 硬件加速：GEMM 是视觉和 NLP 模型的主力计算，NPU、GPU 以及 TPU 的脉动阵列等专用 ASIC 的底层是否都以矩阵乘为支撑？这是 AI 硬件与体系结构要回答的问题。
- 片上存储：输入、权重、输出张量能否完全塞进 NPU/GPU 的 L1、L2 缓存？放不下就得靠循环分块 Loop Tile 来做切片优化。
- 局部性：循环里的核心语句能否利用局部性？包括空间局部性，缓存线内相邻数据是否连续访问，和时间局部性，同一块内存多久后会再次被用。预估后可通过编译调度来优化。
- 内存管理与扩展：工程师会提前算好每层的输出、输入、核张量的大小，据此评估算力需求、设计内存管理与换入换出策略。
- 运行时调度：算子按顺序执行时，框架如何做运行时管理？
- 算法变换：多层循环效率不高，能否转成更利于优化的矩阵计算？
- 编程方式：怎样的编程范式能让模型开发更快，降低算法工程师负担，让他们更专注创新？

### 1.4.3 从代码到芯片的执行链路
现在算法工程师或应用开发者只需用框架提供的 API，用 Python 等高级语言写网络算法，不用关心底层执行细节。抽象提升了效率，却也把细节藏了起来，需要系统工程师去深挖。

前面已经会用 Python 写 AI 程序，也明白像卷积这样的算子如何被翻译成 for 循环实际计算。这类循环通常被厂商提供的运行时库如 cuDNN、cuBLAS 抽象掉，不需要反复手写。

在编译与计算架构层，已经抽象到为 Kernel 执行提供的高级 API，这时仍会冒出几个疑问：
- 为什么还要 AI 框架，PyTorch、MindSpore 等存在的意义是什么？
- 框架在系统里承担什么角色、提供哪些能力？
- 用户写的 Python 代码如何最终翻译成硬件可执行的指令？

继续以 LeNet 为例讲解。如果没有框架，只暴露算子库的调用，比如 cuDNN，算法工程师只能用 CUDA+cuDNN 这类底层 API 写网络。系统从下往上是分层处理的，如图 1.4.2 所示。

- Python API 来描述网络计算图结构；
- 基础算子的调用封装，大幅减少代码量；
- 自动内存管理，隐藏指针与手动管理；
- 自动微分，自动构建反向传播图；
- 调用或生成运行时优化代码，调度算子在指定 NPU 上执行；
- 运行期并行算子，提升 NPU 利用率等动态优化。
