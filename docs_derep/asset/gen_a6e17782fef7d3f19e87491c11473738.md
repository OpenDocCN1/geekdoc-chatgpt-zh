ClawHub 技能中心命令行快速上手

ClawHub 技能注册表可以通过命令行客户端 clawhub CLI 来操作，定位和 npm 在 Node.js 生态中的角色类似，先单独装一次就可以长期使用。

# 安装 clawhub CLI

npm i -g clawhub

装好后必须先登录才有权限操作。去 clawhub.ai 注册账号 → 点右上角头像 → Settings 设置 → API tokens → Create token，把生成的 token 复制下来：

# 登录，粘贴你的 token

clawhub login --token ＜你的 token＞

# 检查登录状态

clawhub whoami

登录通过后，日常会用到的操作有：

# 查找技能

clawhub search [关键词]

# 拉取技能

clawhub install [技能名]

# 查看本地已装列表

clawhub list

# 批量更新

clawhub update --all

# 卸载技能

clawhub uninstall [技能名]

**小贴士**

技能安装完成后不需要重启 Gateway，能力立刻生效。装完可以试一句“我刚刚装了 XXX 技能，帮忙演示一下”，龙虾会自检新能力并给出使用示例。

**安全安装指南**

截至 2026 年 3 月 16 日，ClawHub 上架的技能已经超过 23 000 个，质量参差不齐。2026 年初发生的“ClawHavoc”事件里，341 个恶意技能被集中下架，这件事提醒我们随意装包风险很高。下面是一套可参考的安全流程。

**第一步：先验证，再安装**

# 查看技能详情，确认评分、作者、上线时间

clawhub info ＜技能名＞

# 也可打开 clawhub.ai 页面查看该技能的 VirusTotal 扫描结果

**第二步：遵循“1 000/3 原则”**

● 下载量要超过 1 000 次，说明有一定用户基数
● 上线时间超过 3 个月，经历过时间的检验，不是刚上线的黑箱
● 作者明确且提供源码链接，可追溯可审阅

**第三步：高风险类型要格外小心**

● 名称与知名技能只有一两个字母差别，例如“calwdhub”冒充“clawhub”，这是恶意伪装常见手法
● 权限要求很宽泛，例如访问全部文件、发起网络请求，但功能描述却很简单
● SKILL.md 为空、描述模糊或根本说不清它要做什么

## 4.4 记忆系统：让助手真正认识你

没有记忆，每次对话都要重新自我介绍“我是做什么的、喜欢什么风格、项目背景怎样”，很累。OpenClaw 的记忆分为两层：SOUL.md 负责性格，MEMORY.md 负责经历，两份文件配好后龙虾就记住你了。

**SOUL.md 性格是长期的**

SOUL.md 在第三章已初步配置，这里讲进阶用法：让它随使用动态调整。

使用一段时间后发现回复不合口味，比如太啰嗦、太保守、格式不对，不用重写文件，直接在对话里说：

**用户：**你最近回复太长了，我想要简洁，每次不超过 3 句话，除非我要求详细

[PRE6]

它会自动更新 SOUL.md，下次生效。这正是可进化的助手和固定参数工具的差别。

**MEMORY.md 经历是累积的**

MEMORY.md 是长期记忆档案，对话里产生的重要信息会自动沉淀：工作背景、项目细节、特殊偏好，下次打开依然记得。

典型内容结构：

## 用户信息

- 姓名：Alex，产品经理，做 SaaS 工具
- 时区：Asia/Shanghai，作息：晚 10 点后不回消息

## 项目背景

- 当前主项目：为客户做企业数字化转型
- 常用工具：Notion、飞书多维表格、Python

## 偏好记录

- 回复风格：直接，不要废话
- 报告格式：优先表格，其次列表
- 不喜欢：过度道歉和客套

## 经验教训

- 2026.03.09：搜索关键词加“最新”效果更好
- 2026.03.07：处理 Excel 时先确认列名避免歧义

你也可以主动喂养信息，如“记录这条内容”“用 write 工具帮我长期保存这条信息”。

[PRE7][PRE8]

**Self-Improving-Agent 让 AI 从错误中学习**

上一节推荐的 Self-Improving-Agent 安装后，记忆系统会多出错误经验库这一维度。

每次 AI 犯错或被你纠正，它会记录：出了什么问题、正确做法是什么、下次如何避免。这些记录会写入 MEMORY.md，形成踩坑经验，同类错误不再重复。你的龙虾真正地在成长。

## 4.5 会话管理：龙虾的短期记忆规则

长期记忆之外，还有更日常的一层——Session，会话，也就是短期记忆。

常见现象：聊久了变慢、今天说的话明天忘掉、飞书说过钉钉不知道。这些都与会话机制有关，弄明白它是用好 OpenClaw 的必修课。

**Session 是什么 对话的容器**

每次与 OpenClaw 的对话都被装进一个叫 Session 的盒子，里面包含当前对话内容、工具调用记录、token 消耗统计。

Session 与 MEMORY.md 的关键区别：Session 是临时的，会被清空；MEMORY.md 是永久的。形象点说，MEMORY.md 是写给龙虾的档案，Session 是今天的通话录音，档案常在，录音会被覆盖。

**Session 变慢怎么办**

用久了回复会变慢，因为历史越长处理成本越高。先 /compact 压缩，90% 情况立刻恢复。若话题已结束，直接 /new 更干脆。养成“一件事完成就处理 Session”的习惯，助手始终保持轻快。

**小贴士**

MEMORY.md 中有时效性强的记录，如已结束的项目，要定期清理。Session 靠 /compact 和 /new 维护，MEMORY.md 靠定期整理，两层分开效果最好。

**Session 常见问题**

**问题 1：为什么群里 @ 它，它不记得私聊说的话？**

群聊与私聊 Session 隔离，属隐私设计。如需在群里使用私聊背景，需在群里重新说明。

**问题 2：怎么彻底忘掉某段对话？**

发 /new 清空当前 Session。若要删除 MEMORY.md 内容，需手动编辑文件。注意 /new 不会清理 MEMORY.md。

**问题 3：定时任务执行完会记住内容吗？**

不会。定时任务每次都是全新 Session，不共享历史。如需跨任务保留，需写入 MEMORY.md。

**问题 4：凌晨 4 点自动重置能关掉吗？**

可在配置文件 ~/.openclaw/openclaw.json → session.resetAtHour 调整时间，或改为纯空闲重置模式。

## 4.6 定时任务：让它自动替你干活

主动找它只是入门，最爽的是你不用找，它自己执行。每天早报、每小时股价监控、周一自动周报，设一次就能一直跑。

**cron 定时任务 设置一次永久执行**

OpenClaw 定时任务基于标准 cron 语法，用 openclaw cron add 创建。

不懂 cron 也有两种捷径：网页端定时任务面板可视化设置，或直接用中文描述时间由 AI 转成表达式。

基本用法：

# 每天早上 8 点发送简报

openclaw cron add --name “早报” --cron "0 8 * * *" --message “发送今日简报，含天气、日程提醒和重点任务”

# 每小时整点检查服务器

openclaw cron add --name “服务器巡检” --cron "0 * * * *" --message “检查 CPU、内存、磁盘，有异常立即通知”

# 每周一早上 9 点生成周报

openclaw cron add --name “周报” --cron "0 9 * * 1" --message “根据上周任务完成情况生成周报，发到飞书”

# 每天下午 3 点健康提醒

openclaw cron add --name “健康提醒” --cron "0 15 * * *" --message “提醒喝水，站起来活动 10 分钟”

管理任务：

# 查看全部

openclaw cron list

# 暂停

openclaw cron disable “早报”

# 启用

openclaw cron enable “早报”

# 删除

openclaw cron remove “早报”

**推送到聊天工具**

结果默认在 Web UI 显示。如需推送到飞书，加上 --channel 参数：

# 推送到飞书

openclaw cron add --name “早报” --cron "0 8 * * *" --message “发送今日简报” --channel feishu

[PRE19]

**小贴士**

不会写 cron 没关系，直接告诉 AI 你想要的时间点，例如“每个工作日下午 6 点”“每隔两小时”“每月第一天早上 10 点”，它会生成正确表达式。

**主动推送与条件触发**

定时任务是时间触发，也可设置条件触发：

● 服务监控：每 5 分钟检查网站是否可访问，挂了立刻飞书告警
● 文件监控：监控 ~/Downloads，有新文件就通知文件名和大小
● 价格提醒：查询特斯拉股价，跌破 200 美元就推送
● 邮件摘要：每天上午 10 点总结收件邮件，按优先级排列
