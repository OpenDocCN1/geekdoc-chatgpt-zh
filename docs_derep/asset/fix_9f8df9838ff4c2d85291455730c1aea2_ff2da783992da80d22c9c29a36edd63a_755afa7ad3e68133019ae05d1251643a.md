#### 8.1.9 LangChain到LangGraph的平滑过渡
LangChain 自 2023 年起构建了活跃社区来定义大模型应用规范。目前已发布多个大版本，其体系中两大核心为 RAG 与 AI Agent。LangChain 中构建 AI Agent 的底层架构如图 8.12 所示。
[PRE13]

首先在 LangChain 框架内设计 AI Agent，内部划分为 Agent、Message 与 Toolkits 三个核心组件。每个 Agent 通常由大语言模型+提示+输出解析器构成，形成 Chain 处理用户输入。Agent 可处理的输入来自三方面：用户的原始输入 Input、模型对子任务的响应 Model Response、以及携带背景信息的 Context。Agent 的输出对接实际工具库，具体调用哪些工具由 Agent 拆解的子任务决定。大模型调用外部函数分为识别工具和实际执行两步。Messages→AI Agent→Toolkits 流程负责拆解子任务，并在工具库中匹配对应工具、提取工具名称及所需参数，可视作一种静态执行流程。把决策转化为实际行动的工作则交给 AgentExecutor。

总的来说，在 LangChain 的 AI Agent 实际架构中，Agent 的职责是接收输入并决定应执行的操作，但并不直接执行，执行由 AgentExecutor 完成。只有将 Agent 作为决策核心与负责操作执行的 AgentExecutor 结合使用，才能构成完整的 Agent。其中 AgentExecutor 负责调用 Agent 并执行其指定的工具，从而实现整个 Agent 的功能。

LangChain 仍是构建大语言模型应用的前沿框架之一。尤其在最新 v0.3 版本中，已基本完成从传统类向 LCEL 的过渡，为开发者带来的直接好处是定义和执行分步操作序列即链变得更简洁高效。专业地说，LangChain 构建的是一个有向无环图 DAG。随着 AI 应用尤其是 AI Agent 的发展，对大语言模型的使用正从单纯执行工具转向更复杂的推理引擎，这正是 LangGraph 诞生的根本原因。该转变带来了更多对循环结构和复杂条件交互的支持需求，使得基于 LCEL 的线性序列构建方式在实现更高级、更智能系统时逐渐显现局限性。
