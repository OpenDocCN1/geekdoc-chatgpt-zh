### 9.6.2 OutputParser

在与大模型协作并以其输出驱动应用时，输出格式不稳定是一个常见痛点。尤其在 LangChain 中搭建复杂链路时，对返回内容的稳定解析至关重要。如代码9-32 所示，CleanLLMOutputParser 就是为此定制的解析类，继承自 BaseOutputParser，用来处理输出污染，例如类型注解混入业务数据。

[PRE2]

工作方式大致如下：接收到模型原始文本后，文本里通常混合行动指令与输入信息，但常夹带干扰，比如 Union[str, Dict[str, Any]] 这类 Python 类型说明，对下游程序无意义，反而易导致解析失败。

解析器先按行拆分原文，抽取出行动标识与输入两段，再对输入段进行清洗，用 str.replace 去除不需要的类型注解字符串，保留可被识别为合法 JSON 的部分。清洗后调用 json.loads 尝试转为 Python 字典，供后续逻辑直接使用。若转换失败，例如格式仍不合规，就会抛出 ValueError，明确提示输入解析失败，便于排查修复。

这种针对性的文本清洗，使 LLM 输出在特定场景下更可靠，也提升了整套系统的健壮度与可用率。

实战：垂直领域大模型

从发展趋势看，垂直领域大模型的潜力或将超过通用大模型。原因在于：通用模型如 GPT-4 已形成难以突破的高壁垒；自研通用大模型的成本也远超多数企业承受能力。
