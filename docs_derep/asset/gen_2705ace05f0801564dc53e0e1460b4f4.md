10.2.5 DeepSeek R1-Zero 为什么跳过 SFT

业界常用的大模型训练路径是预训练、监督微调、基于人类反馈的强化学习，已成为构建大语言模型的基础范式。DeepSeek R1-Zero 在做推理模型时却跳过了 SFT，这点极具冲击力。

需要明确，预训练占据了绝大部分算力和语料开销。SFT 和 RLHF 的作用分别是让模型会对话、让输出更符合人类价值观。对于推理模型，长 CoT 数据难以人工构造且成本极高，直接用长 CoT 数据体进行训练是更现实的路线。

更关键的原因是，若先用普通语料做 SFT 再做强化学习，会出现收敛困难。具体来看，GRPO 与 PPO 中都带有如下正则项：

10.2.6 DeepSeek R1 为什么需要进行少量 Long-cot 数据的监督微调

DeepSeek R1 采用的是 GRPO，这是一种具备在线探索的强化学习算法，其收敛结果高度依赖起始点与优化目标的距离。优化目标是提升长 CoT 能力，若完全不做长 CoT 数据的 SFT，起点与目标相距太远。

因此用少量长 CoT 数据做 SFT，相当于先把模型拉到一个离目标较近的次优解，让后续强化学习更容易收敛。

另外，长 CoT 数据是人工标注的，能有效遏制 DeepSeek R1-Zero 出现的不可读、语言混乱问题。

10.3 DeepSeek VL2 的训练逻辑

DeepSeek VL2 的训练被拆成 3 个阶段，各阶段目标各异，最终得到强大的视觉-语言理解与生成能力。

10.3.1 初始阶段：视觉-语言对齐

目标：在视觉特征与语言特征间建立初步联系，让大语言模型能够初步理解视觉输入。

方法：使用图像-文本配对数据训练时冻结语言模型参数，只训练视觉编码器与视觉-语言适配器。适配器权重是随机初始化的，先训练它能找到更合适的映射。这一阶段强调视觉理解，仅在文本标记上计算下一标记预测损失。

结果：视觉编码器能把图像转为大语言模型可理解的视觉特征，完成初步对齐。

10.3.2 预训练阶段：多模态联合学习

目标：发展全面的联合视觉-语言能力，提升多模态理解。

方法：使用大规模图像-文本数据训练。解冻全部模型参数，包括视觉编码器、视觉-语言适配器等，进行端到端优化。训练规模约 8000 亿个图像-文本标记，覆盖各类视觉-语言任务。

结果：模型能理解图像与文本的复杂关联，并生成与图像内容相关的自然语言描述。

10.3.3 微调阶段：指令跟踪和对话能力增强

目标：强化指令跟踪与对话能力，让模型更好地理解并执行用户指令。

方法：使用内部视觉语言数据做监督微调。优化全部参数，仅对答案与特殊标记做监督，屏蔽系统与用户提示。多模态数据与纯文本对话数据混合，增强对话理解。

结果：模型能按指令给出更准确、更自然的回复，在表格/图表/文档/图形理解、视觉推理、语言理解等任务上表现突出。

分阶段使用不同数据与算力，实现 VL2 在各类视觉-语言任务上的优异表现。

第十一章 DeepSeek 的推理及优化

在大模型推理里，吞吐量与延迟决定系统可用性与商业可行性。DeepSeek V3/R1 通过大规模跨节点专家并行 EP、计算通信重叠优化、动态负载均衡三大核心手段，实现理论成本利润率 545% 的惊人效率，重新定义万亿参数模型的实时响应。

11.1 DeepSeek 推理阶段的报告原文

DeepSeek V3/R1 推理优化目标是提升吞吐量、降低延迟。方案核心是使用大规模跨节点专家并行 EP。一方面 EP 能把 Batch Size 大幅提高，提升 GPU 矩阵乘法效率，带来吞吐量增益；另一方面专家分散到不同 GPU，每个 GPU 只负责少量专家计算，访存压力下降，延迟降低。

使用 EP 也带来复杂性，主要有两点：

使用 EP 会引入跨节点传输，需要设计计算流程让传输与计算同步进行。
使用 EP 必然涉及数据并行 DP，不同 DP 间需要做负载均衡。

因此要解决如何用 EP 增大 Batch Size、如何压低传输耗时、如何做负载均衡。

1.大规模跨节点“专家”并行

DeepSeek V3/R1 专家数量极多，每层 256 个专家仅激活 8 个。模型高度稀疏，迫使必须采用很大的全局样本批次，才能为每个专家提供足够样本，实现更高吞吐更低延迟，需要大规模跨节点专家并行。

采用多机多卡专家并行策略：

Prefill：32 路路由专家并行、32 路 MLA 并行、共享专家 32 路数据并行。一个部署单元用 4 个节点，32 个冗余路由专家，每卡 9 个路由专家 + 1 个共享专家。
Decode：144 路路由专家并行、144 路 MLA 并行、共享专家 144 路数据并行。一个部署单元用 14 个节点，32 个冗余路由专家，每卡 2 个路由专家 + 1 个共享专家。

2.计算和通信重叠

多机多卡专家并行会带来较大通信开销，采用双 Batch 重叠来掩盖通信，提高整体吞吐。
