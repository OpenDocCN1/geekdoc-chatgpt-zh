### 4.4.3 如何管理与排查 Cron 任务

OpenClaw 用命令行就能完整操控定时任务：

# 列出所有定时任务
openclaw cron list

# 查看某个任务的详情和下次运行时间
openclaw cron show daily-morning-brief

# 立刻跑一次，不等计划时间
openclaw cron run daily-morning-brief

# 暂停/恢复任务
openclaw cron pause daily-morning-brief
openclaw cron resume daily-morning-brief

# 删除任务
openclaw cron remove daily-morning-brief

# 查最近运行历史
openclaw cron history daily-morning-brief --last 10

为了让定时任务更稳，OpenClaw 内置三层兜底：

• 自动重试。打开 retryOnError: true 后失败会自动再跑，最多 maxRetries 次，默认 3 次，重试间隔采用指数退避，避免频繁重试拖垮系统。
• 失败告警。配置 onError.notify，在耗尽重试后仍失败时，会把通知发到指定的会话，保证你能第一时间介入。
• 执行超时。通过 timeoutMs 给任务设上限，防止网络卡顿或模型响应慢导致无限挂起，保护资源。

参考配置：
{
  "id": "daily-morning-brief",
  "schedule": "0 7 * * 1-5",
  "agentId": "main",
  "message": "...",
  "timezone": "Asia/Shanghai",
  "timeoutMs": 120000,
  "retryOnError": true,
  "maxRetries": 2,
  "onError": {
    "notify": {
      "sessionKey": "agent:main:whatsapp:+8613800138000",
      "message": "⚠️ 晨报任务执行失败，请检查 Gateway 日志。"
    }
  }
}

排障时最常见的现象是任务触发了但 Agent 没按预期动。几个实操技巧：

• 直接手动触发并实时观察。用 openclaw cron run daily-morning-brief --watch，--watch 会实时打印 Agent 执行日志、工具调用和模型输出。
• 查会话历史。每次运行都会留下记录：openclaw sessions history cron:daily-morning-brief --last 5
• 在 message 里加调试指令。比如让 Agent 先输出一行步骤说明：[步骤 N]正在执行：...
Cron 任务会继承绑定 Agent 的工具权限。若要执行 Shell 备份等操作，必须保证该 Agent 的 tools.exec.security 不是 deny，且命令在白名单里。对于涉敏的定时任务，建议单独建一个低权限 Agent，只开放最小必要能力，避免用大权限通用 Agent。

### 4.5 配置体系与热更新实践

OpenClaw 的配置很灵活，从单文件到多文件分层都能用，而且大部分改动不用重启 Gateway 就能生效。

#### 4.5.1 配置文件分层与复用

主入口是 ~/.openclaw/openclaw.json，采用 JSON5 格式，支持注释，集中管理 Gateway、Agent、Channel、Tool 等顶层项。

配置变复杂时可以用 $include 把文件拆开，指令会递归合并外部内容：
{
  "gateway": {
    "$include": "./config/gateway.json"
  },
  "agents": {
    "defaults": {
      "$include": "./config/agent-defaults.json"
    },
    "list": {
      "$include": "./config/agents.json"
    }
  },
  "channels": {
    "$include": "./config/channels.json"
  }
}
注意：安全审计会检查 $include 的路径，若包含来自云盘同步等不可信目录的文件会发出警告。

配置文件还支持环境变量插值 ${ENV_VAR_NAME}，把密钥放到环境变量里，配置可以安全提交到 Git：
{
  "channels": {
    "telegram": {
      "token": "${TELEGRAM_BOT_TOKEN}"
    },
    "discord": {
      "token": "${DISCORD_BOT_TOKEN}"
    }
  }
}

#### 4.5.2 热更新能力一览

改完配置后很多项无需重启 Gateway 就能生效，大幅提升效率。支持热更新的类型如下表。

表 4-9 OpenClaw 支持热更新的配置类别及说明
配置类别	热更新支持	说明
Agent 工具策略（tools.*）	是	立即生效，下次 Agent Loop 启动时使用新策略
Agent 模型配置（model）	是	下次 Agent Loop 启动时使用新模型
Cron 任务（cron.jobs）	是	立即更新调度计划
渠道配置（channels.*）	部分	消息策略立即生效，账号连接需重启
Gateway 绑定（gateway.bind）	否	需要重启
Gateway 认证（gateway.auth）	是	立即生效
沙箱配置（sandbox.*）	是	下次沙箱创建时生效

热更新也可以用 CLI 触发：
# 不重启重载配置
openclaw config reload
# 只校验语法
openclaw config validate
# 查看当前生效配置
openclaw config show
# 局部打补丁
openclaw config patch --path "agents.defaults.model" --value "gpt-4.1"

Agent 自我配置是 OpenClaw 的特色功能。Agent 可调用 gateway 工具自行修改自身配置，例如收到“把模型切到 GPT-4.1 Mini 省 Token”的指令后，会自动执行 config.patch 把 agents.list[0].model 改成 gpt-4.1-mini，并反馈从下次对话开始生效。

但 gateway 工具权限很高，被列为高风险。若在会接收不可信内容的 Agent 上启用，就可能被恶意指令篡改配置，导致系统异常。所以在群组、外部渠道等场景建议明确禁止使用 gateway。

### 4.6 实战：从零搭一个生产级安全方案

#### 4.6.1 业务场景拆解

目标是一套能直接上生产的安全部署，覆盖三类场景并满足安全底线：

• 个人助理：用 WhatsApp 和 Telegram 交互，支持代码执行、文件读写，但所有操作严格限制在用户个人工作空间内。
• 社区机器人：在 Discord 服务社区问答，工具权限受限，所有操作在隔离沙箱执行，防止提示词注入。
• 自动化流程：Cron 实现每日晨报、每周代码审查等。
• 安全基线：Gateway 不直连公网，通过 Tailscale 安全访问；所有 API Key 全部走环境变量，不写明文。
