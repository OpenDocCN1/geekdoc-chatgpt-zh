# ReAct 工具代理的闭环拆解

这套实现把 ReAct 的思路做成了可执行的流程：先把步骤状态写回规划工具，再从计划文本里主动找下一个待办，最后由大模型在 think 与 act 两个阶段驱动工具调用，形成完整的思考-执行回路。

## 计划的读写与下一步定位

步骤完成后会通过 planning 工具的 mark_step 接口把状态改成 completed，参数里带上计划编号、步骤序号与新状态，成功时写 info 日志，出错则走 warning，保证异常不会打断整体流程。

找当前步骤的核心是 _get_current_step_index。没有激活的计划就直接返回空。拿到计划后先按行切分，定位出 Steps: 所在的行作为起点，之后从下一行开始逐行排查。碰到标记为 [ ] 或 [→] 的条目就视作未开始或进行中，立刻调用 planning 工具将其状态改为 in_progress 并返回该条目的相对索引。若整段都找不到可执行项则返回空，异常同样以 warning 记录并返回空。

生成首个计划时，会把外部请求封装成一条用户消息，要求模型为当前 active_plan_id 产出规划。消息写入记忆后调用 llm.ask_tool，系统提示和可用工具一起传入。响应回来后把助手消息写入记忆，遍历 tool_calls，一旦发现 planning 调用就立即执行并把工具返回结果以 tool_message 形式存回记忆，标记计划已创建。若全程未触发 planning 调用，则记录 warning 并写入一条提示 plan_id 缺失的错误助手消息。

class ToolCallAgent(ReActAgent):

    # 处理工具 / 函数调用的基础代理类，提供更高层的抽象

    name: str = "toolcall"

    description: str = "一个能够执行工具调用的代理。"

    system_prompt: str = SYSTEM_PROMPT

    next_step_prompt: str = NEXT_STEP_PROMPT

    available_tools: ToolCollection = ToolCollection(

        CreateChatCompletion(), Terminate())

    tool_choices: TOOL_CHOICE_TYPE = ToolChoice.AUTO  # 类型忽略

    special_tool_names: List[str] = Field(

        default_factory=lambda: [Terminate().name])

    tool_calls: List[ToolCall] = Field(default_factory=list)

    _current_base64_image: Optional[str] = None

    max_steps: int = 30

    max_observe: Optional[Union[int, bool]] = None

## 思考阶段 think

think 负责根据已有记忆判断是否需要调用工具。若配置了 next_step_prompt，会先把它追加到对话历史。随后向大模型发起带工具的请求，系统提示按需注入。

异常处理里单独捕捉 TokenLimitExceeded 引发的 RetryError，记录错误日志、向记忆写入超出 token 限制的提示并把代理状态置为 FINISHED。普通的 ValueError 直接抛出。

拿到响应后提取 tool_calls 与内容，输出思考摘要和本次选择的工具数量，若有工具调用还会打印工具名称与首个调用的参数。随后按 tool_choice 分支：NONE 模式下即使模型返回了工具调用也只警告，若有文本内容则写入记忆并返回 True；正常路径先把助手消息写入记忆，REQUIRED 模式下没有工具调用也返回 True 交给 act 处理，自动模式下没有工具调用但有内容时继续，否则根据是否有工具调用决定返回值。未预期异常会记录并写入错误助手消息后返回 False。

async def think(self) -> bool:

    # 处理当前状态并决定下一步是否使用工具

    if self.next_step_prompt:

        user_msg = Message.user_message(self.next_step_prompt)

        self.messages += [user_msg]

    try:

        # 获取带有工具选项的响应

        response = await self.llm.ask_tool(

            messages=self.messages,

            system_msgs=(

                [Message.system_message(self.system_prompt)]

                if self.system_prompt

                else None),

            tools=self.available_tools.to_params(),

            tool_choice=self.tool_choices,)

    except ValueError:

        raise

    except Exception as e:

        # 检查是否是 TokenLimitExceeded 的 RetryError

        if hasattr(e, "__cause__") and isinstance(e.__cause__, TokenLimitExceeded):

            token_limit_error = e.__cause__

            logger.error(

                f"🔒 Token 限制错误 (来自 RetryError): {token_limit_error}"

            )

            self.memory.add_message(

                Message.assistant_message(f"达到最大 token 限制，无法继续执行：{str(token_limit_error)}"))

            self.state = AgentState.FINISHED

            return False

        raise

    self.tool_calls = tool_calls = (

        response.tool_calls if response and response.tool_calls else [])

    content = response.content if response and response.content else ""

    # 记录响应信息

    logger.info(f"🧠 {self.name} 的思考: {content}")

    logger.info(f"🔧 {self.name} 选择了 {len(tool_calls) if tool_calls else 0} 个工具")

    if tool_calls:

        logger.info(f"🛠️ 正在准备工具: {[call.function.name for call in tool_calls]}")

        logger.info(f"📝 工具参数: {tool_calls[0].function.arguments}")

    try:

        if response is None:

            raise RuntimeError("未收到 LLM 的响应")

        # 处理不同的工具选择模式

        if self.tool_choices == ToolChoice.NONE:

            if tool_calls:

                logger.warning(

                    f"🤔 嗯, {self.name} 在没有工具的情况下尝试使用工具!")

            if content:

                self.memory.add_message(

                    Message.assistant_message(content))

                return True

            return False

        # 创建并添加助手消息

        assistant_msg = (

            Message.from_tool_calls(content=content,

                                    tool_calls=self.tool_calls)

            if self.tool_calls

            else Message.assistant_message(content))

        self.memory.add_message(assistant_msg)

        if self.tool_choices == ToolChoice.REQUIRED and not self.tool_calls:

            return True  # 将在 act() 中处理

        # 对于 'auto' 模式, 如果没有命令但有内容, 继续执行

        if self.tool_choices == ToolChoice.AUTO and not self.tool_calls:

            return bool(content)

        return bool(self.tool_calls)

    except Exception as e:

        logger.error(f"⚠️ 哎呀! {self.name} 的思考过程中出现了问题: {e}")

        self.memory.add_message(

            Message.assistant_message(

                f"处理过程中遇到错误: {str(e)}"))

        return False

## 执行阶段 act

act 负责把 think 阶段决定的调用真正跑起来。tool_calls 为空且模式为 REQUIRED 时抛出 TOOL_CALL_REQUIRED 错误。若没有工具调用，直接返回最近一条消息的内容或默认空提示。

有调用时逐个处理：每次先清空 _current_base64_image，再执行对应工具。若开启了 max_observe，则对返回结果做截断。执行完毕后记录日志，并把工具返回结果封装为 tool_message 写入记忆，完成一次调用-观测的闭环。
