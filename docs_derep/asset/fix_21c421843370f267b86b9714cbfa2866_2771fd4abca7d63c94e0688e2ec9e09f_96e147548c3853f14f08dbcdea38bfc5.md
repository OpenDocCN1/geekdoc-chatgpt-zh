**2.1 Agent 三要素：LLM、Prompt、Action**

复合型智能体是近年来大模型应用中最具代表性的架构之一，广泛用于搜索问答、任务助手、机器人流程自动化、代码生成、数据分析等复杂场景。尽管实现路径各有差异，本质都由三大关键要素驱动：LLM、Prompt、Action。三者共同构成感知、推理、行动的闭环，形成智能体能力的核心骨架。

**1．LLM：复合型智能体的“大脑”**

LLM 是智能体的核心推理中枢，基于海量语料训练而成，具备强大的自然语言理解与生成能力。它决定了智能体的智力上限，即能否理解复杂表述、做出合理判断、保持上下文记忆与推理，完全取决于所用模型的能力边界。

目前主流可用于智能体构建的大模型包括：

· OpenAI 的 GPT-4/GPT-3.5 系列，如 ChatGPT。
· Anthropic 的 Claude 系列。
· Google 的 Gemini 系列。
· 国内自研的 Qwen 通义千问、DeepSeek、Seed/Doubao 豆包系列。

在具体实现中，LLM 通常以 API 形式提供。智能体接收用户输入后，将其转为 Prompt 发送给 LLM，再由模型生成响应参与后续决策。后续章节会结合案例详细介绍 LLM API 的能力与用法。

**2．Prompt：驱动模型行为的语言接口**

Prompt 是智能体与 LLM 沟通的桥梁，决定模型如何理解输入、如何给出回应。它不仅是一段文本，更是控制模型行为的语言。提示词工程已成为构建强大智能体的核心技能之一。

日常使用中，Prompt 可以是直接的任务描述或自然语言提问，例如：

“请帮我生成一份周报的开头段落。”
“列出三种提高工作效率的方法。”

但在更复杂的场景中，仅靠简单提问难以获得稳定精准的输出。此时可通过特定技巧优化 Prompt，显著提升推理深度和任务完成效果。例如 Few-shot Prompting 的示例：

不难发现，通过精心设计 Prompt，可以把模型从一个泛化的“大脑”变成定制化的“智能助手”。无论是设定角色语气、拆解任务步骤，还是引导模型执行结构化任务，Prompt 都是控制智能体行为表现的关键工具。在实际开发中，Prompt 优化往往是提升智能体表现最直接最有效的手段之一，后续章节也将结合具体案例深入探讨不同场景下的提示词工程策略。

**3．Action：连接模型与真实世界的执行接口**

Action 是让模型从“说”走向“做”的关键机制。LLM 本身无法访问互联网、数据库或本地环境，其生成结果仅基于上下文预测。通过 Action，智能体可调用外部工具或函数，执行真正的任务操作，其工作流如图 2-2 所示。

图 2-2 Action 工作流

在具体实现中，智能体先将用户输入转为合适的 Prompt，通过调用 LLM API 获取模型响应，随后根据输出判断是否触发对应的 Action 来完成任务，这就是 Function Calling 技术。后续章节将结合实例深入讲解如何利用 Function Calling 实现模型与工具的灵活联动。

因此，一个真正可用的智能体需要 LLM、Prompt 和 Action 三者紧密协同：LLM 提供语言理解与决策能力，是智能体的核心引擎；Prompt 负责对输入进行结构化和语义引导，确保模型按预期完成任务；Action 则将模型的决策转化为具体操作，实现任务落地执行。三者相辅相成，共同构建从理解到推理再到执行的完整闭环，是打造高效可靠智能体的关键基础。

**2.2 LLM：以 DeepSeek API 为例**

目前，大多数大语言模型以云端托管服务形式提供，通过开放 API 向开发者提供推理能力，这类服务称为 LLM API。

OpenAI 率先推出此类服务，其 GPT-3.5 和 GPT-4 通过 chat/completions 端点实现交互对话，成为行业标准。受其影响，众多模型厂商采用了相似接口以简化接入和迁移。本节以 DeepSeek API 为例，系统讲解模型 API 的关键概念与实用技巧，包括：

· 基础 API 调用方式：如何构造请求、设置参数并处理响应。
· 流式 Streaming 请求机制：如何实现响应内容的实时处理与渲染。
· System Message 系统消息：如何通过系统指令设定模型角色、语气与行为边界。
· DeepThinking 深度思考标签：DeepSeek 首次推出的深度思考控制机制，用于体现推理过程。

通过这一部分的学习，读者将掌握调用云端大模型的核心方法，为后续构建 LLM 应用打下坚实基础，本章示例使用 Python 完成。

**2.2.1 基础调用**

在学习调用 DeepSeek API 之前，首先需要了解 API keys。API keys 是服务提供商生成的身份凭证，调用者在程序中通过请求头发送给服务器，用于身份鉴权和权限控制。除了验证身份外，API keys 还可用于监控调用次数和计费管理。开发者可登录 DeepSeek 官方开发平台，在“创建 API keys”页面生成专属密钥，如图 2-3 所示。

**2.2.2 请求参数**

在调用大模型接口过程中，请求参数的设置对模型响应的质量、随机性以及调用成本都有显著影响。OpenAI 接口提供了丰富参数控制能力，而 DeepSeek API 在此基础上保留并扩展了多个关键参数，供开发者根据实际需求灵活配置。

这些参数不仅可用来控制生成内容的风格与稳定性，比如设定回答是否更严谨或更具创意，还可用于控制 token 消耗、是否采用流式响应等性能与成本维度的优化。详细参数说明如表 2-4 所示。

值得一提的是，temperature 与 top_p 是两个常用于调控模型输出随机性与创造性的采样策略参数，它们在实际应用中往往被混淆，实则各有侧重：

· temperature 温度：作用于模型输出的概率分布本身。较高的值如 1.0 使输出更加多样且不确定；较低的值如 0.2 会趋向输出概率最高的 token，生成内容更确定但较保守。
· top_p 核采样：作用于模型输出的候选集合。它按概率累计对 token 进行裁剪，仅从累计概率不超过 top_p 的 token 中进行选择，能在一定程度上剔除长尾词，平衡多样性与合理性。
