#### 7.2.1 LCEL 核心概念速览
LCEL 即 LangChain Expression Language，属于一种声明式链式语言，用来把不同模块按流程串接，完成 RAG、Agent 等任务。

LangChain 里每个部件都是 LCEL 对象，由它们拼成的链同样是 LCEL 对象，因此可用统一调用方式运行自定义流、并行处理、降级或动态调整内部结构。模块总览见图7.2。

[PRE0]

LCEL 对象的特点：

- （1）契约一致：每个 LCEL 对象都实现了 Runnable 接口，拼接很顺畅。
- （2）独立开发：组件可单独编写测试，只要输入输出对齐就能接入链路。
- （3）灵活扩展：组件提供 invoke、batch、stream、ainvoke 等通用方法，适配不同场景。

Model I/O 层为对接外部大模型提供了标准接口。涵盖提示、模型本身和输出结果，通俗说就是把 Prompt 送入模型获取推理答案。

该层包含三部分：Format、Predict、Parse，见图7.3。

- Format：Prompt 模板，用结构化方式管理输入。
- Predict：模型调用，通过统一接口接入不同大模型。
- Parse：输出处理，从推理结果抽取信息并按预设格式规范。

[PRE1]

##### 1. Format
传统做法是手写 Prompt 配合 Few-Shot、CoT 等技巧提升推理。但工程化时 Prompt 不能固定，真实用户提问多样，固化模板会限制灵活性和覆盖面。例如天气查询，用户可能说“今天冷不冷”或“纽约明天温度”，模板只适配一种表达就难以通用，影响体验。

模板把 API 调用、问答流程等复杂逻辑封装成结构化格式。准备好外部函数说明和用户问题，就能自动生成定制 Prompt，引导模型按既定步骤思考并完成函数调用，示例如下。

[PRE2]

因此引入模板可支持变量与动态内容，同一应用能根据不同输入实时调整提示，更贴合用户需求，提升通用性和体验。

##### 2. Predict
Predict 负责模型从接收输入到完成推理的全过程。按模型类型分 Base 类和 Chat 类，LangChain 在 Model I/O 中归为 LLM 与 Chat Model。以 OpenAI 的 Completion 与 Chat Completions 为例。

[PRE3]

LLM 提供基于 Prompt 的文本生成，属于简化版功能。Chat Model 抽象聊天接口，需保留历史对话记忆，交互更接近自然会话。

##### 3. Parse
大模型输出格式不稳定，同一 Prompt 可能得到不同表达。纯对话影响不大，但在工程链路中，后续步骤常依赖模型输出作为输入，必须做标准化以保证流程顺畅。

输出解析器用于结构化模型响应，可按格式指令解析，也支持更深层抽取。

总的来看，Model I/O 一方面让开发者快速接入 OpenAI、ChatGLM、Qwen 等模型并按规范推理，另一方面通过输入输出模板化更符合工程实践。接下来介绍如何在 LangChain 中使用这三部分。
