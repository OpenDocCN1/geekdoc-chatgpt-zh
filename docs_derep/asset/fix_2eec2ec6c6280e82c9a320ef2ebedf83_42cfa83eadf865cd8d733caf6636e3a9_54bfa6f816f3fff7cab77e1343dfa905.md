多入口打通：让智能执行贴进日常工作

把智能执行能力沉进日常运营，是 OpenClaw 在企业侧的核心思路。要做到这一点，需要把入口铺开。把 DingTalk、飞书、企微、Telegram 等常用工具打通后，团队可在熟悉的工作台直接调用平台能力与插件，实现随时响应、协同完成。打通的本质是把数据与权限两条通道串起来，保证跨平台联动稳定、信息一致、授权可控，并把集成流程固化为可复制的操作模板，让技术储备不同的团队都能快速上线。

本篇围绕主流入口的对接思路、配置要点、实操细节与优化建议展开，帮助 OpenClaw 真正沉入日常办公，发挥全流程智能执行的价值。

钉钉连通

钉钉是国内企业协作的主阵地。深度联动后，智能作业可直接进入办公流。员工借助客户端或小程序即可触发文档处理、数据汇总、任务派发，无需切换系统。

整体可拆为准备、填参、授权、上线、验证调优。准备阶段企业需持有钉钉企业号并能操作开放平台，系统保持最新并开启钉钉支持，注册应用后拿到 AppKey 与 AppSecret。填参阶段进入后台渠道管理选钉钉，录入密钥并设定对接地址与回调地址，保存即完成基础连通。授权阶段在开放平台为应用开通消息推送、用户信息读取、审批等权限。发布阶段将钉钉小程序提交开放平台审核通过，员工在客户端搜索添加后即可使用。验证阶段组织员工通过小程序调用插件，检查互通、稳定与响应，按反馈微调。

配置要点：钉钉账号实名且具备应用注册权限；系统版本需支持并建议更新；网络可达钉钉开放平台与系统；按组织架构分配访问与功能权限，防止滥用。

典型场景：日常协同、任务分发跟进、数据统计上报、文档共享。比如一家区域分销商接入后，员工通过小程序调用统计插件完成日销售汇总并同步至群组与管理后台，管理者通过小程序派单，反馈自动回写钉钉，形成闭环。

飞书连通

飞书由字节推出，在文档与任务管理上表现突出。打通后智能作业与办公场景融合，适配在线业务与科技团队的协作习惯，员工可在客户端或应用内直接使用核心能力。

流程分为准备、配置、授权、部署、测试调优。准备阶段企业需有飞书企业号，登录开放平台注册第三方应用获取 AppID 与 AppSecret，同时保持系统最新。配置阶段在渠道管理选飞书，填入 AppID 与 AppSecret，设定对接地址、回调地址与权限范围。授权阶段在开放平台为应用授予用户信息读取、消息推送、文档操作等权限。部署阶段把飞书应用提交审核发布，员工添加后即可使用。测试阶段通过应用调用插件执行任务，检查互通、稳定与响应，优化配置。

配置要点：飞书账号完成企业认证且可注册第三方应用；系统需支持并建议更新；网络可达开放平台与系统；做好用户、任务、文档的实时同步，按组织分配应用访问权限，实现分级管控。

典型场景：协同办公、项目管理、文档协作、数据分析。譬如一家在线平台公司接入后，员工在飞书内调用文案生成插件产出推广文案并写入飞书文档供团队迭代；项目经理调用项目管理插件查看进度并派单，同步到飞书任务模块，实现全流程管控。

企微连通

企微是腾讯系企业通讯办公平台，在中小型公司普及度高。接入后通讯与智能作业无缝衔接，员工通过客户端或小程序即可完成业务，降低使用门槛。

流程分为准备、参数配置、权限配置、小程序上线、测试优化。准备阶段企业需持有企微账号，登录开放平台注册应用获取 CorpID、AgentID、Secret，系统版本需支持。参数配置阶段在后台渠道管理选企微，填入 CorpID、AgentID、Secret，配置对接与回调地址。权限配置阶段在开放平台为应用设置用户信息获取、消息推送、客户管理等权限。发布阶段将企微小程序提交审核，管理员放入应用列表供员工使用。测试阶段组织员工通过小程序调用插件，验证互通、稳定与响应，按需调优。

配置要点：企微账号已认证且可注册应用；系统支持对应接入；网络可访问开放平台与系统；对客户信息严格管控，仅获取业务所需数据；按岗位分配小程序访问权限，确保合规。

典型场景：日常办公、客户管理、任务执行、数据统计。比如一家零售小店接入后，员工在小程序中调用客户管理插件查看跟进记录并同步至客户模块；调用统计插件完成日销汇总并推送给管理员，减少手工上报。

Telegram 连通

Telegram 是全球主流通讯工具，适合跨国与海外业务团队。结合后海外办公场景可直接使用智能作业能力，实现跨区协同。

流程分为准备、参数配置、机器人授权、功能测试、优化推广。准备阶段企业需有 Telegram 账号，创建机器人获取 Token 与会话 ID，系统保持支持版本，网络可达 Telegram，如受限可配代理。参数配置阶段在后台渠道管理选 Telegram，填入机器人 Token 与会话 ID，设置消息接收地址与回调参数。授权阶段在 Telegram 侧设置消息接收、指令执行等权限。测试阶段通过客户端向机器人发送指令如生成销售报告、统计数据，验证能否正确调用完成任务。优化阶段依据测试结果优化响应速度与指令适配，并将机器人推广给海外员工并提供使用指导。

配置要点：网络稳定访问 Telegram；系统支持接入；Token 与会话 ID 需安全保管，避免泄露，仅限员工使用；可按海外需求优化多语言指令，提升体验。

典型场景：跨区协同、海外业务执行、多语言处理、远程办公。比如一家跨国制造商接入后，海外分支通过机器人调用生产数据统计插件并将结果同步总部；调用多语言翻译插件处理海外客户需求，提升适配度。

多渠道优化建议

接入完成后，优先推广员工高频使用的渠道以提升采纳率；定期巡检各渠道运行状态，及时修复同步异常或卡顿；依据组织架构与岗位授予差异化访问与功能权限，保障合规；随业务演进逐步扩展接入渠道，让智能作业真正渗透到日常工作的每个环节。

### **4.1 Skill 标准化开发：SKILL.md 官方规范**
Skill 是 OpenClaw 执行业务任务的核心载体，数据统计、文案生成到跨系统协同本质上都是 Skill 的组合。标准化开发是解决各自为战、接口混乱、难复用、难协同的关键，没有统一规范就会出现参数不一致、逻辑冲突、异常处理缺失，导致无法接入、无法协同、重复建设。

官方唯一认可的格式为 SKILL.md，采用 YAML 前置元数据加 Markdown 正文，不支持独立的 YAML/JSON 接口文件，所有 Skill 必须遵循该规范以便 Agent Runtime、Gateway、ClawHub 正确解析与调度。统一标准让 Skill 具备可复用、可扩展、可协同、可维护的特性，为工程化落地奠定基础。

[PRE1]
所有 Skill 必须包含六大核心模块，统一在 SKILL.md 中定义：
1. 技能基础信息，用于标识属性便于系统识别与调用；
2. 输入定义，明确所需数据、类型、必填项与示例；
3. 输出定义，定义结果结构与示例；
4. 执行步骤，用自然语言描述流程指导 Agent；
5. 异常与容错，声明可能异常及处理策略；
6. 依赖与权限，声明依赖 Skill、工具、网络与系统权限。

**4.1.1 SKILL.md 格式规范**
[PRE2]
SKILL.md 作为 Skill 的唯一入口，结构固定为前置元数据区负责声明信息，不可省略或格式错误；Markdown 正文负责执行逻辑、步骤、输入输出示例，必须使用自然语言。Agent Runtime 自动解析执行，Skill 本身不含代码。

**4.1.2 输入/输出/执行逻辑的官方规范**
输入输出在 Markdown 里以示例形式定义，无独立 JSON Schema；执行逻辑为纯自然语言步骤，不写代码也不写判断语句；异常处理仅声明策略如重试、回退、告警、终止，错误码与调度由 Runtime 统一管理；依赖配置在 Markdown 里声明依赖 Skill 名称，由 ClawHub 自动解析安装。
