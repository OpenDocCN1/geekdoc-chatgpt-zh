### 4.4.3 Cron 任务的可视化运维

OpenClaw 提供了完整的一套命令行手段来管理定时作业：

# 列出所有 Cron 任务
openclaw cron list

# 查看特定任务的详情（包括下次执行时间）
openclaw cron show daily-morning-brief

# 手动触发一次 Cron 任务（不等待下次计划时间）
openclaw cron run daily-morning-brief

# 暂停/恢复 Cron 任务
openclaw cron pause daily-morning-brief
openclaw cron resume daily-morning-brief

# 删除 Cron 任务
openclaw cron remove daily-morning-brief

# 查看 Cron 任务的执行历史
openclaw cron history daily-morning-brief --last 10

运行过程中常会碰到网络超时、工具失效、Token 耗尽等问题，OpenClaw 内置了三层保障。

• 自动重试：开启 retryOnError: true 后任务失败会自动再试，最多 maxRetries 次，默认 3 次，重试间隔采用指数退避，避免高频重试加剧压力。
• 失败通知：配置 onError.notify，历经全部重试仍失败时，系统会向指定会话推送告警，确保能及时介入处理。
• 超时保护：通过 timeoutMs 设定单次运行的上限，防止因网络阻塞或模型迟滞导致任务挂起，保护系统资源。

配置示例：

{
  "id": "daily-morning-brief",
  "schedule": "0 7 * * 1-5",
  "agentId": "main",
  "message": "...",
  "timezone": "Asia/Shanghai",
  "timeoutMs": 120000,
  "retryOnError": true,
  "maxRetries": 2,
  "onError": {
    "notify": {
      "sessionKey": "agent:main:whatsapp:+8613800138000",
      "message": "⚠️ 晨报任务执行失败，请检查 Gateway 日志。"
    }
  }
}

排错时最典型的是作业已触发但 Agent 执行偏离预期。几个实用办法：

• 立刻手动跑并观察。用 openclaw cron run daily-morning-brief --watch，--watch 会实时输出 Agent 运行日志、工具调用及模型返回。
• 查阅会话历史。每次执行都会在对应会话留下记录：openclaw sessions history cron:daily-morning-brief --last 5
• 在任务消息里加入自检指令，例如要求 Agent 在每一步前先打印一行动作说明，格式如 [步骤 N] 正在执行：...

定时作业会继承所绑定 Agent 的工具授权。若需执行 Shell 备份等操作，要保证该 Agent 的 tools.exec.security 不是 deny 且命令在白名单中。对安全性要求高的定时作业，建议单独创建一个权限最小的专用 Agent，只开放必要能力，避免使用大权限的通用 Agent。

### 4.5 配置体系与热更新

OpenClaw 的配置既支持单文件，也支持多文件分层，并且大部分改动无需重启 Gateway 就能生效。

#### 4.5.1 配置文件的分层与复用

主入口为 ~/.openclaw/openclaw.json，采用 JSON5 格式，允许注释，统一收敛 Gateway、Agent、Channel、Tool 等顶层配置。

配置规模变大时可用 $include 进行拆分，指令会递归合并外部文件内容：

{
  "gateway": {
    "$include": "./config/gateway.json"
  },
  "agents": {
    "defaults": {
      "$include": "./config/agent-defaults.json"
    },
    "list": {
      "$include": "./config/agents.json"
    }
  },
  "channels": {
    "$include": "./config/channels.json"
  }
}

注意：安全审计会校验 $include 的目标路径，若引用自云盘同步等不可信目录会发出警告。

配置文件还支持环境变量插值 ${ENV_VAR_NAME}，把密钥放进环境变量，配置本身可以安全提交到 Git：

{
  "channels": {
    "telegram": {
      "token": "${TELEGRAM_BOT_TOKEN}"
    },
    "discord": {
      "token": "${DISCORD_BOT_TOKEN}"
    }
  }
}

#### 4.5.2 热更新机制

修改后多数配置无需重启 Gateway 即可生效，能显著提升调整效率。支持热更新的类型参见表 4-9。

表 4-9 OpenClaw 支持热更新的配置类别及说明
配置类别 热更新支持 说明
Agent 工具策略（tools.*） 是 立即生效，下次 Agent Loop 启动时使用新策略
Agent 模型配置（model） 是 下次 Agent Loop 启动时使用新模型
Cron 任务（cron.jobs） 是 立即更新调度计划
渠道配置（channels.*） 部分 消息策略立即生效，但账号连接需要重启
Gateway 绑定（gateway.bind） 否 需要重启
Gateway 认证（gateway.auth） 是 立即生效
沙箱配置（sandbox.*） 是 下次沙箱创建时生效

热更新也可以通过 CLI 触发：

# 重新加载配置文件（不重启 Gateway）
openclaw config reload

# 验证配置文件语法（不应用）
openclaw config validate

# 查看当前生效的配置
openclaw config show

# 通过 patch 更新特定配置项
openclaw config patch --path "agents.defaults.model" --value "gpt-4.1"

Agent 自我配置是 OpenClaw 的特色。Agent 可调用 gateway 工具自行修改自身配置，例如收到把模型切到 GPT-4.1 Mini 的指令后，会自动执行 config.patch 将 agents.list[0].model 改为 gpt-4.1-mini，并告知用户从下次对话开始生效。

但 gateway 工具权限极高，被列为高风险。若在接收不可信内容的环境中启用，可能被恶意指令篡改配置，导致系统异常。因此在群组、外部渠道等场景建议明确禁止使用 gateway。

### 4.6 实战：从零构建一个安全的生产级部署

#### 4.6.1 场景说明

本次案例目标是搭建一套可直接上线的 OpenClaw 生产部署，覆盖三大场景并满足安全底线：

• 个人助理：通过 WhatsApp 和 Telegram 交互，具备代码执行、文件读写能力，但所有操作严格限制在用户个人工作空间内。
• 社区机器人：在 Discord 为社区用户提供问答，工具权限受限，所有操作在隔离沙箱执行，防止提示词注入攻击。
• 自动化流程：Cron 实现每日晨报、每周代码审查等。
• 安全底线：Gateway 不直连公网，通过 Tailscale 安全访问；所有 API Keys 均走环境变量，不以明文写入配置。
