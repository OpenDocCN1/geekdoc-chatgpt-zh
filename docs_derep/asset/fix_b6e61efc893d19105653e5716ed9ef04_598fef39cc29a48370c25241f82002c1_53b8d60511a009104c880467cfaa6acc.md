预填和解码阶段的调度思路相仿，图 11-2 依旧是两路管道同时推进，目的在于把数据搬运的开销掩盖在计算里。单路的执行顺序为：先 ATTN-0，随后 ATTN-1，再 MoE 层的 Dispatch 通信，接着 MLP 中路由专家的计算，之后 MoE 层的 Combine 通信，最后 Shared 层的共享专家计算。

把 H100 的 132 个共享内存全部投入计算，时间线安排如下。

1）在 A 路进行 MoE 分发的同时，A 路的共享专家计算与 B 路的 ATTN-0 并行进行。
2）A 路继续完成路由专家的计算。
3）B 路的 Combine 通信尚未启动前，先完成 B 路的 ATTN-1。
4）B 路执行分发的同时，B 路的共享专家计算与 A 路的 ATTN-0 一同推进。
5）B 路接着完成路由专家的计算。
6）B 路进行 Combine 通信的同时，A 路的 ATTN-1 在执行。

**3.动态负载均衡**

大规模数据并行叠加专家并行后，单卡算力或带宽拖后腿就会成为全局瓶颈，其他卡空闲等待导致整体效率下降。必须让每张卡的计算与通信负载尽量均衡。

（1）预填阶段的均衡
●核心矛盾：不同数据并行实例的请求数、请求长度不一，导致 Core-attention 量和分发通信量不一致。
●优化方向：让各卡的 Core-attention  workload 相近，输入 Token 总量相近，分发通信量相近，避免长尾。

（2）解码阶段的均衡
●核心矛盾：不同实例的请求数、长度不同，Core-attention 量随 KV-cache 占用变化，分发通信量也随之变化。
●优化方向：各卡 KV-cache 占用趋同，Core-attention 负载均衡；请求数趋同，分发通信负载均衡。

（3）专家负载均衡器
●核心矛盾：MoE 模型存在天然热点专家，导致卡间专家计算不均。
●优化方向：单卡专家计算量趋同，等价于压低所有卡中分发通信量的峰值。

### **11.2 推理阶段的综合解读**

**1.采取 PD 分离技术**
PD 分离指把 Prefill 与 Decode 放在不同设备、不同策略上执行。Prefill 是计算密集，仅一次并行，需增大 BatchSize 保效率，一个 DeepSeek 部署单元的 Prefill 使用 4 个节点。Decode 是访存密集，需优先 I/O，BatchSize 需缩小，可采用高带宽低算力的设备，一个 Decode 单元共使用 14 个节点。

**2.“专家”并行推理**
大模型推理中 Decode 耗时占优。专家并行可降低单卡访存压力，同时提升每个专家并行处理的 Token 规模。

**3.张量并行数偏小**
训练经验显示张量并行的通信开销高于流水线、数据并行，TP<8 即可单卡完成。对 MoE 的单个专家 TP=1，因专家参数量大幅下降，单卡即可完成。

**4.设置“冗余专家”**
冗余专家即热点专家，目的在降低通信。极端情形：设备 A 的专家 a 负载 100%，所有 Token 都需发往 a，设备 B 有专家 b。某 Token 同时需 a 与 b 计算，则需发往 A、B。若把热点专家 a 复制到 B 作为冗余，该 Token 只需发往 A，减少一次搬运。

### **11.3 Prefill 阶段的推理设计及优化**

**1.硬件部署与并行策略**
●最小部署单元：4 个节点共 32 张 GPU，单节点 8 卡，支持 EP 与 DP 结合的多维计算。
●注意力计算层：采用 TP4、序列并行、DP8 分布式，小规模 TP 降低通信，序列并行优化长序列。
●MoE 层专家并行：EP32，每卡承载 8 个共享专家和 1 个冗余专家，共 32 个冗余专家动态分配，保证专家获得足够批大小。
●浅层优化：前 3 层密集 MLP 使用 TP1，进一步降低通信。

**2.路由机制设计**
●动态冗余路由：基于在线统计的 Token 处理量、GPU 利用率，每 10 分钟检测一次热点专家并复制冗余实例，通过节点内 GPU 间专家重排实现均衡。
●专家分配策略：每卡除 8 个共享专家外再托管 1 个冗余专家，用冗余覆盖热点，避免跨节点通信。
●全局路由探索：研究动态激活策略，如每卡托管 16 个共享专家每次只激活 9 个，结合 Prefill 计算余量实时优化路由。

**3.通信架构设计**
●分层通信协议：跨节点经 InfiniBand 传输 Token，节点内经 NVLink 低延迟转发，实现 MoE 层 All-to-all 高效执行。
●计算-通信重叠：并行处理两个微批次，将注意力计算与 MoE 分发/汇聚通信交错，隐藏延迟。
●量化通信优化：MoE 激活值以 FP8 传输，结合 IB 直连减少数据量，提升带宽利用率，需与训练量化兼容。

**4.冗余策略与容错机制**
●动态冗余调整：依据实时监控的专家负载如 Token 分配数、显存占用，每 10 分钟调整冗余专家集合并重排物理位置。
●容错设计：冗余专家覆盖热点模块，单 GPU 故障时可快速切换至备用专家，保障服务连续。
●内存优化：探索专家参数的 FP8 混合精度存储，权衡冗余专家的显存占用与精度。

**5.性能优化**
●通信瓶颈优化：跨节点 All-to-all 延迟占比高，可优化 IB 调度，引入 IBGDA 技术绕过 CPU，直接 GPU 内存交换数据。
●负载不均衡优化：动态路由易因专家热度差异产生长尾，可引入轻量贪心算法如 Top K 剪枝或预编译路由表，降低实时计算开销。
●内存带宽限制优化：微批次小时专家计算受显存带宽限制，可采用块稀疏矩阵乘法如 MegaBlocks 方案优化访问模式。

### **11.4 Decode 阶段的推理设计及优化**

**1.硬件部署与并行策略**
●最小部署单元：40 个节点共 320 张 GPU，单节点 8 卡，支持大规模并行。
●注意力计算层：TP4、序列并行、DP80 分布式部署，多维切分提升效率。
●MoE 专家并行：EP320，每卡独立托管 1 个专家，共 320 个，其中 64 卡固定托管 64 个冗余专家与共享专家，其余 256 卡动态分配领域专家。

**2.路由机制设计**
●强制路由规则：共享专家作为热点，在 Token 级路由时必选，其余专家从动态池选取。
●负载均衡：基于历史负载统计定期调整冗余专家组规模，因每卡仅承载 1 个专家，无需重排物理位置。
●动态冗余探索：研究全局最优路由算法，需与分发通信内核融合以减少调度开销，如通过稀疏化计算或硬件加速优化决策。

**3.通信架构设计**
●低延迟调度：经 IB 网络多对多直连传输，实现多对多通信，避免传统协议栈开销。
●IBGDA 技术增强：利用 NVIDIA IBGDA 绕过 CPU，直接 GPU 内存交换数据，降低端到端延迟并提升带宽利用率。
●计算-通信重叠：异步执行微批次的注意力计算与 MoE 层通信，隐藏延迟。

**4.冗余策略与容错机制**
●静态冗余配置：依据实时监控的专家负载如 Token 处理量、GPU 利用率，动态调整冗余专家数量，应对热点。
●专家动态激活：探索仅激活部分专家如每次推理在 16 个本地专家中激活 9 个的轻量化策略，优化内存访问模式如 FP8 混合精度存储。
●容错设计：冗余专家覆盖关键功能模块，确保单 GPU 故障时服务不中断。

**5.性能优化**
●内存优化：Decode 阶段 Token 批小通常≤256，专家计算受内存带宽而非算力限制，可采用稀疏存储或 FP8 量化降低内存占用。
●动态路由复杂度优化：全局最优路由需实时计算分配，可能引入额外延迟。可设计轻量贪心算法如 Top K 剪枝或预编译路由表，用局部最优替代全局最优，降低计算复杂度。
