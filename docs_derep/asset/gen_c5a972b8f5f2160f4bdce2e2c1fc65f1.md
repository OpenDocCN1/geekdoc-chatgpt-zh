# 重排技术怎么选：Cross-Encoder、ColBERT 与大模型重排

Cross-Encoder 的思想源头可追溯到 2018 年 Google 发布的 BERT。BERT 是一种双向 Transformer，初衷是通过海量无标注文本学习通用语言表征，并非专门为查询与文档的语义匹配或排序而设计。真正把预训练语言模型引入段落重排，是 Nogueira 等人在 2019 年论文《Passage Re-ranking with BERT》中首次提出来的。

工作方式很直接：把查询和检索到的候选文本块拼接起来，用特殊符号 [SEP] 隔开后一起喂入 BERT、RoBERTa 等预训练模型。借助 Transformer 的自注意力，查询的每个 token 都能与文本块的每个 token 充分交互，模型由此捕捉二者间的语义关联。最后取 CLS 向量接属于分类头，直接输出一个相关性得分，实现高精度的排序。实现流程可参考图 7-5。

在 RAG 实践里，Cross-Encoder 通常承担“二轮精排”的角色。第一轮用 Bi-Encoder 做快速召回，拿到一个粗排列表后，再把其中比如 Top-100 的候选交给 Cross-Encoder 做细排，最后返回 Top-10 左右最相关的片段。

> 上面说的 Bi-Encoder 检索，本质上就是一种基于密集向量的检索。模型出现前，学术界惯用两个神经网络，单个或成对地对查询和文档编码成固定长度向量，再靠余弦相似度或点积等相似度做匹配。

#### 7.1.3 ColBERT重排

ColBERT，全称 Contextualized Late Interaction over BERT，是斯坦福大学在 2020 年 SIGIR 提出的一种密集检索方法。核心创新点是“后期交互”。

与 Cross-Encoder 让查询和文档全量交互不同，ColBERT 先让查询和文本块各自独立编码得到表征，只在最后一层做 token 级别的交互。查询和文本块的每个 token 向量两两点积，再汇总成最终的相关性分数。

小冰：ColBERT 看起来和普通的余弦相似度没什么差别，我们为什么还要它？传统检索里不早就做过向量余弦比较了吗？

咖哥：表面像，但精细度完全不同。传统做法是把整个查询和整个文档压缩成一个向量再算余弦；ColBERT 保留了查询和文本块全部 token 的向量，通过逐 token 交互来判断相关性。这样能捕捉局部对齐，更细的语义匹配。

小冰：那它和 Cross-Encoder 到底差在哪？

咖哥：ColBERT 的编码是分离的，文本块可以提前编码好存起来，检索时只要做 token 级点积。Cross-Encoder 必须对每个查询-文档对做端到端联合推理，所有 token 全面交互。于是 ColBERT 在重排阶段效率更高，代价是存储开销变大，需要保存海量的 token 级表示。

表7-1展示了ColBERT与Cross-Encoder、RRF的对比。

表7-1 ColBERT与Cross-Encoder、RRF的对比

| 特性 | ColBERT | Cross-Encoder | RRF |
| :--- | :--- | :--- | :--- |
| 设计目标 | 高效密集检索+精细重排 | 深度语义匹配，用于精细重排 | 融合多模型结果的轻量级重排 |
| 语义交互 | token级别交互，捕捉细粒度语义 | 查询-文档全句交互，精确语义匹配 | 无语义交互，基于排名融合 |
| 计算成本 | 中等（查询与文档分离编码+点积） | 高（每个查询-文档都需要进行全模型推理） | 低（直接融合已有排名分数） |
| 适用场景 | 密集检索或Top-k文档重排 | Top-k文档精排 | 信号融合或轻量重排 |
| 上下文感知能力 | 强（基于token级别嵌入） | 非常强（全句语义建模） | 弱 |
| 适合大规模检索 | 是（支持预计算文档向量） | 否（计算成本过高） | 是 |

Cross-Encoder 因为查询与文档充分交互，效果通常更好，但每次都要重新推理，成本高。ColBERT 用后期交互可以预先算好并存储文档的向量表示，查询时只需算相似度，效率大幅提升。所以小规模、求极致精度的重排选 Cross-Encoder，大规模检索重排则更偏向 ColBERT。

#### 7.1.4 Cohere重排和Jina重排

小冰：咖哥，除了 RRF、Cross-Encoder、ColBERT 这三种重排，我还听说过 Cohere 重排和 Jina 重排，它们有什么区别？

咖哥：两者都是基于大模型的重排方案。先说 Cohere 重排。

Cohere 类似 OpenAI 的大模型服务商，推出的 Rerank API 面向企业级搜索。它依托自研的 Command 系列大模型，比如 Command R，利用大模型的语义理解能力，采用 Cross-Encoder 架构对候选文档做深度理解和精排。

正如前面讲的，Cross-Encoder 会把查询和文档拼接后联合编码，直接给出相关性分数，从而捕捉细粒度匹配。

因为是商业 API，用户无需自训模型，只需把 BM25 或向量搜索返回的 Top-100 等结果传给 Cohere 重排服务，就能拿到优化后的排序。即便没有领域训练数据，模型也能零样本适配不同排序任务。

Cohere 重排多语言支持，默认英语，如需汉语等语言要申请定制化模型。它还针对高并发低延迟做了优化，官方数据显示处理 100 个候选文档平均响应在 300ms 以下。
