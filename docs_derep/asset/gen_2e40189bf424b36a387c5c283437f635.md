## 第一篇  AI产品研发全流程解析

人工智能（AI）是一门跨学科、跨领域的前沿交叉学科，核心在于利用人工手段模拟、延伸并拓展人类智能，赋予机器智能特质。自诞生至今，AI硕果累累，应用版图持续扩展。本篇聚焦**需求管理、产品设计、开发平台应用**三大核心环节，带你拆解AI产品从0到1的研发全链路。

### 项目一  AI产品需求管理：从模糊认知到精准定义

#### 学习目标
- 洞悉AI产品需求的本质定义
- 掌握需求管理全生命周期流程
- 精通需求文档撰写规范与**5W2H分析法**
- 具备面向真实场景的需求文档交付能力

#### 项目背景
成功商业化的AI产品（如智能机器人、自动驾驶）均源于对现实痛点的精准捕获。本项目以**“新零售商品检测”**为实战主线，带你完整走一遍：需求定义 → 管理流程 → 文档落地，为后续产品设计夯实基础。

#### 知识储备

##### 1.1 需求的双维定义
“需求”在AI开发中极易模糊，需从**商业视角**与**技术视角**双维厘清：

| 维度 | 分层 | 核心内涵 | 自动驾驶案例 |
| :--- | :--- | :--- | :--- |
| **商业视角** | **业务需求** | 宏观层面：产品解决何种市场痛点 | 减少驾驶员操作负荷 |
| | **用户需求** | 用户视角：需完成的任务及方式 | 自动、安全抵达目的地 |
| | **系统需求** | 工程视角：功能拆解与落地逻辑 | 环境感知→路径规划→车辆控制 |
| **技术视角** (IEEE标准) | 统一定义 | 为满足用户/合同/标准要求，系统需具备的条件/能力的**文档化表述**。强调：**以用户为中心** + **显性化文档沉淀**。 | — |

##### 1.2 需求管理四步法：搭建“用户-开发”高效桥梁
目标：将用户模糊期望转化为开发者可执行的功能规格，保障产品价值与可行性。

1.  **需求获取** —— *广撒网，防遗漏*  
    来源：用户、企业、市场。手段四选一/组合用：
    - **用户访谈法**：面对面/远程（电话、微信）深度挖掘。
    - **问卷调查法**：互联网分发，量化统计，快速覆盖大样本。
    - **使用测试法**：实地观察真实操作行为，洞察隐性需求（难度高、价值高）。
    - **数据分析法**：海量日志挖掘偏好模式（如影视偏好画像）。

2.  **需求分析** —— *筛噪存真，寻找切入点*  
    继承传统方法论，核心是简化筛选，还原用户真实诉求。复杂场景下，唯有科学分析才能发现高价值切入点，避免“技术强却落不了地”。

3.  **需求表述** —— *可视化交付，三类文档分层达意*  
    ![需求文档层级](PRE2)  
    - **产品前景文档**（决策层读物）：聚焦业务需求，覆盖市场分析、盈利预测，精简无细节。
    - **用户需求文档**（交互设计依据）：聚焦用户需求，描绘理想交互路径与界面。
    - **产品规格说明文档**（研发蓝图）：聚焦系统需求，在用户需求基础上补充**非功能性指标**（性能、质量、外观等约束）。

4.  **需求验证** —— *双标准把关，保真实有效*  
    - **内容标准**：每条需求真实反映用户意图，集合完整一致。
    - **文档标准**：可读、可改。
    *交付前必经严格评审。*

##### 1.3 需求文档核心三要素：需求·目标·功能
虽无统一格式标准，但核心骨架不可或缺：

1.  **产品需求** —— *用 5W2H 七维拆解*  
    **5W**：Who(谁)、When(何时)、Where(何地)、Why(为何)、What(什么)  
    **2H**：How(怎么做)、How much(成本几何)  
    *逐项设问，若7个维度均能自洽，方案可行；否则存优化空间。*  
    | 维度 | 核心追问 |
    | :--- | :--- |
    | **Why** | 为何要解决？为何此时？为何此难点？ |
    | **What** | 必要条件？助力/阻力？核心挑战？ |
    | **Who** | 关键干系人？潜在解决者？ |
    | **When** | 问题发生/解决的时间窗口？ |
    | **Where** | 发生场域/覆盖范围？着力点位？ |
    | **How** | 发生频度/演变规律？工期预估？ |
    | **How much** | 关键指标？成本/销量预测？ |

2.  **产品目标** —— *一句话定调子*  
    格式：**“一种具备[核心特点]、适用于[应用场景]的产品，目标是完成[核心任务]。”**  
    为开发团队提供统一北极星指引。

3.  **产品功能** —— *铺路径，画蓝图*  
    格式：**“基于[目标]，先完成[步骤1]，再完成[步骤2]，最后完成[步骤3]，达成目标。”**  
    实战中常将产品拆解为子项目逐个描述，方法论通用。

##### 1.4 实战路径设计
结合“新零售商品检测”案例，三步落地：
1.  5W2H 全维度剖析需求
2.  提炼锁定产品目标
3.  梳理输出产品功能清单

**步骤一：5W2H 深度设问**

| 维度 | 实战追问与结论 |
| :--- | :--- |
| **Why (缘起)** | **核心痛点**：零售业争夺客户核心在于货架曝光率。商品缺货、错位、陈列不规范直接流失销售额 → **商品检测是破局关键。** |
| **What (对象)** | **定义**：通过技术手段识别货架商品信息（品类、陈列顺序、层数、场景），统计排面数量/占比，辅助陈列管理。模型能力随项目定制。 |
| **When (时机)** | **高频刚需**：市场需求瞬息万变，商家需持续优化陈列提升转化。检测需**常态化、规律化**执行，非一次性动作。 |
| **Where (场景)** | **全覆盖**：普通货架/货柜、无人货柜、智能结算台、地堆、堆箱、堆头、地龙等。支持基本信息识别、数量可视化、占地面积估算。 |
| **Who (主体)** | 零售商家运营/陈列管理团队、品牌方巡检人员、第三方审计机构。 |
| **How (路径)** | 图像采集→目标检测/识别→信息结构化→异常对比预警→生成整改报告。 |
| **How much (代价)** | 硬件部署成本（相机/边缘盒子）、模型训练迭代成本、人工复核成本 vs. 销售额提升/损耗降低收益。 |

**步骤二：锁定产品目标**  
> **一种基于计算机视觉、适用于多元零售终端场景的智能商品检测系统，目标是实现货架商品陈列合规性的自动化巡检、异常实时预警与数字化管理。**

**步骤三：梳理产品功能**  
> 基于上述目标，**先**完成多场景下的商品图像采集与预处理，**再**完成多SKU目标检测与关键属性（位置、层数、朝向）结构化识别，**最后**完成陈列规则引擎匹配、异常可视化报表生成及整改工单闭环，实现陈列管理数字化升级。
