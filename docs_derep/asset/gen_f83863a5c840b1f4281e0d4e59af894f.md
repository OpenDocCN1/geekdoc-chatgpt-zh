Prompt 也能像模型权重一样训练？DSPy 把提示工程自动化了

DSPy，全名 Declarative Self-improving Python，声明式自改进 Python，是把自适应策略思想贯彻最彻底的框架之一。它直击一个行业通病：手工写的 Prompt 极度脆弱，换个基座模型效果就断崖式下跌，甚至直接失效。

DSPy 给出的新思路是把 Prompt 当成可学习的权重来处理。使用者只需要声明一个评估目标，比如“数学题算对了没有”，框架里的 Teleprompter 优化器就会自动去搜寻最优的 Prompt 组合。具体会做什么：自动试探不同的少样本示例，自动生成或重写指令，系统性地组合多种 Prompt 元素并进行调优。最后在验证集上对所有候选配置打分，保留得分最高的组合。提示工程因此从人工试错，转向自动化、数据驱动和自适应优化。

### 7.4.4 自适应策略的演进轨迹与组合方式

工程实践里，自适应策略的演进大致是这样一条线：从需要人工干预的 A/B 测试，到基于自动化老虎机算法的动态决策，再到端到端的在线强化学习。架构师的核心意图是让系统从“被配置”变成“自我配置”，从而具备感知环境、自主决策和持续进化的能力。

### 1. 演化路径：从统计实验到强化学习

- A/B 测试，人工分流。人工设定流量比例，例如策略 A 占 50%，策略 B 占 50%，然后按周或按月出报表再手工改代码。结论出来前，系统长期运行次优方案，造成可避免的损耗。模式本质是静态离线，反馈滞后。

- 多臂老虎机，自动选优。引入 ε-Greedy 或 Thompson Sampling 等方法后，系统能根据实时奖励信号动态调整策略投放，自动把更多流量推向回报更高的选项。但它通常忽略用户上下文，对所有人一视同仁，只能产生平均处理效应，个性化不足。

- 上下文多臂老虎机，因人而异。把用户等级、问题复杂度、历史交互等上下文作为决策输入，实现个性化选择。例如，对新手用思维链提升可读性，对专家直接给答案提升效率。

- 在线强化学习，轨迹优化。这是 2025 年的主流趋势，DeepSeek-R1 与 OpenAI o1 都在用。关键突破是不再只优化单步，而是优化整段交互轨迹。在多轮对话或任务执行中，Agent 持续累积经验，通过最大化长期累积回报来调整策略。端到端的在线学习让系统真正做到越用越聪明，在真实交互中不断进化推理、规划和自适应能力。

### 2. 模式组合示例

自适应策略像决策的元层，可以动态优化任意下游模式的参数或行为。

- 自适应策略与工具编排模式的结合 = 智能工具选择。面对功能重叠的工具集如 Bing Search 与 Google Search，硬编码调度被可学习的概率模型取代，实现数据驱动调度。演进过程：起初 Agent 用 Thompson Sampling 之类的方法随机尝试不同工具收集经验；反馈循环阶段记录每次调用的延迟、相关性、用户显式或隐式反馈；成熟阶段 Agent 会归纳出上下文偏好，例如天气查询偏好响应快的工具，学术检索偏好准确率高的工具，并动态调整调用权重。

- 自适应策略与推理模式的结合 = 系统动态切换。该组合在推理成本与输出质量间做智能平衡，达成认知经济学的最优解，把算力精准投到最需要的地方。流程：策略网络先分析问题语义复杂度、意图清晰度等特征；简单问题如“你好，今天天气如何”触发 System 1 式快速低开销直接生成；复杂问题如“证明黎曼猜想”“对比 Transformer 与 Mamba”则激活 System 2 式高阶推理，调用思维树或思维链换取更高准确率与深度。

- 自适应策略与路由模式的结合 = 专家权重自我调优。在混合专家系统中实现绩效考核与优胜劣汰。流程：路由器把任务动态分发给多个专家 Agent，并行或串行执行；奖励模型对最终结果做端到端评估，产生质量信号如正确性、连贯性、用户满意度；学习器根据每个专家在任务中的实际贡献，例如反向归因或 Shapley 值估算，自动更新其被选中的概率权重。

借助自适应策略，Agent 架构正从机械设计走向有机生长。我们不再用繁琐的 if-else 穷举边缘情况，而是设计好奖励函数，让 Agent 在持续交互与博弈中自主探索、试错并演化出最优路径。

### 7.4.5 设计哲学：走向反脆弱

自适应策略让 Agent 具备纳西姆·塔勒布提出的反脆弱性。

传统确定性系统里，错误等于故障，遇到未覆盖边界就会崩溃。适应性系统里，错误不是故障，是燃料。

每一次用户拒绝，都在帮助模型更清晰地划定能力边界与意图对齐范围。每一次任务失败，都通过反馈信号修正策略分布，推动向更优决策演化。

引入强化学习后，Agent 从静态代码块变成活的有机体，不必被完美预设，只需被正确激励。架构师的职责也从“设计流程”转向“设计奖励”。

小结：决策能力如何进阶

至此，Agent 的行动模式已基本搭建完成。

- ReAct 模式：赋予类似手眼协调的微操能力，在感知与行动的闭环中应对不确定性。
- 规划—执行模式：赋予运筹帷幄的项目管理能力，通过分步规划与动态调整驾驭高复杂度任务。
- 工具编排模式：赋予善假于物的连接能力，突破模型局限，灵活调用外部工具与服务。
- 自适应策略模式：赋予自我进化的学习能力，在持续交互中优化决策，克服系统僵化。

当 Agent 能感知、记忆、推理并以明智自适应方式行动时，它已接近完整智能系统。但仍有一个致命弱点：它不仅会出错，还可能深信自己的错误，陷入自我强化的逻辑闭环，拒绝修正，甚至把偏见当真理。

为此需要更高阶的认知机制，让 Agent 能跳出系统看系统，对自身思维过程审视、评估与修正。这正是反思模式的核心使命：赋予元认知能力，不仅思考如何解决问题，还要追问思考方式是否合理、结论是否可靠、是否被偏见或错误前提误导。

# 第 8 章 反思模式

> “吾日三省吾身。”
> ——《论语·学而》
> 
> “君子博学而日参省乎己，则知明而行无过矣。”
> ——《荀子·劝学》

在 Agent 体系中，反思构成了智慧的第二层结构：感知让人看见世界，记忆连接时间，推理构建逻辑，行动付诸实施，反思则判断一切是否正确。

我们之所以能学习，并非因为不犯错，而是因为能意识到犯错并从中吸取教训加以改正。若 AI 要跨越算力与智能的鸿沟，就必须学会问自己：“我哪里错了？为什么错？下次如何改进？”

Agent 如何知道自己出错？答案可从人类自省寻找。人类自省依赖三种机制，表 8-1 给出了对应关系。

表 8-1 人类的自省机制与对应的 Agent 机制

| 人类的自省机制 | 对应的 Agent 机制 | 说明 |
| :--- | :--- | :--- |
| 预测误差监测 | 结果与预期不符，触发损失信号 | 神经科学中，由前扣带皮层检测偏差并启动反思过程 |
| 元认知评估 | 置信度评估与推理链回溯 | Agent 对自身输出的可靠性进行评估，并可回溯推理路径以识别潜在错误 |
| 情绪信号 | 负奖励、异常检测、用户反馈等外部信号 | 外部“惊讶”或负面反馈作为强化信号，促使 Agent 内化经验并触发内省机制 |

AI 的反思本质上是错误检测、原因分析和策略修正三者的工程化组合。由此形成 Agent 系统的意识回路：输出→检查→批判→改进→再输出→经验更新。

基于此逻辑，本章把反思能力拆解为三种模式。

- 自我修正模式 Self-Correction Pattern：“修事”。关注当下，作用对象是输出结果。核心机制是在返回用户前通过内部循环检测并修正错误，包括逻辑错误、代码错误，以确保输出质量。
- 反思记忆模式 Reflexion Pattern：“修脑”。关注下次，作用对象是情景记忆。核心机制是任务失败后生成语言形式的教训存入记忆，下次遇到相似任务时主动检索并作为 Prompt 指导决策。
- 元学习模式 Meta-Learning Pattern：“修法”。关注长远，作用对象是 System Prompt 或策略。核心机制是在观察大量任务后，若发现重复犯同一类错误，则主动优化 System Prompt 或调整工具调用、推理等底层策略，实现行为模式的根本改进。

自省始于不确定。Agent 的觉醒不源于信心，而源于怀疑。真正的智能不在于永远正确，而在于能质疑自己是否正确。

## 8.1 自我修正模式

> “通过语言进行反思与自我修正，是增强语言 Agent 长期决策能力的有效途径。”
> ——Reflexion 论文①

在出版行业，很少有作家能一次写出完美手稿。通常过程分三阶段：作家挥洒灵感快速产出初稿，代表发散性 System 1 思考；编辑冷静审阅指出逻辑漏洞、错别字或事实错误，代表收敛性 System 2 思考；作家根据批注修订，完成迭代优化。

自我修正模式把“作家”和“编辑”内化为同一个 Agent。Agent 不再是单次生成的机器，而是一个生成—评估—修正的闭环系统。在交付用户前，通过多轮迭代提升输出质量，借助模型自身批判能力或外部工具验证来识别并纠正幻觉、逻辑错误和代码漏洞。这是护栏机制最关键的发挥阶段。

在企业级 AI 系统中，护栏不是束缚，而是让模型在安全边界内更自由地发挥。可以概括为三点：一是界定能做什么，二是确保按规则执行，三是出错时及时拦截。越强大的 Agent 越需要更坚固智能的护栏。

护栏主要分为四种实施方式。

第一种，权限护栏 Capability/Permission Guardrail：模型只能执行被明确授权的操作。落地做法是为每个 Agent 配置权限表，调用工具前做白名单检查。

第二种，策略护栏 Policy Guardrail：必须严格遵守业务规范与合规要求。这更依赖规则工程而非 AI 技术。典型条款包括不得输出敏感数据，不得生成偏见或歧视内容，不得提供超出资质范围的建议如医疗诊断、法律意见，不得修改未授权数据，不得绕过 HITL 节点。落地做法包括输出前内容过滤、对高风险任务强制人工审核、在 Prompt 中内嵌明确规则如“你不得做……你必须做……”。

第三种，行为护栏 Runtime Guardrail：在出错时自动踩刹车，实现实时干预。落地做法包括沙箱执行，限制代码执行的 CPU、I/O、网络资源；安全监控实时检测异常行为，如输出长度突增、行为模式偏离、生成危险指令或连续多次失败。一旦判定跑偏，立即中断流程并触发回退机制，回退包括切换更可靠模型、转交人工或降级到保守执行路径。

第四种，审计护栏 Audit Guardrail：确保全程可追溯。落地做法包括记录完整推理链、记录 Agent 间交互内容及数据指令传递、记录每次外部 API 调用完整输入输出、记录失败根因及系统自动修复动作。
