语境治理与记忆构建是多智能体协作的底座。本章围绕记录压缩、语义召回、协同记忆与隐私保护展开，为搭建具备持续记忆能力的智能体系统提供可落地的思路。

### 5.3.1 对话历史的压缩与摘要技术

大语言模型的输入窗口本质上是智能体的短期工作记忆物理上限。虽然当前主流模型的窗口已拉到 128K 甚至更大，但在持续多轮的交互里，原始记录的词元消耗会迅速膨胀。研究也指出，随着输入变长，模型对中间位置信息的关注会衰减，形成所谓的中心衰减现象。因此，如何压缩历史记录成为工程化系统必备能力。

业界常见三种做法。最简单的是裁剪法，只保留最近 N 轮对话并丢弃更早内容，实现成本低但会损失关键上下文。提炼法则借助模型把整段历史浓缩成要点，保留核心信息的同时引入提炼质量风险，且需额外推理开销。混合法兼顾两者，既保留近期对话的完整文本，又维护一份历史提要，在信息完整度与词元效率之间取得折中。

图5-7 对比了三种压缩思路的工作方式。左侧展示原始对话随轮次增长带来的词元累积问题。裁剪法直接剔除旧轮对话，仅留最近 K 轮，操作简单但丢失历史。提炼法用压缩器把全量历史压成摘要，可实现约 10:1 的压缩比，但可能失真且需额外调用。混合法在右侧呈现，它维护灰底的历史摘要区与近期缓冲池，缓冲池溢出时触发渐进式提要。综合来看，混合法在保持近期信息完整的同时可实现约 80% 的压缩，适合生产环境。

### 5.3.2 向量数据库在Agent记忆中的应用

提要解决了短期背景的压力，但智能体仍需长期记忆来存储与检索历史知识。向量数据库把文本映射为高维向量，支持语义相似度检索，成为记忆系统的核心支柱。相比关键词匹配，向量检索能理解查询意图，召回真正相关的历史记录。

典型的向量记忆体系采用分层设计。工作记忆对应模型输入窗口，存放当次对话的即时信息。短期记忆借助内存缓存如 Redis 保存近期会话的关键状态，访问极快。长期记忆则用 Pinecone、Chroma、Qdrant 等向量库持久化对话记录、用户画像与领域知识，支持语义召回。三层架构在速度、容量与持久性之间做了权衡。

图5-8 展示了基于向量库的记忆架构。顶层是智能体核心模型，通过灰底的记忆管理器协调三层记忆访问。工作记忆延迟小于1毫秒。短期记忆用虚线框标出临时特性，延迟在1～5ms。长期记忆延迟10～50ms。下方还说明了向量库内部的 Embedding 向量、Metadata 元数据与 HNSW 索引，以及语义检索流程 查询→Embedding→相似度搜索→上下文注入 和存储流程 分块→Embedding→入库。

### 5.3.3 Agent间的共享记忆与知识同步

多智能体协作时，上下文与知识的共享不可避免。例如用户从售前咨询智能体转到下单智能体时，后者需要知道之前的咨询商品。共享记忆让智能体复用彼此积累的信息，避免重复提问，也支持知识协同。

共享记忆架构一般分三层。私有记忆层存放智能体专属的专业知识与配置，只有本智能体可访问。会话共享层保存当前会话的背景、意图、偏好与会话提要，同一会话内的所有智能体可读写。全局知识层存放跨会话的通用知识如产品库、FAQ、业务规则，所有智能体可读通常只读。分层既保证协同又做信息隔离。

图5-9 描绘了共享记忆的设计。顶部是各智能体及其灰底的私有记忆，智能体 N 用虚线框表示可扩展性。中间会话共享层包含用户背景、跨智能体会话提要与任务状态，同一会话智能体可读写。底部全局知识层用虚线框表示只读特性，包含产品知识库、FAQ 与业务规则。访问权限上，私有记忆仅自用，会<|start|>ation 共享层同会话读写，全局知识层全体只读。

[PRE6]

在设计共享记忆系统时，访问权限控制是需要重点考量的问题。

- 最小权限原则：Agent仅访问完成任务所需的最小记忆范围

- 写入审计：所有共享记忆的写入操作应记录操作者和时间戳

- 冲突处理：多Agent同时写入时需定义合并策略或加锁机制

- 数据分级：敏感信息与普通信息分开存储，设置不同访问级别

- 过期清理：会话级记忆应在会话结束后自动清理或归档

### 5.3.4 记忆遗忘机制与隐私保护

记忆系统不仅要会记住，也要会遗忘。遗忘既是性能优化的需要，防止记忆膨胀拖慢检索，也是合规要求，例如 GDPR 的“被遗忘权”。合理的遗忘策略要在系统有效性与隐私合规间取得平衡。

记忆生命周期包含创建、活跃、归档、删除四个阶段。创建时评估信息价值与隐私等级。活跃期记忆参与检索，并随访问频率与时间衰减调整优先级。归档期把长期冷数据迁移到低成本存储，保留索引但降低优先级。删除期按保留策略或用户请求彻底移除。

图5-10 呈现了完整生命周期。顶部的流程图显示创建进行价值评估与隐私分级，活跃支持频繁检索并更新优先级，归档用虚线框标出过渡性质，删除永久移除并保留审计记录。中部时间轴标注各阶段节点。下方左侧列出自动遗忘的触发条件：时间衰减、访问频率、容量阈值、业务规则。右侧用虚线框标出用户驱动的场景，包括 GDPR 被遗忘权、隐私偏好设置、数据更正、账户注销。底部展示三种实现方式：硬删除、软删除标记保留审计、匿名化脱敏后保留统计价值。
