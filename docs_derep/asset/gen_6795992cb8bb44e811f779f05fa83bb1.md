向量索引目前主要有这几种做法。

- 平铺索引：又叫扁平索引、线性索引或全量索引，核心思想是跳过降维、压缩、聚类等预处理，直接把全部向量摊在一个平面里保存，检索时用查询向量逐个和库里所有向量算距离，找出最像的那一批。
- 聚类索引：先用 k-means 之类的聚类算法把向量分到多个簇里，检索时先判断查询向量离哪个簇中心最近，再只在该簇内部做精细搜索。
- 量化索引：借助量化技术把向量做压缩存储，同时让检索时的计算量变小。
- 图结构索引：依托近邻图来组织向量，通过图上的跳转快速锁定相似向量。

向量数据库怎么选、索引参数怎么配，后面会再展开讲。

文本块的检索
检索，也就是相似度检索，是 RAG 体系里不可绕开的一环。它的任务是从海量的向量库里迅速挑出和用户问题最相关的信息，为后续的生成提供上下文支撑。

比如用户问“悟空的战斗工具是什么？”，系统会先用嵌入模型把这句自然语言转成一个高维向量，这个向量在语义空间里代表查询意图，再去和库里的文本向量做相似度匹配。图0-8 文本块的检索

在检索界面里可以调这几个关键参数。

- Top K：控制返回结果的数量，比如取相似度最高的 3 条。
- Similarity Threshold 相似度阈值：设定一个分数线，只有分数达到或超过这个值的结果才会被放出来。
- Minimum Word Count 最小词数：用长度门槛过滤掉过短或不完整的内容块。

系统在选定的向量库里对查询向量做相似度检索，返回语义最接近的文本块。这个过程依赖前面建好的向量索引结构，才能做到高效。

检索到的片段会按相似度分数排序，排序列表既可以在后台查看，也能直接呈现给用户。更常见的做法是把这些结果作为上下文喂给生成步骤，让大模型在它们的基础上优化答案。

生成模块最考验的是模型选择。想要高质量回答，OpenAI 的 GPT 系列和 Anthropic 的 Claude 系列是常见选择；追求灵活部署和开源免费，Llama 系列和 Qwen 系列更合适；面向中文场景，DeepSeek、Kimi、ChatGLM 这类中文模型响应更快，也支持本地高效运行。用户可以切换模型，对比它们在生成质量、响应速度和资源占用上的差异。

提示词也是调节生成效果的重要手段。可以要求模型用专业术语作答，也可以让它用通俗方式解释概念。温度 temperature 参数还能控制随机性：温度高创意更强，温度低结果更严谨精确。

咖哥：向量索引在 RAG 里是个核心概念。作动词时，指把经过嵌入处理的文档数据存起来的过程，目的就是支撑高效语义搜索。文档加载后会被切成若干文本块，每个块通过嵌入模型变成高维向量，和元数据如文档 ID、段落位置一起存进索引里 此时索引作名词。索引底层会用 HNSW、平铺索引等数据结构，实现快速近似最近邻 ANN 搜索。
