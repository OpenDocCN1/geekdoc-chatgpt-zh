### 5.1.4 扣子搭建生成式应用

生成式应用是指借助大模型能力开发的软件，可完成复杂任务、数据分析与决策，典型代表有智能搜索、智能翻译等。

#### 1．扣子能做哪些事

基于扣子制作的应用扩展性强，可绑定个性化界面，依托先进大模型形成独立解决方案。

这类应用的业务逻辑通常由工作流或对话流承载，内置节点库覆盖逻辑处理、知识写入检索、大模型服务、会话管理等，帮助开发者灵活编排自动化流程，构建多样化智能服务。

兼容性方面，可适配移动端与网页端主流框架，也能运行于多种终端。支持以 API 或 Chat SDK 形态嵌入现有产品，或发布为微信小程序、抖音小程序、投放到其他社交平台，甚至以 Web 页面形态对外开放。

#### 2．开发路径

扣子为具备复杂交互的生成式应用提供了一套高效路径，具体步骤如下。

（1） **新建项目** 。在扣子里新建一个生成式应用项目，创建完成后自动进入“扣子应用 IDE”，这是编排业务与配置的核心区。

（2） **编排逻辑** 。借助工作流编排核心逻辑，并通过变量、插件、知识库、数据库等与本地或云端数据交互。平台提供试运行机制，便于开发阶段调试。

（3） **搭建界面** 。提供丰富的组件与可视化编排面板，支持拖拽式构建，实现所见即所得。非专业开发者也能快速上手，组件支持数据与事件绑定，实现前后端联动。

（4） **预览测试** 。提供预览功能，可实时查看运行效果是否符合预期。

（5） **正式发布** 。完成开发与验证后，可将应用分发到各平台，供更广泛用户使用。

#### 3．开发环境

扣子提供在线集成开发环境“扣子应用 IDE”，支持可视化编排与调试，让开发更聚焦创意与业务。

## 5.2 本地智能体开发

本节以开源智能体平台 Dify 为例，说明如何基于 Dify 构建本地智能体与本地工作流。

### 5.2.1 Dify 概览

Dify 把后端即服务与大模型运维理念结合，帮助开发者快速搭建可生产部署的生成式应用，即使是无技术背景的人员也能参与应用定义与数据运营。

平台内置了构建大模型应用的关键技术栈，可兼容上百种模型，提供直观的提示词编排界面、高质量 RAG 引擎、稳定智能体框架、灵活工作流，并配备易用界面与 API，避免重复造轮子。

为何选用 Dify？

类 LangChain 的开发库像工具箱，Dify 更像脚手架，提供满足生产需求的完整方案，并经过精良工程设计与测试。

Dify 完全开源，由全职团队与社区共同维护。开发者可在任意模型上部署类似 Assistants API 与 GPT 的能力，保持灵活的同时拥有数据主权。

可将大模型接入现有业务，通过 RESTful API 解耦提示词与业务代码，并在管理后台追踪数据、成本与用量，持续优化效果。

作为企业级大模型底座，多家银行与大型互联网公司已将其部署为内部大模型网关，推动生成式 AI 在企业落地并实现集中监管。

普通爱好者也能通过 Dify 练习提示词工程与智能体，已有超 6 万开发者在此创建应用。不少团队基于 Dify 打造 MVP 获取投资，或通过 POC 赢得客户订单。

为解决自然语言意图识别难题，Chatflow 提供问题理解类节点，相较工作流增加对话历史、标注回复、Answer 节点等特性。

为处理复杂业务逻辑，工作流提供代码节点、IF/ELSE 节点、模板转换节点、迭代节点等，并支持定时与事件触发，便于构建自动化流程。

节点是流程的关键组成，通过连接不同功能节点实现操作序列。变量用于串联前后节点的输入输出，包含系统变量、环境变量、会话变量等。

Chatflow 支持多轮交互，常见路径为“指令→生成→讨论→再生→结束”。

工作流不支持多轮交互，常见路径为“指令→生成→结束”。

节点均可拖拽编排，支持串行与并行两种模式。

**串行模式** 要求节点按预设顺序依次执行，前一个节点完成后下一个才开始，有助于保证逻辑顺序。例如小说生成应用中，用户输入风格后，系统依次补全大纲再生成正文，保持风格一致。

**并行模式** 允许多个节点同时工作，前置节点可同时触发并行结构内的多个节点，提升效率。例如并行翻译流程中，源文本触发后多个节点同时进行多语言翻译，缩短处理时间。
