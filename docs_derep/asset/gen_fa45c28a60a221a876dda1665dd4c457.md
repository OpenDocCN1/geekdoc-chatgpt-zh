知识图谱的底层蓝图是由几套规范拼起来的。数据模型和逻辑结构决定了它怎么存储和表达，W3C 提出的 RDF 就是最典型的代表。类、属性、关系、词汇这些构成层由 Schema 与本体来规范。数据在硬盘上的具体长相则由交换语法决定，比如 Turtle、JSON 这类格式。实体的命名规则和唯一标识规范，则由实体命名及 ID 体系来统一。

从承载的知识粒度看，图谱大致可归为词、实体、关系、事件、术语体系、规则这几类。词级别的知识以词为核心，关注词与词之间的联系，WordNet、ConceptNet 等就是这个思路。实体级别的知识以具体事物为核心，不仅描绘实体间的关系，还要借助术语体系来定义实体。事件可以看成是多个要素组合而成的复合实体。

W3C 的 RDF 把三元组 Triple 作为基础数据单元，逻辑上由主语 Subject、谓词 Predicate、宾语 Object 组成。不同知识库在表述上可能各有差异，但抽象下来都离不开实体、实体的属性、实体之间的关系这三大要素。

## 3. 知识抽取
知识抽取的任务谱系包括概念抽取、实体识别、关系抽取、事件抽取、规则抽取。专家系统时代几乎全靠人工录入，规模很难做大。现在的图谱构建更多是先把已有结构化数据转成基础数据集，再用自动化抽取和补全技术从多源数据里扩充，最后靠众包来提升质量。

目前最主流的知识来源是结构化和文本数据。从结构化数据库里取数一般会用 D2R 系列工具，比如 Triplify、D2RServer、OpenLink、SparqlMap、Ontop 等。从非结构化文本里获取知识，核心就是实体识别和关系抽取。以关系抽取为例，常见的技术路线有基于特征模板的方法、基于核函数的监督学习、基于远程监督的方法，以及基于深度学习的监督或远程监督方法，比如简单 CNN、MP-CNN、MWK-CNN、PCNN、PCNN+Att、MIMLCNN 等。远程监督的核心思路是用大型语义库自动打标签，标签难免带噪声，但海量数据能在一定程度上抵消噪声影响。也有工作引入多任务学习把实体和关系联合抽取，最新的探索则借助强化学习减少人工标注并降低噪声。

## 4. 知识融合
构建图谱时常会从第三方知识库或已有结构化数据里引入信息。Linked Open Data 项目会定期发布整理好的语义数据，里面既有 DBpedia、Yago 这类通用库，也有 MusicBrainz、DrugBank 等垂直领域库。多个图谱合并或把外部关系库接入本体库时，要同时处理模式层和数据层两个问题。模式层是把新本体融入现有本体库并完成新旧本体的对齐；数据层则是实体指称、属性、关系、类别的融合，关键是如何避免实例和关系的冲突造成的冗余。

数据层的融合本质上是实体和关系元组的对齐，即实体匹配。因为同一个事物可能在不同库里有不同标识，需要合并处理。对新增的知识还要做验证和评估，保证一致性和准确性，常用做法是给新加入的知识赋予可信度值，按此过滤融合。实体对齐包含实体消歧和共指消解，前者判断同名实体是否指代不同事物，后者判断不同命名是否指向同一事物。消歧常采用聚类策略，核心在于如何衡量实体对象与指称项的相似度，常用手段有空间向量模型即词袋模型、语义模型、社会网络模型、百科知识模型、增量证据模型等。近年也出现用知识图谱嵌入进行对齐并结合人机协作提升效果的做法。

本体是在特定领域对 Schema、概念模型和公理进行定义，用来弥合词汇异构和语义歧义，让沟通达成共识。共识不是一次到位的，而是迭代修改的结果。所以本体对齐本质上也是模式演化的管理问题。常见的演化管理框架有 KAON、Conto-diff、OntoView 等。

## 5. 知识图谱补全与推理
补全方法大致分三类。第一类是基于本体推理，比如基于描述逻辑的推理，典型实现有 RDFox、Pellet、RACER、HermiT、TrOWL 等。这类推理主要作用于 TBox，即概念层，也能反补到实体层的关系。

第二类基于图结构和关系路径特征。比如 PRA 算法利用随机游走获取路径特征，SFE 算法关注子图结构，也有层次化随机游走的 PRA 改进版。它们的核心是提取两个实体间路径以及周边图结构特征，用随机游走降低抽取复杂度，再叠加线性学习模型做关系预测。这类方法对图结构和路径的丰富度依赖很大。

第三类是基于表示学习和图谱嵌入的链接预测，早期有翻译模型、组合模型、神经元模型等，基本只能做单步推理。更复杂的方案把随机游走引入向量空间，让路径、实体、关系在同一空间表示后再进行补全。

文本信息也能辅助补全。Jointly(w)、Jointly(z)、DKRL、TEKE、SSP 等方法先把文本中的实体与结构化图谱中的实体对齐，再用双方的语义信息共同预测或抽取关系。这类模型通常包含三元组解码器、文本解码器、联合解码器三部分。三元组解码器把图谱中的实体和关系映射到低维向量；文本解码器从语料中学习实体或词的向量；联合解码器则确保实体、关系、词的嵌入位于同一空间并融合两者信息。

## 6. 知识检索与知识分析
基于图谱的检索主要体现为语义检索和智能问答。传统搜索引擎靠网页超链接找网页，语义检索则是直接找事物，比如人物、机构、地点，这些事物可能分布在文本、图片、视频、音频、IoT 设备等各种载体里。图谱和语义技术提供了事物的分类、属性、关系描述，让搜索引擎可以直接对事物本身做索引和检索。

图谱和语义技术同样能增强数据分析与决策。Palantir 就借助本体融合和多源数据集成，通过图谱语义增强数据间的关联，让用户以图谱方式进行关联挖掘和分析。近年来描述性数据分析越来越受关注，它强调依赖数据的语义描述本身来做分析，先抽取语义、建立逻辑，再用逻辑推理方法如 Datalog 来实现分析，这与以深度神经网络等计算模型为主的计算性数据分析有所不同。

## 1.6 知识图谱的相关技术
知识图谱是典型的交叉学科，牵涉人工智能、数据库、自然语言处理、机器学习、分布式系统等。下面从数据库系统、智能问答、机器推理、推荐系统、区块链与去中心化等角度梳理进展。

GraphDB 实现了 RDF4J 框架的 SAIL 层，和 RDF4J API 无缝对接，可以直接用 RDF4J 的模型、解析器和查询引擎访问 GraphDB。其亮点是对 RDF 推理的支持好，内置基于规则的前向链推理机，能从显式知识推导出导出知识并优化存储，库更新后导出知识会同步更新。

Blazegraph 是基于 RDF 三元组库的图数据库，用户接口同时支持 RDF 三元组和属性图模型，既支持 SPARQL，也支持 Blueprints 标准和 Gremlin 语言。依托分布式动态分片 B+ 树和服务总线技术，它能实现真正的集群分布式存储与查询，因此被 Wikidata 选为查询服务的后端，在与 Neo4j、Titan 的竞争中脱颖而出。

Stardog 由 Stardog Union 开发，是 RDF 三元组数据库，支持 RDF 图数据模型、SPARQL、属性图模型、Gremlin、OWL2 标准、自定义推理与数据分析规则、虚拟图、地理空间查询，以及多语言编程和网络接口。尽管推出较晚，它对 OWL2 推理支持良好，还集成了全文搜索、GraphQL 查询、路径查询、机器学习任务等，成为一个综合的知识图谱存储与查询平台。

原生图数据库方面，Neo4j 是用 Java 实现的开源产品，流行度高。社区版是单机，企业版支持高可用集群，但它本质上是每个节点保存完整图副本的镜像集群，并非把图切分为子图做分布式存储，属于准分布式。当数据量超限，磁盘、内存就会成为瓶颈。

JanusGraph 在 Titan 基础上演进，是 Linux 基金会旗下的开源分布式图数据库。存储后端与查询引擎分离，可接 Cassandra 或 HBase 这类分布式 Bigtable 存储，从而具备分布式能力。主要短板是分布式查询仅限于基于底层存储的简单导航查询，子图匹配、正则路径等复杂查询还不支持真正的分布式处理。

OrientDB 起初是多模型数据库，支持图、文档、键值、对象、关系等，底层设计偏向图和文档存储。记录之间的关联不靠主外键，而是直接的物理指针。

Cayley 由谷歌工程师开发，2014 年 6 月发布在 GitHub，是轻量级开源图数据库。受 Freebase 和谷歌知识图谱图存储影响，目标是为开发者管理 Linked Data 和图模型数据提供有效工具。

总体来看，基于关系的存储继承了关系数据库的成熟度，在硬件充足时可管理千万到十亿级三元组。官方测评显示，Oracle 12c 配合空间和图数据扩展组件可管理高达 1.08 万亿条三元组。百万到上亿规模，用稍强配置的单机加主流 RDF 三元组库如 Jena、RDF4J、Virtuoso 就够。几亿到十几亿以上的大规模场景，可考虑 GraphDB、BlazeGraph 等商业分布式系统，或开源的 JanusGraph 等。近年来 Neo4j 代表的图数据库发展迅速，用图数据库管理 RDF 三元组也是一种选择，但多数图数据库不能直接存 RDF，需要先预处理成属性图模型再管理。目前没有绝对主导的知识图谱数据库，随着三元组库和图数据库融合，存储手段会更丰富。

### 1.6.2 知识图谱与智能问答
基于知识图谱的问答 KBQA 是智能问答的核心，将用户的自然语言问题转成 SPARQL、SQL 等结构化查询，从知识库中直接取出答案。

近年研究聚焦事实型问答，答案通常是一个词或短语，比如“中国的首都是哪个城市？北京”。按知识点数量可分为单跳问题和多跳问题，按领域可分为垂直领域和通用领域。垂直领域的图谱规模小精度高，问答效果更容易提升。

成熟的问答技术能提升检索精度和效率，也改善产品体验，用户像跟人对话一样提问即可。

关键在于理解和解析自然语言问题，涉及 NLP、信息检索、推理等。主流方法分三类：基于语义解析、基于信息检索、基于概率模型。

基于语义解析的主流方法把自然语言问题解析成结构化查询再执行。解析后的语义结构可解释答案来源，有助于用户理解并帮助开发者定位错误。

微软在单跳问答上贡献突出。2014 年叶等人提出把任务拆成话题词识别和关系检测，比如“姚明的妻子是谁?”先通过语义相似度解析成 (姚明，妻子，?)，话题词是姚明，关系是妻子或配偶，再查询得答案。2015 年叶等人指出直接在大型知识库里匹配关系困难，先用实体链接定位话题词，再在与话题词相关的关系子集中找匹配关系。2016 年叶等人基于斯坦福开源的 WebQuestions 数据集，标注出 SPARQL 解析结果，形成 WebQuestionsSP。

基于语义解析的模型在训练时隐式学习标注数据中的语法规律，可解释性好，但标注成本高。基于信息检索的方法则避开标注，流程是先粗粒度检索出候选答案，再依据问题特征排序，需要模型充分理解问题语义，语言中的同义替换等现象增加了难度。

为提升检索式问答，学者尝试集成额外文本信息如 Wikipedia 或搜索引擎结果；设计更复杂的网络结构如多列卷积神经网络 MCCNN、深度残差双向 LSTM、注意力最大池化层；联合训练实体链接和关系检测模块。

也有学者把问答视作条件概率问题，求 P(A=α|Q)，引入概率分解或变分推理技巧来求解。

目前大部分方案仍集中在单跳事实问答，语义解析和信息检索方法并非完全对立，都可拆分为话题词识别和关系检测两个子任务串行，部分论文认为单跳问答已接近人类水平。

未来重点会转向多跳事实问答，这类问题涉及关系词的词汇组合性、多个关系词的语序等更复杂的语言现象。一种思路是把多跳问题转化为单跳问题复用现有模型。此外，模型需要更强的推理能力和可解释性，既满足复杂提问，也让用户知其所以然。
