- (1) 场景覆盖要兼顾常规使用、极限工况和异常输入。常规是类似正常光照下的图像识别，极限是暴雨导致摄像头画面受阻，异常则包括空值、格式错误等边界情况。
- (2) 压力测试专用数据集：高并发请求用于压测吞吐能力，大尺寸输入用于观察延迟表现，用来检验智能体在重压下的稳健性。

### 13.3 选对部署，让智能体跑得更稳

落地方式要跟着业务诉求走，时延容忍度、预算和数据敏感度是关键分水岭。下面梳理几种主流形态。

#### 13.3.1 本地化部署
- (1) 基础搭建：以 Docker + Kubernetes 自建私有云集群。
- (2) 服务形态：Flask/FastAPI 提供 REST 接口，gRPC 满足高性能场景。
- (3) 安全加固：防火墙隔离、TLS 传输加密、RBAC 权限管控。
- (4) 运维监控：Prometheus + Grafana + ELK 组合。
- (5) 适用范围：对隐私要求极致如金融交易、医疗数据；对时延零容忍如工业控制；以及网络不稳定环境。
- (6) 核心特征：模型完全在本地服务器或终端运行，数据不出物理边界。可控性强，但需自建机房，前期投入高。
- (7) 典型案例：银行风控 Agent 本地化避免资金数据外泄；工厂设备故障检测 Agent 实现毫秒级响应。

#### 13.3.2 云上部署
- (1) 主流厂商：
  - AWS：SageMaker、EC2、Lambda。
  - Azure：ML Studio、AKS。
  - GCP：Vertex AI、Cloud Run。
- (2) 能力：支持自动扩缩容、CI/CD 流水线、模型版本管理。
- (3) 成本优化：可结合 Serverless 架构降低闲置开销。
- (4) 适用范围：用户规模波动大如电商大促；需要全球化多区域服务；缺乏本地运维能力的团队。
- (5) 核心特征：模型托管在云厂商节点，通过 API 对外提供能力。算力可按需增减，但受网络状况影响，延迟取决于用户到云端的距离。
- (6) 典型案例：通用图像识别 API 如 Google Vision；跨地域的客服对话 Agent。

#### 13.3.3 边缘侧部署
- (1) 设备类型：摄像头、网关、机器人、无人机。
- (2) 主要难点：算力受限、运维难度大、需要 OTA 升级。
- (3) 应对方案：选用轻量推理引擎 ONNX Runtime、TFLite，搭配边缘编排工具 KubeEdge、OpenYurt。
- (4) 适用范围：物联网设备密集的智能家居、智慧城市；网络带宽受限的偏远传感器；对延迟极敏感的自动驾驶车端决策。
- (5) 核心特征：模型部署在数据产生地附近的边缘节点，显著减少传输量，延迟能压到毫秒级。
- (6) 典型案例：智能摄像头本地人脸识别无需上云；基站实时流量调度 Agent。

#### 13.3.4 嵌入式部署
- (1) 硬件对象：MCU 如 STM32、低功耗 SoC。
- (2) 模型要求：体积需极致压缩至 1MB 以内，常用 TensorFlow Lite Micro。
- (3) 系统支持：FreeRTOS、Zephyr 等实时操作系统。
- (4) 适用范围：智能手表、无人机、智能家居传感器等体积、功耗、算力受限的小型终端。
- (5) 核心特征：模型轻量化到 KB 级别，运行在 ARM Cortex-M、RISC-V 等嵌入式芯片上，功能单一但响应迅速。
- (6) 典型案例：智能手环运动状态识别 Agent；扫地机器人路径规划 Agent。

#### 13.3.5 专项部署
- (1) TensorFlow Lite 移动端：谷歌推出的轻量推理框架，适配移动端和嵌入式，支持模型剪枝压缩和硬件加速如手机 NPU，覆盖 Android/iOS。适合图像分类、语音识别等轻量任务，例如手机相册物体识别、手机端语音识别、OCR、人脸检测。
- (2) NVIDIA Jetson GPU 加速边缘计算：面向边缘的嵌入式 GPU 平台如 Jetson Nano、Orin，功耗 10～60W，算力最高达 275 TOPS，适合中等算力的边缘任务如工业质检、无人机避障。
  - ① 产品线：Jetson Nano 到 Xavier AGX 算力递进。
  - ② 优势：兼容完整 CUDA 生态，可跑 YOLO、BERT 等中等规模模型。
  - ③ 工具链：TensorRT 加速推理、DeepStream 视频分析。
  - ④ 典型应用：智能零售、AGV 导航、无人机视觉。

### 13.4 模型瘦身技术

边缘和嵌入式场景算力紧张，需借助轻量化手段在保证精度的前提下减小体积和计算量。

#### 1. 知识蒸馏
- (1) 原理：用精度高但笨重的教师模型指导轻量学生模型学习输出分布，让小模型在体积缩小后保留核心能力。
- (2) 典型案例：TinyBERT 基于 BERT 蒸馏，参数砍掉 70%，速度提升 9 倍，精度仅下降 1%～2%；Llama-2-1.1B 基于 Llama-2-7B 蒸馏，适配边缘设备对话。

#### 2. 量化感知训练
- (1) 原理：训练阶段模拟低精度计算，如把 FP32 转为 INT8，通过参数调整抵消量化误差。模型体积可降 75%，速度提升 2～4 倍，精度损失控制在 1% 以内。
- (2) 适用场景：对延迟敏感的边缘设备，如智能摄像头的实时目标检测。
- (3) 常见做法：PTQ 后训练量化速度快但损失大；QAT 精度接近原模型，适合关键任务。
- (4) 支持框架：TensorFlow 的 tf.quantization 与 PyTorch 的 torch.quantization。

### 13.5 降本增效策略

算力与运维是长期花费，需要在性能与成本间找到平衡。

#### 13.5.1 算力选型
##### 1. CPU 推理与 GPU 推理
- (1) CPU 推理：适合低频调用如日均 ≤10 万次、计算简单的规则类任务。成本低，单台服务器月租数百元，但并行弱，高并发下延迟明显。
- (2) GPU 推理：适合高频调用如日均 ≥100 万次、计算密集型如 Transformer 推理。单卡可支持数千并发，但价格高，NVIDIA A100 月租数万元。

##### 2. 按需计费模式
- (1) 云上可用 Spot Instance、阿里云竞价实例等闲置算力，成本比固定实例低 50%～70%，适合非核心任务如模型定期更新。
- (2) 无服务器架构如 Aurora Serverless，有请求才启动算力，按时长计费，适合流量波动明显的场景，如夜间流量低的电商客服 Agent。

#### 13.5.2 资源调度
##### 1. Keda 自动扩缩容
基于 Kubernetes 的开源工具，按实时指标如 Kafka/PubSub 队列深度、CPU 使用率自动增减实例。例如队列消息 >1000 时扩至 10 节点，<100 时缩至 2 节点，避免资源空转。队列积压超阈值时自动增加推理实例。
##### 2. 非实时场景停机维护
对夜间无用户的企业内部 Agent 如日志分析，可设置定时停机 23:00～次日 7:00，每天节省 8 小时算力成本。

### 14.1 系统概述

项目“多模态试驾预约 Agent”整合多模态交互与试驾全流程管理，核心功能如下。

#### 1. 多模态输入处理
支持文本、语音、图片三种输入解析。
- (1) 文本输入：识别意图如试驾预约、价格查询，并给出操作建议。
- (2) 语音输入：模拟语音转写，默认识别为试驾预约请求，推荐车型、时间和地点，并提示补充信息如姓名、电话。
- (3) 图片输入：区分驾照和车型照片，提取驾照信息或车型详情并生成试驾规划建议。

#### 2. 试驾预约与调度管理
- (1) 常规预约调度：根据用户提交的时间、车型、位置等，生成含预约 ID、格式化时间、服务时长、位置坐标的调度计划。
- (2) 紧急请求处理：验证紧急预约合法性，调整原计划并顺延后续预约，输出受影响客户明细及通知结果。

#### 3. 信息查询与集成服务
- (1) 库存查询：提供指定经销商车型库存，含名称、数量、颜色、可预约日期，统一用 count 字段标识数量。
- (2) 价格查询：返回指导价、优惠政策、试驾礼包及对比车型信息。

#### 4. 天气与路线规划
- (1) 天气预报：查询地点和日期天气，判断是否适合试驾并提供备选日期和注意事项。
- (2) 天气影响评估：针对大雨、雾天等情况建议改期或调整路线，保障安全。
- (3) 路线推荐：基于起点终点生成基础路线，支持风景、性能、城市三种偏好调整，包含距离、时长、途经点及路况。

#### 5. 交互界面支持
基于 Gradio 构建可视化入口，整合全部功能模块，实现从输入到全流程管理的闭环。

整体上，系统通过多模态交互提升体验，覆盖预约调度、调整、信息查询、环境适配等核心场景，适用于经销商智能化试驾服务管理。
