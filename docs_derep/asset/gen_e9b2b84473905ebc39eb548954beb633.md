AI售货员抛出的“买多少呢？”并非流程里写死的一道审核关，而是模型在推理时自己发现数量信息缺失后，主动发起的一次人工求助请求。

面向商品咨询这类需要模型自行决定何时引入人力的场景，底层仍然依赖 LangGraph 中断机制的四个要素——interrupt、memory、checkpointer 与 thread_id，整体走向与 2.5.2 节保持一致：工作流在中断点暂停并保存状态，等待外部输入，收到反馈后从检查点恢复继续执行。

不同的地方在于中断的触发不再受固定节点控制，而是由大模型在运行期动态判断。为此需要一个巧妙的设计：引入一个不承载业务逻辑、专门用来请求人类的工具。

# 第3章 DeepResearch：深度思考Agent驱动的上下文构建

近年来，随着检索增强技术的演进，LLM 的能力边界持续拓展：从基于静态知识库的检索增强生成 Retrieval Augmented Generation，RAG，到动态调用搜索引擎的网络增强生成 Web Augmented Generation，WAG，再到具备主动规划、多轮检索与迭代验证能力的深度思考型 Agent。

这一演进意味着上下文的构建方式发生了转变：AI 不再被动拼接检索片段，而是在任务驱动下模仿人类行为，自主发起搜索、评估信息质量并实时修正推理路径。

2025 年，OpenAI 发布 DeepResearch，进一步印证了该范式。它把基于自主搜索的上下文扩充推向极致，实现了端到端的深度研究自动化。本章将从理论到实战，系统拆解如何搭建一个可用的 DeepResearch 系统。

## 3.1 深度解析DeepResearch核心演进

本节剖析从 RAG 到 DeepResearch 的技术演进逻辑，揭示其背后的架构思想。

### 3.1.1 RAG的原理与局限

在 2025 年之前，提升回答准确性的主流方案是 RAG，其核心原理如图 3-1 所示。

RAG 通常分为两个阶段。

- 数据索引阶段（图 3-1 中步骤 1～3）：对原始文档进行切分 Chunking，利用嵌入模型转换为向量并持久化到向量数据库。
- 检索生成阶段（图 3-1 中步骤 4～8）：用户提问时将问题向量化，在向量库中进行相似性搜索，匹配的片段作为上下文与原问题一起送入 LLM，类似开卷参考。

[PRE5]

图 3-1 RAG 核心原理

工程实践中，RAG 常见召回率 Recall 偏低的问题。即便库中存在相关信息，也可能因表达模糊或向量偏移导致检索失败。

尽管后续出现了查询重写 Query Rewriting 或 Agentic RAG 等多轮检索验证手段，本质仍是被动检索，难以根据已知信息动态调整搜索策略，获取的信息往往停留在表面，缺乏深度与系统性。

### 3.1.2 DeepSearch的机制与不足

受 RAG 启发，2025 年年初，主流大模型应用如通义千问、DeepSeek 等普及了联网搜索功能。图 3-2 为通义千问对话助手的联网搜索示意。

[PRE6]

图 3-2 通义千问对话助手的联网搜索示意

联网搜索的本质是模型理解用户意图后将其拆解为关键词，调用搜索引擎 API，抓取多页内容汇总后生成带来源的回答。该功能也被称为 DeepSearch。

相较 RAG，DeepSearch 无需预建私有向量库，时效性更强，覆盖面更广。但其局限明显：核心仍是搜索而非研究，通常只做单轮反馈，难以应对复杂的长链研究任务。

### 3.1.3 DeepResearch的核心架构：从搜索转向研究

DeepResearch 标志着重点从单次检索转向自主迭代。它模拟人类工作方式：任务拆解→持续探索→批判反思→结构化输出。其实现架构如图 3-3 所示。

[PRE7]

图 3-3 DeepResearch 实现架构

架构核心是一个由提示词工程驱动的深度思考型 Agent，主要包含三个模块。

- 思考与决策模块：负责推理、任务拆解与结果反思。
- 信息搜索模块：负责联网检索及网页内容提取。
- 报告输出模块：负责把多轮信息整合为结构化文档。

DeepResearch 细化流程如图 3-4 所示，可拆分为：

- 初始探索：基于初始主题进行首轮信息采集。
- 状态评估：分析当前信息，评估完整性与准确性，识别矛盾或缺口。
- 策略制定：据评估结果决定是否追加搜索，并生成更具针对性的长尾指令。
- 迭代执行：进入“探索-反思-再探索”循环。
- 循环终止：信息满足覆盖率要求或达到预设迭代阈值时停止。
- 整合报告：对高质量信息去重校对，生成最终研究报告。
