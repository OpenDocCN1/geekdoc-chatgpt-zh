第 1 章 Embedding 与大模型的关联

第 1 章已经把 Embedding 的基本概念捡起来了，知道了它能把单个词或完整句子映射成向量。不少读者会跟进提问：这玩意儿和 ChatGPT、以及大语言模型到底有什么牵连？为什么要做 Embedding？在哪些场景下会用到？这三点其实可以用一句话收束：为了拿到“相关”的上下文。具体来看，NLP 里一大堆任务，以及大语言模型在真实落地时的用法，都依赖一定的上下文知识，Embedding 就是用来把相关信息找出来并送进模型的技术。业内常把这个流程叫做相似匹配——先把候选内容转成 Embedding，再靠向量间的相似度挑出最贴合的那部分作为上下文。

接下来的内容会先把相似匹配的底层逻辑讲透，特别是怎么把一段自然语言表达到更合理，以及怎么判断两个 Embedding 是否相近。随后会演示 ChatGPT 相关接口的具体用法，别的同类接口套路基本一致。最后会梳理几类和 Embedding 绑定的任务与应用，其中一部分可以用大语言模型来做，也有一部分完全不需要大模型。ChatGPT 或其他大模型本质上只是工具箱里的工具，本章更关注任务本身，怎么解决问题。希望你在阅读时能体会到目的与手段的区别，手段再多变，最终都是为目的服务的。

## 2.1 相似匹配基础

### 2.1.1 更好的 Embedding 表示

#### 1. Embedding 表示技术回顾

先把第 1 章提到的 Embedding 表示方式捋一遍。自然语言的输入终究是一段文本，中文里可以按字、按词处理，业内统称 Token。用模型的第一步就是把文本 Token 化。可以按字，也可以按词，还能按自定义粒度，比如每两个字一组或每两个词一组。以如下句子为例。

·给定文本：人工智能让世界变得更美好。

·按字 Token 化：人 工 智 能 让 世 界 变 得 更 美 好 。

·按词 Token 化：人工智能 让 世界 变得 更 美好 。

·按字 Bi-Gram Token 化：人/工 工/智 智/能 能/让 让/世 世/界 界/变 变/得 得/更 更/美 美/好 好/。

·按词 Bi-Gram Token 化：人工智能/让 让/世界 世界/变得 变得/更 更/美好 美好/。

于是就冒出一个新问题：Token 化该怎么选？不同方案各有优劣。英文多用子词，中文过去常见字或词，现在中文大语言模型基本都采用字加词的混合策略。一种好处是语义表达更细致，另一种好处是遇到未登录词时可以用字来拆解，避免出现无法识别的情况。

Token 化之后，第二步是想办法让计算机能读懂这些 Token。计算机只能处理数字，所以要把 Token 映射成序号。这里需要一个词表，把每个词对应到表中的位置。以上面的句子为例，若按字粒度，词表可以做成一个文本文件，每行一个字。

按行存储每个字作为一个 Token，此时 0=我、1=们……依次类推，假设词表规模为 N。需要留意的是词表的顺序本身并不重要，但一旦确定并训练好模型后就不能随意改动。这里的改动包含顺序调整、增词、删词、改词等。如果只是改顺序或删词，不必重训模型，但要手工把 Embedding 参数按同样方式调整顺序或删掉对应行。若是增改词表，则需要重新训练并拿到增改部分的 Embedding 参数。

下一步是把序号也就是 Token ID 转成稠密向量。核心思路大致是：

- 把特征压到固定维度 D，比如 256、300、768 等，具体数值不关键，重点是维度不再随词表膨胀。
- 借助自然语言的上下文关系，学习一个由 D 个浮点数组成的稠密向量。

我们知道句子才是语义的最小单位，相较 Token，我们更需要句子的表示。而且如果句子能被很好表示，词作为极短句子自然也能被照顾到。我们还希望能在不同上下文里动态地获得句子的表示。围绕这个目标经历了很多探索，最终的走向是在模型架构上做设计——输入任意一段文本，模型经计算后直接输出对应的向量表示。

#### 2. 如何更好地表示

前面把模型当成黑盒，默认丢进一段文本就能吐出一个表示。实际中间还有不少细节，即如何给出这个表示。下面介绍几种常见做法并分析其机理。

直观的做法是借鉴词向量的思路，把“词”换成“句”，训练后得到句子向量。细想会发现这本质上只是粒度更粗的 Token 化，粒度太大时问题会更突出。而且这样得到的句子向量无法反推出其中的词向量，而有些场景恰恰需要词向量。看来这条路走不通。

另一种操作更简单，就是对词向量求平均。无论句子或文档有多长，找到每个词的词向量取均值即可，得到的向量维度与词向量一致。深度学习 NLP 初期几年里这是主流做法，后来也出现了不少改进的平均方式，比如加权求和，权重可依据词性、句法结构等设定为固定值。

2014 年，谷歌发布 Word2Vec 之后不久，同一批研究者提出了 Doc2Vec。思想是在每段话前面加一个额外的段落 Token 作为段落的向量表示，可视作段落主题。训练方式类似词向量，但在更新词向量参数时额外更新这个段落 Token 向量。直观上是把文档语义都浓缩进这个特殊 Token。缺点很致命：推理时若遇到训练集之外的文档，就需要把该文档的参数更新进模型，既不方便效率又低。

随后深度学习继续演进，涌现出 TextCNN 和 RNN 等经典模型。RNN 在第 1 章介绍过，TextCNN 的灵感来自图像领域的卷积神经网络。TextCNN 用若干固定大小的窗口在文本上滑动，每个窗口从头滑到尾产生一组浮点特征，使用 2、3、4 等不同窗口大小，再把得到的特征拼接起来表示整段文本。TextCNN 的表达能力不错，常被用作基准，线上也有不少模型在使用。主要问题是只利用了局部特征，没能很好捕捉全局语义。RNN 及变体是时序模型，按 Token 顺序处理。RNN 表示能力也行，但有两个明显短板：一是慢，难以并行；二是文本过长时效果变差。总的来说，这一时期词向量用得少，文本表示主要靠模型架构体现，Token 化方式以词为主。

2017 年 Transformer 出现，带来迄今最强的特征表示方式——自注意力。模型规模从十万、百万级别逐渐增长到亿级。文档表示方法本身创新不多，但模型变大后表示效果提升明显。自此 NLP 进入预训练时代——基于 Transformer 训练一个基座模型，做任务时在对应数据上微调。代表性成果是 BERT 和 GPT，前者使用 Transformer 编码器，后者使用解码器。BERT 在每个文档前加一个 [CLS] Token 来表示整句语义，和 Doc2Vec 不同的是，推理时不需要额外训练，而是根据当前输入计算自动获得表示。也就是说同样输入下，相比 Doc2Vec，BERT 凭借强大的表示能力无需额外训练就能得到不错的文本向量。GPT 在第 1 章已有介绍，这里不再展开。无论哪种预训练模型，底层都是对每个 Token 计算，并在计算时参考其他 Token 信息。所以预训练模型通常能得到每个位置的向量表示。于是文档表示仍然可以用最常见的方式——取平均。当然由于架构更复杂，平均方式也更灵活，比如用自注意力作为权重做加权平均。

#### 3. 进一步思考

ChatGPT 的出现是语言模型的突破，并不直接涉及 Embedding，但由于大语言模型在超长文本处理上的限制，主要是资源消耗和超长距离上下文依赖问题，Embedding 成了一个重要组件。我们先不谈大语言模型，继续聚焦 Embedding。

目前 Embedding 基本已成为模型架构的副产物，架构增强→Token 表示增强→文档表示增强。第一步问题不大，Token 表示通过架构充分利用了各种信息，还能得到不同层级的抽象。但第二步显得单薄，要么靠 [CLS] Token，要么靠各种形式的平均。这些方法在句子上可能够用，因为句子通常很短，但在段落、篇章乃至更长文本上就未必合适了。

可以类比人类阅读的习惯，很多模型灵感都来自人类，比如 CNN、自注意力。我们读一句话时会抓住关键词，整体语义往往能由这些词概括。读一段话时，关注点仍是关键词、包含关键词的关键句。但读一篇文章时，关键词和关键句的重要性会下降，我们更关注文章整体在表达什么，这种整体表达未必能用原文的词或句来概括。

也就是说，人类处理句子和篇章的方式并不相同。但现在模型把它们当成同一类事物处理，没有考虑量变到质变。通俗讲，就是几粒沙子和沙堆的区别。模型设计是否可以据此做出区分？

最后简单总结，Embedding 本质上就是一组稠密向量，别过度纠结它是怎么来的，用来表示一段文本，可以是字、词、句、段等。拿到这个表示后，就能做下一步任务。可以先思考一下，给定任意句子并得到其固定长度的语义表示后，能做什么。
