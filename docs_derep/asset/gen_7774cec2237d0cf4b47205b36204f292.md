要想真正搞懂上下文学习是怎么运转的，用贝叶斯的视角去拆解会更清楚，也能让少样本学习的底层逻辑变得好理解。贝叶斯解释的核心假设是：在预训练阶段里，一个文档内部的句子、段落、表格往往共享同一套底层的语义主题和表达格式，比如问答页面里问题和答案会交替出现。文档级别的数据里藏着长距离连贯性的潜在概念，模型在预训练时正是利用了这些连贯性来推断概念。

在贝叶斯视角里，上下文学习本质上是一个条件概率问题，即在预训练知识和一组提示信息都已给定的前提下，预测下一个词或短语的概率。这里的预训练知识和提示信息可以分别对应预训练分布与提示分布。预训练分布指的是模型在海量文本上学到的、跨文档的长距离连贯性概念分布，这些被内化的概念构成了模型对世界的通识，也奠定了它理解上下文的基础。提示分布则是在上下文学习时，由一系列特定任务的训练样本即提示所带来的概念分布，用来校准和改进模型对特定任务的理解和回应，是模型实现上下文适应的关键机制。

预训练分布和提示分布一起构成了上下文学习的运行机制，前者提供通用的世界理解，后者完成针对任务的微调与优化。设 p 代表语言模型的预训练分布及其概率。通过少样本学习对提示概念做贝叶斯推断，能明显提升学习效果。若模型能推断出提示概念，就能用它对测试样本做出正确预测。如式 5-1 所示，提示相当于证据，增强了后验概率 p（concept|prompt）的确定性。当 p（concept|prompt）大量集中在提示概念上时，模型就能从提示中有效习得概念，进而提高选择该概念的后验概率。

[PRE0]

这里存在一个直觉上的矛盾：模型是从上下文示例中推断提示概念的，而提示本身是从提示分布里采样的，这个分布可能与模型预训练时学到的预训练分布差异很大。提示把原本独立的训练示例拼接起来，因此在预训练分布下不同示例之间的转移概率很低，推断过程中容易带入噪声。比如把不同新闻主题的独立句子硬凑在一起，就可能产生很不自然的文本，因为单个句子缺乏足够上下文。尽管 GPT-3 中观察到预训练分布与提示分布存在差距，模型依然能够完成贝叶斯推断。

只要信号强度能压过噪声干扰，上下文学习就能成功。这里的信号被定义为在给定提示条件下，提示概念与其他概念之间的 KL 散度，而噪声则来自示例间转换带来的误差项。直观理解是，如果提示能让模型轻松区分出提示概念与其它概念，信号就很强。这也意味着信号足够大的时候，即使去掉某些信息源，比如删除输入输出映射，也是可以容忍的，特别是在提示格式保持稳定且输入输出映射信息已在预训练数据中出现的情形下。这与传统监督学习不同，传统监督学习一旦随机化标签等输入输出映射信息，就无法正常工作。

正如 5.4.1 节讨论的，模型并不完全依赖提示中的 <*x*[i]，*y*[i]> 配对。只要输出 *y*[i] 落在候选集合 *y* 中，即使 *y*[i] 不一定与输入 *x*[i] 严格对应，上下文学习依然可以进行。这说明在上下文学习里，提示本身及其全部构成输入分布、输出空间和格式 都在提供信号，目的是锁定任务的概念分布，从而让模型在预训练期间学到的概念被更精准地定位。由于提示中把随机序列串联起来，随机输入输出映射仍会增加噪声。尽管如此，只要输入分布、输出空间和格式等信号足够强，贝叶斯推断依然会发生。当然，保留正确的输入输出映射仍能提供更多证据、减少噪声，尤其当这种映射在预训练数据里并不常见时。

因此，贝叶斯框架解释了上下文学习为何有效，也为如何构建提示及其各组成部分提供了思路。

## **5.5 思维链：让模型学会分步推理**
为了进一步提升大语言模型在数学推理上的表现，谷歌大脑的 Jason Wei、Xuezhi Wang 等人在 2022 年 1 月首次提出了思维链 Chain of Thought 的概念。简单说，思维链借鉴分治思想，根据零样本、单样本、少样本等不同上下文学习模式，引导模型模仿人类逐步思考和推理的过程，让模型获得分治式的推理能力，从而解决更复杂的推理问题。

思维链最直接的用法是在提示中加入逐步推理的引导，被称为零样本学习思维链，操作很简单却效果明显。具体分两步，见图 5.7：第一步，在零样本提示上加上“让我们逐步地思考”这句引导语，模型会输出完整的推理过程；第二步，把第一步的问题与模型输出的推理过程拼接，再追加提示“因此，答案是”，此时模型会给出最终答案。

这么简单的一步操作就能显著提升推理表现。以数学推理集 GSM8K 为例，加上提示后准确率从原本的 10.4% 提升到 40.4%，如表 5.1 所示。

单样本思维链的核心就是在示例中展示如何把大问题拆解。论文《Chain-of-Thought Prompting Elicits Reasoning in Large Language Models》对比了标准提示与思维链提示在 LaMDA、GPT、PaLM 三种模型上的表现。除了 GPT 来自 OpenAI，其余两款均由 Google 发布。测试显示，拥有 5400 亿参数的 PaLM 在小学生水平的数学推理集 GSM8K 上准确率可达约 60.1%，该数据集最初由 OpenAI 于 2021 年 10 月提出。

思维链提出不久，2022 年 3 月出现的 Self-Consistency 技术进一步把 GSM8K 准确率推高到 74.4%。如图 5.9 所示，Self-Consistency 的思路是在少样本提示的多个示例中为每个示例提供推理示范，不同于前面只输出一条推理链就结束，Self-Consistency 让模型生成多条不同的推理过程和答案，再通过投票选出最佳答案。该方法整合了“把一个提示问题扩展为多个提示问题、检验推理中间步骤的正确性、对多个输出加权投票”三个改进，将 GSM8K 准确率提升到约 83%。

各类思维链应用都体现了分治算法的理念，即把复杂推理拆成若干相对简单的子问题，逐个解决后再综合得到最终答案。大语言模型本身具备推理能力，只要设计好提示并进行分步引导，就能提高其按步骤推理的概率。

不同语料的逐步引导语并不完全相同。例如在中文语料中，与 Let's think step by step 意思相近的引导语可能是“详细解题思路如下”，而不是直译的“让我们逐步思考”。因此不同思维链应用方式必须结合具体语境，通过提示提升任务分解的后验概念分布，让大语言模型能把复杂推理问题拆解为易解的子问题，从而增强推理能力。

## **5.6 小结：规模与少样本的权衡**
GPT-3 基于优化的稀疏 Transformer 解码器架构，参数规模高达 1750 亿。随着规模扩大，它在多种 NLP 任务上展现出明显优势，同时训练成本也显著攀升。为缓解经济压力，GPT-3 采用了基于内容的学习方式，核心是少样本学习策略。这种方法无需调整模型参数，只需在少量样本上学习任务相关知识，就能在新任务上取得不错效果。

# **第六章**

# **大模型预训练的关键策略**
大语言模型的预训练环节，数据量、参数规模、训练架构和过程控制都是关键挑战。这些因素可能导致损失尖峰、收敛困难等问题。为提升预训练的稳定性和收敛性，通常会组合数据处理、架构选择、超参数设定等多种策略。

从 GPT-3 起，OpenAI 开始采用部分闭源策略，许多关键技术细节未完全公开，比如训练数据集构建过程、计算资源和超参数设置等。为了更深入理解 ChatGPT 的预训练思路，本章将基于同等规模模型的公开资料进行分析和讨论。

## **6.1 数据来源：喂给模型什么**

## **6.2 数据怎么清洗与筛选**
GPT-3 基于约 3000 亿 token 进行预训练，其中约 60% 来自精心筛选的 Common Crawl，其余为 WebText2、Books1、Books2 和维基百科。GPT-3.5 还加入了 GitHub Code 等代码语料。不同语料的采样比例并不按规模分配，而是依据质量优化。开源社区曾尝试复刻 ChatGPT，成功案例不多。OPT-175B 和 BLOOM-176B 参数规模接近甚至超过 GPT-3，但性能仍不及 GPT-3 原始模型。它们为本章讨论预训练数据处理的关键问题提供了参考。

1）数据质量与数量。数据量对预训练影响决定性。例如 PaLM 和 GPT-3 的预训练数据量明显高于 OPT 和 BLOOM，见表 6.2，这说明大规模高质量语料是成功的关键之一。数据质量同样重要，GPT-3 使用高效分类器对语料进行筛选，而 OPT 和 BLOOM 训练时未做类似筛选。

2）数据集去重。去重能防止模型在重复数据上过拟合，提升泛化。GPT-3 采用文档级去重，而 OPT 预训练的 Pile 语料库仍存在大量重复。

因此提升预训练语言模型性能可以从以下方向入手：对训练数据做更精细筛选以保证质量；做更有效的去重减少冗余和过拟合；提高多样性以增强泛化；研究数据分布对特定任务性能的影响，以便更好选择和组织预训练数据。GPT-3 对数据的具体预处理细节和数据本身尚未公开。

## **6.3 怎么让巨模型跑得动**
大语言模型的一个显著特征是规模持续扩大。例如 GPT-3 参数达 1750 亿，即使用 1024 个 80GB A100 GPU 训练也需一个月。拥有 650 亿参数的 Meta LLaMA 采用 2048 个 NVIDIA A100 GPU，训练周期长达 21 天。规模扩大带来相应挑战。

1）显存限制。即使是显存最大的 GPU 也无法容纳全部参数。以 GPT-3 为例，模型参数约需 700GB，梯度约 700GB，优化器状态约 1400GB，总计约 2.8TB。
