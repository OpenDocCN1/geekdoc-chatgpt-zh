思维图从并行到自组织的演进

并行推理是思维图最原始的形态。系统用 Map-Reduce 的方式把大问题拆成 N 个子问题，各自并行出答案后再简单拼接。效率看似很高，致命伤是信息孤岛：各分支互不通气，观点无法碰撞、校正和融合。

静态图谱加入了显式的聚合与精炼算子，拓扑事先就画好了，比如 3 个发散节点→2 个聚合节点→1 个循环节点。预设的结构让多分支的信息完成深度融合，最终洞见往往超过任何单个分支。

动态图则把拓扑权交给了运行时的 Agent。图不再是固定的蓝图，而是 Agent 现场绘制的推理网络：“这里信息不够，我先分出两条分支去查资料，再汇合”。这种自生成的能力带来了极强的适应性，最接近人类面对未知时那种探索性和生成性的思考。

### 2. 模式组合示例

思维图擅长调度复杂的信息流，常常作为核心拓扑来挂载记忆与行动模块。

思维图模式与 RAG 模式的组合 = 图谱增强生成
面向需要全局视角的难题，比如“分析 100 份合同的关联风险”。RAG 提供的不是零散文本，而是实体之间的关系。思维图把知识图谱的结构直接映射为推理路径，Agent 沿着图谱的边做多跳推理，并在每个节点聚合邻域信息，实现结构化知识与结构化推理的同构。

思维图模式与工具编排模式的组合 = 自动化数据流水线
利用图的环路特性实现代码质量的螺旋式提升。在自动化数据分析与修复场景里，推理图被转化为执行流，形成“代码—执行—修复”的闭环。
节点 A Generate 调用代码生成工具产出分析脚本；
节点 B Execute 调用代码解释工具运行脚本；
节点 C Analyze 若执行出错，分析错误日志并创建指向节点 A 的反馈边，触发脚本重写。

把线性思维解开编成网，Agent 就不再沿单一逻辑前行，而是能够在全局高度上分发、聚合与重构信息。

### 6.3.5 设计哲学：网络的韧性

思维图深刻体现了现实问题的网络化本质。现实难题很少是线性的思维链，也很少是纯粹的树状结构，因为树意味着一旦选定路径，其他路径就被放弃。

真实问题往往是“既要…又要…”的综合考量。
既要成本又要质量，体现多分支的聚合；
既要向前推进又要适时回溯，体现循环往复的特性。

思维图让 Agent 拥有整合力，不再是钻牛角尖的专家，而是一位能倾听各方意见、融汇各家之长并持续自我完善的架构师。

至此，推理的三种基本拓扑已经搭建完成。
思维链适用于数学、逻辑等线性推导任务；
思维树适用于搜索、决策等多分支选择问题；
思维图适用于综合、创意与优化等需要多向关联与整合的场景。

由此形成相对完备的推理拓扑体系。接下来进入类比推理模式，探讨如何借助记忆实现推理捷径。

## 6.4 类比推理模式

> “创造力并非凭空产生，而是通过将已知事物相互关联，从而发现新的可能性。”
> ——道格拉斯·侯世达，《哥德尔、艾舍尔、巴赫：集异璧之大成》

面对新问题，比如“如何治理一家混乱的初创公司”，Agent 不会从零推演管理学，而是去记忆库检索结构相似的源案例，比如“战国合纵连横”或“乔布斯回归 Apple”。

[PRE0]
它会说：“这种情况我见过，人物地名变了，但权力的游戏规则没变。我们可以借鉴当时的策略并做调整。”

类比推理的核心是结构映射，从长时记忆中检索与当前问题在关系结构上相似的源案例，并把解决方案迁移到目标问题。这是人类“举一反三”和 LLM 少样本学习的关键。

### 6.4.1 模式架构：跨域的跳跃

类比推理不像流水线，更像一个跨时空传输门。在此机制下，Agent 要突破表象直达记忆中的本质结构，再把旧智慧搬运到新场景。

[PRE1]
图6-15 类比推理模式的架构像是一个“跨时空传输门”

关键组件如下。
检索器 Retriever 负责联想，不仅做关键词匹配，更做结构匹配，比如识别出原子结构与太阳系在组织模式上的相似性。
映射引擎 Mapping Engine 负责对齐，构建对应关系字典，例如 {太阳：原子核，行星：电子，引力：电磁力}。
适配器 Adapter 负责改写，把源案例的解法调整为新领域可用形式，比如把牛顿力学公式改写为量子力学形式。

三者协同完成从记忆提取到认知重组的闭环，把静态知识转化为动态策略。

### 6.4.2 类比推理核心机制

Agent 能发现原子与太阳系的相似，并非魔法，而是剥离细节、捕捉拓扑同构。

1. 结构映射理论
认知科学家德德雷·根特纳提出的结构映射理论认为，属性可以丢弃，关系必须保留。
太阳是金黄色的，原子核没有颜色，这些表面属性不重要；
“太阳吸引行星”与“原子核吸引电子”都是“中心吸引外围”的关系结构，这种关系才是映射的关键。

2. 抽象与具体化
类比是一个 V 形过程。
抽象：剥离源案例的具体细节，提炼通用图式；
具体化：将通用图式适配并填充到目标情境。

3. 自我生成案例
记忆库没有现成案例时，强模型可以无中生有。比如提示“构想一个逻辑相似但领域完全不同的案例并据此建议”，模型会用“做菜”类比“写代码”，提出“模块化如同提前备菜”的建议。

从结构映射到自我生成，这些机制赋予 Agent 流体智力，能应对从未见过的情境。

### 6.4.3 类比推理工程实践

工程上类比推理常表现为检索增强的少样本提示，不仅要找知识，更要找思路。

案例1：智能代码助手
GitHub Copilot、Cursor 等工具在用户输入 def connect_to_redis 时，通过类比自动生成实现。
检索：在代码库中找到已有的 connect_to_mysql 实现；
映射：识别 mysql.connector 与 redis-py 的对应，以及主机地址、端口等连接逻辑的通用性；
迁移：借鉴异常处理风格和配置读取方式，生成符合项目规范的 Redis 连接代码。
既复用健壮逻辑，又保持风格一致。

案例2：法律判例推理
律师用 Harvey、Casetext 分析新型“虚拟币诈骗案”时：
检索：找到结构相似的“跨境电信诈骗”或“庞氏骗局”判例；
映射：将“虚拟币”类比为既有金融产品类型，“交易平台”对应“传统金融中介”；
迁移：借用旧案的定罪逻辑、法律适用与量刑标准，生成法律意见书。

案例3：跨域设计灵感
设计师用 Midjourney Prompt Helper 构思“像跑车一样的鼠标”：
检索：从跑车提取流线型车身、进气格栅、金属漆等特征；
映射：流线型车身→鼠标整体造型，进气格栅→按键布局，金属漆→材质与表面处理；
迁移：整合后生成绘图 Prompt。

### 6.4.4 类比推理模式的演化与组合

类比推理从静态 Prompt 技巧演进为动态检索增强，最终发展为可解释的结构映射。

1. 演化路径：从示例到映射
静态少样本 Static Few-shot 是“刻舟求剑”阶段的代表。

2. 模式组合示例
类比推理常作为 Agent 的直觉引擎，需与逻辑引擎或执行引擎协同。

类比推理模式与思维链模式的组合 = 启发式推理
类比提供 System 1 式的战略方向，思维链负责 System 2 式的战术执行。
类比阶段：检索相似旧题，提取解题框架，例如“像追及问题”；
推导阶段：用思维链把框架迁移到新题，逐步填补细节。

类比推理模式与工具编排模式的组合 = 经验迁移
常见于 AI 编程助手或运维 Agent，把他人的经验转化为当前操作。
检索：从代码库检索风格相似片段或历史修复记录；
映射：识别变量与结构对应关系；
生成：调用代码生成工具补全代码或生成修复补丁。

类比是获取流体智力的关键，让 Agent 在陌生场景快速建立认知锚点，从死记硬背走向举一反三。

### 6.4.5 设计哲学：创造力的源头

思维链和思维树拼算力，类比推理拼阅历。人之所以聪明，是善于联想。
见飞鸟便造飞机，观游鱼便造潜艇。

类比推理赋予 Agent 创造力的雏形，真正的创造并非凭空产生，而是把 A 领域的智慧迁移到 B 领域。它是突破领域边界、迈向通用智能的关键钥匙。

小结 理性地编织

我们已构建 Agent 大脑中最核心的推理模块，不再依赖 LLM 的概率直觉，而是建立结构化的认知拓扑。

如果把推理比作交响乐，本章四种模式就是乐器。
思维链模式如小提琴，线性精准；
思维树模式如钢琴，多声部探索；
思维图模式如电子合成器，网络化融合；
类比推理模式如鼓点，跳跃直觉、连接共鸣。

优秀架构师应指挥整支认知乐团。
陌生难题先敲响类比的鼓点激发灵感；
方向初现启用思维树的钢琴探索路径；
路径选定交由思维链的小提琴严谨演绎；
最后调用思维图的合成器融合打磨。

未来推理将不再局限于文本平面，正向三维环境跃迁。Agent 的推理对象将从文本转向几何、物理与动力学，空间智能成为构建世界模型的关键。

经过推理，Agent 已弄清要做什么、为什么、如果不做会怎样。但还不够，它必须走出思维空间，介入现实。

# 第 7 章

## 行动模式

> “知行合一。”
> ——王阳明

感知、记忆、推理之后，Agent 迎来最激动人心的时刻：走出大脑，迈向现实。
若推理是参谋部，行动就是远征军。

Agent 必须具备四种能力。
边想边打 ReAct 模式：在行动中实时获取前线信息并动态调整策略；
运筹帷幄 规划—执行模式：制定全局战略并分解为可执行步骤；
调兵遣将 工具编排模式：精准选择、协同调配海量资源与工具；
自我进化 自适应策略模式：从成败中总结经验，动态优化策略。

行动的本质是对物理或数字世界的有效干预。
从认知看，行动是具身智能起点，智能不再是缸中之脑，而是具备手眼协调的实体；
从工程看，行动是结果的载体，API 调用、数据库写入、文件修改需具备原子性与回滚机制；
从控制论看，行动是反馈回路的执行器，把决策转化为实际影响，触发反馈实现动态调节。
