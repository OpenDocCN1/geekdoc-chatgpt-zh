### 6.2.7 为模型划定边界

有些任务并不需要模型发散，只想让它紧贴用户输入作答。这时可以在 Prompt 里加入约束，控制生成范围防止跑题。

Prompt 约束的演示如下：

身份：资深美食爱好者。

任务：根据用户的提问，精准地推荐地道的食谱。

输出：

- 食谱名称：<食谱名称>

- 食材清单：<食材清单列表>

- 制作步骤：<描述制作步骤>

限制：

- 只讨论与美食相关的内容，拒绝回答与美食无关的话题。

- 输出的内容必须严格按照给定的格式进行组织，不能偏离框架要求。

### 6.2.8 用分步推理拆解复杂任务

分步推理 Prompt 的思路是把复杂任务拆成相互关联的多条指令，逐步引导模型完成。这样在多步骤任务里能保持逻辑连贯和上下文一致，提升完成质量。

假设要写一篇介绍蛋炒饭的文章，就可以用 Prompt 链把整篇拆成多个环节，每个环节由一条指令驱动，保证思路清晰、内容连贯。

①引言，示例如下：

身份：资深美食爱好者。

任务：根据用户的提问，精准地回答问题。

问题：请写一段引言，介绍蛋炒饭的背景和受欢迎程度。

输出：返回JSON结构，键使用"answer"，值为模型返回的结果。

限制：

- 只讨论与美食相关的内容，拒绝回答与美食无关的话题。

- 返回结果的字数不超过50字。

- 输出的内容必须严格按照给定的格式进行组织，不能偏离框架要求。

## 6.3 靠 Prompt 完成 NLP 任务

基于 LLM 搭建的 AI 产品越来越多，即便不做微调，仅靠指令就能完成约 90% 的自然语言处理工作。LLM 虽不是万能，但在评测和裁判角色上作用明显。

下面介绍几类在 NLP 领域用 Prompt 完成任务的案例，展示 LLM 在实战中的灵活性和适用性。

先选定 GPT 大模型，再写一个统一的请求方法，最后用不同指令执行不同任务。公共请求方法的代码如下：

def send_message(messages, temperature=0.1, model='gpt-3.5-turbo'):

    client = OpenAI(

        base_url=OPENAI_API_BASE,

        api_key=OPENAI_API_KEY

    )

    if "GPT4" in model:

        response = client.chat.completions.create(

            model=model,

            messages=messages,

            response_format={"type": "json_object"},

            temperature=temperature,

            max_tokens=2048,

        )

    else:

        response = client.chat.completions.create(

            model=model,

            messages=messages,

            stop=None,

            temperature=temperature,

        )

    for choice in response.choices:

        if "text" in choice:

            return choice.text

    return response.choices[0].message.content

def do_request(prompt, role='user', temperature=0.1, model='gpt-3.5-turbo'):

    messages = [{"role": role, "content": prompt}]

    is_success = False

    try:

        content = send_message(messages, temperature=temperature, model=model)

        is_success = True

        return is_success, content

    except Exception as err:

        content = f"Error: {err=}"

    return is_success, content
