**简讯项目智能体的错误处理示例（第八章）**

**关键故障场景**

1. API 身份验证失败
• 表现：
• API 密钥缺失或失效
• API 响应中的身份验证错误
• 上报路径：
• if not api_key:
• raise ValueError (“No Perplexity API key provided”)
• if ‘PERPLEXITY_API_KEY’ not in os.environ: raise ValueError (“PERPLEXITY_API_KEY environment variable not set”)
• 恢复流程：
a. 核验环境变量配置
b. 确认密钥是否有效
c. 必要时轮换新密钥
d. 有备份时从备用密钥恢复

2. API 访问速率限制
• 表现：
• HTTP 429 错误
• API 延迟增加
• 上报路径：
• except requests.exceptions.RequestException as e:
• logging.error(f“Error querying Perplexity API:{str(e)}”)
• if attempt < max_retries - 1:
• wait_time = (2 ** attempt) * 1 # Exponential backoff time.sleep(wait_time)
• 恢复流程：
a. 采用指数退避策略
b. 切换至备用 API 密钥
c. 暂停非关键操作
d. 持续监控速率限制状态

3. 数据处理失败
• 表现：
• 响应格式无效
• 缺少必需字段
• 上报路径：
• def validate_summary_format(summary):
• try:
• if not isinstance(summary, dict):
• return False, “Summary must be a dictionary”
• if “summary” not in summary:
• return False, “Missing ‘summary’ field”
• return True, “Valid summary format”
• except Exception as e:
return False, f “Validation error: {str(e)}”
• 恢复流程：
a. 归档异常响应
b. 调整参数后重试
c. 条件允许时回退缓存数据
d. 触发监控告警

4. 网络连接问题
• 表现：
• 超时错误
• 连接故障
• 上报路径：
• try:
• response = requests.post(
• “https://api.perplexity.ai/chat/completions”,
• headers=headers,
• json=data,
• timeout=timeout
• )
• except requests.exceptions.Timeout:
logging.error（“由于超时，所有重试尝试都失败”）
• 恢复流程：
a. 设置请求超时阈值
b. 按指数间隔重试
c. 切换至备用端点
d. 跟踪网络健康状况

我们将演示如何借助低代码平台搭建销售情报智能体。该案例体现 AI 智能体如何简化信息收集，使销售人员在实时会议或通话中也能迅速获取关键信息。

我们将利用 Relevance AI 搭建由管理智能体协调多个专业子智能体的多智能体系统。构建将遵循四个核心步骤。

第一步：找到合适的智能体机会。学习识别 AI 智能体的理想应用场景。

从第一步开始，确定适合的智能体机会。

### **第一步：找到合适的智能体机会**

**了解你的使用场景**

构建高效 AI 智能体的首要工作是确定清晰且有价值的应用场景。

本案例聚焦“销售情报智能体”，解决销售运营中快速获取潜在客户与企业信息的常见难题。

该智能体体现了几个关键原则，使其成为自动化理想机会：
• 自动化需重复执行相同步骤的任务
• 可通过不同通信渠道触发的任务
• 整合并输出格式化、即用型信息或报告

确定机会后，需考虑如何构建智能体以满足需求，这就进入第二步，设计高效处理信息收集的架构。

### **第二步：定义 AI 智能体的角色和能力**

**智能体设计**

设计采用多智能体系统，由专业智能体协作提供完整结果。接下来探讨如何构建这些智能体以满足销售情报需求，明确各角色与职责。

本系统采用双层架构，含一个主智能体和两个子智能体。

1. 主智能体：销售情报智能体
• 角色：管理者，接收请求、判断信息类型并调用对应子智能体检索处理
• 能力：邮件处理、回复排版

2. 子智能体 1：个人资料子智能体
• 角色：检索者，从领英获取个人资料信息
• 能力：网络搜索、领英个人资料信息提取

3. 子智能体 2：企业信息子智能体
• 角色：收集者，从领英获取企业信息
• 能力：网络搜索、领英企业洞察提取

用例、角色与能力已明确，接下来设计协同方式。

### **第三步：成功设计 AI 智能体**

• 子智能体执行专业任务并返回格式化结果
