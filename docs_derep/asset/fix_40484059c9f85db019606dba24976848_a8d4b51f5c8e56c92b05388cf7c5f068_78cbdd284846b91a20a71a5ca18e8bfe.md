多卡训练实战：显存与吞吐的四种解法

训练大型网络时，显存天花板和计算效率往往互相拉扯。先从压显存的手段说起。激活重计算在回传时丢弃中间激活，需要时再重新算一次，峰值占用会明显下降，代价是多花一些算力。下面是一组对比。

[PRE0]

无Checkpoint最大内存使用：1024 MB

使用Checkpoint最大内存使用：800 MB

关掉重计算时占用接近一千兆，打开后压到八百兆左右，省下的空间足以让更深的网络继续跑。

谈到多卡协同，最直观的做法是把同一份网络镜像到所有显卡，各自喂不同的一小批样本，训练完再把梯度汇总更新。DataParallel 的封装很薄，上手很快。

[PRE1]python

import torch

import torch.nn as nn

import torch.optim as optim

# 定义简单模型

class SimpleModel(nn.Module):

    def __init__(self):

        super(SimpleModel, self).__init__()

        self.fc1=nn.Linear(1024, 512)

        self.fc2=nn.Linear(512, 256)

        self.fc3=nn.Linear(256, 10)

    def forward(self, x):

        x=torch.relu(self.fc1(x))

        x=torch.relu(self.fc2(x))

        return self.fc3(x)

# 初始化模型和数据

model=SimpleModel()

model=nn.DataParallel(model)       # 使用DataParallel封装模型以支持多GPU

device=torch.device("cuda" if torch.cuda.is_available() else "cpu")

model.to(device)

# 模拟输入数据

input_data=torch.randn(64, 1024).to(device)  # 批次大小为64

labels=torch.randint(0, 10, (64,)).to(device)

# 定义损失函数和优化器

criterion=nn.CrossEntropyLoss()

optimizer=optim.Adam(model.parameters(), lr=1e-3)

# 前向传播和损失计算

outputs=model(input_data)

loss=criterion(outputs, labels)

# 反向传播和参数更新

optimizer.zero_grad()

loss.backward()

optimizer.step()

print("数据并行处理的损失:", loss.item())

这种方式实现快，但调度压力集中在第0张卡，容易成为瓶颈。

如果单卡根本装不下整张网，就得把结构拆分到不同设备，并在正向时手动搬运张量。下面的例子把四层全连接轮流放在两块显卡上，输入和标签也分开放置。

[PRE2]python

class LargeModel(nn.Module):

    def __init__(self):

        super(LargeModel, self).__init__()

        self.fc1=nn.Linear(1024, 512).to("cuda:0")    # 将第1层分配到cuda:0

        self.fc2=nn.Linear(512, 256).to("cuda:1")    # 将第2层分配到cuda:1

        self.fc3=nn.Linear(256, 128).to("cuda:0")    # 将第3层分配到cuda:0

        self.fc4=nn.Linear(128, 10).to("cuda:1")     # 将第4层分配到cuda:1

    def forward(self, x):

        x=x.to("cuda:0")  # 输入放在cuda:0上

        x=torch.relu(self.fc1(x))

        x=x.to("cuda:1")  # 将输出移动到cuda:1

        x=torch.relu(self.fc2(x))

        x=x.to("cuda:0")  # 再次转移到cuda:0

        x=torch.relu(self.fc3(x))

        x=x.to("cuda:1")  # 最终转移到cuda:1

        return self.fc4(x)

# 初始化模型和数据

large_model=LargeModel()

input_data=torch.randn(64, 1024).to("cuda:0")       # 输入数据位于cuda:0

labels=torch.randint(0, 10, (64,)).to("cuda:1")     # 标签位于cuda:1

# 定义损失函数和优化器

criterion=nn.CrossEntropyLoss()

optimizer=optim.Adam(large_model.parameters(), lr=1e-3)

# 前向传播和损失计算

outputs=large_model(input_data)

loss=criterion(outputs, labels)

# 反向传播和参数更新

optimizer.zero_grad()

loss.backward()

optimizer.step()

print("模型并行处理的损失:", loss.item())

拆分后超大结构可以跑起来，但跨卡传输变多，代码维护也更费事。

工程里更主流的是分布式数据并行。每个进程独立运行，靠通信后端同步梯度，扩展性更好。启动前需要先告诉进程组在哪集合，比如主机名和端口。
