| 问题类型 | 典型现象 | 处理建议 |
| JSON 语法错误 | MCP 功能起不来，提示 malformed JSON | 1. 完整复制 mcp.json 的内容<br>2. 放到在线 JSON 校验工具里检查，重点看逗号缺失、括号不匹配等 |
| 鉴权失败 | 工具显示已连接，执行时报 401 Unauthorized 或 Invalid API Key | 1. 仔细核对 API Key / PAT 是否完整复制，注意前后是否带空格<br>2. 确认该密钥已分配所需权限<br>3. 检查密钥是否已过期 |

##### 4. MCP 安全使用规范与最佳实践

MCP 是连接 AI 与各类外部工具的桥梁，能显著提升开发效率，但能力越强越要守住安全边界。安全规范既关乎个人账号和数据，也关乎团队协作的稳定性。下面聚焦如何负责任地使用 MCP，让效率建立在可控之上。

- **凭证保密：** API Key 和 PAT 都是访问数字服务的核心密钥，严禁外泄或上传到公共网络。建议用环境变量保存凭证，不要硬编码进配置文件，从源头降低泄露风险。
- **最小权限原则：** 创建令牌时只赋予完成当前任务的最小权限，避免权限泛化，有效压缩安全事故的影响范围。
- **来源可信：** 仅从官方渠道或高度可信的社区安装 MCP 服务器。对来源不明的服务保持警惕，防止工具投毒等恶意行为，安装前务必核实发布方可靠性。
- **审慎授权：** 初次使用时不要无差别批准所有工具调用。认真阅读授权提示，弄清即将执行的命令和影响范围。只有在完全理解并信任其自动化流程后，再考虑开启自动运行。
- **配置整洁：** 定期清理 mcp.json，移除不再使用的服务器配置，减少攻击面和配置复杂度。

另外要严格校验和清理所有外部输入，防止路径遍历、非法字符等漏洞；构建细粒度的访问控制并保留完整审计日志，保证操作可追溯；在工具描述中明确输入输出边界，避免歧义，提升安全性和可用性。

只有把这些安全习惯落地，才能在提效的同时，真正守护个人与团队的安全。

#### 4.3.5 小结

掌握 MCP，就等于把 AI 从闲聊对象升级为实战帮手。你得到的不仅是一组工具，更是一套 AI 协同的工作方法论。由 MCP 串联的新工作空间，正等待你去探索与驾驭。

# 第5章 实战：从零到一打造习惯追踪器

理论只有在实践中才发光。现在让手里的工具为一个真实目标协同作战。

你会看到如何用 AI 头脑风暴把模糊想法演化为清晰蓝图，如何从零搭建数据库、设计认证、实现核心功能，还会学习接入邮件、文件存储等常见配套。每一步决策和代码，都是独立开发能力的积累。

## 5.1 蓝图：借助 AI 拆解产品规划

好点子像远山，壮丽却不易抵达。攀登的关键是先找到第一步的小径。我们将学习如何用 AI 把习惯追踪器的宏大概念拆成清晰可控的模块，稳健开启开发。

### 5.1.1 让 AI 担任产品搭档

每个产品都始于一瞬灵感。想要做习惯追踪器 App 的念头可能一闪而过，随之而来的是下一步怎么做的困惑。从模糊概念到可执行计划，对新手来说充满未知。

这时，一位随时待命、知识储备丰富且有创意思维的搭档会非常关键，而 AI 正能扮演这个角色。

本节让 AI 成为你的产品搭档，协助头脑风暴、理清思路、挑战假设，最终把灵光想法转化为清晰可落地的产品框架。通过对话共同搭建习惯追踪器的骨架。

结束时，模糊概念会变成坚实结构，明确要解决的核心问题、目标用户画像以及应用应具备的核心功能。

### 5.1.2 用 AI 做产品功能头脑风暴

新项目常卡在空白文档前。习惯追踪器需要什么功能——是简单的打卡，还是要图表、社交？对初学者容易陷入停滞。

这正是 AI 搭档发挥作用的时刻。要让 AI 输出有价值的内容，提问必须结构化。直接问需要什么功能会得到泛泛答案，需要像产品经理一样设计超级提示词。

#### 1. 打造一个超级提示词
有效的提示要包含角色、任务和格式。下面是可用范例：

> 请扮演一位资深产品经理。我正在构思一款习惯追踪器 App，请做全面头脑风暴，给出功能清单。
>
> 请分为两类：
>
> • 核心功能：构建最小可行产品所必需的基础功能
> • 创新/高级功能：未来可提升参与度和差异化的功能
>
> 每个功能用一句话说明作用。

#### 2. 解读 AI 的分析报告
输入该提示后，AI 会整合信息生成战略分析，通常包含以下部分。

- **市场与用户心理洞察：** 解析主流竞品逻辑。如 Habitica 用经验值和装备实现游戏化，Streaks 靠极简界面和连续计数迎合效率用户，Fabulous 则基于行为科学的习惯叠加引导渐进改变。底层支撑有尼尔·埃亚尔的上瘾模型、B.J. Fogg 行为模型、自我决定理论等。
- **功能规划要点：**
  - 核心功能约 9 项：账号管理、习惯创建、灵活计划安排、目标与习惯保持、每日签到、连续计数、基础提醒、进度可视化、数据隐私保护。
  - 创新/高级功能 20 余项，覆盖游戏化激励、全方位健康、社区问责、AI 个性化、环境计算集成五大方向。
- **战略建议：** 分三阶段推进。第一阶段发布 MVP 验证核心循环；第二阶段增加黏性功能；第三阶段用智能功能建立壁垒。

报告还强调要清晰价值主张，并从第一天就落实数据安全与透明合规。

核心结论：成功不靠堆功能，而要做战略取舍，把设计根植于动机科学，以用户价值和信任为核心分阶段推进。

> 注：完整报告较长，含对比表与优先级框架，已整理为电子文档，可在本书社区页面下载。

##### 3. 从功能列表到产品策略
AI 报告不仅是想法集合，更是制定策略起点。

它把现在要做和未来可做区分开。对初创产品，专注至关重要。核心功能是 MVP 基石，要先打磨简单易用，再考虑高级特性。

更深一层，它迫使我们思考要做哪种产品。Streaks 强调极简与健康数据集成，Habitica 把养成变角色扮演，Fabulous 更像健康教练。选择高级功能其实是在选择产品灵魂。

报告也揭示关键权衡：自动化追踪更省心但对隐私合规要求更高，手动记录更可控但增加操作成本。做什么与不做什么同等重要，需在便利、隐私、成本与合规间权衡。

### 5.1.3 五分钟实战：创建用户画像

明确做什么后，更关键的是为谁做。缺乏用户认知容易做错方向。这就需要用户画像。

##### 1. 理解用户画像
用户画像是为典型用户创建的半虚构档案，目的不是统计数据，而是培养同理心。把抽象用户具象化后，决策时自然会问这对李静会不会太复杂，避免自我中心开发。

##### 2. 创建用户画像
借助 AI 搭档快速生成画像。先用真实观察为种子引导 AI，避免空洞输出。

###### 第一步：提供画像模板提示词
> 请为一款习惯追踪器 App 创建 3 个用户画像，按模板填写细节。
>
> 模板：姓名与照片描述、个人简介与背景、基本信息、目标、痛点与挫败、动机、一句引言。
>
> 类型：高压在校大学生；工作繁忙的年轻职场人；重数据健身爱好者。

###### 第二步：检阅 AI 生成的用户画像
AI 生成三个典型角色，核心要点如下：

- 李静，20 岁大学生：学业压力大，需规律学习与健康习惯缓解焦虑，痛点是工具分散、中断后挫败感强。
- 王辰，28 岁市场经理：时间紧张，希望低负担管理个人时间，平衡工作与生活。
- 张伟，32 岁自由设计师：数据驱动的健身爱好者，需要深度分析与量化。

三人代表不同需求层级：李静要引导与情感支持，王辰要效率与灵活性，张伟要数据深度。MVP 优先满足李静和王辰，深度数据留待后续。

> 注：完整画像可通过社区页面下载。

##### 3. 让画像指导决策
有了具体用户，功能列表立刻有了试金石：

- 对李静，负担是否足够低，是否提供暂停模式避免考试周中断带来的挫败。
- 对王辰，关键操作能否快速完成，提醒能否灵活适配变动日程。
- 对张伟，是否提供基础可视化并为后续健康平台同步和自定义指标预留空间。

### 5.1.4 十分钟实战：撰写 PRD
头脑风暴和画像后，需要正式载体对齐认知——PRD。我们让 AI 担任 PRD 架构师输出专业蓝图。

##### 第一步：定义产品的核心宗旨
指令：
> 你好，PRD 架构师。请基于画像李静、王辰、张伟，为习惯追踪器 MVP 撰写产品宗旨，包含问题陈述、目标用户、核心价值。

AI 输出要点：

问题陈述：现代人自我提升时，养成习惯本身变成压力源。现有工具要么零散缺动力，要么复杂费精力，导致放弃。

目标用户：MVP 优先服务有追求但已不堪重负的成长型用户：需要结构化指导的大学生如李静，和追求效率与平衡的职场人如王辰；张伟这类深度数据用户后续再服务。

核心价值：让用户毫不费力看到进步。通过清晰结构降低心理负担，提供无摩擦一键追踪，以连续记录可视化建立可持续内驱力，帮助建立掌控感。

> 注：完整宗旨文档可在社区页面下载。

##### 第二步：用用户故事描述功能
把核心功能转为作为一个角色，我想要动作，以便于价值的格式，确保开发与真实需求挂钩。

指令：
> 架构师，请把 MVP 核心功能改写成用户故事，从王辰和李静视角出发。

AI 输出要点：

- 习惯创建与记录：作为王辰，我希望快速创建并灵活安排习惯，通过一键打卡提升效率；作为李静，我希望把目标具象化，同时追踪想养成和想戒掉的习惯。
- 每日提醒：作为王辰，我需要在众多工作通知中脱颖而出的有效提醒；作为李静，我需要友好温柔的提醒来关怀自己。
