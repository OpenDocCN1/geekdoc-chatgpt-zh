# 从零读懂决策树与K-均值：经典算法实战解析

[PRE0]

想构建一棵决策树，起点可以是任意属性。我们就以“天气”特征为切入点，来拆解“李强周六上午打不打网球”这棵树的生长过程。天气有晴、阴、雨三种取值，对应三个分支，直接把全量样本切分成了三个子集。接下来，我们逐个击破，看看每个子集里藏着什么规律。

[PRE1]

### 场景一：大晴天

数据里晴天出现了5回。这5个样本里，3次不打球，2次打球，类别不纯，必须继续分裂。仔细对比发现：那3次“不打球”全赶上“湿度很高”，而2次“打球”对应的都是“湿度正常”。至于温度和风力？在这儿完全没话语权。所以，晴天分支下直接按“湿度”二分：湿度高→全是No；湿度正常→全是Yes。干净利落。

[PRE2]

### 场景二：阴天

阴天共4条记录，李强**全去打球了**。4个样本全是Yes，纯度满分。直接得出结论：只要是阴天，直接打标签“Yes”，不用再管温度、湿度、风力了。这节点直接变成叶子节点收工。

### 场景三：雨天

[PRE3]

[PRE4]

雨天样本有5个，2个No、3个Yes，还是混着的。继续找规律：那2个“不打球”都碰上了“大风（风力强）”，3个“打球”都是“微风（风力弱）”。温度、湿度在这个子集里又失效了。于是雨天分支按“风力”再分一层：强→No；弱→Yes。

就这样，伴随层层剥洋葱般的分析，一棵分类决策树长出来了（见图8-7）。它长得像棵倒栽的树：矩形框是**决策节点**（属性），底部的标签是**叶节点**（分类结果），最顶端的“天气”是**根节点**，中间的“湿度”、“风力”是**内部节点**。每个节点按属性值发散分支，递归向下，直到节点下的样本“铁板一块”属于同一类，树就造完了。

[PRE5]

> **注**：换个属性当根节点，树长相全变。决策树算法的核心就是——**怎么选根、怎么选内部节点**。最经典的ID3算法，给出了一套标准的“选属性顺序”策略。

## 核心原则：让“纯度”飞速飙升

造树时，首要难题是：根节点选谁？下一层选谁？**核心原则只有一条：树越深，子集的“纯度”涨得越快。**

*   **纯度低** = 样本类别大杂烩，乱糟糟。
*   **纯度高** = 样本高度一致，几乎全是一类。

拿“天气”做根节点为例：分出的“阴天”子集纯度最高，4个样本全是Yes，不用再分了。

为了量化“纯度”，引入两个指标：**信息熵** 和 **基尼系数**。它们的逻辑一致：**纯度越高，指标值越低**。考虑到基尼系数算起来更友好，咱们下面就用它来演示节点选择。

### 知识小站：熵与信息熵

*   **熵**：衡量“无序度”。熵大=乱；熵小=序。
*   **信息熵**：熵论在信息领域的应用。随机变量里看不确定性；样本集里看**纯度**。

有了指标，原则就能硬核表述：**随着树加深，节点的信息熵或基尼系数要迅速下降。**

## 第三节 K-均值算法：聚类界的“重心迭代法”

K-Means，K=类别数，Means=均值。
核心流程：**预设K个初始质心 → 划分数据归属 → 算新质心（均值） → 迭代直到质心不动**。拿到最优聚类结果。

*   **K值**：你得先猜数据大概能分几类。
*   **质心**：每类的“聚类中心”，K定下了，初始质心就有K个。

[PRE13]
