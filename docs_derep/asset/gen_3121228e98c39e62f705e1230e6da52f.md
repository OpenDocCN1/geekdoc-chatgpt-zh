#### 2.3.5 第三方集成部署工具

在本地部署大模型时，除了直接用 Transformers 等基础库加载权重，还可以选用工程化程度更高、性能更强的第三方部署工具。这类方案在加载优化、推理加速、服务化封装与多模型托管上优势明显，特别适合对性能、维护性和并发要求较高的企业级场景。

##### 1. SGLang：智谱推出的 GLM 系列专用推理框架
SGLang 由智谱 AI 开源，专为 GLM 系列模型如 GLM-4、ChatGLM 设计，原生支持对话模板、多轮历史缓存、函数调用、结构化输出等能力。

SGLang 的核心特点如下。
- 与 GLM 模型结构高度契合，支持 multi-turn memory。
- 支持并发调度与动态上下文构建。
- 内置类 OpenAI 的 API 接口。
- 可结合 fastapi/uvicorn 快速上线服务。

##### 2. LMDeploy：国产模型轻量部署工具
LMDeploy 由昆仑芯与魔搭社区联合开发，旨在为国产开源大模型提供统一、简洁且高性能的部署方案。支持 INT4/INT8/FP16 等多种精度，并集成一键脚本、服务启动、QPS 压测等功能。

LMDeploy 的核心特点如下。
- 支持 Qwen、Baichuan、InternLM 等诸多国产模型。
- 原生适配 INT4 推理，显存占用更低。
- 提供完整的 CLI、Web UI、HTTP API。
- 支持多线程调度与批量推理。

##### 3. vLLM：高并发、OpenAI 兼容的服务部署利器
vLLM 由 UC Berkeley 发布的高性能推理引擎，具备动态批量调度、连续批处理、FlashAttention 2 等特性，并实现完全兼容 OpenAI API 协议的服务接口。

vLLM 的核心特点如下。
- 支持 Hugging Face 格式模型，如 LLaMA、Qwen、Baichuan 等。
- 实现高吞吐推理，可达数千 token/s。
- 支持流式输出。
- 原生兼容 chat/completions 接口格式。

##### 4. Ollama：开发者友好的一键本地部署平台
Ollama 面向开发者提供轻量部署方案，支持下载、管理与运行 GGUF 格式大模型，如 LLaMA 2/3、Mistral、Qwen、Phi 等，目标是让本地部署像使用 Docker 一样简单。

Ollama 的核心特点如下。
- 自动下载并注册模型，无需手动管理权重。
- 支持 Mac/Windows/Linux 系统。
- 内置 HTTP API 与 CLI，调用便捷。
- 支持 CPU 与 GPU，支持流式输出。
- 与 llama.cpp 体系一致，兼容 GGUF 格式。

以上工具覆盖了当前主流的本地大模型部署方案，满足不同模型结构、硬件资源与应用场景需求。本节对它们做了简要梳理，便于读者快速了解特性与用法。

##### 3. 模型格式支持
在选择部署方案前，需确认目标模型是否开放权重、支持的格式类型以及是否有量化版本。几类主流模型格式如表 2.5 所示。

表2.5 主流模型格式

| 格式类型 | 常见后缀 | 说明 | 适用部署框架 |
| :--- | :--- | :--- | :--- |
| 原始 PyTorch 格式 | .bin | Transformers 默认格式，文件较大，占用显存高 | Transformers/vLLM/TGI |
| 安全张量格式 | .safetensors | 安全、加载更快、支持并发加载的张量格式 | Transformers/vLLM/TGI |
| 量化格式-INT4 | .bin, .pt (压缩) | 通常通过 GPTQ/AWQ 等量化工具压缩后发布 | AutoAWQ/GPTQ-for-LLaMA/vLLM |
| 量化格式-GGUF | .gguf | llama.cpp/Ollama 使用的统一格式，支持 CPU/GPU 部署 | llama.cpp/Ollama/KoboldCpp |

选定大模型后，需要确认其是否开源、是否提供 Hugging Face 或 GitHub 地址、是否发布 INT4/INT8/GGUF 等版本、是否有官方或社区推荐的部署脚本或 Docker 镜像。

> 说明

模型的 GitHub 项目并非调用的必要条件。

对于发布在 Hugging Face 上的模型，开发者完全可通过 Transformers 接口加载权重并完成本地推理，无需克隆官方仓库。通常克隆官方仓库是为了获取以下附加内容。
- 模型推荐的依赖版本，如 requirements.txt。
- 官方提供的测试脚本或推理样例。
- API 服务部署方式，如 FastAPI、Gradio。
- Docker 容器镜像与部署指令。
- 与模型结构高度耦合的工程化调用逻辑，如多模态组件、定制 tokenizer。

但如果你已熟悉 Hugging Face 的调用方式，并清楚如何配置依赖环境，完全可以脱离 GitHub 项目，仅下载模型权重与 tokenizer 即可完成调用与部署。这种方式更轻量、灵活，适合有经验的开发者快速集成到现有系统。
