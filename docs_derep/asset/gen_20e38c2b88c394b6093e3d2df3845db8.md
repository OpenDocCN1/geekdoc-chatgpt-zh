### 2.1 为什么分块非常重要

咖哥特别认同维基百科里对分块的解释，这个定义不仅适用于 RAG，也能解释认知心理学现象。维基百科写道：“分块是指把若干小的信息单元组合成块，从而改善短期记忆，绕开工作记忆容量的限制，让记忆更高效。”

把大块数据拆成更小、语义完整的片段，其中一个原因就是能更好地发挥大模型的非参数记忆优势（见图2-3）。一方面，检索更准，因为系统可以更精细地匹配关键词和语义，提升搜索效果；另一方面，模型跑得更顺，过长文本容易让大模型吃力，分块后理解和响应效率都会提升，答案也更靠谱。图2-3 长文本的分块

所以分块的核心目标，是让进入向量化的内容噪声尽量少，同时保持语义连贯性。这是构建 RAG 系统时必不可少的预处理环节。

另外，分块也是因为大模型上下文窗口有限。

#### 2.1.1 上下文窗口限制了块最大长度

RAG 运行需要两类模型协同：嵌入模型和生成模型，它们各自都有上下文窗口上限。

文本要先过嵌入模型生成向量，所以必须服从嵌入模型的窗口限制。不同模型上限不一样，商业模型一般在官网文档里说明，开源模型则常在 Hugging Face Hub 的模型卡 Model card 中给出，如图2-4 所示。

确定好嵌入模型后，就能得出分块长度的上限，按 token 算而非字符或单词。一般嵌入模型的窗口限制在 8000 token 以内。

检索到的块会作为上下文塞进生成模型的提示词里生成答案，所以所有检索块的总长度必须控制在生成模型的窗口之内。小模型处理的量更少，实际使用时还要留出空间给系统说明、角色设定或少量示例。因此，检索来的知识上下文最好越精简越好。必要时需要压缩提示词，具体方法第 7 章会介绍。

随着模型升级，这个限制在减弱，很多新模型支持超大窗口，比如 GPT-4o 可达 128 000 token。但即便窗口很大，用超大块仍需谨慎，过多的冗余会拖累对话的相关性。

#### 2.1.2 分块大小对检索精度的影响

嵌入模型给出了单块 token 上限，不等于我们就要用满。实际操作中，为了检索更准，通常会把文本切得更细。

##### 1. 分块与嵌入过程

先剧透一下嵌入向量是怎么生成的。大多数嵌入模型采用仅编码器 Transformer 架构，通过池化层把输入文本映射成固定维度向量，例如 768 维，如图2-6所示。图2-6 文本嵌入的生成过程（平均池化）

[PRE7]

先对输入文本分词，并在开头加上特殊标记 [CLS]；随后 Transformer 为每个 token 生成向量表示。再根据下述一种池化方式，把所有 token 向量压缩成一个向量，得到最终的文本嵌入。池化本质上是一种压缩。

- **CLS 池化**：直接用 [CLS] 标记的向量来表征整个序列。
- **Mean 池化**：把所有 token 向量的平均值作为序列表示。
- **Max 池化**：取各维度上最大值来代表整个序列。

所以输入是 10 个词的句子还是 1000 个词的段落，输出向量的维度都一样。

这个过程必然有信息损失。块太大时，向量会过于概括，关键细节容易被抹平。因此不应把分块大小直接设为嵌入模型的最大承受值。

##### 2. 分块与主题稀释

一块文本过大时可能包含多个主题，部分相关部分无关。单一向量要兼顾多个主题就会稀释焦点，检索精度自然下降。

小块能保持上下文更聚焦，更容易精准匹配。把文档拆成有意义的小段，检索器就能更准确地定位到具体片段或事实，从而提升 RAG 性能。

举个例子，假如山西文旅建了一个涵盖全省景点活动的库。如果一个块里混写了‘五台山、云冈石窟、太原游乐场’，用户问‘带小朋友玩适合去哪’时，这个综合块的检索得分可能不高。

但如果把每个景点单独成块，比如‘五台山：佛教名山’、‘云冈石窟：唐代造像代表’、‘太原游乐场：暑期攻略’，RAG 就能更准确地命中相关信息，避免无关内容干扰相似度计算。

不过块也不能太小。比如用户问‘太原游乐场几点开门’，若把游乐场介绍和开放时间拆到不同块，检索结果里可能混进其他景区的开放时间。因为缺乏元数据，时间与景区之间的关联就断开了。

#### 2.1.3 分块大小对生成质量的影响

从生成效果看，即便新模型窗口很大，把窗口塞满也容易出现‘大海捞针’现象，即关键信息淹没在大量文本中。RAG 领域称之为 lost in the middle，信息越多越难提取重点。

以医疗问答为例，若块过大，用户问‘高血压患者能吃哪些降压药’，系统可能返回一堆与高血压相关的杂讯，包括诊断、治疗方案、用药禁忌等，不仅阅读负担重，还会掩盖关键答案。

采用合理分块，把知识库拆成主题清晰的小块，比如‘高血压：常用药物’、‘高血压：用药禁忌’、‘高血压：生活方式建议’，每块控制在约 500 字符左右。检索就能更精准地抓到每个主题的核心，并传给生成模型，形成准确回答，如‘常用降压药有 A 药和 B 药，需在医生指导下服用’。

小冰：那块能小到什么程度，又不丢上下文？

咖哥：这得看文档类型和项目目标。分块逻辑和大小要结合具体场景，通常需要实验调优。如果只是想定位到文档层面，块可以大一点甚至不分块；如果要精确定位到句子或段落，就得切得更细。一般来说，约 500 token 是一个不错的起点。
