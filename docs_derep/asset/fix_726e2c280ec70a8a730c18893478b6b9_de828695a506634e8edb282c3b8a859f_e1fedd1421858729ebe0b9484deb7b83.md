> **说明**

选用 Parquet 保存图谱的原因

(1) 存储效率突出。
- 图谱数据本质结构化，包含大量实体、关系与向量。
- 列式存储让磁盘占用明显下降，访问速度同步提升。

(2) 加载速度快。
- 问答阶段需要把实体、关系、向量迅速载入内存。
- Parquet 只加载所需列，避免全表扫描。

(3) 生态兼容度高。
- Parquet 为开放格式，被 Pandas、Spark、Hadoop 等广泛支持。
- GraphRAG 在 Python 环境下可直接通过 Pandas 读取。

#### 4.3.4 GraphRAG 问答流程实现

索引构建完成并预览表格后，进入第二阶段——查询。目标是利用图谱、社区报告、实体嵌入等产物，结合大模型产出高质量问答。

##### 1. 导入核心模块与关系组

先导入 GraphRAG 提供的核心模块，大致分为四类：索引数据载入、向量存储、语言模型调用、本地检索与问答。运行：

[PRE7]

模块说明如下。

1）与索引器相关
索引数据读取器 read_indexer_*：从构建阶段生成的 .parquet 文件读取实体、关系、社区报告、文本单元。
实体语义嵌入处理器 store_entity_semantic_embeddings：将实体描述向量化后写入向量库。

2）与 LLM 相关
语言模型调用接口 ChatOpenAI、OpenAIEmbedding：用于问答交互与嵌入生成。

3）与本地搜索相关
本地搜索模块 LocalSearch、LocalSearchMixedContext：基于图邻接与实体嵌入实现本地化问答。

4）与向量存储相关
向量数据库接口 LanceDBVectorStore：负责语义向量的持久化与快速检索。
