## 2.4 本章小结

本章从自然语言协同到标准化通信，从底向上梳理了智能体协同的工作脉络，形成了完整的通信认知框架。

自然语言协同部分，核心是传统刚性通信向自然语言通信的范式迁移。基于 LLM 的智能体可用人类语言灵活交互，打破了 ACL 协议的束缚，同时需要 Prompt 链、上下文管理和 System Prompt 等手段保障规范与可靠。Prompt 链把复杂任务拆成关联步骤，支持顺序、分支、聚合等模式；上下文管理以滑动窗口、摘要压缩、检索增强应对窗口限制；System Prompt 用于定义角色与行为边界。

协同模式部分，本章覆盖了四种主流做法。顺序协同适合依赖明确的流水线，职责清晰但难以并行；并行协同让多个智能体同步执行，可明显提速，但需处理结果合并与容错；Manager-Worker 层级协同引入管理层，实现智能调度与动态分配；竞争协同让多智能体各自出方案再评选，提升决策多样性。

协议层面，MCP 解决了智能体与工具数据的连接难题，终结了 M×N 集成困境并获广泛采纳。A2A 围绕 Agent Card、Task、Message 构建了跨体交互规范，主攻协作通信。ACP 作为 IBM 的轻量方案已并入 A2A，推动标准统一。实践中 MCP 负责赋能，A2A 负责协作，相互补充。

# 第3章 基于LLM的Agent群落协同策略

在智能体群体里，协同策略是把个体智能连成群体智能的枢纽。传统多智能体系统依赖预设规则和固定分配算法，而 LLM 驱动的群体则走向语言化的协同：任务理解、规划推理与动态调整都通过语言完成。本章围绕语义理解与生成能力，讨论智能化任务规划、能力匹配、动态重规划和故障恢复的实现思路。

## 3.1 Agent的任务规划与分配

【学习目标】

- 1) 弄清零样本任务拆解的原理和具体做法

LLM 驱动的规划与分配是群体协同的核心。系统通过语义理解把复杂需求自动拆成可执行子任务，再依据各智能体的自然语言能力描述完成智能匹配。

### 3.1.1 零样本任务分解：让LLM自动拆分任务

任务分解是协同的起点。传统做法多依赖专家制定的规则模板或需大量标注的强化学习模型，前者覆盖面窄，后者成本高。零样本任务分解利用 LLM 预训练积累的推理能力，无需额外训练即可完成智能拆解。

其思路源自“分而治之”。面对复杂需求时，LLM 先用语义理解提炼关键要素，再分析要素间的依赖关系，最后输出结构化子任务序列。整体可分为理解任务、分析依赖、生成计划三个阶段。

理解阶段，LLM 解析用户自然语言，提取目标、约束和期望输出。例如“为科技公司制定下一季度市场营销方案”会被识别为综合策划，涉及市场分析、竞品研究、渠道选择、预算规划等多个维度。
