### 7.4 工作流实践

聊天助手主要依赖大模型本身的能力，面对需要更深专业知识、复杂逻辑推理或外部系统联动的任务时，单靠模型往往力不从心。工作流能够把复杂问题拆解为多个步骤或子任务，每个环节由更匹配的组件承接。例如部分环节需调用外部 API 获取实时数据，部分环节需查询数据库，或需按业务规则做复杂决策。通过有序串联不同处理单元，复杂问题也能得到有效解决。

#### 7.4.1 工作流组件简介

工作流包含两大核心要素：节点和变量。节点是流程的骨架，通过串联不同功能的节点实现一系列操作；变量用于连接前后节点的输入输出，支撑流程中的复杂逻辑，主要分为系统变量、环境变量和会话变量。

#### （1）变量
变量可视作各节点的输入与输出载体。大多数节点都有输入输出，但不同节点所需信息和产生结果各不相同，这些动态信息即为变量。变量按数据类型可为图片、文本、字符串、数字等，作为动态容器在节点间传递与复用，实现信息的灵活流动。

按作用划分，变量分为系统变量、环境变量和会话变量。
系统变量是工作流应用内预置的全局参数，可被各节点读取，命名均以“sys”开头。环境变量用于存放敏感信息，如运行工作流时所需的 API 密钥、数据库密码等，信息以配置形式保存，便于多环境共享。会话变量专用于对话场景，可在同一 Chatflow 会话中临时保存特定信息，并在多轮对话中持续引用，如上下文、用户上传的文件、对话中输入的偏好等。

#### （2）节点
为应对自动化和批处理的复杂业务，工作流提供丰富逻辑节点，如代码执行、条件分支、模板转换、迭代等，并支持定时和事件触发以构建自动化流程。Dify 节点清单见图 7-25。

### 7.5 AI Agent 实践

无论是知识问答助手还是工作流，通常都局限于静态知识库或预设流程，缺乏动态调用外部工具的能力，即使查询某地实时天气也无法实现。

基于 FAQ 的客服系统或静态文档问答依赖预存知识，无法获取天气、实时价格、物流等外部实时数据。例如用户问“北京今天天气如何”，传统系统只能返回库内天气条目，无法调用天气 API 获取最新数据。

工作流虽可执行固定步骤，但规则需人工预设，难以按动态需求灵活调用工具。例如处理用户投诉时需同时查询订单状态、调用客服工单系统并生成退款凭证，传统流程易因接口不兼容或僵化而失败。

为弥补上述不足，工具调用应运而生。

#### 7.5.1 基于 Function Calling 调用外部工具

AI Agent 通过动态调用外部工具链并结合大模型决策能力，解决了传统系统工具使用的静态僵化问题。其价值在于把大模型的理解能力与执行能力结合，从“回答问题”迈向“解决问题”。

典型流程如下。
- ①意图识别：大模型解析用户输入，识别出“查询天气”意图。
- ②工具调用：Agent 调用天气 API，传入参数“北京”。
- ③数据处理：将 API 返回的 JSON 数据解析为结构化信息。
- ④结果生成：大模型据此生成自然语言回答，如“北京当前 22℃ 多云，未来两小时无降水”。

为实现模型调用外部工具，OpenAI 提出 Function Calling。该机制允许开发者将大语言模型与外部函数或工具集成，模型可理解用户请求并生成调用参数，从而完成更复杂动态任务。其原理与流程如图 7-28 所示。

[PRE13]

图 7-28 Function Calling 的原理与流程

- ①理解用户请求：识别出需要调用外部函数的部分。
- ②生成函数调用参数：依据请求生成外部函数所需参数。
- ③触发外部函数：开发者按模型生成的参数调用外部函数，并将结果回传。

#### 7.5.2 基于 MCP 调用外部工具

Function Calling 虽能让大模型调用外部工具，但存在局限且门槛较高。因缺乏统一标准，各家函数定义格式不一，如图 7-29 所示。不同 LLM 供应商接口差异导致多模型适配成本高，且通常依赖特定平台或框架，通用性受限。扩展性也有限，新功能需手写新函数并保证交互兼容。

[PRE14]

为解决这些问题，MCP 模型上下文协议应运而生。

MCP 由 Anthropic 提出，旨在统一大模型与外部数据源、工具之间的通信方式。借助 MCP，开发者能以统一方式将各类数据源和工具接入大模型，提升实用性和灵活性，如图 7-30 所示。MCP 使 AI 应用可安全访问本地和远程数据，提供连接万物的接口。

[PRE15]

MCP 的核心架构如图 7-31 所示。MCP 采用客户端-服务器架构，将 AI 应用与数据、工具无缝对接，消除数据孤岛。除客户端、服务器和数据资源外，还定义了工具、提示及各类消息类型以规范通信。其核心组成包括：

- MCP Host。这是承载 AI 应用的前端，如 Claude 桌面、IDE 或其他 AI 工具。Host 内置 MCP Client，负责与 MCP Server 建立 1:1 连接，发送请求并接收响应。
- MCP Server。轻量级服务端程序，通过统一的 MCP 向客户端暴露特定功能，如数据访问、工具调用、提示信息等，每个服务器可连接不同数据源或外部服务。
- 数据源/资源。MCP Server 可访问本地数据源，如文件、数据库、服务等，也可通过 Web API 获取远程外部数据，使 AI 应用能直接访问互联网信息。

### 8.1 企业超级员工

对新员工或业务不熟悉的员工而言，快速获取知识并完成任务是高效工作的关键。然而企业知识来源不清晰，员工往往无从查证，而传统人际请教方式效率有限。

- 信息获取效率低：新员工需反复寻找对接人，对方可能因繁忙或知识碎片化无法给出完整答案，导致问题解决周期拉长。
- 依赖人工经验：关键信息分散在文档、邮件或老员工记忆中，难以系统调用，且易因人员流动造成知识断层。
- 任务执行门槛高：复杂流程如跨部门协作、数据填报需人工协调，耗时且易出错。

若企业拥有一位对内部信息了如指掌的超级员工来帮助处于迷茫期的员工，将会极大提升效率。该超级员工不仅能解答疑问、提供即时准确的信息支持，还能主动协助处理内部事务，显著提高工作质量。

企业超级员工可全天候工作，随时为员工提供帮助，弥补人力资源缺口，使团队更聚焦价值创造和创新，成为企业不可或缺的助手，助力企业在市场竞争中保持领先。
