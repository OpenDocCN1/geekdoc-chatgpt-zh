## 9.2 Plugin 的物理结构

Plugin 本质上就是一套按规范组织的目录，多数情况放在 Git 仓库里管理，真正的身份凭证是 .claude-plugin/ 子目录下的 plugin.json 清单。

这里有个需要格外留意的物理限制：清单文件 plugin.json 只能放在 .claude-plugin/ 这个固定子目录里，其余所有业务目录 commands、agents、skills、hooks 以及 .mcp.json 配置，都要直接平铺在 Plugin 根目录下。

| 字段 | 必需 | 说明 |

| :--- | :--- | :--- |

| name | 是 | Plugin 的唯一标识符，用于安装命令及内部引用 |

| version | 是 | 语义化版本号（SemVer） |

| description | 是 | 简短描述，将显示在 Plugin 列表中 |

| author | 否 | 作者个人或团队名称 |

| repository | 否 | 源代码仓库地址 |

| license | 否 | 开源许可证协议 |

| keywords | 否 | 用于检索的搜索关键词 |

其中 name 最值得强调。它既是展示用的名称，也决定了后续的命名空间。安装完成后，该 Plugin 内部的所有组件都会自动加上此名前缀，以防止与其他插件冲突。所以挑选名称时要追求清晰简短且不易撞车。推荐风格如 react-workflow、pr-reviewer、db-tools；不建议使用 my-plugin 这样过于宽泛的、tools 这类极易重名、或 v2 这种带版本号无意义的名称。

### 9.3.4 存储位置

默认情况下，安装好的 Plugin 会保存在 ~/.claude/plugins/ 目录。可通过设置 CLAUDE_PLUGIN_ROOT 环境变量来自定义存放路径。

在企业环境里，管理员可以把该路径指向共享网络存储，实现插件的统一部署、集中管控与分发。

## 9.4 命名空间：多 Plugin 共存

当多套 Plugin 同时存在且出现同名 Skill 或 Command 时怎么办？系统通过命名空间机制自动化解冲突。

所有由 Plugin 提供的组件都会被赋予 plugin-name:component-name 的全限定名，保证全局唯一。以 react-workflow 安装后为例：

- 原来的 review 命令变为 /react-workflow:review。
- 原来的 code-reviewer 技能变为 react-workflow:code-reviewer。
- 原来的 security-scanner 智能体变为 react-workflow:security-scanner。

在没有冲突时，直接使用简短名称如 /review 即可，Claude Code 自动解析到唯一项。只有检测到重名时，才需要使用完整限定符如 /plugin-a:review 来明确指定。

该机制的意义在于：团队可以放心组合多个插件，无需提前协调命名；开发者也不必刻意避开他人命名，降低维护负担。

#!/bin/bash

# Bash 命令安全拦截脚本

# 用于在 Claude Code 执行危险命令前进行阻断

INPUT=$(cat)

COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

DANGEROUS_PATTERNS=("rm -rf /" "rm -rf ~" "sudo rm" "> /dev/" "chmod 777")

for pattern in "${DANGEROUS_PATTERNS[@]}"; do

    if echo "$COMMAND" | grep -qF "$pattern"; then

        cat << EOF

{"decision": "deny", "reason": "Blocked dangerous pattern: $pattern"}

EOF

        exit 1

    fi

done

exit 0
