# 第二节　智能网联车辆的关键原则

## 简介

随着车辆智能化程度提升，汽车行业的网络安全风险日益凸显。无论是把汽车改造成可联网热点，还是搭载数百万行代码实现全自动驾驶，车辆都比以往更容易遭受黑客攻击与数据窃取。关键在于，参与制造供应链的各方，从设计师、工程师到零售商与高层管理者，都需要统一的指引来支撑全球产业。交通部与国家基础设施保护中心共同制定以下核心原则，供汽车行业、网联自动车辆及智能交通系统生态圈及其供应链参考。

## 主要内容

### 一、智能交通系统与网联自动车辆系统安全原则

#### 原则 1：组织性安全由董事会层面确定、管理和促进。

1.1 制定与组织整体使命和目标相一致的安全规划。

1.2 董事会须对产品与系统安全承担个人责任，并在组织内部进行清晰、恰当的授权。

1.3 强化安全意识并开展培训，使安全文化深入人心，确保每位员工明确自身在系统安全中的角色与责任。

1.4 新设计必须融入安全考量。开发安全可靠的系统时，应遵循安全设计原则，并将物理、人员与网络安全整合至产品与服务开发全过程。

#### 原则 2：安全风险包括供应链特有风险须得到恰当评估与管理。

2.1 组织应了解当前威胁与工程实践，以便降低其对项目的影响。

2.2 与合格第三方合作，提升风险意识并制定应对方案。

2.3 建立内部安全风险评估与管理流程，对安全风险包括网络安全风险进行识别、分类、排序与处置。

2.4 通过设计规范与采购实践，识别并管理供应链、分包商与服务提供商特有的安全风险。

#### 原则 3：组织需建立售后服务与事故响应机制以保障系统全生命周期安全。

3.1 制定涵盖必要售后支持的规划，确保系统在整个生命周期内保持安全。

3.2 建立事故响应机制，明确如何应对安全相关资产、非安全相关资产及系统故障的潜在危害，并将受影响系统恢复至安全可控状态。

3.3 建立可识别关键漏洞的机制，并配备相称的缓解措施。

3.4 确保系统支持数据取证，能够恢复具有法律证明力且可唯一识别的数据以查明网络安全或其他事件原因。

### 二、智能交通系统与网联自动车辆系统设计原则

#### 原则 4：所有组织包括分包商、供应商与第三方应协同提升系统安全性。

4.1 各组织须对其流程与产品安全提供保障，可通过独立验证或认证实现。

4.2 供应链中所有物料的真实性与来源须可验证。

4.3 各方应共同制定系统与外部设备、连接点、服务、运营或控制中心安全交互的方案，参考行业标准与数据要求。

4.4 识别并管理外部依赖性。当传感器或外部数据准确性对自动化功能至关重要时，应采取措施降低依赖。

#### 原则 5：系统设计采用纵深防御方法。

5.1 系统安全不应依赖单点故障或不透明的安全措施，或在受损后无法及时调整的项目。

5.2 安全架构应采用纵深防御与分段技术，通过监控、告警、隔离存储、减少攻击面、信任边界等补充控制降低风险。

5.3 设计控制应基于整体系统，规范跨信任边界交易，包括最小访问原则、单向数据控制、全盘加密及减少共享存储。

5.4 包含云端服务器的远程与后台系统应具备适当保护与监控以防未授权访问。

#### 原则 6：对所有软件全生命周期进行安全管理。

6.1 采用安全编码实践，适度管理来自已知与未知漏洞的风险，建立代码管理、审计与测试体系。

6.2 能确定所有软件、固件及其配置状态，包括组件版本、变更与配置数据。

6.3 可安全可靠地更新软件，并在损坏时恢复至已知良好状态。

6.4 软件应采用开放设计实践，尽可能使用同行评审代码，源代码可在适当情境下共享。

#### 原则 7：数据的存储与传输安全可控。

7.1 数据在存储与传输时须足够安全，仅允许预期接收者或系统功能访问，传入通信须经验证后方视为安全。

7.2
