### 3.2.5　CO-STAR 框架

CO-STAR 由六个抓手构成。

（1） 情境 context：把任务相关的背景讲透，细节越饱满越好，方便模型把握关联，避免跑偏。
（2） 目的 objective：讲清模型具体要干什么，让方向不含糊。
（3） 呈现风格 style：规定回应的表达方式。
（4） 语调 tone：设定情绪基调，确保输出的情感色彩符合预期。
（5） 读者 audience：明确内容面向谁，避免生成目标读者难以理解的信息。
（6） 输出 response：锁定格式与结构。可要求 JSON 输出便于程序处理，或按金字塔、列表等常见结构组织。

## 3.2　提示词框架

提示词框架是按模块、按场景标准化的建模模板，能帮助使用者更快搭出精准指令。善用框架可减少歧义，提升完成效率，覆盖复杂需求。

### 3.2.1　提示词框架简介

用好框架能带来三个效果。

（1） 帮模型跳出理解盲区。大模型的产出质量很大程度上取决于输入的清晰度，结构化信息能让模型更准确认知意图。
（2） 压缩试错成本。统计显示，采用框架后人与模型间的对话轮次明显减少。
（3） 贴合专业场景。各领域沟通逻辑不同，框架可提供场景化解法。

用提示词框架要把握以下五点。

（1） 先定任务属性。按内容创作、数据分析、角色扮演等匹配框架，创意类更适合 BROKE，技术类更适合 ICIO。
（2） 逐项补全信息。以 CRISPE 为例，“能力与角色”填“资深营养师”，“背景洞察”填“用户是健身新手，需制定减脂食谱”，“风格”填“步骤清晰并附热量计算”。
（3） 反复打磨描述。依据模型输出对模糊表述做优化，如把“正式风格”细化为“商务报告风格”。
（4） 避免堆砌信息。框架并非越复杂越好，需按任务复杂度取舍。
（5） 跨框架拼装。可混用不同框架的模块，如把 BROKE 的“进化”与 CRISPE 的“能力与角色”结合使用。

### 3.2.2　ICIO 框架

ICIO 包含四个核心部分。

（1） 指令 instruction：要求模型执行的核心动作或命令。
（2） 情境 context：为模型提供完成任务所需的环境信息、背景知识等。
（3） 输入数据 input data：需要模型处理和操作的具体素材或数据。
（4） 输出指引 output indicator：明确规定输出结果的格式、风格、长度、结构等。
