## 第 14 章 LangChain 核心生态全览

本章先介绍 LangSmith，再介绍 LangServe，最后说明如何用 LangGraph 构建有状态、多角色应用。

### 14.1 LangSmith 监控评估平台

LangSmith 是一个专为生产级 LLM 应用监控与评估而设计的应用库，可独立于 LangChain 运行。它主要包含五大模块。

1. 监控模块

LangSmith 帮助团队深入了解 LLM 应用的行为。通过监控可快速定位：

- 异常结果产生的根因。
- 代理陷入循环的原因。
- 链执行缓慢的原因。
- 各步骤中代理消耗的 Token 数量。

2. 评估模块

LangSmith 助力开发者掌握 LLM 应用性能变化。它接收链、代理或模型的输入输出集合，通过与参考输出比较，如字符串匹配或 LLM 评判，或校验输出是否为有效 JSON 等方式，返回评估分数。同时支持基于数据集的全量评估。

3. 自动化生产

上线后，LangSmith 提供自动化工具，帮助团队管理关键数据点、扩充基准数据集、记录追踪信息并深入分析重要数据。同时给出应用性能的高层概览，确保在规模化下表现理想。

4. 指令中心

Prompt Hub 提供指令的发现、共享与版本控制，方便管理和优化 LLM 提示词。

5. LangSmith 代理

LangSmith 代理可作为 LLM API 的替代层，使用简单、易配置。

- 易用：只需修改 LLM API 的 URL 即可集成，无需大改应用。
- 缓存支持：支持请求/响应缓存，含流式处理，减少 LLM API 调用次数，提升响应速度。
- 最小开销：基于 Nginx 反向代理，最小化开销，保证请求高效传递。
- 流式支持：支持流式传输 LLM API 响应，实现即时处理。
- 可选追踪：可通过 LangSmith 追踪 LLM 调用，无需改动应用配置。

### 14.2 LangServe API 快速部署

LangServe 能将 LangChain 可运行对象和链快速部署为 REST API。它集成 FastAPI 并使用 Pydantic 做数据校验。核心特性如下：

- 自动推断 LangChain 对象的输入输出模式，并在每次调用时强制校验，同时给出详细错误信息。
- 提供 JSONSchema 和 Swagger 文档页面，方便理解与使用。
- 高效支持 invoke、batch 和 stream 端点，应对大量并发请求。
- 配备 stream_log 端点，可流式输出链/代理的中间步骤。
- 自 0.0.40 版本起新增 astream_events，简化流式传输，无需解析 stream_log。
- 附带 Playground 页面，展示流式输出与中间步骤，便于调试测试。
- 可选集成 LangSmith 追踪，只需添加 API Key 即可启用。
- 基于 FastAPI、Pydantic、uvloop 和 asyncio 等经过实战检验的开源库构建。
- 提供客户端 SDK，支持像调用本地 Runnable 一样调用 LangServe 服务，或直接调用 HTTP API。

### 14.3 LangGraph 构建状态化多角色应用

本节介绍 LangGraph、流式处理、执行图可视化，以及节点与边的创建、入口点和结束点的设置。

#### 14.3.1 LangGraph 核心原理

LangGraph 是 LangChain 的库，专为构建有状态、多角色应用而设计。它扩展了 LangChain 表达式语言，使多条链或多角色能够在多步计算中循环协同。

LangGraph 的核心是为 LLM 应用引入循环机制。

> 提示 LangGraph 并非为有向无环图 DAG 工作流专门优化。若需构建 DAG，建议直接使用 LangChain 表达式语言。

循环在智能体行为中至关重要，例如在一个循环中调用 LLM 以决定下一步行动。

LangGraph 通过引入“状态图” StateGraph 的概念，改进了原 AgentExecutor 的黑盒调用。它用图的形式，即节点和边，精确定义基于 LLM 的任务细节如 RAG、代码生成等。图编译后生成应用，执行过程中 LangGraph 会维护一个随节点跳转不断更新的对象。

> 提示 LangChain 表达式语言便于定义链，但在循环支持上不足，LangGraph 正好弥补了这一点。

1. LangGraph 基础概念

（1）StateGraph：状态图的基础类，构成图的核心框架。
（2）Nodes 节点：状态图的重要组成，可为可调用函数、链或代理。节点 END 表示任务结束。
（3）Edges 边：连接节点，表示跳转关系。包括三类：
- Starting Edge：特殊边，标识任务起点，无前置节点。
- Normal Edge：普通边，表示节点间顺序执行。
- Conditional Edge：条件边，根据上游结果和预设条件函数决定下游节点。

2. LangGraph 使用场景

（1）异步工作流。建议将节点默认设为异步，以优化执行效率。
（2）流式传输令牌。语言模型响应较慢时，可将令牌流式传输给用户，保证实时流畅交互。
（3）持久性存储。内置持久化能力，支持保存图状态并在需要时恢复。
（4）人机交互循环。支持在特定节点前进行人工审核，保证流程准确性。
（5）图形可视化。提供图形输出与可视化方法，支持 ASCII 艺术和 PNG 图像。
（6）时光旅行。允许跳转到图执行的任意点，修改状态后重新执行，对调试和面向用户的工作流非常有用。
