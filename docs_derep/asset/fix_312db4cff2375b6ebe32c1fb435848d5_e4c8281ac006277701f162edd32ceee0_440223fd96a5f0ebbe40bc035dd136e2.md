大模型与知识图谱正在形成双向增强的关系

近几年，生成式大模型和知识图谱的结合成为人工智能研究的重要趋势。图谱以结构化方式承载事实与逻辑关系，让模型输出更具可追溯性和可靠性；大模型则以强大的语言理解和生成能力，支撑信息的抽取、补全与推理。比如借助大模型可以批量抽取数千条 APT 相关的要素来搭建威胁情报图谱，结合图神经网络实现攻击链推演，或通过 RAG 让安全问答的回答更可信。整体上，知识图谱正从人工手工构建走向 AI 驱动的自动构建，组织效率与价值密度同步提升。

**11.1.2**

**实体识别与关系抽取的基础认知**

Named Entity Recognition，即实体识别，是构建图谱的起点。它的核心工作是从自然语言文本中挑出具有明确语义指向的单元，例如人名、地名、机构名、事件、物品等。经过分词、词性分析、上下文建模和语义分类，文本中的普通字符串被转化为可供模型使用的结构化单元，使模型能够回答“是谁”“在哪”“是什么”等关键问题。

在图谱体系里，NER 是产出 entity-relation-entity 三元组的前置环节，其准确度直接牵动后续的关系抽取、实体对齐、知识融合以及推理效果，因而被视作现代知识工程的关键枢纽。随着大模型发展，NER 从基于规则和手工特征，转向深度学习与提示词引导的智能抽取，在长文本中的泛化与理解能力显著增强。图 11-2 展示了实体识别和关系抽取的构建流程及实例。

[PRE0]

图 11-2 实体识别和关系抽取的构建流程及实例

设计合理的实体类型体系是 NER 的核心，涉及界定哪些对象属于实体、如何分类以及类间如何关联。通常将类型划分为通用类如人物、地点、组织，以及行业类如恶意文件、攻击组织、法律条目、历史古迹。在本体层，实体类型不仅用于标注，还起到限制关系合法性的作用，例如“人物→使用→武器”属于合理表达，而“地点→食用→人物”则违反语义。良好的类型体系能提升识别精度并减少融合冲突，因此本体驱动的建模是关键步骤，也是大模型借助提示词划定识别边界的重要依据。

技术演进方面，NER 经历了规则匹配、统计学习、深度学习到提示词增强 Prompt-based NER 的阶段。早期方案依赖人工规则或词典，在领域复杂、表达多样时难以复用；BiLSTM-CRF、BERT-NER 等深度方法借助上下文编码大幅提升精度，但跨域迁移与小样本成本仍高。大模型带来新范式：依靠上下文理解与任务描述提示，可在零样本或少样本条件下识别长文本中的复杂实体关系，尤其适合威胁情报、史料、小说等高异质文本。本书后续将结合 Few-Shot+Prompt Engineering，让 CodeBuddy 自动抽取复杂文本中的实体，为图谱提供优质输入。

示例：
输入： “孙悟空与唐僧一路向西，途经火焰山时与红孩儿交战。”
识别结果：
人物： **孙悟空、唐僧、红孩儿**
地点： **火焰山**
这些节点随后进入图结构。

Relation Extraction，关系抽取，任务是从文本中挖掘实体间的语义联系，是把节点连成网络的关键。与 NER 回答“是什么”不同，RE 回答“如何关联”，如隶属、位于、使用、攻击、师徒等。关系抽取让图谱不仅能记录事实，还能呈现语义网络，从而支撑推理、推荐、检索与可视化。在安全分析、智能问答、文学研究中，关系结构往往比单纯实体清单更具分析价值。大模型时代，RE 通过提示词精确定义关系标签，使模型高效理解语义并输出结构化知识。

为保持图谱规范，RE 通常依赖预定义的关系类型体系，包括通用关系如属于、位于、拥有，以及领域关系如攻击目标系统、师承人物、前往地点。在概念层，关系类型既是标签也是语义约束，用于确保三元组合理。例如在《西游记》体系中，孙悟空保护唐僧合理，而火焰山教学孙悟空则语义不成立。约束可减少抽取时的类别混淆，抽象设计也能支撑图谱的持续演化。

方法层面，关系抽取涵盖规则法、监督学习、深度学习和基于大模型的提示式抽取。规则法靠模式匹配，难以应对复杂语义；传统机器学习依赖手工特征，跨域迁移弱；CNN、RNN、Transformer 等深度方法借助上下文建模提升质量，但需大量标注。随着大模型增强，Prompt-based Relation Extraction 成为主流：精准提示可在无监督或小样本条件下理解隐式关系，特别适用于威胁情报、文学分析等语义丰富的场景。本书后续将借助 CodeBuddy 搭建自动化关系抽取模块，实现端到端构建。

示例：
输入： “孙悟空三打白骨精，最终保护唐僧继续西行。”
抽取结果可包括
**（孙悟空，战斗，白骨精）**
**（孙悟空，保护，唐僧）**
**（唐僧，前往，西天）**
这些关系作为边连接对应节点。

**11.1.3**

**知识图谱常用工具与框架**

图谱建设覆盖建模、抽取、存储到可视化分析的完整链路，已形成成熟的工具生态。

1 建模层，本体编辑器如 Protégé 广泛用于定义领域概念、属性关系及约束规则，支持 OWL、RDF、RDF Schema 等语义网标准，是构建概念层结构的核心。它提供类层级构建、属性限制设定，并具备推理校验功能，可自动检查一致性与语义冲突，保证体系严谨。

2 抽取层，自然语言处理工具如 Stanford NLP、SpaCy、DeepKE、OpenKE 等可支撑实体识别、关系抽取与事件抽取，形成从文本到结构化知识的自动化流水线。随着深度学习发展，这些框架趋向端到端抽取，可用于大规模语料，如网络安全情报、舆情分析、法律文书解析。

3 存储、查询与推理层，图数据库发挥关键作用。Neo4j 作为典型的 Labeled Property Graph 系统，以高效图遍历、Cypher 查询表达力及可视化插件被广泛用于产业级图谱，如安全图谱、商品图谱、金融图谱。与此同时，Apache Jena、RDF4J 作为 RDF/OWL 语义推理框架，支持 SPARQL 查询与基于规则推理，适用于科研与政府治理等对语义一致性要求高的场景。

为提升应用体验，Gephi、Neo4j Bloom 等可视化工具提供图布局、社群检测与路径洞察，让结构特征、行为模式与隐藏关系直观呈现。伴随大模型成熟，GraphRAG、KGBuilder 等框架将知识抽取与问答系统集成，为智能知识服务提供新范式。表 11-2 展示了常用的知识图谱构建工具与框架。

本节以 MITRE ATT&CK 为代表的结构化威胁情报切入，借助 CodeBuddy 自动生成采集与预处理程序，把分散的攻击组织知识转化为可计算、可扩展的安全知识图谱基础数据。

**11.2.1**

**威胁情报概览**

在网络空间安全对抗中，Cyber Threat Intelligence，CTI 被视为态势感知、攻击溯源与防御决策的关键知识资源。相较日志、告警等原始数据，威胁情报更侧重对攻击者意图、能力、手段与目标的结构化刻画，强调可理解、可验证、可行动。典型内容包括攻击组织 APT Group、攻击基础设施如域名、IP、C2 服务器、恶意软件与工具、利用的漏洞与攻击链条 Kill Chain/ATT&CK TTPs 等。对安全运营与威胁狩猎团队而言，系统化的威胁情报是从被动响应走向主动防御的前提。

MITRE ATT&CK 作为国际主流的对手战术、技术与程序 Tactics, Techniques, and Procedures, TTPs 知识库，为威胁情报标准化表达提供统一语义框架。其通过战术维度刻画攻击目标，如初始访问、持久化、横向移动等，通过技术/子技术细化实现方式，并给出检测与缓解建议。图 11-3 展示了 ATT&CK 官网的 14 个技战术类别，系统刻画了攻击者从初始访问、执行、持久化、权限提升、防御逃避、凭证访问、发现、横向移动、收集、指挥控制、数据渗漏、影响、资源开发到侦察的完整对抗链条。

**注意**

自动化采集程序需具备一定健壮性与工程性。例如，用 requests.Session 统一配置 User-Agent，启用重试策略与超时控制，避免因网络波动或网站限流导致中断；在 HTML 解析环节，针对不同页面可能存在的细微差异如某些组织缺少特定小节，要设计容错逻辑与空值填充策略；在文本清洗阶段，应去除 HTML 标签、脚注标号、多余空格与换行，仅保留面向知识抽取的正文信息，以便后续实体与关系抽取模型直接使用。

在与 CodeBuddy 交互上，提示词设计需要精确约束“采集目标”“字段结构”“技术栈”和“异常处理要求”。例如，明确仅采集指定 Group ID 如 G0050、G0007 等，指定输出 CSV 列字段为“序号、APT 组织名称、网址、描述、Use 用法”，要求使用 requests+BeautifulSoup+csv+logging 实现完整流程，并在采集失败时记录日志而非直接退出。通过精心设计的提示词，大语言模型可自动生成可运行的 Python 爬虫脚本，显著降低安全工程师在样板代码与细节调试上的时间成本，将精力更多投入威胁情报分析与知识抽取上。下面是数据采集所构建的提示词。

请编写一个可直接运行的 Python 爬虫脚本，用其自动采集 MITRE ATT&CK 官网指定 APT 组织页面的威胁情报。目标网址前缀为 https://attack.mitre.org/groups/,仅采集以下 ID：G0050,G0007,G0016,G0013,G0064,G0067,G0087,G1002,G0098,G0012。

程序需满足如下条件：

① 使用 requests 与 BeautifulSoup 解析网页；
② 从 <h1> 标题区获取 APT 组织名称；
③ 从 div.description-body 若不存在则回退 #description 提取“描述”正文；
④ 在 div#techniques-used 中定位 table，读取最后一列“Use”内容，合并为一段文本；
