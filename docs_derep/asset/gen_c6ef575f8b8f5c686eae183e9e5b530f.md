**11.2.3**

**数据清洗与规范化**

把 ATT&CK 威胁情报抓下来之后，原始的 CSV 往往一团糟：混杂着 HTML 残留、换行混乱、描述和 Use 重复、同一个 APT 被重复采集。想让数据能用，就必须做系统化清洗，把脏文本变成干净、可直接下游使用的语料。清洗的根本目的就是提质降噪、统一格式、让语义对齐，为后面做实体识别、关系抽取和图谱构建打地基。

在威胁情报场景里，清洗通常落到三类动作上。

• **文本净化**：去掉多余空格、制表符和冗余换行，把分段描述合并成规范段落；中英文标点统一；剔除爬取时留下的脚注、引用标记以及 JS/CSS 碎片。

• **结构对齐**：列名统一口径，比如 APT 组织名称、描述、Use 用法保持一致；补全 URL 前缀；删掉全空行或明显异常的样本。

• **去重筛选**：同组织重复记录按“名称+网址”去重；描述与 Use 完全一致的条目合并，确保一行就是一个高质量情报单元。

借助 CodeBuddy 这类工具，清洗和本地存储也能用提示词一键生成。典型做法是：

• 用 pandas 按 utf-8-sig 打开 attack_groups.csv，对文本列做 strip、正则替换和空值填充；

• 对描述缺失但 Use 有内容的记录打标记方便人工复核，中文文本额外做分词和停用词过滤；

• 最终导出 attack_groups_clean.csv，让后续识别与抽取代码有统一接口。

这样大模型不仅能写爬虫，还能贯穿 “采集-清洗-入库” 全流程，体现 AI Coding 在安全工程流水线里的中枢价值。

## **提示**

大模型驱动抽取与传统深度学习在范式上完全不同。传统方法以 BERT+BiLSTM-CRF 为代表，靠人工标签和序列标注，依赖大量标注数据，在跨句推理、隐式关系上受限，知识受模型参数约束。

大模型如 GPT、CodeBuddy、DeepSeek 则靠指令微调就能做开放域实体、关系、事件抽取，不必严格依赖标注。海量预训练带来世界知识和跨领域映射，能做跨句跨段推理，面对模糊或不完整表达时可做语义归纳重构，提升召回与一致性。总体看，传统是局部任务特定、强结构约束；大模型是全局语义、零样本迁移、跨任务统一，泛化与推理潜力更高。
