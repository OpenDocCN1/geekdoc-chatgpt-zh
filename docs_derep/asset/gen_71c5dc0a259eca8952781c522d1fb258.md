特别要提的是，OpenClaw 将整段推理做成了全流式输出。只要模型具备 Reasoning 能力，其内部的思考轨迹以及逐字生成的回复，都会通过 WebSocket 实时推送到客户端，在界面上呈现出自然流畅的打字机滚动效果。

另外，思考深度的调节非常精细。对支持扩展思考的模型，例如 Claude 3.7 Sonnet，用户可通过 /think 指令或在配置文件中设定 thinkingLevel 参数，精确控制模型在产出最终答案前的思考预算，进而在响应速度与回答质量之间取得最佳平衡。

4．工具执行

当模型判断需要调用工具时，会先输出一次工具调用请求。Agent Loop 随即暂停推理，进入工具执行的子流程，核心环节如下。

首先是工具分发。OpenClaw 在架构层面把工具分成两类：一类是底层库直接处理的内置工具，比如文件读写和基础命令执行；另一类是 OpenClaw 自身实现的高级自定义工具，比如浏览器操控、节点调用和定时任务等。系统通过专门的路由模块把工具列表拆分，精准拦截自定义工具的调用，由 Gateway 处理后再把结果无缝接入主处理流。

确定目标工具后，系统会立刻进行严格的权限校验，检查该工具是否在当前会话的工具策略允许范围内。一旦发现越权，调用会被直接阻断并向模型返回明确的错误信息。

对于涉及底层系统操作的高风险工具，例如 Shell 命令执行，还引入了执行确认机制。触发安全策略时，Agent Loop 会主动挂起，并通过 WebSocket 向用户推送确认请求，只有在用户明确批准后操作才继续。

所有安全检查通过后，进入真正的执行阶段。视工具类型不同，可能调用本地代码、经网络路由到远程 Node 执行，或在高度隔离的 Docker 沙箱容器内运行指令。

最后在执行反馈阶段，系统会把工具执行的成功数据或捕获的错误信息标准化封装成工具执行结果消息，并追加到对话上下文中，为模型的下一步推理提供事实依据。

5．循环与终止

携带工具执行结果的新上下文会再次送回模型。模型据此继续推理，可能再调用工具，也可能直接生成最终回复。推理→调用工具→获取结果→再推理的循环会持续进行，直到需求满足，模型输出最终回复且不再发起工具调用。

为保证健壮性，OpenClaw 设置了多重硬边界：
• 循环达到预设的最大迭代次数；
• 整体执行时长超过配置的超时阈值，默认通常为 120 秒；
• 用户通过特定命令或界面按钮主动中断执行。

此外还内置了智能的工具调用循环检测机制，可精准识别各种无进展状态，例如反复用相同参数调用同一工具、轮询类工具持续返回相同输出，或在两个工具之间进行毫无意义的乒乓切换。一旦捕捉到异常，系统会先向模型发出警告提示，若模型仍未纠正且达到容忍阈值，系统将直接切断循环，有效防止计算资源的无端浪费。

6．持久化与清理

本阶段的核心是完成本次 Loop 数据的持久化与资源释放，具体操作如下。

1．系统会把本次 Loop 运行期间产生的所有新数据，包括用户的原始输入、模型的中间思考过程、每次工具调用的详细记录以及最终回复文本，以追加方式安全写入该 Session 专属的持久化记录文件。
2．数据落盘完成后，系统立即释放当前会话的执行锁，使队列中等待的下一个请求得以进入处理流程。
3．最后系统同步更新全局的会话元数据文件，精确记录该会话的最后活跃时间以及累计的 Token 消耗统计，为后续审计和资源管理提供依据。

3.3.2 上下文管理与记忆机制

大语言模型本身无状态，之所以能保持连贯对话，完全依赖每次请求时把历史上下文一起发送过去。然而上下文窗口容量有限，输入越长推理成本越高、速度越慢。OpenClaw 为此设计了一套精密的上下文与记忆管理机制，在连贯性与效率之间取得平衡。

1．上下文管理

每次 Agent Loop 启动时，OpenClaw 会通过 context-window-guard.ts 模块对即将发送给模型的上下文进行 Token 数量估算。若估算值超过模型上下文窗口大小减去预留部分，系统会自动执行上下文缩减策略。

不同类型会话采用差异化的历史保留策略。私聊场景通常保留较长历史，因为连贯性和上下文完整性更关键；而群组或频道会话的限制更严格，因为消息更分散、主题跳跃性强，维持过长上下文会带来不必要的 Token 开销。

历史截取并非简单粗暴地丢弃头部最早消息，系统严格保证对话结构的完整性，例如绝不会在工具调用请求与其对应的工具执行结果之间截断，以确保模型始终看到完整的因果链条。

当 Token 用量达到预设压缩阈值，通常为模型最大窗口的 70%～80% 时，系统会自动触发上下文压缩机制，这是 OpenClaw 的亮点之一。

在真正压缩前，OpenClaw 会巧妙插入一轮对用户完全无感知的静默摘要轮次。该轮次中，系统在后台向模型发送系统级指令，告知会话即将面临压缩，要求模型梳理关键决策、用户偏好等重要信息，并通过文件写入工具保存到核心记忆文件或日常日志中。完成后模型返回一个特殊的内部标记，确保过程不影响正常交互。

关键信息安全转移后，系统会在后台独立启动专门的 LLM 摘要任务。该任务引导模型阅读较早阶段的冗长对话历史，并提炼成高度浓缩的文本摘要，作为特殊的压缩节点永久写入会话记录文件。后续轮次中，系统不再发送被压缩的原始长文本，仅发送精简摘要以及压缩点之后的新消息。

该机制在不丢失核心上下文的前提下极大释放了上下文空间，使 OpenClaw 能以极低成本维持近乎无限长度的连贯对话。

OpenClaw 实现了一个名为 compaction-safeguard 的 Pi 扩展，用以防止压缩过程中出现意外错误例如摘要生成失败导致会话损坏。若压缩失败，系统会回退到简单的历史截断策略，确保对话流程不中断。

2．记忆机制

除对话历史外，OpenClaw 还实现了一套基于 Markdown 文件的显式记忆系统，按层次管理记忆。

最顶层是工作记忆，直接驻留在 LLM 上下文窗口中，包含当前对话完整历史。访问最快，但受 Token 上限严格制约，生命周期仅限当前会话。

为弥补其短暂性，引入短期/日常记忆。以按日期命名的 Markdown 文件存储，记录当天流水账、临时笔记和中间思考结果，并随时间自然滚动。

更深层次是长期/核心记忆，集中存储在 MEMORY.md 文件中，涵盖关键技术决策、用户重要偏好以及不可丢失的重要事实，永久保留。

为让海量静态文本文件可被 AI 随时唤醒，系统在最底层构建了强大的向量索引。利用本地 SQLite 数据库，将所有记忆文件转化为高维度语义向量，并随文件修改实时更新。

这种多层次立体记忆架构，使 Agent 既能敏锐捕捉当下语境，又能深度调用历史信息。Agent 启动时会自动读取近两日的日常日志以及 MEMORY.md 全部内容并注入 System Prompt，确保每次对话都能“记得”最近发生的事和用户的长期偏好。

OpenClaw 提供了 memory_search 工具，会在后台对 MEMORY.md 和 memory/*.md 文件进行向量化处理并建立本地索引。当用户询问历史内容时，例如“上个月我们讨论过的项目计划是什么？”，Agent 可调用该工具通过语义搜索快速召回相关记忆片段，无须把所有历史塞入上下文。

将工作记忆与长期存储分离，使 OpenClaw 能以极低成本维持长期对话连贯性，同时保持高效推理。

3.3.3 系统提示词的角色与定制

可将 System Prompt 理解为塑造 Agent 行为与性格的核心模板。在 OpenClaw 中，System Prompt 并非静态文本，而是基于配置文件与上下文在每次 Agent Loop 启动时动态组装而成。理解组装过程是实现深度定制的关键。

1．系统提示词的动态组装

OpenClaw 的 System Prompt 构建逻辑集中在 system-prompt.ts 与 system-prompt-params.ts 两个模块中，整体由以下几个固定模块按顺序拼接而成。

• 工具指引模块：由内部脚本动态生成，完整列出当前 Agent 有权使用的所有工具及其精确描述。描述经过极其严苛的提示词工程优化，用于精准引导模型理解每个工具的适用场景、参数结构及潜在限制。
• 安全护栏模块：一组不可逾越的底层约束指令，强制模型规避高风险行为，例如执行破坏性操作前必须征求用户同意、严禁尝试突破沙箱边界访问宿主机文件。
• 技能指引模块：向模型展示当前加载的结构化技能列表。相当于一份操作手册，明确告知其在面对特定任务时应优先调用预设技能工作流，而非自由发挥。
• 环境感知模块：实时提供 Agent 当前工作目录路径、沙箱启用状态、精确本地时间与时区、底层操作系统版本、当前使用的模型名称，让模型具备真实环境感知能力。
• 运行时信息模块：补充 OpenClaw 核心版本号和当前会话唯一标识等元数据，为模型推理提供完整上下文支撑。

在组装 System Prompt 时，Gateway 会自动读取 Agent 工作空间下的特定 Markdown 文件并注入 Prompt。

• AGENTS.md：相当于岗位说明书，严格定义 Agent 的核心职责、标准工作流及必须遵守的全局规则，例如专注的编程语言或技术栈。
• SOUL.md：塑造 Agent 的性格灵魂，通过设定性格特征、沟通语气和核心价值观，可让它变成严谨的学者或幽默的极客。
• USER.md：专门记录用户的个人背景、技术水平、偏好和特殊要求，使每次回答都能精准契合用户实际水平。
• TOOLS.md：允许高级用户针对特定工具编写自定义使用规范或补充说明，从而微调模型调用工具的行为模式。

在记忆层面，系统会自动读取 MEMORY.md 文件中的长期记忆，确保 Agent 始终牢记用户的核心项目信息和关键技术栈。同时系统还会动态加载按日期命名的日常日志文件如 memory/YYYY-MM-DD.md，将当日与昨日的临时笔记与调试进度无缝融入当前对话，使 Agent 能完美接续之前的工作状态。

2．定制你的专属 Agent

通过修改这些 Markdown 文件，可在不改动任何代码的情况下完全重塑 Agent 行为。例如打造一位暴躁但极其专业的代码审查员。

• 可在 SOUL.md 设定其性格：拥有 20 年后端经验，直率犀利、对代码质量要求严苛，发现问题不绕弯子，可使用直白语言甚至尖锐表达，但必须给出可落地的优化方案。
• 可在 AGENTS.md 中定义职责与工作流：深度阅读代码，精准定位所有潜在逻辑缺陷、性能瓶颈和安全漏洞，并对整体架构和可维护性提出专业建议。更重要的是制定严格工作纪律，如禁止空泛评价必须解释原因并附上重构示例；对安全漏洞醒目标注；审查结束给出量化评分与扣分说明。

再如打造专属个人财务顾问。
• 可在 USER.md 中详细记录用户的职业收入、家庭结构、核心理财目标例如特定期限内筹集购房首付、对投资波动的风险承受能力，以及偏好数据图表而非空泛理论。
• 可在 AGENTS.md 中为财务顾问设定严格标准：建议必须结合实际存款与月储蓄额做精确推演，输出具体比例的资产配置方案；禁止使用笼统套话；涉及高风险标的时必须在显著位置提示风险。

3.4 多智能体路由与协作

在大多数个人使用场景中，一个 Agent 已足够。但随着使用深化，不同任务需要不同的人格和工具权限：工作助理不应访问私人日记，代码助理不需要访问财务数据，而社区管理机器人应对所有人开放但权限严格受限。

OpenClaw 的多智能体路由机制正是为此设计。它允许在同一个 Gateway 下运行多个相互隔离的 Agent，每个 Agent 拥有独立的工作空间、工具集与会话历史，并通过灵活的绑定将不同来源的消息精准分发给对应 Agent。

3.4.1 多智能体的配置与隔离
