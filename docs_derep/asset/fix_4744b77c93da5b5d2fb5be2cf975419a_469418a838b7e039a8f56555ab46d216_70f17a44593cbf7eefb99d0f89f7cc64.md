巨型语言模型的算力拆解：从单机瓶颈到集群并行

当前巨型语言模型的参数规模与训练语料规模都已进入极端区间，单机根本无法完成全量训练，市场上公开的案例全部依赖大规模分布式架构分摊算力。文献 [5] 对 GPT-3 的训练记载较为简略，仅说明使用了 NVIDIA V100 GPU 完成全流程。文献 [28] 对 OPT 的披露更具体，该模型动用了 992 张 NVIDIA A100 80GB，组合了全分片数据并行 Fully Sharded Data Parallel [170] 与 Megatron-LM 张量并行 Tensor Parallelism [171]，整体耗时接近两个月。BLOOM [30] 的团队公布了更完整的硬件与系统细节：训练历时 3.5 个月，共计 48 个计算节点，每节点 8 张 NVIDIA A100 80GB，合计 384 张 GPU，节点内部以 4×NVLink 互联，节点间则通过 4 个 Omni-Path 100 Gbps 网卡搭建增强型 8 维超立方体全局拓扑进行通信。文献 [33] 未披露 LLaMA 训练集群的具体拓扑与配置，但给出了不同模型规模的总 GPU 时长，均基于 NVIDIA A100 80GB：LLaMA-7B 约 82,432 GPU 小时、LLaMA-13B 约 135,168 GPU 小时、LLaMA-33B 约 530,432 GPU 小时、LLaMA-65B 高达 1,022,362 GPU 小时。LLaMA 所用语料远超 OPT 与 BLOOM，即便参数量相对更小，其消耗的计算总量依然惊人。

借助分布式训练，单机数十年量级的训练周期被压缩到数千设备数十天内完成。要把集群算力吃满，必须突破计算墙、显存墙、通信墙三大约束。

- **计算墙**：单卡算力与模型总需求差距悬殊。以 2022 年 3 月发布的 NVIDIA H100 SXM 为例，单卡 FP16 算力约 2000 TFLOPS，而 GPT-3 的累计计算需求约为 314 ZFLOPS，两者相差约 8 个数量级。
- **显存墙**：单卡无法容纳完整权重。GPT-3 含 1750 亿参数，若以 FP32 存储需约 700GB 显存，而 NVIDIA H100 仅提供 80GB。
- **通信墙**：分布式环境下各卡需频繁交换参数与梯度，延迟与带宽易成瓶颈。以 GPT-3 训练为例，若系统存在 128 个模型副本，每次迭代至少要搬运 89.6TB 梯度数据。截至 2023 年 8 月，单条 InfiniBand 链路带宽上限不超过 800Gbps。

计算墙和显存墙源自单设备算力与存储的硬上限，与模型庞大需求矛盾。分布式方案能缓解前两者，却引入了通信墙的压力。随着模型参数扩大，集群规模同步放大，多机多卡下各类矛盾更易显现。长时间大规模训练还伴随设备宕机风险，对系统的容错与调度能力提出很高要求。

## 4.2 分布式训练的并行策略

分布式训练的目标是将单节点训练等价地转化为并行的分布式执行。对大语言模型而言，训练即依据数据与损失函数，通过优化算法持续更新神经网络权重。单节点训练结构如图 4.3 所示，核心由数据与模型两部分构成。训练以多个迷你批次 Mini-batch 为单位推进，图示中的数据即为一个迷你批次。系统利用该批次结合损失与优化算法计算梯度，进而修正模型参数。语言模型多层网络的运行可抽象为一个**计算图** Computational Graph，由多个相连的算子 Operator 构成，每个算子对应一层神经网络，参数即训练中需要更新的权重。

[PRE0]

计算图的执行分为前向与反向两个阶段。**前向计算**把数据送入首个算子取输出，依次推进直至最后一个算子结束。**反向计算**则依据损失与优化算法，按顺序为每个算子求梯度并用梯度更新本地参数。一次反向结束后，当前迷你批次完成，系统读取下一个批次继续迭代。

从单节点流程看，并行加速可从数据与模型两个维度切入。对数据做切分并在多设备上复制同一模型，各自处理不同数据分片，称为**数据并行** Data Parallelism，DP。也可以把模型本身拆分，将不同算子分发到多设备执行，即**模型并行** Model Parallelism，MP。实际训练大语言模型时常同时对数据与模型进行切分，形成**混合并行** Hybrid Parallelism，HP，以获得更高并行度。

### 4.2.1 数据并行

在数据并行体系中，每个计算设备都保存一份完整的网络模型副本。每轮迭代时，设备只负责一个批次样本的子集并做前向计算。设一个批次样本数为 $N$，使用 $M$ 台设备并行，每个设备分配到 $N/M$ 个样本。前向结束后，各设备基于本地样本计算损失并得到梯度 $G_i$，$i$ 为加速卡编号，随后将本地梯度 $G_i$ 广播。所有设备聚合各卡梯度，使用平均梯度 $(\sum_{i=1}^{N} G_i)/N$ 更新模型，完成该批次。图 4.4 示意了由两台设备组成的数据并行训练。

增加设备能有效提升整体吞吐量，即**每秒全局批次数** Global Batch Size Per Second。与单节点相比，关键差异在于反向阶段的梯度必须在所有设备间同步，以保证最终模型使用全局平均梯度。主流框架均提供数据并行实现，如 TensorFlow DistributedStrategy、PyTorch Distributed、Horovod DistributedOptimizer 等。由于 Transformer 大语言模型每个算子依赖单个样本而非整批，数据并行不改变计算逻辑。通常前向阶段各设备独立，无需同步。数据并行加速潜力最大，但要求每台设备都备份完整模型，显存开销较高。
