# 多智能体协作四种主流范式

在工程实践中，群体智能方案往往收敛为四种典型结构：串行链路、并行扇出、层级管控和网状协商。串行链路是指多个智能体按预设顺序依次运行，前一步的输出直接作为下一步的输入，适合步骤清晰、流程固定的工作。并行扇出是把同一问题拆到不同维度由多路智能体同步处理，最后由汇总节点整合结果，适合可拆分的高复杂度任务。层级管控由管理者节点负责任务分解与调度，执行者节点完成具体工作并回传，适合需要动态调度与灵活分派的场景。网状协商允许节点间自由沟通，通过多轮对话达成一致，适合需要多方博弈的决策问题。

图5-2把四种结构的外形和适用边界做了可视化。左上线性链路A→B→C依次推进，优点是逻辑通透、调试省心，缺点是延迟逐级累积，典型用于文档处理流水线等确定性流程。右上先由分发节点拆任务，多路节点并行计算后由聚合节点合并，速度快但合并逻辑较重，适合多视角分析类任务。左下以管理者集中指挥多个执行者，虚线表示回传路径，灵活且利于负载均衡，但管理者易成瓶颈。右下允许全网互通，通过多轮沟通达成共识，决策质量高但通信开销大，多用于复杂的多方决策。

### 5.1.3 基于LLM的Agent能力边界定义

在基于大模型的群体系统中，清晰界定能力边界是避免职责混乱与协作冲突的关键。边界的定义不仅要说明能做什么，还要明确不能做什么以及越界时的处置方式。边界最好写入System Prompt，使模型准确理解自身职责范围。

完整的能力边界包含五个核心要素。第一是角色定位，明确在协同网络中的身份与核心使命。第二是能力范围，列出可处理的任务类型、支持的输入形式和可调用工具。第三是边界约束，划定不承接的任务类型及越界时的标准回应。第四是协作接口，定义与其他节点交互的报文格式、协议和交接条件。第五是决策权限，说明可自主决定的范围与需要上报或转交的情形。

为避免职责重叠，设计时需遵循以下原则。

- 单一职责：每个节点只聚焦一类明确业务
- 显式边界：在System Prompt里写清可做与不可做
- 标准化转交：统一转交协议与上下文传递格式
- 兜底机制：设置默认路由节点承接无法归类的请求
- 定期审查：基于运行数据持续调整职责划分

### 5.1.4 协同系统的模块化与可扩展性设计

生产级协同系统必须具备良好的模块化与可扩展性，以支撑业务演进与技术迭代。核心思想是将系统拆分为职责独立、接口统一的模块，单个模块可独立升级或替换而不影响整体。

典型模块化体系包含六层：接入层负责接收各类外部请求并响应；路由层依据请求特征分发任务；智能体层托管所有业务节点，通过消息总线异步通信；工具层提供数据库、外部服务、RAG检索和代码执行等能力；存储层负责会话缓存、向量库、对话历史和审计日志；监控层覆盖性能、日志、链路追踪和Token统计。

模块化设计遵循四项原则。接口标准化要求所有模块通过统一接口通信，确保交互一致可预期。可插拔设计使节点和工具可独立部署替换。配置驱动通过配置文件管理路由与节点，实现运行时灵活调整。水平扩展支持节点实例的动态扩缩容，按负载自动调节容量。图5-3展示了一个典型的模块化Agent系统架构，从上到下分为六个层次。接入层作为入口，处理API、Web、消息队列等渠道请求，提供认证鉴权、限流熔断和协议转换。路由层负责意图识别和请求分发，将任务路由到对应节点。智能体层是核心，可接入Claude、GPT-4、Qwen、DeepSeek等不同模型，节点间通过消息总线异步通信。工具层提供数据API、服务调用、检索与代码执行等能力。存储层持久化会话缓存、向量、历史和审计日志。监控层贯穿全链路，提供可观测性。

### 5.2.1 System Prompt的结构化设计方法

System Prompt决定节点的行为、人格和能力边界，设计质量直接影响表现。在多节点场景下，结构化设计尤为重要，既要定义个体职责，也要规范协作方式和信息交换格式。

结构化System Prompt遵循“角色-能力-约束-协作”四层架构。角色层定义身份、背景和专业领域，建立人格画像。能力层明确任务类型和可调用工具。约束层规定行为边界、禁止事项和异常处理。协作层定义与其他节点交互的协议、报文格式和状态转换。四层设计兼顾完整性与可维护性。

图5-4展示了System Prompt的四层结构化模板。第一层角色定义包含身份声明、人格特征、专业背景和服务对象，用于建立基本画像。第二层能力声明用虚线框标注需按业务定制，涵盖任务范围、工具清单、知识边界和输出格式。第三层约束规则定义禁止事项、安全边界、异常处理和决策权限，确保行为可控。第四层协作接口规定消息格式、转交条件、状态同步和协作对象，支撑多节点协同。底部输出规范统一了标准响应、转交响应和错误响应的JSON格式，保证系统间通信一致。
