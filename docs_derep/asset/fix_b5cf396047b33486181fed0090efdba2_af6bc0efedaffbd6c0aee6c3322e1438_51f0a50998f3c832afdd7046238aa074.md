### 6.3 持久化与异步：跨会话的任务管理

本小节围绕的计划范式是“先拟定计划，再着手执行”。Claude Code 提供了一套更为先进的管控框架，在优化规划与执行衔接的同时，引入了任务持久化等关键特性，使得 Agent 能够跨越会话边界保持长期记忆并持续执行。

下面将逐步展开实现细节，演示如何搭建具备持久化与异步执行能力的任务管理体系。

### 6.3.1 Todo：Claude Code 的计划模式

在 Claude Code 内部，最基础的规划形态被称为 Todo 模式。运作方式是：当模型收到任务指令后，先生成待办清单，并对每个步骤的执行状态进行实时跟踪。为保证严谨，该模式强制串行执行，即同一时刻仅允许一个步骤处于进行中。

从架构角度看，该能力被封装为独立工具，由模型通过工具调用来自主维护清单状态。

沿用上述设计思想，本节首先借助提示词工程对模型行为进行约束，要求处理具体任务前必须先产出执行方案；随后设计一个专门的计划管理工具，让模型能够根据实际情境自主调用并完成方案的更新。

### 6.3.2 Task System：持久化的任务系统

上一节实现的 Todo 本质上只是扁平清单。它能够保证串行执行，却无法处理复杂的依赖关系，例如任务 A 完成后才能启动任务 B 的前置约束，或任务 C 与任务 D 可以并行的协同需求。更关键的是，清单仅驻留在内存中，一旦上下文被压缩或进程异常终止，状态即会丢失，难以支撑长周期开发的连续性。

为解决上述问题，Claude Code 引入了 Task System。核心设计是将扁平清单升级为带状态的任务图，通过把任务状态写入磁盘，确保生命周期不再受单次对话窗口限制，实现跨会话的追踪与管理。

实现思路采用文件化存储，每个任务抽象为独立的 JSON 文件并统一存放在指定目录。数据结构中新增了 `blockedBy` 表示前置依赖、`blocks` 表示后置依赖。

以一个包含4个步骤的复杂流程为例：任务1为基础步骤，完成后再同时启动任务2和任务3，任务4需等待任务2和任务3全部完成。在 Task System 中，这4个任务会被序列化为如下4个 JSON 文件。
