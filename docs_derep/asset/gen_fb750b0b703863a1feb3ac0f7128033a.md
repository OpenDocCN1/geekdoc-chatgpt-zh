# PyTorch JIT 追踪 vs 脚本化，为什么分支会被“固化”

很多同学第一次接触 TorchScript 时会产生一个错觉：只要跑一次 trace，就能把模型完整封存起来。实际上 trace 更像录像回放，它只记录喂入示例时真正走过的那条执行路径。一旦模型里出现了条件判断、循环等动态逻辑，录像就只保留当天发生了的那一幕。

import __torch__

import __torch__.torch.nn.modules.linear.___torch_mangle_1

def forward(self,

    input: Tensor,

    h: Tensor) -> Tensor:

  _0 = self.linear

  weight = _0.weight

  bias = _0.bias

  x = torch.addmm(bias, input, torch.t(weight), beta=1, alpha=1)

  _1 = torch.tanh(torch.add(torch.neg(x), h, alpha=1))

  return _1

可以看到，trace 把 if  else 完全拍平了。示例输入让 sum <= 0，录像里只剩下 torch.neg，换一个正数输入再 trace，结果又会不一样。这就是 trace 的局限：控制流被固化到示例路径上。

如果想保留真正的分支，需要用脚本化。

[PRE5]
>>scripted_gate = torch.jit.script(MyDecisionGate())

>>my_cell = MyCell(scripted_gate)

>>traced_cell = torch.jit.script(my_cell)

    if torch.__isnot__(_2, None):

      output0 = torch.add_(output, bias0, alpha=1)

    else:

脚本化后，if torch.gt(torch.sum(ret...),0) 的判断被原样保留，正负分支都能在运行时生效。

>>class CNN(nn.Module):

        super().__init__()

        self.conv1 = nn.Conv2d(3, 16, 3, padding=1)

        self.conv2 = nn.Conv2d(16, 32, 3, padding=1)

        self.conv3 = nn.Conv2d(32, 64, 3, padding=1)

        self.pool = nn.MaxPool2d(2, 2)

        self.linear1 = nn.Linear(64 * 4 * 4, 512)

        self.linear2 = nn.Linear(512, 10) 

        self.dropout = nn.Dropout(p=0.3)

    def forward(self, x):

        x = self.pool(F.relu(self.conv1(x)))

        x = self.pool(F.relu(self.conv2(x)))

        x = self.pool(F.relu(self.conv3(x)))

        x = x.view(-1, 64 * 4 * 4)

        x = self.dropout(x)

        x = F.relu(self.linear1(x))

        x = self.dropout(x)

        x = self.linear2(x)

        return x
