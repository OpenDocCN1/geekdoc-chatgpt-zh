#### 3.2.1 DeepSeek-R1模型介绍

DeepSeek-R1 由 DeepSeek 于 2025 年 1 月推出，目标是增强大语言模型的推理能力。评测显示其在数学、代码、自然语言推理等任务上的表现可与 OpenAI o1 正式版相媲美。

在开源 DeepSeek-R1-Zero 与 DeepSeek-R1 两个 660B 级模型的同时，团队基于 R1 的输出蒸馏出了 6 个轻量模型，32B 与 70B 版本在多项指标上对标 OpenAI o1-mini。

#### 3.2.3 DeepSeek-R1模型参数详解

通过 API 调用 DeepSeek-R1 时，可灵活调配多项参数以控制生成长度、风格多样性与逻辑严谨性等输出特征。`chat.completions.create()` 接口的关键参数已作说明，DeepSeek-R1 与 DeepSeek-V3 共用该接口。

不过 R1 在参数解析与推理机制上存在部分特有特性与限制，实际调用时需注意以下要点。

##### 1. max_tokens参数

（1）`max_tokens` 控制最终回答部分即 `content` 字段的最大长度。默认值 4096 token，约 3000 汉字，上限 8192 token。

（2）该限制不包含思维链内容 `reasoning_content`。在复杂任务中，思维链可长达 32K token，因此总输出长度可能远大于 `max_tokens` 的设定。官方预计未来会上线 `reasoning_effort` 参数，用于调节 `reasoning_content` 的推理深度与长度。

##### 2. reasoning_content字段

（1）DeepSeek-R1 的特点是除普通回答 `content` 外，还会返回推理过程字段 `reasoning_content`，与 `content` 平级。

（2）该字段记录模型得出结论的思考轨迹，适用于解释性任务、教学与评估场景。

##### 3. 功能支持情况

（1）已支持对话补全标准 Chat Completion 和对话前缀续写 Beta，可用于接续已有内容生成完整对话。

（2）目前暂不支持 Function Calling、JSON 格式输出、FIM Fill-in-the-Middle 补全 Beta 等功能，相关字段设置无效。

##### 4. 不生效的参数

`temperature`、`top_p`、`presence_penalty`、`frequency_penalty`、`logprobs`、`top_logprobs` 在调用 `deepseek-reasoner` 模型时不生效。为保持与 OpenAI 接口的兼容性，设置它们不会报错，仅被静默忽略。

##### 1. DeepSeek-R1思维链执行过程

思维链 `reasoning_content` 是 DeepSeek-R1 完成任务时自动生成的推理轨迹，以自然语言形式模拟问题处理过程中的逻辑推导、步骤展开与中间判断，并与 `content` 一并返回。其演化规律如图3.30。

图3.30 思维链的执行演化规律

在多轮对话中，R1 的思维链呈现清晰的阶段性演进。

（1）首轮对话多为独立推理，模型基于初始提问进行完整且自洽的思考。

（2）进入第二轮时，模型开始递进式推理，会引用前文问答对并自然衔接，体现较好承接性。

（3）第三轮及以后，模型转为综合性推理，整合多轮信息与多个变量，输出逻辑排序清晰的推理链条。随着对话深入，R1 不仅展现单轮分析能力，也体现上下文记忆、逻辑递进与归纳整合能力，具备类人类的思维连续性与对话一致性，适用于复杂交互场景。
