网络层面的可调项主要包括不同层之间如何融合，比如相加、相乘或串联，卷积核的个数与尺寸，整体的层数也就是网络深度，以及选用的激活函数等。

优化层面的可调项通常指学习率、一次前向的样本量、各类优化器内部的系数，以及损失函数中允许人工设定的部分。

正则化层面的可调项则主要围绕权重衰减的强度和 Dropout 的丢弃比例展开。

### 13.1.3 调参的本质冲突
归根到底，超参数调优是在模型优化与正则约束之间寻找平衡。优化的意图是逼近全局最优或更好的局部最优，而正则则希望模型既能拟合又不失约束。两者常有张力，但目标一致，都是压低期望风险。优化擅长最小化经验风险，却容易过拟合；正则的作用正是限制模型复杂度。如何权衡这两者，取得最优或次优解，就是超参数调整要解决的问题。

### 13.1.4 参数影响力排序
按实践中的重要程度排，首位是学习率和损失函数里可调的部分，接下来是批大小和动量优化器的动量系数β，最后是 Adam 的内部超参、权重衰减、Dropout 比率以及网络结构参数，下面分述。

（1）学习率与损失函数可调项。
在网络参数、优化参数、正则参数里，学习率的重要性最高。它直接决定梯度更新的幅度，进而影响模型的实际表达能力。

损失函数中可调的参数，需要结合具体函数来定。多数情况下这些参数也能明显改变有效容限。常见可分为三类。
第1类是配合主损失的辅助损失，用于增强特征表达。比如度量学习里的 Center Loss，往往与交叉熵以一个权重并用。建议辅助损失的数值不要比交叉熵高出或低出两个数量级以上。
第2类是多任务场景下的多条损失，每条对应不同任务，彼此独立或相关，效果取决于任务相关性本身。
第3类是独立型损失，在特定任务上效果突出。如 RetinaNet 的 Focal Loss，其 γ、α 会显著影响结果，这类参数论文里通常会给出推荐值。

（2）批样本数量与动量参数β。
批大小决定梯度下降的方向。过小会导致方向抖动，极端到 Batch Size 为1时，每个样本都会改一次方向，样本差异越大越难收敛。若用了批归一化，样本过少统计量不稳，甚至会失效。因为样本越少，统计代表性越差，噪声越大。过大的批大小会让梯度方向过于稳定，容易卡在局部最优，精度下降。实践参考区间是[1, 1024]，并非硬性，需结合硬件与数据。

动量衰减系数β用于指数加权平均梯度，也可用于参数更新，设为0.9是常见且表现稳定的选择。

（3）Adam 超参、权重衰减、Dropout 比率和网络层数。
把这些放在后面不是不重要，而是实践中不建议频繁大幅尝试。

- (a) Adam 中的 β1、β2、ε 常取0.9、0.999、10⁻⁸，表现通常不错。
- (b) 权重衰减系数一般有推荐值，如0.0005，建议直接采用，不必过度探索。
- (c) Dropout 比率多用于全连接层以防过拟合，建议控制在[0.2, 0.5]之间。注意两点：第一，在 RNN 中不宜把 Dropout 直接放在记忆单元，易放大噪声扰乱学习，建议放在输入层和输出层；第二，不要让 Dropout 紧跟批归一化，会干扰统计量计算，导致推理时方差偏移，极端情况下模型会崩掉。
- (d) 网络层数本身也是超参。通常加深网络能提升容限，但真实有效容限还受样本数量与质量、层间关系影响。因此一般先固定深度，调优到一定阶段或有充足算力后再考虑增加深度。

## 13.2 网络训练中的超参数调整策略

### 13.2.1 超参数优化的一般流程
通常的优化流程如下。
- （1）选取一组超参数，可自动选择。
- （2）搭建对应模型。
- （3）在训练集上拟合，并用验证集衡量最终表现。
- （4）基于历史表现自动挑选下一组候选超参数。
- （5）重复以上步骤。
- （6）最后在测试集上评估模型。
关键在于如何利用验证集的历史反馈，决定下一步评估哪组超参数。

### 13.2.2 调试模型的思路
想到调试，常会联想到优秀模型与技巧。但数据才是根本，优质数据或数据处理能力带来的收益往往大于模型挑选。需在数据质量得到保障的前提下再谈模型设计与训练技巧。

- （1）探索与清洗数据。数据探索是建模前最关键的一步。以图像分类为例，要了解类别是否均衡、各类别样本量差异，以及是否存在跨域问题，如网图质量不一、噪声多。若类别远多于单类样本量，如1万类每类10张，常规方法效果有限，可考虑小样本学习进行增强。目标检测中目标尺度范围会影响性能，需明确关注大目标还是小目标，目标是否密集，完全取决于数据集。因此数据探索与清洗是深度学习中最易被新手忽略却最重要的环节。
- （2）分析模型结果。对验证集性能做细化剖析，有助于进一步提升。将训练集与验证集结果都做验证和可视化，能直观判断是否存在较大偏差。以分类为例，若类别不平衡，要重点看小样本类别在两集上的表现差异，对错例做数值分析和可视化，确认模型行为。
- （3）监控训练与验证误差。很多时候代码规范性和正确性验证被忽略，易致命。若训练验证都异常，先检查代码；再根据误差曲线追踪拟合状态。训练集很小时，监控误差尤为重要，这能帮助更从容地选择学习率策略或其他有效超参。
- （4）反向传播数值验证。多用于自研算子。虽然主流框架已内置自动求导，但未必完全符合需求。可通过比较自动求导结果与有限差分结果的一致性来验证正确性。

### 13.2.3 为何需要调整学习率
学习率是训练中最核心的超参数。合适的学习率既能加速收敛，也能获得更优精度。过大或过小都会影响收敛。当训练到一定阶段，损失不再下降，一阶梯度接近0时，Hessian 矩阵有两种可能。

（1）正定，所有特征值均为正，此时接近局部极小。若该点接近全局最优，性能已不错；若差距大，则仍有提升空间，这在训练初期常见。
（2）特征值正负混杂，可能陷入鞍点，此时模型表现较差。
训练初期与中期出现上述情况，若仍用固定学习率，容易左右震荡或停留在鞍点。衰减或适当增大学习率可帮助减少震荡或跳出鞍点。

### 13.2.5 极端批大小下的训练
极端批大小指 Batch Size 为1 或大于6000 的情况。用得不当会导致性能不达最优甚至崩溃。

在目标检测、分割或三维图像等输入尺寸大的场景，Batch Size 通常很小，这会让梯度不稳定，批归一化的统计也不准确。
