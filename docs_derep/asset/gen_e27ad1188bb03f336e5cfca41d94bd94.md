一种常见的剪枝思路是基于权重的幅度来判断。Wanda 提出把每个权重的大小与对应输入激活的范数逐元素相乘，得到重要性分数作为剪除依据。RIA 引入了相对重要性与激活度这一概念，把权重本身和激活值一起纳入考量，通过分析权重间的连接关系来量化每个权重的作用。RIA 还能把得到的非结构化稀疏模式映射成 N:M 结构化稀疏，从而在 NVIDIA GPU 上获得加速。近期的 Pruner-Zero 放弃了手工调参的做法，尝试为大语言模型自动搜寻最优的剪枝度量。实验显示，对 LLaMA 与 LLaMA-2 而言，最优的度量是 $W \odot W \odot \sigma(G)$，其中 $W$ 表示权重、$G$ 表示梯度，$\sigma(\cdot)$ 是把张量最小值与最大值归一化到 [0, 1] 区间的缩放函数。

无结构剪枝以单个权重为粒度进行剔除，相较结构化剪枝能做到更高的稀疏率，同时对预测结果的干扰更小。缺点在于产生的稀疏模式缺乏规律，内存访问和计算都变得不规则。这种不规则性与现代计算架构偏爱的密集规则数据模式相悖，导致硬件加速潜力受限。总体来看，无结构剪枝虽能换来更高的稀疏度，但在实际的硬件效率与加速收益上往往打折扣。

#### 2. 结构化剪枝
**结构化剪枝（Structured Pruning）** 直接作用于模型中的大粒度单元，比如通道、组或整层。相比非结构化剪枝，它的粒度更粗。因为剪除对象与硬件原生支持的密集规则模式匹配，所以推理速度能够直接提升。代价是粗粒度操作更容易带来性能回落。

LLM-Pruner 提出了一种任务无关的结构化剪枝方案。先依据神经元间的依赖关系在模型中找出成对结构，这些结构必须成组移除才能保证剪枝后模型仍完整。例如 LLaMA 中就存在 MLP 内部耦合、MHA 内部耦合以及全网的维度耦合等不同层次的依赖。方法把这些耦合关系整理成一个依赖图，并用递归搜索快速定位耦合结构。分组完成后，评估每组对整体性能的贡献，按预设剪枝比例对组重要性排序后剔除低价值组。剪枝结束后引入 LoRA 做参数微调，以恢复模型能力。

LoRAPrune 面向搭载 LoRA 模块的大语言模型，提供了一个结构化剪枝框架，实现 LoRA 驱动的快速推理。它设计了基于 LoRA 的剪枝准则，不计算预训练权重的梯度，而是利用 LoRA 权重与梯度来评估重要性，从而避开计算预训练梯度带来的巨大显存开销。将该准则嵌入迭代剪枝流程，能够有效剔除冗余通道与注意力头，在压缩模型的同时维持较好效果。LoRAShear 同样针对 LoRA 为基础的模型，分析模型参数与 LoRA 模块间的关联，构建原始模型和 LoRA 模块的依赖图，挖掘出最小可剪结构并分析知识分布。依托依赖图对 LoRA 适配器进行渐进式结构化剪枝，有助于固有知识迁移，保留冗余结构中的信息。同时引入结构稀疏优化，用 LoRA 的信息更新权重，提升知识保存率。

MoE 在大语言模型中日益流行，围绕专家的剪枝也成为研究热点。ExpertSparsity 是一种专家级稀疏化方法，专门针对 MoE 的前馈专家。它用原始输出与稀疏后输出之间的 Frobenius 范数来衡量专家被稀疏化的损失。对 MoE 中的专家进行分层评估与剪枝，按对整体性能的贡献度剔除影响小的专家，可实现模型压缩与计算提效。剪枝采用渐进式策略，逐步进行专家剪除并在每次操作后评估性能，以找到性能不大幅下降的最优剪枝点。推理时使用动态跳过，根据输入特征动态决定是否跳过部分专家，对当前输入贡献不大的专家直接跳过，减少计算、加快推理。

### 10.3 低精度训练
大语言模型训练消耗的计算资源极大，涉及大量 GPU/TPU 以及存储与内存。即使像 DeepSeek-V3 $^{[38]}$ 这样采用多项优化策略的模型，单次训练仍需约 266.4 万 H800 GPU 小时 $^{①}$。在巨大开销下，提升训练与推理效率成为热点。

降低数值精度被认为是降本最有潜力的方向之一，能带来更高速度、更小显存与更低通信开销。主流框架如 Megatron-LM、MetaSeq、Colossal-AI 仍多用全精度 FP32 或混合精度 FP16/BF16。随着 NVIDIA H100 的推出，FP8 正逐步成为下一代低精度表示的主流。相比 16 比特和 32 比特混合精度，FP8 可将训练速度提升约一倍，同时实现 50%~75% 的内存与通信优化，为下一代大规模基础模型提供空间。

本节先介绍 FP8 编码，再介绍基于 FP8 的大语言模型训练方法。

### 10.3.1 FP8 编码
FP8 是一种为提升计算效率与降低存储需求而设计的低精度浮点格式，广泛用于深度学习训练与推理。FP8 采用 IEEE 浮点表示的变体，包含符号位 S、指数位 E、尾数位 M。指数位决定动态范围，尾数位决定精度。核心是通过减少位数降低计算复杂度与内存占用。常见表示有 E5M2、E4M3、E3M4、E2M5，通过调节指数位数可适应不同动态范围需求。因为 E3M4 与 E2M5 动态范围过小，大语言模型中通常选用 E4M3 与 E5M2 $^{[529]}$。

E4M3 与 E5M2 的细节见表 10.1。NVIDIA GPU 上的 E5M2 遵循 IEEE 754 标准，动态范围与标准一致。E4M3 不符合 IEEE 754，取消无穷大，仅保留一个非数，从而额外表示 256、288、320、352、384、416、448 等数值，扩展了动态范围，在深度学习中很有用。总体上 E4M3 更注重精度，在 [1,2] 区间最小间隔为 1/8，而 E5M2 为 1/4。但 E5M2 动态范围更大，E4M3 为 [-448,448]，E5M2 为 [-57,344,57,344]。训练时常建议权重与激活用 E4M3 表示，梯度用 E5M2 表示 $^{[529]}$，具体选择视模型特性而定。

精度下降会让舍入误差更明显。例如 FP16 在不同区间的精度不同，在 [1024, 2048] 区间最小间隔为 1。若把 1024.0 加上 1.5，结果会被舍入为 1025.0。

在 FP16 中，1024.6 会被舍入为 1025.0。用 FP16 计算 1025.0 加上 0.4，结果仍是 1025.0，因为 0.4 太小无法改变值。而 1025.0 加上 100.6 的结果是 1126.0，因为 100.6 足够大能影响结果。这种舍入误差在低精度浮点中很常见，尤其数值跨度大时，会显著影响训练与推理数值稳定性，是低精度训练需解决的关键难点。

### 10.3.2 FP8 大语言模型训练
NVIDIA Transformer Engine 1.1.0 版已支持 FP8 编码的 GEMM 计算，但主权重与梯度仍以 FP16 或 FP32 存储，因此端到端提速、显存节省与通信优化有限，未能充分发挥 FP8 潜力。为此 Microsoft Azure 与 Microsoft Research 开源了 FP8-LM 框架 $^{[530]}$，提出专为大语言模型设计的高度优化 FP8 混合精度训练方法。其思路是将 FP8 的计算、存储与通信贯穿训练全流程，使前向与反向传播均基于低精度 FP8，从而显著降低系统负载、实现更高效训练。2025 年 1 月，相关工作已把数据格式精度进一步降至 FP4。
