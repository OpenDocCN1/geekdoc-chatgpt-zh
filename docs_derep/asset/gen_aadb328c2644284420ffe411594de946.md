工作原理可归纳为两点。

1）先用专家质心向量 Weight 与输入 hidden_states 做线性变换得到亲和度。推理时采用 noaux_tc 分组策略限制通信范围，具体为：把路由专家划分成若干组；计算 Token 与全部专家的亲和度；每组内取亲和度最高的两个专家求和作为组分；挑选组分最高的 Top K_group 个组；在这些组里再挑出 Top K_expert 个专家并返回其亲和度。

2）对选中的 Top K_expert 个专家的亲和度做归一化，除以该 Token 在这 K 个专家上的亲和度之和，再乘以缩放因子作为最终权重输出。

6.1.2 MoE 架构下计算量下降的分析

MoE 通过稀疏激活显著降低了实际计算开销。

1.MLP 架构下的计算量
假设 MLP 仅含两层线性，中间维度为 hidden_size 的 2.5 倍，密集 MLP 的计算量为：
● 输入矩阵：[*h*]
● 第一个矩阵：[*h*,2.5*h* ]
● 第二个矩阵：[2.5*h* ,*h*]
每个专家对每个 Token 的计算量为
计算量[MLP]=*h*×*h*×2.5*h*+*h*×2.5*h*×*h*=5*h*³

● 第一个矩阵：[*h*/*n*^(1/2),2.5*h*/*n*^(1/2)]
● 第二个矩阵：[2.5*h*/*n*^(1/2),*h*/*n*^(1/2)]

下降主要来源于两方面。
1）专家数 *n* 上升但仅激活 *k* 个。将计算分散到大量专家上，且每次只使用少量专家，计算被大幅剪枝。
2）输入维度降低。每个专家的输入维度变为 *h*/*n*^(1/2)，矩阵乘法成本随之下降。

需要提醒的是，训练成本还受通信和稀疏调度影响。MoE 的通信开销相对较大，实际训练成本的降低不完全等同于计算量的降低。
