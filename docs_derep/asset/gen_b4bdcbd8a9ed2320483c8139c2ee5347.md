# 3.3 鱼骨图：定位根因的经典工具

鱼骨图，也称因果图或石川图，本质上是用分支结构来呈现因果联动的视觉化手段。

借助鱼骨的造型，它能把一个最终结果也就是鱼头，与诸多影响因素也就是鱼骨清晰对应起来。图3-21所示即为一次项目延期原因剖析的鱼骨图示例。

[PRE3]

图3-21 项目延期原因分析的鱼骨图

鱼骨图的核心构成包括：

+ (1) 鱼头：指向待解决的问题或最终影响。(2) 主骨：概括影响结果的主要维度，通常涵盖人员、设备、方法、材料、环境等。(3) 副骨：落在主骨下的具体诱因，属于某一个维度的细分。

鱼骨图的主要价值体现在：

+ (1) 直观呈现结果背后可能被忽视的潜在诱因，尤其是深层根因。(2) 梳理各诱因间的关联，锁定关键驱动因素。(3) 为解决问题提供清晰的思路路径与行动方向。(4) 聚拢团队对同一问题的多元视角，推动共识形成。

# 3.3.1 鱼骨图在架构设计里的落地场景

在架构设计中，鱼骨图既能用来拆解问题、发掘隐患，也能促进跨角色理解。典型应用包括：

+ (1) 产品结构设计：用鱼骨图呈现产品的层级与架构。由顶层产品逐级拆解到子产品、模块、功能，形成树状结构，指导研发落地，也帮助团队快速对齐认知。(2) 需求管理：借助鱼骨表达需求间的父子或依赖关系。区分核心需求与衍生需求，并标注优先级与影响度，从而优先攻克关键需求，牵引开发节奏。(3) 产品交付规划：把需求与任务结构化，明确依赖关系，拆解出阶段目标与时间节点，让交付全流程更透明高效。(4) 变更管理：需求或环境变动时，用鱼骨评估变更对产品的传导影响。判断是否波及核心模块与功能，量化实现难度与工作量，为应对策略与资源调配提供依据。

(5) 故障管理：产品出现异常时，可快速沿鱼骨定位问题层级与具体模块，判断故障是否会引发连锁反应。进而制定修复方案，尽快恢复服务。

总体来看，鱼骨图通过结构化呈现产品层级与要素关系，在结构设计、需求管理、交付计划、变更管控与故障定位等环节都极具价值。它能加速团队共识，提升协作效率，是产品管理中简单却高效的利器。

# 4.1 UML总览

UML即统一建模语言，是一种用于软件系统建模的标准语言，提供统一的图形符号与规范，用于描述系统的结构、行为与交互。它广泛应用于需求分析、系统设计、代码生成等全流程。

# 4.1.1 UML的演进与版本

UML的起源可追溯至20世纪90年代初，融合了Booch方法、OMT方法和OOSE方法三大面向对象建模思路。

随着发展，UML历经多次迭代，目前主流为UML 2.x系列，包含UML 2.0、2.1、2.2等版本，每个版本都在表达能力和适用范围上做了增强。

# 4.1.2 UML图种分类与应用

UML提供多类图形用于描述系统不同侧面。常见类型包括：

+ (1) 类图：描述系统的静态结构，展示类、接口及其关联、继承等关系。(2) 用例图：刻画系统功能需求与用户角色的关系，表现用例与参与者间交互。

(3) 活动图：描述业务流程与操作行为，呈现活动、决策、并发等流程。

(4) 时序图：描述对象间交互与消息传递顺序，展示时序关系。

各类图各有侧重，可帮助架构师与开发团队更清晰描述系统，促进协作。后续章节将逐一解析其要素、绘制方法与注意事项。

# 4.2 类图

类图是UML中最常用的图种，用于描述系统的静态结构与类间关系，展示类、接口、关联、聚合、组合、继承等，有助于理解对象结构与交互。

(4)确定继承关系：继承关系表示类之间的继承关系，其中子类继承父类的属性和方法。通过带有箭头的实线连接父类和子类，箭头指向父类，表示子类继承自父类。(5)添加类图的其他元素：根据需要，可以添加类之间的依赖关系、接口实现关系等其他元素。依赖关系表示一个类依赖于另一个类，可以使用带箭头的虚线表示。接口实现关系表示类实现了一个或多个接口，可以使用带空心三角形的箭头表示。

> 在绘制类图时，还需要注意以下事项。(1)类的命名：选择有意义且符合命名规范的类名，以清晰地表达类的职责和功能。(2)关联关系的多重性：根据系统需求确定关联关系的多重性，即一个类与另一个类之间的关联数量。可以使用数字或符号表示多重性。(3)箭头的方向：在关联关系、继承关系和依赖关系中，箭头的方向表示类之间的方向性，指向被依赖、被继承或被关联的类。(4)类图的简洁性：保持类图的简洁性和可读性，避免过多的类和关系，以便更好地理解系统的结构和设计。遵循以上步骤和注意事项，大家可以绘制出准确、清晰的类图，用于描述系统中的类、属性、方法和它们之间的关系。这样的类图有助于沟通和理解系统的设计，并为软件开发和维护提供指导。
