Agent 既能感知外部信息，又能把信息存下来，思考所需的原材料就算齐了。那这些原材料怎么被加工成可用的逻辑呢？第6章，我们把镜头对准推理这件事。

# 第 6 章

## 推理机制

> “思想无内容则空，直观无概念则盲。”

> ——伊曼努尔·康德（Immanuel Kant），《纯粹理性批判》

记忆负责给 Agent 建仓库，推理负责给它装生产线。前者解决“知道什么”，后者解决“怎么用”。两者配合，知识才从库存变成可用能力。

诺贝尔经济学奖得主丹尼尔·卡尼曼在《思考，快与慢》里把人的思维拆成两套系统：System 1 快速、直觉、靠启发式；System 2 缓慢、刻意、靠反思，如图 6-1。复杂判断或强约束任务时，人更倚赖 System 2 的慢思考；熟悉且低风险的场景，System 1 的直觉反而更稳。

Agent 的推理也需要快慢两种节奏，并能随任务难度和计算成本在两者间切换。研究和综述显示，复杂逻辑里硬用贪婪或快速策略解题，容易出现系统性偏差和过度自信。这时就要切到“刻意”模式，把中间步骤显式展开、核查证据链，才能提升准确性和可信度。

双系统提示我们，推理不是单一路线的输出，而是一个多机制协同的多层结构。不能把“Prompt 链”当成唯一的逻辑通道。人类认知最早的协同就体现在三种基本范式上——演绎、归纳、类比，如图 6-2。

- 演绎：由一般规则推出特定结论，逻辑严密、可保证性强，适合规则明确、形式化的领域。
- 归纳：从多个具体案例中提炼一般规律，用于知识扩展、模式发现和经验总结。
- 类比：靠结构映射实现“由已知推未知”，在新颖或抽象问题上释放创造性，是类推思维的核心。

当代认知科学强调，推理并非想完再动，而是一个持续预测、试探、校正的闭环。大脑不断生成假设、驱动行动、收集误差，再修正内部模型。行动既是推理的产物，也是检验推理的重要手段。

同理，Agent 的推理应坐镇行为回路中心，既能向前推动规划与工具调用，也能向后修正模型与信念。

要把这个闭环工程化，推理可以拆成三层抽象。

- 结构层：提供思维的容器，显式刻画任务里的变量、假设、证据及相互关系。
- 流程层：组织推理进程，覆盖假设生成、多路径推演到候选方案评估的完整链条。
- 反思层：承担元推理职能，通过自检、自评和备选路径分析，提升鲁棒性和适应性。

基于这三层，不同任务会呈现出不同形态。根据问题歧义度、探索深度与约束条件，典型形态有四种：链式、树式、图式、类比式，见图 6-3，各自对应不同问题类型。

- 问题清晰、路径唯一时，用链式推理，沿单条路径逐步推进至答案。
- 存在多分支或需权衡时，用树式推理，系统探索各条路径并评估结果。
- 变量依赖复杂、存在循环或非线性交互时，用图式推理，以图结构显式建模要素关联。
- 问题新颖、数据稀缺、缺乏先验规则时，类比式推理常是突破口，通过映射已知结构来启发未知问题的理解。

下面依次展开这四种典型推理模式在 Agent 中的适用场景、结构特征与工程要点。

## 6.1 思维链范式

> “思维链是 LLM 的 ‘草稿纸’。”

> ——魏杰森（Jason Wei），思维链论文作者

数学老师常要求写出证明过程，而不是只给答案。因为跳步容易错，逐步推导才能保证证据链完整、可验证。

传统 LLM 的推理更像靠直觉猜答案的学生，对诗写闲聊这类开放任务尚可，在数学、逻辑、代码等需要严谨推导的任务里，往往算力不足、中间步骤缺失，容易出现灾难性遗忘或逻辑断裂。

思维链的本质是强制 Agent 在给出最终结论前，先生成一系列显式的中间推理步骤。它把原本需要一次跃迁解决的难题，拆成多个只需普通算力处理的原子步骤，实现“用时间换智能”。

核心意图是借助过程显式化，把计算压力摊到更长的时序上，提升可解释性、可验证性和鲁棒性。

### 6.1.1 架构视角：线性流程的优势

从架构看，思维链把黑盒式的输入到输出映射，重构为一条清晰的顺序处理管道，见图 6-4。线性结构降低了复杂问题的处理难度，同时保留了可观测、可拦截、可调试的中间状态，大幅增强透明度与可控性。

图 6-4 中关键组件说明如下。

- 引导机制：启动思维链的钥匙，把简单输入转化为结构化推理。可通过“让我们一步步思考”等显式 Prompt 引导，也可通过微调实现隐式引导。
- 推理缓冲区：Agent 的工作内存，不直接产出结论，而是依次执行问题拆解、中间计算、逻辑推演。产生的 Token 构成后续上下文。
- 逻辑自检：推理结束后的质量关卡，验证链条连贯性和合理性。通过则进入答案提取，未通过则触发重试或修正。
- 答案提取器：把思考过程与最终结论分离。借助特殊终止符识别推理边界，剔除冗长的思维链，只返回清洗后的结论。

### 6.1.2 思维链核心机制

思维链能显著增强推理，并非偶然，而是三方面底层重构的结果。

**1. 概率的重新分配**

直接预测答案等价于计算 P(Answer|Question)。复杂问题下该分布扁平、噪声大，难以命中正确答案。引入中间步骤后，目标变为 P(Answer|Question, step1, step2, …)。条件化收敛了答案空间，从“猜答案”转向“推答案”，准确率与可靠性提升。

**2. 显式分解**

单次前向传播难以同时处理多重逻辑冲突。思维链遵循从简到繁原则，把复杂问题序列化为原子步骤，见图 6-6。这种降维让每一步只需处理简单运算，避免逻辑拥堵。

**3. 自我校准**

步骤显式化后，模型借助注意力“回看”上一步输出，形成微型短期记忆回路，有助于抑制幻觉累积。

### 6.1.3 思维链工程实践

思维链的发展史，也是模型从鹦鹉学舌走向逻辑推理的进化史。工程上大致经历四代演进。

**1. 启蒙时代：作为“魔法咒语”的思维链（2022年）**

始于 Google Brain Jason Wei 等人提出的 Chain-of-Thought Prompting。研究者发现，只在 Prompt 中加入带中间推理的示例，LLM 在数学和逻辑任务上表现明显提升。随后 Kojima 等人证明，即便无示例，仅一句“让我们一步步思考”的零样本指令，也能诱发结构化推理。这一阶段像咒语，机制未明但效果显著。

此时工程聚焦提示工程，LangChain 等框架封装大量思维链模板，实现模式产品化。思维链被视为不改参数、以额外 Token 换取智能的低成本策略。

**2. 黑盒巅峰：OpenAI o1/o3与“测试时计算”（2024年）**

OpenAI o1 的发布把思维链从用户侧技巧内化为模型本能。o1 在输出前强制执行不可见的隐式推理，并通过强化学习优化推理质量而非仅预测下一个词。

o1 验证了测试时计算的新规模规律：参数固定时，增加推理阶段计算、让模型“想得更久”，性能持续提升。推理侧算力可部分转化为智能。

对架构师而言，调用从毫秒级请求响应变为可能持续数十秒的异步任务，需要长连接、状态轮询与流式输出设计。

**3. 开源突围：DeepSeek-R1与纯强化学习的胜利（2025年）**

o1 是封闭黑盒，DeepSeek-R1 则展示了思考如何涌现。它证明无需大规模人工标注监督微调，仅靠纯强化学习和 GRPO 算法，模型即可自发涌现思维链能力。

顿悟时刻体现在训练日志中：模型自发学会自我反思、“Wait, let me check…”、回溯验证和长程规划，这些能力是在追求正确解的奖励下被“逼”出来的。

蒸馏方面，R1 的长思维链数据能有效教导小型模型，7B/14B 版本经蒸馏后推理能力大幅提升，使思维链落地到端侧和低成本场景。

**4. 垂直落地：Agentic Coding（Devin和Cursor）**

应用层，思维链成为编码 Agent 的核心引擎。

- Devin、Cognition AI 处理 GitHub Issue 时，先构建执行计划：阅读文档、定位代码、写测试、改逻辑、跑验证，再生成代码。
- Cursor、Claude Code 内部引入影子工作区，在后台持续进行快速思维链推理，预测下一步修改、预检 Lint 错误等。

此时思维链不仅是文本生成，更像伪代码执行，每一步对应文件系统或编译器的真实操作。

未来的工程师要理解的不仅是 Prompt 怎么写，更是算力在训练与推理间的分配逻辑。系统设计需要在响应速度与严谨思考间做权衡，System 1 还是 System 2 取决于业务场景。

### 6.1.4 思维链模式的演化与组合

思维链是推理能力的基石，从咒语式提示演进为示例规范，再内化为 System 2 思考模式。

**1. 演化路径：从咒语到本能**

- 零样本思维链/咒语式提示：用“Let’s think step by step”等简单指令激发推理潜能，成本低但可控性差，易出现逻辑看似通顺却算错。
- 少样本思维链/示例规范：在 Prompt 中写入高质量 <问题、推理步骤、答案> 示例，规范推理格式，在 RAG 系统中广泛使用。
- 原生/内化思维链：DeepSeek-R1 通过强化学习把思维链内化为默认反应，无需 Prompt 模型自动生成隐式思维令牌，推理成为模型扩展的核心维度。
