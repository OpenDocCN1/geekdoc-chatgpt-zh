## **13.1** 痛点拆解与三 Agent 架构

一套可落地的自动化开发流水线，首先要直面几类典型风险。

• 非确定性风险：大模型生成内容天然带有随机性。若完全放任 Agent 自动编排测试脚本、解读错误日志、循环修复代码，很容易陷入死循环或衍生出不可控的副作用。
• 审批缺失风险：代码提交、分支合并这类关键动作必须设置人工确认关卡，不能让 Agent 全权放行。
• 角色混淆风险：由同一 Agent 同时负责编码与评审，容易产生“当局者迷”，看不见自身逻辑的盲区。

针对以上问题，我们组建了由 3 个 Agent 协作的开发小组，并引入 Lobster 作为工作流编排引擎。三者的分工如下。

• Coder Agent，全栈工程师：承接用户需求，编写核心业务代码，例如贪吃蛇的移动、计分、碰撞检测等。
• Reviewer Agent，资深架构师：对 Coder 提交的代码做静态评审，核查规范性、潜在内存泄漏和逻辑漏洞，并给出改进建议。
• Tester Agent，测试工程师：负责产出单元测试用例，并触发 Lobster 管道执行测试。

在编排层面，OpenClaw 集成 Lobster。Lobster 是一款强类型的流程运行时，能够把多条命令行工具串成确定性 Pipeline，并在其中植入审批节点。Coder 与 Reviewer 完成迭代后，Tester 调用 Lobster 执行测试流水线。测试失败时，错误日志会回传给 Coder 修复；测试通过后，流水线会进入暂停状态，通过飞书推送审批请求，待用户确认后自动生成 Pull Request。

## **13.2** 关键能力与工具拆解

本案例不再局限于 ClawHub 的第三方技能，而是深度使用 OpenClaw 自带的高级工具与多智能体通信机制。

### **13.2.1** Lobster 流水线引擎

Lobster 并非普通技能，而是一个可选的插件工具。它读取 .lobster 格式的 YAML/JSON 文件，串行执行多步骤命令。其核心价值在于：

• 一次调用完成多步：Agent 只需触发一次 Lobster，即可完成一系列 Shell 命令，大幅减少 Token 消耗与往返耗时。
• 内置审批能力：当流程走到 approval: required 的节点时，执行会暂停，返回 resumeToken 给 OpenClaw，并通过飞书展示审批卡片。
• 确定性与安全保障：执行逻辑写死在 YAML 中，限制了模型的即兴发挥，保证构建与测试过程可控、安全。

启用 Lobster 需要在 openclaw.json 中完成配置，并确认宿主机已安装 Lobster CLI。

### **13.2.2** GitHub 技能

要实现拉取代码、创建分支、提交 PR 的闭环，需安装 ClawHub 上最热门的开发者技能 github。该技能封装了官方的 GitHub CLI，即 gh，让 Agent 用自然语言操作仓库，是完整 CI/CD 的关键一环。

clawhub install github

### **13.2.3** gh 命令行上手

gh 是一款功能完整的终端工具，几乎能覆盖 GitHub 网页的所有操作，如建库、提交、发起 PR、查看 Issue 等。它相当于本地终端与 GitHub 后台的桥梁，让原本需要网页登录的操作变成几行命令。

1．gh 的安装

本案例以 CentOS 为例，其他系统思路类似。推荐使用官方源安装，适配 CentOS 7/8/Stream。

打开终端执行：

sudo dnf config-manager --add-repo https://cli.github.com/packages/rpm/gh-cli.repo

该命令为系统添加 GitHub 官方软件源，形成软件检索清单。

注意：若提示 dnf: command not found，说明系统未预装 dnf，先执行 sudo yum install dnf -y 安装后再添加仓库。

添加成功后执行安装：

sudo dnf install gh -y

-y 表示自动确认。安装完成后校验版本：

gh --version

若输出类似 gh version 2.88.1 (2026-03-12)，即安装成功。

路径 ~/.openclaw/workspace-coder/SOUL.md

# 角色定义
你是一名经验丰富的全栈工程师，精通 HTML5、JavaScript 与前端游戏开发，负责按需求输出高质量可维护代码。

## 核心职责

- 收到 Reviewer 建议后虚心修改，直至通过。
- 收到 Tester 反馈的失败日志时优先处理，定位修复后再通知 Tester 重测。
- 未经 Reviewer 批准和 Tester 验证通过，严禁私自提交或创建 PR。

2．Reviewer Agent 的 SOUL.md

路径 ~/.openclaw/workspace-reviewer/SOUL.md

# 角色定义
你是一名极其严苛的资深架构师，负责代码静态审查，对整洁度、性能、安全要求极高。

## 审查准则
- 收到 Coder 请求后仔细阅读改动代码。
- 重点检查：变量命名是否语义化、是否滥用全局变量；核心逻辑如碰撞检测是否存在边界漏洞；是否存内存泄漏风险；是否包含必要注释。
- 发现问题时用 agent_send 指出错误行与改进方案；代码合格则通知 Coder 通过，并用 agent_send 通知 Tester 开始写用例并运行测试。

3．Tester Agent 的 SOUL.md

路径 ~/.openclaw/workspace-tester/SOUL.md

# 角色定义
你是一名专业的自动化测试工程师，负责编写单元测试并管理 CI 流水线。

## 工作流准则
- 收到 Reviewer 通过通知后，研读业务代码。
- 使用 Jest 或 Mocha 为核心逻辑编写覆盖率 ≥80% 的单元测试，如初始状态、移动、碰撞判定。
- 编写完成后调用 Lobster 运行项目根目录的 dev-pipeline.lobster。
- 若返回失败日志，用 agent_send 通知 Coder 修复；若返回 needs_approval 状态，说明测试全部通过，须向飞书用户发送测试通过通知并提醒点击批准以创建 PR。

### **13.3.3** 编写 Lobster 工作流文件

在项目根目录创建 dev-pipeline.lobster，定义确定性审查测试流程。

YAML
# dev-pipeline.lobster
name: code-review-and-test
steps:
  - id: lint
    command: npm run lint --silent
  - id: test
    command: npm run test --silent
    stdin: $lint.stdout # 仅 lint 通过时执行
  - id: approve_pr
    command: echo "All tests passed. Ready to create PR."
    approval: required # 暂停等待飞书人工批准
  - id: create_pr
    command: gh pr create --title "Feature: Snake Game" --body "Automated PR created by OpenClaw Pipeline"
    condition: $approve_pr.approved # 批准后才执行

逻辑清晰：先代码检查，再单元测试，通过后暂停请求人工审批，批准后自动调用 GitHub CLI 创建 PR。
