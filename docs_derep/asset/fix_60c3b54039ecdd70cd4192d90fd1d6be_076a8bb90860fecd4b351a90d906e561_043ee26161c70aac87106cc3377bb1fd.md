## 第 3 章 学会和 OpenClaw 对话

基础安装和配置完成后就能开始使用，但很多人会困惑：明明按步骤下指令，为什么 OpenClaw 总是理解偏？同样任务别人就很顺，自己却总出错？

问题不在于模型不够智能，而在于沟通方式需要优化。它能听懂人话，但理解路径和人不一样。本章解决如何让指令更精准、怎么调教工具更贴合需求，以及如何从“能用”进化到“好用”。

## 3.1 让它读懂你的意思

和 OpenClaw 沟通本质是与大语言模型对话。每个字都会先被“理解”再生成回复或执行动作。理解质量受指令清晰度、上下文完整度和表达准确度影响，直接决定反馈是否符合预期。

### 3.1.1 提示词三要素

第一次打开对话框时常会不知说什么。核心在于提示词，即你输入的文字。

很多人习惯用极简指令，如“帮我整理文件”“查一下这个”。对人足够，对 AI 信息太少，只能靠猜，猜的偏差往往很大。

一个好的提示词应包含明确目标、充分背景、必要信息，三者都要齐全。

先讲清目标。不要把 OpenClaw 当成读心术。比如“帮我整理一下”要说明整理什么、从哪整理、整理成什么格式。

背景信息同样关键。例如让你写求职邮件，只说“帮我写一封”只能得到千篇一律的模板。补充岗位、公司、自身经历等，输出才会落地。

### 3.1.2 描述任务的技巧

掌握原则后，可用以下实用技巧。

把大任务拆成小步。复杂任务如“分析行业趋势”，可拆为收集数据、梳理玩家、分析格局、给出建议，每步单独问，结果更清晰，也便于把控质量。

给例子比说教有效。想控制写作风格，别只说“写得专业点”，直接给一个参考样本：“这是我喜欢的风格，请参考写一段类似的”。具体例子胜过抽象形容。

说清输出格式。需要表格、清单或特定结构时提前说明：“请整理成表格，列出公司名、成立时间、融资轮次”。指令越具体，结果越可直接用。

多轮对话逐步推进。不必一次说完，像聊天一样先拿第一步结果再追问第二步。如先让列头部公司，再问“按成立时间排序”。

一次没说清也正常，直接追问或纠正：“我刚才没表达清楚，其实是…”、“这部分对了，那里我想改成…” 模型会记住上下文不断调整。

### 3.1.3 角色设定方法

通过角色设定引导行为，适合需要专业知识或特定语气的场景。

核心是在任务前先说明角色，如“你现在是有十年经验的资深产品经理”或“请以心理咨询师视角分析”。

角色像一个过滤器，会影响理解角度、回答语气和知识引用。

有效角色设定通常包含专业背景、经验水平、思维模式。如“你是一位严谨的数据分析师，擅长用统计学解释现象并习惯用数据说话”，框架清晰易懂。

### 3.1.4 上下文管理策略

多轮任务中上下文管理很关键。

主动提供前置信息是首要策略。开始新任务前可简要复述已有信息，如“基于我们之前讨论的用户画像，现在帮我想个营销方案”，避免让模型翻历史记录。

适时重申关键约束更稳妥。预算上限、截止时间、语言要求等，在每次对话中适当提醒比只提一次更保险。

进阶做法是利用系统提示词。OpenClaw 可配置长期生效的系统提示，如“提到‘简报’指不超过两页 A4 文档”“所有代码注释用中文”，减少重复说明。

### 3.1.5 不同场景的沟通模式

文案写作注重风格引导。提供足够参考样本并明确目标受众，说明是面向小白还是专业用户，风格是活泼还是稳重，输出更贴合。

数据分析需清晰说明数据来源和分析目的。告知数据位置、想发现的问题、结果呈现形式，复杂分析时提供数据结构说明很有帮助。

编程辅助重在准确描述需求和报错。遇到 Bug 时完整提供错误信息、相关代码、已尝试方法，能更快定位。新功能开发时说明输入、期望输出、语言框架，信息完整才高效。

创意类任务需要发散引导。限制越少创造空间越大，可用头脑风暴式提示：“帮我想十个创意方向，先不要考虑可行性，想到什么写什么”。
