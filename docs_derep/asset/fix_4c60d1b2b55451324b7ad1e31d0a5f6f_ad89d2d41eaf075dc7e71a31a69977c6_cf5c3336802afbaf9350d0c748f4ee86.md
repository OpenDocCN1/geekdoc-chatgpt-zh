让检索增强更可靠的四种实操

工程化落地 RAG 时，表现好坏和问句设计及索引组织紧密相关。以下四类常用增强手段，分别对应多跳推理、召回盲区、语义偏差和长文档上下文缺失，均可直接复现。

一、对多步问题进行子问题拆分与合成

需要串联多个信息点或进行多步推理时，单次检索容易遗漏。先让模型把原问句拆成若干更具体的子问句，对每个子问句独立检索并生成答案，再把这些问答按序号拼成上下文交给最终合成链。子问句更聚焦，检索信号更强，合成结果的证据链也更完整。

def retrieve_and_rag(question,prompt_rag,sub_question_generator_chain):

    """RAG on each sub-question"""

    # 问题拆解

    sub_questions = sub_question_generator_chain.invoke({"question":question})

    # 初始化列表保存 RAG 结果

    rag_results = []

    for sub_question in sub_questions:

        # 为每个子问题获取文档

        retrieved_docs = retriever.get_relevant_documents(sub_question)

        # 根据子问题和获取的文档生成答案

        answer = (prompt_rag | llm | StrOutputParser()).invoke({"context": retrieved_docs, "question": sub_question})

        rag_results.append(answer)

    return rag_results,sub_questions

二、通过抽象问句扩大召回面

问句过于具体时，检索易受用词限制。先让模型把原问句抽象为更概括的主题问句，同时对原始问句和抽象问句进行双通道检索，再融合结果作答。以“2024 年中国是否发射天问三”为例，抽象后会指向中国火星探测的整体进程，从而召回更宽泛的相关资料。

from langchain_core.runnables import RunnableLambda

response_prompt_template = """需要根据如下提供信息来回答用户提出的问题，如果如下提供的信息对回答用户问题没有帮助，就忽略它们。

#{normal_context}

#{step_back_context}

#用户问题: {question}

#请给出答案:"""

response_prompt = ChatPromptTemplate.from_template(response_prompt_template)

chain = (

    {

        "normal_context": RunnableLambda(lambda x: x["question"]) | retriever,

        # 用退一步的问题来获取信息

        "step_back_context": RunnableLambda(lambda x: x["step_back_question"]) | retriever,

        "question": lambda x: x["question"],

    }

    | response_prompt

    | ChatOpenAI(temperature=0)

    | StrOutputParser()

)

chain.invoke({"question": question,"step_back_question":step_back_question})

三、用假设文本引导检索

HYDE 的思路是让模型先写一段针对问题的假设回答，再用这段文本去检索。假设文本与真实资料往往在词法和表达上接近，能带来更好的匹配，随后再用常规 RAG 基于检索结果生成最终答案。

四、父子文档结构保留长文本语境

长篇传记或报告切分后容易丢失整体语境。采用父子检索器，先用切分器把全文拆成小块建向量索引，同时保留完整原文作为父文档。检索时先命中小块，再回溯到父文档，既保持召回精度又保证上下文完整。
