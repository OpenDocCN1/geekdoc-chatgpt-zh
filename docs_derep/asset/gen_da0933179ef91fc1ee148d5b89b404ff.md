## 1.1 智能体时代的图景

MCP 应运于生成式 AI 时代，随着 AI 智能体兴起而被提出。因此，理解智能体的概念、应用与挑战是学习 MCP 的前提。若已有深入认知，可直接跳转至 1.2 节。

### 1.1.1 智能体的早期脉络

智能体并非大模型时代的专属，其雏形可追溯至 AI 学科初创期。早期被定义为能感知环境、经推理决策并采取行动以达成目标的实体，具备感知—推理—行动闭环，如图 1-1 所示。

20 世纪 80-90 年代，研究逐步深化，以专家系统、符号系统等形态出现，核心是借助规则与知识库模仿专家决策。此类系统常受计算能力不足、数据匮乏、环境适应性差等因素制约，应用多限于理论探索与小规模场景。

总体来看，在深度学习兴起前，智能体面临明显瓶颈：规则难以覆盖多样场景、泛化能力薄弱、语言交互能力有限。尽管如此，自主感知、自主推理决策、自主行动的基本理念始终被学界与业界视为 AI 关键方向，并持续推动技术演进。直到 LLM 大语言模型的出现，才为智能体在更广场景落地提供了新范式。

### 1.1.2 大模型时代的智能体

Transformer 架构于 2017 年提出，随后 GPT-3.5、GPT-4 等大模型快速发展，智能体研究迎来爆发。大模型时代的智能体摆脱纯规则与符号限制，具备更强理解与泛化、更丰富知识、更复杂推理与更强记忆，从而完成更复杂的任务。

以 GPT、Claude、DeepSeek 为代表的大模型赋予智能体三大革命性能力。

1. 自主推理与规划。借助链式思考 Chain-of-Thought 等提示范式，智能体可将复杂任务拆解为子任务。例如用户输入“帮我规划东南亚三日游”，智能体自动生成行程规划→景点调研→预算评估的推理链，并在其基础上产出行动步骤。
2. 推理与工具使用。借助函数调用或 ReAct 推理—行动范式，智能体能推理并调用工具完成实时操作。例如先调用 Google API 获取位置，再通过图像模型生成旅游路线图。工具使用是智能体区别于纯聊天机器人的核心。
3. 记忆与知识检索。结合向量数据库的存储与语义检索，加上大模型理解能力，智能体可实现跨会话上下文继承与长期记忆。配合 RAG 检索增强生成，智能体能针对不同用户与环境做出个性化决策。

若把大模型比作博览群书的智者，智能体就像其拥有强大记忆与执行力的管家，会依据需求拆解任务并主动调配资源。例如指令“对比 A 公司与我公司产品差异并把报告发到邮箱”，智能体会规划并执行：

1. 通过网页搜索工具获取 A 公司产品信息。
2. 通过本地 RAG 工具检索我司产品信息。
3. 借助大模型生成对比报告。
4. 使用邮件工具发送至邮箱。

可见基于大模型的智能体把强语言模型与主动行动机制结合，让模型不仅能懂、能想，还能做。

### 1.1.3 两种智能体系统形态

智能体正快速发展，整体共识逐渐形成，但细分划分仍百花齐放。Anthropic 公司 2024 年文章《构建有效智能体》中给出的划分较为清晰务实。

Anthropic 将现有智能体统称为智能体系统 Agentic System，并从架构上分为两类，如图 1-3 所示。

[PRE2]

图 1-3

1. Workflow 工作流
也称 Agentic Workflow。此类系统任务路径明确且预先编排，通过既定流程、步骤与工具链实现目标。优点是可预测性强、结果可控，适合企业中借助大模型提升智能化但流程相对固化的业务，如标准化数据抽取与分析。

常见构建块是大模型调用 LLM Call。随着模型能力增强，增强型大模型调用 Augmented LLM Call 成为主流。它不再是简单问答，还可带简单知识检索与工具使用，可视为“微型智能体”嵌入更大工作流。

例如一个典型顺序模式工作流包含 3 个增强型大模型调用，如图 1-4 所示。

[PRE3]

图 1-4

2. Agent 智能体
指更理想的真正智能体系统，强调自主性与灵活性，通过动态推理、自主决策与环境交互达成目标。相比 Workflow，Agent 适用于开放、通用、动态且难以穷举的任务，如面向个人的通用助手。

既然 Agent 更自主，为何仍需 Workflow？因为大模型能力仍有限。即使理解推理能力惊艳，在模拟人类任务的准确率测试中，模型最高仅接近人类 50%。“黑盒”Agent 的不确定性在关键场景是致命缺陷。因此 Workflow 作为补充很有价值：遵循预定义流程但以大模型为核心完成多步任务，以牺牲部分灵活性换取可靠性。

类比总结：Workflow 像听话的员工，按既定步骤完成任务并借助大模型提升智能；Agent 更像被授予权限的代理人，自主规划步骤并完成。两者共同点是都需借助工具提升行动力。

### 1.1.4 智能体面临的挑战与演进方向

各类智能体已在个人与企业端涌现。个人端以助理、智能家居助手等形态融入生活；企业端多出现于客服、营销、财务、HR 等流程自动化。然而当前智能体仍处积累期，市场产品多集中于个人助理、娱乐、写作等可靠性要求不高的领域。在对准确性、可预测性、可追溯性要求极高的生产场景，智能体仍面临大模型局限性带来的规划错误、不当建议、风险内容与输出不确定等挑战。

尽管仍处早期，其潜力巨大。未来演进可展望如下。

1. 更强的自主性与智能化。随着技术进步，智能体将更好理解人类意图、逻辑推理与复杂任务处理，在更多场景下自主决策与执行。
2. 深度行业化与定制化。各行业将定制专属智能体，如开发助手、医疗诊断助手、家庭助手及智能实体机器人等。
3. 更强的个性化与人性化。智能体将通过长期互动学习用户习惯、个人信息与偏好，提供更贴心服务。
4. 持续学习与自适应。智能体具备根据环境变化与新数据自我调整优化的能力，不断提升智能水平。
5. 伦理与法规重视。随着应用普及，隐私、安全、伦理关注将推动相关法规与标准，确保 AI 负责发展。

## 1.2 初识 MCP

### 1.2.1 智能体时代集成复杂度提升

智能体兴起使 AI 应用集成环境愈发复杂。应用不再止于与大模型对话，而是需自主协调任务、调取外部数据、使用外部工具，甚至与其他智能体协作。这种与纷杂外部资源交互的能力，成为智能体落地的关键挑战。

举例：作为技术博客主理人，你可能想拥有“AI 秘书”，定期采集行业动态、GitHub 热门项目排名、关注科技巨头的社交媒体新闻，整理编辑后发邮件，并通过 OA 系统自动提醒你。构建此类智能体需要与多系统连接：搜索引擎或浏览器获取结果、社交平台或专业社区开放 API、文件系统与编辑排版工具、云邮件系统、企业 OA 接口推送通知。

你需研究各类模块与第三方 API 并连接之。学会调用搜索引擎 API、使用 Playwright 自动浏览、使用云邮件接口、使用 Python 文档编辑库……历经重重 Bug 后智能体终于上线。

使用一段时间后新问题出现：

1. 增加新功能需研究新平台协议。
2. 某 API 调整安全机制与数据格式，需重新集成与测试。
3. 与同事交流发现大量集成工作已重复。
4. 应用反复修改后难以维护，频繁出错。

根源在于为让 AI 秘书具备“动手能力”，每接入新数据源、工具或服务，开发者都需编写定制集成代码，处理消息格式、身份认证等安全策略，做大量“黏合”工作，如图 1-5 所示。

### 1.2.2 MCP：面向集成的统一标准

Anthropic 于 2024 年年末提出的 MCP，正是为简化智能体与外部资源集成而设计。它定义统一方式，让智能体访问、管理与共享所需外部数据源与工具，摆脱逐个适配的碎片化方案。核心思路是在传统架构中引入中间层，如图 1-6 所示。

[PRE5]

图 1-6

在该架构下，智能体通过统一 MCP 连接可共享的中间层即 MCP Server 访问外部资源与工具，中间层负责适配不同外部资源。

好处体现在：

1. 简化开发与集成。智能体无需适配各私有协议，只需以统一方式连接到 MCP 服务端并调用其公开资源，显著缩短上线时间。
2. 提升互操作性。采用相同 MCP 集成的不同智能体可良好互通，可在不同提供商、不同 MCP 服务端间灵活切换，极少改动即可使用更优工具。
3. 良好可扩展性与弹性。遵循相同标准“同一种语言”，可随时插拔新外部资源。如同 USB 接口标准，新设备即插即用。插入新 MCP 服务端即可为智能体扩展新能力，如图 1-7 所示。

4. 快速适应变化、提升可维护性。若外部资源接口变化，只需在对应 MCP 服务端适配数据格式、通信协议与安全机制，所有接入的智能体即可无缝切换，且应用侧使用接口保持不变。
5. 形成新的 AI 能力共享生态。
