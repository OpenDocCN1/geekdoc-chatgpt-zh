Ubuntu 的使用特点

发布节奏快：Ubuntu 约每半年推出一次新版本，让用户能较早接触到新软件和新能力。对 LLM 这类需要紧跟深度学习框架更新的场景，这一点有帮助。

上手友好：交互界面人性化，配套文档丰富，初学者进入门槛较低。官方提供技术支持，社区资源也较为充裕。

硬件覆盖面宽：对各类硬件适配度高，部署 LLM 时对机器选择的限制少。

短板

稳健性偏弱：偏重新特性的策略使系统稳健性相对不足，在对可靠性要求极高的生产服务器环境中需权衡。

LTS 维护期：长期支持版的维护周期虽比常规版长，但放在 Linux 生态里仍显偏短，届满后需要规划升级或迁移。

## 8.3 搭建环境所需组件

### 1. CUDA
CUDA 由 NVIDIA 发布，是面向 GPU 的通用计算方案，涵盖驱动、接口、库、编译器与调试器等部分。

该架构调动 GPU 内部并行单元，让开发者编写可扩展的并行程序。主机 CPU 与设备 GPU 的分离模型下，代码可用 C/C++ 等语言编写，再经 NVIDIA 工具链编译优化。

适用范围包括图像处理、物理仿真、深度学习、科学计算等。借助 GPU 并行能力，CUDA 能把原本耗时长的计算压缩到很短时间内完成。整体而言，CUDA 帮助开发者释放 GPU 并行潜力，大幅提升计算效率。

### 2. cuDNN
cuDNN 即 cuDA Deep Neural Network library，是 NVIDIA 为自家 GPU 设计的深度神经网络加速库。对前向后向卷积、池化、归一化、激活等标准操作给出高度优化实现，使训练与推理阶段提速明显。

全球深度学习研究者和框架开发者普遍依赖 cuDNN 以获得 GPU 加速，避免在底层调优上耗费过多时间。兼容 Caffe2、Chainer、Keras、MATLAB、MxNet、PyTorch、TensorFlow 等主流框架。

总体看，cuDNN 是 CUDA 生态的重要一环，为神经网络训练与推理提供高效便捷方案，帮助开发者更好利用 NVIDIA GPU 算力，推动各领域创新。

### 3. Anaconda
Anaconda 为开源 Python 发行版，内置 conda、Python 及大量科学计算和数据分析包。conda 包管理器提供包管理与环境管理功能，轻松解决多版本 Python 并存、版本切换、第三方包安装等难题。

发行版预装众多常用数据分析与机器学习库，用户可迅速搭建 Python 数据科学环境。新手与专业人士均可借此高效开展科学计算与数据分析。

### 4. PyTorch
PyTorch 由 Facebook AI 研究院 FAIR 研发，面向 GPU 加速的深度神经网络编程。

设计追求封装少、重复少，风格简洁灵活且易调试。原生支持 Python，运行时生成动态计算图，错误可直接定位到触发代码行，调试体验顺畅。

可与 Caffe2、Chainer、Keras、MATLAB、MxNet、TensorFlow 等框架互通，集成成本低。也支持分布式训练，兼顾研究与生产场景的可扩展训练与性能优化。

整体而言，PyTorch 为研究者与开发者提供 GPU 加速、动态图和高效分布式训练能力，是功能强大且易用的神经网络框架。

VSCode 由微软推出，免费开源的源代码编辑器，覆盖 JavaScript、TypeScript、Python、PHP、C#、C++、Go 等语言，提供优秀的编辑与调试体验。

设计强调用户体验与扩展性，插件生态丰富，通过扩展可快速增强功能。具备语法高亮、可自定义快捷键、括号匹配、代码片段收集等现代编辑器标配特性。

### 8.4.4 模型类型
所有 LLM 基本都基于 Transformer 架构，通常可归为三类。

1. Decoder-only
多用于生成类任务，如文本生成、机器翻译等。
代表模型：GPT 系列，包括 ChatGPT，多用于文本生成与对话系统。
2. Encoder-only
多用于理解类任务，如文本分类、实体识别等。
代表模型：BERT，即 Bidirectional Encoder Representations from Transformers，用于问答、文本分类等多种 NLP 任务。
3. Encoder-Decoder
兼具编码与解码能力，适合既要理解输入又要生成输出的任务，如机器翻译、问答等。
代表模型：Transformer 本身即为 Encoder-Decoder 结构，用于序列到序列学习。ChatGLM 也是基于 Transformer Encoder-Decoder 构建的对话模型。需要说明的是，ChatGLM 并非业界通用名称，而是特指某个项目或公司的模型。

总体来看，Transformer 凭借强大的自注意力机制和并行计算能力大幅提升了 NLP 性能，不同类型在不同任务上各有侧重。

### 8.4.5 模型开发框架
主流框架有三种：PyTorch、TensorFlow 和 PaddlePaddle。

### 8.4.6 量化大小
模型量化用于缩小模型体积、降低推理延迟，同时尽量保留精度。核心做法是将权重和激活值从 32 位浮点数 Float32 转换到更低精度整数，如 8 位 Int8 或 4 位 Int4。

1. Int8 量化
权重与激活值转为 8 位整数，模型体积和显存占用大幅下降，且整数运算通常更快，推理速度提升明显。在保持较高精度的同时显著降低存储与计算需求，是目前应用最广的量化方式之一。
2. Int4 量化
权重与激活值进一步压缩为 4 位整数。这种量化方式能够实现更进一步的模型压缩。

## 8.5 量化技术
量化手段可归纳为三种。

- 1. AWQ
AWQ 用于压缩神经网络模型、降低计算复杂度。其核心思路是仅保护模型中约 1% 的关键权重，其余 99% 的权重进行量化，从而大幅减少量化误差，确保性能损失可控。
- 2. GPTQ
GPTQ 由 Google AI 提出，基于 Group 量化和 OBQ 方法。Group 量化把权重拆分为多个子矩阵进行量化，有助于减小模型与计算量。OBQ 用于优化量化流程，进一步提升量化后性能。需注意，GPTQ 在量化语境下指量化技术，而非 Generative Pre-trained Transformer。
- 3. GGUF
GGUF 由 Llama.cpp 团队推出，用以替代已停止维护的 GGML 格式。它提供了一种标准化方式来表示和交换量化后模型数据。GGUF 支持多种量化方案如 Q2_K、Q3_K_S、Q4_K_M 等，可优化文件大小与性能，并提供 2 位、3 位、4 位等不同精度的模型，便于在 CPU+GPU 环境下推理。兼容性良好，适配多款第三方图形界面与库。

## 8.6 模型选择

### 8.6.1 通义千问
通义千问由阿里云推出，具备多轮对话、文案创作、逻辑推理、多模态理解及多语言支持等能力。
参数大小：7B（试过较卡）、4B（建议）、1.8B（建议）、0.5B（建议）。
量化：不建议使用量化，以免影响精度。

### 8.6.2 ChatGLM
ChatGLM 基于千亿基座模型 GLM-130B 开发，由清华大学 KEG 实验室与智谱 AI 共同研发，支持中英双语，具备问答、多轮对话和代码生成功能。目前有两个版本：千亿参数的 ChatGLM 内测版和 6B 参数的 ChatGLM-6B 开源版。

ChatGLM-6B 于 2023 年 3 月 14 日开源，可在消费级显卡上本地部署。模型在约 1TB 中英双语语料上训练，并结合监督微调、反馈自助、人类反馈强化学习等技术，已能生成更符合人类偏好的答案。
参数大小：6B。
量化：不建议使用量化，以免影响精度。

### 8.6.3 Llama
Llama 即 Large Language Model Meta AI，由 Meta 人工智能研究院研发，旨在帮助研究人员和工程师探索 AI 应用。该模型在生成文本、对话、总结材料、证明数学定理或预测蛋白质结构等复杂任务上具有广阔前景。

Llama 首次发布于 2023 年 2 月，在海量文本数据上训练，学习了广泛的语言知识与模式，能根据输入生成连贯有逻辑的文本。
参数大小：7B、13B、33B、65B。
量化：不建议使用量化，以免影响精度。

## 8.7 模型应用实现方式
按实现难度从易到难可分为 Chat、RAG、高效微调三种。

### 8.7.1 Chat
Chat 通过 prompt 实现模型应用，以对话方式解决问题，核心技术即 prompt 工程。

### 8.7.2 RAG
RAG 融合了信息检索与文本生成。当用户提问时，系统先从大型知识库或文档集中检索相关信息，再结合检索结果生成答案，可使输出更准确具体。

RAG 的优势在于引入外部知识源，丰富模型输出。常见实现包含 prompt + 知识库（通常为向量数据库）+ 向量化方法，向量化技术常用 BERT、ERNIE 等。

### 8.7.3 高效微调
高效微调是对大模型进行快速有效调整，使其适配特定任务或领域。由于 LLM 参数动辄数十亿，全面微调成本高昂，因此发展出多种高效方法。

代表方法 LoRA，即 Low-Rank Adaptation，通过在权重矩阵上添加低秩更新实现微调，大幅减少可训练参数量，在保持性能的同时降低成本与复杂度。

实践中需要少量高质量标注数据，以及充足算力如 A100、V100。高效微调通常由 LoRA + 高质量标注数据 + 算力构成。

## 8.8 通义千问 1.5-0.5B 本地 Windows 部署实战

### 8.8.1 介绍
通义千问 1.5-0.5B，简称 Qwen1.5-0.5B，是阿里云推出的 0.5B 参数规模模型。基于 Transformer 架构，在超大规模预训练数据上训练，数据涵盖网络文本、专业书籍、代码等多种类型。在此基础上，团队通过对齐机制打造了 AI 助手 Qwen1.5-0.5B-Chat，本案例基于该仓库。

主要特点如下。
低成本部署：提供 Int8 与 Int4 量化版，推理显存不足 2GB，生成 2048 个 token 约需 3GB 显存，微调最低约 6GB 显存。也提供基于 AWQ、GPTQ、GGUF 的量化模型。
大规模高质量语料：使用超 2.2 万亿 token 预训练，覆盖高质量多语言、代码、数学等，兼顾通用与专业领域，并对语料分布进行了优化。
优秀性能：支持 32KB 上下文长度，在常识推理、代码、数学、翻译等中英文下游任务上显著优于同规模开源模型。
更全面的词表：约 15 万词表，对多语言更友好，便于在不扩展词表情况下增强部分语种能力。
系统指令跟随：可通过调整系统指令实现角色扮演、语言风格迁移、任务与行为设定等。
