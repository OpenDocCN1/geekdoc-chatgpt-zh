## 4.2 智能网联基础报文的定义与结构

实现智能网联驾驶各阶段的应用，本质上要先对智能网联基础报文进行定义与解析，以满足 V2X 交互需求。

### 4.2.1 消息层数据集如何搭建

消息层数据集采用 ASN.1 即抽象语法记法一进行定义，遵循“消息帧-消息体-数据帧-数据元素”逐层嵌套的逻辑。交互的编解码方式遵循非对齐压缩编码规则 UPER。消息帧是单个应用层报文的统一打包格式，也是编解码的唯一操作对象。消息帧由不同类别的消息体构成并支持扩展；消息体是最基础的 5 种报文；数据帧由其他数据单元或数据类型组合而成，具有特定实际意义，是消息体的组成部分；数据元素则是消息体或数据单元的构成部分，由基础数据类型生成，具有物理意义。

#### 1. 基本安全报文 BSM

##### 1）定义

基本安全消息 Basic Safety Message 是使用最广泛的应用层报文，用于车辆间交换安全状态数据。车辆通过广播自身实时状态告知周边车辆，从而支撑各类协同安全类业务，BSM 的使用场景见图 4.2 所示。

[PRE3]

图 4.2　BSM 的使用场景

##### 2）消息主体结构及说明

作为智能网联驾驶中各网联汽车发送和广播的报文，BSM 需要具备消息编号、车辆编号和发送时间，以实现分类与识别。

BSM 还需包含车辆自身信息，车辆出厂时已具备尺寸大小和车辆类型信息。车辆类型可从基本类型如小汽车、卡车等定义，也可从燃料动力类型定义。车辆行驶时的实时状态也是 BSM 的组成部分，运动实时状态可用 3D 位置、速度、航向概括，并延伸到车辆控制层面，涵盖挡位、方向盘转角、四轴加速度、刹车系统状态等信息。

其中 3D 位置为经度、纬度和高程；挡位包括空挡、停止挡、前进挡和倒挡；四轴加速度为纵向加速度、横向加速度、垂直加速度、横摆角速度；刹车系统状态包含刹车踏板踩下情况、车轮制动情况、牵引力控制系统作用情况、制动防抱死系统作用情况、车身稳定控制系统作用情况、刹车助力系统作用情况和辅助制动系统一般指手刹情况，共 7 种状态。这些信息与速度、航向角直接相关，故需纳入车辆基本安全报文。

除必要的车辆自身信息外，其他信息也有助于提升智能网联汽车的智能性并预判驾驶风险，包括消息发送时间精度、实时位置精度、定位系统精度以及由车速精度、航向精度、方向盘转角精度组成的运行状态精度。精度信息意味着智慧交通中基于报文内容与预设算法得到的交通参与者实时信息的准确性，对统筹交通路线管理意义重大。

此外 BSM 还包括车辆安全辅助信息集合和紧急车辆辅助信息集合。车辆安全辅助信息集合由车辆特殊事件状态、车辆历史轨迹、路线预测、车身灯光状态等构成。紧急车辆辅助信息集合用于向周围车辆告知本车正在进行特殊作业的状态，如警车、消防车、救护车需获得优先或避让，包含车辆特殊行驶状态、警笛和指示灯使用等。

##### 3）BSM 应用

在实际应用中 BSM 更像一个“广播员”，持续将自车状态广播给周边车辆以交换安全状态数据并支撑各类业务。

例如前向碰撞预警、交叉路口碰撞预警、紧急制动预警等场景中，两车互收互解 BSM 中的基础信息如时间、位置、速度、航向角、车身尺寸等即可完成碰撞预警计算；再结合转向灯判断即可实现盲区/变道预警。

BSM 中除基础信息外还包含车辆安全辅助信息及紧急车辆附加信息，涉及车辆特殊状态位、灯光信息及紧急车辆状态，通过灵活应用可实现异常车辆预警、车辆失控预警、紧急车辆提醒等功能。

BSM 还支持兼容性拓展，如 T/CSAE158-2020 就在 TD/T3709-2020 标准定义 BSM 的基础上丰富了自动驾驶车辆特有信息，提供更精准的车辆及行驶信息，支持路侧协同的车道级通行等场景。

##### 1）定义

地图消息 MAP 由路侧单元广播，向车辆传递局部区域地图信息，包括局部路口、路段、车道信息及道路间连接关系。单个 MAP 可包含多个路口或区域的地图数据，MAP 的使用场景见图 4.4 所示。

[PRE7]

图 4.4　MAP 的使用场景

##### 2）消息主体结构及说明

同 BSM 一样，MAP 也需要消息编号、发送时间以区分不同广播。消息编号配合时间戳可防重放攻击，时间戳一般读取 GPS 时间后加入 MAP 发送。地图中包含的路段、车道、路口本源均为节点，因此 MAP 的一个组成字段为地图节点列表，节点是地图最基本单元，可为交叉路口或路段起点/终点。

为区分不同节点，引入节点 ID 和节点名字段。节点位置信息是确认地图构成的必要条件，为减少位置数据量，采用以地图中心节点为参考，其他节点位置信息使用中心节点坐标加上各自偏移量。地图上顺序的两个节点可确定一条有向路段，起点记为上游节点，终点记为下游节点，定义地图路段时以下游节点为参考定义下游节点的上游路段列表作为字段信息。

通常路段信息包括路段名和车道信息。映射到消息格式时，上游路段首先包含上游节点 ID 及路段名以确认起点和名称。路段常包含多条车道，需对车道列表中不同车道的宽度、限速、允许转向行为、车道属性、上游车道与下游车道的连接关系等进行定义。

##### 3）MAP 应用

MAP 用于描述道路信息，在智能网联应用中更多扮演“服务者”角色，为业务落地和预警触发提供明确的位置信息。例如路侧设施可将 MAP 下发给周边车辆，提升行车环境感知、定位精度并便于规划合适行驶路线。MAP 已成为应用落地的关键支撑。

此外 MAP 可与 SPAT 消息结合，为车辆提供实时前方信号灯相位信息。在闯红灯预警场景中，若前方大车遮挡或恶劣天气影响视线，导致远车无法正确判断红灯，预警应用会检测车辆当前位置和速度，通过计算预测车头经过路口停止线时信号灯状态并向驾驶员预警。此过程用到 MAP 中路口始末点位置信息和 SPAT 中路口信号灯相位状态信息。

#### 3. 路侧消息

##### 1）定义

路侧信息 Road Side Information RSI 指路侧单元向周围车载单元发布的交通事件信息及交通标志信息。RSI 的使用场景如图 4.6 所示。

其中交通事件信息当前遵循标准 GB/T29100-2012；交通标志信息当前遵循标准 GB5768.2-2009。RSI 可打包一个或多个交通事件信息或交通标志信息，同时包含发送该消息的路侧单元编号以及参考位置坐标。

## RSI

车载单元会依据自身定位与运行方向，以及消息本身提供的时效信息、关联区域/路段范围，来判定事件或标志的生效区域。

[PRE10]

图 4.6　RSI 的使用场景

### 2. 消息主体结构及说明

路侧信息由 RSU 提供，RSU 消息中包含消息序号及发送时间，同时包括 RSU 的 ID 以区分不同发送方。为方便 RSI 作用范围内位置描述，提供本消息作用范围内的参考三维位置坐标，消息中所有位置偏移量均基于该参考坐标计算，真实位置坐标等于偏移量加上参考坐标。

道路交通中的交通事件信息和交通标志信息也会由路侧信息提供。交通事件 Road Traffic Event RTE 可能包含多个，其信息从信息源、发生区域、时效、优先级、事件置信度及影响区域等方面描述，除使用事件编号 ID 区分事件外，还可使用字符串文本描述进一步定义该事件。区域大小定义为以中心点为圆心的某个半径范围内。

交通标志信息 Road Traffic Sign RTS 同样具备 ID、文字描述字段，根据实际道路交通标志，可定义路侧信息中关于交通标志的信息，包括标志的位置信息、类型、起止时间及置信度、优先级等。

交通事件信息和交通标志信息都可通过定义关联路径及关联路段与 MAP 配合，帮助车载单元判定事件和标志的影响区域。

图 4.7 给出了 RSI 的主体结构，其中实线框为必选项，虚线框为可选项。

### 3. RSI 应用

RSI 通常用于事件下发，向周围车载单元发布交通事件信息及交通标志信息。车载单元依据自身定位与运行方向，以及消息本身提供的区域范围判定消息生效区域后向驾驶员推送。RSI 传递的是与道路相关的预警或提示信息，不用于车辆求救或其他安全类应用。

在场景应用方面，结合车辆自身 BSM 和 RSI 中的位置和交通事件集合可进行道路危险状况提示，使行经该路段的车辆及时采取避让措施避免事故。RSI 中的交通标志集合信息，结合 BSM 中的车辆自身信息以及 MAP 中的路段和车道信息，可应用于车内标牌。

应用据此计算自车在路网中的位置并判断前方是否有交通标识牌，若有则通过车内交通标牌对驾驶员进行提示，标牌会在消息有效区域和时间段内亮起。同理，对地图中的道路交通拥堵状况可进行提示，进而帮助车辆重新规划路线、缓解交通压力、减少拥堵时间。

## 4. 路侧安全消息

### 1. 定义

路侧安全消息 Road Safety Message RSM：路侧单元通过自身路侧感知识别手段，获得其周边交通参与者包括路侧单元本身、周围车辆、非机动车、行人等的实时状态信息，并将这些信息整理成本消息体定义的格式，作为这些交通参与者的基本安全状态信息类似于 BSM 广播给周边车辆，支撑相关应用。

RSM 的存在使车辆对周围环境的感知不再完全依赖 BSM。路侧单元基于路侧传感器帮助车辆探测周围环境并将实时信息通过 RSM 传递给车辆。

RSM 的使用场景如图 4.8 所示。

[PRE13]

图 4.8　RSM 的使用场景

### 2. 消息主体结构及说明

RSM 具备消息 ID 和不同消息发送方 RSU 的 ID 字段。RSM 中的位置信息字段用于提供本消息作用范围内的参考三维位置坐标，消息中所有位置偏移量均基于该参考坐标计算，真实位置坐标等于偏移量加上参考坐标。

RSU 获取路侧感知单元检测的所有或部分周边交通参与者信息并组成 RSM 的参与者列表信息，该部分信息实际上相当于 BSM 中 OBU 广播的自身车辆信息，信息内容组成与 BSM 类似，只不过由 RSU 获取感知信息并发送给周边其他车辆，一些只能由车辆自身提供的信息如刹车状态则无法在 RSM 中体现。

当某参与者信息来源于 RSU 收到的 BSM 时，其中的车辆 ID 字段必须与 BSM 中的车辆 ID 字段一致。当消息中包含非机动车、行人等交通参与者时，RSM 可减去属于机动车部分的信息字段。

### 3. RSM 应用

RSM 主要对接路侧感知设备和边缘计算设备，用于道路事件识别，如车辆事故、车辆异常、异物闯入等，通过路侧设备自身感知识别技术获得周边交通参与者实时状态信息并整理为本消息体定义的格式。RSM 的存在使车辆对周围环境的感知不再仅依赖 BSM。路侧单元基于路侧传感器帮助车辆探测周围环境，获得超视距感知。

在场景应用方面，RSM 中包含的行人感知信息可用于弱势交通参与者碰撞预警场景，该场景可分为前车遮挡视野盲区内的行人碰撞和倒车视野盲区的行人碰撞，可通过 RSM 进行预警提醒。

图 4.10　SPAT 消息使用场景

### 2. 消息主体结构及说明

SPAT 同样包含消息 ID、发送时间戳、字符串描述。SPAT 的主体信息为信号灯状态集合，道路交通中的信号灯设在路口处，并主要指示信号灯的颜色及持续时间的信息。因此在 SPAT 中，需要定义路口 ID、信号灯相位状态。其中的信号灯相位状态就是信号灯的颜色、剩余时间，可能也会包括信号灯的下一个相位状态。
