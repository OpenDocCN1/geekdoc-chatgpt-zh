（6）`researcher_node.py` 实现了 `researcher_node`，它是研究任务的入口。该函数先通过 `research_agent.invoke` 驱动研究流程，对返回内容做收尾。若末尾消息需修复 JSON 格式，则先修正，再把结果封装成 `Command` 对象返回，携带刷新后的对话记录并指示流程转交 `supervisor` 进行后续裁定。

[PRE0]

（7）`supervisor_node.py` 中的 `supervisor_node` 承担监督节点的决策角色，负责甄选下一位执行者。依据当前状态生成适配监督智能体的提示模板，并对对话记录做预处理以提升判断质量；随后借助 `get_llm_by_type` 取得对应大模型处理提示，得到将要转发的智能体名称。若结果为 `FINISH`，工作流即告结束；否则把任务委派给指定的智能体继续推进。

[PRE1][PRE2]

（8）`types.py` 声明了 `State` 与 `Router` 两种结构，用以刻画工作流状态和监督路由结论。`State` 保留对话记录、完整方案、后续操作、深度思考模式开关、规划前是否搜索等信息。`Router` 枚举了监督智能体可选择的跳转目标，囊括 `coordinator`、`planner`、`supervisor`、`researcher`、`coder`、`browser`、`reporter` 以及终止标记 `FINISH`。

[PRE3]

### **11.6.2 浏览器智能体解析**
本系统在 agents 文件夹下为不同角色分别建立独立文件，涵盖浏览器智能体 `browser_agent`、编程智能体 `coder_agent`、协调智能体 `coordinator_agent`、报告智能体 `reporter_agent` 与研究智能体 `research_agent`。它们统一通过 `invoke` 接口接受对话记录，调用各自绑定的语言模型完成加工并给出结果，共同构成网页浏览、代码执行、任务编排、报告生成、信息研究等多角色协作的多智能体体系。

`browser_agent.py` 提供了 `BrowserAgent` 类，专责网页浏览类任务。类内 `invoke` 接口接受对话记录作输入，利用 `get_llm_by_type` 召回浏览器智能体对应的 LLM，处理后产出结果。模块导出 `browser_agent` 实例，可被其他组件直接引用调用。

[PRE4][PRE5]

### **11.6.3 编程智能体概览**
`coder_agent.py` 提供了 `CoderAgent` 类，承接编程相关任务。类中 `invoke` 接口接受对话记录，通过 `get_llm_by_type` 拉取编程智能体绑定的 LLM，对输入进行加工后给出结果。

[PRE6]

### **11.6.4 协调器说明**
`coordinator.py` 实现了任务协调器 `TaskCoordinator`，在多智能体与工具间做任务编排。初始化时装载规划智能体、执行智能体、工具智能体等角色，以及网页浏览器工具、代码执行工具、数据检索工具等资源。该类对外暴露 `execute_task` 接口，接收任务描述后先由规划智能体生成执行方案，再由执行智能体按方案推进。类内每个工具都配备对应方法，可完成网页浏览、代码运行或数据检索等具体动作。

### **11.6.5 报告智能体细节**
`reporter_agent.py` 提供了 `ReporterAgent` 类，聚焦报告生成。`invoke` 接口接受对话记录，调用 `get_llm_by_type` 取得报告智能体对应的 LLM，处理后返回结果。

### **11.6.6 研究智能体细节**
`research_agent.py` 提供了 `ResearchAgent` 类，负责研究与信息收集。`invoke` 接口接受对话记录，通过 `get_llm_by_type` 取得研究智能体对应的 LLM 处理记录并返回结果。

## **11.7 提示模板体系**
项目在 `prompts` 目录集中收纳并管理各智能体的提示模板。该目录下有多份 `.md` 模板文件，分别对应浏览器、编程、协调、规划、报告、研究、监督等不同功能的智能体，描述了执行时所需的提示内容。`template.py` 提供了统一工具类，用于加载与应用这些模板，确保智能体能按任务需求生成合适的提示，提升与大模型的交互效率。

### **11.7.1 模板管理机制**
`template.py` 提供了 `OpenManusPromptTemplate` 类，用以统一管理智能体提示模板，设有两项静态方法。

◎ `get_prompt_template`：依据指定路径加载模板，并把模板中 `<<VAR>>` 形式的占位符转为 `{VAR}` 形式。
◎ `apply_prompt_template`：把当前智能体的状态变量填充到模板中，生成带有系统提示与历史记录的对话列表。

该类保证智能体能根据任务动态生成适配的提示内容，从而更高效地与语言模型协作。

[PRE11][PRE12]

### **11.7.2 浏览器提示模板**
`browser.md` 是 Markdown 格式的提示模板，专为浏览器智能体设计。模板涵盖角色定位、核心职责、执行指引、技术规范和输出规范，为智能体提供完整的上下文与指令，助力其高效完成网页浏览、交互操作与数据抽取，并以清晰格式汇报执行状态与结果。

## **11.8 Web 请求响应能力**
系统基于 FastAPI 实现了 Web 请求响应，提供聊天流式接口并支持跨域与任务处理。同时提供命令行客户端，可向服务器提交任务并输出格式化结果。

### **11.8.1 FastAPI 服务端**
`server.py` 是 FastAPI 服务器实现，提供 OpenManus 的 API 接口。定义了聊天流式接口 `/api/chat/stream`，接收请求并返回流式响应。内部通过 `run_agent_workflow` 调用工作流服务处理消息并生成事件流。服务配置了日志记录与 CORS 中间件以支持跨域，并在主程序中使用 `uvicorn` 启动。

[PRE17][PRE18]

### **11.8.2 客户端脚本**
`client.py` 是命令行客户端脚本，用于向 OpenManus 服务器提交任务。脚本借助 `requests` 库向服务器 `/task` 端点发送 POST 请求并处理返回。成功时返回服务器的 JSON 响应，失败时返回错误信息。脚本使用 `argparse` 解析命令行参数，支持用户指定任务描述与服务器地址。

[PRE19]
