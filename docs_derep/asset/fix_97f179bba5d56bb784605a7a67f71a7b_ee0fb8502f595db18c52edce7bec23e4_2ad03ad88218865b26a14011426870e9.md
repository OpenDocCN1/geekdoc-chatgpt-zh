#### 3.2.1 DeepSeek-R1 模型概览

DeepSeek-R1 由 DeepSeek 于2025年1月推出，目标是强化大语言模型的推理水平。测试显示，其在数学、代码、自然语言推理等任务上的表现可与 OpenAI o1正式版相媲美。

同步开源了 DeepSeek-R1-Zero 与 DeepSeek-R1 两个 660B 级版本，并基于 R1 的输出蒸馏出 6 个轻量版，其中 32B 与 70B 在多项指标上达到 OpenAI o1-mini 的水准。

另外，article 元素也可用于呈现插件，让插件看起来像页面内嵌组件。

需要强调的是，DeepSeek-R1 与 DeepSeek-V3 采用完全相同的架构，仅训练流程与训练数据不同。具体而言，R1 先在 V3 base 上进行有监督微调，再做强化学习训练；R1-Zero 则省略有监督微调，直接在 V3 base 上强化学习得到。

因此在 R1 项目中看不到独立的权重、推理脚本、部署说明等关键材料，因为这些内容已包含在 DeepSeek-V3 项目中，具体可见3.1节。

#### 3.2.3 DeepSeek-R1模型参数详解

通过API调用 DeepSeek-R1 时，可灵活设置参数控制生成长度、风格多样性、逻辑严谨度等。chat.completions.create（）接口的关键参数已作说明，R1 与 V3 共用同一接口。

此外，R1 在参数解析与推理机制上存在部分特有特性与限制，调用时需注意以下要点。

##### 1. max_tokens参数

- （1）max_tokens 用于限制最终回答部分 content 字段的最大长度。默认值 4096 token 约3000汉字，上限 8192 token。
- （2）该限制不包含思维链内容 reasoning_content。在复杂场景中，思维链可达 32K token，因此总输出可能远超 max_tokens 设置。官方计划未来推出 reasoning_effort 参数以控制推理深度与长度。

##### 2. reasoning_content字段

- （1）R1 除常规回答 content 外，还会返回推理过程字段 reasoning_content，与 content 同级。
- （2）该字段记录模型推导结论的思考路径，适用于解释性任务、教学、评估等场景。

##### 3. 功能支持情况

- （1）目前已支持标准对话补全及对话前缀续写 Beta，适用于续写已有内容生成完整对话。
- （2）暂不支持 Function Calling、JSON 格式输出、FIM 补全 Beta，相关字段无效。

##### 4. 不生效的参数

temperature、top_p、presence_penalty、frequency_penalty、logprobs、top_logprobs 在调用 deepseek-reasoner 时不生效，但为兼容 OpenAI 接口标准，设置后不会报错，仅被静默忽略。

R1 的思维链在多轮对话中呈现清晰的阶段性变化。

- (1) 首轮通常为独立推理，基于初始提问进行完整自洽的思考。
- (2) 第二轮开始递进式推理，可引用前文问答并自然衔接。
- （3）第三轮及以后形成综合推理，整合多轮信息与多个变量，输出逻辑清晰的推理链。随着对话深入，R1 不仅展现单轮分析能力，还体现上下文记忆、逻辑递进与归纳整合能力，具备类人思维连续性与对话一致性，适用于复杂交互。
