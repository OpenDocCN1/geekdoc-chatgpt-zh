图3-15 Sequential Thinking源码位置

从实现角度看，它提供了一个 sequentialthinking 工具，内部包含轻量状态管理器，用来记录历史步骤与当前计划的执行状态。

真正的关键并不在代码，而在工具的描述文档。在 MCP 体系里，这段描述会被注入大模型上下文，作为系统级的推理准则。它强制模型遵循“提出假设→检验→修正→推进”的闭环，打破了传统直觉式回应的局限，使其呈现出接近专家式的深度思考特征。

下面把该工具英文原版的核心描述整理如下。

这是一款借助思考实现动态反思式问题求解的工具。

它通过灵活、可演进的思考路径来剖析问题，随着理解加深，每个步骤都可以基于先前见解、对其提出质疑或加以修正。

适用情形：

- 需把复杂任务拆分为多步处理
- 规划设计时希望保留修改空间
- 分析过程中可能中途调整方向
- 问题边界初始不清晰
- 需要多步骤求解
- 需在多步之间保持上下文
- 需剔除无关信息

主要特点：

- 思考过程中可增减总步骤数
- 可对已有思考提出质疑或修订
- 即使看起来已结束，仍可追加思考
- 能表达不确定性并探索备选方案
- 思考不一定线性，可分支或回溯
- 可生成解决假设
- 依思维链步骤验证假设
- 反复进行直至满意
- 最终提供正确答案

参数说明：

- thought：当前思考内容，可包括常规分析、对旧思考的修订、对旧决策的质疑、意识到需更多分析、方法变更、假设生成与验证等
- next_thought_needed：是否还需要下一步思考，必要时设为 true
- thought_number：当前序号，可超出初始预估
- total_thoughts：预估所需步骤数，可动态调整
- is_revision：是否为修订
- revises_thought：被修订的思考编号
- branch_from_thought：分支起点编号
- branch_id：当前分支标识
- needs_more_thoughts：已到结尾但意识到仍需思考时使用

使用建议：

1. 先给出初始预估步数，但保持可调性
2. 随时质疑或修订既有思考
3. 必要时追加思考，即使看似已结束
4. 不确定时明确表达
5. 标记修订或分支的思考
6. 忽略与当前步骤无关信息
7. 适时生成假设
8. 基于链式步骤验证假设
9. 重复直至满意
10. 最终输出单一、理想正确的答案
11. 只有真正完成且满意时才将 next_thought_needed 设为 false

### 3.3.3 私有化方式部署Sequential Thinking

生产环境通常需要把 Sequential Thinking 部署为独立远程服务，以便多个智能体协作调用。

官方提供的 Docker 镜像 searxng/searxng:latest 默认基于 stdio 通信，MCP Client 必须在本地启动容器并接管其输入输出，无法通过 IP 远程访问。

要实现独立部署，需要构建包装器架构。核心思路是编写一个支持 Streamable-HTTP 的中转 MCP Server 作为代理前端，架构分层如图3-16 所示。

- 自封装 Streamable-HTTP MCP Server：对外交互入口，运行在标准 Streamable-HTTP 协议栈，接收 Agent 侧 MCP Client 的异步指令并维护连接状态。
- 自封装 sequentialthinking 工具：架构核心，不处理业务逻辑，仅做桥接。外层 Server 收到请求后，通过 docker run 启动容器并与其中 MCP Server 建立连接。
- Docker 容器：实际执行单元，Sequential Thinking MCP Server 在容器内运行，通过 stdio 接收桥接层的指令并返回结果。
