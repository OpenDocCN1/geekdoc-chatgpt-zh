## 第 6 章 MCP 对 AI Agent 框架的影响

MCP 的提出正深刻影响当前广泛采用的经典 AI Agent 框架，尤其是工具使用这一核心模块。同时，MCP 通过对 Resources、Prompts 和 Sampling 机制的扩展，增强了 AI Agent 在复杂场景下的感知与响应能力。本章将进一步探讨 MCP 对 AI Agent 构建平台的影响，厘清“MCP 出现后 Workflow Agent 是否就失去价值”等争议，帮助读者全面理解 MCP 带来的范式转变及其现实意义。

### 6.1 MCP 对经典 AI Agent 框架核心组件的影响

#### 6.1.1 经典 AI Agent 框架介绍
探讨 MCP 对 AI Agent 框架的影响，离不开前 OpenAI 研究员 Lilian Weng 于 2023 年 6 月提出的经典 AI Agent 框架，如图 6-1 所示，访问链接：https://lilianweng.github.io/posts/2023-06-23-agent/。

[PRE25]
LLM 驱动的自主 AI Agent 框架包含三大核心组件。

（1）规划
任务分解：将复杂任务拆解为更小、更易管理的子任务，可通过思维链 Chain of Thought 或思维树 Tree of Thoughts 实现。
自我反思：通过反思过往行动和决策来改进后续计划与执行，包含 ReAct 和 Reflexion 等方法，通过行动后的反思与调整提升任务完成质量。

（2）记忆
短期记忆：把当前会话中历史多轮对话一次性喂给模型，使其能依据先前对话内容回应最新请求。
长期记忆：跨会话的记忆信息，通常借助外部向量存储保存与检索长期记忆。

（3）工具使用
工具调用：AI Agent 通过调用外部 API 获取模型本身不具备的信息，如最新资讯、代码执行能力、访问专有信息源等。涵盖工具接入、调用与结果获取，对应架构图中的工具与行动部分。

该架构已成为行业共识，后文称为“经典 AI Agent 框架”。MCP 的提出对三大核心组件均有涉及，其中对工具使用的影响最为关键。

#### 6.1.2 MCP 对经典 AI Agent 框架中工具使用模块的影响
过去，Agent 集成外部工具和数据如 API、数据库、文件系统一直是复杂、耗时且低效的过程：

- 工具多样性和复杂性：外部工具和数据源种类繁多，各自接口与协议各不相同。开发者需为每个工具单独编写适配代码，导致开发周期长、成本高。

- 重复开发问题：缺乏统一标准，不同 Agent 需重复开发相似的工具集成逻辑，浪费大量开发资源。

为解决此问题，各方都在探索统一格式方案，希望建立类似 HTTP 的通用标准来规范模型调用工具的核心交互。在 MCP 之前，Open WebUI、PydanticAI 等均提出过各自协议，目前 MCP 获得的市场反响最大，也最有可能成为最终胜出者。
