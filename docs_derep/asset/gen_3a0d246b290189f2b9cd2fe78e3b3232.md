## 9.1 概览：从临时变量到永久存储

变量、列表、字典、NumPy 数组或是 pandas 对象，它们都只能提供**临时**的数据存储。一旦作用域结束或程序退出，数据随之消亡。文件系统解决了这个痛点：它将数据持久化保存在固态硬盘、机械硬盘等辅助存储介质上，脱离程序生命周期独立存在。

本章将深入讲解 Python 如何创建、修改与处理数据文件。重点覆盖三大主流文本格式：
- **纯文本**：最基础的存储形态。
- **JSON (JavaScript Object Notation)**：跨语言、跨平台的数据交换通用语，用于对象序列化与网络传输。
- **CSV (Comma-Separated Values)**：数据科学领域的“通用货币”，特别适合表格型数据。

> **特别提示**：请务必关注本章“数据科学入门”板块（9.12 节），我们将实战演示如何用标准库 `csv` 模块与 `pandas` 高效加载、清洗 CSV 数据，并以经典的**泰坦尼克号灾难数据集**为例。后续数据科学案例研究章节也将高频复用各类热门数据集。

### 安全警示：拒绝 `pickle`，拥抱 JSON
作为安全编码规范的一部分，我们必须强调：标准库 `pickle` 模块在反序列化不可信数据时存在**任意代码执行**的高危漏洞。生产环境中，**请坚决使用 JSON 替代 pickle** 进行数据序列化。

### 异常处理：编写“抗压”代码
此前你已遇见 `ZeroDivisionError`、`ValueError`、`KeyError` 等旧识。异常即运行时故障。本章将系统讲解 `try` 语句配合 `except` 捕获异常，`else` 分支在无异常时执行，`finally` 分支兜底执行清理逻辑。掌握异常处理，意味着你的程序能在局部报错时优雅降级，而非直接崩溃退出。

### 资源管理：`with` 语句的优雅
文件、网络连接、数据库句柄均为稀缺资源，用完即归。`with` 语句通过上下文管理器协议，保证即便代码块中抛出异常，资源也能确定性释放，是防止资源泄露的标准范式。

## 9.2 文件本质：字符流与字节流

Python 区分两种文件视角：
- **文本文件**：视为**字符序列**（Unicode 字符串）。
- **二进制文件**：视为**字节序列**（图像、视频、编译后的字节码等）。

同列表索引一样，文件首字符/首字节位置编号为 `0`，长度为 `n` 的文件，最大位置编号为 `n-1`。

[PRE0]

每个被打开的文件，Python 都会创建一个对应的**文件对象**，所有读写操作均通过该对象完成。

### 文件尾标记 (EOF)
操作系统层面通过特殊标记或记录总长度来标识文件结束。高级语言屏蔽了这些底层差异，开发者无需关心具体实现。

### 三大标准流对象
程序启动时自动创建三个预置文件对象（需 `import sys` 显式访问，日常极少直接用）：
- `sys.stdin`：标准输入（`input()` 底层依赖它）。
- `sys.stdout`：标准输出（`print()` 默认写向此处）。
- `sys.stderr`：标准错误（异常回溯、报错信息输出至此）。

#### 为什么必须用 `with`？
获取资源（文件句柄、网络连接……）→ 使用资源 → **确保释放资源**。`with` 语句完美闭环：
1. 调用 `open()` 获取文件对象，绑定变量 `accounts`。
2. 进入代码块操作文件。
3. **无论正常退出还是抛出异常**，退出代码块时自动调用 `close()` 释放句柄。

- `mode='w'`：写模式。文件不存在则创建；**文件存在则清空内容（截断为零字节）**，极其危险，写前请三思。

## 9.4 文本文件更新的“阵痛”与“良方”

**核心难点**：文本文件是变长记录的字节流，**不支持原地修改**。
案例：将账号 300 的姓名 `White` (5字符) 改为 `Williams` (8字符)。直接覆盖会导致后续字符“被顶挤”：
- 原行：`300 White 0.00`
- 盲目覆盖后：`300 Williams0.00`（`ams` 覆盖了空格、`0`、`.`）

根因：内存中定长的数值，文本化后长度不一（`7` vs `27383`）。

### 标准更新范式：临时文件法
1. 打开原文件读、临时文件写。
2. 逐行处理：非目标行原样写入临时文件；目标行修正后写入。
3. 关闭两文件。
4. 删除原文件 (`os.remove`)。
5. 重命名临时文件为原文件名 (`os.rename`)。

> 单条更新遍历全文看似低效，但批量更新时摊销成本极低，且规避了原地修改的数据破坏风险。
