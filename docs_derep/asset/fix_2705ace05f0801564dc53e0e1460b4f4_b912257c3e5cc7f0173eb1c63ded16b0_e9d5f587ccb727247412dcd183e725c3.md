10.2.5 DeepSeek R1-Zero 为何舍弃 SFT
主流大模型的构建路径是预训练、监督微调、人类反馈强化学习，已形成常规范式。R1-Zero 在构建推理模型时却省去了 SFT，这一点颇具冲击。

预训练阶段消耗了绝大部分算力与语料。SFT 与 RLHF 分别用来让模型学会对话并贴合人类偏好。对于推理模型，Long-CoT 数据难以人工采集且成本高，直接在长 CoT 数据上做强化是更现实的选择。

更关键的阻力在于，先用普通语料做 SFT 再做强化会让收敛变得困难。GRPO 与 PPO 都含有如下正则项：

起初该项表示旧模型在给定输入 s[t] 下产生输出 a[t] 的概率。对未用 Long-CoT 数据做 SFT 的模型，该概率会高于纯预训练模型，导致正则项过大，收敛速度变慢。

10.2.6 DeepSeek R1 为何需要少量 Long-CoT 监督微调
R1 采用 GRPO，属于具备在线探索的强化学习，其收敛高度依赖起点的远近。优化方向是增强 Long-CoT 能力，若完全不做长 CoT 的 SFT，起点与目标差距过大。

因此用少量人工标注的 Long-CoT 数据做 SFT，相当于先把模型拉到一个离目标较近的次优位置，后续强化更易推进。同时，这类人工标注数据能显著遏制 R1-Zero 出现的不可读与语言紊乱问题。

10.3 DeepSeek VL2 训练流程
VL2 的训练被划分为三个阶段，各自聚焦不同目标，最终形成强力的视觉语言理解与生成能力。

10.3.1 起步阶段：视觉语言对齐
目的在于让视觉表征与语言表征建立初步联系，使基座语言模型能初步读懂视觉输入。
做法是使用图文配对数据训练时冻结语言模型，仅更新视觉编码器与视觉语言适配器。适配器权重随机初始化，先训练它能找到更合理的映射。本阶段只在文本位置计算自回归损失，突出视觉理解。
效果是视觉编码器能把图像转为语言模型可用的特征，完成初步对齐。

10.3.2 联合预训练阶段：多模态协同学习
目的在于发展完整的视觉语言协同能力，提升多模态理解广度。
做法是使用海量图文数据进行训练，解冻全模型参数，包括视觉编码器与适配器等，进行端到端优化。训练规模约 8000 亿个图文词元，覆盖多类视觉语言任务。
效果是模型能捕捉图像与文本的复杂关联，并产出贴合图像内容的自然语言描述。

10.3.3 指令微调阶段：指令遵循与对话增强
目的在于强化指令跟随与对话表现，让模型更好地理解并执行用户需求。
做法是使用内部视觉语言数据做监督微调，全参数更新，仅对答案与特殊符标记监督，屏蔽系统与用户提示。并将多模态数据与纯文本对话数据混合，增强对话理解。
效果是模型能按指令给出更精准自然的回复，在表格图表文档图形理解、视觉推理、语言理解等任务上表现突出。

分阶段利用不同数据与算力，使 VL2 在各类视觉语言任务上取得优异表现。

第十一章 DeepSeek 推理与优化
在推理层面，吞吐与时延决定可用性与商业可行性。DeepSeek V3/R1 通过大规模跨节点专家并行、计算通信重叠、动态负载均衡三项核心手段，实现了理论成本利润率 545% 的效率，重新定义万亿参数模型的实时响应可能。

11.1 推理阶段报告要点
V3/R1 推理的优化目标是提升吞吐、降低时延。核心手段是跨节点专家并行 EP。EP 能让全局 Batch 显著增大，提升 GPU 矩阵乘法效率；同时专家分布到不同卡，每卡只处理少量专家，访存压力下降，时延降低。

使用 EP 也带来复杂性：
使用 EP 会引入跨节点传输，需要设计流程让传输与计算并行进行。
EP 天然涉及数据并行，不同数据并行组间需要负载均衡。
因此要解决如何用 EP 放大 Batch、如何压缩传输耗时、如何做负载均衡。

1.大规模跨节点专家并行
V3/R1 的专家规模很大，每层 256 个专家仅激活 8 个。高度稀疏决定了必须采用很大的全局样本批次，才能为每个专家提供足够样本，实现更高吞吐更低时延。这需要大规模跨节点专家并行。

多机多卡专家并行策略：
Prefill：32 路路由专家并行、32 路 MLA 并行、共享专家 32 路数据并行。一个部署单元用 4 个节点，32 个冗余路由专家，每卡 9 个路由专家 + 1 个共享专家。
Decode：144 路路由专家并行、144 路 MLA 并行、共享专家 144 路数据并行。一个部署单元用 14 个节点，32 个冗余路由专家，每卡 2 个路由专家 + 1 个共享专家。

2.计算通信重叠
多机多卡专家并行会带来较大通信开销，采用双 Batch 重叠来掩盖通信，提高整体吞吐。
