### 11.1.5 基于TensorFlow搭建VGG16

在掌握 TensorFlow 基础用法之后，就可以动手搭建网络了。虽然网上教程很多，这里刻意采用最原始的 TensorFlow 语法和代码，避开更高层的 API，来展示一个标准的 VGG16 架构是如何从零拼起来的。示例代码如下。

import numpy as np

import tensorflow as tf

def get_weight_variable(shape):

    return tf.get_variable('weight', shape=shape,

    initializer=tf.truncated_normal_initializer(stddev=0.1))

def get_bias_variable(shape):

    return tf.get_variable('bias', shape=shape, initializer=tf.constant_initializer(0))

def conv2d(x, w, padding = 'SAME', s=1):

    x = tf.nn.conv2d(x, w, strides=[1, s, s, 1], padding = padding)

    return x

def maxPoolLayer(x):

    return tf.nn.max_pool(x, ksize = [1, 2, 2, 1],

                          strides = [1, 2, 2, 1], padding = 'SAME')

def conv2d_layer(x, in_chs, out_chs, ksize, layer_name):

    with tf.variable_scope(layer_name):

        w = get_weight_variable([ksize, ksize, in_chs, out_chs])

        b = get_bias_variable([out_chs])

        y = tf.nn.relu(tf.bias_add(conv2d(x, w, padding = 'SAME', s=1), b))

    return y

def fc_layer(x, in_kernels, out_kernels, layer_name):

    with tf.variable_scope(layer_name):

        w = get_weight_variable([in_kernels, out_kernels])

        b = get_bias_variable([out_kernels])

        y = tf.nn.relu(tf.bias_add(tf.matmul(x, w), b))

    return y

def VGG16(x):

    conv1_1 = conv2d_layer(x, tf.get_shape(x).as_list()[-1], 64, 3, 'conv1_1')

    conv1_2 = conv2d_layer(conv1_1, 64, 64, 3, 'conv1_2')

    pool1 = maxPoolLayer(conv1_2)

    conv2_1 = conv2d_layer(pool1, 64, 128, 3, 'conv2_1')

    conv2_2 = conv2d_layer(conv2_1, 128, 128, 3, 'conv2_2')

    pool2 = maxPoolLayer(conv2_2)

    conv3_1 = conv2d_layer(pool2, 128, 256, 3, 'conv3_1')

    conv3_2 = conv2d_layer(conv3_1, 256, 256, 3, 'conv3_2')

    conv3_3 = conv2d_layer(conv3_2, 256, 256, 3, 'conv3_3')

    pool3 = maxPoolLayer(conv3_3)

    conv4_1 = conv2d_layer(pool3, 256, 512, 3, 'conv4_1')

    conv4_2 = conv2d_layer(conv4_1, 512, 512, 3, 'conv4_2')

    conv4_3 = conv2d_layer(conv4_2, 512, 512, 3, 'conv4_3')

    pool4 = maxPoolLayer(conv4_3)

    conv5_1 = conv2d_layer(pool4, 512, 512, 3, 'conv5_1')

    conv5_2 = conv2d_layer(conv5_1, 512, 512, 3, 'conv5_2')

    conv5_3 = conv2d_layer(conv5_2, 512, 512, 3, 'conv5_3')

    pool5 = maxPoolLayer(conv5_3)

    pool5_flatten_dims = int(np.prod(pool5.get_shape().as_list()[1:]))

    pool5_flatten = tf.reshape(pool5, [-1, pool5_flatten_dims])

    fc_6 = fc_layer(pool5_flatten, pool5_flatten_dims, 4096, 'fc6')

    fc_7 = fc_layer(fc_6, 4096, 4096, 'fc7')

    fc_8 = fc_layer(fc_7, 4096, 10, 'fc8')

    return fc_8

## 11.2 Caffe

Caffe 的全称是 Convolutional architecture for fast feature embedding，它是一个以清晰高效著称的深度学习框架。底层核心是 C++，同时提供命令行、Python 和 MATLAB 接口，可在 CPU 和 GPU 上运行。

2017 年，Facebook 正式发布了 Caffe2。

### 11.2.1 Caffe的特性

Caffe 具有以下特点。

- 高度模块化。从设计之初就追求模块化，便于扩展新的数据格式、网络层和损失函数。
- 表示与实现分离。网络结构通过 Protocol Buffer 语言写入配置文件。Caffe 以任意有向无环图的形式表示网络，会按需分配内存，并能通过一个函数在 CPU 与 GPU 之间切换。
- 测试覆盖完善。每个独立模块都配备对应测试。
- 同时提供 Python 和 MATLAB 接口。
- 预训练参考模型。针对视觉任务提供了若干参考模型，仅限学术和非商业用途，许可证并非 BSD。

### 11.2.2 Caffe2的特性

2017 年 Facebook 推出的 Caffe2 是一个兼顾表达力、速度和模块性的开源深度学习框架。它继承了大量 Caffe 的设计思路，并解决了 Caffe 长期使用和部署中的痛点，最终为算法实验和新产品落地打开了通道。

Caffe2 的特点如下。

- 一个轻量级的深度学习算法框架。
- 主要面向产品级深度学习算法设计。
- 对移动端实时计算做了大量优化。
- 支持大规模分布式计算。
- 跨平台框架。支持移动端 iOS、Android，服务端 Linux、Mac、Windows，甚至物联网设备如 Raspberry Pi、NVIDIA Jetson TX2 等。

### 11.2.3 Caffe2和PyTorch的区别

从使用者视角看，两者的主要差异有两点。

- 训练层面，Caffe2 更强调极致性能，PyTorch 则更强调灵活性。
- 发布层面，Caffe2 是为产品设计的，提供覆盖各类平台包括移动设备的运行时环境。PyTorch 并未针对此做优化。

## 11.3 PyTorch

PyTorch 是 Torch 的 Python 版本，由 Facebook 开源，专注于 GPU 加速的深度神经网络编程。Torch 是一款经典的张量库，用于对多维矩阵数据进行操作，在机器学习等数学密集型任务中应用广泛。与 TensorFlow 的静态计算图不同，PyTorch 的计算图是动态的，能随计算需求实时改变。

2018 年 10 月，Facebook 发布了 PyTorch 1.0，这是框架发展历程中最重要的版本，整体已相当稳定成熟。

### 11.3.1 为什么选择PyTorch

（1）简洁。
PyTorch 封装较少，设计遵循 tensor → variable（autograd）→ nn.Module 三层由低到高的抽象，分别对应高维数组、自动求导和神经网络层/模块，三者关联紧密，可同时修改操作。简洁带来了可读性，PyTorch 源码量约为 TensorFlow 的十分之一，抽象概念少、设计直观，阅读起来十分轻松。

（2）速度快。
灵活性并未以牺牲速度为代价，多项评测中 PyTorch 的表现优于 TensorFlow 和 Keras。虽然运行效率与程序员水平密切相关，但同等算法下，用 PyTorch 实现往往更快。

（3）易用。
在面向对象设计上，PyTorch 是目前神经网络框架中最优雅的一个。其接口源自 Torch，而 Torch 以灵活易用著称。PyTorch 继承了 Torch 的 API 设计和模块接口，保持高度一致。整体设计贴合思维习惯，让用户能专注于想法实现，所思即所得，无需过多关注框架本身的限制。

（4）活跃的社区。
PyTorch 拥有完整的文档、循序渐进的教程，以及由作者维护的论坛供交流。Facebook 人工智能研究院 FAIR 对其提供强力支持，保证了持续的开发更新。

### 11.3.2 PyTorch的架构

PyTorch 1.0 将 Caffe2 并入，通过混合前端、分布式训练以及工具库生态，实现了快速灵活的实验和高效生产。PyTorch 与 TensorFlow 的计算图实现不同，前者静态后者动态。PyTorch 的高级特性包括。

- 混合前端。易用且灵活的新前端可无缝切换到图模式。
- 分布式训练。通过本地异步执行集合操作以及 Python、C++ 可访问的点对点通信来优化性能。
- Python 优先。为深度集成 Python 而构建，可与流行的 Python 库、Cython、Numba 等配合使用。
- 丰富的工具和库。活跃的研究者和开发者社区构建了丰富的生态，覆盖计算机视觉到强化学习等领域。
- 原生 ONNX 支持。以开放式神经网络交换格式导出模型，便于在兼容平台、运行环境、可视化工具间使用。
- C++ 前端。纯 C++ 接口，遵循 Python 前端的设计和架构，面向高性能、低延迟的裸机 C++ 应用研究。

### 11.3.3 PyTorch 1.0三大重要更新

PyTorch 1.0 主要带来三大更新。

第一，新增混合前端，支持从 Eager 模式即动态图模式到图模式的跟踪和脚本化模型，弥合研究与生产部署的鸿沟。

第二，改进了 torch.distributed 库，使开发者能在 Python 和 C++ 环境中进行更快的训练。

第三，提供了面向关键性能研究的 Eager 模式 C++ 接口，在测试版中发布。

目前研究人员和工程师往往需要多个不兼容的框架和工具来完成模型研究并迁移到大规模生产运行，这严重降低了突破性 AI 研究产品化的效率。PyTorch 1.0 将 PyTorch 的灵活性与 Caffe2 的生产能力结合，实现了从研究到产品化的无缝衔接。
