[PRE2]

先来看 LangChain 内部的智能体设计，整体拆分为三大块：智能体本身、Message 以及 Toolkits。单个智能体通常由大语言模型 加 提示词 再加 输出解析器构成，形成一条 Chain 来处理用户输入。智能体可接受的输入来自三方面：Input 对应用户的原始提问，Model Response 表示模型对子任务的中间输出，而 Context 则携带上下文信息。智能体的输出会连接到真实的工具库，具体调用哪些工具由智能体拆解的子任务决定。大模型调用外部函数分为两步：先识别工具，再执行。Messages → AI 智能体 → Toolkits 这条路径负责拆解任务，然后在工具库中匹配对应工具并提取名称与参数，可视作一种静态执行流程。把决策落地为行动的工作交给了 AgentExecutor。

总体来看，LangChain 的 AI 智能体架构里，智能体只负责接收输入并决定该做什么动作，自己并不执行；执行部分由 AgentExecutor 承担。只有把作为决策核心的智能体和负责运行的 AgentExecutor 结合起来使用，才能构成完整的智能体。

LangChain 仍是构建大模型应用的前沿框架之一。最新 v0.3 版本基本完成了从传统类到 LCEL 的重要过渡，让定义与执行分步操作序列变得更简洁高效。专业角度看，LangChain 构建的是有向无环图 DAG。随着 AI 应用尤其是智能体的发展，大模型的使用正从单纯执行工具转向更复杂的推理引擎，这正是 LangGraph 诞生的根本原因。这种转变带来了更多对循环结构和复杂条件交互的需求，使得基于 LCEL 的线性序列构建方式在实现更高级、更智能系统时逐渐暴露局限。

#### 8.1.10 LangGraph 搭建智能体的底层逻辑

##### 1. LangGraph 究竟是什么

从名字就能看出与 LangChain 关系紧密。实际上 LangGraph 就是基于 LangChain 表达式语言构建的框架，专门用于开发 AI 智能体。因此在大模型接入与智能体构建方面的优势可以自然迁移过来。从技术本质看，大模型本身无法行动，只能输出文本，即接收用户输入并给出响应。

##### 2. 基础图结构是怎样的

在基于图的框架里，任何可执行逻辑都能作为对话、智能体或程序的启动点。该入口可以是大模型 API、基于大模型构建的 AI 智能体，或通过 LangChain 等实现的线性序列，如图 8.13 中 Start 标记所示。无论形式如何，它首先处理用户输入并决定下一步操作。图 8.13 展示了基于 LangGraph 概念的基础智能体模型。

在该框架里，具备可执行逻辑的组件都被视作节点 Node，涵盖模型调用、检索操作、条件判断等。起点节点作为入口，接收用户输入后可做如下处理。

- (1) 调用动作节点进行外部信息查询，如网页检索、数据库查询或 RAG 检索。
- (2) 将获取的信息送入语言模型节点，生成自然语言回复。
- (3) 最终把回复传递给终点节点，完成整条链路。

如图 8.13 所示，这是一个基于 LangGraph 概念构建的基础智能体示例。每个圆圈代表一个节点，每条连线是边 Edge，用来控制流程方向；状态通过消息沿边更新。

因此无论智能体设计多复杂，最终都是节点和边以特定方式组合的图结构。这种工作流的核心在于：节点完成任务后会经由边通知下一个节点继续执行。简言之，该框架底层采用的消息传递算法定义了通用程序的工作模式：节点完成操作后沿一条或多条边向其他节点发送消息，接收方执行相应功能并把结果传给下一节点，如此循环往复。

在真实应用里，智能体不会沿固定路径执行，需要判断是否调用工具、调用哪个工具、是否直接给出答案等。下面看一个更贴近实际的例子。

- 提示工程：指示大模型以特定格式作出回应。
- 输出解析器：用后处理从模型响应中提取结构化数据。
- 工具调用：利用大模型的内置工具调用能力生成结构化输出。

##### 4. 共享状态机制

我们已知道该框架通过组合节点 Node 和边 Edge 创建复杂的循环工作流，消息传递串联所有节点形成通路。而保持消息及时更新并传向正确位置，则依赖状态机制的概念。在流程中，每次执行都会启动一个状态，图中节点在处理时会传递和修改该状态。该状态不是一组静态数据，而是由各节点输出动态更新，进而影响循环内的后续操作，如图 8.15 所示。

共享状态指图执行过程中节点间传递的数据或信息。该框架支持节点在执行时通过共享和更新公共状态进行交互。这种机制使节点能基于共同维护的数据通信、交换信息并相互影响行为。借助共享状态，该框架可实现节点间操作协调与同步，支持动态交互和复杂工作流构建，使节点能根据已有共享信息协同工作并做出决策。

##### 5. 官方定位与核心优势

从官方定义看，该框架是使用大模型构建有状态、多参与者应用程序的库，可创建智能体和多智能体工作流。其官方总结的优势如下。

- 循环和分支：在应用中实现循环与条件。
- 持久性：图每一步后自动保存状态，随时暂停恢复图形执行，支持错误恢复、人机交互流程、时间旅行等。
- 人机交互：中断图形执行以批准或编辑智能体计划的下一个操作。
- 流支持：流输出由每个节点生成，包括令牌流。
- 与 LangChain 集成：LangGraph 与 LangChain 和 LangSmith 无缝集成。
