消息交互在 OpenClaw 里分为三类。

请求消息由客户端发往 Gateway，采用 {type:"req", id, method, params} 的结构，type 固定为 req，其余字段视调用而定，主要用于触发 Gateway 提供的各类 RPC。

响应消息是 Gateway 对请求的直接回馈，格式为 {type:"res", id, ok, payload|error}，成功时返回数据，失败时返回错误详情。

事件消息是 Gateway 主动推送的单向流，格式为 {type:"event", event, payload, seq, stateVersion}，承载实时状态同步和打字机式输出。

3. Gateway 核心 RPC 方法
Gateway 向客户端暴露的一组远程调用接口，关键方法如下。

connect 为连接握手所必需，客户端在建立连接后即刻调用，并在其中声明身份信息。
health 用于健康探测，返回 Gateway 的运行状态和版本信息。
agent/send 是对话交互入口，可触发一次完整的 Agent Loop；send 变体可在不启动推理循环的情况下向指定会话静默投递消息。
sessions.list 与 sessions.history 分别用于枚举当前活跃会话和读取指定会话的历史记录。
config.get 与 config.apply 分别提供读取当前配置和热更新配置的能力。
cron.add/cron.remove 用于动态增删定时任务；pairing.list/pairing.approve 则负责跨设备节点的配对申请处理。

4. Gateway 主动推送的关键事件
为实现实时同步，Gateway 会推送以下事件。

tick 为心跳，保持连接活性，维持通道稳定。
agent 为 Agent 运行状态，推送空闲、思考中、调用工具中、流式输出中等状态以及 Token 消耗统计。
delta 为流式文本片段，在模型生成回复时持续下发，用以还原打字机效果。
tool-call 为工具调用前置通知，告知客户端即将调用的工具及参数。
tool-result 为工具执行结果，携带最终产出。
presence 为节点状态广播，发布各节点的在线离线变更。
message 为新消息到来通知，实现实时提醒。

6. 节点的双重角色
节点在握手时将 role 声明为 "node"。它既是客户端也是能力供给方。

作为客户端，节点通过 WebSocket 连接 Gateway 并接收下发指令；作为供给方，节点在连接时注册自身具备的物理能力或命令，如 canvas.*、camera.*、location.get、system.run。
Gateway 将这些能力统一抽象为 Agent 可调用的工具，Agent 决策调用时，Gateway 通过 WebSocket 路由指令至对应节点执行并回传结果。

3.2 感知与执行的触手
若把 Gateway 视作 OpenClaw 的大脑，Node 就是延伸到物理世界和各设备的触手。Node 的设计打破了单一服务器的虚拟边界。

核心设计哲学在于，Agent 的能力边界与所连设备的边界完全对齐。单台服务器的 AI 只能用服务器的能力，接入手机后便拥有手机的“眼睛”和“耳朵”。

3.2.1 将设备物理能力转化为 AI 工具
Node 的核心理念是能力虚拟化，把分散在各设备的硬件与系统特性，统一抽象为标准化的 AI 工具供 Agent 按需调用。

1. Node 的类型
目前主要支持四类 Node。

macOS Node 通常以菜单栏应用运行，提供屏幕录制、摄像头、system.run 本地命令执行以及 Canvas 渲染能力。
iOS Node 运行在 iPhone/iPad 上，使 AI 能够获取实时 GPS、调用摄像头拍照录像并发送系统级通知。
无头节点可部署于任意 Linux/macOS 服务器，专注于远程命令执行与底层文件访问。
浏览器节点以 Chrome 扩展形式存在，赋予 AI 深度操控浏览器、操作 DOM 元素和网页截图的视觉感知能力。

2. 能力虚拟化的工作流程
转化与调度遵循“设备能力→标准化命令→AI 工具”的路径，全流程分为五步，Gateway 承担路由与管理。

第1步：节点注册
Node 连接时在 connect 握手中声明支持的命令集，例如：

{
"type": "req",
"method": "connect",
"params": {
"role": "node",
"id": "iphone-pro",
"platform": "iOS",
"caps": ["camera.take_photo", "camera.record_video", "location.get", "system.notify"]
}
}

第2步：工具映射
Gateway 接收注册信息后，将命令集动态映射为当前 Agent 可用工具，并加入工具列表。Agent 无需区分工具来自本地代码还是远程节点，适配由 Gateway 透明处理。

第3步：Agent 工具调用
处理用户请求时，Agent 识别所需能力并生成调用，例如：

{
"tool": "nodes",
"action": "camera_snap",
"node": "iphone-pro"
}

第4步：路由与执行
Gateway 拦截调用请求，查询注册表确认提供方，随后通过 WebSocket 下发指令至 iPhone。节点应用调用 iOS AVFoundation 拍摄照片，并将图片数据或路径回传 Gateway。

第5步：结果反馈
Gateway 把照片数据交给 Agent，Agent 可进一步调用图像分析工具解析内容，最终以自然语言描述桌面物品。

该机制实现跨设备协同：大脑运行在云端，眼睛在 iPhone，手在 Mac，能力分布式调度。

3. Node 工具的完整能力
内置的 node 工具为所有已连接节点提供统一接口，覆盖设备发现与管理、配对管理、系统交互、多媒体/传感器访问、设备监控五大维度。

设备发现与管理提供 status 查看实时状态、describe 获取详细信息。
配对管理支持 pending 查看待配对请求、approve 批准、reject 拒绝。
系统交互中 notify 可向 macOS 节点发送系统通知，run 支持在远程节点执行 Shell 命令，并可指定工作目录、环境变量与超时。
多媒体和传感器访问集成 camera_list、camera_snap、camera_clip 用于枚举摄像头、拍摄照片、录制视频；screen_record 提供屏幕录制；location_get 精准返回经纬度、精度和时间戳。
设备状态监控提供 device_status、device_permissions 等操作，用于监控健康与权限。

3.2.2 安全的远程调用与连接机制
Node 常运行在移动设备上并处于不同网络环境，连接安全至关重要。

1. 设备配对
新 Node 首次连接时需在握手阶段提供设备身份标识与平台元数据。Gateway 发现未知设备后拒绝连接并生成待审批配对请求，同时通过事件总线向已连接管理客户端推送通知。
用户需在控制端手动审查并批准，例如执行 openclaw pairing approve 批准。获批后 Gateway 签发强加密的持久化设备令牌并写入配对白名单，后续连接必须携带该令牌。

2. 签名与防重放攻击
握手阶段 Gateway 发送随机挑战码 Challenge Nonce，Node 需用自身私钥签名并随 connect 请求返回，防止中间人与重放攻击。
签名负载同时绑定平台信息与设备家族，Gateway 首次配对时记录这些元数据。若后续连接指纹变化，例如 Token 被窃取至不同类型设备，连接将被拒绝并要求重新配对。

3. 节点命令的权限控制
成功配对后并非所有命令都可执行。gateway.nodes.allowCommands 与 gateway.nodes.denyCommands 允许管理员精确管控可执行命令。
安全审计重点关注高风险命令，如 camera.*、screen.*、contacts.*、calendar.*、system.run，这些被标记为 gateway.nodes.allow_commands_dangerous，需管理员明确授权。

4. 通过 Tailscale 实现安全的跨网络连接
当 Node 与 Gateway 位于不同物理网络时，推荐使用 Tailscale 建立隧道。基于 WireGuard 的加密通道确保端到端加密，公共网络下通信难以窃听。Tailscale 的身份验证机制保证只有授权设备可加入专属 Tailnet，在网络层提供额外保障。

3.3 智能体的心跳
在 Gateway 与 Node 的基础设施之上，Agent Loop 是 OpenClaw 的核心执行引擎，负责将自然语言转化为行动和回复。

每个会话拥有独立的 Loop 队列以保证状态一致性。OpenClaw 基于 pi-coding-agent 库构建运行时并做大量定制。

1. 接收与排队
用户发送消息后，Gateway 解析目标 Session。为避免并发竞争，每个 Session 拥有独立的 FIFO 命令队列，新请求追加至队尾，等待当前 Loop 完成后处理。
Gateway 立即返回 runId 与 acceptedAt 时间戳，表示任务已受理，即使 Agent 正忙也不会丢失消息。

2. 上下文组装
系统首先进行工作空间准备，定位 Agent 工作目录并加载配置文件。
随后进行技能加载，深度扫描 skills/ 目录读取所有 SKILL.md，并将其转化为大模型可理解的 JSON Schema。
对话上下文处理时，从会话持久化存储提取近期历史，按历史限制与 Token 预算智能裁剪，保持丰富度与成本平衡。
系统提示词构建阶段，将基础设定、用户画像、Agent 性格等多维度信息拼接为完整 System Prompt，并按工具策略生成可用工具列表，格式化为目标模型 API 所需样式。
若会话运行于隔离环境，还会注入沙箱路径与可用命令等环境信息，提升模型感知。

3. 模型推理
上下文组装完成后，完整的上下文包包含 System Prompt、历史消息、当前输入及格式化工具列表，被发送给配置的大语言模型。支持 OpenAI GPT-4o、Anthropic Claude Opus 4.5、阿里云 Qwen3.5-Plus 以及各类本地部署模型，模型随后进入思考状态。
