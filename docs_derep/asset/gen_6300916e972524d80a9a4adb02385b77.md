# AI 浪潮下，律师如何从普通到超级

图 13-3 科技会放大人与人之间的差距

希望这本书能成为一个助推器，帮每位年轻律师在 AI 新时代抢先一步，开启向超级个体的进化之旅。

下面给出从青涩青年律师成长为超级律师的四段进阶路径。

**13.4.1 信息化**

首个阶段是数字化转型。由过去的纸质办公、靠大脑硬背，到现在的数字办公，把记忆压力外包给系统。

书中提供了一套可直接复制的律师管理系统，可作为迈向数字化的起步工具。尤其是第十章的知识管理，把所有知识最终汇聚到一个关键词，实务中遇到问题时，先在脑中提炼成关键词，再到自己的数字系统中检索。

完成数字化后，能获得如下收益。

●把记忆负担从大脑里剥离出来，让大脑集中做思考。

●把知识数字化沉淀、相互关联，形成知识复利效应。

●检索提速，遇到问题能迅速找到相关资料，省去知识的读写延迟。

●协作能力增强，以信息化平台为枢纽实现多人协同，工作过程留痕便于后继学习，也能避免人员流动导致团队知识流失。

●为未来铺路：为自有 AI 积累语料，因为信息都是亲手录入，可靠性更高。

**13.4.2 流程化**

第二阶段是流程化。从过去精神紧绷、在脑中过一遍所有环节，到无意识地按流程和核对清单逐项打勾。

第九章构建了一种特殊的复盘框架，跳脱流水账式复盘，真正帮助律师从日常工作中提炼方法与流程，形成属于自己的办案 SOP。

建立流程化后，会有以下效果。

●把繁琐的思考拆解开来，控制单次思考的范围，保留上轮思考结果，让大脑能渐进式推进，把庞大课题愚公移山般完成，腾出空间做创造性思考。

●用制度防疏漏，降低因担心而产生的焦虑。

●为未来做准备：流程每个节点都要明确输入与输出信息，让思考链上的环节可逐步被 AI 替代。

**13.4.3 间接工作**

第三阶段是间接工作。为清晰区分，我们把现有的人直接上手的工作叫直接工作，把人不再直接介入、而是通过指令 AI 完成的工作叫间接工作。

这一阶段，要有意识地把第二阶段总结出的流程每个节点，用间接方式重构为提示词，逐步尝试让 AI 接管。具体做法是设计微提示词，即有明确输入与输出的提示，把输入转成输出。设计好后即可替代流程中的人工节点。

在 ChatGPT 环境下，每个微提示词可做成一个 GPTs，通过 @ 调用串联成流程。

举例说明。第二阶段设计了一个两步流程：第一步分析案件，输入案情输出法律意见；第二步起草起诉状，输入法律意见输出模板。第二阶段两步都由律师手工完成。第三阶段则变成：

律师@GPTs 分析案件助手：这是案件情况……

GPTs 分析案件助手：生成的法律意见是……

律师@GPTs 起草起诉状助手：到你了

GPTs 起草起诉状助手：生成的起诉状模板为……

这只是简化演示，完整的律师工作流至少包含 4 个大环节、40~50 个小步骤。

建立间接工作后，有以下好处。

●把人脑从重复机械的思考中解放出来，聚焦创造性思考与未知探索。

●把个人最佳智力状态固化成提示词，避免因睡眠、情绪、年龄、精力、利益关联、成见或刻板印象造成的决策质量波动。

●可用外部智力对流程特定环节进行强化与优化，实现超越个人智力上限的输出。

●为未来做准备：为 AI 自动化打基础。

**13.4.4 AI 自动化**

第四阶段是自动化。让律师管理系统与流程从 5×8 小时扩展到 7×24 小时运转，实现自动运行。比如 10.2.2 节的例子，即使在睡觉时，系统仍在默默工作。

实现 AI 自动化后，收益如下。

●突破人体精力上限，睡眠中系统也在自动思考与运行。

●工作生活更平衡，休假期间系统照常运转。

●人脑进一步解放，去处理更本质、更创造性的问题。

## **Notion 的使用与数据的备份及导出**

本书搭建系统时，数据存储采用的是 Notion 的多维表格 Database。它类似 Excel，但增加了多人协作与表间关联，可视为轻量级数据库，从而能在其上模拟简单的软件功能。我们借助 21 张相互关联的表，搭建了一个简化版的“律师管理系统”，作为与 AI 协作的基础。相比传统架构，AI 相当于前端界面，多维表格相当于后台管理与部分前端，AI+多维表格是一种 AI 原生应用的构建方式。

多维表格目前很流行，被视为无代码平台的重要方向之一。较早支持的是 Airtable，后来 Notion 二次重构时借鉴了该思路。随着 Notion 火爆，其他产品也纷纷跟进，如飞书云文档的多维表格、企业微信的智能表格。部分产品支持数据本地存储以保障安全，如 Collections Database 等。也有开源项目提供完整源码供自托管，如 NocoDB、APITable 等。耐心的用户用 Excel 的数组公式+TEXTJOIN 也能实现类似效果，但过于费时费力。

本书以 Notion 为例，并不意味着只能用 Notion。部分多维表格产品的优劣见表 A-1，大家按需选择。数据可通过 CSV 格式定时备份，在不同多维表格间导入导出迁移，无需担心丢失。

以下为逐行说明。

①“import requests”：导入 requests 库，用于发起 HTTP 请求。

②“import json”：导入 JSON 库，用于处理 JSON 数据。

③“url='https://api.notion.com/v1/databases/{your databaseid}/query?filter_properties=title&filter_properties=eOfa'”：设置请求 URL，需将 {your databaseid} 换成自己的数据库 ID。filter_properties 用于指定筛选属性，先不加该参数调用一次接口，再从中挑选所需属性 ID 作为参数。

④“headers={...}”：定义请求头，需将 {your notion Secrets} 换成个人密钥，同时指定 API 版本与内容类型。

●“'Authorization': '{your notion Secrets}'”：授权头。

●“'Notion-Version':'2022-06-28'”：指定 API 版本。

●“'Content-Type':'application/json'”：指定发送数据类型为 JSON。

⑤“response=requests.post（url，headers=headers）”：向 URL 发起 POST 请求并附上请求头，获取响应。

⑥“response_json=response.json（）”：将响应内容转为 JSON。

⑦初始化空字符串“content_str=""”，用于拼接条目信息。

⑧“for item in response_json['results']:”：遍历 results，每个 item 代表数据库一条记录。

⑨“content_str+='\\n'+item['properties']['Name']['title'][0]['plain_text']+'渠道有'+str（item['properties']['律-咨询数量']['rollup']['number']）+'个咨询'”：从属性中提取 Name 与律-咨询数量并格式化后追加到 content_str。

注意：此处使用“\\n”表示换行，实际应使用“\n”。

⑩“output={'result':content_str}”：将拼接字符串封装为字典，键为'result'。
