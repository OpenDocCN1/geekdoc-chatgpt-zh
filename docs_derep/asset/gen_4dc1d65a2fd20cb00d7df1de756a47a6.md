嵌入模型的切换其实很顺手，实例化对应的 Embedding 实现类后就能直接用。单条文本调用 embed_query，批量文本调用 embed_documents，两者都会返回向量列表。OpenAI 这类托管模型需要 API Key，可以走环境变量也可以显式传参；Hugging Face Embeddings 与 SentenceTransformer Embeddings 都可以通过 model_name 指定不同的预训练权重，来适配不同任务；SelfHostedEmbeddings 则让你跑自训或自部署的本地模型，把数据隐私和推理开销完全掌握在自己手里。

#### 5.4.3 基于 LangChain Vector Store 搭建向量数据库
向量化只是第一步，要做高效相似搜索就得把向量存进专业的向量库。LangChain 的 Vector Store 层统一了接口，支持多家后端：

- Chroma：开源向量库，支持本地文件或云存储，多种相似度策略可选。
- Pinecone：全托管向量服务，自动扩缩容与高可用。
- Weaviate：开源图数据库结合向量检索，GraphQL 查询，支持跨模态。
- FAISS：Facebook 出品的密集向量近似检索库，搜索速度极快。
- Milvus：开源可扩展向量数据库，吞吐和并发表现强。
- Qdrant：开源向量搜索引擎，内置高级过滤和完整 CRUD。
- Pandas DataFrame：内存表存储向量，适合测试和轻量场景。
- Annoy：基于随机投影树的近似最近邻 C++ 库。
- Elasticsearch：基于 Apache Lucene 的搜索引擎，已原生支持向量相似度。

#### 5.5 搭建端到端问答流程
知识库建立后即可串联完整的问答链路。LangChain 提供了一套 Question Answering Chain，把问题理解、检索、生成串起来，大幅降低开发门槛。

#### 5.5.1 解析用户问题
问题理解是入口，目标是从自然语言中提炼查询意图和关键信息，为检索提供依据，核心涉及问题分类、实体抽取和问题改写。

（1）问题分类与意图识别
先判断问题类型，常见有事实型、定义型、观点型、过程型、比较型等，不同类型对应不同的答案策略，比如事实型适合直接检索，观点型需要有据生成。随后识别具体意图，如查询、服务请求、寒暄、闲聊等，意图不同会触发知识问答、任务协助、关系维护等不同对话能力。

在 LangChain 中，可以用 HumanChatMessage 与 SystemChatMessage 组合对话记录，并加入 few-shot 示例，实现少样本的问题分类和意图识别。
