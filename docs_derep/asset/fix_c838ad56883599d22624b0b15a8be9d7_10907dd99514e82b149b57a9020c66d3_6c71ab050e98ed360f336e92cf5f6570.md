# 破解巡店造假、货架失管：零代码实战 EasyDL 零售版商品检测全流程

**核心利器：翻拍识别，给巡店数据装“防伪锁”**
平台内置翻拍检测模块，可精准甄别手机对屏拍摄或二次拍摄的货架/地堆陈列照片。此功能双重收效：一是大幅压缩人工复核开支；二是从源头杜绝“以旧图充新巡”的造假套路，保证终端数据真实有效。

#### 3.2 AI 落地标准四部曲：定需求、搞数据、练模型、上业务

工业级 AI 项目落地，核心链路无非四步。百度 EasyDL 平台将全链路可视化、零代码化，鼠标点点即可闭环。下面以**货架商品自动识别**为实战样板，拆解标准化动作。

#### 3.2.1 定需求：从“货架争夺战”倒推技术指标

**业务痛点几何？**
线下终端是快消决胜的“主战场”，黄金货位、排面占比直接定生死。执行层却顽疾难除：必销项缺货、新品挤冷宫、陈列乱七八糟、物料虚设。数据惊人：断货致品牌方流失 **46%** 意向客，零售商流失 **30%**。成百上千家门店靠人海战术巡检不可持久，必须引入视觉 AI——以商品识别辅助人工审陈列，方能实现降本增效。

**技术任务如何落笔？**
业务诉求映射为**目标检测任务**：输入一张货架图，输出所有目标商品的类别与坐标框。选型直指 **EasyDL 零售行业版**，零代码定制专属模型，跑通最短路径。

#### 3.2.2 搞数据：模型上限，数据决定

数据工程三板斧：**收、洗、标**。本项目核心燃料仅两款：**SKU 单品图** 与 **实拍场景图**。

> **核心区别**：单品图非训练强制项，但可通过“合成增强”低成本喂入多角度特征，大幅节省实拍图采集标注成本；实拍图是训练“主粮”，必须源自真实业务现场。

##### 1. 收集：标准不降，上限才高

**【单品图：平台自带成品库，缺啥补啥】**
平台内置饮品、日化两大类百余 SKU 成品库，每款预置 50+ 多角度图。绝大多数场景**无需自拍**，首轮训练跑完看报告，哪款识别弱，针对性补拍死角角度即可。若确需自拍，死守四条红线：

| 维度 | 硬性指标 |
| :--- | :--- |
| **画面内容** | 单图单品；纯色背景且与主体色强反差（见 [PRE0]）；光照覆盖实战场景冷暖色温差异。 |
| **分辨率** | ≥ 1920×1080，拍摄设备 ≥ 200 万像素。 |
| **视角覆盖** | 货架场景须覆盖**水平、俯拍、仰拍**三大视角（见 [PRE1]）；无人货柜主俯拍；结算台以水平/俯拍为主，酌情加仰拍。 |
| **样本量** | 起步建议：各视角 **10 张/款**（详见表 3-1）；地堆场景建议直接在实拍图中覆盖视角。 |

**【实拍图：源头对齐，设备同源】**
*   **设备同源**：巡店用啥拍（手机/专用终端），采集就用啥拍；结算台用自带摄像头，货柜用货柜摄像头。分辨率建议参考表 3-2。
*   **特征清晰可见**：肉眼能辨清每个商品关键特征（见 [PRE2]）。
*   **角度别贪大**：货架场景**正面硬刚为主，微倾斜可接受，大倾斜坚决不收**（见 [PRE3]），透视畸变直接毁识别率。
*   **起训底线**：首训每 SKU 至少 **20 张** 已标注实拍图。平台自动 7:3 切分训练/测试集；样本不足会导致 mAP、精确率、召回率“三连跪”。

##### 2. 洗数据：平台入场券
*   格式：PNG/JPG/BMP/JPEG
*   单文件 ≤ 4MB
*   长宽比 ≤ 3:1，长边 < 4096px，短边 > 30px
*   压缩包仅限 ZIP，≤ 5GB

##### 3. 标注：质量生命线，容错极低
单品图免标；实拍图标注执行力直接定模型生死。

*   **框选黄金准则**：**紧贴目标外轮廓的最小外接矩形框**（见 [PRE4]）。
*   **遮挡处理分场景执行**：
    *   货架/货柜：露出 **>70% 且保留核心识别特征** 才框。
    *   无人货柜/结算台：**仅框露在外面的部分**（见 [PRE5]）。
*   **相似品“强制分户”防串类**（见 [PRE6]-[PRE8]）：
    1.  同品牌不同系列/口味/包装；
    2.  同款不同规格（如 330ml 对 500ml）；
    3.  高度神似竞品（色/型/材质酷似）。
    > **铁律**：相似品归同一类，误识别率必飙升。
*   **避坑指南：零容忍“错标”与“漏标”**（见 [PRE9]-[PRE11]）：
    *   **错标高发区**：同款不同规格/口味/包装，最易误贴同一标签。
    *   **漏标三大元凶**：
        1.  **视角盲区**：只标正面，侧后视角视而不见（[PRE9]）。
        2.  **人为疏漏**：目视扫描未全覆盖（[PRE10]）。
        3.  **遮挡误判**：明明露特征 >70% 却因犹豫漏标（[PRE11]）。

#### 3.2.4 用模型：从评估报告跑通“数据飞轮”

训练完读**评估报告**，核心盯 **F1-score**（精确率与召回率调和均值）：
*   **F1 > 85%** → 支撑**精准计数**业务。
*   **F1 > 60%** → 满足**分销铺市统计**业务。

**效果不达标？别动算法参数，只管优化数据！** 零售版已完成场景化深度调优。迭代遵循 **“数据飞轮” 5 步法**：
1.  **回流挖难例**：用平台优化工具回流补充实拍图。
2.  **补齐弱项单品**：针对识别差的 SKU 补角度图。
3.  **新旧数据混合重训**。
4.  **发布新版 API 实战测**。
5.  **循环往复，直到达标上线**。

**部署形态灵活选**：云端 API 直连，或一键嵌入 H5 页面现场验收（界面见 [PRE12]）。

#### 3.4 保姆级操作演示：EasyDL 零售版实战

##### 步骤 1：新建模型 & 录入 SKU 库

1.  **进场**：登录实训系统 → 启动 “AI 平台实验” 中的 EasyDL 入口（[PRE13]）。
2.  **选型**：点 “立即使用” → 勾选 **“零售行业版”**（[PRE14]） → 登录账号。
3.  **建模**：左侧栏 “我的模型” → “创建模型” 填信息（[PRE15]-[PRE16]）。
    *   **模型名**：业务导向命名，如 “饮料检测”。
    *   **归属/场景**：个人 / 普通货架-货柜。
    *   **功能描述**：10-500 字，讲清解决什么问题。
4.  **落地**：点 “下一步” 创建成功，列表页即可见（[PRE17]）。
5.  **建 SKU**：点列表 “创建 SKU”，按提示填核心字段：
    *   **命名铁律**：返回格式固定为 `SKU名称_品牌_规格`，**三字段内容严禁重复**。
    *   **必填维度**：SKU 名称（如“原味可乐”）、品牌（如“可口可乐”）、规格（如“330mL”）、品类、包装类型。
    *   **业务关联**：自有商品编码/条码填入，便于后续系统对接。
    *   **增强素材**：上传单品图用于合成增强，提升模型鲁棒性。
