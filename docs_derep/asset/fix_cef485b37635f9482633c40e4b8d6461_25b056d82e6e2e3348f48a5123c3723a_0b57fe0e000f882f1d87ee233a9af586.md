# 破解循环测试生成难题：k+1 混合执行模型与死路径特征画像

## 核心引擎：四阶段混合策略增量构造可达路径

针对循环嵌套导致的路径搜索困境，本节提出一套 **“启发式引导的 k+1 循环处理模型”**。其核心在于将符号推演与具体运行深度融合，专门用于生成覆盖循环体内目标节点的测试输入。

模型要素拆解：
*   **k**：对目标环路 `L_target` 施行 k 次展开的符号推演；
*   **1**：对目标前环路 `L_before` 及目标后环路 `L_after` 各执行一次具体运行，获取部分可达轨迹；
*   **启发式**：引入目标函数，驱动 `L_before` 内的具体运行倾向于逼近目标的分支；
*   **+**：上述策略叠加，实现对目标可达路径的增量式拼装。

为加速流程，算法设置**初始化扫描阶段**，一次性完成支配节点至目标的距离预计算。完整流水线如下：

### 流水线详解

**初始化扫描**  
全量扫描控制流图（CFG）识别所有环路拓扑，标记出目标环路 `L_target`。随即反向回溯 CFG，获取目标节点 `t` 的支配节点集合 `S_t`，并计算该集合内所有节点到 `t` 的跳数距离集合。

**阶段一：入口推演与环路分发**  
从程序入口出发，沿 CFG 推进符号推演，同步积累路径约束。每引入一个逻辑判断，即调用求解引擎校验可满足性；若冲突则判定该路径为死路，立即回溯。推演过程中一旦触及环路入口，依环路类型分流：
*   命中 `L_target` → 跳转 **阶段三**；
*   命中 `L_before` → 跳转 **阶段二**。

**阶段二：启发式具体运行穿越 `L_before`**  
旨在获取 `L_before` 内部既可达又可能通往目标的路径片段。利用阶段一积累的前置约束，通过求解引擎生成多组测试输入并实运行，采集执行轨迹。所有轨迹在入口至 `L_before` 入口段共享相同前缀，随后在环路内部随机探索分支。  
**关键决策——距离排序**：依据初始化阶段预计算的节点距离，对轨迹按路径距离升序排列。距离越小，轨迹越逼近目标。截取距离最小轨迹在 `L_before` 内的路径段作为新前缀，回返 **阶段一** 继续推演。

**阶段三：目标环路 `L_target` 内的符号深度搜索**  
在 `L_target` 内开启全路径符号推演，确保覆盖到达 `t` 的路径。针对嵌套环路的复杂拓扑，采取递归策略：
*   遭遇 `L_before` → 跳转 **阶段二**；
*   遭遇 `L_target` → 递归执行 **阶段三**；
*   若在预设展开上限 `k` 内未触达 `t` → 回溯至上一决策点尝试他分支；
*   若在 `k` 次展开内成功获得含 `t` 的可达片段 → 携带该片段进入 **阶段四**。

**阶段四：具体运行补全 `L_after` 尾部**  
利用阶段三得到的部分可达片段对应的测试输入，直接实运行获取目标节点之后的完整轨迹，从而拼凑出覆盖目标的全路径。

## 攻克死路径：从特征统计到 LDc² 模式定义

### 痛点背景：为何死路径难判？

程序中的**死路径**（不可达路径）指任意输入均无法触发的执行轨迹。环路结构导致路径呈指数级爆炸，死路径随之激增，严重拖累静态分析精度与效率——例如在自动测试生成中，大量无效路径消耗算力，导致覆盖率难以达标。

主流对抗手段是推演过程中的约束可满足性检查。按推演方向分为：
*   **顺向推演**：从入口出发，顺控制流生成路径并判定可达性。
*   **逆向推演**：从指定目标点出发，逆控制流搜索判定。

**核心症结**：死路径本质源于约束冲突（CSP 问题），而 CSP 不可判定，不存在通用高效算法。现有技术（冲突片段识别、约束求解、具体运行等）效果深受程序拓扑、约束类别、搜索策略影响。

**典型场景对比**（参考 P. Dinge 工作 [10]）：  
若路径末尾两个谓词冲突（如 `y>0` 与 `y==0`），顺向推演需遍历完整长路径才能发现冲突，极易超时；逆向推演从目标点出发，**瞬间即可捕获矛盾**。路径越长，优势越显著。

[PRE2]

**启示**：死路径特征决定了最优判定策略，但现有研究缺乏对“特征-策略”映射关系的系统探索。本章将重新定义判定问题，归纳路径特征，挖掘程序结构与死路径的关联，给出适配的判定技术。

### 问题重定义：精准建模死路径

*   **路径建模**：路径 `p` 由节点序列 `n1...nk` 及控制流边组成，`k` 为长度。
*   **可达路径 (Def 5-4)**：存在输入 `v ∈ D` 使执行轨迹与 `p` 一致。等价于路径约束 `Cp` 可满足 (`Cp ⊨_D v`)。
*   **矛盾约束 (Def 5-5)**：路径约束 `Cp = φ1 ∧ ... ∧ φk`。若 `p` 为死路径，则 `Cp` 在域 `D` 上无解，记为 `Cp ⊨_D ⊥` (后文省略 `D`)。
*   **矛盾触发点 (Def 5-6)**：死路径 `p` 中，存在子式 `φi ∧ ... ∧ φj` 不可满足 (`i ≤ j ∈ [1, k]`)。称 `j` 为矛盾触发位置。**若 `k-j < i-1`，逆向推演比顺向推演更早发现矛盾。**

下节将通过实证调研，统计死路上矛盾约束的位置分布特征。

### 核心模式：依赖环路的等值代码片段

#### 1. 基础概念体系

*   **环路结构**：`L = (EL, NL, inL, outL)`，对应 CFG 中的有向环。
*   **数据依赖 (Def 5-7)**：节点 `ni` 与 `nj` 对同一内存位置存在读写交集 (`R∩W`, `W∩R`, `W∩W` 不为空)，记为 `ni ↔ nj`。
*   **数据传播 (Def 5-8)**：赋值语句 `v = expr(y)` 表示 `y → v`，具传递性 (`y→v, v→z ⇒ y→z`)。
*   **条件依赖 (Def 5-9)**：两条件节点 `ni`, `nj` 间路径 `p` 上，若无赋值且读变量集交集非空，或有赋值且变量经传播关联，则存在条件依赖。这反映了不同上下文中约束对同一变量的关联约束。
*   **支配环路 (Def 5-10)**：节点 `n` 的所有支配节点中包含某环路 `L` 的入口与出口，则 `L` 为 `n` 的支配环路。意为：通往 `n` 的每条路径必完整经过 `L`。
*   **专属节点 (Def 5-11)**：环路 `L` 内节点 `n`，若从 `inL` 到 `n` 的所有路径要么不经过任何环路，要么完整包含另一环路 `L'` 的入口出口。见图 5-10 示意。
*   **等值判定条件 (Def 5-12)**：条件节点 `n` 的逻辑式含 `v = N` 形式（`N` 为常量）。C 语言典型形式见表 5-1（如 `v==N` 真分支、`v!=N` 假分支、`if(v)` 假分支、`switch case N`）。求解引擎常对此类约束专项优化。

[PRE4]

#### 表 5-1 C 语言等值判定条件速查

| 代码形式 | 约束形式 (分支条件) |
| :--- | :--- |
| `if(v == N)` | 真分支: `v = N` |
| `if(v != N)` | 假分支: `v = N` |
| `if(v)` | 假分支: `v=0` |
| `switch(v) case N:` | 每个 `case N`: `v = N` |

#### 2. LDc² 模式正式定义

**定义 5-13 (依赖环路的等值代码片段 / LDc²)**  
设 `L` 为环路，`n` 为等值判定条件节点。若满足：
1.  **控制流前提**：`L` 是 `n` 的**支配环路**，**或** `n` 是 `L` 的**专属节点**；
2.  **数据流关联**：`L` 内存在节点 `n_l` 与 `n` 存在**数据依赖**或**条件依赖**；
3.  **纯净性约束**：`L` 内**无** `n` 中变量的重定义（重定义会破坏内存位置一致性，违背依赖定义）。

则称 `L` 与 `n` 构成 **LDc² 模式**。

**模式语义解读**：
*   **支配环路/专属节点** → 保证从入口到 `n` 的路径必经 `L`，路径可达性由 `L` 主导。
*   **数据/条件依赖** → `L` 内操作直接影响 `n` 的约束变量取值。
*   **无重定义** → 变量身份在环路内保持稳定，依赖链完整未断。

图 5-11 列举多种拓扑结构，满足条件的标记 `√`，不满足（如非支配环路 `L_4`, `L_5`）标记 `×`。

**核心猜想**：包含 LDc² 模式的程序中，等值判定条件 `n_c` 极易引发矛盾路径约束，**且矛盾恰在 `n_c` 处被触发**。这为针对性判定（如逆向推演切入点选择）提供了理论锚点。
