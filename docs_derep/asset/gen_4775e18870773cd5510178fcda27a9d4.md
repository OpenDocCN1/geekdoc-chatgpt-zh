- 挑对工具：Agent 会先启用搜索类工具，把任务所需的外部资料抓回来。
- 精准下指令：Agent 把搜索需求拆成明确的具体提问，确保拿到的结果足够精确。
- 回合式加工：搜集到结果后，Agent 再切换到计算器工具做数值推演，估算在特定预算下可购买的额度。

这一串操作体现出 Agent 在工具调用上的精准度，以及信息采集与加工之间的高效协同。借助这种配合，Agent 既能把任务做完，也能让决策过程更优。OpenAI 提出的函数调用 Function Calling 就是工具调用的典型代表。

不过工具调用并非一帆风顺，也带来了不少难题。

第一点，Agent 必须能看懂并操作不同类型的工具。这涉及解析复杂的接口、理解多样的格式，并学会把工具用起来。第二点，Agent 要在合适时机挑出正确工具。这要求它清楚每种工具的功能、长处和局限，并能基于当前任务和环境迅速判断。第三点，Agent 还要学会多工具协同。在复杂场景里往往需要同时调用多个工具，并保证数据在它们之间顺畅流转。

针对这些挑战，研究者给出了几类提升思路。工具封装把底层复杂性包起来，为 Agent 提供简洁统一的入口，降低使用门槛。借助机器学习等自适应手段，Agent 可以在实践中不断学习更有效的用法，通过反复试错和反馈提升对工具的理解。还有上下文感知的决策算法，能根据任务需求评估可用工具的表现，并预测使用后果，从而挑出最合适的方案。

工具调用能力正在打开 Agent 的应用空间。医疗场景里，Agent 可调阅医学数据库和分析工具，辅助医生做出更可靠的诊断和治疗建议；金融场景里，它能调用市场数据和分析模型，为客户定制投资方案；智能制造里，它可以接入设计软件、排产系统和质检工具，提升效率和品质。

以上只是冰山一角。随着大模型持续进化、商业模式不断创新，咖哥期待未来会出现统一的 Agent 工具调用标准。在新的互联网生态里，工具即服务 Tools as a Service 有望成形，Agent 将像搭积木一样调用各种工具，与其他 Agent、数据和服务联动，在更多领域释放价值。

## 2.5 ReAct 框架：Agent 推理的发动机

Agent 的推理引擎决定了它如何规划、决策并通过工具行动。它掌控着信息抽取、任务规划、经验利用和工具调用的全过程。

学术界提出了不少推理逻辑，如 CoT、ToT、LLM+P 等。其中脱颖而出的 ReAct，被 LangChain 和 LlamaIndex 等主流 AI 开发框架采纳为推理引擎。它提供了一种灵活的结构，帮助构建既能深度推理又能实际行动的 Agent。

ReAct 的出发点很直观：收到用户输入后，先思考再行动，让大模型在任务驱动下做出判断。

### 2.5.1 ReAct 到底是什么

小雪：ReAct 框架，名字怎么这么耳熟？

咖哥：别跟前端的 React 混了。这里的 ReAct 是指导大模型推理与行动的认知框架，由 Shunyu Yao 等人在 ICLR 2023 的论文 “ReAct: Synergizing Reasoning and Acting in Language Models” [4] 中提出。

ReAct 的核心是把推理和行动绑在一起。它不是固定的决策树或僵化算法，而是一个能实时处理信息、做决策并执行动作的综合系统。设计理念是：在动态不确定的环境里，有效决策需要持续学习与适应，并能迅速把思考转化为行动，形成观察—思考—行动—再观察的闭环（见图 2.5）。

[PRE0]

图2.5 观察—思考—行动—再观察的循环

闭环主要包含三步。

- 思考 Thought：对下一步行动进行推理，评估现状并权衡可选方案。
- 行动 Action：在思考基础上选择具体行动，是计划的落地。
- 观察 Observation：执行后收集反馈，评估结果并可能影响下一轮思考的方向。

可以看出，ReAct 的思想与 KwaiAgents 展示的 Agent 推理流程高度一致，精髓在于通过循环实现持续学习与适应，从而制定流程、做出决策并解决问题。

一个以大模型为核心的自主 Agent 工作包含以下要素。

- 任务：起点是一个用户查询、目标或待解问题。
- 大模型：任务进入模型后进行推理，理解需求并生成解决思路。
- 工具：模型可能决定调用 API、数据库查询或其他资源来获取信息和能力。
- 行动：Agent 根据推理结果与环境交互，如发送请求、操作设备或修改数据。
- 环境：行动会改变环境，环境以结果形式反馈回来，可能意味着任务完成或产生新数据。
- 结果：反馈回 Agent，影响后续行为，直至任务彻底解决。

LangChain 强调，推理能力与工具功能共同构成 Agent 的能力内核。内部使用大模型作为推理引擎来决定做什么、按什么顺序做。整个大模型应用开发的核心观点由此浮现：操作序列不再硬编码，而是由大模型动态选择。这凸显了大模型作为 AI 自主决定应用逻辑这一新编程范式的价值。

ReAct 流程强调 Agent 如何借助大模型推理和外部工具与环境互动产生结果，凸显了大模型在推理决策中的中心地位，并说明工具如何扩展大模型能力，以及 Agent 如何通过动态交互推动任务完成。

在 ReAct 指导下，Agent 展现出四大特质。

- 适应性：不绑定特定算法，可结合多种机器学习方法与执行机制，适用于从自动化到决策支持的广泛场景。
- 交互性：支持持续学习和动态知识管理，能与环境互动并优化行为，在变化环境中保持有效。
- 自主性：可自行决策并根据变化调整策略和行为。
- 功能性：通过工具调用实现搜索、生成 PPT、收发邮件等具体任务。

小雪：什么是提示？详细说一下呗。

咖哥：提示就是喂给大模型的信息，可以是语言、代码，也可以是图像、语音等多媒体，甚至人类看不懂的编码，只要模型能理解即可。

> 提示工程 Prompt Engineering 是设计和优化输入，以引导大模型产生特定输出的方法。它涉及创造性地构建、测试和优化提示，这些提示可能是问题、陈述或指令，目的是让模型更有效地提供所需信息。它不仅关乎文本内容，还涉及格式、风格和上下文，以激发最佳响应。
>
> 好的提示工程能提升输出效率和准确性，让模型更快抓住问题本质并给出有用答案。在法律、医学、工程等专业领域，可通过提示定制回应，使其更相关、更专业。同时也能提升用户与 AI 的交互体验，让对话更自然。
