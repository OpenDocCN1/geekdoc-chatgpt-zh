# Node2vec：从数学本质到工程落地的全景解析

Node2vec 的核心目标是最大化节点出现的概率。在条件独立性假设下，节点邻域的联合概率可拆解为单节点条件概率的乘积，从而得到基础似然函数（公式 3-80）。进一步展开邻域集合，似然函数演变为双重乘积形式（公式 3-81）。

为具体计算条件概率 $P(n_i \mid u)$，Node2vec 引入向量内积的 Softmax 机制：以中心节点向量为查询，对全体节点向量做归一化打分（公式 3-82）。细观此式，会发现它与 Word2vec 的 Skip-gram 模型在数学形态上高度同构。若把当前节点视作“中心词”，邻域节点视作“上下文词”，Node2vec 实质上就是一个“以中心预测上下文”的建模范式。

**工程落地的两个关键细节：**

1.  **Embedding 共享策略**：原始公式中，节点与邻域节点共用同一映射函数 $f(\cdot)$，即共享 Embedding Lookup Table。这与 LINE、Word2vec 采用的双表（入/出、中心/上下文）机制不同。实际部署时，可根据数据分布与业务指标，灵活决定是共享还是分离参数。
2.  **邻域的定义**：$N_s(u)$ 非指一阶邻居，而是由游走算法采样生成的节点序列。这正是 Node2vec 区别于传统图嵌入的核心——**建模流程拆解为两步走：先游走采样得邻域，再 Skip-gram 优化似然。**

## 同质性与结构性：游走策略的理论基石

在详述游走算法前，需明确图嵌入要捕捉的两类相似性：

*   **同质性**：拓扑距离越近，节点越相似。如图示，u 与 s4 相似度 > u 与 s5，呈现同心圆式衰减。
*   **结构性**：拓扑角色相似则节点相似。u 与 s6 均为各自邻域的“中心角色”，故二者相似度高于 u 与边缘节点 s8。

这两种特性在现实网络中并存，单一游走策略难以兼顾。Node2vec 的巧思在于：**融合 BFS 与 DFS，通过超参数动态平衡。**

*   **DFS（深度优先）倾向远跳**：像深度扫描网络全貌，擅长捕捉**宏观同质性**。
*   **BFS（宽度优先）倾向近跳**：像显微镜聚焦局部邻域，擅长挖掘**微观结构性**。

## 二阶随机游走：参数 p/q 的精妙调控

区别于 DeepWalk 的一阶随机性，Node2vec 引入**二阶马尔可夫链**：下一步跳转不仅看当前节点 $v$，还需参考上一步节点 $t$。跳转概率由边权重 $\omega_{vx}$ 与偏置函数 $\alpha_{pq}(t, x)$ 共同决定（公式 3-83, 3-84）。

偏置函数依赖前驱节点 $t$ 到候选节点 $x$ 的距离 $d_{tx} \in \{0, 1, 2\}$：

| 距离 $d_{tx}$ | 场景 | 偏置系数 | 参数含义 |
| :--- | :--- | :--- | :--- |
| **0** | 回头跳回 $t$ ($x=t$) | $1/p$ | **返回参数 $p$** 越小，越爱回头 $\rightarrow$ 强化局部结构（**结构性**） |
| **1** | 跳向 $v$ 的邻居 ($x \neq t$) | $1$ | 基准概率 |
| **2** | 跳向更远节点 | $1/q$ | **进出参数 $q$** 越小，越爱远行 $\rightarrow$ 强化全局同质性（**同质性**） |

**退化特例**：$p=q=1$ 且忽略边权时，Node2vec 退化为 DeepWalk。

以图 3-29 为例，从 $t \to v$ 后，候选节点 $t, x, x_1, x_2, x_3$ 的跳转概率显式地受 $p, q$ 调控。工程上，只需按概率采样即可生成训练序列。

## 可视化验证与推荐场景的业务映射

论文可视化（图 3-30）直观印证了参数效果：
*   **$q < 1$ (DFS主导)**：节点按拓扑距离聚类，呈现**同质性**特征。
*   **$q > 1$ (BFS主导)**：无直接连边但结构角色相似的节点聚拢，呈现**结构性**特征。

实战中，可将不同超参下生成的多版本向量，作为**召回多路由**或**排序模型预训练特征**并行使用。

在推荐系统的物品同构图中，这两种特性极具业务解释力：
*   **同质性向量** $\approx$ **“强关联/替代品”**：同款商品、同类视频。适用于**精准召回**，保准确率。
*   **结构性向量** $\approx$ **“语义相关/互补品”**：巧克力与电影票（均为节日礼物）。适用于**多样性召回**，拓宽兴趣边界。

# EGES：引入 Side Information 攻克冷启动

Graph Embedding 依赖高阶拓扑，但面临两大痛点：**新品孤立无邻域（冷启动）** 与 **长尾稀疏导致高阶噪声大**。GES 与 EGES 尝试从**属性侧信息**切入破局。

Side Info（品牌、导演、歌手等标签）发挥双重作用：
1.  **图构建增边**：行为共现 + 属性相似 共同决定边权，让新品不再孤立。
2.  **特征融合增强**：节点表征 = ID 向量 + Side Info 向量融合。

## GES：平均池化的基线融合

GES 采用 Average Pooling（公式 3-85），ID 与 Side Info 共享维度与空间。但实业务中 ID 空间（千万级）远大于 Side Info 空间（万级），强行对齐维度不合理。改进版（公式 3-86）让 Side Info 走低维 Embedding，经 Pooling 后再接全连接层与高维 ID 向量拼接融合。

## EGES：加权平均的精细化进化

GES 平等对待所有 Side Info，但业务上**特征重要性天然差异巨大**（品牌 > 尺码；主角 > 配角）。EGES 引入 **Weighted Average Layer**（公式 3-87），为每个特征学习权重 $a_v^j$，经 Softmax 归一化（指数化保正、放大差异）后加权求和。

[PRE3]

**架构视角（图 3-31）**：稀疏特征层 $\to$ 稠密 Embedding 层 $\to$ **隐层加权融合** $\to$ 输出层。因输入不再是单一向量而是加权组合，EGES 将其定义为 **Weighted Skip-gram**。

**小结**：EGES = DeepWalk + Side Info 加权融合。它显著提升了向量表达力，并有效缓解了冷启动难题。

# 用户行为序列建模：显式时序下的兴趣捕获术

召回的本质是**用户兴趣建模**——将历史行为与物品映射至统一向量空间。与传统协同过滤（MF、图模型）将时序隐含在共现/邻接统计中不同，序列建模**显式强制时序约束**：严格用 $t$ 时刻及之前预测 $t+1$。

且用户兴趣常呈**多峰分布**，单一向量难以覆盖，需引入多兴趣表征机制。

## 3.5.1 三大技术流派与核心模块

处理行为序列提取高阶兴趣，主流路线分三类：

| 流派 | 核心逻辑 | 典型模型 | 时序处理方式 |
| :--- | :--- | :--- | :--- |
| **集合视角** | 忽略顺序，视为 Bag-of-Items | Sum/Max/Avg Pooling, CNN, Attention | **无时序**（或隐含位置编码） |
| **循环视角** | 显式建模状态演进 | LSTM, GRU, RNN 变体 | **隐式时序**（隐状态传递） |
| **注意力视角** | 显式编码位置关系 | Transformer, SASRec, BERT4Rec | **显式时序**（位置编码/注意力掩码） |

### 1. Pooling：高效的主干兴趣提取器

沿袭 CBOW 思想，将历史物品独立编码后聚合。
*   **优点**：工程极简，算力友好，擅长抽取**主干兴趣**。
*   **缺点**：丢失权重差异与偏序关系，难捕捉细微偏好漂移。
*   **经典案例**：YouTube DNN 召回模型——观看/搜索序列经 Average Pooling 拼接入深层网络（图 3-32）。

### 2. CNN：局部模式的捕猎者

Pooling 视全序列等权，易掩盖局部信号。CNN 引入**滑动卷积感受野**，借鉴 TextCNN 思想，把行为序列视为一维“图像”，捕捉**局部连续行为模式**（如连刷《雍正王朝》《康熙王朝》 $\rightarrow$ 推断偏好“历史正剧”）。

**标准协作范式**：
`CNN (提取局部) → Pooling (聚合全局) → FC (维度对齐)`
三者协同，兼顾精细纹理与整体轮廓。
