像 MiniGPT-4[39]、LLaVA[294] 这类视觉指令模型，通常需要海量的图像-文本配对才能把视觉编码器和大语言模型连起来。LLaMA-Adapter V2 选择了另一条路，只在规模有限的通用图像字幕集上做微调，数据利用效率更高一些。代价是它对图像的理解相对吃紧，实际对话中会时不时出现不准或跑题的回复。与其继续扩充图文数据或直接上更强力的多模态模型，不如在框架里接入专家模型来强化图像侧的推理能力。

如图 3.11 所示，增强思路是让专家模型为 LLaMA-Adapter V2 提供文本化的视觉线索。输入一张图后，LLaMA-Adapter V2 先用预训练的视觉编码器提取视觉内容，再调用专家模型生成一句字幕作为文本补充。在默认实现里，这个专家模型就是在 COCO Caption[315] 上预训练的 LLaMA-Adapter，能够输出简短精准的图像描述。

这里的专家模型并不固定，任何图像到文本的模型甚至搜索引擎都能胜任。正是这种松耦合的设计，让作者可以根据具体下游任务灵活切换不同的专家。

## 3.6 VideoChat

视频更接近人类持续感知的真实世界，智能视频理解在人机交互、自动驾驶、智能监控等场景里需求很大。当前的主流做法仍是把预训练的视频基础模型针对特定任务做微调，这限制了面向客户级需求的通用时空理解能力。

以视觉为核心的多模态对话系统正成为热点[253]。依托预训练的 LLM、图像编码器和可学习模块，这些系统能深入解读图像，比如识别表情包梗，并在多轮对话中完成图像相关任务[39, 319]。虽然应用上带来革新，但学界尚未从数据侧系统性地解决视频为中心任务的处理问题。

现有视频对话方案通常先用开源的分类、检测、字幕模型把视频转成文本，再化为自然语言问答。对象和动作清晰的片段里效果尚可，可视频转文本必然带来视觉信息的损失和时空复杂度的简化。几乎所有视觉模型在视频里做时空推理、事件定位和因果推断时都捉襟见肘。

为此 VideoChat[320] 提出了一个以聊天为中心的视频理解系统，兼顾视频和语言两端的 SOTA 技术。VideoChat 在模型层面构建了一个闭环，用可学习方式融合视频与语言基础模型，并在数据层面补齐训练所需的所有要素。如图 3.12 所示，它是一个端到端的聊天式视频理解系统，通过可学习的神经接口把视频基础模型和 LLM 接起来，在时空推理、事件定位、因果推断上表现突出。

[PRE1]

VideoChat-Text 将视频文本化为流，VideoChat-Embed 将视频编码为嵌入，两种视频内容都将输入 LLM 中进行多模态理解

系统架构上，VideoChat 用可学习神经接口把视频基础模型和 LLM 结合起来。模型在大型视频文本集和自建的视频指令集上做两阶段轻量训练，只更新时空对齐和视频-语言对齐模块。指令集里有数千条视频，每条配有详细文本描述以及由 ChatGPT 根据时序密集字幕合成的对话。数据刻意强调时空元素、动作、事件和因果关系，为视频对话系统提供宝贵训练资源。

VideoChat 把所有视频相关任务统一成多轮视频问答，任务在推理时由词语即时定义，训练时不提供或仅少量示例。在这种设定下，LLM 被当作通用的视频任务解码器，把视频的描述或嵌入转成人类可读的文本，对各种应用都很友好。

### 3.6.1 VideoChat-Text

首先用若干视觉模型把视频的视觉数据转成文本，再用特定提示在时间轴上结构化预测文本，最后让预训练的 LLM 通过回答基于视频文本描述的问题来完成用户指定任务。

给定视频后，VideoChat 先用 FFmpeg 以低帧率抽取关键帧，得到 $T$ 个视频帧和对应音频。把帧和音频送入各模型，可得到动作标签、帧摘要、视频标签、综合描述、物体位置坐标、视频叙事、时间戳等片段级细节。随后结合时序信息把相关内容整合成带时间戳的文本描述。先介绍所用视觉模型和提示框架，再分析 VideoChat-Text。

#### 1. 感知模型

借助视频和图像模型的组合，VideoChat 从动作、带位置标注的物体等多个角度解析视频。各模型输出相对独立，VideoChat 用预训练的 T5 模型[25] 对描述做优化以提升清晰度。此外，VideoChat-Text 还整合 Whisper[321] 语音识别，充分利用视频音频，进一步丰富描述。

#### 2. 提示系统

### 3.6.2 VideoChat-Embed

VideoChat-Embed 是一个端到端视频对话模型。结构如图 3.15（a）所示，由视频和语言基础模型加可学习的视频-语言 Token 接口 VLTI 组成。整体基于 BLIP-2[308] 和 StableVicuna，训练分对齐阶段和指令调优阶段。受文献 [322-325] 启发，为更好跨模态优化，模型采用语言友好的视频基础模型。考虑到视频冗余，VLTI 用交叉注意力压缩视频 Token，通过视频文本数据微调实现视频到语言表示的对齐，最后把视频 Token、用户查询和对话上下文一起送入 LLM。

#### 1. 结构

VideoChat-Embed 基于 BLIP-2 和 StableVicuna 实现。具体而言，视频侧用预训练的 ViT-G[326] 配合全局多头关系聚合器 GMHRA，GMHRA 是 InternVideo[324] 和 UniFormerV2[327] 中的时间建模模块。Token 接口采用预训练 Q-Former，并补充线性投影，同时加入额外查询 Token 以建模视频上下文，使模型能得到适合 LLM 的紧凑视频嵌入。

## 3.7 SAM

基于大规模网络数据的预训练 LLM 正以强大的 Zero-shot 和 Few-shot 泛化能力重塑自然语言处理[14]。训练时，这些“基础模型”[1] 能在未见任务和数据分布下泛化，通常靠提示工程实现，即用手工文本提示语言模型生成针对当前任务的有效回复。随着规模化训练，Zero-shot 和 Few-shot 性能可与微调模型相当，现象随模型规模、数据量和训练计算提升而增强[14, 21, 27, 333]。

基础模型在计算机视觉领域也有探索，最典型的是基于网络文本-图像对的对齐。例如 CLIP[2] 和 ALIGN[334] 用对比学习训练文本和图像编码器，使其相互对齐。训练完成后，精心设计的文本提示即可实现对新视觉概念和数据分布的 Zero-shot 泛化，且编码器可与其他模块组合支持下游任务如图像生成，例如 DALL·E[3]。尽管视觉-语言编码取得很大进展，计算机视觉问题远不止于此。

SAM[139] 的目标是为图像分割构建基础模型，即开发一个可提示的模型，在广泛数据上预训练以实现强泛化。通过提示工程，SAM 可解决新数据分布上的系列分割问题。成功依赖三要素：任务、模型和数据。为实现 SAM，需回答关于图像分割的几个关键问题。

- （1）哪个任务能实现 Zero-shot 泛化？
- （2）对应的模型结构是什么？
- （3）哪些数据能支撑任务和模型？

三者相互交织，需要整体方案。SAM 通过定义一个足够通用的可提示分割任务来解决这些问题，该任务既能提供强大的预训练目标，又支持广泛下游应用。任务还需一个支持灵活提示、被提示时能实时输出分割掩码的模型，便于交互使用。为训练模型，SAM 需要多样化的大规模数据集。不幸的是，目前并无大规模网络分割掩码数据集；为此 SAM 构建数据引擎，在数据收集过程中反复用高效模型辅助采集，并利用新数据改进模型。

（1）**任务**。在 NLP 和 CV 领域，基础模型可通过提示技术在新数据集和任务上做 Zero-shot 和 Few-shot 学习。受相关工作启发，SAM 提出可提示的分割任务，目标是在给定分割提示的情况下返回有效分割掩码（如图 3.19（a）所示）。SAM 将可提示分割既用作预训练目标，也通过提示工程完成通用的下游分割任务。
