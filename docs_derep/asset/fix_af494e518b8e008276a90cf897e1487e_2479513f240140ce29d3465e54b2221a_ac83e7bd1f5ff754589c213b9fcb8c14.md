RTAB-Map，全称 Real-Time Appearance-Based Mapping，是一款带实时约束的 RGB-D SLAM 实现，核心是利用增量式外观特征进行闭环判断的 SLAM 架构。它能够接纳 RGB-D 相机、立体相机或激光雷达完成建图与定位任务。闭环检测依赖词袋模型来评估当前画面更可能对应既有位姿还是全新区域；确认闭环后，系统会向地图追加新约束，随后借助图优化压低整体误差。为了在大型场景中保持实时性，RTAB-Map 采用内存管控手段，限定参与闭环搜索与图优化的位姿数量。该方案支持手持 RGB-D、双目或三维激光雷达实现六自由度重建，整套流程如图 4-23 所示。

# 2D SLAM 概述

传感器本身工作在三维空间，并不固有维度限制。然而大多数轮式平台仅在固定平面内活动，不会像飞行器那样随意变换姿态。扫地机在水平地面行进，爬墙机在垂直面上移动。酒店送餐机器人机体虽有高度，但 SLAM 算法真正关心的运动主体仍然是平面的。

从俯视视角看，二维 SLAM 可以视作激光雷达 SLAM 的平面简化。扫描数据与地图数据都被压缩为平面形式，与图像十分接近，地图甚至能以图片方式存储，部分图像特征提取与匹配技术也能迁移过来。二维 SLAM 对扫地机、AGV 等平台至关重要，历史上曾是主流方向，涌现出 Fast SLAM、GMapping 等代表性方法。不过平面运动假设在现实中存在瓶颈：一旦平台或环境出现明显三维结构便难处理。大多数二维方案默认障碍物与雷达同高，若场景中存在异高障碍物，或物体外形随高度变化明显，如桌腿与桌面差异，二维地图难以完整表达，易导致碰撞；再如平台在倾斜坡面行驶时，扫描距离与真实距离会出现几何偏差，这些都违背了二维假设，属于系统固有局限，而三维 SLAM 能很好弥补。下面重点讨论二维 SLAM。

## ROS 中基于 2D 激光的 SLAM 算法

ROS 中较为常用的二维激光 SLAM 实现包括：HectorSLAM、Gmapping、CoreSLAM、KartoSLAM，以及 Google 开源的 Cartographer。虽然 Cartographer 本身并非 ROS 原生，但已有社区移植的 cartographer_ros 版本。

### 1. `HectorSLAM`

HectorSLAM 融合了鲁棒的扫描匹配二维 SLAM 方法与惯性导航技术。对传感器要求较高，扫描匹配主要借助高斯-牛顿法求解。它无需里程计，因而适用于不平整地面上的无人机或小车建图。通过优化激光束点阵在地图上的占据概率，获得激光点集到现有地图的刚体变换。为避免陷入局部最优，HectorSLAM 采用多分辨率地图。

该方法需要高刷新频率且噪声小的激光扫描，建图时平台速度需保持较低。HectorSLAM 没有回环检测机制，此外在里程计精度较高时无法有效利用里程计信息。

HectorSLAM 的多分辨率地图如图 4-28 所示。网格单元边长从左到右分别为 20cm、10cm 和 5cm，同时保存多分辨率地图可降低陷入局部极小值的风险。思路是在内存中并存不同分辨率的地图，并用先前姿态估计去更新它们。计算开销较低且地图保持一致。

最后，三维空间的导航状态估计基于扩展卡尔曼滤波器 EKF，但仅在存在 IMU 时才需要，如空中机器人情况。此处仅讨论二维 SLAM。

图 4-28 `HectorSLAM`多分辨率地图

### 2. `Gmapping`

Gmapping 是一种基于激光的 SLAM 算法，已集成于 ROS，是移动机器人中最常用的 SLAM 实现之一。该算法由 Grisetti 等人提出，属于 Rao-Blackwellized 粒子滤波 SLAM。粒子滤波用大量加权粒子表示路径后验，每个粒子带有重要性权重，通常需要足够多的粒子才能获得较好效果，计算复杂度随之上升。粒子滤波的重采样过程还会带来粒子退化问题，即大量权重极低的粒子被剔除，可能误删正确假设。为此发展出自适应重采样技术。

Gmapping 的主要特性为：①是基于滤波 SLAM 框架的常用开源实现；②基于 RBPF，将定位与建图分离，先定位后建图；③在 RBPF 基础上做了改进提议分布和选择性重采样的改进。

它能实时构建室内地图，小场景下计算量小、精度较高。相比 HectorSLAM，对激光雷达频率要求更低、鲁棒性更好，HectorSLAM 在平台快速转向时易发生错误匹配导致地图错位，主因是优化易陷入局部最小。相比 Cartographer，Gmapping 不需要太多粒子且无回环检测，计算量更小、精度差距不大。Gmapping 能有效利用轮式里程计提供位姿先验，这也是其对激光频率要求低的原因。HectorSLAM 与 Cartographer 的设计初衷并非平面移动机器人定位建图，HectorSLAM 主要面向地面不平情况故不使用里程计；Cartographer 面向手持激光雷达 SLAM，也无里程计可用。

随着场景扩大所需粒子数增加，每个粒子都携带一张地图，内存与计算消耗都会上升，故不适合大场景。Gmapping 缺少回环检测，回环闭合时易产生地图错位，增大粒子数可改善但会付出计算与内存代价。Gmapping 与 Cartographer 分别代表滤波框架与优化框架的权衡，前者牺牲空间换取时间，后者仅用一个粒子存储地图，空间占用远小于 Gmapping，但计算量较大，一般计算机难以流畅运行。

### 3. `CoreSLAM`

CoreSLAM 旨在以简洁易懂的方式实现 SLAM 并尽量减少性能损失。算法简化为距离计算与地图更新两个核心过程。每次输入扫描时，CoreSLAM 基于简易粒子滤波计算距离。粒子滤波用于将激光扫描与地图匹配，每个粒子代表平台可能位姿及其概率权重，权重依赖于前次迭代。算法挑选最佳假设分布进行优化，低权重粒子被剔除并生成新粒子。地图更新时，新扫描的线条被加入地图。遇到障碍物时，算法并非仅绘制孤立点，而是围绕障碍点绘制调整点集，以更准确刻画障碍形状。该方法保证了地图连续性与准确性，同时保持简洁易解。

### 4. `KartoSLAM`

KartoSLAM 基于图优化，采用高度优化的非迭代 Cholesky 分解求解稀疏系统。图优化用图的均值表示地图，每个节点对应机器人轨迹的一个位姿点及传感器测量数据，连接箭头表示连续位姿间的运动约束，新节点加入后地图依据约束逐步更新。

ROS 版本的 KartoSLAM 使用稀疏姿态调整 Sparse Pose Adjustment SPA，结合扫描匹配与闭环检测，地标越多内存需求越大。与其他方法相比，图优化在大环境建图上更具优势。某些场景下 KartoSLAM 更有效，因为它仅构建由点组成的机器人位姿图，先求得位姿再进行建图，如图 4-29 所示。

### 5. `Cartographer`

2016 年 10 月 5 日，谷歌发布即时定位与地图构建库 Cartographer，开发者可用其实现机器人二维或三维条件下的定位与建图。Cartographer 的目的是在有限计算资源下实时获得较高精度的二维地图。考虑到粒子滤波在较大环境下对内存与计算的需求较高，Cartographer 采用基于图网络的优化方法。目前主要基于激光雷达实现 SLAM，后续计划支持更多传感器与平台。Cartographer 是 Google 的实时室内建图项目，传感器装于背包，可生成 5cm 分辨率的二维栅格地图。算法分为两部分：Local SLAM 通过逐帧激光扫描建立并维护一系列子图，利用扫描匹配在最佳估计位置插入子图，匹配仅与当前子图相关；Global SLAM 通过回环检测消除累积误差，子图构建完成后不再插入新扫描，随后进入闭环检测。

### 6. `LOAM`

LOAM 提出一种实时 SLAM 方案，用两种独立算法分别解决里程计与建图。定位算法以高频低精度方式进行里程计，建图算法以低频高精度方式构建地图。硬件层面结合三维 IMU 与激光雷达估计姿态与地图。实验表明该方法定位性能较高，IMU 辅助下精度进一步提升。由 LOAM 生成的点云图如图 4-30 所示，图中白点为相对特征点提取算法提取的特征点，线条为当前时刻激光雷达扫描到的物体位置。

[PRE7]

图 4-30 由`LOAM`算法生成的点云图（详见彩插）

V-LOAM 是 LOAM 的改进版，提出融合视觉与激光雷达信息的通用框架，定位结果优于 LOAM。对 V-LOAM 而言，视觉里程计以 60Hz 高频进行运动估计，激光雷达里程计以 1Hz 低频细化运动估计、消除畸变并校正漂移，使系统能适应快速运动与光照变化环境。该算法性能优于纯 LiDAR 方案，在 KITTI 基准测试中排名第一，视觉与激光雷达测程融合时的漂移误差为 0.55%。

### 7. `AMCL`

AMCL 即 Adaptive Monte Carlo Localization，自适应蒙特卡洛定位，是机器人在二维运动中基于已知地图的概率定位系统，采用粒子滤波跟踪机器人位姿，对大范围局部定位问题工作良好。正确定位至关重要，若起始点错误，后续路径规划必然失效。

1）蒙特卡洛方法：以概率统计理论为指导，通过“实验”频率估计随机事件概率或数字特征，并作为问题解。以机器人定位为例，机器人可能出现在地图任意位置，用粒子表达置信度，粒子密集处可能性更高。

2）粒子滤波：粒子数量代表可能性高低。通过评价方法改变粒子分布，例如认为粒子 A 在某坐标可能性高则打高分，下一轮在该位置附近多布置粒子，反复迭代后粒子集中于高可能性区域。

3）自适应体现在：①解决机器人绑架问题，当粒子平均分数骤降时，认为正确粒子被抛弃，会在全局重新撒布粒子；②解决粒子数固定问题，定位收敛后粒子集中，维持大量粒子无必要，此时可减少粒子数。

### 8. `3D-CTSM`

低成本激光雷达三维建图能够快速、准确、高效地完成场景点云三维重建，具有高时效、高灵活、高精度特点，但低成本激光雷达视场受限、点云分布不均，大范围点云融合配准仍具挑战。武汉大学测绘遥感信息工程国家重点实验室杨必胜教授团队提出新颖 SLAM 方法 3D-CTSM。它是一种基于激光雷达的大场景三维地图构建系统，通过提取结构化特征构建鲁棒特征关联，利用误差向量椭圆解决激光退化问题，利用样条线模型对运动轨迹建模以减小点云运动畸变，最终恢复时空连续、低冗余的三维点云地图。3D-CTSM 系统架构如图 4-31 所示，其中定位模块实现快速运动估计，建图模块完成高精度三维场景建图。

## 4.3 ROS 导航算法实战

本节包含 Gmapping 与 Cartographer 两部分的实战内容。

### 4.3.1 `Gmapping`
