#### 当前最明显的瓶颈：服务拥堵

4. 多次刷新：反复尝试通常可进入

##### 效果平平，往往是过度限制

> 写方案时，为什么DeepSeek的输出显得单薄？我明明已按结构告知它。

**提示：** 感觉体验不佳，多半是提示词过长，反而压缩了推理空间。按固定四维度框架硬套，得到的就是模板化报告。**推理型模型与指令型模型不同，并不需要冗长的指令。**

##### 推理型模型是否需要提示词

前面提到，DeepSeek属于推理型大模型，擅长逻辑推演，使用逻辑更贴近“让AI适应人”。官方虽提供示例库，但越接近自然表达，效果越好。

**推理型模型 如 DeepSeek**
- 表达需求与场景即可
- 擅长开放性逻辑问题
- 例如：“需要一封给客户的感谢信，语气真诚并体现长期合作意愿”

**指令型模型 如 GPT**
- 需要明确步骤指令
- 擅长结构化任务
- 例如：“写一封感谢信，需包含感谢、合作回顾、未来展望三点”

##### 可以随意提问吗？常见低效提问

提示词不必太长，不代表可以随意提问。不精准的表述会拉低质量，不过模型也会通过推导引导补充细节。

**1. 指令模糊，形式不清**
- 错误示例：“帮我写点关于人工智能的东西。”
- 问题：未说明文体、领域或具体方向。
- 后果：内容空泛，实用性弱。

**2. 信息缺失，缺乏上下文**
- 错误示例：“这个报错怎么解决？” 配错误截图
- 问题：未说明开发环境、依赖版本或已尝试步骤。
- 后果：需多次追问，效率下降。

**3. 问题叠加，主旨混乱**
- 错误示例：“详细解释深度学习的原理、应用和未来趋势。”
- 问题：三个主题各自可成文。
- 后果：回答浮于表面，缺乏洞察。

##### 三个进阶提问框架

不需要结构化指令，但带清晰需求与场景的提问更能激发深度推理：

**1. 分析类框架**
- 结构：是什么 + 为什么 + 怎么做
- 适用：复杂问题的深度拆解
- 示例：
  - 短视频流量下滑的原因是？
  - 平台算法近期有哪些调整？
  - 一周内如何通过内容优化提升播放？

**2. 反向提问框架**
- 结构：需求 + 担忧/风险 + 解决措施
- 适用：规避风险、寻求对策
- 示例：
  - 我计划开展跨境电商业务
  - 担心海外政策变化影响物流
  - 请给出三条风险规避策略

**3. 个性化输出框架**
- 结构：身份 + 目标对象 + 核心重点 + 风格要求
- 适用：对语言风格有要求的场景
- 示例：
  - 我是母婴博主
  - 为新手妈妈推荐辅食工具
  - 重点强调安全与性价比
  - 语言亲切易懂

##### 回答优化与校验要点

**优化**
- 补充场景信息：每次迭代增补1-2个关键信息点
- 约束输出形式：明确格式或字数，如要求表格
- 拆解问题：把复杂议题拆成小问题逐个深挖

**校验**
- 角色代入：让模型扮演特定身份复述
- 反向论证：要求用相反结论论证，检验可靠性
