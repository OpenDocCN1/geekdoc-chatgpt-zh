- 为每个迭代设定明确的截止节点，按顺序把功能逐项实现。

Agent 类型的操作方式即便不一定具备代码库检索能力，也能以更有序的思路拆解复杂项目，特别适合多环节协作的开发任务。

### 3. 选择合适的模式

常规模式适合的场景：

- 需求明确单一，任务边界清晰；
- 希望迅速拿到一份完整可用的解决方案；
- 需要借助代码库进行上下文参考。

Agent 模式适合的场景：

- 任务较为复杂，必须拆成多个子任务推进；
- 希望 AI 在执行过程中持续打磨、反复调整；
- 想要更智能的任务拆解和整体规划能力。

实际工作中两种工作方式可以灵活切换。比如先用常规模式快速搭出基础框架，再切换到 Agent 模式做细化和完善，就能兼顾效率与质量。如图3-8所示为移动端待办事项应用调试界面。

- AI 助手使用要点：先介绍项目背景，再追问细节
- 代码生成要点：逐步迭代优化，不要追求一步到位

# 第4章 使用Cursor开发Agent

## 4.1 Agent基础知识介绍

在人工智能快速演进的当下，Agent 作为一种新型智能应用形态，正在改变人与 AI 的协作方式。本节从概念、特性和系统提示词构建入手，帮助读者建立系统认知。

### 4.1.1 什么是Agent

先用生活类比来理解。设想你拥有一位极其能干的私人助理，他不仅能听懂指令，还会自主思考、规划执行路径，并灵活调用各类工具完成工作。这个角色就相当于 Agent。

Agent 是一种具备自主决策能力的智能程序。它能够感知环境、独立推理、调用工具并采取行动来完成交办的任务。

Agent 由三大模块构成。

1) 大脑——模型
大脑是 Agent 的核心，通常由一个或多个大语言模型组成，负责信息处理与决策。
- 解析用户指令与需求；
- 基于已有知识进行分析与推理；
- 制定解决问题的步骤；
- 根据情境动态调整策略。

2) 手脚——工具
工具是 Agent 与外部世界交互的延伸。
- 搜索引擎：获取最新资讯；
- API 接口：执行具体操作；
- 文件系统：读写数据；
- 计算工具：完成数值运算。

3) 大管家——编排层
编排层承担任务调度职能，协调模型与工具的配合。
- 决定何时调用何种工具；
- 处理各步骤的中间结果；
- 规划下一步动作；
- 保证整体协作顺畅。

例如规划一次旅行，Agent 会先理解需求，通过搜索获取目的地信息，调用天气 API 查看预报，再用订票系统预订机票酒店，编排层确保全流程有序进行。

### 小白必记

- Agent 的本质：具备思考能力的智能助手
- 模型功能：充当 Agent 的大脑中枢
- 工具的作用：相当于 Agent 的手脚
- 编排层职责：统筹协调各项任务
- 智能决策的特点：感知、思考、行动一体化

### 4.1.2 Agent与LLM的区别

了解 Agent 后，自然会问它与大语言模型有何不同。用一个比喻说明：第一位助手是博学但闭门造车的图书管理员，只能基于馆内书籍作答；第二位是机灵的私人助理，能上网查资料、用工具办事、处理实际问题。前者像传统 LLM，后者就是 Agent。

#### 1. 信息获取能力

1) 大语言模型
知识是静态封闭的。
- 仅限训练数据范围，无法更新；
- 不能获取实时信息，对新事件无感；
- 面对变化信息无力应对；
- 回答依赖记忆内容。

2) Agent
信息获取是动态开放的。
- 可借助搜索引擎、专业数据库等工具获得最新信息；
- 知识边界随工具使用不断拓展；
- 能融合实时信息与既有知识给出更准答案；
- 可主动学习并更新知识库。

#### 2. 上下文记忆能力

1) 大语言模型
记忆像金鱼，短暂受限。
- 对话记忆仅限当前会话窗口；
- 难以延续历史话题；
- 缺乏长期上下文关联；
- 需要用户反复重复。

2) Agent
记忆管理更持久。
- 能构建用户画像，记住偏好习惯；
- 自然延续既往对话；
- 建立持续的对话脉络；
- 基于历史交互优化服务。

#### 3. 工具操作能力

1) 大语言模型
偏于纸上谈兵。
- 只能提供建议，无法执行；
- 局限于文本交互，无法直接操作外部工具；
- 能力受模型自身限制；
- 不能完成实际操作任务。

2) Agent
具备实操能力。
- 可调用 API 与工具完成具体任务；
- 能访问数据库、文件系统等外部资源；
- 可组合多工具解决复杂问题；
- 拥有真实的执行能力。

### 小白必记

- Agent 的特点：主动学习，擅长用工具
- 传统模型局限：知识固定，无法实操
- 记忆能力差异：Agent 长期记忆，LLM 短期记忆
- 工具使用区别：Agent 可执行，LLM 仅能建议
- 应用场景对比：Agent 解决任务，LLM 回答问题

### 4.1.3 System Prompt详解

前面介绍了 Agent 的概念，下面讲解如何用系统提示词来“培训” Agent。就像给新员工发放入职手册，告诉他身份、职责与方式，这就是 System Prompt 的作用。

#### 1. System Prompt与User Prompt的区别

以餐厅为例，System Prompt 像厨师的岗位手册：
- “你是一位专业的中餐厨师”；
- “必须严格遵守食品安全标准”；
- “顾客特殊要求需特别注意”；
- “每道菜保持品质一致”。

User Prompt 像顾客点单：
- “我要一份宫保鸡丁”；
- “少放辣椒”；
- “不要放花生”。

System Prompt 定义身份与行为准则，User Prompt 提出具体任务。

#### 2. System Prompt的核心要素

一个好的 System Prompt 应包含四个要点。

1) 角色定位
明确 Agent 的工作证信息。
- 所属专业领域；
- 沟通语气风格；
- 专业知识覆盖范围。

2) 行为规范
相当于工作守则。
- 可做与不可做的边界；
- 问题处理的优先级；
- 用户隐私与安全保护方式。

3) 能力边界
相当于工具箱清单。
- 可使用的工具列表；
- 解决问题的方法；
- 输出格式要求。

4) 异常处理
应对意外情况的预案。
- 面对不明确问题如何处理；
- 出错时的应对策略；
- 何时需要人工介入。

要素组合后可得到行为可控、目标清晰的 AI 助手。

### 小白必记

- System Prompt 的作用：界定 Agent 的行为准则
- 角色定位原则：身份与领域要明确
- 行为规范要求：划清边界与准则
- 能力边界设定：明确工具使用范围
- 异常处理机制：提前准备应急预案

### 4.1.4 System Prompt设计实践

设计 System Prompt 如同建房，需要图纸与规范指导。遵循以下原则可提升质量。

#### 1. 清晰性原则

表达要具体、可执行。
(1) 用具体描述替代模糊表述。
- 不佳：“要友好一点”。
- 推荐：“使用礼貌用语，回答详细耐心，专业术语需主动解释”。

(2) 指令明确可落地。
- 不佳：“尽量写好代码”。
- 推荐：“代码必须包含完整错误处理与中文注释”。

(3) 语言简洁直接。
- 不佳：“在可能的情况下考虑性能优化”。
- 推荐：“对超过O(n²)的算法必须优化”。

#### 2. 分层性原则

设计要有层次，循序渐进。
(1) 基础层：定义基本行为与交互方式。
- 语气风格；
- 用户输入处理方式；
- 基础响应格式。

(2) 专业层：规定领域特定要求。
- 专业知识使用范围；
- 技术标准遵循；
- 行业规范执行。

(3) 特殊层：处理异常与边界。
- 敏感信息处理；
- 错误情况应对；
- 超出能力范围的处理。

### 小白必记

- 设计 System Prompt：先明确原则再动手
- 清晰性要求：表述具体，避免模糊
- 分层性原则：从基础到进阶逐步构建

### 4.1.5 使用Cursor生成System Prompt

4. 友好性：语气亲切不过分熟络

行为规范：
- 不确定时主动询问用户

输出格式：

   - 提供详细注释与文档

(3) 迭代优化。
- 查看 Cursor 建议；

工作原则：
1. 文档结构清晰、层次分明
2. 使用准确术语并提供通俗解释
3. 示例代码可直接运行
4. 重视实用性与可操作性

行为规范：
- 使用 Markdown 格式撰写
- 重要概念配示意图或流程图
- 代码示例包含完整注释
- 每主题含“最佳实践”与“常见问题”

输出格式：
1. 标题采用规范层级
2. 代码块标注对应语言
3. 关键信息用引用块突出
4. 步骤说明用编号列表

工具使用：
- 允许使用：Markdown 编辑器、代码格式化工具、图表生成工具
- 使用限制：不生成具体业务逻辑代码
- 异常处理：对复杂技术问题提供相关资源链接

- System Prompt 模板：创建 AI 助手的起点
- Cursor 优化流程：先模板，后需求，再优化
- 需求描述原则：具体明确，重点突出
- 迭代优化方法：根据效果持续改进
- 实践验证重要性：理论指导实践，实践优化理论
