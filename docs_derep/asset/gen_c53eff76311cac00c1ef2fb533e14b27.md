模型只回“是/否”：给浇水决策加硬约束

想让本地大模型做个超简单的二选一判断，最怕的就是它话多、跑偏。这段实践的核心思路就是用系统指令把回答空间锁死，再用代码在外层做兜底，保证最终永远只输出一个字。

先给模型上紧箍咒。系统提示里明确角色是植物浇水决策助手，输出必须且只能是一个汉字“是”或“否”，禁止解释、禁止标点空格、禁止任何额外词汇。浇水的逻辑也写死：气温低于0℃坚决不浇；0到5℃区间只有土壤极度干燥且植物特别需要水才考虑；土壤湿度是主要依据但必须结合温度一起看；沙土干得快，但低温下仍然不建议浇水。最后收口也写清楚，需要浇水回“是”，不需要回“否”。

为了防止模型还是偷跑，调用层做了两道保险。第一道是极端温度预判，用正则抓取用户输入里的“气温是：X℃到Y℃”，只要最高温≤0℃就直接返回“否”，根本不进模型。第二道是后处理清洗，先把HTML标签和多余空白去掉，再判断返回内容是否干净包含“是”或“否”。如果同时出现或都不出现，就用负面词表和正面词表做二次推断，负面词命中就判“否”，正面词命中判“是”，兜底默认“否”，安全第一。

接口参数也调得很保守，温度0.1、最大Token 50、repeat_penalty 1.2、top_p 0.5，模型基本只负责给出一个字。调用失败或解析错误会返回明确的错误提示，方便排错。

示例里对比了两种场景，注释掉的-21℃到0℃沈阳沙土干燥是典型极端低温，直接走预处理得到“否”；实际运行的是15℃到20℃晴天沙土干燥，符合常规判断流程交给模型+后处理。

def force_yes_no_response(text):

    """强制只返回"是"或"否"的处理函数"""

    # 先清理文本

    text = clean_response(text)

    # 直接检查是否包含确切的"是"或"否"

    if "是" in text and "否" not in text:

        return "是"

    elif "否" in text and "是" not in text:

        return "否"

    # 如果同时包含或都不包含，进行更复杂的分析

    negative_terms = ["不需要", "不建议", "不必", "不适合", "不宜", "无须", "没必要", "不要"]

    for term in negative_terms:

        if term in text:

            return "否"

    positive_terms = ["需要", "应该", "建议", "必须", "适合", "适宜"]

    for term in positive_terms:

        if term in text:

            return "是"

    # 默认返回"否" (安全起见)

    return "否"

def clean_response(text):

    """响应清洗函数"""

    text = re.sub(r'<\/?[\w\s]+>', '', text)

    text = re.sub(r'\s+', ' ', text).strip()

    return text

def needs_preprocessing(prompt):

    """检查是否有需要预处理的极端条件"""

    temp_match = re.search(r'气温是：(-?\d+)°C到(-?\d+)°C', prompt)

    if temp_match:

        low_temp = int(temp_match.group(1))

        high_temp = int(temp_match.group(2))

        if high_temp <= 0:

            return True

    return False
