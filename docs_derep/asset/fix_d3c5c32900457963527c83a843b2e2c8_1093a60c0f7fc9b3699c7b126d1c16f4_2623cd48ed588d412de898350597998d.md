#### **3.3.3 流式交互提升体验**

相较于常规 Web 服务，大模型并非查库返回，而是现场推理生成。文本产出需要时间，若沿用传统的请求-响应模式，用户提问后往往要空等数秒甚至十几秒，答案才一次性送达，体验感较差。

大模型的推理本质是逐步预测，模型每次产出若干 token 再逐步拼接成完整回复。只要把这个渐进生成过程映射到客户端，就能避免长时间空白。OpenAI 兼容接口因此引入 SSE。SSE 是 HTML5 的推送机制，服务端可在不被轮询的情况下主动把新数据推送到客户端，消息产生即时送达，从而形成动态聊天效果。从用户视角看，内容是逐段递进出现的，过程不卡顿，并带有类打字机视觉，像是 AI 在边思考边输入作答。这样既缓解了用户对模型性能的焦虑，也提升了交互流畅度，还分摊了 API 服务的并发压力。SSE 的原理见图 3-5。

### 4.1 基础设施

#### 4.1.1 服务器要求

大模型应用的硬件主要由服务器与推理卡构成。服务器可用高性能个人电脑替代，对主板与电源有一定要求，电源功率建议不低于 750W，主板需兼容推理卡。与消费级显卡不同，推理卡通常没有内置风扇，温度过高时会触发自我保护，导致系统无法识别。因此机箱内需加装风扇以保证散热，维持正常工作。

#### 4.1.2 操作系统准备

操作系统可选用主流 Linux 发行版或 Windows。在安装推理卡前，先完成系统更新与补丁安装。如在 Ubuntu 上，可通过“sudo apt update”刷新包列表，再用“sudo apt upgrade”执行升级。若服务器上已有应用在运行，建议谨慎使用 upgrade，以免升级后导致服务异常。Windows 的更新相对简单，进入“设置”→“更新与安全”→“检查更新”即可自动完成，风险较低。

#### 4.1.3 推理卡安装

以 NVIDIA P100 推理卡为例。安装时将卡插入 PCI-E 插槽并拧紧螺丝，确保固定牢靠且散热通畅，随后连接电源，效果如图 4-1 所示。

**5.解决 PyTorch 报错**

若校验结果为“False”，通常会伴随报错信息。常见错误有“undefined symbol:__nvJitLinkAddData_12_1，version libnvJitLink.so.12”或“The NVIDIA driver on your system is too old”。

以下情况易导致报错，需留意。

❍ CUDA 版本低于 12.0。
❍ 处于 Windows 环境。
❍ 安装时未指定 PyTorch 版本导致安装了最新版。
❍ 推理卡未正确安装。
❍ 推理卡驱动未安装。

在 Linux 环境、CUDA 版本 12.0 及以上、指定 PyTorch 版本号的情况下，安装过程通常较为顺利。

遇到报错时，一般做法是适度降低 PyTorch 版本。先卸载已装版本，再从 PyTorch 官网查找旧版安装命令重新安装，安装后再次验证，如仍报错则重复此过程，直至找到合适版本。

#### **注意**

应使用 pip 而非 conda 命令。旧版本链接为 https://pytorch.org/get-started/previous-versions/。
