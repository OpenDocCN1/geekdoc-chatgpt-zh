LangGraph：状态驱动的图式智能体构建思路

LangGraph 的设计哲学在于把复杂的循环化工作流拆解为功能节点 Node 与控制边 Edge 的组合，通过消息在节点间传递来形成一条完整可执行的路径。信息能否在图中实时刷新并送达正确位置，关键取决于它提供的 State 机制。每次图运行都会产生一个状态实例，节点在处理时读取并改写该实例。状态并非一次性快照，而是在节点输出驱动下持续演化，进而影响循环内部后续环节的推进方向，如图 8.15 所示。

共享状态指的是图执行期间节点之间流动的公共数据与信息。LangGraph 让节点在运行时读写同一份状态来交互。这种机制使得各节点能够基于共同维护的数据交换上下文、相互影响行为，实现操作的协调与同步，支撑起动态协作与复杂流程的编排，让节点依托已有共享信息协同决策。

##### 5. 官方如何定义 LangGraph 及其核心优势
根据官方表述，LangGraph 是一个面向大模型构建有状态、多角色应用的开发库，可用于搭建单智能体或多智能体流程。其概括的主要优势包括：

- 条件循环：可在应用里落地分支判断与循环控制。
- 状态持久化：每一步执行后状态自动保存，支持随时暂停与恢复，便于容错、人机协同流程、时间回溯等场景。
- 人机协同：在执行过程中可中断人工确认或修改下一步计划。
- 流式输出：各节点可产生流式结果，涵盖 Token 级流式。
- 生态兼容：与 LangChain 及 LangSmith 实现无缝对接。

如图 8.16 所示，BiliAgent 的整体脉络如下。

- (1) 用户提出问题，对应图中①。
- (2) 进入检索节点完成信息召回，对应图中②③④。
- (3) 通过评分节点判断文档相关性，对应图中⑤⑥。
- (4) 若判定不相关则调用问题重写 transform_query 节点优化提问并回到检索形成循环。
- (5) 若判定相关则进入生成答复 generate 节点输出最终答案，对应图中⑦。
- (6) 后续还能接入幻觉检测与代码校验节点，对应图中⑧。

当流程顺畅时，最终会产出答复，完成①②③④⑤⑥⑦⑧的闭环。

代码层面主要分布在三个文件。

- nodes.py：实现各节点的具体功能。
- edges.py：定义节点间的跳转规则。
- graph.py：负责图结构的组装与整体执行。
