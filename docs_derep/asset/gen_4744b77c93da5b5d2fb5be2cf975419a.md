大语言模型在参数规模和训练数据量上都达到了极端水平，所以现有的训练全都依赖分布式架构来完成。文献 [5] 对 GPT-3 的训练仅提到全部采用了 NVIDIA V100 GPU。文献 [28] 则详细说明 OPT 的训练使用了 992 张 NVIDIA A100 80GB，组合了全分片数据并行 Fully Sharded Data Parallel [170] 与 Megatron-LM 张量并行 Tensor Parallelism [171]，整体耗时接近两个月。BLOOM [30] 的团队披露了更完整的硬件与系统信息：该模型训练历时 3.5 个月，共动用 48 个计算节点，每个节点装有 8 张 NVIDIA A100 80GB GPU，合计 384 张 GPU，节点内部通过 4 条 NVLink 互联，节点间则靠 4 个 Omni-Path 100 Gbps 网卡搭建增强型 8 维超立方体全局拓扑进行通信。文献 [33] 未给出 LLaMA 训练集群的具体配置和网络拓扑，但提供了不同规模的总 GPU 时长，均基于 NVIDIA A100 80GB：LLaMA-7B 约需 82,432 GPU 小时，LLaMA-13B 约需 135,168 GPU 小时，LLaMA-33B 约需 530,432 GPU 小时，LLaMA-65B 高达 1,022,362 GPU 小时。LLaMA 的训练语料远超 OPT 与 BLOOM，即便参数量更小，所消耗的计算量依然极为惊人。

借助分布式训练，单设备需要数十年的训练时长，可以被压缩到数千台设备、数十天内完成。分布式系统要想把集群算力吃满，就必须攻克计算墙、显存墙、通信墙等一系列瓶颈。

- **计算墙**：单台设备可提供的算力与大模型总需求之间差距悬殊。2022 年 3 月发布的 NVIDIA H100 SXM 单卡 FP16 算力约为 2000 TFLOPS，而 GPT-3 的总计算需求约为 314 ZFLOPS，两者相差约 8 个数量级。
- **显存墙**：单台设备无法容纳完整模型。GPT-3 拥有 1750 亿参数，若以 FP32 保存需约 700GB 内存，而 NVIDIA H100 GPU 显存仅 80GB。
- **通信墙**：分布式环境下各设备须频繁传输和同步参数，延迟与带宽会成为瓶颈。GPT-3 训练时若存在 128 个模型副本，每次迭代至少要搬运 89.6TB 梯度数据。截至 2023 年 8 月，单条 InfiniBand 链路带宽上限不超过 800Gbps。

计算墙和显存墙本质上是单设备算力与存储受限，与模型庞大需求矛盾。分布式训练可以缓解前两者，却带来了通信墙的压力。在多机多卡场景下这些矛盾会逐步显现，随着模型参数增长集群规模同步扩大，问题更加突出。长时间大规模训练还会伴随设备宕机风险，对系统的容错与调度能力提出很高要求。

## 4.2 分布式训练的并行策略

分布式训练的目的是把单节点训练等价地转化为分布式并行训练。对大语言模型而言，训练就是依据数据与损失函数，通过优化算法不断更新神经网络参数的过程。单设备训练结构如图 4.3，核心由数据与模型两部分构成。训练以多个数据小批次 Mini-batch 为单位推进，图示中的数据即为一个小批次。系统利用该批次结合损失函数和优化算法计算梯度，从而修正模型参数。大语言模型多层网络的运行可抽象为一个**计算图** Computational Graph，该图由多个相连的算子 Operator 组成，每个算子对应一层神经网络，参数即为训练中需要更新的权重。

[PRE0]

计算图的执行划分为前向计算和反向计算。前向计算把数据送入首个算子得到输出，依次推进直至最后一个算子完成处理。反向计算则依据损失函数与优化算法，按顺序为每个算子计算梯度并用梯度更新本地参数。完成一次反向计算后，当前小批次结束，系统读取下一个小批次继续迭代。

从单设备流程来看，并行加速可以从数据与模型两个维度切入。对数据做 Partition 并在多设备上复制同一模型，各自处理不同的数据分片，这种方式称为**数据并行** Data Parallelism，DP。也可以把模型本身拆分，将不同算子分发到多设备执行，这就是**模型并行** Model Parallelism，MP。实际训练大语言模型时常同时对数据和模型进行切分，形成**混合并行** Hybrid Parallelism，HP，以获得更高并行度。

### 4.2.1 数据并行

数据并行下，每个计算设备都保存一份完整的神经网络模型副本。每轮迭代时，设备只负责一个批次样本的子集，并对其做前向计算。设一个批次样本数为 $N$，使用 $M$ 台设备，每个设备分配到 $N/M$ 个样本。前向结束后，各设备基于本地样本计算损失并得到梯度 $G_i$，$i$ 为加速卡编号，随后将本地梯度 $G_i$ 广播。所有设备聚合各卡梯度，使用平均梯度 $(\sum_{i=1}^{N} G_i)/N$ 更新模型，完成该批次。图 4.4 示意了由两台设备组成的数据并行训练。

增加设备能有效提升整体吞吐量，即**每秒全局批次数** Global Batch Size Per Second。与单设备相比，关键差异在于反向阶段的梯度必须在所有设备间同步，以确保最终模型使用全局平均梯度。主流框架均提供数据并行实现，如 TensorFlow DistributedStrategy、PyTorch Distributed、Horovod DistributedOptimizer 等。由于 Transformer 大语言模型每个算子依赖单个样本而非整批，数据并行不改变计算逻辑。通常前向阶段各设备独立，无需同步。数据并行加速潜力最大，但要求每台设备都备份完整模型，显存开销较高。
