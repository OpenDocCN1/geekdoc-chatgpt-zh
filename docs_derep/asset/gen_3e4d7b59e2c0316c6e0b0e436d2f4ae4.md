### 3）存储优化

存储侧的优化核心在于对数据访问路径和内存层级做精细化调校，从而整体拉升系统表现。内存时延隐藏的思路就是把等待数据返回的时间压到最低，常见手段是提前把数据预取到缓存、调整访问顺序提升命中率，或者在等待期间并行推进别的计算。

让处理器在数据加载的间隙也保持忙碌，是时延隐藏要达成的目标。双缓冲是典型做法，用两块缓冲区轮转平滑数据流。当 A 区正在被算时，B 区已经在后台载入下一批数据，特别适合图形渲染、视频处理这类数据持续到来且对时序敏感的场景。

除此之外，合理的内存分配、把数据结构瘦身减少占用、引入内存池来降低申请释放开销，都是存储优化的常见组合拳。这几类策略协同起来，能明显改善内存访问效率，削弱内存瓶颈带来的拖累。

## 11.3.3 DSL 开发算子

手写算子要钻到硬件底层，数据布局、指令挑选、索引计算都要反复精调，编写 Kernel 的门槛因此很高。为此出现了 TVM、Triton 等高级语言 DSL 来提速开发。

这类 DSL 用高层抽象把常用的优化封装起来，编译阶段自动识别并落地。开发者只需写计算逻辑，利用提供的 API 就能得到高性能算子。与纯手写极致优化相比，性能通常能达到 90% 以上，而开发效率却能提升数十倍，这个取舍在多数场景下是值得的。

Triton 由 OpenAI 主推，面向深度学习和高性能计算的 GPU 编程语言与编译器，目标是用比 CUDA 更高的生产力快速写代码。

## 11.3.4 Triton 实现原理

在 Triton 之前，算子工程师需要同时兼顾 DRAM、SRAM、计算单元，面临诸多挑战：

- 内存管理：利用好内存体系，把高频访问数据块放到更快的存储区；访存对齐与合并，避免带宽浪费。
- 线程管理：最大化硬件计算资源，规划并行线程数与线程束大小。
- 指令使用：CUDA 实现同一功能有多条指令，时延与吞吐不同。

Triton 让开发摆脱硬件细节的束缚。CUDA 直接面向 Thread 编程，Triton 面向 Thread Block 编程，开发者只需关心 ① Kernel Launch 参数；② 每个数据分块的大小；③ 分块之间的交互，其余细节由 Triton 完成。

- 优化策略：结合算子特性与硬件资源特点，采用循环优化、指令优化和存储优化等技术提升性能。
- DSL 开发算子：使用 TVM 和 Triton 等高级语言加速算子开发，通过封装优化技术和自动调优提高开发效率。

## 11.4 算子循环优化

硬件执行时大量使用 for 等循环指令不断读取不同数据执行重复操作，SIMT/SIMD 下循环优化的意义在于提升数据局部性或计算并行性，从而提高算子整体性能，这两者都依赖 AI 芯片硬件的支撑。

### 11.4.1 循环优化挑战

1. 数据局部性

数据局部性与存储层级相关，计算机有多级存储，从慢到快、从大到小。最上层寄存器在 CPU 片内，速度最快但最贵容量最小。主存存放运行程序与数据，速度与 CPU 有差距，为此在主存与 CPU 间插入速度更快容量更小的高速缓冲存储器即 Cache。主存与 Cache 间的数据迁移由硬件自动完成，对程序员透明不可直接控制。

现代多核 CPU 的 Cache 分为 L1、L2、L3。对运算速度影响最大的是 L3，因为不命中会触发片外访存。L3 大小一般在几 MB 到几十 MB，容量有限，无法容纳全部数据，只能放 CPU 最可能处理的数据。

两个经典局部性原理：

- 时间局部性：CPU 处理了一个数据后，很可能再次处理它。
- 空间局部性：CPU 处理了内存中某块数据，很可能读写附近数据块。

分析局部性的意义在于 Cache 容量有限。若 CPU 要读写的数据在 Cache 中为命中，可在该级返回；若不在则未命中，需向下一级取数，增加 IO 开销。

2. 计算并行性

现代 CPU 通常多核，可进行线程级并行。单核上多任务运行靠时间片轮转等调度模拟并行，同一时刻只执行一个任务。

多核上每个核可独立计算，配合超线程技术一个核可执行两个线程。把多个计算线程分到多个核上可实现并行加速，这是 CPU 上最有效的优化方式。

Windows 任务管理器可查看核心与逻辑处理器数。逻辑处理器由超线程模拟，让处理器在同一时间段处理多个线程，提升多任务能力。

向量化是数据级并行优化，即批量操作。计算机常见执行模型是 SIMD，通过对批量数据做相同计算提升效率。向量架构把分散在存储器的数据集取出，放到大型顺序寄存器堆即向量寄存器中，对整个寄存器操作从而同时计算多个元素。向量可容纳不同大小数据，如一个寄存器可容纳 64 个 64bit 元素，也可容纳 128 个 32bit 或 512 个 8bit。凭借硬件多样性，向量化特别适合多媒体与科学计算。

### 11.4.2 循环优化方案

针对不同局部性和并行性需求，有循环分块、循环展开、循环重排、循环融合、循环拆分等方案。下面详细介绍不同循环优化方案。

1. 循环分块

循环分块利用 Cache 的数据局部性做优化。现代 CPU 具有多级 Cache，Cache 在寄存器后最靠近 CPU，相比主存更快但容量更小。Cache 复制 CPU 频繁使用的数据以便快速访问。容量有限时数据会在 Cache 中换入换出。若访问数据不在 Cache 中会产生 Cache Miss，需向低一级发起请求并把数据载入 Cache，访问时间大幅增加。若数据在 Cache 中则可直接复用。

循环分块主要针对大型数据集。大数据集无法一次全放进 Cache。遍历时按顺序访问会把之前载入的数据挤出去，导致后续指令无法复用而重新加载，产生大量 Cache Miss，复用性差，执行时间变长，大量时间花在载入数据上。

循环分块把大数据集切成多个小块以充分复用。数据块的内存访问是一个具有高局部性的小邻域，可一次性载入 Cache，在被替换前完成尽可能多的计算任务。

实现上把一层内层循环拆成 Outer Loop * Inner Loop，再把 Outer Loop 提到更外层，确保 Inner Loop 能满足 Cache。
