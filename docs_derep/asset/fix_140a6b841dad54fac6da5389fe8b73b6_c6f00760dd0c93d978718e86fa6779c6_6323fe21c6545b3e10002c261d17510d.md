大模型调用保稳：多模型熔断降级方案

在生产环境里，单模型依赖很容易因为服务不稳定、响应超时或流量限制而直接影响业务可用性。把所有请求压在同一个接口上，容错空间几乎为零。下面的多模型容错调度实现，通过输入净化、优先级路由、熔断保护和自动降级，让调用链路更具韧性。

整体流程是请求到达后先做安全清洗，再根据优先等级选择当前可用的模型实例。熔断器负责隔离持续异常的节点，达到失败阈值后进入熔断状态，期间不再调度；超过恢复等待时间后进入半开状态做探测，成功则恢复，失败则继续隔离。失败次数、恢复时长、单次超时和重试上限都可通过配置调整，语义缓存则用于减少重复请求。

输入清洗会移除不可见控制字符和 HTML 标签，并将长度截断到 4000 以内。端点池中优先使用 deepseek-v3、qwen-max、glm-4-plus，高优先级数值越小越靠前；当主力节点不可用时自动切换到 qwen-turbo、glm-4-flash 等降级资源。熔断状态分为关闭、打开和半开三种，打开期间不放行流量，半开时允许试探请求验证恢复情况。

class CircuitState(Enum):

    CLOSED = "closed"    # 正常状态

    OPEN = "open"        # 熔断状态

    HALF_OPEN = "half_open"  # 半开状态（尝试恢复）

@dataclass

class ModelEndpoint:

    name: str

    base_url: str

    api_key: str

    priority: int  # 优先级，数值越小，优先级越高

    failure_count: int = 0

    last_failure_time: float = 0

    circuit_state: CircuitState = CircuitState.CLOSED

@dataclass

class FaultToleranceConfig:

    failure_threshold: int = 3      # 连续失败次数阈值

    max_retries: int = 2            # 最大重试次数
