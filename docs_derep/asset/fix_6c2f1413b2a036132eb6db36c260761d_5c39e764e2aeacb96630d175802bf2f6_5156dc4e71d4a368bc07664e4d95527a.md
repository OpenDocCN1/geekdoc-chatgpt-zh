LangGraph：用状态驱动的图把 Agent 跑起来

LangGraph 的核心想法是把带循环的复杂流程拆成功能单元 Node 与控制关系 Edge，让消息在单元间传递形成可执行的链路。消息能否及时更新并送达正确位置，关键在于 State 机制。每次图调度都会产生一个状态实例，参与执行的单元会读取并修改这个实例。状态不是一次性快照，而是在各单元输出的推动下持续演化，进而影响循环内部后续步骤的推进，如图 8.15 所示。

所谓共享状态，就是图运行期各单元之间流转的公共数据。LangGraph 允许单元在执行中读写同一份状态来交互。这种设计让不同单元能够基于共同维护的数据交换上下文、相互制约行为，实现协调与同步，支撑动态协作与复杂流程编排，让单元依据已有公共信息协同决策。

##### 5. 官方对 LangGraph 的定义与主要优势
官方把 LangGraph 定位为面向大模型构建有状态、多参与者应用的库，可用来搭建单 Agent 或多 Agent 流程。归纳的优势如下：

- 循环与分支：支持在应用里实现循环和条件判断。
- 持久化：图每走一步状态会自动保存，可随时暂停恢复，便于容错、人机协同、时间回溯等。
- 人机交互：可中断执行以便人工确认或修改下一步计划。
- 流式输出：各单元都能产生流式结果，包含 Token 级流式。
- 生态兼容：与 LangChain 及 LangSmith 无缝衔接。

如图 8.16 所示，BiliAgent 的主线如下。

- (1) 用户输入问题，对应图中的①。
- (2) 进入检索单元进行信息召回，对应图中的②③④。

流程顺畅时，最终会得到答复，完成①②③④⑤⑥⑦⑧的闭环。

- nodes.py：实现各单元的具体功能。
