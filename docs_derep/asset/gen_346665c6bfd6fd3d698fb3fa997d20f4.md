OpenClaw 的核心配置全部集中在数据目录里的 openclaw.json 这个文件里，后续要改动设置直接编辑这份文件即可，改完以后记得重启 OpenClaw 程序才生效。动手前要记住三点：核心配置节点不要随意删掉，否则系统起不来；先备份一份 openclaw.json，防误操作丢失；如果改出问题，可以重新走一遍 onboard 流程，勾选“覆盖现有配置”来重做初始化。

### 9.4 初始化失败快速自检指南

OpenClaw 第一次启动跑 onboard 时，常因配置写错、环境不对、权限不够或网络波动导致失败，典型现象是流程卡住、提示初始化失败、程序闪退或打不开 Web 界面。本节把首次启动失败的常见根因、排查思路和实操步骤梳理清楚，适配各大平台，方便新手快速定位，也给进阶用户一个系统的排查清单，减少反复踩坑。

排查思路是先找准报错原因再对症处理。先看 onboard 页面或终端给出的错误提示，再看运行日志，之后再逐项检查配置、环境、权限、网络，避免盲目尝试。错误信息直接在 Web 界面或命令行里就能看到，比如“API 密钥无效”“端口被占用”“权限不足”。日志路径按启动方式不同：PM2 用 `pm2 logs openclaw`；nohup 用 `nohup.out`；Windows 服务看事件日志；Docker 用 `docker logs 容器ID`，日志里会记录更细的报错信息。

常见场景与处理办法：

场景一，模型配置步提示“API 密钥无效”。多半是密钥填错、过期或没开通对应模型的调用权限。重新登录第三方平台拉取最新密钥，输入时注意大小写和空格，确认该密钥有对应模型的权限，过期就重新创建。若用本地模型提示“模型路径错误”，核对路径写法是否正确，路径不存在就新建目录并放好模型文件，选择正确的模型格式。

场景二，提示“端口被占用”。默认 18789 或自定义端口被别的进程占用。Linux/macOS 执行 `lsof -i:端口号`，Windows 执行 `netstat -ano | findstr 端口号`，找到占用程序后停止它或卸载。实在停不掉就换一个 1024~65535 间的空闲端口，重新进 onboard 修改。Docker 用户同时要改好端口映射，保证容器端口和主机端口一致。

场景三，提示“权限不足，无法写入配置文件”。当前用户对安装目录或数据目录没有读写权限。Linux/macOS 可执行 `sudo chmod -R 775 安装目录/数据存储路径`，或切到 root 再跑一次初始化。Windows 要用管理员身份打开终端或浏览器重试，仍不行就右键安装目录→属性→安全，给当前用户读写权限，取消只读。

场景四，插件初始化失败，提示“网络异常，无法下载插件”。网络不稳、防火墙拦截或官方仓库访问不了。先检查网络是否通畅，关闭防火墙或把 OpenClaw 加入白名单，重新尝试。若仍失败可先跳过插件初始化，后续在系统“插件管理”里手动安装，下载安装包放到指定目录执行初始化命令。核心插件失败时，可重跑 onboard 只勾选核心插件，降低下载压力。

场景五，初始化完成却打不开 Web 界面。可能是端口配错、程序没正常起来或防火墙拦截。核对访问地址端口与配置一致；查进程状态，`systemctl --user status openclaw` 看是否为 online，errored 就重启 PM2 进程。Windows 服务用户确认 OpenClaw 服务在运行；关闭防火墙或放行端口。Docker 用户用 `docker ps` 确认容器 Up，端口映射正确，未运行就 `docker start 容器ID`。

其他特殊情况：初始化闪退。本地模型常见原因是设备性能不够或依赖编译失败。本地模型可调小上下文长度、线程数，或改用云端 API。源码安装用户重跑 `pnpm install` 装依赖，再 `pnpm run build` 编译后重启。若硬件不足，升级内存硬盘或换资源占用更低的模型版本。

预防建议：启动前确认设备满足本地模型内存硬盘要求，网络通畅，端口未被占用；配置时仔细核对 API 密钥、路径、端口等关键项；提前赋予当前用户足够权限；初始化过程中不要关浏览器、终端或容器，避免中断；完成后及时备份配置文件，方便回滚。

### 9.5 启动状态查看与运维技巧

初始化完成后，日常使用要定期看启动状态，及时发现进程崩溃、内存泄漏或端口冲突。下面结合主流安装方式讲清查看方法和常用管理操作，兼顾新手和服务器用户。

命令行查看高效精准，方法可组合使用：

PM2 守护：`pm2 status openclaw` 看进程 ID、名称、状态、内存 CPU 和运行时长，online 正常、errored 异常、stopped 已停止；`pm2 logs openclaw` 看实时日志；`pm2 show openclaw` 看启动命令、环境变量等详情。

nohup 守护：`ps aux | grep openclaw` 或源码安装时 `ps aux | grep pnpm` 看进程是否存在；`lsof -i:端口号` 确认端口占用；`cat nohup.out` 看运行日志。

Windows 服务：`net start OpenClaw` 启动服务后，`sc query OpenClaw` 或 `net status OpenClaw` 查看状态，RUNNING 表示正常，异常可查 Windows 事件日志。

Docker：`docker ps` 看容器是否 Up；`docker logs 容器ID` 看日志；`docker inspect 容器ID | grep PortBindings` 核对端口映射。

核心管理操作包括启动、停止、重启、重载配置和监控。

启动：源码非守护进目录执行 `openclaw gateway`，PM2 守护执行 `pm2 start ecosystem.config.js`；包管理器非守护 `openclaw start`，PM2 守护 `pm2 start $(which openclaw) --name openclaw -- start`；Windows 服务 `net start OpenClaw`；Docker `docker start 容器ID`。

停止：非守护直接关终端；PM2 `pm2 stop openclaw`；nohup 找到 PID 执行 `kill -9 PID`；Windows `net stop OpenClaw`；Docker `docker stop 容器ID`。

重启：PM2 `pm2 restart openclaw`；Windows `net restart OpenClaw`；Docker `docker restart 容器ID`；非守护先停再启。

重载配置：改完 openclaw.json 或 Web 界面“系统设置”后必须重启生效。PM2 重启进程，Windows 重启服务，Docker 重启容器，非守护重新启动即可。

状态监控：PM2 用户可用 `pm2 monit` 打开实时监控看资源和日志；Linux 服务器可配 crontab 定时检查进程，异常自动重启；Windows 可用任务计划定时检查服务状态，异常自动重启。

异常处理技巧：发现进程异常先看日志定位原因；PM2 会自动重启，频繁崩溃需排查配置错误、依赖缺失或性能不足；内存持续升高可在 PM2 调整 `max_memory_restart` 限制；端口被占就停用占用程序或改端口重启；Docker 容器异常退出，查日志排查端口映射、配置挂载问题后重启容器。

### 第10章 配置文件与大模型接入

配置文件决定 OpenClaw 能否正常启动和稳定运行，模型对接则决定智能对话、工具调用等核心功能的好坏。本章围绕配置结构、主流大模型接入、修改保存方法、权限配置和参数调节展开，帮助新手快速上手，进阶用户精细调优。

### 10.1 配置文件结构与规范解读

OpenClaw 配置采用 JSON 格式，结构清晰、可读性强，所有核心配置都写在单一文件 openclaw.json 中，便于统一管理。文件在首次 onboard 完成后自动生成，默认放在数据存储目录下。源码和包管理器安装默认在安装目录下的 data 文件夹，Docker 安装默认在挂载的 data 目录。

系统启动时会读取该文件，若文件缺失、语法错误或核心参数缺失，会导致启动失败或功能异常。

JSON 规范要点：键名必须用双引号包裹，不可用单引号；字符串值用双引号，数字、布尔值不用；数组用 `[]`，元素间用逗号；对象用 `{}`，键值对间用逗号，最后一个后不加逗号。JSON 不支持注释，需要备注请另建文档。不要随意删除核心节点，可选参数删除前确认不影响运行。

### 10.2 GPT、Claude、本地模型接入实操

OpenClaw 同时支持云端 API 模型和本地模型。云端无需本地部署、配置简单、响应快，适合新手；本地模型隐私性强、无调用费用、可离线，适合有高配设备且关注数据安全的用户。

GPT 接入：OpenAI 官方模型如 gpt-3.5-turbo、gpt-4、gpt-4-turbo，通过调用 OpenAI API 实现，对话、工具调用、文档分析全覆盖。注意密钥保密，调用有额度频率限制，超限会失败；提示密钥无效或调用失败时，检查密钥正确性、网络是否通畅、是否需要科学上网、模型版本是否支持。国内用户可通过合规代理访问。

Claude 接入：Anthropic 官方模型如 Claude 2、Claude 3，长文本和大上下文是优势，适合处理长文档和数据分析。密钥同样需保密，额度频率规则与 OpenAI 不同，需在 Anthropic 官网查看，部分地区需代理。上下文窗口默认较长，可按需调整参数，但参数过大提升成本和延迟。

本地模型接入：模型文件部署在本地电脑或服务器，无需网络和第三方 API。优势是数据不外泄、无费用、可离线。注意填写绝对路径，不可用相对路径；模型格式要和配置一致；设备性能直接影响加载速度和响应，内存不足会导致闪退，需根据硬件调参。推理能力通常略逊于云端，可通过参数优化体验，追求更强推理可选用更大参数模型并升级硬件。

### 10.3 如何安全修改并保存配置文件

openclaw.json 支持手工编辑修改，关键是保证格式正确、参数有效，修改后保存并重启程序才生效。

Web 界面修改：登录 Web 界面进入系统设置，直接改配置并保存，系统会提示“配置保存成功，请重启程序生效”，重启后新配置生效，适合不熟悉 JSON 的用户。

手工编辑修改：适合需要改插件个性化配置、防火墙规则等进阶场景。

第一步，定位文件：按安装方式找到数据目录下的 openclaw.json，例如 Windows 包管理器安装路径为 `C:\Users\用户名\AppData\Roaming\npm\node_modules\openclaw\data\openclaw.json`。

第二步，备份文件：复制一份重命名为 config_backup.json，以防改错可快速恢复。

第三步，编辑文件：用 VS Code、Notepad++、vim 等编辑器打开，按需修改对应节点，严格遵守 JSON 语法，键名引号、逗号位置都要正确，不要删核心节点。保存后结束编辑。

第四步，重启生效：关闭当前 OpenClaw，重新启动。源码安装执行 `pnpm start`，包管理器执行 `openclaw start`，PM2 守护执行 `pm2 restart openclaw`，重启后新配置才会起作用。
