## 工具配置与适用场景速览

3. 高风险工具的额外安全控制

OpenClaw 中部分工具风险极高，额外提供了分层管控机制。

exec 是系统里最强也最危险的组件，针对它设置了三层策略。
tools.exec.security 控制命令执行策略，deny 模式彻底禁止 Shell，适合极致安全场景；allowlist 模式仅放行 tools.exec.safeBins 白名单内的命令，在安全与便利间折中；full 模式允许任意命令，灵活性最高但风险最大，仅限完全可控的个人环境。
tools.exec.ask 控制执行前的确认，off 直接执行适合高度自动化；on-miss 仅在命令不在白名单时询问；always 每次执行都须人工确认，提供最大人工监督。
tools.exec.host 决定执行位置，sandbox 为默认隔离容器；gateway 在 Gateway 宿主机直接运行，权限极高风险大；node 可投递到指定的远程节点设备。

gateway 工具能调用 config.apply、config.patch、update.run 等方法，实现对 OpenClaw 的持久化配置修改，权限极高。在可能接收不可信内容的 Agent 中应当明确禁止。

cron 工具可在对话结束后创建持续运行的定时任务。一次成功的提示词注入就可能留下长期执行的恶意任务，因此在处理不可信内容时也应禁止 cron。

4. 公共聊天平台 DM 访问策略

接入 Telegram、Discord 等公共平台时，OpenClaw 提供 4 种 DM 访问策略，见表 4-7。
策略值 说明
配对（默认） pairing 未知发件人收到配对码，经批准后才能与 Agent 交互
白名单 allowlist 仅白名单内的发件人可发消息
开放 open 任何人可发消息，需显式配置到白名单
禁用 disabled 完全忽略所有 DM

pairing 是最安全的默认做法。未知用户发起消息后，系统会发送配对码并在 CLI 展示配对请求，只有管理员手动批准后对话才会被建立。

5. 安全加固基线配置

官方给出了一套 60 秒安全加固基线，作为新部署的最小权限起点。示例如下：

{
  "gateway": {
    "mode": "local",
    "bind": "loopback",
    "auth": {
      "mode": "token",
      "token": "replace-with-long-random-token"
    }
  },
  "session": {
    "dmScope": "per-channel-peer"
  },
  "tools": {
    "profile": "messaging",
    "deny": [
      "group:automation",
      "group:runtime",
      "group:fs",
      "sessions_spawn",
      "sessions_send"
    ],
    "fs": { "workspaceOnly": true },
    "exec": { "security": "deny", "ask": "always" },
    "elevated": { "enabled": false }
  },
  "channels": {
    "whatsapp": {
      "dmPolicy": "pairing",
      "groups": {
        "*": { "requireMention": true }
      }
    }
  }
}

该最小权限实现了：
Gateway 仅监听本地回环并强制令牌认证，构成网络边界；
每个渠道与联系人组合拥有独立 DM 会话，从源头避免上下文泄露；
工具集收敛为消息类，其它自动化、运行时、文件系统能力全部禁用；
Shell 执行被完全禁止，消除最高风险向量；
WhatsApp DM 需配对认证，群组消息需 @ 明确提及才触发，防止误触。

4.3.4 安全审计与应急响应

OpenClaw 内置自动化审计与标准化的应急流程，帮助快速发现风险并降低损失。

1. 内置安全审计命令

系统提供统一审计入口，可自动扫描常见配置问题。
入站访问：检查 DM 策略、群组策略与白名单是否合理；
工具爆炸半径：评估权限提升是否会让提示词注入演变为 Shell、文件系统或网络操作；
网络暴露：核查 Gateway 绑定地址、认证配置、Tailscale Serve/Funnel 使用及令牌强度；
浏览器控制暴露：审查远程节点配置、中继端口开放与远程 CDP 访问控制；
本地磁盘卫生：检查关键文件权限、符号链接指向、配置文件包含关系与同步文件夹路径；
插件：确保所有扩展在显式白名单内，未经审查的插件可能引入未知风险；
策略漂移：定期比对配置是否被意外变更，并排查常见配置陷阱。

常用命令：
# 基础审计
openclaw security audit
# 深度审计，含实时 Gateway 探测
openclaw security audit --deep
# 自动修复可修复问题如文件权限
openclaw security audit --fix
# 输出 JSON 方便接入 CI/CD
openclaw security audit --json

2. 安全事件应急响应步骤

怀疑遭受攻击或数据泄露时按以下流程处理：
遏制：立即执行 openclaw stop 停止 Gateway，断开所有外部渠道，防止扩散。
轮换：若凭证可能泄露，立刻轮换所有 API Key 与认证令牌，使旧凭证失效。
审计：检查 ~/.openclaw/agents/*/sessions/*.jsonl 中的完整历史，还原事件期间的操作并评估损失。
收集：完整保存相关日志与配置文件，为后续分析、复盘与合规提供证据。

4.4 定时任务（Cron）与自动化工作流

OpenClaw 不仅被动响应请求，通过内置 Cron 还能主动执行周期任务，实现端到端自动化，是从聊天工具升级为个人自动化平台的核心。

4.4.1 Cron 任务的工作原理

Cron 本质是预定的 Agent Loop 触发器，按时间点以特定初始消息启动一次会话。其 sessionKey 格式为 cron:<jobId>，历史与普通 DM 完全隔离。

在 openclaw.json 中静态定义的任务会在 Gateway 启动时自动注册，例如每日晨报与每周代码审查。动态创建则通过对话中的 cron 工具实现，任务会持久化，重启后依然有效。

Cron 采用标准 5 段表达式：分钟 0~59、小时 0~23、日 1~31、月 1~12、星期 0~6，格式 * * * * *。系统完整支持时区，为每个任务单独指定 Asia/Shanghai、America/New_York 等，确保按本地时间触发。

表 4-8 常用的 Cron 表达式
表达式 含义
0 8 * * * 每天早上 8 点
0 8 * * 1-5 工作日早上 8 点
0 10 * * 1 每周一早上 10 点
0 0 1 * * 每月 1 日午夜
*/30 * * * * 每 30 分钟
0 9,12,18 * * * 每天 9 点、12 点和 18 点

4.4.2 构建实用的自动化工作流

Cron 的价值在于与工具调用结合形成闭环。

1. 每日晨报自动化
工作日 7 点触发，执行 web_search 获取科技新闻、抓取 GitHub Trending、读取 MEMORY.md 项目记录，整理成 Markdown 晨报，通过 message 工具推送到指定 WhatsApp，并存档到 memory/morning-brief-YYYYMMDD.md。

2. 代码仓库健康检查
每周一 9 点进入 ~/projects/my-app，查看最近 7 天提交、运行 npm audit、npx depcheck、统计 TODO/FIXME/HACK 数量，生成健康报告。若发现 Critical 漏洞则通过 Slack 紧急通知 #security 频道。

3. 智能备份与归档
每周日 2 点压缩 workspace-main 与本周对话记录到 /backup，校验大小与完整性，清理 30 天前的旧备份，汇总写入 memory/backup-log.md，失败时通过 WhatsApp 告警。

4. 个人知识库自动化整理
每周定时从日志与会话中抽取知识点、问题方案与待办，形成结构化知识沉淀，实现持续积累。
