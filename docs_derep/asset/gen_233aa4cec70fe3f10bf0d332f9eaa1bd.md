Manus 本质上是一个以任务解析和结构化处理为核心的多智能体协作框架。起初，智能体通过需求分析模块来读懂用户意图，借助大模型抓取核心目标，对表述模糊的需求主动追问澄清，随后把复杂请求拆解成可直接落地的子任务。

在执行层面，Manus 整合了一整套工具链，覆盖浏览器交互、文件系统操作、Shell 命令、通信接口以及部署能力，能够处理多模态任务，兼容 JavaScript、Python 在内的十余种编程语言和主流开发框架。

执行引擎采用动态规划机制，分步推进时持续监测进度，一旦出现阻碍就触发自适应策略，自动生成备选方案。

质量控制部分构建了结果校验、代码测试与反馈学习的闭环，保证输出可信，同时严格遵守伦理边界，包括隐私保护、系统安全限制和道德准则。

整体上 Manus 能通过持续学习提升处理能力，但受上下文窗口长度和沙盒隔离原则制约，无法触达外部系统或执行越权操作。

### 7.1.3　开源方案介绍

Manus 的表现带动了开源社区对通用智能体方向的跟进热情。闭源收费、邀请码管控等模式让开发者更倾向于可自主掌控、成本可控且技术透明的替代方案，于是 OpenManus 等项目相继出现。

技术路径上，开源实现与 Manus 保持高度一致，均采用多智能体协作架构。核心思路是把用户输入的复杂自然语言指令，例如“分析数据并生成报告”，自动拆解为逻辑清晰的子任务，分发给不同专长的智能体协同完成，比如负责搜索、负责写代码、负责整理文件。各家都重视工具集成，通过接入网络搜索、代码解释器、文件系统等外部能力，扩展智能体在数字环境中的实际行动力。

开源与闭源的差别，免费只是表象，真正关键在于技术透明与可演进。OpenManus 公开致谢了 Computer Use、Browser Use 等项目，直观呈现了其技术来源和构建思路。透明的架构让开发者可以审阅、定制和优化，从而加速整个 AI 智能体领域的技术迭代和生态繁荣。

OpenManus 主要由智能体模块、流程模块、工具模块和提示词模块构成。

（1） **智能体模块** 。定义基础智能体接口和主要实现，涵盖任务规划、ReAct 模式以及工具调用处理。
（2） **流程模块** 。定义 Manus 风格的工作流基类，实现智能体的获取、添加与状态管理，状态包含未开始、进行中、已完成、被阻塞，并提供 FlowFactory 类用于为多个智能体创建不同类型的工作流。
（3） **工具模块** 。收纳各类工具脚本。OpenManus 同样采用 browser-use 库操控浏览器，支持的操作类型包括导航如访问网址、返回、刷新、网页搜索，元素互动、内容互动如提取网页内容，以及标签页管理等。
（4） **提示词模块** 。内置 Manus、Planning、Swe、Toolcall 等智能体的提示词，分为系统提示词和指导下一步行动的提示词 NEXT_STEP_PROMPT。

从 Manus 到开源替代方案的演进表明，多智能体任务分解与工具调用已成为通用 AI 智能体的共识。公开代码与协作开发降低了门槛，让智能体从封闭产品转向可审计、可修改的开放基础设施，为后续创新奠定基础。

### 7.1.4　商业对手介绍

Manus 的走红让用户真切感受到通用 AI 智能体与传统对话大模型的差异：前者能自主操作电脑、驾驭浏览器、编写代码。Manus 基本描绘了这一品类产品的形态和功能边界，也点燃了赛道热情。

#### 1．扣子空间

2025 年 4 月 18 日，字节跳动旗下首款面向消费者的通用 AI 智能体“扣子空间”开启内测。定位兼具通用实习生的广度和领域专家的深度，具备无限拓展能力。产品可自动解析需求、拆解子任务、调用浏览器、代码编辑器等工具，并以 PPT、网页、文档等多种形式交付成果，核心在于集成外部工具与服务处理复杂任务。

发布前，字节跳动于 2025 年 3 月开源了智能体产品 TARS。TARS 界面与 Manus 相似，左侧对话窗口，右侧实时展示智能体在虚拟机中的操作。TARS 支持 MCP 协议，具备图形界面交互能力。

TARS 的视觉交互基于自研原生 GUI 智能体模型 UI-TARS。该模型采用视觉-语言架构，通过强化视觉感知、推理机制和统一动作建模，识别 GUI 元素并执行点击、输入等操作。扣子空间的浏览器调用和界面操作即应用了 UI-TARS。

从 Manus 到 TARS 再到扣子空间，竞争焦点由“能否操作”转向“如何高效开放地操作”。开源 UI-TARS 并支持 MCP 协议，字节跳动既推出消费级产品，也在构建以智能体为核心、工具可扩展的开放生态。

#### 2．AutoGLM

AutoGLM 是智谱 AI 团队开发的移动端通用 AI 智能体，创新在于将大模型的规划决策能力与机器人流程自动化技术深度融合，使其像人一样直接操控手机应用界面，完成真实日常任务。

不同于依赖 API 的方案，AutoGLM 基于 Android 系统的无障碍服务，通过“观察”屏幕内容解析 GUI 并“模拟”点击、滑动等操作实现自动化。兼容性广，但对界面稳定性有依赖。

作为行动型智能体，其特点包括：

（1）端到端自主执行：接收到“点外卖”或“预订机票”等自然语言指令后，自主完成打开 App、搜索浏览、比价到下单的完整链路，最终支付需人工确认。
（2）多模态环境感知与决策：结合视觉识别与 ReAct 等推理框架，实时分析屏幕元素如按钮位置，动态规划下一步路径。
（3）持续学习优化：通过在线强化学习，任务成功率随使用数据反馈不断提升。

应用覆盖生活服务自动化如外卖订购与旅行预订、信息处理自动化如新闻整理与论文摘要、设备管理自动化如手机清理与跨应用数据迁移。

生态还延伸出 AutoGLM-Web 专注浏览器自动化，以及 GLM-PC 专注桌面办公自动化，共同形成移动、网页、桌面全覆盖的智能体解决方案。

#### 3．Genspark

Genspark 超级智能体由 MainFunc 公司推出，用于执行复杂数字任务与现实世界任务。定位不是对话接口，而是具备自主规划与执行能力的数字执行者，可调用多样工具替代或辅助用户完成从信息处理到实际联络的全流程。

架构采用混合智能体模式，不依赖单一大模型，而是动态整合 DeepSeek 等多种专用模型，形成内部专家委员会，根据任务类型自动分派给最合适的模型组合，在速度与准确性间取得平衡。

工具生态包括深度信息获取，通过增强搜索与网页抓取主动整合信息；现实世界交互，具备自动电话呼叫等能力，可代为酒店预订、餐厅订座；内容与创意生成，支持图像、视频、专业文档与演示文稿；数据分析，可直接处理复杂数据集并给出洞察。

此外，Genspark 还能按指令生成功能性数字成果，如个人介绍页、可交互网页应用、简易 HTML 游戏，体现思考即构建的能力。整体路径为多模型协同决策加广域工具调用，推动 AI 从顾问角色走向主动执行并交付成果的代理角色。

#### 4．ChatGPT Agent

ChatGPT Agent 由 OpenAI 于 2025 年 7 月发布，由原 Operator 团队与 Deep Research 团队合并组建。

其突破不在于新增工具，而在于技术路径的根本改变：不把浏览器操作、研究分析、代码执行等能力工程化拼接在模型之外，而是通过端到端统一训练，将智能体技能内化为单一模型的核心能力，更像一个能自主规划并使用多种工具完成复杂任务的数字大脑。

模型可集成文本与图形浏览器、终端命令行及图像生成器等关键工具，展现出实用智能体特性。

（1）自主任务分解与执行：用户用自然语言下达“分析我的日程与近期新闻，为下周客户会议准备简报”等复杂指令，Agent 会自主规划步骤，依次检索、筛选、分析并生成可直接使用的 PPT 或文档。
（2）交互式协作与可控性：支持多轮对话，会主动询问细节并确认意图。用户可随时打断、修改要求或完全接管控制，实现人机协同的灵活工作。
（3）安全与权限设计：可能产生实际影响的操作如购物、发邮件、处理个人信息默认需用户明确许可。模型内置严格防护，自动拒绝高风险请求如金融转账、法律建议，对生物化学等领域风险采取最高级别安全处理。

ChatGPT Agent 的发布标志着 AI 智能体从问答式聊天机器人向使用工具完成任务的主动数字助手演进，统一模型架构与安全优先原则为构建可靠、可协作的通用智能体提供技术基础。

### 7.2　AI 自动化工具

通用 AI 智能体的能力背后，依赖浏览器自动化、桌面自动化和移动端自动化等工具。它们让智能体覆盖 Web、桌面与移动端。

### 7.2.1　Browser Use

Browser Use 是为 AI 智能体定制的浏览器自动化工具，为缺乏物理交互能力的智能体提供标准化接口，使其能理解网页内容并执行精细化操作，与真实 Web 应用交互。

不同于传统脚本化自动化，Browser Use 直接服务于智能体的决策流程。智能体可接收自然语言指令如“查询今日美股涨幅前十的股票”，并将其分解为导航、点击、滚动、表单填写、数据提取等精准浏览器动作，自主完成信息收集、任务执行与状态验证。

技术架构围绕赋能智能体设计：

（1）多模型驱动内核：可接入 GPT-4、Claude、DeepSeek 等大模型，由模型负责理解指令、解析页面结构并做决策，适配不同复杂度与成本需求。
（2）智能化环境感知：通过 DOM 与 XPath 识别元素，结合视觉与语义理解精准定位交互目标，确保在动态网页中操作稳健。
（3）复杂任务流管理：支持多标签页管理，可在多任务间切换协作；跨平台特性保证部署环境一致。
（4）可扩展行动体系：开发者可添加自定义工具如保存数据到数据库，将浏览器操作与企业内部流程无缝衔接。

关键应用场景包括自主信息代理，定期抓取竞品价格、金融数据等结构化信息；交互验证与测试，模拟真实用户行为执行复杂 UI 流程并动态校验；数字化工作流执行，登录在线办公系统完成文档撰写、报表生成与导出等任务。

Browser Use 在自然语言指令与低层浏览器操作之间建立桥梁，增强智能体的环境感知与行动执行力。

### 7.2.2　Computer Use

Computer Use 是 Anthropic 于 2024 年 11 月提出的技术范式，使 AI 能像人类一样操作计算机系统，包括点击图标、输入文本、管理文件等。

核心特点包括：

（1） **多模态感知** ：通过视觉语言模型解析屏幕截图，结合光学字符识别定位可交互元素坐标。
（2） **拟人化操作链** ：遵循感知→决策→执行循环，例如截图分析→光标移动→点击→验证结果。
（3） **系统级输入模拟** ：直接调用操作系统 API 执行键盘鼠标操作，支持跨应用操作如 Excel 处理、PPT 制作。

典型场景为跨软件任务，如股票分析到数据整理的自动调用；端到端测试，模拟用户行为进行全流程测试；隐私限制场景，通过界面操作间接完成任务以避免直接访问 API。

该技术可将自然语言精确转换为复杂系统操作指令，未来用户无需学习繁琐软件逻辑，用自然语言即可完成计算机上的常见工作。

OmniParser 是另一种实现。微软研究院于 2025 年 2 月发布 OmniParser V2，可实时解析屏幕界面元素并转化为 JSON 等结构化数据，使 AI 能理解指令并执行点击、输入等操作，无需针对特定界面微调，显著提升效率与精准度。

主要特点为精准解析 UI 元素，从像素级图像中提取可交互区域边界框、功能语义与文本内容，不依赖 HTML 或视图层级；多模态兼容，可与 DeepSeek-R1、Qwen 2.5VL 等主流大模型无缝集成，提升代理任务执行精度。

### 7.2.3　DroidRun

DroidRun 是一个强大的工具，可用自然语言命令控制 Android 设备，具备视觉理解与 UI 结构提取能力，实现流畅交互。

主要特点包括：

（1） **视觉+UI 解析** ：结合视觉模型识别屏幕内容与 UI 结构提取解析控件树，实现精准交互。
（2） **智能自愈机制** ：能检测网络中断、界面变化等错误并自动调整操作路径。
（3） **支持 Android Portal APK** ：类似智能体通行证的 Android 应用，部署后 AI 可操控整个系统。
（4） **多系统管理** ：支持多台设备多实例，支持复杂工作流与并行处理。
（5） **元素追踪** ：可精准提取点击元素，复现大模型行为，保证自动化一致性。
（6） **凭证管理器** ：支持登录信息与双因素身份验证绑定，个性化用户体验。

DroidRun 标志着大模型与移动操作系统的闭环被打通，智能体终于能看懂手机、动得了 App，像人一样打开应用、点击按钮、滚动页面、处理表单，甚至完成网页交互与账号登录。

这一步让智能体从只能看网页走向全端自动化，实现智能化移动交互。
