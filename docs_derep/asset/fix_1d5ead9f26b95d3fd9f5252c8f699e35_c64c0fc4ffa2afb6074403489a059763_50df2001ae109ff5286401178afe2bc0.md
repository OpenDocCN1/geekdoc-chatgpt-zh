8.4.3 Compose 一键编排

把 OpenClaw 搬上服务器，先把官方镜像取下来。官方镜像全名是 ghcr.io/openclaw/openclaw:latest，latest 标签指向最新稳定版。在终端里执行 docker pull ghcr.io/openclaw/openclaw:latest，Docker 引擎就会从 GitHub 仓库把镜像拉到本地主机。

容器跑起来之前要先搞清楚数据卷和目录映射的关系。容器本身是无状态的，停止删除后容器里的配置文件、运行日志等都会丢失。若要让 openclaw.json、会话记录、后续安装的技能插件等核心资料得以保留，就必须把宿主机上的物理目录挂载进容器。按官方说明，OpenClaw 在容器内部的数据统一放在 /root/.openclaw。

用一条冗长的 docker run 来指定端口、卷、环境变量容易出错也难维护，生产上更推荐 Docker Compose，用一份结构清晰的 YAML 来统一描述。先在服务器上建一个专门存放 OpenClaw 数据的目录，并在目录下新建 docker-compose.yml。

文件里定义一个服务 openclaw-gateway，使用官方镜像，并加上 restart: unless-stopped 保证异常或主机重启后自动拉起。端口把容器 3000 映射到宿主机 3000，方便外部访问。数据卷最关键，把宿主机当前目录下的 ./data 映射到容器里的 /root/.openclaw，完成持久化。

还可以通过 environment 注入环境变量，例如把时区设为 Asia/Shenzhen，或把大模型的 API Key 以环境变量方式传入，避免明文写进配置文件。最后用 command: ["gateway"] 指定启动 Gateway 服务。

OpenClaw 官网提供的标准 Docker Compose 配置如下：

services:

  openclaw-gateway:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN:-}
      OPENCLAW_ALLOW_INSECURE_PRIVATE_WS: ${OPENCLAW_ALLOW_INSECURE_PRIVATE_WS:-}
      CLAUDE_AI_SESSION_KEY: ${CLAUDE_AI_SESSION_KEY:-}
      CLAUDE_WEB_SESSION_KEY: ${CLAUDE_WEB_SESSION_KEY:-}
      CLAUDE_WEB_COOKIE: ${CLAUDE_WEB_COOKIE:-}
      TZ: ${OPENCLAW_TZ:-UTC}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    ports:
      - "${OPENCLAW_GATEWAY_PORT:-18789}:18789"
      - "${OPENCLAW_BRIDGE_PORT:-18790}:18790"
    init: true
    restart: unless-stopped
    command:
      [
        "node",
        "dist/index.js",
        "gateway",
        "--bind",
        "${OPENCLAW_GATEWAY_BIND:-lan}",
        "--port",
        "18789",
      ]
    healthcheck:
      test:
        [
          "CMD",
          "node",
          "-e",
          "fetch('http://127.0.0.1:18789/healthz').then((r)=>process.exit (r.ok?0:1)).catch(()=>process.exit(1))",
        ]
      interval: 30s
      timeout: 5s
      retries: 5
      start_period: 20s
  openclaw-cli:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    network_mode: "service:openclaw-gateway"
    cap_drop:
      - NET_RAW
      - NET_ADMIN
    security_opt:
      - no-new-privileges:true
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN:-}
      OPENCLAW_ALLOW_INSECURE_PRIVATE_WS: ${OPENCLAW_ALLOW_INSECURE_PRIVATE_WS:-}
      BROWSER: echo
      CLAUDE_AI_SESSION_KEY: ${CLAUDE_AI_SESSION_KEY:-}
      CLAUDE_WEB_SESSION_KEY: ${CLAUDE_WEB_SESSION_KEY:-}
      CLAUDE_WEB_COOKIE: ${CLAUDE_WEB_COOKIE:-}
      TZ: ${OPENCLAW_TZ:-UTC}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    stdin_open: true
    tty: true
    init: true
    entrypoint: ["node", "dist/index.js"]
    depends_on:
      - openclaw-gateway

8.4.4 启动与运维实操

配置文件准备好后，启动变得很简单。在 docker-compose.yml 所在目录执行 docker-compose up -d，Compose 会以守护模式在后台创建并运行容器。

运行期间排查问题可用 docker-compose logs -f 实时查看标准输出。若要做初始化配置如 openclaw configure，或安装新插件，不能直接在宿主机执行，需要先用 docker exec -it openclaw-gateway /bin/bash 进入正在运行的容器，再在容器内部执行相应命令。

版本升级很平滑。官方发布修复或新特性后，在同目录先执行 docker-compose pull 拉取最新镜像，再执行 docker-compose up -d 用新镜像重建并启动。容器会被无缝替换，而放在 ./data 的配置文件和历史记录因数据卷挂载会完整保留并自动接入新版本。

第九章 让 AI 嵌入工作群

上章已把 OpenClaw 部署到云上，具备随时待命的能力。但优秀的 AI Agent 不应只停留在服务器终端，它要融入日常工作，与常用沟通工具无缝对接。OpenClaw 的 Channel 架构可接入主流聊天平台，本章聚焦国内三大企业协同工具：飞书、企业微信和钉钉。

接入后，成员无需切换网页或终端，直接在熟悉的聊天窗口里像与同事对话一样下指令、收报告，大幅降低使用门槛，提升协作效率。

9.1 飞书对接全攻略

飞书以流畅体验和强大的开放平台能力受到众多创新团队青睐。OpenClaw 对飞书提供原生深度支持，最大亮点是利用飞书开放平台的 WebSocket 长连接事件订阅。不必像传统 Webhook 那样在服务器上暴露公网 URL 接收消息，避免了反向代理和 SSL 证书的配置，也从源头提升了安全性。

9.1.1 新建应用与机器人

让 OpenClaw 接入飞书，首先要在飞书开放平台创建一个企业自建应用，作为在飞书生态中的合法身份。

用有权限的企业账号登录飞书开放平台，海外版进入对应开发者后台。进入开发者后台后点击“创建企业自建应用”，为助手取一个易识别的名称如“OpenClaw 智能助手”，填写描述并上传清晰图标。

创建成功后进入应用详情页，左侧“凭证与基础信息”里有两项关键参数：App ID 通常以 cli_ 开头；App Secret 即应用密钥。这相当于机器人的账号密码，用于 OpenClaw 向飞书服务器校验身份，请妥善保存。

9.1.2 授权与事件订阅

仅创建应用不足以收发消息，还需申请 API 权限。在应用详情页左侧依次选择“开发配置”→“权限管理”，选择“应用身份权限”。可通过批量导入导出功能粘贴以下 JSON 权限配置：

{
  "scopes": {
    "tenant": [
      "im:chat.members:bot_access",
      "im:message",
      "im:message.group_at_msg:readonly",
      "im:message.p2p_msg:readonly",
      "im:message:readonly",
      "im:message:send_as_bot",
      "im:resource"
    ],
    "user": [
      "contact:contact.base:readonly"
    ]
  }
}

其中 user 节点下的 contact:contact.base:readonly 最关键，允许机器人只读访问企业通讯录基础信息，用于身份校验、上下文匹配和合规回复。若未开通，机器人因拿不到用户数据而交互失败。
