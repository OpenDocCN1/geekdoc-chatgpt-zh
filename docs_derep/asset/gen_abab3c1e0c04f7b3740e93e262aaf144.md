目前在多Agent协作领域里，主流做法大致可收敛为四种范式：串行链式、并行扇出、层级管控和网状协商。串行链式是多个Agent按事先定好的顺序逐个跑，前一个的输出直接喂给下一个，适合流程清晰、步骤固定的场景。并行扇出则是把同一任务拆到不同维度同时处理，最后由一个汇总Agent整合结果，适合可拆分的高复杂度任务。层级管控由 Manager Agent 负责拆分和调度，Worker Agent 去执行并回传结果，适合动态变化需要灵活调度的业务。网状协商则让Agent之间自由对话，多轮博弈后达成一致，适合需要多方角力的决策问题。

图5-2把这四种协作方式的形态和适用边界可视化。串行链式在左上呈现线性链路，Agent A→B→C依次推进，优点是逻辑通透、调试省心，缺点是延迟会逐级累积，典型用在文档处理流水线等确定性流程。并行扇出在右上先由分发Agent拆任务，多路Agent同步计算再由聚合Agent合并，速度快但结果合并逻辑较重，适合多视角分析这类可并行任务。层级管控在左下以Manager集中指挥多个Worker，虚线表示回传路径，灵活且能均衡负载，但Manager容易成为瓶颈。网状协商在右下允许全网互通，通过多轮沟通达成共识，决策质量高但通信开销大，多用于复杂的多方决策。

### 5.1.3 明确Agent能力的边界线

在LLM多Agent体系里，清晰界定能力边界是避免职责打架的关键。边界不仅要说能做什么，还要说不能做什么，以及超出时如何处置。边界最好写入System Prompt，让模型准确自知。

一条完整的能力边界应包含五要素。第一是角色定位，明确在协同网络中扮演的身份与核心使命。第二是能力范围，列出可处理的任务类型、支持的输入形式和可调用工具。第三是边界约束，划定不接手的任务类型及越界时的标准回应。第四是协作接口，定义与其他Agent交互的消息格式、协议和交接条件。第五是决策权限，说明可自主决定的范围与需要上报或转交的情形。

- 兜底机制：设置默认路由Agent承接无法归类的请求

### 5.1.4 协同系统的模块化与可扩展性设计

生产级多Agent系统必须模块化、可扩展，才能跟上业务演进。核心思想是把系统拆成职责独立、接口统一的模块，单个模块可独立升级或替换而不影响整体。

典型模块化体系包含六层：接入层负责接收各类外部请求并响应；路由层依据请求特征分发任务；Agent层托管所有业务Agent，通过消息总线异步通信；工具层提供数据库、外部服务、RAG、代码执行等能力；存储层负责上下文缓存、向量库、对话历史和审计日志；监控层覆盖性能、日志、链路追踪和Token统计。

模块化设计遵循四项原则。接口标准化保证模块间交互一致可预期。可插拔设计让Agent和工具独立部署替换。配置驱动通过配置文件管理路由与Agent，减少重新编译。水平扩展支持Agent实例动态扩缩容，按负载自动调节容量。图5-3展示了一个典型的模块化Agent系统架构，从上到下分为六个层次。接入层是入口，处理API、Web、MQ等渠道请求，提供鉴权、限流、熔断和协议转换。路由层带智能意图识别，将任务分发给对应Agent。Agent层是核心，可接入Claude、GPT-4、Qwen、DeepSeek等不同模型，Agent间通过消息总线异步通信。工具层提供数据API、服务调用、检索与代码执行等能力。存储层持久化上下文、向量、历史和审计日志。监控层贯穿全链路，提供可观测性。

### 5.2.1 System Prompt的结构化设计方法

System Prompt决定Agent的行为、人格和能力边界，设计质量直接影响表现。在多Agent场景下，结构化设计尤为重要，既要定义个体职责，也要规范协作方式和信息交换格式。

结构化System Prompt遵循“角色-能力-约束-协作”四层架构。角色层定义身份、背景和专业领域，建立人格画像。能力层明确任务类型和可调用工具。约束层规定行为边界、禁止事项和异常处理。协作层定义与其他Agent的协议、报文格式和状态转换。四层设计兼顾完整性与可维护性。

图5-4展示了System Prompt的四层结构化模板。第一层角色定义包含身份声明、人格特征、专业背景和服务对象，用于建立基本画像。第二层能力声明用虚线框标注需按业务定制，涵盖任务范围、工具清单、知识边界和输出格式。第三层约束规则定义禁止事项、安全边界、异常处理和决策权限，确保行为可控。第四层协作接口规定消息格式、转交条件、状态同步和协作对象，支撑多Agent协同。底部输出规范统一了标准响应、转交响应和错误响应的JSON格式，保证系统间通信一致。
