流程编排器承担着应用层与软件栈之间的入口角色，负责对推理任务的执行流程进行整体管控。它把一次离线模型的全部工作拆解为多个阶段性引擎，并通过调用AI模型管家的加载接口完成设备端的初始化以及离线模型的挂载。随后离线模型执行器启动，对模型文件实施反序列化与解码，得到可执行形态；同时借助执行环境的存储接口申请内存，将模型中各算子的权重数据搬入内存；另向运行管理器申请执行句柄、执行流与事件等运行资源，并完成资源与模型的绑定映射。一个执行句柄对应一次神经网络计算图的完整运行，一个句柄下可容纳多个执行流；每个执行流中承载AI Core或AI CPU的计算任务，单个任务由对应核上的核函数执行，而事件则承担不同执行流之间的同步职能。

完成一次模型计算需要遍历离线模型里的全部算子，并在任务信息刷新后，离线模型执行器调用运行管理器接口把任务下发至任务调度器，最后由执行器向AI模型管家返回加载结束的通知，流程编排器再设置输出结果的回调以获取执行完成的返回。至此离线执行器结束加载阶段，下一步即可进入推理计算。该加载过程实质上是把模型与昇腾AI处理器做适配，把硬件资源与离线模型算子进行统筹规划，为后续推理提供预加速基础。

### 4. 离线模型推理执行
离线模型装载完毕后即可发挥推理能力。离线模型本质仍是神经网络，推理时需要真正执行如图像识别等功能。模型生成与加载阶段并未用到具体待处理数据，只是借助软件栈对算子与计算流程进行构造、编排、优化、封装及硬件适配，而真实的推理执行才会读入具体输入数据驱动计算并产出结果。

离线模型推理流程如图4-21所示。当应用产生数据处理需求并准备好待处理数据后，流程编排器调用AI模型管家的处理接口把数据送入离线模型执行器。执行器随后调用运行管理器的执行流接口rtModelExecute，将流内的多个推理任务下发给任务调度器。调度器把任务拆分为任务块分发到AI Core或AI CPU执行，执行完毕后把块结果回传。调度器遍历执行流中的任务，循环投放任务块并收回结果直至全部完成，并将任务结果写入运行管理器的内存。多执行流并行计算时，通过运行管理器的事件记录与事件等待接口实现算子间的同步，保证有序推进。单个执行流内所有算子调用结束后，执行器通过rtStreamSynchronize接口同步等待各流完成。所有相关执行流结束后合并结果生成模型最终输出，执行器通知AI模型管家执行流已完成。AI模型管家最后调用预设的输出回调，把推理结果返回给流程编排器，再由编排器反馈给应用。

## 4.2.7 神经网络软件流实战案例
神经网络软件流的整体工作包括在深度学习框架下定义网络结构、生成模型，并交由软件流在昇腾AI处理器上实现功能。以Inception v3分类网络为例进行说明。

Inception v3是一个用于图像分类的卷积神经网络。用户可在神经网络软件流提供的Caffe框架下定义网络结构并完成训练，通过prototxt保存结构，通过caffemodel保存权重。网络由卷积层、池化层、全连接层等交替构成，输入数据逐层处理后向后传递。

得到原始模型后需进行离线转换，可借助软件流中的离线模型生成器与张量加速引擎完成转换。命令行调用生成器运行程序后，生成器依次完成模型解析、编译与序列化，产出最终离线模型；若需量化，也可在生成阶段完成参数量化。

转换完成后可得到离线模型，并以有向无环图呈现算子执行顺序与数据依赖。可视化工具显示的Inception v3离线模型结构如图4-22所示。Caffe模型转换时会进行算子融合，输入数据形式也会变化。原始Caffe模型中步长、卷积核等常用默认值，转换后的离线模型则用常数Const节点表示输入，这些常数节点可接收可变的步长、卷积核等参数传入模型，提升灵活性。

为让Inception v3分类功能在昇腾AI处理器上运行，需通过流程编排器开发计算引擎，创建计算引擎流程图并执行以实现功能。需要定义数据引擎、预处理引擎、模型推理引擎、后处理引擎四个计算引擎，并完成引擎间串联与节点属性配置文件定义。

假设在开发者板上实现，流程编排器依据配置生成计算引擎流程图，再调用AI模型管家初始化接口加载Inception v3离线模型。

加载阶段，应用经流程编排器通过AI模型管家发起加载，离线模型执行器对Inception v3离线模型进行反序列化。随后调用运行管理器接口完成权重复制到内存，并为执行句柄、执行流、事件等申请硬件资源并绑定。资源配置完成后，将模型算子与执行流映射，每个执行流负责一组算子构成的计算子图，并通过事件分配管理多流同步。执行器还调用运行管理器接口把执行流中的任务与AI Core或AI CPU上的核函数建立地址对应，刷新任务执行信息，每个核函数在推理过程中承担特定任务。最后执行器调用运行管理器任务接口把模型任务分发给执行硬件。至此Inception v3功能被拆分为任务并与硬件资源匹配，离线模型加载完成，计算引擎流程图创建完毕。

创建完成后执行流程图。数据引擎接收待分类图片，流程编排器启动预处理引擎，引擎通过DVPP接口调用数字视觉预处理模块完成编解码、缩放等预处理。处理后的数据经流程编排器进入模型推理引擎开始推理。

推理过程中，模型推理引擎调用AI模型管家接口启动推理。预处理数据由AI模型管家传入离线模型执行器，执行器调用运行管理器接口把加载时配置好的任务与输入数据下发给任务调度器。调度器调度对应AI Core或AI CPU执行，依次完成各执行流中的任务，在事件同步控制下整合不同执行流输出生成最终结果。AI模型管家把分类结果返回给流程编排器，后者再传给后处理引擎，由后处理引擎通过回调展示分类结果。

输出结果后，需经流程编排器销毁Inception v3计算引擎流程图并释放计算资源。至此完成Inception v3在昇腾AI处理器上的完整功能实现。

以Inception v3为例，本节展示了从原始模型到离线模型生成、再到流程图创建与执行、包括加载与推理，最后到流程图销毁的完整链路，全部依托昇腾AI软件栈的模块协同完成，为各类神经网络在昇腾AI处理器上的实现提供软件支撑。

### 5.1.1 编程范式解析
深度学习开发风格与传统Python开发差异较大，涉及声明式编程、元编程、特定域语言等概念。对昇腾AI软件栈而言，输入通常是主流框架自定义的模型文件，了解其生成与保存内容对编程至关重要。

#### 1. 声明式编程与命令式编程
声明式编程又称符号式编程，与命令式编程相对。前者只需定义运算，运行期显式或隐式编译为底层内核调用，把计算图定义与编译运行分隔；后者每行代码执行时计算立即发生。

代码 5-1 所示的 Python 代码便采用了命令式编程风格，其用 NumPy 库实现了向量乘法和加法。当程序执行到任意一行时，便会立即执行相应的操作。以 c = a * b 为例，程序执行到这一行时，计算机便立即执行对应的向量乘法运算，并得到结果 c。此时，如果使用 print 函数便能够打印出具体的结果。
