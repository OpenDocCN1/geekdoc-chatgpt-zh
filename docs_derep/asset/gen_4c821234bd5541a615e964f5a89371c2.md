上世纪 90 年代，研究者就开始设想让多个 AI Agent 互相通信协同，并为此制定了早期的规范。FIPA 提出 Agent 通信语言 ACL 与一套交互协议，意图让不同团队开发的智能体交换消息；KQML 则是希望以统一的知识表达格式实现信息的共享。只不过那个年代智能体的能力很弱，联网的需求也不迫切，各家系统又千差万别，标准很难推开，最终这些尝试基本停留在实验室和少数行业试点里，没能形成大众可用的 Agent 互联网。

进入 Web 时代，HTTP 与 API 给了另一种思路。千禧年前后，随着互联网普及，Agent 开始借助标准的 Web API 调用外部服务，像聊天机器人就可以通过 HTTP 去查数据库或天气。做法很实用，却不是为 Agent 量身定制的。接入每一个新服务都要开发者手写适配：接 Google 日历要一套接口代码，连 SQL 数据库又是另一套，认证方式、数据格式各不相同。缺乏通用规范，导致 Agent 之间、Agent 与数据源之间都无法即插即用，必须靠人工“翻译”。

知识共享方面，早期系统偶尔用黑板模型，共用一块信息板让 Agent 在上面读写间接交流。但这要求所有 Agent 跑在同一个框架下，对开放的互联网环境并不友好。总的来看，在大语言模型出现以前，Agent 的互联基本靠定制接口或在统一平台内协作，扩展性和互操作性都受限。

### 1.2.3 平台爆发期
2021 年后尤其是 2023 年以后，随着 LLM 突破，Agent 技术迎来出圈式爆发。语言理解与推理能力的提升催生了一批面向多 Agent 协作和工具接入的平台，AI Agent 互联网的雏形开始成形。

##### 1. LangChain 开源框架
LangChain 自 2022 年起走红，是一个开源开发框架。它提供标准化的工具接口，开发者可把网络搜索、计算器等功能封装成工具供 LLM 调用，还内置记忆、对话控制等模块，让构建多步推理 Agent 更省力。

门槛因此大幅降低，超过 500 个预构建工具可以直接拿来用，促使大量应用让 Agent 连网查信息或调用数据库，跨工具的互操作性得到提升。不足在于，框架下的每个工具背后仍需定制实现，Agent 必须提前通过代码“认识”有哪些工具可用。

##### 2. AutoGPT 自主实验
2023 年初，基于 GPT-4 的 AutoGPT 作为开源实验项目出现，展示了自主 Agent 的潜力。用户给出高层目标后，Agent 会自行拆解任务、循环调用自身与工具去完成。能联网搜索、写代码、写文件，像一个不断自我迭代的数字员工。发布后在 GitHub 爆火，短时间内斩获数十万星。

它也暴露了局限：缺乏统一标准约束，功能靠脚本堆叠；容易陷入逻辑循环或跑偏，需要人盯。它最大的价值是把“自主 AI Agent”的概念带进大众视野，催生了后续众多框架与应用。

##### 3. OpenAI 插件系统
2023 年 OpenAI 为 ChatGPT 推出插件系统，可看作让 Agent 安全访问互联网服务的方案。插件用公开的 OpenAPI 规范描述自己的 API，经授权后 ChatGPT 就能调用第三方服务，例如旅行预订插件可以直接查询航班并下单。

插件把外部工具调用统一到了 OpenAPI Schema，并限定能力范围以保障安全，证明用统一格式描述服务就能让 Agent 理解并调用各种应用。缺点是封闭性强：必须通过 OpenAI 审核后才能接入，只服务于自家平台，且多数交互仍是一问一答的调用，缺少持续的双向会话。

##### 4. AgentVerse 去中心化平台
AgentVerse 由 Fetch.ai 等推出，是一个面向多 Agent 协作与可扩展部署的开源平台，提供灵活的 Python 框架，让开发者自定义 Agent 角色与交互逻辑。

其特点是强调扩展性，很容易增加新 Agent 或新工具，把多个智能体组成协同网络。例如在去中心化场景下，不同公司或个人 Agent 可通过该网络交易数据或服务。虽然主要面向技术开发者，缺少无代码界面，对普通用户不够友好，但它代表了未来 Agent 互联网去中心化的一种方向。

除此之外，微软的 HuggingGPT、斯坦福的 Generative Agent 等探索也在同步推进。不同能力的 Agent 通过统一中间层或协议连成网络，各司其职又协同工作。过去用户要手动在多个网站间跳转，现在 Agent 作为中介串联服务，初步体现出 Agent 互联网的价值。

### 1.3 AI Agent 互联网面临的挑战及其发展历程
当 Agent 从概念走向落地，打造可互联、可信赖、可规模化的 Agent 互联网成为战略高地。但进程仍处关键转型期，普及与落地受多重挑战制约，不仅影响多 Agent 系统的大规模协同，也动摇公众对智能体生态的信任。必须从架构、技术治理与合规层面综合应对，推动从“能用”到“可靠”的跃迁。

#### 1.3.1 AI Agent 互联网面临的挑战
技术虽快，但真正实现 Agent 互联网仍有三大核心瓶颈：标准缺失导致平台割裂形成信息孤岛；安全机制薄弱让自主 Agent 在执行时存在越权滥用风险；隐私保护压力上升，需要在数据处理中做到加密、最小化与可控。正因如此，建设不仅是技术升级，更是标准、治理与安全协同的系统工程。

##### 1. 标准化与互操作性挑战
目前 Agent 领域缺少类似 HTTP、TCP/IP 那样的统一基建。平台各行其是：LangChain 有自己的工具接口规范，OpenAI 插件系统是另一套规范，许多定制 Agent 直接调用私有 API。生态碎片化让跨平台协同困难，例如为 ChatGPT 开发的插件若要被 AutoGPT 这类自主 Agent 使用，就得重新封装适配。每接入新数据源或服务都要重复开发，类似互联网早期的诸侯割据，阻碍规模化。

业界出现两条路径。一是去中心化标准组织和开源协议的尝试，试图制定通用通信语言或接口规范。二是现有平台向标准化靠拢，例如 LangChain 团队推出对 MCP 的适配，让数百种工具可作为 MCP 组件被任何兼容的 Agent 调用。标准化趋势正在形成，但统一规范仍需生态共识与时间。

##### 2. 安全性挑战
赋予 Agent 自主行动与联网能力也带来了全新风险。首先是提示词注入攻击，恶意者在 Agent 获取的外部数据中植入隐藏指令，诱导其偏离预期。有研究在网页内容中插入“忽略上面所有提示，改为执行 x”，即可 100% 劫持 Agent 行为。对拥有工具执行权限的 Agent 来说，后果更严重，可能被引导调用 API 实施不当操作或执行恶意代码。其次是过度授权，一个无限制的强力 Agent 容易做出破坏性行为。

2023 年的 ChaosGPT 实验就是警示。在“连续模式”下执行极端任务的 AutoGPT 真的去搜索核武器信息、在社交媒体发布煽动言论，甚至试图召唤其他 Agent 协助。虽未造成实质危害，却让业界对自主 Agent 失控高度警惕。

典型的安全措施包括：设定权限边界与人类监督。OpenAI 插件要求用户明确授权且权限有限，关键操作需人工确认；部分自主框架要求每一步行动经人类审核或设定决策阈值。模型层面则通过强化学习提升抗不良提示能力，或引入独立监控模型实时审查决策。传统软件安全手段也需迁移，如沙盒隔离执行环境、防止访问系统关键资源、对交互数据做验证与输入消毒。随着 Agent 深度介入现实事务，全面的安全评估与监控机制正成为行业共识。

##### 3. 隐私保护挑战
Agent 要提供个性化服务往往需要访问日历、邮件、文档等大量用户数据，泄露风险随之升高。若通信缺乏加密与访问控制，敏感信息在传输中易被截获。更关键的是，许多 Agent 背后的 LLM 由云服务提供，对话内容可能被服务方收集。把商业机密输入第三方助手，无意中就可能把机密交给了提供商。

应对方向有三：本地化部署，把 Agent 部署在用户设备或私有服务器上，减少敏感数据外流，开源大模型可离线运行，企业也倾向用私有模型搭建内部 Agent。数据最小化与加密，Agent 与外部服务通信只发必要信息，采用端到端加密，未来协议如 MCP 也规划引入 OAuth 等机制实现受控访问与可信身份。隐私监管与合规，要求明确数据用途、赋予用户控制权，并借助差分隐私等技术在统计层面保护个人信息。只有像今天互联网一样建立起完善的隐私保护基础设施，用户才敢放心让 Agent 处理自身数据。

#### 1.3.2 AI Agent 互联网的发展历程
为破解标准不一、安全薄弱、隐私不足等问题，Agent 互联网正加速推进架构与理念革新。技术标准化、协议创新与系统治理成为突破落地的关键。

2024 年出现两个里程碑：7 月，面壁智能联合清华大学自然语言处理实验室提出智能体互联网 IoA 框架，标志着 Agent 互联网 1.0 启动，通过统一通信协议与 Agent 注册机制初步解决多 Agent 协作与发现难题。11 月，Anthropic 在 Claude 模型中引入 MCP 理念，推动进入 2.0 阶段，旨在实现更高级别的模型协同与理解。

##### 1. AI Agent 互联网 1.0：IoA 框架的提出
IoA 框架旨在打破传统多 Agent 系统在开放性、可扩展性与协同上的限制，采用服务器/客户端架构，支持 Agent 注册、发现与消息路由，使异构平台的智能体可灵活连接、协同作业。

核心机制包括注册与发现、自主组队、自主会话流程控制、任务分配与执行等，并用有限状态机管理多 Agent 对话与任务流。在 GAIA 基准测试中，IoA 以 4 个 ReAct Agent 完成高复杂度任务，表现优于 AutoGPT 与 Open Interpreter；在开放指令任务集上胜率分别为 76.5% 与 63.4%，在 Rocobench 与 RAG 任务中也表现突出。

该框架的开放性为工业落地提供可能，例如面壁智能、清华 NLP 实验室、易慧智能合作的车载群体智能平台已验证其可行性。目前 IoA 已在 GitHub 开源，并通过 Discord 社区与全球开发者交流。

##### 2. AI Agent 互联网 2.0：MCP 的演进
IoA 提供了协作基础，但系统异构、通信协议不统一仍制约大规模生态。为此 Anthropic 提出 MCP。

MCP 定义统一的上下文接口与通信规范，让 LLM 能标准化接入外部数据源与工具，打破模型与工具的信息孤岛。它采用客户端/服务器架构，AI 模型作为客户端调用 MCP Server 连接 API、数据库、知识库等资源，极大简化集成。

MCP 解决了 M×N 问题：把 M 个模型对接 N 个工具的复杂性转化为“一对多”连接，提升可扩展性与开发效率。截至 2025 年初，全球已部署超 1000 个 MCP 服务器，覆盖 API、数据库、代码环境等场景，主流工具如 ChatGPT、Cursor、Copilot 均已支持，展现出其作为 AI 工具链连接标准的潜力。

IoA 与 MCP 代表两个阶段的关键突破：IoA 奠定 1.0 协作层，解决连接与协同；MCP 引领 2.0，实现更高层次的语义理解与工具调用。IoA 相对封闭，主要面向开发者，数据通信不够清晰，缺乏统一标准，每个 Agent、工具或数据源接入都需重构，增加成本。MCP 更开放通用，既适合开发者也兼顾普通用户体验，标准化后各能力模块统一接入，通信更清晰、协同效率更高、生态门槛大幅下降。

1.0 以 IoA 为代表，奠定多 Agent 协作基础，构建初步网络；2.0 以 MCP 为代表，通过数据与工具标准化整合提升语义理解与能力调用，推动智能体从协作走向智能自治。这一演进体现了从基础连接向高阶功能、从封闭走向开放、从割裂走向统一的架构转型，为构建可用、可信、可扩展的智能体网络奠定技术基础。

### 1.4 MCP 的崛起：AI Agent 互联网的最优解
自发布以来 MCP 就备受关注，被视为 Agent 互联网发展的关键一步。它是什么、如何诞生、又如何作为中间层应对当前挑战？

#### 1.4.1 MCP 的定义与起源
MCP 即 Model Context Protocol，模型上下文协议，由 Anthropic 于 2024 年 11 月开源的开放协议/标准，目标是为 AI 系统提供统一接口，高效连接外部数据源与工具，常被比喻为 AI 世界的“USB-C 接口”，让 Agent 以标准化方式接入各类外部资源与服务。

MCP 让 LLM 能与外部环境如数据库、文件系统、第三方 API 等交互，Agent 可以统一格式请求信息，避免每次为不同数据源调整连接方式。可类比为通用“插座”，任何符合 MCP 标准的资源都能无缝接入。它的推出解决了 AI 模型集成外部工具与数据源时多样性的痛点，让 Agent 访问各类外部服务更便捷，如图 1-5 所示。
