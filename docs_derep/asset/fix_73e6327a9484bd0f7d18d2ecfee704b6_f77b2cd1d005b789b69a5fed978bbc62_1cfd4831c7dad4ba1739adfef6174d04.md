Gremlin：跨平台图遍历语言初探

`Gremlin` 由 `Apache TinkerPop`\[2\] 于 2009 年推出，是一种跨平台的图数据库查询语言，采用函数式数据流范式。借助它，用户可以用简洁的方式在图数据上表达复杂的遍历逻辑。一次遍历本质上是一串可嵌套的操作链，每一步都对图库执行一次基本单元操作。基本单元大致可归为三类：转换类用于把图数据映射为新形态、筛选类用于剔除不符合条件的对象、统计类用于计算聚合信息。`Gremlin` 的全部能力都是在这三类基础之上扩展而来的，组合起来即可形成丰富的查询手段。

设计遵循“一次编写，随处运行”的理念，`Gremlin` 的图检索既能在 `TinkerPop` 自有的图系统里执行，也能作为实时查询请求被不同数据库接收。实际使用时通常会先起一个虚拟机来运行。现阶段主流实现支持 `Groovy` 与 `Java`。用户写好的语句会被编译成脚本对象，再交由对应的脚本引擎执行。相比传统编程语言，`Gremlin` 在表达查询时更凝练易读；相比关系型数据库的查询语言，它对图上操作的掌控力更强，能让使用者自由设计遍历路径。扩展性也很友好，可在 `Gremlin` 或 `Java` 中原生定义新方法与操作。下面以查询公司名为“Xiaomi”的法人代表为例。

从代码可以看出，`Gremlin` 的写法更像编程语言里的函数调用。`g` 代表由边和点构成的完整图，`V()` 则取出图中全部顶点，后续常跟筛选条件。像 `SQL` 这类经典查询语言被认为与生产环境使用的编程语言存在冲突难以融合。传统数据库因此要求开发者同时精通查询语言和系统编程语言，查询语言与编程语言之间的鸿沟长期存在。`Gremlin` 填补了这道鸿沟，图遍历可以用任何支持函数组合和嵌套的语言来写。这样编写的 `Gremlin` 程序就能和业务代码同在一个工程里，享受宿主语言提供的类型检查、语法高亮等工具红利。目前常见的变体有 `Gremlin-Java`、`Gremlin-Groovy`、`Gremlin-Python`、`Gremlin-Scala` 等。

#### 2. 语义搜索的进阶
前面讲的是基于查询语言的知识检索。图数据库的查询语言再怎么贴近自然语言，本质仍是让用户写结构化脚本。传统检索手段的语法组合能力也很有限。随着 `Linked Open Data` 等结构化数据平台逐步开放，可用于构建知识图谱的数据源持续增加，`RDF`、`OWL` 等表示语言下的知识图谱也在快速积累。于是以 `Google` 为代表的公司开始用知识图谱提升搜索质量，实现语义层面的知识检索。语义搜索是在查询语言检索之上的一次跃迁，其核心是用数学方法摆脱传统检索的近似与模糊，为词语含义及其与输入的关联给出清晰理解。简单说，就是让用户输入越像自然语言越好，同时返回越精确的答案。它依托知识图谱的表达力挖掘用户需求与数据的内在关联，对复杂查询的理解和回应能力也更强。

语义搜索大致可分为轻量级的信息检索与更复杂的语义搜索。轻量级系统没有知识图谱那样的复杂表示，通常只用词典或分类器等简单模型把语义数据与检索目标关联起来。复杂系统则需要知识图谱或本体进行显式建模，在模型基础上检索关键词时可借助推理或联想返回更相关的结果。理想状态下，若用户能用结构化查询语言精确描述需求，系统便可给出精确结果。现实中用户往往做不到，也难以掌握知识表示方法，这时语义搜索的重要性就凸显出来。

常用做法包括关键词查询和自然语言查询。关键词查询最基础，流程是先按索引在知识图谱里找到与关键词定义相符的子图，大幅缩小搜索空间，再在小范围内检索。以查询小米公司法定代表人为例，系统先输入“小米公司”与“法定代表人”两个关键词，用“小米公司”筛出子图，再在其中找法定代表人。流程如图 2-17 所示。

自然语言查询复杂度更高。用户输入句子后，系统要先剔除无意义成分、做消歧，再做句法词法分析并向量化。把输入向量与知识图谱信息的向量表示比较后得到精确结果。例如输入“小米公司的法定代表人是谁？”，系统会做语义语法分析、必要时向量化后在知识图谱中查询。具体实现将在第 7 章展开。在自然语言驱动的语义搜索里，输入往往隐含推理与联想，所需答案未必显式出现，这就要求检索系统像人一样推理，即后面要介绍的知识推理。

### 2.4.2 知识推理

## 知识推理概述
当一个完整的知识图谱建成后，机器拥有学识的程度又向前迈了一步。但仅有构建与查询还不足以实现认知。人类演化中，运用知识进行推理是认知的关键。概念上，推理就是从已有知识推导出尚不拥有的新知识。`Kompridis`\[11\] 把推理定义为理解事物、建立验证事实、运用逻辑、基于新旧知识修正体系等能力的集合。推理涉及两类知识：已有的和尚未获得的。演绎推理中最简单的三段论由大前提、小前提和结论构成，前两者是已有知识，结论是新知识。

在知识图谱里，核心单元是三元组 <主体，谓词，客体>，由已知三元组推断未知三元组的过程即为知识推理。如已知 <小米公司，经营范围，手机> 且手机属于电子产品，则可推出 <小米公司，经营范围，电子产品>。主要应用有知识补全、知识对齐与知识图谱去噪。在此概述通用概念后，本节先介绍传统推理，再介绍近年流行的表示学习方法。

### 传统知识推理方法
传统方法主要依赖规则。基于规则的推理借用逻辑推理思想，把简单规则、约束或统计方法施加到知识图谱表示的数据上进行判断。完全规则驱动的常见类型是类别推理与属性推理。

类别推理针对实体所属类别，常用于图逻辑结构中层次较低实体的分类。例如图谱里私营有限责任公司是有限责任公司的子类，有限责任公司是公司类的子类，那么实例小米科技有限公司应属于公司类。图 2-18 中实线为已知知识，虚线为推理得到的新知识。

把这类确定类与属性的规则统计并复杂化，就能形成对知识图谱正确性的校验手段，用规则进行纠错与补全。

除了静态规则，还能用图谱训练规则再推理。如 `NELL`\[12\] 结合一阶逻辑与概率学习，人工筛选学习到的规则后用图谱实体实例化，再学习新的推理规则。规则还能用于多步推理，多步比单步更复杂，例如 A 与 B 有关系 R，B 与 C 有关系 R'，则 A 与 C 有关系 R"。人工或统计难以覆盖这类模式，可通过挖掘实体间路径近似实现。针对多步任务，一种方案是基于图谱全局规则与结构进行路径挖掘，筛选后把部分路径视作规则，通常采用随机游走发现路径。`Lao`\[13\] 等人提出的 `PRA`（`Path Ranking Algorithm`，路径排序算法）旨在预测实体间是否存在关系，输入为实体间的路径。`PRA` 在构造数据时使用随机游走思想，收集足够正例后训练逻辑回归分类器进行多步关系推理。

总体看，规则推理可通过统计、人工筛选或机器学习构建有效规则，准确性较高、计算量小、速度快。但图谱规模动辄百万以上，验证规则需要大量实体；规模上升时抽象全局与多步规则非常困难。过度依赖统计特征易过拟合，对噪声抵抗差。随着深度学习发展，表示学习与深度学习驱动的推理更具优势。

### 基于表示学习的知识推理
在规则方法里，规则无论人工定义还是模型学习都显式给定特征。表示学习则把图谱中的节点和关系映射到同一连续向量空间，学习每个元素的向量表示。表示可以是向量或矩阵，学习过程中会自动获得下游任务所需特征，把离散实体与关系嵌入空间。该思路源自自然语言处理中的词表示学习，得到的向量同样具有空间平移特性。

最经典的算法是 `TransE`\[14\]。它期望学习实体与关系的低维向量，使三元组 (h, r, t) 满足 t ≈ h + r，即尾实体近似于头实体加上关系。举例 <小米公司，法定代表人，雷军>，若头实体小米公司向量为 [1,0]，关系法定代表人向量为 [0,1]，则 `TransE` 期望雷军向量为 [1,1]，此时 h + r = t，三元组成立。形式化表示见图 2-20。

据此得到得分函数为向量距离 `||r+h-t||_{L1/L2}`，训练时替换 h 或 t 构造负例，让负例得分更低、正例得分更高。`TransE` 虽经典但存在不足：它要求 t 与 h + r 严格接近，虽能严格约束元素，却在尾实体多值时导致多个实体竞争同一空间点，语义差距大的实体挤占同一区域会产生误差；它未考虑层级关系，而层级对推理至关重要。

在此基础上，`Wang` 等人提出 `TransH`\[15\]。`TransH` 为每个关系额外学习一个映射向量，把实体映射到关系指定的超平面，使同一实体在不同关系下有不同表示，缓解多值问题。`Lin` 等人提出 `TransR`\[16\]，在独立的实体空间和关系空间中分别表示，每个关系对应一个空间，头实体经关系映射到关系空间中的尾实体，更好弥补 `TransE` 的缺陷。获得实体与关系表示后，既可通过向量运算做简单推理，也能结合机器学习模型完成复杂场景推理。目前该方向常结合强化学习、时序预测模型与图神经网络等方法。
