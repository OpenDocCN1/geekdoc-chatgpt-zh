#### 8.1.2 LangChain开发框架全景拆解

LangChain 这一开源体系由 LangChain AI 公司推出，它的本质定位是服务于大语言模型驱动型应用的工程化框架。框架的底层逻辑是搭建一套标准化的模块抽象，把大模型的输入输出统一规范化，从而形成可组合、可插拔的开发链路。整体设计围绕“Chain”展开，强调把模型调用、上下文管理、工具执行、内容解析等环节以链式方式串联，让开发者能高效地把原始数据一路处理到智能响应。

归根结底，LangChain 的出发点是模型能力本身，结合开发者在真实任务中的经验沉淀，对大模型的涌现能力做高级抽象，并通过统一接口兼容多种底层模型服务。正是这一思路，让它演变成一个通用性很强的大模型应用开发范式。

目前 LangChain 已经发展为覆盖面极广的开发平台，其模块化设计既体现了对 LLM 的深刻理解，也为 Agent 的标准化开发提供了关键支撑。LangChain 抽象出的核心模块如图8.4所示。

[PRE0]

图8.4 LangChain核心模块

##### 1. Prompt

提示词是任何大模型应用的起点。LangChain 用 PromptTemplate 提供了统一定制的模板机制。一方面开发者可以注入自定义变量，为模型提供精准的背景与任务指令；另一方面模板本身做了结构化封装，支持变量插值、参数校验和复用，通过填充模板即可生成动态变化的提示内容。

##### 2. Models

Models 模块把主流大语言模型都封装在内，并给出统一的调用入口。配置好模型信息后，整个项目的业务逻辑无需改动，就能平滑切换底层模型。

##### 3. Output Parser

大模型原生返回的是自然语言文本，而工程里通常需要固定格式的输出，比如 JSON、列表、表格或代码块。Output Parser 就是为此而生。LangChain 内置了字符串解析器、列表提取器、Pydantic 校验器等多种解析器，帮助把每一步模型输出结构化，提升链式执行的稳定性。

##### 4. Memory

Memory 模块让对话类场景具备多轮记忆能力。它区分短期与长期记忆，可对用户历史输入和模型输出进行存储与复用，保持上下文连贯。

##### 5. Callbacks

Callbacks 提供了一套事件监听机制，能对模型调用链路的每个环节进行监控、调试和可视化。日志可以输出到终端、写入文件，或接入可观测性平台，实现全链路追踪。

##### 6. RAG

LangChain 对 RAG 做了深度封装，涵盖检索器构建、向量数据库适配如 Chroma、FAISS、Milvus 等，以及上下文压缩器和相关度过滤器。开发者可按需组合这些组件，快速搭建针对特定语义检索的增强生成链。

##### 7. Agent

Agent 模块是实现复杂任务自动化的核心引擎。它让大模型扮演工具调用者，根据任务需要动态决定是否调用外部工具、API 或其他链条。LangChain 提供了多种内置 Agent 类型，支持任务自动拆解与执行。

在 LangChain 里，这七大模块就像积木，各自职责清晰，又能灵活组合。既可以实现基础的问答响应，也可以搭建具备记忆、知识增强、结构化输出和多工具协同的高级 Agent 系统。如图8.4所示。

#### 8.1.3 LangChain中的高阶RAG构建

在 BiliAgent 的数据分析场景里，要完成多阶段处理与智能分析，就必须借助 LangChain 来接入大模型并搭建 RAG 流程。整个过程类似搭积木，每个模块都支撑着 Agent 系统的运转。

如图8.5所示，RAG 的运行逻辑是把用户查询送入检索器，在一个已持久化的知识库 Knowledge 中快速定位最相关的信息片段，再把这些片段作为上下文注入 LLM 的 Prompt，引导模型给出更准确、更相关的回答。

[PRE1]

换句话说，RAG 本质上是用外部知识来补强 LLM 能力的增强范式。从宏观来看，大模型虽有强大的理解与推理能力，但受限于训练截止的知识边界，在特定领域或时效性场景下会力不从心。通过构建信息流通通道，按需把高质量外部知识引入推理流程，正是 RAG 诞生的初衷。其核心流程如图8.6所示。

[PRE2]

如图8.6所示，RAG 的搭建主要包含以下环节。

- **索引（Index）**：索引是离线准备的关键第一步。先对原始数据进行清洗与抽取，把 PDF、HTML、Word 等格式统一转为纯文本。为适应模型上下文限制，再把文本切分成更小块，即分块处理。随后用嵌入模型把这些块转为向量表示，最后建索引把文本块与向量以键值对形式存储，支撑高效可扩展的检索。

- **检索（Retrieval）**：用户问题会先被编码模型处理生成语义向量，再在向量数据库中做相似性搜索，取出最接近的前 k 个数据对象作为候选上下文。

- **生成（Generation）**：把用户原始查询与检索到的上下文填入提示模板，形成增强提示，再输入 LLM 生成最终答案。

完整流程用原生代码实现较为繁琐，LangChain 的封装让它变得简洁。但复制标准 RAG 路径在复杂任务中往往效果有限，优化是必须的。图8.7展示了 LangChain 已封装的高阶 RAG 方案。

##### 1. 翻译查询

自然语言问题常语义复杂或表达不规范，直接检索召回不佳。LangChain 提供了查询改写能力，支持多查询生成等价表述提升召回、RAG 融合聚合多表达检索结果、问题分解把复合问题拆成小问题等策略，让查询在语义层与知识库更好对齐，下游检索更精准。

##### 2. 路由

路由模块根据问题类型或语义特征选择合适的检索路径与提示模板。包括逻辑路由基于问题结构选择数据库或查询方式，以及语义路由把问题嵌入向量空间后匹配最合适的 Prompt 结构。

##### 3. 数据库的支持

在高级 RAG 构建中，系统可接入三种底层数据库：图数据库、关系型数据库和向量数据库。

[PRE3]

##### 4. 构建查询

面对自然语言问题，系统会先按目标数据库类型生成结构化查询指令。

- **关系型数据库**：借助 Text-to-SQL 把自然语言转为 SQL，并结合向量检索做增强。
- **图数据库**：采用 Text-to-Cypher 生成图查询语言，从知识图谱中抽取语义关联信息。
- **向量数据库**：利用 Self-query retriever 自动提取问题意图与元数据过滤条件，生成向量检索请求。

##### 5. 索引

好的检索依赖好的索引。LangChain 在索引阶段引入了多项机制。

- **块优化**：按字符、段落或语义断点切分文档，提升嵌入质量。
- **多表示索引**：如 Parent+Summary+Dense 向量结构，让检索更全面。
- **专业嵌入**：结合微调或 ColBERT 等模型生成更精准的领域向量。
- **层级索引**：如 RAPTOR，构建跨层级、多抽象层的文档树，实现摘要层级的高效索引。

##### 6. 检索

路由确定后进入信息检索阶段。

- **排名**：对候选文档进行语义重排，方法包括 Re-Rank、RankGPT、RAG-Fusion 等。
- **细化**：若初轮结果不理想，可进行再检索或检索压缩。
- **主动检索**：根据初轮回答质量自动判断是否需要重写问题并重新检索。

##### 7. 生成

检索到文档后，LLM 会结合原始问题与增强上下文生成答案。LangChain 在生成阶段引入 Self-RAG / RRR 优化，模型可主动判断理解是否正确、信息是否充分，从而触发再检索与反馈。
