#### 4.3.4 GraphRAG问答流程实现

在完成知识图谱的索引搭建并检视相关结构化文件后，我们进入 GraphRAG 的第二阶段——问答阶段。这一阶段利用图谱、社区报告、实体向量等索引产物，结合大模型为用户问题生成高质量答案。

首先导入 GraphRAG 提供的基础模块。这些模块大致可归为四类：索引数据加载、向量存储、大模型调用、本地检索与问答。运行下方代码。

各模块的作用如下。

1）与索引器相关的模块
索引数据读取器（read_indexer_*）：从此前构建的 .parquet 文件中读取图谱相关数据，包含实体、关系、社区报告、文本单元等。
实体语义嵌入处理器（store_entity_semantic_embeddings）：把实体的语义描述向量化并写入向量数据库。

2）与 LLM 相关的模块
语言模型调用接口（ChatOpenAI、OpenAIEmbedding）：负责与大模型交互，完成问答与嵌入生成。

3）与本地搜索相关的模块
本地搜索模块（LocalSearch、LocalSearchMixedContext）：基于图谱邻接结构与实体嵌入实现精细化问答。

4）与向量存储相关的模块
向量数据库接口（LanceDBVectorStore）：管理语义向量的持久化与高效检索。

相关参数说明如下。

- community_reports：传入已加载的社区报告数据 reports，用于在本地搜索中补充社区层级的背景信息。
- text_units：传入已加载的文本单元数据，提供来自原始文档的片段，用于回答具体问题或补充上下文。
- entities：传入知识图谱实体，提供实体详情与属性，帮助定位特定实体。
- relationships：传入知识图谱关系，用于描述实体间的交互，有助于构建更复杂的答案。
- covariates：传入协变量，若索引阶段未启用则设为 None，用于提供额外的声明式元数据。若未启用，本地搜索仍可运行，但答案的附加语义信息会减少。
- entity_text_embeddings：传入实体嵌入存储对象 description_embedding_store，将实体文本嵌入存于向量库，支持语义检索快速找到相关实体。
- embedding_vectorstore_key：设置嵌入向量存储的键类型。若向量库按 ID 存储实体，使用 EntityVectorStoreKey.ID；若按标题存储则设为 EntityVectorStoreKey.TITLE。
- text_embedder：传入嵌入生成器对象 text_embedder，用于生成问题或文本的语义嵌入，与存储的实体嵌入做相似度比较。
- token_encoder：传入分词器，确保生成的上下文不超过 LLM 的窗口限制，有助于合理分配查询时的上下文。

上下文构建器是本地搜索的核心，它把加载的数据整合成结构化上下文，具体作用如下。

- 融合社区报告，提供更高层次的背景，利于回答主题性问题。
- 整合文本单元，引入原始文档片段，为问题构建直接上下文。
- 集成图谱实体与关系，为实体相关问题提供详细语义信息。
- 借助嵌入与分词器，保证上下文语义准确且符合 LLM 的窗口限制。

相关参数说明如下。

- text_unit_prop：上下文窗口中分配给文本单元的比例，默认值 50%。控制原始文档文本在上下文中的权重。
- community_prop：上下文窗口中分配给社区报告的比例，默认值 10%。为回答提供更高层次的社区背景。
- conversation_history_max_turns：上下文中包含的最大对话轮数，默认值 5 轮。控制是否纳入过往对话历史及保留轮数。
- conversation_history_user_turns_only：若为 True，仅保留用户提问，忽略模型回复。
- top_k_mapped_entities：从嵌入向量库检索的相关实体数量，默认值 10 个。
- top_k_relationships：检索并纳入上下文窗口的最大关系数，默认值 10 个。
- include_entity_rank：是否在上下文中包含实体排名，默认按节点度数计算。
- include_relationship_weight：是否在上下文中包含关系权重，用以体现关系重要性。
- include_community_rank：是否在上下文中包含社区排名。
- return_candidate_context：若为 True，返回包含所有候选实体、关系和协变量记录的数据帧集合，记录中含 in_context 列表示是否进入上下文窗口。
- embedding_vectorstore_key：嵌入向量存储的键类型，若标识符为实体标题而非 ID，则设为 EntityVectorStoreKey.TITLE。
- max_tokens：上下文窗口允许的最大 token 数，12 000 个。需依据所用 LLM 的限制调整，如 GPT-4 支持 8192 或 32 768。
