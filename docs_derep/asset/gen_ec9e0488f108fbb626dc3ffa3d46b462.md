| 布尔 | 组件内部是否有元素需要按需显示或隐藏 | 在按钮组件中新增名为 Show Icon 的布尔属性，用开关控制图标是否可见 |
| 文本 | 按钮文字是否需要让使用者自行修改 | 为按钮的文字图层添加名为 Label 的文本属性，使用者在属性面板即可直接改写文案 |
| 实例交换 | 图标或子组件是否需要被替换 | 为按钮图标创建名为 Icon 的实例交换属性，允许使用者从图标库中挑选并替换 |

接下来进入综合演练，用一次练习把按钮组件做到既强大又灵活。

## 4. 十五分钟实战：打造一套完整的按钮组件集（可选学习）

这项练习能帮助你牢牢掌握组件系统的核心要点，沉淀出真正可用的设计资产。通过构建具备多种状态与可定制属性的按钮集合，你会直观感受到组件化设计的威力—一次搭建，到处复用，统一维护。

具体操作步骤如下。

1.  **搭建基础按钮**。新建一个 Button 文字层，旁边放置一个图标组件实例（来自 2.3.1 节的练习）。选中两者后按 Shift + A 自动将其包裹进一个水平自动布局框架，调整间距与内边距，并为框架添加填充色。

2.  **生成主组件并添加属性**。选中步骤 1 完成的按钮框架，按 Ctrl/Cmd + Alt + K 将其转为主组件。在右侧 Design 面板找到 Properties 区域，点击 “+”，为图标图层新增一个布尔属性并命名为 Show Icon；为文字图层新增一个文本属性并命名为 Label。

3.  **新增变体属性**。再次在 Properties 区域点击 “+”，选择“变体”，将首个变体属性命名为 Style，其取值设为 Primary。

4.  **创建更多变体**。点击组件集紫色边框下方的 “+” 新建变体，将该变体的填充方式从填充改为描边，并把 Style 属性值改为 Secondary。

5.  **补充状态变体**。选中整个组件集，再次新增一个变体属性并命名为 State，默认值为 Default。分别为主样式与次样式创建 Hover 状态变体：框选这两个变体，右键复制粘贴出两份新的变体，将它们的 State 值改为 Hover，并调整背景色以模拟悬停效果。

6.  **验证按钮组件**。把左侧 Assets 面板中的按钮组件拖到画布上。在右侧属性面板中应能看到切换 Style 与 State 的下拉菜单、可编辑 Label 的文本框，以及控制 Show Icon 的开关，自行测试各种自定义效果。

掌握组件后，我们再来认识一个更高级的概念——变量。

## 5. 用变量实现设计令牌（可选学习）

如果说样式是将具体数值固定为一个名字，那么变量就是其进阶形态：一个可根据不同情境承载不同值的占位符。这正是构建设计令牌的核心机制。

设计令牌是将设计决策，例如“主背景色应该是什么”，从具体实现中抽离出来，以数据化方式统一管理的单一事实来源，让设计系统更易维护。

在 Figma 中，变量由专门的 Variables 面板管理，核心包含三个概念。

-   **集合 Collection**：用于归类管理变量，比如一个集合放颜色，另一个放间距。
-   **模式 Mode**：同一集合内可配置多套取值组合，是实现主题切换如明暗模式的关键。
-   **别名引用 Aliasing**：高级技巧，允许一个变量引用另一个变量的值，进一步提升关联性与可维护性。

接下来的练习将让你体验变量带来的“一键换肤”效果。

## 6. 十五分钟实战：实现明暗模式切换（可选学习）

本实战让你感受变量系统的强大—一次配置即可完成整个设计系统的主题切换。

开始前请确认已完成前序练习，尤其是响应式卡片的创建。若未完成，可先快速做一张包含标题、描述文本和按钮的简单卡片作为测试对象。具体步骤如下。

1.  **创建颜色集合**。取消画布所有选择，点击右侧边栏的 Variables 打开变量面板，新建一个集合并命名为 Theme: Colors。

2.  **定义模式**。在变量面板中把默认模式列标题改名为 Light，再点击 “+” 新增一个模式并命名为 Dark。

3.  **创建颜色变量**。
    -   **color/background**：Light 模式设为白色 #FFFFFF，Dark 模式设为深灰 #1E1E1E。
    -   **color/text**：Light 模式设为深灰 #1E1E1E，Dark 模式设为白色 #FFFFFF。

4.  **应用变量**。打开之前创建的响应式卡片，为卡片根框架的填充色应用 color/background 变量，为内部所有文字层的填充色应用 color/text 变量。

5.  **观察切换效果**。在画布上新建一个顶层框架，如手机屏幕尺寸，将已应用变量的卡片实例放入其中。选中该顶层框架，在右侧属性面板的 Layer 区域找到变量模式图标，点击把模式从 Light 切换到 Dark，框架内所有卡片会同步切换为深色主题。

## 2.3.3 从静态稿到可交互产品（可选学习）

到这里，我们已经能做出结构清晰、样式统一、动态响应的界面单元。本节介绍如何把这些静态稿串联起来，制作出用户可真实点击体验的交互原型，并最终交付开发。若难度偏高可先跳过。

### 1. 高级原型制作

原型能让设计“活”起来，直观呈现用户流程与交互细节。在 Figma 中，原型制作的核心是建立页面间的连接关系并定义触发条件与动画效果，从基础跳转到条件判断的复杂交互均可实现。下面从简到繁梳理原型制作的四个关键环节。

-   **基础连接**：切换到界面右上角的 Prototype 标签，选中任意图层或框架，按住拖动其边缘的蓝色圆形节点连接到目标框架，即可建立基础交互链接。
-   **触发器与动作**：创建连接后，在右侧 Interaction 面板可定义交互的触发方式，如点击、拖拽，以及动作类型，如导航到页面、弹出浮层。
-   **智能动画 Smart Animate**：用于制作平滑过渡动画。将两个框架间的过渡设为 Smart Animate 后，Figma 会自动为名称相同的图层在位置、尺寸、颜色变化时生成补间动画。
-   **用变量制作有状态原型**：借助变量可创建具备记忆与状态的真实原型。可通过交互动作 Set Variable 修改变量数值或状态，如点击按钮让 itemCount 加 1，也可为交互添加条件逻辑 if/else，实现原型状态的动态切换。

下面通过一个实战来演练这些功能。

### 2. 十五分钟实战：搭建动态购物车原型

本实战让你体验变量系统的真正威力——打造能记住用户操作的动态原型。我们将构建一个简单但功能完整的购物车交互，演示如何用变量管理应用状态，具体步骤如下。

1.  **设置变量**。打开 Variables 面板，创建 Number 类型的变量，命名为 cartItemCount，初始值设为 0。
2.  **设计界面**。在一个框架中设计一个带“加入购物车”按钮的商品卡片，并在框架顶部设计导航栏，内含购物车图标及旁边的文本层。
3.  **绑定变量**。选中购物车图标旁的文本层，在右侧 Design 标签的 Text 区域点击最右侧的 Apply variable 图标，选择 cartItemCount 变量，文本层会立即显示为 0。
4.  **创建交互**。切换到 Prototype 标签，选中“加入购物车”按钮。
5.  **添加 Set Variable 动作**。为按钮创建 On Click 交互，在 Action 下拉菜单中选择 Set Variable，Target 选择 cartItemCount 变量，Value 输入表达式 cartItemCount + 1。
6.  **测试原型**。点击右上角 Present 按钮进入预览模式。每次点击“加入购物车”按钮，导航栏中的购物车数字都会实时递增。

完成原型后，最后一步是将设计交付开发团队。

### 3. 开发者模式完全指南

开发者模式是 Figma 官方提供的专属工作区，目标是弥合设计与开发的鸿沟。作为设计师，了解开发者的可见信息有助于更精准地准备交付物。

在 Figma 底部工具栏有设计/开发模式切换开关，快捷键 Shift+D。切换后开发者可看到以下核心信息。

-   **检查面板**：开发者的核心工具。选中任一元素，面板会实时展示其尺寸、颜色、字体等属性，并自动生成 CSS、iOS、Android 等代码片段。
-   **资源导出**：开发者可快速查看并一键导出标记为可导出的所有图标与图片资源。
-   **变更对比**：可清晰展示当前版本与上一版本的设计差异。
-   **注解**：你在设计稿上留下的评论与注解，在开发者模式下会完整呈现。

下面的实战模拟设计师交付阶段的最后工作。

### 4. 十五分钟实战：为开发者交付设计文件

本实战模拟交付前的收尾工作，确保交付物清晰、完整、无歧义，具体步骤如下。

1.  **最终检查与清理**。交付前再次审视文件，确保所有图层已合理命名、有序组织，删除所有草稿或无用页面。
2.  **标记导出项**。检查所有开发需要使用的资源，如图标、图片、Logo，选中后在右侧 Design 面板底部的 Export 区域点击 “+”，为图标设为 SVG 格式，位图如照片设为 PNG 或 JPG 格式。
3.  **标记准备好开发**。按 Shift + D 切换到开发者模式，选中已确认可进入开发的顶层框架，点击顶部工具栏出现的 Mark as ready for dev 按钮，为框架标注明确状态，方便开发者快速定位。
4.  **添加关键注解**。对于静态稿无法完整表达的复杂交互，使用评论工具在对应位置添加说明。例如“此处的卡片列表加载时需有淡入效果，动画时长 300ms”。
5.  **分享交付链接**。点击右上角 Share 按钮生成链接，确保给开发团队“可以查看”权限。发送链接后交付工作完成。

### 5. 实战工作坊：从 Figma 到 Tailwind CSS 代码

这里带你领略设计到代码自动化的前沿。这些工具并非取代开发者，而是作为加速器，把高质量设计稿转化为前端基础代码。要关注两个核心技巧。

###### 实现设计到代码的自动化转换

在现代前端开发中，设计到代码的自动化已成为提效关键。输出质量取决于输入设计稿的质量。要获得高质量代码，Figma 文件需遵循以下结构化原则。

-   **语义化命名**：图层名称应体现内容与功能。
-   **全面使用自动布局**：可直接映射为 CSS Flexbox 或网格布局。
-   **组件化设计**：将可复用元素创建为 Figma 组件。
-   **规范使用变量/样式**：工具可将其转化为 CSS 变量或 Tailwind 配置文件。

###### 借助第三方插件实现自动化转换

市场上已有众多插件可智能分析 Figma 设计并自动生成前端代码。以下两款较为流行。

-   **Anima**：可直接把 Figma 设计转为 React、Vue 或 HTML 代码，并支持 Tailwind CSS，提供灵活的技术栈选择。
-   **Builder.io**：借助 AI 驱动工具的核心功能 Visual Copilot，可将 Figma 设计一键转为多种前端框架和样式库的代码，适合多框架团队。

### 6. 十五分钟实战：从 Figma 设计到 React + Tailwind CSS 代码

下面通过完整实战演示如何把登录页设计稿转为可用的 React + Tailwind CSS 代码。本实战使用 Anima 插件完成流程。

1.  **设计登录页英雄区**。在 Figma 中运用自动布局、组件、变量等技巧，设计一个简洁美观的登录页面英雄区。
2.  **安装 Anima 插件**。在 Figma 的 Resources 菜单中搜索 Anima 并安装。
3.  **配置并导出**。运行 Anima 插件，在插件窗口中将代码输出设置为 Framework -> React，Styling -> Tailwind CSS。
4.  **选择并生成**。在画布上选中英雄区的顶层框架，Anima 会实时分析设计并生成代码预览。
5.  **审查与使用**。可在插件中直接复制生成的 JSX 组件代码和 Tailwind CSS 类名。代码虽需开发者少量微调与逻辑集成，但已完美把视觉设计转化为代码，为开发提供极佳起点。
