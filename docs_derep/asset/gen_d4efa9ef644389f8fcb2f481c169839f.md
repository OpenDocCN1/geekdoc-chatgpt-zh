AI 基建的电耗问题已经越来越刺眼，数据中心尤其是为 AI 专门优化的那批，电力需求在直线攀升。有测算指出，到 2030 年中国的数据中心用电量可能占全国总用电的 4.8% ^(⁶⁶)。因此可持续性不能事后补课，必须在架构设计之初就置顶：选用低功耗硬件、搭配更高效的冷却方案。

### 6.4.3 制造场景 LLM 怎么选
为制造业挑一个合适的 LLM 并不是单一指标比拼，而是技术、成本、安全与应用场景的综合权衡。主流的判断维度如下。

1. 模型性能与能力
这是能否胜任制造特定任务的底线。
**● 专业理解与准确度**：模型要会读制造业的行话、流程和物理规律。比如能否准确识别图纸上的文字标注、读懂 PLM 里的 BOM 结构或工艺参数。对于工艺参数优化这类强精度场景，准确率就是生死线。
**● 多模态处理**：工厂数据不只是文字，还有 CAD 图、3D 模型、照片等。能同时联动文本、图像、三维等信息的多模态模型价值更高。
**● 推理与规划**：质量根因追溯、研制计划动态调整等复杂问题，需要模型具备扎实的逻辑推理和规划能力。
**● 实测基准**：在技术问答、需求生成、数据分析等制造任务上做基准测试，用量化结果做横向比较。

2. 适应性与定制化
通用大模型必须适配才能释放专业价值。
**● 微调弹性**：能否用企业自有数据做微调，学会企业特有的产品知识、工艺规范和历史记录。
**● RAG 兼容性**：能否和检索增强生成配合好。通过接入内部知识库如设计手册、质量文件、供应商资料，RAG 能给模型实时准确的上下文，减少幻觉，提升专业可信度。
**● 开源 vs 闭源**：① 开源模型如 DeepSeek、Llama 系列，定制自由度高、数据可控，支持本地私有化部署，更利于隐私和知识产权保护，但维护优化成本要企业自己扛。② 闭源模型如 GPT 系列，通用能力强、API 成熟，上手快，但定制受限，数据经 API 传输会带来安全顾虑。

3. 成本效益
能否规模化落地，关键看钱。
**● 训练与微调成本**：重新训练或深度微调需要海量算力，费用高昂。
**● 推理成本**：日常使用中持续产生。模型大小、响应速度、调用频次都会拉动费用，性能达标的前提下选更省的推理方案更理性。
**● 部署与运维成本**：云端还是本地数据中心、是否需要 GPU 等硬件，都是长期投入。

4. 安全合规与可信赖
制造涉及核心 IP 和敏感生产数据，安全是红线。
**● 数据隐私与安全**：部署方式能否做到数据不出域。选闭源 API 时要严格审视其数据使用与隐私政策。开源模型本地部署在这方面更占优。
**● 可解释与可追溯**：关键决策如工艺参数调整、质量判定时，模型能否说明判断依据，是建立信任和风控的必要条件。
**● 合规性**：模型及其应用必须符合所在行业和国家的数据安全法规与标准。

5. 集成与可扩展
AI 平台要无缝嵌入现有 IT 架构。
**● API 与生态**：是否提供稳定易用的 API，周边工具链和开发者社区是否成熟。
**● 部署灵活性**：是否支持云端、本地或边缘部署。对产线实时监控等场景，边缘能力尤为重要。
**● 可扩展性**：应用扩大、数据量增长时，服务架构能否平滑扩容，应对更高并发和计算压力。

基于以上五条维度，我们对 DeepSeek R1、通义千问 Qwen 2、ChatGPT、Llama 等常见模型做了对照，如表 6-1 所示。模型迭代很快，下述信息仅反映 2025 年上半年的普遍认知。

对制造业 AI 平台而言，理想做法不是四选一，而是按场景组合。

**● 核心研发、高度保密且需极致定制**：Llama 的开源与私有化特性，是保障数据安全的不二之选。
**● 需要强中文能力和云生态深度联动**：通义千问依托阿里云生态和中文优化，优势突出。
**● 需要顶尖编程与科学计算**：DeepSeek R1 的专用模型和高性价比 API 很有吸引力。
**● 追求快速集成、最强通用能力与成熟多模态交互，且合规允许**：ChatGPT 仍是验证原型、快速落地的首选。

总的来说，选型要围绕场景在性能、成本、安全和适应性之间找平衡。常用的是“模型矩阵”策略，同一平台内并行多个模型，不同任务配最合适的 LLM。例如用通义千问做客户交互的通用问答，用 DeepSeek 去分析技术文档、生成材料配方并做验证。

## 6.5 数据知识层：工业智能的枢纽
在现代 AI 或数据平台里，数据/知识层是承上启下的核心。它坐落在服务器、云平台等基础设施之上，为上层的模型与应用服务。核心任务是把企业内外原始、分散、异构的数据，清洗成高质量、可信、易用、能驱动智能的知识资产。

### 6.5.1 打通系统、汇聚数据
大部分企业已在使用 PLM、ALM、SDM、TDM、ERP、CRM 等研发相关系统。引入 AI 不是推倒重来，而是与之集成，盘活存量数据与流程。实践中通常走一套系统化的多层路径。

1. 建立稳定可靠的连接与数据通道
根据系统类型和实时性要求，选择不同集成方式。
**● API 集成**：对提供现代 API 如 RESTful 的系统，这是首选，可实现实时或准实时调用和 CRUD 操作。
**● 数据库直连**：对老旧系统或需要大批量抽取的场景，可通过 JDBC/ODBC 直接连后台数据库定期抽取。
**● 消息队列/事件总线**：对 MES 这类强实时系统，采用事件驱动。比如工序完成或设备告警时，立即发事件到 Kafka，AI 平台订阅后实时响应。
**● 文件交换**：批处理场景仍在使用 FTP 或共享文件夹定时交换 CSV、XML 等文件。

2. 构建统一的数据汇聚与处理中心
连通后不能直接用，必须集中治理。湖仓一体和向量数据库在成熟 AI 平台里角色互补，数据会按特性在两者间流动。
**● 湖仓一体**：是企业数据的主力存储与分析中心。来自 PLM、ERP、MES 等的结构化、半结构化和非结构化数据，经 ETL 或 ELT 清洗、去重、转换、整合后形成标准化资产入库。湖仓作为单一可信源，统一存储、管理、治理和权限控制，为机器学习提供干净的训练集。
**● 向量数据库**：为 AI 时代设计的语义搜索引擎。它不存原始数据，而是存从数据里抽取的向量表征。① 相似性检索核心是超高速向量相似度计算，比如找到最像一张缺陷品图片的十张样本，或找最相关的设计文档。② 检索增强生成是 LLM 应用的关键。提问时先转向量在向量库里检索相关片段，再作为上下文喂给 LLM，输出更准更稳。

**● 汇入湖仓**：PLM、ERP、MES 等数据经集成清洗后统一入湖仓一体库。
**● 数据向量化**：挑选湖仓中语义丰富的非结构化/半结构化数据，如产品描述、设计文档、技术手册、维修日志、质量报告，用 Embedding 模型转为向量。
**● 写入向量库**：向量连同指向湖仓原始数据的 ID 一并存入向量数据库。
**● 应用调用**：AI 应用做语义搜索或 RAG 时，先查向量库得相关 ID，再回湖仓取完整原始记录做后续处理。

可见数据先入湖仓统一管理，语义理解和相似搜索需要的“向量分身”存入向量库，两者协同构成 AI 平台的数据底座。

3. 实现语义统一与知识化
让 AI 真正“懂”数据，是集成的核心。统一语义模型像企业数据的通用词典与语法规则，屏蔽底层系统差异，让数据在企业内部无歧义流动，是数据驱动与 AI 成功的基础。

不同系统因设计目的不同，同一业务对象的描述天然不一致，表现为命名、格式、单位、定义不一致。比如零件在 PLM 叫 Part Number，在 ERP 叫 Material Code，在 MES 叫 Component ID，实指同一物理实体。PLM 的产品 BOM 指工程结构，ERP 的 BOM 可能是订单或生产结构，范围细节都不同。不解决这些，AI 分析会得出混乱甚至错误结论。
**● 主数据管理 MDM**：为产品、物料、客户、供应商等核心实体建立企业级黄金标准，统一定义与编码，解决跨系统不一致。
**● 构建统一语义模型**：为每个核心实体创建标准、全企业通用的模型，把各源系统字段映射到标准模型并定义转换逻辑。例如 PLM.Part Number→Master Part ID；ERP.Material Code→Master Part ID。数据流入时经语义层自动清洗映射转换，保证后续流程数据一致标准。

知识图谱的构建则是把治理后的数据及其业务关系结构化。例如清晰表达：某产品的某个零件由哪家供应商提供，用在哪些生产批次，交付给哪个客户。

4. 实现双向集成与价值闭环
最高效的集成是双向的。AI 平台既读取业务系统数据进行分析，也把分析结果写回业务系统形成闭环。
**● 读取与分析**：从 PLM、ERP 等读取数据做预测性维护、供应链风险分析、工艺参数优化。
**● 写回与执行**：把优化后的工艺参数通过 API 写回 MES 执行；把预测的采购需求自动在 ERP 生成建议单；把设计变更影响分析自动附在 PLM 变更流程中。

按以上四步，制造 AI 平台能与现有系统深度融合，实现数据到知识、知识到智能决策、决策反哺业务的完整价值链。

### 6.5.2 知识图谱如何构建
知识图谱是数据/知识层的升华，让数据开口说话，揭示深层联系。它把分散数据转为关联网络，帮助 AI 更好理解业务逻辑与实体关系，为需求追溯、变更影响分析等应用提供高质量基础。在研发体系中，它是连接数据、信息与智能的桥梁。

1. 研发知识图谱拆解
制造业研发天然面对庞大割裂的数据源：CAD、CAE、PLM、ALM、ERP、SDM、TDM 及大量遗留系统，形成普遍的数据孤岛，难以获得产品全生命周期视图。

数据割裂导致重复设计、需求变更难追溯、质量控制薄弱、对市场变化反应迟缓。工业软件是工业知识结晶，但其产生的数据常被困在各自系统。核心挑战是整合异构数据源。

数字主线的愿景正是产品生命周期信息无缝流动，知识图谱是实现数字主线的关键使能技术，通过语义层把孤立数据连成有意义整体。

知识图谱由实体、关系、三元组构成。
**● 实体**：研发世界的“名词”，如钛合金 Ti-6Al-4V、3D 打印中的选择性激光熔化工艺、涡轮叶片#77-B、疲劳寿命＞10000 次循环的需求、测试结果、仿真模型或工程师。
**● 关系**：连接实体的“动词”，如“涡轮叶片#77-B 由 Ti-6Al-4V 制成”、“选择性激光熔化是增材制造工艺的一种”、“工程师张三是计算流体动力学专家”。
**● 三元组**：实体-关系-实体构成的基本单元，是机器可读的事实陈述，图结构能表达传统关系库难以捕捉的网状知识。

构建的关键在于分层架构。
**● 数据层**：由具体实例构成的大图，含数百万甚至上百亿三元组，是知识的事实基础。
**● 模式层**：研发领域的抽象蓝图，定义允许的实体类型、属性、关系类型，为数据层提供结构与约束。模式层常通过本体形式化。

本体是共享概念的形式化规范，是知识图谱的“根本大法”，定义统一词汇表与规则。制造业研发复杂、术语模糊，必须靠本体实现语义统一与互操作。例如“应力”可能指机械应力 MPa，也可能指热应力，本体为每个概念提供唯一标识与精确定义，避免 CAD、CAE 数据集成时混淆。本体构建可自顶向下由专家定义，也可自底向上从数据发现，实践中混合最好。空客的研究展示了利用 BFO 等顶层本体和 IOF-Core 等领域本体为飞机装配构建专用本体的做法 ^(⁶⁷)。

双层架构是知识图谱区别于传统数据库的关键。数据层提供海量事实，本体驱动的模式层才把数据转化为智能可计算知识。没有健壮本体，图只是数据库；有了本体，它才能成为可推理的认知引擎。研发数据的复杂性要求形式化词典与规则手册，本体提供了这种机器可读的语义统一。

2. 研发知识图谱构建过程
传统构建需知识工程师手工定义实体关系并写规则抽取，缓慢昂贵难扩展。LLM 的自然语言理解与 RAG 的精准检索结合，可颠覆流程，实现自动化构建。整体可分为若干阶段。

（1）战略定义与本体建模
构建必须始于业务目标而非技术。首先定义“能力问题”，即知识图谱必须能回答的关键问题，如“哪些替代材料能承受 500°C 高温、蠕变率低于 2%，并且由欧洲供应商提供”。
