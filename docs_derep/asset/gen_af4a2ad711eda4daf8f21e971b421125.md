### 5.2.3 Web 自动化测试脚本

Web 应用是互联网体系的核心组成部分，随着应用普及与复杂度提升，自动化 Web 测试已成为保障质量并提升效率的关键。当前业界主流的工具与实践主要有：

❑ Selenium：最广为人知的 Web 自动化工具，通过浏览器驱动模拟点击、输入、拖拽等操作并校验页面响应^([6])。

❑ Cypress：执行速度快、API 简洁、内置等待机制，适合现代 JavaScript 框架开发的应用。

❑ Playwright：支持多浏览器并行，处理动态内容能力强。

❑ 跨浏览器测试：不同渲染引擎表现可能不一致，跨浏览器测试能保证一致性。

这些工具为自动化提供了强力支撑，但在脚本编写与维护上仍需大量人工。因为传统模式下，测试工程师要手工把功能用例转为自动化脚本，市面上自动生成工具多为录制操作行为。

借助 LLM，可以进一步提升脚本编写的自动化效率。业界已有工具如 LangChain，通过扩展封装 LLM 实现了 Web 自动化测试脚本生成。

LangChain 的思路是：

❑ 用户用自然语言清晰描述操作步骤。

❑ 为 LLM 外挂工具包，使其具备执行用例的能力。

❑ 执行 Agent 记录执行步骤并反馈给 LLM。

❑ LLM据此生成 Web 自动化测试脚本。

借鉴这一思路，普通开发测试人员使用通用 LLM 也能完成 Web 自动化测试脚本生成。下面以一个具体案例探讨。

本案例使用的环境与工具：

❑ 开发语言：Java

❑ 测试框架：Selenium、Junit

❑ 测试工具：ChromeDriver、Edge WebDriver

❑ 代码编辑器：IntelliJ IDEA

❑ LLM：OpenAI-ChatGPT

Web 测试依赖浏览器及其驱动，通过模拟用户行为检查应用响应。利用 LLM 生成脚本的四个关键点：

❑ Web 应用功能说明：提供功能描述，让 LLM 理解测试目的与预期结果。

❑ 测试要点描述：用自然语言说明不同操作下预期的响应，作为通过标准。

❑ 前端 UI 代码或组件的 XPath：提供定位信息，LLM 才能定位组件并模拟操作。

❑ 浏览器与驱动：明确浏览器及驱动，LLM 才能编写启动浏览器的脚本。

### 5.2.4 移动 App 自动化测试脚本

移动 App 测试是保障应用质量的关键。随着移动设备普及，自动化测试需求持续增长，业界已沉淀了丰富经验与工具^([7])。主流工具与实践：

❑ Appium：最常用的开源移动应用自动化测试工具，支持跨平台，兼容多种语言与框架。

❑ Espresso：Google 推出的 Android 测试框架，轻量快速，适合 CI/CD，白盒测试为主。

❑ 跨设备测试：不同屏幕尺寸、系统版本、硬件性能会影响表现，跨设备测试保证一致性。

❑ 用户体验测试：结合自动化与体验指标如响应时间、流畅度，保证功能正确且体验良好。

这些方法在移动开发测试中广泛应用，但脚本编写与维护仍需人工介入。因此可利用 LLM 从脚本自动生成角度提升效率。下面以具体案例说明如何借助 LLM 生成移动 App 自动化测试脚本。
