栈底的位置始终固定，而栈顶会随着入栈与出栈不断变动，类似叠盘子，最底层的盘子就是栈底，最后放上的盘子正好在栈顶。

**3.栈与链表的区别**
栈属于抽象数据类型，核心在于后进先出的访问规律；链表则是具体的存储结构，用来存放并组织数据。实现栈时，既可以借助链表，也能借助数组。

**14.2.3 队列**

**1.了解队列**
队列的应用面很广，比如任务排程、消息投递等场景。凭借先进先出的特点，它能确保处理顺序与进入顺序保持一致。

**2.队列的概念**
队列是线性表的特例，遵循先进先出 FIFO 规则。主要操作有入队 enqueue 和出队 dequeue：入队把新元素放到队尾，出队把元素从队头取出。操作只发生在两端，添加在尾部，移除在头部，见图 14-4 所示。

先进先出 FIFO 原则意味着最早进入队列的元素会最先离开。

队头对应最早进入的元素，队尾对应最近进入的元素，类似食堂排队，先来的人站在前面先打饭。

**3.队列与栈的区别**
队列按 FIFO 运行，先进先出；栈按 LIFO 运行，后进先出。两者擅长的场景不同，队列适合顺序化处理，栈适合处理嵌套、回溯类问题。

**14.3.1 树**

**1.了解树**
树能很好地表达层级关系，用途广泛。如文件系统里文件夹与文件的层级就是树状组织，借助树可以快速管理和检索。在编程里，树还能帮助优化算法，提升效率。

**2.树的概念**
树是非线性结构，由节点和连接它们的边构成。树包含唯一根节点，其余每个节点都有且仅有一个父节点，同时可拥有零个或多个子节点，如图 14-5 所示。树中不会出现环路。

（1）节点。树里每一个基本单元。
（2）边。用来连结两个节点的连线。
（3）根节点。树中没有父节点的唯一节点。
（4）子节点（或称孩子节点）。直接隶属于某节点的下级节点。
（5）叶子节点。没有子节点的终端节点。
（6）高度。根到最远叶子所经过边的最大数量。在图 14-5 中树的高度为 2。
（7）深度。节点到根之间经过的节点数，根的深度计为 0。在图 14-5 中①的深度为 0，②、③、④的深度为 1，⑤、⑥、⑦、⑧的深度为 2。

**3.常见的树类型**

（1）二叉树。二叉树是每个节点最多有两个子节点的树形结构，通常左子先于右子插入，子节点允许为空。
（2）二叉搜索树。二叉搜索树是一种常用的数据结构，是一棵二叉树，其中每个节点都包含一个可比较的键 key 和一个对应的值 value。对于每个节点，它的左子树中的所有键都小于该节点的键，而右子树中的所有键都大于该节点的键。这个特性使得查找、插入和删除操作都可以在较短的时间内完成。

**4.树的存储结构**
1）双亲表示法
用数组存放各节点，每个元素记录自身数据和父节点在数组中的下标。
这种表示方法的优点是可以很方便地找到一个节点的唯一双亲节点，缺点是要查找一个节点的子节点时，需要遍历整个数组，查看哪些节点的双亲节点索引值等于该节点在数组中的索引值。

2）孩子表示法
为每个节点配一个链表来保存其全部子节点。其优点是可以很方便地找到一个节点的所有子节点，只需遍历该节点对应的孩子链表即可。其缺点是查找一个节点的双亲节点比较困难，需要遍历所有节点的孩子链表，查看是否有指向该节点的子节点，时间复杂度较高。

**14.4 哈希表与集合初探**

**14.4.1 哈希表**

**1.了解哈希表**
处理大数据时，传统线性查找效率不高。哈希表能把查找复杂度降到接近 O 1，大大提高了数据处理的效率。

**2.哈希表的概念**
哈希表，也称为散列表，是一种根据键 Key 直接访问内存存储位置的数据结构。它通过哈希函数将键映射到一个固定大小的数组索引上，这个数组就是哈希表的存储区域。

**3.哈希函数**
哈希函数是哈希表的核心，它的作用是将键转换为数组的索引。常见的哈希函数有除法哈希法、乘法哈希法等。一个好的哈希函数应该具备以下特点。
（1）均匀性。能够将键均匀地映射到数组的各个位置，减少哈希冲突的发生。
（2）高效性。计算速度快，不会成为哈希表操作的瓶颈。
（3）确定性。对于相同的键，哈希函数应该返回相同的索引。

**4.哈希冲突及处理方法**
哈希冲突是指不同的键通过哈希函数映射到了相同的数组索引上。常见的哈希冲突处理方法如下。
（1）开放寻址法数组。当发生冲突时，通过一定的规则如线性探测、二次探测在数组中寻找下一个可用的位置。
（2）链地址法链表。在每个数组位置上都维护一个链表，当发生冲突时，将冲突的元素插入对应的链表中。

**14.4.2 集合**

**1.了解集合**
集合是一种不允许有重复元素的逻辑结构，可以进行交、并、差等运算。在解决很多实际问题时，如数据去重、元素查找等，集合都有广泛的应用。

**2.集合的概念**
集合是由一组唯一的元素组成的数据结构。集合中的元素没有特定的顺序，并且每个元素都只出现一次。

**3.集合与哈希表的关系**
集合可以使用哈希表作为存储结构来实现。在哈希表中，键就是集合中的元素，值可以是一个占位符如布尔值 true。通过哈希表的快速查找特性，集合可以高效地进行插入、查找和删除操作。

**14.5 算法初探**

**14.5.1 枚举算法和递推算法**

**1.了解枚举算法思想**
在解决很多问题时，我们无法直接找到问题的解，但可以确定问题的解的可能范围。枚举算法通过遍历这个范围内的所有可能情况，逐一检查是否满足问题的解的判定条件，条件满足的情况即为问题的解。它是一种简单、直接的算法思想，适用于问题规模较小的情况。

**2.了解递推算法思想**
递推算法适用于问题的解可以由前面的解逐步推导出来的情况。通过建立递推关系，我们可以利用已知的初始条件，逐步计算出后续的解，避免了重复计算，提高了算法的效率。

**3.枚举算法与递推算法的比较**
（1）枚举算法和递推算法都是解决问题的基础算法思想，在解决某些问题时可以结合使用。例如，在解决一些递推问题时，可能需要枚举一些参数来确定递推的起始条件或递推关系。
（2）枚举算法是通过遍历所有可能的情况来寻找解，不依赖于之前的计算结果；递推算法则是根据已知的初始条件和递推关系，逐步计算出后续的解，每一步的结果都依赖于上一步。

**14.5.2 排序算法**

**1.冒泡排序**
冒泡排序是一种简单的比较排序算法，重复地遍历要排序的数列，一次比较两个元素，如果它们的顺序错误就把它们交换过来。这个算法名字的由来是因为越小的元素越会经由交换慢慢浮到数列的前端，就像气泡一样向上冒。冒泡排序算法的特点如下。
（1）稳定。冒泡排序是稳定的排序算法，即相等元素在排序后顺序不变。
（2）原地排序。只需要常数级别的额外空间。
（3）自适应。可以检测到输入数组是否已经排序完成。

**2.选择排序**
选择排序是一种简单、直观的比较排序算法。它的工作原理是，首先在未排序序列中找到最小或最大元素，将其存放到排序序列的起始位置，再从剩余未排序元素中继续寻找最小或最大元素，然后将其放到已排序序列的末尾。选择排序算法的特点如下。
（1）不稳定。选择排序是不稳定的排序算法，即相等元素在排序后顺序可能改变。
（2）原地排序。只需要常数级别的额外空间。
（3）交换次数少。最多进行 n-1 次交换。

**3.插入排序**
插入排序是一种简单、直观的比较排序算法，它的工作原理类似于我们整理扑克牌的过程。对于未排序的元素，在已排序序列中从后向前扫描，找到相应位置并插入。插入排序算法的特点如下。
（1）稳定。插入排序是稳定的排序算法。
（2）原地排序。只需要常数级别的额外空间。
（3）自适应。对部分有序的元素效率很高。

**14.5.3 查找算法**

**1.顺序查找**
顺序查找是最基础、最简单的查找算法，也称为线性查找。它不要求数据有序，从数组的第一个元素开始，逐个与目标元素进行比较，直到找到目标元素或遍历完整个数组。顺序查找的适用场景如下。
（1）数据量很小。
（2）数据经常变动，无法维持有序。
（3）只需要偶尔查找一次。

**2.二分查找**
二分查找的效率比顺序查找高得多。它要求数据必须是有序的，通过不断地将查找区间缩小一半，快速定位目标元素。

其算法原理是将数组分成两个部分，比较中间元素与目标元素的大小，如果中间元素等于目标元素，则查找成功，如果中间元素大于目标元素，则在左半部分继续查找，如果中间元素小于目标元素，则在右半部分继续查找。二分查找的适用场景如下。
（1）数据量较大。
（2）数据基本为静态的，不经常修改。
（3）需要频繁进行查找操作。
（4）对查找性能有较高要求。
