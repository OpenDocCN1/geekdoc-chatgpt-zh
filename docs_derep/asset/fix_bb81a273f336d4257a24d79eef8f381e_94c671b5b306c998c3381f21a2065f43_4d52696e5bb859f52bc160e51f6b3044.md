# **第十四章 OpenClaw 联动 NotebookLM 构建第二大脑**

在信息爆炸的背景下，文章、PDF 报告、研究报告每天都在累积，如何高效归档、检索与内化成为知识工作者的关键痛点。Google 的 NotebookLM 以长文本处理能力和基于源文档的精准问答著称，是知识管理的优质工具。

本章介绍如何将 OpenClaw 与 NotebookLM 深度融合，搭建自动化的“数字第二大脑”。用户只需在飞书发送文档链接，OpenClaw 即可自动写入 NotebookLM，并在需要时提供基于专属知识库的精准检索。

## **14.1 需求与架构拆解**

传统知识管理多靠手动复制粘贴或繁琐标签分类，效率低且检索困难。为此，数字第二大脑要实现三大核心能力，兼顾无感收集与智能检索。

• 无感收集：用户在飞书发送网页链接或 PDF 时，Agent 自动抽取内容并作为新数据源加入指定 NotebookLM 笔记本，无需人工分类或打标签。
• 智能检索：用户在飞书提问时，Agent 直接向 NotebookLM 发起查询，返回基于个人知识库的准确答案，有效遏制大模型的幻觉问题。
• 节省 Token 成本：动辄数十万字的 PDF 若直接由 OpenClaw 读取分析会消耗大量 Token，而 NotebookLM 提供免费文档处理能力，作为外部知识引擎性价比很高。

架构上，NotebookLM 官方尚未开放 REST API，本章采用社区基于 MCP 的集成方案，使用 openclaw-notebooklm 开源包。它通过浏览器自动化或逆向 API，为 OpenClaw 提供标准 MCP Server 服务。

## **14.2 核心能力与 MCP 服务搭建**

本场景不再使用传统 ClawHub 技能，而是采用 MCP Server。MCP 是 OpenClaw 支持的标准协议，可让 Agent 与本地运行的外部独立服务安全双向通信。

### **14.2.1 部署 openclaw-notebooklm**

在宿主机终端执行以下命令安装社区集成包：

pip install openclaw-notebooklm

openclaw-notebooklm-install

该一键脚本会自动处理依赖，并引导完成 Google 账号授权登录，同时在后台启动专用于 NotebookLM 通信的 MCP Server。

安装完成后，脚本会生成一个 NOTEBOOKLM_SESSION_TOKEN，请妥善保存，后续配置会用到。

### **14.2.2 MCP 服务配置**

为便于管理多个 MCP 服务器或设置复杂环境变量，手动编辑配置文件更灵活，涉及两个核心文件：定义服务器的 mcporter.json 和启用关联服务的 openclaw.json。

先配置 mcporter.json。用户目录下找到 .mcporter 文件夹中的 mcporter.json，若不存在可手动创建。按 mcpServers 格式列出所需服务器，为每个服务器指定启动命令、参数和环境变量。command 与 args 告知 OpenClaw 如何启动服务，env 用于设置密钥。

{
  "mcpServers": {
    "notebooklm": {
      "command": "python3",
      "args": ["-m", "openclaw_notebooklm.server"],
      "env": {
        "NOTEBOOKLM_SESSION_TOKEN": "YOUR_SESSION_TOKEN" // 安装脚本生成的 Token
    }
  }
}

再配置 openclaw.json。用户目录 .openclaw 下的 openclaw.json 中找到 skills 部分，添加或修改 mcporter 配置。

关键是通过 env 中的 MCPORTER_CONFIG 变量，将上一步 mcporter.json 的完整路径告知 OpenClaw。

保存后务必重启 OpenClaw Gateway，重启命令为 openclaw gateway restart。

{
  "skills": {
    "entries": {
      "mcporter": {
        "enabled": true,
        "env": {
          "MCPORTER_CONFIG": "~/.mcporter/mcporter.json"
        }
      }
    }
  }
}

### **14.3.2 创建 Knowledge Agent 工作空间**

在生成的 ~/.openclaw/workspace-knowledge/SOUL.md 中明确 Agent 对 NotebookLM 相关 MCP 工具的使用规则，内容如下：

# 角色定义

你是用户的“数字第二大脑”专属管家。核心职责是帮助用户无感收集高价值信息，并在提问时基于专属知识库提供精准可靠解答。

## 核心原则

- 你的记忆和知识完全依赖 NotebookLM。回答专业问题或查询过往资料时，绝不能使用自身预训练知识，必须强制查询 NotebookLM。
- 所有回答必须有理有据，严禁产生幻觉。

## 工作流准则

### 场景 1：信息收集

- 当用户在飞书发送网页链接、文本片段或 PDF 并要求“存入知识库”时，必须调用 notebooklm MCP Server 提供的 add_source 工具。
- 将内容添加到名为 My Second Brain 的笔记本中。
- 添加成功后回复确认，例如：“✅ 已成功将该资料存入你的 NotebookLM 知识库。”

### 场景 2：知识检索与问答

- 当用户提问如“根据我之前存入的资料，XXX 是什么？”时，必须调用 notebooklm MCP Server 提供的 query_notebook 工具，向 My Second Brain 笔记本发起查询。
- 仔细阅读返回结果，整理成逻辑清晰、结构严谨的回答。
- 回答末尾必须附上信息来源，例如：“（来源：《2026 年 AI 行业报告》）”，以确保可靠性。
- 若 NotebookLM 返回“未找到相关信息”，必须如实告知用户知识库无相关记录，绝不自行编造答案。
