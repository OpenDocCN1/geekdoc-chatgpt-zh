多模态 RAG：从文本检索走向全感官理解

落地门槛不低，但多模态检索增强生成的实际收益已经显现。系统能就图片提出的问题给出基于外部知识的深度阐释，真正实现图像问答；也能做跨模态创作，比如按图意调取相关文献，或由文字驱动自动生成配图和音轨；检索形态也被重塑，出现图搜文、声搜图的混合交互，让知识库的触达方式更灵活直观。

要把这些能力稳定引入生产，尤其是金融、医疗等对严谨性要求极高的场景，必须建立系统化的评测闭环，能明确判断模型输出是建立在正确召回内容之上，还是无中生有。目前 TruLens 等工具已支持多模态 RAG 的评估实践，可追踪数据流、核验召回相关性并评价生成质量，是走向成熟不可或缺的一环。

一套典型架构由三部分协同运转。

**·** 多模态检索器：从融合文本、图像、音频的知识库中定位最相关素材。常用 CLIP 这类多模态嵌入模型把异构数据投到同一向量空间，再借助多模态向量库完成高效召回。

**·** 多模态生成器：接收召回的多模态上下文，产出符合需求的答案。可选用能直接处理多模态输入的大模型，也可由文本生成、文生图、文生语音等专用模型协同完成。

**·** 数据融合与对齐模块：作为系统神经中枢，负责在语义层面统一不同模态的信息。通过共享嵌入空间与注意力机制实现跨模态特征的深度融合与对齐，为生成提供一致的上下文表征。

总体看，多模态 RAG 标志着检索增强从单一文本处理向理解真实世界多元信息迈进。通过攻克异构数据的召回、对齐与融合难题，它拓展了传统 RAG 的能力边界，也为更智能更直观的新一代人机交互奠定基础。

## 9.4　进阶 RAG 技术

本节归纳几种进阶的检索增强方法，包括上下文检索、缓存增强生成、知识图谱 RAG 等。

### 9.4.1　上下文检索

传统 RAG 把文档切成独立片段时，背景信息丢失常致召回失效。例如查询某企业 2023 年第二季度营收增速，系统可能只返回“收入比上季度增长 3%”这样孤立的句子，企业名、时间等关键背景缺失，信息便失去意义。

Anthropic 团队提出的做法是通过重构片段表示来弥补。核心理念是在嵌入与索引前，为每个片段补充一段结构化背景摘要。比如把上述句增强为：“[来源：某公司 2023 年第二季度 SEC 财报。上文提及：上季度收入为 3.14 亿美元。] 公司的收入比上一季度增长了 3%”。如此每个片段在语义上都变成可自洽独立理解的信息单元。

实现上依赖两类子技术协同。

**·** 上下文嵌入：对带背景摘要的片段生成语义向量，提升语义召回的准确度。

**·** 上下文 BM25：在增强后的片段上建倒排索引，保证关键词的精确命中。

检索时系统并行跑语义召回与关键词召回，随后去重、融合与重排序，挑选最相关的若干片段供生成。有研究显示该策略可把召回失败率压低 49%；叠加专用重排序器后，失败率还能再降 67%。其价值在于兼顾语义关联的广度与术语匹配的精度，为生成提供更可靠依据。该改进可无缝接入现有 RAG 流程，无需改动核心架构即可明显提升对依赖背景的复杂查询的响应。

### 9.4.2　缓存增强生成

检索增强已成为用定制信息强化大模型的主流路径，但前期建设成本高、响应速度偏慢。随着长上下文模型进步，企业可直接在提示中写入私有信息绕过动态检索。

研究表明，借助长上下文模型与缓存机制，开发者能打造性能优于传统 RAG 流水线的定制应用。这种方案称作缓存增强生成 CAG。在企业场景里，把知识库一次性装入模型上下文窗口即可作为一种简便有效的替代。

CAG 强调预缓存与结构化内部数据，而非实时检索。依托精选缓存可最大化降低延迟、提升生成效率，特别适合数据稳定、领域明确的应用。

主要优势：

**·** 缓存读取减少外部调用带来的延迟。
**·** 架构更简洁，有助于加快上线并降低运维成本。
**·** 减少因外部检索产生的使用费用。

明显劣势：

**·** 缓存集必须细致更新才能保持时效。
**·** 过度依赖预定义数据会制约动态或扩展场景。
**·** 需要可靠的失效与更新机制，这对系统稳定性至关重要。

### 9.4.3　知识图谱 RAG

2024 年 4 月微软发布 GraphRAG，并于同年 7 月 2 日开源。它是对传统 RAG 的重要演进，核心是在理解复杂关联信息上引入知识图谱。传统 RAG 虽高效，但片段孤立难以捕捉实体、关系与属性的深层联系，GraphRAG 正为此而生。

GraphRAG 把非结构化文本转化为结构化图谱。利用大模型从领域文档抽取实体、关系与属性，构建语义连接丰富的网络，图谱可进一步组织为多层多社区结构，系统化揭示知识库中隐含的关联。

检索与提示构建因此被加强。处理查询时，GraphRAG 除召回相关文本片段外，还会从图谱中提取与查询实体直接或间接相关的子图，包含相连实体、关系与属性。这些结构化知识与召回文本共同构成更丰富的上下文输入模型生成答案。

相比传统方案，GraphRAG 呈现三点提升。

**·** 解释性更强：图谱提供清晰的实体关系路径，使回答可追溯逻辑结构，可信度增强。
**·** 回答更全面深入：借助图谱推理可提供超越直接匹配的关联信息与深层分析。
**·** 擅长复杂查询：面对需串联多文档或概念的问题，图谱的网络特性能连接分散信息点，传统方案易因片段孤立而遗漏关键关联。

总之 GraphRAG 并非替代 RAG，而是对检索能力的结构化升级。它赋予模型更强的全局理解与关系推理能力，在复杂领域知识任务上显著提升准确性、可靠性和深度，是 RAG 发展的重要方向。

### 9.4.4　代理 RAG

代理 RAG 的核心是在检索增强的各环节引入 AI 智能体，主要流程如下：

（1）**查询重写**。智能体对用户输入进行改写，如修正拼写错误。

（2）**额外信息获取**。智能体判断是否需要补充信息，若需要则通过搜索引擎或调用工具获取。

（3）**内容检查**。生成后智能体会校验答案的相关性与有效性，不符合要求则回退到第一步修改查询并继续迭代，直至找到相关内容或告知用户问题无法解答。

在传统 RAG 基础上，代理式方案强调自主决策与动态交互，能处理复杂对话、多轮交互并动态调整检索策略，满足更复杂的用户需求，也是未来智能体研发的重要基础思路。

不过相比传统 RAG，代理 RAG 成本更高、耗时更长，更适合复杂对话系统与虚拟助手等场景。随着模型成熟与生态完善，代理 RAG 有望成长为基础设施级能力，甚至直接内嵌到基础大模型成为核心功能。

### 9.4.5　多模态 RAG

传统检索增强在降低幻觉方面已有进展，但仅依赖文本，难以利用文本、图像、视频等丰富数据。现实中人类常融合多种模态理解信息，如浏览网页时结合文字、图片与视频。

多模态 RAG，即 Multimodal Retrieval-Augmented Generation，MRAG，通过扩展框架把多模态数据纳入召回与生成，提升问答质量并因事实基础更广而减少幻觉。

核心目标是将跨模态上下文融入召回与生成，以提升问答、创作与搜索的覆盖面与准确率。目前研究仍在发展中，仍有若干难题。

首先是数据异构性，文本、图像、音频结构迥异难以统一处理。其次是跨模态对齐，如图文匹配、音画同步需要精细时空关联。最后是语义融合，需借助 CLIP 等多模态预训练模型把不同模态映射到统一语义向量空间，才能进行联合召回与推理。

尽管有挑战，价值已经清晰。系统可结合外部知识对图像进行深度解读，实现视觉问答；可按图意召回文献，也可由文字生成配图与音乐；检索方式被彻底改写，图搜文、声搜图等混合模态检索极大增强知识库交互灵活性。

在金融、医疗等高严谨场景落地，必须有系统化评估以确认模型是否基于正确召回内容生成，而非虚构。目前 TruLens 等工具已提供多模态 RAG 的评估支持，用于追踪数据流、验证召回相关性及评价生成质量，是走向成熟的关键环节。

典型架构包含三部分协同工作：多模态检索器负责从混合库中定位文本、图像、音频相关信息，多依赖 CLIP 等嵌入模型与多模态向量库；多模态生成器接收召回上下文生成答案，可为单一模型或多专模型协作；数据融合与对齐模块作为中枢，通过共享嵌入空间与注意力机制实现跨模态特征深度融合，为生成提供一致上下文表征。

总体而言，多模态 RAG 代表 RAG 技术从处理单一文本向理解丰富现实世界的关键一步。通过解决异构数据的召回、对齐与融合难题，它不仅拓展传统 RAG 的能力边界，也为构建更智能、更直观的新一代人机交互系统奠定技术基础。
