## 核心工具：标准库 `json` 模块

Python内置的 `json` 模块提供了四大核心函数，实现原生对象与JSON文本的双向转换：
*   **序列化（编码）**：`dump(obj, fp)` 写入文件流；`dumps(obj)` 返回字符串。
*   **反序列化（解码）**：`load(fp)` 从文件流读取；`loads(s)` 从字符串解析。

## ⚠️ 安全警示：远离 `pickle` 陷阱

标准库 `pickle` 虽能序列化任意复杂Python对象，但**官方文档明确警告**：
1.  **极高风险**：反序列化不可信来源的pickle数据可导致**任意代码执行**（RCE）。网络传输场景下**严禁**直接 `loads` 外来pickle流；仅限本地受信文件且确保无他人篡改时使用。
2.  **生态封闭**：pickle是Python专有协议，**无法跨语言通信**。

**结论**：遗留代码中虽常见，但新项目**坚决不推荐**使用pickle，首选JSON或MessagePack等安全中立格式。

## 文件操作备忘录：模式与方法

### 打开模式速查表

| 模式 | 行为说明 |
|------|----------|
| `'r'`  | 只读（默认），文件不存在抛 `FileNotFoundError` |
| `'w'`  | 只写，**清空**现有内容或新建 |
| `'a'`  | 追加写，文件不存在则新建，数据写入末尾 |
| `'r+'` | 读写兼备，文件必须存在 |
| `'w+'` | 读写兼备，**清空**现有内容或新建 |
| `'a+'` | 读追加兼备，文件不存在则新建 |

> 二进制模式只需在上述字母后加 `b`（如 `'rb'`, `'wb+'`），处理图片、音视频、压缩包等非文本文件时必用。

### 常用文件对象方法

*   `read(size=-1)`：文本模式返回字符串，二进制模式返回 `bytes`；省略参数读全文。
*   `readline()`：逐行读取，保留末尾换行符，EOF返回空串。
*   `writelines(iterable)`：批量写入字符串序列，**不自动添加换行**。

底层实现细节可参考 `io` 模块官方文档。

## 异常处理：让程序在错误中“存活”

文件操作、类型转换、数学运算均可能触发异常，常见类型包括：
*   `FileNotFoundError`：读模式打开不存在文件。
*   `PermissionError`：无权限访问/创建文件（如系统目录）。
*   `ValueError`：向已关闭文件写入，或 `int('hello')` 类型转换失败。
*   `ZeroDivisionError`：除数为零。

#### 结构拆解
1.  **`try` 子句**（第6-9行）：包裹“高风险”代码块。
2.  **`except` 子句**（第10-13行）：可堆叠多个，按顺序匹配异常类型；匹配成功执行对应处理逻辑（如打印提示）。
3.  **`else` 子句**（第14-16行）：**仅当 `try` 块零异常时执行**——本例中输出结果并 `break` 退出循环。

#### 控制流深度解析

**场景 A：用户输入 `100 / 0` 触发 `ZeroDivisionError`**
1.  第7、8行正常获取输入。
2.  第9行执行除法，**抛出异常**，`try` 块**即刻终止**，后续代码不再执行。
3.  解释器自上而下检索 `except`：
    *   第10行捕获 `ValueError` → **不匹配** → 跳过。
    *   第12行捕获 `ZeroDivisionError` → **命中** → 执行打印提示。
4.  异常处理完毕 → 无 `finally` → 直接进入 `try` 后的代码（本例即循环下一轮）。
> **关键点**：**不会**返回异常抛出点（第9行）继续，而是彻底离开 `try` 结构。

**场景 B：用户输入 `100 / hello` 触发 `ValueError`**
1.  第8行 `int('hello')` 直接抛出 `ValueError`。
2.  首个 `except ValueError` 匹配成功，打印提示。
3.  同理，循环继续，给用户重试机会。

---

> **最佳实践提示**：`else` 子句将“正常业务逻辑”与“异常防护逻辑”物理隔离，避免在 `try` 块过大时误捕非预期异常，代码更健壮、可读性更强。
