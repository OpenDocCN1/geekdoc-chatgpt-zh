LangGraph 工作流拆解与实践

在 LangGraph 的设计思路里，任何能够独立完成一段可执行逻辑的单元都被视作图中的一个单元，涵盖大模型推理、外部检索、流程判断等多种形态。流程的起点通常是 Start 单元，它先汇聚用户输入，再按需求分发任务。最简走向一般是：

- 先触发动作类单元去做外部查询，比如网络搜索、数据库读取或 RAG 检索；
- 再把查到的资料送给负责语言建模的 LLM 单元，让它产出自然语言回复；
- 最后把回复交给 End 单元，结束整条链路。

图 8.13 展示的就是用 LangGraph 概念搭建的最小智能体雏形。每块圆圈代表一个单元，每段连线代表流程控制用的连接线；上下文信息则是沿着连接线以消息形式流动并持续更新。

因此无论智能体多么复杂，本质都是若干单元和连接线按特定方式组合成的图。工作流的核心是消息分发：一个单元完成任务后，会通过连接线把信息推送给下一个单元，后者收到后执行并继续转发，如此循环。换句话说，LangGraph 的底层消息分发机制让程序呈现出一个通用执行范式：单元完成操作即向相邻单元发送消息，被动方处理后再转发，最终形成闭环。

##### 3. 条件分支与路由决策
现实使用中，智能体不会沿固定路径直线行进，通常需要判断是否要调用工具、调用哪一个工具、还是直接给出答案。下面给出一个更贴近实际的例子。

这里把 AI Agent 设为应用的起点。没有工具的 Agent 能力有限，因为即使用复杂的提示词也能让推理模型如 OpenAI 的 o1 直接思考作答。一旦配备工具，Agent 就通过函数调用来使用它们，而不是自行执行。用户问题进入 Agent 后，大致会出现两种结果。

1）不需要工具时，Agent 直接给出自然语言回答。例如：
用户：你好，请介绍一下你自己。
AI Agent：你好，我是一个人工智能助手，可以帮你解决问题。

图 8.14 展示经过首个 Agent 单元后，若模型判定需要调用函数，就要确定用哪一个工具、带哪些参数。当可选工具不止一个时，动作单元会出现多条可能路径。如何挑选？LangGraph 提供了条件连接线这一机制，它依据条件是否满足来选择走向，比如决定走搜索工具还是直接生成答案。为此引入了类似 if-else 的 Router 结构。基于路由决策，Agent 可能被导向 Web Search 单元执行搜索并返回原始文本，也可能直达 End 单元生成格式化回复。若走搜索分支，得到的文本还需经另一轮大模型处理才能变成用户可读的答案；若走直接回答分支，则可用专用工具做输出格式化。

在 LangGraph 体系中，Router 以 if-else 的形式决定路径，主要有三种实现手段。

- 提示工程：通过指令让大模型以约定格式回应；
- 输出解析器：对模型返回做后处理，抽取出结构化数据；
- 工具调用：借助大模型的内置工具调用能力生成结构化输出。

##### 4. 公共状态机制
我们已知道 LangGraph 用单元和连接线组合出复杂的循环流程，并靠消息传递把各个单元串联起来。让消息及时更新并送到正确位置的，则是 State 这一概念。每次运行都会创建一份上下文容器，单元在处理时读取并修改它。该容器不是静态快照，而是被各单元输出动态改写，进而影响循环中的后续行为，如图 8.15 所示。

共享状态指的是图执行期间单元间传递的数据与信息。LangGraph 允许单元在执行时读写同一个公共容器来交互。这种机制让单元能够基于共同维护的数据通信、交换信息并互相影响，从而实现操作的协调与同步，支撑动态交互和复杂工作流的构建，单元可以依据已有的共享信息协同决策。

##### 5. 官方定位与优势归纳
按官方说法，LangGraph 是一个用于构建有状态、多参与者的大模型应用的库，可用来创建智能体与多智能体工作流。官方归纳的优势如下。

- 循环与分支：可在应用中实现循环和条件判断；
- 持久化：每个步骤执行后自动保存状态，支持随时暂停恢复，用于错误恢复、人机协作流程、时间旅行等；
- 人机交互：可在执行中中断以便人工批准或编辑 Agent 下一步计划；
- 流式输出：各单元均可产生流式输出，包括 token 流；
- 与 LangChain 集成：与 LangChain 及 LangSmith 无缝衔接。
