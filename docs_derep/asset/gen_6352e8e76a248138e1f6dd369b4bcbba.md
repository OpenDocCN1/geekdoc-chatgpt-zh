## 6.7 十分钟实战：集成Stripe实现完整的付费流程

现在给积分系统接入商业级支付能力。通过 Stripe 这类行业标准支付平台，可以快速搭建起自动化的付费闭环。

### 6.7.1 Stripe产品与价格配置

在 Stripe 后台以声明式方式创建商品，全部可视化操作，无需写代码，具体流程如下。

1. 登录 Stripe 账号，确保处于 Test Mode 测试环境。
2. 进入 Products 商品目录。
3. 新建商品与服务。先建两个订阅商品，分别是“爱好者套餐”和“专业套餐”，分别挂上每月 10 美元、25 美元的循环价格；再建一个一次性商品，命名为“积分包”，挂上 5 美元的一次性价格。
4. 填写 Metadata 元数据。这是打通 Stripe 商品与自家积分系统的关键。为每个 Price 价格项添加自定义元数据：
- 爱好者套餐：key 为 credits，value 为 100。
- 专业套餐：key 为 credits，value 为 500。
- 积分包：key 为 credits，value 为 50。

支付成功后的 Webhook 会读取这些元数据来自动充值。配置汇总见表6-3。

### 6.7.2 支付流程集成

参考 Vercel 官方 Next.js + Supabase + Stripe 订阅模板的最佳实践，集成步骤如下。

1. 创建结账会话。新建 API 路由 `app/api/stripe/create-checkout-session/route.ts`。用户点击购买时，前端调用接口并带上选择的 price_id，后端在 Stripe 中创建或查找客户对象 customer，随后用 Stripe Node 客户端创建结账会话，并把 session_id 回传前端。
2. 跳转到 Stripe 结账页。前端拿到 session_id 后，使用 Stripe.js 的 `redirectToCheckout` 把用户带到 Stripe 托管的支付页。所有敏感支付信息由 Stripe 处理，应用服务器不接触，大幅降低 PCI 合规成本。
3. 处理支付结果。后台在 Stripe 仪表盘配置 Webhook，指向 `app/api/webhooks/stripe/route.ts`，重点监听 `checkout.session.completed` 事件。支付成功后 Stripe 会 POST 事件详情到该地址，后端据此为用户充值积分。

### 6.7.3 积分自动充值系统

Stripe Webhook 处理器是自动充值的核心，收到 `checkout.session.completed` 时按如下流程执行。

1. 验证 Webhook 签名。首要安全步骤，使用从 Stripe 仪表盘获取的签名密钥校验请求头中的 `Stripe-Signature`，确保请求来源真实完整。
2. 解析事件数据。安全提取事件里的 `stripe_customer_id` 以及所购价格信息。
3. 读取积分数量。从价格对象的 `metadata.credits` 中取出预设的积分值。

## 6.8 十分钟实战：使用Resend构建邮件营销系统

一个成熟的 SaaS 不仅功能强，还需要在关键节点主动触达用户。借助开发者友好的邮件 API Resend，可以打造智能自动化的邮件通信体系。

### 6.8.1 自动化用户生命周期邮件

基于 Supabase 与 Resend 覆盖注册到订阅全链路的三类自动化邮件：

- **注册欢迎邮件：** 在 Supabase 里对 `auth.users` 表建触发器，新增用户时自动调用边缘函数，通过 Resend SDK 发出欢迎邮件。
- **注册后使用指南邮件：** 利用 Supabase 内置的 `pg_cron` 定时扩展，每天跑一次，筛选注册满三天的用户，推送包含进阶技巧的指南邮件。
- **订阅续费提醒邮件：** 同样用 `pg_cron` 每日任务查询即将到期的有效订阅，调用边缘函数在续费日前三天发送提醒，降低非主动流失。

### 6.8.2 异步任务完成通知邮件

像 AI 图像生成这类异步功能，用户提交后需要等待结果。邮件通知是提升体验的最好方式，可直接集成到 Replicate Webhook 处理路由 `/api/webhook/replicate`。

当收到生成成功回调且图片已保存到 Supabase Storage 后，在完成数据库写入前，增加一步：调用 Resend API 发送通知邮件，主题类似“你的 AI 作品已生成”，正文可带缩略图预览和直达个人作品页的链接。

### 6.8.3 用户行为触发式营销邮件

邮件系统还能做进阶营销自动化，根据行为精准触达。例如低积分提醒与促销，当用户剩余积分低于阈值如 5 分时自动触发个性化邮件。

实现上可在每次积分扣除的 Supabase 边缘函数里加入余额检查，若低于阈值则调用另一个边缘函数，通过 Resend 发送含个性化文案与优惠的邮件，刺激用户回充。

接入 Resend 后，应用从被动响应工具变为能主动沟通的平台，用户体验与商业目标更紧密结合。

## 6.9 十分钟实战：用Vercel部署并配置生产环境

本地开发完成，进入线上部署阶段。用 Vercel 部署 Next.js 项目可获得高度集成的无缝体验。

### 6.9.1 环境变量配置

在 Vercel 项目的环境变量设置里，逐一填入本地 `.env.local` 中的所有密钥与配置：

- Supabase 的 URL、ANON_KEY、服务端的 SERVICE_ROLE_KEY；
- Replicate 的 API_TOKEN；
- Stripe 的 SECRET_KEY 和 WEBHOOK_SECRET；
- Resend 的 API_KEY。

这样变量会在构建与运行时安全注入，避免敏感信息泄露到代码仓库。

### 6.9.2 域名绑定与SSL证书

在 Vercel 项目的 Domains 页面添加已购的自定义域名，按 Vercel 给出的 DNS 记录，通常是 A 记录或 CNAME，前往域名注册商后台配置。DNS 生效后，Vercel 会自动申请、配置并续期免费的 Let's Encrypt SSL 证书，实现全站 HTTPS，无需手动干预。

### 6.9.3 性能优化

Vercel 自带多项性能优化，无需额外配置：

- **全球边缘网络：** git push 触发部署后，应用会分发到全球边缘节点，用户自动就近访问，显著降低延迟。
- **图像优化：** Next.js 的 `<Image>` 组件与 Vercel 网络深度集成，展示 Supabase Storage 图片时会自动做格式转换、尺寸缩放并缓存到全球 CDN。
- **边缘函数：** 所有 Next.js API 路由如 `/api/generate-image`、`/api/webhook/*` 以及服务端组件的数据获取逻辑，都被部署为高性能边缘函数，后端逻辑同样靠近用户，API 响应更快。

Vercel 把繁琐的基础设施运维抽象掉，让开发者聚焦产品本身。
