# 第2章 实战起点：设计驱动 Agent 的 Prompt

AI 对话很流畅却常在执行任务时出错，差距就出在 Prompt 设计上。聊天式 Prompt 重信息传递，执行式 Prompt 需要任务规划、工具调用和状态管理。接下来介绍如何设计驱动智能体完成实际工作的 Prompt，涵盖基本原则、实用模板及多智能体协作，构建完整的 Prompt 工程体系。掌握这些方法能把 AI 从聊天伙伴变为工作伙伴，为后续开发打下基础。

### 2.1 超越聊天：面向执行的Prompt设计原则

#### 2.1.1 明确意图、约束与结构化输出

设计可靠的 AI 工作伙伴，关键在于指令设计。简单的对话提问类似对新人含糊交代，日常聊天或许可容忍，执行任务时会致命。系统因信息不足难以判断需求，导致答案宽泛或偏离。设计执行指令时，先把模糊想法转化为清晰任务，如项目负责人分配工作时需说明主题、读者和格式等。除明确目标外，赋予系统专业角色也很重要，这会影响其处理视角。OpenClaw 等框架中角色常固化在系统提示里。

复杂任务还需引导分步思考。智能系统要把大任务拆解为小步骤，如分析市场趋势时明确先后顺序，便于理解和问题追溯（见图2-1）。

## 人工智能指令设计：构建可靠AI工作伙伴的关键

| 日常聊天（模糊指令） | 严格方法（清晰任务） |
| :--- | :--- |
| 简单对话提问，像对新人含糊交代 | 把模糊想法细化为明确任务，界定主题、受众、格式 |
| 没有角色定位和视角 | 给系统设定专业身份，OpenClaw 中常写入系统提示 |
| 大任务不拆步，系统混乱 | 诱导分步推理，把整体拆成小步，便于回溯 |
| 输出空泛偏差，因缺信息致命 | 结果规范、格式统一、易追溯问题 |

在 OpenClaw 的推理-行动循环里，分步思考会被演绎为“评估现状→执行操作→观察反馈”。每完成一步，系统都会核查实际结果是否达标，再据此调整下一步计划。此机制让智能系统能够应对执行中的不确定性，而非硬走到底。

界定行为边界与设定目标同样重要，是从实验走向实用的安全保障。首先要明确数据边界，限定只能访问指定文件，不能自行搜索或编造信息。OpenClaw 通过工作区权限实现。其次约束操作行为，采用工具白名单，禁止危险操作，对高风险指令设置人工审核。建议在容器环境中运行执行组件，通过隔离防止误操作影响主机。这些措施共同保障安全可靠运行（见图2-2）。

第三类约束用于规范内容风格，要求明确语言风格，如通俗易懂或客观中立。处理隐私、商业机密等敏感信息时需声明处理原则，如对个人身份信息做匿名化。企业环境中的此类约束可确保输出合规，避免法律或声誉风险。

定义清晰的输出格式是第三要素。智能系统产出常为中间结果，需采用机器可读的结构化格式，如 JSON 或 Markdown 表格，便于自动化脚本解析和整合，降低后续处理成本。OpenClaw 生态中的可视化组件要求输出格式一致，技能模块结合固化模板。例如代码审查技能预设报告格式，确保每次执行结果统一，提升一致性和效率（见图2-3）。

## 第三类约束：规范、合规与结构化输出

明确目标、设定约束和定义格式构成可执行指令框架，把随意提问升级为工作规范。OpenClaw 通过系统提示、技能定义和安全环境来实施。掌握这些原则意味着从提问进阶到定义能力，让智能系统从会聊天变为能协作。

#### 2.1.2 设计任务分解与多步骤逻辑

处理复杂工作时拆分为小任务是核心能力。智能体同样需要此能力，若能分解复杂需求并规划执行步骤，就能完成实际工作。任务分解把需求转化为操作序列，例如准备季度汇报可拆为收集数据、分析趋势、撰写文稿和检查格式等，确保产出完整连贯。

在智能体框架中，任务分解采用推理-行动模式，即先思考再行动，每次结果影响后续步骤，形成循环工作流，赋予应对变化的灵活性（见图2-4）。

图 2-4 推理－行动工作模式
