# 聊天话题体系构建方法

上一部分已说明音乐推荐场景下的知识抽取做法，本部分聚焦用户画像构建中的另一项任务，即从对话记录里挖掘用户的聊天偏好。日常闲聊属于开放式对话，覆盖面极广、边界不清晰，很难直接判断个体的兴趣倾向。以用户 A 爱篮球、用户 B 偏二次元为例，如何从海量聊天内容里提炼出这类标签？关键在于对聊天话题进行抽象归纳，把相关的话题关联起来，把相似的话题归并，形成一套完整的话题体系，进而对用户输入进行话题识别并做频次统计，推断出聊天偏好。构建话题体系既能辅助偏好抽取，也为话题的跳转与关联联想提供依据。话题之间普遍存在上下位关系，比如休闲娱乐下可细分为旅游、摄影、K 歌、游戏、阅读等子项。当用户提到旅游时，系统可判定其处于休闲娱乐范畴，并联想到同域的其他话题来组织回复，如图 5-15 所示。

[PRE1]

图 5-15　聊天话题联想示例

下面介绍基于真实日志构建话题体系的思路。整体流程是先从用户日志中挖掘潜在的话题词候选，再对候选词进行聚类得到初步类别特征，随后借助外部知识库补充领域概念，最后整合成话题体系。实质上就是一个话题领域图谱，图谱中的每个节点代表一个话题，节点间存在上下位关系，同一层级的节点保持一定相关度，每个话题都能看作一个概念，可通过外部知识库实现扩展、联想与跳转。每当用户输入一句聊天内容时，先做话题识别，再围绕该话题生成回复，或跳转到相关话题继续对话。具体步骤如下。

* 数据清洗：收集大量用户日志，剔除唤醒词、功能指令等与话题无关的内容。

* 关键词筛选。
  * 先对语料进行分词与词性标注，可并行使用多种工具以获得多视角结果。
  * 为每个词计算 TF-IDF 权重，并训练 LDA 主题模型获取各主题下的关键词集合。
  * 综合词性、TF-IDF 分数以及是否落在 LDA 关键词集合中进行打分。抽取话题时，动词、名词权重更高，形容词、副词次之，助词、代词、介词、数词等价值较低，可过滤掉。

* 话题领域映射。
  * 利用通用百科知识图谱，将关键词映射到图谱中查找对应标签、属性及所属概念，从而抽象出多个话题类别并进行领域划分。

* 剪枝：
  * 依据话题出现频率、所属标签与领域的频率，剔除低频项。

完成上述流程后，可获得一批话题关键词及其标签与概念信息，通过分布统计大致了解用户常与机器人聊什么，进而据此搭建话题体系。搭建完成后还需人工整理与干预，按用户关注范围划分层级，补充同领域的其他话题，以完善整体。图 5-16 给出一个较为完整的话题结构示例，供参考。

# 第 6 章 知识图谱应用

知识图谱的应用是检验构建价值的体现，也是衡量构建质量的黄金标准。第 5 章在构建领域图谱时已涉及底层设计需要覆盖的实体类型与关系属性。本章围绕图谱应用展开，首先介绍较为成熟的知识可视化，随后介绍与语义理解密切相关的实体链接，再介绍业界广泛研究的知识问答，最后探讨前瞻性的联想应用。

## 6.1 知识可视化

知识可视化是将结构化知识以图谱形式呈现。通过可视化能够更直观地传递知识，更方便地挖掘关联，更友好地与用户交互。按是否内置 Neo4j 连接，可将工具分为内置 Neo4j 连接类、无直接连接类、独立第三方类三种[\[1\]](#part0033.html#note_1)。本节重点介绍以 D3 为代表的无直接连接工具、以 ECharts 为代表的第三方可视化工具，以及其他相关工具。

### 6.1.1 D3

D3[\[2\]](#part0033.html#note_2) 即 Data-Driven Document，是基于 Web 标准的可视化 JavaScript 库，可用 HTML、CSS、SVG、Canvas 呈现数据。以“节点-关系-节点”形式展示的力导向图是 D3 的重要手段，下面详细说明如何用力导向图实现知识图谱可视化。
