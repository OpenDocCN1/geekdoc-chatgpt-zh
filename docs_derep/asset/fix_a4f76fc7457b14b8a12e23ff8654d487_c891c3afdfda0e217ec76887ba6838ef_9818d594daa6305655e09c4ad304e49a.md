#### 4.3.3 Cursor 里的 MCP 配置与使用

接下来介绍另一款为 AI 编程而生的 IDE——Cursor。它从零为协同编程设计，内置的 Composer Agent 能理解复杂任务并调用已配置的 MCP 工具。

##### 1. mcp.json 配置与 Composer Agent 集成

与 Trae Solo 一样，Cursor 也支持全局与项目级两种 MCP 配置，文件均名叫 mcp.json。

- 全局配置：作用于全部项目，保存在用户主目录 ~/.cursor/mcp.json。可按 Ctrl/Cmd+, 打开设置，左侧选 Tools & Integrations，右侧找到 MCP 设置，如图4-16。
- 项目级配置：仅当前项目生效，文件放在项目根目录 .cursor/mcp.json。打开该项目时才加载对应服务器，适合存放项目专属能力，比如电商项目的订单数据库 MCP。团队协作时可把文件提交到代码库，成员拉取后直接可用。

配置完成后启用 Composer Agent：在 Composer 里按 Ctrl/Cmd+I 选择 Agent 模式。启用后 Agent 会主动识别已配置的工具并在需要时调用。

Composer Agent 的核心能力包括：

- 读写代码：自动识别并修改文件。
- 代码库检索：在项目中进行语义搜索。
- 调用 MCP 服务器：借助 MCP 提供的功能。
- 执行终端命令：在编辑器内运行命令行。
- 网页自动检索：获取最新资料与文档。

当提出需要外部能力的需求时，Agent 会在聊天区提示将使用的工具并请求许可。对常用且可信的流程可开启自动运行，让调用无需人工确认。

#### 4.3.4 MCP 进阶玩法与实用技巧

MCP 的真正威力在于把独立工具组合起来，构建可自动完成复杂任务的个性化流程。

### 1. 多工具协同与性能调优

让多个 MCP 服务器协同工作，核心是编排。编排是指让多个独立服务器为同一目标协同，AI 智能体扮演总指挥，根据复杂指令智能判断各步骤调用哪个工具。

典型案例是线上事故响应：告知 AI“网站登录页好像出问题了，帮我查一下”，AI 会立即启动多工具协同。

- 先调用 Sentry MCP 检查错误监控系统的最新日志，并反馈“好的，我正在检查 Sentry 错误监控系统的最新日志”。
- 发现用户认证相关严重错误后，调用 GitHub MCP 查找相关代码提交记录。
- 最后调用 Slack MCP 在开发团队频道发出警报“已定位到问题，可能是由昨晚一次代码合并引起的，已附上错误日志和代码链接”。

整个过程流畅自然，像经验丰富的工程师在处理事故。

这种复合型应用的核心价值来自工具的智能编排与组合，这与 UNIX 命令行哲学相像：用管道符连接简单命令构建强大流水线，而 MCP 正是 AI 世界的管道符。因此学习 MCP 的关键是培养超越单一指令的流程设计思维。

为特定项目搭建复杂流程时，最佳实践是使用项目级 mcp.json，确保只加载当前项目所需的服务器，让 AI 环境保持轻便高效。
