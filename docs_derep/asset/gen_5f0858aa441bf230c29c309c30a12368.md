Ascend C 算子的开发建立在标准 C++ 语法之上，结合自研的类库接口来完成。开发者可以根据实际需求挑选合适的接口。类库整体结构如图 13.4.1 所示，API 的操作数统一为 Tensor 类型，包含代表外部存储的 GlobalTensor 和代表核上内存的 LocalTensor。接口体系主要分为高阶 API 和基础 API 两类。

[PRE0]

#### 1. 基础 API

基础层接口提供计算、数据搬运、内存管理以及任务同步等底层能力。自由度很高，通过组合不同的基础接口即可搭建出自定义的算子逻辑。可以把基础 API 看作对硬件计算能力的直接映射。

##### 1）基础 API 分类

- 计算类 API：下分标量、向量、矩阵三类，分别调用标量计算单元、向量计算单元、矩阵计算单元完成相应计算。
- 数据搬运 API：计算都在 Local Memory 上进行，需先把 Global Memory 的数据搬入本地，完成计算后再搬回全局。负责搬运的接口如 DataCopy。
- 内存管理 API：用于动态分配片上内存，如 AllocTensor、FreeTensor。受限于板上内存容量，数据往往无法一次性全部驻留，因此需要动态申请释放以实现内存复用。
- 任务同步 API：用于任务间通信与同步，如 EnQue、DeQue。由于指令间存在依赖且可异步并行，同步接口会在内部发出必要的同步信号，保证跨队列指令按正确逻辑执行，开发者只需简单调用。

#### 2. 高阶 API

高阶 API 把常用算法如 MatMul、Softmax 等封装好，减少重复开发，提升效率。调用高阶接口即可快速实现相对复杂的算法逻辑，可理解为对特定算法的抽象表达。

以 MatMul 为例，使用高阶 API 时需先构造一个矩阵乘法对象，传入两个输入矩阵 A、B 的信息、输出矩阵 C 的信息以及偏置 Bias 信息，这些信息包括数据在内存中的逻辑位置、存储格式、数据类型、是否转置等。对象创建完成后，直接通过高阶 API 设置 A、B、Bias 并完成乘法与结果输出，无需自行实现数据通路和运算细节。

## 13.4.5 资源管理

Ascend C 中流水任务间的数据传递内存由资源管理模块 TPipe 统一管理。TPipe 负责作为片上内存管理器，通过 InitBuffer 为 TQue 提供内存初始化能力，开发者可为指定 TQue 分配内存。

## 13.4.6 临时变量

编程过程中常需临时变量，如 Compute 阶段的复杂数据结构。TBuf 可用于管理这类临时变量的内存，存储位置通过模板参数指定，可设为 VECIN、VECCALC、VECOUT、A1、A2、B1、B2、CO1、CO2 等逻辑位置。

建议将临时变量作为算子类成员初始化，避免重复申请释放以提升性能。TBuf 的存储空间由 TPipe 管理，通过 InitBuffer 初始化后即可用 Get 获取指定长度的 Tensor 参与计算。

为 TBuf 分配与为 TQue 分配存在差异：为 TBuf 分配的内存仅能参与计算，不能入队出队；一次 InitBuffer 调用只为 TBuf 分配一块内存，而 TQue 可通过参数申请多块；使用 TBuf 时无需反复申请释放。

## 小结与思考

- Ascend C 是对标准 C++ 的扩展，提供特定语法与 API，支持在华为自研毕昇编译器上进行设备侧编程，涵盖函数执行、地址空间限定符、数据存储与任务同步机制。
- 通过基础 API 与高阶 API 提供灵活编程方式，基础 API 涉及计算、数据搬运、内存管理、任务同步，高阶 API 封装特定算法，简化开发。
- 数据存储层面使用 GlobalTensor 与 LocalTensor 代表全局与局部空间，任务通信与同步依赖 TQue 队列，资源管理由 TPipe 完成，临时变量内存由 TBuf 管理并通过 TPipe 初始化。更多细节可查阅昇腾社区文档。
