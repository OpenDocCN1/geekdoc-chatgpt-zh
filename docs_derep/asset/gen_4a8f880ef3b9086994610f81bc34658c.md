**·** **请求错误** 。上线后智能体丢掉了多少次调用？这类失败既包括 API 报错，也涵盖工具执行中断。想让系统在生产环境更稳健，就需要设计兜底方案和重试逻辑。比如主模型 A 宕机时，自动切换到备用模型 B 接管请求。

**·** **显式用户反馈** 。用户直接给出的评价是强信号。典型形式是明示打分，例如 [PRE0] / [PRE1] 的评分区间、:star:1～5 星，或是文本评论。若负面评价持续累积，就要提高警惕，说明智能体的产出与预期存在偏差。

**·** **隐式用户反馈** 。即使没有打分，用户的行为也在说话。常见的间接信号是立刻重写提问、反复提交相同查询、点重试按钮。持续出现这类操作，往往意味着智能体未能给出可用答案。

**·** **准确性** 。智能体产出符合预期的比例是多少？准确性的定义随场景而变，可能指问题求解正确率、信息检索精确度或用户满意程度。评估前先明确成功标准，再通过自动化校验、评分或任务完成标签来追踪，例如把一次交互标记为“成功”或“失败”。

**·** **自动评估指标** 。可引入自动化打分机制。比如用大模型对输出进行评判，或借助开源评测库：RAGAS 适合 RAG 类智能体，LLM Guard 可检测有害内容或提示注入风险。

把以上维度组合起来使用，才能对 AI 智能体的健康状况形成立体判断。

#### 2．AI 智能体的评估
可观测性给出的是指标，评估则是基于指标判断智能体表现并指导改进。

因为智能体具有非确定性，且模型更新或行为漂移会随时间发生，没有持续评估就无法确认是否在变好还是在退化。

评估通常分为离线和在线两类，各有价值且相互补充，一般先做离线，再做在线。

（1） **离线评估** 。在受控环境里用测试集评估，而非真实用户提问。挑选有标准答案的数据集让智能体跑通。

例如一个数学应用题智能体，可准备 100 道题目及已知答案。离线评估多在开发和 CI/CD 阶段使用，用来优化能力或防止回退。优点是可复现、能得到清晰的准确率。也可以模拟查询并把响应与理想答案对比，或使用自动评测。

关键挑战是测试集必须足够全面且保持时效。模型在固定集上表现好，不代表能在生产中应付新式提问。因此要持续扩充测试集，加入边缘案例和真实场景。建议同时维护小规模冒烟集用于快速自检，和大规模评测集用于全面体检。

（2） **在线评估** 。在真实生产环境中对实际用户交互进行实时监控与分析。

例如追踪成功率、满意度评分或实时流量指标。优势在于能捕捉实验室里难以预见的情况，观察模型随输入模式变化的漂移，并发现测试集未覆盖的异常查询，更贴近真实表现。

在线评估常结合隐式和显式用户反馈，并可做影子测试或 A/B 测试，让新旧版本并行对比。难点在于实时交互难以获得可靠标签，往往需依赖用户反馈或下游行为指标来间接判断。

两者互补：在线发现的问题类型可以反哺离线测试集的建设，经过离线验证后再更有信心上线并进入在线观察。

评估不仅看输出结果，也要看运行全过程，包含但不限于：

**·** 初始模型请求；
**·** 智能体识别用户意图的能力；
**·** 智能体正确调用工具的能力；
**·** 工具对请求的响应情况；
**·** 智能体解读工具返回结果的能力；
**·** 用户对最终响应的反馈。

模块化拆解有助于精准定位改进点，并衡量模型、提示词、工具等变更的效果。

典型企业级架构可划分为 5 层。

（1） **基础模型层** ：选用 DeepSeek 等大模型，支持本地化或云端 API 接入，按需微调或优化。

（2） **工具集成层** ：对接搜索引擎、知识库、数据库及第三方 API，支持插件化扩展，统一接口便于任务拆解与执行。

### 12.1.2　部署流程
企业级智能体部署流程如下。

（1） **需求调研与场景定义** ：明确痛点与目标，如客服自动化、销售辅助、内部知识管理，梳理优先级与核心问题。

（2） **框架选择与技术选型** ：基于业务评估 LangChain 等主流框架，决定公有云 API 还是自建模型。

（3） **数据准备与安全设计** ：准备训练或微调数据，保证质量；设计权限控制与加密传输。

（4） **模型集成与工具开发** ：打通大模型与业务工具 API，开发定制插件如 ERP 查询、订单处理等。

（5） **智能体逻辑开发** ：设计任务分解与执行链路，规划多轮对话与记忆策略。

（6） **测试与迭代** ：执行功能、性能、安全测试，收集反馈优化对话流与调用策略。

（7） **上线部署与运维** ：部署到生产环境保障高可用，建立监控运维体系支持持续迭代。

随着技术演进，企业级部署将趋向：

**·** 多模态融合，融合文本、语音、图像提供更丰富交互；
**·** 自监督与在线学习，让智能体持续进化并适应业务变化；
**·** 边缘计算与混合云部署，实现低延迟与高安全；
**·** 行业标准与生态建设，推动组件互联互通，形成可复用产业链。

#### 1．AI 智能体的可观测性
没有可观测性，智能体像黑箱，难以排查问题；有了可观测性，它才像玻璃箱，透明可信。

进入生产后，可观测性是刚需，主要作用包括：

**·** **调试与根本原因分析** 。遇到失败或异常输出时，跟踪数据帮助定位是模型调用、工具交互还是逻辑分支的问题。

**·** **延迟与成本管理** 。智能体依赖按 token 或调用计费的模型与 API，可观测工具能精细统计调用，帮助优化提示词、换更高效模型或重构流程来控成本与提升体验。

**·** **信任、安全与合规检查** 。可审计行为是否安全合规，例如提示注入、有害生成、敏感信息泄露等，通过轨迹了解决策依据。

**·** **持续改进循环** 。生产数据指引迭代，线上洞察为离线实验提供方向，形成反馈闭环。

常用监控指标包括：

**·** **延迟** 。任务及各步骤响应时长，长时间等待会损害体验。可通过更快模型或并行调用优化。

**·** **成本** 。每次运行的费用，频繁工具调用或多次模型调用会快速抬高成本，需评估必要性。

**·** **请求错误** 。失败请求次数，涵盖 API 报错或工具调用失败。可设置重试与备用模型增强韧性。

**·** **显式用户反馈** 。直接评分如 [PRE7] / [PRE8]、:star:1～5 星或文字评论，持续负面需警惕。

**·** **隐式用户反馈** 。重写提问、重复查询、点重试等行为，反映满意度。

**·** **准确性** 。产出符合预期的频率，需先定义成功标准，再以自动检查、评分或完成标签追踪。

**·** **自动评估指标** 。用大模型评分，或借助 RAGAS、LLM Guard 等开源库评估不同维度。

#### 2．AI 智能体的评估
可观测性提供指标，评估则是分析指标以判断表现并指导优化。

因非确定性和模型漂移，定期评估必不可少，否则无法确认是否在退化。

评估分为离线与在线，两者互补，通常先离线后在线。

（1） **离线评估** 。在受控环境用测试集评估。以精选数据集运行智能体，常见于开发和 CI/CD，用于改进或防止性能回退。优点是可重复、有明确基准。可模拟用户查询并与理想答案对比，或用自动评测。

挑战在于测试集的全面性和时效性，需不断加入边缘案例和真实场景。建议同时使用小型冒烟集快速自检和大型评测集全面衡量。

（2） **在线评估** 。在生产环境实时评估实际用户交互，持续分析结果。可追踪成功率、满意度等指标，能捕捉实验室难以预见的情况，观察模型随时间漂移，并发现未覆盖的异常查询，反映真实表现。
