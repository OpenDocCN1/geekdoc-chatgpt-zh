11.1 知识图谱入门

本节介绍知识图谱的基础知识。

11.1.1 核心概念解析

知识图谱 Knowledge Graph，KG 是一种以结构化方式组织、表达和关联知识的语义网络，核心由实体 Entity、属性 Attribute 与关系 Relation 构成，通过三元组 head, relation, tail 构建可计算、可推理的知识体系，如图 11-1 所示。与传统数据库偏重存储事实不同，知识图谱强调知识间的语义关联与逻辑结构，实现知识的显式化、可视化与可推理。作为融合语义网、数据库、自然语言处理与机器学习的跨学科技术，它不仅关注存储数据，更追求理解知识，是搜索引擎、智能推荐、问答系统与决策的重要底座。

[PRE17]

图 11-1 知识图谱基本组成

知识图谱的理论根基来自语义网 Semantic Web 与图论 Graph Theory，因而具有强可解释性、强可扩展性与灵活结构。三元组既能表达静态事实，也能承载事件、过程、行为模式等复杂语义。采用开放世界假设 Open World Assumption，知识是动态增长的，不要求信息完全已知。这种表达方式非常适合处理复杂场景，如 APT 组织行为演化、云安全环境中的多实体交互等。

知识图谱主要组成要素见表 11-1，用结构化方式表达客观世界知识。其中实体指可唯一识别的对象，如《西游记》中的“孙悟空”“唐僧”“火焰山”“金箍棒”；关系描述实体间的语义联系，如“孙悟空→保护→唐僧”“唐僧→前往→西天”“红孩儿→居住→火焰山”；属性刻画实体的内在特征，如“金箍棒 重量=13500 斤”“孙悟空 师承=菩提祖师”。这些要素通常以三元组形式表达，如 孙悟空 战胜 六耳猕猴，构成最小语义单元。多个三元组联结形成异构图结构，实现人物关系、地理空间、法器属性等知识的系统表达与计算。

在组织层面，知识图谱以图结构呈现，由多类型节点与多语义关系构成复杂网络，并划分为概念层 Ontology Layer 与实例层 Instance Layer。

概念层定义抽象类别与语义规则，如“人物”“地点”“妖怪”“法器”等；
实例层包含具体事实，如“白骨精 类型=妖怪”“花果山 类型=地点”“紧箍咒 类型=法器”。

这种自上而下的语义层级使图谱既能规范表达纷繁的人物关系、空间体系与剧情事件，也能支撑基于语义规则的推理。随着知识扩展，图谱可通过人工标注、规则抽取、大语言模型自动抽取如 CodeBuddy 驱动的实体识别、关系抽取等方式动态更新，实时纳入新的研究视角与数字人文成果。总之，知识图谱构建了一个可计算的知识世界，为人工智能从感知智能迈向认知智能提供关键支撑。

知识图谱的理论源自语义网研究，由 Berners-Lee 等提出，目标是让互联网从信息互联迈向知识互联，通过 RDF、OWL 等语义模型实现机器可读与可推理。语义网提出主体-谓词-客体的三元组表示体系，为后续发展奠定基础。早期主要用于知识管理、语义搜索与逻辑推理，但因构建成本高、维护困难，产业应用有限。

“知识图谱”概念真正进入公众视野是在 2012 年 Google 推出 Knowledge Graph 之后。Google 以大规模网页实体为基础，通过结构化知识与实体关系组织搜索结果，使搜索从字符串匹配转向语义理解。这一事件推动知识图谱从理论走向大规模产业应用，带动微软 Satori、Facebook Graph、阿里巴巴、百度等纷纷构建企业级知识图谱系统。此后，知识图谱成为现代搜索引擎、推荐系统、语音助手、对话系统的重要知识支撑。
