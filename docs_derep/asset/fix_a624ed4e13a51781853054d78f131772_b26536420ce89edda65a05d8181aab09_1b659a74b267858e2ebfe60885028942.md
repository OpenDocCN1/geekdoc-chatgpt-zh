**7.2.3 节点与卡间的通信负载均衡**

**1.报告原文**

与 V2 的设备受限路由相同，V3 也采用受限路由来控制训练期通信开销。简言之，每个 Token 最多投送到*M*个节点，这些节点依据各节点专家集合的最高*K**[r]*/*M*亲和分数之和挑选。在此约束下，MoE 训练框架几乎能实现计算与通信的完全重叠。

为保证 Dualpipe 有足够算力，我们定制了高效的跨节点全对全通信内核，兼顾调度与合并以节省通信 SM。内核实现、MoE 门控与集群网络拓扑需协同设计。具体地，集群跨节点 GPU 以 IB 全互联，节点内以 NVLink 互联。NVLink 带宽约 160GB/s，约是 IB 50GB/s 的 3.2 倍。为充分利用差异，限制每个 Token 最多分发到 4 个节点，降低 IB 流量。路由确定后，Token 先经 IB 传到目标节点同索引 GPU，随后在节点内尝试经 NVLink 立即转发到托管目标专家的 GPU，避免被后续 Token 阻塞。这样 IB 与 NVLink 通信可完全重叠，每个 Token 能在每个节点平均选择约 3.2 个专家且无额外开销。也就是说，实际仅路由 8 个专家时，可在相同通信成本下扩展到最多 13 个，即 4 个节点、每个节点约 3.2 个专家。总体上，仅需 20 个 SM 就能吃满 IB 与 NVLink 带宽。

**2.解读**

卡间与节点间均衡的核心在于 NVLink 与 IB 带宽差距大，因而要限制跨节点流量，这对应第六章提到的专家分组策略，每组专家放一个节点，最终限制每个 Token 被投到前 K_group 个节点，在这 K_group 个节点内再挑前 K_expert 个专家，其中 K_expert>K_group。

由于卡内通信速度约为节点间 3.2 倍，若不浪费卡内带宽，需要卡内通信量约为节点间的 3.2 倍。选择 4 个节点推理时，每个 Token 理论可选择约 12.8 个专家，此时卡内与卡间通信达到平衡。

### **8.1 混合精度训练**

**8.1.1 为什么要进行混合精度训练**

混合精度在同一流程中混用不同数值精度，例如 FP32 与 FP16。矩阵乘、卷积等计算放在低精度执行，梯度累加、权重更新等关键操作保留高精度，以此换取内存与速度。

主要原因：

**1.减少内存占用**
FP16/BF16 相比 FP32 可减半显存，支持更大模型或更大批大小。

**2.提升计算速度**
低精度在 Tensor Core 上加速明显，训练迭代更快。

**3.降低通信开销**
低精度数据传输量更小，分布式训练带宽压力下降。

**4.保持模型精度**
关键路径保留 FP32 避免梯度消失与数值不稳。

**5.节能与成本效益**
低精度计算能耗更低，训练成本与碳排放下降。

V3 是公开首个采用 FP8 混合精度训练的大模型，并在全程使用三种精度。下面以报告解读。

**1.报告原文**

为加速训练，核心 GEMM 内核均以 FP8 实现。GEMM 接受 FP8 输入，输出为 BF16 或 FP32。图 8-2 中与线性算子相关的三个 GEMM，即前向传播 Fprop、激活反向 Dgrad、权重反向 Wgrad，均以 FP8 执行。相比 BF16，理论算力翻倍。FP8 Wgrad GEMM 还允许以 FP8 保存激活用于反向，大幅降低内存。

尽管 FP8 高效，部分算子对低精度敏感，仍保留高精度。经调研，嵌入模块、输出头、MoE 门控、归一化与注意力算子保持 BF16/FP32 原精度，以保障训练动态稳定。为进一步保证数值稳定，主权重、权重梯度与优化器状态以更高精度存储。虽带来少量内存开销，可通过跨 DP 等级分片在分布式系统中削减。
