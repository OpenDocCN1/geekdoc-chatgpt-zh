## 12.2.4 编程抽象与硬件实现对照

编程模型是开发者撰写程序时依赖的抽象层，规定程序如何组织与调度，让人能聚焦逻辑而忽略底层细节。它通常包含语言、数据结构、算法与并发机制，用来描述程序行为。

硬件执行模型则刻画机器真实运行程序的方式，涵盖微架构、指令集、寄存器、存储层次、缓存与并行策略。它决定指令顺序、数据搬运与并发策略，硬件层面同时用到 SIMD 与 SIMT。

抽象经编译器映射到具体执行，两者在概念上差异明显。

## 小结与思考

- SIMD 与 SIMT 都属于单指令多数据范式，SIMD 要求数据严格对齐且同步，SIMT 允许线程独立寻址、可异步推进，灵活性更高。
- NVIDIA CUDA 基于 SIMT 架构实现高效并行，以线程块与网格组织工作，通过 CUDA Core 调度提升 GPU 效率。
- 编程抽象为组织代码提供视角，硬件执行描述代码在物理设备上的真实运行，厘清两者对性能优化很有帮助。

# 12.3 SIMD 与 SIMT 编程关联

前面已分析 AI 芯片上 SIMD 与 SIMT 的计算本质，并以 NVIDIA CUDA 作对比，本节介绍不同并行编程方式。

## 12.3.1 并行编程的三种典型模式

从指令级看，常见模型可归为串行、数据并行与多线程：

- SISD：程序顺序推进，每条指令处理单一数据。适合简单顺序任务和小规模数据，大规模场景效率受限。
- SIMD：通过向量或并行指令一次处理多组数据，同一单元执行相同操作但作用于不同数据。适合图像处理、科学计算等强数据并行场景。
- MIMD/SPMD：多处理器并行执行不同或相同指令以处理不同数据，充分发挥多核优势，适合分布式系统与并行计算。

选对模型能更好利用硬件资源。

## 12.3.2 串行执行 SISD

以向量相加 $C[i]=A[i]+B[i]$ 举例，for 循环每次迭代都完成一次加法，CPU 常采用这种方式，通常借助流水、乱序与超长指令集提升效率。

[PRE1]

### 1. 流水线执行

指令被拆成取指、解码、执行、访存、写回等阶段，由专用单元处理，实现指令重叠。未用流水线时每次迭代都要完整走一遍；启用后可在空闲时并行推进不同指令，提升指令并行度。

[PRE2]

### 2. 乱序执行

在保持语义前提下重排指令执行顺序以提高指令级并行。处理器按依赖关系与资源动态调整。若不乱序，指令 1 完成后才启动指令 2，周期内会出现大量空闲。

[PRE3]

采用乱序后可在 CPU 空闲时提前发射指令 2，受依赖的指令 4 需等指令 1 写回后执行，同时 for 循环由硬件动态展开。

[PRE4]

### 3. 超长指令字 VLIW

VLIW 允许一条指令打包多个操作，同一周期并行执行。并行在编译时完成，编译器优化能力直接影响性能，硬件执行编译后的并行指令，提升指令级并行。

## 12.3.3 数据并行 SIMD

数据并行体现在循环迭代独立完成。程序层面可手写 SIMD 指令或由编译器生成，硬件提供宽 ALU。以向量加法为例，VLD 将 A 载入 V1 时 Iter.1 读 A[0]、Iter.2 读 A[1]，后续 VLD、VADD、VST 均以相同指令处理不同数据，实现数据并行。

[PRE5]

## 12.3.4 多线程 SPMD

SPMD 是一种并行计算模型，多线程 SPMD 用多个线程执行并行任务。每个 Thread i 运行同一程序但处理不同数据，通过并发加速。程序上由开发者或编译器生成线程对应迭代。SPMD 属于编程模型，SIMT 属于硬件执行模型，后者用独立线程管理驱动硬件。

[PRE6]

SPMD 与 SIMD 的区别是 SIMD 在同一指令下处理不同数据，而 SPMD 用线程管理每个迭代。SPMD 最终运行于 SIMD 机器，因而发展出单指令多线程的硬件执行模式 SIMT。

## 12.3.5 NVIDIA 的 SIMT 机制

GPU 的 SIMT 实质是硬件以 SIMD 方式执行指令，采用 SPMD 编程模式控制线程。每个线程有独立上下文，执行相同指令时硬件会把线程动态组织为 Warp。Warp 本质是 SIMD 操作的体现，SIMT 构成前端调度，后端在 SIMD 上执行。

在 NVIDIA GPU 中，Warp 是执行相同指令的线程集合，是 SM 调度的基本单元，内部以 SIMD 方式推进。CUDA 编程本质是 SPMD，开发者只需写单程序多数据，硬件层面以 SIMT 实现单指令多线程。

综合来看，各概念可区分：

- SIMD：指令执行方式及其对应的硬件体系。
- SIMT：以 SIMD 指令为基础，配备 Warp Scheduler 等硬件模块，支持 SPMD 编程模型的硬件架构。
- SPMD：具体并行编程模型，类似 CUDA 提供的范式。
- DSA：面向 AI 的专用硬件架构，如 NPU/TPU，用于大规模数据处理与分布式存储等场景。

| 类型 | 硬件架构或执行模型 | 方式 |
| :--- | :--- | :--- |
| 执行模型 | Traditional SIMD | （1）单条指令执行；（2）ISA 包含向量/SMD 指令信息；（3）SIMD 指令锁同步操作，即顺序指令执行；（4）编程模型直接控制指令，无额外线程控制，软件需知数据长度 |
| 执行模型 | Warp-base SIMD (SIMT) | （1）由多个标量线程以 SIMD 方式执行组成；（2）ISA 为标量，SIMD 操作可动态形成；（3）各线程可单独处理，支持多线程与灵活线程动态分组；（4）本质上在 SIMD 硬件上实现 SPMD 编程模型，CUDA 采用此方式 |

值得注意的是，NVIDIA 在 GPU 中加入 Tensor Core，专用于神经网络矩阵计算并支持混合精度，因此其 GPU 呈现 SIMT+DSA 的混合形态。

## 小结与思考

- SISD、SIMD 与 MIMD/SPMD 是并行编程的三种基本方式，适用于不同规模与类型的计算。
- SIMD 借助向量化指令实现数据并行，SIMT 在 SIMD 基础上通过 Warp 实现更灵活的多线程并行。
- NVIDIA CUDA 编程模型基于 SPMD，利用 SIMT 硬件执行单指令多线程，使开发者以单程序多数据方式编写并行程序，降低开发复杂度。

NVIDIA GPU 采用 SIMT 指令执行模式，带来以下优势：

- 无需开发者手动把数据拼成合适矢量长度再传入硬件；
- 硬件层面化解大部分 SIMD 数据通路的流水编排难题，对编译器更友好；
- 线程可独立执行，允许分支分化，这是 SIMT 的核心；
- 硬件动态将执行相同指令的线程组织成 Warp，提升 SIMD 计算并行度。

假设一个 Warp 含 32 个线程，需做 32000 次迭代，每个迭代用一个线程，则共需 1000 个 Warp。第 1 个迭代 Warp0 执行第 0~32 个线程，第 2 个迭代 Warp1 执行第 33~64 个线程，如此类推，第 21 个迭代 Warp20 执行第 20×32+1 ~ 20×32+32 个线程。可看出 SIMT 是标量指令的多指令流，可动态分组 Warp 以提升并行度。

## 2. Warp 与 Warp 级 FGMT 关系

SIMT GPU 通过细粒度多线程 Fine-Grained Multi-Threading 调度，将执行流水线切分为更小单元，使不同线程指令交错执行，减少等待与资源浪费，实现访存与计算重叠。

Warp 是在不同地址数据下执行相同指令的线程集合，Thread Warp 包含多个 Thread，多 Warp 组成 SIMD Pipeline 执行对应操作。

[PRE14]

SIMT 架构借助 FGMT 隐藏延迟，SIMD Pipeline 中每个线程一次执行一条指令，Warp 支持乱序执行以掩盖访存延迟，并非严格顺序调度，线程寄存器值保存在 RF 中且 FGMT 允许长延迟。NVIDIA 通过 Warp Scheduler 硬件调度，在 Warp 访存完成后让 SIMD Pipeline 执行尽可能多指令，隐藏其他 Warp 的访存时间。

[PRE15]

SIMT 相比 SIMD 在可编程性上的根本优势在于硬件解决了大部分流水编排问题。Warp 指令级并行中每个 Warp 含 32 个线程与 8 条执行通道，每个时钟周期执行一次 Warp，一次 Warp 可完成 24 次操作。

在 GPU 宏观架构层面，GDDR 数据经内存控制器传输到片内总线，再分发至 CUDA Core/Tensor Core 等执行核心，每个核心内部含 SIMD 执行单元，从而实现并行计算。
