## 4.10 vLLM 推理提速

vLLM 能够大幅提升大模型推理速度，相比直接使用 HuggingFace 的 generate() 方法，提速可达 24 倍。

### 4.10.1 KV Cache

先回顾一下大模型生成 token 的流程。输入“中国的历史”会被切分为三个 token：“中国”“的”“历史”，映射为 token id 后送入模型，模型预测出下一个 token“非常”。随后把“非常”接在原输入后，形成“中国的历史非常”再预测，得到“悠久”，如图所示。

[PRE4]

再回看 Transformer 的自注意力机制。以“中国的历史”这三个 token 为例，每个 token 只能关注自身及前面的 token。第 1 个 token 仅与自己做注意力，输出自身的 v 向量。第 2 个 token 用自己的 q 向量分别与第 1 个 token 和自己的 k 向量匹配，经 softmax 得到权重后，对两个 v 向量加权求和，得到自注意力结果。可以看出，计算时只依赖当前 token 之前部分的 k、v，不受后面 token 影响。

[PRE5]

## 图4-62 第2个token的自注意力计算

prompt 中的全部 token 在第一次推理时，即可算出各层对应的 k、v 向量，并生成下一个 token“非常”。

随后把新生成的“非常”拼接到原输入末尾，进行第二次生成。因为 prompt token 的 k、v 在首次推理时已算出，且不受新 token 影响，所以无需重算。HuggingFace 的 generate 方法默认会缓存此前生成的 token 的 k、v。值得注意的是，后续 token 的自注意力计算并不需要前面 token 的 q 向量，因此只需保留已算的 k、v。第二次生成后，“非常”的 k、v 也会被保存，这就是 KV Cache，如图所示。

[PRE6]

## 图4-63 大模型第2次生成

借助 KV Cache，与大语言模型的对话不会因持续输出而变慢。每次推理只需计算当前 token，历史 token 的 k、v 均已缓存。

### 4.10.2 Page Attention

KV Cache 虽能加速推理，但传统分配方式效率低下。以 40GB 显存的 A100 为例部署 13B 模型，参数约占 26GB，KV Cache 约占 12GB。

实测发现 KV Cache 所在显存的实际利用率仅 20%~40%。浪费主要来自三方面：

1. 生成阶段无法预知最终长度，通常按设定的最大 token 数预分配 KV Cache，如最大设为 1000，实际只生成 100，剩余 900 的缓存被闲置。

[PRE7]

2. 假设某请求确实需要生成 1000 个 token，但在输出第 1 个 token 时，其余 999 个尚未使用，显存却已被预占。此时其他新请求无法使用这些显存，而它们可能只需生成 10 个 token 即可完成，本可并行处理。

3. 显存碎片化。不同请求的提示词长度不同，预分配的 KV Cache 大小也不同。请求完成后释放缓存，若下一个请求的提示词更长，就无法复用刚释放的空间，形成碎片。

vLLM 正是为解决 KV Cache 的浪费而生，支持更大的批处理规模，从而提升吞吐量。传统系统批大小为 8，经 vLLM 优化后可提升至 40。原系统每秒输出约 300 个 token，优化后可达 900 个 token，如图4-65 所示。

[PRE8]

## 图4-65 vLLM与现有系统性能比较

vLLM 为何能取得如此提升？核心在于 Page Attention 技术。KV Cache 的低效问题与操作系统早年的内存管理类似：是否要为每个进程预分配内存？进程结束如何释放？如何应对内存碎片？操作系统已用虚拟内存和分页管理解决。

在操作系统中，物理内存被切分为 4KB 的页。进程申请和释放内存按页进行，物理页不必连续。为屏蔽不连续访问，引入虚拟内存，进程在虚拟地址空间操作，操作系统通过页表将虚拟页映射到物理页。

Page Attention 将这套思路搬到 KV Cache 上。显存被划分为 KV 块，按块管理 KV Cache 的分配。每个请求的 KV Cache 被映射到显存中不连续的多个 KV 块里。

假设每个 KV 块可容纳 4 个 token 的 KV 向量，对于“中国的历史非常悠久”中的这 5 个 token，就对应到两个 KV 块里。这两个 KV 块在显卡的显存里可以是不连续的，如图4-66 所示。

可以看出 vLLM 克服了原来预分配显存的问题，只在需要时分配新的 KV 块，并且按块进行分配，大大地缓解了显存碎片的问题。因为每个块按 4 个 token 的 KV Cache 进行分配，一个生成序列最多只会产生 3 个 token 的 KV Cache 占用显存的碎片。

vLLM 也把类似虚拟内存的技术引入 KV 块的访问上。每个生成序列都有自己的逻辑 KV Cache，在逻辑 KV Cache 里，生成序列 token 的 KV Cache 是连续的，但实际在显卡显存里并不保证是连续的。从逻辑 KV Cache 里的 KV 块到物理显存里的 KV 块的映射关系被保存在每个生成序列的映射表里，由 vLLM 进行维护，如图4-68 所示。

Page Attention 按 KV 块来分配显存，大大地减少了显存碎片的大小，而且 KV 块的分配是按需进行分配的，不会提前预分配大量显存，并且通过虚拟显存技术，方便了每个生成序列对 KV Cache 进行调用。最终将 KV Cache 的利用率从原来的 20%~40% 大幅提升到了 96%。

### 4.10.3 块共享

vLLM 对原始大模型的生成进行的第 2 个大的改进是对 KV 块进行共享。当用户在进行大模型生成时，有时会想用一个提示词生成多个不同的输出。

例如，想让大模型对一句中文生成两个不同的英文翻译。在 vLLM 的 sampling 参数里，可以通过将 n 设置为 2 来实现。此时，同一个提示词会产生两个不同的序列，它们的提示词是相同的，即都是“请把下边这句话翻译为英文：色即是空”。虽然要生成两个序列，但这时在显卡的显存里只会存放一份提示词里 token 的 KV 块。它们被两个不同生成序列的逻辑 KV Cache 引用着。在物理显存里，每个提示词 token 对应的块都标记自己现在被两个生成序列引用着。只有当引用计数为 0 时，这个块占用的显存才会被释放，如图4-69 所示。

接着第 1 个序列开始生成，它生成的第 1 个 token 是 Color，这时会触发 Copy-on-Write 机制，也就是它发现它要写入的块有两个引用，也就是有多个序列共用，它不能直接修改，需要复制一份进行写入，所以 vLLM 此时会分配一个新的 KV 块，并复制原来块里的 KV Cache，然后将原来 KV 块的引用数减一，将新的 KV 块的引用数设置为 1。接着第 1 个生成序列在新的 KV 块里写入 Color 这个 token 的 KV Cache。当第 2 个序列生成自己的下一个 token（Matter）时，它发现它引用的 KV 块的引用计数为 1，可以直接写入。接着两个序列就分开各自生成自己的 token 了，如图4-70 所示。

## 4.11 FlashAttention

[PRE14]

当前在训练大模型时默认会采用 FlashAttention 技术，FlashAttention 的论文题目为 Fast and Memory-Efficient Exact Attention with IO-Awareness 。从论文题目中可以看出 FlashAttention 技术主要有两大优点：第 1 个是 Fast，它可以大大地加快模型训练的速度，第 2 个是 Memory-Efficient，它可以在模型训练时节省对显存的占用。同时它还是一个 Exact Attention 的算法，意味着 FlashAttention 计算结果和标准的 Attention 计算结果是完全一致的。这一切都得益于用 IO-Awareness 来实现，意味着它是通过对 I/O 感知的程序设计来实现的，通过改进整个算法的 I/O 效率来提升算法的整体效率。

在 Transformer 架构中，Attention 机制的简化计算过程具体如下。

1. 输入处理：将输入的 token 转换为向量表示。
2. 生成矩阵：生成查询 Query，Q、键 Key，K 和值 Value，V 矩阵。
3. 计算注意力分数：通过 Q 矩阵与 K 矩阵的转置相乘，得到注意力分数矩阵 S。
4. 归一化注意力分数：对 S 矩阵按行进行 softmax() 操作，得到注意力矩阵 P。
5. 计算注意力输出：使用注意力矩阵 P 与 V 矩阵相乘，得到注意力输出 O。

## 图4-72 简化Attention计算流程

在考虑 GPU 的 I/O 的情况下，具体过程如下。

- 1. 矩阵存储：首先，矩阵 Q、K、V 存储在高带宽存储器 HBM 中，它们的形状均为 N × d，其中 N 表示序列长度，d 表示特征维度。
- 2. 加载矩阵：将 Q 和 K 矩阵从 HBM 加载到片上存储器 SRAM。
- 3. 计算注意力分数：计算注意力分数矩阵 S，S = QK^T。
- 4. 写入分数矩阵：将 S 矩阵写回 HBM。
- 5. 加载分数矩阵：将 S 矩阵从 HBM 加载回 SRAM。
- 6. 计算注意力矩阵：对 S 矩阵进行 softmax() 操作，得到注意力矩阵 P，P = softmax(S)。
- 7. 写入注意力矩阵：将 P 矩阵写回 HBM。
- 8. 加载矩阵：将 P 和 V 矩阵从 HBM 加载回 SRAM。
- 9. 计算注意力输出：计算注意力输出矩阵 O，O = PV。
