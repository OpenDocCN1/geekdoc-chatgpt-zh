Wikidata 在组织知识时主要依赖一组核心构件：页面 Pages、实体 Entities、条目 Items、属性 Properties、陈述 Statements、限定符 Qualifiers、引用 References 等。它源自 Wikipedia，和 Wikipedia 一样把 Page 页面作为最基本的组织单元。Entities 可以理解为 OWL 里 Things 的上位概念，指图谱中最顶层的对象，每个 Entity 都拥有独立的维基页面。Entities 主要分为两类：Items 与 Properties。Items 类似于 RDF 中的 Instance，用来指代具体的实例。Properties 与 Statements 分别对应 RDF 中的 Property 与 Statement。每个 Item 的页面通常还会列出多组别名 aliases，以及若干通向 Wikipedia 的站点链接 Sitelinks。

一个 Entity 下往往挂载多条 Statement。Statement 由一个 Property、一个或多个值 Values、一个或多个 Qualifiers、一个或多个 References，以及用于标示重要程度的 Rank 共同构成。

Qualifiers 用来处理更复杂的多元情境。以陈述 “spouse: Jane Belson” 为例，它本身是一个二元关系，通过 Qualifiers 可以附加额外的限定来刻画多元信息，比如 “start date: 1991 年 11 月 25 日” 与 “end date: 2011 年 5 月 11 日”。

References 主要用来表明每条陈述的出处，例如来自某个 Wikipedia 页面。Reference 本质上也是一种 Qualifiers，通常以附件形式加到 Statement 上。

Wikidata 支持多种取值类型，包括自身定义的 Item 类型、RDF 字面量 Literal、URL、媒体资源 Commons Media，以及 Time、Globe coordinates、Quantity 三种复杂类型。

系统允许为每条 Statement 设定三种可信度权重：默认的 normal、更可信的 preferred 以及已废弃的 deprecated。

在描述 Statement 的具体形态上，Wikidata 划定了三种 Snack 结构：PropertyValueSnack、PropertyNoValueSnack、PropertySomeValueSnack。其中 PropertyNoValueSnack 与 OWL 中的否定表达类似，用来表述诸如 “伊丽莎白一世没有配偶” 这类知识。PropertySomeValueSnack 则类似 OWL 中的存在量词 someValuesFrom，用来表述 “林修斯教皇有出生日期，但目前未知” 这类知识。

URI 设计遵循 Linked Open Data 原则，采用统一格式 http://www.wikidata.org/entity/<id>。其中 <id> 既可以是 Item，例如 Q49，也可以是 Property，例如 P234。

## 2.5 知识图谱的向量表示方法
前面几节介绍的是基于离散符号的表达方式，本节要介绍的是把知识图谱中的实体和关系映射到低维连续向量空间，而非继续使用离散符号。

# 2.5.1 知识图谱表示的挑战
此前提到的多种表示方案，大多以三元组为基础来组织知识。在实际的知识库网络中，节点对应三元组的头实体和尾实体，边对应三元组的关系。离散符号化表达在结构化数据方面效率很高，但在大规模应用中会遇到明显瓶颈。

知识以离散符号表达时，符号本身无法承载语义层面的信息，也难以进行语义计算，对下游任务并不友好。在图结构的知识图谱上应用算法时，由于图本身的特性，相关方法多依赖图算法，复杂度较高，难以在海量数据上扩展。

数据存在明显的稀疏问题，现实中的知识图谱里实体和关系都呈现长尾分布，即部分实体或关系仅有极少量样本，这会拉低应用的准确率。

综合来看，面对数据体量大、应用场景多变的知识图谱，传统表示方式需要改进。

# 2.5.2 词的向量表示方法
在谈知识图谱的向量表示前，先回顾词的表示思路。在自然语言处理里，离散符号化的词不蕴含语义，因此常用把词映射到向量空间的做法，这既便于计算，也能让向量在映射过程中携带语义。知识图谱的向量表示方法借鉴了这一思路。

# 1. 独热编码
传统的独热编码 One-Hot Encoding 会把一个词展开成一个很长的向量，向量维度等于整个词表大小。对某个具体词，其独热向量中仅在对应编号的维度上为 1，其余全为 0。如图 2-19 所示，若 Rome 的编号为 1，则其编码只有第 1 维是 1，其余皆为 0。该方法实现简单，但不包含语义信息，稀疏性极强，词典越大向量越庞大。

# 2. 词袋模型
词袋模型 Bag-of-Words、BoW 是对文本中词的一种计数式表示。把文本想象成装词的袋子，不考虑词序和上下文，仅统计每个词在该文本中出现的次数。具体流程是先汇集所有文本的可见词汇组成词典，给词编号，再用一个记录各词出现频次的向量来表示文本，该向量每维数值即对应词在该文本中的出现次数。如图 2-20 所示，在 doc_1 中 Rome 出现 32 次，Paris 出现 14 次，France 出现 0 次。

### 2.5.1 连续词袋模型
该模型忽略词序，核心思想是用上下文预测中心词，从而让训练出的词向量蕴含上下文信息。如图 2-21（a）所示，wₙ 为中心词，wₙ₋₂，wₙ₋₁，wₙ₊₁，wₙ₊₂ 为其上下文。将上下文词的独热表示与词向量矩阵 E 相乘得到各词向量求和形成投影层，再经 Softmax 输出，输出每维代表词表中每个词作为该上下文中心词的概率。训练时模型像滑动窗口在语料上移动，故称连续词袋模型。

Skip-gram 与 CBoW 思路相反，用中心词预测上下文。如图 2-21（b）所示，先通过中心词的独热表示从词向量矩阵中取出词向量形成投影层，再经 Softmax 得到输出，输出每维表示某个词作为输入中心词上下文出现的概率。

### 2.5.3 知识图谱嵌入的概念
为解决前述表示挑战，受词向量启发，研究者尝试把知识图谱中的实体和关系映射到连续向量空间并保留语义信息，以便在问答、关系抽取等下游任务中更方便操作。对计算机而言，连续向量能携带更多语义，更易理解与处理。该方向即知识图谱嵌入 Knowledge Graph Embedding，也称知识图谱向量表示、表示学习 Representation Learning、知识表示学习。

与词向量相似，知识图谱嵌入也是通过机器学习训练模型。与独热编码、词袋模型相比，其训练基于监督学习。训练过程中可以学习语义层信息，且词向量的空间平移性同样适用。经典模型 TransE 的设计思想是，若三元组（h, r, t）成立，则需满足 h+r≈t，例如：

vec(Rome) + vec(is-capital-of) ≈ vec(Italy)

### 2.5.4 知识图谱嵌入的优点
研究者转向嵌入方法，是因为向量表达的实体关系相比传统方法有明显优势。

向量表达提升计算效率，映射到向量空间后算法可用数值计算，效率同步提高。

丰富下游应用设计。向量表示后知识图谱更适配当前主流的机器学习方法，如神经网络等。输入不再是符号，可选方法也不局限于图算法。

把知识图谱嵌入作为下游任务的预训练向量输入，使输入信息不再是孤立无语义的符号，而是已训练并包含一定信息的向量。

总体而言，知识图谱嵌入能提高计算效率、拓展下游应用、提供语义预训练，具有很高的应用价值与前景。

### 2.5.5 知识图谱嵌入的主要方法
多数模型依赖知识图谱中可直接观察到的信息训练，即基于所有已知三元组学习。对这类方法，常只需训练出的实体与关系表示满足训练三元组即可，但结果未必能完全满足所有下游任务。因此也有研究关注引入知识图谱之外的额外信息，如实体类型 Entity Types、关系路径 Relation Paths 等。

依据综述[11]，可将方法划分为：

### 1. 转移距离模型
转移距离模型 Translational Distance Model 的核心是把向量化后三元组的合理性问题转化为衡量头实体与尾实体距离的问题。关键在于设计得分函数，得分函数通常刻画利用关系把头实体转移到尾实体的合理性。

受词向量启发，可把知识图谱中头实体与尾实体的向量关系类比词与词的语义关系，即把两者映射到向量空间，其联系视为三元组中的关系。TransE 正是受词向量平移不变性启发，把实体和关系都表示为向量，对关系（head, relation, tail），把关系向量解释为头实体到尾实体的转移向量。若三元组成立，则需满足 head+relation≈tail。

### 2. 语义匹配模型
相比转移距离模型，语义匹配模型 Semantic Matching Models 更侧重挖掘向量化后实体与关系的潜在语义。该方向代表模型为 RESCAL 及其延伸。

RESCAL 的核心是把整个知识图谱编码为三维张量，再分解为核心张量与因子矩阵。核心张量中每个切片对应一种关系，因子矩阵中每一行对应一个实体。由两者还原的结果被视作三元组成立的概率，大于阈值则认为正确，否则错误。其得分函数可写成
