在实现资源 API 时，安全设计不可忽视。服务端常需向模型暴露本地文件、数据库或外部接口，任何疏漏都可能导致风险。建议采用纵深防御思路。

首要环节是 URI 校验。所有进入的 URI 都应视作外部输入，校验不仅看格式，还要确保所指对象落在允许范围，防止路径穿越类攻击，例如构造 ../../etc/passwd 读取敏感文件。严格的 URI 校验是第一层屏障。

确认合法后，需执行细粒度权限控制。不同资源敏感度差异较大，涉及个人隐私、配置或商业秘密的内容必须受限。权限判断要结合操作类型，如读取、写入、执行，而非仅判定是否可访问。检查应在操作执行瞬间完成，以保证授权实时有效，体现最小权限思想，让每个调用方只能触及完成任务所必需的最小集合。

最后关注数据保真。处理二进制对象如图像、音频或可执行文件时，必须先做正确编码，MCP 中常用 Base64。由于传输层基于文本的 JSON-RPC，直接透传原始字节易引发解析错误或损坏。经编码后，接收方才能得到与源完全一致的内容，确保链路完整。综合 URI 校验、最小权限控制与二进制编码，才能构建可靠的 MCP Server。

#### 2.3.2 工具集成

MCP 允许服务端向大模型暴露可调用能力，模型借此查询数据库、调用 API、执行计算、获取实时信息或实现自动化。每个能力以唯一名称区分，并附带元数据描述使用方式。

在 MCP 中，工具可以依据功能和特性分为6类，如表2-4所示。

表2-4 MCP工具的类型

| 工具类型 | 描述 | 示例 |

| :--- | :--- | :--- |

| 计算工具 | 执行计算和数据处理 | 计算器、单位转换、统计分析 |

| 数据检索工具 | 从外部源获取数据 | 天气查询、股票价格、新闻搜索 |

| 内容生成工具 | 创建或修改内容 | 图像生成、代码格式化、文档转换 |

| 通信工具 | 与外部系统或人员通信 | 电子邮件发送、消息通知、API调用 |

| 自动化工具 | 执行系统操作或工作流 | 文件操作、任务调度、工作流触发 |

| 分析工具 | 分析和解释数据 | 情感分析、文本摘要、数据可视化 |

返回可包含结构化与非结构化信息。结构化结果放入 structuredContent 字段作为 JSON 对象，为兼容性考虑，建议同时给出等价的非结构化描述，例如文本块中的序列化 JSON。非结构化内容置于 content 字段，可能的类型有：

- 文本内容：{"type": "text", "text": "工具结果文本"}。

- 图像内容：{"type": "image", "data": "base64编码数据", "mimeType": "image/png"}。

- 音频内容：{"type": "audio", "data": "base64编码音频数据", "mimeType": "audio/wav"}。

- 资源链接：{"type": "resource_link", "uri": "file:///project/src/main.rs", ...}。

- 嵌入资源：{"type": "resource", "resource": {"uri": "...", "text": "..."}}。

若工具声明了 outputSchema，服务端必须返回符合该模式的结构化结果，调用方据此校验。
