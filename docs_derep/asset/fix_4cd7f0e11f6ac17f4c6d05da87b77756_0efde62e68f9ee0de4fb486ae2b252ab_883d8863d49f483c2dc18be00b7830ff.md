### 3.4 代理

Agent 的设计思路是把大语言模型当成决策中心，在运行时动态挑选并排序一系列操作。与链式结构里操作顺序写死在代码的做法不同，Agent 依靠模型的推理能力判断该执行哪些动作以及先后顺序。设计时需要厘清几个关键角色：Agent 本身作为执行主体，AgentExecutor 负责落地决策，Tools 是可调用的操作单元，Toolkits 则是一组协作工具的集合。这几部分共同构成 Agent 的基础架构，帮助它在复杂环境中做出智能判断并完成任务。

#### 3.4.1 核心思想

在 LangChain 中，Agent 与 Chain 相互补充，二者根本差异在于：Chain 的步骤在代码里预先固定，而 Agent 让语言模型担任推理引擎，依据上下文动态决定下一步做什么、怎么做。这种机制让行为更具弹性与智能。

实现涉及下面核心要素。

- (1) AgentAction：数据类，用于描述 Agent 计划执行的动作。包含 tool 指明调用的工具名称，tool_input 提供该工具的输入参数。
- (2) AgentFinish：表示 Agent 结束运行，准备把结果返回给用户。通常包含 return_values 映射，其中一般有 output 键，对应返回给用户的响应文本。
- (3) 中间步骤：记录 Agent 之前已执行的动作及其产出，以便在后续迭代中保持记忆。其类型为 List[Tuple[AgentAction, Any]]，observation 目前保留为 Any 以保证灵活性，实践中多为字符串。

Agent 类负责判定下一步动作，通常依赖语言模型、提示模板和输出解析器。不同场景可能需要不同的提示风格、输入编码方式和输出解析策略，LangChain 既支持定制 Agent，也提供多种内置类型供扩展。

Agent 的输入是一个键值映射，其中必需的键是 intermediate_steps，对应上述中间步骤。一般由 PromptTemplate 把键值对转成适合 LLM 的格式。输出则是下一个待执行的动作，或最终发给用户的响应，即 AgentAction 或 AgentFinish。

AgentExecutor 是 Agent 的运行环境，负责调用 Agent、执行其选择的动作、把结果反馈给 Agent 并进入下一轮迭代。表面看流程简单，但它替开发者处理了大量细节，比如工具不存在、工具执行失败、输出无法解析为工具调用等，同时在决策和调用各层级提供日志与可观测性。

#### 3.4.2 代理类型

按 LangChain 的划分，Agent 可依据预期模型类型、是否支持聊天历史、是否支持多输入工具、是否支持并行函数调用等特征来挑选。比如 OpenAI Tools Agent 兼容聊天模型，能处理聊天历史、多输入工具及并行函数调用，适合使用最新 OpenAI 模型的场景；而 XML Agent 则更适合擅长 XML 格式的 Anthropic 等模型。选择取决于应用需求、模型能力与任务复杂度等多重因素。

选型时应综合考虑模型能力、任务复杂度、效率要求、可用工具和定制需求。若任务需要支持聊天历史的多轮交互，OpenAI Tools 这类 Agent 更合适；若效率至关重要，可优先考虑支持并行函数调用的 Agent 以加快处理；也需根据输出格式需求挑选支持 XML 或 JSON 的 Agent，或按工具特性挑选支持多输入的 Agent。充分了解各类 Agent 的特性和适用场景，有助于做出更明智的选择。

例如搭建客服聊天机器人时，目标是理解用户查询并给出有用反馈。此时代理需要保留聊天历史以把握上下文，OpenAI Tools Agent 就很匹配，它不仅支持聊天历史，还能使用多输入工具并行调用，提升效率。配合最新的 OpenAI 模型，机器人可以理解复杂提问，并借助外部工具如数据库查询给出准确答案。

再如内容生成工具，比如自动撰写新闻稿或代码注释，可能倾向于使用擅长特定格式的 Agent。若需要生成结构化 XML 数据，XML Agent 更合适，因为 Anthropic 等模型能直接以 XML 格式理解和生成内容，从而提高准确性和效率。

在数据分析和报告场景中，可能需要 Agent 整理、汇总数据后生成报告。此时 Structured Chat Agent 是不错的选择，它支持多输入工具，可同时调用数据查询与数据处理工具，再把结果整合成易读的报告。并行函数调用特性还能加快数据处理与报告生成的速度。

#### 3.4.3 工具

在 LangChain 框架里，Tool 是构建智能 Agent 不可或缺的部分，它让 Agent 能够与外部世界交互。Tool 的设计思路是提供清晰的接口，使 Agent 可以执行特定操作或访问特定服务。每个 Tool 通常包含以下要素。

- 1. 工具名称：唯一标识，便于在 Agent 中引用。
- 2. 工具描述：简要说明功能与用途，帮助理解其作用。
- 3. 工具输入的 JSON 模式：定义期望的输入格式，确保参数结构符合预期。
- 4. 调用的函数：指定被触发时应执行的函数或操作。
- 5. 结果处理方式：标明执行结果是否直接返回给用户。

这些要素构成 Tool 的基本框架，使 Agent 在决策时能精确指定并执行动作。简洁的输入有助于大语言模型更高效地使用 Tool，而清晰的名称、描述和 JSON 模式则确保模型准确理解和调用。
