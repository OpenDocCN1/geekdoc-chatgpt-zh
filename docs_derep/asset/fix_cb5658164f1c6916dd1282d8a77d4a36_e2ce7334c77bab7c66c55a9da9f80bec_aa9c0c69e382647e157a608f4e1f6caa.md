# **第七章**

# **金融数据持久化：存储介质选型与 MySQL 落地**

金融海量数据的存储管理是分析链路的关键一环。科学的存储方案能高效组织海量资产，保障安全与可用。

金融领域常见持久化形态涵盖：SQL 数据库、Excel、CSV（字符分隔值）、JSON（JavaScript 对象标记）。各有所长，适配场景各异：

（1）SQL 数据库：MySQL、PostgreSQL、Oracle 等关系型产品，擅长承载强结构、强关联的结构化数据。凭借标准 SQL 与 ACID 特性，支撑复杂检索与事务分析，为交易流水、账户主数据等核心业务首选。

（2）Excel：电子表格形态直观易懂，适配小规模数据整理、组合跟踪、报表产出等人工参与度高、灵活性要求强的轻量级场景。

（3）CSV：纯文本、轻量通用，以分隔符界定字段，跨语言、跨平台解析零门槛。是海量行情导入、指标批量导出、异构系统对接的标准交换格式。

（4）JSON：轻量级交换格式，原生支持嵌套层级，天然适配半结构化与非关系型数据。在金融场景常用于 API 返回的行情快照、经济指标、另类数据的交互与暂存。

选型无绝对优劣，唯“适配”论。需综合数据规模、结构复杂度、访问模式、下游工具链决策；工程实践常采“多格式分层共存”策略，各司其职。
