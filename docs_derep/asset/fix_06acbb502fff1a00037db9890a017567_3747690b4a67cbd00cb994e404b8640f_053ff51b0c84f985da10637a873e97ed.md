## 2.4 本章小结

本章从自然语言协同到标准化通信协议，自下而上梳理了智能体协同的工作脉络，形成了完整的通信认知体系。

自然语言协同部分，核心是从传统刚性通信向自然语言通信的范式转变。基于 LLM 的智能体可用人类语言灵活交互，突破了传统 ACL 协议的限制，同时需借助 Prompt 链、上下文管理和 System Prompt 等手段保证规范与可靠。Prompt 链将复杂任务拆解为关联步骤，支持顺序、分支、聚合等模式；上下文管理通过滑动窗口、摘要压缩、检索增强等方式应对窗口限制；System Prompt 用于定义角色与行为边界。

协同模式部分，本章涵盖了四种主流做法。顺序协同适用于依赖明确的流水线，职责清晰但难以并行；并行协同让多个智能体同时执行，可显著缩短耗时，但需处理结果合并与容错；Manager-Worker 层级协同引入管理层，实现智能调度与动态分配；竞争协同让多个智能体独立提出方案再经评选，提升决策的多样性。

协议层面，MCP 解决了智能体与工具数据的连接难题，终结了 M×N 集成困境并获广泛采纳。A2A 围绕 Agent Card、Task、Message 构建跨智能体交互规范，聚焦协作通信。ACP 作为 IBM 的轻量方案已并入 A2A，推动标准统一。实践中 MCP 负责赋能，A2A 负责协作，二者互补。

# 第3章 LLM驱动的智能体群落协同策略

在智能体群体中，协同策略是连接个体智能与群体智能的关键桥梁。传统多智能体系统依赖预设协调规则和固定分配算法，而基于 LLM 的群落则呈现出语言化的协同范式：任务理解、规划推理与动态调整均通过自然语言完成。本章将围绕语义理解与生成能力，探讨智能化任务规划、能力匹配、动态重规划以及故障恢复的实现思路。

## 3.1 Agent的任务规划与分配

【学习目标】

- 1) 掌握零样本任务拆解的原理与实施方法

LLM 驱动的规划与分配是群落协同的核心能力，系统通过语义理解将复杂需求自动拆分为可执行子任务，再依据各智能体的自然语言能力描述完成智能匹配。

### 3.1.1 零样本任务分解：让LLM自动拆分任务

任务分解是协同的起点。传统多智能体系统多依赖专家预设的规则模板或需大量标注的强化学习模型，前者覆盖有限，后者成本高。零样本任务分解利用 LLM 预训练积累的推理能力，无需额外训练即可实现智能拆解。

其思想源于“分而治之”。面对复杂需求时，LLM 先通过语义理解提炼关键要素，再分析要素间依赖关系，最后输出结构化子任务序列。可分为任务理解、依赖分析、计划生成三个阶段。

在理解阶段，LLM 解析用户自然语言指令，提取目标、约束和期望输出。例如“为科技公司制定下一季度市场营销方案”会被识别为综合策划，涉及市场分析、竞品研究、渠道选择、预算规划等多个维度。

### 3.1.2 能力感知分配：基于Agent能力描述的智能匹配

任务拆解后，需将子任务分配给具备相应能力的智能体执行。在 LLM 群落中，每个智能体以自然语言形式描述自身专长，能力感知分配正是利用语义理解将需求与描述匹配。
