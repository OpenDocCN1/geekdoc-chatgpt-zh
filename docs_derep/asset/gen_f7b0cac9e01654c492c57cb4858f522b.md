2. 推理
训练完成后，推理采用自回归方式，每轮基于已有 Token 生成下一个 Token，直至结束，更贴近人类语言习惯。示例：

一般机器学习推理需与训练保持一致，但 Mask 矩阵上三角为 0 导致训练时前向 Token 不能看到后向 Token，因此推理时需逐个生成并追加到序列末尾。
为提升推理速度，研究者提出 KV-cache 以用空间换时间。
（1）KV-cache 与推理
1）无 KV-cache 推理的复杂度
大语言模型推理是 Next Token Predict 的自回归过程，每轮把上一轮输入和输出拼接再预测。已知模型复杂度是 *O*（Length²），提示词 *n* 个 Token，经过 *N*-*n* 次自回归得到 *N* 个 Token，最终计算量为
计算量=*O*（*n*²）+*O*（（*n*+1）²）+*O*（（*n*+2）²）+…+*O*（（*N*-1）²）+*O*（*N*²）=*O*（*N*³）
2）有 KV-cache 的原理
KV-cache 降低上述复杂度。自回归时每次都要把前面所有 Token 重新喂入 Transformer，其中大量计算是重复的，于是把 Key 和 Value 缓存到内存，下次直接读取。
以“你好帅啊”四个 Token 为例说明有无 KV-cache 的差异。

从图 2-9 到图 2-12 可知，有 KV-cache 时每次推理 ***Q*** 形状为 [1，emb_size]，每次 ***Q***K***^T 复杂度为 *O*（Length）。若输入 *n* 个 Token，经过 *N*-*n* 次自回归得到 *N* 个 Token，最终 ***Q***K***^T 计算量为

● KV-cache 占用大量显存，需在 HBM 与 SM 之间搬运，增加开销。
● Transformer 复杂度既与注意力 *O*（Length²）相关，也与 MLP *O*（hidden_size²）相关，KV-cache 仅降低注意力部分。

**3.Prefill 和 Decode 阶段**
上述例子初始输入仅一个 Token 再自回归，实际任务常以多 Token 起步。
（1）Prefill 阶段
Prefill 是对输入序列进行预处理和编码的阶段，把上下文转为内部表示或键值缓存以便复用，避免重复计算。简单说，多 Token 输入时并行计算所有 Token 的 ***Q*** 和 ***K***。
Prefill 一次性处理大量文本，无需像 Decode 那样频繁搬运 HBM 矩阵，计算复杂度为 *O*（Length²），适合用高算力设备。Prefill 主要影响首字响应，端侧设备算力受限时，输入越长首字延迟越明显。
（2）Decode 阶段
Decode 以自回归方式逐步生成输出，每次生成一个词或 Token 并作为下一步输入。Prefill 完成后提示词的 KV-cache 已在设备中，Decode 即完成自回归任务。
