# k+1 混合执行模型与 LDc² 死路径特征分析

## 算法 5-2 启发式引导的 k+1 循环处理算法

承接前文，本节给出一种混合策略模型，用于生成覆盖循环体内目标节点的测试输入。该模型融合符号推演与具体运行，核心要素解析如下：
*   **k**：对目标环路 `L_target` 实施 k 次展开的符号推演；
*   **1**：对目标前环路 `L_before` 及目标后环路 `L_after` 各执行一次具体运行，获取部分可达轨迹；
*   **启发式**：引入评价函数，驱动 `L_before` 内的具体运行倾向于逼近目标的分支；
*   **+**：策略叠加，实现对目标可达路径的增量式拼装。

为提升效率，算法设置**预处理阶段**，一次性完成支配节点至目标的距离预计算。完整流程详述如下。

**预处理阶段**  
全量扫描控制流图（CFG）识别所有环路拓扑，标记出目标环路 `L_target`。随即反向回溯 CFG，获取目标节点 `t` 的支配节点集合 `S_t`，并计算该集合内所有节点到 `t` 的跳数距离集合。

**步骤 1：入口推演与环路分发**  
从程序入口出发，沿 CFG 推进符号推演，同步积累路径约束。每引入一个逻辑判断，即调用求解引擎校验可满足性；若冲突则判定该路径为死路，立即回溯。推演过程中一旦触及环路入口，依环路类型分流：
*   命中 `L_target` → 进入 **步骤 3**；
*   命中 `L_before` → 转至 **步骤 2**。

**步骤 2：启发式具体运行穿越 `L_before`**  
旨在获取 `L_before` 内部既可达又可能通往目标的路径片段。利用步骤 1 积累的前置约束，通过求解引擎生成多组测试输入并实运行，采集执行轨迹。所有轨迹在入口至 `L_before` 入口段共享相同前缀，随后在环路内部随机探索分支。  
**关键决策——距离排序**：依据预处理阶段预计算的节点距离，对轨迹按路径距离升序排列。距离越小，轨迹越逼近目标。截取距离最小轨迹在 `L_before` 内的路径段作为新前缀，回返 **步骤 1** 继续推演。

**步骤 3：目标环路 `L_target` 内的符号深度搜索**  
在 `L_target` 内开启全路径符号推演，确保覆盖到达 `t` 的路径。针对嵌套环路的复杂拓扑，采取递归策略：
*   遭遇 `L_before` → 转至 **步骤 2**；
*   遭遇 `L_target` → 递归执行 **步骤 3**；
*   若在预设展开上限 `k` 内未触达 `t` → 回溯至上一决策点尝试他分支；
*   若在 `k` 次展开内成功获得含 `t` 的可达片段 → 携带该片段进入 **步骤 4**。

**步骤 4：具体运行补全 `L_after` 尾部**  
利用步骤 3 得到的部分可达片段对应的测试输入，直接实运行获取目标节点之后的完整轨迹，从而拼凑出覆盖目标的全路径。

## 5.2 基于代码片段和反向符号执行的不可达路径判定技术

### 5.2.1 背景介绍

程序中的**死路径**（不可达路径）指任意输入均无法触发的执行轨迹。环路结构导致路径呈指数级增长，死路径随之激增，严重制约静态分析精度与效率——例如在自动测试生成中，大量无效路径消耗算力，导致覆盖率难以达标。

主流对抗手段是推演过程中的约束可解性检查。按推演方向分为：
*   **顺向推演**：从入口出发，顺控制流生成路径并判定可达性。
*   **逆向推演**：从指定目标点出发，逆控制流搜索判定。

**关键难点**：死路径根源在于约束冲突（CSP 问题），而 CSP 不可判定，不存在通用高效算法。既有手段（冲突片段识别、约束求解、具体运行等）成效高度依赖程序拓扑、约束类别、搜索策略。

**典型案例对比**（参考 P. Dinge 工作 [10]）：  
若路径末尾两个谓词冲突（如 `y>0` 与 `y==0`），顺向推演需走完全程才能发现冲突，极大概率超时；逆向推演从目标点出发，**即时发现矛盾**。路径越长，优势愈发明显。

[PRE2]

**启示**：死路径特征主导了最优判定策略，但现有研究鲜有系统性探索“特征-策略”映射。本章将重述判定问题，梳理路径特征，探究程序结构与死路径的关联，提出匹配的判定技术。

### 5.2.2 不可达路径判定问题的重定义

*   **路径建模**：路径 `p` 由结点序列 `n1...nk` 及控制流边组成，`k` 为长度。
*   **可达路径 (定义 5-4)**：存在输入 `v ∈ D` 使运行轨迹匹配 `p`。等同于路径约束 `Cp` 有解 (`Cp ⊨_D v`)。
*   **冲突约束 (定义 5-5)**：路径约束 `Cp = φ1 ∧ ... ∧ φk`。若 `p` 为死路径，则 `Cp` 在定域 `D` 内无解，记为 `Cp ⊨_D ⊥` (后续省略定域标记)。
*   **冲突触发点 (定义 5-6)**：死路径 `p` 中，存在子式 `φi ∧ ... ∧ φj` 无解 (`i ≤ j ∈ [1, k]`)。称 `j` 为冲突触发位置。**若 `k-j < i-1`，逆向分析比正向分析更快定位冲突。**

下节将通过实证研究，统计死路上冲突约束的位置分布特征。

### 5.2.4 依赖循环的等值代码片段

#### 1. 基本定义

*   **环路结构**：`L = (EL, NL, inL, outL)`，在 CFG 中表现为有向环。
*   **数据依赖 (定义 5-7)**：结点 `ni` 与 `nj` 对同一内存位置存在读写集合相交 (`R∩W`, `W∩R`, `W∩W` 不为空)，记为 `ni ↔ nj`。
*   **值传播 (定义 5-8)**：赋值节点 `v = expr(y)` 表示 `y → v`，具有传递性 (`y→v, v→z ⇒ y→z`)。
*   **条件依赖 (定义 5-9)**：两个判断节点 `ni`, `nj` 间路径 `p` 中，若无赋值且读变量集合相交，或经赋值传播建立关联，则存在条件依赖。这体现了不同位置约束对同一变量的关联。
*   **支配环路 (定义 5-10)**：结点 `n` 的支配结点集包含某环路 `L` 的入口和出口，则 `L` 为 `n` 的支配环路。意为：到达 `n` 的所有路径必完整穿越 `L`。
*   **独占节点 (定义 5-11)**：环路 `L` 内的结点 `n`，若从 `inL` 到 `n` 的所有路径要么不经过任何其他循环，要么完整包含另一环路 `L'` 的入口和出口。如图 5-10 所示。
*   **常量判等条件 (定义 5-12)**：判断节点 `n` 的逻辑表达式包含 `v = N` 形式（`N` 为常数）。C 语言常见形式列于表 5-1（如 `v==N` 真分支、`v!=N` 假分支、`if(v)` 假分支、`switch case N`）。求解器常对这类约束做专门优化。

#### 表 5-1 C 语言常量判等条件形式

| 代码形式 | 约束形式 (分支条件) |
| :--- | :--- |
| `if(v == N)` | 真分支: `v = N` |

| `if(v)` | 假分支: `v=0` |
| `switch(v) case N:` | 每个 `case N`: `v = N` |

#### 2. LDc² 模式定义

**定义 5-13 (依赖环路的等值代码片段 / LDc²)**  
设 `L` 为循环，`n` 为常量判等判断节点。当满足：
1.  **控制流前提**：`L` 是 `n` 的**支配环路**，**或** `n` 是 `L` 的**独占节点**；
2.  **数据流关联**：`L` 内存在节点 `n_l` 与 `n` 存在**数据依赖**或**条件依赖**；
3.  **纯净性约束**：`L` 内**不重新定义** `n` 中的变量（重定义会破坏内存位置一致性，违反依赖定义）。

则称 `L` 与 `n` 形成 **LDc² 模式**。

**模式语义说明**：
*   **支配环路/独占节点** → 确保从入口到 `n` 的路径必经 `L`，路径可达性取决于 `L`。
*   **数据/条件依赖** → 循环内操作直接决定 `n` 的约束变量值。
*   **无重定义** → 变量在循环内保持身份不变，依赖链完整未中断。

图 5-11 展示多种拓扑形态，符合者标 `√`，不符合者（如非支配环路 `L_4`、`L_5`）标 `×`。

**核心假设**：包含 LDc² 模式的程序中，常量判等判断节点 `n_c` 极易触发路径约束冲突，**且冲突恰在 `n_c` 处爆发**。这为靶向判定（如逆向推演切入点选择）提供了理论支点。
