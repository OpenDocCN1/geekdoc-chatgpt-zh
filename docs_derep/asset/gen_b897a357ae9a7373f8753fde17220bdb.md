业务服务层承载了商品服务、库存服务、订单服务等核心业务逻辑，专门处理具体的业务请求。该层会与数据层配合完成数据的增删改查。MCP Server 是整个系统的枢纽，负责接收 MCP Client 发来的请求并分发到对应的服务来执行任务。它完整实现了 MCP 协议，提供了资源访问、工具调用以及提示词模板等能力。

数据层承担数据的持久化与访问职责。为了方便本项目的演示，采用内存数据结构来模拟数据库的读写，到了生产环境则通常会接入真实的数据库系统。

[PRE0]

采用这种分层方式，可以在扩展系统功能的同时保持代码结构清晰、易于维护。后续开发时，各层的具体实现可以按需调整优化，而不会破坏整体架构。下面是用户场景应用层、业务服务层和数据层之间的协作流程。

- 用户通过 MCP Client 提出请求。
- 请求经由 MCP 传输到 MCP Server。
- MCP Server 解析请求后调用对应的业务服务。
- 业务服务在处理过程中会按需访问数据层读取或更新数据。
- 处理完成后业务服务把结果交回 MCP Server。
- MCP Server 对结果进行格式化，再通过 MCP 返回给客户端。
- 客户端将结果呈现给用户。
