从示例里可以看到，SqliteSaver 的接入逻辑和 MemorySaver 几乎一致，同样要指定当前会话的 thread_id；唯一的区别是实例化 SqliteSaver 时需要给出数据库文件的具体位置，若文件还不存在则会自动新建，之后所有会话的读写缓存都会落到该数据库中，从而实现持久化。

[PRE0]

图 5-30 持久化缓存的示例效果

持久化缓存的价值在于，即便会话被中断或程序被关闭，对话上下文依然会被安全地保存在后端存储里。重新启动会话后，模型能够基于已保存的历史记录继续进行连贯的问答，真正做到有记忆的对话体验。

**5.3.5 工具调用**

实际部署时，若仅依赖模型自动决策，在需要执行具体操作或跨系统调用的场景下风险更高。引入工具调用机制后，模型可在推理过程中调用外部函数或服务，把复杂推理与结构化执行解耦，模型聚焦决策与规划，具体执行交给可控可监控的工具。

借助 langgraph 可将该流程结构化，把每个工具封装为图中的节点，结合 OpenAI Function Calling 实现自动化调用，使智能体在多步推理中能够：

· 根据用户意图自动判断是否调用工具、调用哪个工具及使用哪些参数。
· 在需要时通过工具获取真实世界数据辅助推理。
· 将执行结果回传给模型，用于下一步推理或生成回应。
· 在流程中保留可观测的中间态，便于调试、审计与优化。

这种设计让推理、执行、反馈解耦，构建出可维护、可追踪、可控的执行链，适用于需要复杂业务流程和跨系统协作的生产级 AI 应用。下面分别讲解工具的定义与执行、模型与工具的绑定。

**1．工具定义和执行**

· ToolNode：用于把已定义的工具封装为可执行节点，模型发出调用后触发真实执行并把结果传回下一步推理。

**5.3.6 子图嵌套**

**5.4 典型 Agent 示例**

本节介绍实际应用中常见的 Agent 实现范式，包括 CRAG、ReAct 和 Supervisor 三类，覆盖从单步决策到多步推理、从自主执行到可控监督的不同路径。

（1）CRAG 融合检索增强生成与纠错机制，让 Agent 在生成答案的同时具备反思修正能力，提升准确性与可靠性。
（2）ReAct 结合推理与行动，让 Agent 边思考边行动，通过自然语言链式推理引导工具调用，是检索增强型 Agent 的常用思路。
（3）Supervisor 模式引入人类或系统监督作为外部可控环节，将中间状态或关键决策回传校验，适合对安全性要求高的生产环境。

下面结合既有知识展示三个示例，帮助在不同业务需求下选择合适的实现方式。

**5.4.1 CRAG**

**5.4.2 ReAct**

ReAct 是构建复合型 Agent 的常用范式，通过让大模型先对用户问题进行自主推理，再根据推理结果自动触发工具调用，并结合调用结果生成最终回复，实现高效可控的链式推理与工具调用闭环。
