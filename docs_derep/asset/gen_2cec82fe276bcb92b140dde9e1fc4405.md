# 从沙箱到权限，先把安全边界锁死

openclaw config set security.sandbox.allowedPaths '["~/workspace", "~/Documents/projects"]'

# 一键禁用文件删除

openclaw config set security.permissions.delete false

# 关闭 Shell 执行，进入只读模式

openclaw config set security.permissions.shell false

**精细权限白名单：把每种操作拆开管**

沙箱只是第一层，更细的控制是用权限白名单，明确每类动作是直接放行、需要确认还是直接拒绝。

{
 "security": {
  "permissions": {
   "fileRead": "allow",
   "fileWrite": "confirm",
   "fileDelete": "deny",
   "shellExec": "confirm",
   "networkRequest": "allow",
   "sendMessage": "allow"
  },
  "confirmThreshold": {
   "description": "需要用户确认的操作阈值",
   "fileSize": "10MB",
   "batchSize": 10
  }
 }
}

权限只有三种状态：allow 立即执行、confirm 执行前弹窗确认、deny 直接拦掉。把写文件和跑 Shell 设成 confirm，就是让每次关键操作都等你点头；删除文件用 deny，直接切断风险口子。
[PRE0]

**注意**

新接入的渠道尤其是群聊，先用最严配置跑一段时间验证稳定再逐步放开。群里一次 @ 就可能触发 Shell，风险必须提前控住。

**行为审计：随时知道龙虾在做什么**

进阶用法是定期看日志，特别是定时任务在跑的时候，不看日志等于闭眼飞行。

# 查看最近 24 小时全部操作
openclaw audit log --last 24h

# 只查最近 7 天的文件写入
openclaw audit log --action write --last 7d

# 只查 Shell 执行记录
openclaw audit log --action shell

# 开启实时操作推送
openclaw config set security.audit.notify true
openclaw config set security.audit.channel feishu

打开实时通知后，龙虾每做一次写文件、跑脚本、发消息等动作，飞书就会推送一条提醒。建议初期开几天确认行为符合预期，再酌情关闭。

## 错误学习循环（写进 SOUL.md）

每次任务结束后主动自检：
1. 结果是否符合用户预期？
2. 执行中是否报错或出现偏差？
3. 问题根因是什么？下次怎么避免？

- 把经验教训写入 MEMORY.md 的经验板块

有了这套机制，你不用盯输出质量，它自己盯自己。发现问题就总结、写入记忆，接近真正的自我进化用法。
