**7.2.3 节点与卡间的通信负载均衡**

**1.报告原文**

与 DeepSeek V2 使用的设备受限路由一致，DeepSeek V3 也采用受限路由机制来限制训练期间的通信成本。简言之，每个 Token 至多会被发送到 M 个节点，这些节点是依据分布在各节点上的专家集合的最高 K[r]/M 亲和分数之和来挑选的。在此约束下，MoE 训练框架几乎能够实现计算与通信的完全重叠。

为保证 Dualpipe 拥有足够的计算性能，我们定制了高效的跨节点全对全通信内核，兼顾调度与合并以节省通信 SM。内核实现、MoE 门控算法以及集群网络拓扑需要协同设计。具体而言，集群中跨节点 GPU 通过 IB 技术全互联，节点内通信通过 NVLink 处理。NVLink 提供约 160GB/s 带宽，约为 IB 50GB/s 的 3.2 倍。为了充分利用 IB 与 NVLink 的差异，我们限制每个 Token 最多分发到 4 个节点，从而降低 IB 流量。路由确定后，Token 会先经 IB 传输到目标节点上同索引的 GPU，到达后通过 NVLink 迅速转发到托管目标专家的具体 GPU，避免被后续 Token 阻塞。这样 IB 与 NVLink 的通信可完全重叠，每个 Token 能在每个节点平均挑选约 3.2 个专家，且不产生额外通信开销。这意味着尽管实际只路由 8 个专家，仍可在相同通信成本下扩展到最多 13 个，即 4 个节点，每个节点平均约 3.2 个专家。总体来看，仅需 20 个 SM 即可充分利用 IB 与 NVLink 的带宽。

**2.解读**

卡间与节点间通信均衡的核心在于 NVLink 与 IB 带宽差异巨大，因而需要限制跨节点流量，这对应第六章提到的专家分组策略，每组专家放在一个节点，最终限制每个 Token 分发到前 K_group 个节点，在这 K_group 个节点内再挑选前 K_expert 个专家，其中 K_expert > K_group。

另外，卡内通信速度约为节点间通信速度的 3.2 倍，为避免卡内带宽浪费，需要让卡内通信量约为节点间通信量的 3.2 倍。选择 4 个节点推理时，每个 Token 理论上可挑选约 12.8 个专家，此时卡内与卡间通信达到平衡。

### **8.1 混合精度训练**

**8.1.1 为什么要进行混合精度训练**

混合精度训练在同一流程中混用不同数值精度，如 FP32 与 FP16。矩阵乘、卷积等计算放在低精度执行，梯度累加、权重更新等关键操作保留高精度，以此换取内存与速度。

主要原因：

**1.减少内存占用**
FP16/BF16 相比 FP32 可将显存减半，支持更大模型或更大批大小。

**2.提升计算速度**
低精度在 Tensor Core 上执行更快，训练迭代加速。

**3.降低通信开销**
低精度数据传输量更小，分布式训练带宽压力下降。

**4.保持模型精度**
关键路径保留 FP32 避免梯度消失与数值不稳。

**5.节能与成本效益**
低精度计算能耗更低，训练成本与碳排放下降。

**8.1.3 DeepSeek V3 的混合精度训练**

DeepSeek V3 是公开首个使用 FP8 混合精度训练的大模型，全程涉及三种精度。下面以报告解读。

**1.报告原文**

为加速训练，核心 GEMM 内核均以 FP8 实现。这些 GEMM 操作接受 FP8 精度张量作为输入，并以 BF16 或 FP32 精度生成输出。图 8-2 中与线性算子相关的三个 GEMM，即 Fprop、前向传播、Dgrad、激活反向传播、Wgrad、权重反向传播，均以 FP8 执行。相比 BF16，理论算力翻倍。此外，FP8 Wgrad GEMM 允许将激活值以 FP8 精度存储以便反向使用，大幅减少内存消耗。

尽管 FP8 效率高，部分算子对低精度敏感，仍需更高精度。经调研，嵌入模块、输出头、MoE 门控模块、归一化算符和注意力算符保持原始精度 BF16 或 FP32，以确保 DeepSeek V3 训练动态稳定。为进一步保证数值稳定性，主权重、权重梯度与优化器状态以更高精度存储。虽带来少量内存开销，可通过跨多个 DP 等级的分片在分布式训练系统中最大限度减少影响。
