##### 2. AI Agent 与工作流的本质差异

AI Agent 和工作流的分化主要集中在三个维度。

（1）确定性 vs 适应性
工作流在搭建时就把执行路径锁死，环节间的依赖关系清晰可预见，更像一份照本宣科的剧本，人或系统按部就班完成台词。AI Agent 则面向动态环境设计，内置感知与判断能力，更像一位现场即兴的演员，能根据变化即时调整表演。

（2）规则驱动 vs 目标驱动
工作流靠预设规则和条件推进，路径由开发者硬编码，例如“若条件A满足则执行步骤B”。AI Agent 以达成目标为导向，通过推理或学习自主挑选最优路径，例如“目标是解决问题”，它可能尝试多种策略来收敛答案。

（3）控制权的归属
工作流的控制权牢牢在设计者手中，执行方只是按规操作。AI Agent 把部分控制权让渡出去，拥有一定自主决策空间。

两者在企业落地各有价值点。将 Agent 嵌入到工作流中，能让业务自动化既保持规范又具备智能，提升效率与客户满意度。

#### 11.1.2 AI 原生工作流与 AI 融合 ERP 的区别

AI 构建的工作流与 AI 与 ERP 等企业系统的融合，在定位上存在明显分野，具体对照见表 11-2。

表 11-2 AI 原生工作流与 AI+ERP 融合的对比

| 对照维度 | AI 原生工作流 | AI 与 ERP 等企业系统的融合 |
| :--- | :--- | :--- |
| 核心职能 | 任务自动执行、智能化处理、数据驱动的决策辅助 | 资源统一、业务流程统筹、财务与供应链运营 |
| 目标 | 提升单项任务的效率与智能化程度 | 全面优化资源使用与整体业务运转 |
| 数据处理 | 侧重实时分析、预测与智能决策支持 | 侧重结构化数据存储、查询与报表输出 |
| 流程管理 | 灵活可调，快速响应业务变化 | 相对固化，强调稳定与标准化 |
| 决策支持 | 实时个性化建议 | 基于历史数据的综合分析与规划 |
| 集成与扩展 | 易于与其他系统对接，功能可快速扩展 | 集成难度大，扩展需兼顾整体架构 |
| 用户体验 | 交互强，支持多轮对话与自然语言 | 功能完备，界面相对复杂 |
| 成本与效益 | 起步投入低，按需扩展，适合中小企业敏捷上线 | 初期投入高，适合大企业长期战略 |

从核心职能看，AI 原生工作流用技术实现自动化与智能化，如自动生成报告、智能客服；AI+ERP 则是强化 ERP 能力，如财务预测、供应链优化。

从目标看，前者追求单点任务的快速响应与效率提升，后者追求企业整体资源与流程的智能升级。

从数据能力看，前者擅长动态数据的实时分析与预测，后者侧重对 ERP 结构化数据的解析与分析，如发票识别、数据洞察。

从流程看，前者灵活可变，后者稳定标准化，利于长期规划。

从决策看，前者提供即时个性化建议，如风险评估、客户洞察；后者提供基于历史的综合分析与规划，如预算、资源分配。

从集成看，前者接入快、扩展敏捷；后者集成复杂、需考虑全局影响。

从体验看，前者对话友好、自然；后者功能全面但学习成本较高。

从成本看，前者投入门槛低，适合中小企业快速部署；后者投入高，契合大企业长期布局。

### 11.2 工作流的常见分类

工作流可按场景与特质做多种划分。

##### 1. 按功能划分
按功能可分为自动化任务工作流、数据处理工作流、客户服务工作流、内容生成工作流、审批工作流、实时工作流、批量工作流、对话式工作流、非对话式工作流、行业专属工作流等，具体见表 11-3。

表 11-3 不同功能类型的工作流特征

| 工作流类型 | 特征 |
|---|---|
| 自动化任务工作流 | 串行执行任务，减少人工干预；适用于文件处理、数据清洗、报告生成、任务调度 |
| 数据处理工作流 | 集中于数据的清洗、分析与转换；适用于预处理、数据可视化、挖掘与机器学习、库同步 |
| 客户服务工作流 | 以自动化或智能交互提升服务效率；适用于智能客服、反馈处理、多轮对话支持 |
| 内容创建工作流 | 用于生成和优化内容；适用于文本、图像、视频编辑 |
| 审批工作流 | 支撑多级审批；适用于采购、项目、文档审批 |
| 实时工作流 | 要求即时响应；适用于实时分析、实时客服、实时监控告警 |
| 批量工作流 | 集中批处理，通常定时触发；适用于大数据处理、定时任务、批量报告 |
| 对话式工作流 | 以对话交互为核心；适用于智能客服、虚拟助手、多轮应用 |
| 非对话式工作流 | 全自动无需交互；适用于批量处理、定时任务、自动报告 |
| 行业特定工作流 | 按行业定制；适用于医疗病历管理、教育成绩管理、金融交易审批等 |

##### 2. 按复杂度划分
可分为简单工作流、复杂工作流、多 Agent 协作工作流。

简单工作流流程短、节点少、逻辑直观，多为线性任务，用于单一自动化，如格式转换、简单清洗。

复杂工作流流程繁复，含多分支与条件判断，常跨系统协作，需处理多输入输出并动态调整，如订单处理、审批链路、ERP+CRM 集成。

多 Agent 协作工作流由多个 Agent 分工，需共享上下文与智能决策，适合多轮交互与复杂决策，如多专家客服、自动化项目管理。

表 11-4 不同复杂度的特征

| 工作流类型 | 特征 |
| :--- | :--- |
| 简单工作流 | 流程简明、节点少、逻辑清晰，单任务自动化 |
| 复杂工作流 | 流程复杂、分支条件多、跨系统协作 |
| 多 Agent 协作工作流 | 多 Agent 协同、共享上下文、适合多轮交互与复杂决策 |

简单任务与简单工作流的区别见表 11-5。

表 11-5 简单任务 vs 简单工作流

| 维度 | 简单任务 | 简单工作流 |
| :--- | :--- | :--- |
| 复杂性 | 单一操作如发邮件、求和 | 多步骤按序执行以达成目标 |
| 自动化程度 | 需人工或手动 | 全自动，步骤间顺序明确 |
| 流程结构 | 无明确结构，独立操作 | 有开始、处理、结束节点 |
| 系统集成 | 不涉及 | 可能调用 API 等简单集成 |
| 应用场景 | 单一操作 | 需多步骤完成如文件转换 |
| 执行逻辑 | 简单，无分支 | 可能含简单条件分支 |
| 任务依赖 | 无依赖 | 有依赖，前置输出为后置输入 |
| 资源需求 | 较低 | 需一定内存存储等 |
| 扩展性 | 差 | 可增添节点，扩展性好 |
| 监控管理 | 无需 | 需简单日志监控 |

##### 3. 按执行方式划分
共 7 类。

- (1) 顺序工作流 按序执行，每一步依赖前一步完成。
- (2) 状态机工作流 在预定义状态间流转，顺序非固定，依赖条件或触发器，多用于动态流程如工单解决。
- (3) 规则驱动的工作流 由预设条件与业务逻辑控制，如电商退货按产品类型自动分派。
- (4) 事件驱动的工作流 由特定事件触发，按需启动，适用于实时响应如异常检测告警。
- (5) 基于 AI 的工作流 利用机器学习、NLP 等实现自动化与优化，如智能客服自动理解并回复。
- (6) 批量工作流 定时或集中处理大数据、定时任务、批量报告。
- (7) 实时工作流 要求即时执行，适用于实时分析、实时客服、实时监控。

##### 4. 按交互方式划分

- (1) 对话式工作流
特点是通过对话交互。场景包括智能客服、虚拟助手、多轮应用。
对比基于提示词的 AI 工具，交互上支持多轮对话、记忆上下文、流式输出；后者多为单轮、无记忆、一次性输出。
任务复杂度上，对话式可处理复杂业务并动态分支；提示词工具适合简单生成、翻译。
应用上，对话式擅长客服、个性化建议、复杂问题引导；提示词工具擅长文本生成、简单数据处理。
体验上，对话式更自然、个性化；提示词工具交互机械、服务通用。
技术上，对话式架构复杂，含记忆、上下文管理、多节点；提示词工具简单，单次 API 调用。

表 11-6 对话式工作流与基于提示词 AI 对比

| 维度 | 对话式工作流 | 基于提示词的 AI |
| :--- | :--- | :--- |
| 交互方式 | 多轮交互，带记忆与流式输出 | 单轮交互，无记忆，一次性输出 |
| 任务复杂度 | 可处理复杂任务并动态调整 | 仅适合简单任务，流程固定 |
| 应用场景 | 智能客服、虚拟助手、复杂解答 | 文本生成、数据处理、内容优化 |
| 用户体验 | 自然交互，个性化服务 | 机械交互，通用服务 |
| 技术实现 | 复杂架构，多节点处理 | 简单架构，单节点处理 |

具有记忆的 DeepSeek、Kimi 等可视为 Agent 类工作流。

- (2) 非对话式工作流
完全自动化，无需用户干预，适用于批量数据处理、定时任务、自动化报告生成。

##### 5. 按应用场景划分
分为企业级工作流、个人工作流、行业特定工作流。

企业级用于内部复杂流程，如 ERP/CRM 集成、项目管理。
个人级用于任务管理，如邮件分类、日程管理。
行业特定针对行业需求定制，如医疗病历、教育成绩、金融审批。

### 11.3 工作流的适用范围

##### 1. 适用领域和场景
- (1) 企业内部流程管理 优化请假、报销、审批等，实现自动化、规范化、透明化。
- (2) 跨部门协作 建立高效协同机制，信息快速传递，支撑研发、生产、销售全链路。
- (3) 客户关系管理 自动化投诉处理与服务流程，实时跟踪，提升满意度。
- (4) 生产流程管理 优化生产、物料、质量流程，实时监控并快速解决问题。
- (5) 项目管理 覆盖启动、执行、监控、收尾，协调进度与问题。
- (6) 营销活动管理 规划、执行、评估营销活动，实时跟踪并优化。
- (7) IT 与软件开发 用于敏捷开发、进度管理、Bug 跟踪，如 Jira、Trello。
- (8) 金融服务 贷款审批、理赔、风险管理，实现标准化与监控。

##### 2. 共性原因
适用场景多呈现流程重复、跨部门协作、复杂审批等特征，适合处理多步骤、结果要求严格的任务，能协调部门、保障信息流畅、确保环节可控。

##### 3. 不适用场景
简单任务、无需多步骤的操作、超高实时性需求、依赖人工创造的任务不适合。工作流擅长有状态异步长周期业务，对高频交易等极致实时场景响应不足；对艺术创作、广告创意等高度灵活任务，预设规则会限制创造力。
