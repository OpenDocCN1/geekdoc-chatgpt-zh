#### 8.1.9 从 LangChain 平滑迁移到 LangGraph

LangChain 在 2023 年便聚集了活跃社区来定义大模型应用规范，至今已发布三个大版本。其构建体系里最关键的两块是 RAG 与 AI Agent，Agent 的底层架构如图 8.12 所示。

[PRE12]

在 LangChain 框架中，AI Agent 被拆分为 Agent、Message、Toolkits 三大核心。每个 Agent 通常由大语言模型 + 提示词 + 输出解析器构成，形成一条 Chain 来处理用户输入。Agent 可接收的输入主要有三类：Input 为用户原始提问，Model Response 为模型对子任务的中间响应，Context 则承载上下文信息。Agent 的输出会连向工具库，具体调用哪些工具由 Agent 拆分后的子任务决定。大模型调用外部函数分两步：先识别工具，再执行。Messages→AI Agent→Toolkits 的流程负责拆解子任务，并在工具库中匹配工具、提取名称与参数，这是一条相对静态的执行线；把决策落地为实际行动的工作则交给 AgentExecutor。

总体来看，Agent 的职责是接收输入并决定操作，但并不直接执行，执行由 AgentExecutor 完成。只有把作为决策核心的 Agent 与负责运行的 AgentExecutor 结合，才能构成完整的 Agent。其中的 AgentExecutor 负责调用 Agent 并执行其指定的工具，从而实现整体功能。

LangChain 仍是构建大模型应用的前沿框架之一。v0.3 版本基本完成了从传统类向 LCEL 的过渡，定义和执行分步操作序列变得更简洁高效。专业上说，LangChain 本质上构建的是一个有向无环图 DAG。随着 AI 应用尤其是 AI Agent 的发展，对大模型的使用正从单纯的工具执行转向更复杂的推理引擎，这正是 LangGraph 诞生的动因。该转变要求更多循环结构与复杂条件交互的支持，基于 LCEL 的线性序列在构建更高级系统时逐渐显现局限。

#### 8.1.10 LangGraph 构建 Agent 的底层原理

##### 1. LangGraph 概述

从名称看，LangGraph 与 LangChain 关系紧密。实际上 LangGraph 是以 LangChain 表达式语言为基础构建的框架，专门用于开发 AI Agent。因此在大模型接入与 Agent 构建上的优势可以自然迁移。从技术角度看，大模型本身无法执行行动，只能输出文本，即接收输入并给出响应。

##### 2. LangGraph 的基础图模型

在图式框架中，任何可执行的功能都可作为对话、Agent 或程序的起点。该起点可以是大模型的 API、基于大模型的 Agent，或通过 LangChain 等实现的线性序列，如图 8.13 中“Start”圆圈所示。无论形式如何，它首先处理用户输入并决定后续操作。图 8.13 展示了基于 LangGraph 概念的基础 Agent 模型。

在 LangGraph 里，任何带有可执行逻辑的组件都被视为节点 Node，包括模型调用、搜索操作及条件判断等。图中的“Start”节点作为流程入口，负责接收用户输入，并根据处理需求决定下一步走向。
