# 第 7 章 智能网联交通事件场景实战

[PRE6]

智能网联交通事件场景应用

目前多数车辆仍以单车智能为主，驾驶员的决策主要依靠眼前所见的路况，难以和周边交通参与者协同，也无法提前获知远端道路的交通态势，因而很难做出最优驾驶决策。

在天气相关的安全方面，驾驶员很难感知到很远的前方天气、积水或湿滑等路况，无法提前获知潜在风险，常在遇到坑洼、积水时才手忙脚乱地猛变道、急刹车，进而带来碰撞隐患。道路前方若出现拥堵而未能及时获知，路线调整也会滞后，影响出行效率。

在应急管理方面，由于难以关注后方情况，遇到特种车辆需要优先通行、警方行动需借道等情形时，难以及时避让或换道，既耽误特种车辆通行，也易引发拥堵甚至事故。

因此，让自车实现超视距、提前感知前方状况是关键。通过事件主动下发，提前提示诱导驾驶员调整行程、提前变道避让或协调通行，能够显著提升驾驶体验与道路通行效率。

在智能网联场景能力上，限速提醒可告知当前道路限速，减少违章超速；道路危险状况的提前推送和前方拥堵提醒能让驾驶员从容决策；紧急车辆提醒可协调交通参与者为特种车辆让行，满足快速通行需求并降低对整体交通的干扰。

## 7.2 限速预警技术

### 7.2.1 限速预警的定义

限速预警 Speed Limit Warning，SLW 指主车 HV 行驶中一旦超出路段限速，系统会对驾驶员发出预警并提醒减速。该应用适用于所有设有速度限制的普通道路与高速公路，可辅助避免超速，减少安全隐患与事故。

### 7.2.2 限速预警的主要场景

HV 与 RSU 需支持短程无线通信。行驶过程中，RSU 周期性下发特定路段的限速信息。当 HV 判断自身位于 RSU 指示的路段且车速高于限值时，SLW 会向驾驶员发出预警提示减速，如图 7.1 所示。

[PRE7]

图 7.1 车速超过限速时进行预警

### 7.2.3 限速预警的基本工作原理与算法实现

SLW 工作原理如下。

① HV 解析收到的 RSU 消息，提取限速路段与具体限速值。

② HV 根据自身定位与行驶方向，将位置映射到对应路段。

③ 若 HV 处于限速路段内，则校验当前车速是否合规；不合规时触发超速报警，系统通过 HMI 向驾驶员发出限速预警，提示减速。

本册 SLW 算法的实现思路如下。

①定义函数 doSLW()，接收三个参数：hvInfo 和 spdLmt。hvInfo 为主车信息，spdLmt 为所在道路限速。

②内部先初始化 warningFlag 与 adviser。warningFlag 表示预警等级，0 为无需预警，1 为需减速预警；adviser 表示建议类型，keep 为维持现状，slow_down 为减速行驶。

③从 hvInfo 中提取主车 x 坐标、y 坐标、速度、航向角、尺寸与车辆类型并赋值。

④判断主车速度是否大于道路限速 spdLmt，若是则将 warningFlag 置 1，并将 adviser 置 slow_down。

⑤最终返回 warningFlag 与 adviser。

### 7.3.1 紧急车辆提醒的定义

紧急车辆提醒 Emergency Vehicle Warning，EVW 指主车 HV 行驶过程中接收到紧急车辆提醒，为消防车、救护车、警车或其他呼叫车辆提供让行。EVW 应用帮助 HV 实现对紧急车辆的让行。

### 7.3.3 紧急车辆提醒的基本工作原理与算法实现

EVW 工作原理如下。

①解析收到的紧急车辆 RV 消息，筛选出落在 HV 影响区域的车辆。

②将范围内的一定距离内的紧急车辆作为优先让行对象。

③计算优先让行紧急车辆 RV 的到达时间与距离。

本册 EVW 算法的实现思路如下。

①定义函数 doEVW()，接收两个参数：hvInfo 与 rvInfo。分别表示主车与远车信息。

②内部先初始化 warning_flag 与 adviser。warning_flag 表示预警等级，0 为无需预警，2 为需变道预警；adviser 表示建议类型，keep 为保持现状，lane_change 为变道。

③从 hvInfo 与 rvInfo 中提取主车与远车的 x 坐标、y 坐标、速度、航向角、尺寸与车辆类型，以及远车的刹车、灯光与 abs 状态并赋值。

④调用自定义函数 my_calc_distance() 计算主远车间的纵向、横向与直线距离及相对位置关系。

⑤若主远车同时满足以下三条件，则将 warning_flag 设为 1 并继续判断：远车为紧急车辆、主车速度大于 0.1 且远车距主车后方小于 80m。

⑥若两车同车道且远车位于主车后方 20m 范围内，则将 warning_flag 设为 2，并将 adviser 设为 lane_change。

⑦最终返回 warning_flag 与 adviser。

## 7.4 道路危险状况提示技术

### 7.4.1 道路危险状况提示的定义

道路危险状况提示 Hazardous Location Warning，HLW 指主车 HV 行驶至存在潜在危险，如桥下深积水、路面大坑、湿滑路面、前方急弯等路段时，HLW 应用会对驾驶员进行预警。该应用适用于城市道路、郊区道路、高速公路等易发危险路段以及临时出现的危险路段。

HLW 可及时向周边车辆推送危险信息，便于驾驶员提前处置，提升对危险路况的感知能力，降低进入危险区域的事故风险。

### 7.4.2 道路危险状况提示的主要场景

道路存在危险状况时，附近 RSU 或临时路侧设备对外广播道路危险提示信息，包含位置、危险类型、危险描述等。行驶至该路段的 HV 根据信息及时避让，避免事故，如图 7.3 所示。

### 7.4.3 道路危险状况提示的基本工作原理与算法实现

HLW 工作原理如下。

①具备短程无线通信的 RSU 周期性广播道路危险提示信息。

② HV 依据自身位置与危险提示信息，计算与危险区域的距离。

③ HV 依据当前速度估算到达危险区域的时间。

④系统通过 HMI 及时向驾驶员发出预警。

本册 HLW 算法的实现思路如下。

①定义函数 doHLW()，接收两个参数：hvInfo 与 rteInfo。hvInfo 为主车信息，rteInfo 为 RSI。

④调用 distance() 函数计算主车与危险路段的距离。

⑤若距离小于安全阈值，则将 warning_flag 置 1。

⑥最终返回 warning_flag。

## 7.5 前方拥堵提醒技术

### 7.5.1 前方拥堵提醒的定义

前方拥堵提醒 Traffic Jam Warning，TJW 指主车 HV 前方发生拥堵时，RSU 将拥堵路段信息发送给 HV，TJW 应用提醒驾驶员。该应用适用于城市、郊区普通道路及高速公路拥堵路段预警。

TJW 可提醒驾驶员前方路段拥堵，有助于合理规划行车路线，提升通行效率。

### 7.5.2 前方拥堵提醒的主要场景

TJW 的主要场景为：HV 接近 RSU，RSU 周期性广播局部道路拥堵数据；TJW 应用结合车辆定位与行驶状态，计算车辆在路网中的位置并判断前方是否拥堵，若有则提示驾驶员。

### 7.5.3 前方拥堵提醒的基本工作原理与算法实现

TJW 工作原理如下。

① HV 根据收到的道路数据及自身定位运行数据，判定在路网中的位置与行驶方向。

②判断前方道路是否拥堵，若存在则直接提醒驾驶员。

本册 TJW 算法的实现思路如下。

前方拥堵提醒算法描述

①定义函数 doTJW()，接收两个参数：hvInfo 与 rteInfo。hvInfo 为主车信息，rteInfo 为 RSI。

②内部先初始化 warning_flag。warning_flag 表示预警等级，0 为无需预警，1 为前方拥堵提醒。

③从 hvInfo 中提取主车 x 坐标、y 坐标、速度、航向角、尺寸、车辆类型与所在车道，从 rteInfo 中提取道路拥堵状况与拥堵范围并赋值。

④调用 distance() 函数计算主车与拥堵路段的距离及相对位置关系。

⑤若距离小于设定阈值且主车位于拥堵路段所在车道，则将 warning_flag 置 1。

⑥最终返回 warning_flag。
