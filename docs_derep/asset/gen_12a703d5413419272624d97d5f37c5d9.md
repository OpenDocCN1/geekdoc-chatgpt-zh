### 7.2 用 LangChain 驱动 DeepSeek-V3 搭建高阶 RAG 对话系统

#### 7.2.1 LCEL 核心思想快速上手
LCEL 是 LangChain Expression Language 的缩写，是一种声明式的链式表达式语言，用来把不同的算子串联起来完成具体的任务，比如 RAG 或 Agent。所有组件都通过统一的 Runnable 接口接入，从而构成可执行的流程。

LangChain 内部每个模块都是 LCEL 对象，基于这些对象拼接而成的链本身也仍是 LCEL 对象，因此可以用统一的调用方式去执行定制链、并行化、降级、动态改链等操作。LangChain 的整体模块划分如图7.2 所示。

[PRE0]

LCEL 对象的典型好处有：

- （1）接口统一：每个对象都实现了 Runnable 接口，拼接起来非常顺滑。
- （2）组件化开发：各个部件可以独立编写和测试，只要输入输出对齐，就能通过 LCEL 组合。
- （3）扩展方便：组件都支持 invoke、batch、stream、ainvoke 等通用调用方式，组合场景很灵活。

LangChain 的 Model I/O 层提供了标准化的扩展接口，用于对接外部大模型。Model I/O 涵盖提示输入、模型本身和输出处理，大致就是把 Prompt 送入模型，再拿到推理结果。

在该层设计中包含三个核心环节：Format、Predict、Parse。如图7.3 所示。

- Format：对应 Prompt Template，用模板化方式管理模型输入。
- Predict：对应 Models，通过通用接口调用不同大语言模型。
- Parse：对应 Outputs，用于从模型推理结果中抽取信息并按预设模板规范化。

[PRE1]

##### 1. Format
提示词模板是第一步。传统做法是手写提示词并依赖 Few-Shot、CoT 等技巧来提升效果，但在工程化场景中提示词不能一成不变。因为应用要面对多样化的用户意图和场景，固化的提示会限制灵活性和覆盖面。比如做天气查询时，用户可能问“今天天气怎样？”或“明天纽约气温多少？”，如果模板只适配一种问法，就很难通用，影响体验。

提示词模板把 API 调用、问答流程等复杂逻辑封装成结构化格式。准备好外部函数信息和用户问题后，就能生成定制化提示，引导模型按既定思路思考并触发函数调用，如下所示。

[PRE2]

因此模板支持变量和动态内容注入，同一应用可根据不同输入动态调整提示，更好地满足具体需求。LangChain 正是通过这种方式提升通用性和体验。

##### 2. Predict
Predict 负责模型从接收输入到完成推理的全过程。按模型类型可分为 Base 类和 Chat 类，LangChain 在 Model I/O 中分别归为 LLM 和 Chat Model。以 OpenAI 的 Completion 与 Chat Completions 为例。

[PRE3]

LLM 提供基于 Prompt 的内容生成能力，是简化版的大模型功能。Chat Model 则抽象了聊天 API，需要保留对话记忆，具有更强的会话属性。

##### 3. Parse
大模型输出并不稳定，相同 Prompt 可能得到不同格式的答案。在纯自然语言交互中问题不大，但在工程链路里，模型的输出往往是下一步处理的输入，因此必须做规范化。

输出解析器用来结构化模型响应，可执行格式指令或更深层的解析。

总体看，Model I/O 的抽象一方面让开发者能快速接入 OpenAI、ChatGLM、Qwen 等不同模型并按规范推理；另一方面通过输入输出的模板化处理，更贴合工程最佳实践。接下来介绍如何在 LangChain 中集成并操作这三个环节。
