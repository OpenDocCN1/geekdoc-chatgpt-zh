需求到交付：让 PRD 成为产品定盘针

项目起步的早期，产品经理往往承担信息汇总与转译的工作。来自用户、业务等多个来源的需求要点，需要被收集、梳理、整合，再与研发、业务及其他相关人员反复讨论、权衡、确认，最终沉淀为一份产品需求文档。PRD 的核心在于把产品在功能、性能、体验、安全、可靠性等方面应达到的水平写清楚，保证开发始终围绕初始用户意图推进，并在全流程提供参考依据。这类文档一般涵盖以下几个维度。

❑ 需求规格说明书：把系统在功能、性能、界面、数据、安全、接口等方面的具体诉求系统化呈现，形成研发与客户都能读懂并确认的材料。

❑ 用例规约：针对系统的每一个用例给出说明，包含用例名称、描述、参与方、前置条件、主流程、分支流程、异常处理等，帮助团队理解使用场景与具体要求。

❑ 界面原型设计：借助原型图展示界面的布局、视觉风格与交互逻辑，让客户与研发对界面效果达成一致并便于迭代。

❑ 数据字典：对系统中使用的各类数据元素的定义、属性、关联关系与类型进行详细说明，明确数据的具体要求。

❑ 需求跟踪矩阵：把需求规格中的条目与测试用例、代码模块、设计文档等建立对应关系，便于全流程追踪与落地。

PRD 的作用十分关键。它为研发提供了清晰方向，降低研发与业务之间的沟通成本，避免后期返工，同时也是交付的重要成果，客户可通过它了解产品的具体内容与设计思路。

某收单机构拟建设 TMS，以统一管控分散在全国各地的收银终端，提升信用卡业务处理效率，同时减轻大规模商户终端运维的复杂度。

1.3 项目范围

2.1 产品概述

本项目致力于为支付机构打造一套终端集中管控平台，覆盖全国范围的收银设备，帮助提升收单业务流转效率并规范商户侧终端管理。面向对象主要是内部运营团队，核心工作集中在终端、配置、程序、密钥的统一管理。

2.2 系统架构

系统采用分布式形态，由前端展示层、后端业务层和数据层构成。前端负责呈现人性化的操作界面，后端处理业务逻辑并完成与其他平台的对接，数据库则承担数据持久化职责。

2.3 系统组成模块

TMS 主要划分为两层。
❑ 核心功能层：终端管理、配置管理、程序管理、密钥管理。
❑ 支撑功能层：与商户信息平台、日志处理平台、通知推送平台、统一登录平台集成。

2.4 用户角色及其职责

主要面向以下角色。
❑ 终端管理员：负责各地设备的日常管控，包括终端、配置、程序、密钥操作。
❑ 系统管理员：负责平台运维，涵盖配置、性能调优、安全保障。
❑ 商户：通过商户信息平台实时同步信息，为终端管理提供数据支撑。

2.5 操作环境

运行环境要求如下。
❑ 计算：基于云服务的容器管理平台。
❑ 数据库：MySQL。
❑ 网络环境：需打通商户信息平台、日志处理平台、通知推送平台和统一登录平台的互联。
❑ 系统资源：需支撑 50 个并发请求，平均响应控制在 3s 以内。 [PRE6]

3 功能需求

3.1 核心功能层

3.1.1 设备管理

设备管理包含查询终端信息、监控运行状态和远程操作等能力。用户可在界面上查看各地 POS 的基本信息，实时掌握设备状态，并在必要时执行重启、关机等远程操作。

3.1.2 参数管理

参数管理支持设置、更新和查询。用户可在界面上调整 POS 运行参数并即时下发，确保设备正常运行，同时可查询当前参数以便调优或排查故障。

3.1.3 软件管理

软件管理覆盖版本控制、更新、安装与卸载。用户可查看终端已装软件版本，执行更新，在需要时安装或卸载组件，保证设备软件始终保持最新，提升安全与稳定。

3.1.4 密钥管理

密钥管理包含生成、更新、分发和注销。用户可在界面上创建并更新 POS 所需密钥，实现安全分发，并在必要时执行注销，保障终端安全。

3.2 支撑功能层

3.2.1 远程支持

远程支持使管理员能直连 POS，为商户提供实时技术支持和问题解决，提升满意度并降低维护成本。

3.2.2 日志管理，与日志处理服务集成

日志管理通过接入日志处理服务实现日志采集、分析与报表。用户可在界面上查看并分析终端运行日志，及时发现和处置问题。

3.2.3 用户管理，与单点登录服务集成

用户管理依托单点登录服务实现统一登录、权限分配和身份认证。管理员可在界面上为不同角色分配权限，保障系统安全。

3.2.4 通知管理，与通知发送服务集成

通知管理通过接入通知推送服务实现故障、更新、安全等各类通知的推送。用户可在界面上查看和处理来自终端的通知，确保设备正常运行。 [PRE8]

4 性能需求

4.1 响应时间

响应时间是体验的关键指标。TMS 应在不同场景下保持快速反馈。
❑ 终端管理操作响应不超过 2s。
❑ 配置管理操作响应不超过 1s。
❑ 程序管理操作响应不超过 3s。
❑ 密钥管理操作响应不超过 1s。
❑ 其他支撑功能操作响应不超过 2s。

4.2 吞吐量

吞吐量指单位时间内可处理的请求数。系统需支撑大规模终端管理。
❑ 支持至少 1000 台 POS 同时在线。
❑ 支持每秒至少 100 次设备操作请求。
❑ 支持每秒至少 50 次配置、程序、密钥管理请求。

4.3 可用性

可用性体现系统可靠与稳定。
❑ 正常运行时间不低于 99.9%。
❑ 故障恢复时间不超过 30min。
❑ 提供数据备份与恢复，确保数据安全。

4.4 可扩展性

可扩展性指随业务增长可通过扩容提升处理能力。
❑ 支持横向扩展，应对设备与用户量的增长。
❑ 支持纵向扩展，提升单个模块的处理能力。
❑ 采用模块化设计，便于未来按需增加新功能。 [PRE10]

7 安全需求

7.1 访问控制

系统应实施严格访问控制，保护资源免受未授权访问与篡改。
❑ 用户身份验证，确保仅认证用户可访问资源。
❑ 角色权限管理，为不同角色分配差异化权限。

7.2 安全审计

应建立安全审计机制，记录与监控用户操作。
❑ 操作日志记录，追踪用户行为与系统事件。
❑ 定期审查审计日志，发现潜在安全问题。
❑ 异常时立即告警并通知相关人员。

7.3 数据保密

应采取措施防止敏感数据泄露。
❑ 对敏感数据加密存储与传输。
❑ 展示或导出时对敏感信息脱敏。
❑ 按敏感等级隔离存储。

7.4 安全性标准和认证

系统应遵循国家与行业安全规范。
❑ 遵守相关法规、标准与规范。
❑ 定期开展安全评估与审查，确保安全性能达标。
