模型挑选没有唯一解，需要在质量、效率与成本之间权衡。规模越大、训练语料越丰富，向量通常越可靠，但延迟与费用也会随之上升。最稳妥的做法是在自有数据集上做横向对比。也可用 SAL，即 Semantic Alignment Leakage（https://arxiv.org/abs/2305.18208）这类指标，检验当前嵌入产生的语义空间是否与下游任务需求对齐，再决定是否重训或微调。需注意不同批次产生的向量可能不在同一空间。向已有向量库增添新文档前，建议把全部文档重新编码一次，确保空间一致；底层编码器一旦更新，历史向量也应同步刷新。

#### 5.4.3 用 LangChain 的 Vector Store 搭建向量库
文本向量化只是开端，真正做相似检索需要把向量写入专用索引。LangChain 的 Vector Store 层统一了多个后端：

- Chroma：开源方案，支持本地文件或云存储，相似度策略多样。
- Pinecone：全托管服务，提供弹性伸缩与高可用。
- Weaviate：开源向量搜索引擎，基于 GraphQL，支持跨模态。
- FAISS：Meta 发布的高效稠密向量检索库，速度极快。
- Milvus：开源可扩展向量库，吞吐并发强劲。
- Qdrant：开源检索引擎，内置高级过滤与完整 CRUD。
- Pandas DataFrame：内存表存储向量，适合验证与小规模数据。
- Annoy：基于随机投影树的近似最近邻 C++ 库。
- Elasticsearch：基于 Apache Lucene 的搜索引擎，已支持向量相似度。

落地选型除了功能与性能，还要看易用性、可维护性与数据安全。隐私要求严格时更偏向自托管的 Chroma 或 Milvus，追求交付效率的团队适合 Pinecone 的托管形态。评估时建议做对比实验或 PoC。

LangChain 的 Vector Store 给出统一接口规范，迁移成本很低，能灵活应对数据量、性能与部署环境的变化。Embedding 与 Vector Store 配合，可把非结构化文本转为语义表征并实现可扩展检索，是构建智能问答知识库的基础。

### 5.5 实现问答流程
知识库就绪后即可串起端到端问答链路。LangChain 内置多条 Question Answering Chain，把问题理解、检索、生成串联，减少开发复杂度。

#### 5.5.1 问题理解和分析
问题理解是入口，目标是从用户自然语言输入中准确抽取查询意图与关键信息，为检索提供依据。主要涉及问题分类、实体识别与问题扩展。

（1）问题分类与意图判断。
分类任务是判断输入属于哪种提问类型，常见划分有事实型、定义型、观点型、过程型、比较型等。不同类型对应不同的生成逻辑，例如事实型适合直接检索，观点型需要带论据的主观生成。还要识别具体的提问意图，常见有查询、请求服务、寒暄、闲聊等，不同意图会触发知识问答、任务协助、关系维护等不同对话能力。

在 LangChain 中可用 HumanChatMessage 与 SystemChatMessage 组成对话记录，配合 few-shot 示例，实现小样本的问题分类与意图识别。
