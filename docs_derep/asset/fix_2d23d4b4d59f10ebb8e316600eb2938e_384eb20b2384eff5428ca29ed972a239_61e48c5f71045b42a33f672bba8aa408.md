# 第6章 Harness工程实践：复现Claude Code核心设计模式

Harness Engineering 近期在 Agent 开发圈被提及。名称虽新，内核并不陌生。Harness 原意为马具，“马”喻指常用的 LLM，故 Harness 工程指在 LLM 外围进行的系统性工程建设。用公式表达即 Agent = LLM + Harness。前五章围绕上下文工程所做的开发，本质上都在 Harness 范畴。

自 2025 年起，主流厂商的演示重点发生变化，不再只展示单轮问答，而是强调 Agent 能连续运行数小时、整夜无人值守。

代表案例有：

- DeepResearch 可持续运行数十分钟，完成深度信息调研；
- Claude Code 作为 Coding Agent 的代表，能自动进行数小时的编码、测试、修复再测试闭环；
- OpenClaw 已支持 24 小时自动化任务，从邮件整理到股票监控全程无需人工。

这标志着 AI 应用从短时交互转向长时任务执行。除了要管好上下文、提升即时能力，还需为 LLM 搭建长期稳定、安全运行的环境，这正是 Harness 工程被系统化总结的背景。

业界的 Claude Code 与 OpenClaw 等产品，不追求堆工具或复杂工作流，更像是 Harness 工程的典型代表。本章将拆解、复现并理解这两类产品的设计精髓。

Claude Code 是 Anthropic 2025 年初推出的自然语言编程工具。与 GitHub Copilot 这类被动补全插件不同，它能根据开发者意图自主规划并执行任务。输入“构建一个 React 组件”，它不仅生成代码，还会分析现有代码库、编写测试用例并完成集成。

Claude Code 未走堆砌工具、强行引导模型的老路，核心哲学是为模型打造理想工作环境，按模型需求封装环境能力。

思路体现在四个层面：

- Agent Loop：保证持续工作的基础。针对本地文件操作，仅保留 Read、Write、Bash 等核心工具并授予系统级权限，减少中间损耗；
- 上下文工程：通过上下文压缩等机制解决窗口限制和冗余信息导致的幻觉，实现动态精准筛选；
- 持久化与异步：借助持久化任务管理，实现跨会话延续；
- 多 Agent 系统：Agent Teams 新特性支持多个 Claude Code 实例协同工作。

不直接干预模型内部决策，而专注边界支撑环境，正是 Harness 工程的核心。Claude Code 堪称编程领域的典型范例。

本章将从上述维度拆解 Claude Code 的运行机制并通过代码实现对应特性，帮助读者掌握 Harness 工程设计思想并迁移到其他 AI 产品研发中。

## 6.1 Agent Loop：Agent可以长时间工作的核心

自 2025 年起，衡量 Agent 的关键指标从单次交互质量转向自主长周期的连续工作能力。在此背景下，Agent Loop 成为实现该目标的技术基石，也是 Claude Code 构建 Harness 工程的核心引擎。

即使只配置少量基础工具，依托 Agent Loop，Agent 也能在操作系统层面执行复杂的连续任务。以下通过代码实战剖析原理并演示效果。

### 6.1.1 一个Agent=一个Loop+一个Bash工具

回顾前五章，从计划-执行到 DeepResearch 等多种形态，工具调用的底层都遵循同一模式：用 while True 循环调度人、LLM 与工具环境的多轮对话，这就是 Agent Loop 的基础形态。
