配置完成后第一步一定是先做验收测试。在 Coze 的插件试运行面板里，把 location 填成“北京”后点“发送请求”。若返回的 JSON 里能读到“温度25℃”“晴”之类的字段，就说明连通没问题；如果弹出来的是“API Key无效”等报错，就要回头核对密钥是否填对，或看看 location 参数的写法是否符合规范。

通过测试之后就进入发布阶段。页面右上角点“保存并发布”，等平台完成审核，通常只要几分钟，插件就会出现在 Bot 的“插件”标签页里。随后在 Bot 配置里勾选该插件，用户一提到天气相关的问题，Bot 就会自动触发调用。

6.2.2 避“坑”指南
做“已有服务 API 插件”时抓住下面几个细节，能少踩很多坑。

1. 描述要够精准，别含糊
写“本插件用于调用天气 API”这种笼统话，Bot 根本判断不出什么时候该用。正确做法是把功能、使用场景、所需参数都写进描述，例如“当用户问‘××城市今天天气怎么样’‘××地气温多少’这类实时天气问题时调用本插件，需传入城市名称，返回实时温度、天气状况等”。这样调用时机才清晰。

2. 参数说明要具体
以 city 为例，别只写“城市名”。要明确输入方式和限制，比如“支持中文如‘广州’、拼音如‘guangzhou’或英文如‘Guangzhou’，暂不支持县级及以下地区”。有了这层说明，Bot 就不会把“广州市天河区”这种无效值传进去了。

3. 响应数据要做精简
很多 API 返回字段非常多，天气接口可能带气压、能见度、紫外线强度等。如果实际只需要温度和天气状况，就在“响应解析”里限定只提取 temperature 和 text。去掉冗余能加快传输，也避免 Bot 整理答案时出错。

4. 错误情形提前写明
比如用户输的城市不存在，接口可能返回 404。可以在描述里加一句“若返回‘城市不存在’提示，则请用户核对城市名称”。这样 Bot 遇到异常会给出友好提示，而不是简单说“调用失败”，体验会好很多。

6.2.3 应用实例：搭建完整的天气查询流程
下面以接入高德地图 API 为例，把创建步骤串起来。

先填基础信息。进入 Coze“已有 API”创建页，插件名写得具体一点，例如“高德地图实时天气查询”，避免和其他天气插件混淆。描述里要写明功能、参数要求和特殊说明，例如“本插件调用高德地图 API 查询国内城市实时天气，返回温度、天气状况、风向、风力等信息。必须传入城市编码，如北京为‘110000’；若用户只给城市名，需先经高德地理编码 API 转码后再调用”。特意点出城市编码，是因为高德接口不支持直接传城市名。

再设认证方式。高德采用 API Key 认证，且密钥要放在 URL 的 Query 里，参数名是 key。所以在 Coze 的认证配置中选“API Key”，位置选“Query”，参数名填 key，把在高德开发者平台申请的 Key 填入。注意 Key 是私密信息，不要外泄。

然后手动编辑 API Schema。如果没有 OpenAPI/Swagger 地址，就手动配置。接口完整地址是 https://restapi.amap.com/v3/weather/weatherInfo，所以 Path 填 /v3/weather/weatherInfo，方法选 GET。添加参数：city 设为必填，类型字符串，描述写“城市编码，如北京‘110000’，可通过高德地理编码 API 获取”；extensions 设为可选，类型字符串，默认值 base，描述补充“返回类型，base 为实时天气，all 为预报”。

配置完一定要测。在测试面板里把 city 填 110000 点发送请求。若返回 JSON 的 lives 数组里包含 temperature：25、weather：晴、windDirection：东北风 等字段，就说明配置正确。此时可在响应解析里只保留 lives[0].temperature、lives[0].weather、lives[0].windDirection 三个核心字段，减少干扰。

最后发布。发布后可在 Bot 中使用。例如用户问“北京今天刮什么风”，Bot 会判断需要调用高德地图实时天气查询插件，先用地理编码插件把“北京”转为“110000”，再用天气插件查询，最后整理成自然语言回复：“北京今天刮东北风，当前气温25℃，天气晴。”

小技巧：不想让用户记编码，可额外建一个“高德地理编码 API”插件，在 Bot 工作流里设置前置先调用编码插件，再调用天气插件，两个插件配合能大幅提升体验，具体工具路径、请求方式、输入输出参数设置见图6.2.1。

6.3.2 核心能力
编程插件几乎不受限，Python 能做的逻辑基本都能实现，主要有三大能力。

1. 逻辑自由：可串联多步骤流程。可以写条件判断、循环、多个 API 调用。例如“航班动态查询插件”：先调航班信息 API 获取起飞时间和目的机场，再判断是否需查目的地天气，起飞前1小时内则调天气 API，最后整合返回。

2. 私有化集成：可对接内网服务。公司内网有 CRM、ERP，只要 Coze 能访问接口，就可在代码里调用。例如“CRM 客户信息查询插件”：用公司账号密码认证，建议存在 Coze 密钥管理里不要写死，调用查询接口输入客户姓名返回联系方式，Bot 即可快速查询。

3. 复杂计算：可在代码内完成计算，不依赖外部 API。例如“个税计算器”：代码里写好应纳税所得额=工资-5000-专项附加扣除，按税率表计算，用户输入工资和扣除项后直接返回结果。

Coze 支持导入常见库如 requests、pandas，需特殊库可在依赖管理添加，部分未默认支持的库可联系官方申请。

输出：
- status，布尔值：执行是否成功。
