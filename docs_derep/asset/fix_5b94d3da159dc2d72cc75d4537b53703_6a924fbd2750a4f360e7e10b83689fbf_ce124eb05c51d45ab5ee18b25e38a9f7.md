### 4.2 向量数据库中的索引

向量数据库的典型流程包含以下步骤。

1. 数据存储：将高维向量写入数据库。
2. 索引构建：借助哈希、量化或图结构等技术为嵌入建立索引，加速查询。
3. 查询检索：接收查询请求后，比较查询向量与索引向量，利用余弦相似度、欧几里得距离或点积等度量确定最近邻。
4. 检索后处理：对最近邻结果做进一步筛选或排序，优化输出。

在海量数据集中做向量检索是计算密集型任务，尤其在高维空间。引入不同索引结构可以大幅减少比较的向量数量，降低计算成本。

> 索引在向量数据库和整个 RAG 系统中都是核心概念。2.6 节指出，RAG 系统中的索引目的是通过高效的文本块存储机制优化检索，包括文档嵌入向量和元数据的构建，这属于应用层索引。而本节讨论的是向量数据库内部索引，更偏向技术实现，目的是优化高维向量数据的存储与检索性能，提升相似度检索效率，涉及 FLAT、IVF、HNSW 等结构与算法，用于加速 ANN 搜索，属于数据库底层实现。

向量索引是加速数据库检索的关键技术，决定了向量的组织方式和检索策略。下面介绍几种常见方案。

#### 4.2.1 FLAT

扁平索引 Flat Index，简称 FLAT，是最基础的索引方式。其特点是对库中所有向量逐一比较，以保证检索的绝对准确。由于不做近似或压缩，FLAT 能达到 100% 召回率。

查询时，FLAT 会计算查询向量与库中每个向量的相似度或距离。代价是必须遍历全部向量，数据量增大时检索速度明显下降。

可以想象一个二维空间，所有向量分布其中，查询向量需要与每个数据点计算距离，如图4-11 所示。图4-11 查询向量（红色）需要与所有数据点（紫色）计算距离

[PRE6]

FLAT 适合数据规模较小、百万级以下的场景。当对召回率要求极高且能容忍较慢查询时，它是不错的选择。

#### 4.2.2 IVF

倒排文件索引 Inverted File Index, IVF 通过聚类向量来缩小查询范围，从而加快检索。最基础形式是 IVF_FLAT，还有 IVF_SQ8、IVF_PQ 等变体。

IVF_FLAT 先把向量聚成若干簇，每个簇代表数据空间的一个区域。查询时先算查询向量与各簇中心 图4-12 中粉点 的距离，只挑选最相似的前 n 个簇，再在这些簇内做精确匹配。图中向量被分配到不同簇，查询向量只需与选定簇内的向量比较。图4-12 查询向量（红色）仅需要与选定的簇（粉色区域）中的向量进行比较

[PRE7]

只搜索部分簇大幅减少了计算量，同时簇内精确比较保证了结果质量。

小冰：为什么叫倒排？

咖哥：在文本检索里，倒排索引为每个词维护一份包含该词的文档列表。搜索某个词时，直接查这份列表即可，无需扫描全部文档。

IVF 借鉴了这一思想，把向量聚成多个簇，每个簇记录自己的向量列表，像倒排列表一样。查询时根据查询向量与各簇中心的相似度，只检索最相关的几个簇，而不是遍历整个数据集。
