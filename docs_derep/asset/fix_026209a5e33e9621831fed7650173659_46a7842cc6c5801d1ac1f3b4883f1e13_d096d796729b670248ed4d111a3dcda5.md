#### 7.2.3 知识图谱构建的核心步骤和组件

在 LangChain 加持下，图谱搭建大致可拆为数据准备、知识抽取、知识融合、本体构建、知识存储、知识应用六个环节，如图7-2所示。

（1）数据准备。
- DocumentLoader：内置 CSVLoader、JSONLoader 等加载器，可方便地从不同格式源读取原始材料。例如用 JSONLoader 读取 .json 文件。
- TextSplitter：处理长文档时可用 CharacterTextSplitter 等，切成便于管理的片段。例如把长文按句子拆分。
- Embeddings：借助 HuggingFaceEmbeddings 等把文本转为语义向量，加速后续语义分析。例如把一段描述映射为向量以便后续处理。

图7-2 知识图谱构建的核心步骤

（2）知识抽取。
- Prompt：可自定义提示模板，明确告知模型从文本中抓取哪些关键信息。例如设计一个提示要求抽取地名和人名。
- LLM：调用 OpenAI 等语言模型执行提示，完成结构化抽取。例如用 GPT 模型抽取事件描述。
- Chain：把提示与语言模型串联形成可复用的抽取链。例如用 SequentialChain 依次完成多步抽取任务。

（3）知识融合。
- Agent：通过子任务拆分与调用调度，实现复杂的融合逻辑。例如让 Agent 判断文本间的相似度。
- Vector Store：存放文本及其向量，加速相似内容的检索。例如用 Pinecone 保存文本向量以便快速查找。
- Chain：组合不同组件实现融合的子目标。例如搭建一个专门做文本摘要的 Chain。

（4）本体构建。
- Prompt：用户可定义 Prompt 以提取本体构建相关知识。例如设计 Prompt 以提取特定领域的本体概念。
- LLM：调用 LLM 生成本体相关的详细信息。例如利用语言模型定义一个概念的属性。
- Agent：整合多个子任务，完成本体构建的流程。例如通过 Agent 整合概念提取和属性定义的步骤。

（5）知识存储。
- Graph Database：使用图数据库存储知识三元组，构建知识图谱。例如采用 Neo4j 存储实体之间的关系。
- Vector Store：存储语义向量，辅助语义检索和相似度计算。例如在 Redis 中存储实体的向量表示。
- LangChain Integration：为知识图谱数据库提供连接和操作支持。例如通过 WeaviateVectorStore 集成实现语义搜索。

（6）知识应用。
- Chain：根据应用场景组合 LLM 和知识图谱数据库，实现应用链。例如开发一个 ChatVectorDBChain 实现智能对话。
- Agent：编排多个 Chain，构建复杂的应用代理。例如使用 RetrievalQA Agent 整合问答和检索功能。
- Memory：使 Chain 能够处理多轮对话，实现上下文感知的应用。例如通过 ConversationBufferMemory 保持对话的连贯性。

LangChain 的组件覆盖了从数据到应用的完整链路，尤其 Prompt、Chain、Agent 的组合，为个性化需求提供了灵活且强大的实现手段。

#### 7.3.3 基于规则和few-shot的知识抽取

前面介绍的命名实体识别和关系抽取工具，主要适用于通用领域和常见模式。但现实世界的知识图谱往往有特定的业务需求，需要抽取定制化的实体和关系类型。例如，医疗知识图谱中的疾病、药品、副作用等，电商知识图谱中的商品、品牌、优惠券等。对这些领域，我们需要更加灵活的知识抽取方法。

一种思路是总结领域内的抽取规则和模式，用 Prompt 引导 LLM 按规则提取。另一种思路是给出少量样例，让 LLM 自动学习和生成更多结果。LangChain 在 Prompt 工程和 few-shot 学习方面提供了很好的支持。
