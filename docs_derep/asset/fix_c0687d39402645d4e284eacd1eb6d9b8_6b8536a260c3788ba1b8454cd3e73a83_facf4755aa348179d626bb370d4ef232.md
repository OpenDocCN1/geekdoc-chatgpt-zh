代码里用循环把 1 到 n 累加，迭代次数完全由 n 决定，所以总耗时与 n 成正比，记作 O(n)。n=100 时大约执行百次，n=1000 时大约执行千次，运行时间跟着输入一起线性放大。

这里要强调的点是，复杂度关注的是增长态势，而非某次运行的绝对秒数。随着规模变大，算法是变快还是变慢，才是衡量效率的核心。一般来说，复杂度越低在大规模数据上越占优势。分析的实质就是统计不同规模下基本操作的次数，遇到嵌套循环或递归时思路一致，只是推导会更复杂。
