### 6.3 持久化与异步执行：跨会话任务管理

本节要讲的计划模式核心思想是“先规划，后执行”。Claude Code 引入了一套更成熟的任务管理方案，不仅梳理了规划与执行的流程，还加入了任务持久化等关键能力，让 Agent 具备跨越会话的长程记忆与持续执行力。

下面将逐步复现实现思路，展示如何搭建一个支持持久化与异步执行的任务管理系统。

### 6.3.1 Todo 计划模式：Claude Code 的任务规划范式

在 Claude Code 里，最基础的规划方式就是 Todo 模式。其运行机制是：LLM 收到任务指令后，先产出一份待办清单，并实时维护每一步的执行状态。为保证严谨性，该模式强制串行执行，同一时刻只允许一个步骤在进行。

在架构层面，这一能力被封装成独立工具，由 LLM 通过工具调用自主更新 Todo List 的状态。

沿着同样的设计思路，本节会先用提示词工程约束 LLM 的行为，要求在动手前必须先生成执行计划；随后设计一个专用的计划管理工具，让模型能够根据实际情况自主调用并完成计划的更新。

### 6.3.2 Task System：持久化任务系统

上一节的 Todo 功能本质上只是扁平化的清单。它能保证串行执行，却无法处理复杂的依赖关系，比如“任务A完成后才能启动任务B”的前置约束，或“任务C与任务D可并行”的协同需求。更关键的是，任务列表仅存在于内存中，一经上下文压缩或进程异常终止，状态就会丢失，难以支撑长周期开发的连续性。

为解决这些痛点，Claude Code 引入了 Task System。核心设计是将扁平清单升级为有状态的任务图，通过把任务状态持久化到磁盘，确保生命周期不再受单次对话窗口限制，实现跨会话的追踪与管理。

在实现思路上，采用文件化存储，每个任务抽象为独立的 JSON 文件并统一存放到指定目录。数据结构中新增了 `blockedBy` 表示前置依赖、`blocks` 表示后置依赖。
