形式化表述上，若 P 为含变量 x 的逻辑式，则语句 ∃x P 的含义是论域内至少能找到一个个体 x 使 P 成立。

全称量词 ∀ 与存在量词 ∃ 可通过否定实现相互转换。其根源在于 ∀ 实质上是对论域中全部个体的合取，∃ 实质上是对全部个体的析取，因而二者遵守以下 De Morgan 规律：

∀x ¬P ≡ ¬∃x P    ¬(P ∨ Q) ≡ ¬P ∧ ¬Q

¬∀x P ≡ ∃x ¬P    ¬(P ∧ Q) ≡ ¬P ∨ ¬Q

∀x P ≡ ¬∃x ¬P    P ∨ Q ≡ ¬(¬P ∧ ¬Q)

∃x P ≡ ¬∀x ¬P    P ∧ Q ≡ ¬(¬P ∨ ¬Q)

命题逻辑与一阶谓词逻辑是人工智能早期最主流的陈述式知识表达手段。它们以统一简洁的方式刻画命题，使知识表述与推理过程解耦，推理不依赖具体领域。在命题逻辑基础上引入量词与变量后，能表达更抽象的内容，从而提升推理能力。一阶谓词逻辑拥有完备的推理机制，可保证表达的一致性与推导的可靠性。不足之处在于这类产生式难以刻画过程性知识和不确定性知识，且当属性、谓词、命题规模扩大时，符号组合会发生爆炸，推理复杂度呈指数级上升，耗时且效率偏低。

### 2.1.2 语义网络
[PRE0]
语义网这一概念由 Quillian M. Ross 于 1966 年在研究人类联想记忆时提出，源自一种心理学模型[39]。该设想受两点启发 [资源 2-1]：
- ① 人脑记忆的显著特征是不同信息片段之间联系极其紧密；
- ② 相关性越高的概念，回忆速度往往越快。随后该模型被用于知识表示。

语义网是通过语义联系把概念组织成网络，以点边模式编码知识。节点对应实体、事件、数值等，边对应对象间的语义联系。整体上它即一种有向图式知识系统。最基础的语义单元可用三元组形式写作 <节点1,关系,节点2>，记作 <E1,R,E2>，其中 R 表示 E1 与 E2 之间的语义关联，对应的基本图形为 E1 R > E2。例如“珊瑚是一种动物”即可按此方式表示。

[PRE1]
图 2.1 语义网络简单示例

网络中的关系类型较为丰富：
- 1. 实例关系 ISA，反映具体与抽象的层次，意指“是一个”，如“小王是一个人”。
- 2. 分类关系 AKO 即 a kind of，也称泛化关系，反映子类与超类，意指“是一种”，如“篮球是一种球”。
- 3. 成员关系 a-member-of，反映个体与整体，意指“是一员”，如“小余是一位公务员”。
- 4. 属性关系，描述事物与其属性的关联。常用 Have 表示“有”，如“狗有尾巴”；Can 表示“能/会”，如“鱼能游泳”；其余还有身高、年龄等具体属性。
- 5. 聚合关系亦称包含关系，描述具有组织或结构特征的部分与整体之间的联系，如“凳子是桌子的一部分”。
- 6. 时间关系，描述事件发生先后次序。常用“在前”“在后”，如“2022 北京冬奥会在 2008 北京夏季奥运会之后”。
- 7. 位置关系，描述事物在空间上的方位。常用“在”“在上”“在下”“在内”“在外”，如“显示器在桌子上”。
- 8. 相近关系，描述事物在形状、内容等方面的相似或接近，如“狮子和老虎在食物链的位置非常相近”。

按论元个数，关系可分为一元、二元、多元。一元关系可用一元谓词 P(x) 表示，刻画实体/概念的性质或属性，例如“鸟有翅膀”“鱼能游泳”分别可表示为有翅膀(鸟)、能游泳(鱼)。二元关系可用二元谓词 P(x,y) 表示，其中 x、y 为实体，P 为实体间的联系，如“北京是中国首都”可表示为首都(中国,北京)。一元与二元关系很容易用语义网表示，多元关系的处理是将多元关系拆分为多个二元关系的组合，再用合取连接。例如“2008年，奥运会北京举行”包含了举办地与举办时间的两个二元关系，可先设计一个“奥运举办事件”节点，再关联地点与时间，如图 2.2 所示。

[PRE2]
图 2.2 语义网络表示多元关系示例图

语义网与一阶谓词具有相同的表达能力，不同的是它用最简统一的形式描述全部知识，非常有利于计算机存储与检索。不足之处在于它仅用节点及其关系描述知识，推理过程不如谓词逻辑那样清晰，需要针对不同关系做不同处理，推理方法尚不完善。

1988 年建立的知网 HowNet 是一个典型的语义网络，它以汉语和英语词语代表的概念为描述对象，以揭示概念与概念之间以及概念属性之间的关系为基本内容的语言认知知识库/常识知识库。

[PRE3]
> 知网的创始人董振东教授认为 [资源 2-2]：“自然语言处理系统需要强大的知识支撑，知识是一个系统，是一个包含着各种概念与概念之间的关系、概念的属性与属性之间的关系的系统。一个个人比另外一个人有更多的知识说到底是他不仅掌握了更多的概念，而且掌握了更多的概念之间的关系以及概念的属性与属性之间的关系。”

关于知识库的建设，他认为首先建立一种可以被称为知识系统的常识性知识库，这个常识知识库以通用的概念为描述对象，建立并描述这些概念之间的关系，并认为不能依靠若干专家构建人类各行各业的知识，而应该先让知识工程师设计知识框架并建立基本的知识库原型，在此基础上再向专业性知识库延伸和发展。其中，专业性知识库或称领域知识库主要靠专业人员来完成，专业人员采用知识工程师的框架完成自己专业知识的编撰。

### 2.1.3 框架
框架表示法最早由美国人工智能学者 Minsky 于 1975 年提出[341]。从认知学角度看，框架理论继承了人类认识世界的方式，人类对现实世界中各种事物，都是以一种类似于框架的结构存储在记忆中。面对新事物时，人会从记忆中调出合适的框架，并根据实际情况对框架中的具体值进行填充，填充的部分被称为槽，框架与槽的粒度则随人类对事物的认知程度而定。因此理论上框架表示法是对世界知识的一种有效建模。

框架将事物抽象化，用来表示事物各方面的属性以及事物之间的类属关系。例如图 2.3 中展示了两个框架的例子。

| 槽4: <院系> | 侧面3.1: <死亡人数> |

| 槽8: <毕业院校> | 侧面4.2: <间接经济损失> |

|  | ... |

教师和灾难是两个概念或类别，框架定义了这些概念的实例应该或可能具备的属性，这些属性被称为槽。例如对于框架 1：< 教师 > 包含九个槽，若存在一个教师的实体，就需要对教师框架中的槽或部分槽进行值的填充，例如 < 教师实例 > { < 姓名 > {张三}，< 年龄 > {30}，< 学校 > {中国科学院大学}，< 院系 >{人工智能学院}, < 职称 >{讲师}。类似地，对于一个灾难的实例，关联着一个特定时间发生在特定地点的事实，例如“5.12 汶川地震”。

在原始框架定义中，槽可以是任何形式的信息，包括原子值或值的集合；对于非原子的槽，还可以由多个侧面对槽的描述进行补充，如图 2.3 中灾难的框架，在伤亡、损失、救援的槽结构下都具有若干描述槽的某些方面属性的侧面定义。这样做的目的是更立体更准确地描述事物的属性与关系，但在一些基于框架的系统中，省略了侧面的定义而直接表示为平铺式的槽结构，如 FrameNet。

人类对事物的认识存在层级的特性，框架的设计就引入了层级结构，并且根据类别之间的所属与细化，框架中的属性集合存在着继承的性质。例如，地震在真实世界中是灾难的一种，因此灾难框架的所有槽，在地震中都是存在的；而为了避免框架结构的重复定义，就有了框架之间的继承关系。但除了灾难的公共属性外，地震还有震级、震源深度等特有属性，这是需要在地震框架下单独定义的，因此我们可以得到地震框架的定义，如图 2.4 所示。

框架以强大的结构式表达能力和接近于人类思维过程的特性，被应用于多个领域专家系统的构建以及通用知识的表达，例如 FrameNet 就是基于框架表示的语义知识库。FrameNet 针对词汇级的概念进行框架建模，认为大部分词汇的语义能够通过语义框架的形式进行表示。例如，“烹饪”这一概念通常包括烹饪的发起者、烹饪的对象、烹饪的工具和加热的来源。在 FrameNet 中，上述概念通过框架进行表示，其中框架名称为“加热”，而“厨师”“食物”“加热设备”和“容器”叫做框架元素。最能指示该框架发生的词叫做该框架的词法单元，例如“烘焙”“油炸”“蒸煮”等都是上述框架的词法单元。

FrameNet 中的数据是以层级结构进行表示和存储的，图 2.6 是 FrameNet 语料的数据结构的示意图。图中每个 LU 下的 S_k 是该 LU 的标注样例，“Inheritance”是图中两个框架的语义关系。位于最上层的节点表示框架，框架之间的边表示框架间的关系。框架之间有两种边：无向边和有向边，它们分别对应 FrameNet 中的无向关系和有向关系。每个框架下跟随的节点表示该框架的词法单元，它们由带词性限制的词元组成。如“invade.v”是框架“Invading”的一个词法单元，它表示动词形式的“invade”。FrameNet 还为每个词法单元标注了一组样例，每个样例中详细标注了当前框架的词法单元和框架元素的信息。

FrameNet 定义了 1000 多个不同的框架、10000 多个词法单元，总计标注了超过 150000 个例句。另外，FrameNet 还在框架之间定义了八种关系，它们分别是：继承关系、视角关系、子框架关系、前置关系、使动关系、因果关系、使用关系和参考关系。FrameNet 被证明对一系列的自然语言处理任务具有明显的效果，包括信息抽取、文本蕴含、语义解析和角色标注等任务。其中，具有代表性的工作包括：艾伦人工智能研究所将 FrameNet 应用于从教科书中抽取信息，并应用于科学问答等任务；中科院自动化所等利用 FrameNet 和事件结构之间的相似性，从 FrameNet 中自动识别事件实例作为事件抽取模型的训练语料，解决事件抽取数据稀疏的问题。

### 2.1.4 脚本
脚本是一种与框架类似的知识表示方法，是由 Schank 等于二十世纪七十年代提出的。脚本通过一系列的原子动作来表示事物的基本行为，按照时间顺序描述事物的发生，类似于电影剧本。脚本表示的知识有确定的时间或因果顺序，必须是前一个动作完成后才会触发下一个动作的开始。与框架相比，脚本是用来描述一个动态的过程而非静态知识的表示方法，与框架有着不同的目的。以下的例子是使用脚本的方法描述一般顾客去餐厅吃饭的过程或流程。

例：顾客去餐厅吃饭脚本

- 第一场：进入餐厅

- 顾客走进餐厅

- 顾客拿号等待

- 顾客被叫号

- 领餐员将顾客带到固定座位就座

### 第二场：点餐

- 服务员拿来菜单

- 顾客翻阅菜单

- 顾客确定菜品

- 顾客告知服务员

- 服务员在点餐器上点餐

- 服务员将已点菜品和顾客确认

### 第三场：上菜进餐

- 厨师烹饪菜品

- 上菜员取走菜品

- 上菜员将菜放置到餐桌上

- 顾客吃菜品

- 顾客买单

这个例子是一个通用的顾客去餐馆就餐的流程，它细致地刻画了一个顾客在餐馆就餐经过的就座、点餐、进餐等关键步骤，但它并不能称为一个完整的脚本，根据脚本表示法的定义，一个完整的脚本应该包括以下几个重要的组成部分：

- 进入条件：指出脚本所描述的事件可能发生的先决条件，即事件发生的前提条件。对于餐馆就餐的例子来说，顾客饿了，而又不能在家中就餐，就是餐馆就餐这一脚本的进入条件。
- 角色：描述事件中可能出现的人物。在餐馆就餐的例子中，参与的人物包括顾客、领餐员、服务员、厨师、上菜员。
- 道具：描述事件中可能出现的相关物体，主要指人物角色在完成动作时使用的工具，如上例中的叫号机器、菜单、点餐器、菜品等。
- 舞台：脚本中事件发生的空间。在餐馆就餐的例子中，餐馆就是舞台。
- 场景：时间发生的序列，也就是上面例子中的主体部分，但在上例中仅描述了正常顾客就餐的流程，并不是所有的餐馆都有叫号和领位的步骤，对于一些快餐店需要顾客付钱后才会领到相应的食物，而在一些场景下，顾客可能会对菜品或服务不满意并与餐馆人员发生争执或冲突。因此场景并不是单一的动作序列，而是可以存在多个可能的分支，对所有可能发生动作序列的枚举是一个庞大的工程，因此这也是脚本表示法的一个缺陷。
- 结局：给出在剧本所描述的事件发生以后通常所产生的结果，对应着进入后续脚本的先决条件，顾客不再饿了就是这一脚本的结局。

从脚本表示方法的例子和必要因素中可以看出，这种表示方法能力有限，不具备对于元素基本属性的描述能力，也难以描述多变的事件发展的可能方向。但在非常狭小的领域内，脚本表示方法却可以比其他方法更细致地刻画步骤和时序关系，例如作战计划、电影脚本等。因为脚本能够描述有一定时序关系的槽信息，其在人工智能以及自然语言处理的一些任务中得以应用，最具代表性的就是智能对话系统，如酒店预定、机票预订等。

综上，经典知识表示理论中的语义网络、框架和脚本都属于基于槽的表示方法，有所区别的是槽是否具有层次、时序、控制关系。其中，语义网络是最简单的一种，它的每个三元组都可以看成一个槽结构。框架系统由一组相关的框架联结而成，其中每个框架是由若干节点和关系构成的网络，因此，框架可以看成是层次化的语义网络，是语义网络的一般化形式。脚本是按照一定的时间流程对事件的发展和变换控制进行的建模，因此，可以认为是定义了时间和控制条件的槽结构，与语义网络也没有本质区别。

## 2.2 语义网中的知识表示方法
### 2.2.1 语义网表示方法
