| :--- | :--- | :--- | :--- |

| 原始 PyTorch 格式 | .bin | Transformers 默认格式，文件较大，占用显存高 | Transformers/vLLM/TGI |

| 安全张量格式 | .safetensors | 安全、加载更快、支持并发加载的张量格式 | Transformers/vLLM/TGI |

| 量化格式-INT4 | .bin, .pt (压缩) | 通常通过 GPTQ/AWQ 等量化工具压缩后发布 | AutoAWQ/GPTQ-for-LLaMA/vLLM |

| 量化格式-GGUF | .gguf | llama.cpp/Ollama 使用的统一格式，支持 CPU/GPU 部署 | llama.cpp/Ollama/KoboldCpp |

锁定目标模型后，建议先核查开放性、托管位置、量化版本与配套脚本。需确认模型是否开源、能否在 Hugging Face 或 GitHub 上找到仓库、是否提供 INT4/INT8/GGUF 等压缩版、官方或社区是否给出部署脚本或 Docker 镜像。

### 2.3 本地化落地全景
本节围绕本地化落地的核心链路，系统介绍算力、环境、下载、推理验证等关键环节，并与主流第三方工具做对比，为后续 Agent 构建提供运行基础。

#### 2.3.1 部署前资源盘点
实际应用中，出于数据安全、服务稳定性、成本管控、模型可控性等多方面考量，越来越多的团队选择将大模型置于本地或私有云。本地化可掌控推理过程，降低敏感数据泄露风险，减少长期接口费用，提升响应并支持离线运行。与此同时，本地化门槛更高、工程更复杂，动手前需对以下关键需求做全面评估。

##### 1. 硬件算力
在所有本地化条件中，算力尤其是 GPU 是能否跑起大语言模型的决定因素。轻量场景可尝试 CPU 模拟推理，但效率远逊于 GPU，对中大型模型基本不可行。因此部署前必须具备相应规模的 GPU 硬件。

> **说明**
>
> 为何不能仅靠 CPU？
>
> 大语言模型推理涉及百亿级参数的矩阵计算，尤其在多层 Transformer 结构中，存在大量矩阵乘法、归一化、注意力计算等高强度并行任务。GPU 在并行数值计算上优势明显，CPU 更擅长逻辑控制与串行任务。同等条件下 CPU 推理速度可能仅为 GPU 的 1/100 至 1/10。

在推理场景下不同参数规模对应的显存需求如表2.2所示。

**表2.2 不同模型参数规模对应的显存需求**

| 模型规模 | 推理时显存需求（FP16） | 支持的典型GPU（单卡） |

| :--- | :--- | :--- |

| 7B | 14GB～16GB | RTX 3090 / 4090 / A500 |

| 13B | 26GB～30GB | RTX 4090（24GB）基本可运行 |

| 33B | 60GB～80GB | 多卡 A100 或 2×4090 并行 |

采用量化如 INT4、INT8、GPTQ 等技术后，显存通常可减少 1/4～1/2。以 7B 为例，FP16 需 14GB～16GB，INT4 后仅需 4GB～6GB，可在单张 RTX3060/4060 甚至笔记本 GPU 上运行。

当前大模型训练或推理绝大多数基于 NVIDIA GPU，得益于成熟的 CUDA+cuDNN+PyTorch 生态。主流型号如表2.3所示。

| 类型 | 常见型号 | 适用说明 |

| :--- | :--- | :--- |

| 数据中心级 | A100, H100, A800, L40S | 高稳定性、高带宽，适合集群部署 |

| 消费级高端 | RTX 3090, 4090, 4080 | 适合个人开发与中小模型推理 |

| 云租用平台 GPU | Tesla V100, T4 | 支持量化模型，成本可控 |

若本地无 GPU，可租用云平台算力。AutoDL、阿里云 PAI、百度飞桨 Studio、Google Colab 均提供在线 GPU 租赁。

##### 2. 系统与软件栈
硬件满足后，还需配置操作系统与依赖栈。以下是部署主流 PyTorch/Hugging Face 风格模型所需的通用说明。

1) 操作系统
建议优先使用 Ubuntu，其稳定且兼容 CUDA，是主流 Linux 发行版，能完整支持 NVIDIA 工具链。CentOS 与 Windows+WSL2 虽可运行部分模型，但不推荐用于生产环境，存在兼容风险。
