FAISS 从加载到落盘的完整链路拆解

这段实现把向量读取、索引构建到持久化的全过程串联起来，与常见的嵌入生成存储流程基本一致，可以归纳为七个关键动作：

1. **嵌入载入**：打开 4.1.2 节生成的 text_embeddings.pkl，文件里每个文档的向量最初以列表保存。通过 pickle 解码后转成 NumPy 数组，方便 FAISS 直接消费。
2. **索引实例化**：新建 IndexFlatL2，这是一种基于 L2 距离的平面结构，对小规模集查询足够快。若数据规模很大，可换成 IndexIVFFlat 或 IndexPQ 等更复杂的方案来提升效率。
3. **写入向量**：先统一把数据转为 float32 的 NumPy 数组，再调用 add 写入。写入完成后用 index.ntotal 查看当前向量总数，确认是否全部入库。
4. **检索接口**：封装 search_faiss 函数，接收查询向量和 top_k 参数，返回最相似的若干结果。FAISS 的 search 会同时返回距离值和对应的索引位置，便于后续分析。
5. **效果验证**：用一个示例向量跑一遍检索，展示最相似的文档 ID 以及对应的距离。距离越小，语义越接近。
6. **索引持久化**：调用 faiss.write_index 把索引写到磁盘，服务重启后能快速恢复，适合线上大规模检索的部署。
7. **索引恢复**：用 faiss.read_index 从文件重新载入，再次执行查询并对比结果，确保保存与加载没有偏差。
