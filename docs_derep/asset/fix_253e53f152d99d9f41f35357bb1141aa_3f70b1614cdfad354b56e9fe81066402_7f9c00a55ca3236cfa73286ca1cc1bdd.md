### 5.2.4 工程化最佳实践
本节围绕密钥管理、配置界面、异常处理与代码迁移给出建议。

密钥管理
- 研发阶段：可硬编码以便快速调试
- 生产环境：必须通过配置页或环境变量，避免前端泄露
- 推荐做法：前端提供配置页让用户输入密钥并存入 LocalStorage，后端使用环境变量

配置界面
- 基础配置：密钥输入框，可选 API 地址
- 用量信息：展示已消费金额、最高限额等
- 模型选择：多模型场景下提供选择器
- 本地持久化：配置写入 LocalStorage，刷新后仍保留

异常处理
- 密钥未配置：启动时检查并提示前往设置
- 密钥无效：捕获鉴权错误并提示核查
- 网络失败：加入重试机制并展示错误信息
- 异步超时：设定合理超时时间，支持手动重试

代码迁移
- Google AI SDK 项目：优先使用 setDefaultBaseUrls 改动最小
- 需要多模型支持：使用 OpenAI SDK 兼容接口
- 耗时任务：采用异步接口并实现轮询机制

## 5.3 Vercel 云端发布
代码打磨完成后即可将应用公开发布，供他人访问，如同出版书籍或上菜。

传统发布需租服务器、配置运行环境、解析域名、申请 HTTPS 证书，步骤繁琐。借助 Vercel，Vibe Coding 开发的 AI 应用可简化为几次点击，无需自建服务器，部署到全球节点，细节自动处理，并提供性能优化和安全保障。

对个人开发者而言，目前基本免费，每月提供 100 GB 流量，自动申请并续期 SSL 证书。

使用前先明确适用场景。

适合的类型：
- 前端框架应用：React、Vue、Next.js、Vite 等构建的单页应用
- 静态网站：由 HTML、CSS、JavaScript 构成的页面

### 5.3.1 GitHub 导入与首次部署
建议先将项目托管到 GitHub。Vercel 和 GitHub 紧密集成，可直接导入，代码更新后能够自动重建。若尚未托管，可参考 5.1 节。

部署步骤：

- (1) 登录 Vercel 并授权 GitHub
使用 GitHub 账户登录并授权访问仓库
- (2) 进入导入页
控制台首页点击 “Import Project” 或 “Add New Project”，系统会列出仓库，仓库较多时可用搜索定位
- (3) 选择并导入
找到目标项目后点击右侧 “Import”，Vercel 会进行结构分析、识别框架并设置构建命令与输出目录
- (4) 确认配置
检查以下项，如图 5-7：
  - Project Name：作为访问地址一部分，如 my-learning-app，对应 https://my-learning-app.vercel.app
  - Framework Preset：通常自动识别，错误可手动选择
  - Root Directory：代码位于子目录时需指定
- (5) 配置构建（可选）
Build and Output Settings 包含：
  - Build Command：如 npm run build
  - Output Directory：如 dist、build、out
通常会按框架自动填充，一般无需修改
- (6) 添加环境变量（如需）
在 Environment Variables 中添加，如 GOOGLE_AI_API_KEY，值来自 Google AI Studio。敏感信息安全保存，不会进入代码库
- (7) 启动部署
点击底部 “Deploy”。Vercel 会拉取代码、安装依赖、执行构建、生成静态文件、上传统计 CDN、配置 HTTPS，约需 2～5 分钟
- (8) 访问应用
部署成功后会显示访问链接，点击即可打开，全球用户均可访问

首次部署后，Vercel 会监听 GitHub 仓库变更。每次推送更新都会自动触发重建，耗时约 2～5 分钟。后续只需在 Cursor 中优化并推送即可。

### 5.3.2 部署错误排查
部署失败较为常见。Vercel 会展示详细日志，说明错误环节与原因。

常见错误：
- 构建命令配置错误
- 缺少环境变量
- 依赖安装失败
- 项目代码存在语法错误

修复流程：
- 查看错误日志，明确问题点
- 本地执行 npm run build 复现问题
- 将报错信息交给 Cursor 的 AI 辅助定位与修复
- 推送修复后的代码，Vercel 会自动重新部署
- 在 Deployments 标签页查看最新结果

若因环境变量缺失导致失败，需在项目设置中补全后点击 “Redeploy”。Vercel 保留历史记录，出现问题时可一键回滚到之前可用的版本。
