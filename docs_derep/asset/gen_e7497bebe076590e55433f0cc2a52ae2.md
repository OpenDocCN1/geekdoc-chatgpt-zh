## 9.1 Spring 登录验证核心组件解析

在 Spring 体系中，实现登录校验主要依赖以下几个核心类：

*   **AuthenticationManager**：认证流程的总控制器，接收 `Authentication` 对象，经处理后返回填充完整的认证对象。
*   **AuthenticationProvider**：具体认证逻辑的执行者，依据用户名密码判定合法性，并返回携带权限信息的 `Authentication` 对象。
*   **UserDetails**：封装应用层面的用户详细信息载体。
*   **UserDetailsService**：定义从数据源（如数据库）加载 `UserDetails` 的契约。
*   **UsernamePasswordAuthenticationToken**：承载用户名与密码的凭证令牌，用于向 `AuthenticationManager` 发起认证请求。

## 9.2 借助 ChatGPT 剖析第三方源代码

面对知名框架，AI 往往已有认知；但面对私有、非公开代码库，AI 处于“盲人摸象”状态。此时该如何破局？

### 9.2.1 核心策略：静态结构为骨，动态行为为魂

分析手段本质无异：先理清静态结构（类/模块关系），再推演动态行为（运行时交互）。

**⚠️ 避坑指南：守护原始代码完整性**

分析他人代码，**严禁直接修改原始源码**，以免引入风险。建议采取“三步走”策略：

1.  **建立副本**：拷贝一份代码副本，所有操作均在副本上进行（格式化、加注、重构）。
2.  **最小干预**：副本上仅做格式美化与关键注释补充，提升可读性，不动核心逻辑与架构。
3.  **尊重原意**：深度理解作者设计意图，非原则性缺陷不建议大动干戈；仅在发现严重隐患时，提出修正建议。

综上：**副本隔离、仅格式化加注、尊重原始设计**，是分析第三方代码的铁律。

## 10.3 技术选型与分层架构设计

需求落地，架构先行。Web 应用首选**分层架构**，职责分离，利于维护与扩展。

*   **Django**：大而全，自带 Admin、ORM，适合快速落地标准电商。

架构分层建议（以典型 MVC/分层为例）：
*   **表现层**：Controller / View / API 接口
*   **业务逻辑层**：Service / UseCase
*   **数据访问层**：Repository / DAO / ORM Model
*   **基础设施层**：配置、第三方集成、工具类
