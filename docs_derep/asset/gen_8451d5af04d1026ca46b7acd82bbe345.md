第16行里实现了 `LoadTensorsTables`，主要作用是抽取模型中全部 `Tensor` 的基础信息。第25行定义了 `LoadOperatorsTable`，负责读取模型所依赖的所有操作符对象的元数据。第40行出现的 `ImportTensors` 用来从模型中取出所有 `Tensor` 的实际数据。第60～76行会解析导入的 `Tensor` 数据中的 `quantization` 字段以判断是否经过量化，若已量化则读取量化下限与上限，并按照相关参数对数据执行量化。第80行定义了 `ImportOperators`，它会遍历模型中的每个操作符，先检查名称是否已在系统中注册，未注册则抛出错误；已注册则调用 `Deserialize` 还原模型数据，若 TensorFlow 对该自定义操作符不支持也会报错；校验通过后创建 `Op` 对象并初始化数据后加入模型。第122～134行在 `Tensor` 记录中查找操作符关联的全部输入 `Tensor` 并挂载到操作符上，第135～140行则完成输出 `Tensor` 的查找与挂载。第144行定义的 `ImportIOTensors` 专注于导入模型中参与数据输出的 `Tensor`。第169行的 `Verify` 用于判断缓冲区是否符合标准的 `flatbuffers` 格式，符合则返回校验后的缓冲区。第175行的 `Import` 是从文件导入 TensorFlow 模型的入口，先调用 `Verify` 核验缓冲区，再调用 `GetModel` 读取模型，接着执行 `LoadTensorsTable`、`LoadOperatorsTable` 加载张量表与操作符表，然后调用 `ImportTensors` 和 `ImportOperators` 填充数据，最后调用 `ImportIOTensors` 导入输出 `Tensor` 并返回加载完成的模型对象。`Export` 函数实现较为繁复，本文不展开，感兴趣可自行阅读 TensorFlow Lite 源码作为扩展了解。

## 11.5 本章小结

本章核心在于 TensorFlow Lite 的集成与源码剖析。先讲解了构建问题，因为 TensorFlow Lite 采用 Bazel 构建系统，故先介绍 Bazel，再说明 TensorFlow Lite 内的 Bazel 构建文件。随后讨论如何在自有系统里直接集成 TensorFlow Lite，以简易 C++ 程序为例演示了基础调用方式。之后阐述了 TensorFlow Lite 的内部架构与关键组件，并探讨根据需求对 TensorFlow Lite 进行定制修改的方法。最后聚焦模型处理代码，完成了 TensorFlow 模型的转换与压缩，实现了移动端运行 TensorFlow 训练模型，这也是 TensorFlow Lite 的要点所在。

## 12.1 Core ML

在结束移动端深度神经网络的理论与实践之前，还有一批通用且流行的移动平台机器学习框架与接口值得补上。这些技术上手快，适合快速搭建面向典型场景的机器学习应用。例如要做一个图像识别 App，通过摄像头输入识别拍摄花朵的种类，使用本节介绍的 `Core ML` 及配套工具就会很高效。开发者可借助 `Core ML` 构建图像识别、自然语言处理以及训练好的决策树推理。`Core ML` 基于苹果自家的 `Accelerate`、`BNNS` 与 `Metal Performance Shaders` 等技术构建，对性能、存储与功耗做了优化，能让普通开发者轻松在 iOS 上部署离线的机器学习应用。

这并不意味着 `Core ML` 只适合简单任务。Amazon 与 Apple 在 MXNet 框架上投入大量精力，通过 Amazon AWS 或直接使用 MXNet 训练的模型，经简单配置即可在 iOS 或 iPadOS 上运行。因此，对常见通用机器学习任务而言，`Core ML` 能在兼顾优化的前提下快速构建运行于 iOS/iPadOS 的应用，对生产环境具有实用价值，值得重点介绍并演示典型工作流。
