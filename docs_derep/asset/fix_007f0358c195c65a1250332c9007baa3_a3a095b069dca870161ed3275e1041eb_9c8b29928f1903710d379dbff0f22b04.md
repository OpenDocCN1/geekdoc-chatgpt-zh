### 4.4.3 定时任务的运维与排错

OpenClaw 给定时作业准备了一整套命令行操作面：

# 列出所有 Cron 任务
openclaw cron list

# 查看特定任务的详情（包括下次执行时间）
openclaw cron show daily-morning-brief

# 手动触发一次 Cron 任务（不等待下次计划时间）
openclaw cron run daily-morning-brief

# 暂停/恢复 Cron 任务
openclaw cron pause daily-morning-brief
openclaw cron resume daily-morning-brief

# 删除 Cron 任务
openclaw cron remove daily-morning-brief

# 查看 Cron 任务的执行历史
openclaw cron history daily-morning-brief --last 10

实际跑起来常会碰到网络抖动、工具报错、Token 用完等情况，平台内置了三层兜底。

• 自动重试：打开 retryOnError: true 后失败会自动再跑，最多 maxRetries 次，默认 3 次，间隔采用指数退避，避免短时间狂刷加重压力。
• 失败告警：配上 onError.notify，当所有重试都耗尽仍失败时，会主动给指定会话推送通知，保证你能及时介入。
• 运行上限：用 timeoutMs 给单次执行设个封顶时间，防止因为网络卡顿、模型迟疑或逻辑死循环导致任务卡死，保护资源。

配置示例：

{
  "id": "daily-morning-brief",
  "schedule": "0 7 * * 1-5",
  "agentId": "main",
  "message": "...",
  "timezone": "Asia/Shanghai",
  "timeoutMs": 120000,
  "retryOnError": true,
  "maxRetries": 2,
  "onError": {
    "notify": {
      "sessionKey": "agent:main:whatsapp:+8613800138000",
      "message": "⚠️ 晨报任务执行失败，请检查 Gateway 日志。"
    }
  }
}

排错时最常遇到的是作业已触发但 Agent 行为跑偏。几个好用的抓点：

• 立刻手动跑并盯日志。用 openclaw cron run daily-morning-brief --watch，--watch 会实时把 Agent 的执行流、工具调用和模型返回都打出来。
• 看会话历史。每一次运行都会在对应会话留下记录：openclaw sessions history cron:daily-morning-brief --last 5
• 在任务指令里加自检。可以在 message 里要求 Agent 每步先输出一行动作说明，比如 [步骤 N] 正在执行：...

定时作业会继承绑定 Agent 的工具授权。若要让它跑 Shell 备份，得确认该 Agent 的 tools.exec.security 不是 deny 且命令在白名单里。对安全性要求高的定时作业，建议单独建一个最小权限的专用 Agent，只开必要能力，别用大权限的通用 Agent。

### 4.5 配置体系与热更新

OpenClaw 的配置既能单文件搞定，也能多文件分层管理，而且大部分改动不用重启 Gateway 就能生效。

#### 4.5.1 配置文件的分层与复用

入口是 ~/.openclaw/openclaw.json，用 JSON5 语法，支持注释，统一收敛 Gateway、Agent、Channel、Tool 等顶层项。

配置变大时可用 $include 拆分，指令会递归合并外部文件：

{
  "gateway": {
    "$include": "./config/gateway.json"
  },
  "agents": {
    "defaults": {
      "$include": "./config/agent-defaults.json"
    },
    "list": {
      "$include": "./config/agents.json"
    }
  },
  "channels": {
    "$include": "./config/channels.json"
  }
}

注意：安全审计会检查 $include 的目标路径，若引用自云盘同步等不可信目录会发出警告。

配置文件里还能直接引用环境变量 ${ENV_VAR_NAME}，把密钥放在环境变量里，配置本身就能安全进 Git：

{
  "channels": {
    "telegram": {
      "token": "${TELEGRAM_BOT_TOKEN}"
    },
    "discord": {
      "token": "${DISCORD_BOT_TOKEN}"
    }
  }
}

#### 4.5.2 热更新机制

改完配置多数情况下不用重启 Gateway，即改即用，提升效率。支持热更新的范围见表 4-9。

表 4-9 OpenClaw 支持热更新的配置类别及说明
配置类别 热更新支持 说明
Agent 工具策略（tools.*） 是 立即生效，下次 Agent Loop 启动时使用新策略
Agent 模型配置（model） 是 下次 Agent Loop 启动时使用新模型
Cron 任务（cron.jobs） 是 立即更新调度计划
渠道配置（channels.*） 部分 消息策略立即生效，但账号连接需要重启
Gateway 绑定（gateway.bind） 否 需要重启
Gateway 认证（gateway.auth） 是 立即生效
沙箱配置（sandbox.*） 是 下次沙箱创建时生效

也可以用 CLI 触发热更新：

# 重新加载配置文件（不重启 Gateway）
openclaw config reload

# 验证配置文件语法（不应用）
openclaw config validate

# 查看当前生效的配置
openclaw config show

# 通过 patch 更新特定配置项
openclaw config patch --path "agents.defaults.model" --value "gpt-4.1"

Agent 自我配置是 OpenClaw 的特色。Agent 能调用 gateway 工具自行改配置，比如收到把模型切到 GPT-4.1 Mini 的指令后，会自动执行 config.patch 把 agents.list[0].model 改成 gpt-4.1-mini，并告知用户从下次对话开始生效。

但 gateway 权限极高，被列为高风险。若在群组、外部渠道等可能接收不可信内容的 Agent 中启用，可能被恶意指令篡改配置，导致系统异常。因此这类场景应明确禁止使用 gateway。

#### 4.6.1 业务场景拆解

• 一对一助手：经 WhatsApp 和 Telegram 交互，具备代码执行、文件读写能力，但所有操作被限制在使用者自己的工作目录里。
• 社群机器人：在 Discord 为社区成员答疑，工具面被大幅收紧，所有操作在隔离沙箱里跑，防止提示注入风险。
• 定时自动化：用 Cron 实现每日晨报、每周代码复盘等流程。
• 安全底线：网关不直接挂公网，通过 Tailscale 安全访问；所有 API 密钥走环境变量，不以明文写进配置。
