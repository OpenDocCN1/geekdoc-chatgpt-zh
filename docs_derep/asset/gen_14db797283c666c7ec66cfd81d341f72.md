**小贴士**

**Cookie 要怎么拿？**

小红书、抖音用的都是浏览器凭证，全程大概 3 分钟就能搞定。以小红书为例：

● 用电脑浏览器打开小红书网页版，先登录好运营账号
● 按 F12 调出开发者工具，切换到 Network 网络标签
● 刷新页面后点开任意一条请求，在右侧 Headers 请求头里找到 Cookie
● 把 Cookie 那一行完整复制下来保存，这就是平台操作凭证

抖音的浏览器凭证获取方式和小红书完全一样，几乎没有技术门槛。

拿到凭证后就去填配置。打开 social-cli 文件夹找到 .env.example，复制一份改名为 .env，注意文件名开头有个点；用文本编辑器打开，只填你要用的平台凭证，没用的平台直接空着。

【Prompt 模板】填写示例（.env 文件，只写在用的平台）

//微博
WEIBO_ACCESS_TOKEN=你的微博 Token

//小红书
XHS_COOKIE=你复制的 Cookie 内容

//微信公众号
WEIXIN_APPID=你的 AppID
WEIXIN_APPSECRET=你的 AppSecret

//AI 功能（评论自动回复和周报需要，填一个即可）
DEEPSEEK_API_KEY=sk-你的 Key

[PRE3]
**注意**

填完前一定要记住：.env 文件相当于各平台账号的钥匙，里面都是能直接操作的敏感信息，严禁发给别人、发到社交平台或上传到代码托管。万一怀疑泄露，立刻去对应平台重新申请凭证，旧凭证会失效。

各平台对发帖频率的限制不同，发太多容易被限流。凭证配置好后，先给每个平台设定每日上限。打开 config.yaml，找到 publish_schedule 这一块按需修改：

（1）需要用的平台把 enabled 改为 true，不用的保持 false
（2）给每个开启的平台设定 max_per_day，建议结合平台规则合理设置

【Prompt 模板】config.yaml 配置示例
publish_schedule:
weibo:
enabled: true
max_per_day: 3 // 微博每天最多发 3 条
xiaohongshu:
enabled: true
max_per_day: 2 // 小红书每天最多发 2 条
weixin:
enabled: false // 暂时不用就关掉
douyin:
enabled: false // 抖音先关闭，稳定后再开

两处配置完成后，在 OpenClaw 对话框里发一条验证指令，就能检查连通性：

返回“小红书连接成功”“微博连接成功”就说明没问题，可以正式用了；如果失败，检查凭证是否复制完整、账号是否正常登录，重新配一次即可。

**小贴士**

**为什么必须人工审核才能发？**

不直接自动发是有原因的。AI 写的稿子难免有偏差或和账号调性不符，人工看一眼、改一下再发，能保证质量和安全。工具只会投放你明确标记为“审核通过”的内容，从源头杜绝误发风险。

发完内容自然想看效果。过去要一个个进后台翻，现在一句指令就能拉数据分析。

## **本章小结**

第六章把前五章的原理落地到真实使用场景，不讲理论，只看实操。五个案例覆盖不同人群核心需求。

6.1 节面向程序员。氛围编程工作流解决的是工作流混乱问题。需求描述、架构设计、代码生成、调试优化、持续迭代各阶段产出清晰，AI 从聊天工具变成可协同的搭档。核心是人定方向，AI 落地。

6.2 节面向开发者。GitHub 管理工具一键配置个人访问令牌后，仓库管理、日记生成、CI/CD 监控、故障追踪全自动化，且会主动推送需要决策的事，减少盯后台时间。

6.3 节面向知识工作者。第二大脑工具解决“记了找不到、找到不关联”的痛点。捕获、整理、语义检索、知识图谱、间隔复习构成全自动闭环，数据本地保存。

6.4 节和 6.5 节面向内容创作者。内容智能工具自动扫描热榜、筛选话题、生成多平台脚本；社交运营工具负责一键发布、数据拉取、评论处理、变现追踪。核心设计是 AI 绝不自作主张，只发布审核通过的内容。

贯穿始终的线索是：OpenClaw 负责执行，你负责决策。它承接机械重复工作，在每个决策节点等待你的指令。

本章五个技能包均配有可直接复制的指令模板和配置示例，按步骤配置即可当天上线。

读完六章，你已能搭建完整的 AI 工作系统，让 OpenClaw 成为高效助手。它会随使用成长，越用越贴合。
