需求描述越细，AI 给的方案越准

> 我想做一个以图为主的社交产品，大致需求如下。
> 1. 用户能上传照片并配文字，就像发朋友圈那样
> 2. 可以关注别人并进行点赞评论
> 3. 有互动时能立刻收到提醒
> 
> 使用前提：
> - 主要在手机 App 上用
> - 预计第一年用户在 1 万到 10 万之间
> - 图片加载要快，App 启动要顺滑
> 
> 请用大白话推荐技术选型并说明每个技术在干嘛。

当需求讲到这个程度，模型回应的针对性会明显提升。它会用生活化的类比来拆解方案，下面是示意。

**用户可见的前端层**

- React：像乐高积木拼界面，组件可复用改动快；
- React Native：一套代码同时覆盖 App 和网页，节省开发时间；
- Tailwind CSS：快速装扮界面的样式工具，相当于给 App 换衣服。

**后台运行层**

- Node.js：处理用户请求的服务端程序，像餐厅里传菜的服务员；
- MongoDB：存用户资料的文档型数据库，像超大号电子档案柜；
- Redis：提升读取速度的缓存，像贴在桌面的便利贴。

**图片存取与分发**

- AWS S3：存放海量图片的云盘，像无限容量的网络相册；
- CloudFront：全球节点加速分发，像遍布各地的快递网点。

**实时互动**

- Socket.IO：负责即时消息的底层引擎，像聊天软件的心脏；
- Firebase：提供推送提醒，像手机自带的通知中心。

新手速记
- 描述需求时功能要讲透、场景要具体
- 前端挑型以用户体验为优先
- 后端架构要兼顾性能、扩容和维护
- 存储方案要权衡安全与访问效率
- 通信设计要保证实时与稳定
- 技术组合主张简洁可靠，别盲目追新
- 提前留好成长空间
- 花费按实际体量来匹配

### 2.4.3 在 GitHub 找开源项目实战指南

对新手来说 GitHub 就像程序员的社区，也是个藏书巨大的数字图书馆，里面都是开源仓库。别慌，下面讲怎么挑到合适的书。

#### 1. 基础检索方法

在 GitHub 找项目和在电商找商品思路差不多。

1. 打开 github.com，顶部有搜索框。
2. 输入项目类型关键词，比如“图片分享应用”。
3. 用右侧筛选器缩小范围，像网购筛选项。

举例找图片分享项目：
1. 搜索 image sharing app 或 photo sharing。
2. 左侧挑偏好的编程语言，比如 JavaScript。
3. 按 点赞数 排序，点赞数相当于商品的好评。

#### 2. 读懂项目页信息

每个仓库页都有关键身份标识。

##### 1) 基础数据
- Stars：相当于点赞，数字越高越受欢迎。
- Forks：被复制的次数，体现影响力。
- Watchers：持续关注的人数。

##### 2) 主题标签 Topics
- 位于简介下方，像商品标签。
- 蓝色标签标明技术或类型，如 react、web-app。
- 点进去能找到同类仓库。

##### 3) 语言构成
- 简介下方的彩色条。
- 像配料表，展示所用语言比例。
- 帮助判断技术栈。

#### 3. 看懂说明文档 README.md

README.md 相当于说明书，通常包括：

##### 1) 项目简介
- 这个项目用来干嘛；
- 解决什么痛点；
- 有没有截图或演示视频。

##### 2) 技术要点
- 用了哪些核心技术；
- 运行环境要求；
- 设计思路概述。

##### 3) 使用指南
- 安装启动步骤；
- 基本操作方式；
- 常见问题解答。

#### 4. 判断好坏

非技术人员可以从以下角度判断：

##### 1) 活跃度
- 点赞过千的通常比较可靠；
- 近半年有更新说明维护在线；
- 维护者是否及时回复 Issue。

##### 2) 文档完整度
- README 是否清晰全面；
- 是否提供截图或在线演示；
- 说明是否通俗易懂。

##### 3) 上手门槛
- 安装步骤是否简明；
- 是否有详细教程；
- 最好有在线演示。

#### 5. 实用小技巧

##### 1) 热门项目页
- 访问 github.com/trending；
- 展示当前最受关注的项目；
- 可按语言和时间筛选。

##### 2) 收藏
- 点仓库右上角 Star；
- 后续可在个人主页找到。

##### 3) 找相似
- 点击 Topics 标签；
- 找到同类仓库。

##### 4) 遇到问题
- 查看 Issues 页面；
- 看看是否有人遇到过类似问题；
- 可用英文提问。

关键回放
- 先看点赞靠前的仓库
- 阅读 README 重视介绍和使用
- 选择看更新频率和文档质量
- 解决难题先搜 Issues 再提问
- 及时 Star 方便以后查找
- 定期逛 Trending 抓热点
- 按需求筛选语言
- 评估文档看完整性和可读性

官网为 https://github.com/copilot/。下面介绍如何借助它找项目。

#### 1. 两种对话方式

Copilot 提供两种交互形式，像在咨询台提问或在书架前请教。

##### 1) Copilot 对话模式

GitHub Copilot Chat模式界面如图2-4所示。

借助 Copilot 就像拥有全天候技术导师，帮助在开源海洋中找到合适的学习资源。记住编程学习贵在循序渐进，从简入深逐步积累。

### 2.4.5 借助 AI 解读技术文档

技术文档对没有背景的人常显晦涩。现在有 AI 担任“翻译官”，能把专业术语转为易懂表达。下面以 Cursor 为例说明如何轻松解读文档。

#### 1. 准备工作

使用前需要准备，类似出国前准备护照地图。

1. 收集资料
   - 将开源项目代码下载到本地；
   - 收藏相关技术文档链接；
   - 准备想了解的 API 文档地址。
2. 配置翻译工具
   - 打开 Cursor 软件，导入项目文件夹；
   - 等待项目索引完成；
   - 在设置中添加技术文档。

#### 2. 用 Docs 功能解读文档

Cursor 的 Docs 功能相当于给 AI 配专业参考书库，让回答更准确。

##### 1) 添加文档
- 在对话框输入 @Docs 命令选择 Add new doc，或在设置功能标签页添加；
- 输入文档网址，如框架官方文档、API 文档；
- 起个易记名字，如“React 文档”或“Express API”；
- 等待添加成功。

##### 2) 使用文档解读内容
@docs React Router请帮我解读 React Router 文档。
1. 用通俗语言解释路由概念
2. 给一个简单路由配置示例
3. 指出使用时的常见陷阱
4. 说明与普通 React 组件的区别

##### 3) 文档管理
- 按技术类型归类，如前端、后端、数据库；
- 定期更新保持信息最新；
- 清理不再使用的文档；
- 与团队共享重要资源。

#### 3. 用 Codebase 分析代码

Codebase 是 Cursor 中理解和交互代码库的功能，通过扫描索引整个项目，使 AI 能把握完整上下文。

##### 1) 工作原理
- 自动扫描并索引代码库；
- 用向量化技术保存代码语义；
- 实时更新保持同步；
- 分析依赖关系和架构。

##### 2) 分析项目
@Codebase请分析项目结构：
1. 主要功能模块划分
2. 数据流转方式
3. 核心业务逻辑在哪些文件
4. 整体架构设计

##### 3) 交叉验证
@docs @Codebase关于用户认证功能：
1. 对比文档最佳实践和当前实现
2. 指出可能的安全隐患
3. 建议改进方向

#### 4. 技术可行性评估

确定方案时可结合文档和代码分析可行性。

基于文档和代码分析，请评估[技术方案]：
1. 技术难度：适合什么水平的团队
2. 开发周期：大概需要多长时间
3. 维护成本：需要怎样的技术支持
4. 扩展性：未来扩展难度如何

#### 5. 使用技巧与注意事项

##### 1) Docs 使用技巧
- 确保文档来源可靠；
- 不要添加含敏感信息的文档；
- 控制数量避免混乱；
- 可添加团队内部规范等自定义文档。

##### 2) Codebase 使用技巧
- 修改后重新索引保持更新；
- 清晰注释有助于 AI 理解；
- 合理组织结构提高分析准确度；
- 大型项目可选择性索引核心模块。

##### 3) 组合最佳实践
- 先用 Codebase 了解结构；
- 再用 Docs 学习技术细节；
- 结合两者分析现有实践与最佳实践差距；
- 利用建议指导开发方向。

#### 6. 实际案例

##### 1) 学习新框架
- 将官方文档添加到 Docs；
- 导入示例项目到 Codebase；
- 请求 AI 解释核心概念并对照代码；
- 逐步深入高级特性。

##### 2) 接手维护项目
- 用 Codebase 快速理解架构；
- 添加相关技术文档到 Docs；
- 通过 AI 分析代码质量和潜在问题；
- 规划改进路线和优先级。

##### 3) 评估技术选型
- 将多个候选技术的文档添加到 Docs；
- 请求 AI 对比优缺点；
- 结合需求选择最合适方案；
- 验证是否满足扩展需求。

通过这种方式，即使没有技术背景也能做到：
1. 理解文档核心内容；
2. 把握项目整体架构；
3. 评估方案可行性；
4. 与开发团队有效沟通。

记住目标不是成为技术专家，而是做出明智决策并与团队顺畅协作。

关键回放
- 解读文档先理解概念再看实现
- 善用 @docs 和 @Codebase，提问要具体
- 代码分析采用模块拆解，逐步理解
- 技术评估需兼顾难度、周期、成本
- 团队沟通要把专业术语转为通俗语言
- 决策以需求为本、落地为重
- 学习路径循序渐进、稳扎稳打
- 工具应用多方验证、谨慎决策

## 2.5 从需求到文档：打造清晰的产品设计文档

前面学习了需求分析和技术探索。现在需要把想法整理成清晰的产品设计文档，让 AI 助手如 Cursor 能准确理解需求并开展开发。

### 2.5.1 产品设计文档的核心要素

想象你在和 AI 助手聊天，希望它帮你开发应用。这时需要一份清晰的说明书告诉 AI 想要什么。这份说明书就是产品设计文档，应包含哪些关键内容？

#### 1. 产品总览与目标

如同介绍新朋友，先让 AI 了解产品是什么。这部分是产品自我介绍，需包含基本信息和目标。

举例说明。

**产品设计文档：智能学习助手**

##### 产品愿景

打造一个帮助学生高效学习的 AI 助手，像贴心学习伙伴，协助制定学习计划、监督学习进度。

##### 目标用户
- 主要用户：在校大学生和备考学生
- 次要用户：希望自我提升的职场人士

##### 核心卖点
1. 智能规划：根据个人情况制定学习计划
2. 进度追踪：实时记录和分析学习情况
3. 学习建议：提供个性化学习方法指导

#### 2. 功能清单说明

这一部分如同给 AI 讲解产品的“使用说明书”，每个功能都要说清楚，就像教小朋友玩新玩具一样详细。

##### 核心功能模块

###### 1. 智能学习计划生成器

功能说明：
- 输入：用户学习目标和可用时间
- 输出：定制化的每日学习任务清单
- 特点：支持随时调整，智能适应学习进度

实际场景：

小明准备考研，每天能投入 4 小时学习。他只需：
1. 选择“考研备考”目标
2. 设置每天可用时间
3. 系统就会自动生成适合他的学习计划表

技术要点：
- 智能算法：基于学习规律生成计划
- 数据分析：跟踪学习效果
- 实时调整：根据完成情况更新计划

#### 3. 界面交互规划

这部分像给 AI 看产品的“装修设计图”，让它明白用户看到什么、怎么操作。2.7 节会更深入介绍界面和交互。

##### 用户界面设计

###### 主页设计

布局安排：
1. 顶部区域
   - 左边：显示 Logo
   - 右边：个人头像和设置按钮
2. 中间内容区
   - 今日任务卡片（占屏幕 40%）
   - 学习数据图表（占屏幕 30%）
   - 学习建议板块（占屏幕 30%）

操作方式：
