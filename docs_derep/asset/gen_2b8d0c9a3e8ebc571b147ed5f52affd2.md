## 8.1　MCP

当 AI 从单一问答走向多模态、长上下文的复杂场景，模型孤岛和上下文断层的问题就凸显出来。对话需要记住历史，跨模态任务需要把文本、图像等不同来源的信息揉在一起，行业迫切需要一套更通顺的协作方式。MCP 正是在这种需求下被推到台前，它是一套面向模型间上下文传递的统一规范，既能让系统更连贯、更智能，也给开发者提供了一条应对计算和集成压力的捷径。

### 8.1.1　MCP 简介

MCP 由 Anthropic 在 2024 年 11 月开源，2025 年起关注度快速攀升。2025 年 3 月 27 日 OpenAI 在 Agent SDK 中宣布兼容 MCP；2025 年 4 月 4 日谷歌则在 Gemini 官方 API 文档里补充了 MCP 用法示例。

它的目标是把大模型与外部数据、工具之间的沟通统一起来，破解数据孤岛让模型潜力被真正释放。借助 MCP，AI 智能体可以在受控范围内读写本地与远程数据，成为真正连通万物的桥梁。

设计上，MCP 追求开放与标准化，意在解决传统集成碎片化的痛点。它提供一套规范化的上下文管理思路，并用同一套协议和外部世界中的工具、服务、数据对话。用一个比喻来说，就像给电脑配上 USB-C，适配不同外设变得简单。大模型通过这一层可以很方便地调用各种数据源和能力。

生态也在加速成型。mcp.so、smithery.ai 等聚合平台出现，网上已涌现数千个 MCP 服务器。工具对智能体来说变得即插即用，重复开发大幅减少。开发者既能直接使用社区开源的服务器，也能按需自建，接入效率明显提升。

### 8.1.2　MCP 与函数调用的区别

函数调用是 OpenAI 于 2023 年 6 月在 GPT 系列中推出的 API 能力。开发者在请求里提供函数定义，包含函数名、参数 JSON Schema 和描述等，模型会根据上下文自行判断是否需要调用，并以符合 Schema 的 JSON 指令返回。本质上是通过 Chat Completion 接口递交一份工具说明书，让模型决定是否取用外部数据再返回给用户。

以询问杭州天气为例，流程大致是：把用户问题连同 `get_weather` 的 JSON 定义一起发给模型；模型决定调用后在 `tool_calls` 中输出指令；客户端据此执行 `get_weather`、拿到结果后再把原始问题和天气信息一起喂回模型；模型再结合完整信息给出自然回复。

函数调用解决了模型外联工具的问题，工具实现仍由开发者负责。但不同厂商的实现细节不一致，比如 Claude API 把 OpenAI 的 `parameters` 改成了 `input_schema`。每家差异意味着每个函数都要单独适配。

因此，随着工具增多，适配和维护成本会快速上升。更理想的思路是约定一个通用标准，让模型端和工具端各适配一次即可。MCP 就是为此而生，它把开发和使用流程大幅简化。

总结来看，MCP 是一套通用标准化的交互协议，适合大规模工具集成；函数调用则是厂商提供的特定调用入口，更适合简单场景的扩展。

### 8.1.3　MCP 的工作原理

本节围绕 MCP 的构成、数据来源和运行流程展开。

#### 1．MCP 的核心组件

MCP 由主机、客户端和服务器三部分组成。

MCP 主机是整个链路的起点，通常是 Cursor、Claude Desktop、Cline 这类启动应用。它接收用户的提问或指令，转发给大模型，并在交互全程担任沟通桥梁，确保需求被准确传达和处理。

MCP 客户端运行在主机内部，负责和 MCP 服务器通信。当模型处理请求时若需要触达外部资源或工具，客户端会被触发，按模型需求连接合适的服务器，完成资源访问。

MCP 服务器是能力供给侧，通过统一协议向客户端提供上下文、工具、提示等。收到请求后它会执行具体操作，比如查询数据源、调用 API，再把结果回传给客户端。它的存在让模型能高效利用外部资源，拓展应用边界。

#### 2．MCP 的数据基础

MCP 服务器依托两类数据：一是本地数据源，二是远程服务。

本地数据源包括本地文件、本地数据库、本地 API 等。服务器可直接连接这些资源，为用户提供信息或执行操作。例如查询本地数据库时，服务器通过直连快速取数返回。

远程服务则涵盖外部文件、外部数据库、外部 API。当用户需要最新外部数据时，服务器通过与远程服务的交互来满足需求，提供更丰富的信息和更广的操作范围。

## 8.2　A2A 协议

技术栈、开发框架和数据格式各不相同，导致智能体之间沟通协作困难。A2A 协议正是为缓解这些摩擦而设计。

### 8.2.1　A2A 协议简介

A2A 是一种开放协议，聚焦智能体间的交互与协同。它让来源和技术不同的智能体能够互相对话、安全交换信息并一起完成复杂任务，核心目标是打破系统孤岛，提升跨平台协作能力。

该协议由谷歌于 2025 年 4 月 9 日推出，意在让不同框架和厂商的 AI 智能体实现互通互联，已获得 50 多家科技公司的支持，主要解决企业级智能体的互操作难题。

作为开放标准，A2A 重点解决智能体在用户与企业场景中的通信问题，其特点之一是采用标准化消息格式。为 AI 智能体打造一套共同“语言”，清晰表达需求和回答内容。
