# 全局检索到图谱可视化：GraphRAG 关键环节拆解

GlobalCommunityContext 是专为 Global Search 模式设计的上下文组装器，核心职责是从社区报告、实体表、社区元信息等多源素材中抽取相关片段，拼装成覆盖面广的查询上下文供检索使用。

- community_reports=reports：传入的是从文件中读取的 COMMUNITY_REPORT_TABLE 数据。每一份报告都记录了不同社区的主题、摘要、影响力、研究发现等高层信息，在全局检索中主要用于快速形成全量数据的概览视角。
- communities=communities：存放社区的组织结构与属性信息。在图谱视角下，社区往往对应主题、领域或高相关实体群，在全局检索时常被用来做分组与排序，比如按社区重要性或与查询的相关度进行排列。
- entities=entities：来自前序索引阶段的实体数据，来源是 ENTITY_TABLE。人物、地点、事件等具体实体可以把检索边界进一步延展，提供名词、对象和概念层面的上下文。若不想让社区权重干扰实体排名，可把该参数置为 None。
- token_encoder=token_encoder：文本编码工具，负责把自然语言切分为模型可接受的 token 序列。此前代码里采用 tiktoken.get_encoding("cl100k_base") 来完成分词，便于控制输入长度。

此处实例化一个全局搜索引擎，依赖前面准备好的上下文构建器、语言模型及其他配置。参数含义如下。

- llm：已配置好的大模型，例如 ChatOpenAI，用来生成最终答案。
- context_builder：即前文提到的 GlobalCommunityContext，依据社区报告和社区信息来组织查询上下文。
- token_encoder：文本编码器，通常是模型专属的 tokenizer。
- max_data_tokens：上下文中允许的最大数据 token 数，需结合模型上限预留余量，比如模型 8K 时可设 5000 左右，用来限制全局检索的窗口规模。
- map_llm_params 和 reduce_llm_params：分别对应映射与归约两阶段的 LLM 配置，会影响生成时的 max_tokens、temperature 等行为。
- allow_general_knowledge：是否允许模型引入外部通用知识。开启可能带来幻觉，默认关闭为 False。
- json_mode：是否以结构化 JSON 返回结果。开启则输出规范化结构，关闭则为自由文本。
- context_builder_params：传给上下文构建器的细化配置，例如是否使用社区简要摘要、是否加入社区排序等。
- concurrent_coroutines：并发协程数量，支持同时处理多个查询，例如 32 表示最多并行 32 个请求。
- response_type：描述返回内容的格式与类型，这里设为 "multiple paragraphs"，即多段落的长文本说明，适合报告式输出。

**ID3 决策树算法概述**

ID3 属于基础的决策树分类方法，核心做法是对连续变量如年龄、收入进行离散化处理，以降低数据集不纯度，这一操作是决策树建模的关键 [Data: Reports (1)]。离散化有助于提升模型精度与效率。

**与 CART 的差异**

ID3 经常拿来对照 CART 树。两者目标都是减少不纯度，但在划分数据的策略上不同，理解这种差异有助于判断在不同数据科学场景下的优劣 [Data: Reports (1)]。

**计算依赖**

ID3 的信息熵计算高度依赖 Numpy 这类科学计算库，体现了数值计算在决策树建模中的支撑作用 [Data: Reports (1)]。

**实现限制**

ID3 无法直接基于主流机器学习库 Sklearn 实现，这种不兼容意味着依赖 Sklearn 的用户需要寻找替代实现或做适配调整 [Data: Reports (1)]。

**模块化设计**

ML_basic_function 模块可能提供了 ID3 建模过程中常用的基础机器学习函数，体现了模块化、可复用的实现思路 [Data: Reports (1)]。
