10.2.5 DeepSeek R1-Zero 为何舍弃 SFT
业界成熟的 LLM 工坊是先大规模预训练，再做监督微调，再做基于人类偏好的强化学习。R1-Zero 在构建推理专用模型时却直接省略了 SFT，这一取舍被视作关键创新。

预训练阶段占据了绝大多数算力与语料开销。SFT 与 RLHF 的作用分别是让模型能进行对话交互以及让输出更符合人类价值观。对于推理类模型，长 CoT 数据人工难以获取且制作昂贵，直接在长 CoT 上做强化学习更具可行性。

更本质的障碍在于，普通语料 SFT 之后再做强化学习容易出现收敛困难。GRPO 与 PPO 的目标里都包含这类正则项：

10.2.6 DeepSeek R1 为何需要少量 Long-CoT 监督微调
R1 采用的 GRPO 本质上是具备在线探索的强化学习，收敛质量高度依赖起始点与目标点的距离。目标是强化长 CoT 能力，若完全跳过长 CoT 的 SFT，起点与目标差距会非常大。

因此先用少量人工标注的长 CoT 数据做一次 SFT，相当于把模型先拉到离目标较近的次优区域，后续强化会更顺畅。同时这类人工数据还能明显遏制 R1-Zero 里出现的不可读与语言混乱现象。

10.3 DeepSeek VL2 的训练逻辑
VL2 的整体训练被切分为三个阶段，各自承担不同职责，最终实现强视觉语言理解与生成。

10.3.1 起步阶段：视觉语言对齐
目标是让视觉表征与语言表征建立初步映射，使基座大模型能基本读懂图像。
做法是使用图文配对数据训练时冻结语言模型本体，仅更新视觉编码器与视觉语言适配器。适配器随机初始化，先单独训练能找到更合理的映射区间。本阶段只在文本位置计算自回归损失，突出视觉理解。
结果是视觉编码器可把图像转为大模型可用的特征，完成初步对齐。

10.3.2 预训练阶段：多模态联合学习
目标是发展全面的视觉语言协同能力，拓宽多模态理解广度。
做法是使用海量图文数据端到端训练，解冻全部参数包括视觉编码器与适配器。训练规模约 8000 亿个图文标记，覆盖各类视觉语言任务。
结果是模型能捕捉图像与文本的复杂关联，并生成贴合图像内容的自然语言描述。

10.3.3 微调阶段：指令遵循与对话增强
目标是强化指令跟随与对话表现，让模型更好理解并执行用户需求。
做法是使用内部视觉语言数据做监督微调，全参数更新，仅对答案与特殊标记监督，屏蔽系统与用户提示。并将多模态数据与纯文本对话数据混合，增强对话理解。
结果是模型能按指令给出更精准自然的回复，在表格图表文档图形理解、视觉推理、语言理解等任务上表现突出。

分阶段利用不同数据与算力，实现了 VL2 在各类视觉语言任务上的优异表现。

第十一章 DeepSeek 的推理及优化
在推理侧，吞吐量与时延决定可用性与商业价值。DeepSeek V3/R1 依托大规模跨节点专家并行、计算通信重叠、动态负载均衡三大手段，实现了惊人的效率，重新定义了万亿参数模型的实时响应。

11.1 DeepSeek 推理阶段的报告原文
V3/R1 推理的优化目标是更大吞吐更低时延。核心手段是跨节点专家并行 EP。EP 能显著放大全局 Batch，提升 GPU 矩阵乘法效率；同时把专家分散到不同卡，每卡只需处理少量专家，访存压力下降，时延降低。

使用 EP 也带来复杂性：
使用 EP 会引入跨节点传输，需要设计流程让传输与计算并行进行。
EP 天然涉及数据并行，不同数据并行组间需要负载均衡。
因此要解决如何用 EP 放大 Batch、如何压缩传输耗时、如何做负载均衡。

1.大规模跨节点专家并行
V3/R1 的专家数量很大，每层 256 个专家仅激活 8 个。高度稀疏决定了必须采用很大的全局样本批次，才能为每个专家提供足够样本，实现更高吞吐更低时延。这需要大规模跨节点专家并行。

多机多卡专家并行策略：
Prefill：32 路路由专家并行、32 路 MLA 并行、共享专家 32 路数据并行。一个部署单元用 4 个节点，32 个冗余路由专家，每卡 9 个路由专家 + 1 个共享专家。
Decode：144 路路由专家并行、144 路 MLA 并行、共享专家 144 路数据并行。一个部署单元用 14 个节点，32 个冗余路由专家，每卡 2 个路由专家 + 1 个共享专家。

2.计算通信重叠
多机多卡专家并行会带来较大通信开销，采用双 Batch 重叠来掩盖通信，提高整体吞吐。
