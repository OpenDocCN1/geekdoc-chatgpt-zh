phidata 的定位很清晰，就是把通用的大模型改造成面向特定业务的专业化 RAG 助手。实现思路是给 LLM 扩充三类能力：

- 记忆：把历史对话持久化到数据库，让模型支持长时间的连贯交流。
- 知识：将业务资料写入向量数据库，为模型提供即时的上下文支撑。
- 工具：赋予模型调用外部能力，比如拉取 API 数据、发送邮件或发起网络请求。
整体上可以理解为，智能助手 = LLM + 记忆 + 知识 + 工具

### 7.1.3 Ollama 环境搭建
Ollama 是一个开源的大模型本地服务工具，能让用户在本地便捷地运行和管理大模型。本案例里的主模型 Llama 3 以及嵌入模型 nomic-embed-text 都是借助 Ollama 部署的。

#### 1. 获取与安装 Ollama
进入 Ollama 官网下载页，按照 Windows、Linux 或 macOS 系统选择对应安装包，点击下载。下载完成后双击运行，按向导提示完成安装即可。

#### 2. 配置 Ollama 环境变量
- （1）通过 Windows 开始菜单打开设置，在“查找设置”框输入“环境变量”并回车。
- （2）在搜索结果中点选“编辑系统环境变量”。
- （3）打开弹出的“系统属性”窗口，切换到“高级”页，点击“环境变量”按钮。
- （4）找到“Path”变量，双击或点击“编辑”下的“新建”。

若采用默认安装路径，可复制 C:\Users\Administrator\AppData\Local\Programs\Ollama 到其中，或自行定位 ollama.exe 所在目录复制路径，确认保存。

### 7.1.4 基于 Ollama 部署 Llama 3 与 nomic-embed-text
大语言模型如 GPT 这类，经过训练后具备推理和对话能力，本例选用 Llama 3。
嵌入模型的作用是将高维数据如词、句、图像映射为低维向量，让相似对象在向量空间更靠近、不相似对象更远离，从而支持检索与计算，广泛用于 NLP、CV 和推荐等场景。本例选用 nomic-embed-text。

在 Ollama 环境变量配置完成后，打开 PowerShell，首先执行“ollama pull llama3”拉取主模型，随后执行“ollama pull nomic-embed-text”拉取嵌入模型。安装完毕后运行“ollama list”即可查看已有的模型清单。

### 7.1.5 用 Docker 获取向量数据库镜像
Docker 是一个容器平台，可用于封装已配置好的向量数据库。它把应用及其依赖打包成可移植容器，在任意支持 Docker 的系统上运行，是轻量级的隔离运行方案。本例借助 Docker 拉取向量数据库镜像。

（1）先在 Docker 官网下载并安装 Docker。然后打开 PowerShell，执行“docker pull phidata/pgvector:16”拉取镜像。

restart_assistant 的作用包括：

- （1）生成唯一标识：为文件上传组件分配唯一 key，保证在 streamlit 重渲染时能被正确识别与更新。
- （2）状态追踪：通过 session_state 保存 key，追踪用户是否已上传文件，每次上传后 key 自增，让上传组件被视作全新组件触发逻辑。
- （3）避免重复处理：检查 session_state 中是否已存在以 {rag_name}_uploaded 命名的键，防止同一文件被重复读取。
- （4）重新加载应用：用户上传新文件或切换模型时，函数会清空当前会话并重启应用，key 的递增确保输入与上传组件状态刷新。

举例来说，若用户先上传文件并填入 URL，随后重启助手：不递增 key 会导致旧文件或旧 URL 仍显示，造成混乱。通过递增 url_scrape_key 与 file_uploader_key，可保证重启后组件均为全新状态，提升体验并避免状态冲突。
