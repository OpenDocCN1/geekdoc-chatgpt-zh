2012 年，Google 向外界发布了《The Datacenter as a Computer》这篇论文。

在那之前，程序员的注意力几乎全部锁在单节点上，像个钟表匠一样追求把每台服务器、每个进程都打磨到近乎完美。只要有一台机器宕机，就会被当作严重事故来处理。

Google 给出的新说法是：真正运行软件的不是孤立的服务器，而是整个数据中心这台“计算机”。

在这个视角下，硬件故障不再被视作例外，而是统计意义上的必然。硬盘终会损坏，网络终会抖动。软件的设计目标也从“杜绝故障”转向“在故障常态化时依然可靠”。这正是从确定性思维向概率性思维转身的第一步。

### 2. 从鲁棒到反脆弱

2012 年，Netflix 将 Chaos Monkey 开源。

在软件史上，这堪称极具挑衅的决定：公司写了一个专门在生产环境里随机掐死自家服务器的程序。

在 GoF 盛行时，这样的行为难以想象。Netflix 的理由很直接：既然故障躲不掉，不如让它来得更频繁。

从此，“反脆弱”进入软件工程的视野。系统不再追求像钻石那样硬到一碰即碎，而是像免疫系统那样，通过持续的小幅创伤不断进化生存能力。确定性设计想筑起一道墙挡住混乱，反脆弱设计则学会利用混乱。

### 3. 不可变的基础设施

2013 年，Docker 上线。

Docker 之前，服务器是需要手工呵护的。运维人员远程登录，装依赖、改配置、打补丁。随着时间推移，机器逐渐变成带有独家记忆的“雪花”服务器，重启都让人心惊，因为没人清楚它现在是什么样子。

Docker 带来的容器化浪潮，让基础设施变得不可变。容器坏了不修，直接销毁再起一个。新软件组件于是变成无状态的消耗品，而非需要长期维护的资产。这也为 Agent 之后能动态调度、销毁工具环境提供了底层条件。

### 4. 控制权的转移：声明式 API

2014 年，Kubernetes 诞生。

K8s 抛弃了命令式的操作习惯——先启动 A 再启动 B 失败就重试 C，改用声明式 API——我只要 3 个副本，剩下的你处理。

它引入了至关重要的调解循环。

- 期望状态：用户声明的意图。
- 实际状态：系统当下的样子。
- 调解器：持续感知差距并采取行动把它抹平。

感知—差异—行动的循环，与 Agent 心智模型雏形惊人相似。Kubernetes 的控制器，本质上就是一个面向特定任务的原始 Agent。

这些变化指向同一个结论：确定性时代结束了。软件不再是精密的瑞士手表，更像是自组织的生物群落。

- 稳定性不再依赖单一组件的完美，而是依靠群体的冗余与协作。
- 控制不再靠严苛指令，而是靠意图的声明和动态调节。

我们学会不再扮演上帝去管控每一颗电子的跳动，而是学会引导一个充满不确定性的复杂系统：复杂系统的稳定，来自持续的适应而非完美的设计。

### 1.3.5 新世界的轮廓

在不确定性的土壤里，新的“物种大爆发”开始了。

如果说 GoF 的模式是为了在单机时代对抗变化，那么新一代模式就是为了在分布式时代拥抱变化。曾经的经典在云原生浪潮下显得力不从心：单例在集群里失去唯一性，观察者在异步网络中丢失实时性，繁琐的抽象工厂在微服务的碎片化调用面前显得笨重。

于是新的生存法则催生了新的模式。

- 从控制流程到响应变化：不再写严格的步骤序列，而是搭建数据管道。数据像水流一样通过，系统只对数据的到来做出反应。无论是 RxJava 还是现代流式计算，核心都是处理异步与背压，而不是控制顺序。
- 从共享状态到消息传递：共享内存锁不住，就别共享。Actor 模型与微服务把对象还原到最原始的定义——通过消息通信。组件之间形同陌路，只靠异步信箱交换信息，从而实现真正的隔离与解耦。
- 从修改变量到不可变数据：为应对并发混乱，工程借鉴了函数式的智慧。不再就地修改，而是每次生成新状态。类似区块链或 Git 的提交记录，历史不可篡改，也就消除了竞争条件带来的 Bug。

## 与故障共舞：断路器、舱壁隔离与重试

断路器、舱壁隔离、重试等模式不再预设系统完美，而是预设故障随时会到。它们像软件的安全气囊，正因承认脆弱，才换来反脆弱。

这些新模式共享同一个哲学内核：放弃上帝视角的全局控制，追求局部自治与适应。它们不试图消除不确定性，而是接纳它。

设计模式并未死亡，只是在进化：从 GoF 的 23 张建筑图纸，演变成云原生的生存指南。

## 小结 在十字路口的坚定

2016 年，AlphaGo 战胜李世石。

这不仅是 AI 的胜利，也是问题解决范式胜利的象征。AlphaGo 没有依赖预设套路，而是靠数百万局自弈涌现出人类难以理解的策略。

对软件工程的冲击巨大：如果围棋这样复杂的问题都无法靠“设计”解决，而要靠“学习”与“演化”，那么我们构建软件的方式是否也该彻底重构？

软件工程站在十字路口。

- 继续沿着 GoF 的路径，追求更精致的静态设计？
- 拥抱不确定性，探索动态演化的新形态？

旧范式在黄昏中退场，新力量正从代码缝隙中生长——函数式的纯粹、响应式的流动、分布式的共识。

从对象到智能体，从设计到演化，从确定到适应——软件工程的新纪元即将开启。

设计模式统治软件世界二十年，它将在新世界以何种形态重生？当我们不再写代码，而是去“指导”一个拥有自主意图的 Agent 时，还需要设计模式吗？

答案是肯定的。但我们需要的不再是代码的模具，而是思维的罗盘。

在真正的 Agent 降临前，必须先完成一场思想的武装。

在第 2 章，让我们开始这场范式的迁移。

# 第 2 章

## 从模式到意图：软件工程的范式迁移

在传统软件工程里，人们习惯用“模式”来降低复杂性。如今进入 Agent 时代，这一观念必须被重新审视：规则仍重要，但意图更关键。模式只回答怎么做，意图才回答为什么做。

随着系统规模扩张、环境不确定性上升、用户需求加速变化，固定的设计蓝图已显不足。Agent 的出现，让“意图”首次能够显式嵌入系统，使软件具备理解问题、推演状态并执行动态行动的能力。

本章将回顾过去数十年的核心范式，并说明 Agent 系统从模式驱动走向意图驱动的必然性。

## 2.1 函数与流：计算的原子化

GoF 黄金时代，我们试图用静态的类和对象固化世界，坚信封装得足够好就能控制状态。随着互联网爆发和摩尔定律边际效应递减，我们慢慢认识到：控制状态的最佳方式，或许是尽量减少状态本身。

这为 Agent 的诞生埋下伏笔——大语言模型本质上是一个庞大且无状态的纯函数。

### 2.1.1 无状态的复兴：从对象封装到纯函数管道

1977 年，John Backus 在图灵奖演讲中问：“Can Programming Be Liberated from the von Neumann Style?” 他批评命令式编程只是修改状态的一串指令，预言程序应是数学函数的组合，无状态、无副作用，只有纯粹变换。这是函数式编程发展史上的里程碑。

他指出，当时的语言如 Fortran、C 本质上是冯·诺依曼架构的附庸。CPU 与存储分离，性能受限于总线传输——即冯·诺依曼瓶颈。命令式语言把变量映射为存储单元、赋值映射为数据传输，思维被硬件物理限制束缚，不得不做“一次一个字”的操作，像独裁者向内存发号施令，副作用与状态追踪随之而来。

但 1977 年内存以 KB 计、主频以 MHz 计，“不改状态”听起来像奢侈的幻想。面向对象正崭露头角，C++ 即将诞生，谁会在意这个数学幻想呢？

随之而来的是“名词的王国”——OOP 统治软件世界。Java 与 C++ 告诉我们世界由对象构成，应把数据与行为封装在类这个黑盒里。三十年后，随着云计算与 AI 浪潮，这个封装神话出现裂痕。

#### 3. 终极映射：LLM 即纯函数

为何花篇幅介绍 FP？因为它是理解 AI Agent 本质的基础。

LLM 本质是一个巨大的无状态纯函数：输出 = f(权重，上下文)。

- 权重：推理阶段冻结，多次调用模型本身不变。
- 上下文：唯一变量。Agent 的“记忆”不在模型内部，而是每次以参数形式显式传入。

这一认知重塑 Agent 系统设计。

- 上下文工程成为核心：记忆必须显式构建在输入管道中。
- 幂等性得以实现：相同 Prompt 且随机种子固定时输出一致，为复杂 Agent 调试提供基础。

Backus 1977 年的愿景在 AI 时代意外实现。

如今构建 Agent，我们不再设计复杂对象层级，而是搭建数据处理管道：

输入 Prompt → 检索增强 → 思维链推理 → 格式化输出

工程由此跳出对象身份执念，回归数据变换本质。

### 2.1.2 响应式的觉醒：从阻塞等待到异步事件

传统编程的时间观是线性的：第 1 行执行完才执行第 2 行。这种同步阻塞模型符合人类阅读清单的习惯，但在高延迟时代会成为性能瓶颈，甚至引发系统性故障。

#### 1. 倒塌的多米诺：阻塞的代价

回想 2025 年 5 月 X 平台的崩溃：系统像被冻结，每个请求都在等待，每个线程都被阻塞，集体昏迷。

设想一个典型 Agent 任务：先调用 Google Search 约 1s，再解析结果约 0.5s，最后请求 LLM 生成摘要约 8.5s。

同步阻塞下每一步必须串行完成，会导致：

- CPU 空转：主线程 99% 时间在等进度条，无法做其它事。
- 系统失聪：这 10 秒内用户想取消或插入新指令，系统完全无响应，因被牢牢卡在 HTTP 请求上。

早期 Node.js 引入回调，却演变成回调地狱。层层嵌套的金字塔代码让逻辑破碎、难以维护。

#### 2. 响应式宣言：一切皆流

约 2010 年，Erik Meijer 等人提出响应式编程的核心隐喻：世界不是离散指令，而是连续的事件流。

- Excel 的隐喻：在 C1 输入 "=A1+B1"，A1 变化时 C1 自动更新，无需主动拉取，是被动响应。
- Observable：响应式编程的基本单元。数据不再是静态变量，而是一个随时间发出值的事件序列。

对 Agent 架构师而言，这是观念转变：不要“调用” LLM，而是“订阅” LLM。
