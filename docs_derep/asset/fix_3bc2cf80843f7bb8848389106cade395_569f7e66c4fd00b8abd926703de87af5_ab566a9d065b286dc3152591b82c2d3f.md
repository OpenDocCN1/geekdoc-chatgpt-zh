# 群体模式：让 Agent 自己接力编排

在多 Agent 的群体编排里，环境就是大家共享的公共介质，负责搬运信号与同步状态。OpenAI Swarm 中它体现为上下文变量；体系更复杂时，它常化作共享黑板、即时通讯群组或虚拟仿真世界。

群体架构主要依赖两类机制。

交接机制（Handoff Mechanism）：群体间的关键衔接点可类比神经突触。Agent A 完成任务后，能直接把执行权和上下文交给 Agent B，无需路由器或 Manager 审批。

局部规则（Local Rule）：写在 Agent System Prompt 里的硬编码行为准则，简洁明确，例如“若发现他人代码有 bug，直接修复，无需请示”。

这种设计大幅削弱系统耦合。新增一个 Agent，就像往池塘里再放一条鱼——中央调度不需改动，只需规定它与邻居的互动规则。

### 9.4.2 群体核心机制

群体模式看似杂乱，背后却有严谨的数学支撑。支撑其运转的三大支柱是留痕、动态交接与涌现，分别对应沟通、流程与能力的难题。

### 1. 留痕
“留痕”源自昆虫学 Stigmergy，由希腊语 Stigma“痕迹”与 Ergon“工作”组成，指个体通过改造共享环境来间接交流协作。比如你在维基页面改一行字，我看到后继续编辑，我们无需直接对话，页面本身就是介质。

Agent 之间不必建立直连。Agent A 可以把订单状态写进共享内存 Redis 或 Blackboard：`{"status": "approved"}`；Agent B 持续监听环境变化，一旦捕捉到该变更就自动触发打款。

工程本质是解耦：生产者不必知道消费者是谁在哪，只需把痕迹、状态或事件写进环境；消费者按自身职责对环境变化作出反应。

### 2. 动态交接
动态交接是 Swarm 的核心之一。

传统路由的流向是：Router 中央集权 → Agent。
Swarm 的流向是：Agent 去中心化 → Agent。

例如客服场景，客服 Agent 服务中发现问题涉及底层代码错误，不会上报 Manager，而是直接返回指令：`Transfer(target="TechAgent")`。执行流在毫秒级完成切换，并带走完整上下文，实现无缝衔接。该机制让响应极快，也大幅降低维护成本——谁更懂业务，就由谁决定交接给谁。

### 3. 涌现
涌现是系统论中迷人而神奇的现象，被视作系统论的“魔法”。

微观上，每个 Agent 看起来笨拙，只会执行简单的 if-else。比如检测到差评就生成道歉信。

宏观上，当成百上千个这样的 Agent 并行协作时，系统会展现出审慎的决策力和自我修复力。

可概括为：

> 涌现 = 简单局部规则 × 大量互动 × 开放环境

涌现无法被直接设计，只能被培育。需要好的初始条件与有效反馈，为涌现创造土壤。

留痕回答如何表达，动态交接回答如何传递，涌现决定能做到什么。三者结合，使群体模式成为应对高并发、高动态、高抗毁任务的理想选择。

学术界对群体智能与涌现最早且最具影响力的探索之一，是斯坦福大学“斯坦福小镇”项目中的生成式 Agent。该项目搭建了一个虚拟小镇，25 个 Agent 按局部规则自主生活——它们会传播信息、安排日程，却无人编写“举办情人节派对”的指令。正是这些简单交互，促成了一场自发的情人节派对，展现出典型的涌现。

这一成果成为社会模拟的里程碑，不仅验证了构建逼真游戏 NPC 的潜力，也为经济预测、组织行为学提供了新方法。

OpenAI 的 Swarm 2024 年发布，是轻量级无状态多 Agent 编排框架的代表。其核心理念是 Routines as Agents——Agent 不是“人”，而是一组指令与工具的集合。该设计显著降低开发门槛：开发者用普通 Python 函数即可定义复杂交互。

群体模式表明：复杂行为不依赖复杂控制逻辑。通过简单的任务交接与共享上下文，就能搭建出高度灵活、易扩展的系统。

### 9.4.4 群体模式的演化与组合
群体模式已从早期的“喧闹集市”演化为有序的“接力赛”。架构师不再追求全能的上帝节点，而是优化个体连接拓扑，强化基于既有模式的协作。

### 1. 演化路径：从喧嚣到有序
群聊：在 Camel 和 AutoGen GroupChat 早期版本中，所有 Agent 共处一个上下文窗口轮流发言。易产生“鸡尾酒会效应”，无关信息混杂，上下文迅速污染，Token 消耗指数增长，易偏题。

黑板：在 HuggingGPT 中，Agent 不直接对话，而是读写共享状态如 Shared State 或 JSON。实现模块解耦，数据流与控制流分离，适合复杂流水线任务。

交接：Swarm 采用去中心化控制权交接。Agent A 完成后直接把上下文和工具调用权限转给 Agent B，例如从分诊护士 Agent 移交至医生 Agent。该模式兼具黑板的有序性与群聊的灵活性，已成为轻量级多 Agent 系统的工业标准。

### 2. 模式组合示例
单独使用群体模式容易沦为乌合之众。借助反思模式与记忆模式可进行强化。

群体模式与路由模式的组合 = 智能网格：体现梅特卡夫定律，网络价值随节点连接数指数增长。借助 A2A 协议，原本孤立的点被编织成涌现集体智慧的网，适用于去中心化服务发现与动态临时组队。

流程如下。
去中心化路由：不再依赖中心路由器，每个 Swarm Agent 内嵌基于 A2A 的轻量级路由与服务发现。
广播与握手：Agent A 无法独立解决时，通过 A2A 向邻近 Agent 广播需求。
动态响应：邻近 Agent B、C 根据自身能力与需求匹配度主动握手，临时组建子团队协同应对。

群体模式与元学习模式的组合 = 达尔文进化：适用于大规模销售话术优化、广告投放策略生成。通过迭代评估与反馈实现优胜劣汰与自然选择，持续演化更高效策略。

流程如下。
初始化：创建 100 个同质销售 Agent，各自 System Prompt 略有差异模拟基因变异。
并发服务：在群体环境中并行为客户建议。
评估表现：用元学习评估器按转化率打分。
进化迭代：淘汰劣者，以优者的 Prompt 为基础引入突变，生成下一代。

群体模式与分层记忆模式的组合 = 蜂巢思维：适用于大型技术支持中心或代码开发群落。构建群体的集体潜意识，将个体经验沉淀为共享知识，避免重复犯错。

流程如下。
工作记忆与长期记忆分离：上下文窗口仅作短暂工作记忆处理即时信息。
共享长期存储：所有 Agent 共同访问全局长期存储如向量数据库保存群体长期知识。
经验沉淀：Agent A 解决疑难后通过记忆巩固写入共享长期记忆。
经验复用：Agent B 遇到类似问题时检索获取 Agent A 的经验。

演化揭示反直觉真理：放手控制不意味着秩序崩塌。涌现可以被工程化引导。注入元学习进化与分层记忆共享后，我们不是在写传统软件，而是在培育能自我组织、自我修复、生生不息的数字群落。这是软件工程最接近生物学的一刻。

### 9.4.5 设计哲学：失控的智慧
群体模式是对传统工程学的深刻背离。

传统工程追求精确控制，群体模式追求的不是失控，而是受控的失控。

我们不再事无巨细指挥每一步，而是设定规则、营造环境后退观望，让智慧在混沌中自发涌现。

这不仅是应对复杂问题的有效范式，或许更是通往通用人工智能的唯一路径——因为人类大脑本身就是一场没有指挥官的神经元风暴。

# 后记

## 熵的园丁：从软件工程到 Agent 工程的生物化演进

当我们审视本书所构建的 Agent 架构——从感知回路到记忆网络，从群体涌现到自我进化——便会意识到，我们所构建的已不再是一台机器，而是一个具有生命特征的系统。

### 1. 牛顿力学的黄昏，达尔文逻辑的黎明

传统的软件工程建立在牛顿力学的隐喻之上：世界如同一台精密的钟表，由齿轮（模块）严丝合缝地咬合而成——输入 A，必然输出 B。我们追求零熵（zero entropy），将一切不确定性视为 bug。

然而，在 Agent 时代，这一隐喻已然失效。

模型本质上是一台概率机器。当我们引入模型时，实际上是在系统中主动引入了熵（entropy）。当 Temperature>0 时，意味着我们允许系统有一定的“自由发挥空间”。正是这种“自由发挥”，赋予了 Agent 创造力与常识。

我们正从确定性工程转向概率性工程：不再追求如建造大教堂般严丝合缝的控制，而是致力于培育如热带雨林般生生不息、具备反脆弱性的系统。

### 2. 软件的生物化

回顾本书所探讨的各个 Agent 设计模式，我们不难发现它们在生物学中均有对应的体现。

- 感知模式（见第 4 章）：对应视觉与听觉的进化，从被动接收信息转向主动“觅食”式感知。

- 记忆模式（见第 5 章）：类比海马体与大脑皮质的协作，实现从短期工作记忆到长期记忆的固化。

- ReAct 模式（见第 7.1 节）：如同神经反射弧，在感知与行动之间构建快速闭环。

- 群体模式（见 9.4 节）：体现为蚁群与椋鸟群的社会性行为，通过局部个体间的简单交互，涌现出集体智慧。
