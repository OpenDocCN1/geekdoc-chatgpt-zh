## 5.4 容错与恢复：打造更稳健的多智能体

### 【学习目标】
1) 识别大模型幻觉的典型表现及判断方法
2) 理解多智能体互验的工程实现思路
3) 学会在智能体体系中应用熔断机制
4) 设计合理的人机协同介入流程

容错与恢复是保障多智能体协同稳定运转的底线能力，从捕捉幻觉、隔离故障到引入人工，形成层层可靠性防护。

### 5.4.1 幻觉检测与纠正：避免模型“造假”

以大模型驱动的智能体存在独特风险：AI 幻觉。与传统软件的确定性错误不同，幻觉是表面合理但实质错误的产出。研究表明，即便是顶尖模型在特定情境下也会出现幻觉。多智能体系统必须构建系统化的检纠能力，把影响控制在可接受范围。

幻觉成因多样：训练语料的噪声与偏见、模型结构固有限制、解码随机性，以及训练目标对自信输出的隐性激励。最新研究把幻觉重新定义为激励问题——模型被训练去给出确定答案而非表达不确定。把握这一本质有助于设计更有效的检测策略。

检测手段大致可分四类：基于外部知识的校验借助 RAG 将输出与可信知识源对照；基于自洽性让模型多次作答并用语义熵评估稳定性；基于内部表征分析隐藏层状态判断生成过程的不确定性；基于多智能体互验则让多个智能体相互审查以发现潜在错误。

图5-11展示了多层检测流程。智能体输出先进入四层机制：知识库校验用 RAG 与可信源比对；自洽性检查用语义熵评估多次结果的稳定度；多智能体互验通过辩论与投票实现互审；置信度评估融合前三层结果给出最终分数。置信度达到85%阈值时带标签直接返回；未达标则进入纠正流程，包含重生成与人工复核。虚线箭头表示纠正后内容会重新进入验证。

多智能体互验是有效手段。核心逻辑是：具备不同知识背景或推理路径的多个智能体若对同一问题达成一致，可信度较高；若出现明显分歧，则需进一步审查。代码5-5展示了实现方式。

### 5.4.2 智能体失效的检测与自动恢复
多智能体环境下，单点失效属常态。原因包括大模型 API 超时、上下文窗口溢出、Prompt 注入或陷入无限循环。系统需建立健康监测，及时发现失效并触发自动恢复，保证整体可用。

健康监测覆盖多个向度：可用性探测通过心跳判断响应能力；质量探测评估输出是否符合格式与语义规范；性能探测监控响应时长与资源占用；行为一致性探测验证行为是否符合角色定义。综合结果可准确判断运行状态。

### 5.4.2 智能体健康检查与恢复机制
自动恢复遵循渐进原则：先尝试重试，采用指数退避避免对过载服务造成更大压力；重试失败则切换至备份智能体或进入降级模式；最后手段是隔离故障节点并触发人工介入。恢复过程需保持任务上下文完整，确保接替智能体能从断点继续。

### 5.4.3 级联错误的预防与隔离
智能体间存在复杂依赖，一个节点故障可能导致依赖方等待或接收错误数据而连锁失效，形成级联故障。断路器模式是有效预防手段。

断路器借鉴电气概念：检测到异常时主动“断开”以免更大损害。软件中，断路器监控调用，当失败率超阈值自动转“打开”状态，后续调用直接失败或返回降级响应，而非继续尝试故障服务，从而释放资源并给予恢复时间。

断路器有三种状态：关闭时正常转发并监控失败率；打开时直接拒绝或降级；半开时放少量探测请求判断是否恢复。状态转换由失败阈值与超时时间控制。多智能体系统中每个调用路径都应配备独立断路器，实现精细隔离。

图5-13展示了工作机制。调用方智能体经断路器访问被调智能体。关闭状态下正常转发并统计失败；失败率超阈值如50%则切至打开，请求被导向降级响应；超时后进入半开，放探测请求，成功则恢复关闭，失败则重新打开。参数面板列出失败阈值、采样窗口、打开超时与半开探测次数。断路器可带来隔离收益：避免单点故障引发雪崩，快速失败防止长时间阻塞，及时释放资源避免耗尽，支持自动恢复检测，并在主服务不可用时提供降级保障。
