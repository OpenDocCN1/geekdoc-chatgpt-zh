## TPU v3 核心速览

- 相比 TPU v2，TPU v3 在时钟、内存带宽和算力上全面拉升，并改用液冷来提升能效。
- 在体积仅放大约 10% 的前提下，MXU 数量翻倍，芯片间带宽和互联节点数也同步提升。
- TPU Pod 由多颗 TPU 通过专用网络拼成超算集群，强化互联让大规模数据处理更顺畅，神经网络训练尤其受益。
- TPU v3 Pod 选用 2D Torus 网络，降低了通信延时与带宽瓶颈，同步训练效率更好，便于组建大规模集群并支撑预训练。

## 5.5 TPU v4 与光路交换技术

TPU v4 距离 TPU v3 间隔了四年，期间谷歌在研究层面成果不断，但芯片产品线保持沉默，研发重心转向面向消费者的 Tensor、Pixel 系列等处理单元。同期英伟达已迭代 Volta、Ampere、Hopper 三代架构，PyTorch 也取代 TensorFlow 成为主流训练框架，业界对超大规模算力的需求进一步抬高。TPU v4 正是在此背景下推出，以应对新的挑战。

### 5.5.1 TPU v4 概览

TPU v4 采用 7 nm 制程，MXU 再翻倍，内存容量与带宽显著拉高，整体性能大幅跃升。最受关注的是 Sparse Core 的加入，专门加速稀疏计算，让 Embedding 层处理更高效。此外 TPU v4 首度引入 3D Torus 互联，构建 TPU v4 Pod，体现了谷歌在超大规模并行与高效互联上的突破。Palomar 光路开关芯片基于 MEMS 技术，进一步压低系统时延与功耗，也降低了网络成本。以下展开说明。

#### 1. TPU v4 架构图

每颗 TPU v4 集成 2 个 Tensor Core，每个 Tensor Core 由 6 个单元构成，4 个为 TPU 的核心脉动阵列 MXU，另外 2 个为 1 个标量单元和 1 个向量单元。2 块 HBM 内存分别置于 Tensor Core 的左右两侧，用来缩短走线带来的时延。

#### 2. TPU v4 产品形态

相较往代，v4 的形态变化很大。

[PRE1]
- 制程：从上一代的 16 nm 升级到 7 nm。
- 硬件增量：MXU 数目较 TPU v3 再翻倍；片上内存增至 244 MB，涨幅约 9 倍，HBM 容量仍为 32 GB，但内存带宽达到 1.2 TB/s，比前代提升约 33%。
- 稀疏计算核：新增 Sparse Core 支持，利好稀疏场景。
- 3D Torus：首次采用 3D Torus 互联，紧密耦合 4096 个 TPU v4 引擎，Pod 级别可提供 1.126 exaFLOPS 的 BF16 峰值算力。

随后将详细讲解 Sparse Core 与 3D Torus。

### 5.5.2 Sparse Core

#### 1. Embedding 层的计算

Embedding 用来处理离散型分类特征，是典型稀疏计算范式，NLP 与搜推类算法输入多为字符串形式的稀疏向量。这些特征不适合直接落到矩阵乘法单元做 Tensor 计算，本质更接近哈希表。待处理输入矩阵中零元素极多，传统矩阵方式会反复做大量无效的零乘法，浪费算力。

把稀疏变量放到 Tensor Core 上计算，还会产生大量小规模内存访问，容易触及 CPU 与 DRAM 瓶颈，尤其在 TPU 与 CPU 比例为 4:1 的集群中，网络中心的延时也会放大负面影响。因此 TPU 上引入了高效稀疏向量计算范式。

深度网络在稠密 Tensor 上表现更好，需要通过 Embedding 层对稀疏矩阵做信息压缩，生成稠密表达，这通常是 NLP 或搜推模型的第一层。

图 5.5.2 为搜推场景经典的 Wide&Deep 框架。Wide 部分可为任意广义线性模型，Deep 部分是基于 Embedding 的全连接网络。图中用户稀疏特征先转为稠密 Embedding，再进入隐藏层，与 Wide 部分协同输出最终结果。

[PRE2]

TPU v4 的 Sparse Core 原生支持 Embedding 的模型并行与数据并行，提供很高的并行灵活性，让大规模 Embedding 计算在超大集群中得到妥善调度。

#### 2. Sparse Core 架构

图 5.5.3 为 Sparse Core 架构示意，深蓝色方块为最通用的 16 个计算瓦片。每个瓦片挂载一条 HBM 通道并支持多路内存访问，内部包含读取单元 Fetch Unit、可编程 8 路 SIMD 向量处理单元 scVPU 和 Flush Unit。Fetch Unit 从 HBM 把激活值与参数读入瓦片 2.5 MB 的稀疏向量内存 Spmem 切片。反向传播时 Flush Unit 把更新后的参数写回 HBM。此外 5 个跨通道单元以黄色方块示意，在 16 个 Spmem 上执行对应名称的嵌入操作。与 TPU v1 类似，这些单元执行类 CISC 指令，支持可变长输入，单条指令耗时取决于数据。

### 5.5.3 TPU v4 Pod

TPU v4 Pod 具备强大的芯片间互联，可提供 exaFLOPS 级算力。谷歌把 64 颗 TPU v4，4×4×4 组成立方体 Cube；再用光互联把 4×4×4 个 Cube 连接，形成 4096 颗 TPU v4 的超算。

#### 1. 光互联

在如此规模的 Pod 中，互联效率决定整体性能。若带宽不足，芯片会长时间空闲等待数据。光互联适合长距离连接。光交换器 OCS 实现 64 颗 TPU 构成的 Slice 间互联，完成 Pod 内部 4096 颗 TPU 的全光互联，也可用于 Pod 间互联。

使用可配置光互联与光路开关时，在芯片可靠性 99% 的假设下，系统平均性能可提升约 6 倍，凸显光互联开关的重要性。

#### 2. 拓扑结构

TPU v4 Pod 采用 3D Torus 拓扑，每个节点在三个维度上与相邻节点相连，形成三维网格。这种高密度互联让芯片在 X-Y-Z 上形成连续环路，提供高带宽低时延，适配高性能计算与大规模并行。TPU v4 可紧密耦合 4096 引擎，合计 1.126 exaFLOPS BF16 算力。每端口对应一颗芯片，端口连接交换机提供 6 TB/s 带宽，作为网卡与 3D 环面网络的基础，保证大规模并行任务的高效稳定。

图 5.5.4 为 3D Torus Cube 示意。每个节点与上下左右前后 6 个邻居相连，位于立方体边缘的芯片与相对面节点相连，实现每节点 6 连。

Cube 的展开见图 5.5.5。为实现 6 面连接，每面需 16 条链路，每个 Cube 共 96 条光链路接入 OCS。为提供完整 3D Torus 连接，相对侧面需接入同一 OCS。因此每个 Cube 接入 48 个 OCS，48 个 OCS 共连接来自 64 个 Cube 的 48 对光缆，并联 4096 颗 TPU v4。搭建一个 TPU v4 集群需 4096 颗芯片与 48 个 OCS 光互联交换器，成本很高。

### 5.5.4 光路交换机

#### 1. 光路开关芯片

多开关芯片的光路方案称为 Palomar，采用基于 MEMS 反射镜阵列技术，通过控制二维 MEMS 反射镜的位置调整光路实现切换。MEMS 光路开关具有低损耗、低切换时延毫秒级、低功耗、低成本等特点。

### 5.5.5 TPU v4 优缺点分析

TPU v4 Pod 在成本、功耗、速度上具优势，3D Torus 带来低时延与低网络成本，但也面临系统成熟度、拓扑刚性与负载均衡等挑战。未来设计更强调算法与芯片协同，以及新数据格式与稀疏计算支持，反映 AI 集群的重要性提升。

#### 1. 优点

- 低时延：相邻节点距离短且直连，密集 I/O 与紧耦合并行任务更顺畅。
- 低网络成本：同等节点数下 3D Torus 网络直径小于 Clos 拓扑，交换机、线材、连接器用量更少，网络层级更少，硬件成本更低。
- 路由可重配：OCS 网络支持动态可重配，Slice 集群部署后即可投入生产，无需全网收敛，也便于隔离或下线故障节点。
- 更好集群布局：物理邻近节点在逻辑上保持邻近，密集 I/O 与数据流局限在局部域，降低通信开销并优化时延与功耗。3D Torus 可把大集群切分为紧耦合局部域，局部互联共享作业。

#### 2. 缺点

- 系统成熟度偏低：Clos 拓扑具备非阻塞特性，性能稳定可预测，全时全带宽无冲突，而 3D Torus 无法保证。
- 拓扑僵硬：Clos 的脊叶结构扩容叶交换机相对简单，3D Torus 扩缩容较复杂耗时，可能需重配整体拓扑。
- 负载均衡：Clos 任意两节点间路径更多，实现负载均衡与冗余更充分。3D Torus 亦有多路径，但备选路径数量通常少于 Clos，取决于具体配置。

## TPU v4 核心总结

- TPU v4 通过 7 nm 工艺、Sparse Core 与 3D Torus 互联实现性能跃升，并高效处理稀疏计算；3D Torus 与 Palomar 光路开关展示了大规模并行与高效互联的突破。
- 架构优化尤其体现在稀疏计算支持上，大规模 Embedding 处理更高效。Sparse Core 为超大集群提供极高并行灵活性，3D Torus 与光互联有效降低时延与功耗、减少网络成本，提升整体效率。
- TPU v4 在降本降耗上占优，但系统成熟度与负载均衡仍是挑战，需持续创新保持竞争力。
