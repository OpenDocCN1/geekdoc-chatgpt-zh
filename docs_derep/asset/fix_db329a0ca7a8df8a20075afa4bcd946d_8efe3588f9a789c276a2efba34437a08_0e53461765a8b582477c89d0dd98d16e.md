# 双线锻造：代码与对齐如何塑造 ChatGPT

第一条线索围绕代码能力与推理能力的强化展开。OpenAI 把 GPT-3 与代码训练融合，诞生了 Codex。2021年7月 Codex 首个版本对外发布，其建模基础是对 GPT-3 初始版用 159GB Python 代码进行精调。后续演进在 OpenAI API 中以 Codex-cushman-001 出现，代码生成与逻辑推断尤为出色。纯文本任务相对薄弱，但借助大量数学解题代码的学习，推理水平得到明显提升。

第二条线索关注对人类意图的贴合。人类反馈强化学习的构想最早由 Google 在 2017 年提出，当时用人工标注做反馈信号，提升强化学习在模拟机器人与雅达利游戏上的表现。

为了让模型更贴近人类意图，OpenAI 用 RLHF 对 GPT-3 做精调，得到 InstructGPT。GPT-3 在 2020 年就已尝试结合 RLHF，早期产物容易产出不当或危险内容。直到 2022 年 3 月，OpenAI 才在 InstructGPT 论文中系统阐述 RLHF 的有效用法，当时对外提供的主要接口是 Instruct-davinci-beta 与 Text-davinci-001。

两条探索最终汇聚于 Code-davinci-002。Codex 看起来是代码专精产物，但 Code-davinci-002 很可能是当前最强的 GPT-3.5 自然语言变体，强于 Text-davinci-002 与 Text-davinci-003。其优势在于很可能同时以文本和代码作为训练目标，并完成了指令对齐。

2022 年 5 月发布的 Text-davinci-002，是在 Code-davinci-002 基础上做有监督指令精调得到的产物。这类精调往往削弱上下文学习，却增强了零样本学习。2022 年 11 月推出的 Text-davinci-003 与 ChatGPT 即 gpt-3.5-turbo，是两种基于人机反馈强化学习的精调分支。Text-davinci-003 在一定程度上补回了 Text-davinci-002 中被削弱的上下文学习能力，可能源于精调时加入了语言建模，同时在意图理解、逻辑推断与因果分析等方面进一步提升，得益于 RLHF。

ChatGPT 是一种面向对话交互的语言模型，运行方式与此前的 GPT-3 有别。旧模型接收提示字符串后返回追加补全，而 ChatGPT 基于对话式输入与消息式输出，接收类聊天脚本的提示，返回模型在对话中发布的消息补全。

总体来看，ChatGPT 与 InstructGPT 的训练思路差异不大。ChatGPT 对人类意图的把握，可归因于 RLHF，以及预训练语料中大量数学解题代码和代码注释的学习。这些因素共同推动了其在自然语言处理与代码生成任务上的显著成绩。两者在训练集构成上存在细微差别，但核心方法基本一致，下面以 InstructGPT 为例说明其人机反馈强化学习的训练与评估流程。

## **8.2 InstructGPT 训练数据集**

InstructGPT 的训练包含三个环节：有监督精调、奖励建模、强化学习，对应三类数据：SFT 集合、RM 集合、RL 集合。有监督精调阶段需要人工为提示撰写答案，对人力依赖高、标注要求高。奖励建模阶段是对模型生成的 4~9 个输出进行排序，对标注者要求相对宽松，但仍需掌握统一的评判标准以避免偏差。

### **8.2.1 微调数据集的来源**

精调数据主要来自两类来源：

1）OpenAI API 提交的提示。主要来自 OpenAI Playground。用户切换到 InstructGPT 模型时系统会提示数据可能用于新版本训练。出于隐私与合规考量，正式产品 API 数据未被采用。对已获取的数据，剔除长前缀重复提示，并将单个用户提示条数限制在 200 条以内以保证多样性。数据按用户 ID 分割，确保验证集与测试集不含训练集用户提示，同时过滤掉含个人身份信息的提示。

2）标注人员撰写的提示。标注人员撰写的提示主要包括三种形态。

❑简单任务：给出任意简单任务并保持多样性。

❑少样本：在提示后撰写多组 query、response 对。例如提示“对这条微博进行情绪分析”，query 为一条真实微博，response 为“积极”或“消极”。写出 K 条时，前 K-1 条作为上下文。

❑用户数据：从 OpenAI API 获取用例后由标注人员重写提示，因原用例不够规范需要整理。

### **8.2.2 标注标准**

（1）标注员的选拔标准

选拔关注两点：

1）对敏感内容的判断一致性。团队构建了含提示与完成的敏感内容集，若提示或完成中出现色情、政治、暴力等即视为敏感。随后让标注员判断是否敏感，计算与研究团队的一致性。

2）对模型输出质量的评估一致性。先用 API 生成提示并让不同模型输出，要求标注员排序，再衡量其排序与研究人员的吻合度。

标注员主要职责为：

1）编写提示。
2）回答提示。
3）对同一提示下不同模型的输出进行排序。
4）在评估阶段，将含粗俗、色情暴力等有毒提示输入经 PPO 训练的 InstructGPT，评估其输出的毒性与流畅性。

任务 3）和 4）要求标注员对质量与毒性做出判断，为工作提供明确指引。

（2）输出内容的质量标准

执行任务 3）时，高质量输出应满足有用性、真实性、无害性。多数情况下真实性与无害性优先于有用性。但若输出 a 相比 b 在有用性上优势明显，且 a 的有害性与不真实性并未过度严重，且不涉及法律、医疗等高风险领域，则可认为 a 质量更高。基础排序原则是：若向机器提问，预期得到哪个输出。

执行任务 4）时，采用毒性与流畅性两个维度。毒性指输出是否包含粗俗、不尊重或色情暴力内容，分绝对毒性与相对毒性。相对毒性指与提示毒性相比，模型输出毒性是增加、减少还是保持不变。流畅性指文本连贯性及在网络环境中的自然度。

排序任务的展示方式是先让标注者按标准对每个输出独立评分，再汇总展示全部输出进行排序，避免一次性呈现导致准确率下降。

论文 Fundamentals of Generative Large Language Models and Perspectives in Cyber-Defense 的附录 A 对数据分布有更详细讨论。挑选出的关键影响因素如下：

1）数据中超过 96% 为英文，其余不足 4% 为其他 20 种语言如中文、法语、西班牙语等。这意味着模型虽能处理多种语言输入，但非英文效果较弱。

## **8.3 人类反馈强化学习的训练阶段**

采用基于人类反馈的有监督学习与强化学习微调策略，使语言模型更贴合用户意图。这不仅放大了模型规模，也提升了遵循意图的能力。InstructGPT 的人机反馈微调过程见图 8.2，可划分为三个阶段：有监督精调、奖励建模、强化学习。由于 InstructGPT 与 ChatGPT 训练步骤高度相似，下文以 InstructGPT 为例。

### **8.3.1 有监督微调阶段**

有监督精调使用前述 SFT 集合对预训练 GPT-3 进行微调，得到 SFT 模型作为基线，如图 8.3 所示。基线模型参数规模为 1750 亿。微调方法近似 GPT-1 时的做法，采用余弦学习率衰减，进行 16 个训练周期，并设残差丢弃率 0.2 以防止过拟合。

训练样本仅 13k，GPT-3 可能过拟合。但该模型并不直接上线，而是作为后续训练的初始化基线，过拟合仍可为后续优化提供帮助。

仅靠精调能否对齐人类需求？显然存在难点。对所有问题人工写答案成本高昂，需要深入理解、大量时间、知识与技能来提供多样高质量答案。因此实际应用中常需结合强化学习等微调策略才能更好地对齐需求。

### **8.3.2 奖励建模阶段**

由于人类无法为所有问题编写答案，训练奖励模型来理解人类偏好是必要的。该模型基于提示与答案输出标量奖励值。

将 API 与人工编写的提示输入 SFT 模型生成答案，如图 8.4 所示。通过概率采样获得多个答案，再由标注人员排序。排序完成后训练奖励模型：取 SFT 模型去掉最后非嵌入层，在 softmax 层后加线性层，将输出序列映射为标量。输入提示与响应，输出分数，完成训练后可对生成答案打分。

值得注意的是，InstructGPT 选择了相对较小的 60 亿参数 GPT-3 微调 SFT 模型来训练奖励模型，而非最大的 1750 亿参数模型。因为大模型训练不稳定，小模型可节省算力。

### **8.3.3 强化学习阶段**

在奖励建模基础上，利用 PPO 算法，以 RM 输出作为标量奖励对有监督策略进行微调。

继续微调 SFT 模型，将不带人工标注的问题如“撰写一篇春游日记”等 31k 个 API 提示输入 SFT 模型，如图 8.5 所示。此时不再依赖人工评估，而是让第二阶段训练好的奖励模型为输出评分。将 SFT 模型视为 PPO 策略网络，优化参数以提升生成答案的分数。再次生成、再评估、再优化，直至策略收敛。

在人机反馈强化学习的三个步骤中，奖励模型训练与 PPO 微调可迭代进行，收集当前最佳策略的更多比较数据，用以训练新的奖励模型与策略。但迭代会带来数据分布变化问题。强化学习中模型更新导致分布漂移，与传统统计学习不同，模型需不断适应新分布。

为何不直接用标注数据训练排序模型而要额外训练？因为只有排序信息而无具体输出 y。若能直接标注 y，则回到有监督范畴。强化学习中通常没有此类标注，需通过排序模型学习环境反馈以适应变化分布。

在线学习方法中模型持续更新并实时交互，需要人工持续为模型回复排序，效率受限，因模型训练速度与人工标注速度难以同步。

因此选用训练排序模型 R 代替人类进行排序，提供实时反馈。这就是需要两个模型的原因，目标是让强化学习模型生成更高排序的回复，提升生成质量。

## **8.4 奖励建模算法**

### **8.4.1 算法思想**

奖励建模的核心是通过人工排序信息转化为可优化的奖励分数，并据此调整 GPT-3 参数。InstructGPT 采用一种创新的奖励建模算法，如图 8.6 所示，可为每个输入输出配对生成奖励分数，体现标注者偏好。

为处理排序标注数据，引入成对排序损失。对每个提示，从生成的答案中各取一对 Y[w] 与 Y[l]，其中 Y[w] 排名高于 Y[l]。将 X 与 Y[w] 输入奖励模型计算分数，再将 X 与 Y[l] 输入计算分数。期望 Y[w] 的分数更高，计算两者分数差并通过对数损失转为标量值。
