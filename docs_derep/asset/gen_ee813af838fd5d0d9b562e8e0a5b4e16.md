##### 2. Map-Rerank 链的典型用途与适配的文档形态

Map-Rerank 链是在 Map-Reduce 基础上衍生的增强方案，除了对片段做处理并汇总，还会对每一份中间结果打分排序，以此提升输出的相关度与准确性。这类链特别适合需要从众多候选中挑选最优解的任务。

应用场景：
- （1）针对超长文档的问答，挑出最合适的答案。
- （2）从多个片段中抽取出最相关的信息。
- （3）进行内容过滤并产出高质量结果。

适用文档类型：
- （1）片段众多且需要按评分筛选的文档集合。
- （2）来自不同来源的材料，需要择优出答案的情境。
- （3）需要在海量信息中提炼优质内容的情境。

| 链类型 | 特点 | 适用场景 |

| :--- | :--- | :--- |

| LLM 链 | 直接调用语言模型，通过提示词模板和参数设置优化生成效果 | 基础生成任务，适用于单一内容生成 |

| 序列链 | 多步骤任务链，按顺序调用每个步骤，逐层生成内容 | 多层次生成需求，如内容预处理和逐步扩展 |

| 路由链 | 基于条件判断选择不同的任务路径，实现动态内容生成 | 多分支流程，如客服问题分类、内容筛选 |

| Stuff 链 | 将所有文档片段合并后一次性处理，简单高效，但受限于上下文长度 | 小型文档快速处理，适合内容简洁、信息量少 |

| Refine 链 | 逐步精炼文档片段，将每一步的输出传递给下一个文档片段，构建完整内容 | 大型文档精炼、层次分明的内容生成 |

| Map-Reduce 链 | 将文档片段独立处理（Map）后归并（Reduce），适合大规模内容分步处理 | 长文档问答、多个文档片段的总结和分析 |

| Map-Rerank 链 | 在 Map-Reduce 链基础上增加评分和排序步骤，筛选最优内容 | 多片段内容筛选，如长文档问答、最相关内容提取 |

### 5.5 本章小结

本章梳理了 LangChain 中各类链技术及其使用场景。LLM 链负责基础生成，依赖提示词模板与参数调优；序列链把多步任务按序串联，实现分层生成；路由链借助条件判断动态切换路径，适配多分支流程。

文档类链方面，Stuff 链适合小文档合并一次性处理，Refine 链通过逐步精炼累积完整内容，Map-Reduce 链实现分块处理再汇总，Map-Rerank 链在汇总前加入评分筛选。借助这些链技术，可以灵活应对不同内容生成与文档处理的诉求，为企业级应用提供稳健的架构支撑。

## 核心组件 2：内存模块

在搭建智能对话系统时，内存模块是 LangChain 的核心构成之一。它让模型能够保留先前的对话记录，从而实现上下文理解与多轮交互。通过引入内存，模型不仅能处理当前请求，还能在对话过程中动态调整生成策略，提升连贯性和逻辑性，这对智能客服、个性化助手等复杂场景尤为关键。

本章将深入解析内存模块的核心能力与实现方式，涵盖聊天消息记忆、会话缓冲区与会话缓冲窗口、会话摘要与向量存储，以及基于 Postgres 和 Redis 的持久化存储等内容。

掌握本章后，读者能够利用内存模块有效管理聊天记录，提升对话系统的响应力与记忆力，为企业级智能对话应用奠定基础。
