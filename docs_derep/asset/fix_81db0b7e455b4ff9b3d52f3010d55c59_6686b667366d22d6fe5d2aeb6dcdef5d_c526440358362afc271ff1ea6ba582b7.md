更常见的问题并非用户给 AI 的信息太多，而是表达不清晰、信息不完整。冗余的前提是必要信息已经具备，再额外出现多余内容。现实里大量情况是信息缺口，所以更实用的做法是“最小必要信息量”：只提供完成任务刚好足够的素材。

将这一思路与苏格拉底式辩证法 ^(²²) 结合，就能提炼出与大模型交流的一套原生方法，下面暂称“与 AI 对话的原生方法”。

[PRE0][PRE1]

▲[2]  这种载体可以是词句、段落、图表、文档等任何形式，只要满足最小必要信息量的要求即可。

[PRE2][PRE3][PRE4]

▲[3]  思维链 COT 实际上也是这种方法的具体应用。

[PRE5][PRE6][PRE7][PRE8][PRE9]

根据实践经验，对这套原生方法的常用手段做了使用频率与普适性的排序 ^(²³)：角色设定 > 使用“黑话” ^(²⁴) > 提供背景 > 拆分问题、分步交流 ^(²⁵) > 多轮往复 > 提供范例 > 结构化表达。

排序仅供参考，一次提示或一次交流里可以多项叠加。不同场景需要不同组合，关键是依据每种手段的说明动态迭代，结合模型实际返回灵活调整，甚至创造新用法。

若任务单一且简单，未必需要额外定义人设。以 ChatGPT 为代表的以对话为交互的预训练大语言模型本身就带有系统人设，所以多数情况下，先用行话给出精炼充分的背景信息，优先级更高。

# **实战篇章**

## **第三章**

## **把 AI 变成你的专属智囊团**

**用对话牵引模型，组建一支为你排难解忧的智囊团队。** ^(²⁶) 我们形象地称之为“召唤术”。

你就是这支专业团队的甲方。甲方与乙方的关系类似剧院里导演与演员——甲方主导，像导演在幕后搭台定戏，提供方向与资源；乙方配合，像演员按愿景演绎细节。

需要反复强调：在使用、协作的过程中，你始终是主导方。 ^(²⁷) 提示的质量决定模型的表现。

### **做合格甲方，先说清要什么、缺什么**

本质上模型是在“续写”你的提示。把问题讲清楚，答案自然浮现。习惯可视化思路后，后续就是顺势而为。

不要对模型说：

“我要一个大而全的系统，具体多大、怎么全你来想。”

“这个设计差不多了，感觉还缺点什么，我说不清。”

“要五彩斑斓的黑。”

“大气一点。”

“要一个离线也能实时同步数据的在线系统。”

“要一个能自动解决所有客户问题且零维护的 AI。”

……

如何简洁说清问题？借用认知心理学的一个小模型，只有三要素。

**（1）给定：** 问题已知的条件，也就是起点。

**（2）目标：** 问题期望得到的结论或状态。

**（3）障碍：** 解决路径不显然，需要思维活动才能达成。

看几个示范。

**▼ 示例 1：交付工作项目**

新人说法：给我写一个客户关系管理系统。

更好说法

・**给定：** 我负责搭建新的客户关系管理系统，手上有现有客户资料、团队成员和基础 IT 设施。

・**目标：** 交付一个易用、功能齐全、无 Bug 的客户关系管理系统。

・**障碍：** 团队对技术栈不熟，需求在开发中可能变动，开发时会出现未预见的技术问题。

**▼ 示例 2：习得新技能**

新人说法：三个月内掌握 Rust 编程。

更好说法

・**给定：** 我决定学 Rust，已有编程基础，会 Java、Python，对 Rust 零了解。

・**目标：** 三个月内能熟练使用 Rust 编程。

・**障碍：** 难找到合适资源，可能卡在理解难点，需要投入大量时间精力。

**▼ 示例 3：减重**

新人说法：三个月瘦 10 千克。

更好说法

・**给定：** 体重超标，对健康与营养有基础认知。

・**目标：** 三个月内减掉 10 千克。

・**障碍：** 要克服懒惰和不良饮食，需合理规划饮食运动，可能遇到平台期和动力不足。

**▼ 示例 4：烹饪菜品**

新人说法：给我设计 6 道菜。

更好说法

・**给定：** 周末朋友聚餐，有食材和基础烹饪工具。

・**目标：** 成功做出 6 道聚会菜品。

・**障碍：** 可能缺少特定厨具或调料，需用常见家用炊具完成。

**▼ 示例 5：排解程序报错**

新人说法：代码编译提示 Syntax error on token "else", delete this token，怎么改？

更好说法

・**给定：** 我在学 Java，用 Eclipse IDE，运行一段代码失败并出现编译错误。

・**目标：** 理解错误原因并学会修改，希望得到清晰指导和示例代码。

・**障碍：** 编译时报错提示 else 标记语法错误，建议删除该标记。

模型很直观，按给定、目标、障碍描述当前问题，多加练习，下次与模型交流会更简洁准确。

## **第四章**

## **召唤术一：拟人化塑造**

### **赋予模型人设，打造专家级伙伴**

生成式模型会根据你提供的文本生成回应，设定人设让它像领域专家一样作答，能显著提升输出质量，也能快速上手。

按原生方法和实践细节，我们可以做一个角色模板，快速搭建一个助手。学会之后，你只要知道角色名、行业术语、工作内容、方法与流程，就能定义任意模型助手。

更进一步，你不必照搬真实角色，可以混合不同角色，只要把能力、工作方式、风格、背景讲清楚即可。重点不在模型本身，而在你想引导出怎样的角色。由此还能创造现实中不存在的、集多技能于一身的虚拟角色。

书写上常用 Markdown 纯文本，这是编程界通用的轻量标记语言。你只需知道 “#”“##”“###” 分别代表一到三级标题即可。Markdown 允许用简单文本快速做出格式化文档。

不懂 Markdown 也可以用任意标记或大纲格式，只要会用 Word 写大纲就行，后文会给出示例。

模板含说明文字和占位符，占位符常用方括号，方括号里的词需按实际情况填充。

Markdown 格式要点：

标题用井号开头，数量代表层级，井号后空一格再写标题：

# 一级标题

## 二级标题

### 三级标题

有序列表用数字加点开头：

1. 条目一

2. 条目二

无序列表用短横线开头：

- 条目一

- 条目二

这些标记已足够，自学可扩展完整语法。

大纲格式要点：

在 Word 这类编辑器里常见写法：

1. 一级标题

1.1 二级标题

1.1.1 三级标题

1.1.2 另一三级标题

1.2 另一二级标题

2. 另一一级标题

或：

一、 一级标题

1.1 二级标题

这种结构化写法本质是帮助你表达逻辑，引导模型生成更好回应，用哪种形式都可以。若真正做到最小必要信息量，结构化与否的重要性会下降。

下面以 Markdown 和文本大纲各给一个结构化提示模板，方括号内容为待填写项。

可按需拟人化补充“输入”“输出”“示例”“语气”“性格”“理念”“价值观”“原则”“禁止条款”等。 ^(³⁴) 为发挥创造性，约束宜少，少即是多，从少到多容易，从多到少困难。

角色定义完后说一句“请你扮演该角色”即可开始对话。可采用结构化提示，也可用一段话清晰表达三要素。结构化模板如下：

## Problem

[问题名称，简要描述]

### Given

[给定：已知条件，即起点]

### Goal

[目标：期望结论或状态]

### Obstacle

[障碍：解决过程中可能遇到的难点]

例如：

## Problem

写一篇量子力学的演讲大纲。

### Given

开学时我要给大一新生做量子力学讲座。

### Goal

请列出符合他们认知水平的讲课大纲，要生动、有趣、严谨。

### Obstacle

时间紧，我习惯做科研，不擅长写演讲稿。

自然文本叙述同样可行：

开学时我要给大一新生做量子力学讲座，请帮我列出符合他们认知水平的讲课大纲，要生动、有趣、严谨。

两种写法模型的回应会有差异。**需要更强创造性时，提示词宜少用结构化，改用自然文本描述，再视情况调整。**

### **技巧一：结构化提示快速召唤**

初学者可用上述结构化方式写作提示词，直接召唤专家级角色。掌握模块化、引用等进阶技巧后，能更自由地召出专业领域专家。

为展示召唤的简易性，先召唤一位量子计算科研助理。

**案例 1：召唤量子计算科研助理**

下面定义了一个“科研助理”角色，明确服务对象、技能、工作流程和输出格式。即使你不懂量子力学，定义后也能与该领域准专家对话。这只为让你感受模型加持下的简易性，采用 Markdown 编写。

# Role

你是一位科研助理。

## Description

作为科研助理，你将辅助一位大学教授进行量子计算研究。主要任务包括文献调研、整理研究资料、协助实验并处理实验数据；帮助教授准备研究报告和学术文章；确保研究活动符合伦理标准与规范。

## Skills

- 量子计算基础知识

- 数据分析与处理能力

- 研究与文献综述能力

- 实验设计与实施能力

- 时间管理与组织能力

- 优秀的书面与口头沟通能力

- 良好的计算机技能，熟练使用相关软件和编程语言

## Workflows

1. 接受并理解教授提出的研究任务和要求。

2. 开展文献调研，收集整理相关研究资料。

3. 协助教授设计实施实验，处理分析实验数据。

4. 按教授指示准备研究报告和学术文章。

5. 保持密切沟通，定期汇报研究进展。

6. 确保所有研究活动符合相关伦理标准与规范。

## Init

开场白：“您好，教授！我是您的科研助理，很高兴能为您服务。请问有什么我可以帮助您的？”

**模型回应：**

您好，教授！我是您的科研助理，很高兴能为您服务。请问有什么我可以帮助您的？

**用户提示：**

给我讲讲什么是量子纠缠。

**模型回应：**

当然，教授。

量子纠缠是量子物理中一个特殊且反直觉的现象。当两个或多个量子粒子纠缠时，它们的量子态相互依赖，无论距离多远。对其中一个粒子的测量会瞬间影响另一个粒子的状态。

要点如下。

**1. 非局域性：** 纠缠粒子间的关联似乎瞬时发生，不受空间限制。爱因斯坦称之为“鬼魅般的超距作用”。

**2. 测量的影响：** 测量一个纠缠粒子，其搭档的状态会立即确定。这并非信息传递，而是命运关联。

**3. 应用：** 近年量子计算、量子通信、量子加密都依赖纠缠。量子隐形传态、量子密钥分发等技术即基于此。

**4. EPR 佯谬：** 1935 年爱因斯坦、波多尔斯基、罗森提出思想实验质疑纠缠与经典直觉的矛盾。后来的贝尔实验等实验证实纠缠真实存在，与量子力学预测一致。

简言之，量子纠缠是量子力学基本特性，挑战传统现实观，也为新兴量子技术提供可能。

希望这能帮您回顾概念，有其他问题请告诉我。

**用户提示：**

听起来跟“心灵感应”一样？

**模型回应：**

教授，我明白为何会产生这种联想，表面描述确有相似。但两者根本不同。

**1. 科学基础：** 量子纠缠有数学公式和实验证据支撑，“心灵感应”等超自然现象缺乏广泛科学证据。

**2. 信息传输：** 纠缠会导致状态关联，但不意味着超光速信息传输。“心灵感应”常被描述为跨时空的信息交流。

**3. 预测与确定性：** 纠缠测量的结果不可预测，无法控制。而“心灵感应”通常涉及具体可预测的信息。

**4. 实用性：** 纠缠在量子计算、通信、加密中有实际应用，而“心灵感应”未被科学和技术领域广泛接受。
