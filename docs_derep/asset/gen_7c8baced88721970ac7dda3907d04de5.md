### 4.2 GraphRAG项目介绍

与传统 RAG 以“向量相似度检索+文本拼接生成”为主的思路不同，GraphRAG 加入了知识图谱构建、实体关系建模以及社区摘要生成等机制，让上下文表达更结构化、关联更清晰、可控性更强。面对海量文档、复杂问法和高难度推理场景，它在多跳推理和答案准确度上明显占优。通过拆解 GraphRAG 的技术渊源、核心流程与索引机制，读者可以系统把握其面向企业级落地的设计思路和工程实现路径，为后续实战部署与个性化扩展建立清晰认知框架。

#### 4.2.1 传统RAG技术实现流程与技术瓶颈

大模型走向企业化、产品化后，如何把模型能力与私域数据有效结合成为核心难题。私域数据包括内部文档、研究资料、业务记录、邮件往来等，体量大、结构杂、知识点分散。受限于上下文窗口，模型无法一次性装载全部信息，必须借助高效筛选机制从私域知识库里精准抽取与问题相关的内容。

为此 RAG 应运而生。RAG 由 Facebook AI 于 2020 年提出，是检索与生成式语言模型融合的混合范式。基本流程分为两步：

- 检索阶段：基于用户问题，从已构建的向量库中挑出最相关的知识片段。
- 生成阶段：把检索到的片段与问题一起输入大语言模型，产出最终答案。

传统 RAG，也即基线 RAG 或 Native RAG，主要依赖向量相似度完成检索。在结构简单、问答目标明确的场景下，它能显著提升响应准确性和稳定性。传统 RAG 技术实现流程如图4.2所示。

随着应用需求升级，传统 RAG 的局限也逐渐暴露，典型表现如下。

1. 难以串联多片段信息。问题需要多份文档片段的逻辑联动才能作答时，传统 RAG 缺乏全局视角，容易遗漏关键联系。
2. 推理能力偏弱。面向“基于已有数据推导新结论”这类需要逻辑链条的任务，传统 RAG 倾向于表面匹配，难以完成真正推理。
3. 对复杂结构或长文档不友好。面对结构复杂的大文档或文档集，需要整体理解和语义归纳时，向量切片机制容易丢失上下文，难以建模全局信息。

#### 4.2.2 GraphRAG技术方案的提出背景

为弥补传统 RAG 在复杂数据结构处理和逻辑推理增强方面的不足，技术社区开始探索更结构化、图谱化的知识表示方式。GraphRAG 正是当前 RAG 发展的一个新方向。

其核心思路是在原始文档基础上引入知识图谱构建，通过大语言模型自动抽取概念、实体及其关系，形成结构化语义图谱，从而强化文档间的上下文关联与推理能力。实际应用中，GraphRAG 先把语料库转成知识图谱，再结合图机器学习方法对用户查询做增强式提示构建与推理路径规划，使生成结果更精确、逻辑更连贯。

这里我们先了解 GraphRAG 和传统 RAG 的区别，如图4.3所示。

基于语义块检索的 RAG，最大的痛点是很难拿到全局信息。例如问题分散在不同语义块时，块检索式 RAG 很容易遗漏全貌。关键词匹配的局限在于，若用户问“哪些动物吃食物？”，传统方法可能只检索到“Dog eats Food”或“Cat eats Food”其一，无法同时汇总全部相关信息。

图结构可以在图谱中建立实体间的关联，从而更全面地获取全局信息。检索时可以从图谱中一次性拿到与问题相关的一切信息。图结构中信息关联的示例如图4.4所示。

#### 4.2.3 GraphRAG项目介绍及核心特点

Microsoft GraphRAG 项目 https://github.com/microsoft/graphrag 在版本迭代中数据处理、检索问答能力持续提升，配置方式也有较大变化。

传统 RAG 在查询时难以在不同信息片段间建立关联，或难以对大规模数据集做整体理解。GraphRAG 通过以下方式解决：

1. 更好地连接信息点。能够处理需要从多个数据点合成新见解的任务。
2. 更全面的理解能力。更擅长对大型数据集做整体理解，能更好地处理复杂抽象问题。

借助微软开源的 GraphRAG，可快速实现：

1. 传统 RAG 使用向量相似度检索，GraphRAG 引入知识图谱捕捉实体、关系及其他元数据，实现基于图的检索。
2. 使用 Leiden 技术做层次聚类，组织实体及其关系，提供更丰富的上下文以应对复杂查询。
3. 支持多种搜索模式。
    - 全局搜索：借助社区总结进行全局性推理。
    - 局部搜索：通过扩展相关实体的邻居和关联概念进行具体实体推理。
    - DRIFT 搜索：结合局部搜索和社区信息，提供更准确相关的答案。
4. 图机器学习：集成图机器学习技术提升查询响应质量，并从结构化和非结构化数据中提供深度洞察。
5. Prompt 调优：提供调优工具，帮助根据特定数据和需求调整查询提示，提高结果质量。

#### 4.2.4 GraphRAG整体流程介绍

与传统 RAG 一样，GraphRAG 包含两个主要阶段：Indexing 索引与 Query 查询。完整流程如图4.5所示。

##### 1. GraphRAG Indexing阶段

索引阶段是 RAG 体系的核心。相比传统 RAG 仅用向量相似度构建索引，GraphRAG 引入知识图谱构建、实体关系建模与社区结构识别等图语义增强手段，大幅提升复杂问题语境下的推理与检索效果。

图4.6展示了 GraphRAG 构建索引的完整流程。索引阶段主要负责对原始语料做结构化加工和图谱构建，包含 6 个步骤。

[PRE4]

图4.6 GraphRAG构建索引的完整流程

###### 1) 文档预处理与分块

流程起点是对原始文档统一加载，按设定的最大 token 长度分块。这一步与 Baseline RAG 类似，目的是把长文本切成语义完整的小片段，便于后续分析与图谱构建。

1. 文本分块通常采用带重叠的滑动窗口，避免切分处丢失重要信息。
2. 每个生成的文本块 TextUnit 都记录来源文档与编号，形成基础文本单元表。

###### 2) 图谱抽取

在每个文本单元基础上进一步提取图结构。该阶段进行图谱提取，包含实体关系提取与图谱总结。每个文本块被转为图节点，通过关系提取建立图边，描述文本单元间相互关系。同时进行观点提取，识别文本中的核心信息与观点。

###### 3) 图谱增强

构建初步图结构后进行增强，使用图聚类与图嵌入技术优化图结构。采用 Leiden 分层社区检测算法发现图中的社区，并利用 Node2Vec 对图进行嵌入。增强后的图结构为后续分析和推理提供更丰富的语义信息。

###### 4）社区总结生成

图结构增强后，对每个社区进行总结。生成社区报告，汇总每个社区的核心内容、主题、实体、关系以及相关文档片段。社区报告再做总结与嵌入，形成社区表以便后续使用。

###### 5）文档处理

将文档与增强后的图结构结合，生成文档粒度的嵌入表示，系统更好地理解文档间关联，并汇总为文档结构表，支持更高层次的文档间信息组织与查询。

###### 6）网络可视化流程

最后提供可视化工具帮助用户直观理解图结构与实体关系。通过 UMAP 降维并可视化文档与实体，用户能更轻松理解知识图谱及其推理路径。

##### 2. GraphRAG Query阶段

查询阶段围绕用户问题展开，借助已构建的图谱与结构化表示完成更精确的响应生成，流程如下。

###### 1）User Query（用户查询）

接收用户输入的自然语言问题。

###### 2）Select Community Level（选择社区层级）

根据问题内容定位适配的社区或语义层级，确定检索范围。

###### 3）Retrieve Community Summaries（检索社区信息）

从已构建的社区结构中检索出与当前问题语义最匹配的社区摘要，作为上下文支撑。

用户可通过不同搜索模式查询：

- 全局搜索：了解整个语料库整体概况时，利用社区摘要快速推理，适用于大范围问题。
- 局部搜索：问题聚焦特定实体时，向该实体的邻居扩展搜索，获得更详细精准答案。
- DRIFT 搜索：在局部搜索基础上引入社区上下文，提供更深入推理与连接。

###### 4）Generate Partial Responses（生成部分回复）

将检索到的信息组织归纳，形成多个部分回复或语义片段。

###### 5）Combine Response（合并回复）

对多个部分回复归纳总结，构建完整回复。

###### 6）Final Answer（最终回答）

输出最终问答结果，供用户查看或用于下游任务。

相较于传统 RAG 的“向量相似度+文本拼接”方式，GraphRAG 通过知识图谱构建、实体关系建模与社区摘要生成等机制，显著增强上下文表达的结构化、语义关联性和可控性。在大规模文档、复杂查询和高难度推理任务中，展现更强的多跳推理能力和问答精度保障。
