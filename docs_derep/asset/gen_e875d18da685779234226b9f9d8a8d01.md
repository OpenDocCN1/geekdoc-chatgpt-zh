### Keras 进化史：从“积木式”接口到 TensorFlow 核心

Keras 诞生于 Python 生态，由 F. Chollet 主导开发，是一个开源的神经网络高层 API。其设计初衷极其务实：以高度模块化、易扩展的特性，降低深度学习门槛，让开发者无需深究底层算法细节，即可像搭积木一样快速完成模型构建与训练。这种“解放生产力”的特质，曾让它在 2019 年前稳居深度学习框架接受度次席，仅次于 TensorFlow。

架构上，Keras 采用前后端分离模式。后端对接 Caffe、CNTK、TensorFlow 等引擎承担底层运算，前端则提供统一抽象接口。这种面向应用层的封装，让数据科学家聚焦业务逻辑，极大提升了开发效率。

故事的转折点在于 Chollet 的 Google 员工身份，以及 PyTorch 的强势崛起。早期 Keras 与 TensorFlow 是“亦敌亦友”关系。但随着 PyTorch 凭借易用性与社区活跃度攻占学术界（CVPR、ICLR、ICML 顶会论文占比超 60%），TensorFlow 感知到强烈的危机感。于是，双方彻底结盟：TensorFlow 2 正式确立 Keras 为唯一高层接口（`tf.keras`），废弃了 1.x 时代的 `tf.layers` 等旧 API。

对开发者而言，现在的 `tf.keras` 就是 TensorFlow 众多子模块（如 `tf.math`、`tf.data`）中的平等一员。本文后续提及 Keras 均特指 `tf.keras`。该模块内置了数据集加载、网络层、损失函数、优化器及经典模型等高度封装的组件，开箱即用。

### 6.3 Dataset 变换：把原材料“炼”成模型爱吃的饲料

数据导入只是第一步，`Dataset` 强在丰富的**链式变换**能力，可将原始流转换为训练就绪流。核心操作四件套：**打乱 → 分批 → 映射 → 重复**。

#### 6.3.1 `shuffle(buffer_size)`：打破顺序，防过拟合

固定顺序喂数据，模型易“死记硬背”标签位置导致过拟合。`shuffle` 维护一个缓冲池，随机抽取打乱顺序。**关键点：特征与标签的对应关系永不破坏**。`buffer_size` 越大，随机度越高，通常设为数据集大小或较大常数。

[PRE11]

#### 6.3.2 `batch(batch_size)`：分批的三重奏

将数据切分为固定大小的块（Batch）。
1.  **并行友好**：无依赖计算可分发到多核 CPU/GPU 核心（数据并行）。
2.  **显存保命**：大数据分块加载，避免 OOM。
3.  **算法适配**：主流优化器（SGD、Adam 等）均基于小批量随机梯度下降变体。

调用 `dataset.batch(32)` 即设批大小 32。该超参数需结合硬件显存“摸索”最优值。

#### 6.3.4 `repeat(count)`：多轮训练

一个 `epoch` = 遍历全量数据一次。`repeat(5)` 将数据流复制 5 轮。

训练循环范式：
```python
for epoch in range(epochs):
    for x_batch, y_batch in train_db:  # train_db 为 Dataset 对象
        train_step(x_batch, y_batch)
```
*   **Step**：处理一个 Batch。
*   **Epoch**：遍历完所有 Batch。

> **通俗理解**：Epoch 如“书读百遍”。神经网络初始参数随机，性能差；第 n 轮训练继承第 n-1 轮权重，初值更优，效果自然更好。但遍数非越多越好，需防过拟合，视情况早停。
