#### 7.2.1 LCEL 核心概念快速上手
LCEL 即 LangChain Expression Language，是 LangChain 里用于声明式编排的语言，作用是把不同算子按链条串起来完成特定任务，比如检索增强生成或智能体。所有部件都遵循统一的 Runnable 契约，于是可以无缝衔接形成可执行的流程。

在 LangChain 体系里，每个模块本质上都是 LCEL 对象，由它们拼接成的链依然属于 LCEL，可调用统一的接口来跑定制流、并行执行、降级切换或动态改动内部结构。整体模块划分见图7.2。

[PRE0]

LCEL 对象的典型好处有：

- （1）接口一致：所有 LCEL 对象都实现了 Runnable 契约，拼接过程十分顺滑。
- （2）解耦开发：各部件可单独编写、单独验证，只要输入输出匹配就能通过 LCEL 组合。
- （3）扩展灵活：组件都提供 invoke、batch、stream、ainvoke 等通用调用方式，方便在不同场景下自由编排。

Model I/O 层为对接外部大语言模型提供了标准扩展接口。它涵盖提示输入、模型主体和结果输出，通俗讲就是把 Prompt 送进模型并拿到推理结果，从而快速实现对话交互。

该层由三个关键环节构成：Format、Predict、Parse，示意图见图7.3。

- Format：对应 Prompt 模板，用结构化方式管理输入。
- Predict：对应模型调用，通过统一接口接入不同大语言模型。
- Parse：对应输出处理，从推理结果里抽取信息并按预设格式规范化。

[PRE1]

##### 1. Format
第一步是提示模板。过去常见做法是手写 Prompt 并借助 Few-Shot、CoT 等技巧来提升推理，但工程化时 Prompt 不能一成不变。因为真实场景的用户提问五花八门，固化模板会削弱灵活性和覆盖面。比如天气查询，用户可能说“今天好冷”或“纽约明天几度”，如果模板只适配一种表达，就很难通用，最终影响体验。

模板把 API 调用、问答流程等复杂逻辑封装成结构化格式。准备好外部函数描述和用户问题后，就能自动生成针对性 Prompt，引导模型按既定步骤思考并完成函数调用，示例如下。

##### 2. Predict
Predict 负责模型接收输入到完成推理的全流程。按类型可分 Base 类和 Chat 类，LangChain 在 Model I/O 中分别归为 LLM 和 Chat Model。下面以 OpenAI 的 Completion 与 Chat Completions 作说明。

LLM 提供基于 Prompt 的文本生成能力，属于简化版模型功能。Chat Model 则抽象聊天接口，需要保留历史对话记忆，交互更接近自然会话。

##### 3. Parse
大模型输出格式波动较大，同一 Prompt 可能得到多种表达。纯对话场景影响不大，但在工程链路中，后续步骤常依赖模型输出作为输入，因此必须做标准化处理以保证流程顺利。

输出解析器用于把模型响应结构化，可按照格式指令解析，也支持更深层次的抽取。

总的来看，Model I/O 的抽象一方面让开发者能快速接入 OpenAI、ChatGLM、Qwen 等模型并按规范推理，另一方面通过输入输出的模板化更符合工程实践。接下来介绍如何在 LangChain 中使用这三部分。
