**3.2.3 向量存储与相似检索**

向量需要借助向量型存储来统一管理。与传统关系型或文档型存储不同，向量库专为保存和检索高维向量设计，具备高效的向量管控和相似检索能力。内部会构建近似最近邻 ANN 索引，能够在海量向量中快速找到与查询向量最接近的集合。

不少向量库还集成了向量化处理流水线，可直接对文本、图像、音频等原始数据完成向量化后自动入库，简化“拆分-向量化-入库”流程，提升开发效率和一致性。这对搭建 LLM 知识库、相似内容推荐、语义搜索以及检索增强生成都至关重要。

Chroma 是款轻量开源的向量库，支持本地无服务部署，便于快速集成到开发测试环境。它提供简洁的 Python/JavaScript 接口，能把文本片段直接向量化写入，同时支持条件过滤与相似检索，帮助以最小成本搭建私有化向量检索系统。下面具体介绍如何用 Chroma 完成向量存储和相似匹配。

**3．相似度计算**

建立多维向量空间后，可通过计算向量间距离衡量语义相似性。但距离定义不唯一，不同算法带来不同匹配效果。Chroma 内置多种距离计算方式，可按业务需求选择。

创建集合时，create_collection API 接受可选的 metadata 参数，其中 "hnsw:space" 用于指定距离计算方法。例如：

    collection = client.create_collection(
        name="collection_name",
        metadata={"hnsw:space": "cosine"}  # 默认 "l2"
    )

当前支持的主流算法见表 3-6。

[PRE15]

余弦相似度和欧氏距离在文本相似任务上表现都不错，但余弦相似度更具优势，尤其对高维文本嵌入。因为余弦关注方向角度而非绝对长度，能避免文本长度、词频差异带来的偏差，更贴近语义相似。

欧氏距离对向量模长敏感，在极端分布下可能出现语义偏差；内积不适合文本相似匹配，主要用于得分排序或推荐系统中衡量用户偏好与内容特征的匹配度。

因此，文本语义检索场景一般优先选用 "cosine" 模式，以获得更稳定准确的结果。

**4．自定义嵌入模型**

若未显式传入向量，Chroma 默认使用开源模型 all-MiniLM-L6-v2 进行自动向量化，由 SentenceTransformers 提供，推理快、语义表达良好，适合多数英文场景。

在高级应用中，可能希望使用更强的预训练模型，如 intfloat/multilingual-e5-large，以获得更高维、更精细的表示。Chroma 支持自定义机制，允许开发者用外部模型预处理文本并将向量手动传入。只需实现 EmbeddingFunction 协议即可统一处理。

    class MyEmbeddingFunction:
        def __call__(self, texts: List[str]) -> List[List[float]]:
            # 将文本列表转为向量列表
            ...

实现要点：
· texts 接收字符串列表
· 返回必须为二维列表，每个子列表为对应文本向量
· 向量维度需与后续匹配任务一致

示例实现：

    from sentence_transformers import SentenceTransformer
    class SBERTEmbeddingFunction:
        def __init__(self):
            self.model = SentenceTransformer("intfloat/multilingual-e5-large")
        def __call__(self, texts: List[str]) -> List[List[float]]:
            return self.model.encode(texts).tolist()

实现后可在创建集合时绑定，后续增删查操作会自动调用该函数向量化，例如：

    embedding_fn = SBERTEmbeddingFunction()
    collection = client.create_collection(name="my_collection", embedding_function=embedding_fn)
