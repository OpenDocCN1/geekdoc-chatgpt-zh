AI基础设施：标准、交付与智能协同

生态共识的沉淀最终会凝结为行业标准。龙蜥社区与国内各系统开源阵营就接口规范达成一致，使行业规则的影响力扩大；同时联合国内权威标准组织，把产业内部的共识转化为正式标准。

（2）商业化交付：容器生态与软件分发
AI软件栈的复杂已经成为部署和运维的门槛。让模型跑起来，需要驱动、基础库与工具链、框架等多层组件配合，版本搭配不当就会牵动安全、稳定和可用性。典型情况是内核与组件选型不匹配，导致存储性能损失超过30%，进而拖累训练效率，最终体现在GPU利用率下滑。异构芯片混布进一步放大了选型难度。

面对这一现状，厂商提供预编译的AI容器镜像，实现即用即跑，是降低门槛的关键。要点在于搭建完整的容器构建体系和端到端交付链路。

阿里云服务器操作系统借助龙蜥社区构建AI容器生态，并以Alibaba Cloud AI Containers即AC2实现商业化交付，在多方面提供保障。

• 组件选型：龙蜥社区与芯片厂商联合制定涵盖CUDA、ROCm、OneDNN等关键基础库与工具的版本基线兼容认证，确保底层库与工具的选型与芯片型号及系统内核版本严格对应，并通过CI/CD发布流程保障稳定可靠。
• 镜像构建：内置不同硬件加速库、运行时和模型框架，覆盖多样化场景，例如预集成PyTorch、vLLM等并引入业界最新优化；同时对ECS、ACK、ECI、ACS等云产品及灵骏集群做深度适配，提升云上AI性能体验。
• 供应链安全：建立SBOM软件物料清单追溯、安全漏洞修复与公告、镜像签名等机制，确保从源码到分发的全程可信；配套全链路AI镜像发布平台，覆盖构建、测试、发布、维护。
• 分发：依托阿里云容器镜像服务ACR统一分发，官网已上架预构建AC2镜像并支持大规模集群加速；同时接入龙蜥社区AI软件仓库EPAO源，支持运行时动态安装组件。

总体而言，AI容器生态是提升基础设施易用性的抓手，让企业建设重心从环境适配回归算法创新。

（3）全栈协作：系统栈端到端调优
AI系统栈复杂度呈指数级上升。分布式训练中，因架构特性故障影响面会被急剧放大，局部节点的NCCL通信异常就可能导致整组GPU掉线，造成经济损失。节点级监控与故障诊断因此成为提升集群效能的核心；同样，单点性能瓶颈会因同步机制被放大，训练框架的定期Checkpoint在存储层常成为瓶颈。

分布式推理同样严峻。以DeepSeek混合专家架构为例，其参数稀疏与动态路由在千亿级模型上有效降本提效，但在云上落地需协同数十节点、数百张GPU，带来多重复杂性：故障影响半径依然很大，专家路由的负载均衡需精细化，且为降低时延普遍采用RDMA，进一步提升通信优化难度。MoE架构引入使运维与技术优化难度明显攀升。

当前不少服务器操作系统仍停留在集成与支撑层面，错失全栈协同机会。操作系统需深度参与AI系统软件的全栈优化，持续拓展端到端性能边界。

以阿里云服务器操作系统为例，全栈协同在三个方向拓展边界。
• 预处理阶段，提供存储链路数据加速，优化Checkpoint写入、数据预处理与模型加载速度。
• 异构计算管控，强化单节点故障诊断与上报，与调度系统联动，对可快速自愈的故障采用快速恢复策略。
• 异构计算数据，深度集成并优化模型框架，直接提升单节点训练与推理性能。如基于vLLM、SGLang的PD分离技术配合弹性资源池化，将DeepSeek推理成本显著下降。

在基础设施从“能用”走向“好用”的过程中，阿里云服务器操作系统已在DPU-CPU-GPU全链路上逐步拓展优化边界。

2）AI for System：操作系统的智能化跃迁
算力成本下行叠加大模型能力跃升，推理与智能体应用将迎来爆发。在OS领域，用智能体重塑研发、运维、售后全流程，以AI提升生产效率与体验，已成关键命题。

研发生产端，操作系统可借力大模型优化产品化研发流程，提升研发智能化水平。
售后服务端，大模型结合RAG构建知识与问题库，通过自动化分拣与处理工单，加快响应速度。
运维管理端，集成大模型能力降低使用门槛，大幅提升故障诊断效率，并以自然语言交互改善体验。

阿里云服务器操作系统已研发并集成OS Copilot组件，兼容DeepSeek与通义千问，具备以下特质。
• 智能：持续学习用户习惯，给出更准的预测性建议。
• 专业：覆盖操作系统相关各类问题解答。
• 高效：在系统诊断、调优、编程等场景中快速处置。
• 协作：可管理阿里云资源，提供一体化服务。

主要功能包括：
• 命令行自然语言问答：用户可在命令行用自然语言提问，获取专业解答，提升操作效率。
• 辅助命令执行：帮助新手快速掌握Linux常用操作。
• 阿里云CLI调用：基于阿里云开放API，支持在操作系统内便捷调用CLI，例如查询ECS实例信息。
• 系统运维与调优：通过自然语言调用运维调优工具，尤其是阿里云自研工具，帮助定位问题、提升性能。

展望未来，随着MCP、A2A协议与多智能体协作框架成熟，操作系统将探索基于智能感知的资源管理新范式。智能体在自我学习与迭代上取得突破，推动OS从执行者进化为决策者，核心价值由资源管控转向智能决策，重塑基础设施管理范式。

**3.技术驱动：补齐能力与需求差距**
新场景驱动基础设施重构，架构复杂性带来的系统性问题愈发突出。实时对话要求毫秒级时延，离线批处理要攻克高吞吐存储，混合云面临跨域协同挑战，产品能力与场景需求的差距需要跨越。这些需求最终转化为稳定性、安全、弹性伸缩、性能与成本优化四大诉求。在完成双向赋能后，直面技术挑战、塑造差异化竞争力，才能把场景想象力变为商业可行性。

1）稳定性：为复杂系统提供确定性保障
分布式训练与推理成为主流，AI基础设施稳定性直接决定SLA。操作系统需构建多层防御体系，在可观测性与RAS处理上针对智能特性形成完整支撑。

（1）AI系统的可观测性。阿里云服务器操作系统的SysOM组件集成应用观测、系统监控、告警、诊断与安全运维，基于大数据与机器学习深入分析内核行为，实现实时性能观测与智能故障定位，达成一键运维。
为应对稳定性挑战，SysOM扩展可观测体系，通过动态注入采集算子、调度与内核函数信息，实现低侵入、低开销的作业观测，助力运维实时分析。当前模块支持：
• 系统观测：应用与任务状态监测，CPU与GPU性能问题分析。
• 异常告警：监控GPU利用率与分配率，给出资源优化建议。
• 链路追踪：支持CPU、GPU、分布式存储、RDMA网络链路追踪。
• 故障发现与预测、定界定位：CPU与GPU故障监控与定位。

（2）异构全链路RAS支持。大规模数据中心里，服务器宕机率是传统RAS指标，在智能场景下GPU可用时长更具本质意义。规模化扩展带来双重压力，加剧可用性挑战。
• 垂直扩展：故障域扩展到机架级，如NVIDIA NVL72，爆炸半径增大；单机CPU核心数百量级、内存向TB级演进、GPU液态级联，单机可部署上百虚拟机、上千容器，CPU、GPU、DPU、NVLink等关键硬件混杂，故障处理复杂度上升。
• 水平扩展：分布式架构下单点故障影响全局，模型规模推高集群规模，GPU故障率高成为运维痛点。
阿里云服务器操作系统通过软硬件协同构建端到端RAS方案，提供：
• 故障注入：覆盖CPU、GPU、DPU、PCIe、CXL等异构场景，验证硬件与操作系统全链路隔离、报告、诊断与处理。
• 故障诊断：对接各智能芯片处理机制，实现从设备故障码解析与拓扑诊断到进程、算子状态诊断的细粒度定位。
• 故障持久化：重启后读取ROM中持久化硬件故障信息，提升根因定位，避免任务二次受损。
• 轻量级故障收集与分析：依托tracepoint实现CPU、内存、EGM、AER、CXL等错误通知式采集，用户态完成解析、统计与告警。

2）安全性：端云协同的AI隐私计算体系
端云一体联合计算成为主流。智能场景下提示词、训练集、私有数据集频繁上云，泄露风险更高。传统云环境中数据安全高度依赖云平台自身能力，用户需承担高信任成本。
机密计算技术成熟后，数据在加密状态下计算、存储、传输，用户掌握解密权与排他所有权，形成端云协同的数据主权保护体系。
模型规模增长推动跨域数据传输需求上升，用户希望数据在第三方基础设施运行不被泄露或篡改。传统虚拟化隔离只能防恶意租户，无法保障工作负载完整性与保密性。可信执行环境TEE与机密计算成为行业共识，允许在不信任底层平台下安全运行敏感任务。
针对大模型训练推理的高敏感性，阿里云服务器操作系统提供基于异构TEE的CAI方案，核心能力包括：
• 异构TEE与GPU安全验证：在CPU可信环境基础上验证GPU执行环境，并在物理总线建立安全通道，实现CPU-GPU端到端机密性与完整性，防止高价值训练数据与模型参数泄露。
• 无缝适配主流模型框架：与TensorFlow、PyTorch等框架无缝集成，无需改动代码即可部署可信训练推理，提示词、输入、输出全程加密，避免提示词泄露与模型逆向风险。
• 远程证明与信任传递：通过远程证明向用户展示执行环境未被篡改、软件栈完整、处理可追溯，解决模型提供者与平台提供者间的信任断层，尤其适用于模型即服务与多方协作训练。

大模型时代数据跨域流动常态化，隐私、性能、效率与产权归属的平衡是关键挑战。CAI方案为保障数据隐私下的规模化落地提供实践，未来将持续融合软硬件创新与标准体系，深化行业应用。

3）弹性伸缩：云加AI架构的敏捷响应
在云加AI形态下，容器成为事实标准。基于Kubernetes的智能应用管理生态具有显著竞争力，KubeRay、Koordinator、KServe、Knative、KubeFlow、Fluid等项目简化分布式推理开发运维，并可对接AI容器生态，如AC2、NVIDIA NGC与NIM。
阿里云服务器操作系统支持原生容器runC与安全容器runD，实现云加AI部署。结合Kubernetes生态套件，AI容器可在训练微调与分布式推理服务中弹性伸缩。为实现秒级弹性，需在多环节优化。
RunD在支撑Serverless AI时面临挑战：Kata容器资源开销大，常超100MB，启动需数秒；安全容器臃肿，内存与设备直通开销高，系统服务启动慢；高并发创建CGroup导致同步时延与调度开销上升。
RunD快速弹性伸缩特性包括：
• Rust实现VMM Dragonball：VMM内存从百兆降至3MB，支持设备直通、热插拔、NUMA，适配复杂业务。
• 多进程融合设计：便捷运维升级，降低通信开销，提升启动性能与稳定性。
• 精简操作系统组件：剥离非容器特性，降低资源占用与攻击面。
• VMM与Guest Kernel融合设计：安全容器统一提供二者，深度融合提升启动速度与效率。
同时优化内核，解决高并发CGroup的调度开销问题。
技术落地后，RunD已在生产环境支撑单节点4000个安全容器、200个/秒并发、200ms启动。相关成果发表于2022年USENIX ATC与2023年SOSP，并已部分并入OpenStack开源项目Kata Container 3.0。

4）性能和成本优化：全栈协同的工程实践
AI基础设施的性能与成本优化是算力成本问题的核心，本质是挖掘智能芯片并行能力，确保数据在DPU、CPU、GPU全链路高效传输、处理与计算，在吞吐与时延约束下持续提升各环节利用率。掌控操作系统与硬件资源，通过端到端的软硬协同工程实践，可拓展优化边界，释放更大价值。
