# 重排选型：精度与效率怎么取舍

交叉编码器的思路可以追溯到 2018 年 Google 发布的 BERT。BERT 采用双向编码结构，目标是利用海量无标注语料学习通用的语言表征，并非为查询与文档的匹配或排序专门设计。真正把预训练模型引入段落重排的工作，是 Nogueira 等人在 2019 年论文《Passage Re-ranking with BERT》中首次提出的。

实现方式很直接：把查询和候选段落拼接起来，用 [SEP] 隔开后一起送入 BERT、RoBERTa 等预训练模型。借助 Transformer 的自注意力，查询的每个词元都能与段落的每个词元充分交互，模型由此捕捉两者间的语义关联。最后由 CLS 向量的输出接入分类头，直接给出相关性分数，完成精细排序。流程示意见图 7-5。

在 RAG 场景里，交叉编码器通常扮演二阶段精排的角色。先用 Bi-Encoder 做粗排召回，拿到一个候选集后，再把例如 Top-100 的片段交给交叉编码器细排，最终返回 Top-10 左右最相关的结果。

> **咖哥发言**
>
> 这里说的 Bi-Encoder 检索，本质上就是一种密集向量检索。嵌入模型普及前，学界常常用两条神经网络，结构可以相同也可以不同，通常是 Transformer 或 LSTM，分别对查询和文档编码成定长向量，再通过余弦或点积等相似度进行匹配。

咖哥：正是。

#### 7.1.3 ColBERT重排

ColBERT，即 Contextualized Late Interaction over BERT，是斯坦福在 2020 年 SIGIR 提出的一种密集检索方法。核心创新是“后期交互”。

不同于交叉编码器让查询和文档全量联合交互，ColBERT 先让查询和文本各自独立编码得到表征，只在最后阶段做词元级的交互。查询与文本的每个词向量两两点积，再汇总成最终得分。

小冰：ColBERT 看起来和普通的余弦相似度没区别，我们为什么还要它？传统检索里不早就做过向量余弦比较了吗？

咖哥：表面相近，但颗粒度不同。传统做法是把整条查询和整篇文档压缩成一个向量再算余弦；ColBERT 保留查询和文本全部词元的向量，通过逐词交互判断相关性。这样能捕捉局部对齐，实现更细的语义匹配。

小冰：那它和交叉编码器到底差在哪？

咖哥：ColBERT 编码可分离，文本可以提前编码好存起来，检索时只需做词元级点积。交叉编码器必须对每对查询-文档做端到端联合推理，所有词元全面交互。因此 ColBERT 在重排阶段效率更高，代价是存储开销增大，需要保存海量词元级表示。

表7-1展示了ColBERT与Cross-Encoder、RRF的对比。

表7-1 ColBERT与Cross-Encoder、RRF的对比

| 特性 | ColBERT | Cross-Encoder | RRF |
| :--- | :--- | :--- | :--- |
| 设计目标 | 高效密集检索+精细重排 | 深度语义匹配，用于精细重排 | 融合多模型结果的轻量级重排 |
| 语义交互 | token级别交互，捕捉细粒度语义 | 查询-文档全句交互，精确语义匹配 | 无语义交互，基于排名融合 |
| 计算成本 | 中等（查询与文档分离编码+点积） | 高（每个查询-文档都需要进行全模型推理） | 低（直接融合已有排名分数） |
| 适用场景 | 密集检索或Top-k文档重排 | Top-k文档精排 | 信号融合或轻量重排 |
| 上下文感知能力 | 强（基于token级别嵌入） | 非常强（全句语义建模） | 弱 |
| 适合大规模检索 | 是（支持预计算文档向量） | 否（计算成本过高） | 是 |

交叉编码器因查询与文档充分交互，效果通常更好，但每次都要重新推理，成本高。ColBERT 通过后期交互可预先计算并存储文档向量表示，查询时只需算相似度，效率大幅提升。所以小规模、追求极致精度的重排选交叉编码器，大规模检索重排则更倾向 ColBERT。

#### 7.1.4 Cohere重排和Jina重排

小冰：咖哥，除了 RRF、交叉编码器、ColBERT 这三种重排，我还听说过 Cohere 重排和 Jina 重排，它们有什么区别？

咖哥：两者都是基于大模型的重排方案。先说 Cohere 重排。

Cohere 类似 OpenAI 的大模型服务商，推出的 Rerank API 面向企业级搜索。它依托自研的 Command 系列大模型，比如 Command R，利用大模型的语义理解能力，采用交叉编码器结构对候选文档做深度理解和精排。

正如前面所讲，交叉编码器会把查询和文档拼接后联合编码，直接给出相关性分数，从而捕捉细粒度匹配。

因为是商业 API，用户无需自训模型，只需把 BM25 或向量搜索返回的 Top-100 等结果传给 Cohere 重排服务，就能拿到优化后的排序。即便没有领域训练数据，模型也能零样本适配不同排序任务。

Cohere 重排支持多语言，默认英语，如需汉语等语言要申请定制化模型。它还针对高并发低延迟做了优化，官方数据显示处理 100 个候选文档平均响应在 300ms 以下。
