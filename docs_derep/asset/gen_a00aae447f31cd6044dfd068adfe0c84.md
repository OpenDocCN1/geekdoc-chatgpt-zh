2.1.5 流式输出提升响应速度

结合前两个示例的实际运行，容易发现模型回复相较于传统应用要慢不少。实际上模型并非等到全部生成才输出。先前的调用方式要求模型把整段内容生成完毕后再一次性发送给应用端。另一种做法是让模型在生成过程中边产出边推送给应用端，这种机制称为流式输出。

流式输出是改善响应时效和互动体验的常用手段。采用流式输出后，模型生成一部分内容就能立即推送到客户端呈现，无需等待整段回复完成，从而缩短用户等待时长，交互感更顺畅。尤其在长文本生成场景下效果明显，用户能及早看到初稿，若不满意可及时中止，避免在漫长等待后才发现问题而浪费时间和算力。

为获得更流畅的实时体验，可在前述示例基础上进行改造以支持流式输出。

首先是在调用客户端方法 chat completions create 时新增参数 stream 并设为 True。此时模型会以标准的事件流形式逐块回传内容，流结束时提示符为“data: [DONE]”。为体现这一特性，可将封装函数更名为 get_stream_completion，也可保留原函数再新增一个 get_stream_completion。

[PRE2]

完成上述修改后，模型就能以流的方式回传响应。为了让应用及时捕获事件流并把收到的文字展示到界面上，界面展示部分也需要相应调整。

以流式方式呈现文字时，需要在每次取到片段后立即输出且不换行，否则阅读体验会受影响，而 streamlit 并未提供理想的直接支持。一种可行做法是在每次交互中为用户和助手各创建一个动态容器，流式内容到来时把截至目前收到的全部字符写入该容器，实现渐进显示。流结束后将完整结果保存并在同一容器中输出最终文本。

2.2 提示词工程实战

与生成式模型交互时，用户输入的文字即为提示词。提示词的编写有其规律和技巧，恰当的提示词能引导模型产出令人满意甚至超出预期的答案，不当的提示词则容易导致答非所问。随着模型能力提升，对提示词的容忍度在提高，但高质量的提示词设计仍是有效利用模型、开发生成式 AI 应用的核心能力之一。

本节围绕提示词编写与优化即提示词工程展开，下文示例均可借助上一节搭建的示例程序进行验证。

2.2.1 迭代式提示词开发：营销文案优化案例

在工作实践中，首次尝试的提示词很少能一次达到理想效果，通常需要依据模型反馈不断调整优化，直至输出符合预期。

以某公司灯箱安全监控产品为例，期望借助模型完成营销文案。整理产品技术信息后，初步提示词如下：

> 以下是一个产品的相关技术信息，请根据这些信息生成一份产品的营销文案。

IUBIOT 灯箱安全监控产品...

将该提示词提交后，模型生成了冗长的一版文案，如图 2-5。

图 2-5 所示的回复篇幅过长，阅读负担较重。为控制长度，可在提示词中增加字数限制：

> 以下是一个产品的相关技术信息，请根据这些信息生成一份产品的营销文案。

**字数限 50 字以内。**

“<产品信息内容同前例>”

重新提交后，模型产出两句话左右的版本，如图 2-6。

【IUBIOT灯箱守护神】——让安全与智慧并行，点亮城市的每一处角落！

+   【安全升级，防范未然】采用前沿物联网技术，IUBIOT灯箱安全监控产品针对各类户外灯箱进行24小时实时监管，预防电气隐患，降低火灾风险。实时故障报警，过载短路自动断电，为您的灯箱安全保驾护航！

【智能控制，轻松管理】通过手机APP远程操控，随时调节灯箱开关与亮度，实现智能管理。温湿度、线温、位移、烟雾等多重监测功能可选配，全面掌握灯箱状况。

【远程监控，随时应对】灯箱运行参数实时上传，故障初步定位，手机APP即时接收异常消息。无论身处何地，都能迅速响应，确保灯箱稳定运行。

【应用广泛，兼容性强】适用于机场、地铁、门店、商场、路边等多种场景，满足各类灯箱安全监控需求。模块化设计，灵活搭配，快速组装，即时投入使用。

【软硬件结合，易于操作】硬件方面，智能物联灯箱控制器、调光控制器等多款设备可选；软件方面，Web管理端与手机APP相结合，操作简便，轻松实现灯箱远程监控与管理。

【节能环保，智慧照明】搭配调光控制器，实现节能降耗，为绿色环保贡献力量。可控电压12V或24V，满足不同灯箱需求。

IUBIOT灯箱安全监控产品，让每一处光明都充满智慧与安全。赶快加入我们，开启智能灯箱管理新时代！

“智守安全，光控未来！IUBIOT灯箱监控，防火防灾防意外，手机远程调控，智慧商业新选择！”

注：提示词中明确要求字数时，模型会尽力遵循但不会严格执行。存在其他约束时表现类似。因此可以期待模型大致遵循指示，但需理解其执行存在一定弹性，这种弹性有助于保持输出连贯性和准确性。

这次模型把原文压缩到约 39 字，简明概括了产品核心功能，便于终端用户快速了解。

> 以下是一个产品的相关技术信息，请根据这些信息生成一份产品的营销文案。字数限 50 字以内。由于该产品并非直接面向最终用户销售，而是由系统整包集成商采购，通常他们更关心产品所采用的技术，所以生成的文案要适合面向系统整包商进行营销，要具有技术性质，侧重于产品的技术优势。

2.2.2 引导式推理：破解思维题

与模型互动时，若得到偏差或错误结果，不必急于否定其能力，而应尝试重构提示词，要求模型在给出最终答案前进行一系列相关推理。换言之，面对难以在短期内完成的任务时，模型容易给出不完美的答案，此时通过细化步骤引导其思考，往往能得到更可靠的结果，这与人类解题过程类似。

5★3→28

9★1→810

8★6→214

5★4→19

7★3→？
