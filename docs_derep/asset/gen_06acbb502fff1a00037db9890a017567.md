## 2.4 本章小结

本章从自然语言协同到标准化通信协议，系统梳理了 Agent 协同的工作脉络，形成了一套完整的通信认知框架。

自然语言协同部分，重点讲了从传统刚性协议通信向自然语言通信的转变。基于 LLM 的 Agent 能用人类语言灵活交互，打破了 ACL 协议的局限，同时需借助 Prompt 链、上下文管理和 System Prompt 等手段保证规范与可靠。Prompt 链把复杂任务拆成关联步骤，支持顺序、分支、聚合等模式；上下文管理用滑动窗口、摘要压缩、检索增强解决窗口限制；System Prompt 则用来定义角色与行为边界。

协同模式部分，本章覆盖了四种主流做法。顺序协同适合有明确依赖的流水线，职责清晰但难并行；并行协同让多个 Agent 同步工作，可显著提速，但要兼顾结果合并与容错；Manager-Worker 层次协同引入管理层，实现智能调度与动态分配；竞争协同则让多 Agent 各自提案再评选，提升决策多样性。

协议层面，MCP 解决了 Agent 与工具数据的连接问题，终结了 M×N 集成困境，并获得广泛采纳。A2A 围绕 Agent Card、Task、Message 构建了跨 Agent 交互规范，主攻协作通信。ACP 作为 IBM 的轻量方案已并入 A2A，推动标准统一。实战中 MCP 负责赋能，A2A 负责协作，互为补充。

# 第3章 基于LLM的Agent群落协同策略

在 Agent 群落里，协同策略就是把个体智能连成群体智能的桥梁。传统多 Agent 系统靠预设规则和固定分配算法做协调，而 LLM 驱动的群落则走向自然语言化的协同：任务理解、规划推理和动态调整都通过语言完成。本章将围绕语义理解与生成能力，探讨智能化任务规划、能力匹配、动态重规划和失败恢复的实现思路。

## 3.1 Agent的任务规划与分配

【学习目标】

- 1) 弄清零样本任务拆解的原理和具体做法
- 2) 学会用 Agent 能力描述做智能匹配
- 3) 掌握任务执行中动态调整计划的方法

LLM 驱动的规划与分配是群落协同的核心。系统通过语义理解把复杂需求自动拆成可执行子任务，再依据各 Agent 的自然语言能力描述完成智能匹配。

### 3.1.1 零样本任务分解：让LLM自动拆分任务

任务分解是协同的起点。传统做法多依赖专家制定的规则模板或需大量标注的强化学习模型，前者覆盖面窄，后者成本高。零样本任务分解利用 LLM 预训练积累的推理能力，无需额外训练即可完成智能拆解。

其思路源自“分而治之”。面对复杂需求时，LLM 先用语义理解提炼关键要素，再分析要素间的依赖关系，最后输出结构化子任务序列。整体可分为理解任务、分析依赖、生成计划三个阶段。

理解阶段，LLM 解析用户自然语言，提取目标、约束和期望输出。例如“为科技公司制定下一季度市场营销方案”会被识别为综合策划，涉及市场分析、竞品研究、渠道选择、预算规划等多个维度。
