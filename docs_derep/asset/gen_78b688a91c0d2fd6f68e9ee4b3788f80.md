FPGA 发展到今天的规模，已经可以用复杂来形容。比如赛灵思在 2019 年推出的 Versal 系列，晶体管总数达到 360 亿；英特尔的 Stratix10 GX 10M 被称为当时体量最大的 FPGA，装载了 433 亿个晶体管、1020 万个可编程逻辑单元以及 2304 个可编程 I/O 接口。

光看晶体管数目并不能概括其复杂程度。这几百亿个晶体管背后，是大量可编程逻辑单元与查找表、数千个高性能运算单元、多种容量和类型的存储资源、高速串行 I/O、多个内置处理器，以及成百上千种软硬核 IP。相比传统芯片，FPGA 拥有独特的阵列式可编程逻辑，能够实现大范围硬件并行和定制化流水线，进而带来高吞吐、低功耗以及由此产生的系统级效率提升，这正是它最具吸引力的地方。

当所有资源都集成在一颗芯片上时，核心难题随之而来：用户该如何驾驭这些硬件？

对一个具体应用而言，通常需要划分硬件执行部分和软件执行部分。在 FPGA 上，这种划分更为繁琐：哪些功能放在可编程逻辑里，哪些放在片上微处理器上；片上内存如何分配，容量不足时如何借助片外内存；如何提升性能、吞吐量和时钟频率；如何增加并行度、加入流水线等。

由此可见，做出一个高效的 FPGA 应用设计极其艰难。对许多尝试 FPGA 的团队来说，最大的阻力来自 FPGA 本身的结构。一旦软硬件架构确定，团队就要面对设计复杂数字电路的任务。这需要用硬件描述语言建模电路，并要求工程师精通综合、映射、布局布线、时序收敛等各环节，门槛因此被大大抬高。

降低开发难度一直是 FPGA 厂商几十年的重点。时至今日，英特尔和赛灵思投入 EDA 工具开发的工程师人数，甚至超过了芯片研发队伍。还存在庞大的现场应用工程师团队随时支援客户，此外第三方设计咨询、IP 提供商和外包公司也形成了一条产业链，专门帮助客户简化开发流程。

目前 FPGA 正快速进入多个扩张市场：从边缘到云的加速、网络数据处理与存储加速，以及 5G、汽车等嵌入式场景。然而这些领域的多数团队缺乏 FPGA 设计经验，应用多以纯软件方式开发，且对人工智能依赖加深，开发难度被进一步放大，使用推广也因此受阻。

业界的共识是：开发环境需要升级，让特定领域的软件开发者能够直接利用复杂的异构硬件，独立完成 FPGA 应用开发，而不必深入底层电路细节，也无需 FPGA 专家深度介入。

## 4.2 让软件工程师开发 FPGA——高层次综合

高层次综合的本质，是把用高层语言描述的逻辑架构，通过 EDA 工具自动转换为低抽象层次的电路模型。高层语言如 C、C++、SystemC，抽象程度高，通常不含时钟或时序概念；而 Verilog、VHDL、SystemVerilog 等硬件描述语言，则用于描述按时钟周期精确的寄存器传输级模型，是 ASIC 与 FPGA 设计的主流方法。

近十年里 HLS 在 FPGA 领域获得高度关注，原因主要有三。

其一，用更高抽象层次建模是集成电路发展的必然。随着摩尔定律推进，芯片复杂性已超出人工手工管理范围。据 NEC 2004 年的研究，一个拥有 100 万逻辑门的芯片设计通常需要约 30 万行 RTL 代码。若改用 C、C++ 等高层语言建模，代码量可压缩至原来的 10% 到 14%，压缩比达 7 到 10 倍，极大缓解了设计复杂度。

其二，高层语言提升 IP 重用效率。传统 RTL IP 需要固定架构和接口标准，重用时接口互连与验证耗时。相比之下，高层语言隐藏了这些细节，由 HLS 工具完成具体实现。现代 FPGA 内建大量成熟 IP，如嵌入式存储、算术运算单元、嵌入式处理器、AI 加速器、片上互联网络等，HLS 工具可以充分利用这些固定功能 IP，提升重用效率、简化综合流程并改善综合后性能。

其三，HLS 让软件与算法工程师参与主导芯片或 FPGA 设计。通过封装硬件实现细节，软件与算法人员可专注上层算法；对硬件工程师而言，HLS 有助于快速迭代，集中优化对性能、面积或功耗敏感的模块。

### 4.2.1 FPGA 高层次综合的前世今生

在 FPGA 出现前，人们就已尝试用高层语言进行行为级描述并借助自动化工具生成电路。上世纪 80 到 90 年代，面向集成电路的 HLS 已是学术热点，代表性工作包括卡耐基梅隆大学的 CMU-DA 工具，以及加拿大卡尔顿大学提出的 force-directed 调度算法。

从今天看，这些工作为后续综合算法奠定了基础，也提供了宝贵经验。但该阶段的成果转化并不成功，原因可以概括为“在错误的时间遇上对的人”。当时后端自动布线已成主流，前端 RTL 综合兴起，传统工程师纷纷转向基于 RTL 的建模，RTL 综合工具高速发展。而当时的 HLS 研究多采用特殊编程语言，如 CMU-DA 采用的 ISPS，在与 RTL 处于蜜月期的工程师群体中难以获得青睐。

沉寂一段时间后，HLS 在 2000 年后重启。较有代表性的工具包括 Bluespec 和 AutoPilot。转折点在于 HLS 开始以 C/C++ 为主要目标语言，被不熟悉 RTL 的软件与算法工程师接受，同时综合结果质量显著提升，在某些应用中可接近手工 RTL 的性能。

FPGA 的兴起也助推了 HLS。与 ASIC 不同，FPGA 的片上逻辑资源是固定的，HLS 不必在面积、性能、功耗上做极致权衡，只需将设计合理映射到固定架构即可，这使其成为在 FPGA 上快速实现算法的理想途径。

时至今日，主流 FPGA 厂商均推出自家 HLS 方案，如赛灵思的 Vivado HLS、英特尔的 HLS 编译器与 OpenCL SDK，学术界也有多伦多大学的 LegUp 等成果。

### 4.2.2 高层次综合的主要工作原理：以 AutoPilot 为例

AutoESL 公司的 AutoPilot 是 HLS 学术成果产业化的典型案例。它源自 UCLA 丛京生教授主导的 xPilot 项目，后由丛京生与张志如共同创办 AutoESL，并于 2011 年被赛灵思收购，成为其后的 Vivado HLS。

AutoPilot 的工作流程前端采用基于 LLVM 的编译架构，可处理可综合的 ANSI C、C++ 以及 OSCI SystemC 等模型。前端编译器 llvm-gcc 将高层模型转为中间表示 IR，并进行针对代码复杂度、冗余、并行性等方面的优化。随后依具体硬件平台综合生成 RTL 代码、验证与仿真环境，以及必要的时序与布局约束。

AutoPilot 的突出表现在于某些场景下超越人工优化 RTL。例如在无线 MIMO 系统的 Sphere 解码器 IP 中，AutoPilot 将 4000 行 C 代码算法综合到赛灵思 Virtex5 系列 FPGA，工作频率 225MHz，且逻辑资源占用低于赛灵思原厂 Sphere 解码器 IP，见表 4-1。该结果即使放在现在仍具震撼力，证明了 HLS 具备超越 RTL IP 的潜力。

### 4.2.3 高层次综合工具常用的优化方法

HLS 工具需要在性能、功耗、面积等电路指标与自身资源占用、运行时间等工具性能之间取得平衡。主流优化方法包括：

其一，字长分析和优化。FPGA 支持任意字长的数据通路与运算，HLS 工具可对设计进行全局或局部字长优化，从而兼顾性能提升与面积缩减。此类优化要求使用者对目标算法与数据集有深入理解，是推广的主要限制之一。

其二，循环优化。目的是将软件中原本顺序执行的循环语句映射为硬件并行结构，最终目标是让相邻两次操作在最小时延下完成。理想情况是完全并行展开，但受资源限制与循环嵌套、依赖关系影响难以实现，优化循环以获得最优硬件结构是研究重点。

循环优化的常见手段是多面体模型，即 Polyhedral Model。该模型把循环语句表示为空间多面体，再依据边界约束与依赖关系，通过几何操作进行调度与变换。

多面体模型在 FPGA HLS 领域已取得较好效果，可帮助优化性能与面积，也能提升片上内存使用效率。

第三类优化是对软件并行性的支持。C/C++ 原为面向处理器顺序执行的语言，而 RTL 可通过例化多个运算单元实现并行。随着处理器并行支持加强以及 GPU 等异构芯片兴起，C/C++ 引入了 pthreads、OpenMP 等多线程机制，以及面向 GPU 等异构系统的 OpenCL 扩展。HLS 工具因此需要支持这些并行表达，例如多伦多大学的 LegUp 工具整合了对 pthreads 与 OpenMP 的支持，实现任务与数据层面的并行。

### 4.2.4 高层次综合的发展前景

历经十余年发展，AutoPilot、OpenCL SDK 等已成为 FPGA HLS 的商业化成功案例，但完全替代手工 RTL 建模仍有很长路要走。对 FPGA 而言，内存瓶颈始终是制约性能的关键。除片上各类 BRAM 外，还有 DDR、QDR 以及近年兴起的 HBM 等片外存储，如何有效利用片上与片外存储是研究热点。

同时，HLS 生成结果的等效性、仿真与调试方法也需进一步探索。等效性方面可能需要形式化方法证明 RTL 与高层代码在逻辑功能上等价。软硬件协同仿真与调试时，工具应提供测试环境、用例、脚本与调试手段；硬件出现问题时，需要自下而上的调试方法论来定位高层代码缺陷。

近年来，特定领域的编程语言与对应的 HLS 方法受到关注。例如 P4，即 Programming Protocol-Independent Packet Processors，是面向网络数据包处理领域的高层语言。P4 由 Barefoot 初创公司联合英特尔、谷歌、微软、斯坦福与普林斯顿于 2014 年起草发布并开源，主要设计者是斯坦福大学教授 Nick McKeown，他是软件定义网络的先驱，创立了开放网络基金会与 P4.org。

P4 的目的是为 SDN 数据平面提供协议无关的可编程能力，如包头解析、匹配、表项配置等。网络数据包处理历来是 FPGA 的优势领域，而 SDN 与网络功能虚拟化等新兴应用正是 FPGA 的未来方向之一。赛灵思与英特尔均已发布面向 FPGA 的 P4 编译器，使设计者可通过 P4 直接生成高性能数据包处理流水线。2019 年英特尔收购 Barefoot，Nick McKeown 成为英特尔资深院士。

伴随人工智能发展，面向 AI 应用的 Python HLS 工具不断涌现。2019 年 FPGA 国际研讨会上，UCLA 丛京生课题组与康奈尔大学张志如课题组合作的 HeteroCL：A Multi-Paradigm Programming Infrastructure for Software-Defined Reconfigurable Computing 获颁最佳论文奖。该工作提出基于 Python 的领域专用语言与编程模型 HeteroCL，专门针对图像处理与机器学习进行优化，在很大程度上降低编程难度并解决现有 HLS 工具的痛点。

当前 HLS 工具的使用体验仍未达到理想状态，可说是“理想很丰满，现实很骨感”。虽然算法可用 C、OpenCL 等高层语言编写，但直接综合往往结果不佳。为获得最优硬件性能，开发者仍需清楚底层 FPGA 架构，按硬件思路编写代码，并通过 Pragma 等预处理指令引导编译器生成期望结构。这一过程多为手动，会影响效率与可读性，且经处理后的代码与源代码差异较大。图 4-4 即展示了点积函数的源代码与为 HLS 优化后的代码对比。
