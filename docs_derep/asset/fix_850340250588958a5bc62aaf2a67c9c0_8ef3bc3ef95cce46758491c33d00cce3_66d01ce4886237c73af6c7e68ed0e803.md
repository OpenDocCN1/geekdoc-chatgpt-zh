| merge_branch | 将一个数据库分支合并到主分支 | 功能开发与测试结束时，AI 助手会把开发分支自动合入主分支 |
| execute_sql | 执行任意 SQL 查询 | AI 助手能把自然语言指令翻译成 SQL 并执行，例如‘列出所有年满 31 岁的用户邮箱’ |
| create_record | 在指定表中创建新记录 | 按照用户提供的字段值，AI 助手在目标表中生成一条新数据，例如‘新增用户，用户名 test’ |

#### 3.3.6 场景化多 MCP 联动展望

##### 1. 物联网：智能家居实战
智能家居里，用口语控制设备并获取环境态势，需要多套 MCP 协同。

- Agent+MCP (Langflow)：Langflow 搭建的家居中控 Agent 负责对话，它充当 MCP 的调用方。
- IoT 设备 + MCP (假设)：智能灯泡、恒温器、安防摄像头若都实现 MCP 服务端，可分别暴露调光、控温、取流等能力，Langflow Agent 可通过 MCP 发现并操控。
- 数据 + MCP (Supabase MCP)：Supabase 保存用户偏好如理想温度、灯光方案，以及能耗等历史，Agent 经 Supabase MCP 读写。
- Tool+MCP (Zapier MCP)：要做到异常时发短信，Agent 可借助 Zapier MCP 接入 Twilio。

场景流程：用户说“晚上好，我回来了”。
1. Agent 先用 Supabase MCP 拉取回家的个性化设定。
2. 通过 MCP 调用灯泡和恒温器的服务端，把灯光调到预设亮度，温度调到偏好值。
3. 同时查询摄像头服务端获取最新画面并分析，判断家中是否正常。
4. 若用户说“我有点冷”，Agent 再次调用恒温器服务端提升室温。
5. 若摄像头发现异常，Agent 经 Zapier MCP 调用 Twilio 给用户推送警报短信。

##### 2. 医疗健康：远程患者监护
MCP 可搭建连通病人、医疗设备与服务方的远程监护体系。

- Agent+MCP (OpenAI Agent SDK)：基于 OpenAI Agent SDK 的虚拟护士 Agent 是患者主要交互窗口。
- 医疗设备+MCP (假设)：血糖仪、血压计、心率带等可穿戴设备若实现 MCP 服务端，能实时输出生理数据。
- 数据+MCP (Supabase MCP)：电子健康档案含病史、用药、监测数据，存于 Supabase。
- LLM+MCP (Claude)：虚拟护士需医学知识或初步判断时，可把数据交给 Claude 的 MCP 接口分析。
- Tool+MCP (Zapier MCP)：紧急时，Agent 可用 Zapier MCP 对接急救呼叫或通知医护。

场景流程：血糖仪定期经 MCP 上报数值。
1. 虚拟护士 Agent 经 MCP 收到血糖读数。
2. 用 Supabase MCP 查阅该患者的历史血糖与目标区间。
3. 若超出范围，先调用 Claude MCP 把近期数据和病史送去初步评估并获取建议。
4. 根据分析，Agent 可经 MCP 向患者推送提醒或建议。
5. 若情况危急，Agent 用 Zapier MCP 触发急救呼叫，并附上位置与基础生命体征。

##### 3. 教育：个性化学习平台
借助 MCP 能打造适配每个学习者的个性化教学平台。

- Agent+MCP (Langflow)：Langflow 构建的智能学习助手为学生定制路径与辅导。
- 学习资源+MCP (假设)：在线课程、数字馆、教育应用若实现 MCP 服务端，可开放课程、练习、测评能力。
- 数据+MCP (Supabase MCP)：学习记录、偏好、进度存于 Supabase。
- LLM+MCP (OpenAI)：助手可调用 OpenAI 的 MCP 接口，按学习状态生成定制化材料与题目。
- SaaS+MCP (QGIS MCP-地理学习)：地理或环境科学可接入 QGIS MCP，让学生用自然语言操作地理空间分析与可视化。

场景流程：学生问“请介绍亚马孙雨林的气候特征”。
1. 通过 Langflow 助手提出问题。
2. 助手用 Supabase MCP 查学习记录，了解知识水平与偏好。
3. 经 MCP 连接多个在线平台与数字馆服务端检索相关资料。
4. 调用 OpenAI MCP 接口，基于资料与个人情况生成定制化气候小结。
5. 为增强直观性，调用 QGIS MCP 生成亚马孙地区的气候可视化图。
6. 把总结与图表一起呈现给学生。

##### 4. 金融：智能投资助手
MCP 可构建投顾助理，帮助用户管理资产并做决策。

- Agent+MCP (OpenAI Agent SDK)：基于 OpenAI Agent SDK 的智能投顾 Agent。
- 金融数据源+MCP (假设)：券商平台、财经新闻、分析工具若实现 MCP 服务端，可实时提供股价、新闻、研报。
- 数据+MCP (Supabase MCP)：投资组合、交易历史、风险偏好存于 Supabase。
- Tool+MCP (Zapier MCP)：Agent 可用 Zapier MCP 连接银行或券商账户执行交易或发送报告。
- LLM+MCP (Claude)：面对复杂市场研判，Agent 可把最新数据与组合信息交给 Claude 的 MCP 接口分析。

场景流程：用户问“我该买科技股吗？”
1. 顾问 Agent 用 Supabase MCP 读取组合与风险偏好。
2. 经 MCP 连接金融数据源服务端获取科技股最新价格、新闻与研报。
3. 调用 Claude MCP 分析信息并结合风险偏好评估收益风险。
4. 根据结论，Agent 可经 Zapier MCP 连接券商账户，建议买入数量并请用户确认。
5. 确认后，Agent 再用 Zapier MCP 执行交易，并在 Supabase 更新组合。

MCP 作为新一代开放规范，在智能体互联、SaaS 嵌入、LLM 增强、工具互通与数据共享方面潜力巨大。统一的交互方式让 AI 应用接入外部资源更便捷，降低门槛，为更灵活方案奠基。

在互联层面，Langflow 能同时作 MCP 客户端与服务端，配合可视化界面让开发者轻松编排工作流。SaaS 层面，Blender-MCP、QGIS MCP 等案例显示 AI 能力可融入专业桌面软件，自然语言交互提升效率。LLM 层面，Claude 与 OpenAI Agent SDK 的原生支持让模型易于扩展，访问外部知识并执行操作。Zapier MCP 接入数千应用，提升自动化水平。Supabase MCP 体现了在数据集成与共享上的价值，让 AI 应用安全便捷地操作数据库。

展望未来，物联网、医疗、教育、金融等领域都能凭借统一标准让 AI 更广泛落地并带来变革。总之，MCP 代表下一代 AI 应用的关键底层，其开放、标准与灵活性将持续推动技术进步与创新。

### 3.4 MCP 生态的创业机会

MCP 的出现重塑了 AI 应用架构，也催生新产业生态。在该生态下，创业者在多个细分赛道切入，有机会打造平台级产品。业界普遍认为围绕 MCP 有三大方向：Agent OS、MCP Infra、MCP Marketplace。下面分别介绍。

#### 3.4.1 Agent OS

##### 1. 市场现状与趋势
在 AI Agent 时代，构建操作系统级平台成为热点。业界认为 OS 将成为大模型厂商的核心护城河。Anthropic 率先开源 MCP，意在打造 AI 应用的“USB-C”统一接口，为 Agent 提供工具与数据调用的统一方式，大幅提升集成效率。

基于此，Agent OS 概念出现，目标是把分散的 MCP Server 能力抽象成统一平台，像传统 OS 管理硬件那样管理 Agent 的工具与上下文，让 Agent 更自然地调用功能与分发信息。目前 Anthropic、OpenAI、Google 都在探索路径，例如 OpenAI 用插件与函数调用构建生态，Google 推出 A2A 通信协议。

整体上 Agent OS 正从理念走向落地。PwC 发布企业级 Agent OS 以整合业务流程；开源社区 AIOS、OpenManus 等快速发展；开发工具 Cursor、Devin 等 AI 编程助手逐步具备完整 Agent 能力，成为 MCP Host 的雏形。共识是：掌握 Agent OS 就掌握了生态入口。

##### 2. 代表性产品与参与者
目前呈现大厂领跑、初创突围、开源繁荣的局面。Anthropic 凭借率先推出 MCP 占得标准先机，其桌面版 Claude 已是早期 MCP 主机的代表，积累系统能力经验。OpenAI 虽未直接采用 MCP，但 ChatGPT 插件生态已形成封闭却功能丰富的平台雏形，目标与 Agent OS 高度一致。

技术深度上，AIOS 由学术团队主导，聚焦嵌入式 LLM 的操作系统内核，提供调度、上下文切换、内存管理、工具调用等系统级能力，分为内核与 SDK 两层，目标打造完整的 Agent 运行时。

初创方面，Manus 由 Monica.im 团队推出，是首个具备自主拆解任务与工具调用能力的通用智能体，标志 AI 从对话助手迈向可自主执行复杂任务，发布后获腾讯云等关注，推动国内厂商加速布局。

开源生态反应迅速，MetaGPT 团队开源的 OpenManus 发布 3 天获 2.4 万 Star，显示开发者对 Agent OS 架构的强烈需求。Cline 与 Cursor 演化为面向开发者的领域级 Agent OS。工具箱型项目如 Composio 提供数百种插件能力，丰富 Agent 工具生态。

无论硅谷公司还是中国互联网巨头，都在争夺这一智能时代的操作系统入口。

##### 3. 当前挑战
前景虽好，发展仍面临多重难题。

其一，技术复杂度：Agent OS 需管理 LLM 上下文、工具调用、长期记忆并实现稳定调度，需解决调度、上下文切换、内存管理等。

其二，标准化难题：各家 Agent 框架如 LangChain、OpenAI 函数调用各不相同，形成统一 OS 标准不易。目前 MCP 虽开放，但多 Agent 协同、身份认证等能力尚缺。

其三，安全与可信：让 Agent 控制电脑或联网服务可能带来误操作或滥用，需沙盒与权限控制，例如 AIOS 引入类似系统调用的管控。

其四，生态成熟度：Agent OS 需大量应用与驱动即 MCP 服务器工具支撑，目前工具生态增长快但质量参差。

其五，用户体验：普通用户如何直观使用 Agent OS 仍需探索，界面与交互范式待验证，如 Manus 的对话加自动执行模式是否通用还需市场检验。

##### 4. 创业机会与战略价值
Agent OS 孕育成为“AI 时代的 Windows”的机会。切入策略多样。

其一，聚焦垂直场景的 Agent OS，如面向企业办公的智能助理 OS 集成邮件、日程、文档，或面向开发者的编程 OS 集成编辑、测试、部署工具，以深度取胜。

其二，构建通用 Agent OS 平台，提供开放插件接口兼容 MCP，走 Android 模式吸引开发者。

其三，跨模型兼容，支持多种大模型作为内核，引入模型路由按任务调度最优模型形成差异化。创业者还可与硬件或操作系统结合形成壁垒，如开发桌面 AI 助手 OS，深入系统底层。

Agent OS 在 MCP 生态中相当于入口与中枢，连接用户与海量工具服务。掌握它意味着掌控用户、工具与数据交互。随 AI Agent 越来越多介入工作生活，优秀的 Agent OS 将大幅降低使用门槛，契合从单一应用向通用助手演进，谁先打造稳定平台，谁有望在 Agentic AI 浪潮中取得主导。

#### 3.4.2 MCP Infra

MCP Infra 指 MCP 运行所需的基础设施与工具链。MCP 功能强但仍处早期，企业级落地有诸多挑战，这正是创业机会：提供专业基础设施，帮助团队更高效可靠地使用 MCP。

##### 1. 市场现状与痛点
MCP 作为开放协议，短时间内聚集 2000 多个服务器，成为 LLM 工具集成的事实标准之一，但底层基础设施仍薄弱。多数服务器部署在本地或内网，缺乏大规模分布式部署支持。

例如，多数 MCP 服务器为单用户/单会话设计，不支持多用户/多租户。跨网远程调用机制不完善，缺少统一身份认证与服务发现，限制云端大规模应用。对开发者而言，配置维护仍需人工，缺少便捷托管发布链路，调试兼容性问题也缺乏专用工具。

此外，MCP 目前不支持多 Agent 直接通信，无法像 ANP 那样构建去中心化 Agent 网络，在复杂场景会成局限。性能与可靠性也需关注：MCP 引入额外请求/响应开销，不及模型内置函数轻量实时。要达到生产可用，基础设施层面仍有诸多问题待解。

##### 2. 技术趋势与关键参与者
针对痛点，新一波基础设施方案正在涌现。Anthropic 官方与开源社区正完善 MCP 规范，例如计划增加无状态交互、远程鉴权等特性，使 MCP 成为无状态协议，便于分布式扩展。
