任务型闭环，以 AutoGPT、ReAct 为代表，运行骨架是 Goal → Plan → Action → Observe → Adjust。Agent 在这个骨架里获得了决策权，能自行挑选检索目标、决定检索频次，首次查询失手时会换词重试。这种设计提升了容错，却也容易陷入反复打转的死循环。

另一条路径是认知型探索：World Model → Gap Detection → Curiosity → Exploration。这被看作更前瞻的方向。Agent 不只为完成指定任务而感知，更为完善自身世界模型而感知。它会像人一样，在空闲时因好奇“那扇门后是什么”而主动发起探索。只有这种架构，才能真正改善常识匮乏和环境适应力不足的问题。

Deep Research 的出现，本质上是在和“过度信任输入”做结构性对抗。它通过严格限定信息来源，比如只允许论文、权威数据库，来强化证据驱动推理，让模型在证据不足时学会说“不知道”，而不是随意编造。但光靠来源限制仍远远不够，现实世界的知识早已超出论文边界，开放网络的网页质量参差不齐。模型可以检索网页，却缺乏原生能力去分辨：

- 哪些页面具备权威性？
- 哪些内容已经过时、带有偏见、被商业操纵甚至造假？
- 哪些表述看似可信，逻辑上却站不住脚？

这正是主动感知系统下一步要补足的能力：不仅要会拿信息，还要会做知识层面的判别。这种判别不是简单的文本打分，而是一套认知机制，包括来源可信度建模、证据间一致性检查、反事实验证与逆向推理、时间敏感性过滤，以及结构化证据链的构建。

于是 Agent 的行为范式从 Function(Input) → Output，转向了更为开放的形态。

[PRE0]

这一转变让 Agent 的定位从被动答题者变成主动调查员，工作方法从接收并复述事实，变为主动检验并整合事实，决策依据也从依赖内部参数化记忆的直觉生成，转向基于检索与推理的循证行动。

因此 Deep Research 的核心价值并非让模型“多看论文”，而是培养质疑、验证和构建可靠知识链的能力。

### 4.3.4 主动感知演进路径与协作方式

在演进过程中，Agent 好像经历了一次好奇心的觉醒：从最初的静态单次检索，到动态迭代查询，再到基于假设检验的自主探索。

1. 演化路径：从检索到觅食

- 单轮检索（Single-Turn Retrieval）：与传统 RAG 类似，用户提问后系统直接检索。痛点是信息茧房，Agent 只能依赖前几段返回片段作答，若答案不在其中，便容易产生幻觉，因为它没有“再试一次”的机制。
- 迭代查询（Iterative Querying）：WebGPT（2021 年）和 Step-Back Prompting 代表了感知进入动态阶段。Agent 在首次结果不足时，会自主发起第二轮、第三轮查询，逐步搭建多跳推理的信息链，获得更全面准确的答案。
- 信息觅食（Information Foraging）：Agent 的行动已不限于为回答而检索，而是为了消除不确定性而主动探索环境。例如在 Minecraft 中主动揭开地图迷雾，或反问用户“你的需求更接近 A 还是 B”。这一思路引入信息价值论，Agent 会权衡获取信息的成本与对任务的贡献，决定是否值得获取。

2. 模式组合示例

主动感知通常扮演侦察兵，但单独使用无法形成闭环，需要与其他模式协同。

- 主动感知与注意力聚焦模式的组合 = 呼吸效应。主动感知负责吸气，通过广撒网和多轮查询获取大量原始信息；注意力聚焦负责呼气，通过评分器与压缩算子剔除噪声，只把核心事实注入 LLM。
- 主动感知与多模态融合模式的组合 = 跨模态侦查。适用于机器人巡检、视频分析。主动感知决定看哪里，控制摄像头转向、变焦或截取视频片段；多模态融合决定看到了什么，进行图像或视频的解析与语义理解。若反馈图像模糊或置信度低，主动感知会触发靠近、换滤镜或重新采样等动作优化质量。
- 主动感知与 ReAct 模式的组合 = 认知特化。在 ReAct 循环中，当思考模块判断缺乏 X 的证据导致 Y 不成立时，触发主动感知生成针对性查询，持续获取外部信息直到认知缺口被填补。ReAct 提供通用执行框架，主动感知则是信息获取领域的特化。
- 主动感知与情节记忆模式的组合 = 探索地图。Agent 将每次主动探索的轨迹记录到情节记忆库，如“在某网站搜关键词 A 无果”。后续任务遇到相似需求时，可检索记忆避开无效路径，直达高价值信息源。

在主动感知里，架构师不再预设 Agent 能看见什么，而是赋予其自主寻找答案的能力。

### 4.3.5 设计理念：从全知假设到求知本能

传统软件默认数据库里有全部答案，即全知假设。主动感知承认无知是常态，并把求知内化为 Agent 的生存本能。真正的智能不在于知道所有答案，而在于不知道时懂得如何去找。这种对已知未知的主动应对，是机器显现自我意识的微光。

小结 系统与世界的接口层

至此，Agent 架构的第一块拼图完成，即感知模式。

- 注意力聚焦模式解决信息太多的问题，在噪声中提取信号。
- 多模态融合模式解决信息太杂的问题，把视觉、听觉统一为语言。
- 主动感知模式解决信息太少的问题，主动出击填补认知盲区。

当 Agent 能看懂世界、筛选重点并主动补全盲区时，就拥有了学习的基础。接下来这些信息要流向何处？如何被存储、沉淀为经验？请翻开第 5 章，我们一起学习记忆模式。

# 第5章 记忆模式

> “感知是世界来访；记忆是世界在我心中的停留。”
> ——黄佳

从人类到机器，推理都依赖记忆，没有可调用的事实、情节与范式，推理就会沦为即兴的语言拼装。

可用“三类 + 四象限”勾勒人类记忆。

“三类”记忆如下。

- 情节记忆（Episodic Memory）：曾经发生在自己身上的事件。
- 语义记忆（Semantic Memory）：与个体无关的世界知识。
- 程序/技能记忆（Procedural Memory）：如何做一件事的操作范式。

记忆的“四象限”如下。

- 短期/工作记忆（Working Memory）：极小量的正在使用上下文。
- 长期/持久记忆（Long-term Memory）：跨会话、跨任务的稳定记忆。
- 自我（Self）记忆：偏好、风格、身份。
- 任务（Task）知识：领域知识、规则、情境地图。

工程上，记忆是上下文的工程化管理，是推理的素材库与约束集，也是 Agent 身份与风格的生成器。它决定某一时刻进入模型的那一小片宇宙是什么、如何呈现、如何度量与更新。

感知提供当下，推理创造洞见，记忆实现持续。记忆让 Agent 有过往、有个性、有经验，也让系统可伸缩、可治理、可协作。

本章将深入探讨分层记忆模式、RAG 模式和情节记忆模式，这是一组围绕上下文经营的工程与哲学组合拳，把写入、读取、蒸馏、遗忘变为可编排的系统能力，以支撑长期、鲁棒、可解释的 Agent。

> 上下文是你此刻输入模型的所有状态，包括系统指令、任务目标、检索片段、最近对话、工具返回、世界状态……上下文工程的核心是如何在有限窗口内组织这些状态，使模型稳定产出可预期行为。当前工程实践强调把“上下文即系统状态”作为设计核心对象，围绕选取、压缩、结构化与评估进行全链路管理，而非当作 Prompt 附件。

## 5.1 分层记忆模式

> “记忆是时间在心中的投影。”
> ——威廉·詹姆斯（William James），《心理学原理》

设想一台计算机有 L1/L2 缓存、RAM 与磁盘，这是工程师为平衡速度与容量的存储金字塔。操作系统核心任务之一是管理内存需求，会把高频数据调入 RAM，把暂时不用数据移至磁盘交换空间。

分层记忆模式把虚拟内存机制引入 Agent 设计。

- 工作记忆（技术实现如 Context Window）≈ RAM：Agent 的意识流，处理当前任务，容量有限、速度快但易失。
- 长期存储（技术实现如 Vector DB/Graph）≈ 磁盘：知识库与经验库，存储海量经验，持久但访问较慢。
- Agent ≈ 操作系统内核：主动调度者，决定何时把关键记忆载入工作记忆，何时把冗余信息移出。

核心意图是突破 LLM 上下文窗口的物理限制，通过分层存储与动态换页实现理论上无限的记忆容量。

### 5.1.1 模式架构：倒金字塔形的数据流

从架构视角，需要构建倒金字塔形的数据流，如图 5-3 所示。

[PRE1]

该架构未引入复杂控制组件，而是通过 3 个存储层级和两种流转机制管理信息生命周期。

1. 存储层级

- L1 缓存（工作记忆）：类似 Agent 的大脑前额叶，对应模型上下文窗口，存 System Prompt 与近期活跃对话。容量有限 8000~128000 Token，访问最快但维护成本高、易丢失。
- L2 缓存（短期缓存）：信息中转站。L1 溢出后，非活跃对话历史会被压缩为摘要或存入情感缓冲区暂留于此，作为 L1 与 L3 的缓冲，防止过早丢失或过早写入长期存储。
- L3 缓存（长期存储）：类似海马体与图书馆，由向量数据库和知识图谱构成，持久化海量非结构化文本与结构化实体关系。容量近乎无限，但需检索接口访问，延迟较高。

2. 流转机制

信息流转如下。

- 溢出与巩固：用户输入不断涌入，L1 旧信息被挤出，经过摘要进入 L2，或向量化沉淀至 L3。这是信息由热变冷的过程。
- 检索与唤醒：面对新问题时触发检索，从 L3 精准定位相关历史数据并注入 L1。这是信息由冷变热的过程。

[PRE2]

> 如何理解“倒金字塔”？它不是直观的图形，而是描述信息从多到少、从临时到持久的递减结构。顶层 L1 是信息源头，像洪水汹涌、未经筛选、临时易变；中层 L2 像河道，对漫流数据筛选压缩；底层 L3 像水库，只有经过筛选验证的重要信息才沉淀为持久知识。

倒金字塔分层记忆的本质是让信息沿“从繁到简、由热转冷、由静返动”流动。它把海量对话蒸馏为可用知识，并在关键时刻让知识重新成为行动力量。过程中 Agent 能感知信息流动与变化，获得时间感，并保持自我连续性。

### 5.1.2 分层记忆核心机制

核心机制包括虚拟上下文管理和记忆生命周期管理。

1. 虚拟上下文管理

MemGPT 提出的核心概念。通过该机制 Agent 可模拟无限上下文，系统后台不断进行换页操作，在小窗口推理效率与大量信息管理间取得平衡。

- 分页（Paging）：上下文窗口临近上限时，系统自动把最旧信息移至外部存储，并在当前上下文保留引用链接，便于后续快速访问。
- 主动召回（Active Recall）：Agent 发现信息不足时，如用户提到“上次那个项目”，会主动触发系统调用 memory.search("上次那个项目")，把相关数据加载回上下文。

2. 记忆生命周期管理

记忆需要治理，生命周期分为四步。

第一步，编码（Encoding）：写入工作记忆。起点是控制窗口不被无效信息挤满，对异常或关键事件即时标记，涉及敏感内容在此脱敏。

第二步，巩固（Consolidation）：移入长期记忆。对话结束或窗口溢出时，系统筛选仍具价值信息移入长期记忆。巩固不是搬运，而是基于语义重要度筛选、压缩并保留因果链条，同时去重避免污染向量库。

第三步，检索（Retrieval）：从磁盘读回内存。推理时上下文不足会触发检索，把长期记忆读回工作记忆。检索采用语义 × 新鲜度 × 可信度的多因子评估，避免召回幻觉，最终返回可验证证据链。

第四步，遗忘（Forgetting）：衰减与删除。长期未访问或重要性下降的记忆逐步衰减，按需软删除或彻底清除；冗余信息压缩为精炼知识条目，避免向量库无限膨胀。遗忘让记忆系统保持轻盈、高效、可治理。

表 5-1 记忆治理

| 阶段 | 动作 | 触发条件 | 治理原则（新增） | 工程隐喻 |
| :--- | :--- | :--- | :--- | :--- |
| 编码 | 写入工作记忆 | 用户输入 | 信息脱敏、标记重要度、限制上下文窗口膨胀 | RAM 写入 |
| 巩固 | 移入长期记忆 | 对话结束 / 上下文窗口溢出 | 去重、压缩、结构化、保存因果链条 | 从缓存到磁盘 |

### 5.1.3 分层记忆工程实践

随着 AI 应用规模扩大，记忆成为基础设施并形成独立赛道，已演化出三种核心架构形态。

1. 中间件模式：Mem0 与 MaaS

企业级应用痛点是数据孤岛，例如客服 Agent 看不到代码助手已了解的用户偏好。Mem0 等框架定义记忆中间件标准，不仅是存储系统，更是动态编排层。采用混合检索架构，对非结构化文本同时建立语义索引与图索引并结合使用。

Mem0 把个体偏好、身份与事实整合为可查询、可更新、可治理的记忆层，服务开发者并形成开源生态。对架构师而言，可构建统一用户数字孪生，通过多租户隔离（User、Session、Agent 等作用域）实现不同业务线 Agent 读写共享记忆池，达成一次交互、全域认知。
