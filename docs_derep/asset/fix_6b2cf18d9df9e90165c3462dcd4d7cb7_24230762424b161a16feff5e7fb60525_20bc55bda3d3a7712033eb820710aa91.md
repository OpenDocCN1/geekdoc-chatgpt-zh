在受限网络的虚拟环境里拉取 OpenAI 相关包时，代理的预设是关键前置。下面先说明如何通过终端设定 HTTP 与 HTTPS 代理，再借助 pip 按指定版本安装 OpenAI 并按需补充依赖的整体思路。

在需要代理的场景下，操作流程大致为：

1. 启动终端或命令行窗口。
2. 配置 HTTP 与 HTTPS 代理，执行：
set HTTP_PROXY=http://YOUR_PROXY_IP:YOUR_PROXY_PORT
set HTTPS_PROXY=https://YOUR_PROXY_IP:YOUR_PROXY_PORT
3. 把 YOUR_PROXY_IP 和 YOUR_PROXY_PORT 替换为实际可用的代理地址与端口。
4. 执行安装命令：
pip install openai==0.28.1
5. 视需求，用类似的 pip 指令补充其它关联库。

完成上述配置后，即可在代理环境中顺利完成 OpenAI 包的安装。

### 4.1 RAG体系全景
本小节聚焦检索增强生成，阐明其运行原理、关键构成与工程落地方法。作为将信息检索与生成式语言模型结合的问答范式，RAG 能够提升回答的准确度与信息量，同时有效抑制生成式模型出现的幻觉问题，适用于知识库问答、企业智能体等场景。

以下以构建本地化系统为主线，依次拆解文本向量化、文档载入与分块、向量库搭建、检索策略设计以及模型调用等核心环节。并引入主流 API 模型作为答案生成组件，帮助读者理解框架与大型语言模型的对接方式。

#### 4.1.1 RAG概念速览
大型语言模型在生成时易出现偏差，具体表现为：

- 事实偏差：输出可能基于错误或过时的知识。
- 知识滞后：难以获取最新信息，尤其在专业领域。
- 推理不足：面对复杂推理任务时效率与准确性欠佳。

为缓解上述问题，RAG应运而生。它先从知识库中检索与问题相关的信息，再基于检索结果生成回复，从而大幅提升输出的准确性与相关性。该方法还能加速知识更新并增强可追溯性，使方案在实际应用中更可信。

#### 4.1.2 RAG系统核心模块
实现 RAG 需要以下五个核心模块。

1. 向量化模块：把文档片段映射为向量表示，便于后续检索。
2. 文档加载与切分模块：负责读取原始文档并切分为易处理的片段。
3. 存储模块：保存文档片段及其对应的向量。
4. 检索模块：依据用户查询检索相关片段。
5. 生成模块：调用语言模型基于检索信息生成回答。

上述模块共同构成简易 RAG 的核心架构，各自在检索到生成的不同阶段发挥作用，保证查询处理的连贯性。

#### 4.1.3 文本向量化模块构建
在自然语言处理与机器学习中，Embedding 是把文本转为数值向量的常用手段。通过向量可以度量文本间的相似性，并应用于搜索、分类、推荐等任务。OpenAI 已发布第三代 Embedding 模型，在性能、成本与多语言支持上均有提升。下面介绍该系列特点与调用方式。

##### 1. OpenAI 第三代 Embedding 模型概述
Embedding 是把文本字符串表示为浮点数列表的技术，通过比较向量间的距离判断相关性，距离越近相关性越高。

常见应用包括：

- 搜索：按相关性排序结果。
- 聚类分析：依据相似度分组。
- 个性化推荐：基于相关内容推荐信息。
- 异常检测：找出相关性低的异常文本。
- 多样性评估：分析文本集合相似度分布。
- 分类任务：按文本与标签相似度归类。

OpenAI 的 text-embedding-3-small 与 text-embedding-3-large 性能更好，支持更多语言，分别输出 1536 维和 3072 维向量。用户可通过设置维度参数在保持语义的前提下优化存储与计算开销。
