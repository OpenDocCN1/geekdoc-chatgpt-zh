## 第 13 章 把 LCEL 原型推向生产

本章先带你认识 LCEL 与 LCEL 链，再聊对话历史的管理、消息持久化及基础构件，最后演示如何校验可运行对象。

### 13.1 LCEL

LCEL 是 LangChain 提供的类 Unix 管道式语法，用来方便拼装 LLMChain，实现对话调用、检索增强生成等能力。

#### 13.1.1 认识 LCEL

借助 LCEL 把多条子链组合成新链非常顺手，无论是简单的指令加模型，还是复杂的编排都能胜任。

LCEL 的主要体验提升包括：

- 首 token 延迟很低：基于 LCEL 的链能把 LLM 原始 token 直接送给流式解析器，解析速度接近模型本身的输出速度。
- 同步异步兼顾：LCEL 同时支持同步和异步调用，适合 Jupyter 原型，也适合 LangServe 生产服务，既保性能又支持并发。
- 并行自动调度：链中存在可并行环节时，LCEL 会自动优化执行路径，同步或异步接口下都能压低时延。
- 可配置重试与回调：链的任意节点都可挂重试和回调，大规模运行更可靠。
- 中间结果可观察：复杂链支持流式透传中间步骤，便于实时通知和排查，LangServe 也能使用。
- 模式自动校验：LCEL 会依据链结构推导出 Pydantic 与 JSONSchema，用来校验输入输出，是 LangServe 的关键能力。
- LangSmith 自动追踪：链越复杂，LCEL 越会自动把每一步记录到 LangSmith，提升可观测与可调试性。
- 无缝接入 LangServe：用 LCEL 搭建的链能直接部署到 LangServe，上线很顺滑。

#### 13.1.2 LCEL 的核心亮点

LCEL 具备以下特性：

- 接口统一：所有 LCEL 对象都实现 Runnable 接口，提供 invoke、batch、stream、ainvoke 等通用调用方式，链式结构自然获得批处理与流式能力。
- 基础构件丰富：LCEL 提供了一套基本构件，让建链、并行化、添加备选、动态改参变得简单。

#### 13.1.4 Runnable 接口

LangChain 通过 Runnable 接口简化自定义链的构建，统一了定义与调用方式。

接口对外暴露的方法：

- stream()：以流式返回响应片段。
- invoke()：对输入执行链。
- batch()：对输入列表执行链。

异步版本：

- astream()：异步流式返回片段。
- ainvoke()：异步执行单条输入。
- abatch()：异步执行输入列表。
- astream_log(): 在返回最终结果的同时流式返回中间步骤。

#### 13.1.5 流式处理

流式处理对 LLM 应用的响应性至关重要。

LangChain 的核心基础组件如 LLM、解析器、提示器、检索器和代理均实现 Runnable 接口。该接口提供：

- sync stream() 与 async astream()：默认流式实现，从链中流式传输最终输出。
- async astream_events() 与 async astream_log()：可从链中流式传输中间步骤及最终输出。

#### 13.1.6 基于输入的动态路由逻辑

路由允许构建非确定性链，每一步输出决定下一步执行，为 LLM 交互提供清晰结构和一致性。

常用路由方式：

- RunnableLambda()：可有条件地返回可运行对象，是推荐做法。
- RunnableBranch()：可实现路由逻辑。
