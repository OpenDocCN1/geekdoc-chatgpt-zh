在编写 JSX 组件时，建议先进行三项快速自检：循环结构是否已从命令式的 `for...of` 换成声明式的 `array.forEach` 等写法；组件函数是否遗漏了 `return`；返回的内容是否能合法地作为 JSX 的属性值或子节点使用。

表 2-1 汇总了两者差异。

表 2-1 JSX 与 HTML 的异同

| 特征 | HTML | JSX |
| :--- | :--- | :--- |
| 标签闭合 | 不严格，如 `<p>段落` | 严格，如 `<p> 段落 </p>` |
| 空标签闭合 | 无须闭合，如 `<br>`、`<img>` | 需要闭合，如 `<br />`、`<img />` |
| 单根元素 | 不限制 | 组件需返回单根元素，如 `<div></div>`、`<></>` |
| 属性值加引号 | 可选，如 `<input type=text size=10>` | 须加引号或者大括号，如 `<input type="text" size={10} />` |

| 属性名 | 不区分大小写，如onclick | 驼峰命名法，区分大小写，如onClick |
| 样式类属性名 | class | className |
| 样式属性值 | 字符串，如style="background-color: red;" | 对象，如style={{backgroundColor:'red'}} |
| <script>标签 | 支持 | 不支持（React 19以前版本） |
| JavaScript 表达式 | 不直接支持 | 在标签属性值或子元素位置使用大括号 { } |
| 注释 | <!-- xxx --> | {/* xxx */} |

### 2.2.1 声明式 VS 命令式
开篇已提到 React 是声明式且组件化的方案。声明式与命令式是两种对立的编程范式。表 2-2 从生活例子到具体代码做了系统对比。

表 2-2 前端开发中声明式与命令式的对比

| | 声明式 | 命令式 |
| --- | --- | --- |
| 现实世界用例 | 我希望大象在冰箱里。 | 一、打开冰箱门；二、把大象装到冰箱里；三、关上冰箱门。 |
| 代表性编程范式 | 函数式编程 | 面向对象编程 |
| 代表性后端技术 | SQL | Java |

### 2.2.2 JSX 最终生成的 React 元素
组件函数返回的是完整 JSX 结构。编译后每个节点都称为 React 元素，是应用最基础的构建单元。按类型可分为三类。

- React 封装的 HTML 或 SVG 元素，如 `<div></div>`、`<img />`，最终渲染为真实 DOM 节点。
- 组件渲染的元素，如 `<ThreadsPane />`，会触发对应组件的渲染逻辑。
- React Fragment 元素，`<React.Fragment></React.Fragment>` 或简写 `<></>`，不产生额外 DOM，仅用于分组。

Portal、Suspense 等类型暂不展开。

可为 JSX 元素添加 props 以区分类型，这里特意保留英文强调接口概念。

HTML 元素的 props 与原生 attributes 基本对应，差异前面已对比。

组件元素的 props 需与组件定义参数对应，未处理的 props 会被忽略。常见错误是修改了组件内部参数名，却未同步更新 JSX 中的传值，导致子组件拿不到预期数据。

Fragment 不支持额外 props。

除显式 props 外，若闭合标签内含有子节点，React 会自动生成隐式的 `children` prop。

谈到元素类型，也要区分子元素。JSX 元素可指定子元素。后续会多次提到“子组件”，需明确：子组件一定是子元素，子元素不一定是子组件。

子元素类型包括：
- 字符串，最终渲染为标签内文本；
- 另一段 JSX，会被嵌套渲染；
- JavaScript 表达式，渲染时执行并参与输出；
- 布尔值、null、undefined，不会渲染；
- 上述类型的数组。
