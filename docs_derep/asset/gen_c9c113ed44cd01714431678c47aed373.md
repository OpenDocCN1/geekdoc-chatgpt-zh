开放域抽取的开创者 TextRunner
`TextRunner`[\[10\]](#part0020.html#note_10) 由华盛顿大学图灵中心研发，是第一款落地的知识抽取系统，也是开放域知识抽取的早期代表。该系统能直接从网页文本中抽取出实体对与关系的三元组，并为每条结果给出置信度估计。

`TextRunner` 由三个核心模块构成\[6\]，介绍如下。

1）自监督学习器 Self-Supervised Learner：生成过程分两步。先对文本数据自动打标，区分正例与负例；再基于已标注数据训练一个朴素贝叶斯分类器，供后续抽取使用。整个过程无需人工标注。

2）单通道抽取器 Single-Pass Extractor：借助第一步得到的分类器在文本上进行三元组抽取。每条记录可能产生一个或多个候选三元组，经分类器筛选后保留被判定为可信的结果并写入数据库。

3）冗余度评价器 Redundancy-Based Assessor：抽取时 `TextRunner` 会把关系标准化，例如 `(company1, supplier, company2)` 与 `(company1, supply, company2)` 表示同一种供应商关系，系统会统一格式。随后利用网络文本的冗余性统计合并后相同三元组的出现次数，从而计算置信度。

4\. `ReVerb`
`ReVerb`[\[11\]](#part0020.html#note_11) 同样出自华盛顿大学图灵中心，是一款开放域知识抽取系统。为改善 `TextRunner` 易产生错误三元组和无效三元组的问题，`ReVerb` 增加了句法与词汇的约束。输入为分词并做词性标注的自然语言句子，输出为系统抽取的三元组。抽取分为两部分\[7\]。

1）关系抽取：针对句子中的每个动词，寻找从该动词开始的最长字符串，且需满足句法与词汇约束。句法约束要求关系短语为动词短语，且其后需跟介词、助词、名词短语之一。词汇约束要求关系短语必须在基于 Web 数据构建的词典库中出现。关系短语主要通过正则表达式匹配，作为后续步骤的候选。

2）实体抽取：在得到关系短语后，取距离该短语最近且位于左侧的名词短语作为候选实体，并过滤代词等干扰项；再取距离该短语最近且位于右侧的名词短语作为候选实体。若能找到实体对，则返回 `(候选实体1，关系，候选实体2)` 的三元组。

`ReVerb` 在抽取基础上手工编写特征，并为每个特征赋予置信度分数，符合该特征的三元组会被打上对应分数。通过逻辑回归分类器 Logistic Regression Classifier 实现特征赋分，从而在较少训练样本下提取三元组。

## 3.3　知识存储工具

图数据库强调关联，视数据间的联系与数据本身同等重要。基于图的建模具备天然的可扩展性，无需预先定义数据模型即可便捷存储。

数据互联、知识互联、万物互联成为大趋势，图数据库正顺应此潮流。传统关系型数据库处理关联操作需用表连接 JOIN，实时查询代价较高。图数据库则把关系与数据在物理层面一起存储，访问节点和关系可做到线性时间复杂度，甚至能在 1s 内遍历百万级边。

### 3.3.1　Neo4j
`Neo4j` 是一款热门的原生图数据库，由 `Java` 与 `Scala` 编写，于 2007 年发布。存储层实现属性图模型，采用指针方式构建与遍历图数据，并支持 `ACID` 事务。分为社区版与商业版，付费商业版提供备份、分布式、容灾等企业级服务。

主要特性如下。

* 大图遍历性能可观，基于高效的节点与关系表示及存储，可在常规硬件上存放亿级节点，并以线性时间复杂度完成广度优先或深度优先遍历。
* `Cypher`，专为图数据设计的声明式查询语言，类似 SQL。设有开源的 `openCypher` 项目。`Cypher` 支持多种复杂功能，因篇幅所限不展开，读者可查阅官方文档[\[4\]](#part0021.html#note_4)。
* 灵活的属性图数据模式，依托关系边连接数据，易于后期扩展，能适应业务需求变化，加速领域数据扩充。
* 数据库驱动支持多种热门编程语言，包括 `Java`、`Python`、`JavaScript`、`Go` 等。本文主要以 `Python` 为例说明，其他语言可参考官方文档[\[5\]](#part0021.html#note_5)。
* 支持 `ACID` 事务，保证操作正确与完整。

### 3.3.2　Neo4j 安装与部署
使用 `Neo4j` 进行知识存储前需先配置运行环境与 `Neo4j` 本身。

本书使用的版本为 3.5，需注意不同版本差异较大，特性支持存在差异，例如索引在 3.3 后变动明显。部分版本不支持向下兼容，旧数据库文件迁移到高版本时可能失败。此外，编程语言的数据库驱动版本应尽量与 `Neo4j` 版本匹配，否则易出错。

本节以 `Docker` 方式介绍安装部署，也是本书推荐的方法。基于 `Docker` 安装、部署、监控和管理都更便捷，尤其在多实例场景下。文中出现 `Docker` 指令时会作必要解释。`Docker` 安装与使用说明可参考官网[\[6\]](#part0021.html#note_6)，后文假设 `Docker` 环境已正常运行。`Neo4j` 支持主流平台 `Linux`、`Mac OS` 与 `Windows`，各平台具体安装方式难度不高，可按官方文档[\[7\]](#part0021.html#note_7)自行完成。

## 3. 端口映射
`Neo4j` 提供三个端口供外部接入：
