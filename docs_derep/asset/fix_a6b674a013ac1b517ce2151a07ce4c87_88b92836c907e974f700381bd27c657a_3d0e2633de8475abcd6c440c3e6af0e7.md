从零到上线：用智能助手把小程序做出来

即便没有专业的设计功底，也能借助智能编程助手做出贴合产品定位的高品质视觉。向 Cursor 输入一条明确要求：“做一款极具现代感的小程序，采用毛玻璃拟态，整体配色以紫色渐变为核心。”工具几乎是即时响应，不仅输出完整的 WXML 结构，还自动产出复杂度较高的 WXSS 样式。成品具备良好的响应能力，在 iPhone、安卓手机、iPad 上都能自然适配，这种表现手写代码很难在同等时间内达到。

#### （2）以智能模型打磨推荐能力
推荐模块是这类项目的灵魂，也是竞争壁垒所在。可以接入千问接口与字节跳动的豆包接口，利用大语言模型的泛化优势，从海量网络信息中筛选非标准化旅游内容。落地时借助 Cursor 搭建 Express 后端，并让助手参与 RESTful 接口的设计。当前运行方式是用户点一下定位，后端自动拼装提示词发给大模型，模型返回结构化 JSON，前端再进行可视化呈现。

#### （3）把运维与部署自动化
服务器部署对技术门外汉过去是拦路虎，现在基本被智能工具平滑掉。它可以协助撰写自动化部署脚本 deploy.sh，配置 Nginx 反向代理，甚至完成 SSL 证书的申请与自动续期逻辑。使用者只需要告知服务器 IP 与账号，后续的配置工作基本由助手独立完成。

4. 常见坑位与规避思路
智能工具能让开发效率提升约十倍，但调教不当很容易踩雷。

#### （1）规避经验一：破解大模型的地理幻觉
大模型对距离感知存在偏差。不要指望模型自行理解地理限制，必须在提示词里写入硬性规则。比如把指令改成“出发地为 ${city}，只能推荐 200 公里以内的景点；若为天津，仅限蓟州、宝坻、河北廊坊等周边，并且描述要带具体区县”。这样就能根治问题。

#### （2）规避经验二：拒绝一次性全量生成，坚持增量推进
曾尝试让 Cursor 一次输出“收藏+搜索+地图”的复杂模块，结果逻辑混乱报错频繁。应坚守 KISS 原则，每次只完成一件事。把整体拆成定位、模型接口对接、界面优化三个阶段，每个小块验证通过再进入下一步。增量式推进是避免产生冗余代码的关键。

#### （3）规避经验三：重视权限与环境细节
微信小程序的 wx.getLocation 接口需要繁琐的权限声明，早期生成的代码一直报错，根因是 app.json 中缺失 requiredBackgroundModes 字段。遇到权限类问题，最好要求助手查阅微信开发者最新的官方文档。模型很强，但训练数据可能滞后，必须明确指令让它遵循最新规范。

#### 3. 避坑经验
第一，拒绝模糊指令。早期让助手“把复杂模块拆成微服务”，出现幻觉机械搬移代码导致依赖断裂项目崩溃。后来改用链式思维，把大任务拆成原子级小任务，先分析依赖关系再设计接口最后写逻辑，每次只让助手执行单一原子任务。

第二，小步快跑持续验证。切勿期望助手一次性生成两千行代码直接运行。做法是先生成核心业务逻辑测试通过，再添加界面细节，最后处理异常捕获。增量开发大幅减少调试痛苦。

第三，人工审查是最后防线。助手易在边缘情况出错。俊哥担任审查官角色，助手负责执行，他负责风险控制与纠错。
