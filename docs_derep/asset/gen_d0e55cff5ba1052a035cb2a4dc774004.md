在 LangGraph 的设计里，只要能独立执行一段逻辑的单元就被归类为节点，涵盖大模型推理、外部检索、条件分支等各种操作。流程的入口通常是 Start 节点，它先收敛用户输入，再按需求分发任务，基本走向是：

- 1）先调用 Action 类型的节点去做外部查询，比如 Web 搜索、数据库读取或 RAG 检索；
- 2）把查到的信息送给负责语言建模的 LLM 节点，让它生成自然语言回复；
- 3）把最终的回复交给 End 节点，结束整个链路。

如图 8.13 所示，这就是用 LangGraph 概念搭建的最小 Agent 雏形。每个圆圈都是一个节点，每条连线都是边，用来规定执行顺序；状态则是通过消息沿边流动并不断更新的。

于是无论 Agent 多复杂，本质上都是若干节点和边按特定方式组合而成的图。工作流的核心机制是消息传递：一个节点完成自己的任务后，会通过边把信息推送给下一个节点，后者收到消息后执行、再把结果继续传下去，如此循环。通俗地说，LangGraph 底层的消息分发算法让程序呈现出一种通用的执行模式：节点完成操作即向相连节点发送消息，被动方收到后处理并转发，最终形成闭环。

在 LangGraph 框架中，Router 以 if-else 的形式决定路径，主要有三种实现手段。

- 提示工程：通过指令让大模型以约定格式回应；
- 输出解析器：对模型返回做后处理，抽取出结构化数据；
- 工具调用：借助大模型的内置工具调用能力生成结构化输出。

##### 4. 共享状态机制
我们已经知道 LangGraph 用节点和边组合出复杂的循环流程，并靠消息传递把各个节点串联起来。让消息及时更新并送到正确位置的，则是 State 这一概念。每次运行都会创建一份状态，节点在处理时读取并修改它。该状态不是静态的快照，而是被各节点输出动态改写，进而影响循环中的后续行为，如图 8.15 所示。

共享状态指的是图执行期间节点间传递的数据与信息。LangGraph 允许节点在执行时读写同一个公共状态来交互。这种机制让节点能够基于共同维护的数据通信、交换信息并互相影响，从而实现操作的协调与同步，支撑动态交互和复杂工作流的构建，节点可以依据已有的共享信息协同决策。

##### 5. 官方对 LangGraph 的定位与优势归纳
按官方说法，LangGraph 是一个用于构建有状态、多参与者的大模型应用的库，可用来创建 Agent 与多 Agent 工作流。官方归纳的优势如下。

- 循环与分支：可在应用中实现循环和条件判断；
- 持久化：每个步骤执行后自动保存状态，支持随时暂停恢复，用于错误恢复、人机协作流程、时间旅行等；
- 人机交互：可在执行中中断以便人工批准或编辑 Agent 下一步计划；
- 流式输出：各节点均可产生流式输出，包括 token 流；
- 与 LangChain 集成：与 LangChain 及 LangSmith 无缝衔接。
