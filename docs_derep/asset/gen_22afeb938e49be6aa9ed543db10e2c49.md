RAG 常踩的四个坑

落地 RAG 时，理想很丰满，现实常打脸。基础 RAG 在实战里普遍会遇到这几类硬伤。

（1） 相关性错位。向量搜索有时会把表面相似却与问题无关的文档排在前面，而真正含答案的材料反而被挤下去。应对思路是先让大模型根据查询先猜一个初步假设，再把原始查询和假设一起做嵌入去检索，可以显著提升召回的精准度。

（2） 相似度被文本长度稀释。长文本里虽有目标信息，由于整体向量被稀释，相似得分常不如短小无关的片段，最终排序失真。做法是做合理的文本切分，每块控制在数段以内，让单块信息更集中、更具辨识度。

（3） 汇总类问题无解。RAG 只擅长点查，当用户需要跨库统计、聚合或综合推导时，单纯靠相似检索很难拼出完整结论。因为相似搜索擅长找单个命中文档，却不擅长把分散在多份材料里的信息合起来。

（4） 顺序感知偏差。检索后按相似度排序送入大模型时，人类会更关注列表前几位，而模型注意力往往集中在首尾，对中间位置的内容容易忽略。缓解办法是重排策略：把高相关文档交替放在开头和结尾，相关度低的放到中间，以免被模型“跳过”。

4． 让基础 RAG 更准的实战技巧
光靠原生 RAG 往往达不到业务要求，需要在检索和表示上做增强。

（1） 查询优化。常用的两招是重写与扩展。查询重写用于纠正错别字、把复杂问题拆成若干子问题，使表达更适合检索。查询扩展则在原问题基础上生成多角度的改写问法，分别检索后再合并结果，覆盖面更广。

（2） 重排序。先用快速检索宽松召回 Top-100 左右的候选，再用计算成本高但更精准的模型比如 Cross-Encoder 对候选做二次打分，挑出最终的 Top-k。这种方式在查询扩展场景下提升尤其明显。

（3） 嵌入模型微调。通用嵌入模型在医疗、法律等专业领域效果有限。利用行业语料对嵌入模型做领域微调，能大幅改善向量相关性，让检索结果更贴合业务语言。

4.2.2　向量数据库
向量数据库本质上是可随时增删改查的嵌入集合，用数值向量来表征文本、图像等数据块。

1． 什么是向量
向量是 n 个实数构成的有序数组 v = (v[1], …, v[n])，可视作 n 维空间中的点或方向。实际使用中它是一串数字，如 {1,2,3,4,5}。在向量库里，每个向量对应一个对象，维度可达数十到上百维，能刻画电影的时长、类型、年份等多种属性，使相似对象在空间中自然聚类。传统关系库靠精确匹配，向量库靠相似度度量和近似最近邻 ANN 搜索来找最接近的匹配。

2． 典型使用场景
相似与语义搜索：把相关项目聚在一起，支撑图像搜索、商品推荐、音乐/影视推荐等。
机器学习与深度学习：通过关联相关信息构建复杂认知任务模型。
大模型与生成式 AI：借助向量库做上下文关联，帮助大模型理解自然语言并生成文本。

4.2.3　嵌入模型
嵌入模型负责把文本、图像、图表、视频等映射为数值向量，捕捉多维语义差异。模型选择需权衡语义深度、计算效率、数据类型和向量维度。通过语义相似度分析，可显著提升搜索与分类效果，在聊天机器人、大模型、RAG 和向量库等场景中起核心作用。

1． 嵌入模型如何与向量数据库搭配使用
私有数据先被切块并生成向量，和原始块、元数据一并写入向量库。用户提问时，系统用嵌入模型把查询转成向量，在库中做语义搜索，取出 Top-k 的向量及其数据块作为上下文送给大模型。

4.2.4　重排序器
标准 RAG 的首轮检索会带回大量质量参差的文档，重排序器就是在检索与生成之间加的精细过滤层，通过更深层的查询-文档理解对结果重排，让大模型优先看到最相关的材料。

1． 重排序器的作用
向量检索高效但有三点瓶颈：面对短句、模糊或专业术语时语义理解不足；为提升召回而扩大结果集会引入大量噪声，降低精确率；把所有文档塞进上下文既受窗口限制也增加成本。重排序器的核心目标是在保持高召回前提下，把精确率拉满。

2． 重排序器如何工作
典型增强流程分三步：初始检索先广撒网，用向量、关键词 BM25 或混合检索召回 Top-100 左右的候选，保证不漏；精细化重排序由交叉编码器等模型对每个候选做深度打分并重排；高质量生成只取重排后 Top-3~Top-5 作为净化上下文送入大模型生成答案。

4.3　RAG 框架
随着复杂 AI 需求增长，开源 RAG 框架蓬勃发展，各自在检索策略、模型集成和应用场景上各有侧重。

4.3.1　RAGFlow 框架
RAGFlow 是面向深度文档理解的企业级开源框架，强调开箱即用的文档中心方案。其优势在于高精度解析非结构化文档：利用视觉解析技术识别 PDF、Word、扫描件、图片中的复杂版式、跨页表格和合并单元格，实现高保真结构化。切片阶段提供通用、问答、法律文书等模板化策略，保证可控可解释。检索生成阶段支持多路召回与融合重排，答案可附原文快照溯源，降低幻觉。还提供可视化拖拽式工作流编排，兼容多种大模型和向量库，易于 API 集成。

4.3.2　LlamaIndex 框架
LlamaIndex 遵循“索引即抽象”理念，定位为大模型与外部数据的智能连接层。它引入“节点”概念，把文档解析成语义连贯并保留元数据和上下文的单元，并提供可组合的索引结构：单一向量索引、关键词索引、树状索引与底层向量索引的复合等，以适配不同数据类型和查询模式。查询引擎支持重写、检索、重排和生成等多步编排，并推动向推理式检索发展，智能体可自主多轮检索整合。框架还支持多模态，模块化程度高，可接入主流向量库、大模型和重排序器。

4.3.3　Haystack 框架
Haystack 是面向生产级 RAG 的开源框架，采用模块化流水线设计。文档处理阶段内置 PDF、DOCX 解析与智能分块向量化。检索阶段提供关键词、语义及混合检索。生成阶段把相关文档作为上下文送入生成器，减少幻觉。Haystack 2.0 引入智能体，可主动调用检索流水线完成复杂问答。框架扩展性强，支持 Elasticsearch、FAISS 等向量库，并提供监控与评估工具。

4.3.4　LangChain 框架
