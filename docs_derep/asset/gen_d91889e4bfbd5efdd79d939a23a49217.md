VxWorks 需要按授权收费，是一款成熟的高实时商用系统，开发工具链完善，源码可裁剪定制，安全稳定度很高，已在卫星控制系统、导弹、国际空间站等重大航天项目中多次验证。

Linux 是一种可自由使用传播的类 UNIX 系统。可移植性好、开源免费、可定制、高可靠和高安全性，使其在航天领域应用广泛，例如 2021 年美国发射的火星车就运行在 Linux 上。

RTEMS 是面向嵌入式系统设计的开源实时操作系统，代码质量和可靠性都很突出。最早服务于美国国防系统，目前由 OAR 公司负责迭代维护，在航空航天、军工和民用领域都有大量落地。

μC/OS-Ⅱ 是一种基于优先级的抢占式多任务实时系统。各任务独立运行互不干涉，能准时无误执行，让实时应用的设计与扩展更简单。它已通过美国国家航空航天局认证，可用于飞行器、太空站等关键系统开发。

eCos 是一种嵌入式可配置实时操作系统，完全开放源代码且无版权费用，可配置性强，代码量非常小，通常在几十到几百千字节，可支持众多处理器与平台，主要面向车载、手持等低成本便携式场景，在国内星载计算机上已有初步应用。

总体来看，卫星操作系统要具备高稳定性与实时性、良好可移植性、开源可裁剪、丰富的开发工具、代码可固化、弱交互性以及统一接口等特征。传统星载操作系统以单星为主，用来完成单颗卫星的星务管理、数据处理、姿态和载荷控制，是长期稳定运行的基础，发展主线长期围绕单星单 CPU 展开。

### 5. 发展启示

对比不同场景操作系统的演进轨迹，可以提炼出以下规律：

① 精准匹配应用需求是操作系统发展的典型路径，新场景的出现会催生全新系统，开发者对场景的认知牵引着系统演化。

② 操作系统是复杂系统的信息基座，满足复杂场景应用需求的必然选择。

③ 生态是操作系统成功的关键，需要行业共同投入才能产生乘数效应。

④ 一款操作系统只有对应特定硬件架构，才能实现最优性价比并形成软硬件共赢生态。例如个人电脑时代 Windows 对应 80×86，移动互联网时代 Android 对应 ARM。

⑤ 微内核架构因安全性、容错性、可移植性等优势，已成为谷歌、华为等头部企业下一代万物智联操作系统的内核主流。

⑥ 操作系统是大型基础软件，研发投入巨大、失败率高，最终能成功的往往是所属大国的行业头部企业，带有鲜明的国家意志。

## 11.1.3 巨星座操作系统发展思路

基于上述分析，面向我国巨星座的高效管控与智能应用需求，巨星座操作系统的研发需要围绕架构定义、硬件载体、内核设计、安全可信和生态建设展开。

### 1. 架构定义

架构定义涵盖需求、层次结构、功能结构、层间接口、内核架构、协议架构、安全架构，是研制核心基础也是难点。必须先研究面向万颗级巨星座节点海量硬件资源管理以及巨量智能应用快速部署的架构定义，实现资源网格化抽象与管理，支撑千颗级场景下的“即时聚优”和“多域联合”等功能。

以巨星座操作系统统筹系统资源、任务应用为主线，构建开放架构，开发应用框架，推动各层采用标准接口，便于节点互联互通、硬件软件移植重用、新技术快速转化。以此细化协议架构与安全架构，完成体系架构设计。

面向应用场景持续演进，采用层次化设计，精细定义各层功能结构，选用“微内核+系统服务+应用框架+行为管控”架构。微内核负责线程/进程通信、内存地址空间、中断等基础管理；系统服务即外核，负责路由控制、移动性管理、虚拟协同计算、APP 动态加载；应用框架面向通信、导航、遥感等多类型空间任务，采用模块化定制化设计，具备规模可伸缩、功能可裁剪特点；行为管控基于博伊德 OO-DA 观察-分析-决策-行动循环模型，实现群体自主智能。

### 2. 硬件载体

星载计算机是巨星座功能实现的硬件基础，中枢是 CPU，直接决定操作系统应用能力。选型需考虑性能、功耗、太空环境适应性、对外通信接口以及操作系统支持度。主流星载处理器包括 80×86、MIL-STD-1750A、PowerPC、SPARC、MIPS、ARM 等系列。

80×86 因高安全稳定在航天领域应用广泛；MIL-STD-1750A 为 16 位非精简指令集，我国风云系列卫星星载计算机采用该架构的处理器；PowerPC 兼具高性能低功耗，NASA 多采用该架构；SPARC 为精简指令集，质量等级高、运算能力强、功耗适中，我国 BM3803、BM3823、S698 等 SPARC 抗辐照 CPU 已实现量产；MIPS 为精简指令集，中科院研发的“龙芯”采用 MIPS 架构，部分高可靠性芯片已在国内卫星中应用；ARM 外围接口丰富、可扩展性强，搭载操作系统后在星务管理、数据处理上性能突出，ARM+操作系统的技术路线已成国内外研究热点。

受空间环境特殊性和电子技术水平制约，星载计算机性能相比地面落后数代，是制约星载操作系统发展的关键因素。设计时需重点考虑轻量化、运行效率、可靠性、稳定性。操作系统最优性能与适配的 CPU 架构紧密相关，需结合国内星载 CPU 发展现状合理选择架构，构建软硬件互惠生态。

### 3. 内核设计

巨星座操作系统内核负责星上资源与任务的抽象管理。应用场景带来三重挑战：一是单星节点硬件资源强受限且异构，需要内核轻量化和异构资源灵活管控；二是多星任务高效协同，需要低时延能力；三是太空辐射易导致软件错误，需要高效容错机制。

卫星运行于空间辐照环境，易受宇宙射线影响，操作系统作为核心基础设施，其抗单粒子翻转的稳定性至关重要。宏内核中任何程序可访问全部内存和内核数据，一个错误就可能导致系统崩溃。微内核中模块间独立隔离，即使受辐射出错也能保持稳定运行。微内核的模块化可裁剪特性也契合天基信息系统资源受限需求。

针对资源受限异构、多星即时协同、空间辐照高效容错三大需求，采用微内核架构，研究内核轻量化、低时延、强容错关键技术，突破异构墙、时延墙、容错墙，设计完全自主可控、高效灵活管控海量异构星载资源的安全实时内核，充分发挥硬件能力、降低软件开销、以低代价增强容错与运行效能。

### 4. 安全可信

安全可信是巨星座稳定运行的基础。通过研究“云-边-端”分布式协同架构、多维资源管理、系统链路安全、空间数据防护、接入认证等关键技术，建立基于可信计算的双体系分布式安全可信机制，构建可靠运行环境，形成自主创新的主动免疫三重防护框架，设计安全组件保障操作系统的安全可信能力。

在保证时效性前提下，基于操作系统、一体化融合网络、计算平台控制平面、高可靠共享数据存储、集成化软件加载控制器，构建支持在轨部署升级、星载应用软件实时更新和动态加载的体系架构，保障应用软件安全稳定运行与功能更新。

作为系统安全基座，巨星座操作系统依托“云-边-端”分布式安全可信机制，构建“芯片-链路-数据-应用”全链路安全可信体系，保障系统整体可信与安全。

### 5. 生态建设

巨星座操作系统是面向复杂应用场景的统一基础软件平台，将推动航天软件从专用闭源定制向标准开源通用转变。随着系统复杂度提升和开放程度增大，用户与开发者群体扩大，形成开放、开源、自主可控的航天软件生态体系。

围绕生态模式、社区规划、运行机制、管理机制等需求，构建研发资源数据库和数据采集分析工具。定义多维度评价指标，设计用户画像与项目画像系统，为基于巨星座操作系统的软件资源汇聚与共享提供支撑。

## 2. 高效内核关键技术

内核是巨星座操作系统的基础，对下管控硬件，对上提供抽象，负责资源管理与任务调度。面向复杂场景，内核需满足轻量化、低时延、强容错需求。

按内核结构，操作系统可分为宏内核、简要结构、外核、微内核。

### 1）简要结构操作系统

应用程序与操作系统运行在同一特权级别和地址空间，面向不支持地址空间或特权隔离的嵌入式设备及单程序场景。交互简单快速，但错误会直接导致系统崩溃，缺乏可持续演进能力，异构星载硬件扩展性差。

### 2）外核结构操作系统

通过把硬件抽象封装到与应用程序直接链接的库操作系统中，库操作系统由开发者自主配置或开发。运行时库操作系统与应用同地址空间用户态运行，外核仅保证多应用安全高效共享硬件资源。面对复杂场景，库操作系统会变得复杂甚至等同完整宏内核，丧失外核优势。

### 3）宏内核结构操作系统

整个操作系统运行在内核态且同一地址空间，文件系统、网络栈、硬件驱动、进程管理等均运行在特权内核态。优势是生态良好，但缺乏系统隔离，安全可靠不足，难以形式化验证。

### 4）微内核结构操作系统

包含运行在内核态的微核和运行在用户态的若干功能模块如文件系统、网络协议栈、硬件驱动。微核代码量少，主要支撑上层服务运行并提供服务间通信机制；不同服务运行在用户态不同地址空间彼此隔离，通过微核通信协同。优势是容错性和安全性更好，服务故障不会直接导致系统崩溃，且便于为不同场景定制服务以适应需求。

综合巨星座任务需求，选用全自主研发微内核路线，在轻量化、可控时延、运行效率、可靠性、安全性和扩展性以及自主软件生态构建方面优势明显，满足复杂应用场景需求。

## 3. 融合组网关键技术

节点互联互通、灵活组网是实现巨星座高效管理与智能应用的基础。巨星座空间网络复杂、规模巨大、高动态拓扑、故障难预测，对实时性与可靠性带来挑战，需结合操作系统内核优化网络设计。

采用 SDN 软件定义网络作为基本路线，结合分级管控与分域管控。分级管控提升对单个网络的可管控规模，分域管控把大网划分为相对独立小网，二者结合可实现万颗级以上卫星的实时高效鲁棒管控。

分域管控把万颗级以上卫星划分为多个相对独立的网络域，分而治之，域间内部信息不干扰，仅提供抽象层面的路由与协作接口，可指数级降低节点规模对整体管控的可扩展性压力。

面向万颗级节点管控需求，卫星网络按星座功能与轨道特征划分。先按功能划分为遥感、通信、气象、导航等星座，再对规模较大的星座按相对稳定的组网结构划分为更小网域，如一个轨道面划为一个网域。一般一个网域规模不超过 200 个节点。
