#### 8.1.9 从 LangChain 平滑迈向 LangGraph
LangChain 在 2023 年便形成了活跃的社区规范。现已发布多个大版本，体系中 RAG 与 AI Agent 是两大支柱。LangChain 下的 Agent 底层架构如图8.12所示。

[PRE13]

Agent 设计在内部拆分为 Agent、Message 与 Toolkits 三大要素。每个 Agent 通常由大模型+提示+输出解析器构成 Chain 处理用户输入。输入来源有三类：Input 为用户原始提问，Model Response 为子任务的模型响应，Context 承载上下文信息。Agent 的输出会连向工具库，具体调用哪些工具由 Agent 拆分后的子任务决定。大模型调用外部函数包含识别工具与实际执行两步。Messages→AI Agent→Toolkits 的流程负责拆解子任务、定位工具并提取名称与参数，可视作“静态”执行流程；把决策落实为行动则交由 AgentExecutor 完成。

总体而言，LangChain 的 Agent 只负责接收输入并决定操作，不直接执行，执行由 AgentExecutor 承担。只有 Agent 与 AgentExecutor 配合，才能构成完整 Agent，其中 AgentExecutor 负责调用 Agent 并执行其指定的工具。

LangChain 仍是构建 LLM 应用的前沿框架。v0.3 版本已基本完成从传统类到 LCEL 的迁移，让分步操作序列的定义与执行更简洁高效。专业上看，LangChain 构建的是有向无环图 DAG。随着 AI 应用尤其是 Agent 的发展，LLM 用途正从执行工具转向复杂推理引擎，这正是 LangGraph 诞生的原因。该转变对循环结构与复杂条件交互提出更高需求，使得基于 LCEL 的线性序列在构建更高级系统时逐渐受限。
