WebSocket 连接建立后，客户端发出的首个数据帧必须是 connect 请求。网关若启用了 OPENCLAW_GATEWAY_TOKEN 鉴权，握手帧里就必须携带该令牌，否则网关会立刻终止连接，直接拒掉所有未授权的接入请求。

2．消息类型体系

OpenClaw 的 WebSocket 通信建立在三类基础消息之上，构成了客户端与网关之间完整的语义闭环。

• 请求消息：由客户端向网关发起，结构为 {type:"req", id, method, params}。type 固定为 req，其余字段按具体调用而定，主要用于触发网关提供的各类 RPC 服务。
• 响应消息：网关对请求的直接回执，结构为 {type:"res", id, ok, payload|error}。用于返回调用的成功结果或详细的错误信息。
• 事件消息：网关主动推送的单向流，结构为 {type:"event", event, payload, seq, stateVersion}。是状态实时同步和打字机式输出效果的实现基础。

3．核心 RPC 方法

网关对外暴露的一组 RPC 接口是客户端操控的核心能力集合。

• connect：握手必备，连接初建时客户端调用并声明身份信息。
• health：健康检查，用于获取网关运行状态和版本信息。
• agent/send：对话交互入口，触发一次完整的 Agent Loop；send 变体可在不启动推理循环的前提下向指定会话静默发送消息。
• sessions.list / sessions.history：会话管理，分别列出当前活跃会话和查询指定会话的历史记录。
• config.get / config.apply：运维接口，读取当前配置并支持热更新。
• cron.add / cron.remove 和 pairing.list / pairing.approve：扩展能力，前者动态增删定时任务，后者处理跨设备节点的配对申请。

4．核心事件类型

网关会向已订阅的客户端推送以下关键事件，实现实时同步。

• tick：心跳，用于探测连接是否存活，维持链路稳定。
• agent：Agent 运行状态推送，包含空闲、思考中、调用工具中、流式输出中等状态及 Token 消耗统计。
• delta：流式文本片段，模型生成过程中持续下发，用以还原打字机效果。
• tool-call：工具调用前置通知，告知客户端即将调用的工具及参数。
• tool-result：工具执行结果返回，携带最终输出。
• presence：节点在线状态广播，实时反映各 Node 的上下线变化。
• message：新消息到达通知，推送会话中新消息的到来。

6．节点的特殊角色

节点在握手时需声明 role: "node"。它兼具客户端与能力提供者的双重身份。

一方面作为客户端与网关保持 WebSocket 连接，接收指令；另一方面在连接时向网关注册自身具备的物理能力，如 canvas.* 渲染画布、camera.* 访问摄像头、location.get 获取地理位置、system.run 执行本地命令等。网关会把这些能力统一抽象为 Agent 可调用的工具，指令经网关路由到对应节点执行，结果再回传给 Agent。

## 3.2 感知与执行的“触手”

如果说 Gateway 是 OpenClaw 的大脑，Node 就是延伸到物理世界和各设备的触手。Node 让 OpenClaw 跳出单一服务器的虚拟环境。

核心设计哲学是：Agent 的能力边界与所连设备的能力边界完全一致。服务器只能提供服务器能力，连接上手机后，AI 就获得了手机的“眼睛”和“耳朵”。

3.2.1 将设备物理能力转化为 AI 工具

Node 体现的能力虚拟化思想，是把分散在各设备的硬件特性聚合成标准 AI 工具供 Agent 调度。

1．Node 的类型

目前主要支持四类节点：

• macOS Node：通常以菜单栏应用运行，提供屏幕录制、摄像头、system.run 本地命令执行及 Canvas 渲染能力。
• iOS Node：运行在 iPhone/iPad 的伴侣应用，提供实时 GPS、摄像头拍照录像及系统级通知。
• 无头节点 Headless Node：部署于 Linux 或 macOS 服务器，提供远程命令执行与底层文件访问。
• 浏览器节点 Browser Node：以 Chrome 扩展存在，赋予 AI 深度操控浏览器、DOM 操作及网页截图的视觉感知能力。

2．能力虚拟化的工作流程

从设备能力到 AI 工具的转化共分五步，网关承担统一路由与管理。

第1步：节点注册
Node 连接时在 connect 握手中上报自身命令集，例如：
{
"type": "req",
"method": "connect",
"params": {
"role": "node",
"id": "iphone-pro",
"platform": "iOS",
"caps": ["camera.take_photo", "camera.record_video", "location.get", "system.notify"]
}
}

第2步：工具映射
网关收到注册信息后，将节点命令动态映射为 Agent 可用工具，直接加入工具列表，Agent 无需关心实现位置。

第3步：Agent 工具调用
当用户指令需要摄像头时，Agent 生成工具调用请求，例如：
{
"tool": "nodes",
"action": "camera_snap",
"node": "iphone-pro"
}

第4步：路由与执行
网关查询能力注册表，将指令通过 WebSocket 下发至 iphone-pro 节点。节点调用 iOS AVFoundation 拍摄照片，并把图片数据回传网关。

第5步：结果反馈
网关把照片交给 Agent，后续可调用图像分析工具解析内容，并以自然语言回复用户。

由此形成大脑在云端、眼睛在手机、手在 Mac 的分布式协同。Node 虚拟化接入网关为用户提供服务的整体交互流程如图 3-3 所示。

3．Node 工具的完整能力

内置的 node 工具为所有在线节点提供统一接口，覆盖设备发现与管理、配对管理、系统交互、多媒体/传感器访问、设备监控五大维度。

• 设备发现与管理：status 查看实时状态，describe 获取详细信息。
• 配对管理：pending 查看待配对请求，approve 批准，reject 拒绝。
• 系统交互：notify 向 macOS 节点推送系统通知，run 在远程节点执行 Shell 命令并可指定工作目录、环境变量与超时。
• 多媒体和传感器访问：camera_list 枚举摄像头，camera_snap 拍照，camera_clip 录像，screen_record 屏幕录制，location_get 获取带经纬度、精度和时间戳的 GPS 坐标。
• 设备状态监控：device_status、device_permissions 等用于监控健康与权限。

3.2.2 安全的远程调用与连接机制

Node 常运行在移动设备上并处于不同网络环境，连接安全至关重要。

1．设备配对
全新 Node 首次连接时需在握手阶段提供设备 ID 和平台元数据。网关识别为未知设备后拒绝连接并生成待审批配对请求，同时通过事件总线向已连接管理客户端推送通知。用户需在控制端手动审批，获批后网关签发强加密的持久化设备令牌并写入白名单，后续连接必须携带该令牌。

2．签名与防重放攻击
握手时网关发送随机挑战码 Nonce，Node 需用私钥签名并随 connect 请求返回。可防止中间人与重放攻击。签名负载绑定平台信息和设备家族，网关首次配对时记录。若后续指纹变化，连接将被拒绝并要求重新配对。

3．节点命令的权限控制
配对成功后仍需权限管控。gateway.nodes.allowCommands 与 gateway.nodes.denyCommands 可精确限制可执行命令。高风险命令如 camera.*、screen.*、contacts.*、calendar.*、system.run 被标记为 gateway.nodes.allow_commands_dangerous，需管理员显式授权。

4．通过 Tailscale 实现安全的跨网络连接
当 Node 与网关不在同一物理网络时，推荐使用 Tailscale 构建 WireGuard 加密隧道。通信端到端加密，公共网络下亦不易窃听；身份验证机制确保只有授权设备可加入专属 Tailnet，提供网络层额外保障。

## 3.3 智能体的“心跳”

1．接收与排队
用户发送消息后，网关先解析目标 Session。为避免并发竞争，采用命令队列机制：每个 Session 拥有独立 FIFO 队列，新请求入队等待。网关立即返回 runId 与 acceptedAt 时间戳，表示任务已受理。

2．上下文组装
该阶段整合多源数据并标准化。

首先进行工作空间准备，定位 Agent 工作目录并加载配置文件。随后是技能加载，扫描 skills/ 目录下的 SKILL.md，将人类可读指令转译为大模型可理解的 JSON Schema。

对话上下文处理时，从持久化存储提取近期历史，结合历史限制与 Token 预算智能裁剪。接着构建系统提示词，融合基础设定、用户画像、Agent 性格等多维信息；同时按工具策略生成可用工具列表并格式化为模型 API 规范。
