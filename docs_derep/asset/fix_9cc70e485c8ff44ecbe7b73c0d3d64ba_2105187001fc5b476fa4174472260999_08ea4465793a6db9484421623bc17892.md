意图驱动创作：公文写作智能体需求生成链路拆解

在 1-B 无参考稿的分支里，意图归类组件是把用户诉求与专业知识库桥接起来的枢纽。它先判断这次要产出哪一类文稿，例如工作规划、调研报告或年度小结，随后调起对应的知识体，让后续生成的创作需求既贴合提问意图，又具备专业指向。

**（1）组件概览：接口与配置思路**
该组件依赖大模型的语义解析能力完成意图自动归类，为后续选库与需求生成提供确定依据。

接入侧通常取 sys.query 作为载体，文本类型，即用户提出的作稿请求，比如“我是智能体研发工程师，需要写 2025 年 Q3 的季度规划”。输出侧给出预设的类目标签，同样为文本，例如工作规划、调研报告、年度小结，用以刻画需求的核心类型。

配置可从三点入手。首先选用语义理解强的基座模型，如 Qwen2.5，让它捕捉请求中的指示词“规划”“报告”“总结”等完成归类。其次提前固化类目体系，把可用标签列清，模型才能规范作答。再次可在高级设置里加入自定义规则，比如出现“季度目标”“资源分配”这类词就归入工作规划，以提升判准率。

举例来讲，用户输入“生成 2025 年 Q3 智能体研发工程师季度规划”，组件会调用 Qwen2.5 做分析，判定为工作规划类，输出 class_name:"工作计划"，为下一步调用工作计划知识体做准备。图 3-24 为问题分类组件的配置面板，用户可灵活调整类目选项与输出变量名。

3.变量聚合组件：多分支结果的统一收敛
在 1-B“依托知识库生成创作需求”的流程里，用户意图可能同时触发工作规划、调研报告、年度小结等多个并行分支，每个分支对应不同的知识库和模型配置。变量聚合组件的价值在于把这些分支产出的分散变量收敛为统一变量，让后续如迭代创作组件能直接调用，避免为每个分支重复配置逻辑，从而提升协作效率和运行稳定性。

**（1）功能定位：接口与收敛逻辑**
该组件核心是把多源变量整合成标准化的单一变量，关键在于保证数据类型一致，简化下游调用。

它负责接收 1-B 中各分支输出的创作需求变量，每个变量一般是 JSON 格式，包含标题、大纲、字数等结构化字段。组件可把它们聚合成一个统一变量，也可按需分组为多组同类型变量，为下游如迭代创作或模板转换组件提供单一入口，降低分支增多带来的逻辑冗余和维护成本。

输入端接收各分支的分散变量，例如工作规划分支输出 plan_content，JSON 格式含季度规划的标题、大纲、字数；调研报告分支输出 report_content，结构相同；年度小结分支输出 summary_content。输出通常为聚合后的单一变量如 grouped_content，格式与输入保持一致，囊括所有分支的需求信息。也可开启聚合分组功能，按业务逻辑划分为多组，例如业务文档组和总结文档组，但组内变量类型必须一致。

**（2）配置要点：类型与分组规则**
图 3-26 为变量聚合组件的配置界面。配置要严格遵循同类型聚合原则，否则会整合失败。

首先，所有待聚合变量必须数据类型完全相同。比如各分支都输出含 title、outline、count_num 字段的 JSON 对象就能直接聚合；若某分支是纯文本字符串，需先通过代码组件转成统一 JSON 格式再参与聚合，否则报错。

其次，可开启聚合分组，按业务逻辑分组。例如把工作规划和调研报告归入业务类文档组，年度小结归入总结类文档组。分组后每组内部仍需类型一致。该功能适合需要同时生成季度规划、市场调研、年度小结等多类型文档的复杂并行场景。

合理配置后，系统能有效整合多分支输出，保证数据一致性和可用性，为后续自动化处理提供清晰高效的输入。

4.条件组件：工作流的逻辑控制中枢
在公文写作专家智能体里，条件组件是流程分支的决策者。根据用户是否上传参考稿等变量状态，自动导向功能模块 1-A（已上传参考稿时的需求生成）或功能模块 1-B（未上传参考稿时的需求生成），是实现多场景自适应和全流程自动化的关键控制单元。

**（1）组件概览：接口与分支逻辑**
核心机制是基于变量状态做分支判断，通过 IF-Else 等逻辑实现精准控制。

输入一般是变量状态值，例如开始节点定义的 example 变量，用于存放用户上传的参考稿模板是否为空。输出是分支执行指令：若满足 IF 条件如 example 不为空，说明用户已上传参考稿，则进入功能模块 1-A 执行文档提取与大模型分析；若满足 Else 条件如 example 为空，则转向功能模块 1-B 触发知识库检索、问题分类、变量聚合等流程。

配置上先设定 IF 分支，例如 example 非空时执行模块 1-A；再设置 Else 分支，例如 example 为空时执行模块 1-B。也支持扩展，用户可添加条件实现多变量复合判断，例如 example 非空且请求中包含“季度规划”关键词，或新建分支加入 ELIF 条件应对更复杂场景。图 3-27 为条件组件配置界面。

3.2.6 功能模块 1-C
功能模块 1-C 承担数据解析标准化与变量跨组件复用的职能。它用代码组件把非结构化数据如大模型输出的 JSON 文本转为结构化变量，再借助变量赋值组件把这些变量变为全流程可见的会话变量，为后续内容生成、格式校验等环节提供统一灵活的数据调用基础。模块由代码组件和变量赋值组件组成，通过输入—处理—输出链条把零散数据转化为可精准调用的创作资源。图 3-29 为功能模块 1-C 的结构图。

1.代码组件：突破预设逻辑的灵活数据操作
代码组件是星辰智能体平台实现自定义数据操作的核心部件，能用超出预设组件能力的逻辑处理变量，显著增强工作流扩展性。在公文写作场景里，主要用于两类操作：一是解析大模型输出的 JSON 文本，例如把包含标题、大纲、字数限制的结果拆分为 title 字符串、outline 字符串数组、outline_num 数值等多个精确变量；二是处理预设组件难覆盖的复杂逻辑，如清洗爬取的脏数据或对多轮对话结果做自定义聚合。

配置与数据流可分为三部分：

● 输入变量：选定待处理的原始数据载体，例如大模型输出 JSON 文本对应的变量，作为代码执行的原材料。
● 错误重试：若代码需调用外部 API 如联网获取参考数据，开启后网络波动导致失败时会自动重试，保证流程鲁棒性。
● 输出变量：明确变量名与数据类型。以公文写作为例，输出包括 title 字符串存文档标题、outline Array[string] 存大纲子标题、outline_num 数值存每条大纲最少字数限制。这些变量将作为变量赋值组件的输入源，实现数据传递。

2.变量赋值组件：全流程变量复用的连接器
该组件的逻辑是数据全局化。把来自代码组件的已有变量赋给会话变量，使其可在当前工作流任意组件被引用，大幅提升灵活性。在写作场景里，常把代码组件输出的 title、outline、outline_num 转为会话变量，供大纲扩展、内容生成、字数校验等环节统一使用。

运作可从配置逻辑和数据流两方面理解：

● 配置逻辑：会话变量映射与写入。先在平台功能面板的会话变量配置界面，按名称和类型一一对应创建会话变量，例如 title 对应字符串、outline 对应字符串数组、outline_num 对应数值。会话变量不仅存储当前数据，还具备上下文记忆功能，如记录用户偏好，是智能体理解需求的全局记忆体。图 3-31 为会话变量配置界面。以保存大纲组件为例，在赋值的变量中选择会话变量 outline，在设置变量中选定代码组件输出的 outline，并在写入模式中选择覆盖。写入模式有覆盖、追加、清空三种，覆盖会清空原值写入新内容，追加适用于向数组添加元素，清空则重置为空字符串。通过此配置，大纲数据被固化为全流程可见的会话变量。

● 数据流：从局部到全局的价值延伸。输入是代码组件输出的精确变量如 title、大纲列表、字数限制，输出是写入会话变量后的全局可调用数据。代码组件完成从非结构化到结构化的初次加工，变量赋值组件实现从组件内变量到全流程变量的二次升级，前者保证数据可用，后者保证数据好用，二者共同支撑多环节协同。通过代码组件加变量赋值组件的组合，模块 1-C 形成大模型输出解析—关键变量提取—全流程变量复用的完整闭环，把标题、大纲、字数规则等核心信息从大模型黑盒输出转为可调度数字资产，供后续模块使用。

3.2.7 功能模块 2
大纲已搭好骨架，模块 2 的任务是填充血肉，基于每条大纲生成贴合主题且真实可靠的内容。单靠大模型易出现信息滞后和幻觉，因此模块 2 以大模型加工具加迭代为核心，联动变量赋值、模板转换等组件，构建信息采集—内容生成—循环优化的自动化闭环，让大纲从框架落地为可交付文档片段。

从构成看，模块 2 围绕智能体组件、变量赋值、迭代、模板转换、大模型记忆五大组件运转。智能体组件输入大纲主题和工具反馈，输出初稿；变量赋值标准化存储数据；迭代组件依据内容质量标记触发优化；模板转换把零散内容封装成规范章节。各组件通过输入输出数据流串联，完成大纲到优质内容的转化。

1.智能体组件
在模块 2 中，智能体组件是推动大纲到优质内容转化的核心引擎。面对大模型单独创作的信息滞后、逻辑跳跃问题，该组件基于大模型加网络搜索工具加迭代推理架构，实现接收大纲主题—自主采集参考信息—输出结构化内容的闭环。它是信息补充与内容生成的关键载体，也为后续工具配置和迭代优化提供基础。智能体组件配置界面如图 3-32 所示。

**（1）功能介绍**
核心任务是为每条大纲主题匹配实时可靠的参考信息，并据此生成内容。数据流上，输入包括单条大纲文本例如章节主题“星辰智能体平台组件分类”，以及历史迭代积累的参考信息如工具返回的行业报告链接或已有片段；输出为该大纲对应的初稿内容含数据、案例、逻辑推导，以及任务状态标记如“需补充竞品案例”或“内容达标可进入下一环节”。

要实现自主搜索加高质量创作，需突破三大关键点：

● 推理规划能力：让大模型拆解从大纲到内容的生成步骤，例如先分析大纲核心诉求，再规划需补充的信息维度。
