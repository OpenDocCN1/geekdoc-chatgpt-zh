### 5.2.3 让检索更快更准的三类做法

在搭建智能体时，找信息的效率和准确度直接决定能不能读懂用户想什么、回什么。这一块主要围绕问法扩充、二次排位、自适应检索展开。

#### 1. 问法扩充

用户提问往往模糊、太简或有歧义。对原始问句做合理加宽，能把召回面撑开，减少因词不全带来的遗漏。

常见做法：

1. 近义词补充：给原词加上相近表达。比如“汽车”可扩展为“汽车OR小轿车OR车辆”。

2. 语义关联：借助词向量或知识图谱引入意思相近的表述。Word2Vec、BERT 这类模型能找出语义邻近的词。

3. 假相关反馈：先用原问句检索一遍，把排名靠前的文档当作相关，从中抽取新词再做二次检索。流程是原始问句→初次检索→分析头部文档→抽取新词→再次检索。

4. 历史行为补充：结合用户过往的提问和点击行为来补全当前意图。

#### 2. 二次排位

召回阶段用 TF-IDF、BM25、向量检索等先拉一批候选，再用更精细的模型重新打分、调整顺序，把最相关的推到前面，以此提升精确度。

常用技术：

(1) 基于特征的学习排序：融合 TF-IDF、BM25、词向量相似度等多项特征，用机器学习模型排序。常用算法有 LambdaMART、RankNet。

(2) 深度语义匹配：用 BERT、RoBERTa 等预训练模型计算问句与文档的深层语义相关性。常用做法是 Cross-Encoder 架构。

(3) 多样性再排：避免结果扎堆相似，提升覆盖面。常用算法是 MMR。

(4) 个性化再排：结合用户画像和历史行为微调顺序。

#### 3. 自适应检索

检索策略会随外部环境变化而变化，比如用户状态、场景和对话背景。核心在于具备适应性，而不是固守固定规则。

##### 1) 核心特点

(1) 背景感知：纳入对话历史、用户偏好等背景信息。

(2) 多轮检索：根据前期结果动态调整后续检索方式。

(3) 实时反馈闭环：利用用户即时反馈来优化检索。

##### 2) 落地方式

(1) 问句改写：基于对话历史改写当前问题。例如用户问“它多少钱？”，系统结合背景改写为“iPhone 15 多少钱？”。

(2) 混合检索：动态组合多种检索方法。例如先用关键词检索，再用向量检索补充。

(3) 迭代检索：根据初步结果质量决定是否继续检索。当头部结果置信度低时触发扩展检索。

(4) 基于强化学习的策略调整：学习最优的检索策略选择机制。

## 5.3 编码能力

在智能体开发里，自动编程是关键能力之一。它让智能体能自主写、改、优化程序，从而实现环境动态适配、自主完成工具调用、流程自动化、问题求解等复杂任务。下面从定义、核心作用、技术路径等方面梳理。

### 5.3.1 自动编程能力

#### 1. 什么是智能体里的自动编程能力

指基于人工智能模型尤其是大模型，自动或辅助生成符合需求的代码片段、脚本或完整程序。与传统模板化补全不同，它具备更强的理解力和创造力：能基于自然语言需求、对话逻辑或任务目标，生成语法正确、逻辑自洽的程序，并可根据环境反馈动态调整。

在智能体内，自动编程的目标是赋予自主编码能力，无需人工干预即可通过程序实现工具调用、任务拆解、流程控制等。

#### 2. 自动编程在智能体里的核心作用

智能体的“感知-决策-执行”闭环中，自动编程支撑执行层，具体体现在：

- 动态工具调用：调用外部工具如 API、数据库、机器人控制接口时，自动生成符合规范的调用程序，如 HTTP 请求、SQL 语句。

- 任务自动化：把抽象任务如“分析近3个月用户数据并生成可视化报告”转化为可执行脚本，如 Python 的 Pandas+Matplotlib 程序。

- 自适应调整：环境变化时，如输入数据格式改变、工具接口更新，自动修改程序以匹配新场景。

- 复杂逻辑拆解：将多步骤任务如“爬取网页→清洗数据→训练模型”拆成模块化程序，实现端到端自动化。

#### 3. 自动编程的核心路径

当前主流的实现路径如下。

##### 1）以大模型为核心的生成式方法

目前最主流，依赖专门优化代码理解与生成能力的大模型。

（1）代表模型：CodeLlama 支持 Python/C++ 等多语言、GPT-4 在代码生成上优化明显、CodeGeeX 支持多语言与长代码生成、StarCoder 为开源代码模型。

（2）原理：模型在海量代码数据如 GitHub 开源项目上预训练，学习语法、逻辑结构、上下文关联，再根据自然语言描述或部分代码片段生成完整程序。

（3）优势：灵活性强，可处理从简单函数到复杂项目的多样化需求，支持多语言多场景。

##### 2）规则与模板辅助的增强生成

纯大模型生成可能存在逻辑漏洞或冗余，常结合规则与模板优化。

（1）规则约束：通过语法检查器如 Python 的 ast 模块、领域知识规则如“嵌入式代码需避免动态内存分配”过滤错误程序。

（2）模板填充：对高频场景如数据库连接、API 接口封装预设模板，大模型只需填入关键参数如地址、账号，提升效率与准确性。

##### 3）多模态融合的程序生成

为增强对复杂需求的理解，可结合多模态输入如文本、图表、日志。

（1）例如接收流程图图片后，通过图像识别抽取流程逻辑，再生成对应的控制流程序如 if-else、循环。

（2）基于错误日志文本定位程序漏洞并生成修复程序。

##### 4）强化学习与反馈优化

通过执行反馈持续优化生成质量：

（1）智能体生成程序后自动执行并收集结果，如运行报错、输出不符预期。

（2）基于反馈信息如错误类型、预期差异，用强化学习如 RLHF 或微调方法调整模型，提升下次生成准确性。
