## 工作原理

`torchtext` 提供的 `TabularDataset` 能直接解析 CSV，也兼容 TSV、JSON 以及用 Python 字典描述列的输入。我们先构造一个元组列表，每个元组由列名和对应的 `Field` 对象组成，`Field` 用来指定文本转换规则；若某列在最终数据中不需要，就把对应的 `Field` 设为 `None`，比如 ID 列。

本次以新闻分类为例，文本列套用 `Review` 字段，其余标签列套用 `Label` 字段。测试侧只有新闻正文，所以 `content` 列沿用 `Review` 字段，而 `id` 列直接剔除。随后通过 `TabularDataset` 的 `splits` 方法传入存放训练和验证文件的根路径，并用 `train`、`valid` 参数指定具体的文件名。

文件类型声明为 `csv`，设置 `skip_header=True` 去掉表头，并通过 `fields` 指定必须保留的列，测试集同理处理。最后调用 `Fields` 对象的 `build_vocab()`，以词频不低于两次为阈值建立词表，未进入词表的词在验证和测试阶段会被映射为未知标签。

## 工作原理

迭代器的作用是为训练、测试、验证组装小批量并把数据搬运到 CPU 或 GPU。借助迭代器这些操作会变得非常流畅。我们选用 `BucketIterator`，它会把长度相近的序列归到同一桶内，并自动打乱顺序。批量大小提前定义好，同时探测机器可用的计算设备。

利用 `BucketIterator` 的 `splits` 方法分别生成训练、测试、验证三个迭代器。`sort_within_batch` 默认设为 `False`，若使用 `pack_padded_sequence` 则需设为 `True`，以避免 LSTM 处理到填充部分。当设为 `True` 时，可配合 `sort_key` 参数按降序对批量内的序列进行排序。

## 更多

迭代器种类多样。普通迭代器直接从 `Dataset` 按批加载，`BPTTIterator` 则专为语言建模设计，相邻序列间隔一个时间步。

# 预训练词向量探索

## 工作原理

模型类 `LSTMClassifier` 继承自 `torch.nn.Module` 并初始化基类。嵌入层的输入维度等于词表大小，输出维度为嵌入维度；其输出进入 LSTM 层，输入维度对应嵌入维度，隐藏维度自行设定。

随后定义全连接层和丢弃层。前向函数接收输入序列，先经嵌入层得到维度为 `embedding_dim` 的向量，再送入 LSTM，输出包含输出状态、隐藏状态和细胞状态。隐藏状态汇总了序列至今的信息，我们取其做 dropout 后通过全连接层得到最终向量，其大小等于类别数。例如有毒评论数据集有六类，而二分类情感分析可只保留一个输出，用 `1` 表示正面、`0` 表示负面。

## 更多

多分类任务常用 `CrossEntropyLoss()`，单输出情感任务常用 `BCEWithLogitsLoss()`。其余训练流程与第 3 章卷积神经网络部分类似。
