互联网被普遍看作成熟为一切互联的状态，检索的终极追求则是绕开载体直指实体本身。传统检索以网页间的超链为线索定位页面，语义化检索把页面当成跳板，直接追踪人物、组织、地名等具体存在。这些存在可能散落在文字、图像、视频、音频或物联网终端里。知识图谱和语义技术为它们提供了类目、属性与关联的刻画，使搜索引擎能够以实体为粒度建立索引并发起查询，如图 1-5 所示。

# 2 问答增强
人与机器通过自然语言互问互答是人工智能成熟的重要标志。除检索之外，图谱在人机交互式问答中扮演核心角色。产业实践里，IBM Watson 的深度问答建立在 DBpedia、YAGO 等百科库与 WordNet 等语言资源之上；亚马逊 Alexa 主要依托 True Knowledge 公司积累的图谱；度秘、Siri 的后续形态 Viv、小爱同学、天猫精灵等产品背后均有海量图谱支撑。

[PAGE 21]

伴随机器人与物联网智能化的推进，基于图谱的对话问答在智能驾驶、智能家居、智能厨房等场景大量涌现。常见做法包括语义解析、图结构匹配、模板学习、表示学习与深度学习以及混合模型等。在这些方案中，图谱既用于辅助解析句义，也用于把问句中的指称对齐到实体，还被用来训练神经网络与排序模型。图谱已成为人机问答不可或缺的模块。

# 3 数据洞察助力
图谱与语义技术同样被用来提升数据分析与决策能力。以大数据公司 Palantir 为例，其通过本体融合把多源数据整合，借助图谱与语义增强数据间的关联，让用户以图形化方式开展关联挖掘与分析。

在文本处理中，图谱可作为先验知识帮助抽取实体与关系，例如远程监督的场景；也能辅助实体消歧、指代消解以及文本理解等任务。

近年来，描述性数据分析获得更多关注。描述性分析强调依托数据本身的语义描述来驱动分析。与以构建深度神经网络为主的计算性分析不同，描述性分析先抽取语义、建立数据间的逻辑，再依靠逻辑推理方法如 Datalog 来完成分析。

# 4 理解能力加成
背景知识尤其是常识，被认为是实现深度语义理解如阅读理解、人机问答的必要前提。典型案例是 Winograd Schema Challenge。该挑战由人工智能专家 Hector Levesque 提出，首届于 2016 年在 IJCAI 上举办。WSC 主要关注必须叠加背景知识才能理解句子语义的 NLP 任务。例如下面例子，人类可以本能判断：it 与 big 搭配时指向 trophy，与 small 搭配时指向 suitcase。

The trophy would not fit in the brown suitcase because it was too big（small）. What was too big（small）?

Answer 0: the trophy Answer 1: the suitcase

对人而言这几乎是理所当然的问题，机器却难以解决。正如自然语言理解先驱 Terry

Winograd 所言，人听到或读到句子时会调动全部知识与智能去理解，这不仅涉及语法，还包括词汇知识、上下文知识，更重要的是对相关事物的理解。

# 5 设备互联赋能
人机对话的核心难点是语义理解，即让机器读懂人类语言。机器之间的对话同样需要语义表示与处理。语义技术也可被用来辅助设备间的语义互联。OneM2M 成立于 2012 年，是全球最大的物联网国际标准化组织，其定位是为物联设备互联提供“标准化黏合剂”。OneM2M 关注用语义技术封装设备数据的语义并实现设备间语义互操作，也关注设备数据语义与人类语言语义的适配问题。如图 1-6 所示，设备产生的原始数据在封装语义描述后，更易与其他设备数据融合、交换与互操作，并可进一步接入知识图谱，以支持检索、推理和分析等任务。

## 1.4 国内外典型的知识图谱项目
自人工智能概念提出以来，构建大规模知识库一直是 AI 与自然语言理解的核心任务之一。下面分别介绍早期知识库项目、互联网时代的知识图谱、中文开放知识图谱和垂直领域知识图谱。

### 1.4.1 早期的知识库项目
Cyc 是持续时间最久、影响面广且争议较大的知识库项目。Cyc 最初的设想是建立人类常识的最大规模库，典型常识如 “Every tree is a plant”“Plants die eventually”等。Cyc 由术语 Term 与断言 Assertion 构成，术语用于定义概念、关系与实体，断言用于建立术语间的关联，包含事实 Fact 描述与规则 Rule 描述。最新版本已积累约 50 万条术语和 700 万条断言。其特点是基于形式化知识表示，优势在于支撑复杂推理，但过度形式化也导致扩展性与应用灵活性不足。

WordNet 是最知名的词典知识库，由普林斯顿大学认知科学实验室自 1985 年起开发。WordNet 主要刻画名词、动词、形容词和副词间的语义关系。例如名词的上下位关系，“猫科动物”是“猫”的上位词；动词的蕴涵关系，“打鼾”蕴涵“睡眠”等。

ConceptNet 最早源于 MIT 媒体实验室的 OMCS 项目。与 Cyc 相比，ConceptNet 采用更接近自然语言的非形式化描述，而非 Cyc 的形式化谓词逻辑。与链接数据和谷歌知识图谱相比，ConceptNet 更侧重词与词间关系。某种程度上它接近 WordNet，但关系类型更为丰富。

### 1.4.2 互联网时代的知识图谱
互联网的发展为知识工程提供了新机遇，在一定程度上突破了传统知识工程在知识获取上的瓶颈。从 Tim Berners Lee 1998 年提出语义网至今，涌现大量以互联网资源为基础的新一代知识库。这类库的构建可分为互联网众包、专家协作和互联网挖掘三类。

Freebase 是一个开放共享、协同构建的大规模链接数据库。由硅谷初创公司 MetaWeb 于 2005 年启动。2010 年谷歌收购 Freebase 并作为知识图谱的数据来源之一。其主要采用社区协作方式构建，数据来源包括 Wikipedia、世界名人数据库 NNDB、开放音乐数据库 MusicBrainz 以及社区用户贡献等。Freebase 基于 RDF 三元组模型，底层采用图数据库存储。其特点是对顶层本体控制较松，允许用户创建与编辑类和关系定义。2016 年谷歌宣布将 Freebase 数据与 API 服务迁移至 Wikidata 并关闭原服务。

DBpedia 意指数据库版 Wikipedia，是早期语义网项目之一，从 Wikipedia 抽取链接数据集。DBpedia 采用较严格的本体，包含人物、地点、音乐、电影、组织机构、物种、疾病等类定义，并与 Freebase、OpenCYC、Bio2RDF 等数据集建立链接。采用 RDF 语义模型，总计约 30 亿个 RDF 三元组。

Schema.org 自 2011 年起由 Bing、Google、Yahoo 与 Yandex 等搜索引擎公司共同推动的语义网项目。Schema.org 支持网站以语义标签方式将语义化链接数据嵌入网页，搜索引擎自动采集归集，快速抽取语义化数据。其提供一个词汇本体用于描述语义标签，目前已包含 600 多个类与 900 多个关系，覆盖个人、组织、地点、时间、医疗、商品等。谷歌 2015 年推出定制化知识图谱，支持个人与企业在网页中增加联系方式、社交信息等语义标签并快速汇集高质量数据。统计显示，超过 31% 的网页与 1200 万个网站已采用 Schema.org 发布语义化链接数据。Cortana、Yandex、Pinterest、Siri 等也采用了部分功能。实质上是互联网众包生成与收集高质量图谱数据的方式。

Wikidata 目标是构建免费开放、多语言、可由人或机器编辑的大规模链接知识库。由 Wikipedia 于 2012 年启动，早期获微软联合创始人 Paul Allen、Gordon Betty Moore 基金会与谷歌联合资助。Wikidata 继承 Wikipedia 的众包协作机制，但以三元组为基础的知识条目 Item 支持自由编辑。一个三元组代表关于该条目的陈述 Statement。例如可为“地球”条目增加“<地球，地表面积是，五亿平方公里>”的陈述。截至 2018 年已包含超过 5000 万个知识条目。

BabelNet 是类似 WordNet 的多语言词典库。目标是解决 WordNet 在非英语语种数据匮乏的问题。方法是将 WordNet 词典与 Wikipedia 集成，先建立 WordNet 词与 Wikipedia 页面标题的映射，再利用 Wikipedia 多语言链接辅以机器翻译。BabelNet 3.7 包含 271 种语言、1400 万个同义词组、36.4 万个词语关系与 3.8 亿个从 Wikipedia 抽取的链接关系，总计超 19 亿个 RDF 三元组。它融合了 WordNet 在词语关系上的优势与 Wikipedia 在多语言语料上的优势，是目前规模最大的多语言词典库之一。

NELL 即 Never-Ending Language Learner，由卡内基梅隆大学开发，采用互联网挖掘方式从 Web 自动抽取三元组知识。其理念是在给定少量类与关系定义和样本后，机器可通过自学习不断从 Web 中学习抽取新知识。目前已抽取 300 多万条三元组。

Yago 由德国马普研究所研制，是链接数据库。它整合 Wikipedia、WordNet 与 GeoNames 三库数据，将 WordNet 词汇定义与 Wikipedia 分类体系融合，具备更丰富的实体分类体系，还考虑时间和空间属性为条目增加时空维度。目前包含 1.

OpenBase.AI 由 OpenKG 团队打造，类似 Wikidata 的开放知识图谱众包平台。与 Wikidata 不同，OpenBase 以中文为中心，突出机器学习与众包协同，将自动化知识抽取、挖掘、更新、融合与群智协作的知识编辑、众包审核、专家验收结合。还支持将图谱转化为 Bots，允许用户选算法、模型与图谱数据定制生成 Bots，即时体验新知识图谱作用。

### 1.4.4 垂直领域知识图谱
领域知识图谱相对于 DBpedia、Yago、Wikidata、百度与谷歌等通用图谱，是面向特定领域的图谱，如电商、金融、医疗等。相比通用图谱，领域图谱的知识来源更多、规模化扩展要求更快、知识结构更复杂、质量要求更高、应用形式更广泛。如表 1-1 所示，对通用与领域图谱进行多维度比较。

| 分类\比较项目 | 通用知识图谱 | 领域知识图谱 |
| --- | --- | --- |
| 知识来源及规模化 | 以互联网开放数据如 Wikipedia 或社区众包为主，逐步扩大规模 | 以领域或企业内部数据为主，通常要求快速扩大规模 |
| 对知识表示的要求 | 主要以三元组事实型知识为主 | 知识结构更复杂，通常包含复杂本体工程与规则型知识 |
| 对知识质量的要求 | 多采用面向开放域的 Web 抽取，对抽取质量有一定容忍度 | 抽取质量要求更高，多依靠企业内部结构化、非结构化数据联合抽取并经人工审核校验 |
| 对知识融合的要求 | 融合主要起到提升质量的作用 | 融合多源领域数据是扩大构建规模的有效手段 |
| 知识的应用形式 | 主要以搜索和问答为主，对推理要求较低 | 应用更全面，除搜索问答外还包括决策分析、业务管理等，对推理要求更高且可解释性要求强 |
| 举例 | DBpedia、Yago、百度、谷歌等 | 电商、医疗、金融、农业、安全等 |

## 1 电商垂类图谱案例
以阿里巴巴电商知识图谱为例，最新规模已达百亿级别。数据主要以阿里已有结构化商品数据为基础，并与行业合作伙伴数据、政府工商管理数据、外部开放数据融合扩展。在表示上，除简单三元组外，还包含层次更复杂的电商本体与面向业务管控的大量规则型知识。质量上对覆盖面与准确性要求较高。应用上广泛支撑商品搜索、商品导购、天猫精灵等产品的智能问答、平台治理管控、销售趋势预测分析等。电商知识具有较高动态性，交易型知识与销售趋势类知识时效性强。

## 2 医疗垂类图谱案例
医疗领域构建有大量规模巨大的领域知识库。例如 Linked Life Data 项目包含的 RDF 三元组规模达 102 亿个，涵盖基因、蛋白质、疾病、化学、神经科学、药物等领域。再如国内中医药知识图谱，通常需融合基础医学、文献、医院临床等多源数据，规模达 20 多亿个三元组。医学知识结构复杂，如 UMLS 包含大量复杂语义关系，GeneOnto 包含复杂类层次结构。在质量上，涉及临床辅助决策的知识库通常要求零错误。

## 3 金融垂类图谱案例
金融领域典型如 Kensho 采用知识图谱辅助投资顾问与投资研究，国内恒生电子等金融科技机构及多家银行证券机构也在构建金融图谱。构建主要来源于机构已有结构化数据与公开公报、研报、新闻的联合抽取。金融概念复杂且层次丰富，多依赖规则型知识进行投资因素关联分析。应用上主要以金融问答与投顾投研类决策分析为主。金融图谱显著特点是高度动态，需考虑知识时效性，对时间维度建模要求高。

由上可见，领域知识图谱具有规模巨大、结构复杂、来源多样、高度异构、动态时效性强、推理需求深等特点。

## 1.5 图谱构建的技术链路
知识图谱用于表达更规范的高质量数据。一方面采用规范标准的概念模型、本体术语与语法格式建模描述数据；另一方面通过语义链接增强数据关联。这种表达规范、关联性强的数据在改善搜索、问答体验、辅助决策分析与支持推理等方面作用显著。

方法论涉及知识表示、知识获取、知识处理与知识利用。一般流程为：先确定知识表示模型，再根据数据来源选择获取手段导入知识，随后利用知识推理、融合、挖掘等技术提升质量，最后按场景需求设计访问与呈现方式，如语义搜索、问答交互、图谱可视化分析等。下面概述核心技术要素。

## 1 知识来源
可从文本、结构化数据库、多媒体数据、传感器数据与人工众包等多源获取图谱数据。每种数据源的知识化需综合不同技术。例如文本需结合实体识别、实体链接、关系抽取、事件抽取等 NLP 技术实现知识抽取。

## 2 知识表示与 Schema 工程
知识表示是指用计算机符号描述人脑知识以支持机器推理的方法与技术。它决定图谱构建的产出目标，即知识图谱的语义描述框架、Schema 与本体、知识交换语法、实体命名及 ID 体系。
