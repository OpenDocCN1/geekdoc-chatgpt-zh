最后看 TRAE SOLO 如何做到用户只能访问自己的数据，这依靠 PostgreSQL 原生的 RLS 行级安全策略实现。RLS 能为每一行数据设置精细的访问规则。

[PRE4]

这些策略遵循三大安全原则：默认拒绝、用户隔离、操作细分。

- **默认拒绝：** 若没有明确的授权策略，任何数据访问都会被阻断。
- **用户隔离：** 通过 auth.uid() = user_id 的校验，确保只能操作与自己相关的记录。
- **操作细分：** 可针对 SELECT、INSERT、UPDATE、DELETE 等不同操作分别制定独立策略。

其中 auth.uid() 是 Supabase 内置函数，能在数据库层面返回当前已登录用户的唯一 ID。它是把认证状态与数据权限串起来的关键，即使应用层出现漏洞，也无法绕过数据库层面的检查。

在此基础上，生产环境通常会扩展更完善的邮件体系，比如注册后的欢迎邮件、每周习惯完成统计报告、基于用户设置和时区的个性化提醒、达成里程碑时的激励邮件等。

如果用个人邮箱程序化发送，会面临明显局限：

- 送达率低，容易被主流邮箱判定为垃圾邮件；
- 缺少打开率、点击率等分析数据，不利于优化沟通；
- 需要手工处理退订链接、邮件头等合规细节。

因此专业邮件服务是现代应用的必选项。

实现邮件功能时必须遵守安全规范，邮件 API 密钥属于敏感信息，不能暴露到客户端。正确做法是把所有发送逻辑封装在服务端 API 路由中，并用环境变量管理密钥。
