
# 第11章

词形还原有点花哨，因为它需要理解那些需要被词形还原的词。对于像“painting”这样的单词来说，这是很容易的—只要把“ing”去掉，你就会得到一个词根“paint”。

不是所有的单词都有这么简单的词根。例如，“better”和“best”都有“good”作为它们的词根，“feet”有“foot”这样的词根。没有明显的方法来还原这些词。

通常的方法是使用一个已经确定的词汇数据库。这是一个庞大的语料库，里面包含了大量的单词和它们之间的联系，所以不用编写一个庞大的复杂系统来确定“feet”是否与“foot”匹配，你只需查询数据库。

其中最流行的一个（如果你曾经做过任何NLP的工作，很可能你已经使用过但没有意识到它）是`WordNet`，它包含大量的单词（超过15万个）以及它们之间的关系。

标注的工作方式与词形还原类似，因为你需要查询词汇数据库。同样，`WordNet`是另一个受欢迎的选择。你只要给出单词，它就会告诉你它的语法形式。

在词汇数据库的背后没有什么神奇的东西，只有经过长时间积累的大量数据。

## 11.5 推荐

在8.5节中，我们使用`CoreML`内建的`MLRecommender`创建了一个电影推荐器。

`MLRecommender`可以使用一些不同的方法，其中包括`Jaccard`、`Pearson`和余弦相似度度量。

默认情况下，我们使用的是`Jaccard`，因为当推荐之间的相对差异没有用户是否推荐重要时，`Jaccard`的效果最好。

就电影而言，我们认为推荐（或不推荐）一部电影是最重要的指标，其次是用户推荐程度的高低。`Jaccard`的核心是两组数据之间的差异统计。`Jaccard`也被称为“并集的交集”，因为它实际上是用两个集合的并集来分割两个集合的交集。数字越大（0到1之间），两组数据越接近。

被比较的数据不需要是表格数据；可以是你拥有的任何一组数据。例如，可以为图像计算`Jaccard`索引以获得它们的数值相似性，这对于直接比较应该近似相同的图像非常有用（如果你想要更多的话，我们在第10章中更详细地介绍了各种距离指标）。

简而言之，这是基于这样一个假设：如果两组数据大部分是重叠的，它们很可能彼此相似。对于电影推荐这样的数据，这种方法非常有效，对于这些数据来说，仅仅存在一个推荐就意味着相关性。当数据的其他方面（比如数据的排序）很重要时，它就会失败。不过，对于一个电影推荐人来说，我们可以直接看到两个人喜欢的电影中的重叠，这是一个很好的选择。

## 11.6 预测

在8.6节中，我们使用了一个用`MLRegressor`构建的回归器，对20世纪70年代和20世纪80年代波士顿的房价进行了一些预测。我们做这件事时很少对回归器进行自定义或调整，基本上只是保留了所有的默认设置，并相信工具可以为我们创建一个有效的回归器。

在10.2.1节中，已经详细描述了回归预测的核心原理，所以我们就不再重复了。它们的核心是数学函数，而不是神经网络。它们创建一个数学函数来匹配训练数据。现在，你可以将回归器看作返回预测的函数。如果你想了解更多细节，请参阅第10章。

在回归器中，我们使用了梯度提升回归树(`GBRT`)，也称为功能梯度提升或梯度提升机。`GBRT`本质上是各种决策树的集合，你将其中每棵树的结果组合在一起，以获得比它们自己更准确的预测。但是从外部来看，它们的工作方式与所有回归器一样，即你给它们一个值，它们就会为该值提供一个预测结果。

我们（好吧，其实是`MLRegressor`）决定使用`GBRT`的原因是它们是最常见、最可靠的回归技术之一。它们在广泛的数据集上工作得非常好，而且，在我们的案例中特别有趣的是，它们可以很好地捕捉非线性关系。然而，如果数据相当稀少，它们就会失败。

`MLRegressor`如何选择一个回归类型还不完全清楚，但是根据苹果所说的一些内容，我们假设它正在尝试每一种回归类型，并在整个训练过程中进行比较。当它继续训练的时候，它会评估每个回归变量的运行情况，并排除那些做得不好的变量，最终确定一个回归变量。它可能不会像这样工作，但至少这是一种方法，你可以这样做，从这里开始，因为你知道最终这会给你一个很好的回归器。你可以使用的另一种方法或与“全部尝试”技术相结合的方法是，在开始训练前浏览数据并做一些统计分析。不同的回归器在某些类型的数据上工作得很好，所以在快速浏览数据后，很明显，一个回归器比另一个回归器更好。

## 11.7 文本生成

在8.3节中，我们使用马尔可夫链用相对较少的输入数据生成一大堆大部分有效的英语句子。马尔可夫链是以安德烈·马尔可夫(`Andrey Markov`)的名字命名的。安德烈·马尔可夫是俄罗斯数学家，他在20世纪初首次研究并正式描述了马尔可夫链。马尔可夫链是潜在状态和状态之间转换的机会的图形。每个转移都被视为无记忆的，所以决定将哪个状态移到下一个状态完全取决于当前状态，而不是之前发生的事情。这就产生了一个在模拟现实世界和抽象问题时非常精确的过程。它们（以及它们许许多多的变体）已经被广泛应用于各种领域，我们很有信心地说，你所使用的系统在某个地方就有一个马尔可夫链。

![](images/1237069d-6062-4907-a570-43ecf11d8c4f.png)在技术术语中，马尔可夫链的无记忆性指的是它的马尔可夫性质，即当一个随机过程是无记忆的。其他系统也可以是无记忆的，却既不具有马尔可夫性质，也不是马尔可夫链。

在8.3节中我们使用了马尔可夫链来生成句子，以稍微进一步讨论它们的基本原理。在这里，我们将做一些非常类似的事情，但是我们将从字符级别而不是单词级别来看它。方法是完全相同的，只是使用更小的样本。假设我们想用马尔可夫链创建一个单词生成系统，但是输入的只是“hi there”。这显然不是很多的输入，所以不会产生很多东西，但它足够小，足以展示工作原理。

第一步是收集输入中的每个字符的集合。我们需要一个集合，因为需要每个元素都是唯一的，所以即使输入中有两个e字符，我们也只需要结果图中的一个。这为我们提供了用于生成的`[h, i, ', 't, e, r, .]`字符集。

接下来，我们需要对从一种状态到另一种状态的转移进行建模。我们通过观察一个字符在另一个字符之前的频率，来得到从一个字母移动到另一个字母的概率。因为马尔可夫链是无记忆的，我们不需要担心如何得到字符，只需要关心从这里到了哪里。例如，在字母h的情况下，我们可以移动到字母i或e，我们不从一个h移到别的地方。在我们的输入中，两种情况只出现一次，所以有50%的机会从h移动到i或e。这给了我们初始链，如图11-3所示。

![](images/991ece1e-370b-48b3-80ed-98ee44f024db.jpeg)

图11-3：马尔可夫链的第一阶段

现在我们可以使用这个图来生成一些单词。可以选一个点作为开始节点（我们会选h）然后沿着图走。当我们到达一个有多个选择的点时，基本上只是掷一个骰子然后选择一条路径。这意味着，如果我们沿着这个图走，会期望得到相同数量的“he”和“hi”。

如果对输入集中的每个字符都重复计算转移及其概率的过程，最终得到的图形如图11-4所示。

![](images/cba3520e-0b91-40f2-ab36-835492d2dfe6.jpeg)

图11-4：完成的马尔可夫链

现在，如果我们按照这个图，就可以得到像“he”“hi”“here”“the”“there”这样的词，如果我们只对图做微小的修改（例如去掉作为有效节点的空格），就可以得到像“hit”或“here”这样的单词。通过添加一些只做小改动的额外语料库单词，例如将i节点连接到r节点，我们可以得到“their”。希望通过这样一个小例子就能很容易地看出，通过遍历图就可以很快地生成一大堆单词。通过更多的输入，我们可以得到更令人印象深刻的结果。

![](images/38e24b3a-29ab-4ea5-bb45-5d6b85537771.png)马尔可夫链虽然简单得令人印象深刻，但却没有上下文来说明它们在做什么。这意味着，即使我们可以很容易地生成有效的单词，也可以生成“ererererere”或“ther”。链并不理解我们需要有效的词语。它只知道从一个状态到另一个状态的概率。不要盲目地相信马尔可夫链！

## 11.8 生成

生成对抗网络是要添加到神经网络工具带中的一个最新的，可能是最酷的工具。我们在8.4节中使用它们来生成图像。

它们在生成内容（正如它们的名字所暗示的）方面取得了巨大的成功，当你需要神经网络来做一些事情时，它们是当前的首选方法。然而，被称为对抗似乎有点令人困惑：它们在和什么东西斗争吗？它们和谁斗争？科学家们为什么要让这种事情发生？

这里的“对抗性”是指生成内容被评估器（也称为判别器）与一些已知的正确内容进行比较。生成方越来越努力地做出判别器无法从已知内容中区分的东西。

这两个组件—生成器和判别器—都是`GAN`的一部分。基本上，它是在和自己竞争，创造越来越好的模型，然后来尝试欺骗自己。

![](images/7d98b1c0-2d2c-47c7-9105-7cf46d7850d4.png)`GAN`在生成逼真的人类图像、音频和视频方面取得了如此巨大的成功，以至于科学家们现在开始担心它们会被用于恶意目的。

不要用自己的智慧去作恶。

`GAN`的生成器组件以类似于CNN自动编码器的方式工作（见11.2.5节），并且经常使用CNN作为其基本构造块。捕获训练内容中的潜在变量，并从中生成类似的新内容。给出观测数据后，生成器开始从训练数据中提取特征。

生成器最终在训练内容中创建一个巨大的多维空间，包含潜在变量或特征。到了创建上下文的时候，生成器使用这个巨大的潜在空间和你给它的任何输入，然后从输入中提取特征，并在潜在空间中使用它们来创建新的内容。

从本质上说，生成器学习了训练内容中的大量特征，然后，当输入时，通过将它们与它对原始内容的理解相匹配来构建新的信息。如果训练不好，特征会导致奇怪的、嘈杂的、无用的数据；如果处理得当，就可以制作从原始内容上检测不出来的新内容。

判别器以类似的方式工作，它学习训练数据中巨大的潜在空间。但是，与生成器使用这些信息进行创建不同，判别器使用这些信息进行分类。

给判别器的所有输入有两种分类：真实的和生成的。根据你试图执行的操作，可以重用生成器的某些部分作为判别器的基础。

然后是对抗阶段：在训练过程中，两部分不断竞争，生成器生成新的内容，同时提供真实的训练内容，判别器对其进行分类。

给判别器的输入被正确标记，判别器就可以利用这些知识，来更好地在下一轮进行分类。生成器根据分类的方式以及分类的强弱，使用分类结果来改进下一轮的生成。

每一方都使用新创建的信息来帮助提高训练，并试图超过`GAN`的其他部分。在一个经过完美训练的`GAN`中，分类器不再能够区分真实的内容和生成的内容，而是给它们一个均匀的权重。不过，你不需要完美。

在我们的`GAN`中，生成组件使用密集层和卷积层的组合，而评估器使用卷积层、池化层和密集层，这两个组件分别有大约6个层。然而，我们的`GAN`只能在`MNIST`图像非常有限的尺寸和颜色空间上工作。

更大的数据域将导致需要更大、更复杂的`GAN`。

## 11.9 CoreML的未来

在2019年`WWDC`大会上推出的`CoreML 3`中，苹果引入了另一种将`CoreML`用于图像的方法。在`CoreML 3`之前，要对图像使用`CoreML .mlmodel`文件，必须使用`CVPixelBuffer`对象（这涉及转换图像），或者使用苹果的`Vision`框架来处理`CoreML`。

在`CoreML 3`中，可以使用`MLFeatureValue`。`MLFeatureValue`允许你将`CGImage`对象（这意味着你可以使用图像文件）直接传递到`CoreML`模型中。

## 12.1 在CoreML的魔法背后

在非常高的层次上，`CoreML`的工作方式是加载在`CreateML`或`TensorFlow`等工具中创建的预先训练好的模型文件，然后运行模型，并根据你提供的输入返回预测。

在11.1节中，我们稍微谈到了`CoreML`的程序内部是如何工作的，但是我们忽略了模型格式的结构，因为理解`CoreML`的工作方式并不重要。

为了理解`CoreML`在做什么，我们至少需要对其格式进行一个基本的了解。`CoreML`模型格式本身是基于`protobuf`序列化数据格式的，它有一个自定义的模式，允许你定义机器学习模型的类型、模型的特性、标签、输入和输出、属性、元数据和其他任何你需要完整描述模型的内容。

数据格式的核心是精确地描述模型，这样其他程序就可以读取、理解并重新构建精确的模型。

![](images/e701d44f-13f5-46a1-808e-5043fea5a7ca.png)有关`CoreML`模型格式的更多细节，请参阅2.3.1节。

这意味着`CoreML`必须读取模型文件，并将其转换为神经网络、广义线性模型、树分类器或任何模型类型，然后运行它。`CoreML`从我们这里接收到的模型（一个`.mlmodel`文件）本质上是模型的通用描述。

`CoreML`构建一个特定于设备的模型版本，该版本针对其运行的硬件进行了优化。这个特定于设备的版本用与我们在本章将要做的类似的方法构建，并且不会改变模型的工作方式，它只是针对设备进行了优化。

新格式创建后，将被编译并保存为`.mlmodelc`格式，这就是`CoreML`实际运行时使用的格式。

`CoreML`并不经常运行那些`MLmodel`，而是将它们转换为新的格式，然后运行。

![](images/076458da-5cfa-4ca0-933b-61cc94b3ba78.png)如果要动态更新或加载模型，可以在`MLModel`类上使用`compileModel(at:)`方法，该方法将接受一个`.mlmodel`并从中创建一个`.mlmodelc`。

尽管这是本书大部分内容的主要方法，也是你应该采用的通用方法，但它并不是了解`CoreML`如何工作的最佳方法。因此在本章中，我们将后退一步，使用基本神经网络子程序(`Basic Neural Network Subroutines, BNNS`)库自己构建一个神经网络，它是苹果`Accelerate`框架的一部分（我们在2.3.4节中提到过这个框架）。

这里只涵盖了神经网络的情况，`CoreML`（以及通常的机器学习）支持的远不止神经网络，但它们是目前最流行的机器学习形式，也是最值得从头构建的。

![](images/dda79837-b250-4ff7-b85e-cbd829ba20c7.png)`Accelerate`框架不仅包含`BNNS`，还有各种不同的库来实现CPU的快速加速。

除了`BNNS`之外，`Accelerate`还提供了用于向量和四元数运算、信号处理和稀疏矩阵线性代数求解等的代码。

尽管你可以自己编写它们，但苹果已经为它们编写了高度优化和硬件加速的版本，非常值得一试。

`BNNS`是`CoreML`使用的底层库之一，运行在CPU上。你不会经常发现自己在编写直接使用`BNNS`的代码，但是你通过`CoreML`运行的任何模型都很有可能使用它。你可以使用`BNNS`来构建任意大小或不同复杂度的神经网络，支持三种不同的层类型：

• 卷积层

• 池化层

• 稠密层

![](images/020db9d4-610b-4e9a-9911-aaab9b26aa0b.png)`BNNS`通常被戏称为香蕉(`bananas`)。你明白了吗？

如果你的神经网络设计可以使用这些层类型（很多都可以），可以用`BNNS`创建它。`BNNS`是用`C`语言编写的，`Swift`通过桥接来调用该库，让你可以像使用原生`Swift`代码一样与库通信。然而，事实并非如此，因此有一些独特之处需要警惕，当我们发现它们时会指出。

![](images/7f7c926a-d751-4134-9661-522e8e795f04.png)`BNNS`只是苹果在`CoreML`中使用的众多技术之一。

`CoreML`使用的另一种技术是`Metal Performance Shaders`（更确切地说，是`Metal Performance Shaders`中为构建神经网络而设计的部分），其工作方式与设计的API非常相似，但看起来略有不同。

`BNNS`和`Metal Performance Shaders`的主要区别是`BNNS`是CPU独占的，而`Metal Performance Shaders`是GPU独占的。我们使用`BNNS`而不是`Metal Performance Shaders`有一个简单的原因：`BNNS`可以在`macOS`和`iOS`上工作，而`Metal Performance Shaders`主要是专注于`iOS`的。
