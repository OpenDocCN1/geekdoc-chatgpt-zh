文本理解、常识推理和业务经验。例如，德国《联邦数据保护法》第 4b 节第一款规定：

# 一、将个人数据转移给以下机构时：

+   1. 欧盟的其他成员国，......

只要转移的影响与活动部分或全部落在欧盟共同体的法律范围内，根据适用于此类转让的法律和协议，就应当遵照第 15 节第（1）款、第 16 节第（1）款和第 28 节到第 30a 节的约束。

二、第一款应准用于个人数据……向其他外国、超国家或国际机构的转移。只要数据主体具有排除转让的合法权益，转让不得进行，特别是如果本小节第一款所述的机构无法保证足够的数据保护水平。

三、应根据所有情况评估所提供保护水平的充分性。

四、允许转移的责任应由转移数据的机构承担。①

完全将这一规定形式化是非常困难的，但人类专家会知道这可能是不必要的。专家可能从经验中知道，巧妙处理法案保护个人数据这一要求的最简单方法是避免将个人数据传输出德国。因此，专家将准备业务规则（表 2.1 中的 R3 ）作为一种启发式拇指规则，以确保数据仅在德国处理（同上）。

# 2.5.3. 流程合规语言的要求

单独的谓词逻辑不足以完成将监管规则的应用建模到业务流程模型的任务。一种合适的语言需要支持：

+   1. 带有可辩驳法律规则的推理。

+   2. 从逻辑规则到规章渊源的同构链接。
