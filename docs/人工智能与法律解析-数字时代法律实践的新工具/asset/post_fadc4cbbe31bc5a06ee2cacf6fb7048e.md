对于机器学习算法，研究者使用语词的加权特征向量（一元模型）训练支持向量机分类器（第 8.5.2 节），应用三种类型的权衡，二元（存在或不存在），术语频率，或词频 / 反文档频率值（见第 8.3 节）。

研究者对最近的两项立法中的知识工程和机器学习方法进行了比较。一个只改变现有法律，而另一个包括这些改变并施加新法律。研究人员发现机器学习改变法律方面的得分略好于知识工程，但在施加新法律方面则比知识工程差。特别是，机器学习在定义分类和许可与义务之间的区别方面存在问题。研究者分析了这些错误并列出了原因，包括表 9.1 中的错误和原因。

如表所示，出现在从句或缺少标准短语的关键词对于知识工程和机器学习都可能是有问题的。模式单词顺序的变化会导致知识工程出现问题，但机器学习对单词顺序不敏感（至少在词袋表示适用的情况下）。缺乏数据、词和类之间的虚假相关性或者没有区分度的关键词都是机器学习的问题（de Maat 等，2010）。

在知识工程和机器学习之间进行选择涉及许多权衡。知识工程需要手动表述规则以捕获识别分类器实例的相关模式。机器学习自动识别区分模式，尽管机器学习不必然识别与知识工程相同的模式，并且需要准备一套人工分类的训练集。在涉及荷兰法律的上述实验中，知识工程和机器学习实现了大致相似的分类准确性。新法律中的分类条款不同于训练集，知识工程规则实现了比支持向量机分类器更高的准确性。然而，更大的训练集改善机器学习模型的可转移性是可能的（de Maat 等，2010）。在调试时，即检查分类错误时，知识工程方法提供了有关缺失规则的更多有用信息，也提供了模式应该已触发但未触发或者模式不应触发但已触发的更有用的信息。如前所述，支持向量机分类器的模型更难以检查，尽管其他机器学习模型（如决策树）更容易检查。

在知识工程和机器学习之间进行选择的另一个方面是在混合模型中将两者结合在一起的可能性。例如，如第 10.5.3 节所述，卢依马程序使用机器学习进行句子角色识别，使用知识工程来注解子句类型，例如标准的法律陈述（Standard Legal Formulations），比如“原告必须证明。”因为这样的表达式提供了清晰的模式示例，转而构建规则以识别它们。机器学习作为一种有效的替代方案，其中区分模式不太清楚或涉及诸如标准的法律陈述之类的组件。

## 9.5. 从制定法和规章中提取逻辑规则

从制定法和规章文本中提取逻辑规则是自动化法律推理的重要目标。想象一下，用从英国国籍法文本或德国家庭法中自动收集的规则自动填充英国国籍法案程序（第 2.3.4 节）或卡涅阿德斯（Carneades）程序（第 5.3.1 节）的可能性。这是一个雄心勃勃的目标，但不幸的是，这是一个难以实现的目标。

仅有自然语言工具可能不足以完成任务。在怀纳和戈韦尔纳托里（Wyner 和 Governatori，2013）的著作中，研究者使用最先进的开源自然语言翻译工具——C & C / 工具箱——进行了一项试点研究，将规范陈述转化为语义表示。作者将输出表示与《澳大利亚电信消费者保护法典》（2012）中关于投诉管理的五个句子的手动创建的可辩驳逻辑表示进行了比较。

```
< T1 > 对自然人 < /T1 >
< A > 他 / 她被取消资格后拥有资格保证， < /A >
< C > 被保险人的条款加在一起。 < /C >

< T2 > 对于这项法律规定的养老金金额， < /T2 >
< A > 当这个国家或其他地方的生活标准有了显著变化时， < /A >
< C > 必须立即修订养老金数额以满足这些情况。 < /C >
```

图 9.3. 为逻辑部分注解的制定法句子示例 前件 <A>，结果 <C> 和主题 <T> ( Bach 等, 2013 )

例如，对于规定“供应商必须为消费者提供监控投诉进展的手段”而言，语义表示识别个人、事件、关系和时间关系。该工具确定了模态必须，但它没有表明义务的承担者，也没有确定模态运算符的范围。最后，一般而言该表述并未涵盖规范对供应商的应用。

为了从制定法文本中成功地自动提取逻辑规则，似乎有必要关注一个具体的法律领域，并确定该领域的逻辑结构特征，以用作规则的模板。

例如，一个项目已经应用机器学习从制定法段落中提取逻辑结构，这些段落来自涉及日本国家养老金法的语料库。对语料库中多句子条款的系统研究已经确定了主句和从句之间的四种关系，以及它们作为模板使用的相关逻辑结构（Takano 等，2010）。巴赫等作者（Bach，2013）提出了一个两阶段框架，用于从段落中提取在特定条件下对特定代理人施加义务的逻辑规则。该程序首先学习分类器以识别法规中的“逻辑部分”，包括前因（A），结果（C）和主题（T）。图 9.3 显示了为这些逻辑部分注解的制定法句子的两个例子。基于这些部分，然后程序学习分类器以选择适当的模板，再用这些模板把这些逻辑部分分与逻辑结构和完成的规则组合在一起。

给定第一个分类器识别为逻辑部分的新的法律段落，第二个分类器选择适用的逻辑模板，系统根据模板组装逻辑规则。作者用日本国家养老金法中确定的一部分逻辑结构证明所取得的某些成功，该系统的第二阶段确定法律段落中的逻辑结构模板，但在这个阶段，人类专家输入的逻辑部分比系统自动识别的逻辑部分效果更好（Bach 等，2013，p.3:27）。

通过关注狭窄的法律规制领域来提取规则和确定该领域特征的逻辑结构，也已应用于管理建筑物等产品设计的模型规范。

## 9.6. 符合产品设计的提取要求

第 2.5.1 节中讨论的合规性是涉及产品、系统或其他人工制品设计的许多行业中的重要实际问题。例如，建筑规范明确规定了对建筑设计的约束，例如“天井［在建筑物墙壁周围的开放区域意义上］宽度不应小于 3 英尺”的规则。

法律规章规制对大多数工程领域（如民事、电气和环境）的产品设计。不同地区、社区和政府层面的规章差异很大。尽管规章可能会限制产品或系统设计，但产品工程师和系统设计人员可能不知道适用哪些规章。相反，法律人员可能不了解拟议设计的技术方面，因此未能预见到规章可能引发的后果。

这些考虑因素促使研究人员尝试从制定法文本中自动提取规则，以便可以或多或少地自动应用这些规则来测试拟议设计是否满足相关的法律约束。例如，一种方法自动从建筑法规的语料库中提取信息，并将其转换为可以直接用于自动化合规性检查的逻辑条款（Zhang 和 El-Gohary，2015）。

作者开发了一种多阶段方法，涉及：

- 1. 文本分类（Text classification，简称为 TC）：基于机器学习的文本分类识别包含与自动合规性检查相关的要求类型的句子（例如，建筑行业的监管要求），
- 2. 信息提取：基于规则的语义自然语言处理在相关句子中识别携带目标信息的单词和短语，并用预定义的信息标签对它们进行标记，以及
- 3. 信息转换规则（Info Transformation Rules，简称为 ITr）：语义自然语言处理算法（信息转换规则）采用模式匹配规则将提取的信息转换为逻辑陈述，逻辑程序可以用逻辑陈述进行推理。这些规则使用句法和一些语义信息。

例如，文本分类承认以下句子与建筑设计的自动合规性检查相关：“天井宽度不得小于 3 英尺。” IE 标记有针对性的单词和短语，例如：

- 主语：天井
- 合规性检查属性：宽度
- 比较关系：不小于
- 数量值：3
- 数量单位：英尺
- 参考数量：不适用。

然后，信息转换规则触发；它的左侧标识规则模式：

```
主语 + 情态动词 + 否定 + 是 + 比较关系 + 数量值 +
数量单位 + 介词 + 合规性检查属性。
```

该规则的右侧是：“为‘主语’信息实例，‘属性’信息实例和‘有’信息实例生成谓词。”

一旦信息转换规则生成了元素，消费和生成机制就会将这些元素组合成一个逻辑子句：

符合—天井—宽度（天井）如果宽度（宽度），天井（天井），具有一（天井，宽度），大于一或一等于宽度，数量（3，英尺）

信息转换规则模式匹配规则是根据“国际建筑规范”的两章研发的，并在第三章的文本作为黄金标准进行了测试。在第三章中，包含数量要求的 62 个句子被自动识别出来，这些句子来自手工构建的包含 1,901 个逻辑子句元素的 62 个逻辑子句。

实验评估了系统的信息转换规则模式匹配规则的精确率和召回率，以便根据从第三章自动提取的信息标签生成 1,901 个逻辑子句元素。两个版本的实验在运行，一个具有较小的信息标签集，另一个具有更具包容性的集合。后一版本产生了更好的结果：98.2% 精确率，99.1% 的召回率和 98.6% 的 F1 测量值（Zhang 和 El-Gohary，2015）。

作者确定，识别逻辑子句元素中的错误是由以下情况引起的：信息提取过程丢失或错误识别的标签，处理具有不常见表达结构的句子中的错误，由于形态特征导致的匹配错误，某些匹配规则模式的问题，以及监管文本中连词使用的结构性模糊。例如，“剪力墙段为壁墩提供侧向支撑并且此类段具有总刚度……”（shear wall segments provide lateral support to the wall piers and such segments have a total stiffness...）中“并且”的范围没有具体说明。它可以连接“墙墩”和“此类段”或前面的分句和后面的分句。这是在法律法规中处理句法歧义挑战的一个有趣例子（第 2.2.2 节）。

尽管性能非常高，但这些实验仍然存在一些局限性。首先，实验仅仅关注量化要求的处理。这些在建筑规范和许多类似的工程规范中很重要，但即使这些规范也采用其他类型的要求，而不是用定量术语表达，这可能更难以解析。其次，该实验仅仅限于测试国际建筑规范的一个章节，部分由于手动创建黄金标准有难度。

### 9.6.1. 执行遵守已提取的规章

保罗·张和 El-Gohary（Zhang 和 El-Gohary, 2015）关于定量构建要求的项目是直接从规章文本中提取复杂逻辑规则的好例子。与可扩展标记立法语言分类器和提取器（第 9.3 节）中的方法类似，它把步骤（1）的机器学习和步骤（2）的知识工程规则结合在一起，机器学习提取规章要求类型，知识工程规则提取用于操作规则的单词和短语。然而，这项工作采取了实际构建这样一条规则的重要额外步骤（3），该规则可以直接应用于合规性测试。

该项目聚焦于相当受限制的规章条款类型。到目前为止，还没有从法律规章文本中自动提取逻辑规则的一般方法。机器学习和知识工程采取一种方式，但是将提取的部分组装成逻辑规则需要专门的规则和模板，以适应特定规章类型特点的逻辑模式。

韦尔纳托里和舍克（Governatori 和 Shek, 2012）关于电信消费者投诉处理的项目（第 2.5.5 节）举例说明了使用逻辑规则进行推理自动检查机构的现实监管合规性。它说明了在现实业务环境中直接应用逻辑规则的巧妙方法。作者展示了一种包含规章要求的技术设计环境，这些规章要求来自（仍然）手动构建的治理通信系统的可辨驳规则。使用这些工具的人类设计者可以设计一种保证符合从法规中提取的逻辑规则的通信系统。

想象其他设置是有趣的，其中从规章文本中自动提取的逻辑规则可以直接应用于监控实际业务的合规性。在某些合规语境中，法律规章管理公司文件，建议另一种方法直接应用于提取的规则。例如，“诚实贷款法”——美国联邦法规第 12 章第 226 部分——的实施规范规定，如果广告中出现各种“触发词”则必须满足的某些监管要求。根据该规定，提及信用卡广告中的年度百分比率（APR）会触发要求进行某些相应的披露。在这种合规环境中，人们可以想象直接从规章文本中提取的逻辑规则，这些逻辑规则用于监控广告要求，并直接应用于广告文本或副本（Deisher-Edwards, 2015）。

### 9.6.2. 改进人类合规性注解的半自动方法

研究者还设计了半自动技术，用于从法规文本中提取权利和义务，例如，美国《健康保险可携带和责任法》（HIPAA）。自动化技术提高了人类注解者的表现（Breaux 等，2006）。在基亚维茨卡亚等人（Kiyavitskaya 等，2008）看来，研究者采用了半自动语义注解工具 Cerno（见 Zeni 等人，2013）以及规章文本的扩展工具盖尤斯·特（Gaius T）① 从美国《健康保险可携带和责任法》隐私规则条款中提取权利、义务或例外。

Cerno 使用无上下文语法法，即描述如何从满足语言句法的语言可用符号形成陈述的规则，以生成文本的解析树，解析树的成分为法律语言文本元素。然后，注解规则分析解析的文本，用标签注解它们，指示某些概念的存在与否。这些概念选自域本体。每个概念都有一个相关的指示词汇表，包括应该（或不应该）存在的文字和已解析实体的名称。最后，转换规则选择某些带注解的文本片段和输出模板，其中的域根据注解填充。

为了扩展注解规章文本的工具，作者手动解析了美国《健康保险可携带和责任法》隐私规则的一个片段，并生成了四个主要概念的指示列表。

- 1. 权利：有条件地允许利益相关者采取的行为；
- 2. 义务：有条件地要求利益相关者履行的行动；
- 3. 约束：描述单一前置或后置条件的权利或义务的一部分；和
- 4. 例外：从域中考虑移除的元素（Kiyavitskaya 等，2008，p.5）。

研究者将该工具应用于美国《健康保险可携带和责任法》隐私规则的其他片段（以及意大利制定法条款），他们将系统识别的权利、义务、约束和交叉引用的数量与人类识别的数量进行了比较。结果大致相当。评估表明需要添加更多规范性短语来识别约束。此外，该系统在识别约束的主体和客体方面存在一些困难，在识别合取和析取的主体方面也存在一些困难。

值得注意的是，研究人员比较了使用盖尤斯·特已经注解的文本的非专家人类注解者的输出和没有使用已经注解文本的注解者的输出。前一组的效率提高了约 10%，工作速度提高了约 12%，并且产生的注解与不使用自动注解文本的注解者的注解一样准确（Kiyavitskaya 等，2008，p.9）。

同样，在吉田（Yoshida 等，2013）的著作中，作者证明，当得到突出显示术语——存在于与模板相对应的文档——的工具的支持时，人们可以根据不同的模板更准确更有效地对法规进行注解。

作者定义了三个模板，用于从制定法文本中捕获信息。定义模板用于注解法规中使用的法律术语的定义。功能模板标识法定条款要求（或许可等）的功能过程类型。数据模板识别法规要求受规制方输入功能过程的数据或信息。它们将各种单词、概念和短语与三种模板类型中的每一种相关联。例如，短语“以下称为……”在附加说明中出现，建议应用定义模板。如“通知”之类的名称和“报告”之类的动词术语建议使用数据模板，以指定法规要求提交的信息。像“付费”这样的动词术语表示使用函数模板注解制定法过程。

他们的工具为人类注解预处理了制定法文本，识别建议注解者应用相关模板的各种单词、概念和短语。如图 9.4 所示，该工具使用单个下划线来表示数据模板，用双下划线表示函数模板，用虚线表示定义模板。

人类选择与提示相关联的模板并手动填写所需信息。定义模板请求术语和定义。在图 9.4 的上下文中，这将是“合格的接收者”，“具有接收者资格的人。” 功能模板请求过程、任何模态限定和条件，例如“付费”，“应该”，“关于天数”。数据模板请求文章标识符、参与者、行为、数据和来源，模态限定符和条件，例如“15（2）款”，“公务员”、“输入”、“合格接收人就业申请数据”，“应当”和“离职后”。

在一个分为两组的小型实验中，每个小组由两名公务员和一名学生组成，注解了他们不熟悉的日本法规的多个条款，一组有工具，一组没有。该任务的重点是注解条款中的制定法功能，研究者已经确定有 22 个。使用工具的小组参与者更快地完成了注解任务（平均 9.5 和 11 小时）并在识别功能时实现了更高的准确率和覆盖范围。

这两个项目说明了工具的效用，这些工具使用知识工程规则和模板来部分注解文本以支持人类注解。这些工具不仅可以使人类注解者的工作更有效，而且还可以使非专业人员能够和专家一样进行注解。这可能有助于满足日益增长的注解需求，以便为概念检索（第 6.5 节）索引法规，以及为机器学习编译训练集以自动化注解。例如，上述工具可以帮助非专业人员根据参与者、行为、模态限定符和条件来注解法规，这些工具有助于为机器学习注解公共卫生法规，自动注解和建构制定法网络，正如第 9.7.1 节描述的那样。第 10.6 和 12.5.2 节还讨论了对法规和案例的人工注解——包括学生注解和通过众包的注解——和机器学习的计算机化支持。

## 9.7. 将功能信息提取到比较规则

业务合规性的一个重要组成部分是需要比较跨辖区的类似用途的规章。许多行业和商业机构跨越多个州和国际边界。在保险、医疗保健、计算机安全和隐私规制等领域，这些机构受多州法律的约束。虽然不同的州和国家规制框架的总体目标可能相似，但规章本身可能在很多方面有所不同。跟踪差异并将差异纳入监管合规的计划是持续关注之事。
