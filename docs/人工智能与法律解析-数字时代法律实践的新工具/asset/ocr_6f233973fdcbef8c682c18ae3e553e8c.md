人们已经开发了一些自动化技术来维持法规的同构表示。例如，本奇 - 卡彭（Bench-Capon，1991）的研发环境在法规的文本、逻辑和媒介表示之间维持着一系列复杂的链接。在这样的环境中，规则的改变可以以局部的方式进行。文本和逻辑规则之间的链接可以帮助验证。此外，诸如制定法规则的文本摘录以及评论和案例的链接等裁判辅助工具可以链接到程序对结论的逻辑解释。然而，用于维护这种忠实表示的技术要求保持多种表示（该开发环境有三个），并且要求复杂的软件来跟踪它们。

# 65 能够临时表达不同类型的义务和理由

业务流程合规建模的语言需要具有正确的“语义”，用于表达法规和规章所采用的各种规范性概念以及它们所施加的各种义务。义务可能因以下方面而有所不同：

+   - 需要在其生效期间的所有实例中遵守，
+   - 在生效时需要至少实现一次，
+   - 即使在义务实际生效之前，也可以履行，
+   - 需要立即实现或触发违规，
+   - 这样可以补偿违规行为，或者
+   - 被侵犯后仍然存在。（Hashmi 等，2014）

支持表达这些不同类型义务的语言也需要能够进行时间推理。除了义务持有多长时间之外，法律规则还有其他时间属性，包括“规范生效和 / 或已经颁布的时间”和“规范可以产生法律效果的时间”。有关维护技术和用多种制定法条款版本进行时间推理的讨论见帕尔米拉尼的论文（Palmirani，2011）。
