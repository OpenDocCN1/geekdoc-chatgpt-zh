# 2.3.3. 作为设计约束的句法歧义

在转向大规模法律逻辑编程序的示例之前，让我们总结一下句法歧义的含义。

句法歧义，使得将制定法文本转换成用计算机形式化逻辑规则的任务成为问题（Allen and Saxon, 1987）。在计算机表达的规则中，句法歧义可以被消除。问题在于，选择用于形式化为逻辑编程语言（如逻辑编程）的制定法规则的版本不一定是立法机构所预期的。

作为句法歧义的结果，知识工程师无法确定立法机构的意图。将标准化过程应用于甚至相当简单的制定法条款导致句法上的多种可能解释，这令人不安。第3505 节——第四修正案排除规则的拟议限制——规定：

除法律明确规定外，如果搜查或扣押是在合理诚信的信念下进行，则它符合美国宪法第四修正案，在美国法院的诉讼程序中不得排除因搜查或扣押而获得的证据，并且这些证据是可以接受的。证据是根据并在逮捕令范围内获得的，对此的证明构成了这种合理诚信信念的表面证据，除非该逮捕令是通过故意和重大失实陈述获得的。

虽然只有两个句子长，但在标准化时，第 3505 节仅仅根据条款中的句法歧义得出了 48 种不同强度的解释，它们的强度根据其限制性或包容性衡量（Allen 和 Saxon，1987）。

实际上，只有少数版本看起来是明显合理的，而其他版本可能显然是不合理的。问题是谁选择？如果知识工程师决定实施哪个标准化版本，则它不是权威选择。法律学者或某一领域的其他专家可以表达对立法机构打算或应该打算采用哪种版本的意见。然而，唯一能够进行权威选择的机构是立法机构。
