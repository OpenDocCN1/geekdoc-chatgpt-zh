即使它们没有共享相同的因素。案例论证系统通过这种方式可以在更高的抽象层次上进行类比。

案例论证系统也可以淡化或强调区别。如图 3.7 所示，如果一方的论点引用了当前事实情境中特定的区别因素，那么该程序可以基于同样的原因通过指出被引案例中的另一个因素来淡化它。或者，该程序可以通过概括差异来强调区别，这种差异是基于因素层级中具有共同根源的其他因素的更抽象案例之间的差异。

# 表 3.1. 商业秘密因素 (Aleven, 1997)

| 因素 | 意义 | 阐述 |
| :--- | :--- | :--- |
| F1 在谈判中披露（D） | P 在与 D 谈判时披露他的产品信息 | P 把他的财产拿走了 |
| F2 贿赂员工（P） | D 支付 P 的前雇员换工作，显然是为了诱使员工带来 P 的信息 | D 通过不正当手段获得了 P 的财产 |
| F3 员工是唯一的研发者（D） | 员工 D 是 P 的产品的唯一研发者 | D 应该在他的发明中拥有财产权 |
| F4 同意不披露（P） | D 与 P 签订了保密协议 | P 采取合理措施保护他的财产 |
| F5 协议没有特别规定（D） | 保密协议没有规定哪些信息被视为机密信息 | P 没有具体说明他声称的财产权益 |
| F6 安全措施（P） | P 采取了安全措施 | P 采取了合理的措施保护他的财产 |
| F7 带来工具（P） | P 的前员工将产品研发信息带给了 D | D 偷了 P 的财产 |
| F8 竞争优势（P） | D 访问 P 的产品信息节省了时间或费用 | P 的商业秘密是有价值的财产 |
| F10 向外人披露秘密（D） | P 向外人披露了其产品信息 | P 把他的财产拿走了 |
| F11 垂直知识（D） | P 的信息是关于客户和供应商的（这意味着它可以独立于客户甚至目录） | P 不能对其客户的业务信息拥有财产权益 |
