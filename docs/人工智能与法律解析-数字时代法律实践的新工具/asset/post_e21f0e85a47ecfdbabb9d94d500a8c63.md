对《英国国籍法》程序的输入是对涉及公民身份问题的描述。程序输出答案和解释。问一个问题等同于陈述一个命题并要求逻辑编程证明它。例如，一个此类命题是：

A：根据条款 z，在那一天（1984 年 1 月 16 日）彼得是一位英国公民。

在这里，z 是一个变量，代表法规某些节的序号，它可以确保结论。逻辑编程既是编程语言又是定理证明者。给定 A，逻辑编程试图建构一个证明，通过从结论 A 向后推理来识别 A 需要满足的条件。（向后链接在第 1.3.1 节中介绍过了）在这个过程中，它找到所有以 A 形式命题结束的规则。可能有许多不同的规则来建立结论 A，逻辑编程将尝试按照所有规则的编写顺序来排列。

假设有一个 n 个规则的列表，其结论是 A。如果逻辑编程正在考虑该列表中的规则 r_i，那么我们将列表中的下一条规则称为 r_i+1。最后，当逻辑编程正在考虑规则 r_j 时，如果它找到一条新规则，其结论是规则 r_j 的前件，那么让我们将新发现的规则称为 r_j1，并将其称为规则 r_j 的“后代”，这是一条证明 A 的路径。

逻辑编程将以深度优先搜索顺序尝试列表中的 n 条规则。在深度优先搜索中，程序在从 r_i+1 开始新路径之前，遵循从列表中的一条 r_i 到其结束的路径，不管成功或失败。换句话说，如果逻辑编程正在考虑规则 r_i，程序在继续查找列表中的下一条规则 r_i+1 之前总是选择尝试发现规则 r_i 的后代 r_i1。当且仅当来自 r_i 的路径没有证明 A 时，它将继续查找 r_i+1。

相反，在广度优先搜索中，程序在搜索后代的任何后代之前，试图为 n 条规则中的每条规则打开路径。也就是说，即使基于搜索的程序找到规则 r_i 的后代（即 r_i1），它在尝试查找 r_i1 的后代之前，也选择尝试为列表 r_i+1，r_i+2，……, r_n 上的每下一条规则找到后代。

为了得出结论 C，每条规则都有需要满足的条件 B_1……B_n。请记住，逻辑编程将这样的规则视为一个程序：显示 C，显示 B_1，显示 B_2，……并显示 B_n。对于这些 B_n 子问题中的每一个，逻辑编程通过以下四种方式中的一种方式予以解决：

- 1. 可能有另一条规则，其结论是 Bn 的形式。
- 2. 可能有一个满足 Bn 的事实。
- 3. 系统可以询问用户 Bn 是否为真。
- 4. 系统可以询问专家 Bn 是否为真。

## 2.3.5. 将制定法转换成程序的某些问题

在设计和实现《英国国籍法》的计算模型时，设计者遇到了四个问题或约束：有时需要重新表述先前表述的规则或谓词。此外，需要解决法规对否定、缺省推理、反事实条件和开放结构术语的使用问题。

### 重新表述

将大量的法规形式化是一个试验和试错的过程。人们经常遇到一个新的语境，规则概念先前的表述是不充分的，并且必须重新表述以适应该法案中后续规则所施加的额外限制。例如，研究人员发现“仅仅得出一个人是英国公民的结论是不够的；还有必要确定获得公民身份的相关条款。”此外，一个新遇到的条款明显需要“更明确的时间处理”来计算约束，使得一个非英国公民随后在某些情况下被登记为英国公民（Sergot 等，1986，p.374）。研究人员不得不改变一些现有的规则、条件或参数或添加新的规则以解决新的约束。

### 缺省推理

作者指出，《英国国籍法》采用缺省推理。“如果新信息以后是可以获得的，相反信息缺省情况下做出的结论可能不得不撤销”（Sergot 等，1986, p.381）。

一个例子是《英国国籍法》的第 1-(2) 节，该条款涉及遗弃婴儿。作者追问，如果弃婴的父母——他们的公民身份是在信息缺省的情况下被授予的——突然出现但不是英国公民，那会发生什么？（同上）。《英国国籍法》似乎没有对这种可能发生的事情做出规定，但即使这样做，也会出现问题。

缺省推理是非单调的：根据新事实，曾经证明的命题可能需要撤回。谓词逻辑（即逻辑编程中实现的经典一阶逻辑）是单调的；它不支持撤销已被证实的命题。①

### 反事实条件句

法规通常还利用反事实条件句，例如“会 [ 成为英国公民 ]，但因为他已经去世或 [ 通过 ] 放弃……而不再是公民。”立法机关可以采用这种表述作为引用的快捷手段。“起草人避免通过 [ 引用 ] 立法的某些其他部分明确列出一系列复杂条件”，条件可以从这些立法中推断出来（Sergot 等，1986，p.382）。

研究人员制定了特殊规则来处理这种反事实条件句。他们写了“额外的替代规则；例如，一套描述在那个日期活着的个人开始获得公民身份的条件，另一组描述在那个日期之前死亡但在死亡前其他方面满足所有其他必要条件的个人”（同上）。

研究人员仔细解析了法规，以假设哪些要求可能合理地适用于反事实条件句。这增加了需要形式化的规则数量。根据上述，立法起草人采用反事实条件句来避免拼写出这些条件的繁琐工作。另一方面，起草人总是有可能将问题保持开放。

无论如何，这是另一个需要知识工程师在没有立法授权的情况下做出疑难解释决定的例子。

## 2.4. 制定法解释的复杂性和论证的需求

《英国国籍法》项目聚焦于“实施规则和规章的有限目标，其目的是把它们机械地应用于个案”（Sergot 等，1986，p.372）。《英国国籍法》程序从未打算模拟法院制定法推理的输出，但有趣的是比较它通过逻辑演绎生成答案的方式（如图 2.5 所示）与法院的所作所为。

法律哲学家朗·富勒在一篇具有里程碑意义的文章中展示了机械适用法律规则的方法的局限性。“第二次世界大战中使用过的卡车”，“以完美的工作秩序”，“安装在公园的基座上”违反了禁止任何车辆驶入公园的规定吗？（Fuller，1958，p.663）。或者假设一个市政规章规定，“在任何一个火车站睡觉都应该是轻罪，应罚款 5 美元。”一名警察在车站遇到两个人：

第一个是一位因火车延时而于凌晨 3 点仍然等待的旅客，当他被逮捕时，他正在安静地坐着，但执行的官员听到了他轻微的鼾声。第二个是一位带着毯子和枕头去车站的人，显然是想在车站过夜的，然而他还没来得及睡觉之前就被逮捕了。（Fuller, 1958, p.664）

根据该规则的机械适用，第一人违反规则但第二人没有；前者在火车站睡着了，但后者不是。然而，基于市政规章的可能目的，这似乎是完全错误的结果。正如富勒所问，“真的有可能在不知道法规目的的情况下解释法规中的一个术语吗？”（同上）。

确定制定法条款的含义并将其应用于具体事实情境的过程通常被称为制定法解释。当法院将“法规适用于特定案件，以便就争议或审判中的事项做出权威的和具有约束力的决定”时，当法院“形成一种似乎可以适用于这个案件的法规的适当含义的观点”时，当法院阐明“应该以这种方式理解法规的观点”时，法院就是在从事制定法解释的工作（MacCormick 和 Summers, 1991, p.11 及下页）。

制定法解释的过程涉及逻辑演绎，但相当复杂。麦考密克和萨默斯确定了制定法解释论证类型的层级，包括：

- 语言学：来自法规的普通含义或技术含义的论证（即法律或特定领域的技术含义）。
- 系统性：来自语境协调、先例和类比的论证，逻辑概念论证以及来自一般法律原则和历史的论证。
- 目的/评价：来自目的和实质理由的论证。
- 跨类别式：包括来自意图的论证（MacCormick 和 Summers, 1991, pp.512-515）。

禁止在火车站睡觉的市政规章的目的论证是一个目的/评价论证的例子。可接受的技术清单及其标签与法律体系或传统有关，并且可能饱受争议。

## 2.4.1. 制定法解释的逐步过程

作者将这些论证类型组织成一个简化的接近算法的制定法解释模型（MacCormick 和 Summers, 1991, p.531）。根据这一过程，在解释制定法条款时，人们以下面的顺序考虑三个层级的论证：（1）语言论证，（2）系统论证，（3）目的评价论证。

更具体地说，该过程基于论证指定了做出决定的步骤：

层级 1：除非有理由继续进行到层级 2，否则在层级 1 接受初步证明是明确的解释；

层级 2：在有充分理由证明层级 2 的情况下，除非有理由进入层级 3，否则在层级 2 接受初步证明是明确的解释。

层级 3：如果处于层级 3，则仅接受整个可适用论证最佳支持的解释（MacCormick 和 Summers，1991，p.531）。

一般而言，在上述一系列步骤中，意图论证和其他跨类别论证（如果有的话）偏离了上述表面的排序，作者建议将它们视为或许相关的根据。

鉴于这种对制定法解释的复杂描述，人们可以领会安·加德纳的观察，即法律是一种“规则指引而非规则治理的活动：‘专家可以用规则做更多的事情，而不仅仅是遵循规则……（他们）可以争论规则本身’"（Gardner，1985 引自 Berman 和 Hafner，1988，p.208）。

为了将制定法解释的法理学学模型（MacCormick 和 Summers，1991）应用于具体情景，人们不得不将基于规则、案例和潜在社会价值的推理与立法目的相结合。至关重要的是，推理者需要提出或考虑支持和反对一种解释的论证。解释过程的每一步都涉及做出和评估各种类型的论证。一个推理者需要在当前案例和过去案件之间进行类比，法院将法律规则或法规、价值理由和潜在于法律规则之中的目的（在法规和先例中阐明的）适用于案件。即使有人演绎地适用制定法规则，他 / 她也需要考虑提议的结果是否与潜在于法规之中的目的和政策一致。

尽管本书第一部分描述的《英国国籍法》程序和其他程序实现了法律推理的计算模型，但它们都没有像麦考密克和萨默斯（MacCormick 和 Summers，1991）所描述的那样实现全面的制定法解释过程。

相反，人工智能与法律领域发明了可以实现部分过程的组件。例如，《英国国籍法》程序根据逻辑编程规则所表示的法规的简单含义构建了一个证明。第三章描述了基于案例的法律推理的计算模型，并考虑了如何考虑潜在的政策和价值。第五章描述了法律论证的计算模型，它提供了一个框架，人们可以想象使用麦考密克和萨默斯模型实现制定法解释的计算过程。例如，参见抓取解释性论证的初步形式框架（Sartor 等人，2014）。

## 2.4.2. 法律不确定性的其他渊源

然而，如果目标是为了制定法解释的目的而来建构论证模型，那么为什么像《英国国籍法》程序那样的经典逻辑演绎方法不足够的理论理由是存在的。对方当事人经常从不同的前提开始。他们不同意手头的案件事实或适用的法律规则。然而，在法律上，对于不一致的结果遇到合理的论证是很普遍的，在这种情况下对方当事人似乎同意事实以及适用的法律规则。如上所述，这是“法律不确定性”现象（Berman 和 Hafner，1988）。

第 2.2.1 节中约翰逊案中已经说明了法律不确定性的一个来源。法律规则采用具有开放结构的法律概念，对于这些法律概念可以做出合理但相互矛盾的论证。

另一个来源涉及规则应用的未陈述条件，例如其结果与某些抵消原则一致。

里格斯诉帕尔马案（Riggs v. Palmer，115 N.Y. 506，1889）阐述了这种情况。该案涉及一名谋杀了他的祖父的继承人，根据他祖父的遗嘱，他将继承祖父的遗产。法院指出，“的确，制定法规定了遗嘱的制定、证据和效力以及财产的转移，如果从字面上解释，……把这个财产交给谋杀犯。”（同上）

然而，法院拒绝执行这条法律，因为它违反了“普通法的基本原则”和“由公共政策支配”，即“任何人不得从自己的欺诈或者错误行为中获得利益，或发现基于自己的罪孽的任何权利请求，或通过他自己的罪行获得财产”（同上）。

法律规则可能有其他未说明的条件，例如：规则满足法律要求的选择吗？规则符合宪法要求吗？可以想象，其中一些条件可以表示为法律规则的附加条件。然而，伯曼和哈夫纳指出，像上面经常违反“基本原则”这样的抽象条件很难形式化（同上）。

基于法律不确定性的现实，伯曼和哈夫纳认为，经典的逻辑模型不适合对法律人如何推理进行建模。

> 法律不确定性对逻辑有效性概念提出了直接的挑战，因为如下事实：法律人必须能够论证一个结论或其相反的结论。
> 
> 假设存在一个具有结果 C 的理论 T（即，存在一个有效的逻辑论证，其前提是 T 的公理，其结论是 C）。然后我们知道在每个 T 模型中 C 都是真的；也就是说，在每个领域中 C 都是真的，在那种情况下 T 的公理都为真。根据矛盾定律，我们也知道如果 C 为真，那么非 C 必假：所以，在每个 T 模型中，非 C 都是假的……
> 
> 我们 [ 也 ] 表明没有以 T 公理开头的有效论证（无论我们做出什么额外的假设）可以得出结论非 C。
> 
> 从一组前提开始并创建一个同时支持一个结论及其反论的有效论证从逻辑上讲是不可能的。这种限制当然是有道理的，但在法律中，这种 “逻辑上的不可能性” 似乎是正在发生的事情！
> （Berman 和 Hafner，1988，p.191）

矛盾命题对于经典逻辑模型也是有问题的，因为如果两个命题都为真，那么可以证明任何东西（见 Carnielli 和 Marcos，2001）。阿什沃思（Ashworth）等人讨论了从哲学史中得出的经典演绎的这种 “爆炸性” 特征的一个有益的例子（1968，p.184）。一个 16 世纪的意大利人证明了 “从一个不可能的命题推出任何东西，通过证明 ‘苏格拉底是和苏格拉底不是’ 推衍出 ‘人是马’ ”：

- 1. “苏格拉底是和苏格拉底不是暗示苏格拉底不是。”
