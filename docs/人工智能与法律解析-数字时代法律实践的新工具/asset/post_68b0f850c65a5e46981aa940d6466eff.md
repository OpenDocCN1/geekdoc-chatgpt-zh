标准化折现累积增益的直觉是每个相关文档对一个排名总体质量的贡献，其根据是它相对于理想排名的排序。折现累积增益是排名项目相关性的权重总和。项目的排名下降，权重也下降。从这个意义上讲，增益是“打折的”。通常，使用对数折扣函数数来模拟下降的权重。标准化折现累积增益（NDCG）以最佳排序结果的折现累积增益度量——理想折现累积增益（IDCG）——除以折现累积增益，并且结果总是[0，1]区间的数字（见 Wang 等人，2013）。

为了测量整个系统的表现，关于所有查询的系统排名表现是根据平均精确率度量（MAP）和平均标准化折现累积增益来衡量的。

平均精确率度量是每个查询的平均精确率（AP）的所有查询集合的平均值。它被定义为：

```
MAP(Q) = \frac{\sum_{i}^{|Q|} AP_i}{|Q|}
```

其中 Q 是所有查询的集合，APi 是每个查询的平均精确率。平均标准化折现累积增益（Average NDCG）被定义为：

```
AverageNDCG = \frac{\sum_{r}^{|Q|} NDCG_i}{|Q|}
```

① 对于更倾向于技术的读者，在卢依马实验中，标准化折现累积增益的定义如下：

```
NDCG = \frac{DCG}{IDCG} \qquad DCG_p = \sum_{r}^{p} \frac{2^{relevance_i}-1}{log_2(i+1)}
```

在这里相关性 i ∈ {0, 1}，p 是排名位置，在我们的案例中高达 30，使用预测排名计算折现累积增益，并且使用真实排名计算理想折现累积增益。

标准化折现累积增益（NDCG_i）是每一次查询的标准化折现累积增益（Burges 等，2005；Grabmair 等，2015）。

顺便提一下，由于真正的排名是通过重新排列商业法律信息检索系统检索到的案例创建的，因此每个基准结果的召回率（即，响应查询的所有相关文档的覆盖范围）为 1。此外，由于卢依马搜索将所有无响应文档附加到检索到的案例的末尾，实验系统无法根据召回率比较基准线。

## 改进卢依马的性能

在接下来的工作中，研究者通过使用词性标记扩展结构化查询，证明了卢依马搜索准确率的提高。也就是说，系统使用由每个单词充当的词性（名词，动词，确定符等）自动标记文档句子和查询文本的内容，并且在查询和句子之间考虑词性标签的相似性。

他们还改善了卢依马重排的性能。他们仅根据前 N 个检索结果中的句子数量修改了之前的投票方法，并根据 BM-25（最佳匹配 25）度量标准添加了新的重新排名特征，这是对词频 / 反文档频率权重的细化，这更好地解释了句子和文档长度中任何引用的类型和位置（Bansal 等，2016）。

## 讨论

对卢依马的评估表明，文档中卢依马类型（疫苗、伤害、因果关系和句子类型）实例的自动注解及其在索引和查询中的使用，相比不使用此类信息的商业法律信息检索系统，产生了更好的重排表现。概念法律文档检索系统聚焦于与论证相关信息，来自自然语言法律文档到检索结果，这种检索系统至少对于疫苗伤害索赔领域中的一组有限文档是可行的。

通过注解句子角色类型，例如基于证据的发现，以及法律决定或法律裁决，论证检索系统可以帮助用户找到“应用案例”。除了在摘要中支持法律命题之外，这些案例是将一个命题应用于可能类似于用户问题的具体事实（见 Mart, 2010, p.222）。

卢依马注解根据它们在论证和各种子句注解中的句子级别角色标记检索到的案例句子，原则上系统可以为用户突出显示与论证相关的信息。特别是，可以按照适合用户的论证需求的方式总结检索到的案例。丹尼尔·朱拉夫斯基（Daniel Jurafsky）区分了提取和抽象概括：

> 提取摘要通过从文档（片段）中获取一组短文本片段来回答查询……抽象概括至少少部分地用不同的词来表述［在文本中的］理念。抽象摘要更接近于法律备忘录中的语言，它目前是一个重要的研究目标，但非常困难。（Remus 和 Levy, 2015, p.22）

据推测，由卢依马注解识别的与论证相关的信息，例如句子是否陈述法律规则，是否通过使用法律规则于事实来获得法律结论，或报告事实发现，可以帮助程序执行抽象概括或至少在提取摘要方面做得更好。

总而言之，卢依马系统实现了特定于法律文本信息的一般和以域为中心的注解类型。它用手工制作的规则识别子句注解，用在一小组金标文档上训练的机器学习句子分类器识别和句子层级注解。通过在检索和重新排序过程中考虑这些注解，卢依马对检索到的文档进行排名的结果优于商业全文法律检索系统基线。然而，这些结果需要在更大更多样化的数据集的测试中得到确认。这项工作目前正在进行中。

## 11.5. 继续将法律信息检索转换为论证检索

卢依马的设计者已经应用法律专业知识来智能地设计论证挖掘的功能，从而产生“更智能”的机器学习和更智能的重新排名，即使数据量远远小于数据挖掘的数据量（Grabmair 等，2015）。卢依马从法律信息检索转换为论证检索还有很长的路要走，但它提供了概念检验和架构基础。

前进的道路似乎很清楚，但存在许多挑战。如下所述，关键是扩展在案例文本中注解与论证相关的信息、实质性法律信息和命题信息的技术。

本书的重点是未来的工作；目标是详细描述其他人可以遵循的路径。本书将解释未来的法律论证检索 / 认知计算系统（称为 LARCCS）如何与法律信息检索系统连接，并说明它可以支持的新型概念查询以及商业法律信息检索系统目前无法支持的概念查询。它描述了类型系统的一些扩展，它们将启用新类型的概念查询，并解决自动注解扩展类型和在查询中引出用户论证需求的前景。

虽然这一节描述了未来的工作，但它不仅仅是“天空中的馅饼”。建立卢依马的经验，人工智能与法律研究人员从案例中提取与论证相关信息的经验（第 10 章中描述的），以及将这些技术与现有的法律推理和论证计算模型联系起来的目标，得出构建法律论证检索 / 认知计算系统原型的计划。

## 11.5.1. 连接法律论证检索 / 认知计算系统与法律信息检索系统

卢依马提供了将法律论证检索 / 认知计算系统原型连接到现有法律信息检索系统的指南。卢依马的注解和重新排名技术可应用于由更传统的法律信息检索系统检索的文档。由外部全文法律信息系统使用正常倒排索引、相关概率模型和重新排名技术（第 7.4 节）检索的排名前 n 位的案例可以被输入文本注解管道。

通过添加执行语义标记和重新排名的能力，信息检索系统的输出可以根据与论证相关的标准进行重新排序。结果，这些系统可以有效地考虑关于用户为什么寻求信息以及他 / 她打算如何在论证中使用它的更详细信息。外部信息检索搜索系统 [ 如律商联讯高阶、万律进阶或谷歌学术案例（ Google Scholar Cases ） ] 可以执行自己的重新排名，但据我们所知，此类重新排名不包括与论证相关的信息。

因此，原则上，用于法律文档的智能语义分析技术可以在没有中断信息检索数据库和索引的情况下改善信息检索系统的性能。语义注解和基于论证的重新排名仅仅外在地应用于信息检索系统的输出。文本注解技术是否可以足够有效地应用于信息检索系统输出的数十、数百或数千个文档是需要注意的。出于讨论的目的，我们假设足够的工程资源承诺是可能的。这是一个很大的假设，但我的目标是激励，为什么这样的努力值得投资。

## 11.5.2. 用扩展的与论证相关的信息查询案例

更全面的论证类型系统根据法律上重要的概念和关系检索、排序和汇总文档，这将支持用户表达具有更广泛的与论证相关的约束的更广泛的查询。

例如，代表疫苗案件中的客户的律师可能想知道在什么案件中特殊法官做出了基于证据的发现，发现特定疫苗如麻疹、腮腺炎和风疹（ MMR ）引起特定的状况，比如顽固性癫痫症。律师可能想知道法院接受的证据种类，甚至更紧急的是，在其他判决中有些发现和证据表明麻腮风疫苗不会导致这种情况。

辩护律师也可以在涉及特定事实的情况下寻求适用法律规则的案件。涉及商业秘密盗用案件的律师可以寻找如下案件：根据定义商业秘密盗用索赔的特定要素的法律规则，法院裁判支持或反对一方当事人。律师希望找到如下案例：他当前问题的事实在这些案件中也存在，例如原告的产品是独一无二的，原告采取了一些安全措施来保护信息，例如获得被告的保密协议，但有也是在公共论坛上披露了一些信息。

普通的法律信息检索系统可以基于图中的查询单词检索材料，但是它们并不理解与论证相关的概念和约束。专门基于文本的搜索引擎将这些简单地视为附加的普通关键词，而不是视为指定与论证相关的信息的法律概念，这些信息关乎所寻求的案例文档中类似句子的目标角色。它可以使用关键字查询扩展或法律同义词库，但即使这样，概念标签的关键字符仍然存在。即使法律信息检索系统可以检索与自然语言查询相关的案例，它也不能使用与论证相关的信息来按照用户试图解决的问题的方式对案例进行排序或汇总。如果它能够理解和控制这些约束，用户将享受到前所未有的表达和发现他们真正想要的东西的能力。

如第十二章所述，法律论证检索 / 认知计算系统方法可以帮助像法律机器这样的新商业法律应用程序（见第 12.2 和 12.3 节）将与案例的实质优点相关的语义特征考虑在内，以便进行检索和预测。第 12.4.1 节表明基于法律论证检索 / 认知计算系统的法律应用程序如何处理类似于图 11.5 和 11.6 中的查询并参与认知计算，使人类用户能够针对案例语料库测试法律假设。然而，在解决这些可能性之前，至少需要解决三个挑战：

- 1. 扩展类型系统以支持更广泛的论证、文档和特定领域法律现象的更广泛的概念查询。
- 2. 使用扩展类型系统注解文档。
- 3. 以方便可靠的方式引出用户的论证需求。
