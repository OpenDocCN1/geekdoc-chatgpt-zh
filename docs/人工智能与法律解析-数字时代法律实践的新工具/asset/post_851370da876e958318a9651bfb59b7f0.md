
假设可以关注概念随时间的改变而改变。例如，法院是否以与国会听证会相同的方式处理《健康保险携带与责任法案》隐私规则中的“待遇”概念？根据《美国法典》第 11 卷第 13 章，提交破产计划时“善意”要求的含义有哪些趋势？

法律渊源的形式和性质也会有所不同。律师事务所的法律备忘录和简报记录了该所过去如何解决特定问题或类型的问题。摘要提出了三元组语料库的有趣可能性：律所对一个问题的简要赞成意见，对手的简要反对意见，以及法院解决争议的实际判决。上面扩展的论证类型可以识别关于法律规则要求的竞争结论的嵌套论证结构。然而，需要额外的技术来比较竞争的论证结构，确定它们的突出差异，并以一种得出暂定的战略教训的方式来获取解决方案。

当从法律案例意见、简报和法律备忘录转向法律评论文章和论文时，人们需要扩展与论证相关的类型系统，以包含这些媒介的论证模式。法律评论作者的主张往往更为笼统；他们假设法律的变化及其对政策的影响。这些作者用来证实其主张的论证将更加笼统，因此需要更多地依赖于主张和结论的嵌套论证结构。

最后，对于一些公共利益的场所，过程和任务、假设、相关概念和关系，以及人类用户的专业水平会有所不同。向退伍军人提供建议——关于证明服务相关的创伤后应激障碍的法律问题——的资源将聚焦于在过去案例论证的不同方面，而不是旨在支持他们的公益法律顾问。适应这些更一般的查询和假设需要想象力和意愿，观察真实的消费者、员工和公民如何参与这些过程的意愿。

## 用例中的常见任务

无论用例如何，该方法都将涉及一些基本的查询。人们需要确定一个程序如何帮助从业者应用法律文本中注解的语义信息来回答问题、检验假设、做出预测、解释答案或预测或做出支持和反对结论的论证。对“帮助”的强调凸显了认知计算聚焦于支持计算机系统和人类用户之间的协作。该系统可以访问大量文本信息，但需要组织该信息以帮助人类。

开发者应该调查用户有兴趣测试的假设类型，调查帮助他们这样做的文本信息的类型，调查他们期望支持或反对结论的解释和论证的类型。以下问题的答案应有助于设计恰当的类型系统、注解过程和协作互动：

- 1. 文本文档中的哪些概念对于这些任务最重要，哪些文本参考或提及表明概念存在？（见第 6.7，6.8 和 11.6.1 节）
- 2. 程序如何自动注解概念？（见第九章和第十章）
- 3. 程序如何学习根据注解概念的重要性对候选文本进行排名？（第 11.3 节）
- 4. 程序如何支持用户在构建概念性查询或假设时采用有针对性的概念？（第 11.5 和 12.4 节）
- 5. 程序如何使用检索到的文本来评估假设？（第 12.4 节）

开发者可能仍然想知道从哪里开始问题 1。哪种类型对于提出和评估法律假设很重要？实体法的哪些方面需要加以注解？

答案涉及另一个问题：文档以及它们代表的情境的哪些方面的确要人类根据实质法律特征进行比较？这种比较通常是评价那些预测法律结果、限制和趋势的假设的基础。在某种程度上，可以想象用于这些比较的元素能在文本中注解，它们需要在类型系统中表示。

我们在本书中看到的大多数论证结构能够根据事实情况相对于特定类型的主张的优势来衡量案例的实质比较。案例可以通过以下方式进行比较：

- 增加了判决的价值权衡（基于价值判断的论证预测，第 5.7 节）的法律因素和问题的模型（基于问题的预测，第 4.5.2 节），
- 缺省逻辑框架规则树和证据因素中的要求覆盖（第 5.8 节），
- 法律论证和组件户依马类型中句子的角色（第 6.8 节），
- 标准事实的结构匹配 [ 基于范例的解释生成器（第 3.3.3 节） 和 SIROCCO（第 3.6 节）] ，
- 引用网络的中心性（BankXX，第 7.9.3 节）。

比较规制标准的限制性已经模拟：

- 图表（第 2.5.1 节），
- 要求水印（第 9.7 节），
- 制定法强制互动的网络分析（见第 2.6 和 11.6.3 节），
- 实施概念和概念变化的规则树或判决树的限制性（见第 5.8 节。第 7.9.4 和 12.6 节），
- 比较根据规制标准判决的案件的结果和相对优势的上述组合。

可能是用于比较的概念不可能自动注解（问题 2），例如基于范例的解释生成器或 SIROCCO 中的标准事实的语义网络。或者，也许假设不是程序可以直接处理的类型，但它仍然可以帮助人类用户构建对文档或案例进行比较的概念性查询（问题 4）。例如，程序可以通过网络解析或热图汇总来帮助人们解析制定法或引文网络，但是人类必须提出假设并解释评估。

在某种程度上，为了通过预测和论证（问题 5）评估假设，预期的协作涉及系统用注解信息进行推理，法律论证的计算模型最需要到位。此时，只有上述案例比较类型中的某些类型连接到这样的模型，并且某种程度上可以在文本中自动提取。正如我们在第五章中所看到的，人工智能与法律社区中开发的论证模型可以基于法律因素执行某种程度的预测、论证和推理。当规则树要求、证据因素和法律论证中的句子角色及他们的组件覆盖补充了法律应用程序时，一个法律应用程序可以帮助人类直接从案例文本中提出和评估法律假设。

这项努力的成功将代表认知计算的范例和人工智能与法律的巅峰。

### 12.8. 结论

在帮助人类用户明确提出假设并根据概念约束指定查询和语料库对它们进行测试时，认知计算法律应用程序将使人与计算机进行富有成效的合作。

仍然存在许多挑战，包括对人类注解以及设计新界面的需求，这些新界面能够引出和处理用户的法律假设并帮助他们评估结果。注解需要对界面设计、流程工程和人工进行投资。人们如何合理地扩展跨法律领域的这种资源密集型工作是一个开放的问题。

## 第十二章 认知计算法律应用程序

然而，希望律师事务所、数据库提供者、公司法律部门、政府机构或法律诊所等组织能够支持这项工作似乎是现实的。人们可以定制类型系统以捕获概念和关系，这些概念和关系与特定论证相关的信息检索要求、语料库和法律实践问题相关，人们可以使用最方便的计算机支持的注解环境招募人类注解者，训练机器模型注解数据，并将它们应用于语料库，这些工作一起通过定制的法律论证检索、分析和预测来支持各类组织的运营。

## 词汇表

- **Ablation 切除**  
  "关闭" 模型的知识来源以确定它对模型功效的贡献。

- **Abstract argumentation framework 抽象论证框架**  
  一种论证框架，其论证图只包含相互攻击的论证。

- **Acceptable 可接受的**  
  在给定该阶段的论证和一系列假设的情况下，一个论证中的一个命题可能是真的。

- **Accuracy ( A ) 准确率**  
  正确案例预测除以所有案例预测的比率。

- **Algorithm 算法**  
  用于解决一个问题的一组计算步骤。

- **Area under the ROC curve( AUC ) 接收器操作特性曲线面积**  
  用于评估二进制分类器的机器学习度量，AUC 涉及分类器将随机选择正数数据点（例如，相关规定）排序高于随机选择的负数据点（不相关规定）的概率。

- **Argument mining 论证挖掘**  
  语料库的自动分析，以识别文档中的论证结构，例如前提、结论、论证型式以及论证对之间的论证－子论证和论证－反驳关系。

- **Argument retrieval ( AR ) 论证检索**  
  使信息检索系统能够使用有关命题在法律论证中发挥作用的信息和其他与论证相关的信息，以提高检索性能。

- **Argument scheme 论证型式**  
  具有预定义组件的模板，用于构造论证的典型类型。

- **Argument-related information**  
  与论证相关的信息  
  在法律案例中关于命题作用的信息，在一个案例提出的论证中关于其他文本元素的作用的信息。它对论证检索很有用，包括句子在论证中作为命题、前提、结论，或摘要或特定事实中的规则陈述的作用，包括句子作为案例裁决和事实发现、法律因素和证据因素的作用。

- **Argumentation framework**  
  论证框架  
  将论证定义为包含前提、结论和例外的结构。

- **Attribution**  
  归属  
  在一个法律判决中，信息传达或影响法院对论证信念的判断。

- **Augmented Transition Network (ATN)**  
  扩充转移网络  
  将涉及事件顺序的问题解析为一系列状态和规则定义的从一个状态到下一个状态的可能转换的图形结构。

- **Average precision (AP)**  
  平均精确率  
  排名表现的度量，等于检索到的文档的比例的平均值，这些文档与检索到的排前i名的文档是相关的。

- **Backward chaining**  
  反向链接  
  测试任何规则的结论是否是预期的目标，并将该规则的条件添加到预期的目标集合中。

- **Bag of words (BOW)**  
  词袋  
  将文档表示为忽略文档中术语的顺序的术语集合。

- **Bayesian network (BN)**  
  贝叶斯网络  
  概率因果关系的图形模型。每个节点表示一个带有变量的事件，以指示它是否已经发生。孤表示影响事件发生可能性的因果影响，包括与那些因果影响相关的条件概率。

- **Bipartite**  
  二分图  
  一个论证图，用于区分支持命题的命题和论证以及攻击命题的命题和论证。

- **Boolean relevance measure**  
  布尔关联度量  
  在信息检索系统中，针对要检索文档的一组逻辑标准。

- **Breadth-first search**  
  广度优先搜索  
  给定一个用于给定结论的规则列表，程序在尝试证明任何规则后代的后代之前，试图证明列表上每条规则的后代规则。

- **cfs**  
  当前事实情境  
  这代表“当前事实情境”，即关于将做出哪些论证的手头案件。

- **Citation network diagram**  
  引文网络图  
  法规、规章条款或案例系统表示为它们之间的参考关系的网络或图表。

- **Cognitive computing**  
  认知计算  
  通过人和计算机一起工作协同解决问题，各自执行各自做得最好的智能活动。

- **Computational model of legal reasoning ( CMLR )**  
  法律推理的计算模型  
  一个计算机程序，用于实现证明人类法律推理属性的过程。法律推理的计算模型实现法律论证的过程被称为法律论证的计算模型（ CMLAs ）。

- **Conceptual legal information retrieval**  
  概念法律信息检索  
  根据匹配文档的概念和角色以及解决用户法律问题所需的概念和角色，自动检索与回答用户问题相关的文本法律信息。

- **Confidence interval**  
  置信区间  
  在统计估计中，估计值的范围包含关于群体中感兴趣特征的真实值，具有期望的置信水平。

- **Confidence level**  
  置信水平  
  在统计估计中，源于随机样本的置信区间的概率将包括具有感兴趣特征的群体中元素的真实百分比。

- **Critical question**  
  关键问题  
  论证型式的组成部分，处理该型式的前提的可接受性，并指出该型式可能不适用的特殊情况。

- **Cross validation or k-fold cross validation**  
  交叉验证或 k- 折交叉验证  
  用于评估机器学习程序的标准流程，其中数据被分成 k 个子集或 “ 折 ” 。在每一次 k 轮中， k 子集中不同的一个子集被保留作为测试集。使用 k-1 子集作为训练集训练机器学习模型。

- **Decision tree**  
  决策树  
  一种机器学习技术，它学习一组树状的问题或测试，以确定新实例是否是分类器的正实例。每个问题都是一个测试：例如，如果特定要素的权重小于阈值，则以一种方式分支，否则以另一种方式分支。

- **Defeasible rule**  
  可辩驳规则  
  当规则的条件得到满足时，其结论可能成立的规则，但不一定是真的。

- **Depth-first search**  
  深度优先搜索  
  给定用于给定结论的规则列表，程序试图证明当前规则的后代，并且如果成功，则在尝试列表上的任何其他规则之前使后代成为当前规则。

- **Dimension**  
  维度  
  在海波程序中，表示法律因素的一般性框架

- **Document-term matrix**  
  文档词项矩阵  
  在来自文本的机器学习中，一个用行和语词表示的电子表格。每行是根据单词/特征来表示文档的向量，它包含语料库中的所有单词/特征表示的文档向量。

- **e-Discovery**  
  电子发现  
  在审前披露中电子存储信息（ ESI ）的收集、交换和解析。

- **Elusion**  
  规避  
  在信息检索中，相关的未被检索到的文档的比例。

- **Evidence factor**  
  证据因素  
  指示事实审理者陈述结论和似真性分配的理由。说明为什么证据足以证明法律规则的前件（ 或不是 ）。

- **Extensible Markup Language ( XML )**  
  可扩展标记语言  
  用于以人类可读和计算机可读格式注解（即标记）文档的标准化规则集。

- **Extensional definition**  
  外延定义  
  提供什么是 / 不是概念实例的示例。

- **F1-score or F1-measure**  
  F1 评价或 F1 测量  
  精确率和召回率的调和平均值，两种测量都被视为同等重要。

- **Factor**  
  因素  
  （初始容量）在案例论证系统程序中，一种用于表示简化维度的法律因素的知识表示技术。

- **Feature vector**  
  特征向量  
  文本表示，其中每个特征的值是在一个文本中沿着特征维度的特征大小。与术语向量类似，但使用术语和术语频率以外的特征。

- **Forward chaining**  
  正向链接  
  根据数据库中当前事实测试任何规则的条件是否得到满足，并将该规则的结论添加到数据库中。

- **Heuristics**  
  启发法  
  经常有用的“经验法则”，但不保证能够产生正确的结果。

- **Horn clause logic**  
  霍恩子句逻辑  
  大多数谓词逻辑的实现和逻辑编程语言的基础。

- **Hypothesis**  
  假设  
  基于实质性法律考虑的规则式一般化形式的预测，在某些条件下应如何或可合理地决定法律问题的预测。

- **Hypothetical**  
  假设的  
  想象或构造的情境，涉及诸如建议的测试之类假设，旨在探索测试的意义或挑战它太宽或太窄。

- **Intensional definition**  
  内涵定义  
  规定作为概念实例的必要和充分条件。

- **Intermediate legal concept ( ILC )**  
  中级法律概念  
  一条规则的具有开放结构的法律术语，其意义受制于论证。

- **Inverted index**  
  倒排索引  
  一种通用信息检索系统数据结构，它列出出现在数据库中存储的任何文本中的特征，对于每个特征，列出该特征出现的所有文档的记录、它们的位置和频率。

- **Isomorphism**  
  同构  
  正式模型中的规则与建模的立法章节之间存在一对一的对应关系。

- **Legal factor**  
  法律因素  
  常见的观察集合或陈规定型模式或事实的专业知识，这些知识倾向于加强或削弱原告支持法律主张的论证。

- **Legal text analytics**  
  法律文本解析  
  也称为法律文本挖掘：使用语言的、统计的和机器学习的技术自动发现法律文本数据档案中的知识。

- **Lex Specialis**  
  特别法优先  
  解释准则，根据该准则，更具体的法律规则优先于更一般的规则。

- **Logistic regression**  
  逻辑回归  
  一种统计学习算法，可根据自变量值（预测变量）预测成为类别实例的几率。它采用迭代统计程序来估计预测变量的权重。

- **Lucene**  
  卢芭恩  
  阿帕奇开源文本搜索引擎库，支持实现文档术语矩阵以及索引、检索和排名功能。

- **LUIMA**  
  卢依马  
  基于非结构化信息管理架构的类型系统，适用于法律领域。它聚焦于概念、关系和提及，以识别有助于法律信息检索任务的司法判决中的句子的论证功能。

- **Machine learning ( ML )**  
  机器学习  
  可以学习基于数据做出预测的计算机程序。

- **Majority-class baseline**  
  多数类基线  
  无论新问题的实际情况如何，都可以预测大多数类的基线。

- **Mean average precision ( MAP )**  
  平均精确率值  
  对每个查询而言，平均精确率的所有查询集的平均值。

- **Mentions**  
  提及  
  在类型系统中，一种类型捕获方式，其中概念和概念关系在域文本中被引用或表现出来。

- **Model**  
  模型  
  在机器学习中，概括了用于描述或预测的一组数据并且可以用作分类器的结构。

- **Monotonic reasoning**  
  单调推理  
  一个命题一旦被证明就不可能被撤回的逻辑。

- **n-grams**  
  n元模型  
  来自给定文本序列的 n 个项目（例如，单词）的连续序列。

- **Network analysis**  
  网络分析  
  在信息检索中，基于文档的链接和链接权重或其在网络中的概念来得出关于文档的相关性的推断。

- **Non-monotonic reasoning**  
  非单调推理  
  随着信息被添加推论可能改变或变得无效的逻辑。曾被证明的命题或许被撤回。

- **Normalized discounted cumulative gain ( NDCG )**  
  标准化折现累积增益  
  通过累积每个相关文档对排名总体质量的贡献来衡量排名绩效的度量，具体取决于排名相对于理想排名的位置。

- **Ontology**  
  本体  
  与域中的对象相应的概念、概念的关系和属性的一般化形式化说明。

- **Overfitting**  
  过度拟合  
  当机器学习模型过于灵活时，以至于它适合数据中的随机变化，就好像它是结构特征一样。

- **Point estimate**  
  点估计  
  在统计估计中，总体特征的最可能的值。

- **Precision ( P )**  
  精确率  
  正确的正实例预测数量与正实例预测的总数相比的比率。

- **Predicate logic**  
  谓词逻辑  
  逻辑，也称为谓词演算或一阶逻辑，使用逻辑连接词和单独符号表示谓词、主词和量词。通过表示命题的结构来扩展命题逻辑。

- **Presuppositional Information**  
  预设信息  
  在卢依马中，包括与受规制领域相关的事实和语言概念、关系和提及。

- **Pretrial discovery**  
  审前披露  
  处理法律诉讼当事人对对手及其他人手中材料的要求，以揭露事实并为审判提供证据。

- **Probabilistic latent semantic analysis ( PLSA )**  
  概率潜在语义分析  
  一种基于大型文本语料库提取和表示单词的语境使用意义的统计方法。语料库中单词出现或不出现的上下文决定它们意义的相似性。

- **Proof standard**  
  证明标准  
  为论证目的建立命题所需的确实性水平。

- **Propositional logic**  
  命题逻辑  
  采用逻辑连接词和代表整个命题的符号的逻辑。

- **Protocols**  
  协议  
  提供指定人类关注者用于注解文本的语言或逻辑线索的标准和示例。

- **Random forests of decision trees ( RFDT )**  
  决策树随机森林  
  机器学习技术通过对一组决策树进行平均来替换单个决策树，以便在预测中实现来源的多样性。

- **Rebuttals**  
  反驳  
  赞成或反对特定结论的论证。权衡论证和应用证明标准解决冲突。

- **Recall ( R )**  
  召回率  
  正确的正案例预测数与正案例数的比率。

- **Receiver operating characteristic ( ROC )**  
  接收器操作特性  
  用于评估二元制分类器的机器学习度量，接收器操作特性曲线是针对不同可能的判定阈值的真阳性率与假阴性率的关系图。

- **Relevance feedback**  
  相关性反馈  
  在信息检索中，使用用户能够指示返回回响应相关查询并且最能代表用户所寻求的内容的文档的功能。

- **Relevance hypothesis**  
  相关性假设  
  在电子发现中，诉讼律师的理论或主题的抽象描述，如果在文件中找到它们，则使文档相关。
