
## 第二章 建模制定法推理

### 2.1. 导言

法律是一个规则领域，其中许多法律规则都体现在制定法和规章中。由于规则可以逻辑地表达，计算机可以演绎地推理，因此用计算机建构制定法推理模型应该很容易。人们只需将事实情况输入计算机程序；程序识别相关规则，决定规则的条件是否得到满足，并根据适用或不适用的规则解释答案。

然而，建构制定法推理的计算模型提出了挑战。如下所述，法规通常是模糊的，语法歧义以及语义模糊，并且受制于结构的不确定性。如果计算机程序要应用于一条制定法规则，它应适用哪种逻辑解释，它如何处理法规条款的模糊性和开放性，或决定是否存在例外？

本章对演绎地适用一条法规与制定法解释的复杂过程进行了对比，后者经常涉及相互矛盾的合理论证。经典逻辑模型在处理法律不确定性时可能会失效，法律推理的一个共同特征是：即使拥护者对问题中的事实和决定事项的规则达成一致，他们仍然可以做出法律上合理的论证支持和反对一个命题。

然而，用制定法进行推理仍然迫切需要。本章检讨了解决或处理这些问题的各种人工智能与法律方法：系统地阐述制定法的多个逻辑版本的规范化过程，演绎地适用一条制定法的逻辑实施，以及最近的业务流程合规性模型和基于网络的制定法建模，两者都可能对认知计算有用。

本章解决的问题包括：制定法规则在语义上和语法上如何有歧义吗？法律人如何处理这些歧义问题，以及计算机程序如何应对？规范化的法律起草是什么？逻辑编程（Prolog）是什么？逻辑编程程序又是什么？深度优先搜索是什么？它与广度优先搜索有何不同？法律不确定性是什么？为什么它对法律推理的逻辑模型是一个问题？逻辑程序如何评估业务流程是否符合规章？法规的同构知识表示有哪些问题？引文网络和制定法网络图是什么？它们如何支持认知计算？

### 2.2. 建模制定法推理的复杂性

制定法和规章是复杂的法律文本。用法律技术术语写成的经常错综复杂的条款定义了什么是法律、什么不是法律。制定法和规章有大量的交叉引用和例外情形，它们过于复杂，没有受过科班教育的公民难以理解。即使法律专家也可能难以简单地识别所有条款，以及仅与分析给定疑问、问题或主题相关的条款。

人工智能与法律领域长期以来一直在研究如何设计计算机程序，这些计算机程序可以用制定法和规章的法律规则进行逻辑推理。它取得了长足进步，并取得了一些成功，但它也使人们对这个问题的困难程度有所重视。在此过程中，在试图设计可以应用于制定法规则的计算机程序时，该领域已经识别了大量的需要解决或处理的限制。如上所述，这些限制包括：制定法规则中的模糊性和两种类型的歧义，制定法解释的复杂性，支持关于法律规则意味着什么是相互矛盾但合理的论证的需要，以及维护法规与文本规则的逻辑表示的实际问题。

两种类型的歧义使得建构制定法推理的计算模型变得复杂，语义歧义及其姊妹概念模糊性是常见的。立法机关选择的规章概念和术语可能没有界定清楚，无法决定它们是否适用或如何适用。第二种类型的歧义——句法歧义——可能不那么熟悉：立法机构使用的逻辑术语——如“如果”、“和”、“或”和“除非”——引入了对简单法规的多种解释。

### 2.2.1. 语义歧义和模糊性

语义歧义是关于一个术语意义的“相对较少的……不同选择之间的不确实性”（Allen 和 Engholm，1978, p.383）。“模糊性是关于一个术语指称和不指称的精确边界的不确实性”（同上书，p.382）。

两者都是因为如下事实：立法机关可能会使用模糊的或其他定义不明确的术语。沃特曼面临的问题是：定义不明确的法律术语用来构建法律专家系统规则（第 1.3.1 节）。而加德纳试图用她的算法解决这个问题，以区分疑难法律问题和简易法律问题（第 1.4.2 节）。

语义歧义和模糊性是对人类、社会和政治现实的让步。立法机关不能使用足够详细的语言来预见它可能希望规制的所有情境。相反，它在制定法规则中使用了更为一般性的术语，并依赖法院在新的事实情境中解释和应用抽象的术语和概念。故意以语义模糊的方式呈现关键条款也可以促进立法妥协。如果立法机构试图使用特定的详细的语言，可能会增加达成政治共识的难度（同上书，p.384）。

然而，语义歧义和模糊性也是法律不确定性的来源：反对者可以就什么法律规则适用以及事实是什么达成一致，并且还产生支持相反结果的合理法律论证（Berman 和 Hafner, 1988）。

即使立法意图明确并且制定法的语言直截了当，法律对手也经常就规则术语的含义做出合理但相互矛盾的论证。在他们的例子约翰逊诉南太平洋公司案 [ 117 Fed. 462 ( 8th Cir. 1902 ) rev'd 196 U.S. 1 ( 1904 ) ] 中，联邦法规规定“在州际交通中‘任何没有配备通过撞击自动耦合的车辆’使用铁路是非法的”。根据法规的序言，该法案的目的是“通过强制运营商……为他们的车辆配备自动耦合器和带驱动轮制动器的机车……促进员工的安全。”（ Berman 和 Hafner，1988，p.196）

对事实没有异议。“原告，一名铁路制动员，为了将餐车从轨道上移开，在试图将机车与餐车耦合在一起时受伤。”因果关系不是问题，原告受伤是由如下事实造成的：虽然机车配备了这样一个耦合器，但它不是一个可以自动耦合这个特定餐车的耦合器。

然而，法院对制定法规则的条件是否得到满足有分歧，特别是“关于本规则条件部分中所有三个谓词的含义：‘汽车’的含义，‘用于州际贸易’的含义和‘配备’的含义（ Berman 和 Hafner，1988，p.198）。”“车辆”中包含的机车是否要求拥有自动耦合器？“州际贸易”是否包括车辆等待下次装载的时间？餐车和机车是否配备了自动耦合器？初审和上诉法院对这些问题的答案持不同意见，他们肯定不会将这些答案视为术语的字面含义所决定的。

### 2.2.2. 句法歧义

句法歧义是另一种类型的歧义，它源于不同的现实：制定法语言并不总是遵循单一融贯的逻辑结构。这部分来自自然语言文本的属性。41 与数学和逻辑形式主义和计算机代码不同，文本不允许明确指定逻辑连接器的范围，例如“如果”、“和”、“或者”和“除非”。制定法的句法也会因为实施例外和交叉引用所使用的语言而不清楚。条款的例外情况可以明确表达也可以隐含地表达，不仅可以出现在这一条款中，而且可以出现在其他条款中，甚至出现在其他制定法中（ Allen 和 Engholm，1978 ）。

莱曼·艾伦（Layman Allen）证明，句法歧义导致甚至相对简单的制定法条款也有多种可能的逻辑解释，这对受监管者有潜在的深远影响。他举了一个路易斯安那州法规定义犯罪的例子：

任何人不得参与或建立匿名性的本地电话、对话或会议，并使用淫秽、亵渎、粗俗、猥亵、淫荡或不雅的语言，淫秽性质的建议或提议以及任何形式的威胁。（同上书）

据推测，立法机关运用开放结构的全部知识故意选择诸如“淫秽”和“不雅”之类的模糊术语。

他们故意发布具有内在句法歧义的刑事标准的可能性要小得多：违反制定法，呼叫包括淫秽语言或威胁的一个电话就足以违反制定法吗？或者如同路易斯安那州诉希尔案 [ 245 La 119 ( 1963 ) ] 中的被告在地区法院成功辩论那样，包括淫秽语言和威胁的电话才是违反制定法吗？路易斯安那州最高法院不同意；它将“和”解释为“或”，似乎违反了普通法的格言，即应严格解释刑事法规。当然，颁布一个句法上没有歧义的标准本来是更好的立法政策（同上书）。

艾伦描述了一种识别这种歧义的系统规范化过程。在给定一条法规的情况下，人们：

- 识别法规的“原子”实质命题并用标签（S1, S2, ……）替换它们。
- 使用命题逻辑来澄清法规的句法。
- 恢复实质性命题的文本。

在命题逻辑中，符号代表整个命题。使用逻辑运算符和连接词，……命题可以组合成复杂的陈述，其真值仅取决于组件命题的真假。与下面定义的谓词逻辑不同，命题逻辑不考虑单个命题的组成部分或结构（见 Clement，2016）。

### 2.3.2. 谓词逻辑

人们还想表达制定法条款的实质性命题的内容，而不仅仅是其整体逻辑句法。这可以用经典逻辑（也称为谓词逻辑，谓词演算或一阶逻辑）来完成。

经典逻辑是初学逻辑学生已知的作为“谓词逻辑”的形式逻辑，其中，（1）形式语言的所有句子恰好具有两个可能的真值之一（真，假），（2）推论规则允许人们从一组不一致的假设中推导出任何句子，（3）所有谓词都完全定义在变量的范围内，以及（4）形式语义是由塔斯基发明的，他用元语言为形式语言提供了第一个精确真之定义。（Dowden，2016）

经典逻辑使用符号表示谓词、主词和量词。在命题逻辑中，“所有人都是凡人”的命题只用一个符号表示，没有内部结构。相反，在经典逻辑中，可以定义谓词M(x)来表示x是凡人或使用全称量词（“For all”）：所有 x. M(x) 表示所有 x 都是凡人。

作为逻辑编程基础的霍恩子句逻辑实现了大多数（但不是全部）谓词逻辑，并允许人们表达制定法条款的规范化版本的实质命题内容及其逻辑句法。例如，赫伯特·哈特著名的样本制定法条款“禁止车辆驶入公园”，①可以用逻辑编程（即霍恩子句谓词逻辑）表示为：

```
违规（X，S）：- 车辆（X），公园（S），在（X，S）。
```

也就是说，“如果 X 是车辆并且 S 是公园，并且车辆在公园中 -> 车辆在公园中是违规的。”在逻辑编程中，谓词之间的逗号表示“和”；表明使用的是全称量词

如果输入逻辑编程程序信息，例如：

```
车辆（X）：- 摩托车（X）
车辆（X）：- 汽车（X）
```

该程序可以证明，通过将一条规则的结论链接到其他规则的前提下，人们或许不会将摩托车、汽车或者实际上我们输入的任何其他作为车辆的东西驶入公园。

### 2.3.3. 作为设计约束的句法歧义

在转向大规模法律逻辑编程的示例之前，让我们总结一下句法歧义的含义。

句法歧义，使得将制定法文本转换成用计算机形式化逻辑规则的任务成为问题（Allen and Saxon, 1987）。在计算机表达的规则中，句法歧义可以被消除。问题在于，选择用于形式化为逻辑编程语言（如逻辑编程）的制定法规则的版本不一定是立法机构所预期的。

作为句法歧义的结果，知识工程师无法确定立法机构的意图。将标准化过程应用于甚至相当简单的制定法条款导致句法上的多种可能解释，这令人不安。第3505 节——第四修正案排除规则的拟议限制——规定：

除法律明确规定外，如果搜查或扣押是在合理诚信的信念下进行，则它符合美国宪法第四修正案，在美国法院的诉讼程序中不得排除因搜查或扣押而获得的证据，并且这些证据是可以接受的。证据是根据并在逮捕令范围内获得的，对此的证明构成了这种合理诚信信念的表面证据，除非该逮捕令是通过故意和重大失实陈述获得的。

虽然只有两个句子长，但在标准化时，第 3505 节仅仅根据条款中的句法歧义得出了 48 种不同强度的解释，它们的强度根据其限制性或包容性衡量（Allen 和 Saxon，1987）。

实际上，只有少数版本看起来是明显合理的，而其他版本可能显然是不合理的。问题是谁选择？如果知识工程师决定实施哪个标准化版本，则它不是权威选择。法律学者或某一领域的其他专家可以表达对立法机构打算或应该打算采用哪种版本的意见。然而，唯一能够进行权威选择的机构是立法机构。

不幸的是，立法者可能没有意识到这种歧义（Allen 和 Saxon，1987）。虽然语义歧义可以促进立法妥协并且通常是有意的，但句法歧义在政治过程中没有任何合法的功能，也不利于政治构成。实际上，在制定一个系统的程序来产生制定法条款的标准化版本时，莱曼·艾伦（Layman Allen）的目标之一是让立法者和法律学生对这种现象敏感（Allen 和 Engholm，1978；Allen 和 Saxon，1987）。

田纳西州的一位法学教授格雷弗雷德·格雷（Grayfred Gray）在说服国家立法起草委员会采用标准化作为消除无意识句法歧义方面取得了一些成功，比如消除国家精神卫生法关于精神病患者承诺和解除规定的条款中句法歧义。委员会注意到，“对于必须与之合作的人来说，法律是明确的，其中大多数人不是律师”（Gray，1985，pp.479-480）。立法机构似乎没有标准化的问题。另一方面，该州成文法典的出版商担心，标准化自由使用缩进来传达法规的简化逻辑结构会占用太多空间，从而增加印刷出版物的成本。最终，只有少数法规以标准化形式出版。

今天，在万维网上，空间不是问题。标准化的法规版本和随附的流程图可以通过网络低成本地发布，这使非法律人更容易阅读和理解法律要求。在基于网络的出版物中，帮助链接和下拉菜单可以帮助外行使用和解释标准化的条款。

与此同时，当然，对法规的多种逻辑解释并没有使法律职业者屈服。相反，它创造了就业机会。代表纳税人或保险公司的律师和法律专家将被保留，以生产和利用复杂条款的替代句法解释。在对抗的背景下，识别法规或复杂保险政策条款的替代逻辑解释，为争论支持某位客户的解释提供了机会，就像在上面的路易斯安那州希尔的刑事审判中一样。

在不同的背景下，例如公司合规，规避风险的律师可能会建议对法规采用更宽泛的逻辑解释，以便在业务规则系统中形式化。选择安全宽泛的解释将有助于减少后续违反法律规则的行为。47
