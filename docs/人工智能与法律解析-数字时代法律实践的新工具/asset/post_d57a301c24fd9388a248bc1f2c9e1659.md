## 12.4.4. 解释假设

目前为止所描述的过程是一种法律假设驱动的概念信息检索。法律应用程序将评估查询的结果，以确定是否已检索到目标假设的实例，实例支持哪一方，即检索到的案例是否为假设的正面、负面或混合实例，以及结果是否似乎证实了这一假设。应用程序或许能够完成更多。

第一部分所说的论证的计算模型适用于案例的注解特征，识别法律因素或其他与论证相关的信息，应用程序可以构建支持或反对该假设的法律论证，并根据相互竞争的法律论证来评价该假设。在这样做时，应用程序将应用论证型式于可辩驳的法律规则和案例、法律因素和基础价值。

应用程序将确认或质疑用户的假设，并根据论证解释原因。根据其分析，该应用程序将为人类用户提供包括修改假设在内的各种选项。实际上，该应用程序将帮助用户探索关注法律主张或问题的合理假设空间，并协作测试和修改假设。下一节将介绍这种协作假设测试，首先是以价值判断为基础的论证预测模型，然后是缺省逻辑框架模型。

为基础的论证预测模型）进行协作假设测试的一个例子，考虑图 12.2 的假设（d），应然假设如下：

原告对其独特产品采取安全措施，并且被告同意不披露信息，即使原告在公共论坛上披露了这些信息，在这种情况下也应该判决原告赢得商业秘密盗用索赔诉讼。

使用提供菜单支持和接受的自然语言输入的法律应用程序界面，用户可以输入这样的法律假设作为查询并将其标记为要测试的假设。程序将根据第 11.5.3 节中扩展的论证类型列表来注解查询文本，包括法律因素的类型。程序将使用法律因素类型实例注解的自然语言表述转换成特定法律因素列表。对假设的解释存在不确实性时，应用程序可以提供菜单选项，指示根据用户的假设并有待用户确认的前 n 个解释。

确认了用户假设的具体解释后，程序将开始它的测试过程。首先，程序会将假设分解为案例查询，这些查询具有指定商业秘密领域的法律因素和论证功能（如图 11.6 中的查询 3）：

法律应用程序将访问应用这些查询的案例数据库。可以想象，数据库可以在运行时从法律信息检索程序的一般语料库中使用查询 3 的普遍化来组装，例如：

法律应用程序将在运行时为查询的法律信息检索程序的输出添加注解，其根据是法律因素和扩展列表中的其他论证类型。根据注解的效率，它或许会关注与假设和相关查询明显相关的类型子集。或者，它将采用先前组装和注解的商业秘密盗用案件意见的语料库，可能在运行时补充更新对法律信息检索程序的查询。可以想象，用户可以指定管辖区域和时间范围来定位数据库。

注解将导致根据句子层级类型索引的句子和相关案例数据库，包括一般性法律因素类型和商业秘密索赔的特定法律因素。我们假设系统可以解释表达法律裁决或裁定和 / 或基于证据的发现的句子，以便很好地知道裁决、裁定或发现支持哪一方。涉及原告或被告条款并表明一方“赢得”、“胜诉”、“已成功”的短语以及其他短语可能被视为标准法律表述（第 6.8 节）。解释这些句子类型的更复杂的实例可能会引起第 12.5.1 节中讨论的归属和极性问题。

法律应用程序将查询 3 应用于带注解的数据库，检索满足查询的案例，并分析结果。最初，分析可能只是比较回应每个查询的案例数。虽然商业秘密在公共论坛 [ 因素 F27 在公共论坛披露（D） ] 中披露出来了原告又赢得商业秘密盗用索赔的案件可能没有，但存在一些混合案件，有些情况下原告胜诉，有些情况下被告胜诉。

法律应用程序可以发布用数字比较的初步报告：n 个与假设一致的原告实例和 m 个与假设相反的被告实例。该报告将包括一项附带条件，即它仅基于 n 个商业秘密案件的当前数据库（在特定的管辖区域和时间范围内）。

此时，应用程序可以为用户提供一些选项，包括：

- 1. 修改数据库（应用程序 / 用户）：扩展或更改数据库以搜索与假设相关的附加实例。
- 2. 修改假设（应用程序 / 用户）：改变假设并返回搜索。
- 3. 做出法律论证（应用程序 / 用户）：建构一个法律论证以支持或反对假设。
- 4. 评价假设（应用程序 / 用户）：根据法律论证评价假设。

“修改数据库”选项假定有关数据库的可用选项。例如，可以指定限制数据库的管辖区域或时间范围。也许搜索可以包括额外的文本语料库，或者可以修改的信息检索查询。括号 “（应用程序 / 用户）” 表示应用程序或用户可以建议对数据库进行修改。

关于修改假设选项，典型的变化是通过向查询约束减去或添加法律因素或可能的其他事实来做出更一般或更具体的假设。用户的假设通过这种方式成为如下假设，即在一个或多或少完全指定的事实情景中在公共论坛披露商业秘密的法律意义，例如：

（ d' ）即使原告在公共论坛上披露了这些信息，在被告同意不披露信息的情况下，商业秘密盗用索赔问题也应判决原告胜诉。

假设（ d' ）不如假设（ d ）具体，因为它只涉及法律因素 F4 同意不披露（ P ）和 F27 在公共论坛披露（ D ）。

做出法律论证选项将邀请应用程序（或用户）提出支持和反对当前假设的法律论证。使用基于价值判断的论证预测（或案例论证系统或 IBP 模型）之类的论证计算模型，应用程序可以根据事实情况做出支持和反对假设的基于法律因素或价值的论证。

例如，在与假设（ d ）相关的情景中，原告对其独特产品采取了安全措施，即使原告在公共论坛上披露了该信息，被告仍同意不披露该信息。也就是说，可适用的因素包括 F4 同意不披露（ P ），F6 安全措施（ P ），F15 独特产品（ P ）和 F27 在公共论坛披露（ D ）。通过将这些因素输入到像基于价值判断的论证预测这样的模型，应用程序可以建构类似于图 5.13 所示的论证，说明动力研究公司案案例的一个论证——它是假设 d 的一个实例。

如果用户指定一个论证，程序将尝试回应它，但输入的论证必须采用系统可以根据适用的法律推理或论证的计算模型理解的形式。例如，用户可以将一个案例或事实情况指定为应用程序试图区别回应的反例。

评估假设选项与前一个选项相关。基本上，应用程序可以根据适用的法律论证的正方和反方评价假设，即预测相关事实情景的结果，应用程序使用基于价值判断的论证预测模型（或案例论证系统或 IBP）将预测事实情况的结果并根据论证证明其合理性。用户选项允许用户更改预测结果并指导应用程序对其进行评价。

法律论证的最后两个选项——即做出法律论证和评估假设——采用论证计算模型中支持的论证型式。这将包括与假设一致的过去案例的论证，区别于与假设相反的案例（即反例），并考虑到对潜在案例价值的影响，这些案例是假设的正面或负面实例。如图 5.13 中的动力研究公司案论证所示，证成识别了支持预测的案例和论证，也识别了反例。它试图根据法律因素、潜在价值以及对当前情景中相反结论价值的有害影响来区分反例或以其他方式淡化它们的重要性。应用程序还可以基于反例识别假设的近似缺失假设变化，这些假设可能会影响稍微不同的事实结果给出了略微不同的事实（ Ashley, 1990 ）。

## 用描述性证据论证模型进行协作假设检验

在诸如疫苗伤害项目等证据法律论证领域中，法律应用程序也可以处理如图 12.3 所示的假设，例如：

- ( a ) 如果疫苗是麻疹、腮腺炎和风疹疫苗并且伤害是顽固性癫痫，原告可以在疫苗伤害索赔问题上取得成功。

如上所述，这里可以假设（图 12.1 中表 [2] 后形成的图）不同于图 12.2 中处理法律因素的应然假设。而不是“一个问题应该被判决支持原告”或“原告应该胜诉”，在“一些原告已经胜诉”的意义上，在假设描述的给定条件中，它们被称为“原告可以成功”。这种差异反映了论证的基本计算模型以及他们建模的法律论证范围的差异。

证据法律论证的描述性计算模型准确地表示法院的事实裁决、支持和矛盾的理由以及关于法律规则的要求是否得到满足的法律判决。

该模型不支持关于法律规则要求的意义的论证。

可以想象，证据法律论证的描述性模型可以为预测提供基础。“语料库提供数据……[使用]逻辑结构来预测类似案例中的结果或表述用于类似案例的论证”（Walker 2011，pp.303,329）。根据这种模型注解的广泛的案例语料库将提供通过规则树以及相关论证成功和不成功路径的数据库。这些路径可以根据特定的规则和要求在各种案例中进行排列。在这方面，它们类似于 GREBE 的 EBE（见第 3.3.3 节），这是另一个模型，用于追踪法官在决定法律规则的要求是否得到满足时所采用的推理。

给定这样的语料库，程序可以追踪从假设的事实和子问题结论到期望的结论的路径。规则树指示仍需满足的规则要求。这些案例表明已经尝试过的已知成功和不成功路径，并且可以提供在详细的规则树中已经尝试或成功的特定路径或环节的频率。

语料库还将提供详细的追踪记录，记录特定的事实审判者——即特定的法官或特别法官——过去如何决定具体问题。它记录了法官选择和解释证据以及解决相互矛盾的证据的原因。对面临类似问题情景的律师而言，法官的推理作为律师需要提供的证据类型以及律师需要构建的论证的一个例子是有益的。作为特定事实审判者——例如，凯西案判决中的特别法官——如何处理某些问题、证据甚至专家证人，法官的推理也是一个有益的例子。因此，将类似缺省逻辑框架的模型应用于法律判决文本可能使法律机器项目能够找到并应用细粒度信息来预测特定法官如何决定特定问题。

基于语料库中的这些信息，在给定一个假设的情况下，法律应用程序可以确认或否定该假设并总结统计数据。如果假设得到确认，法律应用程序可以指向成功路径和与假设一致的论证。它可以根据这些正面实例给出建议论证，并提醒用户任何例外和不成功的论证。如果它否定这个假设，那么应用程序就可以指向排他性负面路径。

一个有趣的问题是，在给定假设中提出的事实情况下，法律应用程序使用描述性论证模型是否可以预测原告应该赢得一场诉讼。在这里，“应该”用于形式 [1] “应该假设”的组合规范和经验意义上。虽然提出一个规范性假设并用这种模型进行确认是有意义的，但从本质上讲，附属查询的内容是事实发现是否满足定义一个主张或问题的相关法律规则的要求。在这样的模型中，在论证缺失的情况下，通过类比有关法律规则要求的含义的案例来评估规范性假设是很困难的。

描述性模型的目的是捕获另一种基于事实审判者证据推理的规范性信息。如上所述，这种模型记录案件中的判决是法律结论还是事实裁定，以及它与案件中其他判决的关系。该模型还以裁判者自己的语言记录裁判者的原因，并说明他们如何影响判决，即他们是否支持判决、反驳判决以及支持反驳的程度。例如，表 12.1 显示了特别法官判决中证据理由的例子，这些判决在缺省逻辑框架表示的三个案例——凯西案（n.1）、霍华德（Howard）案（nn.2-5）和斯图尔特案（n.6）案——中进行了研究。①

## 12.5. 对认知计算法律应用程序的挑战

一个用于构建、测试和评估的与人类协作的法律应用程序应该很快就可以实现。如上图所示，如果可以自动成功地对与论证相关的信息进行注解，则现有的法律论证计算模型可以与假设和案例的文本描述一起工作，预测结果并用论证支持它们。

在实现基于协作假设的查询和测试的目标之前，有三个要解决的实质研究的挑战。第一，法律论证相关信息在多大程度上可以从文本中提取，包括法律因素、证据因素和法律论证中的句子角色？第二，主要挑战是否有足够的手动注解训练数据用于机器学习和自动注解。第三，设计一个用户可以指定假设和查询的界面将是一个挑战。已在前一章中讨论过这些挑战，在此将根据支持假设检验的目标重新讨论。

## 12.5.1. 挑战：自动注解与法律论证相关的信息

第九章至第十一章报告的工作提供了乐观的理由，即与论证相关信息可以自动注解，并足以支持假设检验。

我们已经看到了很多例子。如第 10.3 节所述，莫查莱斯和莫恩斯已经应用机器学习来自动识别法律语料库中的命题作为论证前提和结论，用 F1 测量可以识别出 68% 的前提和 74% 的结论。他们使用知识工程规则确定了嵌套的论证结构，准确率为 60%。冯和赫斯特自动注解了论证型式，例如准确率范围从 63% 到 91% 的例证（第 10.3.5 节）。在第 10.5.4 节描述的评估中，卢依马团队自动注解了句子发挥的两个法律论证角色，即法律规则句子和基于证据发现的句子，F1- 测量值分别为 68% 和 48%（Bansal 等，2016）。SMILE 程序已经在商业秘密盗用案件中自动识别出法律因素，其中 F1 测量值较低，平均因子为 26% 至 28%，但足以将 IBP 对预知基线的预测提高 15%（第 10.4 节）。此外，SPIRE 程序通过使用因子文本语料库重新排序案例来减少预期的搜索长度（第 7.9.2 节）。

虽然不是针对注解案例，但是在用本体基础支持立法起草项目（第 9.3 节）和定量建设规章（第 9.6 节）中划分制定法条款和提取功能信息的技术，或从基于多州制定法的培训数据中学习（第 9.7.3 节），也建议注解法律因素可以起作用。甚至自动注解和逻辑规则的提取也取得了一些成功（第 9.5 节）。法律因素应该比逻辑规则更容易自动注解。因素就像规则的前件，因此比规则更简单。另一方面，要注解因素的案例文本可能比制定法文本更多样化。

虽然有希望，但考虑到这些结果的范围，显然需要做更多的工作。有四个迫切的需求，即需要处理某些归属问题，区分某些命题的极性，获取某些特定领域的概念和关系，以及至关重要的是，生成更多手动注解的培训实例。

## 归属

在基于案例证明假设的合理性时，重要的是法律应用程序能够区分法官的结论和法官对当事人或证人陈述的认定。“归属……是确定谁相信一个陈述的命题为真的问题”（Walker 等，2015a）。判决中的特定句子报告当事人的指控、专家证人的证词、文档展示的文本、法官的法律结论或事实的发现或来自引用案例中的上述任何内容。

法律应用程序的认知计算需要确定在表述命题时法官是否认为它为真（Walker 等，2015a）。当事人的陈述通常只是对他们想要支持主张的断言。法官将一个陈述归属于一方当事人看起来像是一个法律因素，这个事实只是证明这个主题被讨论，但它并未表明法官确定了该因素存在。法官可以引用证人主张作为证据，但法官可以在做出判决前引用相互竞争的证据。

这是一个说明基于归属的区别的例子，卢依马尚未得出但需要弄清楚的区别。思考一下沃德里奇案判决中相同的两个句子，S2 和 S3，第十一章的开头使用这两个句子说明对查询 Q2 有效的句子，“是否在有些案例中有人认为乙型肝炎疫苗可以导致多发性硬化症？”和新句子 S4：

> S2: “签名人认为，乙型肝炎疫苗导致或显著加重了请求者的多发性硬化症。”
