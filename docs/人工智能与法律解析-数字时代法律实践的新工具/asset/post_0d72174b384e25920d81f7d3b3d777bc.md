
## 7.4. 法律信息检索系统如何工作？

法律信息检索系统接受用户的查询，从索引数据库中检索文档，测量文档对查询的回应，对其进行排序，并输出有序的结果列表供用户阅读。

用户可以输入用句子、关键词、案例名称或引用表达的自然语言查询，并指定所需术语的存在或位置。

给定一个查询，信息检索程序：

- 1. 剥去禁用词，诸如“the”，“a”和“and”之类的常用词，词干，如“ing”或“es”之类的结尾。
- 2. 识别单词旁边的其他剩余功能，例如对制定法的引用，宪法条款或先前案例，重要短语和特殊索引概念。
- 3. 计算每个剩下的单词或其他要素在文本中出现的次数。
- 4. 使用反向索引从数据库中检索候选文档，即，所有那些索引为包含查询中任何特征的文本。（Turtle，1995，p.18）

数据库包含处理方式与查询方式大致相同的文档，数据库很可能使用倒排索引实现（见 Büttcher 等，2010，p.33）。索引列出了存储在数据库中的任何文本中出现的某些特征。对于每个特征，倒排索引记录它出现的所有文档，它在每个文档中的位置，以及它在文档和文本语料库中出现的次数（Büttcher 等，2010，p.48；Turtle，1995，p.18）。由于不断添加新文档，必须采用各种索引维护策略（见 Büttcher 等，2010，第 7 章），但这里不讨论这些问题。

信息检索系统输出根据其与查询的相关性排序的案例列表。信息检索系统采用了各种技术和措施来评估与查询的相关性，包括：布尔，向量空间和概率模型（见第 7.5 节）。所有这些都利用包含在倒排索引中的频率信息。

为了说明检索过程，这里是一个样本查询，受到第 6.9 节的后波波夫情景的启发，涉及面临未来财产法纠纷的法官或辩护人，涉及原告搜索一个废弃的机器人深海探测器，搜索行动在最后一刻被被告黑客挫败，黑客通过覆盖计算机拦截了探测器。这是一个可能有用的全文法律信息查询：

侵占行为，原告几乎抓住了一个废弃的机器人深海探测器，但被告通过黑客入侵计算机在最后一刻拦截了探测器。

即便是这个小例子也说明了法律信息检索的一个挑战：词语具有多重含义。考虑三个句子中“action”和“conversion”的含义：“侵占行为( action for conversion )涉及严重干扰”，“数据转移( conversion )已完成”，“某些行动（ action ）可能会欺骗”。

在示例查询中，“行为”和“侵占”旨在传达用户的期望，涉及侵占的法律行为和所描述的事实的案例是相关的。然而，每个术语都有多种含义。除了法律意义上的强制执行索赔之外，“action”也可以指做某事的事实。“Conversion”不仅表示一种财产法主张，而且表示某事的变化或转换。因此，单词不是用于分辨相关文档和无关文档的理想特征。类似地，将五个句子与查询进行比较，可以看出“probe”具有多种含义。虽然这次查询将其用作名词，但句子[ 4 ]将其用作动词。另外，“hack”是[ 5 ]中的专有名称，但这次查询使用它来指代干扰探测器的计算机系统。

读者可以在他或她自己喜欢的法律信息检索系统上试用查询。在我的尝试中，上述样本查询的商业法律信息检索系统产生的结果显然没有处理涉及侵占财产索赔的案件，也没有处理包括被告阻止原告猎人捕获其意向猎物的情景的案件。仔细阅读信息检索系统结果列表中报告的前 20 个案例的案例报告显示，有两个案件涉及一系列其他索赔中的侵占索赔（例如，联邦窃听法案，电子通信隐私法案和计算机欺诈和滥用法案，版权，商标，商业秘密，侵犯隐私权，刑事审判中的计算机证据的可接受性，比文斯（ Bivens ）救济，以及涉及内战后被遗弃和被捕获的财产法案索赔的三起案件）。当然，人们能理解为什么这个案例被检索时查询中给出了各种术语以及它们的替代涵义（例如，“侵占”，“被遗弃”，“机器人”，“截获”，“黑客攻击”，“计算机”），但没有一个案例似乎有用。

不同的相关性模型及其相应的措施在尝试处理词语多义的挑战时在不同程度上是有效的。

## 7.5. 信息检索的相关性度量

如上所述，信息检索系统使用布尔、向量空间和概率模型来评估文档与查询的相关性。其中，布尔相关性度量是最简单的。

### 7.5.1. 布尔相关性度量

在布尔相关性度量中，查询为要检索的文档提供一组逻辑标准。该标准指定了要回应的文档的指示术语的存在和接近程度。相关性度量根据查询的布尔标准完全满足的方式来对案例进行排序（Turtle，1995，p.24）。

将上述深海探测示例表示为布尔查询并不容易，但可以尝试以下方法：

- （行为 w/5 侵占）和[（捕获！ w/5 猎物）或(捕获！ w/5 猎物）]
- 和 [（被告 w/5 干扰！）或（被告 w/5 拦截！）]

在上述查询中，感叹号（!）表示系统应包括以指示的词根开头的所有单词，例如 “capture” “captures” “captured” “capturing” 等。也许预计发现涉及废弃探测器的案件的可能性很低，用户也用更广泛的术语 “猎物” 取而代之，希望能够返回到涉及捕获其他物品的案件。

### 7.5.2. 向量空间的相关性方法

在向量空间的相关性方法中，文档和查询可以用 “词袋” 表示，并作为 “术语向量” 进行比较（Turtle，1995，第 26 页）。一个文档表示的词袋（bag of words，简称为 BOW）包括没有特定顺序的术语集合。回到深海探测示例，查询可以表示为词袋：

- 海 抓获 行为 侵占 深 计算机 近乎 黑客 分钟 机器人 原告 废弃 被告 探测器 拦截 最后

词袋表示不保留术语在句子中出现的顺序。关于句子含义的信息丢失了。

由于很难比较表示为词袋的句子，因此可以按字母顺序放置术语并将其表示为术语向量：

废弃 ( abandon ) 行为 ( action ) 抓获 ( capture ) 计算机 ( computer ) 侵占 ( conversion ) 深 ( deep ) 被告 ( defendant ) 黑客 ( hack ) 拦截 ( intercept ) 最后 ( last ) 一分钟 ( minute ) 近乎 ( nearly ) 原告 ( plaintiff ) 探测器 ( probe ) 机器人 ( robotic ) 海 ( sea ) 在哪里 ( where )

术语向量 ( term vector ) 根据其词语、引用、索引概念或其他特征表示句子或其他文档。它是从原点 ( 0, 0, 0, ……, 0 ) 到表示大维空间中的案例文本的点的箭头。由于完整文本语料库中的每个不同的术语（ 即，单词或其他特征 ）对应于另一个维度，因此维度的数量 n 非常大。

![](img/e7e3f10d60275df947102e1b729aba54_305_0.png)

图 7.1. 三维的向量空间模型

如图 7.1 中的简单三维向量空间模型所示，向量指定沿着每个维度到达表示整个文档的点的距离。由于任何给定的文档在语料库中缺少许多术语，因此沿着许多维度的距离将为零（ 0 ）。然而，对于文档中的术语，沿着每个维度到术语的距离将是一（1），或者在一些实现中，距离是计算的量值，单词的词频 / 反文档频率权衡。

单词的词频 / 反文档频率权衡与相关术语在文档文本中出现的次数[ 即词频( tf )成正比，并且与术语在语料库中出现的次数成反比( 即，反文档频率 )( idf ) ]。因此，在查询和文档中出现的术语增加了如下结论的权重：查询和文档类似于该术语在文档中频繁出现而在语料库中很少出现的程度。

术语向量方法的一个优点是易于计算向量空间相似性（ vector space similarity， 简称为 VSS ），即文档之间或查询与文档之间的相似性。实际上，查询被视为用于此目的的文档，并且还表示为术语向量。如在以上示例中那样，将术语放置在特定（例如，字母顺序）的顺序中有助于自动比较术语向量以评估它们的相似性。相似性度量对应于多维空间中的术语向量的端点之间的欧几里德距离。在确定相似性时，使用三角计算将查询与从倒排索引检索的所有文档进行比较。人们计算它们相应的术语向量之间角度的余弦。余弦越小，相应术语向量之间的角度越小，并且全文本方法假定，向量表示的文本的含义越相似。

### 7.5.3. 相关性概率模型

利用概率相关性模型，信息检索被构造为关于用户的查询意味着什么，语料库中的文档是什么以及哪些文档最能满足查询的评价证据问题。关于查询和文档内容的证据包括它们的表示方式。这包括它们包含的单词和短语，它们在词典和辞典中的定义和同义词，文档中的其他特征，例如引文和主题索引，例如韦氏法律汇编主题和关键数字以及统计信息。就好像查询和文档的内容，即它们的含义，会导致观察到的证据，即它们是如何表示的。相反，如何表示查询和文档，即证据，取决于它们意味着什么，即原因。

### 贝叶斯网络简介

贝叶斯网络是用于模拟情境的有用工具，“因果关系在其中发挥作用，但我们对正在发生的事情的理解是不完整的，因此我们需要概率地描述事物”（ Charniak, 1991, p.51）。例如，在以前的“韦氏是自然”（ West is Natural, 简称为 WIN）系统中实现的相关性概率模型中，贝叶斯网络自动推断出如下可能性：如他或她的查询所证明的那样，寻求者的信息需求是由数据库中的特定文档满足的。（ Turtle, 1995, p.27 ）

贝叶斯网络是概率因果关系的图形模型。每个贝叶斯网络节点表示一个带有变量的“事件”，以指示它是否已经发生。弧线代表影响事件发生可能性的因果影响，包括与那些因果影响相关的条件概率。如果满足某些假设，则人们可以计算具有特定状态的事件变量的概率，其中给定的信息是关于图中的紧接在前的事件变量的状态的。这些假设包括独立性假设，即在给定父变量的情况下每个事件都有条件地独立于其非后代（ Turtle and Croft, 1990, p.21 ）。这种独立性假设减少了需要计算的概率的数量，使得贝叶斯网络成为用于模拟因果推理的有效方法。

![](img/e7e3f10d60275df947102e1b729aba54_307_0.png)

图 7.2. 家人离开问题的贝叶斯网络

尤金·查尼亚克（ Eugene Charniak ）在他的文章“没有眼泪的贝叶斯网络”中提供了一个平淡无奇的贝叶斯网络示例，如图 7.2 所示，其功能是在作者听到他家的狗叫声的情况下，帮助作者步行回家时确定他的家人不在家的可能性。

图中弧线的因果解释如下：家人外出的先验概率仅为 15%，但家人外出与狗在外面有直接的因果关系，而狗在外面反过来与查尼亚克听到她直接相关。然而，该图显示了狗在外面与狗的消化系统有关的另一个原因。狗出现这种问题的先验概率仅为 1%，但该图表示具有消化问题也可能导致狗外出。此外，该图表示显示，当家庭成员离开查尼亚克的房子时，他们在 60% 的时间会打开户外灯光，但是，如果他们期待客人的到来，即使他们在家时，户外灯光在 5% 的时间里也会打开（Charniak, 1991, p.52）。

贝叶斯网络允许人们在已经观察到一些节点值的情况下计算网络节点的条件概率。如果查尼亚克观察到，灯亮（灯亮 = 真）但听不到狗叫（听到狗叫 = 假），他可以根据这些证据来计算家人离开的条件概率（对于这种情况，它约为 0.5。Charniak, 1991, p.52）。可以在布拉赫曼和莱什斯克的著作（Brachman 和 Levesque, 2004, p.248）中找到计算的细节。

### 使用贝叶斯网络评估信息检索中的相关性

如上所述，贝叶斯网络是用于评估因果链中的证据的便利工具。它可以处理法律信息检索系统对用户查询的意谓或其集合中的文档内容的不确定性。贝叶斯网络的节点表示概率，即用户的查询术语仅基于表示该组文档的概念信息正确地描述了一组文档的概率（Turtle 和 Croft, 1990; Turtle, 1995, p.33）。信息检索系统可以使用网络计算特定文档与查询相关的可能性。

如图 7.3 所示，信息检索系统的贝叶斯网络包含两部分。第一部分是图中底部显示的查询网络，是在用户提交查询时构建的。查询网络来自系统对查询文本的处理并根据查询概念（单词，引用等）表示。可以使用本体或同义词来扩展查询（见下文），以将特定查询概念连接到同义表示概念。

![](img/e7e3f10d60275df947102e1b729aba54_309_0.png)

图 7.3. 推断网络检索模型 (见 Turtle, 1995, p.33)

然后，查询网络与文档网络（在图 7.3 的顶部）连接，该文档网络已经预先构建，并且在处理查询时不会改变。从查询节点到文档节点的节点和弧线表示各种条件概率关系。满足用户特定信息需要的可能性取决于查询组件。观察特定查询组件的可能性取决于查询特征。观察特定查询特征的可能性取决于文档特征。观察特定文档特征的可能性取决于文档。

观察到的任何特定文档 Doc_i 的先验概率是语料库中文档数量的概率。换言之，在考虑查询之前，任何文档将回应的先验概率都被假定为均匀随机的（Turtle 和 Croft, 1990）。

与倒排索引中的文档特征表示相关联的词频 / 反文档频率值被用于估计这些条件概率。通过假设每个文档 Doc_i 被观察，反过来，贝叶斯网络计算 Doc_i 满足信息需求的机会。然后，系统按概率的大小对文档进行排序，并向用户返回最可能相关文档的有序列表（Turtle，1995）。

商业法律信息检索系统在使用贝叶斯网络进行相关性评估方面有所改进（见，例如，第 7.7 节）。然而，使用贝叶斯网络的推理网络信息检索方法代表了有效地使用词频信息来评估相关性的进步。人们也可以使用贝叶斯网络来模拟布尔和向量空间模型来评估相关性（Turtle，1995，p.32）。

然而，出现了这样一个问题，即全文法律信息检索系统如何更好地运作，这个问题至今仍然相关。

## 7.6. 评估法律信息检索系统

评估法律信息检索系统的初始问题是如何衡量其绩效。第 4.4.4 节已经介绍了经典的信息检索措施，以解释如何评估机器学习分类器的性能。在信息检索领域：

- 真负（TN）：不相关且被预测为不相关的文档数量。
- 真正（TP）：相关且预测为相关的文档数量。
- 假负（FN）：相关但被预测为不相关的文档数量。
- 假正（FP）：不相关但预测为相关的文档数量。

那么，信息检索系统的性能通常用以下方式来衡量：

精确率（Precision）：检索的相关文档数量与检索到的所有文档数量的比率。

```
P = \frac{|Relevant \cap Retrieved|}{|Retrieved|} = (TP) / (TP+FP)
```

召回率（Recall）：检索到的相关文档数量与语料库中所有相关文档数量的比率。

```
R = \frac{|Relevant \cap Retrieved|}{|Relevant|} = (TP) / (TP+FN)
```

F1 测量（F1 Measure）：精确率和召回率的调和平均值，这两个测量被视为同等重要。

```
\(F_1 = 2 * \frac{P * R}{P + R} = \frac{2 * TP}{2 * TP+FN+FP}\)
```

### 逃避率（Elusion）： 相关的没有检索到的文档的比例。

```
\(E = \frac{|Relevant \cap Unretrieved|}{|Unretrieved|} = (FN) / (TN+FN)\)
```

在评估下一章讨论的电子发现中信息检索的有效性时，规避措施非常重要（见 Oard 和 Webber，2013，pp.152-154）。

事实上，所有信息检索系统都会检索文档然后对它们进行排名。用于评估信息检索系统如何对检索到的文档更好地排名的度量标准将在第 11.4.1 节中定义。

在普通的信息检索系统中，需要在精确率和召回率之间进行权衡。限制较少的搜索会返回更多文档，但更多的文档是不相关的（更高的召回率和更低的精确率）。相反，限制性更强的搜索会返回较少的文档，但其中较大部分将是相关的（较低的召回率和更高的精确率）。即使权衡无法避免，也有同时提高精确率和召回率的策略。例如，使用一组检索的文档用于后续更精细搜索的多级检索过程在精确率和召回率方面都有所改进（见 Buckland 和 Gey，1994，p.18-19）。信息检索系统中这种策略的一个例子是“相关性反馈”（见第 7.9.2 节）。
