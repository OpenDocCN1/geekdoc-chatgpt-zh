
F6、F15 和 F21，这些因素没有出现在约卡娜案中。这些是判决当前事实情境中原告胜诉的原因，这个情境不适用于所引用的案例（见图 3.2，中间）。

其次，托尼·梅森可以引用一个有利的先例：在美国精密工业公司案中，原告胜诉，在这个案件中支持原告的 F21 在当前事实情境中适用。

第三，梅森可以使用美国精密工业公司案胜过被告的论证，该论证以约卡娜案为基础。在美国精密工业公司案中，尽管支持被告的 F16 可以适用，原告仍然胜诉。当前事实情境更类似于美国精密工业公司案，因为它们共享一系列因素，F16 和 F21；约卡娜案和当前事实情境只共享该集合的一部分，即 F16。换句话说，美国精密工业公司案是约卡娜案的王牌反例（见图 3.2，中间）。

更具体地说，反例是其结果与所引用案例相反并且满足如下附加约束的案例。如果一个共享当前事实情境的被引案例的一组法律因素是共享当前事实情境的反例集合的子集，则反例比被引案例更具有说服力，并且被称为王牌反例。如果反例与当前事实情境和被引案例共享同一组法律因素，那么它就是一个抓住了重点的反例。如果反例与被用案例和当前事实情境共享一个法律因素，但法律因素的量级（相应维度的量级）比被引案例中支持的一方更强，则它是一个边界反例。它倾向于削弱这一维度支持那一方的结论。

海波系统可以做出所有这些论证。这个例子没有说明边界反例，但如果梅森案涉及对外人的披露而且被告依赖向外人披露商业秘密，则原告可以引用“通用数据”案作为边界反例，在该案中原告向 6,000 人披露了商业秘密。当然，在反驳中，海波系统会通过指出向外人的披露受到限制来区分支持被告的“通用数据”案。

## 海波系统中的案例检索与排序

给定输入的人的事实情境后，海波系统在数据库中检索了与当前事实情境共享一个维度的所有案例。然后，它根据案例与当前事实情境共享的法律因素集（由维度表示）的重叠来对案件进行排序。海波系统通过与问题共享的维度集的包容性，用被称为“诉讼请求格”的图形结构组织案例。图 3.4 显示了海波系统可以为梅森案的当前事实情境建构的诉讼请求格。当前事实情境处于根部。当前事实情境的每一个直系后代都共享它们适用的维度的一些子集。它们的每个后代都共享与当前事实情境共享的维度集的一些子集，依此类推。在诉讼请求格中注意到，美国精密工业公司案比约卡娜案更接近当前事实情境，这反映了图 3.2 和 3.3 中所示的王牌反例关系。

海波系统模型说明了计算比较案例的相似性和相关性的一种方法。海波系统没有根据与当前事实情境共享的维度数量来比较案例。

相反，它根据每个案例与当前事实情境共享的维度集的包容性来比较它们。换句话说，海波系统将每个案例共享的法律因子集与当前事实情境进行比较，并确定一个案例集是否是另一个案例集的子集。如果它是一个子集，前一个案例比后一个案例不得要领。例如，在图 3.4 中，“数字开发案”与当前事实情境共享四个维度，相比而言，“美国精密工业公司案”只共享了两个维度，但这并不能说明问题。此外，由于“美国精密工业公司案”与当前事实情境共享的维度集合不是“数字开发案”的子集，因此根据海波系统模型无法比较这两个案例。

比较维度集合具有法律意义。它近似于比较一个案例涵盖当前事实情境中法律优势和劣势的情况。根据共享的维度数量比较案例忽略了法律因素之间的语义差异。

## 在卡巴莱系统中的法律规则谓词维度

卡巴莱系统是海波系统的第一个继承者，它处理制定法领域，特别是涉及所得税家庭办公扣除的美国《国内税收法》条款（Rissland 和 Skalak，1991）。它使用维度来表示陈规定型的事实模式，这些模式强化或削弱了法律规则的谓词（例如，税法规定中的“主要营业地”）得到满足的主张。

卡巴莱系统集成了两个模型，一个基于规则，另一个基于案例。基于规则的模型代表了相关美国国内税务署条款及其中级法律概念的法律规则。给定一个问题场景，基于规则的模型从事实中向前链接以确认目标，并从期望目标向后链接到需要显示的事实。

这些规则类似于沃特曼程序（第 1.3.1 节）中的规则，但有一个主要区别。如果规则“穷尽”（即没有进一步的规则定义制定法术语），该程序可以采用海波式基于案例的推理。卡巴莱系统中的维度与法律因素相关联，这些因素加强或削弱了制定法条款得到满足的论证。这些维度索引引了法院认为制定法术语是否满足的案例。

给定问题场景和制定法术语，基于案例的推理模型确定应用哪些维度，检索由这些维度索引的案例，并为受制于论证的制定法术语生成如图 3.4 所示的诉讼请求格。根据海波模型中测量的相关性，诉讼请求格组织与制定法术语相关的过去案例。

卡巴莱系统通过议程机制集成了两种计算模型：一种算法可以对分析的当前状态进行推理，并适当地召集基于规则的推理（rule-based reasoning，简称为 RBR）模型或基于案例的推理（case-based reasoning，简称为 CBR）模型。议程机制采用一套启发法规则对当前的分析状态进行推理。控制启发法的示例包括：

- 尝试其他：如果基于案例的推理失败，则转换到基于规则的推理（反之亦然）。

- 健全性检查：用基于案例的推理检测基于规则的推理的结论（反之亦然）。

- 基于规则的推理未命中：如果一条规则的所有前件都已建立但只有一个，则使用基于案例的推理扩大规则对错失前件的应用。例如，使用基于案例的推理来表明有些情况下结论是正确的，但因为错失前件规则没有触发。

- 匹配制定法概念：查找在相同制定法概念上失败或成功的案例。

## 案例论证系统中的因素

海波系统的第二任继承者案例论证系统用因素简化了维度表示（Aleven, 2003）。与海波系统一样，案例论证系统根据法律因素处理商业秘密盗用，但它这样做的时候没有使用维度来表示它们。

相反，它用相应的二进制因素替换每个维度。一个因素要么适用于场景，要么不适用。它没有使用幅度或范围，也没有相关的前提条件来测试一个因素是否适用。案例论证系统使用了更完整的因素列表，如表 3.1 所示，并模拟了如何淡化或强调区分因素（Aleven, 1997）。案例论证系统在计算机化教学环境中使用增强因素来帮助学生学习基于案例的论证技巧，例如区分。如第四章所述，它还使用因素来预测案例结果（Aleven, 2003）。

案例论证系统增加了一个因素层级，图 3.6 说明了它的摘录，这是一个知识型式，用于表示为什么因素的存在与法律观点相关的原因（Aleven, 2003, 图 3，第 192 页）。因素层级的原因解释了为什么一个因素加强（或削弱）了商业秘密诉讼请求。

利用这些原因，案例论证系统可以生成新的淡化或强调区别的法律论证，即海波系统无法生成的论证。它可以根据问题组织一个引用多个案例的论证，将与当前事实情境共享共同问题的案例分组在一起，即使它们没有共享相同的因素。案例论证系统通过这种方式可以在更高的抽象层次上进行类比。

案例论证系统也可以淡化或强调区别。如图 3.7 所示，如果一方的论点引用了当前事实情境中特定的区别因素，那么该程序可以基于同样的原因通过指出被引案例中的另一个因素来淡化它。或者，该程序可以通过概括差异来强调区别，这种差异是基于因素层级中具有共同根源的其他因素的更抽象案例之间的差异。

### 关于区分 F16 的重要性的论证

- > 原告在梅森案中弱化梅森案中 F16 的区别。在梅森案中，原告的产品信息可以通过逆向工程学到「F16」。在布赖斯案中不是如此。然而，这不是一个重要的区分。在布赖斯案中，原告在与被告谈判时披露了他的产品信息「F1」，然而原告赢了。在两个案例中，被告通过合法的手段获得或能够获得信息「F12」，但原告还是赢了。

- < 被告的论证强调区分梅森案中的 F16。在梅森案中，原告的产品信息可以通过逆向工程学到「F16」，在布赖斯案中不是如此。这个区分是特别重要的。它表明在梅森案中，原告的信息可以从原告商业以外的资源中获得「F10」，在布赖斯案中不是如此。

阿尔文（Aleven）用于淡化和强调的算法与因素层级中表示因素的信息相互作用。鉴于当前事实情境和被引案例之间基于因素的区别，它从区分因素向上穿过因素层级的节点，以识别可用于在案例中绘制抽象并行的焦点抽象，并可能导致识别在其他案例中削弱区别重要性的因素。另一种算法可以通过在因素层级中找到焦点抽象来强调区分，以抽象地比较这两个案例。它可能导致在一个案例中识别进一步证实的因素，并在另一个案例中比较因素，以支持区分的重要性（Aleven，2003，pp.202-208）。

阿尔文以两种方式评估了案例论证系统。首先，他评估了它在向学生传授基于案例的法律论证的基本技能方面的效果，这可以与由经验丰富的人类讲师传授相同的技能相比较。其次，他根据如何成功预测案例结果来评估论证模型，如第四章所述。

## 3.3.3. 基于范例的解释

卡尔·布兰廷(Karl Branting)开发了第三种基本知识表示技术——基于范例的解释。这项技术用于比较案例的相似性，对正面案例示例进行类比并区分负面案例。他的基于范例的解释生成器（Generator of EBEs，简称为 GREBE）程序使用不同类型的扩展表示型式——语义网（Branting，1991,1999），然后通过类比过去的案例来模拟论证。

语义网是包含节点的图，它表示概念（包括法律概念和事实）以及表示概念之间的关系的弧。布兰廷使用语义网表示法院根据标准事实对案件结果的解释，法官认为重要的事实支持其结论，即从法规中得出的特定中级法律概念是否满足。布兰廷称这些语义网表示为基于范例的解释。

图 3.8 显示了一个样本基于范例的解释，它是沃恩（Vaughn）案的语义网表示，是基于范例的解释生成器数据库中的一个案例。在沃恩案中，一名货车司机在下一次行驶前将车开到餐馆吃饭时发生了意外事故。由于推迟卸货，他的老板指示他先去吃饭。问题在于沃恩是不是在他的雇佣过程中受伤，在这种情况下，他的雇主将是否有责任

( Branting, 1991, p.810 ) 。

### 图 3.8. 表示沃恩案的基于范例的解释生成器语义网络

基于范例的解释生成器的知识来源包括制定法、普通法和常识规则，以及 16 个法律判例、4 个典型案例和 21 个用基于范例的解释表示的假设测试案例。根据法官的解释，每个案例的基于范例的解释被索引为具有开放结构的法律概念的正面或负面例子。

基于范例的解释生成器的输入是表示工人赔偿方案事实的语义网。基于范例的解释生成器的输出详细说明了引用德克萨斯州工人赔偿法中的法律规则的文本论证，并对证明如下结论合理性的先例进行了类比：参与事故的个人 [ 没有 ] 资格获得赔偿。

为了说明基于范例的解释生成器的基于案例的法律推理过程，下面是它如何处理作为语义网的贾瑞克（Jarek）问题输入。铁路公司雇用贾瑞克作为搬运工，有一天指示他工作到很晚。由于贾瑞克需要通知他的妻子他将工作到很晚（在手机时代之前），铁路公司允许贾瑞克专程回家告诉他的妻子。然而，在回家的路上，贾瑞克滑倒并受伤。该问题表示为事实的语义网络，其中大部分列在图 3.9 的右栏中。

在输入时，基于范例的解释生成器试图证明贾瑞克有权获得工人赔偿。它使用反向链接，试图根据制定法规则构建证据，阐明成功的工人赔偿请求的要求。但是，这些规则没有足够详细地定义所有制定法要求来完成这样的证明。特别是，其中一项要求规定，雇员的旅行必须是促进工作，但没有规则进一步界定该法律概念。
