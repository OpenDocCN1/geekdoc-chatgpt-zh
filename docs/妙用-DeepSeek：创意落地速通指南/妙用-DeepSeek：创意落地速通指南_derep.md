## 第3章

## 高效对话核心方法

高效对话 AI 的实战心法

本章把和大模型达成高质量沟通的方法拆开讲，帮你抓住提升交互效率的核心要点。通过正反案例的对照，会剖析指令含糊、前置信息缺、任务边界过大等典型困境，并给出对应的改进思路。把这些做法迁移到工作、学习和日常使用里，模型的实用价值会明显放大。

### 3.1 什么是提示词
提示词本质上是给 AI 的一份任务说明，是引导它理解意图并产出理想答案的关键指令。就像教孩子作画，需要把画面要素说清楚，比如“画一只在草地上追蝴蝶的小狗”，描述越具体，成品越贴合。

对比示例：
- 模糊输入：“写一首诗。”
- 精准输入：“请创作一首五言小诗，主题秋夜思乡，诗中必须出现明月、孤雁、烛火这三个意象。”

前者容易得到风格随意、质量平平的文本，后者更容易稳定产出符合预期的作品。输入质量直接决定输出的专业度与准确度，做针对性优化后相关性提升可达五成以上。

### 3.2 新手最易踩的三个坑

#### 1. 指令不够清晰
对模型说“带我去个好玩的地方”，就像跟司机报模糊地址，很难命中预期。提问需要具体化。例如：

**优化后的输入：**
我想找一个可带孩子免费游玩的公园，车程在20分钟以内。

把需求要素讲清楚，也给了模型明确的执行边界，结果的准确度和可用性会大幅提升。

#### 2. 前置信息缺失
提问时不说明身份和场景，期待模型自行推断，往往导致回答脱离实际。正确做法是在开头就交代清楚自身情况和上下文。例如：

**优化后的输入：**
我刚入职做会计，需要……

补充背景后，模型能更准确地把握语境，给出更贴合实际的建议。

#### 3. 任务边界过大
没有限定格式、篇幅或风格，模型就会自由发挥。应该明确输出方式和结构。例如：

**优化后的输入：**
用小学生能理解的比喻，分三点解释区块链。

既规定了难度层级，又限定了结构，生成的答案才清晰易懂、有条理。

### 3.3 构建优质提示词的三大支柱

模型像一位能力很强的新员工，需要主管给出清晰的工作指引。本节用模板和对比帮助你建立人机协作的能力。与模型高效配合的核心公式是：

**优质提示词 = 目标明确 + 情境充分 + 输出受限**

#### 1. 目标明确
含糊表达：“请写一篇关于环保的文章。”
细化表达：“请以高中生视角，写一篇800字议论文，主题是垃圾分类对城市环保的重要性，需包含三个具体案例分析。”

#### 2. 情境充分
补充上下文帮助模型理解场景：“假设你是一名资深营养师，请为糖尿病患者制定一份一周早餐食谱，并标出每餐热量和升糖指数。”

#### 3. 输出受限
限定结果边界：“请用三句话概括量子力学，少用专业术语，并用小学生能懂的比喻说明。”

### 3.4 新手可直接套用的通用框架

通用公式为“身份-任务-情境-要求”。

**身份：** 你是一名____
**任务：** 我需要你完成____
**情境：** ____
**要求：**
- 输出形式：____
- 注意点：____

### 3.6 提示词进阶技巧

本节介绍三大进阶方法：渐进式对话、激活深层能力、防幻觉策略，可显著提升对话质量与信息可信度。

#### 3.6.1 渐进式对话技巧

##### 1. 分层递进提问法
从发散到收敛逐步缩小范围，避免信息过载。分为四层：

**第一轮：开放探索**
输入：我想做教育类课程，有哪些方向？
回复建议：从年龄层、技术形式、内容载体等维度展开……

**第二轮：细化维度**
输入：聚焦成人职业技能培训，列出当前市场需求前三领域，需附2024招聘平台数据及来源。
回复建议：据某招聘平台2024报告，增长最快为生成式AI提示工程师、ESG合规顾问、RPA等……

**第三轮：落地方案**
输入：针对生成式AI培训，设计“理论+实操+认证”三阶段课程体系，明确课时与考核方式。
回复建议：第一阶段理论……第二阶段实操……第三阶段认证……

**第四轮：假设验证与修正**
输入：第二阶段实操安排二十课时是否足够？
回复建议：若学员零基础，建议增加十课时用于环境搭建……继续调整方案……

##### 2. 风格定制训练法
用连续示范锁定语言风格，分三轮：
第一轮提供示范：用科研论文风格分析2023年第三季度全国新能源车销量同比增速。
第二轮强化记忆：保持学术风格，分析同期充电桩覆盖率。
第三轮风格迁移：同样方法解析2023年第三季度新能源车出口数据。

##### 3. 上下文维护法
保持对话连贯，分四步：
第一轮记忆强化：总结前三次对话要点作为本次基础。
第二轮焦点锚定：让我们回到蛋白质折叠主题，聚焦AlphaFold2局限，不讨论其他路线。
第三轮版本声明：开启新版本v2.0，重点讨论硬件选型，不再涉及电源设计。
第四轮动态修正：根据2024行业白皮书最新数据，调整之前的预测模型。

##### 4. 终止对话判断法
当维护上下文成本高于新开对话时应及时重启，通常在第七加减两轮。表3-5列出判断信号。

###### 表3-5 终止对话判断要点

| 信号类型 | 典型表现 | 处理方式 |
| :--- | :--- | :--- |
| 逻辑发散 | 连续二到三轮回答偏离核心超五成 | 用焦点锚定强制复位 |
| 数据污染 | 错误信息被反复引用形成链条 | 清除部分历史，开启新对话并声明版本 |
| 性能衰减 | 响应变慢且重复率升高 | 新开对话并简化问题结构 |

#### 3.6.2 激活模型深层能力的技巧

##### 1. 身份设定
赋予具体身份让输出更专业。
示例：你是一位有二十年经验的机器学习工程师，正指导研究生改论文。请按学术会议评审标准逐段分析第二章，重点找理论漏洞和实验不足。
示例：你是一位擅长人际关系的心理学家，富有耐心和同理心。请分析我与朋友的冲突并给出建议。

##### 2. 思维链引导
让模型逐步推理，避免跳步。
示例：请分析通胀对经济的影响。先定义通胀，再谈对消费者、企业、政府的影响，最后给出应对策略。

##### 3. 激发创新指令
鼓励突破常规。
示例：给我五个截然不同的年轻向广告创意，每个主题和表现手法都要独特。
示例：假设不受传统广告形式限制，提出一个有颠覆性的全球级广告创意。

#### 3.6.3 避免模型幻觉的技巧

模型幻觉指表面合理实则错误的内容，多见于专业、实时数据、精确计算场景。

##### 1. 来源追溯法
要求标注来源与可信度。
示例：所有数据需附来源，不确定内容请表述为“据行业推测”。
示例：按“结论+数据来源机构/文献+发表年份”格式作答。
示例：对每个重要陈述标注可信度A-D。A多方权威验证；B单一可靠来源；C行业共识未独立验证；D基于推导的结论。

##### 2. 知识库调用法
上传可信领域资料供模型优先参考，减少错误。
上传要点：选择权威结构化资料；确保格式符合要求，支持多种文档和图片，单库最多五十文件，单文件不超过一百MB。
基于知识库作答能显著提升可靠性与专业性，确保输出基于验证信息。

本章系统拆解 DeepSeek 接口的使用路径，从密钥申请与管控到参数配置，再到多语言调用实战，每一步都有说明。无论你是编程入门者还是资深工程师，都能找到进阶路线与高效技巧，在集成开发中游刃有余。

#### 4.1 接口总览

API 即应用程序编程接口，是一套规定系统间如何交互的规则与协议，让不同程序或服务可以共享数据与能力，实现无缝协作。可把接口比作餐厅服务员。你是顾客，有点餐需求，不能直接进后厨，只能通过服务员传达请求，服务员把需求告知后厨并把菜品带回。这样你无需了解后厨流程，只需通过服务员表达需求即可获得服务。

DeepSeek 在设计时高度对齐 OpenAI 接口，格式基本一致。因此使用者只需做少量配置调整，就能直接使用 OpenAI SDK 或兼容 OpenAI 接口的工具对接 DeepSeek 接口。

#### 4.2 生成接口密钥

接口密钥是访问 DeepSeek 服务的数字凭证，核心作用在于身份鉴权、权限管控与资源计量。申请流程如下。

(1) 进入 DeepSeek 官网首页的“API开放平台”，用已注册账号登录。企业用户需先完成实名认证与权限申请。

(2) 在图4-1所示的 API key 管理页面，点击左侧“API keys”，点击“创建 API key”按钮，在弹出的对话框中填写密钥名称。

(3) 点击“创建”按钮即可生成 API 密钥，如图4-2所示。

注意，API 密钥仅在创建瞬间完整展示一次，DeepSeek 不提供再次查看。若密钥丢失，需注销后重新创建。为保障账户安全，请妥善保管密钥，切勿共享或写入浏览器及客户端代码中，以免泄露。DeepSeek 内置自动防护，一旦检测到密钥公开或泄露，系统会自动禁用该密钥，以最大程度保护账户安全。请始终保持警惕，避免密钥暴露。

#### 4.3 核心参数配置

调用 DeepSeek 接口依赖 3 个核心参数的准确配置，它们是连接服务的基石。

##### 4.3.1 base_url

base_url 定义了接口服务的网络入口。开发者需按运行环境选择对应端点，分为生产环境与测试环境。

生产环境用于线上应用，调用地址为 https://api.deepseek.com/v1 ，内置负载均衡与自动容灾，适合高并发场景。

测试环境用于开发调试，调用地址为 https://api.staging.deepseek.com/v1 ，提供请求日志回放与异常注入功能，便于排查问题。

另请注意，URL 中的 /v1 表示协议版本号，与模型版本无关。

##### 4.3.2 api_key

api_key 是身份验证的核心凭证，采用符合 RFC 6750 标准的 Bearer Token 机制。该密钥由前缀“sk-”加上 48 位随机字符构成，共 64 位哈希值，如 sk-abc123…xyz456 。为确保安全，密钥应通过环境变量或密钥管理服务如 AWS KMS 动态注入，严禁硬编码在客户端代码或版本控制系统。DeepSeek 的实时密钥审计会监测异常使用，一旦发现泄露将自动触发熔断机制。

##### 4.3.3 model

model 决定调用的模型能力。指定 model 为 deepseek-chat 将调用最新的通用对话模型，当前为 DeepSeek-V3，支持 32k tokens 长上下文；若需数学推导、代码生成等复杂任务，则选用 deepseek-reasoner ，该模型针对逻辑推理优化了注意力机制。模型版本采用语义化版本控制，可通过 deepseek-chat-2024q2 格式锁定特定季度版本，避免兼容性问题。

##### 4.3.4 Python 调用示例

Python 是高级解释型语言，语法简洁、生态丰富，广泛用于数据分析、AI、Web 开发等。不熟悉 Python 的读者可跳过本节。

下方是一段简化示例，仅演示 base_url、api_key、model 三个必填参数的调用方式。
```python
import os
import requests

# 1. 配置API服务地址，根据环境选择相应端点（生产或测试）
base_url = "https://api.deepseek.com/v1"  # 生产环境地址
# 若为测试环境，可改为：
# base_url = "https://api.staging.deepseek.com/v1"

# 2. 动态获取身份验证密钥，确保密钥安全性（请提前设置环境变量DEEPSEEK_API_KEY）
api_key = os.environ.get("DEEPSEEK_API_KEY")
if not api_key:
    raise ValueError("请设置环境变量DEEPSEEK_API_KEY，用于身份验证")

# 3. 指定调用的模型，可选择deepseek-chat或deepseek-reasoner
model = "deepseek-chat"  # 示例中使用通用对话模型

# 构建HTTP请求头，遵循Bearer Token验证机制
headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json"
}

# 示例请求数据，根据实际需求修改prompt内容
payload = {
    "model": model,
    "prompt": "请简要介绍DeepSeek API的核心功能。"
}

# 发送POST请求调用DeepSeek API（此处'/endpoint'为示例接口路径，请根据文档实际修改）
response = requests.post(f"{base_url}/endpoint", json=payload, headers=headers)

# 处理返回结果
if response.status_code == 200:
    print("调用成功，返回数据: ", response.json())
else:
    print(f"调用失败，状态码: {response.status_code}\n错误信息: {response.text}")
```

各选项说明如下。

- Max Tokens：控制 AI 单次回答的最大 token 数。每个字、标点都计为 token。设为 8192 意味着最多生成 8192 个 token，约几千字。增大可输出更长内容，减小则输出更短。
- Temperature：决定回答的创造性程度。值越接近 1，回答越随机、创造性强；值越接近 0，回答越精确、保守。若需准确直接的回答，可选择较小值。

- Top-P 用来限定单次生成时采样的概率累积窗口。举例将 Top-P 设为 0.7，模型仅在累计概率最高的前 70% 词表中抽样。数值越高，输出越发散、创意越强，但偏离预期的可能性也越大；数值越低，输出越收敛、更贴合指令。
- Top-K 通过限制候选词数量来调控多样性。设为 50 即只在概率前 50 的词里挑选。K 越大，语言通常更流畅自然；K 越小，可控性提升，但容易出现重复或生硬感。
- Frequency Penalty 用来抑制高频重复。设为 0 时不做惩罚，重复表达更常见；提升数值后重复率下降，文本新鲜度提高。

三项参数可以协同实现对输出风格的精细调节，满足拉长篇幅、增强创意或追求准确少冗余的需求。

#### 5.2 DeepSeek本地部署
大语言模型已在各行各业普及，但多数以云服务形式由大厂提供，限制了深度研究与个性化改造。银行若把客户数据上传云端分析，相当于把金库钥匙交给第三方；网络不稳地区每次提问都受连通性制约；初创团队想做专属系统，商业 API 却像租赁房屋难以随意改造。正因如此，本地化部署成为越来越多团队的选择。

##### 为什么要选择本地部署大模型？
- 隐私与安全：敏感数据无需外发，全程本地处理，降低泄露风险。
- 响应更即时：省去网络传输，推理延迟明显下降，体验更流畅。
- 定制与可控：可按需微调与优化，灵活度大幅提升。
- 成本更可控：前期硬件投入后，长期使用成本远低于持续付费的云服务。

Function CallDeepSeekAPI(api_key As String, inputText As String) As String

    Dim API As String

    Dim SendTxt As String

    Dim Http As Object

    Dim status_code As Integer

    Dim response As String

    API = "https://api.deepseek.com/chat/completions"

    SendTxt = "{"model": "deepseek-chat", "messages": [{"role": "system", "content": "You are a Word assistant"}, {"role": "user", "content": "" & inputText & ""}], "stream": false}"

    Set Http = CreateObject("MSXML2.XMLHTTP")

    With Http

        .Open "POST", API, False

        .setRequestHeader "Content-Type", "application/json"

        .setRequestHeader "Authorization", "Bearer " & api_key

        .send SendTxt

        status_code = .Status

        response = .responseText

    End With

    If status_code = 200 Then

        CallDeepSeekAPI = response

    Else

        CallDeepSeekAPI = "Error: " & status_code & " - " & response

    End If

End Function
