## **底层逻辑**

要想知道 OpenClaw 究竟有什么独特之处，我们需要先了解一个基事实：AI 工具从功能上可以分为意图理解引擎和自动化执行引擎两大类。绝大多数人所熟知的 AI 工具，都属于前者。它们擅长理解人类的语言，然后调用自己的知识库或搜索引擎，生成一个回答。这种交互模式的核心是“一问一答”，工具扮演的是“信息加工者”的角色。

OpenClaw 属于后者——自动化执行引擎。它的工作方式不是“理解并回答”，而是“理解并执行”。理解了这一点，你就知道为什么 OpenClaw 能做很多其他 AI 工具无法做到的事情了：

• 它能处理实时变化的动态信息；

• 它能操作需要登录的私有系统；

• 它能跨平台整合数据。

**操作方法**

明白了以上区别之后，下一个问题随之而来：作为用户，我该如何有针对性地选择 AI 工具？换句话说，如何判断一个任务应该交给 ChatGPT，还是交给 OpenClaw？我们可以用一个简单的三维判别法来做决策：任务类型、数据来源和执行方式。

**1.** **看任务类型：是“问问题”还是“跑流程”？**

如果任务是“获取信息并整合成答案”，这类任务就适合交给意图理解引擎。

如果任务是“按照固定步骤操作并获取结果”，这类任务就适合交给自动化执行引擎。

**2.** **看数据来源：是“公开知识”还是“私有界面”？**

如果数据已经存在于 AI 工具的知识库或公开的搜索引擎，ChatGPT 就能搞定。

如果数据存在于需要登录、滚动加载、点击才能看到的界面，就只能选择 OpenClaw。

**3.** **看执行方式：是“一次性回答”还是“持续性监控”？**

如果你只需要一个答案，今天问完明天就不再关心，那么绝大部分 AI 搜索工具都可以做到。

如果你需要持续关注某个变化，或者每天固定时间汇总信息，就必须选择 OpenClaw 了。

**本节小结**

OpenClaw 之所以能从极客工具走向大众工具，关键在于降低门槛，而不是降低能力。它把代码变为人话，把过程变得透明，用模板降低使用成本，用场景让大众更容易理解。它的设计理念，是让工具适应人，而不是让人适应工具。

## **10 分钟搞懂工作原理，OpenClaw 是怎么替你跑腿的**

**问题锚点**

用 OpenClaw 时，很多人都会有这样的顾虑：它是怎么模拟人的操作的？能不能识别屏幕内容？执行任务时，能不能做其他事？断网了，会怎样？如果这些疑问得不到解决，就很难和用户建立信任，而信任才是用好自动化工具的前提。现在，我们就把 OpenClaw 的工作原理讲透，让你看清这个“数字员工”的跑腿逻辑。

## **底层逻辑**

OpenClaw 的核心工作原理其实很简单：就像一个人坐在你的设备前，动手操作你的设备，按照你的要求完成任务。拆解开来，运行 OpenClaw 主要包含 3 个关键环节。

**1. 它靠视觉识别“看”屏幕。**

它没有眼睛，就用 OCR 识别文字、图标形状和界面结构，精准找到“登录”“搜索”等按钮、输入框，判断页面上的各类元素。

**2. 它靠模拟操作“动”手脚。**

看懂屏幕后，它会模拟人的动作：移动鼠标、点击按钮、输入文字、滚动屏幕，所有你能手动完成的操作，它都能复刻。

**3. 它靠执行引擎“想”逻辑。**

它有自己的“大脑”，能解析你的指令，拆解成一步一步的动作，支持顺序执行、条件判断、循环操作和异常处理。

以上三者结合，就形成了它的完整工作流：看→想→动→再看→再想→再动，循环往复，直到任务完成。

**操作方法**

弄懂了原理，我们就能更好地运用 OpenClaw 干活。写指令时，对应它的 3 个核心环节，就能让任务执行得更顺畅。

**1. 告诉它“看什么”：用客观描述定位目标。**

OpenClaw 视觉识别能力强，但需要你给出明确的指引，用文字、图标或相对位置描述，比如“点击包含‘登录’的按钮”“找到放大镜搜索图标”。

**2. 告诉它“怎么动”：拆解完整的动作序列。**

不能跳步、不能省略，明确写出“打开”“等待”“输入”“点击”“滚动”“提取”“保存”等每一步，关键步骤后加上“等待”，给页面加载留时间，比如“点击搜索后，等待 2 秒再提取结果”，避免操作过快导致出错。

**3. 告诉它“怎么想”：建立清晰的条件逻辑。**

利用它的执行引擎，写出正常流程和异常流程，比如“如果价格低于 500 元就发送通知，否则继续监控”，再加上“失败后重试 3 次”的异常处理，就像教新人干活一样，既要讲怎么做，也要讲出了问题应该怎么处理。

**4. 可视化执行：看着它干活更放心。**

第一次运行新任务时，打开“实时预览”，能清楚地看到它执行到哪一步了，发现操作错误可随时干预，确认无误后再设为后台自动运行。

标准指令示例（对应工作原理）如下。

步骤 1：打开某购物平台 App，等待首页完全加载。

步骤 2：在搜索框中输入“某品牌耳机”，点击“搜索”按钮。

步骤 3：等待搜索结果加载，向下滚动加载 20 条商品。

步骤 4：提取每条商品的标题、价格和销量。

步骤 5：如果某商品价格低于 500 元，将其信息存入“降价提醒”表格，并发送钉钉通知。

步骤 6：任何一步执行失败，等待 5 秒后重试，最多重试 3 次。如果仍然失败，发送错误报告到指定的电子邮箱。

这个指令的每一步都对应 OpenClaw 的工作原理，具体如下。

步骤 1～3：看（识别页面元素）+动（点击、输入、滚动）。

步骤 4：看（提取文字）。

步骤 5：想（条件判断）+动（保存、发送）。

步骤 6：想（异常处理）。

**常见偏差**

在实际操作中，用户有可能出现以下 4 类偏差。

**偏差 1：高估视觉识别的能力。**

写“找到好看的图片”这类主观指令，工具无法理解什么叫好看。

**校正：**用客观描述定位，比如“找到包含‘商品主图’的区域，提取图片链接”，视觉识别只能识别文字、图标等客观元素，无法判断主观审美。

**偏差 2：忽略等待时间，导致操作过快。**

直接写“点击登录，输入账号”，页面未加载完成就输入，导致失败。

**校正：**关键操作后加等待指令，优先选择“等待直到某元素出现”，比固定等待时间更可靠，适配不同的网络速度。

**偏差 3：用固定坐标代替元素识别。**

图省事写“点击坐标（500，300）”，一旦屏幕分辨率或窗口大小变化，就会出错。

**校正：**尽量用元素识别，比如“点击包含‘确认’的按钮”；确定需用坐标，需标注屏幕分辨率，并提示用户根据自身设备予以调整。

**偏差 4：忽略执行环境的差异。**

在家调试好的任务，在公司运行失败，大多是网络、软件版本不同导致的。

**校正：**写指令时要考虑环境因素，比如“检测到需要代理则先设置代理”，并在开头标注环境信息，提醒更换环境时要调整。

**本节小结**

OpenClaw 的工作原理并不神秘：视觉识别“看”屏幕，模拟操作“动”手脚，执行引擎“想”逻辑。理解这个逻辑，用户写指令时就能精准配合。不害怕它乱操作，放心把重要任务交给它，这也是用好 OpenClaw 的第一步。

任务规划的核心逻辑，就一句话：以终为始，逆向拆解。

目标：结果要什么样的？（表格？文档？通知？）

变量：哪些信息会变？（日期、关键词、登录状态）

异常：出错了怎么办？（重试？报警？跳过？）

触发：什么时候执行？（定时？手动？条件触发？）

## **实操演示，10 分钟把 OpenClaw 接入飞书群**

**问题锚点**

其实 OpenClaw 可以直接当你的专属群机器人，自己掌控数据。这一节我们就一步步演示：怎么把 OpenClaw 接入飞书群，实现自动推送、降价提醒和@通知。

## **底层逻辑**

OpenClaw 接入飞书群的底层逻辑很简单：通过飞书提供的“群机器人”功能，OpenClaw 把消息以 HTTP 请求的方式发送到飞书的服务器上，飞书再把消息转发到群里。

整个过程分为以下 3 步。

（1）在飞书群创建一个自定义机器人。飞书会给你一个唯一的 URL 地址，任何向这个地址发送的 HTTP 请求，都会被飞书解析并推送到群里。

（2）在 OpenClaw 的任务中，增加一个“发送消息”的步骤。当 OpenClaw 抓取到你需要的信息后，它会把这些信息拼成指定的格式，然后向那个 Webhook 地址发送一个 HTTP POST 请求。

（3）飞书接收请求，把消息展示在群里，如果配置了@某人，就会提醒指定成员。

**操作方法**

下面我们用一个真实案例，分步演示怎么把 OpenClaw 接入飞书群（见图 2-4）。

**1. 在飞书群里创建机器人。**

（1）打开飞书，进入你想要推送消息的群聊。

（2）点击右上角的“设置”图标，选择“群机器人”。

（3）点击“添加机器人”，选择“自定义机器人”。

（4）输入机器人的名字，可以上传一个头像。

（5）点击“完成”，飞书会生成一个 Webhook 地址。

（6）复制这个地址并保管好。

（7）（可选）在“安全设置”中，可以勾选“IP 白名单”，把 OpenClaw 所在计算机的公网 IP 添加进去。

**2. 在 OpenClaw 中配置发送消息的“动作”。**

（1）打开 OpenClaw，新建一个任务，或者编辑现有任务。

（2）在任务步骤中，找到“发送消息”类别，选择“发送飞书消息”。

（3）在弹出的配置框中，输入刚才复制的 Webhook 地址。

（4）选择消息类型。

• 文本消息：适合纯文字内容，支持@某人。

• 富文本消息：可以带颜色、加粗、链接等。

• 卡片消息：布局更美观。

（5）填写消息内容。如果是文本消息，直接写你要发送的文字；如果是卡片，需要按飞书的卡片格式写 JSON。

（6）设置@谁：可以填“all”@所有人，或者填写具体用户的 Open ID，或者不设置。

**3. 编写完整的自动化任务。**

假设我们有一个本地 Excel 表格“待办事项.xlsx”，每天更新当天要做的事情。我们希望 OpenClaw 每天 8:30 读取这个表格，把待办内容整理成消息发送到飞书群。

任务指令如下。

定时：每天 8:30

任务：

步骤 1：打开本地文件“D:\待办事项.xlsx”。

步骤 2：读取工作表“今日待办”中的所有行，提取“事项”“优先级”“截止时间”三列。

步骤 3：将读取的数据拼接成一段文本。

步骤 4：调用“发送飞书消息”动作，Webhook 地址为刚才复制的地址，消息类型为“文本”，内容为步骤 3 生成的文本，并设置@我。

步骤 5：如果发送成功，记录日志；如果失败，重试 2 次。

简化版指令示例如下。

定时：每天 8:30

任务：

let todos = 读取 Excel（"D:\\待办事项.xlsx","今日待办",["事项","优先级","截止时间"]）

let msg = "今日待办（@我）：\n"

for each todo in todos:

msg = msg+todo.优先级+" "+todo.事项+"（截止"+todo.截止时间+"）\n"

发送飞书消息（"https://open.feishu.cn/open-apis/bot/v2/hook/xxxx", "文本", msg, "@me"）

**4. 测试与运行。**

（1）先手动运行一次任务，看飞书群里是否收到消息。

（2）如果没有收到，检查以下内容：

• Webhook 地址是否正确；

• 消息内容是否为空；

• 飞书群里是否禁用了机器人。

（3）测试成功后，任务就会定时自动运行。

## **底层逻辑**

排查的过程，就是先找出问题出在哪一步，然后判断属于哪一类原因，最后采取对应的修复措施。OpenClaw 提供了几个有力的工具来帮你定位问题来源：日志、截图、重放。

问：多模型协同的任务，能手动干预执行过程吗？
