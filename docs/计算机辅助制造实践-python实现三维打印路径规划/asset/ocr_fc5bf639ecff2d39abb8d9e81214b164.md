# 7.4.2 目标邻面寻找

在扫描平面法这一大框架下，在某一特定层高上，我们可以以比较快的速度收集和当前扫描平面(或叫截平面)相交的所有三角面片，我们不妨记这些面片为 faces。注意，这里 faces 为一存放 TFace 类型数据的列表，而且它里面包含的面片数量远远小于整个模型的面片数量，甚至可以忽略不计。我们在这一小节的以下讨论将针对 faces 展开。

因为 faces 中的面片数量不大，因此我们可以直接对 faces 进行遍历，在里面寻找从未被使用过(即 used 属性为 False)的面片作为种子，并将种子面片作为当前面片。此时，我们不必急于寻找和当前面片相邻的面片，因为它至少少和 6 个面片相邻，包括 3 个共用棱边的面片和 3 个以上共用顶点的面片，搜索范围仍然有点大。我们需要做的是缩小搜索范围，定位当前截平面具体和当前面片的哪些半边或顶点相交。假设它们的交点在两条半边上，那么我们只需根据其中一条半边索引它的对边，进而索引对边所在的面片，即可找到目标邻面。这里的目标邻面指的是必然会和截平面相交的当前面片的相邻面片。

幸运的是，这里我们至少不用为求交问题而发愁，因为我们在 TFace 类中封装了一个 intersect 函数，它的功能就是对高度为 z 的截平面和拓扑面片进行求交，并且能够同时返回截交线段和交点所在的半边或顶点。方便起见，我们不妨记交点所在的半边为 edges，顶点为 node。如果我们回顾一下 intersect 的实现代码，我们会发现，这里 edges 为一存放 TEdge 类型数据的列表，它可能包含两个或一个元素。当 edges 包含两个元素时，node 必为 None，此时截平面和面片交线的两个端点均落在半边上；而当 edges 包含一个元素时，node 不为 None，此时截交线段的两个端点分别落在半边和顶点上。在这两种情况下，目标邻面的寻找策略完全不同，我们必须分开讨论。
