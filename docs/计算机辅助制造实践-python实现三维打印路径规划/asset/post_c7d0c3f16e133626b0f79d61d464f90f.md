| 5 | if i == 0: | # 使用 G0 快速跳至路径起点 |

| 7 | else: | # 使用 G1 打印路径上的其他点 |
| 8 | e += p.distance(path.points[i-1]) * nf2 | # 累加得到 e 值,即进丝量 |
| 9 | code += "G1 F%d X%.3f Y%.3f E%.3f\\n" % (pp.g1Speed, p.x, p.y, e) | |
| 10 | return code | # 返回代码文本 |

以上 pathToCode 函数的实现其实非常直观,其核心功能就是将路径上各顶点坐标按 G 代码标准格式化为字符串。它包含 4 个输入参数,其中 path 就是 Polyline 类型的多段线,pp 为 PrintParams 类型的打印参数,e 为累计进丝长度,nf2 为喷头尺寸( nozzleSize )和丝材尺寸( filamentSize )比值的平方,参见式(11-7)。考虑到 genAllPaths 函数可能生成多条路径,在将这些路径转化为 NC 代码时,我们可能需要多次调用 pathToCode 函数,此时参数 e 可以贯穿这些调用,得到累加进丝长度。至于参数 nf2,我们将其作为输入参数而不是在 pathToCode 函数中直接计算纯粹是出于降低计算量的考虑。

在 pathToCode 函数中,对于路径起点,我们使用了 G0 指令,让打印喷头以速度 g0Speed 快速移动至该点,且移动过程中喷头不出丝。对于 FDM 三维打印,在同一层切片上,当喷头从一点平移至另一点时,考虑到平移过程中无障碍物,因此无需设置安全平移高度;当喷头完成一层打印,向上移动一层时,由于喷头 Z 向高度提升,也不会碰到障碍物,因此也无需设置安全移动高度。综上两种情况,在路径起点,我们只要让喷头从上一条路径终点直接以 G0 移动至当前路径起点即可。对于路径上的其他点,我们使用了 G1 指令,让喷头以速度 g1Speed 从前一点沿直线移动至相应点,且移动过程中喷头出丝,出丝增量根据路径上当前点到前一点的距离及 nf2 计算得到。

函数 pathToCode 的返回为指定路径的 NC 代码文本。使用 pathToCode 函数，我们可以获取由 genAllPaths 函数生成的所有路径的所有 NC 代码。只要将所有 NC 代码进行累加，就能最终生成 NC 代码。根据这个思路，下面我们在 GenNcCode 模块中给出打印路径的后处理函数，函数名为 postProcess，具体实现如下：

| GenNcCode.py | NC 代码生成模块,定义打印参数类 | 11 - 11 |
|---|---|---|
| 1 | ...... | # 导入相关库,忽略其他代码 |
| 2 | def postProcess(layers, pp): | # 三维打印路径后处理函数 |
| 3 | code, e = pp.startCode, 0 | # 定义代码文本 code 和进步量 e |
| 4 | nf2 = ( pp.nozzleSize / pp.filamentSize ) ** 2 | # 计算喷头和丝材尺寸比值平方 |
| 5 | for i, layer in enumerate(layers): | # 遍历每层切片中的 5 种路径 |
| 6 | code += " ; Layer %d\n " % i | # 在代码中标识当前层号 |
| 7 | for path in layer.sptCpPaths: code += pathToCode(path, pp, e, nf2) | # 支撑轮廓路径代码 |
| 8 | for path in layer.sptDpPaths: code += pathToCode(path, pp, e, nf2) | # 支撑填充路径代码 |
| 9 | for path in layer.cpPaths: code += pathToCode(path, pp, e, nf2) | # 轮廓路径代码 |
| 10 | for path in layer.ffPaths: code += pathToCode(path, pp, e, nf2) | # 密实填充路径代码 |
| 11 | for path in layer.sfPaths: code += pathToCode(path, pp, e, nf2) | # 稀疏填充路径代码 |
| 12 | return code + pp.endCode | # 返回 NC 代码 |
| 13 | def genNcCode( pp : PrintParams) : | # 定义 NC 代码生成函数 |
| 14 | layers = genAllPaths(pp) | # 生成打印路径 |
| 15 | return postProcess(layers, pp) | # 打印路径后处理,生成 NC 代码 |

在实现 pathToCode 函数的基础上，以上 postProcess 函数的实现已变得非常简单。它的输入为切片序列 layers 和打印参数 pp，注意，postProcess 函数的调用应在 genAllPaths 函数调用之后，因此这里的 layers 中已包含打印路径。每层切片上至多有 5 种路径，即工件部分的轮廓路径 cpPaths、密实填充路径 ffPaths、稀疏填充路径 sfPaths，以及支撑部分的轮廓路径 sptCpPaths 和填充路径 sptDpPaths，针对这些路径，我们分别调用 pathToCode 函数生成了相应的代码。在每层切片路径打印顺序的安排上，我们采用了“先支撑后工件，由外至内”的策略，即先打印支撑部分，后打印工件部分，对每个部分，先打印外围轮廓路径，后打印内部填充路径。

需要说明的是，这里为简单起见，对每种路径中的每条独立路径，我们直接根据它在列表中的序号和相邻路径进行了连接。事实上，在某一层切片上，为了得到最短的总路径（即最短应走路径），我们可以把以上 5 种路径的连接题当作一个旅行商问题（TSP，参见图 8.32）。但这无疑会增加路径连接的难度，有兴趣的读者不妨去尝试解决这个问题。

在 postProcess 函数中，对累加得到的 NC 代码，我们在其开头添加了来自打印参数 pp 的起始代码 startCode，并在结尾添加了结束代码 endCode。在实际应用中，如果有需求，我们只需修改 pp 中的相应参数即可。此外，值得一提的是，为了标记 NC 代码中的切片层信息，我们在每层开头以注释的形式添加了层序号。同理，事实上，我们也可以在每层切片的种种路径前添加相应的注释文本，方便后续查看。

在以上代码的最后，我们定义了一个 GenNcCode 模块的同名接口函数 genNcCode，它的输入为打印参数 pp，输出为 NC 代码文本。归功于之前的良好封装，该函数的实现非常简洁，即先调用 genAllPaths 生成打印路径，再调用 postProcess 对路径进行后处理，输出 NC 代码。需要说明的是，在 genNcCode 函数中，我们并未将第 10 章介绍的模型优化摆放问题纳入考虑，有兴趣的读者不妨在该函数中添加这一功能。此外，我们并未在本书对 GenNcCode 模块展开测试，这主要是因为该模块的输出为 NC 代码文本，无可视化结果，我们也将这个任务留给有兴趣的读者。

事实上，我们在这一节得到的 genNcCode 函数的重要价值不仅仅是相对于 GenNcCode 模块而言的，它也是本书所有工作，所有理论、算法，所有模块、类、函数，所有尝试、实践、测试的最终结果与出口。将万千行代码汇聚成一行代码，这正是我们在本书解决三维打印路径规划中所做的事情。

## 本章小结

在这一章，我们主要完成了两个任务。一是对模型切片上的端面识别问题展开了研究。为了封闭三维打印后得到的工作，我们有必要对模型上的端面进行识别，并对端面区域进行密实填充。同时为了节省打印材料和时间，对除端面外的其他区域，我们可以进行稀疏填充。为此，我们提出了一种基于平面轮廓布尔运算和偏置运算的端面切片识别方法，并在此基础上，将各层切片分成密实填充区、稀疏填充区和轮廓填充区 3 种区域。这部分工作是对三维打印路径规划的进一步补充和完善，我们封装了一个 IdEndLayers 模块。

我们完成的第二个任务是封装一个三维打印 NC 代码生成模块 GenNcCode。通过对本书各章节已得到的模型切片、端面识别、路径生成、支撑生成等相关函数输入参数的梳理，我们建立了三维打印工艺参数表。在此基础上，通过对相关函数的合理组织，我们构建了一个综合打印路径生成函数。结合当下常用的 FDM 三维打印机及其 NC 代码格式，我们封装了一个后处理函数，可将路径转化为三维打印机能够识别的 NC 代码。使用 GenNcCode 模块中的 genNcCode 函数，针对指定三维模型和工艺参数，我们可以生成相应的 NC 代码。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_316_0.png)

由于控制器上用于暂存 G 代码的寄存器容量有限（一般为几百个字节，通常仅能保存若干条指令），因此不能一次性向控制器发送大量指令。上位机向控制器发送一条指令后，必须等待控制器 CPU 从寄存器读取并执行该指令后，才能继续发送下一条指令。对 Marlin 固件，上位机发送的每条指令必须以 '\n' 字符结尾，如“G1 X20 Y20 E1.3\n”；待下位机读取该指令后，会向上位机返回“ok”字符串；上位机接收到“ok”后可继续向控制器发送下一条指令。即在指令发送过程中，'\n' 和“ok”的数量必须保持一致。

在以上代码中，我们首先导入了一个名为 serial 的串口库。这是一个第三方库，如果没有安装过，我们需要使用“pip install pyserial”命令进行安装。在 main 函数中，我们首先创建了一个串口连接对象 con。在连接串口之前，我们需要确保三维打印机已连接至上位机电脑，建立连接之后的串口号可以在 Windows 系统的设备管理器中查看（如果用的是 Windows 系统）。这里我们在程序中设置的串口号为“COM3”，波特率为 115200。对 Marlin 固件，三维打印机控制器一旦和上位机建立串口连接，就会向上位机发送控制器的自身信息，如设备信息、固件版本、制造商信息等，最后以“ok”结尾。因此在建立串口连接后，我们有必要循环读取串口，直至“ok”。为此，我们专门写了一个 readToOk 函数，它的作用就是循环读取串口，直到读到“ok”字符串。

接下来我们对串口写了“G28\n"指令，强制打印机回零。注意，在“G28”后面必须加上‘\n’字符，否则打印机将不会执行回零操作。每次向打印机发送以‘\n’结尾的指令后，我们都需要调用 readToOk 函数，以确保串口返回“ok”。随后我们指定并打开 G 代码文件，循环读取文件中每行代码并将每行代码通过串口发送给打印机，同时读取串口返回，直至 G 代码文件末尾。最后关闭文件，关闭串口连接，打印完成。
