GeomAlgo 中封装的 PointInPolygon 函数）。综上,当 OffsetPolyses 中只有外轮廓曲线时,我们可以遍历其中每条曲线,在它的上一级偏置曲线中寻找直系父曲线,从而构建曲线之间的父子关系。当然,在表示曲线父子关系时需要相应数据结构的支撑。

刚才我们讨论的是打印区域边界 b0 只包含外轮廓的情况,但这只是一种特例,更普遍的情况是 b0 中既有外轮廓,又有内轮廓,如图 8.24。在增加了内轮廓的偏置曲线之后,以上我们所说的 OffsetPolyses [i+1] 中各曲线的直系父曲线在 OffsetPolyses [i] 中就不一定成立了。对包含内、外轮廓的偏置曲线来说,情况变得混乱,如图 8.24 所示:曲线 c1 和 c2 同属第 2 级偏置曲线 b2,但事实上,c1 位于 c2 内部,即 c2 是 c1 的直系父曲线;曲线 c3 属于第 3 级偏置曲线 b3,但 c1 和 c3 同为 c2 直系子曲线。而且对于 OffsetPolyses 中的曲线,我们很难推断它是外轮廓还是内轮廓的偏置曲线。在这种情况下,相对来说,确定 OffsetPolyses 中各条曲线之间包含关系就比较繁琐了,因为我们已经无法再利用 OffsetPolyses 的数据结构特点。

# 图 8.24 包含内外轮廓的连续偏置

既然如此,我们不妨尝试去探索并解决一个更为一般性的命题:对输入的平面封闭曲线序列 polys,已知所有曲线间不存在相交的情况,确定各曲线之间的包含关系。如果能够解决这个问题,那么我们自然而然能找出 offsetPolyses 中各条曲线的包含关系。

我们先来看一下使用暴力算法解决这个命题的基本思路。如上所述,对任意两条曲线,我们已经知道了如何去判断一条曲线是否在另一条曲线内部的方法。对输入曲线序列 polys 中的任意一条曲线 c,我们可以从 polys 中找出包含它的所有曲线,并把这些曲线放在一个临时列表变量中(记为 parents),显然,parents 中的所有曲线都是曲线 c 的潜在直系父曲线。根据直系父曲线的定义,我们只需从 parents 中找出距离曲线 c 最近的那条曲线(记为 p),曲线 p 即为曲线 c 的直系父曲线;反过来,曲线 c 即为曲线 p 的其中一条直系子曲线。同理,对 polys 中的其他曲线,我们也可以按照以上方法找出它的直系父曲线,从而构建所有曲线之间的父子关系。我们之所以称这种方法为暴力方法,是因为它的时间复杂度为 O(n^2),其中 n 为 polys 中的曲线数量,我们需要进行 n^2 次的 pointInPolygon 运算和 n^2 次的曲线之间最近距离计算,而这些运算都是相对比较耗时的。
