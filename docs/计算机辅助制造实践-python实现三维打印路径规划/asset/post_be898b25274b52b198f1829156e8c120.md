
同时降低 pointInPolygon 的判别次数。其实不难发现，在封闭曲线的包含关系中，直系父曲线的面积必然大于直系子曲线的面积。这个发现看起来微不足道，却是以下改进方法的基础。根据这一原理，在以上暴力算法中得到曲线 c 的潜在直系父曲线 parents 后，我们只需计算 parents 中每条曲线的面积，其中面积最小的那条曲线就是曲线 c 的直系父曲线，这样我们就可以完全规避多边形之间繁琐而费时的距离计算。如在图 8.25 中，曲线 c1 的潜在直系父曲线有 c2, c3, c4, c5, c6 共 5 条曲线，而在这些潜在直系父曲线中，c2 面积最小，因此 c2 就是 c1 的直系父曲线。事实上，如果我们一开始便考虑计算 polys 中各封闭曲线的面积，并按面积对 polys 中的曲线进行排序，我们还可以降低 pointInPolygon 至少一半的运算次数。因为对任意曲线 polys[i]，我们只需从面积比它稍大的曲线中（从 polys[i+1] 开始）寻找它的直系父曲线。在运气最好的情况下，我们大概只需 n 次 pointInPolygon 运算；在运气最差的情况下，我们大概需要 n(n - 1)/2 次 pointInPolygon 运算。

PolyPcrSeeker 类的核心功能是通过 seek 函数实现的。在这个函数中，有一点不得不提的是，我们运用了 Python 语言动态属性的添加特性，为 Polyline 类型的 poly 对象临时添加了四个属性，包括：area、parent、childs 和 depth。这样，我们不必回去修改 Polyline 类的定义，因为 Polyline 的这些新增属性在其他场合完全没用。注意，我们只能在 Python 语言下这样操作，如果使用 C++, C# 或 Java 等语言实现以上功能，那么我们只能在类定义中添加额外目标属性字段。

这四个临时属性是实现 seek 函数的关键。其中属性 area 表示曲线所围面积，考虑到通过 Polyline 类的 getArea 函数计算的面积可能为正也可能为负 (面积为正时曲线方向为逆时针, 反之为顺时针)，而这里的面积表示曲线所围区域的大小，须为非负，因此我们在给 area 赋值时要取 getArea 函数返回值的绝对值。属性 parent 表示当前曲线的直系父曲线，它的值可为 None，当值为 None 时，表示当前曲线无直系父曲线，即它是最外层曲线。属性 childs 表示当前曲线的直系子曲线列表，当列表为空时，表示当前曲线无直系子曲线。属性 depth 表示当前曲线所在的深度，这是一个相对概念，如图 8.26 所示，如果一条曲线为最外层曲线，即它的 parent 属性为 None，那么我们定义它的 depth 为 0，它的直系子曲线 depth 为 1，它的直系子曲线 depth 为 2，以此类推。显然，depth 越大，表示曲线越在内层；depth 越小，表示曲线越在外层。在 PolyPcrSeeker 类中，我们使用 findPolyDepth 函数获取当前曲线的深度值，这个函数的原理是从当前曲线出发，自下而上递归统计直系父曲线的个数，每统计到一条直系父曲线，则当前曲线的 depth 值自增 1，直至最外层曲线。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_190_0.png)

图 8.26 曲线包含关系中的深度值概念

在 seek 函数中，我们首先对 polys 中每条曲线的 area 属性赋值，然后据此对 polys 进行排序。对于按面积从小到大排好序的 polys 的第 i 条曲线，如果它有直系父曲线，那么它的直系父曲线必然是从 i+1 条曲线开始往后的首条包含它的曲线。据此，我们可以找到所有曲线的直系父曲线和直系子曲线，即对所有曲线的 parent 和 childs 属性赋值。在 seek 函数的最后，根据得到的父子关系，计算每条曲线的 depth 值，并对 polys 按 depth 值进行升序排序。这样做可以让 seek 函数输出的 polys 更加有序，外层曲线在列表前面，内层曲线在列表后面。

最后，在 PolyPcrSeeker 模块中，除了实现 PolyPcrSeeker 类之外，我们还实现了一个关于这个类的全局接口函数 seekPolyPcr，通过这个函数，可以非常方便地使用这个类。这个函数的输入为平面封闭曲线列表 (一维或多维)，输出为已经构建了父子关系且已排好序的曲线列表 (一维)。需要说明的是，尽管在 PolyPcrSeeker 类中，我们对暴力的曲线父子关系确定方法进行了优化，降低了不少计算量，但从理论上来说，以上 seek 函数的时间复杂度仍为 O(n²)，其中 n 为输入的曲线数量。在本书中，我们不对曲线包含关系的确定问题展开更深层次的研究。

对于连续偏置得到的曲线列表 offsetPolyses，我们只需将其输入以上 seekPolyPcr 函数，就能得到相应的已经构建了父子关系的曲线列表。

### 8.5.3 偏置路径连接

对连续偏置曲线 offsetPolyses，当三维打印机喷头沿着当前偏置曲线走完一周后，需要跳到另一条偏置曲线上，此时，我们就需要考虑如何连接这些偏置曲线。那么，我们是否可以依据 offsetPolyses 中各曲线的序号直接连接所有曲线，并将得到的曲线作为驱动打印机喷头运动的路径呢？这当然是可以的，但通过这种方式得到的路径可能不是最优的。

原因主要来自两个方面，一是各偏置曲线上的起点位置不定，二是同一级偏置曲线可能相距甚远。使用 Clipper 库中的布尔偏置工具得到的偏置曲线起点(终点)位置是没有规律可循的，它可能在曲线左侧，也可能在曲线右侧。对两条需要被连在一起的相邻级别的偏置曲线，连接第一条曲线终点和第二条曲线起点的直线段可能特别长，甚至跨越整个轮廓区域，如图 8.27 所示。而对于两条在同一偏置级别上的曲线，即便我们可以调整它们各自的起点、终点位置，最终得到的连线线段仍然可能非常长。对实际三维打印过程来说，较长的路径连接线段意味着较长的喷头移动时间，而在这段时间内喷头只空走不出丝，这对整个打印过程来说是徒劳的，只会延长打印时间，因此在规划路径时我们应该尽量减少喷头空走的时间，降低路径之间连接、跳转线段的长度。显然，采用以上直接按照序号连接偏置曲线的策略无法得到最短的打印路径。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_191_0.png)

图 8.27 直接连接两曲线端点存在的问题

经过上述讨论，我们的目标变得更加明确。我们需要解决的问题可以进一步抽象为：对一系列连续偏置曲线，寻找一种策略，连接所有曲线并得到最短的打印路径。这看上去又是一个单纯的几何优化问题，那我们该如何解决这个问题呢？

一开始我们可能会觉得毫无头绪，往往在这种时候，我们可以将问题简化或考虑原问题的一种退化情况。显然，这个问题最简单的情形就是求两条相邻曲线的连接问题，进一步地，我们假设这两条相邻曲线具有包含关系，即一条曲线在另一条曲线内部，如图 8.28 所示曲线 b1 和 b2，在这种情况下，我们又该如何连接这两条偏置曲线呢？显然，这个问题相比之下原问题要直观很多，我们只需要从两条曲线上找到距离最近的两点连接即可。假设 P1 和 P2 是曲线 b1 和 b2 上距离最近的两点，那么这两条曲线的连接方式如图 8.28 所示，连接之后得到的新曲线的起点为曲线 b1 的起点，它沿着 b1 走向到 P1 点后连至 P2 点，然后从 P2 点出发沿着曲线 b2 走向绕曲线一周回到 P2 点（具体是先到 b2 终点，再从 b2 起点出发沿着 b2 到 P2 点），随后再从 P2 点连接至 P1 点，沿着曲线 b1 走向到 b1 终点。根据以上连接方法，我们可以将两条相邻曲线连成一体，得到一条新曲线。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_192_0.png)

图 8.28 两条具有包含关系的曲线连接方法

现在我们稍微增加一下问题难度，考虑 3 条具有逐级包含关系的曲线连接问题，即第 1 条曲线 (b1) 包含第 2 条曲线 (b2)，第 2 条曲线又包含第 3 条曲线 (b3)，如图 8.29 所示，而且假如我们事先已经明确了它们之间的包含关系。我们不妨先看一下处于内层的两条曲线 b2 和 b3，对这两条曲线，我们完全可以按照以上介绍的连接方法将 b3 桥接到 b2，并用得到的新曲线替换 b2。然后，对 b1 和新 b2，采取相同的策略将新 b2 桥接到 b1，并记得到的新曲线为新 b1。显然，这里的新 b1 就是包含了所有曲线的最短路径。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_192_1.png)

让我们再增加一下问题难度，考虑 5 条曲线 b1 ~ b5 的连接问题。它们之间的关系是 b1 包含 b2, b2 包含 b3 和 b4, 即 b3 和 b4 位于同一级, b4 包含 b5, 如图 8.30 所示。和上面介绍的方法一样，首先我们需要从 5 条曲线中取出处于最内层的曲线 b5 及其直系父曲线 b4, 对这两条曲线, 我们可以按照上述的连接策略将 b5 桥接至 b4, 并用得到的新曲线替换 b4, 同时移除 b5。现在, 我们需要从剩下的 4 条曲线中取出处于最内层的曲线, 此时 b3 和新 b4 同时位于最内层, 我们不妨先取 b3。对 b3 和它的直系父曲线 b2, 我们可以将 b3 桥接到 b2, 得到新 b2 并移除 b3。接下来, 我们还需要从剩下的 3 条曲线( b1, 新 b2, 新 b4) 中取出处于最内层的曲线新 b4, 并将新 b4 桥接到新 b2, 再次得到一条全新的 b2。此时问题已经十分明朗，最后, 我们只需将全新 b2 桥接到 b1, 得到新 b1, 新 b1 就是包含了所有曲线的最短路径。

我们发现，无论输入曲线的数量有多少，它们之间存在多么复杂的包含关系，我们只要在每一步中遵循将处于最内层的曲线在最近点连接到它的直系父曲线上的原则，最后总能将所有处于内层的曲线桥接到最外层曲线，从而得到连成一体的最短路径，这就是连续偏置路径的最优连接策略。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_193_1.png)

图 8.31 两条线段距离计算

在以上叙述中，我们一笔带过了一个关键问题，即两条曲线最近点的求取问题。这个问题更为一般的形式为：对任意两条不相交的平面多段线，求取它们之间的最近距离以及取到最近距离的两个点。首先我们需要明确的一点是两条多段线的最近距离不一定就在两个顶点处取到，它也有可能在两条边线段上取到，而后一种情况涵盖了前一种情况，如图 8.31 所示。如果不计时间成本，那么这个问题很容易解决，我们只需构造一个双重循环，分别遍历两条曲线中的所有边，两两计算线段之间的距离，从中找出最小距离及取到最小距离时的边序号即可。显然，这种方法的时间复杂度为 O(mn)，其中 m、n 分别为两条多段线的边数，这是一种平方量级的时间复杂度。考虑到在偏置曲线连接过程中( 特别是还有很多切片层)我们需要进行密集的多段线最近距离计算，因此，这种方法不太可取。

在实际应用背景中，既然快速、精确地计算两偏置曲线的最近点这么困难，我们不妨退两步。理论上，两多段线的最近距离在两边线段上取到，但如果真的那么做，在每一次边对距离单元的计算中，我们需要讨论多种情况，如一条线段的端点投影是否落在另一条线段上，如果是，那么我们可能需要在该投影处将线段一分为二，并以此点作为连接点，这将会使单元计算和连接问题本身变得非常繁琐而费时。方便起见，我们首先直接在两多段线的顶点处取最近点。通过这种方法得到的最近距离和真实的最近距离偏差不会太大。接着，我们直接在其中一条多段线上人为指定一个点为最近点 (方便起见，指定起点)，这样做可为我们节省一重循环，我们只要根据这个点在另一条多段线上遍历寻找它的最近点即可。尽管如此，注意，这里的第二重循环是必不可少的，否则如果随便指定第二条多段线上的最近点，可能会出现连接线段穿越轮廓区域的风险。通过这两步的妥协，我们可以将最近点的求取过程降到线性时间复杂度。
