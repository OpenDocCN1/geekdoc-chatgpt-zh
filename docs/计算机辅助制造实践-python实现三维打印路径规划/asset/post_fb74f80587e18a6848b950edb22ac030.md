
以上 findLRPoints 函数的输入参数包括凹峰点 pt 和二维交点列表 ptses，返回为凹峰点两侧最近点。根据这两个点，我们就可以构造凹峰点对应的切分线段。在函数中，我们首先从二维列表中找出和给定凹峰点高度（即 y 值）相同的点列 pts，然后再逐一判断凹峰点的 x 坐标是否落在点列中的相邻点之间，如果落在某相邻点之间，那么这两个相邻点就是凹峰点两侧的最近点。这是为什么呢？如果我们回溯到 calcHatchPoints 函数的实现代码中，就会发现，我们已经对同一层高上的所有交点按照它们的 X 坐标值从小到大进行了排序。在这个前提下，我们不难理解以上代码。细心的读者可能还会发现，事实上，在 calcHatchPoints 函数中，我们已经为凹峰点两侧点的寻找解决了不少后顾之忧，比如我们删除了重合的交点。如果在 calcHatchPoints 函数中不删除重合交点，会对这里产生什么影响？有兴趣的读者不妨去探索一下。

最后，我们再来看一下步骤(4)，根据得到的切分线段分割平面区域，这是区域分区所有 5 个步骤中最难的一步。我们先来看一下最简单的情况，通过一条切分线段将给定平面区域分割成三个部分，生成 3 条全新的封闭轮廓。如图 9.21 所示，要分割图中区域，我们首先需要计算切分线段和区域轮廓的交点，这点我们在获得切分线段时就已做到。此外，更为重要的是，我们还需要知道交点所在的轮廓边（或顶点）在轮廓上的序号，只有这样，我们才能知道从哪里截取原轮廓中的部分轮廓和切分线段组成新的封闭轮廓。我们发现，要识别交点序号还是比较繁琐的，因为 calcHatchPoints 函数在计算交点时并没有保存相交线段的序号信息，因此我们不得不根据交点坐标遍历区域轮廓上的所有边，从中找出各交点所在轮廓边（或顶点）的序号。如图 9.21 所示，不妨设 A、P、B 三个交点在原轮廓上的序号分别为 10、20 和 30，那么最终生成的 3 个新的封闭轮廓的部分点序将是：0-10-30-0、10-15-20-10、20-25-30-20。对复杂的情况，当存在多条切分线段时，我们可以按照以上方法逐条递归分割原始区域。当然，在实现递归算法时我们还需要解决诸如当前切分线段属于上一步分区之后的哪个子区域等细节问题，这有点让人望而生畏。

那有什么简单的方法可以实现区域分区吗？如图 9.22 所示，如果将切分线段 AB 替换成切分矩形，这是否能够为我们提供一些解题思路？在这种情况下，我们只需对输入区域和切分矩形做布尔差运算，就能将输入区域分割成 3 个子区域。而对平面区域的布尔运算我们已经非常熟悉，只需调用 Clipper 库的相关函数即可实现。现在的问题是，我们必须保证以上切分矩形足够“瘦”，才能让其逼近切分线段。如图 9.22 所示，不妨设参数 δ 是一个趋向于 0 的极小正实数，vx 和 vy 分别为坐标系 X、Y 轴的单位方向，那么我们可以构造如下 4 个点为顶点的矩形：

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_229_0.png)

+ P1 = A - δ · vx - δ · vy (9-14)
+ P2 = B + δ · vx - δ · vy (9-15)
+ P3 = B + δ · vx + δ · vy (9-16)
+ P4 = A - δ · vx + δ · vy (9-17)

因为 δ 趋向于 0，因此矩形在沿 X 方向上的长度和线段 AB 相当，而在沿 Y 方向上的高度为 2δ，仍为一个趋向 0 的极小值，因此，我们有理由相信，使用矩形 P1P2P3P4 和使用线段 AB 对输入区域进行切分的效果等价。对复杂的情况，当有多条切分线段时，我们仍然可以构造多个切分矩形进行布尔运算。

在解决了区域切分问题后，我们给出 SplitRegion 模块的剩余代码，主要包括两个函数，一个是 createSplitter，另一个是 split，其中前者的作用是根据式（9-14）至（9-17）创建切分矩形，而后者是整个模块的核心流程控制函数，它们的具体实现如下：

split 函数是 SplitRegion 类的核心。它基本遵循了我们在这一小节开头给出的区域切分步骤，包括凹峰点寻找、凹峰点两侧点（即切分线段）寻找、切分矩形构造、裁剪区域切分等过程。其中在最后一步中，除了构造 Pyclipper 对象 clipper 之外，我们还构造了一个 Clipper 的适配器对象 ca，它的作用仍然是转化多段线的数据格式。我们将输入多边形列表以 PT_SUBJECT 类型添加至 clipper，而将切分矩形列表以 PT_CLIP 类型添加至 clipper，然后调用 Execute 函数并输入 CT_DIFFERENCE 进行布尔差运算，最终得到分割结果。

需要说明的是，如果输入区域本来就是一个单连通区域，那 split 函数直接返回原输入区域多边形。如果我们回过头看一下 SplitRegion 类的初始化函数，就会发现在类设计时，我们将 split 函数的返回结果保存在类的 splitPolygons 属性中。

最后，在 SplitRegion 模块中，我们还定义了一个类的同名全局接口函数 splitRegion，它的输入为待分区的平面多边形列表 polygons 和 adjustPolyDirs，其中第二个参数的作用是保证输入的多边形方向符合规定，函数的输出为已分区的单连通多边形列表。至此，我们已经给出了 SplitRegion 模块的全部代码。

必须注意的是，目前这个模块只能对输入的平面区域沿与 X 轴平行的切分直线分区，如果要实现沿任意方向的切分直线分区，我们可以先对输入区域进行相应旋转。

## 9.4 平行路径生成与连接

在上一节，我们用了大量的篇幅介绍了填充区域分区的原理和方法，创建并实现了一个专门用于将平面多连通区域切分为若干单连通区域的模块。需要再次强调的是，对填充区域进行分区的目的是更方便地连接区域内的填充线。本节我们将重点介绍平行填充路径的生成与连接问题。

在解决了填充线的生成和填充区域的分区问题之后，我们发现，平行路径的生成与连接问题已经变得非常简单，我们只需在路径的生成流程上做一些控制即可，其主要步骤如下：

- 输入表示待填充区域的平面多边形序列、填充间距及填充角度。
- 根据填充角度对多边形序列进行顺时针旋转，得到新多边形序列。
- 对新多边形序列进行分区，生成一系列单连通区域。
- 根据填充间距在各个单连通区域内生成填充线。
- 将各个单连通区域内的填充线段根据 zig-zag 的连接方式连成一体。
- 根据填充角度对得到的每条连接路径做逆时针旋转，生成平行路径。
- 输出平行路径序列。

考虑到以上各个步骤涉及的关键算法我们在前几节都已经解决，并且得到了相应的函数，如 splitRegion，genHatches 等，下面我们直接给出平行路径生成与连接的实现代码。

回到以上 GenDpPath 模块中的 generate 函数，对旋转后的新多边形 rotPolys，我们调用了之前封装的 splitRegion 函数将其分割成一系列单连通多边形 splitPolys。需要说明的是，这里我们将分区得到的单连通多边形 splitPolys 保存为 GenDpPath 类的属性，这样做的目的是方便后续统计指定填充角度下的分区个数。为了方便生成扫描高度列表 ys，我们在类中又定义了一个 genScanYs 函数，它的实现原理我们在本章 9.1 节已经有所介绍。对每个单连通多边形和高度序列 ys，我们将其输入之前实现的 genHatches 函数以生成填充线段。

随后，我们将各个单连通区域内的填充线段分别输入 linkLocalHatches 函数，它的作用是采用 zig-zag 的连接方式将单连通区域内的填充线段连成一体，生成一条多段线路径。最后，在 generate 函数中，对各个单连通区域内得到的已连接平行路径，我们又调用了 rotatePolygons 函数将其逆时针旋转回输入多边形区域内部。

不得不说的是，在 GenDpPath 类中，我们并未将 generate 函数生成的平行填充路径保存到类的任何属性中，这点和 GenCpPath 类的设计模式有所差异（GenCpPath 类将最终得到的路径保存到类的 paths 属性中），让人费解。但这其实是无奈之举，完全出于下一章我们对 GenDpPath 类的扩展需求。

在 GenDpPath 模块的结尾，我们定义了一个 GenDpPath 类的全局接口函数
