## 7.4 拓扑模型切片

通过上一节介绍，我们已经可以对输入的 STL 模型进行拓扑重建。对得到的 TModel 类型的拓扑模型，我们已经有能力从当前三角面片快速索引到与之相邻的所有面片，包括与之共享棱边的 3 个面片和与之共享顶点的若干个面片。我们应该把这种能力和模型切片结合起来。

在前面几章，针对原始 STL 模型的切片轮廓计算，我们已经做了不少工作。在切片过程中，如果截平面和 STL 模型中的其中一个三角面片相交，那么按正常逻辑，截平面也必然会和这个面片的其中一个（或两个）相邻面片相交。根据这一逻辑，对拓扑模型，如图 7.11 所示，我们可以快速定位到和截平面相交的相邻面片并求取截交线段。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_146_0.png)

进一步地，我们可以顺藤摸瓜，不停追踪邻近面片，从而找出拓扑模型中和截平面相交的所有面片。在对以上面片的追踪过程中，由相邻、相接面片求得的截交线段也必然是相邻、相接的，也就是说，这些截交线段是天然有序的，而非散乱无序，这样就可以省去线段拼接环节。

以上我们对拓扑模型切片过程的描述仅仅浮于表面，即便是我们已经得到了拓扑模型，对它的切片也并非真的只是寻找相邻面片而已，在这一过程中，我们还需要解决若干关键问题。而我们需要解决的第一个问题就是寻找“种子”面片，即寻找和截平面相交的第一个面片。

### 7.4.1 种子面片寻找

我们不妨设当前的截平面高度为 z。这里截平面依然为一张平行于坐标系 XY 平面的平面，可在 z 方向上根据需要平移。我们现在需要做的就是在拓扑模型中寻找一个面片，即种子面片，使其满足和截平面相交的条件。这一步是对拓扑模型进行切片的关键，因为如果没有第一个面片，我们将无法追踪随后的相邻面片。

如果我们不计时间成本，那么直接在拓扑模型中寻找一个种子面片并非难事。我们只需遍历拓扑模型中的所有面片，检查当前面片是否和截平面相交，如果相交，则设该面片为种子面片，并退出遍历循环。如果这样做，在以上遍历过程中，我们也并不会真的去求每个面片和截平面的截交线，因为这样可能会消耗大量的计算时间；我们只需判断每个片面的最低点和最高点组成的范围 [zMin, zMax] 是否包含截平面的高度 z 值，如果包含，说明当前面片可能和截平面相交。

假如我们通过以上方法找到了第一个种子面片，并且根据这个种子，我们陆续找出了一圈连续相邻的面片，根据这些面片我们也求得了一条封闭轮廓。可是，当一个截平面去截交模型时，它们之间可能存在不止一条封闭轮廓。因此，我们有必要去寻找第二个种子面片。为此，我们不得不又去遍历一遍拓扑模型中的所有面片。当然，为了不至于重复找到之前被使用过的面片，当一个面片被使用过后，我们必须设置它的 used 属性（即 TFace 类中的 used 属性）为 True。这里一个面片被使用过的意思是它和截平面的交线段已经被添加至轮廓。根据第二个种子面片，在得到第二条截交轮廓线之后，我们还需接着在拓扑模型中寻找第三个种子面片、第四个种子面片……直到模型中所有可能和截平面相交的面片的 used 属性均被设置为 True，即找不到种子为止。

在第 6 章中，我们曾做过这样的统计，对于一个大约包含 33 万个三角面片的 STL 模型（参见图 5.8 中的 monk 模型）来说，在切片后，平均每层得到的截交线段条数约为 988 条，即在每个切片层上，每张截平面平均约和 1000 个三角面片相交。针对这个例子，如果按照以上方法直接在拓扑模型中寻找种子面片，那么每次为了这 1000 个有效的面片，我们就不得不去遍历 33 万个面片，每次都多做了 330 倍的无用功。由此可见，直接从拓扑模型中寻找种子面片并不是一种最优的方式。我们应该努力去避免对整个拓扑模型的所有面片进行遍历。

针对种子面片的寻找问题，为了加快寻找速度，避免做太多无用功，我们可以采取一种“分而治之”的方式。通过以上分析，我们注意到，在每层切片上，截平面仅和有限个三角面片相交，因此，我们事先可以把与当前截平面可能相交的三角面片全部找出来，然后在这些面片中寻找种子面片。这样，针对 monk 模型，我们就可以把搜索范围从 33 万个面片减少到 1000 个左右，这绝对是一个不小的进步，而且，这最终会体现在寻找种子面片的运行效率上。那么我们又该怎样去寻找和当前截平面相交的所有三角面片呢？而且这个过程要求效率高，并要避免遍历，不然还不如直接从拓扑模型中寻找种子面片。

其实我们在第 5 章中介绍过一种方法来处理这个问题，就是扫描平面法。它的基本思路是：首先对模型中的面片按照最低点从低到高排序，然后构造一张扫描平面按切片层高从低到高扫描（参照图 5.3）。每到一处层高，我们首先从扫描平面中移除已经不再与之相交的三角面片，然后再添加新的与之相交的三角面片。通过这种方式，扫描平面总是维护着模型中与之相交的所有面片。扫描平面法采用排序和增量的方式维护面片数据，它的执行效率非常高，这点我们已经在第 5 章中有所见证。

在这里，我们可以仿照之前的扫描平面法截交流程，如图 7.12 所示，首先根据输入的切片厚度生成层高数据列表 zs，然后让扫描平面沿着 zs 中的层高值从下往上扫描。在每一层高处，扫描平面将收集和维护与之相交的所有三角面片，然后我们可以从这些三角面片中寻找第一个种子面片、第二个种子面片、第三个种子面片……直至这些面片的 used 属性均被设置为 True，从而找出当前层高处的所有截交轮廓线。通过这种方式，我们可以对拓扑模型中的面片实现“分治”，从而提高种子面片的搜索效率。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_148_0.png)

图 7.12 扫描平面法分治面片加速种子面片寻找原理

注意，我们在这里用的扫描平面法是一个大的框架，是一种面向全局的方法，即它面向的是整个模型高度上所有连续的切片层高，而不是单单针对某一层高。切片层数越多，它的优势越明显。如果仅仅是求取某一层高上的切片轮廓，扫描平面法是没有太多优势的，因为它还要准备数据、对面片进行排序等，这都将消耗一定的时间。我们在这里考虑的正是面向整个模型的切片，在每一切片层上都得寻找种子面片，因此是可以发挥扫描平面法的优势的。

### 7.4.2 目标邻面寻找

在扫描平面法这一大框架下，在某一特定层高上，我们可以以比较快的速度收集和当前扫描平面（或叫截平面）相交的所有三角面片，我们不妨记这些面片为 faces。注意，这里 faces 为一存放 TFace 类型数据的列表，而且它里面包含的面片数量远远小于整个模型的面片数量，甚至可以忽略不计。我们在这一小节的以下讨论将针对 faces 展开。

因为 faces 中的面片数量不大，因此我们可以直接对 faces 进行遍历，在里面寻找从未被使用过（即 used 属性为 False）的面片作为种子，并将种子面片作为当前面片。此时，我们不必急于寻找和当前面片相邻的面片，因为它至少少和 6 个面片相邻，包括 3 个共用棱边的面片和 3 个以上共用顶点的面片，搜索范围仍然有点大。我们需要做的是缩小搜索范围，定位当前截平面具体和当前面片的哪些半边或顶点相交。假设它们的交点在两条半边上，那么我们只需根据其中一条半边索引它的对边，进而索引对边所在的面片，即可找到目标邻面。这里的目标邻面指的是必然会和截平面相交的当前面片的相邻面片。

幸运的是，这里我们至少不用为求交问题而发愁，因为我们在 TFace 类中封装了一个 intersect 函数，它的功能就是对高度为 z 的截平面和拓扑面片进行求交，并且能够同时返回截交线段和交点所在的半边或顶点。方便起见，我们不妨记交点所在的半边为 edges，顶点为 node。如果我们回顾一下 intersect 的实现代码，我们会发现，这里 edges 为一存放 TEdge 类型数据的列表，它可能包含两个或一个元素。当 edges 包含两个元素时，node 必为 None，此时截平面和面片交线的两个端点均落在半边上；而当 edges 包含一个元素时，node 不为 None，此时截交线段的两个端点分别落在半边和顶点上。在这两种情况下，目标邻面的寻找策略完全不同，我们必须分开讨论。

我们先来看一下 intersect 函数返回的第一种情况，即 node 必为 None。此时截交线段的两个端点分别落在当前面片的两条半边上，如图 7.13 所示，我们可以从 edges 中取出这两条半边，并记 $e_0 = edges[0]$、$e_1 = edges[1]$。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_149_0.png)

此时目标邻面必然在 $e_0$ 对边所在的面或 $e_1$ 对边所在的面当中，即 $e_0.OE.F$ 或 $e_1.OE.F$。我们可以在这两个邻面中任选一个面作为目标邻面，但前提必须是邻面没有被使用过。因此如果 $e_0.OE.F.used$ 为 False，我们就选 $e_0.OE.F$ 作为目标邻面；而如果 $e_0.OE.F.used$ 为 True 且 $e_1.OE.F.used$ 为 False，我们就选 $e_1.OE.F$ 为目标邻面。当然，如果 $e_0.OE.F.used$ 和 $e_1.OE.F.used$ 均为 True，尽管这在现实情况下不太可能发生，但我们还是要把这种情况枚举出来并给出相应对策，这只能说明当前面片的目标邻面为 None，即不存在。

接下来我们再来看一下 intersect 函数返回的第二种情况，即 node 不为 None。此时截交线段的两端点一个落在当前面片的半边上，另一个落在当前面片的顶点上，如图 7.14 所示。我们不妨记这条半边为 e，e = edges[0]。

相对于第一种情况，第二种情况更为复杂，我们先从简单的情形入手讨论。显然，当前面片的目标邻面极有可能就是 e 的对边所在的面片，即 e.OE.F。如果 e.OE.F 从未被使用过，即 e.OE.F.used 为 False 时，如图 7.14(a)，那么当前面片的上一个面片必然和当前面片在顶点 node 处相邻，即轮廓线从上一面片穿过 node 而来，穿越当前面片，在半边 e 处穿出当前面片进入目标邻面，在这种情况下，目标邻面必然是 e.OE.F。但是，如果 e.OE.F.used 为 True，如图 7.14(b)，此时目标邻面必然在以顶点 node 为公共顶点的面片中，我们需要遍历这些面片，找出除当前面片以外和截平面相交的面片，并把这个面片作为目标邻面；当然，如果我们找不到这样的面片，那就说明当前面片的目标邻面为 None。

针对当前面片，以上我们罗列了两种寻找目标邻面的情况。根据这两种情况，我们可以从种子面片开始，连续追踪目标邻面。对于当前面片，或者存在目标邻面，或者不存在目标邻面。如果存在目标邻面，那么轮廓线可以继续生长；如果不存在目标邻面，那么轮廓线的生长到此为止，或闭合，或不闭合。

结合以上分析和讨论，接下来我们考虑将寻找目标邻面的原理和功能封装成一个函数，函数名为 findNextFace，意思为寻找当前面片的下一个面片，这个函数有助于我们构建邻面追踪循环。

当然，在这里，我们并不打算将 findNextFace 写成一个全局函数，我们把它放在 TopoSlicer 类中（对应 TopoSlicer.py 文件），顾名思义，这是一个专门为实现拓扑模型切片而创建的类，是本章核心切片功能的载体。
