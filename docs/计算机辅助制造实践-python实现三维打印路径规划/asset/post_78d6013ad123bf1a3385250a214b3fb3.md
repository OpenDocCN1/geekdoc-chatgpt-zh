
```python
xMin, xMax = float( 'inf' ), float( '-inf' )      # 初始化多边形在 X 方向极值
yMin, yMax = float( 'inf' ), float( '-inf' )      # 初始化多边形在 Y 方向极值
z = polygons[ 0 ].points[ 0 ].z
for poly in polygons:      # 遍历获取多边形各向极值
    for pt in poly.points:
        xMin, xMax = min( xMin, pt.x ), max( xMax, pt.x )
        yMin, yMax = min( yMin, pt.y ), max( yMax, pt.y )
v = Vector3D( math.cos( angle ), math.sin( angle ) )      # 填充方向向量
n = Vector3D( math.cos( angle+math.pi/2 ), math.sin( angle+math.pi/2 ) )      # 填充方向法向向量
O = Point3D( ( xMin+xMax )/2, ( yMin+yMax )/2, z )      # 多边形包络矩形外接圆中心
R = math.sqrt( ( xMax-xMin ) ** 2 + ( yMax-yMin ) ** 2 )/2      # 外接圆半径
P1 = O - n.amplified( R )      # 计算 P1 点，见图 9.9
parallels = []      # 保存生成的平行线段
for i in range( 0, int( 2 * R/interval )+1, 1 ):
    Q = P1 + n.amplified( interval * i )      # 计算 P1P2 上的垂足点 Q
    seg = Polyline()      # 用多段线保存平行线段
    seg.addPoint( Q - v.amplified( R ) )      # 平行线段起点
    seg.addPoint( Q + v.amplified( R ) )      # 平行线段终点
    parallels.append( seg )
hatchSegs = []      # 保存最终生成的填充线段
ca = ClipperAdaptor( )      # 创建 Clipper 的适配器对象 ca
clipper = Pyclipper( )      # 创建 Clipper 对象 clipper
clipper.AddPaths( ca.toPaths( polygons ), PT_CLIP, True )      # 向 clipper 添加裁剪窗口多边形
clipper.AddPaths( ca.toPaths( parallels ), PT_SUBJECT, False )      # 向 clipper 添加平行线段列表
sln = clipper.Execute2( CT_INTERSECTION )      # 执行求交裁剪操作，结果为 sln
for child in sln.Childs:      # 遍历，从 sln 中提取填充线
    if len( child.Contour ) > 0:
        poly = ca.toPoly( child.Contour, z, False )      # 将 Clipper 库 Path 转化为 Polyline
        seg = Segment( poly.startPoint( ), poly.endPoint( ) )      # 将 Polyline 转化为 Segment 对象
        hatchSegs.append( seg )
return hatchSegs      # 最终返回 Segment 类型列表
```

以上 genClipHatches 函数包含 3 个输入参数，其中 polygons 为待填充的多边形区域，interval 为填充线间距，angle 为填充线倾角。genClipHatches 和 genSweepHatches 两个函数的输入参数完全一致。以上代码按功能逻辑可明显分成两个部分，其中前半部分（第 3 ~ 21 行）的作用是生成能够覆盖整个多边形区域的平行线段，这一部分基本遵循上文介绍的步骤（1）～步骤（6）实现。这里我们使用 Polyline 来存储线段，这样做纯粹是为了兼容后面 Clipper 中的数据格式。以上后半部分代码的作用是调用 Clipper 库的裁剪功能生成填充线段，我们着重来分析下这一部分代码。

在后半部分代码中，我们首先创建了一个 ClipperAdaptor 类的对象 ca。在 ClipperAdaptor 类中，我们封装了几个对 Polyline 对象和 Clipper 内置 Path 对象相互转换的函数，这里 ca 的作用就是对两种不同格式的多段线进行相互转换。随后我们进入裁剪操作主体代码，包括创建 Clipper 对象 clipper，向 clipper 分别添加裁剪窗口多边形（即输入的 polygons，PT_CLIP）和待裁剪的平行线段（PT_SUBJECT），最后调用 Clipper 库的 Execute2 函数进行求交操作（CT_INTERSECTION）以获得位于裁剪窗口内部的填充线段。

需要说明的是，面向 Python 的 Clipper 库包含两个版本的裁剪执行函数，一个是 Execute，另一个是 Execute2，这两个函数的功能相似，主要区别在于对输出结果的组织。前者输出的是表示裁剪结果多边形（多段线）的线性列表，而后者输出的是带有父子节点结构的裁剪结果。对这里需要处理的开放线段裁剪问题，我们必须调用 Execute2 函数，否则我们将无法得到裁剪结果。有意向对 Execute2 函数实现细节或返回结果的数据结构进一步了解的读者，可再去查看 Clipper 库的相关文档。

回到代码 9-6，在得到 Execute2 的结果 sln 后，我们需要从中将裁剪得到的线段提取出来，方法是遍历 sln 的子节点（Childs）。每个子节点包含一个 Path 类型的轮廓（Contour），这些轮廓就是我们要求的填充线段。我们需要做的就是将 sln 的子节点轮廓转化为 Polyline 对象，然后再将 Polyline 对象转化为 Segment 对象并保存到填充线段列表中。至此，我们实现了 clipHatches 的后半部分代码，即通过 Clipper 库裁剪得到了一系列填充线段。

但是，我们对这些填充线段在平面上的分布情况是完全陌生的。它们中第一条线段在哪里？第二条线段是否与之相邻？它们是否遵循我们之前生成的平行线段的序号？这些问题都等着我们去回答。

## 9.3 填充区域分区

在前面两节，我们使用了两种方法分别生成了给定平面区域的填充线，一种是我们实现的扫描线法生成填充线，另一种是运用现成的 Clipper 库通过裁剪的方式生成填充线。我们知道，由于 Clipper 库内核使用 C++编写，因此上文中的 genClipHatches 函数相比于 genSweepHatches 函数在运行速度上具有先天优势(经简单测试，前者比后者效率高一倍左右)，但这种优势是相对的，后者可以通过更换编程语言来弥补不足。并且后者相对于前者更为实用，其中最重要的特征就是后者生成的填充线在平面上的分布是完全可控的，这有利于填充路径连接。我们在这一节将基于扫描线法生成的填充线展开进一步研究，最终目标是将得到的离散填充线段连成一体，形成平行路径。

### 9.3.1 填充线连接概述

我们先来看一下平行填充线连接的最简单情形。如图 9.11(a)所示，针对某一矩形区域，假设我们已经用扫描线法在其内部生成了一组平行填充线段，现在要将这些线段连成一体，使得到的多段线满足三维打印工艺需求或打印效率需求。我们当然不可能天马行空地随意去连接这些线段，一般而言，我们会采用 zig-zag, 之字形，图 9.11(b) ) 或单向，图 9.11(c)这两种形式去有序地连接填充线段。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_218_0.png)

我们知道，在使用扫描线法生成填充线段时，如果我们认为每条线段的方向是从起点指向终点的话，那么所有填充线段的方向都是一致的。如图 9.11 所示，zig-zag 连接的特点是在两条相邻平行线段的同侧点（同为起点或同为终点）处连接这两条线段，单向连接的特点是在两条相邻平行线段的异侧点（一个为起点、一个为终点）处连接这两条线段。显然，相比较而言，zig-zag 路径长度较短，加工效率较高；而单向路径长度较长，加工效率较低。由于刀具进给和主轴旋转的共同作用，常规的铣削加工工艺一般可分为顺铣和逆铣。显然，zig-zag 路径既包含顺铣过程，又包含逆铣过程；而单向路径只包含其中一种铣削过程。对机加工路径规划而言，对那些表面制造精度要求较高的零件，我们一般会采用单向连接策略。但三维打印工艺不存在顺铣和逆铣的区别，因此，为保证打印效率，在三维打印中，对平行行填充线，我们一般会选用 zig-zag 这种路径连接方式。

对图 9.11(a) 中的填充线段，我们可以使用 zig-zag 连接方式毫不费力地将所有线段连成一体。现在我们调整一下填充区域形状，如图 9.12 所示，对图中花瓶形状的多边形，我们发现，当填充角度为 0 度时，我们仍然可以非常轻松地将所有填充线段连成一体。但如果我们将原多边形顺时针旋转 90 度，而保持填充角度为 0 度不变，如图 9.13 所示，此时，我们发现已经无法像之前一样轻松地将所有填充线段连成一体。在连接这些线段时，我们将遭遇以下两个问题。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_219_0.png)

图 9.12 多边形区域内 zig-zag 连成一体的填充线

首先是平面上上下层填充线段的识别配对问题。如果我们调用 genSweepHatches 生成填充线段，如图 9.13 所示，那么图中上方局部区域内的 4 条填充线段在函数返回结果中的排列顺序是：AB、CD、EF、GH。假如在某一时刻，我们已经通过 zig-zag 方式连接了 AB 线段，现在我们要从 B 点连接到下一条填充线段。由图 9.13 可知，从 zig-zag 连接逻辑上来说，AB 的下一条线段应该是 EF；这和填充线段列表中线段的顺序是违背的，因为在列表中，AB 的下一条线段是 CD。这样，我们就有必要根据当前线段 AB 从填充线段列表中搜索并识别符合 zig-zag 连接逻辑的下一条线段，这就是我们需要解决的第一个问题。

产生上述问题的根本原因是上下层扫描高度上都存在至少大于一条填充线段。虽然看起来简单，但解决这个问题时却极容易出错，特别是当多边形轮廓形状比较复杂时，因为我们很难制定正确、完备的识别标准。一个很容易想到的识别条件是下一条线段所在的直线和当前线段所在的直线的间距是给定的填充间距值。这当然是对的，但这只是其中一个基础条件。另一个较为直观的识别条件可能是下一条线段的投影落在当前线段

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_220_0.png)

图 9.13 多边形区域内无法连成一体的填充线

上。但这个条件是不对的，如图 9.14 所示，线段 CD 的投影落在 AB 上，线段 EF 的投影没有落在 AB 上，但 EF 却是 AB 的下一条线段。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_220_1.png)

图 9.14 投影配对上下层线段失败案例

我们将遭遇的第二个问题是和当前填充线段配对连接的线段可能不存在。假设我们已经很好地解决了以上第一个问题，现在我们去连接图 9.13 左下方局部区域内的填充线段。我们从 I 点连入，可以轻松地将 IJ、KL、MN、OP、QR 这 5 条线段以 zig-zag 的方式串在一起；但是，当连到 R 点时，我们发现自己陷入了僵局：QR 的下一条线段是哪个？从表面上看，QR 的下一条线段应该是 UV，但是如果我们去连接图 9.13 右下方局部区域内的填充线段，我们会发现，UV 同时可能又是 ST 的下一条线段。一条线段同时和两条线段配对，这样的逻辑似乎有点混乱！此时，我们定义 QR 和 ST 的下一条线段都不存在，即对局部区域内填充线段的连接到此为止。这样定义的后果是我们无法将整个填充区域内的所有线段连成一体，但除此之外，我们没有更好的办法。

对形状完全相同的两个多边形区域，我们可以将图 9.12 中的填充线连成一体，却无论如何都无法将图 9.13 中的填充线连成一体，这到底是为什么呢？如果我们稍微观察图 9.12 和图 9.13 两图中两多边形内部的填充线段，同时结合扫描线原理，就会发现：在图 9.12 中，一条扫描线上只存在一条填充线段；而在图 9.13 中，一条扫描线上可能存在若干条填充线段。对前一种情况，我们可以形象地称扫描线被多边形轮廓切割成了一段；对后一种情况，我们称扫描线被多边形轮廓切割成了多段。不难想象，在图 9.13 中，如果我们把位于同一扫描线上的线段间的缝隙（位于区域外部）补全，那么我们照样可以轻松地将所有线段以 zig-zag 的形式连成一体。

由此可见，一个封闭区域内部的所有填充线能否连成一体和该区域内扫描线被切割得到的段数有关。如果这个区域内所有扫描线均被切割成一段，那么得到的所有填充线
