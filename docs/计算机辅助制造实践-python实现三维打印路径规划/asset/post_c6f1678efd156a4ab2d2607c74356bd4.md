## 10.2.3 切片支撑点计算

通过上一小节的介绍，我们已经能够计算给定三维模型和其网格竖线的交点，如图 10.6 所示，只要校验这些交点序号的奇偶属性，就能提取到用于支撑模型上悬臂结构的支撑线段。那如何将这些线段转化为实际可用的支撑及支撑路径呢？一种直观的思路是让打印材料在竖直方向上直接沿着支撑线段生长，以得到一系列细长的支撑柱子，但考虑到这些细长柱子在打印过程中极易倒塌，因此这种思路意义不大。支撑本身应该具备一定的自支撑性，如图 10.5 所示，在水平面上，支撑路径的填充形式可为上下层平行交叉填充或轮廓加平行填充。如何将沿竖直方向的支撑线段转化为水平面上的支撑填充区域呢？考虑到三维打印的基本特征是通过切片的形式将三维模型转化为平面上的二维轮廓，因此，针对这里的竖直支撑线段，我们也可以尝试使用切片的形式将其转化为平面区域。

如图 10.12 所示，在这一小节，我们的主要任务是对得到的支撑线段进行切片，即计算指定高度的水平面和支撑线段的交点，为了区别于上一小节中的模型支撑点（即模型和网格竖线的交点），我们称这些交点为切片支撑点。通过下一小节的介绍，我们将看到如何在平面上将这些切片支撑点转化为支撑区域。

回到支撑线段的切片问题。我们知道，通过调用 FindSptRegion 类中的 calcModelSptPoints 函数，我们可以得到一个字典变量 gridDic，其中字典的键为网格节点坐标，字典的值为该节点正上方的一组交点。而且在 calcModelSptPoints 函数中，我们已经对每组交点按其 Z 坐标从低到高进行排序。下面我们以 gridDic 中其中一个网格节点上对应的一组交点为例说明支撑线段的提取及切片方法。

## 10.2.4 切片支撑区域生成

通过上一小节介绍，对一指定三维模型，在指定高度的截平面上，我们已经得到了一系列切片支撑点，这些点散乱分布在平面上，但它们的竖直投影恰好都落在网格节点上，如图 10.13 所示。可以想象，网格尺寸越小，即网格节点越密，我们在截平面上得到的切片支撑点就越多越密；如果网格尺寸趋向无穷小，那我们将在平面上得到无穷多的切片支撑点。这些点密密麻麻地聚集在一起，在平面上呈现出的模样就是支撑区域。我们知道，由于计算资源限制，我们不可能将网格尺寸设置得非常小，即最终我们得到的可能是稀疏分布在平面上的有限个切片支撑点，如图 10.13 所示，在这种情况下，我们又该如何根据这些稀疏支撑点生成支撑区域呢？我们在本小节的任务就是寻找一种能够解决上述问题的通用方法和策略。

我们知道，在实际计算中，根据式（10-1）、（10-2），我们在 X、Y 方向上分别设置了两个实际可操作的网格间距值 a_x、a_y。基于这种设置，在指定截平面上，我们得到了一系列稀疏分布在网格节点上的支撑点。我们可以反过来进行如下的思想实验：如图 10.14 所示，当网格间距 a_x、a_y 从初始值逐渐变化到 0 的过程中，必然会有一系列新的切片支撑点（虚拟支撑点）出现。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_264_0.png)

图 10.13 切片支撑点转化为平面支撑区域示意

支撑点出现在原有支撑点附近（可以想象在原支撑点附近做若干竖直直线，试探这些直线是否和三维模型上的危险面片相交）；而且，随着网格间距进一步减小，网格分辨率进一步提高，原有支撑点附近出现新支撑点的区域范围将逐渐明确；并且，对两相邻原支撑点，它们相应的出现新支撑点的范围可能逐渐融合，并在最后合并为一个区域。严格地说，这个思想实验不一定完全正确，但却能在一定程度上指引我们寻找将平面支撑点转化为支撑区域的方法。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_264_1.png)

图 10.14 网格细化过程中在原切片支撑点附近出现的新支撑点

根据以上实验，我们可以定义一个支撑点的影响范围，即在该支撑点附近可能存在新支撑点的最大范围。简单起见，我们不妨假设这个影响范围是一个矩形（这符合我们从图 10.14(a) 和 10.14(b) 得到的直观认识，并且在后面我们将解释矩形假设的合理性），那如何确定矩形的尺寸呢？如图 10.14(b) 所示，网格节点 A、B、C 上各有一个支撑点，在 X 方向上，当 \(a_x\) 不断减小时，节点 A、B 上的支撑点影响范围逐渐清晰并融合。临界情况下，当两个矩形在 X 方向的长度尺寸均为 \(a_x\) 时，相应左右边界完全融合，此时再增加矩形的 X 尺寸已经不能影响它们在边界的融合效果，因此在 X 方向上，我们可以认定矩形的长度尺寸为 \(a_x\)。同理, 在 Y 方向上, 通过分析节点 A、C 上的支撑点影响范围, 我们可以认定矩形的高度尺寸为 \(a_y\)。根据以上假设及分析, 我们知道, 一个支撑点的影响范围为一中心在该点的轴平行矩形, 且矩形的在 X、Y 方向上的边长分别为 \(a_x, a_y\)。

下面我们解释为什么将支撑点的影响范围设定为矩形。首先, 这是一种偏安全的设定。我们知道, 对三维模型支撑生成来说, 如果在需要添加支撑的地方没有添加支撑可能导致打印过程中模型坍塌, 但如果在某些不需要添加支撑的地方添加了冗余支撑, 则并不会对打印过程带来不良影响。因此, 对支撑点的影响范围设定来说, 即便矩形内某些新支撑点对应的三角面片是安全面片, 我们也能接受这样的结果。其次, 矩形设定更易于相邻区域融合。如图 10.15 所示, 不失一般性, 其实我们也可以将支撑点的影响范围设定为圆形。但是, 在对相邻支撑点的影响范围进行融合时, 我们发现, 两个圆形之间容易留下缝隙, 为了覆盖这些间隙, 我们不得不将圆的直径设置得很大, 但这样会带来更多不必要的冗余支撑。而如果使用矩形设定, 我们能够以较小的尺寸实现相邻支撑点影响范围的无缝融合。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_265_0.png)

图 10.15 切片支撑点影响范围圆形和矩形设定优劣对比

使用支撑点影响范围的矩形假设, 让我们回过头来看一下截平面上切片支撑点到支撑区域的转化问题。如图 10.16 所示, 对平面上的一系列支撑点, 首先生成各个支撑点的影响范围矩形, 每个矩形的长宽尺寸分别为 \(a_x\) 和 \(a_y\)。然后我们需要对各个孤立的矩形区域进行“融合”操作, 生成一个(或多个)支撑区域。那如何融合矩形区域呢? 很简单, 布尔运算! 我们发现, 矩形区域的融合问题就是求这些区域的布尔并运算(参见图 8.14)。而关于布尔运算, 我们在本书第 8 章已经介绍了一个非常强大的库——Clipper, 而且, 我们还构建了 Clipper 库的适配器类 ClipperAdaptor, 方便我们交换不同的多边形数据。因此, 这里原则上只要我们将上述各个孤立矩形输入 Clipper 库中的布尔并运算函数, 就能输出我们在这一小节开头所要求的支撑区域。下面我们在 FindSptRegion 类中添加支撑点到支撑区域的转化函数, 函数名为 genRawSptRegion, 具体实现如下：

```
def genRawSptRegions( self, pts ):
    rects = []
    for pt in pts:
        rects.append( self.pointToRect( pt, 1.1 * self.gridSize, 1.1 * self.gridSize ) )
    clipper, ca = Pyclipper(), ClipperAdaptor()
    clipper.AddPaths( ca.toPaths( rects ), PT_SUBJECT )
    sln = clipper.Execute( CT_UNION, PFT_POSITIVE )
    return ca.toPolys( sln, pts[ 0 ].z )

def pointToRect( self, pt, lx, ly ):
    vx, vy = Vector3D( lx/2, 0 ), Vector3D( 0, ly/2 )
    rect = Polyline()
    rect.addPoint( pt - vx - vy )
    rect.addPoint( pt + vx - vy )
    rect.addPoint( pt + vx + vy )
    rect.addPoint( pt - vx + vy )
    rect.addPoint( pt - vx - vy )
    return rect
```

在以上代码中，我们定义并实现了两个函数，genRawSptRegions 和 pointToRect。其中后者是前者的依赖函数，它的作用是在 XY 平面上以给定点为中心生成一个轴平行矩形，在它的三个输入参数中，pt 为给定点，lx 和 ly 分别用于指定矩形在 X 和 Y 方向上的边长。为了配合 Clipper 库的数据结构，在 pointToRect 函数中，我们将矩形定义为一个拥有 5 个顶点且首尾点重合的多段线( Polyline )，各个顶点呈逆时针分布。

我们再来看一下 genRawSptRegions 函数。它的输入为 pts，即切片支撑点序列，该数据具体可通过调用 calcLayerSptPoints 函数获取；输出为当前截平面上的( 初始 )支撑区域。借助 Clipper 库，我们发现，该函数的实现过程非常简单！首先根据输入的 pts 生成平面矩形序列 rects，然后通过 Clipper 库对 rects 序列进行布尔并运算，最终返回表示支撑区域的平面多边形序列。当然在这过程中，我们使用了 ClipperAdaptor 类来转化多边形数据。需要说明的是，在调用 pointToRect 函数时，我们并没有按照上文推导的数据（即 a_x, a_y）去设置矩形边长，而是对 lx 和 ly 参数同时设置了 1.1 倍的 gridSize 值。这是因为 a_x 和 a_y 本身根据 gridSize 值圆整而来，且有 a_x ≤ gridSize, a_y ≤ gridSize，使用较大的矩形来替换较小矩形可以增加相邻矩形间的重叠面积，降低 Clipper 库在布尔并计算中出错的可能性。

在 genRawSptRegions 函数命名时，我们有意为其添加了一个“raw”标识，表明这个函数仍然是一个中间函数，它得到的平面支撑区域仍然是初始数据，需要进一步处理，而不是最终结果。这是为什么呢？如果我们单独从支撑生成的角度考虑，可能很难发现问题所在。但如果把我们在前几章得到的针对三维模型的切片轮廓和现在得到的支撑轮廓放在同一截平面上，也许我们就会发现问题。如图 10.17(a) 所示，因为我们使用了支撑点影响范围的矩形假设，过分自信地将每个支撑点的影响范围都等效放大小一致的矩形，导致最终融合得到的支撑区域侵占了模型区域，即导致切平面上模型轮廓和支撑轮廓相交。如果允许这种情况发生，打印时支撑材料将和模型材料混叠，增加打印后支持从模型上剥离的难度。因此，我们应该在生成支撑区域时避免这种情况发生。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_267_0.png)

那么如何避免模型轮廓和支撑轮廓相交呢？我们知道，模型轮廓来自对三维模型的切片，是精确且真实存在的轮廓，不容更改，否则打印得到的工件将无法匹配设计模型，从而失去打印本身的意义。而支撑轮廓是根据切片支撑点生成的虚拟轮廓，它的存在依赖于我们做出的一些假设，如支撑点影响范围的矩形假设，显然这些假设是不具备几何精度的。基于以上分析，我们应该对平面上的支撑区域轮廓进行修正，使其避开模型轮廓。

那又如何修正支撑轮廓呢？这个问题看似无从下手，因为我们似乎很难制定轮廓修正策略；但是如果结合布尔运算，如图 10.17(a)，我们只需首先让模型区域和支撑区域求交，就能得到重叠区域，然后再让支撑区域减去重叠区域，就能得到一个新支撑区域（这样写是为了便于理解，上述过程等价于支撑区域减去模型区域），此时新支撑区域的部分边界恰好和模型区域的部分边界重合，但两区域已经不再相交。实际上，考虑到打印工艺需求，避免支撑材料和模型材料过度粘连，方便打印完成后支撑剥离，我们应该在模型轮廓和修正后的新支撑轮廓之间预留一定的间隙。因为这个间隙是 XY 平面上轮廓间的间隙，因此我们称其为 xyGap，显然，这个间隙可用偏置的方法实现。我们不妨回头看看 Find-
