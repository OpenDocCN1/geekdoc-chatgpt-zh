
种填充规则,其中前缀 PFT 是 Polygon Fill Type 的缩写,即填充类型。如果不指定,默认情况下, Execute 函数将采用奇偶填充规则。

这里有几点需要说明的是,首先,Clipper 库中的轮廓是 Path,Path 是由二维 Point 组成的列表。在 Clipper 中,Point 结构事实上是二维元组,因此,在以上代码中,我们是通过二维元组和列表对 subject 和 clip 轮廓赋值的。Clipper 库执行布尔运算后可能返回多条轮廓,其中每条轮廓也是二维元组的列表,多条轮廓即返回多个列表。为了显示最终返回的轮廓,我们定义了 tuplesToPoly 函数,可以非常方便地将二维元组列表转化为 Polyline 对象,我们之前已经实现了在 VTK 中显示 Polyline 的方法。

其次,Clipper 对闭合 Path 的定义和我们对 Polyline 闭合的定义有所差别。和 Polyline 不同的是,在 Clipper 中,闭合轮廓并不是通过起点和终点坐标重合实现的,而是通过另外方式标识的。因此在以上代码中,我们创建的 subject 和 clip 轮廓都是非闭合的,当我们调用函数 AddPath 将其加入 clipper 时,我们通过设置第 3 个参数值为 True 告知 clipper 这些轮廓都是封闭的。对布尔运算返回的轮廓,如果我们需要通过将其转化为 Polyline 并在 VTK 中显示,原则上我们要强行设置轮廓闭合,这也是我们在 tuplesToPoly 函数中对得到的轮廓添加轮廓起点的原因。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_175_0.png)

至此,我们对 Clipper 库的介绍已经接近尾声。最后需要说明的是,Clipper 中的各种裁剪算法的时间复杂度接近线性,执行速度非常快,且非常稳定。对 Clipper 库实现原理感兴趣的读者建议阅读一下相关文献,特别是 Vatti 在 1992 年发表的 A generic solution to polygon clipping 论文,或者尝试阅读一下 Clipper 库的源代码(建议阅读其 C++源码)。而对 Clipper 库应用感兴趣的读者可以再去阅读一下官方说明文档,多尝试一些测试案例,做一些有意思的实际应用。注意,这一小节的内容是为下一小节服务的,在下一小节,我们将介绍基于布尔运算的轮廓偏置原理。

## 8.3.2 布尔偏置原理

我们在本章 8.2 节介绍了两种基本的初始偏置轮廓生成方法,线段平移法和角平分线法。我们发现,无论使用哪种方法,在偏置过程中都会难免产生自相交环,而且,这些自相交环通过常规方法很难消除。幸运的是,Clipper 库为我们提供了一种基于布尔运算的平面曲线的偏置方法(以下简称为布尔偏置),可以非常高效、稳定地帮助我们生成平面偏置曲线,消除轮廓上各种各样的非法自相交问题。下面我们尝试解释一下这种偏置方法的实现原理。注意,这一部分的内容完全基于作者对 Clipper 源代码的解读。

Clipper 库中布尔偏置的初始偏置曲线也是通过线段平移的方法生成的,但相邻偏置线段之间的修补策略有所不同。这里我们还是以逆时针轮廓的向内偏置为例进行说明，如图 8.15 所示，对原始封闭轮廓上的连续顶点 P1 ~ P5，我们可以按照上一节介绍的线段平移方法首先生成各条原始线段的偏置线段，如 P1 P2 的偏置线段为 Q1 Q2、P2 P3 的偏置线段为 S2 S3、P3 P4 的偏置线段为 T3 T4 等。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_176_0.png)

当原始轮廓上 3 个连续顶点所夹内角为优角（小于 180 度）时，如图 8.15 所示的顶点 P2，在上一节，我们采取的策略是对相应偏置线段（Q1 Q2 和 S2 S3）在交点处进行修剪后连接，见图 8.5(a)；对这种情况，Clipper 中布尔偏置采取的策略是直接连接 Q2 P2 和 P2 S2，生成 Q1 Q2 P2 S2 S3 这一段带有自缠绕效果的连续偏置轮廓，这样我们将在 P2 附近得到一个自相交环。同理，对顶点 P3、P5、P1，我们也可以得到自缠绕连续偏置轮廓，同时也将在顶点附近得到自相交环。有了 Clipper 库中的各种布尔操作，我们可以暂时不必理会这些自相交环。

当原始轮廓上 3 个连续顶点所夹的内角为劣角（大于 180 度）时，如图 8.15 中的顶点 P4，Clipper 中布尔偏置采用了三种策略来衔接相邻偏置线段间的缝隙：圆弧衔接、矩形衔接和斜角衔接，分别对应 Clipper 库中的 JT_ROUND、JT_SQUARE 和 JT_MITER 三个枚举标识量，其中前缀 JT 是 Joint Type 的缩写，表示衔接类型。

圆弧衔接(JT_ROUND)我们在之前的图 8.5(b) 和图 8.15 中都有所展示，即理论上，用一段圆心位于顶点、半径和给定偏置距离相等的圆弧去弥补两相邻偏置线段的缝隙，使得圆弧和偏置线段在连接处恰好相切，如图 8.16(a) 所示，注意，满足以上条件的圆弧在几何上是唯一的。但在实际操作中，如果我们真的用圆弧曲线（二次曲线）去衔接偏置线段，一方面将导致返回多段线内部数据格式的不统一（包含直线段和圆弧两种格式），这将给我们后续三维打印路径的生成带来无尽的麻烦；另一方面目前 Clipper 库也无法处理圆弧曲线的裁剪问题。所以在实际操作中，我们一般会对圆弧进行离散，即用一系列微小连续的弦来逼近圆弧，事实上，Clipper 中布尔偏置也是这么做的。具体操作时，如果对轮廓精度要求不高，则减少对圆心角的细分份数；如果精度要求较高，则减小圆心角细分角度。

矩形衔接(JT_SQUARE)是用一段和上述圆弧相切且和轮廓顶点角平分线垂直的直线段来弥补相邻偏置线段间的缝隙，如图 8.16(b)。为了保证偏置轮廓的连续性，我们需要同时延长偏置线段并在交点处和衔接线段相连。显然，使用矩形衔接时，顶点到衔接线段的最小距离等于给定偏置距离。相比于圆弧衔接，矩形衔接得到的偏置轮廓的顶点数据量更小，但前提是会损失偏置轮廓的光滑性。

斜角衔接(JT_MITER) 同样是用一段和轮廓顶点角平分线垂直的直线段来弥补相邻偏置线段间的缝隙，如图 8.16(c) 所示，但是轮廓顶点到衔接线段的距离不大于某一给定值(Clipper 中该值默认为偏置距离的 2 倍)。如果轮廓顶点到衔接线段的距离等于偏置距离，那么斜角衔接将退化为矩形衔接，因此，我们可以认为矩形衔接是斜角衔接的一种特殊形式。

在 Clipper 库中，默认的拐角顶点偏置线段的衔接方式是矩形衔接。值得一提的是，Clipper 不支持直接延长两相邻偏置线段至相交点的衔接方式。这是因为对于轮廓上的尖角来说，这种衔接方式可能引发严重的偏置问题，导致不合理的偏置轮廓自相交，进而导致本应一体的轮廓区域被分割成若干部分，如图 8.17 所示。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_177_1.png)

图 8.17 直接连接步尖角偏置线段引发的不合理分区

在解决了所有相邻偏置线段的连接问题之后，我们将得到一条封闭的初始偏置轮廓，如图 8.15 所示，但是在这条偏置轮廓上，可能存在大量的自相交环，特别是在优角顶点附近的局部自相交环。接下来我们可以使用在上一小节中介绍的绕数统计规则来统计由初始偏置曲线围成的各个区域的绕数。从图 8.15 各个区域标记的绕数可知,无论是局部还是全局,自相交区域内的绕数均为 1,而合法偏置区域内的绕数为-1,因此,我们可以用四种填充规则中的负填充规则来识别并提取合法偏置区域。当然这一过程需要 Clipper 库布尔运算支持,它的代码大致如下：

| | 初始偏置曲线上负填充区域提取 | 8 - 4 |
|---|---|---|
| 1 | clipper = Pyclipper() | # 定义 Pyclipper 对象 clipper |
| 2 | clipper.AddPaths(offsetPolys, PT_SUBJECT, True) | # 添加初始偏置轮廓作为 subject |
| 3 | sln = clipper.Execute(CT_UNION, PFT_NEGATIVE) | # 执行 union 操作,填充规则为负填充 |

在以上代码中,我们通过布尔并操作( CT_UNION ),结合负填充规则( PFT_NEGATIVE )消除所有绕数为正的偏置自相交环,最终返回的 sln 就是目标合法偏置区域的边界线,也就是我们所要求的偏置曲线。注意,Clipper 库在执行布尔并操作时,是允许仅添加一种类型的待处理轮廓( 即 subject ),这是因为对布尔并运算来说,subject 轮廓和 clip 轮廓是等价的,对此我们在前一小节已经有所解释。

但是也许我们心里还是有所怀疑,图 8.15 所示的轮廓是否太过简单? 在对逆时针轮廓向内偏置时,初始偏置曲线上自相交区域内的绕数大于 0 真的是一种普遍规律吗? 在这里我们无法对此给出严格的数学证明( 有兴趣的读者可以尝试去查阅文献并给出证明 ),但我们可以来看一下一个更有说服力的案例,一个更加复杂的轮廓偏置问题。如图 8.18 所示,这个轮廓同样出现在图 8.7 中,如果我们统计图中各个自相交区域的绕数,我们会发现,所有自相交区域内的绕数确实都是正的。

至此,我们应该已经把 Clipper 库中基于布尔运算的偏置原理解释清楚了。在实际偏置应用中,我们没有必要去执行布尔操作,因为 Clipper 库为我们封装了一个现成可用的轮廓偏置类。如果我们使用命令行安装 Clipper 库的话,这个类的类名为 PyclipperOffset, 它的使用方法也很简单,下面我们给出偏置示例代码(写在 Test_clipperOffset.py 文件中)：

| Test_clipperOffset.py | Python 版的 Clipper 库轮廓偏置测试 | 8 - 5 |
|---|---|---|
| 1 | from pyclipper import * | # 定义 Pyclipper 对象 clipper |
| 2 | outerPoly = [ (0,0) , (100,0) , (100,100) , (0,100)] | # 外轮廓,逆时针 |
| 3 | innerPoly = [ (30,30) , (30, 70) , (70,70) , (70,30)] | # 内轮廓,顺时针 |
| 4 | pco = PyclipperOffset() | # 创建 PyClipperOffset 对象 pco |

在以上代码中,我们首先创建了一个“回”字形轮廓,包括外轮廓 outerPoly 和内轮廓 innerPoly,这两个轮廓都是二维元组的列表。

然后我们将这两个轮廓通过 PyClipperOffset 类的 AddPath 函数分别加入 pco,并在参数中设置偏置线段衔接类型为 JT_ROUND,即圆弧衔接,轮廓端点类型为 ET_CLOSEDPOLYGON,即封闭多边形。

最后我们调用 Execute 函数生成偏置结果 sln,它的格式和我们之前在代码 8-3 中所得结果的格式完全一致,因此我们可以使用相同的方法来显示 sln 中的轮廓(如图 8.19)。

在 Execute 函数中,我们设置的偏置距离为-7,负号表示对逆时针轮廓向内偏置,对顺时针轮廓向外偏置;如果偏置距离为正,则对逆时针轮廓执行向外偏置,顺时针轮廓执行向内偏置。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_179_0.png)

图 8.19 Clipper 偏置对回形轮廓偏置示例

在实际使用 PyClipperOffset 类时,我们必须十分注意输入轮廓的方向。在我们还能认清各个轮廓的方向时,保证外轮廓方向为逆时针,内轮廓方向为顺时针。如果我们不能保证上述方向,至少保证逻辑上表示区域内、外边界的轮廓方向相反,否则我们将得不到正确的偏置结果。这是因为 Clipper 库的偏置源代码中,Clipper 会判断最外层的轮廓方向,如果最外层轮廓是逆时针,则不调整其他轮廓方向;如果最外层轮廓是顺时针,则会对所有轮廓进行取反处理。

## 8.4 Clipper 适配器构建

在上一节中，我们主要介绍了 Clipper 库和基于 Clipper 库的布尔偏置方法，这种偏置方法执行效率高，可以非常稳定地帮助我们生成平面轮廓的偏置曲线，有了它，我们可以暂时放弃自力更生地去实现一种偏置算法的念想。尽管如此，我们还是无法直接使用 Clipper 库中的布尔偏置工具来生成我们需要的轮廓平行填充路径。我们还需要解决 Clipper 库在实际应用中的两个关键问题，一是数值运算的精度问题，二是轮廓类型转化问题。

我们先来看一下数值运算的精度问题。在 Clipper 库中，Path( Clipper 库内置的多段线类型)顶点的坐标数据类型为整型，所有的运算都是基于整数的运算，如加、减、乘、除、平方、开方等。这样设计的好处是可以提高 Clipper 库在运算时的数值稳定性，缺点是它无法精确地处理那些看起来很小的数。这是什么意思呢？

让我们假设这个世界上存在一个只能处理整数除法的小盒子，它的输入为除法等式中的被除数，输出为商，除数位于小盒子中，且除数、被除数、商均为整数，如图 8.20 所示。我们不妨假设此时小盒子中的除数为 6。现在我们输入被除数 7,7 除以 6 等于 1，显然此时输出的商为 1,这和真实结果 1.166···还有 0.166···的绝对误差。这在实际应用中是绝对无法让人接受的！那么我们怎样能够让小盒子变得有用呢？很简单，我们可以尝试将输入扩大 1000 倍，这样，我们得到的输出将为 1166,然后我们再在外部能够执行浮点数除法的地方对输出的 1166 除以 1000,这样我们将得到 1.166 的结果,这样的结果已经非常接近 7 除以 6 的真实值了。如果我们对结果的精度还有更高的要求，比如我们希望保留小数点后 7 位,那么我们只需对小盒子的输入乘以 10^7,最后对小盒子的输出除以 10^7,我们就能得到具有 7 位小数的结果。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_180_0.png)

图 8.20 只能处理整数除法的盒子

对 Clipper 库的输入和输出,我们完全可以进行类似的操作,即先对输入数值放大 10^N 倍(N 为大于 0 的整数),然后对输出数值缩小 10^N 倍,这样我们就能够让 Clipper 处理那些看起来比较小的数,且最终得到的结果能够保留 N 位小数。

接下来我们再来看一下轮廓类型的转化问题。如前所述,Clipper 库中多段线的类型为 Path,它实质上是一个由二维整数元组组成的列表;而我们自己创建的多段线类型为 Polyline,且将之前 STL 模型截交、线段拼接得到的轮廓全部以 Polyline 的形式保存。如果我们要对 Polyline 对象使用 Clipper 库中的偏置算法进行偏置,我们需要将 Polyline 对象转化为 Clipper 库自带的 Path 对象。

为了使 Clipper 库能够更加贴合实际应用，我们专门设计并实现了一个 Clipper 库的适配器类，方便我们将外部数据类型转为 Clipper 内置数据类型，同时解决数值运算精度的问题。其实我们在第 3 章已经做过类似的事情，实现了一个 VTK 的适配器类 VtkAdaptor，这个类已贯穿应用在后续章节中。事实上，这些适配器类就是对原生库的一层以简化应用为目的的封装。这里，我们把 Clipper 库的适配器类封装在 ClipperAdaptor.py 文件中，类名同为 ClipperAdaptor，它的具体实现代码如下：
