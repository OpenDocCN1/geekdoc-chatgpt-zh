平面多边形序列。当然在这过程中，我们使用了 ClipperAdaptor 类来转化多边形数据。需要说明的是，在调用 pointToRect 函数时，我们并没有按照上文推导的数据（即 a_x, a_y）去设置矩形边长，而是对 lx 和 ly 参数同时设置了 1.1 倍的 gridSize 值。这是因为 a_x 和 a_y 本身根据 gridSize 值圆整而来，且有 a_x ≤ gridSize, a_y ≤ gridSize，使用较大的矩形来替换较小矩形可以增加相邻矩形间的重叠面积，降低 Clipper 库在布尔并计算中出错的可能性。

在 genRawSptRegions 函数命名时，我们有意为其添加了一个“raw”标识，表明这个函数仍然是一个中间函数，它得到的平面支撑区域仍然是初始数据，需要进一步处理，而不是最终结果。这是为什么呢？如果我们单独从支撑生成的角度考虑，可能很难发现问题所在。但如果把我们在前几章得到的针对三维模型的切片轮廓和现在得到的支撑轮廓放在同一截平面上，也许我们就会发现问题。如图 10.17(a) 所示，因为我们使用了支撑点影响范围的矩形假设，过分自信地将每个支撑点的影响范围都等效放大小一致的矩形，导致最终融合得到的支撑区域侵占了模型区域，即导致切平面上模型轮廓和支撑轮廓相交。如果允许这种情况发生，打印时支撑材料将和模型材料混叠，增加打印后支撑从模型上剥离的难度。因此，我们应该在生成支撑区域时避免这种情况发生。

那么如何避免模型轮廓和支撑轮廓相交呢？我们知道，模型轮廓来自对三维模型的切片，是精确且真实存在的轮廓，不容更改，否则打印得到的工件将无法匹配设计模型，从而失去打印本身的意义。而支撑轮廓是根据切片支撑点生成的虚拟轮廓，它的存在依赖于我们做出的一些假设，如支撑点影响范围的矩形假设，显然这些假设是不具备几何精度的。基于以上分析，我们应该对平面上的支撑区域轮廓进行修正，使其避开模型轮廓。

那又如何修正支撑轮廓呢？这个问题看似无从下手，因为我们似乎很难制定轮廓修正策略；但是如果结合布尔运算，如图 10.17(a)，我们只需首先让模型区域和支撑区域求交，就能得到重叠区域，然后再让支撑区域减去重叠区域，就能得到一个新支撑区域（这样写是为了便于理解，上述过程等价于支撑区域减去模型区域），此时新支撑区域的部分边界恰好和模型区域的部分边界重合，但两区域已经不再相交。实际上，考虑到打印工艺需求，避免支撑材料和模型材料过度粘连，方便打印完成后支撑剥离，我们应该在模型轮廓和修正后的新支撑轮廓之间预留一定的间隙。因为这个间隙是 XY 平面上轮廓间的间隙，因此我们称其为 xyGap，显然，这个间隙可用偏置的方法实现。我们不妨回头看看 Find-
