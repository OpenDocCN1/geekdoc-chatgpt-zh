函数，这里 ca 的作用就是对两种不同格式的多段线进行相互转换。随后我们进入裁剪操作主体代码，包括创建 Clipper 对象 clipper，向 clipper 分别添加裁剪窗口多边形（即输入的 polygons，PT_CLIP）和待裁剪的平行线段（PT_SUBJECT），最后调用 Clipper 库的 Execute2 函数进行求交操作（CT_INTERSECTION）以获得位于裁剪窗口内部的填充线段。

需要说明的是，面向 Python 的 Clipper 库包含两个版本的裁剪执行函数，一个是 Execute，另一个是 Execute2，这两个函数的功能相似，主要区别在于对输出结果的组织。前者输出的是表示裁剪结果多边形（多段线）的线性列表，而后者输出的是带有父子节点结构的裁剪结果。对这里需要处理的开放线段裁剪问题，我们必须调用 Execute2 函数，否则我们将无法得到裁剪结果。有意向对 Execute2 函数实现细节或返回结果的数据结构进一步了解的读者，可再去查看 Clipper 库的相关文档。

回到代码 9-6，在得到 Execute2 的结果 sln 后，我们需要从中将裁剪得到的线段提取出来，方法是遍历 sln 的子节点（Childs）。每个子节点包含一个 Path 类型的轮廓（Contour），这些轮廓就是我们要求的填充线段。我们需要做的就是将 sln 的子节点轮廓转化为 Polyline 对象，然后再将 Polyline 对象转化为 Segment 对象并保存到填充线段列表中。至此，我们实现了 clipHatches 的后半部分代码，即通过 Clipper 库裁剪得到了一系列填充线段。

但是，我们对这些填充线段在平面上的分布情况是完全陌生的。它们中第一条线段在哪里？第二条线段是否与之相邻？它们是否遵循我们之前生成的平行线段的序号？这些问题都等着我们去回答。

# 9.2.3 填充线排布探索

这一小节我们再来看一下 genClipHatches 函数返回的填充线段在平面上的排列顺序。这对后续平行路径连接至关重要。我们知道，使用扫描线法生成的填充线在平面上的分布情况是完全可控的，也就是说，我们可以根据其生成原理事先预测填充线的排列顺序。但是，在使用 Clipper 库生成填充线时，由于我们不了解 Clipper 内部的裁剪机理，因此最终得到的填充线在平面上的分布情况对我们来说是未知的。如果我们不去探索求证，在最坏的情况下，我们完全有理由假设这些填充线在平面上是随机散乱分布的。
