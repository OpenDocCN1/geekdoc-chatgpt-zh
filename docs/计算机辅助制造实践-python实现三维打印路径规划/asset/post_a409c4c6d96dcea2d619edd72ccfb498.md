
在以上 ClipperAdaptor 类中，初始化函数中的参数 digits 用于指定 Clipper 库的数值运算精度，即输出结果保留的小数位数，其原理我们已在上面有所介绍，默认情况下，该适配器类的数值精度为小数点后保留 7 位有效数字。属性 arcTolerance 用于指定劣角顶点偏置圆弧衔接中的圆弧离散精度。在 Clipper 库中，arcTolerance 就是离散得到的弦的弓高误差，弓高误差是指弦到真实圆弧的最大距离值，如图 8.21 所示，显然，弓高误差越小，弦就越接近真实圆弧，即用弦代替圆弧的精度就越高，但最终得到的弦的总数就越大。在图 8.21 中，我们甚至可以得出弓高误差和弦长的关系。在 Clipper 库的官方文档中，也有一个表示圆弧精度的变量，且它的默认值为 0.25 个单位，这是相对于 Clipper 中的整型数据来说的。这里我们设置 arcTolerance 的默认值为 0.005 毫米，在具体使用时，我们也要考虑对该值进行放大处理。

在 ClipperAdaptor 类中，我们封装了 2 组在形式上十分相似的多段线转化函数，即我们自己的 Polyline 和 Clipper 内置 Path 的相互转化函数，它们分别是 toPath/toPaths 和 toPoly/toPolys，其中带‘s’的函数表示转化的多段线为复数形式。需要说明的是，因为 Path 为二维平面多段线，而 Polyline 为三维多段线，因此在将 Polyline 对象转化为 Path 对象时，Polyline 对象的 z 坐标信息将全部丢失；而当我们需要将由 Clipper 库运算返回的 Path 对象转化为 Polyline 对象时，需要从外部额外输入 z 坐标信息，这也是以上 toPoly/toPolys 函数带 z 参数的原因，默认情况下，z 值为 0。此外，Polyline 和 Path 对多段线是否封闭的定义不太一致：对 Polyline 对象，如果它是封闭的，那么它的首尾两个顶点重合；而对 Path 对象，即便它是封闭的，它的首尾两个顶点也不会重合，我们只能从相关代码的上下文语境理解 Path 对象是否封闭。因此，对 Clipper 库运算返回的 Path 对象，当我们把 Path 转化为 Polyline 时，我们需要从外部指定多段线是否重合，这正是以上 toPoly/toPolys 函数带 closed 参数的原因，默认情况下，closed 值为 True，即默认 Clipper 库返回的多段线是封闭的。

最后，在 ClipperAdaptor 类中，我们定义了一个 offset 函数，这个函数的功能就是对封闭轮廓执行偏置操作。它的输入为 Polyline 对象的列表 polys、偏置距离 delta 以及劣角顶点衔接方式，其中对参数 delta，当需对输入轮廓执行向内偏置时，delta 为负，反之 delta 为正；该函数的输出也是 Polyline 对象的列表，表示生成的偏置轮廓。由以上 offset 函数的实现代码可知，它基本上就是对 Clipper 库中自带 PyclipperOffset 类的进一步封装。在封装时，有一点需要注意的是，我们必须对作用于 PyclipperOffset 类的圆弧精度和偏置距离都乘以指定的放大系数，否则我们将无法得到正确的偏置结果。

## 8.5 轮廓路径生成与连接

根据之前介绍可知,轮廓平行填充路径就是对表示打印区域的边界轮廓连续偏置若干次后连接得到的路径,因此我们在这一节需要完成两个任务,一是根据三维打印的工艺特点生成连续偏置曲线,二是连接这些偏置曲线,得到一条(或若干条)可以遍历这些偏置曲线的打印路径。

### 8.5.1 连续偏置曲线生成

对某一指定层高上表示打印区域边界的一组轮廓,为了保证工件能够获得较高的表面质量,根据三维打印工艺需求,我们需要对这组轮廓连续向内偏置一定次数,以生成能够覆盖打印区域边缘的具有均匀厚度的填充带。以 FDM 工艺为例,如果设填充带厚度为 W,打印机喷头直径为 Ω,那么我们大致需要对边界轮廓连续偏置 W/Ω 次(取整)。在这一过程中,我们需要关注并解决以下几个问题。

首先是连续偏置中每次偏置距离的取值问题。根据以上设定,打印机喷头直径为 Ω,即每次从喷头挤出的热熔丝材的宽度为 Ω,如图 8.22 所示,为了保证打印模型在尺寸上恰好等于设计模型,不至于放大或缩小,首次偏置距离应设置为 Ω/2,即喷头半径尺寸。随后,为了实现相邻偏置路径之间的无缝填充,其他偏置距离应设置为 Ω。理论上,第 1 次填充后,填充带宽度为 Ω;第 n 次填充后,填充带宽度为 nΩ。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_183_0.png)

图 8.22 工艺限制下的连续偏置距离取值

其次,在连续偏置过程中,我们需要合理选择偏置主体。原则上,为了确保喷头沿着相邻偏置路径填充后丝材边缘恰好靠在一起,不至于重叠或留下缝隙,我们应该基于当前偏置曲线生成下一条偏置曲线,即图 8.22 中 b1 曲线基于打印区域边界轮廓(b0)偏置 Ω/2 生成,b2 曲线基于 b1 曲线偏置 Ω 生成,b3 曲线基于 b2 曲线偏置 Ω 生成,以此类推,bk 曲线基于 b_{k-1} 曲线偏置 Ω 生成。需要说明的是,以上 b_i (i 为非负整数)曲线可能由一条或多条曲线组成,b_i 称为第 i 级偏置曲线,它是由第 i 级偏置得到的偏置曲线。但是,采用这种连续偏置策略可能存在以下两个缺陷：

一是偏置顶点数量的无谓递增。如图 8.23 所示，对于 b0 轮廓上的劣角顶点，在偏置过程中如果我们采用矩形衔接(Square)的方式，那么在 b1 曲线的对应位置上将生成 2 个劣角顶点；在对 b1 进一步偏置得到的 b2 曲线上，在相应位置上将生成 4 个劣角顶点……以此类推，在对劣角顶点的连续偏置过程中，在局部区域，偏置曲线顶点数量相对于上一条曲线会成倍增加，而这种顶点数量的增加对偏置轮廓精度的提升是没有意义的，反而会增加后续运算时间。如果采用圆弧衔接(Round)的方式，那么偏置曲线上劣角顶点的数量将会呈爆炸式增长。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_184_0.png)

图 8.23 连续偏置中劣角顶点数量快速增长

二是偏置轮廓精度的下降。这点是我们在实践过程中发现的，尽管 Clipper 布尔偏置算法很强大，但它还是无法生成完美的偏置曲线。在由 Clipper 生成的偏置曲线上，可能保留了一些轮廓裁剪的印记，导致偏置曲线在局部区域的微小扰动(如局部微小尖角)。但从几何上考虑，这种扰动本身在当前偏置曲线上不会造成什么影响，但是在对当前偏置曲线的连续偏置过程中，这种扰动就可能会被逐渐放大，直至影响偏置轮廓精度。当然我们可以在扰动首次产生时对轮廓进行修复，但对扰动的识别和消除并不那么容易。

为了弥补以上两个缺陷，这里我们选择以边界轮廓为主体，对其进行多次偏置以生成连续偏置曲线。即在图 8.22 中，每次偏置都是以 b0 为原始曲线，如 b1 曲线是对 b0 曲线偏置 Ω/2 距离得到的偏置曲线，b2 曲线是对 b0 曲线偏置 3Ω/2 距离得到的偏置曲线……以此类推，bk 曲线是对 b0 曲线偏置(2k-1) Ω/2 距离得到的偏置曲线。采用这种连续偏置策略其实是一种妥协，它的缺陷是所有偏置曲线只跟随边界轮廓 b0 的形状，相邻偏置线之间形状关联性较小，这样，当喷头沿着相邻偏置线打印后，可能在部分区域留下相互重叠或存在缝隙的丝材。

最后，我们需要确定轮廓上劣角顶点在偏置过程中的衔接问题。根据我们在上一节的介绍，Clipper 库提供了 3 种劣内角衔接方式，如图 8.16，它们分别是：圆弧衔接、矩形衔接和斜角衔接。其中圆弧衔接得到的偏置轮廓精度最高，矩形衔接精度次之，斜角衔接精度最差；但圆弧衔接得到的偏置曲线顶点数最多，矩形和斜角衔接顶点数次之。这 3 种衔接方式各有优缺点，很难取舍，特别是圆弧衔接和矩形衔接两种方式，为了保证路径生成的灵活性，我们在生成偏置路径时，将这 3 种方式都作为可选衔接方式。但默认情况下，我们推荐使用矩形衔接方式。

解决了以上几个问题后，接下来我们将应用 ClipperAdaptor 类生成指定打印区域边界轮廓的连续偏置曲线。我们把这部分功能封装在 GenCpPath 类中( 对应 GenCpPath.py 文件)，类名为 generate contour – parallel toolpath 的缩写，意思是生成轮廓平行路径。GenCpPath 类中连续偏置曲线生成部分的实现代码如下：

我们来看一下以上代码。在 GenCpPath 类的初始化函数中，我们输入的是表示打印区域的边界轮廓 boundaries、偏置距离 interval 和填充带宽 shellThk 三个参数，其中偏置距离就是喷头直径，填充带宽类似于打印后模型的表皮或外壳厚度，这两个参数是和三维打印工艺直接相关的参数，即工艺参数。除此之外，在 GenCpPath 类中，我们还定义了圆弧精度和劣角顶点衔接类型两个工艺参数，默认情况下，圆弧精度为 0.005 毫米，劣角顶点采用矩形方式衔接。事实上，我们在 ClipperAdaptor 类中已经定义过两个同名参数( 属性 )，尽管它们的默认值一致，但在类中定义这两个参数单纯是出于几何上的考虑，而在 GenCpPath 类中定义这两个参数是出于工艺上的考虑，两者的层次不同。

我们在 GenCpPath 类中定义了两个函数，Offset 和 LinkLocalOffsets，分别用于连续偏置路径的生成和连接，但在这一小节我们只实现了 Offset 函数，LinkLocalOffsets 函数将在下一小节实现。在 offset 函数中，我们首先定义了一个 ClipperAdaptor 类的对象 ca，随后设置了 ca 的圆弧精度为指定值，这一步操作事实上仅当劣角顶点衔接类型为圆弧衔接时才有效。然后我们在一个循环中反复调用 ClipperAdaptor 类的 Offset 方法生成输入轮廓的连续偏置曲线。这个循环有两个退出条件:一是当前偏置距离大于指定的填充带宽,偏置过程自然停止;二是最后生成的偏置曲线已到偏置收敛的区域中心,返回空的偏置结果。第二种情况发生的原因是填充带宽设置过大或打印区域过小,生成的偏置曲线已填充整个打印区域。

我们将以上 Offset 函数连续偏置得到的偏置曲线存放在临时变量 OffsetPolyses 中,注意,这是一个存储 Polyline 对象的二维列表,其中第一个维度表示偏置级数,第二个维度表示当前偏置级上的曲线序号。对得到的 OffsetPolyses,我们的最终目标是将其中的每条偏置曲线串连成一体,以生成轮廓平行填充路径,而且为了保证实际打印效率,用于连接连续偏置曲线的路径长度越短越好。为了达成这一目标,我们必须首先找出 offsetPolyses 中各条曲线的包含关系。

### 8.5.2 曲线包含关系确定

在上一小节,针对输入的表示打印区域的边界轮廓 b0,我们已经能够生成它的连续偏置曲线 b1,b2等,而且将这些曲线存放于 GenCpPath 类的二维列表属性 OffsetPolyses 中。我们在这一小节的任务是确定 OffsetPolyses 中各条偏置曲线的层次包含关系,以便后面能够对它们进行连接,生成较短的轮廓平行填充路径。事实上,我们在本书 4.5 节已经处理过类似的问题,只不过在第 4 章,我们的主要目的是确定多边形方向。注意,这里 b0(b1,b2等类似)本身是一个复数的概念,它可以表示一条或多条曲线,即一个打印区域可能由多条外轮廓曲线(逆时针)和多条内轮廓曲线(顺时针)围成。

我们不妨先来分析下,当 b0 仅有外轮廓曲线的情况,如图 8.22 所示。在这种情况下,OffsetPolyses 中各曲线包含关系的确定相对简单。我们知道,OffsetPolyses 的第一个维度表示偏置级数,根据连续偏置的原理,第 1 级偏置曲线必然包含第 2 级偏置曲线,第 2 级偏置曲线必然包含第 3 级偏置曲线……以此类推,第 i 级偏置曲线必然包含第 i+1 级偏置曲线,即 OffsetPolyses[i+1]中各条曲线的直系父曲线必然在 OffsetPolyses[i]中,而 OffsetPolyses[i]中各条曲线的直系子曲线也必然在 OffsetPolyses[i+1]中。

注意,一条曲线可能被多条曲线所包含(即在多条曲线内部),它的直系父曲线是指包含它的曲线中距它最近的那条曲线,而它本身可称为父曲线的直系子曲线。根据这一定义,一条曲线至多有 1 条直系父曲线,但可能有 0 条、1 条或多条直系子曲线。而且,就像人类社会一样,父子曲线的关系是相对变化的,某一对父子关系中的直系子曲线可能是另一对父子关系中的直系父曲线;同理,某一父曲线可能是另一曲线的直系子曲线。通过构建父子曲线的关系图谱,理论上,我们可以通过其中一条曲线索引到整个关系网中的所有曲线,见图 4.9。

根据之前的讨论,对 OffsetPolyses[i+1] 中的任意一条曲线 c,它的直系父曲线必然在 OffsetPolyses[i]中,如果它在 OffsetPolyses[i]中某条曲线 p 的内部,那么 p 就是 c 的直系父曲线,c 就是 p 的直系子曲线。那我们又该如何判断一条曲线在另一条曲线的内部呢? 其实我们在第 4 章中已经处理过类似的问题。考虑到 OffsetPolyses 中所有曲线不存在相交的情况,因此,任意曲线 A 是否在另一曲线 B 内部的问题等价于曲线 A 上的任意一点(如起点)是否在曲线 B 内部,而判断一点是否在曲线内部的问题我们早已解决(参见GeomAlgo 中封装的 PointInPolygon 函数）。综上,当 OffsetPolyses 中只有外轮廓曲线时,我们可以遍历其中每条曲线,在它的上一级偏置曲线中寻找直系父曲线,从而构建曲线之间的父子关系。当然,在表示曲线父子关系时需要相应数据结构的支撑。

刚才我们讨论的是打印区域边界 b0 只包含外轮廓的情况,但这只是一种特例,更普遍的情况是 b0 中既有外轮廓,又有内轮廓,如图 8.24。在增加了内轮廓的偏置曲线之后,以上我们所说的 OffsetPolyses[i+1] 中各曲线的直系父曲线在 OffsetPolyses[i] 中就不一定成立了。对包含内、外轮廓的偏置曲线来说,情况变得混乱,如图 8.24 所示:曲线 c1 和 c2 同属第 2 级偏置曲线 b2,但事实上,c1 位于 c2 内部,即 c2 是 c1 的直系父曲线;曲线 c3 属于第 3 级偏置曲线 b3,但 c1 和 c3 同为 c2 直系子曲线。而且对于 OffsetPolyses 中的曲线,我们很难推断它是外轮廓还是内轮廓的偏置曲线。在这种情况下,相对来说,确定 OffsetPolyses 中各条曲线之间包含关系就比较繁琐了,因为我们已经无法再利用 OffsetPolyses 的数据结构特点。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_187_0.png)

既然如此,我们不妨尝试去探索并解决一个更为一般性的命题:对输入的平面封闭曲线序列 polys,已知所有曲线间不存在相交的情况,确定各曲线之间的包含关系。如果能够解决这个问题,那么我们自然而然能找出 offsetPolyses 中各条曲线的包含关系。

我们先来看一下使用暴力算法解决这个命题的基本思路。如上所述,对任意两条曲线,我们已经知道了如何去判断一条曲线是否在另一条曲线内部的方法。对输入曲线序列 polys 中的任意一条曲线 c,我们可以从 polys 中找出包含它的所有曲线,并把这些曲线放在一个临时列表变量中(记为 parents),显然,parents 中的所有曲线都是曲线 c 的潜在直系父曲线。根据直系父曲线的定义,我们只需从 parents 中找出距离曲线 c 最近的那条曲线(记为 p),曲线 p 即为曲线 c 的直系父曲线;反过来,曲线 c 即为曲线 p 的其中一条直系子曲线。同理,对 polys 中的其他曲线,我们也可以按照以上方法找出它的直系父曲线,从而构建所有曲线之间的父子关系。我们之所以称这种方法为暴力方法,是因为它的时间复杂度为 O(n^2),其中 n 为 polys 中的曲线数量,我们需要进行 n^2 次的 pointInPolygon 运算和 n^2 次的曲线之间最近距离计算,而这些运算都是相对比较耗时的。
