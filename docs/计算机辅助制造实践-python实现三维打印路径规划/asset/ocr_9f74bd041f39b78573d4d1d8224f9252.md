# 8.4 Clipper 适配器构建

在上一节中，我们主要介绍了 Clipper 库和基于 Clipper 库的布尔偏置方法，这种偏置方法执行效率高，可以非常稳定地帮助我们生成平面轮廓的偏置曲线，有了它，我们可以暂时放弃自力更生地去实现一种偏置算法的念想。尽管如此，我们还是无法直接使用 Clipper 库中的布尔偏置工具来生成我们需要的轮廓平行填充路径。我们还需要解决 Clipper 库在实际应用中的两个关键问题，一是数值运算的精度问题，二是轮廓类型转化问题。

我们先来看一下数值运算的精度问题。在 Clipper 库中，Path( Clipper 库内置的多段线类型)顶点的坐标数据类型为整型，所有的运算都是基于整数的运算，如加、减、乘、除、平方、开方等。这样设计的好处是可以提高 Clipper 库在运算时的数值稳定性，缺点是它无法精确地处理那些看起来很小的数。这是什么意思呢？

让我们假设这个世界上存在一个只能处理整数除法的小盒子，它的输入为除法等式中的被除数，输出为商，除数位于小盒子中，且除数、被除数、商均为整数，如图 8.20 所示。我们不妨假设此时小盒子中的除数为 6。现在我们输入被除数 7,7 除以 6 等于 1，显然此时输出的商为 1,这和真实结果 1.166···还有 0.166···的绝对误差。这在实际应用中是绝对无法让人接受的！那么我们怎样能够让小盒子变得有用呢？很简单，我们可以尝试将输入扩大 1000 倍，这样，我们得到的输出将为 1166,然后我们再在外部能够执行浮点数除法的地方对输出的 1166 除以 1000,这样我们将得到 1.166 的结果,这样的结果已经非常接近 7 除以 6 的真实值了。如果我们对结果的精度还有更高的要求，比如我们希望保留小数点后 7 位,那么我们只需对小盒子的输入乘以 10^7,最后对小盒子的输出除以 10^7,我们就能得到具有 7 位小数的结果。

图 8.20 只能处理整数除法的盒子

对 Clipper 库的输入和输出,我们完全可以进行类似的操作,即先对输入数值放大 10^N 倍(N 为大于 0 的整数),然后对输出数值缩小 10^N 倍,这样我们就能够让 Clipper 处理那些看起来比较小的数,且最终得到的结果能够保留 N 位小数。

接下来我们再来看一下轮廓类型的转化问题。如前所述,Clipper 库中多段线的类型为 Path,它实质上是一个由二维整数元组组成的列表;而我们自己创建的多段线类型为 Polyline,且将之前 STL 模型截交、线段拼接得到的轮廓全部以 Polyline 的形式保存。如果我们要对 Polyline 对象使用 Clipper 库中的偏置算法进行偏置,我们需要将 Polyline 对象转化为 Clipper 库自带的 Path 对象。
