
intersect 函数中，我们又重新创造了一遍轮子。在 GeomAlgo 模块中，我们已经实现了一个更为通用的线段和平面的求交函数 intersectSegmentPlane，我们当然可以直接在 TEdge 的 intersect 函数中调用这个通用求交函数，就像下面的 intersect_v1 函数一样：

| TopoSlicer.py | TEdge 类中的 intersect_v1 函数定义，直接调用 intersectSegmentPlane 函数 | 7-3 |
|---|---|---|
| 1 | class TEdge: | |
| 2 | ...... | |
| 3 | def intersect_v1( self, z ): | # 定义 intersect_v1, 返回交点 |
| 4 | seg = Segment( self.A.toPoint3D(), self.B.toPoint3D() ) | # 线段构造 |
| 5 | pln = Plane.zPlane( z ) | # 截平面构造 |
| 6 | return intersectSegmentPlane( seg, pln ) | # 返回截交点 |

但出于通用性考虑，intersectSegmentPlane 函数并没有进行任何预处理，因此 intersect_v1 函数的执行效率不会太高。

对于截平面是 Z 平面这一特殊情况，我们通过非常简单的预处理就可以排除一些显然不相交的情形，这样可以显著提高相交计算效率，如半边的最低点高于截平面、或最高点低于截平面、或半边落在截平面上。在 TEdge 类 intersect 函数的前半部分中，我们正是这么处理的。如果半边确实和 Z 平面相交，那么交点的 z 坐标值必然为 z，如图 7.5 所示，而半边两端点的坐标是已知量，因此我们可以根据交点和半边端点在 z 方向的比值快速确定交点坐标。相比于 intersect_v1 函数，intersect 的相交计算效率更高，在我们的实例测试中，后者的执行效率要比前者高 30% 以上。有些时候，如果再去实现一遍对我们来说难度不太大，那么尝试再去实现一遍也并非是完全错误的抉择。

## 7.2.3 面片拓扑结构

最后，我们来看一下三角面片和顶点以及棱边（半边）的拓扑关系。在建立了顶点和半边的拓扑结构之后，建立面片的拓扑结构就变得相对简单。如图 7.6 所示，首先，一个面片必然包含 3 个顶点，因此，在一个面片中，必须保存 3 个顶点的引用。其次，一个面片必然也包含 3 条半边，且每条半边都是当前面片独有的，因此，在一个面片中，也必须保存 3 条半边的引用。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_139_0.png)

图 7.6 面片拓扑结构

根据以上分析，我们可以马上建立一个拓扑面片类，用于保存面片和顶点以及半边的几何拓扑关系，我们把这个类命名为 TFace，并且把它写在 TopoSlicer.py 文件中。TFace 的具体实现代码如下：

```
TopoSlicer.py | TFace 类定义，它表示具有拓扑关系面片 | 7-4
1 ......
2 class TFace():
3     def __init__(self, tA, tB, tC, te1, te2, te3):
4         self.A, self.B, self.C = tA, tB, tC
5         self.E1, self.E2, self.E3 = te1, te2, te3
6         self.used = False
7     def zMin(self): return min(self.A.z, self.B.z, self.C.z)
8     def zMax(self): return max(self.A.z, self.B.z, self.C.z)
9     def intersect(self, z):
10        if self.zMin() > z or self.zMax() < z:
11            return None, None, None
12        elif self.A.z == self.B.z == self.C.z == z:
13            return None, None, None
14        else:
15            c1 = self.E1.intersect(z)
16            c2 = self.E2.intersect(z)
17            c3 = self.E3.intersect(z)
18            if c1 is None:
19                if c2 is not None and c3 is not None:
20                    if c2.distance(c3) != 0.0:
21                        return Segment(c2, c3), [ self.E2, self.E3 ], None
22            elif c2 is None:
23                if c1 is not None and c3 is not None:
24                    if c1.distance(c3) != 0.0:    # 返回线段，半边 E1、E3
25                        return Segment(c1, c3), [self.E1, self.E3], None
26
27            elif c3 is None:
28                if c1 is not None and c2 is not None:
29                    if c1.distance(c2) != 0.0:    # 返回线段，半边 E1、E2
30                        return Segment(c1, c2), [self.E1, self.E2], None
31
32            elif c1 is not None and c2 is not None and c3 is not None:
33                if c1.isIdentical(c2):
34                    return Segment(c1, c3), [self.E3], self.B    # 返回线段，半边 E3、顶点 B
35                elif c2.isIdentical(c3):
36                    return Segment(c1, c2), [self.E1], self.C    # 返回线段，半边 E1、顶点 C
37                elif c3.isIdentical(c1):
38                    return Segment(c1, c2), [self.E2], self.A    # 返回线段，半边 E2、顶点 A
39
40            return None, None, None
```

在以上代码中，我们为 TFace 类设置了 7 个属性，它们分别是 A、B、C、E1、E2、E3 以及 used。其中 A、B、C 为面片的顶点引用，它们并非单独属于某个面片，而是同时由某几个面片共享；E1、E2、E3 分别为面片的半边引用，在半边初始化时，我们规定 E1 为由顶点 A、B 构成的半边，E2 是由顶点 B、C 构成的半边，E3 是由顶点 C、A 构成的半边，这一规定非常重要，必须遵照执行，否则当我们反过来从半边去寻找顶点时，将无从下手。属性 used 的作用是表示当前面片是否已经被使用过，该属性将在后面截交计算时用到。

在 TFace 类中，函数 zMin 和 zMax 分别用于获取面片 3 个顶点在 Z 方向上极小值和极大值，这两个函数和我们之前在 Triangle 类中实现的 zMinPnt 和 zMaxPnt 两个函数具有相似的功能，不过这里的两个函数更为简洁、直接。除了以上两个函数外，在 TFace 类中，我们还实现了一个较为复杂的 intersect 函数，这个函数的功能是计算当前三角面片和截平面的交线，它也是切片轮廓计算的核心基础函数。它的实现原理和我们之前在 GeomAlgo 模块中实现的 intersectTrianglePlane 函数完全一样，它们的代码在形式上也十分相似。那为什么我们在这里要再去实现一通呢？

我们认真观察就会发现，TFace 类中的 intersect 函数和 GeomAlgo 模块中的 intersectTrianglePlane 函数的返回类型是不一样的。后者的返回是 Segment 类型的截交线段或 None，其中 None 表示三角面片和截平面不相交。而前者的返回相对复杂，包括三个部分，第一部分为 Segment 类型的线段(或 None)，第二部分和第三部分为交线两个端点所在的三角面片的半边或顶点引用。如果交线的两个端点都在三角面片的半边上，则在第二部分返回两条半边的引用；如果交线的两个端点分别在三角面片的一条半边和一个顶点上，则在第二部分返回半边的引用，第三部分返回顶点的引用。如果面片和截平面不相交或只交于一点，则返回的三部分均为 None。

根据以上分析，我们发现，即便是我们之前实现过了 intersectTrianglePlane 函数，但由于它的返回数据不够细致，不符合我们的要求，因此不能直接在 TFace 的 intersect 函数中调用它，我们不得不从底层开始重新实现三角面片和截平面的求交功能，于是就又“造了一遍轮子”。当然，在 TFace 的 intersect 函数中，为了尽量提高求交效率，我们进行了一些简单的预处理，如果三角面片的最低点低于或最高点高于截平面，或者三角面片和截平面重合，则直接判断它们为不相交。此外，在这个函数中，我们用到了 TEdge 类中的 intersect 函数来求取半边和截平面的交点。

# 7.3 STL 拓扑模型重建

在上一节中，我们分析了顶点、棱边（半边）以及面片之间的几何拓扑关系，并在此基础上分别建立了 TVertex、TEdge、TFace 拓扑数据结构，在这些类中，我们着重封装了一些和截交计算相关的函数。在建立这些类之前，我们做了一个非常重要的假设，我们假设模型中不存在冗余顶点。这个假设和事实显然是不符的，因为在 STL 模型中确实存在大量的冗余顶点，而且借助欧拉定理，我们分析出每个顶点平均被重复保存了 6 次。现在，我们可以利用 TVertex、TEdge、TFace 这 3 类对 STL 模型进行拓扑重建，以消除冗余顶点，建立顶点、面片、半边之间相互关联的几何拓扑关系。拓扑重建的最终目标是从当前任一顶点、半边或面片出发，能够快速索引与之相邻的其他顶点、半边或面片，继而可以迭代索引到整个模型中任意的顶点、半边或面片。

## 7.3.1 冗余顶点消除

对 STL 模型进行拓扑重建的第一步或第一个难点是消除模型中的冗余顶点。对输入的 STL 模型，我们可以从每个独立的三角面片中收集顶点坐标，并把这些顶点全部保存到一个顶点列表（数组）中。根据欧拉定理，我们知道，顶点列表中大概有六分之五的元素冗余，具有相同坐标的顶点被不断重复保存，只有其中六分之一的顶点是我们真正需要的。如果我们将这个问题进一步抽象，那么对它更为普通描述将是：对一个可能保存了相同元素的列表，如何以最快的速度得到它的 unique 列表。这里 unique 列表的意思是列表中的元素各不相同。

解决这个问题一个非常直观的思路就是对列表中的元素进行排序。如图 7.7 所示，排序完成后，在列表中，具有相同值的元素被排在相邻的位置上。此时，我们可以从列表的第一个元素开始，逐个比较相邻元素对的值是否相等，如果相等，则移除其中一个元素，直至列表末尾。按照这个思路，我们可以在 O(nlog(n)) 时间内完成对列表中冗余元素的清理，其中 n 为初始列表中的元素个数，这个时间复杂度主要由排序算法决定的，因为后面元素移除过程相对简单，它的时间复杂度为 O(n)。

对冗余顶点消除问题，同样，我们也可以先对得到的顶点列表进行字典序排序，然后逐个移除列表中相同的相邻顶点，最后得到一个 unique 的顶点列表，这其实并不太难实现。但是在得到这样一个毫无冗余的顶点列表之后，我们要实现的模型拓扑重建问题似乎会变得更加困难，因为以上消除冗余顶点过程会完全打乱顶点顺序，我们很难据此回溯哪个顶点属于哪个面片，哪条棱边。在拓扑重建这样一个背景下，消除冗余顶点的最佳时机应是在我们还能理清一个三角面片内面、边、顶点三者关系的时候，这样我们至少能很快速建立面内半边与顶点、面片与顶点、面片与半边之间的拓扑关系。

| 原始序列 | 3, 2, 3, 5, 4, 2, 4, 1 |
|---|---|
| 排序序列 | 1, 2, 2, 3, 3, 4, 4, 5 |
| 移除相邻相同元素 | 1, 2, ~~2~~, 3, ~~3~~, 4, ~~4~~, 5 |
| unique序列 | 1, 2, 3, 4, 5 |

图 7.7 基于元素排序的冗余元素移除方法

在第 6 章基于字典查询的拼接优化方法中，我们将具有相同坐标位置的链接点（Link-Point）放在了字典结构的同一个键下面，从而实现相邻截交线段的快速拼接。这个过程实现的功能从另一个层面来说其实就是寻找并收集冗余顶点，因此我们完全可以应用这一原理消除冗余顶点。

如图 7.8 所示，我们首先需要一个用于存放顶点的字典对象，我们不妨记这个字典对象为 vxDic，其中前缀 vx 为 vertex（顶点）的缩写。然后，我们要弄清楚字典的键和值。这里我们设置 vxDic 的键为顶点坐标标识，即通过坐标就可以从字典中找到相应的顶点对象（引用）；而 vxDic 中的值为顶点本身，或者更贴切地说，是顶点引用。

| 键: 坐标 | 值: TVertex |
|---|---|
| X₀, Y₀, Z₀ | vertex 0 |
| X₁, Y₁, Z₁ | vertex 1 |
| ... | ... |
| Xₖ, Yₖ, Zₖ | vertex k |

图 7.8 顶点字典 vxDic 键值结构

现在我们有了一个字典对象，接下来我们以 STL 模型中的三角面片为单元消除冗余顶点。对 STL 模型中的任意一个三角面片 ABC，记它的顶点（TVertex 类型）分别为 A、B、C，对应坐标分别为(Xₐ, Yₐ, Zₐ)(Xᵦ, Yᵦ, Zᵦ)(Xᶜ, Yᶜ, Zᶜ)。对顶点 A，首先在字典 vxDic 中查询以 ($x_A$, $y_A$, $z_A$) 为键的坐标是否已经存在：如果不存在，则将 ($x_A$, $y_A$, $z_A$) 和 A 以键值对形式添加至 vxDic；如果 vxDic 中已经存在 ($x_A$, $y_A$, $z_A$) 键，则说明之前有坐标相同为 ($x_A$, $y_A$, $z_A$) 的顶点已经被添加进了字典，此时我们不去执行任何操作，让具有相同坐标的点只在字典中保存一次。对顶点 B 和 C，我们按以上步骤执行相同的操作。

借助字典 vxDic，对 STL 模型中的每个三角面片不断重复上述过程，就可以消除冗余顶点。由于字典查询的时间复杂度为 O(log (n))，因此使用字典消除冗余顶点总的时间复杂度为 O(nlog (n))，其中 n 为 STL 模型总顶点数，包含冗余顶点。

## 7.3.2 拓扑关系建立

下面我们接着考虑建立面内顶点、面片、半边的拓扑关系。还是针对上一小节所述的三角面片 ABC，在执行完字典添加操作后，我们可以从字典 vxDic 中把位于 ($x_A$, $y_A$, $z_A$)、 ($x_B$, $y_B$, $z_B$) ($x_C$, $y_C$, $z_C$) 三点处的值（顶点引用）重新取出来，分别记为 tA、tB、tC。以顶点 tA 为例，注意，在计算机内存中，tA 和 A 可能指向同一块内存地址，也可能指向不同的内存地址，如果它们的地址相同，说明顶点 tA 刚被添加进了字典 vxDic；如果它们的地址不同，则说明 tA 在前面的操作中已被添加进了 vxDic。

根据顶点 tA、tB 和 tC，如图 7.9 所示，我们可以建立当前三角面片的 3 条半边（TEdge 类型），将其分别记为 $e_1$、$e_2$、$e_3$，其中 $e_1$ 的两顶点为 tA 和 tB，$e_2$ 的两顶点为 tB 和 tC，$e_3$ 的两顶点为 tC 和 tA。根据顶点 tA、tB、tC 和半边 $e_1$、$e_2$、$e_3$，我们可以建立当前面片的 TFace 对象，记为 f。有了 f 之后，一方面，我们可以进一步对顶点 tA、tB、tC 的 faces 属性赋值，将 f 分别添加至各顶点的 faces 列表，表示面片 f 被这些顶点共享。另一方面，我们还可进一步对半边 $e_1$、$e_2$、$e_3$ 的 F 属性赋值为 f，表明这些半边是当前面片 f 的半边。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_143_0.png)

图 7.9 面片内部面、边、顶点之间的索引拓扑关系

现在，我们已经建立了一个面片内部关于顶点、边、面的拓扑关系，但这不是 STL 模型拓扑重建的全部，因为这其中缺少了两个成对半边之间的相互索引，如图 7.9 所示。少了这层关系，我们从当前面片查询与之相邻的面片就会比较费劲，我们不得不通过顶点的拓扑关系来筛选，即从顶点的 faces 属性中遍历寻找相邻面片。

对 STL 模型进行拓扑重建的第二个难点在于构建成对半边之间的拓扑关系。在拓扑模型中，大多时候，半边总是成对出现的，它们虽然分享了两个相邻三角面片的公共顶点，却各自属于不同的面片。想要构建成对半边之间的拓扑关系，我们首先得把所有的成对半边找出来。这个问题其实又有点类似于我们在上一小节介绍的冗余顶点的消除问题，不过相对来说，这个问题稍微难一点，因为一条半边有两个顶点，而且这两个顶点是无序的。对任意一条半边，我们可以对它的顶点按字典序排序，然后把较小的点坐标放在前面，较大的点坐标放在后面，共同组成一个 6 维坐标。

我们在定义 TEdge 类的时候已经做好了准备，其中的 toTuple 函数正是为此准备的。对任意两条成对边，如果它们的 6 维坐标一致，那么它们就是一组对边，反之则不是。

| 键: 半边6维坐标 | 值: 列表 [ TEdge ] |
|---|---|
| \(X_0, Y_0, Z_0, U_0, V_0, W_0\) | [ edge 0, edge 1 ] |
| \(X_1, Y_1, Z_1, U_1, V_1, W_1\) | [ edge 2, edge 3 ] |
| ... | ... |
| \(X_k, Y_k, Z_k, U_k, V_k, W_k\) | [ edge p, edge q ] |

图 7.10 半边字典 egDic 键值结构

据上所述，我们需要建立一个半边字典，我们不妨记这个字典为 egDic，其中前缀 eg 为 edge（边）的缩写，字典的键为半边的 6 维坐标，值为半边列表，如图 7.10 所示。大多数情况下，字典的值列表中应包含两个元素，即半边应成对出现，不过也不排除因 STL 模型未封闭或缺陷导致的半边单个出现的情况。

对于 STL 模型中任意三角面片 ABC，在得到它的半边 \(e_1, e_2, e_3\) 之后，我们可以分别检查 \(e_1, e_2, e_3\) 的 6 维坐标是否在 egDic 中。以半边 \(e_1\) 为例说明，如果 \(e_1\) 的 6 维坐标不在 egDic 中，则以 \(e_1\) 的 6 维坐标和包含 \(e_1\) 一个元素的半边列表为键值对加入字典 egDic 中；反之，如果 \(e_1\) 的 6 维坐标已经在 egDic 中，则直接将 \(e_1\) 添加至它的 6 维坐标对应的半边列表中。对半边 \(e_2\) 和 \(e_3\)，我们可以按照相同的方法处理。当我们遍历完 STL 模型中的所有三角面片，对得到的半边字典 egDic，我们可以遍历字典中的每个值，即每个列表，将列表中的 0 号半边的对边（即 TEdge 的 OE 属性）设置为 1 号半边，并将 1 号半边的对边设置为 0 号半边。当然，如果列表中只有一个元素，即一条半边，我们不做任何处理，这表明模型在此处未封闭。
