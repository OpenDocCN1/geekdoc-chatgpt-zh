## 第 9 章 方向平行填充路径生成

### 引言

对每层打印区域，三维打印有两种常用的填充方式，一种是轮廓填充，另一种是平行填充。为了兼顾打印精度和效率，在大多时候，我们会混合使用这两种填充方式，即在打印区域边缘处使用轮廓填充以保证轮廓精度，而在其内部使用平行填充以保证填充效率。在上一章中，我们已经对轮廓路径的生成方法做了详细介绍，其核心是平面曲线的偏置算法。在这一章，对一指定区域，我们的任务是在其内部生成平行路径，其核心是平面区域的平行线填充算法，即用一组具有一定倾斜角度的等距平行线去截交区域边界，计算并统计落在区域内部的有效线段。在此基础上，我们只要合理连接这些线段，就能得到平行路径。首先我们来看一下针对平面区域的通用平行填充线计算方法。

### 9.1 扫描线法填充线生成

对任一给定的可能包含若干外边界(逆时针)和内边界(顺时针)的平面多边形打印区域，如图 9.1 所示，在该区域内生成平行填充线的原理其实非常简单，步骤如下：

- (1) 生成一组指定倾角且能够覆盖整个区域的平行直线序列；
- (2) 遍历其中每条直线，计算当前直线和区域的交点；
- (3) 根据交点在直线上的奇偶顺序提取填充线段并输出。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_202_0.png)

图 9.1 平面区域内平行填充线生成原理

步骤（3）中，在每条直线上，如果交点序号从 0 开始计数，那么从偶数到奇数序号交点连成的线段将落在区域内部，即这些线段是有效的填充线段。

以上步骤的核心是平行线序列和多边形序列的求交计算。如果不计时间成本，直接采用容易实现的暴力方法求交，则直线和线段的总求交次数将达 m · n，其中 m 为平行线序列中的平行线数量，n 为多边形序列包含的总顶点数（或总边数）。考虑到我们可能需要为数以千计的切片层生成平行填充路径，以上暴力法显然不是一个很好的选择。那我们该如何减少求交次数呢？

细心的读者可能已经有所察觉，平行线和多边形的求交问题和我们之前在第 5 章介绍的 STL 模型的截交问题十分相似，而在第 5 章中，我们使用了扫描平面（sweep plane）法来加快截交计算的速度。那么这里我们是否可以仿照扫描平面法的框架，设计并实现一种用于平面平行线和多边形间的快速求交算法？答案是肯定的。但在平面上，扫描平面将退化为一条直线，因此我们称这种算法为扫描线（sweep line）法。

### 9.1.1 扫描线数据结构

使用扫描平面法对 STL 模型进行快速截交包含以下三个要点：一是扫描平面数据结构建立，二是对 STL 模型中的三角面片按照面片最低点的 Z 坐标从小到大进行排序，三是当扫描平面移动时剔除不再与之相交的面片，同时从 STL 模型中添加新的与之相交的面片。扫描平面法的效率非常高，原因在于它采用了排序和增量的方式维护面片数据。

在扫描平面法中，扫描平面始终是一张和空间坐标系 Z 轴垂直的平面，这是因为只有在这种情况下，STL 模型中的各个三角面片相对于扫描平面法向的最低点最容易求取，只需直接比较面片顶点的 Z 坐标即可。如果扫描平面和 Z 轴不垂直，如图 9.2 所示，那我们需要把三角面片各顶点投影到扫描平面的法向上，并在法向上找出顶点投影的最低点。这无疑会增加扫描平面法的实施难度，而且，如果那样，扫描平面法将变得更加难以理解。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_203_0.png)

图 9.2 扫描平面不和 Z 轴垂直的情况

让我们把目光转回到针对平面(指 XY 平面)平行线和多边形的交点计算上来。如上所述，为了降低问题难度，我们不妨首先假设平行线相对于 X 轴的角度为 0，即这些平行线是一系列和 Y 轴垂直的平行线。在这种情况下，一条直线只需用它在 Y 轴上的截距（Y 值）就可以表示，我们称这一截距为该直线的高度，称直线本身为 y 线。现在，我们假设平行线序列中每条平行线的高度已知，这些高度值被保存到一个实数序列 ys 中。序列 ys 可能根据指定的各平行线间距生成，也可能由外部输入，我们暂时不必理会它的来源。

仿照扫描平面法，首先我们需要建立扫描线数据结构。扫描平面的作用是维护和当前高度扫描平面相交的三角面片序列，而在平面上，扫描线的作用是维护和当前高度扫描线相交的线段序列。我们将扫描线类放在一个新建的 GenHatch 模块中，类名为 SweepLine。这里 GenHatch 为 generate hatch 的缩写，意思是生成填充线。熟悉 AutoCAD 的读者可能知道，在该软件中，hatch 命令的作用就是在指定平面区域内生成填充线。SweepLine 类的具体实现代码如下：

```
...... # 导入相关库
class SweepLine: # 定义 SweepLine 类,扫描线
    def __init__(self) :
        self.segs = [] # 属性 segs,Segment 类型列表
    def intersect(self, y) :
        ips = [] # 交点列表
        yLine = Line(Point3D(0, y, self.segs[0].A.z), Vector3D(1, 0, 0)) # 创建 y 线
        for seg in self.segs: # 遍历 segs, 和 y 线求交
            if seg.A.y == y: # 重要:如果 y 线经过线段 A 端点
                ips.append(seg.A.clone()) # 则将 A 端点添加至交点列表
            elif seg.B.y == y: # 同理,如果 y 线经过线段 B 端点
                ips.append(seg.B.clone()) # 则将 B 端点添加至交点列表
            else: # 否则,使用 intersect 函数计算 y
                ip = intersect(yLine, seg) # 线和线段交点,并将交点添加至
                if ip is not None: # 交点列表,ip:intersection point
                    ips.append(ip)
        ips.sort(key=lambda p: p.x) # 对交点按 x 值从小到大排序
        i = len(ips) - 1
        while i > 0: # 移除交点列表中的重合点对
            if ips[i].distanceSquare(ips[i-1]) == 0: # 逐个比较相邻点是否重合
                del ips[i]
                del ips[i-1]
                i = i - 2 # 如果点对被移除,i 向前走 2 步
            else:
                i = i - 1 # 否则 i 向前走 1 步
        return ips # 返回处理后的交点列表
```

以上 SweepLine 类仅包含一个列表类型的 segs 属性，用于存储和当前扫描线相交的线段。在 SweepLine 中，我们定义了一个 intersect 函数，这个函数的作用是计算扫描线维护的线段和指定 y 直线的所有交点。在这个函数中，我们首先根据输入的 y 值构造了一条 y 线，然后遍历 segs 中的每条线段和 y 线求交。

理论上，我们只要调用 GeomAlgo 模块中的 intersect 函数去计算直线（Line）和线段（Segment）的交点即可。但当线段端点恰好落在直线上时，由于浮点运算中截断误差的存在，intersect 函数可能无法返回正确的结果，在最差的情况下，intersect 函数可能返回 None，即直线和线段在本应相交的情况下却返回不相交的错误结果。在某些场合下，这样的求交结果可能无足轻重；但是在求平面区域填充线的应用中，如图 9.1，某处交点的有无将直接改变当前 y 线上所有交点的奇偶属性，这对填充结果的影响是巨大的。为了避免截断误差的影响，增强算法的稳定性，这里我们首先判断线段两端点是否落在直线上，当直线是一条和 X 轴平行的 y 线时，这样的判断变得非常简单，我们只需判断线段端点的 y 值是否和 y 线的 y 值相等即可。如果线段端点没在直线上，我们再调用 GeomAlgo 模块的 intersect 函数求取直线和线段交点。

在获取了当前扫描线维护的线段和指定 y 线的所有交点之后，我们首先对交点列表按 X 坐标进行了升序排序，排序的目的是方便我们后续直接从交点列表中提取填充线。此外，我们还执行了一步看似奇怪的操作：通过检查相邻交点间的距离平方是否为 0，删除交点列表中所有有重合的交点对。在下一小节，我们将解释这么做的原因。

需要说明的是，我们在以上 intersect 函数中删除的重合交点对不会对填充结果的正确性造成影响。如图 9.3 所示，这里的重合交点对只可能存在以下两种情形：一是交点两边的线段都在 y 线下方（图中 P1, P2），二是交点两边的线段都在 y 线上方（图中 P3, P4），无论哪种情况，因为两边线段都和 y 线相交，因此最终会计算得到两个重合的交点。在图 9.3 中，按照填充线的提取规则，我们最终将得到 P0 P1, P2 P3, P4 P5 三条有效填充线段。考虑到 P1, P2 重合，P3, P4 也重合，而且所有交点都在同一条直线上，因此我们可以移除 P1, P2 和 P3, P4 两组点对，得到和原来 3 条填充线等价的 P0 P5 填充线。根据以上分析，删除重合的交点对对最终填充结果的正确性不产生影响，而且可以减少输出的填充线数量。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_205_0.png)

图 9.3 扫描线上的重合交点对

### 9.1.2 填充线交点计算

在建立了扫描线数据结构后，接下来我们考虑构建扫描线算法流程。可以想像，扫描线法应该包含两个关键步骤，一是根据线段最低点的 Y 坐标对线段序列进行排序，二是当扫描线平移时对其中维护的线段进行增删。以上所说的线段全部来自输入多边形的边。

参考扫描平面法算法框架，下面我们在 GenHatch 模块中实现一个 calcHatchPoints 函数，其中前缀 calc 为 calculate 的缩写，意为计算。这个函数的作用是使用扫描线法计算多边形序列和平行线序列的所有交点，它的具体实现代码如下：

以上 calcHatchPoints 函数的输入包含两个参数，第一个参数是多边形列表 polygons，第二个参数是扫描高度列表 ys。根据填充线的提取原理可知，对这个函数而言，事实上多边形的方向是无关紧要的，并不一定要求满足“外逆内顺”的条件。

在 calcHatchPoints 函数中，我们首先收集了所有多边形的边，并使用 Python 动态属性特性为 Segment 类的对象临时增加了 yMin 和 yMax 两个属性，分别用于存储当前线段在 Y 轴方向上的最低点和最高点。根据每条线段 yMin 值，我们首先对线段列表 segs 进行了从低到高排序。对当前扫描高度 y，我们首先从扫描线中移除已经不再和扫描线相交的线段，即那些 yMax 值小于 y 的线段。在完成了这一步后，我们又从 segs 中向扫描线添加和扫描线相交的线段，即那些 yMin 值小于 y 且 yMax 大于等于 y 的线段；在这个过程中，如果当前线段的 yMin 大于等于 y 值，则停止向扫描线添加线段，同时记录当前线段在 segs 列表中的序号 k。我们发现，k 是扫描线法高效的关键所在，如果没有这个变量，对每个扫描高度，我们不得不从线段列表 segs 的首个元素开始遍历，这样对 segs 的排序就显得毫无意义。最后，我们使用 SweepLine 类的 intersect 函数计算扫描线中线段和扫描线的所有交点，并将这些交点保存到 ipses 中。函数的返回为 ipses，注意，这是一个二维列表，其中第一个维度表示扫描高度序号，第二个维度表示某一扫描高度上的所有交点。

让我们再来看一下 calcHatchPoints 函数中的向扫描线添加新线段的条件。在代码中，对某一扫描高度 y，我们仅将满足 yMin < y 且 yMax >= y 条件（记为条件 1）的线段添加至扫描线，即小于时等号取不到，大于时等号能取到。那为什么条件不是 yMin <= y 且 yMax >= y（记为条件 2），小于大于同时取到等号呢？这样似乎更加合理。

如果使用条件 2，只要某线段落在 y 线上，那么我们就将该线段添加至扫描线，包括线段上端点落在 y 线上、下端点落在 y 线上、中间被 y 线穿过以及上下两端点都落在 y 线上（即线段和 y 线重合）4 种情况，如图 9.4 所示。从某种意义上来说，应用条件 2 是合情合理的，它会收集所有和当前 y 线相交的线段。但是，当 y 线经过线段端点时，由于线段的连续性，重合的端点将被收集两次，这无疑会增加后续根据交点奇偶属性来提取填充线的难度。类似于我们对图 9.3 的解释，条件 2 并不会影响图 9.4 中 P1、P2、P3、P4、P5、P6 以及 P7、P8 这 4 组点对在提取填充线时的结果，即便我们保留这些点对，最终也能提取到几何上正确的填充线，因为在这些点上，y 线并未真正“穿过”轮廓。但是，条件 2 会影响图中 P9、P10 在提取填充线时的结果，如果不加处理，我们将提取到位于多边形区域外的填充线（即线段 P10 P11），这显然是错误的。有一点需要说明的是，如果线段和直线重合，我们认为它们不相交，这也是为什么图 9.4 中在 P5、P6、P7、P8 处只有一个点的原因。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_207_0.png)

图 9.4 根据条件 2 获得的扫描线上的交点

如果执意要使用条件 2，我们当然可以采取一定的措施进行补救，比如对以上 P9、P10 点对进行合并操作。但这又将带来一个新的问题，我们应该满足什么条件才能合并重合交点对？如果随意合并点对（如 P1、P2），也将导致后续填充线提取出错。我们可以想象，合并的条件和 y 线是否穿过轮廓有关。要判断 y 线是否穿过轮廓，我们不得不去判断重合交点对两侧的线段和 y 线的相对位置，只有它们在 y 线不同侧时，我们才能认为 y 线穿过轮廓，进而才能去合并相应交点对。做出这些判断需要相应数据结构的支撑。我们已经
