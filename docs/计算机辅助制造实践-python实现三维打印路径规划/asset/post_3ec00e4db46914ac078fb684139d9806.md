

核心切片函数，它在类的初始化函数中被触发启动，不过我们在这里只对 slice 函数进行了声明，并未具体实现。

此外，我们在 TopoSlicer 类中实现了两个函数，分别是 findSeedFace 和 findNextFace。其中前者的功能是在扫描平面法的框架下，在和当前截平面相交的三角面片（即参数 faces）中寻找种子面片。它的实现原理非常简单，直接遍历输入的 faces，寻找首个未被使用过的面片并返回，如果所有 faces 均已被使用过，则返回 None，表示找不到种子面片。因为 faces 尺寸不会太大，因此我们不必太在意 findSeedFace 函数的执行效率。

最后，我们来看一下 findNextFace 函数，这是我们在 TopoSlicer 类中重点实现的函数，它的功能是根据当前面片寻找下一个目标邻面。但这个函数的输入并非当前面片，而是当前面片和截平面相交后得到的交点所在的半边和顶点，即 edges 和 node。然后我们按照以上介绍的原理对 edges 和 node 进行分类讨论，包括交点均在半边上以及交点分别落在半边和顶点上两种情况，从而找出目标邻面。

针对第二种情况，当目标邻面和当前面片通过 node 相连时，如图 7.14（b），我们调用了 TEdge 的 intersect 函数对 node 中存储的所有面片（node.faces，当前面片除外）进行遍历求交，那这里为什么要去执行费时的求交操作而不直接判断面片最低点 zMin、最高点 zMax 和截平面高度 z 的关系呢？其实我们已经考虑到了这一点，但是，zMin <= z 且 zMax >= z 是面片和截平面相交的必要非充分条件，因为当面片的一个顶点落在截平面上时，我们认定它们是不相交的。所以，这里我们不得不调用 intersect 函数，确保万无一失。在 intersect 函数中，我们使用了 node 的 z 坐标作为当前截平面的高度，这是因为在这种情况下，截平面的高度确实恰好等于 node 的 z 坐标，这样做的好处是可以为 findNextFace 函数节省一个必要的截平面高度的输入参数。

## 7.4.3 切片轮廓创建

通过以上讨论，针对一个拓扑模型，现在我们可以以较快的速度找出一个种子面片，我们也可以从这个种子面片出发，连续不断地找出当前面片的下一个面片，这些都已经不再是泛泛而谈。对于我们要实现的拓扑模型切片的目标来说，现在缺的似乎只是一个合理的流程。我们在这一小节的任务就是组织整理基于拓扑模型的切片轮廓创建流程，同时给出 TopoSlicer 类的剩余代码。

我们先来看一下切片轮廓的创建流程，如图 7.15 所示。这个流程的输入为当前截平面高度 z 和面片列表 faces，输出为包含了当前层片切片轮廓信息的 layer，其中 faces 为拓扑模型中仅和当前截平面相交的面片，这些面片可由扫描平面法获得。

对输入的高度 z 和面片 faces，我们首先需要创建供收集切片轮廓用的 Layer 对象 layer。此外，我们还有必要对 faces 进行数据清洗，即将 faces 中每个面片的 used 属性值置为 False。这一步看起来微不足道，极有可能被忽略，但是它却非常重要，甚至可以说是切片轮廓创建失败的关键。这是因为在对拓扑模型的切片过程中，有些时候，切片层高值可能小于某些三角面片在 z 方向上的高度，在这种情况下，这些面片就可能被不同高度的截平面多次切到。如果在上一轮切片过程中，我们已经标记了这些面片的 used 为 True，而在这一轮切片开始前没有将 used 重置为 False，那么在这一轮切片过程中，我们很有可能找不全或找不到种子面片，从而导致切片失败。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_153_0.png)

### 图 7.15 基于拓扑模型的切片轮廓创建流程

如图 7.15 所示，在完成 faces 的 used 标识重置之后，接下来我们就开始进入轮廓创建的第 1 层循环。这层循环主要做的就是从 faces 中找出一个种子面片：如果找不到种子面片，表明 faces 中所有面片均已被使用，此时可以输出切片数据 layer，并退出整个流程；如果能够找到种子面片，则新建一条 Polyline 类型的轮廓作为当前轮廓 contour，并进入第 2 层循环。第 2 层循环的核心功能就是不断根据当前面片寻找与之相邻的下一面片，并在这一过程中，把截交得到的线段添加到当前轮廓。

在不同时期，上述第 2 层循环有 3 个不同的退出条件。其中第 1 个退出条件为当前面片和截平面不相交，这个条件在正常情况下看似很难满足。但为了保证流程的稳定性，我们在流程中保留这个退出条件，在下文分析中，我们将会发现，保留这个退出条件确实是必要的。第 2 个退出条件为当前轮廓 contour 已封闭，这是理所当然的正常退出，当前轮廓封闭后，我们就应该再寻找一个种子面片。第 3 个退出条件为根据当前面片找不到目标邻面，即 findNextFace 返回 None，这表明模型在当前面片处未封闭或存在裂缝，这是不正常的，也是不应该发生的，如果在循环中遭遇了这样的退出情况，我们将得到一条非封闭的轮廓线。

不管正常与否，在以上第 2 层循环退出后，如果当前轮廓中包含的点的数量大于 0，则将该轮廓添加至 layer，否则直接放弃当前轮廓。需要注意的是，按照正常流程执行，按理轮廓中顶点的数量不应该为 0，至少种子面片能为当前轮廓贡献两个顶点。其实不然，如图 7.16 所示，如果当前截平面恰好过顶点 v0，而 v0 被若干个面片共享（图中是 6 个），在这种情况下，我们知道面片 f1 ~ f6 都将被添加至扫描平面，即 faces 中。根据我们封装的 findSeedFace 函数，这些面片都有可能被选为种子面片，一旦某个面片被选为种子（如 f1），图 7.15 中的流程是能够进入第 2 层循环的，但因为面片和截平面没有交线，满足上述第 1 个退出条件，这样我们就得到了一条没有顶点的轮廓。所以，在将当前轮廓添加至 layer 之前，我们有必要检查一下它所包含的顶点数。这个问题看起来微不足道，而且很难被发现，但如果不去处理，在最坏的情况下，整个流程将因在循环中跳不出来，这是致命的。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_154_0.png)

### 图 7.16 轮廓包含点数为 0 异常

针对拓扑模型，结合扫描平面法，现在我们可以在指定层高上对模型进行切片，输出切片轮廓，而且这一过程中，我们完全不用关心截交线段的拼接问题。接下来我们考虑将以上介绍的切片轮廓创建流程封装为函数，函数名为 createLayerContours，以补充 TopoSlicer 类，并给出它的剩余代码，具体实现如下：

|---|---|---|

| 2 | class TopoSlicer： | # 定义 TopoSlicer 类 |
| 3 | ...... | # 忽略类中其他代码 |

```python
f = self.findSeedFace(faces)
if f is None: break
contour = Polyline()
while True:
    seg, edges, node = f.intersect(z)
    f.used = True
    if seg is None: break
    contour.appendSegment(seg)
    if contour.isClosed() : break
    f = self.findNextFace( edges, node)
    if f is None: break
    if contour.count() > 0:
        layer.contours.append( contour)
return layer
def slice( self ):
    self.topoModel.faces.sort(key=lambda t: t.zMin())
    zs = self.genLayerHeights()
    k = 0
    sweep = SweepPlane()
    for z in zs:
        for i in range(len(sweep.triangles) - 1, -1, -1):
            if z > sweep.triangles[i].zMax():
                del sweep.triangles[i]
    for i in range(k, len(self.topoModel.faces)):
        face = self.topoModel.faces[i]
        if z >= face.zMin() and z <= face.zMax():
            sweep.triangles.append( face)
    elif face.zMin() > z:
        k = i
        break
    layer = self.createLayerContours(z, sweep.triangles)
    adjustPolygonDirs(layer.contours)
    self.layers.append( layer)
def genLayerHeights( self ):
    xMin, xMax, yMin, yMax, zMin, zMax = self.stlModel.getBounds()
    zs, z = [], zMin + self.layerThk
    while z < zMax:
        zs.append( z)
        z += self.layerThk
    return zs
```

我们首先来看一下 TopoSlicer 类剩余代码中的 createLayerContour 函数，这个函数的实现还原了如图 7.15 所示的切片轮廓创建流程。需要说明的是，在这个函数中，对得到的截交线段，我们通过 Polyline 类的 appendSegment 函数将其添加到当前轮廓中。在每一步循环中，尽管我们知道得到的截交线段必然是可以被直接添加到当前轮廓上的，但是我们不太确定的是，它到底是和当前轮廓的头部还是尾部相接。从理论上分析，对于一条新建的空轮廓，在对其添加第 1 条截交线段时我们可以不在意它的方向，但在添加第 2 条线段时，我们就必须要考虑一下它的走向。如果第 2 条线段是被拼接在了轮廓尾部，那么由追踪截交的原理可知，以后每条线段都将被拼接在轮廓尾部；而如果第 2 条线段被拼接在了轮廓头部，那么以后每条线段也都将被拼接在轮廓头部。

事实上，我们是不希望线段被拼接到轮廓头部的，因为对于大部分编程语言的动态数组来说，在数组头部插入一个数据的效率要低于在尾部添加一个数据的效率。在以上代码中，我们选择了一种方式，直接调用了 appendSegment 函数，让这个函数去判断到底应该将线段拼接到轮廓的头部还是尾部。有兴趣的读者可在这里做进一步优化，在合适的时候调整当前轮廓方向。

尽管我们在这里选择了这样的方式，但为了截交线段能尽量被拼接到轮廓尾部，我们在前面曾理过一些伎俩，比如在代码 7-6 的 findNextFace 函数中，对于截交线段两交点都落在面片半边的情况，我们有意先检查半边 e1 的邻面（第 20 行代码），后检查 e0 的邻面，这是因为截交计算返回的线段是从 e0 指向 e1 的（参考 TFace 的 intersect 函数），先检查半边 e1 显然是一种顺着轮廓生长方向的策略。

接下来我们再来看一下 TopoSlicer 类的 slice 函数，这个函数是完成切片轮廓的主函数，当然，它的核心功能已经被拆分成了几个子函数。我们在 slice 函数中做的主要任务就是构建了一个扫描平面法的框架，包括首先对模型中的所有面片按照最低点从低到高排序，在每一层高上，首先移除扫描平面上不再与之相交的面片，然后再添加新的面片。对每一层扫描平面中的面片，我们调用了 createLayerContour 函数生成当前层切片轮廓，然后把这些数据添加至切片列表 layers 中。以上就是 slice 函数的全部。

最后，还是像以前一样，我们需要在和切片计算相关的全局函数模块 SliceAlgo 中添加一个 TopoSlicer 类的接口函数 slice_topo，它的输入为常规的 STL 模型，输出为包含所有切片轮廓信息的切片列表。这个函数的实现代码如下：

## 7.5 算法测试比较

这一节我们将对之前封装的基于拓扑模型的切片轮廓计算模块，即对 TopoSlicer 模块进行实例测试和比较。在此之前，我们先来看一下它的比较对象。在前面 3 个章节中，我们封装了 3 种模型截交算法和 3 种截交线段拼接算法，它们分别是暴力截交法、扫描平面截交法、层高匹配截交法，以及暴力拼接法、字典序排序拼接法、字典查询拼接法。

根据我们之前的测试，其中扫描平面截交法和字典查询拼接法的效率最高，因此，我们在这里将使用这两种算法的组合和本章的 TopoSlicer 模块进行对比，只有这样的比较才是有意义的。

为了方便起见，我们先对这两种算法的组合进行封装，在 SliceAlgo 模块中新建一个类似 slice_topo 的全局函数，函数名为 slice_combine，它的具体实现代码如下：

| SliceAlgo.py | slice_combine:添加扫描平面截交、字典查询拼接组合切片算法 | 7-9 |
|---|---|---|
| 1 | from TopoSlicer import * | # 导入 TopoSlicer 模块 |
| 2 | ...... | # 忽略 SliceAlgo 其他导入模块及代码 |
| 3 | def slice_combine( stlModel, layerThk ): | # 定义组合切片函数 |
| 4 | layers = intersectStl_sweep( stlModel, layerThk ) | # 首先扫描平面截交 |

| 6 | layer.contours = linkSegs_dlook( layer.segments ) | # 然后字典查询拼接 |
| 7 | layer.segments.clear( ) | # 清除 layer 中的线段，重要 |

在以上的 slice_combine 函数中，我们首先调用了 intersectStl_sweep 函数生成截交线段，并把这些线段数据存放在 layers 中，然后我们通过 linkSegs_dlook 函数对每层中的线段进行拼接，最后得到每层的轮廓数据。

在这个过程中，我们进行了一项非常重要的操作，即在每层的线段被拼接后，清空该层上的所有截交线段。这样做是为了节省计算机内存空间，因为线段被拼接后，再在内存中保留这些线段已经没有意义了。如果不删除这些线段，对于一些大型模型，在切片层数较大时，运行 slice_combine 函数很有可能导致内存溢出。同时，我们也对得到的切片轮廓方向进行了修正，使其满足“外逆内顺”的规定。

接下来我们回到正题，对 slice_topo(拓扑切片) 和 slice_combine(组合切片) 两个函数进行比较测试，测试主机 CPU 为 Intel Core i7-8700@ 3.20GHz。测试模型依然从如图 5.8 所示的四个 STL 模型中选择，这里我们挑选了其中两个模型，分别为 bunny 和 vase 模型，它们包含的面片个数分别约为 27 万和 119 万。
