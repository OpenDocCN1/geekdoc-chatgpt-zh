以上 findLRPoints 函数的输入参数包括凹峰点 pt 和二维交点列表 ptses，返回为凹峰点两侧最近点。根据这两个点，我们就可以构造凹峰点对应的切分线段。在函数中，我们首先从二维列表中找出和给定凹峰点高度（即 y 值）相同的点列 pts，然后再逐一判断凹峰点的 x 坐标是否落在点列中的相邻点之间，如果落在某相邻点之间，那么这两个相邻点就是凹峰点两侧的最近点。这是为什么呢？如果我们回溯到 calcHatchPoints 函数的实现代码中，就会发现，我们已经对同一层高上的所有交点按照它们的 X 坐标值从小到大进行了排序。在这个前提下，我们不难理解以上代码。细心的读者可能还会发现，事实上，在 calcHatchPoints 函数中，我们已经为凹峰点两侧点的寻找解决了不少后顾之忧，比如我们删除了重合的交点。如果在 calcHatchPoints 函数中不删除重合交点，会对这里产生什么影响？有兴趣的读者不妨去探索一下。

最后，我们再来看一下步骤(4)，根据得到的切分线段分割平面区域，这是区域分区所有 5 个步骤中最难的一步。我们先来看一下最简单的情况，通过一条切分线段将给定平面区域分割成三个部分，生成 3 条全新的封闭轮廓。如图 9.21 所示，要分割图中区域，我们首先需要计算切分线段和区域轮廓的交点，这点我们在获得切分线段时就已做到。此外，更为重要的是，我们还需要知道交点所在的轮廓边（或顶点）在轮廓上的序号，只有这样，我们才能知道从哪里截取原轮廓中的部分钮廓和切分线段组成新的封闭钮廓。我们发现，要识别交点序号还是比较繁琐的，因为 calcHatchPoints 函数在计算交点时并没有保存相交线段的序号信息，因此我们不得不根据交点坐标遍历区域轮廓上的所有边，从中找出各交点所在轮廓边（或顶点）的序号。如图 9.21 所示，不妨设 A、P、B 三个交点在原轮廓上的序号分别为 10、20 和 30，那么最终生成的 3 个新的封闭轮廓的部分点序将是：0-10-30-0、10-15-20-10、20-25-30-20。对复杂的情况，当存在多条切分线段时，我们可以按照以上方法逐条递归分割原始区域。当然，在实现递归算法时我们还需要解决诸如当前切分线段属于上一步分区之后的哪个子区域等细节问题，这有点让人望而生畏。
