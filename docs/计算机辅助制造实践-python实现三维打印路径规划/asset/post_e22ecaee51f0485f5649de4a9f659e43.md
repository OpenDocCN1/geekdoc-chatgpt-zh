
前的讨论可知，lpnts 中的元素个数为 2M。对列表 lpnts，我们需要按照点的字典序对其进行排序。接下来我们进入两层循环，其中第 1 层循环不断从 lpnts 中寻找没有用过的点 P：如果点 P 不存在，即 lpnts 中所有的点都已经被使用过，则跳出第 1 层循环，结束整个流程，输出轮廓列表 contours；如果点 P 存在，则新建一条多段线 poly，并进入第 2 层循环。在第 2 层循环中，我们根据 LinkPoint 的 other 属性以及 lpnts 中点按字典序排序后重合点序号临近的特性，不断从 lpnts 中寻找当前点的下一点添加到 poly 中，直至 poly 闭合或寻找下一点失败，跳出第 2 层循环并重新开始第 1 层循环。

有了如图 6.4 所示的逻辑非常清晰的流程图，接下来我们就可以将线段拼接流程转化为实际可用的代码。为了实现以上流程，我们专门封装了一个 LinkSegs_dorder 类，类名中 dorder 是我们生造的一个词，表示 dictionary order(字典序) 的意思。因为之前我们已经建立了一个 LinkSegs_dorder.py 文件，并在里面实现了点的字典序比较函数 cmp_pntSmaller，这里我们还是将 LinkSegs_dorder 类写在这个文件中，其具体实现代码如下：

```python

class LinkSegs_dorder :
    def __init__( self, segs ) :
        self.segs = segs
        self.contours = []
        self.polys = []
        self.link( )
    def createLpList( self ) :
        lpnts = []
        for seg in self.segs :
            lp1, lp2 = LinkPoint( seg.A ) , LinkPoint( seg.B )
            lp1.other , lp2.other = lp2 , lp1
            lpnts.append( lp1 )
            lpnts.append( lp2 )
        lpnts.sort( key=functools.cmp_to_key( cmp_pntSmaller ) ) # 对点进行字典排序
        for i in range( len( lpnts ) ) :
            lpnts[ i ].index = i
        return lpnts
    def findUnusedPnt( self, lpnts ) :
        startIndex = -1
        for lpnt in lpnts :
            if lpnt.used == False :
                startIndex = lpnt.index
                break
        return startIndex
    def link( self ) :
        lpnts = self.createLpList( )
        cnt = len( lpnts )
        while True :
            startIndex = self.findUnusedPnt( lpnts )
            if startIndex == -1 : break
            p = lpnts[ startIndex ]
            poly = Polyline( )
            while True :
                poly.addPoint( p.toPoint3D( ) )
                p.used , p.other.used = True , True
                if poly.isClosed( ) :
                    self.contours.append( poly )
                    break
                index = p.other.index    # 获取 p.other 在 lpnts 中序号
                if index-1 >= 0 and p.other.toPoint3D().isCoincide(lpnts[index-1].toPoint3D()):
                    p = lpnts[index - 1]    # 比对 index 前一点是否重合
                elif index+1 < cnt and p.other.toPoint3D().isCoincide(lpnts[index+1].toPoint3D()):
                    p = lpnts[index + 1]    # 比对 index 后一点是否重合
                else:     # 都不满足则跳出第 2 层循环
                    self.polys.append(poly)    # 将 poly 保存到 polys 中,非封闭
                    break    # 不正常的退出
```

下面我们来看一下以上 LinkSegs_dorder 类的实现代码。这个类的封装风格和我们在上一章介绍的 IntersectStl_sweep 类以及 IntersectStl_match 类十分相似。在类的初始化函数中,我们通过参数 segs 从外部输入截交线段列表,contours 属性用于保存封闭轮廓,外部函数通过这个属性可以获取最终输出,polys 用于保存在拼接过程中可能出现的非封闭轮廓。

在 LinkSegs_dorder 类中,link 函数是执行线段字典序拼接的核心函数,它基本还原了图 6.4 所示的拼接流程:从数据点准备到第 1 层循环、第 2 层循环等。这里数据点准备是通过函数 createLpList 实现的,该函数可以根据输入的线段序列生成按字典序排序的链接点列表。在第 1 层循环中,我们通过 findUnusedPnt 函数从 lpnts 列表中找出一个没有用过的链接点,如果找不到这样的点,该函数返回-1;否则返回一个大于等于 0 的点序号。如果函数 findUnusedPnt 返回-1,则退出第 1 层循环。在第 2 层循环中,当我们获得 p.other 的 index 值后,首先比较 p.other 和 lpnts[ index - 1] 是否重合,这里我们将链接点转化为 Point3D 对象进行比较,比较函数是 isCoincide 而非 isIdentical,这是一种偏安全的做法,可以增强拼接算法的鲁棒性。尽管我们在 LinkPoint 的初始化函数中对点的坐标保留了指定的小数位数(7 位),但仍然无法保证所有本应重合的点坐标完全一致。此外,在以上代码中,我们首先判断了 index-1 >= 0 和 index + 1 < cnt,这其实是非常重要的,这样做的目的是保证列表访问不越界。

在 LinkSegs_dorder 类中,link 函数第 2 层循环的退出条件有两个,其中一个条件是正在生长的多线段 poly 闭合了,这种退出是正常的退出,得到的轮廓也是我们想要的封闭轮廓;另一个条件是当前的 p.other 找不到序号相邻的重合点时退出,这种退出是不正常的退出,此时得到的多段线是非封闭的,这并不是我们想要的。出现这种情况的原因可能有两个:一是输入的 STL 模型本来就是非封闭的(有孔洞);二是 STL 模型中相邻面片间的缝隙过大,这些其实都是模型本身的问题。如果是因为第 2 个原因,我们可以首先收集这些非封闭的多段线,然后通过适当降低点的重合误差对这些多段线进行进一步拼接,因为这样的多段线数量必然不多,因此后期可直接使用暴力法进行拼接。

## 6.4 字典查询法拼接优化

我们在上一节实现了一种基于字典序排序的截交线段优化拼接算法,其核心是依赖 LinkPoint 数据结构和点的字典序排序结果寻找线段之间的邻近关系,它的理论时间复杂度为 O( nlog(n) ),其中 n 为截交线段数量。这一节我们将另辟蹊径,介绍一种在原理上完全不同的线段拼接算法。这种算法的基础依然是 LinkPoint 数据结构,它的本质仍然是构建和寻找线段之间的临近关系,只是这次我们会把所有转化得到的链接点放在一个字典对象中,依赖编程语言内置字典类的快速查询功能定位邻近点的信息。注意,虽然本节方法和上节方法中都带“字典”字眼,但两者是完全不同的概念,一个是指字典序,一个是指字典类。

### 6.4.1 查询法拼接原理

对平面上的 M 条散乱截交线段,根据上一节介绍,我们可以把它们逐一拆分成一对对相互关联的链接点序列,这里,我们不再考虑对这些点进行任何排序操作,而是让它们以最自然的状态排布在平面上,如图 6.5 所示。此时,在图中可见,任意两个重合点的序号不再相邻,它们的差值不再为 1,而是一个随机数。显然,在这种情况下,上一节介绍的基于字典序的线段拼接方法将失效。

让我们把目光聚焦到图 6.5 中的 1 号和 4 号线段上,在图中,这两条线段是相邻相接的,它们的端点分别为 0 号、1 号和 6 号、7 号链接点,其中 1 号点和 6 号点为重合点。我们知道,由 0 号点是很容易定位到 1 号点的,只要通过 0 号点的 other 属性即可。现在的问题是,没有序号相邻这一前提的支撑时,我们应该如何从 1 号点快速定位到 6 号点呢? 比较 1 号点和 6 号点,我们发现,它们俩唯一的相同之处就是坐标,那么我们又该如何通过它们共同的坐标将 1 号点和 6 号点相互绑定起来呢? 我们需要一种由键值对构成的数据结构,键就是两点的共同坐标,值就是被绑定的两个点对象本身。

根据以上分析,我们用字典来衔接两个重合的点。字典的键就是点的坐标,而值的话,因为需要保存两个点对象,因此可以用列表,也就是说字典的值为点列表。针对 1 号点和 6 号点,如果我们用 Python 语法描述,它们在字典中的保存形式为 { (x0, y0): [lp1,

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_122_0.png)

lp6] 。其中（x0，y0）是由 1 号点和 6 号点的共同坐标所组成的元组，它是字典中的键；lp1 和 lp6 分别为 1 号和 6 号链接点，[lp1, lp6] 为保存了两链接点的列表，它是字典中的值。以上字典只有 1 个元素，如果该字典保存了多个元素，我们可以通过坐标（x0, y0）查询得到列表 [lp1, lp6]。从字典中通过键来查询值的速度是非常快的，查询的时间复杂度为 O (log(n))，其中 n 为字典中的元素总数。

需要说明的是，这里我们使用了二维坐标作为字典的键，这是因为在面向三维打印的截交线拼接问题中，线段都是落在同一高度的 XY 平面上的，即线段端点的 Z 坐标总是相等，因此我们可以直接省略掉点的 Z 坐标，这完全不影响字典的查询结果，反而会加快查询速度。在其他应用背景下，如果线段端点可能落在不同高度，那么我们也可以把 z 坐标放上去，共同作为字典的键。

回到刚才的问题，现在我们结合 { (x1, y1) : [lp1, lp6] } 字典来分析一下如何从 1 号点定位到 6 号点。从 0 号点开始，根据 0 号点的 other 我们能立刻定位到 1 号点，然后我们可以把 1 号点的 X 和 Y 坐标提取出来，构成 (x, y) 元组；根据这个元组我们可以从字典中查询得到对应的 [lp1, lp6] 列表，但这个列表中的两个元素是无序存储的；接下来我们可以通过比对 1 号点和 [lp1, lp6] 中元素的指针地址（Python 中为 id）来找出 6 号点。通过以上步骤，我们成功从 1 号点定位到 6 号点。

同理，假设现在字典中有两个元素，变成 { (x1, y1) : [lp1, lp6] , (x2, y2) : [lp7, lp2] } ，此时我们可以通过 0 号点开始依次找到 1 号点、6 号点、7 号点、2 号点和 3 号点。如果我们把平面上所有重合点都按照以上形式放到字典中，我们就可以非常快速地将一条条轮廓线找出来。那么，剩下的问题就是如何构建字典了。

对平面上的 M 条散乱线段 segs，将其转化为字典 dic 存储的步骤如下：

- (1) 遍历列表 segs，从 segs 中取出当前线段，记为 seg。
- (2) 根据 seg 构建两个链接点 lp1 和 lp2，并对两点中的 other 属性相互赋值。
- (3) 将 lp1 添加到 dic 中以元组 (lp1.x, lp1.y) 为键的点列表中。
- (4) 将 lp2 添加到 dic 中以元组 (lp2.x, lp2.y) 为键的点列表中。
- (5) 跳至步骤 (1)，直至遍历结束。

我们将以上步骤封装成了一个 createLpDic 函数，我们将该函数写在 LinkSegs_dlook 类中，对应的文件为 LinkSegs_dlook.py。从类的名字就可以看出来，LinkSegs_dlook 是一个和 LinkSegs_dorder 类相互平行的类，它们的初始化函数、属性以及类结构也完全一致。LinkSegs_dlook 类的功能是实现基于字典查询法的截交线段优化拼接，后缀 dlook 也是我们创造的一个词，表示 dictionary look up，即字典查询的意思。这里我们主要来看一下类中的 createLpDic 函数，它的具体实现代码如下：

```python
# 导入必要库
class LinkSegs_dlook :
    # 类定义
    def __init__( self, segs ):
        # 初始化函数，输入线段列表 segs
        self.segs = segs
        # 保存线段列表
        self.contours = []
        # 保存封闭轮廓
        self.polys = []
        # 保存非封闭轮廓
        self.link()
        # 调用拼接函数
    def link( self ) : pass
        # 字典查询法拼接函数，略
    def createLpDic( self ) :
        # 构建字典函数
        dic = {}
        # 字典初始化
        for seg in self.segs:
            # 遍历 segs
            lp1, lp2 = LinkPoint( seg.A ) , LinkPoint( seg.B )
            # 构建两个 LinkPoint 数据点
            lp1.other, lp2.other = lp2, lp1
            # 点的 other 属性相互赋值
            if ( lp1.x, lp1.y ) not in dic.keys() :
                # 判断 lp1 坐标是否在字典的键中
                dic[ ( lp1.x, lp1.y ) ] = []
                # 如果不在则对该键新建列表
                dic[ ( lp1.x, lp1.y ) ].append( lp1 )
                # 对该键对应的列表添加 lp1
            if ( lp2.x, lp2.y ) not in dic.keys() :
                # 对 lp2 执行相同的操作
                dic[ ( lp2.x, lp2.y ) ] = []
                dic[ ( lp2.x, lp2.y ) ].append( lp2 )
        return dic
        # 返回字典
```

在以上用于构建字典的 createLpDic 函数中，对于每条线段 seg，在得到链接点 lp1 和 lp2 后，我们首先判断元组 ( lp1.x, lp1.y ) 是否在字典的 keys 中，如果不在，则在字典中添加一对新的元组和列表，然后再将 lp1 添加到键 ( lp1.x, lp1.y ) 对应的列表中。然后我们对点 lp2 也执行完全相同的操作。对 createLpDic 函数返回的字典，在正常情况下，如果输入的线段数为 M，则字典中键的个数也为 M，每个键对应的列表存放两个链接点。

现在我们已经把平面上所有截交线段都转化成了 LinkPoint 数据点，并把这些点以重合坐标为键逐个存放到字典中。我们只要遵循以上介绍的原理，应该能够非常轻松地完成对所有截交线段进行拼接，事实也的确如此，我们将在下一小节给出这种线段拼接方法的流程和实现代码。值得一提的是，由于单点的字典查询时间复杂度为 O( log( n ) )，因此整个拼接过程的时间复杂度为 O( nlog( n ) )，其中 n 为线段条数。因为当中不涉及排序算法，因此它的时间复杂度是确定的，不存在最差或最好的情况。
