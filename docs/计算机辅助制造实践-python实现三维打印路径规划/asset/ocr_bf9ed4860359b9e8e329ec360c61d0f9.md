以上我们通过 makeMessySegs 生成的散乱线段对 3 种拼接算法进行了测试，下面我们检验一下这些算法在实际三维打印路径规划计算中的表现。这里我们选用的测试模型是在第 5 章中用过的 monk（见图 5.8），其三角面片数约为 33 万，高度为 175.5 毫米。我们设置切片厚度为 0.2 毫米，使用扫描平面法的截交时间约为 21 秒钟（参见表 5.1），最终得到的切片总层数为 877 层，截交线段总条数接近 87 万条，平均每层线段数约 988 条。这些数据我们在本章 6.1 节中有过介绍。对得到的截交线段，使用暴力法拼接的时间约为 975 秒钟，超过 16 分钟；使用字典序排序法拼接的时间约为 13.1 秒钟，使用字典查询法拼接的时间约为 8.8 秒钟。对该模型，截交、拼接后最终得到的切片轮廓如图 6.8 所示。通过对以上数据的比较，我们发现，在实际三维打印路径规划的应用环境下，字典查询法和字典序排序法的运行性能也是远远优于暴力法的。而且，有了这两种方法，线段拼接的时间基本能和模型截交时间持平。

# 本章小结

在这一章，我们继续研究了三维打印路径规划中的截交线段拼接问题。由于 STL 模型中三角面片存储的无序性，由此生成的截交线段在平面上也是散乱分布的。针对这一问题，在第 4 章，我们曾提出了一种线段的暴力拼接算法，但这种方法性能太差，不能胜任实际应用场合。为此，我们在本章提出了另两种线段拼接算法，一种是字典序排序拼接法，另一种是字典查询拼接法。虽然两种方法都和字典有关，但内在拼接原理大不相同。前者依赖对线段端点进行字典序排序，从点的序号中找出相邻的重合点；后者以线段端点坐标为键建立字典结构，从字典的键值对中查询重合点。这两种方法唯一的相同点就是它们都依赖链接点这一数据结构。理论分析和测试结果都表明，本章介绍的两种拼接算法具有线性的运行时间，它们的性能要远远优于暴力拼接法。就两种算法本身而言，字典查询法的性能比字典序排序法的性能更胜一筹。
