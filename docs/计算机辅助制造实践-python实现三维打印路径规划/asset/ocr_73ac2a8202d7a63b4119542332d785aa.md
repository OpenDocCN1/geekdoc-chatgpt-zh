calHatchPoints 函数的输入一样,仍然不包含填充线的倾角,因此它也只能返回和 X 轴平行的填充线。需要注意的是,genHatches 函数输出的填充线列表是一个一维列表,它失去了扫描线的层次信息,我们将无法从这个返回列表中直接判断两条填充线段是否在同一条扫描线上(当然通过比较线段坐标信息还是可以间接判断的)。将填充线返回为一个一维列表的原因是我们在后面将会把输入的平行填充区域拆分成若干子区域,而在每个子区域内,在一个扫描高度上将只会有一条填充线。

至此,我们已经完成了一个针对平面区域的平行线填充算法,由于使用了扫描线法的框架,因此上述算法的运行效率非常高,它的时间复杂度不超过 O( (m+n) log (m+n) ),其中 m 为平行线数量,n 为多边形总边数。在此基础上,我们实现并封装了一个 GenHatch 模块。按理,接下来我们就可以使用这个模块去生成用于三维打印的平行填充路径,进而去解决诸如路径连接、路径优化等方面的问题。但是,在此之前,我们有必要再介绍一种“现成”的生成区域平行填充的方法。

# 9.2 基于裁剪的填充线生成

我们在实现基于扫描线的平行行填充算法过程中,解决了几个关键问题,如线段端点落在 y 线上时求交的数值稳定性、重合交点对的删除等,而解决这些问题用到的思路和技巧是我们今后实现其他复杂几何算法的基础。尽管如此,我们可能又造了一个轮子,因为在我们之前介绍的第三方库 Clipper 中,已经包含了生成平面区域填充线的方法。我们在这一节的任务就是对现成的方法进行封装,转化为直接能用的函数。

# 9.2.1 平行线段生成原理

如图 9.1 所示,如果我们不是从求交,而是从其他角度去观察图中填充线和平行线以及多边形间关系的话,我们会发现,求取填充线的过程其实就是以多边形为窗口对平行线进行裁剪的过程。而裁剪正是 Clipper 库最擅长做的事! 正如我们在第 8 章中介绍的,Clipper 支持四种裁剪操作,包括:交( intersection )、并( union )、差( difference )、异或( xor )。Clipper 的强大之处在于它除了能够处理封闭轮廓间的裁剪问题外,还支持封闭轮廓和开放轮廓的求交裁剪操作,即求落在封闭轮廓(窗口)内的开放轮廓,而这一功能正好满足我们生成填充线的需求。

结合图 9.1,对输入的多边形区域,使用 Clipper 库在其内部生成平行填充路径的步骤如下:

+   (1) 生成一组指定倾角且能覆盖整个区域的平行线段序列; (2) 以多边形区域为窗口,对平行线进行裁剪,输出填充线。

有了 Clipper 库的支持,生成填充线的步骤变得异常简洁,我们无需再去处理那些烦人易错的求交问题。现在我们唯一需要关注的就是步骤(1)。在上一节使用扫描线法时(参考代码 9-5),因为我们首先旋转了多边形,所有的平行线都和平面坐标系的 X 轴平行,因此我们只需找出旋转后多边形在 Y 方向上的最小值 yMin 和最大值 yMax,然后根据输入间距在 yMin 和 yMax 之间生成扫描高度序列 yS 即可。如果使用 Clipper 库,虽然我们不用再去旋转多边形,但我们需要输给它实实在在的带倾角的线段对象,这是因为 Clipper 库只能处理多段线对象(线段也是一种多段线),而无法处理直线对象。
