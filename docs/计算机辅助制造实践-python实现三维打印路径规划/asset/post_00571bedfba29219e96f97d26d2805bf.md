我们再来看一下 vase 模型的切片时间。这个模型中的面片数量约是 bunny 模型的 4 倍，对它的切片时间也更长。对这个模型，我们可以预测拓扑切片的优势将更早来临而且更加显著。结果确实如此，结合表 7.1 和图 7.17（b），当切片厚度为 0.5 毫米时，两种方法的效率已经旗鼓相当；当切片厚度为 0.2 毫米时，拓扑切片的效率已超组合切片效率；当切片厚度为 0.05 毫米时，拓扑切片的效率约为组合切片的两倍。

## 第 8 章 轮廓平行填充路径生成

### 引言

三维打印是一种典型的“降维”制造方式，它的工艺特点是逐层堆叠生长，三维打印路径规划的作用就是将复杂的三维模型转化为一系列相对简单的二维刀具路径（toolpath）。在前面几章，针对输入的 STL 模型，我们介绍了多种不同的切片方法，得到了各个切层上的轮廓数据。从本章开始，我们将从切片轮廓出发，在这些轮廓表示的打印区域内部，生成能够覆盖这些区域且适应于三维打印工艺要求的刀具路径，我们把这些路径统称为填充路径。在三维打印中，最为常用的填充路径包括轮廓平行（contour—parallel）填充路径和方向平行（direction—parallel）填充路径，这一章我们主要介绍轮廓平行填充路径的生成原理和方法。

### 8.1 常用填充路径概述

在指定层高上，三维打印路径规划的本质是在工艺条件约束下的打印区域填充问题。理论上，对任意形式或任何方法生成的曲线，只要它能够满足打印工艺要求，且能覆盖平面上的整个打印区域，那么它就可以被当作是一种有效的三维打印填充路径。尽管如此，在三维打印中，真正实用的填充路径种类不多，其中最为常用的填充路径仍然是轮廓平行填充路径和方向平行填充路径。我们先来看一下这两种填充路径的概貌，如图 8.1 所示。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_162_0.png)

图 8.1 轮廓平行填充路径和方向平行填充路径

轮廓平行填充路径（以下简称轮廓填充路径或轮廓路径）实质上就是一系列平面偏置曲线。这些偏置曲线通过对表示打印区域的边界轮廓连续偏置生成。如图 8.1（a）所示，$b_0$ 表示打印区域边界轮廓序列，也就是切片轮廓，$b_0$ 包含若干外边界，有时候它也可能包含若干内边界，按照我们之前在第 4 章中的约定，外边界轮廓方向为逆时针，内边界轮廓方向为顺时针。图中 b1 同样表示一个曲线序列，它保存了对 b0 中的各轮廓进行等距偏置得到偏置曲线，这里等距偏置的意思是 b1 上的任意一点到 b0 的距离为一固定常数，而这个常数就是偏置距离。如果两条曲线为等距偏置关系，那么我们可以认为这两条曲线是“平行”的，这也正是我们称偏置路径为轮廓平行路径的原因。等距偏置事实上是三维打印的一个工艺需求，比如在熔融沉积（Fused Deposition Modeling，FDM）三维打印中，从喷头挤出来的丝宽是不变的，从理论上来说，要把这些宽度不变的丝材无缝地平铺在打印区域内，就必须用到等距偏置。同理，图中 b2 为对 b1 等距偏置得到的曲线序列，b3 为对 b2 等距偏置得到的曲线序列等。我们发现，在连续偏置过程中，bk (k = 1, 2, 3···) 在某些情况下可能会分裂成两条或多条曲线（如图中 b3），因此，bk 中曲线的数量总是会越来越多，但由它包围的平面范围会逐渐缩小，并最终收敛于一点（或多点），从而填充整个打印区域。

方向平行填充路径（以下简称平行填充路径或平行路径）实质上就是平面上的一系列平行线段，如图 8.1(b) 所示。相对于轮廓路径，平行路径的生成原理相对直观、简单。如果不计时间成本，我们只需事先在平面上指定一个方向，并根据这个方向在打印区域范围内生成一系列等距平行线，然后计算这些平行线和边界轮廓交点，得到位于轮廓内部的线段，最后通过合适的方式连接这些线段，获得平行路径。这个过程其实和在 CAD 软件里做的线段区域裁剪操作类似。如果我们再稍微思考一下，还会发现：如果表示打印区域的轮廓为凸多边形，那么每条直线最终都将被轮廓截成一段线段；但轮廓若为凹多边形，那么就可能存在一些直线被轮廓截成两段或多段线段，具体线段数量不仅和轮廓形状有关，还和直线的方向有关，轮廓形状不能调整，而直线方向能够调整。我们把事先指定的直线方向称为平行路径的参考方向，参考方向是平行路径生成过程中的重要参数，它关系到最终得到的线段数量、线段平均长度以及打印过程中打印机喷头需要被抬起的次数，显然，每条线段的平均长度越大，喷头被抬起的次数越少，打印效率就越高。

在实际三维打印中，对每层轮廓区域，大多时候我们并不会单独地去填充轮廓路径或平行路径，而是去填充由两种路径混合而成的组合路径。如图 8.2 所示，我们一般会在打印区域的边缘处填充轮廓路径（图中填充了 3 层轮廓路径），这样做的原因是轮廓路径能够非常好地跟随，还原轮廓形状，从而保证被打印模型的外观精度。但由于轮廓路径形状复杂，弯曲频繁，路径上曲率变化通常较大，最终导致打印机各轴电机频繁加减速，因此相对来说，轮廓路径的打印效率不高。如图 8.2 所示，在对形状精度要求不高的打印区域内部，我们一般会去填充平行路径。平行路径在边缘处精度不高，在还原轮廓原貌时会出现难以避免的锯齿现象。从整体来看，虽然平行路径确实在每条线段的端点处方向不断变化，但至少在每条平行线段内部，路径的方向是恒定不变的，这样，打印机就能始终以设定的最高打印速度进给，从而保证打印效率。根据以上分析，我们知道，对一打印区域的外部使用轮廓填充，内部使用平行填充，既可以保证模型外观精度，同时还可以保证打印效率，确实比采用单一的填充路径更为合理。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_163_0.png)

图 8.2 由轮廓路径和平行路径组成的混合填充路径

### 8.2 轮廓偏置基础方法简介

通过以上介绍，我们知道，生成轮廓平行填充路径的基础是平面曲线的等距偏置算法。更准确地，对 STL 模型的三维打印来说，因为我们得到的切片轮廓都是平面简单多边形(封闭点列曲线)，即不存在自相交情况的平面多边形，因此生成轮廓路径的基础是平面简单多边形的等距偏置算法。在以下讨论中，考虑到我们讨论的对象都是平面简单多边形，而且偏置都是等距的，简单起见，描述时我们忽略多边形前面“平面简单”的前缀和偏置前面“等距”的前缀。

多边形的偏置问题是一个传统而通用的平面几何问题，但却非常基础和重要，在数控加工中的刀具半径补偿、路径规划以及平面设计等领域都有广泛应用。如果我们使用严格的数学语言描述，那么这个问题可以定义为：对一个输入多边形，在其一侧生成一个(或多个)新的多边形，使得新多边形上的每点到原始多边形的距离为给定的偏置距离。如果我们使用更加具有操作性的语言描述，那么这个问题还可以定义为：对一半径等于给定偏置距离的圆，使其沿着多边形一侧滚动，得到的圆心轨迹就是所求的偏置多边形，如图 8.3 所示。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_164_0.png)

图 8.3 圆沿轮廓边界滚动时圆心轨迹形成偏置轮廓

多边形的偏置问题虽然看起来简单，但实际解决起来并不容易，在这过程中我们可能需要处理各种各样棘手的难题。如果要我们自己去设计多边形偏置算法，在一开始的时候，我们大概会遵循以下两种非常直观的设计思路，一种是基于线段平移的偏置，另一种是基于角平分线的偏置。

### 8.2.1 基于线段平移的偏置

根据以上描述，我们知道，偏置多边形事实上就是一个沿着原始多边形滚动的圆的圆心轨迹。尽管如此，我们发现，直接从圆在多边形上滚动的角度去求取偏置多边形还是比较困难的。但是我们可以对这个问题进行简化，首先把原始多边形拆分开来，当圆沿着它其中的一条边(线段)滚动时，此时圆心的轨迹就是一条线段，即偏置线段。然后我们可以对原始多边形的每条边进行偏置，最后，理论上，我们只需有序地连接这些偏置线段就可以得到原始多边形的偏置多边形了。但事实真的如此吗？

首先我们来看一下线段的偏置问题，对于我们来说，这个问题其实非常简单。我们只需对线段进行平移即可，平移的方向为原始线段的法线方向。更具体地，我们只需对原始线段的两个端点分别沿着线段法向平移给定的偏置距离即可。这个问题的关键就是获取原始线段的法线方向。但因为我们在 GeomBase 模块的 Vector3D 类中已经封装了 getOrthoVector2D 函数，这个函数的作用就是求取当前向量在 XY 平面内的正交向量(单位向量)，即法向量。因为所有的切片轮廓都在 XY 平面内，因此我们可以直接应用这个函数。如果我们假设输入线段的两端点分别为 P1,P2，那么它的法向量可由以下代码求得：

| | 线段 P1,P2的偏置线段计算方法 | 8-1 |
|---|---|---|
| 1 | v = P1.pointTo(P2) | # v 为直线 P1P2 方向 |
| 2 | n = v. getOrthoVector2D() | # n 为直线 P1P2 法向量,n 为单位向量 |

但线段 P1,P2事实上有两个法向量，分别指向直线的两侧。如图 8.4 所示，如果我们要求取原始多边形的向内偏置多边形，且原始多边形方向为逆时针的话，此时我们要求的线段 P1,P2的法向应该指向 P1,P2的左侧。注意，当我们说一条线段(或一个向量)的左侧或右侧时，我们是站在背向它的起点、面向它的终点的角度说的。遗憾的是，查看 getOrthoVector2D 函数代码可知，它返回的法向量的左右侧方向是不确定的，因此我们必须对以上代码中的法向量 n 做进一步处理。

那我们该如何确保 XY 平面上的向量 n 在线段 P1,P2的左侧呢？其实这很简单，我们只需对 n 和 P1,P2的方向向量(即 v) 进行叉乘(注意，n 在前，v 在后，向量叉乘特别需要注意两个向量前后顺序)，对得到的向量，根据向量叉乘的右手螺旋法则：如果它的方向指向坐标系 Z 轴负向，那么可以判定向量 n 指向线段 P1,P2左侧，此时我们无需对 n 进行任何处理；反之，如果向量叉乘的方向指向 Z 轴正向，那么可以判定向量 n 指向线段 P1,P2右侧，此时我们需要对 n 进行取反处理。接着以上代码，我们得到如下代码：

| | | |
|---|---|---|
| 3 | if n.crossProduct(v).dz > 0; | # 如果 n 和 v 的叉乘向量指向正 Z 向 |
| 4 | n.reverse( ) | # 则对 n 方向取反 |

如果我们记给定的偏置距离为 d，线段 P1,P2两端点沿单位向量 n 平移后的点分别为 Q1、Q2，则 Q1、Q2可由以下代码计算得到：

```
Q1 = P1 + n.amplified(d)  # Q1 为 P1 的偏置点
Q2 = P2 + n.amplified(d)  # Q2 为 P2 的偏置点
```

通过以上代码，我们可以计算任意逆时针多边形每条边的向内偏置线段；如果多边形为顺时针方向，而以上代码不变，那得到的偏置线段将在多边形的外侧。类似地，如果需要计算一个逆时针多边形每条边的向外偏置线段，我们需要调整以上代码中向量 n 的方向，使其总是在线段的右侧。

接下来我们还是以逆时针多边形向内偏置为例展开讨论。在图 8.4 中，事实上，我们已经能够看出一些端倪：直接将偏置线段有序地放在一起是无法得到偏置多边形的，我们需要对它们进行修补。如图 8.5(a) 所示，如果多边形两相邻边所夹内角为优角(小于 180 度)，那么它们对应的两条偏置线段必然相交，此时我们需要计算两偏置线段的交点，并在交点处对它们进行裁剪、连接。如图 8.5(b) 所示，如果多边形两相邻边所夹内角为劣角(大于 180 度)，那么它们对应的两条偏置线段必然存在缝隙，此时我们需要考虑如何弥补这个缝隙，比如分别延长两条偏置线段然后在其交点处相连，或使用一段半径为偏置距离 d 的圆弧衔接这两条偏置线段。这里需要说明的是，如图 8.5(b) 所示，当我们用延长线去衔接偏置线段时，延长线上的点到原始轮廓上的距离将大于给定的偏置距离，这不符合我们对偏置线的定义，但是我们允许这种情况的存在，这其实是偏置过程中的一种妥协。

如果以为处理了以上两个问题就可以生成偏置多边形的话，那我们还是小看了偏置问题的难度。如图 8.6 所示，对于图中轮廓(多边形一部分)，在偏置距离较小的时候，我们可以直接运用以上的修补方法生成它的偏置轮廓；但当偏置距离较大时，如果我们依然只是运用以上的修补方法，我们将得到一个带有自相交环的偏置轮廓。如图 8.6，自相交环上的点到原始轮廓的距离显然小于给定的偏置距离，这是不对的。可以说，偏置轮廓上的自相交环是偏置错误的表现，必须避免或消除。

但是识别和消除偏置轮廓上的自相交环并不是一件容易的事情。这不仅仅是计算量的问题，我们甚至可能找不到一种计算量大但能得到正确结果的方法。如对图 8.6 中修补得到的偏置轮廓，如果要消除自相交环，我们的想法可能是首先计算偏置轮廓的自相交点，然后在自相交点对偏置轮廓进行裁剪，去除自相交环，这种思路对这个例子也许可行，但计算量不小，需要两两遍历计算偏置轮廓上所有边的交点。如果我们对图 8.6 中的轮廓稍做修改，如图 8.7 所示，那么在修补后的偏置轮廓上，将出现若干自相交环，而且这些自相交环可能会相互嵌套，这种情况下，我们又该如何去识别和消除自相交环呢？哪些轮廓段是有用，需要被拼接到输出多边形上的？哪些轮廓段是没用的，需要被舍弃的？这些可能都需要我们在尝试大量的测试例后制定相应的规则，这样的研究可能要持续一段时间。

如果我们以为消除了以上介绍的自相交环就已经解决了多边形偏置问题的话，那我们又小看它了。我们以上介绍的自相交环都位于轮廓局部区域，我们把这种自相交环称为局部自相交环；事实上，在对多边形的偏置过程中，还可能产生全局自相交环，如图 8.8 所示。全局自相交环看起来似乎是偏置过程中的合理存在，它上面的点到对应的原始轮廓距离是满足偏置要求的，但它其实也是一种偏置错误，因为它到另一部分原始轮廓的距离小于偏置距离。全局自相交环常规的消除思路是：首先两两遍历计算偏置轮廓边的所有交点，然后根据交点对偏置轮廓进行分段，并根据每段偏置轮廓到原始轮廓的距离是否小于偏置距离决定这段轮廓是否需要保留，最后按照一定的逻辑(如轮廓段走向)拼接保留的偏置轮廓段得到若干封闭偏置多边形。但执行这种思路需要大量的计算，包括遍历求交和遍历求距离。
