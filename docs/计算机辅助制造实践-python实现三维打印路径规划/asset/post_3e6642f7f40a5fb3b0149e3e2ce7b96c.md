在这一章，我们继续研究了三维打印路径规划中的截交线段拼接问题。由于 STL 模型中三角面片存储的无序性，由此生成的截交线段在平面上也是散乱分布的。针对这一问题，在第 4 章，我们曾提出了一种线段的暴力拼接算法，但这种方法性能太差，不能胜任实际应用场合。为此，我们在本章提出了另两种线段拼接算法，一种是字典序排序拼接法，另一种是字典查询拼接法。虽然两种方法都和字典有关，但内在拼接原理大不相同。前者依赖对线段端点进行字典序排序，从点的序号中找出相邻的重合点；后者以线段端点坐标为键建立字典结构，从字典的键值对中查询重合点。这两种方法唯一的相同点就是它们都依赖链接点这一数据结构。理论分析和测试结果都表明，本章介绍的两种拼接算法具有线性的运行时间，它们的性能要远远优于暴力拼接法。就两种算法本身而言，字典查询法的性能比字典序排序法的性能更胜一筹。

## 第 7 章 基于拓扑模型的切片轮廓计算

### 引言

本章我们打算重新思考针对 STL 模型的切片轮廓计算问题。在前面几章中，我们都是直接从 STL 模型出发，先进行截交计算，得到离散线段，然后再对这些散乱线段进行拼接，得到表示打印区域边界的封闭轮廓。在这一过程中，尽管我们提出了若干优化算法，但我们并没有对 STL 模型进行任何预处理或优化——当然我们曾在扫描平面法的截交操作中对模型中的面片进行排序。事实上尽管在原生的 STL 模型中没有表现出来，但模型中顶点与面片、边与面片、边与边、面片与面片之间是存在一定的几何拓扑关系的，比如由一个顶点可以找到共用它的若干面片，由一个面片可以找到共用同一边的相邻面片等。这一章我们要做的就是首先对输入的 STL 模型进行预处理，重建模型中点、线、面的几何拓扑关系，并在此基础上重新考虑切片轮廓计算问题。

### 7.1 STL 模型存在的问题

回顾一下图 4.1，我们可以发现，在传统的 STL 文件中，保存的是以三角面片为单元、面片顶点坐标为基础的非常原始的几何数据，其中两点组成一边，三点组成一面。它的一个显著特征是各个面片都是被无序保存的，正是为了应付这个特征，我们在前面几章费了不少心机。如果我们观察稍微再仔细点，就会发现在 STL 文件中，各个面片中的各个顶点都是被独立保存的，这直接导致了 STL 模型的顶点冗余问题。

顶点冗余是 STL 模型经常被诟病的问题之一。如图 7.1 所示，图中的四棱锥拥有 5 个顶点，理论上，用 5 个顶点就足以表示这个模型。但如果用 STL 模型来表示这个四棱锥的话，那么至少需要 6 个三角面片，其中每个三角面片包含 3 个独立顶点，共需 18 个独立顶点，每个坐标位置至少有 3～4 个顶点重合。信息量没有丝毫增加，顶点数却增加了若干倍，这直接导致了 STL 模型在保存时占用磁盘或内存空间的增长，这也正是 STL 模型顶点冗余的原因。

下面我们从理论上分析一下 STL 模型中冗余的顶点个数。由欧拉定理可知，对任意简单多面体，它的顶点数 V、面片数 F 和棱边数 E 满足如下公式：

```
V + F - E = 2  (7-1)
```

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_133_0.png)

$E = \frac{3}{2}F$ (7-2)

如果觉得式(7-2)不好理解，我们不妨大胆发挥想象，将一条边拆成两个半边，其中一个半边属于一个三角形，另外一个半边属于另一个三角形，这样半边总数必然是 3F；然后我们再考虑将两个半边合并成一条边，这样就可以得到总边数为 1.5F。如果我们记 STL 模型中实际的顶点数为 Vact，那么显然

$V_{act} = 3F$ (7-3)

根据式(7-1)和(7-2)可得

$V = 2 + \frac{1}{2}F$ (7-4)

式(7-4)中的 V 表示理论所需的顶点数。进而我们可得：

$\frac{V_{act}}{V} = \frac{6F}{4 + F}$ (7-5)

由式(7-5)可知，当 F = 6 时，Vact / V = 3.6，这就是图 7.1 中模型的情况。对一般情况，当面片数 F 远大于 4 时，此时分母中的常数 4 可以忽略不计，那么 STL 模型中实际顶点数是理论上所需顶点数的 6 倍。这意味着什么？意味着 10MB 的模型数据，如果保存成 STL 格式，可能需要 60MB 的存储空间。

除了顶点冗余问题外，STL 模型的另一个问题是模型中面片与面片、面片与棱边、棱边与顶点等各几何元素之间的“相邻”关系是不明确的。具有相同坐标的顶点平均被保存了 6 次，每个顶点隶属于不同的三角面片、不同的棱边。面片与面片之间相互独立，信息通道完全被隔绝，我们没有办法从当前面片快速定位到与之相邻的面片，除非我们进行遍历搜索，但那样做将消耗大量的时间。

我们不妨发挥想象，假设现在我们可以从当前面片查询相邻面片，我们能做什么？也许我们可以用它来切片。首先，我们可以从任意一个面片出发，求取该面片和截平面的交线。然后我们查询该面片的相邻面片，并求取相邻面片和截平面的交线。接下来我们再去查询相邻面片的相邻面片，然后求交。依此不断迭代，直至所有面片被用完。在这一过程中，从相邻面片求得的截交线段也必然是相邻、相接的，因此在截交过程中我们就可以直接对交线依次进行拼接，整个截交和拼接过程将融为一体。如果我们把第一个面片称为“种子”，求取切片轮廓的过程类似于种子不断“追踪”相邻面片的过程，这将非常容易。

当然，以上设想都是建立在构建了 STL 模型中面片、棱边、顶点之间的相邻关系的基础上。在本书中，我们把空间多面体中面片、棱边、顶点这些几何实体之间的相邻、关联、包含、索引等关系统称为“拓扑关系”。一旦我们构建了 STL 模型的拓扑关系，我们就可以剔除模型中的冗余顶点，切片轮廓的计算也将变得非常简单，可以一步到位地实现。那么，我们又该如何高效地构建 STL 模型的拓扑关系呢？在解决这个问题之前，我们先来看一下针对 STL 模型面片、棱边、顶点的拓扑关系表示方法。

### 7.2 拓扑关系表示

一个 STL 模型包含一系列散乱无序的三角面片，其中每个三角面片又包含 1 个面、3 个顶点、3 条棱边。STL 模型中，顶点和面、边，面和顶点、边，边和顶点、面之间都应存在从属或包含的关系。这一节我们要做的就是整理顶点、边和面之间的拓扑关系，并在此基础上，建立相应的数据结构。

### 7.2.1 顶点拓扑结构

在 STL 模型中，每个三角面片都有独立的顶点，这导致即便是坐标相同的顶点，它们也各自拥有不同的顶点对象。这对于我们要建立的顶点拓扑关系显然不是一件好事。理想情况下，每个顶点位置上应该只有一个顶点对象，即我们先假设顶点不存在冗余的情况。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_134_0.png)

#### 图 7.2 顶点拓扑结构

对这个顶点，如图 7.2 所示，首先，它应该拥有 X、Y、Z 三个方向的坐标，以指示它所在的空间位置。其次，这个顶点被若干个三角面片共用，因此在顶点内部，应该有一个面片指针列表，用来保存所有用到该顶点的三角面片指针（引用）。在 STL 模型中，一个顶点至少被 3 个三角面片共用，但具体多少个三角面片会共用一个顶点，我们是无法确定的。此外，一个顶点还被若干棱边共用，因此在顶点内部，理应还有一个棱边指针列表，用来保存所有用到该顶点的棱边指针（引用）。在下面介绍的面片对象中，已经保存了棱边信息，而我们在顶点中已经保存了面片，因此，我们可以间接地从顶点存储的面片中找到相应的棱边信息。基于此，同时也为了简化顶点结构，我们顶点中不设置棱边指针。

根据以上讨论，我们可以用 Python 语言建立一个顶点类。由于这里描述的顶点和几何拓扑相关，因此我们将该顶点类取名为 TVertex，前缀 T 表示 Topology，即拓扑。此外，我们将本章涉及的所有类和函数都写在 TopoSlicer.py 文件中。TVertex 的具体实现代码如下：

### 7.2.2 棱边拓扑结构

接下来我们来看一下三角面片中棱边和顶点以及面片的拓扑关系。如图 7.3 所示，一方面，一条棱边有两个不同的顶点，因此，在棱边中，应该保存两个顶点的引用。另一方面，一条棱边的两侧各有一个三角面片，因此，在棱边中，也应保存和它相邻、以它为公共边的两个三角面片的引用。

我们可以按照以上两点去构建棱边的拓扑结构。但最终我们会因为诸如一条棱边到底应该属于哪个面片这样的问题而变得十分苦恼，因为现在一条棱边是同时属于两个三角面片的。那如何摆脱这种困境呢？其实我们之前在对公式(7-2)的解释中已经引出过解决方法，就是将一条棱边拆分成两个半边。

如图 7.4 所示，我们可以将图 7.3 中的公共棱边 e 拆分成两条半边 e1 和 e2，它们的位置和坐标完全一致，但从属于不同的面片，其中半边 e1 属于面片 f1，半边 e2 属于面片 f2。这样我们就可以建立半边的拓扑结构：一条半边应该有两个顶点的引用，而且它还应该有一个面片引用，用于保存它所从属的三角面片。此外，大多数情况下，半边总是成对出现的，在半边中，应该还有一个半边引用，用于保存和它分享同一棱边的另外一条半边，即对边。但是，需要注意的是，半边也不总是成对出现的，比如在未封闭 STL 模型的边界处。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_136_0.png)

根据以上分析，我们可以建立一个半边类，用于保存半边和顶点以及面之间的几何拓扑关系，我们把这个类命名为 TEdge，其中前缀 T 表示 Topology。同样地，我们把这个类写在 TopoSlicer.py 文件中，它的具体代码如下：

```
# TopoSlicer.py | TEdge 类定义,它表示具有拓扑关系的棱边( 半边) | 7 - 2
...... # 导入必要库,省略其他代码
class TEdge: # 定义 TEdge 类
    def __init__( self, tA, tB) : # 从两个 TVertex 点初始化
        self.A, self.B = tA, tB # 两个顶点引用 A、B
        self.F = None # 所从属的面片引用 F
        self.OE = None # 对边引用 OE
    def toTuple( self) : # 将边转化为元组( 6 维)
        if self.A.isSmaller( self.B) :
            return ( self.A.x, self.A.y, self.A.z, self.B.x, self.B.y, self.B.z)
        else :
            return ( self.B.x, self.B.y, self.B.z, self.A.x, self.A.y, self.A.z)
    def intersect( self, z) : # 边和 z 平面求交,返回交点
        if min( self.A.z, self.B.z) > z or max( self.A.z, self.B.z) < z :
            return None # 如果边高于或低于 z,无交点
        elif self.A.z == self.B.z == z :
            return None # 如果边位于 z 平面,无交点
        else :
            if z == self.A.z : return self.A.toPoint3D()
            else :
                ratio = ( z - self.A.z ) / ( self.B.z - self.A.z ) # 根据 z 比例计算
                vec = self.A.toPoint3D().pointTo(self.B.toPoint3D()).amplified( ratio)
                pnt = self.A.toPoint3D() + vec
                return pnt
```

我们先来看一下 TEdge 的 4 个属性，它们分别是 A、B、F 和 OE。其中 A 和 B 为 TVertex 类型的引用，表示半边的两个顶点，F 为半边所在的面片的引用，OE 为当前半边对边的引用。这里我们特别强调“引用”或“指针”的概念，是为了后期应用时能快速索引这些对象。在 Python 中，一个变量默认保存的就是一个对象的引用，因此我们不用刻意在意这些问题；但如果我们使用 C 或 C++ 来实现这些拓扑类，那么就需要保存对象的指针了。

在 TEdge 的初始化函数中，我们只对半边的两个顶点赋值，其他属性默认为 None。在本章接下来的代码中，我们会在函数的参数中使用小写的“t”前缀来表示它是拓扑类的对象。和 TVertex 类一样，我们同样为 TEdge 类定义了一个 toTuple 函数，这个函数将两个顶点的 6 个坐标转化成了一个 6 维的元组。为了保证两条位置和坐标完全一致的半边最终能够得到一样的 6 维元组，我们在这里用了一个小技巧，即对 TEdge 的两个 TVertex 顶点进行比较，保证较小的点的 3 个坐标落在 6 维元组的前 3 位。在这个过程中，我们用到了 TVertex 的 isSmaller 函数，这也正是我们之前定义 isSmaller 的原因。
