
```python
newPoly.addPoint( child.point(i).clone() )
newPoly.endPoint().w = 2 # 标记 newPoly 上进出点 w=2
for i in range( iAtDMin, parent.count(), 1):
    newPoly.addPoint( parent.point(i).clone() )
return newPoly        # 返回新曲线
def linkLocalOffsets( self ):   # 定义连续偏置曲线连接函数
    self.findParent()   # 首先确定所有曲线的直系父曲线
    for i in range(len( self.offsetPolyses ) - 1, 0, -1): # 逐一将所有直系子曲线连至直系父曲线
        childs = self.offsetPolyses[ i ]
        for j in range( len( childs ) - 1, -1, -1 ):  # 注意 range 里的参数取值
            child = childs[ j ]
            newPoly = self.linkToParent( child )  # 调用 linkToParent 函数
            parent = child.parent    # 用 newPoly 中的点替换原 parent
            parent.points = newPoly.points   # 中的点
            del childs[ j ]   # 重要:从列表中删除直系子曲线
    for path in self.offsetPolyses[ 0 ]:    # 最后将 offsetPolyses 中的剩余
        self.paths.append( path )   # 曲线转存到类的 paths 属性中
    self.offsetPolyses.clear()   # 清空临时列表 offsetPolyses
def genCpPath( boundaries, interval, shellThk ):   # 定义 GenCpPath 类接口函数
    return GenCpPath( boundaries, interval, shellThk ).paths
```

首先我们来看一下以上 linkToParent 函数的实现代码，这个函数的作用是将输入的直系子曲线(child)桥接到直系父曲线(parent)上，它的输出是一条包含了直系父曲线和直系子曲线上所有有序点的多段线。在这个函数中，简单起见，我们人为指定了直系子曲线的起点(pt)为直系子曲线上所有点到直系父曲线的最近点，注意，这是一种为了权衡计算量的近似处理。随后，我们通过遍历计算直系父曲线上的所有点到 pt 的距离，从中找出一个距离取到最小值 dMin 和 dMin 时的直系父曲线点序 iAtDMin。注意，当我们需要从一堆数中寻找一个最小值(最大值)，取到时首先需要初始化一个最小值(最大值)变量，最方便的初始化方式就是设置这个变量的值为实数所能取到的最大值(最小值)。接下来我们要逐一将直系父曲线、直系子曲线上的点按照一定的顺序添加到新建曲线( newPoly )上，首先是直系父曲线上序号为 0~iAtDMin 的点，然后是直系子曲线上起点到终点的所有点，最后是直系父曲线上序号为 (iAtDMin+1) 的点到直系父曲线终点。在这一过程中，我们对新曲线的两个点做了标记，一个点是从直系父曲线连入直系子曲线的那个点，另一个点是直系子曲线连出直系父曲线的那个点，也就是被标记的点和它的下一个点是额外添加的连接线段，这些标记对高效打印代码再生成来说非常重要。标记的方式是对点的 w 值赋 2, 默认情况下，点的 w 值为 1。这里使用 w 属性的原因是它是现成的，我们可以不用再为 Point3D 添加一个额外的属性。

接下来我们来看一下 linkLocalOffsets 函数，这是 GenCpPath 类中除 offset 函数外的第二个核心功能函数。在实现了 findParent 和 linkToParent 两个子函数之后，我们发现这个函数已经变得非常简单。对于 offset 函数得到的 OffsetPolyses，我们只需首先调用 findParent 函数寻找所有偏置曲线的直系父曲线，然后逐一将 OffsetPolyses 中的每条曲线通过 linkToParent 函数桥接到直系父曲线即可。这里必须注意的是，在桥接得到新曲线后，我们用新曲线上的点( Polyline 的 points 属性)替换原直系父曲线上的点，而不是直接用新曲线(newPoly)替换直系父曲线，这样做是为了保持 OffsetPolyses 中曲线元素的地址不变。试想，如果我们直接用新曲线替换原直系父曲线，那么我们将无法再用 OffsetPolyses 索引到新曲线。事实上，在以上代码中，这么操作的根本原因在于我们是通过直系子曲线的 parent 属性索引到直系父曲线的，我们并不知道这条直系父曲线在 OffsetPolyses 中的索引序号；假如我们知道它的序号，如 s 和 t，那么我们可以通过 OffsetPolyses[s][t] = newPoly 来实现曲线的直接替换。此外，在将直系子曲线桥接到直系父曲线后，我们还需注意的是必须从 OffsetPolyses 中移除相应直系子曲线。最后，在将各级直系子曲线桥接到直系父曲线后，OffsetPolyses 应该只保留若干原最外层的曲线地址，我们只需将这些曲线转存到 GenCpPath 类的 paths 属性即可，paths 就是 GenCpPath 最终输出的已经将所有偏置曲线连成一体的轮廓路径。

我们知道，paths 中路径的数量和原 OffsetPolyses 中最外层偏置曲线的数量一致。这些路径之间的连接只能通过“跳刀”的方式实现。对数控加工来说，跳刀意味着刀具从一条路径的终点抬起至安全平面，然后在安全平面上移动至另一条路径的起点上方，最后下降至另一条路径的起点。对数控加工来说，跳刀可以避免刀具在大幅移动过程中和工件发生干涉；但跳刀是一种无效切削过程，因此在路径规划中应尽量缩短跳刀路径长度。对 FDM 三维打印来说，我们无需抬起喷头，只需保证在跳刀过程中喷头不出丝材即可。

注意:在本书中，我们不打算处理 paths 中各条独立路径的优化连接问题。尽管看起来简单，但 paths 中各条独立路径的连接问题是一个典型的旅行商问题(travelling salesman problem，TSP)。TSP 的定义为：给定一系列城市和每对城市之间的距离，求解访问每一座城市一次并回到起始城市的最短回路(见图 8.32)。

![](img/c3ab49ac4eb80e7a0a66462a29869ca2_196_0.png)

图 8.32 蒙娜丽莎 TSP(10 万个点,图片来自 Concorde 官网)

简单的穷举法的时间复杂度为 O(n!)，其中 n 为旅行商需要遍历的城市个数。这是什么概念？举个例子，当 n 仅为 50 时，需要枚举的次数已超过 10^64 次。所以，大部分优化算法都趋向寻找 TSP 的近似解。目前，世界上最快的 TSP 求解器应该是丹麦人 Keld Helsgaun 开发的 LKH，有兴趣的读者可以到他的个人网站（http://akira.ruc.dk/~keld/）下载 LKH 源码（C 语言编写）及文档阅读使用。除此之外，Concorde（http://www.math.uwaterloo.ca/tsp/）也是一个比较著名的 TSP 求解器，有意思的是，目前，Concorde 提供了 Python 编程接口，有兴趣的读者不妨去下载练习。

最后，在 GenCpPath 模块的结尾，我们定义了一个 GenCpPath 类的全局接口函数 genCpPath，以方便我们后续使用该模块生成轮廓路径。它的输入参数和 GenCpPath 类的初始化参数完全一致，输出为已连接的路径列表。

## 本章小结

三维打印的常用填充路径包括轮廓路径和平行路径，这一章我们主要介绍的是轮廓路径的生成原理和方法。生成轮廓路径的基础是对表示打印区域的边界进行偏置，即平面轮廓的偏置算法。我们首先尝试了两种常规的轮廓偏置方法，基于线段平移的偏置和基于角平分线的偏置，但这两种方法都不能很好地处理局部自相交问题。为此，我们引入了一个专门用于平面轮廓裁剪及偏置运算的第三方库 Clipper。为了克服多边形轮廓数据格式的兼容性问题，我们构建了一个 Clipper 库的适配器。在此基础上，我们首先生成了边界轮廓的连续偏置曲线，然后通过识别各条偏置曲线之间的包含关系，将处于内部的直系子曲线逐条连接到直系父曲线上，从而得到若干连成一体的路径曲线，这些路径曲线就是我们所求的轮廓填充路径。我们将生成轮廓路径的流程和功能封装成一个 GenCpPath 类，并在最后对这个类进行测试，结果表明，如果除去编程语言本身的因素，GenCpPath 类能帮助我们在较短的时间内生成轮廓路径。
