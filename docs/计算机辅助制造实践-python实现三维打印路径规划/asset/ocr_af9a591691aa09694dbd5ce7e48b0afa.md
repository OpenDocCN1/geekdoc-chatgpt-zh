此外，我们在 TopoSlicer 类中实现了两个函数，分别是 findSeedFace 和 findNextFace。其中前者的功能是在扫描平面法的框架下，在和当前截平面相交的三角面片（即参数 faces）中寻找种子面片。它的实现原理非常简单，直接遍历输入的 faces，寻找首个未被使用过的面片并返回，如果所有 faces 均已被使用过，则返回 None，表示找不到种子面片。因为 faces 尺寸不会太大，因此我们不必太在意 findSeedFace 函数的执行效率。

最后，我们来看一下 findNextFace 函数，这是我们在 TopoSlicer 类中重点实现的函数，它的功能是根据当前面片寻找下一个目标邻面。但这个函数的输入并非当前面片，而是当前面片和截平面相交后得到的交点所在的半边和顶点，即 edges 和 node。然后我们按照以上介绍的原理对 edges 和 node 进行分类讨论，包括交点均在半边上以及交点分别落在半边和顶点上两种情况，从而找出目标邻面。

针对第二种情况，当目标邻面和当前面片通过 node 相连时，如图 7.14（b），我们调用了 TEdge 的 intersect 函数对 node 中存储的所有面片（node.faces，当前面片除外）进行遍历求交，那这里为什么要去执行费时的求交操作而不直接判断面片最低点 zMin、最高点 zMax 和截平面高度 z 的关系呢？其实我们已经考虑到了这一点，但是，zMin <= z 且 zMax >= z 是面片和截平面相交的必要非充分条件，因为当面片的一个顶点落在截平面上时，我们认定它们是不相交的。所以，这里我们不得不调用 intersect 函数，确保万无一失。在 intersect 函数中，我们使用了 node 的 z 坐标作为当前截平面的高度，这是因为在这种情况下，截平面的高度确实恰好等于 node 的 z 坐标，这样做的好处是可以为 findNextFace 函数节省一个必要的截平面高度的输入参数。
