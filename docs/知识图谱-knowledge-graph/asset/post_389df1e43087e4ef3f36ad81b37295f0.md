
如，获取 Freebase 中的 “32 位出生于二十世纪六十年代且出演过两部电影的男演员 ”( 32 actors born in the 1960s, with two films of each actor )，需要按照 Freebase 提供的结构化查询语言 MQL 的语法和 Freebase 中的词汇（实体、属性、关系等），输入如下相应的查询语句：[“film”：[“limit”：2]，“limit”：32，“type”：“/film/actor”，“/people/person/date_of_birth<”：“1970”，“/people/person/date_of_birth>=”：“1960”]。图 10.2 则是一个用来查询 DBpedia 的 SPARQL 窗口。这种结构化查询语言的优点是表达能力强，可以满足用户精细的信息需求。但是，它的缺点也很明显，用户不但需要掌握结构化查询语言的语法，而且还要充分了解知识库中的资源表示形式。如果不经过训练，普通用户很难利用此类接口找到需要的知识内容。在实际的互联网应用中，这种过于专业的交互方式会降低大部分用户的使用热情。因此，如何构建便捷易用的交互方式，是当前知识库应用中一个迫切需要解决的问题。

使用自然语言进行人机交互是最简便、最直接，也是最有效的一种模式，因此，人们迫切地需要面向知识库的自然语言问句理解技术，也就是说，人们希望知识问答系统可以直接响应自然语言的信息需求，而不需要用户输入计算机可理解的形式化查询语句。知识问答系统使用自然语言作为交互语言，为用户提供了一种更加友好的知识图谱查询方式。一方面，自然语言的表达能力非常强，可以表达用户精细而复杂的信息需求；另一方面，这种方式不需要用户接受任何的专业训练。由于其广阔的应用前景，知识库问答在学术界和工业界都成为研究热点。例如，图 10.3 展示的是一个应用了知识问答技术的商业搜索引擎的基本形态。现在，在百度搜索中直接输入一个完整的自然语言问句（事实型问题），其返回的第一条搜索结果就是知识图谱中的答案。

知识图谱一般表示为相互关联的事实三元组集合，如图 10.4 右侧所示。针对用户使用自然语言提出的问题，问答系统通过与知识图谱进行交互，检索相关知识点（事实集），进而进行知识推理得出最终准确的答案。目前，面向知识图谱的问答系统按照技术方法可以分为以下两种类型：

- （1）语义解析类型：考虑到知识图谱可以使用其支持的查询语言检索信息（如 MQL、SPARQL 等），那么如果能够把自然语言问句自动地转换为结构化查询语句，就可以直接通过检索知识图谱得到精确答案。例如，我们可以把问句“屠呦呦是哪里人？”转换为对应知识图谱的查询语句 “select ?o where {屠呦呦 出生地 ?o.}”，进行知识库检索能够得到答案“宁波市”。我们把这类模型称为基于语义解析的方法（图 10.4 中问答系统左侧模型）。
- （2）搜索排序类型：事实性问题一般都包含相关实体。通常来说，该问题的答案与相关实体在知识图谱中有比较紧密的联系，例如，它们之间可以通过一步或若干步关系路径关联。因此，首先可以通过搜索与相关实体有路径联系的实体作为候选答案，然后利用从问句和候选答案提取出来的特征进行比对，进而对候选答案进行排序得到最优答案。例如，利用问句中的实体“屠呦呦”在知识图谱中检索所有关系/路径，可以得到候选答案“宁波市”“中国”“诺贝尔医学奖”等候选实体，然后进行匹配和排序，选择最终答案。我们把这类模型称为基于搜索排序的方法（如图 10.4 中问答系统右侧模型）。

## 10.2.2 基于语义解析的方法

基于语义解析的问答方法是把问句转换为某种规范的形式化知识表示语句，其实质就是问句的语义解析（semantic parsing）。语义解析是指把一个自然语言句子映射为某种形式化的语义表示，语义表示形式会根据应用领域的不同而不同，典型的应用包括提供航空旅游信息服务接口的 ATIS[384]、用于机器人足球赛的 CLang[83] 和美国地理知识问答系统中使用 的 GeoQuery[519] 等。

具体来说，面向知识图谱的问句解析是指利用知识图谱中的资源项（实体、关系、类别等）表示自然语言问句的语义，并以逻辑公式等形式化语句进行语义表示的任务。例如，对于问句“有哪些城市靠近大上海？”，使用知识库中的符号（在知识库中，实体符号 “Shanghai_City”、类别符号 “City”、关系符号 “next_to” 分别表示问句中“大上海”“城市”和“靠近”的含义）可以把它表示为如下的逻辑形式：λx.next_to(x,Shanghai_City) ∧ City(x)。实际上，这是一个挑战性非常大的任务。首先需要对问句中的词/短语与知识图谱中的资源项（词汇表）进行映射；然后对匹配到的资源项进行组合；最后还需要对匹配和组合过程中存在的歧义进行消解，选择最正确的组合结果。基本上，可以把语义解析的方法分为基于训练数据的有监督方法和基于规则（或先验知识）的无监督方法。

### 10.2.2.1 有监督方法

语义解析的任务是把一种结构的数据（串行结构的自然语言句子或树形结构的句法树）转换成另一种结构的数据（逻辑表达式）。与自然语言处理中的其他任务一样，早期的语义解析方法大都依赖于人工规则（见下一小节）。随着二十世纪九十年代统计方法的兴起，人们开始利用机器学习模型从已知数据中学习显式或隐式的模式，期望对未知数据进行更好的预测。统计语义解析方法正是利用机器学习模型从已有数据中学习解析模型，不同的学习方法依赖于不同的学习数据。

![](img/9549a57f481f525254296dec39e94079_242_0.png)

典型的监督数据为图 10.5 中的形式，即 < 自然语言问句，逻辑表达式 > 的集合①。如何学习结构预测模型，对于新的问句（如“有哪些城市靠近大上海？”），生成其对应的逻辑表达式形式（如 λx.next_to(x, Shanghai_City) ∧ City(x)）。目前的方法主要根据语义组合原则构造完整的语义表示结果。语义组合原则是 Gottlob Frege 提出的理论[376]：一条复杂语句的含义由其子句的含义和它们的语义组合原则确定 [资源 10-10]。语义解析基于语义组合原则得到句子（问句）的形式化表示结果。例如，“有哪些城市靠近大上海？”是由“哪些城市”和“靠近大上海”的语义与它们之间的组合关系“且”确定的。因此，语义解析就包含两个需要解决的关键问题：

- 1) What states border Texas?
- λx.state(x) ∧ borders(x, texas)
- 
- 2) What is the largest state?
- argmax(λx.state(x), λx.size(x))
- 
- 3) What states border the state that borders the most states?
- λx.state(x) ∧ borders(x, argmax(λy.state(y), λy.count(λz.state(z) ∧ borders(y,z))))
- 
- 4) Utah borders Idaho.
- borders(utah, idaho)

图 10.5 语义解析监督数据样例：“问句”和“逻辑表达式”对

① 目前公布的语义解析学习数据，特别是面向知识图谱的语义解析数据都是英文的，因此，此处直接使用原始数据中的样例。另外，也有大量工作利用 < 自然语言问句，答案 > 这种弱监督数据，基于这类监督数据的语义解析模型把逻辑表达式建模为潜在/隐含变量，其本质还是学习自然语言问句到逻辑表达式的转换。

（2）当已知各个子句的含义及其形式化表示，如何对它们进行语义组合？ 考虑到对应辞典的构造与语义组合模型相关，本节首先介绍语义组合模型，然后介绍基础辞典的构造方法。

### 1. 语义组合模型

组合范畴语法（Combinatory Categorical Grammars, CCG）是一种有效的、表达能力强的语义组合语法形式，它能处理长距离依赖等多种自然语言现象[442, 443]。CCG 早期主要用于句法分析，2005 年 Luke Zettlemoyer 和 Michael Collins 首次将其应用于语义解析任务[522]。随后，大量的工作利用 CCG 进行语义解析。

CCG 的主要思想是把词的句法和语义信息组合在一起形成分析的基础辞典，依据组合语法规则自底向上对自然语言句子进行解析。CCG 的核心是辞典 Λ，它包括了语义组合过程中所需的全部语法和语义信息。辞典中的每个项由词/短语、句法类型/范畴和逻辑表达式组成。一般地，可以把辞典项标记为格式 w := s : l，表示词/短语 w 具有句法类型/范畴 s，并且相应的语义表达式为 l。句法类型/范畴 s 可以是原子类型/范畴（如 NP，S），也可以是复杂类型/范畴（如 A/B，其中 A 和 B 可以是原子类型也可以是其他复杂类型）。逻辑表达式 l 一般由知识库中的词汇加上逻辑符号（lambda 演算）组合而成。例如，下面的 CCG 辞典：

```
杭州 := NP : Hangzhou_City
上海 := NP : Shanghai_City
大上海 := NP : Shanghai_City
大上海 := NP : DaShanghai_Film
城市 := N : λx.City(x)
靠近 := (S \ NP)/NP : λx.λy.next_to(y,x)
哪些 := (S/(S \ NP))/N : λf.λg.λx.f(x) ∧ g(x)
```

第一个辞典项为简单项，“杭州”表示词/短语，NP 表示其对应的句法类型（或称为范畴），Hangzhou_City 表示其逻辑形式（使用知识库中词汇表示）。第五个辞典项城市 := N : λx.City(x) 使用了 lambda 算子表示知识图谱中的实体类型。最后一个辞典项稍微复杂一些，表示其右侧可以接受类型为 N 辞典项，接受的右侧辞典项的逻辑表达式作为参数 f 带入 λf.λg.λx.f(x) ∧ g(x) 中形成新的组合逻辑表达式。总之，辞典项的类型和语义表达式定义了该项如何与周围项进行组合以及组合之后得到的结果是什么。

仅有辞典，CCG 还不能够完成语义的组合过程。CCG 中还包括了一组组合规则，规定了相邻辞典项如何组合（包括句法类型的组合和逻辑表达式的组合)，该过程可以循环迭代地进行。CCG 主要包括如下两个基本组合规则①：

X/Y : f   Y : g ⇒ X : f(g)   (>) 
Y : g   X \ Y : f ⇒ X : f(g)   (<)

(>) 和 (<) 分别表示前向和后向组合规则，它们可以组合类型/范畴相匹配的辞典项，例如，对于左右相邻的类型的两个辞典项，他们的类型是 X/Y 和 Y，能够按照前向规则组合成类型为 X 的辞典项。组合项的子句和语义表达式也可以分别构造，首先，子句由左右两个辞典项的子句组合而成（如 “毗邻” 与 “上海” 组合得到 “毗邻上海”），其次，语义表达式为左右两个辞典项的语义表达式组合而成（如 λx.λy.next_to(y,x) 与 SH_City 组合得到 λy.next_to(y,SH_City)）。语义解析的分析过程依次使用这些组合规则，得到句法树，生成相应的逻辑表达式（S 表示最终句子的句法类型）。参考图 10.6 和图 10.7 中的例子，通过自底向上的解析过程，根据句子的句法结构组合成最终的逻辑表达式形式。

① 在实际应用过程中，可能还会使用其他更复杂的组合规则，例如：
- (1) 前向组合规则：
  A/B : f   B/C : g ⇒ A/C : λx.f(g(x))
- (2) 类型提升规则：
  NP : f ⇒ NP/(S \ NP) : λg.g(f)

一阶谓词逻辑和 lambda 演算是最常用的语义形式化表示模型，这种逻辑表示形式不是完全针对自然语言问答系统开发设计的，例如表示的语义结构与自然语言的句法结构有明显的结构差异（见文献 [284] 中的图 2），为了更好地面向知识库问答系统进行问句的语义解析，Percy Liang 等人 [285] 提出了依赖组合语义（Dependency-Based Compositional Semantics, DCS）并用于对问句在知识图谱中的语义进行形式化表示。他们使用了一种新的逻辑表示语言：Lambda DCS [283]，并在此基础上提出了相应的语义组合方法，该方法比组合范畴语法中的辞典项规则简单得多，只包含 join 和 intersect 两种组合规则。

在 DCS 中，逻辑形式以树结构表示，被称为 DCS 树，这种树结构与句子的句法结构平行。因此，相比较于一阶谓词逻辑和 λ 演算表示形式，DCS 树更容易解析和学习。DCS 树中的每个节点都表示了一个限制性满足问题（CSP），它可以通过有效的方式获得各个节点的目标值（根节点的目标值即为该逻辑形式的结果）。DCS 最早用于限定领域的知识库问答中 [284]，取得了包括 Geo880 在内的多个测试集中的最好效果。2013 年开始，Berant 和 Percy Liang 等人 [49, 50] 将 DCS 用于回答面向 Freebase 的问题，不仅提出了依赖组合语义方法和模型，还开源了相对应的完整知识库问答系统和评测平台 SEMPRE [资源10-11]。通过该开源项目，人们可以持续改进和提高问句解析的效果和知识库问答的性能 [478]。

### 2. 语义辞典构造

为了自动学习自然语言文本到逻辑表达式之间的映射关系，大多数方法都需要如下这种“句子-逻辑表示式”对标注数据：

句子： 哪些城市靠近大上海？

逻辑表达式： λx.City(x) ∧ next_to(x, Shanghai_City)

但是，从标注数据中只知道整个句子对应的整个逻辑表达式，而解析方法需要的是句子的片段（如词、短语等）和细粒度的逻辑表达式之间的匹配关系，例如，词语“靠近”对应 λx.λy.next_to(x, Shanghai_City)，短语“哪些城市”对应 λx.City(x)。

对于给定的句子“杭州靠近上海？”和逻辑表达式 next_to(Hangzhou_City, 上海_City)，我们希望得到如下辞典：

- 杭州 := NP : Hangzhou_City
- 上海 := NP : Shanghai_City
- 靠近 := (S \ NP)/NP : λx.λy.next_to(x, y)

因为不知道具体词汇对齐，可能也会得到如下的错误辞典：
靠近 := NP : Hangzhou_City
靠近上海 := (S \ NP)/NP : λx.λy.next_to(x,y)
实际上，辞典构建过程中是允许这种情况发生的，这种错误词典可以通过后期剪枝等操作进行过滤。例如，去除出现频率低的辞典项，去除不能够解析成正确逻辑表达式的辞典项。
为了从训练集中的 <句子，逻辑表达式> 对获得 <短语，子逻辑表达式> 的匹配关系，可以通过模板和规则从整个问句的逻辑表达式中提取子逻辑表达式，然后与问句中提取的短语进行匹配形成候选辞典项。每条规则包含一个能识别逻辑表达式子结构的触发词。对于每个能匹配触发词的逻辑表达式子结构，CCG 都需要为其创建一个对应的范畴。以图 10.8 中①的第二个规则为例，该规则定义了一个一元谓词 p 作为触发词的规则，这个一元谓词创建的范畴为 N : λx.p(x)。对于逻辑表达式 λx.major(x) ∧ city(x)，因为它包含两个一元谓词，因此，可以得到两个范畴，分别是 N : λx.major(x) 和 N : λx.city(x)。

图 10.8 辞典构建规则

| 输入触发词 | 输出范畴 | 示例 |

| 常量 c | NP : c | NP : 上海 |
| 一元谓词 p1 | N : λx.p1(x) | N : λx.state(x) |
| 一元谓词 p1 | S \ NP : λx.p1(x) | S \ NP : λx.state(x) |
| 二元谓词 p2 | (S \ NP)/NP : λx.λy.p2(y, x) | (S \ NP)/NP : λx.λy.next_to(y, x) |
| 二元谓词 p2 | (S \ NP)/NP : λx.λy.p2(x, y) | (S \ NP)/NP : λx.λy.next_to(x, y) |

| 第二个参数为常量 c 的二元谓词 p | N/N : λg.λx.p1(x, c) ∧ g(x) | N/N : λg.λx.next_to(x, 上海) ∧ g(x) |

| 数值型的一元函数 | S/NP : λx.f(x) | S/NP : λx.size(x) |
