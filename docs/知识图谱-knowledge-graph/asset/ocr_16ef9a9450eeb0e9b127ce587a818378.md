两个独立的 RNN 分别从头到尾和从尾到头处理原始对象，最后拼接相对应位置的隐层状态得到整体对象和每个时刻输入对象的表示。

基于编码器得到的抽象编码表示，另一个 RNN 用于解码，得到最终的语言输出序列 Y = [y₁, y₂, ⋯, y_{L_Y}]，例如，可以利用如下最基本的模型： s_t = f(y_{t-1}, s_{t-1}, c)； p(y_t|y< t, X) = g(y_{t-1}, s_t, c)，其中 s_t 表示解码 RNN 在时刻 t 的隐层状态，时刻 t 的目标词预测模型 p(y_t|y< t, X) 通常使用一个在限定词汇表（如三万个词）上的 softmax 分类器进行建模。

# 10.3.4 评价方法

相较于问答系统，对话系统更难以评价。因为，对话系统中，各个过程都需要人工进行评估和测试；另外，在问答中，每个问题都有精确的答案，但是对话中，对于同样的消息，可以有含义和形式都完全不同的回复，没有唯一的答案。因此，最理想的评价方式就是让人使用对话系统，然后从各个方面对满意度进行打分。表 10.3 就是 Walker 所采用的几个对话系统打分的方法[472]，用户可以对其打 1-5 分，通过计算平均分判断系统的相对性能。

表 10.3 对话系统评价中的用户满意度调查[472]

| 语音合成模块的性能 | 系统合成的语音是否容易理解？ |
| 文本识别模块的性能 | 系统是否理解了你说的语音内容？ |
| 任务易用性 | 是不是便于找到所需信息？ |
| 交互速度 | 系统交互的速度是否合适？ |
| 用户体验 | 在各个步骤上你是否知道自己都能说些什么吗？ |
| 系统反馈 | 系统回复内容的时候迟钝或延迟的频度如何？ |
| 期望行为 | 系统是不是按照你期望的执行？ |
| 未来使用 | 你认为你今后还会使用该系统吗？ |

对于对话系统性能的评价，人参与当然是最好的方式[446]，但是，每改变一次系统（加某个特征、加某个模块、重新学习模型等）都需要人进行评价，这在实践中显然不可行。因此，常常需要有些启发式的自动评价方法，它们能从不同方面对对话系统的性能进行评估比较。这些评价主要关注对话系统如何快速无障碍地满足用户的目标，因此所有评价指标都是基于如下两个准则：① 最大化任务完成度；② 最小化成本开销。
