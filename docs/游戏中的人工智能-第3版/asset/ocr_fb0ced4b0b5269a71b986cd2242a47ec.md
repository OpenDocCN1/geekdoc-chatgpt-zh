```
# 设置置换表中的模型
# (如果深度已经改变的话)
transitionTable.add(models[currentDepth + 1],
    currentDepth)
# 否则，没有要尝试的动作
else:
    # 回退到下一个最高深度
    currentDepth -= 1
# 迭代已经完成，并且没有发现动作
# 返回最小的截止值
return smallestCutoff, null
```

# 5. 数据结构和接口

世界模型与以前完全一样。Action 类现在需要一个 getCost，如果成本仅由时间控制，那么 getCost 可以与之前使用的 getDuration 方法相同。

我们在 Goal 类中添加了一个 isFulfilled 方法。当给出世界模型时，如果目标在该世界模型中得到满足，便返回 true。

启发式对象具有一个 estimate 方法，其返回从给定世界模型达到目标的成本的估计。

我们已经添加了一个 TranspositionTable 数据结构，其中包含以下接口：

```
class TranspositionTable:
    function has(worldModel: WorldModel) -> bool
    function add(worldModel: WorldModel, depth: int)
```

假设有一个可以从世界模型生成哈希整数的哈希函数，那么开发人员可以通过以下方式来实现置换表：

```
class TranspositionTable:
    # 保存单个表的条目
    class Entry:
        # 保存条目的世界模型
        # 所有条目刚开始的时候都是空的
        worldModel = null
    # 保存世界模型被发现时的深度
    # 这在刚开始是无限的
    # 因为在 add 方法中使用的置换策略可以按相同方式
    # 看待所有条目，无论它们是否是空的
```
