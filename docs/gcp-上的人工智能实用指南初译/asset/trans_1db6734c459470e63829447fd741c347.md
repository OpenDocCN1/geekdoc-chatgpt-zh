
# 第七章：Cloud TPU 与 TPUEstimator

## TPUEstimator 核心概念

*   `TPUEstimator` 使用 `model_fn`，它封装计算逻辑并将其分发到所有 Cloud TPU 核心。为获得最佳性能，应根据批量大小调整学习率。
*   跨 TPU 核心的计算复制与分发由 `model_fn` 完成。您必须确保计算仅包含 Cloud TPU 支持的操作。
*   通过 `input_fn` 函数对在远程主机 CPU 上运行的输入管道进行建模。
*   输入操作应使用 `tf.data` 编程。
*   每次调用都会将一个全局批次的输入数据处理到单个设备上。分片批量大小从 `batch_size` 参数获取。为获得最佳性能，请确保返回数据集而非张量。
*   应用代码始终在客户端运行，而工作进程执行 TPU 计算。
*   为保证输入管道的高性能，操作始终放置在远程工作器上，仅 `tf.data` 支持此特性。
*   为摊销 TPU 启动开销，模型训练步骤包含在 `tf.while_loop` 中；目前 `tf.while_loop` 仅能包装 `tf.data`。基于这两个原因，必须使用 `tf.data`。

## TPUEstimator 概念

从根本上说，TensorFlow 程序可采用图内复制或图间复制。`TPUEstimator` 采用图内复制运行 TensorFlow 程序。稍后我们将介绍两者的区别。

TensorFlow 会话主服务器并非在 `TPUEstimator` 中本地运行。我们的程序构建一个计算图，该图被复制到 Cloud TPU 的所有可用核心上，而 TensorFlow 会话主服务器被设置为首个工作服务器。输入管道位于远程主机上，以便快速向 Cloud TPU 提供训练样本。Cloud TPU 工作器间执行同步操作；即每个工作器在同一时刻执行相同的步骤。

## 从 TensorFlow Estimator 转换为 TPUEstimator

迁移至任何新工具时，建议从简单示例入手，再处理复杂场景。这有助于掌握工具的核心概念。

将 `tf.estimator.Estimator` 类转换为 `tf.contrib.tpu.TPUEstimator`，需执行以下步骤：

1.  将 `tf.estimator.RunConfig` 替换为 `tf.contrib.tpu.RunConfig`。
2.  配置 `TPUConfig` 以指定 `iterations_per_loop`。Cloud TPU 执行指定次数的训练循环迭代后返回主机。在完成所有 Cloud TPU 迭代前，不会保存检查点或摘要。
3.  在 `model_fn` 中，使用 `tf.contrib.tpu.CrossShardOptimizer` 包装优化器（如下所示）。您必须将 `tf.estimator.Estimator` 更改为 `tf.contrib.tpu.TPUEstimator` 以完成转换：

```
optimizer = tf.contrib.tpu.CrossShardOptimizer(
    tf.train.GradientDescentOptimizer(learning_rate=learning_rate))
```

默认 `RunConfig` 每 100 步为 TensorBoard 保存一次摘要，每 10 分钟写入一个检查点。

## 设置 TensorBoard 分析 TPU 性能

性能分析至关重要，TensorBoard 可帮助可视化和分析 Cloud TPU 性能。通过 TensorBoard，您不仅能监控应用，还能采纳其建议以提升性能。

设置 Cloud TPU 后，应安装最新版 Cloud TPU 分析器以生成 `capture-tpu-profile` 脚本。启动 TensorBoard 步骤如下：

1.  打开新的 Cloud Shell 启动 TensorBoard。
2.  运行以下命令设置环境变量，为云存储桶和模型目录创建变量。模型目录变量（`MODEL_DIR`）包含 GCP 目录名称，用于存储模型训练期间的检查点、摘要和 TensorBoard 输出。以下代码展示了设置 TensorBoard 所需的参数命令：

```
$ ctpu up --name=[Your TPU Name] --zone=[Your TPU Zone]

$ export STORAGE_BUCKET=gs://YOUR_ST_BUCKET_NAME
$ export MODEL_DIR=${STORAGE_BUCKET}/MODEL_DIRECTORY
```

TensorBoard 跟踪可通过两种方式查看：

*   静态跟踪查看器
*   流式跟踪查看器

若每个 TPU 事件超过一百万，必须使用流式跟踪查看器。

以下介绍如何启用静态跟踪查看器。

3.  在设置环境变量的同一 Cloud Shell 中运行：

```
$ tensorboard --logdir=${MODEL_DIR} &
```

4.  点击该 Cloud Shell 顶部的 `Web Preview`，打开端口 `8080` 查看 TensorBoard 输出。若需从命令行捕获输出，运行：

```
$ capture_tpu_profile --tpu=[YOUR_TPU_NAME] --logdir=${MODEL_DIR}
```

TensorBoard 提供以下功能：

*   多种可视化和分析性能的选项。
*   可视化计算图并利用 Profiler 优化应用性能。
*   XLA 结构图和 TPU 兼容性图对分析极具价值。
*   丰富的分析器选项：概览页面、输入管道分析器、XLA Op 性能剖析、跟踪查看器（仅限 Chrome）、内存查看器、吊舱查看器、流式跟踪查看器（仅限 Chrome）。这些工具对性能分析和应用调优大有裨益。

## 性能指南

开发模型时，调优以获取良好性能至关重要。本节介绍提升 Cloud TPU 上模型性能的技巧。Cloud TPU 本身性能强劲，但通过正确配置可进一步增强。

以下小节将讨论性能优化的重点领域。

### XLA 编译器性能

XLA 编译器是标准 TensorFlow 代码库的一部分。作为 ML 编译器，它为 CPU、GPU、TPU 等平台生成二进制文件。Cloud TPU 的 TensorFlow 模型先转换为 XLA 图，再由 XLA 编译器转换为 TPU 可执行文件。值得注意的是，TPU 硬件架构与 CPU、GPU 截然不同。

CPU 拥有少量高性能线程，GPU 拥有大量高性能线程。Cloud TPU 拥有 `128 * 128` 个 MXU（矩阵乘法单元），可作为单个超高性能线程执行，每周期可完成 16,000 次操作；或作为流水线连接的 `128 * 128` 个微小线程。

### 分块存储的影响

Cloud TPU 中的数组采用分块存储。这要求将其中一个维度填充为 8 的倍数，另一个维度填充为 128 的倍数。XLA 执行数据布局转换，以高效利用内存。这些转换由启发式算法驱动，对大多数模型效果良好，但偶尔可能失效。为获最佳性能，应尝试不同配置。

以下是最大化性能的关键要点：

*   将填充开销降至最低。
*   精心选择批量和特征维度的大小。

### 算子融合

若需组合执行多个操作，XLA 编译器会使用融合技术优化程序。融合操作即将多个可组合执行的操作合并。

例如，考虑以下操作序列：

```
tf_add = tf.add(x, y)
result = tf.multiply(tf_add, z)
```

无融合时，执行流程如下：

1.  循环顺序访问元素执行加法，结果保存在 `tf_add` 并存入临时内存：

```
for (i = 0; i < cnt; i++) {
    tf_add[i] = x[i] + y[i];
}
```

2.  再次访问加法结果并执行乘法：

```
for (i = 0; i < cnt; i++) {
    result = tf_add[i] * z[i];
}
```

启用融合后，数组访问与计算同时完成：

```
# 融合模式下，加法与乘法在同一循环中完成
for (i = 0; i < cnt; i++) {
    result = (x[i] + y[i]) * z[i];
}
```

此例中，内存往返次数减少，XLA 无需为 `tf_add` 分配额外空间。

融合为 Cloud TPU 带来诸多益处：减少内存传输、优化硬件利用率等。

当两个形状相同的张量结合时，广播隐式发生；但请注意，强制广播可能导致性能下降。

## 了解抢占式 TPU

抢占式 TPU 成本低廉，性能与按需 TPU 相当。但需注意：Google 可能随时为其他用途回收资源而终止它。下面介绍如何从控制台创建抢占式 TPU。

### 从控制台创建抢占式 TPU 的步骤

GCP 提供简洁界面创建抢占式 TPU，步骤如下：

1.  在 GCP 控制台的 Compute Engine 下选择 `TPU`。若 API 未启用，点击 `ENABLE` 启用。
2.  点击**创建 TPU 节点**。
3.  填写必填信息，勾选**抢占式**选项，点击**网络、描述、标签**链接。
4.  完善其他详情，点击屏幕底部的**创建**，TPU 即刻就绪。

### 抢占式 TPU 定价

抢占式 TPU 价格约为按需 TPU 的 30%。注意：抢占式 TPU 配额高于普通 TPU，且拥有独立配额。

### 抢占式 TPU 检测

若 TPU 已创建，可通过以下方式检测其是否为抢占式：

*   `ctpu` 命令：运行以下命令查看 TPU 详情。`TPU PREEMPTIBLE` 字段指示抢占状态：`READY` 表示非抢占式，`PREEMPTED` 表示已被抢占：

```
$ ctpu status
```

*   `gcloud` 命令：若未指定区域，将使用当前配置的 compute 区域。运行以下命令列出项目中可用的 Cloud TPU 计算区域：

```
$ gcloud compute tpus list
```

在选择 TPU 方案前，请评估您的用例是否适合抢占式 TPU，这能显著节省成本。

# 第八章：使用 Cloud ML Engine 实现 TensorFlow 模型

> 原文：[https://gitee.com/apachecn/apachecn-dl-zh/blob/master/docs/handson-ai-gcp/08.md](https://gitee.com/apachecn/apachecn-dl-zh/blob/master/docs/handson-ai-gcp/08.md)

**Google Cloud Platform**（**GCP**）上的 Cloud ML Engine 是一种无服务器方式，用于构建机器学习管道。该引擎利用底层平台组件，免除了基础设施配置与维护。数据科学家可专注于数据、模型与预测。这是在生产环境中快速部署并运行模型的理想途径。平台原生提供存储与计算弹性，几乎无限制地扩展模型训练及已部署模型的实时预测能力。

本章将深入探究 Cloud ML Engine，了解其构建模块，并使用 TensorFlow 模型实验机器学习管道。

本章主要涵盖：

*   了解 Cloud ML Engine 组件
*   训练与利用 TensorFlow 模型的步骤
*   在 Cloud ML Engine 中打包与部署训练应用
*   为训练作业选择合适的计算选项
*   监控 TensorFlow 训练模型作业

## 了解 Cloud ML Engine 组件

首先，明确 Cloud ML Engine 满足机器学习工作流的哪些环节。Cloud ML Engine 适用于：

*   训练机器学习模型
*   部署训练好的模型
*   使用部署模型进行预测
*   通过各类参数与 KPI 监控模型使用情况
*   模型管理与版本控制

Cloud ML Engine 拥有多个组件，各司其职，协同构建机器学习管道。这些服务组件利用底层平台资源，根据模型复杂度与数据量动态调用所需存储与计算。以下是 Cloud ML Engine 的核心组件。

## 训练服务

训练服务提供预定义算法，无需编码即可轻松训练。前提是训练数据符合平台算法支持的预期场景。

## 使用内置算法

编写本章时，Cloud ML Engine 支持以下算法：

*   **线性学习器**：基于 TensorFlow 估计器 `LinearClassifier` 与 `LinearRegressor`，适用于分类与回归。支持 **GPU** 加速，默认支持 **CPU** 加速器。
*   **宽和深**：旨在兼顾记忆训练数据与泛化输入的最佳算法。适用于分类、回归与排序问题。支持 GPU 加速，默认支持 CPU 加速器。
*   **XGBoost**：我们在“第 3 章：使用 XGBoost 的机器学习应用”详细介绍过。Cloud ML Engine 提供内置封装，并行简化预处理与训练两阶段。预处理阶段将分类与数值数据转换为统一的数值数据集。适用于点击率预测等场景。不支持 GPU 加速，仅支持 CPU。

选定算法后，需格式化输入（训练、评估、生产）数据以匹配内置算法预期模式。数据需以无标题的 **CSV** 格式提交，首列为目标变量。需在 GCP 上指定存储桶存放训练输出。Cloud ML Engine 为训练作业提供有限自定义（如指定机器类型）。

仅原始机器类型集可用于内置算法。还可指定作业运行区域（默认平台自动选择合适区域）。可通过设置学习率、批量大小等进行作业级自定义。可设定超参数调优目标阈值，以最大化准确率并最小化损失函数。内置算法在 GCP 共享空间的容器中运行，通过特定 **URI** 调用，如下表所示：

| 算法 | 容器 URI |
| --- | --- |
| 线性学习器 | `gcr.io/cloud-ml-algos/linear_learner_cpu:latest`<br>`gcr.io/cloud-ml-algos/linear_learner_gpu:latest` |
| 宽深 | `gcr.io/cloud-ml-algos/wide_deep_learner_cpu:latest`<br>`gcr.io/cloud-ml-algos/wide_deep_learner_gpu:latest` |
| XGBoost | `gcr.io/cloud-ml-algos/boosted_trees:latest` |
