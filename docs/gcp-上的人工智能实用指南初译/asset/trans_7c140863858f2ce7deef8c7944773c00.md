## Understanding Compute Options

`GCP` provides various compute options to deploy your applications and run them using the actual Google infrastructure. The available options are as follows:

*   `IaaS` (Infrastructure as a Service)
*   Containers
*   `PaaS` (Platform as a Service)

All compute options communicate with other `GCP` services and products, such as storage, networking, `Stackdriver`, security, and the Big Data product suite. Depending on the requirements of a given application, choose the appropriate compute option from `Compute Engine`, `Kubernetes Engine`, `App Engine`, and `Cloud Functions`.

Google compute options help you run and customize virtual machines of various sizes on Google infrastructure. It enables you to run containerized applications, and if you don't have to take care of infrastructure-related items, you can deploy code directly on the engine. Therefore, depending on your needs, Google provides multiple choices to leverage compute power, accelerate development efforts, and reduce time to market.

Next, we will discuss the following compute options in detail:

*   `Compute Engine`
*   `App Engine`
*   `Cloud Functions`
*   `Kubernetes Engine`

### Compute Engine

`Compute Engine` is the `IaaS` provided by Google Cloud; it is a virtual machine running in the Google infrastructure.

`Compute Engine` is available in all regions and zones provided by Google Cloud. It has storage options for persistent disks and local `SSD` (Solid State Drives). `SSD` has integrated circuits on chips internally and does not contain any spinning heads or disk drives to read data. Compared to hard disk drives, `SSD` is more durable and has faster read times. Persistent disk is network storage that can scale up to 64 TB, while local `SSD` is an encrypted drive that is actually attached to the server and can scale up to 3 TB.

When spinning up instances, users can choose from one of the predefined compute options or use a custom configuration. `Compute Engine` can be booted with `Linux` or `Windows` operating systems. These instances can be launched with `CPU`, `GPU`, and `TPU`, and since the infrastructure is provided by Google, users can perform OS-level customization.

Users can create managed and unmanaged instance groups in `Compute Engine`:

*   Managed instance groups will always contain identical VMs and support autoscaling, high availability, rolling updates, and more.
*   Unmanaged instance groups can contain machines with different configurations. Instance templates can be used when creating managed instance groups but cannot be used with unmanaged instance groups.
*   It is recommended to choose a managed and uniform instance group until there is a strong need for machines with different configurations in the same pool.

Let's quickly discuss an option that helps reduce cost. Use preemptible machines if possible. Preemptible VMs are short-lived and low-cost options that can be used when the workload is known and expected to finish within 24 hours. These VMs have a significant cost advantage, saving up to 80% compared to regular instances. Preemptible machines save up to 80% on costs, but there is a catch: Google can reclaim the instance from you within 30 seconds at any time. Google bills by the second and provides sustained use discounts to users.

### Compute Engine and AI Applications

When training models for `AI` (`ML`) applications, powerful machines are always needed to improve model efficiency by providing ample training data and reducing model training time. `Google Compute Engine` has multiple options to launch powerful compute instances and groups on which models can be trained and run. For training and running models, the capabilities of `CPU` and `GPU` should be used. For `TensorFlow` applications, machines with `TPU` should be used.

### App Engine

`App Engine` is the `PaaS` provided by Google Cloud; it is a fully managed serverless application platform.

`App Engine` is available in most regions covered by Google Cloud. You can think of `App Engine` as the infrastructure available for deployment; developers just need to focus on building the application and deploying it to `App Engine`, and everything else is taken care of. `App Engine` has great features such as autoscaling, traffic splitting, application security, monitoring, and debugging—all essential for deploying, securing, and scaling any application. Using tools like `Cloud SDK` and `IntelliJ IDEA`, developers can connect directly to `App Engine` and perform operations such as debugging source code and running `API` backends. One limitation of `App Engine` is the inability to customize its operating system.

`App Engine` has two different environments:

*   Standard
*   Flexible

`App Engine` Standard environment applications run in a sandbox environment and support running `Python`, `Java`, `Node.js`, `Go`, and `PHP` applications. On the other hand, `App Engine` Flexible environment applications run in `Docker` containers on Google `Compute Engine` VMs and support running `Ruby` and `.NET` applications in addition to the languages supported by the Standard environment. For more details on choosing between the Standard and Flexible environments, see [here](https://cloud.google.com/appengine/docs/the-appengine-environments).

`App Engine` is very useful for deploying any `Web` or mobile application. Based on resource usage, the infrastructure scales automatically, and Google charges only for the application resources used.

### App Engine and AI Applications

When running any mobile or `Web` application on `App Engine`, in many use cases, these applications require `AI`. These can be achieved when deploying applications in `App Engine`. The service can be deployed with Cloud Endpoints, and `Python` applications can be deployed in `App Engine` to load trained Machine Learning models. Once the model is accessed via `App Engine`, the service can send requests to the `Python` application and get responses in a consistent manner.

### Cloud Functions

`Cloud Functions` is the event-driven serverless `PaaS` provided by Google Cloud, ideal for microservices architecture.

`Cloud Functions` is available in most regions covered by Google Cloud. They are primarily used for small or single-purpose functions, such as calling other services or writing events to a Pub/Sub topic. There are some great features in `Cloud Functions` that provide agility and zero-downtime maintenance. `Cloud Functions` can autoscale and are highly available. You can use `Cloud Functions` to connect to most Google Cloud services.

`Cloud Functions` can be developed using `JavaScript` or `Python`. Users only pay for `Cloud Functions` during execution time. This makes it very cost-effective.

### Cloud Functions and AI Applications

When running any application, if the user wants to invoke `Cloud ML` or `Cloud Vision` `APIs` based on a specific event, `Cloud Functions` can be used.

### Kubernetes Engine

`Kubernetes Engine` is a managed service provided by Google Cloud; it is used to deploy and run containerized applications. The following are the features of `Kubernetes Engine`:

*   It is available in all regions and zones provided by Google Cloud.
*   Under the `Kubernetes` cluster, Google actually runs `Compute Engine`, so most of the advantages we have on `Compute Engine` will come with `Kubernetes Engine`, along with the additional services it provides.
*   In a `Kubernetes` cluster, VMs with custom `OS` images can be used, and the cluster will autoscale the custom images.
*   `Kubernetes` clusters are highly secure and are `HIPAA` and `PCI DSS 3.1` compliant.
*   It comes with a dashboard service that allows users to manage it.
*   It autoupgrades and autorepairs.
*   It supports common `Docker` images and a private container registry through which users can access private `Docker` images.
*   `Kubernetes` clusters can be integrated with `Stackdriver` for monitoring and logging of the cluster.

If your application can handle a scenario where one of the VMs fails, then using preemptible instances with a `Kubernetes` cluster makes a lot of sense, as it can save significant costs.

### Kubernetes Engine and AI Applications

When training models for `AI` (`ML`) applications, powerful machines are always needed to improve model efficiency by providing ample training data and reducing model training time. `Kubernetes` clusters can be built with `GPU` to train models and run `ML` workloads. This can benefit many Machine Learning applications that require a managed containerized cluster with powerful `GPU` machines.

### Cloud Storage

`Cloud Storage` is the object storage provided by `GCP`. The following are the features of `Cloud Storage`:

*   It can store any amount of data and various formats of data, including structured, unstructured, video files, images, binary data, and more.
*   Users can store data in four different buckets in `Cloud Storage` based on the following requirements: Multi-regional storage, Regional storage, Nearline storage, and Coldline storage.
    *   If data is accessed frequently worldwide, go to the "Multi-regional" bucket.
    *   If data is accessed frequently in the same geographic region, go to the "Regional" bucket. For data accessed once a month, use `Nearline`; for data accessed once a year, use the `Coldline` bucket.
    *   Choosing the bucket is important because of the associated costs.
*   By default, data stored in `Cloud Storage` is highly available and encrypted. If you want to customize the default encryption, you can easily do so.
*   `Cloud Storage` provides `APIs` and tools for data transfer in and out.
*   Users can use the `gsutil` tool to transfer data from on-premises, or use the Storage Transfer Service to transfer data from other clouds.
*   All data transfers are secure and encrypted in transit.
*   With features like Object Lifecycle Management to move data to cheaper, less frequently used storage, and users can use `ACL` (Access Control Lists) to secure data access.
*   This is a centralized service and is integrated with all compute and processing options.
*   Services like `BigQuery` and `Dataproc` can access data stored in `Cloud Storage` to create tables and use them for processing.

With all its features, `Cloud Storage` is the most commonly used storage option on `GCP` and is one of the cheapest storage options. Depending on the storage class and access pattern, pricing ranges from $0.007 per GB per month to $0.036 per GB per month.

### Cloud Storage and AI Applications

`Cloud Storage` can help in various `AI` and `ML` use cases. Most Big Data migrations or modern data platforms use `Cloud Bigtable` to build their `NoSQL` databases. For example, `Spark ML` applications will access data in `Cloud Bigtable` and store results in it. `Cloud Storage` has already been used for use cases like genomics, video transcoding, data analytics, and computation.

### Cloud Bigtable

`Cloud Bigtable` is the fully managed `NoSQL` database system provided by `GCP`. It can scale to petabytes of data with extremely low latency and high throughput. The features of `Cloud Bigtable` are as follows:

*   `Cloud Bigtable` is best suited for use cases with very heavy read and write operations; that said, `Bigtable` can be used for both streaming and batch operations.
*   Each table in `Bigtable` contains a single column family, and each column family has multiple column qualifiers. At any given time, column qualifiers can be added to a column family.
*   Data is stored in tables as key-value pairs. When designing tables in `Bigtable`, the most important thing is the row key column. Only based on this column will data be evenly distributed in the table, and users will get optimized performance when reading data.
*   If the data in the row key column is skewed, hotspots will occur. For example, if the row key is a city in the table and data is skewed only for one city, then data will not be evenly distributed, and reads will not be optimized.
*   On the other hand, if the application is receiving data from multiple cities evenly, then data will be distributed fairly, and read operations will be optimized.
*   Update operations can be performed at the row level in `Bigtable`.
*   `Google Cloud Bigtable` is integrated with services like `Stackdriver`, `Cloud Dataflow`, `Dataproc`, and `Hadoop`.
*   It also supports the industry-standard `HBase API`. By default, all data stored in `Bigtable` is encrypted, and access control can be used to provide appropriate access to users.
*   For each `Bigtable` node, the user pays $0.65 per hour, `SSD` storage is charged at $0.17 per GB per hour, and `HDD` storage at $0.026 per GB per hour.

### Cloud Bigtable and AI Applications

`Cloud Bigtable` can act as storage for various `AI` and `ML` use cases. Most Big Data migrations or modern data platforms use `Cloud Bigtable` to build their `NoSQL` databases. For example, streaming `ML` applications can use `Bigtable` effectively as a backend.

### Cloud Datastore

`Cloud Datastore` is the fully managed, scalable `NoSQL` database provided by `GCP`. Datastore is built on top of `Bigtable`; that is why it is highly scalable. The features of `Cloud Datastore` are as follows:

*   `Cloud Datastore` provides some important `RDBMS` features, such as `ACID` support, `SQL`-like queries, and more.
*   To easily use Datastore, you should understand the basic terminology and its similarity to `RDBMS`. This is a comparison table of `RDBMS` and Datastore terminology:

| | `Datastore` | `RDBMS` |
| --- | --- | --- |
| Object Category | Kind | Table |
| Single Object | Entity | Row |
| Unique Identifier | Key | Primary Key |
| Property Information | Property | Field |

If Datastore is so similar to `RDBMS`, why use Datastore? The reason is simple: it provides scalability that `RDBMS` cannot achieve.

*   `Google Cloud Datastore` is integrated with services like `Stackdriver`, `App Engine`, and `Compute Engine`.
*   It is highly available and comes with an admin dashboard. By default, all data stored in Datastore is encrypted, and access control can be used to provide appropriate access to users.
*   For 1 GB of storage, the user is charged $0.18, $0.18 for 100,000 entity writes, $0.06 for 100,000 entity reads, and $0.02 for the same number of deletes.

### Cloud Datastore and AI Applications

`Cloud Datastore` can act as storage for `AI` and `ML` use cases for large `Web` applications. Any e-commerce website hosted on `GCP` can use Datastore to store data, and using this data, `ML` models can be trained and desired recommendations can be served to users, which in turn can improve customer satisfaction.
