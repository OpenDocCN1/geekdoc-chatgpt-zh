
弹出栈顶元素：
If 栈顶元素=goal, 返回并结束；
Else 以任意的顺序把栈顶元素的子节点压入栈中；
End
End while
深度限制加 1, 并返回 2;
End

## 3.3.4 搜索最优策略的比较

宽度优先搜索、深度优先搜索和迭代加深搜索都可以用于生成和测试算法，然而宽度优先搜索需要指数数量的空间，深度优先搜索的空间复杂度与最大搜索深度呈线性关系。迭代加深搜索对一棵深度受控的树采用深度优先搜索，结合了宽度优先搜索和深度优先搜索的优点。与宽度优先搜索一样，它是最优的，也是完备的，但对空间要求和深度优先搜索一样是适中的。

## 3.4 启发式搜索

前述的各种搜索方法都是按事先规定的路线进行搜索的，没有采用问题本身的特征信息，具有较大的盲目性，产生的无用节点较多，搜索空间较大，效率不高。如果能够利用问题自身的一些特征信息来指导搜索过程，则可以缩小搜索范围，提高搜索效率。

启发式搜索通常用于两种问题：正向推理和反向推理。正向推理一般用于状态空间的搜索，推理是从预先定义的初始状态出发向目标状态方向执行；反向推理一般用于问题规约中，推理是从给定的目标状态向初始状态执行的。使用启发式函数的正向推理搜索算法包括 A*算法等，反向推理算法包括 AO*算法等。

### 3.4.1 启发性信息和评估函数

如果在选择节点时能充分利用与问题有关的特征信息，估计出节点的重要性，就能在搜索时选择重要性较高的节点，以利于求得最优解，这个过程称为启发式搜索。“启发式”实际上代表了“大拇指准则”（rule of thumb）：在大多数情况下是成功的，但不能保证一定成功。

与被解问题的某些特征有关的控制信息（如解的出现规律、解的结构特征等）称为搜索的启发信息，反映在评估函数中。评估函数的作用是估计待扩展节点在问题求解中的价值，即评估节点的重要性。

评估函数 $f(x)$ 定义为从初始节点 $S_0$ 出发，约束地经过节点 $x$ 到达目标节点 $S_g$ 的所有路径中最小路径代价的估计值，其一般形式为  
$$f(x) = g(x) + h(x)$$ （3.14）

式中，$g(x)$ 为从初始节点 $S_0$ 到节点 $x$ 的实际代价；$h(x)$ 为从节点 $x$ 到目标节点 $S_g$ 的最优路径的评估代价，体现了问题的启发式信息，其形式要根据问题的特性确定，被称为启发式函数。

启发式方法把问题状态的描述转换成对问题解决程度的描述，用评估函数的值表示。

### 3.4.2 启发式搜索 A 算法

在一般图搜索过程中，如果重排 OPEN 表是依据 $f(x) = g(x) + h(x)$ 进行的，则称该过程为启发式搜索过程。该过程按 $f(x)$ 排序 OPEN 表中的节点，$f(x)$ 值最小者排在首位，优先加以扩展，体现了最佳优先（best-first）搜索策略的思想。

启发式搜索过程的设计与一般图搜索过程相同，也分为如下两个阶段。

- 1）初始化。建立只包含初始状态节点 $S_0$ 的搜索图：

```
G:={ $S_0$ }  
OPEN:= $\{ S_0$ }  
CLOSE:= $\{ \}$
```

- 2）搜索循环。

- ① Move-First (OPEN): 取出 OPEN 表首的节点 $n$。
- ② 扩展出 $n$ 的子节点，插入搜索图 $G$ 和 OPEN 表。
- ③ 适当地标记和修改指针（子节点→父节点）。
- ④ 排序 OPEN 表（评价函数 $f(n)$ 的值排序）。

通过循环地执行该算法，搜索图会因不断有新节点加入而逐步长大，直到搜索到目标节点。

如同一般图搜索过程一样，启发式搜索过程标记和修改指针的方法具体如下。

- 1）扩展出 $n$ 的子节点 $n_i$，插入搜索图 $G$ 和 OPEN 表。对每个子节点 $n_i$，计算

```
$f(n,n_i) = g(n,n_i) + h(n_i)$ （3.15）
```

- 2）适当地标记和修改指针（子节点→父节点）。

- ① 全新节点：$f(n_i) = f(n, n_i)$。
- ② 已出现在 OPEN 表中的节点。
- ③ 已出现在 CLOSE 表中的节点。

```
IF $f(n_i) > f(n, n_i)$ THEN  
    令 $f(n_i) = f(n, n_i)$  
    修改指针指向新父节点 $n$。
```

- 3）排序 OPEN 表（$f(n)$ 值从小到大排序）。

## 算法 3.4 A 算法。

```
Procedure Heuristic Search A  
Begin  
建立一个只有初始节点 $S_0$ 的搜索图 $G$，把 $S_0$ 放入 OPEN 表，计算 $f(S_0)=g(S_0)+h(S_0)$;
假定初始时 CLOSE 表为空；
While OPEN 表不空 do
Begin
从 OPEN 表中取出 f 值最小的节点（第一个节点），放入 CLOSE 表中，假设该节点的编号为 n；
If n 是目标，则停止，返回 n，根据 n 的反向指针指出从初始节点到 n 的路径；
Else do
Begin
扩展节点 n；
If 节点 n 有后继节点：
Begin
① 生成 n 的子节点集合 {n_i}，把 n_i 作为 n 的后继节点加入 G 中，并计算 f(n_i)。
② If n_i 未曾在 G 中出现过（未曾在 OPEN 表和 CLOSE 表中出现过） then 将它们配上第①步计算出的 f 值，设置返回到 n 的指针，并把它们放入 OPEN 表中。
③ If n_i 已经在 OPEN 表中 then 该节点一定有多个父节点，在这种情况下，计算当前的路径 g 值，并和原有路径的 g 值相比较。若前者大于后者，则不做任何更改；若前者小于后者，则将 OPEN 表中的该节点的 f 值更改为第①步计算出的 f 值，返回指针更改为 n。
④ If n_i 已经存在于 CLOSE 表中 then 该节点同样也有多个父节点。在这种情况下，同样计算当前路径的 g 值和原来路径的 g 值。如果当前的 g 值小于原来的 g 值，则将表中该节点的 g、f 值及返回指针进行类似第③步的修改，并考虑修改表中通过该节点的后继节点的 g、f 值及其返回指针。
⑤ 按 f 值从小到大的次序，对 OPEN 表中的节点进行重新排序。
End If
End Else
End While
End
```

### 3.4.3 实现启发式搜索的关键因素

鉴于启发式搜索在提高搜索效率和解决组合爆炸问题中的作用，相关研究成为人工智能形成和成长期的重要议题之一，产生了许多成熟的研究成果，并且至今启发式搜索仍是一个活跃的研究领域。下面就实现启发式搜索应考虑的关键因素进行讨论。

### 1. 搜索算法的可采纳性

在搜索图存在从初始状态节点到目标状态节点解答路径的情况下，若一个搜索算法总能找到最短（代价最小）的解答路径，则称该算法具有可采纳性。例如，宽度优先的搜索算法就是可采纳的，只是其搜索效率不高。

### 2. 启发式函数的强弱及其影响

首先引入评价函数 f*：

f*(x) = g*(x) + h*(x) (3.17)

式中，f*(x)、g*(x)、h*(x) 分别为当经由节点 x 的最短（代价最小）解答路径找到时实际的路径代价（长度）、该路径前段（自初始状态节点到节点 x）代价和后段（自节点 x 到目标状态节点）代价。

在存在多个目标状态的情况下，h*(x) 取 h*(x, x_g) 中最小者 (i=1,2,...)。

可以用 h(x) 接近 h*(x) 的程度衡量启发式函数的强弱。当 h(x) < h*(x) 且两者差距较大时，h(x) 过弱，从而导致 OPEN 表中节点排序的误差较大，易于产生较大的搜索图；反之，当 h(x) > h*(x) 时，则 h(x) 过强，使 A* 算法失去可采纳性，从而不能确保找到最短解答路径。显然，设计恒等于 h*(x) 的 h(x) 是最理想的，可确保产生最小的搜索图（因为 OPEN 表中节点的排序正确），且搜索到的解答路径是最短的。

对于复杂的问题求解任务，设计恒等于 h*(x) 的 h(x) 是不可能的。为此，取消恒等约束，设计接近又总是不大于 h*(x) 的 h(x) 成为应用 A* 算法搜索问题解答的关键，以压缩搜索图，提高搜索效率。可以证明，对于解决同一问题的两个算法 A1 和 A2，若总有 h1(x) <= h2(x) <= h*(x)，则 t(A1) >= t(A2)。其中，h1、h2 分别为算法 A1 和 A2 的启发式函数，t 为相应算法达到目标状态时搜索图包含的节点总数。再以八数码游戏为例，因为 w(x) <= p(x) <= h1(x) <= h2(x) <= h*(x)，所以采用 p(x) 扩展出的节点总数不会比采用 w(x) 时多。更明显的例子是采用宽度优先搜索解决八数码问题，其相当于 h(x) = 0，则图 3.13 中的搜索树会变得比采用 w(x) 时庞大得多。

### 3. 设计 h(x) 的实用考虑

随着问题求解任务复杂程度的增加，即便是设计接近又总是不大于 h*(x) 的 h(x) 也变得更困难，而且往往会导致在 h(x) 上的繁重计算工作量。若 h(x) 的计算开销过大，即使最短路径找到了，实际的搜索代价也会居高不下，因为路径选择代价随 h(x) 的计算开销而增大。删除 h(x) <= h*(x) 的约束，会使 h(x) 的设计容易得多，却由此丢失了可采纳性（可能丢失最短解答路径）。不过在许多实用场合，人们并不要求找到最优解答（最短解答路径），通过牺牲可采纳性来换取 h(x) 设计的简化和减少计算 h(x) 的工作量还是可行的。

从评价函数 f(x) = g(x) + h(x) 可以看出，若 h(x) = 0，则意味着先进入 OPEN 表的节点会优先被考察和扩展，因为即使不以 d(x) 作为 g(x)，通常先进入 OPEN 表的节点也具有较小的 g(x) 值，从而使搜索过程接近于宽度优先搜索策略；反之，若 g(x) = 0，则导致后进入 OPEN 表的节点会优先被考察和扩展，因为后进入 OPEN 表的节点往往更接近目标状态，即 h(x) 值较小，从而使搜索过程接近于深度优先搜索策略。

为了更有效地搜索解答，可使用评价函数 f(x) = g(x) + w h(x)，其中 w 用作加权。在搜索图的浅层（上部），可让 w 取较大值，以使 g(x) 所占比例很小，从而突出启发式函数的作用，加速向纵深方向搜索；一旦搜索到较深的层次，又让 w 取较小值，以使 g(x) 所占比例很大，并确保 w h(x) <= h*(x)，从而引导搜索向横广方向发展，寻找到较短的解答路径。

### 3.4.4 A*算法

### 1. A*算法的概念和过程

为了考察启发式搜索 A 算法的可采纳性，将评价函数 f 与 f* 相比较，实际上，f(x)、g(x) 和 h(x) 分别是 f*(x)、g*(x) 和 h*(x) 的近似值。在理想的情况下，设计评价函数 f 时可以让 g(x) = g*(x)，h(x) = h*(x)，则应用该评价函数的 A 算法能在搜索过程中，每次都正确地选择下一个从 OPEN 表中取出加以扩展的节点，从而不会扩展任何无关节点，就可以顺利地获取解答路径。然而，g*(x) 和 h*(x) 在最短解答路径找到前是未知的，因此几乎不可能设计出这种理想的评价函数；而且对于复杂的应用领域，即使设计接近于 f* 的 f，往往也是困难的。一般来说，g(x) 的值容易从已生成的搜索树中计算出来，不必专门定义计算公式。例如，以节点深度 d(x) 作为 g(x) 的值，并有 g(x) >= g*(x)。然而，h(x) 的设计依赖于启发式知识的应用，所以如何挖掘贴切的启发式知识是设计评价函数乃至 A 算法的关键。

前述八数码游戏（图 3.13）使用的启发式函数 w(x)不够贴切，从而在搜索过程中错误地选用了节点 d 加以扩展。其实可以设计更接近于 h*(x) 的 h(x)，如 p(x)，p(x) 的值是节点 x 与目标状态节点相比较（每个错位棋牌在假设不受阻挡的情况下），移动到目标状态相应位置所需走步（移动次数）的总和。显然，p(x) 比 w(x) 更接近于 h*(x)，因为 p(x) 不仅考虑了错位因素，还考虑了错位的距离（移动次数）。

返回图 3.13，若启发式函数 h(x) 采用 p(x)，则初始状态节点的评价函数值 f(s)=5。在第二个搜索循环结束时，OPEN 表中的节点排序为 e a c d i，这些节点的评价函数值依次为 5 7 7 7 7；而在使用 w(x) 的情况下，OPEN 表中的节点排序为 d e a c i，评价函数值依次为 5 5 6 6 6。显然，p(x) 使得用 w(x) 不能区分的节点 d(5) 和 e(5) 区分为 d(7) 和 e(5)，从而搜索过程不再会错误选择节点 d，而是一下子就选对了节点 e 加以扩展，如图 3.14 所示。

![](img/01b3dd63f105ee2f61ade787bae553f5_76_0.png)

图 3.14 应用启发式函数 p(x) 的八数码问题搜索图

可以证明，若确保对于搜索图中的节点 x 总是有 h(x) <= h*(x)，则 A 算法具有可采纳性，即总能搜索到最短（代价最小）的解答路径。

称满足 h(x) <= h*(x) 的 A 算法为 A*算法。

A*算法过程如下。

- 1）把 S 放入 OPEN 表，记 f=h，令 CLOSE 为空表。
- 2）若 OPEN 为空表，则宣告失败并退出。
- 3）选取 OPEN 表中未设置过的具有最小 f 值的节点为最佳节点 BestNode，并把它放入 CLOSE 表。
- 4）若 BestNode 为一目标节点，则成功求得一解并退出。
- 5）若 BestNode 不是目标节点，则扩展之，产生后继节点 Successor。
- 6）对每个 Successor 进行下列过程。

- ① 建立从 Successor 返回 BestNode 的指针。
- ② 计算 g(Successor)=g(BestNode)+g(BestNode,Successor)。
- ③ 如果 Successor \in OPEN，则此节点为 OldNode，并把它添至后继节点表 BESTNODE 中。
- ④ 比较新旧路径代价。如果 g(Successor)<g(OldNode)，则重新确定 OldNode 的父辈节点为 BestNode，记下较小代价 g(OldNode)，并修正 f(OldNode)值。
- ⑤ 若至 OldNode 的代价较低或一样，则停止扩展节点。
- ⑥ 若 Successor 不在 OPEN 表中，则看其是否在 CLOSE 表中。
- ⑦ 若 Successor 在 CLOSE 表中，则转向第③步。
- ⑧ 若 Successor 既不在 OPEN 表中又不在 CLOSE 表中，则把它放入 OPEN 表中，并添入后继节点表 BESTNODE 中，然后转向第⑦步。

- 7）计算 f 值，然后转入第②步。

### 2. A*算法性质

首先定义下面的符号。

- C(n_i, n_j)：从节点 n_i 到节点 n_j 的费用。
- K(n_i, n_j)：从节点 n_i 到节点 n_j 最小代价路径的费用。
- G：一个目标节点。
- G：目标节点的集合。
- P_{n->g}：从节点 n 到 g 的路径。
- P_{n->G}：从节点 n 到目标节点集合 G 的路径集合。
- g*(x)：从起始节点（根节点）s 到节点 n 所有路径的最小费用，g*(n) = K(s, n)。
- h*(x)：从节点 s 到 G 的所有路径中最小的费用，对所有的 g \in G，有 h*(n) = min K(n,g)。
- C*：从节点 s 到 G 的所有路径中最小代价路径的费用，C* = h*(s)。
