# ## 2.5.2 脚本的结构

脚本表述的是特定范围内原型事件的结构，用一组槽来描述这些事件的发生序列。脚本通常由开场条件、角色、道具、场景和结局等几部分组成，具体如下。

+   1) 开场条件：给出在脚本中所描述事件的前提条件。
+   2) 角色：一些用来表示在脚本所描述事件中可能出现的有关人物的槽。
+   3) 道具：一些用来表示在脚本所描述事件中可能出现的有关物体的槽。
+   4) 场景：用来描述事件发生的真实顺序。一个事件可以由多个场景组成，而每个场景又可以是其他场景的脚本。
+   5) 结局：给出在脚本所描述事件发生以后所产生的结果。

用脚本表示知识的步骤如下。

+   第 1 步，确定脚本运行的条件和脚本中涉及的角色、道具。
+   第 2 步，分析所要表示的知识中的动作行为，划分故事情节，并将每个故事情节抽象为一个概念，作为分场景的名字，每个分场景描述一个故事情节。
+   第 3 步，抽取各个故事情节中的概念，构成一个原语集，分析并确定原语集中各原语间的相互依赖关系与逻辑关系。
+   第 4 步，把所有的故事情节都以原语集中的概念及它们之间的从属关系表示出来，确定脚本的场景序列，每一个子场景可能由一组原语序列构成。
+   第 5 步，给出脚本运行后的结局。

# ### 例 2.11 下面以夏克的“餐厅”脚本为例来说明各个部分的组成及脚本表示知识的步骤。

+   1) 开场条件：①顾客饿了，需要进餐；②顾客有足够的钱。
+   2) 角色：顾客，服务员，厨师，老板。
+   3) 道具：食品，桌子，菜单，钱。
+   4) 场景。
+   场景 1: 进入。
+   ① PTRANS：顾客进入餐厅。
+   ② ATTEND：寻找桌子。
+   ③ PTRANS：走到确定的桌子旁。
+   ④ MOVE：在桌子旁坐下。
+   场景 2: 点菜。
+   ① ATRANS：服务员给顾客菜单。
+   ② MBUILD：顾客点菜。
+   ③ ATRANS：顾客把菜单还给服务员。
+   场景 3: 等待。
+   ① MTRANS：服务员告诉厨师顾客所点的菜。
+   ② DO：厨师通过调用“做菜”的脚本做菜。
+   场景 4: 吃饭。
+   ① ATRANS：厨师把做好的菜给服务员。
