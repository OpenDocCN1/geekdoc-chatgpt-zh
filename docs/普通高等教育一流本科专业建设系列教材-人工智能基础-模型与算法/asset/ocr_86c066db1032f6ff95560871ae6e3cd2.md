② 知识的概念化：概括知识表示所需要的关键概念及其关系，如数据类型、初始条件、目标状态、控制策略等。

③ 概念的形式化：确定用来组织知识的数据结构形式，把概念化过程得到的有关概念用相应的知识表示方法表示出来。

④ 形式的规则化：把形式化的知识转变为由编程语言表示的可供计算机执行的程序。

⑤ 规则的合理化：确认规则化了的知识的合理性，检查规则的有效性。

2) 原型系统开发与实验。当知识表示方式确定之后，即可建立原型系统，它包括整个模型的典型知识，而且只涉及与实验有关的简单的任务和推理过程。

3) 知识库的改进和归纳。在原型系统的基础上，对知识库和推理机反复进行改进试验，归纳出更完善的结果。如此不断提高专家系统的水平，直到满意为止。

# (5) 专家系统与传统程序

专家系统的出现引发了人们对其与传统程序的对比思考。专家系统设计不同于传统的程序设计，因为其问题通常没有算法去求解，而是依靠推理获得一个合理的解决方法。算法是一种理想的解决方案，它会在有限的时间内给出答案。然而，传统算法设计有时会令问题的复杂程度增加，这时就需要使用人工智能算法，在没有任何可用的算法帮助获得最佳方法时，一个合理的方法就是最好的。

专家系统依赖于推理，解释机用于解释这个过程，这个过程是可检查的。有些专家系统甚至允许系统通过规则归纳从例子中学习规则，在归纳时，系统从数据中生成规则。

传统程序事实上是算法和数据结构的结合，关于问题求解的知识隐含于程序中。相比之下，专家系统是知识和推理的结合，知识单独组成知识库，与推理机分离。传统程序与专家系统的对比如表 4.2 所示。

# 表 4.2 传统程序与专家系统的对比

| 传统程序 | 专家系统 |
| :--- | :--- |
| 知识和处理组合在一个单元中 | 知识库和处理机制是两个独立的组件 |
| 涉及数值计算和数据处理 | 涉及对符号的处理 |
| 不具有解释功能 | 具有解释功能 |
| 程序不会出错（除非编程错误） | 专家系统可能会出错 |
| 该系统仅在完全开发后才可运行 | 专家系统持续优化，可以使用少量规则后启动 |
| 需要根据固定算法逐步执行 | 执行是按逻辑和启发式完成的 |
| 需要完整的信息 | 可以在足够或不充分的信息下起作用 |

# 2. Agent (智能体) 系统

人工智能可以看作一个研究能够产生智能行为的计算 Agent 的综合与分析领域，其核心目标是设计和合成有用且智能的产品。

# (1) Agent

Agent 是指在具体环境中具有动作能力的对象，如一个人、一个机器人、一条狗、一阵风、重力、一盏灯或一个能购物和售货的计算机程序。

有意图的 Agent 是具有偏好的，它会偏爱某种状态环境，并将采取行动来达到它最偏好的状态；无意图的 Agent 则会聚集在一起并被称为自然。建模时需设定一个 Agent 是否有意图，这样的假定是否合适是由具体环境来决定的。
