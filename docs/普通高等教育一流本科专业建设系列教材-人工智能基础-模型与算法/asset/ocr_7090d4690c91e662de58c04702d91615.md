也比大多数决策树算法更快，奥妙就在于将剪枝与后处理优化相结合。

# 算法 8.1 RIPPER 算法。

```
Procedure RIPPER
Input
训练样例集 D ;
重复次数 k
Begin
R = IREP*(D);
i = 0;
Repeat
R' = PostOpt(R);
D_i = NotCovered(R', D);
R_i = IREP*(D_i);
R = R' U R_i;
i = i + 1;
Until i = k
Output
规则集 R
```

首先使用 IREP* 剪枝机制生成规则集 R 。 IREP* 是 IREP 的改进，主要是以 \frac{\hat{m}_+ + (m_- - \hat{m}_-)}{m_+ + m_-} 取代了 REP 使用的准确率作为规则性能度量指标，在剪枝时删除规则尾部的多个文字，并在最终得到规则集之后再进行一次 IREP 剪枝。RIPPER 中的后处理机制是为了在剪枝的基础上进一步提升性能。

对 R 中的每条规则 r，RIPPER 会为其产生两个变体。基于 r_i 覆盖的样例，用 IREP* 重新生成一条规则 r'_i，该规则称为替换规则（replacement rule）；对 r_i 增加文字进行特化，并用 IREP* 剪枝生成一条规则 r''_i，该规则称为修订规则（revised rule）。

随后，把 r'_i 和 r''_i 分别与 R 中除 r'_i 之外的规则放在一起，组成规则集 R' 和 R''，将它们一起进行比较，选择最优的规则集保留下来，这就是算法 8.1 第 4 行所做的操作。

为什么 RIPPER 的优化策略会有效呢？原因很简单：最初生成 R 时，规则是按序生成的，每条规则都没有对其后产生的规则加以考虑，这样的贪心算法本质常导致算法陷入局部最优；RIPPER 的后处理优化过程将 R 中的所有规则放在一起重新加以优化，恰是通过全局的考虑来缓解贪心算法的局部性，从而能得到更好的效果。
