## 6.4.6 查看日志和更新系统

### 1. 查看日志

如果需要查看更多日志来帮助调试（或者只是想了解输出信息），你可以使用 `journalctl` 工具来查看系统日志和针对该程序的日志。

`journalctl` 默认会输出很多没用的系统日志，因此最好将程序以服务的形式运行，然后使 `journalctl` 只打印出该服务相关的日志。

例如，将笑脸检测器作为服务启动（或者像往常一样已经在运行中了），你可以通过以下命令来输出该服务的相关日志：

```
sudo journalctl -u joy_detection_demo -f
```

其中，`-f` 选项的作用是每当有新日志产生时就将其打印出来。按下 `Ctrl+C` 组合键来停止日志打印。

### 2. 系统更新

想要获取最新的漏洞修复和新特性，按照以下步骤更新到最新系统镜像：

- 从 `GitHub` 发布页面下载最新的 `.img.xz` 文件（发布细节请参考 changelog）。
- 用一个适配器将 `MicroSD` 卡与电脑相连接。
- 使用如 `Etcher` 一样的工具将 `.img.xz` 文件闪存到 `MicroSD` 卡上。(`Etcher` 在 `Windows`、`macOS` 及 `Linux` 系统上都是免费的。)

刷入完毕后，将 `MicroSD` 卡重新插回 `Vision Kit` 中，就可以继续之后的工作了。

## 7.1 简介与规格

## 7.2 USB 加速器快速上手

`Coral USB Accelerator` 实质上是一个 `USB` 设备，为系统提供 `Edge TPU` 协处理器，可以通过 `USB` 接口连到各种 `Linux` 系统上，加速机器学习推理。本节是入门指南，你需要做的只是将 `Edge TPU` 运行时库和 `Python` 库下载到与 `USB` 加速器连接的机器上，然后就可以运行 `TensorFlow Lite` 模型了。

### 7.2.1 系统要求

使用 `Coral USB Accelerator` 需要你的系统满足以下要求：

- 带有 `USB` 接口的 `Linux` 机器。
- `Debian 6.0` 及更高版本，或同系列系统（比如 `Ubuntu 10.0` 及更高版本）。
- 指令集为 `ARMv8` 的 `x86_64` 或 `ARM64` 架构的机器。

也就是说，`USB` 加速器是支持树莓派的。这里仅对于 `Raspbian` 系统的树莓派 2/3 Model B/B+ 版本提供官方支持。

推荐使用 `USB 3.0` 以达到更高的推理速度（树莓派仅支持 `USB 2.0`，但依然能够运行）。

### 7.2.2 在 Linux 或树莓派上进行配置

首先，按照以下步骤在 `Linux` 或树莓派上连接 `USB` 加速器。

安装 `Edge TPU` 运行时库和 `Python` 库。

![](EPUB/images/image_452.jpg)

注意，安装过程中会询问“是否使用最大工作频率”，如果选择此项就会加速运算过程，但也会让 `USB` 加速器表面非常烫，操作过程中可能会导致烫伤。因此当你不确定是否需要加速时，输入 `N` 然后按回车键，以使用默认工作频率（如更改此配置，只需重新执行安装步骤）。

如果安装过程中出现提示信息 `./install.sh: line 116: python3.5: command not found`，就是没有安装 `Python 3.5` 而导致安装失败。输入 `python3 –version`，然后按回车键来查看 `Python 3` 的版本，如果输出是 `Python 3.6` 或更高版本，则需要将 `install.sh` 脚本最后一行中的 `Python 3.5` 改为 `Python 3`。如果 `Python` 版本低于 3.5，则需要安装 `Python 3.5`。

将加速器通过 `USB 3.0` 插入机器（如果已经插入，那么需要先拔出再重新插入，以确保刚刚安装的 `udev` 规则生效）。

## 7.3 在 Edge TPU 上运行 TensorFlow 模型

为了让 `Edge TPU` 以低能耗提供高性能的神经网络运算，`Edge TPU` 支持一系列特定的神经网络操作和架构。本节介绍与 `Edge TPU` 兼容的神经网络模型机器构建方法，同时对运行方法进行简单的介绍。

### 7.3.1 兼容性概述

`Edge TPU` 能够执行深度前馈神经网络，例如卷积神经网络（`CNN`）。它仅支持完全 8 位量化且专门在 `Edge TPU` 上可编译的 `TensorFlow Lite` 模型。

`TensorFlow Lite` 是 `TensorFlow` 的轻量级版本，专为移动和嵌入式设备而设计。它能够实现低延迟的推理运算，但同时训练模型与编译器内核等二进制文件本身都很小。你不能直接使用 `TensorFlow Lite` 训练模型，而必须使用 `TensorFlow Lite` 转换器将模型从 `TensorFlow` 模型文件（例如 `.pb` 文件）转换为 `TensorFlow Lite` 模型文件（`.tflite` 文件）。

`TensorFlow` 采用一种称为量化的模型优化算法（在 `Edge TPU` 中也得到利用）。量化模型即将所有的 32 位浮点数（比如模型权重与激活函数输出等）转化为与之最相近的 8 位定点数，可以使模型更加小巧和快速。尽管使用 8 位定点数损失了精度，但是神经网络的推理准确率不会因此受到很大影响。

> **注意**
>
> `Edge TPU` 并不支持模型使用训练后量化，因为尽管通过使用 8 位定点数可以使模型更小，但在推理过程中会重新转化为 32 位浮点数。因此，必须使用训练时量化，也就是在训练过程中使用“伪”量化节点来模拟 8 位定点数的效果，使神经网络在推理过程中也使用量化后的值。这种技术使模型更能容忍不够精确的值，进而使模型精度更高（与训练后量化相比）。

图7-4描述了创建与 `Edge TPU` 相容模型的基本流程，其中大多数步骤用到的是基本的 `TensorFlow` 工具。当有一个 `TensorFlow Lite` 模型时，你可以使用 `Edge TPU` 编译器来创建一个与 `Edge TPU` 兼容的 `.tflite` 模型文件。

![](EPUB/images/image_456.jpg)

**图7-4**

实际上，创建 `Edge TPU` 模型并不需要完整遵循以上整个流程，你可以利用当前模型，并使用自己的数据集来重新训练一个模型。比如，`MobileNet` 是一个很受欢迎且与 `Edge TPU` 兼容的图像分类／检测模型架构，可以为此模型创建不同的版本，以便于为训练不同的图像分类器提供不同的起始点。7.3.3 小节将介绍如何使用迁移学习方法来重新训练模型。

如果你打算从头开始训练模型，则需要参考 7.3.2 小节的内容。

### 7.3.2 模型要求

若想充分利用 `Edge TPU` 从头构建 `TensorFlow` 模型，则必须满足以下要求：

- 模型参数是量化的，即为 8 位定点数；必须使用训练时量化，不支持训练后量化。
- 编译时参数张量大小固定，而不能使动态可变的。
- 编译时模型参数（如偏置张量）是常量。
- 模型参数可以是一维、二维或三维张量，若大于三维，则只有最内部的 3 个维度的大小可大于 1（其他维度大小必须为 1）。
- 模型只能使用 `Edge TPU` 支持的操作（参见表7-4）。

**表7-4 Edge TPU 支持的操作**

![](EPUB/images/image_457.jpg)

> **注意**
>
> `Edge TPU` 最多将模型图分割一次，因此只要遇到不支持的操作，其后的所有操作不论是支持还是不支持都将只在 `CPU` 上运行。

观察一下编译好的模型（通过如 `visualize.py` 之类的工具），你会发现这依然是一个 `TensorFlow Lite` 模型，只不过模型图的开始部分包含一些自定义操作，实际上这些自定义操作才是模型真正被编译的部分，包含了所有在 `Edge TPU` 上运行的部分。模型图剩余部分（从首个不支持操作开始）保持不变。

如果模型的一部分在 `CPU` 上运行，那么模型推理速度与完全在 `Edge TPU` 上相比将会显著降低。在此情况下模型会变慢多少将无法预测，因此最好测试不同的架构以努力构建一个能百分百完全与 `Edge TPU` 兼容的模型。也就是说，你所构建的模型所包含的所有操作都应该是 `Edge TPU` 所允许的。

> **注意**
>
> 编译完成时，`Edge TPU` 编译器将会告诉你，`Edge TPU` 所允许和不允许的操作各占多少比例。但是，在 `Edge TPU` 与 `CPU` 上运行部分所占的比例与对性能的影响并不是简单的正比关系，比如当 `CPU` 上只运行很小一部分时，推理速度与完全运行在 `Edge TPU` 上相比可能会有一个数量级的下降。

### 7.3.3 迁移学习

相比于满足以上所有要求来从头训练一个模型，也可以在已有的兼容 `Edge TPU` 模型基础上通过迁移学习（有时也称“微调”）方法来重训练。

从头训练一个神经网络模型（没有已知的权重和偏置项）需要数以天计的训练时间以及大量训练数据，但是迁移学习允许使用已训练好的相关任务模型，加之以一个小规模的训练集来进一步训练，以得到对于新类别的识别能力。还有一种方法是重新训练整个模型、调整整个网络的权重，将分类输出层替换成新的输出层，训练之得到对新类别的识别能力。

迁移学习过程通过足够的训练数据对参数进行微调，你可以一次性训练得到一个精确率很高的 `TensorFlow` 模型。如果对模型性能满意，可以将其转换为 `TensorFlow Lite` 模型，然后编译以用于 `Edge TPU`。模型结构在迁移学习过程中并不会发生变化，若初始模型兼容于 `Edge TPU`，那么迁移学习模型也可以在 `Edge TPU` 上完成完整的编译过程。

如果你熟悉迁移学习，可以先去官网看看那些预编译好的模型，使用这些模型作为自己创建模型的起始点。单击 All model files 下载 `TensorFlow` 模型和迁移学习中可以使用的预训练检查点。

如果是初次接触迁移学习，想要迅速得到一些结果，可以通过接下来的内容来入门（简化了重新训练 `MobileNet` 新类别的过程）：

- 重训练图像分类模型。
- 重训练目标检测模型。

你甚至可以直接在设备上通过 `Edge TPU` 重新训练模型。此时需要使用 `weight imprinting` 方法，可以借助所提供的 `Python API` 来完成。在后面 7.6 节中，将会详细介绍在设备上重训练图像分类模型的方法。

### 7.3.4 Edge TPU 运行时库与 API

想要在 `Edge TPU` 上运行模型，你需要在电脑上安装 `Edge TPU` 运行时库和 `API`。

如果你使用的是 `Coral` 开发板或者 `SoM`，那么运行时库和 `API` 在 `Mendel` 操作系统中已经提供。如果你使用的是类似于 `Coral USB Accelerator` 的配件设备，就必须将相应库和配件设备都装载到主机（仅支持 `Debian` 操作系统）上。

在进行神经网络推理时，可以使用 `Edge TPU` 库中提供的以下 `API` 之一：

- **Edge TPU C++ API**：对 `TensorFlow Lite C++ API` 的简单扩展（`edgetpu.h`），所以在推理过程中实际上大部分时间是在使用 `TensorFlow Lite` 的 `API`。
- **Edge TPU Python API**：对 `C++ API` 的包装，不同之处在于加了一些便于操作的、 `C++` 没有的 `API`（比如 `ClassificationEngine`）。你可以仅通过编译好的 `.tflite` 模型和想要分类的图片来完成图像分类。

### 7.3.5 在多个 Edge TPU 上运行多个模型
