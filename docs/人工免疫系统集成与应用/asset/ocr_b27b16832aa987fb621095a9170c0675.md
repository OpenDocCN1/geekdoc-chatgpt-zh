其聚簇划分,获得聚簇集 C。免疫网络 M 中的各抗体构成了 H 检测器的数据基础 FeaturePoint,每一个抗体对应一个 H 检测器,而 OE-AiNet 采用的压缩阈值 \(\sigma_s\) 则作为 H 检测器匹配阈值 Lc 的参数,H 检测器的匹配阈值统一取值如式(11-34)所示。

```
Lc = \lambda_m \times \sigma_s \qquad (11-34)
```

式中, \(\lambda_m\) 为匹配系数,控制抗体识别的特异性水平。

# 3. 聚簇类型标注

一般而言,同一操作类型的统计特征会在一个相近的空间内变化,因此可以假设一个聚簇主要包含一种类型的操作,对 H 检测器关联类型 Type 的标注也就可以转换为对聚簇关联类型 Type 的标注。假设每个样本 \(Ag \in X\) 都已经关联了检测日志(DetectLog),即 Ag 的实际关联的类型 Type 是已知的。如果缺乏检测日志,则一般认为特征日志关联的操作类型均为正常操作类型,而入侵类型的样本则基于入侵的先验知识模拟产生。利用样本对 M 进行反向识别测试(识别定义见定义 6-2)即可确定抗体聚簇关联的操作类型,识别结果记为 TR,如式(11-35)表示的四元组。

```
TR = \langle Ag, Type, Ab, Cx \rangle \qquad (11-35)
```

式中, Ag 为测试抗原; Type 为 Ag 关联的操作类型;Ab 为识别 Ag 的抗体;Cx 为 Ab 所属的抗体聚簇, \(Ab \in Cx, Cx \subset M\)。

按照 Cx 和 Type,对 TR 作聚集运算,结果 SR 的关系代数如式(11-36)所示。

```
SR = \langle Cx, Type, AgNum \rangle = C_{x, Type} G_{Max(Sum(Ag))} (TR) \qquad (11-36)
```

式中, AgNum 为识别的 Ag 数;SR 的子关系 \(\langle Cx, Type \rangle\) 为聚簇与操作类型的关联关系, \(\langle Ab, Type \rangle\) 关系也就随之确定,完成了抗体与操作类型标注。

经过以上三个步骤后,就产生了 H 检测器库。

# 11.7.2 RFID 协同检测器的动态更新

随着业务的变更,各种抗原类型的特征日志分布也将缓慢变化,所以 H 检测器的动态更新是必要的,否则系统的检测性能会逐步恶化。与 L 检测器类似,H 检测器持续不断地更新会消耗掉大量的资源,影响检测效率,因此也采用周期性更新的方式来维护 H 检测器的有效性,自最近一次 H 检测器生成以来,如果新增的 FeatureLog 数量超过阈值,则重新从历史记录中选取 FeatureLog 样本集,并生成新一轮 H 检测器集。选择 FeatureLog 样本时,为了保证新鲜性,新增的 FeatureLog 记录全部包括。为了保证完整性,各抗原类型的 FeatureLog 样本均需要达到一定规模。用新的 FeatureLog 样本提取的 H 检测器库,其分布将更符合新的 FeatureLog 分布影像。
