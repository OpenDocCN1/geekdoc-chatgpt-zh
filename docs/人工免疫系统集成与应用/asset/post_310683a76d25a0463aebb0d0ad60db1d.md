
多方面的修改，使 RFID 应用的标准化实施困难；再次，加密认证存在着密钥泄漏和密钥被攻破的风险。因此，单纯依赖加密认证协议难以满足 RFID 的安全需求。物理方法因为需要额外的物理器件或额外的操作，可操作性不强。防火墙、病毒防护等网络安全技术对 RFID 后端应用的数据安全起到一定的保护作用，但是对标签与阅读器之间的安全威胁无能为力。因此，RFID 安全技术仍需要探索和完善，有必要引入新的理论和方法来构建 RFID 系统的安全方案。

入侵检测(intrusion detection)是继防火墙、加密认证、病毒防护等传统安全保护技术之后的新一代安全保障技术，入侵检测能与防火墙、加密认证互补地发挥作用，共同为计算机系统构建一个层次防御体系。入侵检测只是针对应用系统的日志和审计作检测分析，并不增加应用系统本身的复杂度。将入侵检测作为 RFID 安全方法，能在无须改变 RFID 现有技术标准和标签结构的前提下，提升 RFID 系统的安全防护能力，从而有效规避标签成本和市场推广的矛盾。

生物免疫系统(immune system)与入侵检测系统有着惊人的相似性，生物免疫系统保护机体不受细菌、病毒等各种病原体侵害，而入侵检测系统保护信息系统不受黑客和计算机病毒的侵扰，两者都是在不断变化的环境中维持系统的稳定性[218]。借鉴生物免疫系统的免疫原理进行入侵检测技术研究已成为当今的热门研究方向之一。RFID 系统涌现出的并行性、分布性、开放性等特性，与生物免疫系统特性有着更加惊人的吻合。生物免疫系统的免疫识别、免疫耐受、免疫学习、免疫应答等机理表现出来的自学习、分布式计算和局部寻优等优点，对 RFID 入侵检测方法的研究有着十分重要的理论指导意义。

综上所述，借鉴生物免疫机理开展 RFID 入侵检测方法的研究，不仅为 RFID 安全方案引入了新的理论和技术方法，同时也丰富了入侵检测的理论和方法，延伸了入侵检测的应用领域，有着十分重要的理论创新和应用价值。

## 11.3 基于免疫组织的 RFID 入侵检测多 Agent 模型

RFID 系统的分布式特性，决定了 RFID 入侵检测也必须以一个分布式的系统结构与之相适应。生物免疫系统的分布式和无中心控制的结构特点也引导着入侵检测系统朝分布式方向发展。多 Agent 系统建模作为一种分布式复杂系统的建模技术，为人工免疫系统提供了一条重要的实现途径。本章参考生物免疫系统的组织结构，在多 Agent 建模方法的指导下，将 RFID 入侵检测进行目标分解，构建 RFID 入侵检测的多 Agent 系统(multi-agent system, MAS)模型。

### 11.3.1 基于免疫组织的 RFID 入侵检测目标层次模型

获取系统目标是 MAS 建模过程的基础，系统目标不会像功能、处理过程和数据结构那样随着时间发生变化，它是比较稳定的，这也是系统分析往往从系统目标开始的原因。对 RFID 入侵检测而言，总的目标是识别出 RFID 系统中的非法操作，保护 RFID 系统免受攻击。然而这个目标过于抽象和模糊，无法提出具体的方法来实现，因此需要对目标进行分解和细化，建立目标层次模型，使各个子目标具有可实现性。

入侵检测系统与生物免疫系统的目标是相似的，均可抽象为对自体/非自体的识别，因此，生物免疫系统的功能目标为 RFID 入侵检测的目标细化提供了参考。从生物免疫系统的组织结构和免疫过程来分析，生物免疫系统对抗原的识别先后经历了免疫细胞产生、抗原提呈、抗原识别和免疫反应等过程，每个过程可视为一个阶段性的子目标。每一个子目标分别由各免疫组织、免疫器官和免疫细胞来承担。生物免疫系统的功能组织模型如图 11-2 所示。其中，骨髓和胸腺产生免疫细胞，单核巨噬细胞实现抗原提呈，淋巴细胞则承担了抗原识别和免疫反应的任务。

### 11.3.4 RFID 入侵检测 Agent 类模型

Agent 类建模是 MAS 建模的核心过程，它实现从系统“做什么”到“怎么做”的过渡，其目标是将前面的建模结果封装到 Agent 中去，最终组装为多 Agent 系统。

定义 11-2 Agent 类。Agent 类是多 Agent 系统中的一类 Agent 的模板，它描述了 Agent 需要扮演的角色和需要实现的目标。Agent 类的形式化描述为 AgentClass = <name, roles, goals> (11-2)

式中，name 表示 Agent 类的名称；Roles 表示 Agent 类的角色集；Goals 表示 Agent类的目标集。

Agent 类模型是多 Agent 系统的框架，它描述了系统中所包含的 Agent 类，以及 Agent 类之间的通信。Agent 类以角色模型和角色交互模型为基础，通过将 Agent 类与角色进行绑定，确定 Agent 类所扮演的角色，而角色交互模型则体现了 Agent 类之间的对话。

一般而言，可以将角色模型中抽象出的角色映射为 Agent 类，如果两个角色之间的通信量很大时，为了减少通信负担，可以将两个角色封装在一个 Agent 类中；当一个角色实现目标的计算和存储量很大时，也可以将这个角色进行进一步拆分，用两个或多个 Agent 类封装。

模仿生物免疫系统的 RFID 入侵检测角色模型，角色承担的目标相对独立，角色之间没有复杂的协作，直接可以将角色封装为 Agent 类，抽象出 RFID 入侵检测器中心、RFID 入侵信息收集器和 RFID 入侵监视器等 Agent 类，以下分别简称为检测器中心、信息收集器和入侵监视器。结合角色模型和角色交互模型构建的 Agent 类模型如图 11-7 所示。图中的方框表示 Agent 类，每个 Agent 类的子框从上到下依次为 Agent 类名称(name)、扮演角色 (roles)和目标集 (goals)，而 Agent 类之间的箭线表示了 Agent 类之间的通信关系，箭头指向请求目标。

### 11.3.5 RFID 入侵检测 Agent 交互模型

本章采用黑板模型和消息传递相结合的方式来构建 Agent 交互模型，对于不需要 Agent 之间实时协作处理，只作为知识共享的交互，通过黑板模型完成，这样有利于 Agent 之间的异步处理，只有需要实时协作的交互才通过消息传递。

- 1. 黑板模型

根据角色模型、目标层次模型和 Agent 类模型，分析各 Agent 类需要的知识，以及能提供哪些知识用来共享。

检测器中心：需要抗原、检测日志、入侵处理日志作为知识源，可共享各类检测器。

信息收集器：可共享抗原，不需要获取其他 Agent 的知识，因为它的信息直接来源于 RFID 应用系统。

入侵监视器：需要获取各类检测器，可共享检测日志。

另外，各 Agent 的注册与注销均在黑板上登记，黑板上始终保持一个活动的 Agent 列表，便于消息分发时能查询到需要分发的目标 Agent。

建立的黑板模型如图 11-8 所示。

![](img/cd91189832ca806b16310970569db51c_186_0.png)

图 11-8 黑板模型

黑板模型中共享的知识均以本体为语义基础表达，从而为各 Agent 对知识的理解提供了一致的概念，就实现而言，黑板一般采用共享内存或数据库的方式实现，本体则通常以内存对象或者数据库对象的方式存在。

- 2. 消息模型

Agent 间的消息交互在 Agent 类模型中已经有所体现，因为黑板模型承担了知识共享的角色，Agent 间的消息交互变得比较简单。本章采用 KQML 语言定义了 Agent 之间的消息模型，定义了 inform 和 trans 两个扩展消息原语。

inform: 通知消息，当检测器中心更新检测器后，通知各入侵监视器从黑板上获取新的检测器；

trans: 传送消息，负责从信息收集器到入侵监视器的抗原传送，驱动抗原识别。

以下定义各类通信的消息格式。

- 1) 检测器中心到入侵监视器的通知消息

```
{inform
:sender CenterX
:receiver MonitorY
:language KQML
:ontology Detector
:content (new)
}
```

其中，sender 参数为发送通知的检测器中心名称，即 DetectorCenter. name；receiver 参数为接收通知的入侵监视器名称，即 IntrusionMonitor. name；ontology 参数为更新的检测器；content 参数为更新的类型，其中，new 表示新增了检测器，delete 表示删除，modify 表示修改，replace 表示全部替换。

- 2) 信息收集器到入侵监视器的传送消息

```
{trans
:sender CollectorX
:receiver MonitorY
:language KQML
:ontology RFIDAntigen
:content (…) 
}
```

其中，sender 参数为发送特征日志的信息收集器名称；receiver 参数为接收特征日志的入侵监视器名称；ontology 参数为 RFID 抗原；content 参数为 RFID 抗原的属性和属性值，用 attr= value 的形式表示。

在传输协议的选择上，为了保证 Agent 的自治特性，可选用非连接的 UDP 协议，通信方式采用简单可靠的点对点方式。

### 11.3.6 RFID 入侵检测 Agent 分布式部署模型

部署模型将根据系统实际运行需求，确定系统运行中每个 Agent 类有几个 Agent 实例存在；然后确定系统的运行结构，从而对这些 Agent 实例进行组织管理；最后，确定这些 Agent 实例的物理分布，形成部署模型。

就应用而言，一个分布式的 RFID 系统一般由多个功能区域组成，如生产管理系统中，产品会按照生产流程分别处于生产车间、检测车间、存储库房等，每个区域都需要应用 RFID 进行信息维护。与应用相对应，信息收集器也必须是分布式的，一个功能区域需要一个或者多个信息收集器。对于入侵监视器而言，可以采用集中式监视和分散式监视两种模式。集中式监视即整个 RFID 入侵检测系统只部署一个入侵监视器，所有信息收集器收集的特征日志都发给一个入侵监视器来分析识别。分散式监视则部署多个入侵监视器，分别监视一个或多个区域的标签操作。就设计而言，集中式监视可视为分散式监视的一个特例。对检测器中心而言，为了保证所有检测器在各入侵监视器中共享，并且考虑到检测器中心不需要承担实时处理任务，一般只部署一个检测器中心实例。根据以上 Agent 实例逻辑关系的描述，RFID 入侵检测各 Agent 的部署实例如图 11-9 所示。

![](img/cd91189832ca806b16310970569db51c_188_0.png)

图 11-9 RFID 入侵检测系统的部署实例

Agent 的物理部署则需要根据 RFID 应用系统的规模和管理而定，信息收集器、入侵监视器和检测器中心可以任意组合部署在一台主机上。

上述运行结构与生物免疫系统的运行结构是基本一致的，作为中枢免疫组织的检测器中心集中生成检测器，而作为外周免疫器官的信息收集器和入侵监视器则分布在系统各区域，负责各自 RFID 区域免遭入侵。

基于免疫机理构建的 RFID 入侵检测 MAS 模型，不仅分解了系统的复杂度，而且实现了系统运行时的健壮性。

定义 11-3 RFID 入侵检测系统的健壮性[56]。设入侵检测系统 $\Sigma_{RIDS}$ 的内部组成 $\Omega_{RIDS} = \{a_1, a_2, \cdots, a_n\}, a_i (1 \leqslant i \leqslant n)$ 为各 Agent 。如任意 $k(k < n)$ 个 Agent 失效，新入侵检测系统 $\Sigma'_{RIDS}$ 的内部结构为 $\Omega'_{RIDS} = \{a_1, a_2, \cdots, a_{n-k}\}$，如果满足

```
\(\frac{DA(\Sigma'_{RIDS}) - DA(\Sigma_{RIDS})}{DA(\Sigma_{RIDS})} \leqslant \Gamma\) (11-3)
```

式中，DA 表示检测性能；$\Gamma$ 为检测性能变化阈值。则称 $\Sigma_{RIDS}$ 具有 k 级健壮性。

以下对 RFID 入侵检测 MAS 的健壮性进行分析。

RFID 入侵检测系统的健壮性主要体现在 Agent 的自主性上，若某个 Agent 失效，可能会造成系统检测性能下降，但不会导致整个系统失效。

- (1) 某个信息收集器失效，只影响所辖 RFID 区域的检测，对其他区域没有影响。

- (2) 某个入侵监视器失效，只影响所辖 RFID 区域，如果建立入侵监视器集群机制，即某个入侵监视器失效，其他入侵监视器主动接替其工作，则某个入侵监视器失效后，对检测性能基本没有影响。

- (3) 检测器中心失效，各个入侵监视器无法获取检测器更新，但是原有的检测器仍然发挥作用。

所以，部分 Agent 失效后，只使局部区域或局部时段的检测性能下降，但不会导致整个系统失效，从而体现出系统良好的健壮性。

## 11.4 基于抗原提呈的 RFID 入侵信息定义与采集方法

### 11.4.1 EPC C1G2 协议及其安全性分析

EPC C1G2 详细地描述了超高频第二代 RFID 标签与阅读器通信的无线接口规范，阅读器操作与标签状态切换如图 11-10 所示。

阅读器通过选择、盘存、访问三个基本操作来管理标签群，每个操作由一个或者多个命令组成，标签则通过七种状态来实现自身管理。

阅读器的三个基本操作定义如下[219]：

- (1) 选择（select）。阅读器选择标签群以便于盘存和访问，阅读器可以用一个或多个 Select 命令在盘存之前选择特定的标签群。

- (2) 盘存（inventory）。阅读器识别标签的过程。盘存操作包括 Query、QueryAdjust、QueryRep、ACK、NAK 等命令。阅读器通过 Query 命令开启一个
